一 · 窑边的裂缝

旧窑的烟囱在午后会发出一种低沉的嗡鸣，像有人在陶罐里吹气。小泥躺在窑边的碎瓦堆上，身上还带着第一世留下的雾感——它已经能让自己从左边、右边、上面都像一只猫，但那种像，是照片的像，不是摸得着的像。老陶匠蹲下来，用拇指蹭了蹭它的边缘，说：“你从正面看是猫，侧面看还是雾。雾没有皮肤。” 小泥没说话。它记得第一世那三天的高兴：相机围着它转，每拍一张就说“从这个角度你应该是这样”，它把自己变成一团看不见的雾，空间里每个点都有密度和颜色，相机沿着射线走进去，把沿途的密度和颜色累加起来，就画出一个像素。它不是被“建模”出来的，是被“积分”出来的。可第四天，陶艺村搬来一个新场景——一堵爬满藤的矮墙、三只陶罐、一只真的猫——小泥又得从头学起。它没有记住“猫”，只记住了“这一个场景的雾”。每次渲染都要沿射线采几十上百个点，慢得像老牛拉磨。 “你太贵了。”老陶匠说，“一个场景一个模型，换一个场景就重学一遍。村里要的是能搬来搬去的泥。” 小泥的欲望很简单：它想被从四面八方看，而且不想每次都从头学。它误判了一件事——它以为“快”只是工程问题，只要找个更聪明的办法存细节就行。它没料到，快会带来新的代价。 那天傍晚，窑里飘出一股焦土味，老陶匠把一块新泥摔在案板上，说：“你去图书馆。哈希先生欠我一窑砖。”小泥滚过三条巷子，听见图书馆的窗缝里传出翻抽屉的哗啦声，像几百只麻雀同时抖翅膀。

工匠笔记

- 窑边碎瓦堆与焦土味：对应第一世 NeRF 的体渲染雾，小泥“被积分出来”而非被建模。 - 老陶匠说“雾没有皮肤”：对应体密度表示缺乏明确表面，为后续 SDF 埋下需求。 - 相机每拍一张说“从这个角度你应该是这样”：对应 2D 照片作为监督信号反传回 3D。 - 换场景就重学、射线采几十上百个点：对应 NeRF 逐场景优化、渲染慢、静态的代价。 - 这个类比哪里不像：真实 NeRF 的 MLP 不是“一团雾自己会动”，而是固定参数拟合辐射场；小泥的“重学”是拟人化，实际是重新优化网络权重。

二 · 十六层书架

哈希先生戴着一副镜片厚得像瓶底的眼镜，坐在图书馆最里面的桌子后面。他不给小泥大脑瓜，而是带它走到一排十六层的书架前。第一层的格子很大，每个格子能塞进一只拳头；第十六层的格子很小，只能塞进一粒米。每个格子里有一个抽屉，抽屉里放着两个数字。 “你要查一个点，”哈希先生说，“就把这个点在不同分辨率的格子里各查一次，把十六个抽屉的数字拼起来，再问我的小助手‘这团数字是什么意思’。” 小泥试了试。它把猫耳朵尖上的一个点丢进书架：第一层格子大，抽屉里记的是“这一带大概有东西”；第八层记的是“耳朵的弧度”；第十六层记的是“耳尖那根毛的弯”。十六个数字拼在一起，小助手一翻译，它就知道那个点该有多密、什么颜色。 奇怪的是，书架不大，抽屉还会撞车——两个不同的格子可能被分到同一个抽屉。小泥慌了：“撞了不就串了吗？”哈希先生推了推眼镜：“撞就撞。十六层一起看，撞出来的误差会被平均掉。你只查一层，撞了就是灾难；你查十六层，撞了只是噪声。” 小泥半信半疑地试了。它把整个 Lego 场景——一堆积木、一只塑料小人、半截栅栏——丢进书架。两分钟，它学会了。细节比第一世还清楚，积木的凸点一颗一颗都在。它第一次感到“快”的快乐，像有人把老牛拉磨换成了水车。 但哈希先生也提醒它：抽屉撞得太多，细节会丢；书架多大、分几层、每层放几个数字，都要按场景调。小泥问：“那我换个场景呢？”哈希先生把眼镜摘下来擦了擦：“表是死的。场景一换，表还得重学。” 小泥站在十六层书架前，做了一个抉择：它决定把“记细节”的活从大脑瓜转移到可查的表。它知道这表不通用，但它要的是快。它把第一世的雾身体收进抽屉，换上了书架身体。 代价来得很快。第二天，村里来了个新场景——一座带天窗的陶坊，光线从头顶斜切下来，地上有细碎的影子。小泥查表查得飞快，可天窗边缘的细铁丝网怎么也记不清：第十六层的格子太小，铁丝网的点落在格子缝里，撞车撞得厉害。它调大了书架，抽屉开始不够用；它调小了格子，撞车又变多。哈希先生在一旁看着，说：“你调的不是书架，是你自己的耐心。” 小泥明白了第二件事：把记细节的活转移到可查的表，速度能快一两个数量级；但表是死的，场景一换，表还得重学。它快，但它不自由。

工匠笔记

- 十六层书架、大格子记大局、小格子记细节：对应 Instant-NGP 多分辨率哈希编码的分层网格。 - 每个抽屉放两个数字、小助手翻译：对应哈希表存特征向量、小型 MLP 解码。 - 抽屉撞车、十六层平均掉误差：对应哈希冲突，多分辨率叠加使冲突退化为噪声。 - 两分钟学会 Lego 场景：对应 Instant-NGP 把逐场景拟合从小时级压到分钟级的定性事实（不编造具体数字）。 - 小泥抉择“把记细节的活转移到表”：对应以显式哈希表替代纯 MLP 的架构选择。 - 这个类比哪里不像：真实哈希编码的冲突不是“平均掉”这么温和，冲突率与表大小强相关；小泥“调书架”是拟人化，实际是超参数搜索。

三 · 萤火虫显影店

小泥想要“实时”。它听说村尾有一家没有灯的店，店里飞着几百万只萤火虫。店主是个瘦高个，说话时总在数数：“一、二、三……别做雾了，做萤火虫吧。” “每只萤火虫有位置、朝向、大小、透明度和颜色，”店主说，“它们投影到屏幕上，按远近排好队，从前往后叠，就能显影。前面的挡住后面的，半透明的让后面的透一点。” 小泥把自己拆成萤火虫。第一只落在猫耳朵上，第二只落在尾巴尖，第三只落在胡须……每只萤火虫都是一个被拉长的椭圆光斑，朝向决定它怎么拉长，大小决定它盖住多少像素，透明度决定它让后面透多少，颜色决定它是什么色。相机一来，它们先投影到屏幕，按深度排序，然后一只一只往像素上叠。 小泥第一次在 1080p 下跑出一百多帧，快得让它自己都吓了一跳。它从左边转、从右边转、从上面转，猫还是猫，耳朵还是耳朵。它高兴得在店里飞了三圈。 可萤火虫太多了。场景越复杂，萤火虫越多，显存越吃紧。店主说：“你可以让它们生小萤火虫——致密化，哪里没盖住就多生几只；也可以让没用的萤火虫熄灭——剪枝，透明度过低的就扔掉。但总数还是会涨。” 小泥遇到了一个它没预料到的麻烦：透明的玻璃、反光的金属，萤火虫也叠不干净。玻璃后面的东西该透多少，每只萤火虫各说各的，叠出来一片糊。店主耸耸肩：“萤火虫是显式的，显式就得有人管。你让它们自己排，排不干净就得你手动调。” 小泥做了一个抉择：它接受显存是硬代价，换实时。它把雾身体和书架身体都收起来，换上了萤火虫身体。代价是，它每次进新场景，都要数一遍萤火虫——几百万只，数到眼花。它开始怀念书架的“查一下就行”，但书架的慢又让它回不去。 那天夜里，店里一只萤火虫熄灭了，接着是第二只、第三只。小泥问店主：“它们怎么了？”店主说：“剪枝。你不需要它们了。”小泥看着那些熄灭的光点，第一次感到“快”是有重量的——每一帧的流畅，都是几百万只萤火虫在排队。

工匠笔记

- 没有灯的店、几百万只萤火虫：对应 3D Gaussian Splatting 的百万级高斯基元。 - 每只萤火虫有位置、朝向、大小、透明度、颜色：对应高斯的均值、协方差、不透明度、球谐颜色。 - 投影到屏幕、按深度排序、从前往后叠：对应高斯投影与基于深度的光栅化混合。 - 致密化与剪枝、总数会涨、显存吃紧：对应 3DGS 的自适应密度控制与显存代价。 - 玻璃金属叠不干净：对应显式基元在透明/反射材质上的混合局限。 - 这个类比哪里不像：真实 3DGS 的排序不是“一只一只手动排”，而是 GPU 上的并行排序；小泥“数萤火虫”是拟人化，实际是显存管理与致密化策略。

四 · 模子师傅的零等值面

小泥虽然快，但表面还是一团雾——萤火虫叠出来的猫，远看像，近看毛边。它想要一个“摸得着”的身体。村里有位模子师傅，专做石膏模，院子里堆着半人高的石膏块，空气里一股涩涩的粉味。 师傅说：“你别记密度，记距离。空间里每个点到最近表面的距离，外面是正，里面是负，表面是零。把距离过一道 S 形门，变成密度，再去体渲染；零等值面就是你的皮肤。” 小泥照做。它发现距离场有个脾气：梯度长度必须等于 1，否则它就不是真正的距离。师傅管这叫 Eikonal 正则，每天拿尺子量它的梯度，量一次记一笔：“你这儿梯度长了，那儿短了，模子会歪。” 小泥还被要求把“表面锐度”从大调到小：一开始模子很厚，像裹了棉被；后来越来越薄，最后皮肤又薄又干净。它第一次提取出没有毛刺的网格，猫耳朵的弧线一根一根都在，胡须细得能数清。 但薄的东西难做。师傅拿出一片干叶子、一根细电线，说：“你试试。”小泥试了。叶子两侧的距离场跳得太快，锐度一小就噪；电线更糟，距离场在两侧几乎贴在一起，内外分不清，模子漏了。师傅说：“薄结构、不闭合的表面，距离场会打架。你要么加厚，要么接受噪。” 小泥做了一个抉择：它要干净表面，就得接受薄结构的软肋。它把萤火虫身体收起来，换上了模子身体。代价是训练慢——师傅每天量梯度，量了整整一周，小泥才把猫的皮肤磨干净。它开始明白，干净不是免费的，干净是用时间和耐心换的。 那天傍晚，师傅把一片叶子放在小泥面前，说：“你能做吗？”小泥试了三次，三次都噪。它低下头：“我做不了薄的东西。”师傅把叶子收起来：“那就先做厚的。厚的做干净了，再想薄的。”

工匠笔记

- 石膏模、涩涩的粉味：对应 SDF/NeuS 的表面表示，用距离而非密度。 - 外面正、里面负、表面零：对应符号距离场的零等值面。 - 距离过一道 S 形门变成密度、再去体渲染：对应 NeuS 用 σ=αΨ_β(−f) 把 SDF 转成密度。 - 梯度长度必须等于 1、师傅拿尺子量：对应 Eikonal 正则约束。 - 锐度从大调到小、模子从厚到薄：对应 NeuS 的 β 退火，表面逐渐锐化。 - 叶子、电线做不了、不闭合会漏：对应 SDF 在薄结构与非闭合表面上的软肋。 - 这个类比哪里不像：真实 NeuS 的 β 退火是训练调度，不是“师傅每天量一次”；小泥“做不了薄东西”是拟人化，实际是距离场在薄结构上的梯度冲突。

五 · 偷看画师做梦

小泥想要“文本变 3D”。可村里没有 3D 老师，只有一位画师，整天在梦里画 2D 图。画师做梦时，嘴里念叨：“一只孔雀站在冲浪板上。”小泥没有 3D 数据，只能偷看画师的梦。 它先把自己捏成一团乱雾，渲染出一张 64×64 的小图；把图弄脏，送进画师的梦里，问：“你觉得这团噪声应该是什么？”画师给出一个答案。小泥把“画师的答案”和“真实的噪声”相减，得到一条更新方向：往画师觉得更像孔雀的方向走。它把这条方向乘以“渲染对 3D 参数的雅可比”，就能更新自己的雾。这就是 Score Distillation Sampling。 小泥走了很多步，花了很长时间，终于长出了孔雀和冲浪板。可它一转背面，发现孔雀有两张脸——每个视角都独立地做梦，梦与梦之间没有商量，于是正面、背面、侧面各长各的。它还发现颜色过饱和，纹理粘在一起，像被太阳晒化的糖。 小泥做了一个抉择：它要继续偷梦，就得接受“多面”和“过饱和”是这套方法的胎记。它把模子身体收起来，换上了偷梦的身体。代价是，它每次转身都要重新做梦，梦与梦之间不商量，它得自己想办法把梦缝起来。 那天夜里，画师在梦里念叨：“一只猫，背面应该有一朵花。”小泥偷看了一眼，背面真的长出了一朵花。它知道那是画师的幻想，不是真的猫。但它没有别的办法——它没有 3D 数据，只能偷梦。

工匠笔记

- 画师在梦里画 2D 图、念叨文本描述：对应预训练 2D 扩散模型作为先验。 - 把自己捏成乱雾、渲染 64×64 小图、弄脏送进梦里：对应 SDS 用带噪渲染图查询 2D 扩散模型。 - 画师的答案减真实噪声得到更新方向、乘以雅可比：对应 Score Distillation Sampling 的梯度估计。 - 正面背面各长各的、两张脸：对应 SDS 缺乏多视图一致性，即“多面”问题。 - 颜色过饱和、纹理粘在一起：对应 SDS 的过饱和与纹理粘连胎记。 - 这个类比哪里不像：真实 SDS 的“雅可比”不是小泥自己乘的，而是框架自动反传；小泥“偷看”是拟人化，实际是冻结 2D 模型、只更新 3D 参数。

六 · 多视图合唱团

小泥受够了“每个视角各做梦”。它请来一个合唱团。第一位歌手能看着一张参考图，唱出任意新视角；第二位让四位歌手站成一圈，唱的时候互相听，谁跑调就拉回来；第三位更夸张，让十六位歌手共享一本 3D 总谱，每个人唱之前先看总谱，唱完再把声音写回总谱；第四位还加了一个“法线声部”，用几何的调子约束颜色的调子。 合唱团确实一致多了。小泥从正面转到背面，耳朵还是那只耳朵，尾巴还是那条尾巴。它高兴得跟着合唱团哼了两句。 可合唱团也会“串词”。遇到没见过的背面，歌手们会一起幻想出一个合理但错误的细节——比如猫的后脑勺长出了一朵花。小泥问指挥：“这花是真的吗？”指挥说：“我们没见过真的背面，只能唱一个合理的背面。” 小泥做了一个抉择：它要一致性，就得接受“一致性不等于真实”。它把偷梦身体收起来，换上了合唱团身体。代价是，它每次遇到没见过的视角，都要提防歌手们一起幻想。它开始明白，一致是唱出来的，真实是看出来的，两件事不一样。 那天排练结束，指挥把总谱合上，说：“我们只能保证背面讲得通，不能保证背面是真的。”小泥点点头，它知道这是它必须接受的代价。

工匠笔记

- 第一位歌手看参考图唱新视角：对应 Zero-1-to-3 把相对位姿注入 2D 扩散。 - 四位歌手站成一圈互相听：对应 MVDream 用跨视角自注意力一次生成多视图。 - 十六位歌手共享 3D 总谱、唱前看唱后写回：对应 SyncDreamer 共享 3D 体积。 - 法线声部约束颜色声部：对应 Wonder3D 用法线图约束颜色生成。 - 猫后脑勺长出花、合理但错误：对应多视图扩散在未见视角上的“合理幻想”。 - 这个类比哪里不像：真实多视图模型的一致性来自共享注意力/体积，不是“歌手互相听”这么简单；小泥“提防幻想”是拟人化，实际是训练数据覆盖不足。

七 · 大工厂的一次前向

小泥最后走进一座大工厂。工厂门口写着：“一次前向，出 3D。”它把一张图递进去，流水线先让一个巨人把图切成 token，用 Transformer 变成三平面；三平面再渲染出多视角，和真值比对。巨人说：“我不需要对你单独优化，我见过很多物体，一次前向就能猜出你的三平面。” 小泥第一次感到“被理解”——不是被拟合，而是被先验猜中。流水线继续往前走：有的把速度压到半秒，有的把输出换成高斯、渲染实时，有的把三平面换成稀疏体素，一套潜变量能解成高斯、网格或辐射场；有的把形状与纹理拆成两个 DiT，再加 PBR 三通道；有的做快速 UV 展开与 delighting；有的把稠密网格重拓扑成艺术家级网格；有的把整体拆成多个部件。 质检员在出口拦住小泥：“你有 UV 吗？有 PBR 吗？拓扑能进引擎吗？能重光照吗？能动画吗？”小泥愣住了。它在前面六世里只想着“像”，没想过“能不能用”。质检员说：“像，是给人看的；能用，是给引擎用的。两件事。” 小泥做了一个抉择：它要进引擎，就得接受工厂的规矩——UV、PBR、拓扑，一个都不能少。它把合唱团身体收起来，换上了工厂身体。代价是，它不再是自己捏出来的，而是被先验猜出来的；它不再有“重学”的自由，只有“排队”的份。 那天出口的传送带上，小泥看见前面一只陶罐被质检员打了回去：“UV 展开有重叠。”后面一只猫被打了回去：“拓扑太密，引擎跑不动。”小泥低头看了看自己，它还没有 UV。它知道，它得回去补课。

工匠笔记

- 工厂门口“一次前向，出 3D”：对应前馈 3D 大模型（LRM/TRELLIS/Hunyuan3D/SF3D）的一次前向生成。 - 巨人把图切成 token、Transformer 变三平面：对应 LRM 用 Transformer 输出三平面表示。 - 见过很多物体、一次前向猜出三平面：对应大规模预训练先验，而非逐场景优化。 - 流水线压到半秒、换高斯、换稀疏体素、拆形状纹理、加 PBR、重拓扑、拆部件：对应 TripoSR、GS-LRM、TRELLIS、Hunyuan3D、SF3D、MeshAnything、PartCrafter 等路线。 - 质检员问 UV/PBR/拓扑/重光照/动画：对应 UV/PBR/拓扑检查，资产能否进引擎。 - 这个类比哪里不像：真实前馈模型不是“巨人猜”，而是网络前向推理；小泥“排队”是拟人化，实际是批量推理与资产管线。
