一 · 两阶段流水线：从网格集合到可预测的离散序列

MeshGPT 的方法骨架是一条两阶段流水线，两个阶段解决的是两个性质完全不同的问题。第一阶段解决“网格能不能变成语言”的问题：三角网格本质上是顶点集合与面片集合的组合结构，面片之间通过共享顶点形成邻接关系，这种集合结构没有天然的线性顺序，无法直接喂给自回归模型。第二阶段解决“语言模型能不能学会这种语言”的问题：一旦面片被离散化成 token，序列上的下一个 token 预测就变成了标准的 decoder-only Transformer 任务。两阶段之间通过一个共享的“面片词表”耦合：第一阶段的 VQ-VAE 编码器定义了词表，第二阶段的 Transformer 只在这个词表上做分类。

第一阶段的数据流是：输入一个三角网格，对每个面片取其局部几何与拓扑邻域，用图卷积网络提取该面片的特征向量，再经向量量化（VQ）把连续特征映射到词表中的一个离散嵌入。这一步的产物有两样：一是码本（codebook），即词表本身；二是把整个网格的面片按某种顺序排列后得到的 token 序列。第二阶段拿这个序列训练 decoder-only Transformer，目标是最大化序列的似然。推理时，从起始 token 出发逐步采样，每采样出一个面片 token，解码器就把它还原成具体的顶点坐标与面片连接，直到生成终止 token 或达到序列长度上限。

这条流水线的关键分工在于：VQ-VAE 负责“什么叫一个合法的面片”，Transformer 负责“面片之间怎么排列”。前者是几何与拓扑的压缩问题，后者是序列建模问题。把两者拆开的好处是第二阶段可以完全复用语言模型的成熟配方（因果掩码、位置编码、交叉熵训练），而不必在自回归过程中直接处理连续坐标。代价是第一阶段的重建误差会成为第二阶段的天花板：如果词表里的面片无法精确表达输入网格的局部形状，那么无论 Transformer 多强，生成结果都会带着量化误差。

二 · 图卷积编码器：面片局部特征的提取机制

面片不是孤立的三角形。一个面片的“长什么样”不仅取决于它自己的三个顶点，还取决于它与哪些面片相邻、邻接面片的朝向如何、共享边构成什么二面角。图卷积编码器的作用就是把这种局部邻域信息聚合进一个定长特征向量。具体机制是：把网格的面片邻接关系视为一张图，节点是面片，边是共享边；每个节点初始特征由其顶点坐标、法向、面积等几何量构成；然后通过若干层图卷积做邻域聚合，每一层把邻居节点的特征按某种权重求和并与自身特征融合。聚合后的节点特征经过池化或读出，得到该面片的局部描述子。

这里的选择很关键：用图卷积而不是简单的多层感知机（MLP）只吃面片自身坐标，是因为 MLP 看不到邻域，无法区分“一个孤立的三角形”和“一个嵌在光滑曲面里的三角形”，而后者才是艺术家网格的典型局部形态。消融实验里图卷积与 MLP 的对比正是针对这一点：去掉邻域聚合后，词表学到的面片会丢失与周围面片的衔接信息，重建时在面片边界处出现裂缝或法向突变。换句话说，图卷积承担的是“让词表里的每个词都带有上下文兼容性”的职责。

系统代价在于图卷积的邻域规模随网格密度增长。一个高面数网格的面片图节点数可达数万，逐层聚合的显存与计算量随边数线性上升，且邻接结构是不规则的，难以像图像卷积那样批量化成规整的张量运算。工程实现上通常要对邻域采样或限制聚合阶数，这就引入了近似误差：邻域被截断后，面片特征对远处邻接的感知变弱，词表的表达力随之下降。一个具体例子是椅子腿与座面交接处的面片，其局部形态高度依赖两侧邻接面的夹角，若聚合阶数不足，这类过渡面片容易被量化成通用词，重建后交接处变得生硬。

三 · VQ 量化与码本：词表的形成与容量权衡

图卷积输出的是连续特征向量，向量量化把它映射到码本中最近的嵌入。机制是标准的最近邻查找：对每个面片特征，计算它与码本中所有嵌入的距离，取最近者作为该面片的 token，并用该嵌入替换原特征送入解码器。训练时码本通过直通估计器（straight-through estimator）更新——前向用量化后的嵌入，反向把梯度直接传回编码器，同时对码本嵌入做移动平均或梯度更新。这样编码器和码本在同一目标下联合优化：编码器学会把面片特征聚拢到码本条目附近，码本学会覆盖面片特征的分布。

码本大小是一个直接的容量权衡。码本太小，不同局部形态的面片被迫共享同一个词，量化误差大，重建网格在细节处失真；码本太大，词表中大量条目在训练数据中很少被激活，形成“死码”，Transformer 在第二阶段面对一个稀疏使用的词表，长尾 token 的预测概率难以学好。消融实验对 VQ 词表大小的扫描正是为了找这个平衡点。工程判断上，码本大小应与训练数据的局部形态多样性匹配，而不是越大越好：ShapeNet 的椅子、桌子、飞机等类别，其局部面片形态的丰富度是有限的，超出这个丰富度的码本容量只会带来稀疏激活。

失败模式是码本坍塌：编码器把所有面片都映射到少数几个词上，量化误差被摊平，重建变得粗糙但训练损失看起来收敛。检测手段是统计码本条目的使用率分布，若大量条目长期零激活，说明容量未被利用。另一个代价是量化是不可微的离散操作，梯度只能近似传递，编码器与解码器的联合优化不如端到端连续模型稳定，通常需要辅助损失（如 commitment loss）把编码器输出拉向码本嵌入，否则编码器会漂移。

四 · 面片序列化：从集合结构到线性顺序

有了词表，还要把网格的面片排成一个序列。这一步是 MeshGPT 区别于纯几何压缩的关键：序列化顺序决定了 Transformer 学到的条件分布。机制上，面片按某种遍历规则排序，常见做法是沿网格表面做类似广度优先或基于邻接的遍历，使得相邻面片在序列中也相邻。这样做的目的是让自回归的条件上下文（前面的 token）在几何上也靠近当前面片，降低预测难度。序列中每个位置对应一个面片 token，序列末尾加终止 token。

序列化带来一个硬约束：序列长度。一个网格的面片数直接决定 token 数，而 Transformer 的上下文窗口有限。面数多的复杂网格会超出长度上限，要么被截断（丢失部分面片，生成不完整），要么无法进入训练集。这就是论文明确指出的“序列长度限制复杂网格”的根源。它不是模型容量问题，而是表示方式的问题：把集合拉成线，线的长度就等于集合的大小。一个具体例子是细节丰富的飞机模型，机翼与机身的过渡区域面片密集，序列化后这一段占据大量 token，挤占了本已有限的上下文预算。

另一个系统代价是顺序的确定性。同一网格若用不同遍历起点或不同邻接优先规则排序，会得到不同序列，模型会看到同一几何的多个“说法”，增加学习负担。因此实现上必须固定排序算法，并保证其对网格的顶点索引不敏感（否则重编号顶点会改变序列）。这要求排序规则基于几何量而非索引，增加了预处理复杂度。失败模式是序列在面片密集区出现“跳跃”：遍历从一个局部区域跳到另一个不相邻区域，条件上下文与当前面片几何上无关，Transformer 被迫在缺乏有效上下文的情况下预测，生成结果在这些位置容易出现拓扑错误，比如面片悬空或非流形连接。

五 · Decoder-only Transformer：自回归预测与逐步采样

第二阶段是标准的 decoder-only 架构：因果自注意力掩码保证每个位置只能看到之前的 token，位置编码提供序列顺序信息，输出层在码本大小上做 softmax 分类，训练目标是每个位置对下一个 token 的交叉熵。数据流很直接：输入 token 序列，经嵌入层查表得到码本嵌入，过若干层 Transformer，输出每个位置的下一 token 分布。训练时用教师强制（teacher forcing），把真实的前缀喂入，并行计算所有位置的损失。

推理时的机制是逐步采样：从起始 token 开始，每一步取当前前缀，前向一次得到下一 token 的分布，按温度或核采样选出一个 token，追加到前缀，直到终止 token。每步只新增一个 token，但每步都要做一次完整前向，计算量与序列长度成二次关系（自注意力的代价）。这就是推理慢的结构性原因：生成长度为 N 的序列需要 N 次前向，且第 N 次前向要处理长度为 N 的前缀。工程上可以用 KV 缓存把已计算的前缀键值对存下来，避免重复计算，把每步代价降到与当前长度线性相关，但总代价仍随序列长度增长。

关键模块的分工在这里收束：Transformer 只输出 token，不输出坐标；token 到顶点与面片的还原由解码器（VQ-VAE 的解码端）完成。这意味着生成过程中模型并不直接“画”几何，而是在词表上做离散选择，几何精度由词表决定。失败模式是误差累积：早期采样错一个 token，后续所有条件都建立在错误前缀上，生成结果可能整体偏离。另一个代价是采样策略敏感，温度过高会选出词表中不常见的面片，拼出非流形结构；温度过低则重复常见面片，生成单调。消融实验对序列长度的扫描反映了这一点：序列越长，条件上下文越丰富，但误差累积的机会也越多。

六 · 训练编排与模块间的耦合代价

两阶段的训练编排是串行的：先训 VQ-VAE 到重建收敛，冻结编码器与码本，再用序列化后的 token 训 Transformer。串行编排的合理性在于第二阶段的目标依赖第一阶段的词表，词表不稳定则序列语义不稳定。但串行也带来耦合代价：第一阶段的任何缺陷都会被第二阶段继承且无法修正。若词表在某个局部形态上表达不足，Transformer 只能在这些位置反复选择次优 token，训练损失下降但生成质量受限。工程上判断流水线是否健康，要看第一阶段的重建误差分布，而不是只看第二阶段的困惑度。

训练规模方面，论文在 ShapeNet 上训练，单卡数天，数据规模小是明确局限。数据规模小与两阶段编排叠加，导致词表的覆盖和 Transformer 的泛化都受限：类别内的形态变化没有被充分覆盖，生成多样性有限。这不是靠加大模型能解决的，而是数据与表示共同约束的结果。一个具体例子是桌子类别，桌面形态相对单一，词表容易学好，但桌腿与横撑的连接方式多样，小数据下这些连接处的面片词覆盖不足，生成时倾向于退回到最常见的连接形态。

模块分工的工程判断可以归纳为：图卷积决定词表的几何保真度，VQ 码本大小决定词表的表达容量，序列化规则决定 Transformer 的学习难度，Transformer 容量决定序列上的模式拟合能力，解码器决定最终还原精度。任何一环的不足都会在最终网格上以特定形态暴露——图卷积不足表现为过渡面片生硬，码本过小表现为细节丢失，序列化不当表现为局部拓扑错误，Transformer 不足表现为长序列后段失控。诊断生成失败时，按这个分工逐环排查，比笼统地归因于“模型不够大”更有操作性。

值得强调的是，这套架构把“生成网格”转化成了“在离散词表上做序列决策”，从而让自回归语言模型的整套工程实践（掩码、采样、KV 缓存、温度控制）可以直接迁移。迁移的代价是几何精度被词表钉死，序列长度被面数钉死。这两个钉子正是后续工作改进的入口：更精细的词表、更紧凑的序列化、分层或分块的生成顺序。理解这条流水线每一步的分工与代价，就理解了“网格即语言”这条路线的能力边界在哪里。
