一 · 最小可跑版本的目录骨架

复现 MVDream 时，先把「能跑起来的最小闭环」和「论文级训练」分开。最小闭环只需要验证一件事：给定文本与四个相机位姿，U-Net 的一次去噪能否在跨视角注意力下产出四张互相约束的图像。目录结构应按数据流切分，而不是按论文的章节切分，否则调试时会在模块之间来回跳。

  • configs/：存放视图数、位姿采样范围、注意力偏置开关、2D 数据混合比例的配置文件。视图数必须显式写成常量，因为它是硬约束。
  • data/objaverse_mv/：多视图渲染清单，每条记录含物体 id、四个相机的旋转与平移、渲染图路径。
  • data/laion2d/：纯 2D 图像清单，只含图像路径与文本描述，不含位姿。
  • models/：文本编码器封装、位姿嵌入层、跨视角注意力注入点、U-Net 主体。
  • train/：联合训练的采样器，负责在一个 batch 内混合多视图样本与 2D 样本。
  • infer/：四视图采样脚本，以及把四视图送入 SDS 或重建模块的接口。
  • asserts/：验收断言脚本，独立于训练代码运行。

关键设计判断是：位姿嵌入不能写死在 U-Net 内部，必须作为可替换模块注入，因为图生 3D 分支要接 Zero-1-to-3 的相机约定，而文生 3D 分支的位姿分布不同。把位姿处理抽出来后，同一套 U-Net 权重可以在两种输入模式下复用，避免为了换相机约定而重训。

最小可跑版本的规模应压到单卡可承受：四个视图、每视图较低分辨率、U-Net 通道数缩减。目的不是复现指标，而是让跨视角注意力的形状错误、位姿嵌入维度不匹配、2D 与多视图 batch 混合时的掩码错误尽早暴露。这些错误在完整规模下往往表现为 loss 不降或图像全灰，定位成本极高。

二 · 数据准备：多视图清单与 2D 混合

Objaverse 多视图数据的核心是相机位姿的规范化。四个视角必须来自同一套相机坐标系，仰角与方位角的采样范围要在配置里固定，否则同一物体在不同样本里的位姿分布漂移，模型学到的是位姿噪声而不是几何约束。渲染清单里每条记录应存绝对位姿而非相对位姿，避免在训练时做链式变换引入误差。

2D 数据的作用是保住预训练扩散模型的图像先验。联合训练时，2D 样本没有四个视图，也没有位姿。工程上最稳的做法是给 2D 样本复制成四份相同图像、位姿置零或使用固定占位位姿，并在注意力偏置里把跨视角项屏蔽掉，使 2D 样本退化为标准的单图去噪。另一种做法是让 2D 样本单独走一条不经过跨视角注意力的分支，但这会让 U-Net 出现两条前向路径，显存与代码复杂度都上升。

混合比例是超参，但它的作用机制不是「越多越好」。2D 比例过高，跨视角注意力得不到足够梯度，四视图一致性退化；2D 比例过低，模型遗忘 2D 先验，生成图像出现纹理崩坏。配置里应把比例写成可扫描的离散档位，并在验收断言里检查两个方向的退化。

数据源每条样本字段训练时的角色常见错误
Objaverse 多视图物体 id、四相机位姿、四张渲染图、文本提供跨视角一致性梯度位姿坐标系不统一，四视图顺序错乱
LAION 2D图像、文本保持 2D 图像先验误把 2D 样本当四视图送入跨视角注意力

一个具体失败模式：四视图的顺序在渲染清单里按方位角递增排列，但训练时的数据加载器做了随机打乱，导致同一物体的四个视图与位姿嵌入的对应关系被破坏。模型仍能收敛到较低的 loss，因为它在学「无序的四张图」，但推理时按固定顺序给位姿，输出的一致性明显下降。验收断言必须显式检查视图顺序与位姿顺序的一一对应。

三 · 跨视角注意力的实现与偏置

论文的注意力形式是在标准缩放点积注意力上加一个视图偏置项：

$$\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}+b_{\mathrm{view}}\right)V$$

实现时，四个视图的 patch token 拼成一个序列送入自注意力，序列长度为四倍单视图长度。跨视角信息共享发生在同一层自注意力内，而不是额外的跨视图模块。这意味着注意力矩阵是块结构的：对角块是视图内注意力，非对角块是视图间注意力。显存开销随视图数平方增长，四视图时注意力矩阵是单视图的十六倍元素数，这是复现时最先撞到的显存墙。

偏置项 b_view 的工程含义是控制视图间注意力的强度与对称性。若四个视图地位对等，偏置可设计为仅区分「同视图」与「异视图」两类，用一个可学习的标量或向量加到对应位置。若希望某个视图作为参考视图，偏置可做成非对称。最小版本建议先用对称的二值偏置，把复杂度留给后续消融。

伪代码思路：把四组 patch 嵌入按视图维度拼接，得到形状为「四倍长度 × 通道」的序列；构造同形状的偏置矩阵，对角块填同视图偏置，非对角块填异视图偏置；送入 U-Net 的每个自注意力层。文本条件通过 cross-attention 注入，与视图维度正交，不需要改动。

系统代价有两处。第一是显存：四视图拼接后，单层注意力的激活值显著变大，梯度检查点必须开在自注意力层上，否则中等分辨率下就会溢出。第二是吞吐：序列变长后注意力的计算量上升，训练数天的量级在单卡上不可行，必须多卡并行，而多卡切分时视图维度不能被随意切开，否则跨视角注意力被切断，一致性梯度消失。一个具体例子：把四个视图分到两张卡、每卡两个视图，若注意力只在卡内计算，模型永远学不到跨卡视图的约束，表现为两两一致但四视图整体不一致。

四 · 超参配方与联合训练的调度

超参分三组：扩散过程组、视图组、混合组。扩散过程组沿用预训练 2D 模型的噪声调度与预测目标，不要重新设计，否则 2D 先验无法迁移。视图组包含视图数、位姿采样范围、位姿嵌入维度、跨视角偏置初始化。混合组包含 2D 与多视图的采样比例、以及 2D 样本的位姿占位策略。

  • 视图数固定为四，配置里写成不可变常量，任何试图在推理时改视图数的路径都应直接报错。
  • 位姿嵌入维度与文本嵌入维度解耦，前者只影响相机条件，后者影响语义条件。
  • 跨视角偏置初始化为零或很小的值，让模型先学视图内去噪，再逐步学长程约束。
  • 2D 比例按训练阶段退火：前期偏高保住先验，后期偏低强化一致性。

联合训练的调度难点在于两类样本的 loss 量级不同。多视图样本的 loss 是四张图去噪误差的汇总，2D 样本是单图误差。若直接按 batch 混合而不做归一化，多视图样本的梯度会压过 2D 样本，先验保持失效。工程做法是对每个样本的 loss 按视图数做平均，使两类样本的单图误差量级可比。

一个具体失败模式：学习率沿用 2D 预训练的值，但联合训练时跨视角注意力是新增参数，新参数在较大学习率下发散，表现为 loss 前期正常、中途突增，四视图输出出现重复纹理。验收断言应监控新增参数层的梯度范数，若持续高于主体层一个量级，说明初始化或学习率分组有问题。

训练数天的量级意味着超参扫描不能全网格搜索。可行策略是先在小规模数据上固定扩散过程组，只扫描视图组与混合组，用四视图一致性的定性检查代替完整指标，收敛后再放大数据规模。

五 · 验收断言：从形状到一致性

验收断言要分层，从形状正确到语义正确逐级加严。最低层是形状断言，在每次前向时检查注意力矩阵的块结构、位姿嵌入与视图的对应、2D 样本的跨视角屏蔽是否生效。中间层是数值断言，检查 loss 分项的量级、新增参数梯度范数、以及 2D 样本与多视图样本的 loss 比值是否在预期区间。最高层是一致性断言，用固定文本与固定位姿采样四视图，检查视图间的几何对应。

层级断言内容失败时的典型症状
形状注意力序列长度为四倍单视图；位姿嵌入维度匹配前向直接报维度错误，或静默广播出错
数值新增层梯度范数与主体层同量级；两类样本 loss 比值稳定loss 中途突增或先验退化
一致性四视图在重叠区域几何对应；视图顺序与位姿顺序一致两两一致但整体不一致，或背面纹理重复

一致性断言不能只看图像是否「好看」。可操作的检查是：取四视图中相邻两个视图，用简单的特征匹配估计相对位姿，若估计结果与给定相机位姿的偏差超出阈值，说明跨视角约束没有生效。这个检查不需要 3D 重建，成本低，适合放进持续集成。

另一个断言针对视图数固定的边界。推理脚本若收到非四视图的请求，必须显式拒绝而不是静默补零。静默补零会让模型在缺失视图上产生幻想，且错误难以追溯。视图数固定是架构级约束，验收断言应把它当作硬性契约。

背面幻想是已知局限，验收断言不应试图消除它，而应标记它。对固定文本生成四视图后，检查背面视图与正面视图在纹理统计上是否出现不合理的重复，若重复率过高，说明模型在用正面信息填充背面，这是数据偏差与视图数固定的共同结果，属于预期行为而非 bug。

六 · 常见崩溃点与工程判断

崩溃点一：位姿嵌入与图像 patch 的相加顺序。若位姿嵌入在 patch 化之前加到像素上，会破坏渲染图的色彩统计；正确做法是 patch 化并线性投影后，再把位姿嵌入加到 token 上。顺序错误的表现是训练早期 loss 下降极慢，且生成图像整体偏色。

崩溃点二：跨视角注意力的掩码与 2D 样本冲突。2D 样本复制成四份后，若忘记屏蔽跨视角项，模型会把同一图像的四个副本当作四个不同视角，学到「所有视角都相同」的退化解。这个退化解在纯 2D 数据上 loss 很低，但在多视图数据上一致性断言必然失败。

崩溃点三：多卡切分切断视图维度。前面已述，症状是局部一致而全局不一致。工程判断是：视图维度必须整体留在同一设备，或使用能跨设备计算注意力的并行方案，不能按视图做数据并行。

崩溃点四：SDS 接口的相机约定不一致。四视图生成后送入 SDS 或重建时，SDS 的相机位姿定义若与生成阶段的位姿定义不同，几何一致性会在下游被破坏。验收断言应在接口处做一次位姿往返变换检查，确保同一相机在两个模块中指向同一方向。

工程判断的落点是：MVDream 的复现价值不在复刻指标，而在建立「多视图一致性」这条可断言的工程契约。视图数固定、背面幻想、数据偏差是架构与数据决定的边界，复现时应把它们写成显式的失败模式清单，而不是试图用调参掩盖。最小可跑版本的作用是让这些边界在低成本下暴露，完整规模训练只是把同一套断言放大到更多数据上。跨视角注意力的块结构与视图维度的不可切分性，是这套契约里最硬的两个约束，任何绕过它们的捷径都会在一致性断言上留下痕迹。
