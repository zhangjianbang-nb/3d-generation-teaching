一 · 对比的坐标系：先把"表示"钉死再谈速度

把 SF3D 与 TripoSR、InstantMesh、CRM 放在同一张表里比较，最容易犯的错误是先比推理时间、后比输出格式。三者的输出根本不在同一个语义层级上：TripoSR 走的是三平面（triplane）神经辐射场路线，输出需要再经过 marching cubes 与纹理烘焙才能变成可进引擎的资产；InstantMesh 用多视图扩散加稀疏视图重建，几何来自隐式场采样；CRM 走的是卷积重建网格的路线，直接吐网格但纹理通常落在顶点色或简单投影上。SF3D 的差异不在"它也吐网格"，而在它把 UV 参数化与 PBR 材质当作一等输出，与几何在同一次前向里联合产生。因此逐项对比必须分成四个正交轴：表示（几何载体 + 纹理载体 + 材质通道）、监督（损失里到底约束了什么）、速度与显存（在什么分辨率、什么 batch 下测）、失败模式（哪一类输入会崩、崩成什么样）。任何把四轴压成一个"谁更好"的排序，都会在工程落地时反噬。

具体机制上，SF3D 的前向是"编码—SDF/网格解码—快速 UV 展开—UV 空间纹理与材质预测—delighting"的串行链，链条中任何一环的中间产物都是显式的：网格顶点、UV 岛、UV 空间纹理图、粗糙度/金属度图、法线贴图。这带来一个关键的对比维度——可检查性。Triplane 类方法的中间表示是一组特征平面，你无法在管线里直接断言"这个 UV 岛没有翻转"；SF3D 可以，因为 UV 岛是真实写出来的数据结构。代价是这条链把误差逐级放大：UV 展开失败会直接污染纹理监督信号，而 triplane 方法里纹理与几何是耦合在同一个隐式场里、不会出现"UV 撕裂"这种离散失败。

用一个具体例子锚定：给一张正面拍摄的马克杯产品图，背景干净、杯身有高光。TripoSR 类管线会给出一个整体形状合理但纹理偏糊、且高光被烘进反照率的资产；SF3D 会给出带 UV 的网格、分离的粗糙度图与被 delighting 压掉低频光照的反照率图，但杯柄与杯身连接处的 UV 岛可能因展开算法在该处拓扑复杂而撕裂。这不是"谁更准"的问题，而是"谁的失败更可修"的问题——前者要在隐式场里重训，后者可以在 DCC 里手工缝合 UV 岛。工程判断的分水岭就在这里。

二 · 监督信号逐项拆：几何、UV、材质三路损失各管什么

SF3D 的联合目标是

$$\mathcal{L}=\mathcal{L}_{\mathrm{geo}}+\lambda\mathcal{L}_{\mathrm{uv}}+\mu\mathcal{L}_{\mathrm{mat}},\qquad \mathcal{L}_{\mathrm{uv}}=\|\hat{T}(u,v)-T(u,v)\|^2$$

三项的分工必须对照基线看清楚。$\mathcal{L}_{\mathrm{geo}}$ 约束的是显式网格/SDF 解码器输出的表面，与 TripoSR 的体渲染损失、InstantMesh 的多视图重投影损失在目标上同源，但梯度落点不同：后者落在隐式密度场，前者落在顶点位移与面片。$\mathcal{L}_{\mathrm{uv}}$ 是 SF3D 独有的——它在 UV 参数域上逐像素比对预测纹理与真值纹理，这要求训练时真值资产本身带合法 UV，因此数据侧必须筛掉 UV 缺失或退化的 Objaverse 资产，这是一条隐性的数据成本，基线方法没有。$\mathcal{L}_{\mathrm{mat}}$ 约束粗糙度、金属度与法线预测，其监督来自渲染分解后的材质通道，配合 delighting 数据增强把低频光照从反照率里剥离。

伪代码层面，一个训练 step 的顺序是：采样单图与对应资产 → 前向得网格、UV、纹理、材质 → 用可微渲染或直接 UV 域比对算三路损失 → 反传。关键工程点是 $\mathcal{L}_{\mathrm{uv}}$ 的可微性依赖 UV 展开算子的近似可微或停止梯度处理：若 UV 展开是纯几何算法（非学习），则 $\mathcal{L}_{\mathrm{uv}}$ 的梯度只流向纹理预测头，不流向几何分支，这意味着"UV 展开质量"与"几何质量"在优化上是解耦的，几何错了 UV 不会自动修正。这正是 SF3D 失败模式的结构性根源，也是与端到端隐式方法最本质的监督差异。

系统代价：三路损失意味着三套真值管线。Objaverse 资产要过 UV 合法性检查、材质通道提取、delighting 预处理，任何一环的标注噪声都会以 $\lambda$、$\mu$ 加权后污染训练。相比之下 CRM 一类方法只需几何真值，数据吞吐高得多。失败模式举例：若某批资产的金属度通道被错误标为全零，$\mathcal{L}_{\mathrm{mat}}$ 会把模型推向"所有物体都是电介质"，表现为金属产品图重建后失去镜面反射，而几何与 UV 看起来完全正常——这种"单通道塌陷"在只看几何指标的评估里不可见。

三 · 速度与显存：0.5 秒在什么条件下成立

SF3D 的 0.5 秒是端到端单图推理时延，包含编码、网格解码、UV 展开、纹理与材质预测、delighting。对照时必须问三个问题：分辨率多少、是否含 UV 展开、是否含纹理烘焙。TripoSR 的快速推理通常只覆盖到隐式场前向，marching cubes 与纹理提取是额外开销；InstantMesh 的多视图扩散采样本身是迭代过程，步数与视图数是时延主项；CRM 的卷积网格重建在网格分辨率提升时显存与时延同步上涨。SF3D 的时延结构不同：UV 展开是几何算法，其耗时随网格面数增长而非随神经采样步数增长，因此它在"面数适中"的区间里时延曲线更平。

显存侧的关键变量是 UV 空间纹理图的分辨率与网格面数。UV 纹理生成在 UV 域上做逐像素预测，显存占用与纹理图面积成正比；这与 triplane 方法的显存模型（特征平面分辨率 × 通道数）不同，后者的显存更多压在隐式场的采样网格上。工程含义：SF3D 在批量生成时，显存瓶颈出现在纹理图分辨率，降分辨率可直接降显存但会牺牲材质细节；triplane 方法降采样网格则同时损失几何与纹理。这决定了两类方法在"高并发、低单资产质量"场景下的扩容策略不同。

具体例子：一条需要每小时产出数百个带 UV 资产的管线，若用 SF3D，扩容靠增加纹理图分辨率以外的并行实例，单实例显存可控；若用隐式方法，扩容要先解决 marching cubes 的峰值显存，否则并发数上不去。失败模式：SF3D 在面数很高的输入（如带大量细碎结构的资产）上，UV 展开的岛数量爆炸，纹理图被切得过碎，单岛像素过少导致纹理预测欠采样，表现为细节区糊成一片——这不是时延问题，是"UV 预算"问题，而基线方法没有这个失败通道。

四 · 失败模式对照：三类崩法与可修性

把失败模式按"崩在哪一层"分类，比按方法分类更有工程价值。第一类是几何崩：细长结构、薄壁、内部结构在隐式场里被平滑掉，TripoSR 与 InstantMesh 都有此问题，SF3D 的显式网格解码同样受限，表现为薄片变厚、孔洞被封。第二类是纹理崩：顶点色方法在低面数下纹理糊，SF3D 的 UV 空间纹理在 UV 岛撕裂处出现接缝错位，两者机理不同但都表现为"看起来不对"。第三类是材质/光照崩：光照耦合方法换环境光就整体偏色，SF3D 靠 delighting 缓解，但 delighting 本身是低频假设，遇到强方向光或彩色环境光时剥离不干净，残留会烘进反照率。

可修性是这三类失败的分水岭。几何崩在隐式方法里几乎不可局部修，只能重采样或重训；SF3D 的显式网格可以在 DCC 里补洞、加厚，修完不需要重跑网络。纹理崩在顶点色方法里靠提高面数缓解，成本是面数膨胀；SF3D 的 UV 接缝可以在 UV 编辑器里手工缝合，修的是参数化而非网络。材质崩在两类方法里都要回到数据侧——这是 delighting 成为管线必备步骤的原因：把光照剥离做成独立后处理，失败时可以单独重跑而不动几何与 UV。

具体机制举例：delighting 去除低频光照的假设是"环境光在空间上缓变"，因此它对单图里的大面积软阴影有效，对硬阴影边缘与镜面高光无效。一张在窗边拍摄的产品图，窗框投下的硬阴影会被 delighting 部分保留，重建后的反照率带上一道暗带，换光照后暗带仍在——这是 SF3D 相对顶点色方法的"重光照优势"在特定输入上的反例。工程判断：delighting 不是万能开关，它的有效性边界由输入光照的频率结构决定，管线里应对硬阴影输入做前置检测或人工复核。

读表方式：先看"纹理载体"与"材质通道"两行，若管线下游是游戏引擎或渲染器且需要换光照，SF3D 是唯一在表内直接给出 UV + PBR 的选项，其余三者都要额外的烘焙或重投影步骤，这些步骤的时延与失败率不在方法本身的 0.5 秒里。再看"可修性"行，若团队没有 DCC 手修 UV 的人力，SF3D 的 UV 撕裂会变成阻塞项，此时应退回 triplane 类方法接受纹理糊。最后看"时延结构"行，高并发场景下要按瓶颈变量做容量规划，而不是按单次时延做线性外推。

一个具体选型例子：某电商管线要批量生成商品资产供实时渲染，输入是白底产品图，下游引擎要求标准 UV 与可切换环境光。按表走，SF3D 命中"需进引擎 + 需重光照"，但"可修性"行提示需要 UV 复核人力；若商品品类集中在硬表面、拓扑简单，UV 撕裂率低，复核成本可摊薄；若品类含大量软体与细碎结构，则应把 SF3D 与 triplane 类方法并行跑，用前者出可重光照资产、后者出预览，按品类分流。这就是决策表的用法——它不是排名，是分流规则。

六 · 与后继标准的接口：对比不止于同期三方法

SF3D 与 Hunyuan3D 2.1 一起定义了 2024–2025 年资产生成标准，这句话的工程含义是对比维度要从"同期三方法"扩展到"后继标准的接口"。后继方法若同样输出 UV + PBR，则对比重点从"有没有 UV"转向"UV 展开的质量与稳定性"以及"材质预测的真实感受数据限制"。SF3D 的局限里明确写了材质真实感受数据限制、几何细节有限，这两条在与后继方法对比时是主要落差项：后继方法若在更大规模、更高质量材质数据上训练，其粗糙度/金属度预测会更贴真值，而 SF3D 的材质头受训练数据分布约束，在训练分布外的材质（如各向异性金属、次表面散射材质）上会退化。

接口层面还有一个容易被忽略的对比点：delighting 作为管线必备步骤的地位。SF3D 把 delighting 做进前向链，意味着它的输出已经过光照剥离；若后继方法把 delighting 留给后处理，则两者在"换光照后是否崩"的对比上要先对齐 delighting 的实现再比，否则是把后处理的功劳记在前向头上。工程判断：对比任何两个声称"光照解耦"的方法，先确认 delighting 在谁的管线里、用什么低频假设、对硬阴影的处理策略，再谈重光照表现，否则对比结论不可迁移。

最后落在具体机制上：SF3D 的对比价值不在于它在某一轴上赢过谁，而在于它把"UV 参数化 + PBR 材质 + delighting"这三个原本分散在后处理管线里的步骤收进一次前向，使得对比的粒度从"资产级"细化到"通道级"——你可以单独比较两个方法的粗糙度图、单独比较 UV 岛数量与撕裂率、单独比较 delighting 前后的反照率差异。这种通道级可比性是它作为生产级基线的方法论贡献，也是后续任何方法要与之对比时必须先对齐的坐标系。
