一 · 复现边界：先钉死"两阶段"的物理含义

从零复现 Fantasia3D 最容易犯的错，是把"两阶段"当成"两次训练跑完就完事"。论文里的两阶段是有严格数据依赖的：阶段一的产物是一个可微网格（DMTet 提取出的顶点、面、SDF 值），阶段二把这份网格冻结，只优化挂在网格上的材质参数。复现时如果阶段二还允许几何梯度回传，就退化成 DreamFusion 式的耦合优化，纹理重新长进几何，验收必然失败。因此工程上第一件事是定义清楚阶段间的契约：阶段一输出 mesh.obj 加一份 SDF/顶点位移缓存；阶段二读入网格后把几何张量的 requires_grad 全部关掉，只留材质 MLP 与 PBR 渲染器的可训练参数。这个契约决定了目录结构。

第二个边界是扩散模型冻结。论文明确冻结扩散模型，只把它当"打分器"。复现时不要试图微调扩散模型，也不要为了"更好看"换一个更强的 2D 先验去改 SDS 的尺度——SDS 的梯度量级与噪声调度强绑定，换模型等于换了一套隐式损失权重，超参全部作废。第三是 DMTet 分辨率：几何精度被网格分辨率硬性限制，这不是调参能突破的，验收断言里必须把"分辨率上限"写成已知约束而不是 bug。

把这三条写进 README 的第一屏，比写任何训练脚本都重要。下面给出的目录结构就是围绕这份契约组织的。

二 · 目录结构与最小可跑版本

最小可跑版本的目标不是复现论文质量，而是让"几何阶段产出网格 → 外观阶段产出可重光照材质"这条链路端到端跑通，且每一步都有可检查的中间产物。推荐结构如下（用文字描述层级，避免代码块）：根目录下分 configs/、data/、stage1_geo/、stage2_app/、render/、checks/、runs/ 七个顶层目录。configs/ 放两份 YAML：geo.yaml 与 app.yaml，两份配置共享一个 prompt 字段和 seed，保证两阶段面对同一个文本与同一组随机采样。data/ 只放提示词清单与（可选的）参考图，论文没有 3D 训练集，所以这里不存在"数据集下载"步骤，任何声称需要 3D 数据的复现方案都是错的。

stage1_geo/ 内含 dmtet.py（网格表示与可微提取）、sds_normal.py（法线条件 SDS 损失）、train_geo.py（优化循环）。stage2_app/ 内含 material_mlp.py（输出反照率 a、粗糙度 r、金属度 m）、pbr.py（可微 PBR 着色）、sds_rgb.py、train_app.py。render/ 放相机采样、光照采样与法线/深度缓冲的渲染工具，两阶段共用同一套相机分布，否则 SDS 的视角先验不一致，几何与外观会对不上。checks/ 放验收脚本，这是本部分的核心交付物。runs/ 按 {prompt_slug}/{timestamp}/ 落盘，每个 run 下强制有 stage1/mesh.obj、stage1/normal_preview/、stage2/material.pt、stage2/relight/ 四类产物。

最小可跑版本的收敛判据不是"好看"，而是三条可自动化的断言：阶段一结束后网格是流形的（无自交、无非流形边）；阶段二结束后在固定相机与固定环境光下渲染出的图与训练末帧的 RGB SDS 输入分布同量级；换一组光照参数重渲染，反照率图不变而亮度图变化。这三条对应论文声称的"几何干净、材质可重光照"，是把定性主张转成工程检查的关键。

三 · 数据准备：提示词、相机与光照三件套

论文没有 3D 训练集，所以"数据准备"实际准备的是采样分布：文本提示词、相机位姿分布、光照分布。三者共同定义了 SDS 的期望，任何一项偏移都会让两阶段失配。提示词侧要准备一份纯文本清单，每条包含主体描述与风格词，且阶段一与阶段二必须用同一条提示词——若阶段二换词，法线条件 SDS 建立的几何语义与 RGB SDS 的纹理语义会打架，典型症状是纹理贴在错误的面上。

相机分布是复现中最容易被忽视的一项。两阶段必须共享同一套方位角/仰角/半径采样器，且采样器要覆盖足够多的仰角，否则 DMTet 的侧面与底面得不到梯度，提取出的网格在这些区域是"平的"。工程上把相机采样写成确定性函数 cam(seed, step)，两阶段用同一个 seed 序列，这样阶段二的每个视角都能对应到阶段一优化过的法线，避免"外观阶段在没被几何阶段看过的视角上瞎猜纹理"。

光照分布在阶段一不参与（法线 SDS 与光照无关），在阶段二才引入。这里有一个具体机制：PBR 渲染把材质参数与光照卷积，若光照分布过窄（例如只用单一方向光），材质 MLP 会把光照信息吸收进反照率，重光照时反照率图会随光照变化——这正是验收断言要抓的失败模式。因此光照采样要覆盖多方向、多强度，并在损失里加材质正则（论文提到材质正则项），约束反照率不要吸收高频光照。

下表把三件套的准备要求与对应失败模式对齐，可作为 checks/ 的输入规范。

准备项具体要求缺失时的失败模式
提示词两阶段同一条，含主体与风格纹理贴错面，几何与外观语义错位
相机分布两阶段共享确定性采样器，覆盖多仰角网格侧面/底面平坦，法线无梯度
光照分布多方向多强度，配材质正则反照率吸收光照，重光照失效

四 · 超参与两阶段配方

论文给出的训练事实是"两阶段 SDS、冻结扩散模型、每资产数小时"，没有给具体学习率与步数，所以复现时的超参必须由量级约束推导，而不是照抄。核心约束来自 SDS 损失的梯度尺度：SDS 梯度正比于噪声预测误差乘以噪声方差，随扩散时间步变化。几何阶段用法线条件扩散，其输入是渲染法线 n̂，损失写作 L_geo = L_SDS(n̂, y)；外观阶段用 PBR 渲染结果，损失写作 L_app = L_SDS(PBR(a, r, m, n̂), y)。两式的 SDS 形式相同，但输入模态不同，扩散模型不同，梯度量级也不同，因此两阶段的学习率不能共用。

$$\mathcal{L}_{\mathrm{geo}}=\mathcal{L}_{\mathrm{SDS}}(\hat{n},y),\qquad \mathcal{L}_{\mathrm{app}}=\mathcal{L}_{\mathrm{SDS}}(\mathrm{PBR}(\mathbf{a},r,m,\hat{n}),y)$$

几何阶段的优化变量是 DMTet 的顶点位移与 SDF 值，梯度通过可微提取回传。工程配方：先用较低分辨率跑若干步让拓扑稳定，再升分辨率细化；学习率按"每步顶点位移不超过网格边长的一个小比例"来标定，否则网格会自交。外观阶段冻结几何后，优化变量是材质 MLP 参数，学习率按"反照率输出落在 [0,1] 且不饱和"标定，饱和会导致重光照时出现死黑或死白。

伪代码思路（文字版）：阶段一循环内，采样相机 → 渲染法线与深度 → 送法线条件扩散算 SDS → 反传更新 DMTet 参数 → 周期性提取网格并做流形检查；阶段二循环内，采样相机与光照 → 用冻结网格渲染法线与深度 → 材质 MLP 出 a/r/m → PBR 着色 → 送 RGB 扩散算 SDS → 加材质正则 → 反传只更新材质 MLP。两阶段都冻结扩散模型，不参与反传。

系统代价必须写进配置注释：每资产数小时的优化意味着单卡串行，不能指望批量生成；DMTet 的可微提取在高分辨率下显存占用随网格分辨率上升，阶段一的分辨率提升要在显存预算内做，否则会在提取步崩溃。一个具体例子：把阶段一分辨率直接拉到上限而不做渐进，常见崩溃是提取时出现退化四面体导致法线为 NaN，SDS 损失随即变成 NaN，整个 run 报废——这就是为什么 checks/ 要在每次提取后断言法线有限。

五 · 验收断言与常见崩溃点

验收断言要写成可执行脚本，每条断言对应一个论文主张或一个已知失败模式。下面五条覆盖最小可跑版本的验收面。

  • 断言 A（几何流形性）：阶段一提取的网格无自交、无非流形边，欧拉特征与预期拓扑一致。失败模式：DMTet 分辨率突变或学习率过大导致自交，表现为法线翻转、SDS 梯度震荡。
  • 断言 B（法线有限性）：每次提取后渲染的法线与深度缓冲全部为有限值。失败模式：退化四面体产生 NaN，NaN 通过 SDS 污染全部参数。
  • 断言 C（视角覆盖）：阶段二使用的相机序列与阶段一一致，且每个视角的法线在阶段一中被优化过。失败模式：外观阶段在未优化视角上生成纹理，重渲染时出现接缝。
  • 断言 D（重光照不变性）：固定相机，换两组光照参数渲染，反照率图逐像素差异低于阈值，亮度图差异显著。失败模式：反照率吸收光照，两组光照下反照率图都变——说明材质未解耦。
  • 断言 E（材质值域）：a、r、m 输出在合法区间内且不饱和。失败模式：学习率过大导致反照率饱和，重光照出现死黑死白。

常见崩溃点按发生阶段归类。阶段一的高频崩溃是 NaN 传播与网格自交，根因是分辨率与学习率不匹配；阶段二的高频崩溃是材质吸收光照与纹理接缝，根因是光照分布过窄与相机序列不一致。还有一类跨阶段崩溃：阶段一产出的网格法线朝向不一致（部分面朝内），阶段二的 PBR 渲染在这些面上得到负亮度，RGB SDS 的输入分布偏移，表现为纹理在局部区域"糊掉"。这类问题不会让脚本报错，只会让结果变差，所以断言 B 要检查法线朝向的一致性而不只是有限性。

一个具体例子说明断言 D 的价值：若材质 MLP 把方向光的方向编码进了反照率，换光照后反照率图会跟着变亮变暗，肉眼看起来"还挺合理"，但导出到引擎里重光照就露馅。断言 D 用逐像素差异把这种隐性耦合抓出来，比人眼验收可靠。

六 · 最小可跑与论文质量的差距定位

最小可跑版本跑通后，与论文质量的差距要能定位到具体机制，而不是笼统地说"效果不够好"。差距主要来自三处：DMTet 分辨率上限决定几何细节的天花板，这是论文自己也承认的局限；材质先验受 2D 扩散模型限制，反照率与粗糙度的真实感不会超过 2D 先验的认知；每资产数小时的优化预算决定了两阶段各自的步数，步数不足时几何未收敛、材质未解耦。复现时应把这三处写成配置里的显式预算项，而不是藏在代码里。

工程判断上，复现 Fantasia3D 的收益不在"复刻某个资产的像素"，而在拿到一条可验证的解耦流水线：阶段一的网格可以被下游引擎直接使用，阶段二的材质参数可以被重光照管线消费。这也是后续 Hunyuan3D 2.x 的形状-材质双 DiT、SF3D 的 PBR 分解延续的思路——解耦的接口比单次生成的质量更有复用价值。因此验收断言的优先级应高于画质调优：先把 A 到 E 五条断言全部通过，再谈提升分辨率与步数。若断言 D 不通过，提升画质只会让耦合更深、更难拆。

最后一个具体机制层面的判断：阶段二冻结几何后，材质 MLP 的输入应包含法线与视角方向，输出 a/r/m，PBR 着色把这些量与光照卷积。若把视角方向也喂给反照率分支，反照率会隐式编码视角相关效应，重光照时出现"视角依赖的反照率"，这是断言 D 之外的第二种耦合。工程上把反照率分支与视角相关分支在 MLP 内部拆开，是复现时值得做的一处结构约束。
