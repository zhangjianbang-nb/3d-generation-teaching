一 · 评测协议：数据集与两条对照轴

GS-LRM 的实验设计把“前馈重建”和“逐场景优化”放在同一张表里比较，这一点决定了它的证据结构。训练数据来自 Objaverse 的多视图渲染，评测则同时使用 Objaverse 的留出对象与 Google Scanned Objects（GSO）。前者是合成资产，视角分布可控、背景干净；后者是真实扫描物体，带有扫描噪声、非理想材质与更复杂的光照响应。把两者并列，等于把“在训练分布内拟合”和“跨域泛化”拆成两个独立的问题来回答，而不是用单一平均分掩盖差异。

基线选取对应三条技术路线。LRM 是同一问题设定下的前身：输入 2–4 张图，输出三平面，再通过体渲染或网格提取得到图像。InstantMesh 代表“前馈 + 显式网格”的路线，用前馈模型生成网格表示再渲染。3DGS 优化则是逐场景的测试时优化基线：给定同样的输入视图，直接优化高斯参数到收敛。这三条基线分别回答三个问题：三平面中间表示是否必要、网格表示是否够用、前馈一次前向能否逼近逐场景优化。评测指标围绕新视角合成质量与渲染速度展开，前者用渲染损失同族的感知与像素度量，后者看单帧渲染耗时与是否需要测试时优化。

这里有一个容易被忽略的协议细节：前馈模型的推理成本是“一次前向”，而 3DGS 优化基线的成本是“每场景数千次迭代”。因此表中“质量接近 3DGS 优化”这一列并不是等价比较，而是两种预算体制的对照。GS-LRM 的论点不是“前馈优于优化”，而是“在固定的一次前向预算下，直接输出高斯比输出三平面或网格更划算”。理解这一点，后面所有数字才有意义。

二 · 主要结果：提升来自输出头而非渲染器

主要结果可以概括为两句定性判断：新视角质量优于 LRM 的体渲染路线，渲染是实时的。这两句必须拆开看，因为它们的归因完全不同。质量提升的来源是输出表示的改变——高斯是显式的、带各向异性协方差的基元，能够表达薄结构、锐利边缘与高频纹理，而三平面经过体渲染积分后天然带有平滑倾向，细节在积分过程中被平均掉。渲染速度提升的来源则是渲染算子——高斯泼溅的光栅化是逐基元投影与混合，不需要沿射线做密集采样，因此单帧成本与高斯数量线性相关而与分辨率的关系更温和。

把这两条归因分开，才能解释为什么 GS-LRM 在“细节更锐”这一点上稳定胜出，而在“整体几何正确性”上并不总是压倒性领先。三平面体渲染在低频形状上是稳健的，因为它对整条射线做积分，局部错误会被平均；高斯泼溅则是局部基元的叠加，单个基元的均值或协方差预测错误会直接显形为漂浮物或空洞。这解释了后文局限中“稀疏视图几何不稳”的位置：不稳来自输出头的局部性，而不是来自 Transformer 的表征能力。

$$\mathcal{L}=\lambda_{\text{MSE}}\,\big\|\hat{I}-I\big\|_2^2+\lambda_{\text{LPIPS}}\,\mathrm{LPIPS}(\hat{I},I)$$

训练用的这个复合损失直接决定了“锐”从哪来。MSE 项约束像素级一致性，倾向于产生均值化的模糊解；LPIPS 项在特征空间度量感知差异，对结构错位与纹理模糊更敏感。两者叠加的效果是：模型不能靠输出一片平滑颜色来降低 MSE，因为 LPIPS 会惩罚缺失的高频结构。高斯输出头恰好提供了表达这些高频结构的自由度——每个基元的球谐颜色系数可以在不同视角下给出不同的颜色响应，协方差矩阵可以拉伸成薄片去贴合边缘。换句话说，损失函数要求的“感知锐度”与高斯表示的“各向异性表达能力”是对齐的，这是质量提升的机制层解释。

一个具体的对照场景：输入两张视角相隔较大的图，物体表面有一片细密的镂空结构。三平面路线在体渲染积分时，镂空孔隙被密度场平滑成半透明薄片，新视角下呈现为模糊的灰带；高斯路线若预测出足够多的小尺度、低不透明度基元，光栅化时这些基元按深度排序混合，孔隙得以保留。这不是渲染器“更准”，而是表示“更能装下”这种结构。前提是高斯数量足够——这就把话题引向消融。

三 · 消融一：输入视图数决定几何可辨识性

输入视图数从 2 到 4 的消融，检验的是多视图 token 的信息量是否被 Transformer 有效利用。机制上，每个视图被 patch 化后加上相机嵌入，Transformer 的注意力在视图间交换信息，输出的高斯参数是全部视图 token 的联合函数。视图数增加带来的不是简单的“平均更多观测”，而是对同一三维点的多方向约束：两个视图只能确定沿极线方向的对应关系，深度在基线方向上存在固有歧义；三个以上视图从不同方向交汇，三角化约束才变得良定。

因此消融的预期形态是：从 2 到 3 视图，几何类误差下降明显；从 3 到 4 视图，收益递减但仍可见，尤其在遮挡边界与自遮挡区域。这个形态本身就是证据——如果视图数增加只带来均匀的小幅提升，说明模型没有真正做跨视图融合，只是在做单视图先验的平均；如果出现明显的非线性跳变，说明注意力确实在利用多视图约束。论文报告的消融支持后者，即输入视图数是影响几何稳定性的主导因素之一。

  • 具体机制：相机嵌入把每个视图的外参/内参编码进 token，使注意力能够区分“同一表面在不同视角的投影”，从而学习对应关系而非纹理匹配。
  • 失败模式：2 视图输入下，薄物体与凹形结构的深度歧义无法消解，输出高斯沿视线方向被拉长或压扁，表现为新视角下的“鬼影”或“双层表面”。
  • 系统代价：视图数增加使 token 序列线性增长，注意力的计算与显存随之上升；这是后文“显存高”局限的直接来源之一。

一个可操作的工程判断：如果应用场景允许捕获 4 张图，就不要用 2 张去换显存，因为几何歧义造成的错误无法在渲染阶段修复；反之，如果只能拿到 2 张，就应当预期凹面与薄结构的失败，并在下游用多视角一致性检查来过滤。

四 · 消融二：高斯数量是表达能力与显存的直接兑换

高斯数量 N 的消融是这篇论文里最“物理”的一组实验。N 决定了输出头的容量上限：每个高斯携带均值（3）、协方差（可参数化为若干自由度）、不透明度（1）与球谐颜色（多阶系数），参数量随 N 线性增长。表达能力上，N 越大，越能覆盖高频细节与小尺度结构；但光栅化的成本、排序的复杂度以及显存占用都随 N 上升。这不是一个可以靠“更大模型”绕过的权衡，因为瓶颈在输出张量本身，而不在 Transformer 的宽度。

$$\text{Mem}_{\text{out}}\approx N\times\big(d_{\mu}+d_{\Sigma}+d_{\alpha}+d_{\mathbf{c}}\big)\times b$$

其中 b 是每参数的字节数。这个式子说明：即使 Transformer 主干不变，仅把 N 翻倍就会让输出激活与梯度缓冲翻倍。训练时的显存峰值出现在光栅化反向传播阶段，因为每个被投影到屏幕的高斯都要保留中间量以计算梯度。因此“高斯数限制”这条局限不是工程实现问题，而是方法本身的容量-成本曲线。

消融的预期形态：N 从较小值增加时，细节类指标快速改善；越过某个区间后，改善变缓，因为场景中的有效表面面积已被覆盖，新增基元更多落在已覆盖区域造成冗余混合。冗余基元还会带来副作用——重叠的半透明基元在排序混合时产生颜色偏移，表现为局部过饱和或雾状感。这就是“更多不一定更好”的具体机制，而不是笼统的收益递减。

一个具体例子：一个带细密纹理的雕像头部。N 偏小时，发丝与眼角被几个大协方差基元糊成一片；N 增大后，发丝由细长基元表达，眼角由小尺度基元表达，锐度提升。但若 N 继续增大而训练信号没有相应细化，多余基元会在表面附近抖动，新视角下出现闪烁。工程上的判断是：N 应当与输入视图数和目标分辨率匹配，而不是无脑取大。

五 · 消融三：Transformer 规模与“容量是否被用上”

Transformer 规模的消融回答一个归因问题：质量提升到底来自输出头，还是来自更大的主干网络？如果扩大主干带来的收益与换输出头带来的收益量级相当，那么“3DGS 作为输出头”这一核心主张就被削弱了。机制上，主干规模影响的是跨视图推理能力——更大的注意力头数与更深的层数能建模更复杂的视图间对应与遮挡关系，但它不改变输出头的表示能力上限。当 N 固定时，主干再大也无法表达超出 N 个基元能承载的细节。

因此这组消融的合理读法是“容量匹配”：主干规模与高斯数量应当同向调整。小主干配大 N，输出头有空余容量但主干给不出足够准确的参数，表现为基元位置噪声大；大主干配小 N，参数准确但表示不够细，表现为整体形状对、细节糊。论文的消融显示主干规模带来可测的提升，但提升幅度小于输出表示更换带来的提升，这支持了核心论点的归因。

  • 具体机制：主干深度影响的是 token 间的迭代信息交换次数，浅层网络在多视图对应上容易停留在纹理匹配而非几何匹配。
  • 失败模式：主干过小时，模型倾向于复制输入视图的外观先验，新视角下出现“贴图拉伸”式的错误，而非几何错误。
  • 系统代价：主干规模与 N 同时上升时，显存与训练时间叠加增长，训练以数天计，这限制了可搜索的配置空间。

工程判断落在配置选择上：在固定显存预算下，优先保证 N 足够覆盖目标场景的最小特征尺度，再把剩余预算给主干；反过来做通常得到“干净但模糊”的结果，因为主干无法凭空创造输出头装不下的细节。

六 · 证据的边界：实时性与稀疏视图的代价如何被实验暴露

“实时渲染”这条结论的证据强度依赖于测量口径。高斯泼溅的光栅化成本与基元数、屏幕覆盖面积相关，与体渲染的射线采样数无关；因此在相同分辨率下，GS-LRM 的单帧渲染不需要沿射线积分，帧时间由排序与混合主导。这条结论在 N 处于可控范围时成立，而当 N 逼近显存上限时，排序与混合的常数项会显现。实验中的实时性因此不是无条件的，它绑定在论文所用的 N 与分辨率配置上。

“稀疏视图几何不稳”这条局限同样有实验痕迹。2 视图配置下的失败模式不是随机噪声，而是结构化的：沿基线方向的深度歧义导致表面被“折叠”，新视角下出现背面渗透或双层轮廓。这与前文消融的预期形态一致——视图数不足时，注意力缺少足够的三角化约束，模型退化为依赖单视图先验补全，而先验在凹面与自遮挡处必然出错。实验通过对比 2/3/4 视图的误差分布暴露了这一点，而不是靠定性描述。

把这两条边界放在一起，可以看出论文证据结构的一个特点：它证明了“前馈 + 高斯输出头”在受控配置下同时取得质量与速度，但没有证明这套配置可以无条件扩展。显存高与稀疏视图不稳是同一枚硬币的两面——前者限制 N 与视图数的上限，后者限制 N 与视图数的下限，可行区间被夹在中间。后续工作（如 LGM）延续了这条路线，其改进方向也落在这个区间两端：更高效的基元表示与更强的多视图约束。

从工程角度看，最值得记住的不是某条曲线的形状，而是失败模式与配置的对应关系：2 视图对应深度歧义导致的折叠，小 N 对应细节糊化与基元抖动，大 N 配小主干对应位置噪声，大 N 配大主干对应显存墙。这四组对应关系构成了部署 GS-LRM 时的检查清单，也构成了判断“提升来自哪里”的最小充分证据——每一次质量变化都能被追溯到视图数、基元数或主干规模这三个可测量量之一，而不是归因于训练技巧的模糊叙述。
