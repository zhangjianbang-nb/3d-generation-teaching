一 · 复现边界：三阶段流水线的目录切分与最小可跑闭环

Hi3DGen 的复现难点不在单点模型，而在三阶段之间的契约：图像到法线的输出必须与法线到几何的输入张量严格对齐，几何到纹理又必须复用几何阶段的相机与网格坐标系。因此目录结构的第一原则是按阶段隔离，而不是按网络层隔离。推荐的最小可跑仓库布局如下：

  • configs/：stage1_normal.yaml、stage2_geo.yaml、stage3_tex.yaml 三份独立配置，外加一份 pipeline.yaml 只负责串联路径与阶段开关。
  • data/：raw_images、normal_gt、objaverse_shards、synth_cad 四个子目录，法线 GT 与几何 GT 必须按同一 object id 命名，避免阶段二拿错监督。
  • models/：normal_diffusion、geo_gen、tex_gen 三个包，各自暴露 forward(batch) 与 export() 两个入口，阶段之间只通过磁盘张量与元数据 JSON 通信。
  • runners/：run_stage1.py、run_stage2.py、run_stage3.py、run_all.py，每个 runner 只做加载、推理、落盘、断言四件事。
  • asserts/：验收断言脚本，按阶段分组，可在 CI 中单独执行。

最小可跑版本应优先打通「单图 → 法线 → 三平面 → 网格 → 纹理贴图」的闭环，而不是先追指标。具体做法是：阶段一固定输入分辨率与法线通道顺序（切线空间 XYZ 映射到 [0,1]），阶段二固定三平面分辨率与网格提取的 marching cubes 阈值，阶段三固定 UV 展开方式。三个阶段的中间产物统一落盘为 .npz（法线图、三平面特征）与 .obj（网格），元数据 JSON 记录相机内参、物体包围盒、阶段版本号。这样任一阶段失败时可以单独重跑，不必整链重算。

系统代价在这里已经显现：三阶段串行意味着显存峰值出现在阶段二（三平面 + 网格提取），而阶段一和阶段三可以独立降配。若把三阶段塞进单进程共享显存，阶段一的扩散采样缓存不会及时释放，阶段二的三平面张量就会触发 OOM。工程判断是：阶段间强制进程隔离，用磁盘换显存，推理时间从数秒到数十秒的量级里，磁盘 IO 不是瓶颈，显存才是。

一个具体例子：输入一张 512×512 的物体图，阶段一输出同分辨率法线图；阶段二以法线图为条件生成三平面，再提取网格；阶段三用网格的 UV 与法线图做纹理生成。若阶段二的法线条件通道被误设为 RGB 顺序而非切线空间顺序，网格会出现整体法线翻转，表现为光照下大面积黑面——这是最常见的契约错位，断言脚本必须在阶段二入口检查法线图的通道统计量（均值应接近 0.5，且 Z 通道非负占比符合预期）。

二 · 数据准备：法线 GT 的对齐、合成 CAD 的补位与分片策略

论文在 Objaverse 与合成 CAD 数据上训练，复现时数据准备的核心是法线 GT 的生成一致性。Objaverse 提供的是网格与材质，法线 GT 必须由渲染管线从网格烘焙，而不是从纹理法线贴图读取——后者包含材质作者的主观细节，会污染几何监督。烘焙流程是：固定相机采样球面视角，对每个视角渲染切线空间法线与深度，深度用于后续遮挡剔除。合成 CAD 数据的作用是补足 Objaverse 中缺失的规则几何与锐边，因为直接回归容易过平滑，而法线桥接要保留高频结构，训练集里必须有干净的锐边样本。

对齐机制用一个显式的数据契约表达：每个训练样本是一个三元组 (image, normal, geo)，其中 normal 与 image 必须来自同一相机位姿，geo 是规范化到单位包围盒的网格。伪代码思路是：

$$\text{sample}=\{\,I_{v},\,n_{v},\,\mathcal{M}\,|\,\mathcal{M}\sim\text{Objaverse}\cup\text{SynthCAD},\,v\sim\text{Sphere}(N)\,\}$$
采样视角数 N 决定法线监督的覆盖度，视角太少会导致背面法线缺失，阶段二在背面区域生成的法线条件为空，网格出现空洞。

分片策略上，Objaverse 按 object id 哈希分片，合成 CAD 按几何类别分层分片，保证每个 shard 内锐边样本比例稳定。每个 shard 预计算法线图并缓存为压缩张量，训练时只做解码与增广，避免每个 epoch 重复烘焙。代价是磁盘占用上升，但换来了数据加载的可预测性；若在线烘焙，GPU 渲染与训练争抢算力，吞吐会抖动。

常见崩溃点：法线图的坐标系约定不统一。渲染管线输出的是切线空间法线，而阶段二的法线条件网络若按世界空间解释，训练损失 ‖n̂−n‖² 会在地面真值上呈现系统性偏差，表现为损失下降但网格细节模糊。验收断言应在数据加载后检查法线图的单位长度（逐像素模长应接近 1）与半球一致性（Z 分量符号分布）。另一个崩溃点是合成 CAD 的尺度归一化遗漏，未归一化的网格会让三平面包围盒溢出，网格提取时出现截断。

三 · 超参配方：三阶段各自的敏感项与耦合项

复现时超参要分两类看：阶段内敏感项与阶段间耦合项。阶段一（法线扩散）的敏感项是采样步数与噪声调度，步数不足会让法线图高频细节丢失，直接削弱桥接的信息量；阶段二的敏感项是三平面分辨率与网格提取阈值，分辨率决定几何细节上限，阈值决定表面是否出现孔洞；阶段三的敏感项是纹理分辨率与 UV 接缝处理。耦合项则是阶段一输出法线的锐度与阶段二条件网络的接受域是否匹配。

训练目标在几何阶段是 L_geo = ‖n̂−n‖² + λL_render，其中 λ 控制渲染监督与法线监督的平衡。λ 过大时渲染损失主导，几何趋向于视觉合理但法线偏离；λ 过小时法线监督主导，网格可能出现法线正确但表面不闭合的碎片。复现时应把 λ 作为首要扫描项，并固定法线监督的归一化方式，否则不同实现间的 λ 不可比。

下表给出最小可跑版本的超参分组与验收关注点，数值只写相对关系，不写未给定的具体数字。
阶段超参组敏感方向验收关注
法线扩散采样步数、噪声调度、条件尺度步数偏少丢高频法线图锐边对比度
几何生成三平面分辨率、λ、提取阈值分辨率与阈值耦合网格闭合性与法线一致性
纹理生成纹理分辨率、UV 接缝、视角数接缝处色差贴图与几何法线匹配

系统代价：三平面分辨率翻倍会让显存需求按平方增长，而网格提取的计算量按立方增长，阶段二是整链的算力瓶颈。工程上应把分辨率作为可配置项，先用低分辨率打通闭环，再逐级提升并观察网格细节是否真的随分辨率改善；若提升分辨率后细节无变化，说明瓶颈在阶段一的法线质量而非几何表示。

具体例子：把 λ 设为偏大值跑一次，观察网格在锐边处是否被磨圆；再把 λ 调小，观察网格是否出现悬浮碎片。两次结果的差异就是 λ 的可行区间边界。这个扫描不需要完整训练，只需在固定小数据集上跑短程，因为 λ 的影响在早期就显现。

四 · 验收断言：从像素级到网格级的可执行检查

验收断言要分层，每层对应一个失败模式。像素层检查法线图的通道统计与单位长度；几何层检查网格的闭合性、法线一致性与包围盒；纹理层检查贴图与几何法线的匹配。断言必须是可执行的脚本，而不是人工目检，否则复现结果不可比。

几何层的核心断言是法线一致性：对网格每个面计算面法线，与阶段二条件法线图在对应视角投影后比较夹角分布。若夹角中位数偏大，说明法线桥接在几何阶段被削弱，常见原因是条件网络的注入位置过浅或法线图分辨率与三平面不匹配。另一个断言是闭合性：统计边界边数量，开放边过多意味着网格提取阈值不当或法线条件在背面缺失。

伪代码思路：

$$\text{assert: }\;\text{median}(\angle(n_{\text{face}},\,\hat{n}_{\text{proj}}))<\tau_{n}\;\wedge\;\text{open\_edges}<\tau_{e}\;\wedge\;\text{bbox}\subseteq[0,1]^{3}$$
阈值 τ 不写具体数字，按最小可跑版本的实际分布定标，先记录再收紧。断言失败时应输出失败样本的中间产物路径，便于定位是阶段一还是阶段二的问题。

失败模式举例：阶段一法线图在物体轮廓处出现模糊过渡，阶段二把这些过渡当作真实几何，网格边缘出现倒角状伪影。像素层断言若只检查均值会漏掉这种局部模糊，必须加局部梯度统计。另一个失败模式是阶段三纹理与几何法线不匹配，表现为贴图高光位置与网格光照不一致，纹理层断言应比较贴图法线与几何法线的夹角。

系统代价：断言脚本本身要跑推理，全量断言的时间与一次完整推理相当。工程上应把断言分为快速子集（单样本、低分辨率）与全量集，CI 只跑快速子集，全量集在发版前跑。

五 · 常见崩溃点：误差传导、显存与坐标系的三类故障

第一类故障是法线误差传导。论文明确指出误差会传导，复现时表现为阶段一的局部法线错误在阶段二被放大为几何错误，且不可通过阶段三纹理修复。机制是：阶段二以法线为条件，条件中的错误区域会被网络当作真实几何生成，误差从 2D 像素级扩散到 3D 表面级。工程判断是：在阶段一后加一个法线质量门控，对低置信区域标记并在阶段二中降权，而不是无条件信任法线图。

第二类故障是显存。三平面张量与网格提取的中间体在阶段二叠加，若与阶段一共进程，扩散采样的缓存会挤占显存。崩溃点常出现在批量推理时，单样本可跑、批量即 OOM。解决办法是阶段间进程隔离与批量大小按阶段二的上限设定，而不是按阶段一的上限。

第三类故障是坐标系。法线图的切线空间约定、三平面的世界坐标约定、网格的导出坐标约定三者若不统一，会出现整体旋转或镜像。具体例子：导出的 OBJ 在查看器中左右镜像，原因是阶段二的三平面坐标系与阶段三的 UV 展开坐标系手性不一致。断言应在导出后检查网格的包围盒与法线朝向，而不是只看渲染图。

推理较慢是论文承认的代价，复现时要区分慢在采样还是慢在网格提取。若慢在采样，可降步数；若慢在网格提取，可降三平面分辨率。两者对细节的影响不同，必须先定位再降配，否则会把几何细节的损失误归因于法线桥接本身。

六 · 最小可跑版本的收敛判据与工程取舍

最小可跑版本的目标不是复现指标，而是证明三阶段契约成立：法线图能被阶段二正确消费，网格能被阶段三正确贴图，断言能稳定通过。收敛判据是：固定单张输入，三次重跑的网格顶点数与法线夹角分布方差在可接受范围内；阶段一换采样步数时，阶段二网格细节随之单调变化。若换步数后网格无变化，说明桥接断路，阶段二没有真正使用法线条件。

工程取舍上，纹理阶段仍靠 2D 先验，复现时不应把纹理质量当作几何质量的证据。几何验收只看网格与法线一致性，纹理验收单独看贴图匹配。这样可以把几何复现与纹理复现解耦，避免纹理的视觉好看掩盖几何的过平滑。

另一个取舍是合成 CAD 数据的使用比例。合成数据补锐边，但分布与真实图像不同，比例过高会让阶段一对真实图像的法线预测偏向规则几何。复现时应把合成数据作为锐边补丁而非主训练集，并在断言中加入真实图像子集的法线锐度检查。

最后落在具体机制上：阶段二的条件注入必须发生在三平面生成的每一层，而不是只在输入端拼接一次。若只在输入端拼接，法线信息会在深层被稀释，网格细节退化到与直接回归相当，这正是论文要避免的过平滑。复现时用断言检查不同深度的条件注入对法线夹角分布的影响，若深层注入无增益，说明实现与论文的桥接机制不一致，应优先修条件注入路径而非调超参。
