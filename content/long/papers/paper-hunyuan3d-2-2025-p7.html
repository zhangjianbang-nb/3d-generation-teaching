一 · 对比的坐标系：表示、监督、速度、显存四条轴

把 Hunyuan3D 2.0 与同期或后继方法放在一起比较，容易滑向“谁的 demo 更好看”的主观判断。工程上更有意义的是先固定四条可测量的轴：表示（模型输出什么数据结构，能否直接进渲染管线）、监督（用什么信号训练，损失落在哪个空间）、速度（端到端从条件到可交付资产的时间）、显存（峰值占用决定能否在单卡上跑）。这四条轴不是并列的，它们之间存在耦合：表示越显式，监督越容易定义，但解码阶段的显存与时间开销越大；表示越隐式，训练信号越依赖可微渲染，速度与显存又反过来受渲染器制约。因此逐项对比时必须把耦合关系讲清楚，否则表格里每一格都正确，合起来却是误导。

本文选取的对照对象是论文给出的三个基线：TRELLIS、Direct3D、LRM。三者的定位不同——TRELLIS 属于结构化潜表示路线，Direct3D 属于直接优化式路线，LRM 属于早期大重建模型路线。把它们与 Hunyuan3D 2.0 并列，正好覆盖“显式结构 / 隐式优化 / 前馈重建”三种典型取舍。需要强调的是，论文并未给出这三者在同一硬件、同一分辨率下的逐项数值，因此下文的速度与显存比较只做机制层面的定性判断，凡涉及具体数字一律沿用论文自身给出的量级（数十 GPU 天训练、推理数十秒），不替基线编造数字。

四条轴的具体含义如下。表示轴问的是：输出是 SDF、网格、VecSet 潜码、三平面还是多视图集合？这决定了后处理链的长度。监督轴问的是：损失是体素级 SDF 回归、渲染图像 L2、还是多视图投影误差？这决定了训练是否需要可微渲染器。速度轴问的是：采样步数、解码（Marching Cubes 或 UV 投影）耗时、纹理阶段的多视图渲染次数，三者相加才是端到端时间。显存轴问的是：潜码张量的空间尺寸、渲染时的分辨率与视图数、UV 贴图的分辨率。下面逐节展开。

二 · 表示之争：VecSet 显式 SDF 与结构化潜码的取舍

Hunyuan3D 2.0 形状分支的输出是 VecSet 表示的 SDF，经 Marching Cubes 转成网格。这条链路的关键机制是：扩散过程在 VecSet 潜空间里进行，潜码与 SDF 场之间是确定性的编解码关系，采样结束后一次性解码为稠密场再提取等值面。它的好处是监督信号可以直接落在 SDF 上，不需要经过可微渲染即可获得几何梯度；坏处是解码阶段的显存峰值由体素网格分辨率决定，分辨率翻倍，体素数量按立方增长。

对照 TRELLIS 一类结构化潜表示方法，后者把几何压进稀疏结构或三平面式的紧凑张量，潜码本身携带空间归纳偏置，采样后解码为辐射场或占用场。这种表示在潜空间里更省显存，但监督往往依赖渲染损失，梯度要穿过体素化或射线采样，训练稳定性受渲染器实现细节影响。Direct3D 走的是另一条路：不训练生成先验，而是对每个资产直接做优化式重建，表示可以是网格或隐式场，监督来自多视图图像的一致性。它的优势是单资产质量可控，劣势是每个资产都要独立优化，端到端时间随资产数量线性增长，无法摊销成前馈推理。LRM 则是早期前馈重建的代表，输出隐式表示，分辨率与纹理完整性受限于单阶段容量。

用一个具体例子说明差别：给定同一张产品图作为条件，Hunyuan3D 2.0 的形状分支在潜空间采样后解码出稠密 SDF，Marching Cubes 直接产出封闭网格，法线与拓扑由等值面提取保证；TRELLIS 类方法需要先把潜码解码为场再提取表面，中间多一层解码器，若解码器与训练时的场表示不一致，会出现表面碎片；Direct3D 则要针对这张图跑优化循环，迭代次数与视图数决定时间。三者都能出网格，但“出网格之前经过了几次表示转换”不同，这正是失败模式差异的根源。

$$\text{cost}_{\text{decode}} \propto N_{\text{voxel}} = \left(\frac{R}{s}\right)^3$$

其中 R 是目标空间边长，s 是体素步长。该式说明显式 SDF 路线的解码代价是立方级的，这是它在高分辨率下的主要系统代价。工程判断是：当目标分辨率在论文所述的高分辨率档位时，必须把 Marching Cubes 放到显存预算之外单独评估，否则形状阶段的采样显存与解码显存会叠加。

三 · 监督之争：SDF 回归 + 渲染 与 纯渲染损失

Hunyuan3D 2.0 的训练配方是形状与纹理分开训练，形状用 SDF 监督加渲染，纹理用多视图渲染。公式上，总损失写成形状项与纹理项的加权和：

$$\mathcal{L}=\mathcal{L}_{\mathrm{shape}}+\lambda\mathcal{L}_{\mathrm{tex}},\qquad \mathcal{L}_{\mathrm{tex}}=\sum_{v}\|\hat{I}_v-I_v\|^2$$

这个式子的工程含义不在形式，而在两项的训练时序：它们不是联合优化的，而是各自独立训练、共享图像条件。这样做的直接收益是形状分支的梯度不必穿过纹理渲染器，纹理分支的梯度也不必回传到形状潜码，两个阶段的失败模式被隔离。代价是两阶段之间存在接口误差：形状网格的 UV 展开质量直接决定纹理阶段能拿到什么样的投影目标，形状阶段的微小拓扑瑕疵会在纹理阶段被放大。

对照之下，纯渲染损失路线（Direct3D 式优化、部分 LRM 变体）把几何与外观放在同一个可微渲染循环里联合优化，监督信号统一为图像 L2。这种做法的机制优势是几何与纹理自动一致，不会出现“网格对了但 UV 错了”的接口问题；系统代价是每次迭代都要跑可微渲染，显存峰值包含渲染缓冲与梯度缓冲，且渲染器的近似（如软光栅、近似可见性）会引入梯度偏差。训练稳定性因此更依赖渲染器实现，调参空间更大。LRM 类前馈方法同样以渲染或投影损失为主，但单阶段容量限制了高频几何与纹理细节，这是它在本对比中处于劣势的结构性原因，而非数据量问题。

一个具体例子：当条件图包含细长结构（如手柄、支架）时，SDF 监督能提供体素级的稠密梯度，细长部位不易断裂；纯渲染损失下，细长结构在多数视角只占少量像素，图像 L2 的梯度贡献被大面积背景稀释，优化容易把这些部位抹平。反过来，当条件图只给出正面视角时，SDF 监督在背面缺乏约束，需要渲染损失补足；Hunyuan3D 2.0 用渲染项参与形状监督正是为了补这个洞。这解释了为什么它的形状损失不是纯 SDF 回归，而是 SDF 加渲染的混合。

四 · 速度与显存：两阶段独立 scaling 的账

速度账要分三段算：形状扩散采样、网格解码、纹理扩散与 UV 投影。论文给出的量级是推理数十秒、训练数十 GPU 天。数十秒的构成中，形状采样步数与纹理阶段的多视图渲染次数是主要项；Marching Cubes 的解码时间随分辨率立方增长，在高分辨率档位不可忽略。纹理阶段的机制是多视图扩散后在 UV 空间投影合成，视图数决定渲染次数，UV 贴图分辨率决定投影与合成的显存。

显存账同样分三段。形状采样阶段的峰值由 VecSet 潜码尺寸与批大小决定；解码阶段峰值由稠密体素网格决定，这是全流程最容易爆显存的位置；纹理阶段的峰值由多视图渲染缓冲与 UV 贴图分辨率共同决定。两阶段独立训练的好处在这里体现：形状训练不需要纹理渲染器驻留显存，纹理训练不需要稠密 SDF 场驻留显存，单阶段的显存预算可以各自优化。代价是端到端部署时两段显存不能同时释放，流水线设计必须显式安排释放点。

这张表里最容易被误读的是速度一列。Hunyuan3D 2.0 的“数十秒”是端到端含两阶段的量级，而 Direct3D 式方法的单资产时间取决于迭代预算，二者不可直接比大小；正确的比较方式是问“单位时间能交付多少个可进渲染管线的资产”。前馈两阶段路线的时间与资产数无关（摊销），优化式路线的时间与资产数线性相关，这是结构性差异，不是常数差异。

五 · 失败模式逐项对照

Hunyuan3D 2.0 的失败模式在论文中明确列出三项：纹理真实感受数据限制、UV 展开失败、推理较慢。这三项不是孤立的，它们分别对应表示、监督、速度三条轴上的结构性代价。

  • UV 展开失败：机制上，纹理分支依赖形状网格的 UV 参数化，若网格存在非流形边、自交或极端细长面片，展开算法会产出重叠或断裂的 UV 岛，投影后的多视图纹理在接缝处错位。这是两阶段解耦的直接代价——形状阶段不知道纹理阶段需要什么样的参数化。对照联合优化路线，UV 与几何在同一循环里优化，接缝问题可以被渲染损失间接惩罚；代价是优化更慢、更不稳定。
  • 纹理真实感受数据限制：监督信号是多视图渲染的 L2，训练数据的分布决定纹理先验的上限。当条件图的光照、材质超出训练分布时，纹理分支只能给出分布内的近似，表现为塑料感或过度平滑。这是纯 L2 监督的通病，Direct3D 式逐资产优化可以用测试时的多视图一致性部分弥补，但需要更多视图与迭代。
  • 推理较慢：两阶段串行、扩散采样步数、多视图渲染次数三者叠加。对照 LRM 类单阶段前馈，后者一次前向即可出结果，速度优势明显，但分辨率与纹理完整性不足；这是速度与质量的直接交换，不是实现缺陷。

对照方法的失败模式各有其结构性根源。TRELLIS 类结构化潜表示的风险在解码器与训练场表示的不一致，表现为表面碎片或空洞；Direct3D 式优化的风险在迭代预算不足时的局部欠优化，表现为细节缺失或视角间不一致；LRM 类前馈的风险在单阶段容量对高频几何与纹理的压缩，表现为模糊与纹理缺失。把这些失败模式并列，可以看出一个规律：表示越显式、监督越直接，失败越集中在接口（UV、解码一致性）；表示越隐式、监督越依赖渲染，失败越集中在优化过程（收敛、视角一致性）。Hunyuan3D 2.0 选择前者，因此它的工程复现清单里 UV 质量检查必须是独立验收项，不能只看网格的 Chamfer 距离。

一个具体例子：条件图为带镂空花纹的装饰件时，形状分支能恢复镂空拓扑，但 Marching Cubes 在薄壁处产生的三角面片长宽比极端，UV 展开在这些面片上失败，纹理阶段把花纹投到错误的 UV 岛，最终贴图在镂空边缘出现拉伸条纹。这个链条上没有任何一步“训练不充分”，全部是表示与接口的结构性后果。工程上的缓解手段是在形状解码后加一道网格重网格化与 UV 重展开，代价是额外时间与可能引入的几何偏差。

这张表的读法是按行匹配约束，而不是按列比强弱。一个常见的误用是把“Hunyuan3D 2.0 工业可用性优于同期开源模型”这句话当成全场景结论；论文的表述限定在开源模型对比与工业资产交付语境下，换成延迟敏感或单卡低显存场景，结论不成立。决策表最后一行值得单独说明：联合优化路线在“不接受 UV 接缝”这一约束下是唯一选择，因为两阶段解耦的接口误差无法在阶段内部消除，只能在阶段之间加后处理，而后处理本身会引入几何偏差。

工程判断落在具体机制上：Hunyuan3D 2.0 的两阶段解耦把“形状 scaling”与“纹理 scaling”变成两个可独立调节的旋钮，这是它相对单阶段方法的根本优势；但解耦同时把 UV 参数化变成一条不受形状损失约束的隐式接口，这条接口的质量只能靠独立的网格与 UV 验收断言来保证。选型时若你的流水线已经具备网格重网格化与 UV 重展开能力，两阶段前馈的接口风险可控，端到端时间与批量摊销的优势成立；若不具备，则应把 UV 失败计入交付成本，或转向联合优化路线。这一判断不依赖任何未给出的实验数字，只依赖表示与监督的耦合结构。
