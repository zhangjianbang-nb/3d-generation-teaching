一 · 最小可跑目录与模块边界

复现 DreamGaussian 的第一条工程判断是：不要把两阶段塞进一个训练脚本。阶段一优化的是高斯参数集合，阶段二优化的是网格上的 UV 纹理，两者的可微渲染器、损失函数、显存占用曲线完全不同。把目录按“表示”切分，而不是按“论文图”切分，能让崩溃点定位从“整个 pipeline 挂了”缩小到“某一个阶段挂了”。

一个能跑通的最小目录可以是这样：configs/ 放阶段一与阶段二各自的 yaml；data/ 只放提示词与可选的参考图，本方法不需要 3D 训练集；gauss/ 放高斯初始化、SDS 优化循环、高斯参数序列化；mesh/ 放 local density 提取、网格清理、UV 展开；texture/ 放 UV 空间的可微渲染与 RGB 精修；render/ 放两套光栅化封装；checkpoints/ 按阶段分目录；asserts/ 放验收断言脚本。关键约束是 gauss/ 不得 import mesh/，texture/ 不得 import gauss/ 的优化器状态——阶段之间只通过磁盘上的高斯点云与提取出的网格通信。

阶段一的机制是：初始化一组高斯（随机点云或球面分布），每个高斯带位置、旋转、缩放、不透明度与球谐颜色；每步从随机相机位姿渲染成图，送进 Stable Diffusion 算 SDS 梯度，反传回高斯参数。伪代码思路如下：

$$\mathcal{G}^{*}=\arg\min_{\mathcal{G}}\mathcal{L}_{\mathrm{SDS}}(\mathrm{Render}(\mathcal{G}),y),\qquad \mathcal{M}=\mathrm{Extract}(\mathcal{G}^{*})$$

系统代价出现在这里：SDS 每步要前向一次扩散模型并反传，显存峰值由扩散模型而非高斯数量决定；500 步的墙钟时间约 2 分钟（RTX 3090），但这个数字对 batch 大小、分辨率、是否用半精度极其敏感。失败模式是显存碎片化——反复创建与销毁扩散模型的计算图会让 caching allocator 无法复用块，表现为步数跑到中途 OOM，而单步显存看起来并不高。具体例子：把阶段一的渲染分辨率从默认值抬高一级，高斯数量不变，但扩散模型输入变大，显存峰值上移，原本能跑完 500 步的卡会在第 300 步左右崩。

二 · 数据准备：提示词、相机与初始化

本方法没有 3D 训练集，数据准备的重心从“数据集”转移到“采样分布”。需要准备三样东西：提示词文本、相机位姿采样器、高斯初始化点云。提示词直接进 Stable Diffusion 的文本编码器，工程上要固定 tokenizer 版本与最大长度，否则同一提示词在不同环境编码出的条件向量不同，SDS 梯度方向随之漂移，复现结果无法对齐。

相机采样决定了 SDS 看到的是哪个视角的监督。常见做法是在球面上采样方位角与仰角，并让半径随训练进程收缩或保持固定。这里有一个必须写进配置的量：仰角范围。仰角过宽会把地平线以下的视角也送进扩散模型，而扩散模型对“从下方看物体”的先验很弱，SDS 会给出噪声梯度，表现为高斯在底部乱长。仰角过窄则背面监督不足，提取网格时背面出现空洞。

高斯初始化是消融项之一，也是复现差异最大的地方。随机点云初始化让高斯在空间里均匀铺开，收敛慢但不容易塌缩；球面初始化把高斯放在一个球壳上，收敛快但容易在球心留下空洞。工程判断是：初始化半径要与相机采样半径匹配，否则第一阶段早期渲染出的图与扩散模型先验的尺度不一致，SDS 会先把物体“拉大”再“拉小”，浪费步数。

一个具体例子：同一提示词下，把初始化从随机点云换成球面分布，前 100 步的渲染图会明显更“像”目标物体，但到 500 步结束时两者质量接近——这说明初始化主要影响收敛速度而非最终上限，验收断言里应把“前 N 步的渲染是否已具备物体轮廓”作为早期健康检查，而不是只看最终结果。

三 · 阶段一超参与验收断言

阶段一的超参分三组：高斯参数组（初始缩放、不透明度初值、球谐阶数）、优化器组（学习率、是否对位置与颜色用不同学习率）、SDS 组（步数、扩散模型采样步、CFG 强度、时间步采样分布）。500 步是论文给出的配方，约 2 分钟；步数消融说明步数不足时高斯尚未收敛，提取出的网格会带大量漂浮碎片。

时间步采样分布是容易被忽略的机制：SDS 在每个优化步随机取一个扩散时间步，加噪后让扩散模型预测噪声，梯度来自预测噪声与所加噪声之差。时间步偏大时梯度更像“全局形状”信号，偏小时更像“纹理细节”信号。若采样分布固定不变，早期与晚期收到同质梯度，收敛会变慢；常见做法是让时间步分布随训练进程移动。这里不写具体调度数字，只强调它是配置项而非硬编码。

验收断言应写成可执行的检查，而不是“看起来还行”。最小集合包括：

  • 高斯数量在训练中单调不减（致密化只增不减），若出现下降说明致密化与剪枝逻辑接反。
  • 每 50 步记录一次渲染图的均值亮度，若亮度在若干步内持续趋近于 0 或饱和，说明不透明度或学习率失控。
  • 训练结束时高斯位置的包围盒尺度与相机半径同量级，偏差过大说明尺度漂移。
  • 固定种子重跑，最终高斯数量的相对偏差应在小范围内，否则随机性主导了结果。

系统代价：致密化会让高斯数量随步数增长，显存与光栅化时间随之上升。失败模式是“致密化爆炸”——梯度阈值设得过低，每步都在克隆高斯，几百步后数量翻数倍，光栅化从毫秒级退化到秒级，500 步的 2 分钟预算被打破。具体例子：把致密化的位置梯度阈值下调一档，高斯数量在 200 步后开始指数增长，墙钟时间从分钟级滑向十分钟级，而渲染质量并未提升——这是典型的用算力换不到质量的失败。

四 · 网格提取与 UV 展开的崩溃点

阶段二的输入是收敛后的高斯集合，输出是带 UV 的网格。提取机制基于 local density：在高斯所在空间划分体素网格，把每个高斯的密度贡献累加到体素上，再用阈值二值化得到占据场，最后跑 marching cubes 得到三角网格。公式上可写成对密度场的阈值操作，阈值是消融项之一。

这里的崩溃点集中在阈值与体素分辨率。阈值过高，网格只剩最密的核心，细节丢失且出现碎片；阈值过低，稀疏的“雾状”高斯也被算作实体，网格膨胀出大量薄片。体素分辨率过高会让提取时间与内存暴涨，分辨率过低则丢失薄结构（比如手柄、细腿）。工程判断是：体素分辨率应与高斯初始缩放匹配，让单个高斯大致覆盖若干体素，而不是让体素远小于高斯尺度。

UV 展开是第二个崩溃点。从 marching cubes 出来的网格拓扑一般，存在非流形边与自交，直接做 UV 展开会失败或产生严重拉伸。常见处理是先做网格清理（去孤立碎片、合并重复顶点、修复法线），再做参数化。失败模式是参数化在薄结构处重叠，纹理精修阶段的可微渲染把重叠区域的梯度叠加，纹理出现鬼影。具体例子：一个带细长突出物的物体，UV 展开时突出物被压进主体 UV 岛，精修后突出物表面出现主体纹理的颜色，验收断言里应检查 UV 岛的覆盖完整性与重叠率。

系统代价：网格提取与 UV 展开是 CPU 侧操作，耗时约 1 分钟量级，且对网格规模敏感。若提取出的网格面数因阈值过低而暴涨，UV 展开与后续可微渲染的时间都会上升，阶段二的 1 分钟预算被打破。这也是为什么阈值消融不能只看视觉质量，还要看面数。

五 · 纹理精修与端到端验收

阶段二的纹理精修机制是：在 UV 空间维护一张纹理图，用可微渲染器把网格加纹理渲染成图，与目标（来自扩散模型或参考图）算 RGB 损失，反传更新纹理像素。它不再走 SDS，因为几何已固定，只需要颜色对齐。这一步的关键超参是渲染分辨率、相机采样是否复用阶段一的位姿、以及纹理图初始值（常初始化为均值色）。

失败模式有两种。其一是相机位姿不复用：阶段二用新的随机位姿，纹理在某些视角过拟合、在另一些视角欠拟合，端到端看出现视角相关的色偏。其二是纹理分辨率与网格 UV 密度不匹配：分辨率过低时薄结构纹理糊成一片，过高时显存与采样时间上升且容易过拟合到渲染噪声。工程判断是纹理分辨率按 UV 岛的平均面积分配，而不是全局一个常数。

端到端验收断言应覆盖两阶段交接处。最小集合：

  • 阶段一输出的高斯文件能被阶段二独立加载，不依赖阶段一进程的任何内存状态。
  • 提取网格的水密性检查（非流形边比例、孤立连通分量数）在可接受范围内，否则纹理精修会在破洞处产生伪影。
  • 阶段二渲染图与阶段一最后若干步的渲染图在相同位姿下的颜色差异不应突变，突变说明 UV 展开把颜色映射错了位置。
  • 总墙钟时间分解为阶段一、提取、UV、精修四段并分别记录，任一段超出预算即视为该段超参需要回退。

一个具体例子：把阶段二的相机位姿改为独立随机采样，纹理精修在少数视角上把颜色压到极值，端到端旋转展示时出现明显的“闪色”视角。把位姿采样器与阶段一共用同一套球面分布后，闪色消失——这说明两阶段之间的隐式契约（位姿分布一致）必须写成显式配置，否则复现者会在不知情的情况下破坏它。

六 · 复现差异的来源与工程判断

即使目录、数据、超参都对齐，复现结果仍会有差异，来源主要有三：扩散模型的版本与权重、光栅化实现（不同 CUDA 扩展对高斯的排序与混合顺序有细微差别）、以及随机数流的管理。第一项影响 SDS 梯度的“品味”，第二项影响渲染数值的确定性，第三项影响可重复性。工程上应把这三项都钉死在配置里，并在验收脚本里记录版本哈希。

质量上限的判断要诚实：本方法的质量略低于慢方法，拓扑一般，多面问题存在。复现的目标不是追平 DreamFusion 或 Magic3D 的质量，而是验证“分钟级可用”这条曲线——500 步约 2 分钟出高斯、再约 1 分钟出带纹理网格，速度比 Magic3D 快一个量级。验收断言应围绕这条曲线设阈值，而不是围绕视觉精美度设阈值。

最后一个具体机制层面的工程判断：阶段一的高斯序列化格式要同时保存位置、旋转、缩放、不透明度、球谐系数与优化器无关的元数据（点数、包围盒、训练步数）。只保存位置与颜色会让阶段二无法复现提取阈值的最优值，因为 local density 依赖缩放与不透明度。把元数据写进文件头，提取脚本读取后自动选择阈值档位，能把“换一台机器重跑提取”这个常见崩溃点消掉。
