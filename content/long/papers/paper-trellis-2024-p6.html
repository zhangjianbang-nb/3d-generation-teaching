一 · 复现边界与仓库骨架

复现 TRELLIS 之前要先划清边界：论文给出的是「结构化潜变量 SLAT + 3D DiT rectified flow + 多格式解码器」的三段式管线，但三段之间的接口契约、各阶段的训练数据配比、解码器的可微等值面实现细节，论文正文只给了定性描述。工程复现的第一件事不是抄超参，而是把三段拆成可以独立验收的模块，让每段都能在缺少下游的情况下单独跑通并给出可检查的中间产物。否则一旦端到端崩掉，你无法判断是 SLAT 编码器塌了、DiT 采样发散，还是解码头把潜变量解错了。

推荐的最小目录结构按「数据 → 表示 → 生成 → 解码 → 验收」分层，而不是按论文的章节顺序排：

  • data/：多视图渲染缓存、相机参数、Objaverse 元数据索引；渲染结果按资产 uid 分片，避免单文件过大。
  • slat/：稀疏体素化、局部特征聚合、编码器与解码器的共享表示层；这一层不依赖扩散。
  • flow/：3D DiT 主干、rectified flow 的采样器与训练循环、时间步嵌入。
  • heads/：高斯头、网格头（可微等值面）、辐射场头；每个头只吃 SLAT，不回头改 SLAT。
  • eval/：渲染一致性、几何闭合性、多格式互转的断言脚本。
  • configs/：把「SLAT 分辨率」「DiT 规模」「解码器类型」三个消融维度显式参数化，而不是写死在代码里。

这个骨架的关键判断是：SLAT 是唯一的跨阶段契约。编码器输出什么形状、什么稀疏布局、特征维度多少，必须用一个 schema 文件固定下来，flow 训练和解码器训练都从这个 schema 读，而不是各自硬编码。工程上最常见的返工就是把特征维度改了一次却忘了同步解码头，导致训练 loss 正常下降但解码输出全是噪声。

二 · 数据准备：多视图到稀疏体素

SLAT 的构建起点是多视图编码器：对每个 3D 资产渲染若干视角，用图像编码器提特征，再把特征反投影到稀疏体素网格上做局部聚合。数据准备阶段真正决定复现成败的不是渲染数量，而是相机与体素坐标的一致性。渲染时用的外参、内参与体素化时用的世界坐标系必须来自同一套变换，任何一次坐标轴翻转或归一化尺度不一致，都会让反投影特征落到错误的体素上，表现为编码器训得动但生成质量极差。

具体机制上，稀疏体素化要先确定一个包围盒归一化到单位立方体，再按目标分辨率切格，只保留被表面占据的体素。设分辨率边长为 R，则体素索引与连续坐标的映射是离散化加取整，这一步的量化误差直接构成论文所说的「分辨率受限」：R 增大，体素数按立方增长，显存和 DiT 的序列长度同步膨胀。工程上必须把 R 当作一等超参，而不是事后调。

$$\mathbf{f}_i=\mathrm{Agg}\big(\{\mathbf{e}_j \mid \pi_j(\mathbf{x}_i)\ \text{可见}\}\big),\qquad \mathbf{x}_i\in\mathcal{V}_{\text{occ}}$$

其中 π_j 是第 j 个视角的投影，V_occ 是占据体素集合，Agg 是局部聚合（池化或注意力）。这条公式的工程含义是：每个占据体素的特征只来自能看到它的视角，遮挡关系必须在反投影时处理，否则背面体素会被正面特征污染。

数据准备的系统代价集中在渲染缓存上。Objaverse 级别的资产量乘以多视角，渲染图和特征图会占掉可观的存储；常见做法是离线渲染一次、在线只读缓存，并把特征也落盘，避免每次训练重跑图像编码器。失败模式有两种：一是缓存分片粒度太细导致 IO 随机读放大，训练吞吐被数据加载拖死；二是相机参数与渲染图不同步更新，缓存里混入旧视角，编码器学到矛盾的几何线索。验收断言应写成「随机抽一个资产，重投影特征与渲染图在可见区域的相关性高于阈值」，把坐标一致性变成可自动检查的项。

三 · 两阶段训练的超参与最小可跑版本

论文的训练是两阶段的：先训 SLAT 编码器/解码器，再训 3D DiT 的 rectified flow。复现时不要一上来就跑全量，最小可跑版本应该是「小分辨率 SLAT + 小 DiT + 单解码头」，先把三段串起来验证梯度能流通，再逐段放大。

第一阶段的目标是让 SLAT 可编码可解码。编码器把多视图特征压进稀疏体素，解码器（此时可以先用辐射场头）把 SLAT 还原成可渲染的表示。这一阶段的超参重点是特征维度、体素分辨率、聚合方式；验收断言是「编码-解码重建的渲染图与输入多视图在训练视角上的一致性损失低于随机基线」，注意这里只要求重建，不要求生成。

第二阶段的 rectified flow 训练，核心是构造直线插值路径并回归速度场：

$$\mathbf{z}_{t}=\mathbf{z}_0+(1-t)\epsilon,\qquad v_\theta(\mathbf{z}_t,t)=\epsilon-\mathbf{z}_0,\qquad \mathcal{L}=\mathbb{E}\big[\|v_\theta(\mathbf{z}_t,t)-(\epsilon-\mathbf{z}_0)\|^2\big]$$

工程上要盯住三件事：z_0 是编码器输出的 SLAT，必须与 DiT 的输入布局严格对齐（稀疏索引的顺序、padding 方式）；t 的采样分布影响收敛，均匀采样是最小可跑版本的默认选择；DiT 的规模（层数、宽度、注意力头数）是论文消融维度之一，复现时应把它做成配置项，先用小规模验证 loss 曲线形状，再放大。推理侧从 t=1 的纯噪声积分到 t=0，采样步数是速度与质量的直接权衡，论文声称推理数秒，这个数秒对应的是固定步数加固定 DiT 规模，换规模就要重新标定。

系统代价与失败模式：两阶段之间如果编码器没冻住就开训 DiT，SLAT 分布会漂移，DiT 学到的速度场对不上推理时的编码器输出，表现为训练 loss 正常但采样结果崩坏。正确做法是第一阶段收敛后冻结编码器，DiT 只学在固定 SLAT 分布上的去噪。另一个常见崩溃点是稀疏布局在不同 batch 间长度不一，若用稠密 padding 到最大长度，显存会被最长样本支配；应按 token 数分桶。

四 · 解码器头的接口与可微等值面

三个解码头共享同一个 SLAT 输入，但输出语义完全不同：高斯头输出一组带位置、协方差、颜色、不透明度的高斯；网格头通过可微等值面把 SLAT 解成带符号距离场再提取表面；辐射场头输出密度与颜色用于体渲染。复现时最容易出错的地方是把解码头的训练和解码头的推理混在一起：训练时等值面提取需要可微的采样，推理时可以用更快的 marching cubes，两者数值行为不完全一致，验收要分别做。

网格头的可微等值面机制是：在体素网格上查询 SDF 值，用三线性插值得到连续场，再用可微的 surface extraction 近似把场变成点与面。这里的工程约束是分辨率——SDF 查询的网格密度受 SLAT 分辨率限制，细结构在低分辨率下会被抹平，这正是论文局限里「分辨率限制」在解码侧的体现。高斯头相对宽松，因为它不依赖网格离散化，但高斯的数量与排序会影响渲染稳定性。

验收断言按头分别写：高斯头检查「渲染图与目标视角的感知差异低于阈值，且高斯数量在预算内」；网格头检查「提取表面的水密性与法向一致性，闭合网格的欧拉示性数符合预期」；辐射场头检查「多视角渲染的深度一致性」。多格式输出是论文的核心卖点，复现时必须验证同一 SLAT 解出的高斯与网格在几何上大致重合，否则说明某个头吃错了特征布局。失败模式典型的是网格头在稀疏区域产生孔洞，根因往往是 SLAT 在那些体素上没有有效特征，而不是等值面算法本身。

五 · 显存、吞吐与常见崩溃点清单

论文明确把「显存高、管线复杂」列为代价，复现时这两点会以具体形式出现。显存的主要来源是 DiT 在稀疏体素序列上的注意力：序列长度正比于占据体素数，分辨率翻倍会让序列长度按立方增长，注意力的二次复杂度随之爆炸。工程缓解手段是分块注意力、梯度检查点、以及按 token 数分桶的批采样；但这些都会改变训练动态，需要在配置里显式记录，不能默认开启。

吞吐方面，多视图编码器是离线瓶颈，DiT 是训练瓶颈，解码头是推理瓶颈。最小可跑版本应把三者解耦成独立进程或独立阶段，用中间产物（SLAT 缓存、采样结果缓存）连接，这样单段崩溃不会拖垮整条管线。常见崩溃点按出现频率排：

  • 坐标不一致：渲染外参与体素化坐标系不匹配，编码器输出语义错乱。
  • 稀疏布局漂移：编码器未冻结就训 DiT，速度场与推理分布错位。
  • padding 支配显存：稠密 padding 到最长序列，短样本浪费大量显存。
  • 解码头特征维度不同步：schema 改了但头没改，loss 正常、输出噪声。
  • 等值面训练/推理不一致：可微提取与快速提取数值差异未验收。
  • 时间步采样偏差：t 分布与推理积分步不匹配，采样早期发散。

每个崩溃点都应配一条自动断言，而不是靠人眼看渲染图。例如坐标一致性用重投影相关性断言，稀疏布局漂移用「冻结编码器前后 SLAT 统计量差异」断言，显存问题用「单 batch token 数上限」硬约束。

六 · 验收断言与不可照搬之处

验收要分层写，每层只依赖上一层已通过的产物。第一层是表示层：SLAT 编码-解码重建在训练视角上的一致性达标，且稀疏布局统计量（占据体素数、特征范数分布）在预期范围内。第二层是生成层：rectified flow 从纯噪声积分出的 SLAT，其解码渲染在多视角上自洽，且与训练集分布的距离在合理区间。第三层是多格式层：同一 SLAT 解出的高斯、网格、辐射场在几何上互相印证。第四层是端到端：图生/文生输入经编码器进入同一管线，输出格式可选。

不可照搬的地方要写清楚。论文的「数十 GPU 天」是 Objaverse 级大规模数据上的训练预算，小规模复现不能照搬这个量级，否则会在数据不足时过拟合；应先用合成数据或子集验证管线，再决定是否放大。SLAT 分辨率与 DiT 规模是论文消融的两个维度，但它们不是独立的：分辨率提高会改变序列长度，进而要求 DiT 规模与显存预算同步调整，照搬某一组超参到另一分辨率上会直接 OOM 或欠拟合。解码器类型的选择也不是免费的，网格头的可微等值面在训练时比高斯头贵，推理时又比辐射场头慢，多格式输出意味着要为每个头单独付训练和推理成本。

最后落在工程判断上：复现 TRELLIS 的成败不取决于能否复刻某一组超参，而取决于是否把 SLAT 当作唯一契约、把三段拆成可独立验收的模块、把分辨率与显存预算绑定成配置约束。最小可跑版本的正确形态是「小分辨率 + 小 DiT + 单头 + 分层断言」，任何一段的 loss 曲线异常都应先在表示层断言上排查，而不是直接调 DiT 的学习率。管线复杂是论文自己承认的代价，工程上的对冲手段就是把复杂度显式化为目录分层与断言清单，让每次崩溃都能定位到具体契约的破坏点。
