一 · 从图像到网格：一条被压缩成一次前向的流水线

MeshLRM 的方法骨架可以拆成四个串联的模块：图像编码器、Transformer 主干、网格参数头、可微网格提取层。四者之外还有一个不参与推理、只参与训练的可微渲染器。输入是单张或少张已标定（或规范化到统一视角）的图像，输出是一张带顶点与面片索引的网格。整条数据流的关键在于：Transformer 不预测三平面、不预测高斯，而是直接预测一张隐式场的参数化表示，再由一个可微提取层把隐式场“硬化”成显式网格。这样，渲染损失可以穿过提取层回传到 Transformer 权重上，网格质量成为被优化的对象本身，而不是三平面提取后的副产品。

把这条流水线写成符号，就是论文给出的核心式：

$$\mathcal{M}=\mathrm{DiffMesh}(\mathrm{Transformer}_\theta(I)),\qquad \mathcal{L}=\sum_{v}\|\hat{I}_v-I_v\|^2$$

第一式说明网格 $\mathcal{M}$ 是图像 $I$ 经 Transformer 参数 $\theta$ 与可微提取算子复合的结果；第二式说明监督信号是若干新视角 $v$ 上的渲染图像误差。注意这里没有显式的 3D 监督项——没有真值网格的倒角距离，没有 SDF 回归。几何正确性完全由“渲染出来像不像”间接约束，这是 MeshLRM 与经典 SDF 回归方法在监督结构上的根本差别，也是它训练困难的根源。

逐段看数据流。图像先经 ViT 类编码器切成 patch token，与相机参数 token 拼接；Transformer 主干做跨视图注意力，把多视图证据融合进一组隐式场查询 token；网格参数头把这些 token 解码成提取层所需的量——在 FlexiCubes 路线下是每个网格单元的 SDF 值与一套可学习的顶点偏移权重，在 DMTet 路线下是单元顶点坐标与 SDF。提取层据此解出等值面，得到顶点、面片与拓扑。最后，可微光栅化器用预测网格渲染出多张新视角图，与真值图比对，梯度沿“渲染→提取→参数头→主干→编码器”整条链回传。

这条链上每一步都必须可微，否则梯度断流。图像编码与 Transformer 天然可微；参数头是线性层，可微；难点集中在提取层——等值面提取本质上是离散决策（哪个单元产生三角形、顶点连到哪个邻居），朴素实现不可微。MeshLRM 的方法贡献因此不在主干网络的新颖性，而在于把“离散拓扑决策”改写成“连续参数上的可微函数”，让渲染损失能穿透它。这是理解整篇论文的支点：架构的复杂度几乎全部堆在输出层，而不是骨干。

二 · 可微网格提取层：把离散拓扑写成连续函数

提取层的任务是把隐式场变成网格，同时保留对隐式场参数的梯度。以 FlexiCubes 为代表的做法是：把空间划分成规则网格单元，每个单元八个角点各带一个 SDF 值，另带一组权重系数用于在单元内部放置顶点。对每个单元，先判断符号变化（等值面是否穿过），再根据角点 SDF 的线性插值确定顶点位置，并根据权重把顶点“拉”向单元内的不同位置，最后按预设的查表规则连接相邻单元的顶点形成三角形。整个过程写成伪代码思路大致是：

  • 对每个单元 $c$：读取八角点 SDF $s_0,\dots,s_7$ 与权重 $w$；
  • 由 $s_i$ 的符号组合确定该单元是否活跃，活跃单元按插值公式算出面上交点；
  • 用 $w$ 对交点做加权组合，得到单元内的唯一顶点位置；
  • 相邻活跃单元的顶点按拓扑查表连接，输出顶点表与面片索引表；
  • 所有位置量对 $s$ 与 $w$ 的偏导在解析上可写，反向传播时按链式法则累加。

关键在于“符号判断”这一步。符号函数本身不可微，工程上的处理是把符号决策当作前向的离散选择，反向时只对位置量求导，符号变化处梯度截断或用直通估计近似。这意味着拓扑一旦在前向中被确定，反向传播无法修改“这里该不该有面片”，只能修改“已有面片的位置”。这正是 MeshLRM 训练困难的机制性来源：拓扑错误无法被渲染损失直接纠正，只能靠参数缓慢漂移让符号翻转，而符号翻转是阶跃式的，梯度不提供方向。

提取分辨率的代价是立方级的。规则网格单元数随分辨率的三次方增长，每个单元要存八个 SDF 与一组权重，显存占用与提取耗时都按 $O(N^3)$ 膨胀。把分辨率从粗到细提升一档，单元数变成八倍，可微光栅化的三角形数也随之上升。论文把“网格分辨率”列为消融维度之一，正是因为它是提取层最直接的质量—代价旋钮：分辨率不足时细薄结构（如叶片、栏杆）会丢失或被合并；分辨率提高则训练显存与时间迅速不可承受。这是 MeshLRM 分辨率限制局限的技术根源，而不是主干网络的容量问题。

一个具体例子可以说明提取层的行为：输入一张椅子图，Transformer 输出的隐式场在椅腿处给出细长的符号变化带。粗分辨率下，相邻两根椅腿落入同一单元，提取层只能给出一个合并的粗腿，拓扑上腿与腿之间没有空隙；提高分辨率后，两腿分处不同单元，各自生成独立的面片链，拓扑才正确。渲染损失在粗分辨率下看到的是“腿变粗”，梯度会推动 SDF 向外扩张以匹配轮廓，却无法把合并的腿分开——这解释了为什么单纯调损失权重不能修复拓扑，必须动提取分辨率或提取方法。

三 · 主干与参数头：跨视图融合与隐式场的条件化

Transformer 主干的职责是把图像证据转成一组能条件化隐式场的 token。图像编码器输出每张图的 patch token，相机参数（内参、外参或规范化后的位姿编码）作为额外 token 注入，主干用自注意力在视图内与视图间做信息交换。多视图输入时，跨视图注意力让不同视角的 patch 互相对齐，把被遮挡区域的几何从其他视角的证据中补出来；单视图输入时，主干只能依赖图像内的单目线索与训练分布中的先验，几何的背面完全由先验填充。论文把“输入视图数”列为消融维度，正是因为视图数直接决定跨视图注意力能提供多少几何约束：视图越多，背面与遮挡区的歧义越小，但输入 token 序列变长，注意力代价按序列长度平方增长。

参数头把主干输出的查询 token 解码为提取层所需的两类量：SDF 值与顶点偏移权重。这里有一个设计上的取舍：SDF 是连续标量场，头可以逐单元回归；顶点权重是单元内的局部自由度，头需要为每个活跃单元输出一组系数。两者共享同一组 token，意味着主干必须在同一表征中同时编码“表面在哪”与“顶点该放在单元内何处”。这种耦合让训练信号更集中，但也让参数头的输出维度随提取分辨率线性增长——分辨率翻倍，头输出的通道数或查询数随之翻倍，这是主干侧唯一随分辨率膨胀的部件。

一个具体的失败模式是“先验压倒证据”。当输入视图很少且视角偏离训练分布时，跨视图注意力没有足够证据，主干的输出退化为训练集平均形状的插值：渲染损失在新视角上仍然不高（因为平均形状在常见视角下轮廓合理），但网格的细节与输入图不符。这种失败不会在渲染指标上暴露，却会在下游使用时暴露——网格进引擎后，用户旋转视角即见形变。这是纯渲染监督的固有盲区：损失只约束“看起来像”，不约束“几何是”。MeshLRM 用网格正则（如拉普拉斯平滑、法向一致性）缓解，但正则只能抑制极端形变，不能替代 3D 监督。

四 · 渲染监督与训练回路：梯度如何穿过提取层

训练回路的中心是可微渲染器。给定预测网格与一组新视角相机，光栅化器把三角形投影到图像平面，按深度排序做可见性判断，再对每个像素做重心坐标插值取属性（初始阶段是几何法向或占位颜色），输出渲染图 $\hat{I}_v$。损失是渲染图与真值图之间的平方误差，按论文给出的形式对所有视角求和。梯度从像素误差出发，经光栅化的重心坐标插值回传到三角形顶点位置，再经提取层的解析偏导回传到单元 SDF 与权重，最后经参数头与主干回到编码器。整条链上没有任何不可微的离散采样——这是可微光栅化相对光线步进渲染的优势：后者在可见性判断上也有离散性，前者把可见性写成软排序或直通近似。

训练数据是 Objaverse 的多视图渲染。每个资产被渲染成若干视角图，训练时取其中一张或几张作为输入，其余作为监督视角。这个设置的关键是输入与监督视角的分离：模型不能靠“记住输入像素”降低损失，必须在隐式场中重建几何才能在新视角上正确渲染。训练耗时以数天计，推理则是一次前向加一次提取，无需逐资产优化——这是前馈大重建模型相对 per-asset 优化的核心优势，也是 MeshLRM 能与 GS-LRM 并列成为“前馈 3D 大模型”两种输出形态的前提。

训练难的具体机制有三层。第一层是拓扑的阶跃性：符号翻转不提供梯度方向，拓扑错误只能靠参数漂移偶然修复，收敛慢且不稳定。第二层是提取层与渲染器的双重离散近似：提取层的直通估计与光栅化的软可见性都引入梯度偏差，偏差累积会让主干学到“讨好渲染器”而非“正确几何”的表征。第三层是分辨率与显存的矛盾：高分辨率提取才能表达细拓扑，但高分辨率下单元数与三角形数暴涨，批量被迫减小，梯度噪声增大，训练更不稳。论文把“训练难”列为局限，对应的正是这三层机制，而不是一句笼统的“难训”。

一个具体例子说明梯度回传的实际路径：输入一张带细栏杆的桌子图，初始隐式场把栏杆糊成一片。渲染损失在侧视角上看到栏杆区域过亮（因为糊片挡住了背景），梯度推动该区域 SDF 向负（实心）方向移动，糊片变厚而非变细。只有当提取分辨率足够高、单元能分辨单根栏杆时，梯度才能分别作用于每根栏杆的符号，让空隙出现。这说明渲染监督的有效性依赖提取层的表达能力：提取层分辨不出的结构，渲染损失也修不了。工程判断因此是：先定提取分辨率，再谈损失设计与主干容量。

五 · 模块分工与系统代价：谁负责什么，代价落在哪里

把四个模块的分工列成表，能看清质量与代价的归属。

模块输入输出负责的质量维度主要系统代价
图像编码器单图/少图patch token证据提取、视角对齐随视图数线性增长
Transformer 主干token + 相机编码隐式场查询 token跨视图融合、先验填充注意力随序列长度平方增长
网格参数头查询 tokenSDF + 顶点权重表面位置、单元内顶点布局随提取分辨率线性增长
可微提取层SDF + 权重顶点表、面片索引拓扑正确性、细结构分辨随分辨率立方增长，显存与耗时
可微渲染器网格 + 新视角渲染图监督信号、梯度通路随三角形数增长，仅训练期

这张表揭示了一个不对称：质量的关键维度（拓扑、细结构）几乎全部由提取层决定，而系统代价的大头也在提取层。主干与编码器的代价随视图数与序列长度增长，但那是可预测的、平滑的；提取层的代价是立方级的，且与质量强耦合，调分辨率就是同时调质量与可行性。这解释了为什么论文的消融把“提取方法”与“网格分辨率”放在最前面：它们不是超参数微调，而是决定系统能否成立的结构性选择。

另一个分工上的事实是纹理。MeshLRM 输出的是几何网格，纹理需要后处理——论文把“纹理后处理”列为局限。机制上，渲染监督在几何阶段只约束形状轮廓与法向一致性，颜色属性要么用占位色，要么在几何收敛后另起一轮优化或投影。这意味着 MeshLRM 的一次前向给出的是可用拓扑与几何，不是带贴图的成品资产；进引擎前还需 UV 展开与纹理烘焙。这与 GS-LRM 形成对照：高斯输出自带颜色，渲染即成品，但无法直接进传统引擎的网格管线。两条路线的分工因此不是“谁更好”，而是“输出形态决定下游管线”：要引擎原生资产选网格路线并接受纹理后处理，要即时渲染质量选高斯路线并接受格式转换。

失败模式的系统层面还有一个：提取层与渲染器的分辨率不匹配。若渲染分辨率远高于提取分辨率，细结构在渲染图中表现为锯齿或空洞，损失把这些伪影当作几何误差回传，推动 SDF 在错误位置振荡；若渲染分辨率远低于提取分辨率，细拓扑在监督中不可见，提取层的高分辨率白费。工程上两者需要匹配到同一尺度，这是训练配置里不写在论文公式中、却决定收敛的实际约束。

最后落到一个工程判断上：MeshLRM 的方法总览说明，前馈出网格的可行性不取决于主干多大，而取决于提取层能否把离散拓扑写成可微函数、以及分辨率与显存的平衡点落在哪里。可微网格提取因此从一个小众组件变成前馈模型的标准输出层——它把“网格质量”从事后提取的运气变成训练时被优化的目标，代价是训练回路的稳定性与立方级的系统开销。这条流水线的每一步都可微，但可微不等于可训；真正的工程难点在符号翻转处的梯度断流与分辨率旋钮上的质量—代价曲线。
