一 · 对比的坐标系：四条轴与三个对手

把 Hunyuan3D 2.1 放进对照实验，先要固定坐标系。这篇论文的基线只有三个：Hunyuan3D 2.0、SF3D、TRELLIS。它们不是同一类方法，因此逐项对比必须拆成四条互相独立的轴，否则表格会变成无意义的排名。第一条轴是表示：输出是网格顶点色、基础颜色贴图，还是带反照率/粗糙度/金属度三通道的 PBR 材质；第二条轴是监督：训练信号来自多视图 RGB 重建、多视图 PBR 真值，还是可微渲染回传的光照一致性；第三条轴是速度与显存：单资产端到端耗时与峰值显存占用；第四条轴是失败模式：在什么输入下会崩、崩成什么样。

这四条轴之所以不能合并成一个分数，是因为它们之间存在结构性 trade-off。PBR 分支把纹理阶段从「一张图」变成「三张图加一次 UV 融合加一次可微渲染」，表示能力提升的同时，监督链路变长、显存占用变高、推理变慢。Hunyuan3D 2.0 是同一形状骨干的前代，因此它与 2.1 的对比是受控对比：形状分支完全一致，差异只在材质阶段，这使「PBR 带来的增益」与「形状带来的增益」可以被分离。SF3D 走的是另一条路线，它同样以生产级材质为目标，是 2.1 在「PBR 完整性」这条轴上的直接同代参照。TRELLIS 则代表结构化表示路线，它的强项在几何表示的通用性与多格式输出，材质通道的完整度不是它的主战场。把这三者放在一张表里，正确的读法是「每条轴上谁赢、赢的代价是什么」，而不是「谁总分高」。

对照实验的设计上，论文使用的数据是 Objaverse 加内部 PBR 资产。这个数据构成本身就是一个对比变量：Objaverse 提供规模与多样性，内部 PBR 资产提供带真实粗糙度/金属度标注的监督信号。任何只在 Objaverse 上训练的方法，在 PBR 通道上都会面临真值缺失，这是 SF3D 与 2.1 之间可比性的边界，也是读表时必须标注的前提。

二 · 表示轴：三通道 PBR 与「一张基础色」的差距

表示轴的差异不是「多两张图」这么简单。Hunyuan3D 2.0 输出基础颜色纹理，进入引擎后，材质系统只能把它当作 albedo 使用，粗糙度与金属度要么取全局默认值，要么由美术手工补。物理正确的渲染要求这三个通道逐像素一致，因为着色方程里它们进入不同的项：反照率进入漫反射项的乘子，粗糙度决定微表面分布的宽度，金属度决定漫反射与镜面反射的能量分配。缺少任一通道，重光照时高光的位置与强度都会错。

2.1 的表示是「多视图 PBR 扩散 + UV 空间融合」：先在多视图上分别扩散出反照率、粗糙度、金属度，再把它们融合进 UV 空间，得到一张完整的三通道贴图。这个流程的关键在于三个通道必须在同一 UV 参数化下对齐，否则融合后的贴图在接缝处会出现通道错位——反照率连续而粗糙度跳变，渲染出来就是一条亮边。SF3D 同样输出 PBR 通道，但它走的是单次前向直接回归材质参数的路线，表示上更紧凑，代价是对多视图一致性的依赖方式不同。TRELLIS 的表示以结构化潜变量为核心，材质通道是附加输出，完整度取决于其解码头的设计。

$$\mathcal{L}_{\mathrm{PBR}}=\sum_{v}\left\|\hat{\mathbf{a}}_v-\mathbf{a}_v\right\|^2+\left\|\hat{r}_v-r_v\right\|^2+\left\|\hat{m}_v-m_v\right\|^2$$

这条损失直接体现了表示轴：监督是逐视图、逐通道的 L2，三个通道权重相同。它的问题在于，L2 对粗糙度这种感知上非线性、且真值标注噪声大的通道并不友好——粗糙度真值在内部资产中往往来自美术设定而非测量，标注方差大，等权 L2 会让反照率的梯度被粗糙度的噪声稀释。这是表示轴上的一个具体机制代价：通道等权监督换来了实现简单，但牺牲了通道间的信噪比平衡。工程上如果要复现并改进，按通道信噪比重新加权是第一个该动的地方。

具体例子：一个金属材质的机械零件，反照率接近中性灰，视觉信息几乎全部来自粗糙度与金属度。2.0 的输出在引擎里表现为一片均匀的灰，重光照下没有金属高光的方向性；2.1 的输出在相同光照下能给出随视角移动的高光带。这个差异不是分辨率问题，是通道缺失问题，也是表示轴上 2.1 相对 2.0 的核心增益所在。

三 · 监督轴：光照解耦与可微渲染回传

监督轴的对比要问一个问题：梯度从哪里来。2.0 的纹理阶段监督来自多视图 RGB 重建，梯度只约束「看起来像」，不约束「在给定光照下渲染出来像」。2.1 在此之上加了两层：光照解耦训练与可微 PBR 渲染监督。光照解耦的作用是把观测图像分解为「材质固有属性」与「当前光照」两部分，使材质分支学到的反照率不被训练数据里的固定光照烘焙进去；可微渲染则把渲染方程接进计算图，让渲染结果与真值图像的差异回传到三个材质通道。

可微 PBR 渲染的机制可以写成一条伪代码思路：对每个视图，取预测的三通道材质与已知或估计的法线、光照参数，走一遍着色方程得到渲染图，再与观测图算损失，梯度经渲染方程回传到材质贴图。这条链路的代价是显存：渲染过程需要保留中间量（法线、光照、BRDF 项）以支持反向传播，显存占用随视图数与分辨率线性增长。这是 2.1 推理与训练都慢于纯回归方法的直接原因之一。

SF3D 的监督更偏向直接回归加渲染一致性约束的组合，它的链路短，因此速度快，但对光照解耦的依赖方式不同——如果训练数据的光照分布窄，回归出的材质会把光照烘焙进反照率。TRELLIS 的监督以其结构化表示的重建为主，材质通道的渲染监督强度取决于其训练配方。三者对比下来，2.1 的监督是最「重」的：多视图 PBR 真值加渲染回传加解耦，换来的是重光照表现优于基础色模型这一结果，代价是训练与推理成本。

失败模式在这里很具体：光照解耦不彻底时，反照率会残留训练光照的方向性，表现为在引擎里换一个光照方向后，模型表面出现固定的明暗块，像是贴图里画了阴影。消融实验里对光照解耦的检查正是针对这一点——去掉解耦，重光照表现退化。这是监督轴上最该被工程复现清单捕获的断言：换光照后不应出现与几何无关的固定明暗结构。

四 · 速度与显存：数十秒推理的成本结构

速度轴上，2.1 的端到端推理是数十秒量级。这个数字要拆开看：形状 DiT 沿用 2.0，其耗时与前代相同；增量全部来自 PBR 分支——多视图扩散要对每个视图跑三个通道，UV 融合要做一次空间补全，可微渲染若在推理阶段用于自检或精修则再加一段。因此 2.1 相对 2.0 的减速比例，等于 PBR 分支耗时除以形状分支耗时，这个比例随视图数与贴图分辨率上升。

显存轴同理。形状分支的显存占用与 2.0 一致；PBR 分支的峰值出现在两处：多视图扩散的批处理（视图数 × 通道数 × 分辨率）与 UV 融合的特征图。可微渲染在训练时是显存大头，推理时若关闭则显存回落。这给出一条工程判断：在显存受限的部署里，把 PBR 分支的视图数或贴图分辨率降一档，是比削减形状分支更划算的取舍，因为形状质量对下游观感的影响更直接。

五 · 失败模式的逐项对照与验收断言

失败模式必须逐项对照，因为它们的触发条件不同，工程上的防御手段也不同。2.1 的第一类失败是 UV 展开失败：几何的非流形边、薄壁结构、高亏格拓扑都会让参数化出现重叠，表现为贴图接缝处的通道错位或局部拉伸。第二类是数据限制：内部 PBR 资产的覆盖范围决定了模型在未见材质类别上的通道偏差，比如透明或各向异性材质不在三通道表示内，模型只能给出近似。第三类是推理慢，在批量管线里成为吞吐瓶颈。

SF3D 的失败模式集中在监督侧：训练数据光照分布窄时，反照率会烘焙进光照，换光照后出现固定明暗块。TRELLIS 的失败模式在材质通道完整度上，取决于其解码头是否对三通道都做了充分监督。2.0 的失败模式最简单：没有 PBR，任何重光照需求都不满足。

逐项对照的价值在于给出可执行的验收断言。对 2.1：换三组不同方向的光照渲染同一资产，检查反照率通道是否出现与几何无关的固定明暗结构（光照解耦断言）；检查 UV 接缝两侧的粗糙度与金属度是否连续（UV 融合断言）；检查金属度通道在非金属材质上是否接近零（通道语义断言）。对 SF3D：同样的换光照检查，重点看反照率的光照残留。对 TRELLIS：检查三通道是否都存在且语义正确。这些断言不依赖具体数字，只依赖机制，因此可以在没有真值的情况下跑。

具体例子：一个薄壁外壳的输入图像，2.1 的 UV 展开在薄壁两侧产生重叠，融合后薄壁内表面与外表面共享同一片 UV 区域，粗糙度通道被平均，渲染时内表面出现外表面的高光。这是 UV 失败的典型表现，也是验收断言要捕获的：薄壁结构的 UV 重叠检查应作为几何预处理的门槛，而不是等渲染出来再发现。

六 · 决策表：按需求选方法

把四条轴收拢成一张决策表，读法是「先定需求，再选方法，再看代价」。需求维度有三个：是否需要重光照与进引擎（决定表示轴）、是否有带 PBR 真值的训练数据（决定监督轴的可比性）、吞吐与显存预算（决定速度轴）。

这张表的工程判断落在最后一行：2.1 的 UV 失败不是偶发噪声，而是几何到参数域映射的结构性风险，因此决策表把「输入几何质量」单列为一个前置条件。这与速度、显存这些可调参数不同——UV 失败不能靠降分辨率解决，只能靠几何预处理或换方法。SF3D 的直接回归路线绕开了 UV 融合，因此在薄壁几何上风险更低，但它把风险转移到了光照残留上。两条路线不是谁替代谁，而是失败模式不同、适用几何不同。

最后落在机制上：2.1 相对 2.0 的增益来自表示与监督两条轴的同时升级，而它的代价集中在 UV 融合与可微渲染这两处具体机制上——前者是几何参数化的失败面，后者是显存与速度的成本面。对照实验的正确用法不是给方法排序，而是把每条轴上的赢家与它的代价配对，然后在自己的管线里检查那个代价是否可接受。决策表的每一行都是一次这样的配对检查。
