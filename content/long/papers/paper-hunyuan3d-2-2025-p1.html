一 · 一个具体的失败现场：为什么“能出模型”不等于“能交付资产”

设想一个典型的生产流程：美术团队接到一批道具需求，要求每个资产带 2K 级 UV 贴图、几何边缘干净、能直接进引擎。团队拿一个当时主流的前馈 3D 生成模型跑了一批结果，形状看起来“像那么回事”，但把网格导入 DCC 工具后问题立刻暴露：表面是糊的，倒角被抹平，细小结构（铆钉、缝线、刻痕）在生成阶段就被平滑掉了；更致命的是没有可用的纹理——模型要么输出顶点色，要么输出一张分辨率极低、接缝错位的贴图。美术只能手工重拓 UV、重画贴图，等于把生成结果当成了概念参考，而不是资产。这个场景不是个别案例，它精确对应论文背景里那句判断：前馈模型多输出无纹理或低分辨率纹理，而工业资产需要高分辨率几何加纹理。痛点的本质不是“生成得不像”，而是“生成管线与资产管线不兼容”。

要理解为什么非改不可，得先看清当时主流做法的结构性缺陷。以 LRM 一类的前馈模型为代表，做法是从单张或少量图像直接回归一个三平面（triplane）或隐式特征，再解码出带颜色的网格。这条路线把几何与外观压进同一个特征场，用同一个网络、同一次前向同时决定“形状长什么样”和“表面是什么颜色”。Direct3D 一类工作进一步引入显式监督，但依然维持单阶段、单目标的骨架。TRELLIS 则把结构表示做得更规整，用结构化潜变量支撑生成，但在“高分辨率几何 + 高分辨率纹理”这一交付标准上仍然留有缺口。这些模型共同的工程后果是：分辨率的提升被耦合在一个瓶颈里，几何精度和纹理精度互相挤占容量，谁都无法单独 scaling。

把这种耦合写成机制层面的描述会更清楚。单阶段模型通常优化一个联合目标，形如对渲染图像的重建误差加上几何正则：

$$\mathcal{L}_{\text{joint}}=\sum_{v}\|\hat{I}_v(\theta)-I_v\|^2+\lambda\,\mathcal{L}_{\text{geo}}(\theta)$$

这里 $\theta$ 是共享的隐式场参数，$\hat{I}_v$ 是从该场渲染出的第 $v$ 个视图。问题在于，渲染误差对几何的约束是“视角相关”的：一个在轮廓上足够接近的粗糙表面，可以在多视图 L2 意义下拿到很低的损失，而真正的几何细节（曲率突变、薄壁、凹槽）对像素损失的贡献极小。于是优化器自然倾向于把容量分配给外观一致性，几何细节被当作噪声平滑掉。这就是“表面糊”的数学来源，而不是数据不够。

系统代价体现在三个具体环节。其一是分辨率：三平面或体素特征的存储随分辨率呈立方或平方增长，把分辨率翻倍意味着特征张量规模急剧上升，而单阶段模型必须同时承载几何与纹理两套信息，显存与算力预算被迅速吃满。其二是 UV：单阶段模型不显式建模 UV 参数化，纹理往往以顶点色或投影形式附着，无法导出为标准贴图，进引擎前必须重拓。其三是失败模式不可分离：当输出质量不达标时，工程师无法判断是几何分支欠拟合还是纹理分支欠拟合，调参只能整体重训，迭代成本高。论文把这一局面归纳为一个明确的问题：如何把形状生成与纹理生成解耦，各自 scaling，输出高分辨率带纹理的 3D 资产。

二 · 两个目标函数根本不同：几何要的是精度，纹理要的是感知

解耦的第一性理由不是工程便利，而是两个任务的监督信号在数学形态上就不一样。几何生成的目标是得到一个符号距离场或网格，其监督可以落在 SDF 值本身，也可以落在渲染出的轮廓与深度上；这类监督对“位置误差”敏感，是可度量的、接近确定性的。纹理生成的目标是得到一个 UV 贴图，其监督只能通过渲染回到图像空间，本质上是多视图图像的重建。论文给出的纹理损失正是这一形态：

$$\mathcal{L}_{\mathrm{tex}}=\sum_{v}\|\hat{I}_v-I_v\|^2$$

其中 $\hat{I}_v$ 是把当前 UV 贴图投影到第 $v$ 个视角后渲染出的图像，$I_v$ 是该视角的参考图。这个损失对纹理的约束是“感知性”的：同一块表面在不同视角下被采样多次，接缝处的连续性、高频细节的统计特性、光照烘培的合理性，都无法被逐像素 L2 完整表达。把这两个目标塞进一个网络，等于要求同一组参数同时优化一个近似确定性的几何回归和一个高度欠定的图像重建，梯度方向会互相干扰。论文的整体训练目标写成两项相加的形式：

$$\mathcal{L}=\mathcal{L}_{\mathrm{shape}}+\lambda\mathcal{L}_{\mathrm{tex}}$$

这个式子的工程含义是：$\lambda$ 不是随便调的超参，而是两个阶段解耦程度的体现。当形状与纹理共享同一骨干时，$\lambda$ 必须很小才能不让纹理梯度破坏几何，结果是纹理学不好；当两者独立训练时，$\lambda$ 退化为组合权重，两个分支可以各自用最适合自己的学习率、分辨率和数据配比。这就是“独立 scaling”的实质：不是把模型做大，而是让两个目标各自拥有独立的容量预算与优化轨迹。

具体机制上，形状分支采用 VecSet 表示加扩散模型加 DiT 骨干，输出 SDF，再用 Marching Cubes 提取网格。VecSet 的关键作用是绕开稠密体素或三平面的立方增长：它用一组无序的潜向量集合表达表面，分辨率提升体现为集合规模与解码精度的提升，而不是特征网格的维度爆炸。纹理分支则走多视图扩散加 UV 投影：先在多视图空间生成一致的图像，再把多视图颜色反投影、融合到 UV 域，输出纹理贴图。两个分支共享图像条件（同一张参考图），但独立训练。这个“共享条件、独立参数”的结构，正好对应上面那个加法式损失：条件一致保证了几何与纹理在语义上对齐，参数独立保证了两者不互相拖累。

失败模式也随之被分离。几何分支的典型失败是过度平滑与薄结构丢失，可以通过提高 VecSet 规模、增加 SDF 监督密度来定位和修复；纹理分支的典型失败是 UV 展开失败与接缝错位，属于参数化环节的问题，与几何精度无关。论文在局限里明确列出纹理真实感受数据限制、UV 展开有失败、推理较慢，这三条恰好分别落在数据、参数化、算力三个不同的工程环节上——如果仍是单阶段模型，这三类问题会混在一起，无法归因。

三 · 单阶段路线在分辨率上的硬墙：为什么“再大一点”救不了

把分辨率问题拆开看，会发现单阶段模型的瓶颈不是模型容量不够，而是表示与监督的错配。以三平面为例，特征存储量随平面分辨率 $R$ 呈 $O(R^2)$ 增长，若再叠加多级金字塔则更高；体素表示则是 $O(R^3)$。当 $R$ 从训练时的中等分辨率提升到工业所需的精细分辨率，特征张量规模上升一个量级，而单阶段模型还要在同一张量里编码颜色与材质。工程上的直接后果是：要么降 batch size 导致训练不稳定，要么截断分辨率导致细节丢失。论文选择 VecSet 正是为了切断这条立方增长曲线，让形状分支的分辨率提升不再以特征网格的维度爆炸为代价。

更隐蔽的问题是监督信号的采样密度。渲染损失在多视图下对几何的约束是稀疏的：每个视图只覆盖表面的一部分，薄壁与凹槽在多数视角下不可见或被自遮挡。单阶段模型没有显式的 SDF 监督来补齐这些区域，只能依赖隐式场自身的平滑先验，结果就是“看不见的地方就糊”。形状分支把 SDF 监督与渲染监督并用，等于给几何提供了与视角无关的稠密约束，这是解耦带来的直接收益，而不是单纯把网络加深。

纹理侧的分辨率问题则是另一套机制。多视图扩散生成的是各视角的二维图像，其分辨率受限于图像生成模型的能力；要把这些图像变成一张高分辨率 UV 贴图，必须经过反投影与融合。融合的质量取决于 UV 参数化是否把表面切成足够均匀的图块，以及接缝处是否有重叠采样。论文把 UV 展开列为失败模式之一，说明这一步不是自动可靠的：当几何存在细长结构或高曲率区域时，展开算法可能产生拉伸或重叠，反投影后的纹理会在此处出现接缝错位。这个失败与几何分支无关，是纹理管线自身的参数化问题——再一次说明两个阶段必须分开归因、分开修复。

用一个具体例子把这条硬墙讲实：一个带细密刻线的金属件，单阶段模型在中分辨率下能把整体轮廓和大致颜色做对，但刻线在渲染损失里只占极少的像素，优化器不会为它分配容量；把模型放大一档，刻线仍然糊，因为瓶颈在监督密度而非参数量。而在两阶段管线里，形状分支的 SDF 监督会在刻线处产生局部梯度，VecSet 的集合规模提升可以直接承载这些局部变化；纹理分支则在多视图里把刻线的明暗对比生成出来，再投影到 UV。两个阶段各自解决自己那一半问题，这就是“独立 scaling”在具体资产上的体现。

四 · 数据与训练预算的现实约束：为什么必须解耦才能喂得动

论文的训练事实里有两条对工程判断很关键：形状与纹理分开训练，形状用 SDF 监督加渲染，纹理用多视图渲染，数据规模大，训练消耗数十 GPU 天，推理数十秒。把这组事实放回单阶段假设下推演，会发现解耦不是偏好而是必需。单阶段模型若要同时学好几何与纹理，需要每个训练样本同时提供精确几何与高质量多视图图像；而现实数据里，精确几何（SDF 或干净网格）与高质量纹理的联合标注是稀缺的，大量资产只有网格没有贴图，或只有渲染图没有干净拓扑。单阶段训练被迫在“有几何无纹理”和“有纹理无干净几何”的样本之间做取舍，任何一边的噪声都会污染共享参数。

解耦之后，两个分支可以各自吃自己那一种数据。形状分支只需要几何监督，纹理分支只需要多视图渲染监督，数据配比可以独立调整。这就是论文所说“大规模数据”能够被实际利用的前提：不是数据总量变多，而是每一份数据都能被送到需要它的分支。系统代价是管线变长：两个分支各自训练、各自调参、各自维护检查点，最后还要做合成。数十 GPU 天的预算被拆成两份，单看每一份的训练成本可控，但总体工程复杂度上升，合成环节引入新的失败面（几何与纹理的对齐、UV 与网格的拓扑一致性）。这是解耦的显式代价，论文没有回避，而是把它列为推理较慢与 UV 失败的一部分。

训练目标的组合方式也反映了这一约束。$\mathcal{L}=\mathcal{L}_{\mathrm{shape}}+\lambda\mathcal{L}_{\mathrm{tex}}$ 在解耦实现里不是一次前向的联合反传，而是两个分支各自优化后的组合评估；$\lambda$ 的作用从“平衡梯度”变成“平衡两个已训练分支在合成时的权重”。这个细节决定了工程上的一个判断：当最终资产纹理偏弱时，正确的动作是回到纹理分支检查多视图一致性与 UV 融合，而不是去动形状分支的学习率。单阶段模型没有这个自由度，它只有一个全局损失，任何局部缺陷都只能靠整体重训来赌。

五 · 基线对照下的缺口定位：缺口在“交付形态”，不在“像不像”

论文给出的基线是 TRELLIS、Direct3D、LRM，数据集是 Objaverse 与内部资产，结论是高分辨率几何加纹理、工业可用性优于同期开源模型。把这组对照放回问题现场，可以精确指出旧路线的缺口位置。LRM 类模型证明了前馈生成可行，但输出形态是带顶点色的网格或低分辨率隐式场，无法直接导出 UV 贴图；Direct3D 引入显式几何监督改善了形状，但没有解决纹理的参数化问题；TRELLIS 的结构化表示提升了生成稳定性，但在“高分辨率几何与高分辨率纹理同时到位”这一交付标准上仍有距离。三者的共同点是：它们优化的是“生成得像”，而工业资产要求的是“能进管线”。

这个缺口可以用一个交付检查表来定位，而不需要任何实验数字。检查项包括：网格是否有干净拓扑与合理面数；是否有非重叠、低拉伸的 UV；贴图分辨率是否达到资产规范；接缝处颜色是否连续；几何细节是否在目标分辨率下可辨。单阶段模型在前两项上系统性失分，因为 UV 参数化不是它的优化目标；在后三项上则受限于联合容量的挤占。两阶段管线把前两项交给形状分支与显式 UV 展开，把后三项交给纹理分支的多视图生成与投影融合，每一项都有独立的负责环节。论文的消融包含形状/纹理分离、VecSet、分辨率三项，正好对应这条检查表上的三个关键决策：分离决定交付形态，VecSet 决定几何分辨率上限，分辨率决定纹理细节能否落地。

需要强调的是，这个缺口不是靠把模型做大能填上的。单阶段模型扩大参数会同时提升几何与纹理的拟合能力，但 UV 参数化仍然缺失，交付形态不变；而工业管线对 UV 的要求是硬性的，没有 UV 就没有贴图，没有贴图就没有材质，资产无法进入渲染与引擎。这就是“非改不可”的工程判断：问题不在生成质量的上限，而在输出接口的缺失。Hunyuan3D 2.0 的两阶段设计本质上是在补这个接口——形状分支输出可提取网格的 SDF，纹理分支输出 UV 贴图，合成后得到的是符合资产规范的交付物，而不是一张好看的渲染图。

把这条判断落到具体机制上：纹理分支的 UV 投影不是事后处理，而是生成目标的一部分，多视图图像在训练时就被约束为同一表面在不同视角下的一致观测，投影融合才有意义；形状分支的 Marching Cubes 提取也不是事后处理，SDF 的零等值面在训练中就被 SDF 监督约束，提取出的网格才具备可展开的拓扑。两个“事后处理”被提前进训练目标，这是解耦管线与“先生成再修补”的拼接方案的本质区别，也是它能把开源 3D 生成推到工业级的机制根源。
