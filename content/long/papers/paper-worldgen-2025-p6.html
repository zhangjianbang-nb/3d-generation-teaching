一 · 复现边界：把论文拆成可独立验收的四个子系统

WorldGen 的系统级公式 $$\mathcal{W}=\mathrm{Compose}\!\left(\mathrm{Layout}_{\mathrm{LLM}}(t),\mathrm{Terrain}_{\mathrm{proc}},\{\mathrm{Gen}(o_i)\}\right)$$ 在复现时最容易被误读成一条流水线。实际上它是四个可以独立运行、独立验收、独立失败的子系统：LLM 布局推理、程序化地形、扩散物体生成、object-aware 分解与组合。复现的第一条工程判断是：不要试图端到端跑通，而是先让每个子系统在给定输入下产出可检查的中间产物，再谈拼接。论文明确说明这是系统级组合而非单一端到端训练，LLM、程序化、扩散模型各自预训练，这意味着复现者面对的是四个异构模型/模块的接口对齐问题，而不是一个统一 loss 的收敛问题。

最小可跑版本（MVP）的定义必须写死：输入一段文本描述，输出一个能被引擎加载、角色能在其中行走、至少有一个可交互物体的世界。MVP 不要求资产精美，不要求布局多样，但要求四个子系统都真实参与，否则复现退化成“程序化地形 + 随机摆件”，无法验证论文声称的组合路线。验收断言按子系统切分：布局子系统断言输出是结构化场景图而非自由文本；地形子系统断言高度场连续且可行走坡度在阈值内；物体子系统断言每个物体有独立的 mesh 与包围盒；组合子系统断言物体与地形无穿插、物体间无重叠。每条断言都要能在无人工目视的情况下自动判定，这是复现与 demo 的分界线。

失败模式在边界处最集中。LLM 输出的场景图字段缺失或单位不一致（米与厘米混用）会让下游程序化地形按错误尺度铺开；扩散模型生成的物体 mesh 朝向不统一会让 object-aware 分解的放置阶段出现整体旋转错位；程序化地形与物体放置共用同一坐标系但原点约定不同，会导致物体悬空或埋入地面。这些都不是模型能力问题，而是接口契约问题。复现时把每个接口的坐标系、单位、朝向约定写成显式契约文档，比调参更能决定成败。

二 · 目录结构：按中间产物而非按模型划分

推荐的目录结构以中间产物为中心，而不是以模型代码为中心。这样每个阶段的输出都是可落盘、可回放、可单独替换的文件，符合论文“输出可编辑”的定位。一个可用的骨架如下：

  • configs/：全局配置，含坐标系约定、单位、坡度阈值、物体数量上限、随机种子。
  • stage1_layout/：LLM 布局推理。输入 prompt 模板与文本，输出 scene_graph.json（区域、物体类别、数量、相对位置、尺度提示）。
  • stage2_terrain/：程序化地形。输入场景图的区域划分，输出高度场、材质分层、可行走区域掩码。
  • stage3_objects/：扩散物体生成。输入物体类别与尺度提示，输出每物体的 mesh、纹理、包围盒、朝向。
  • stage4_compose/：object-aware 分解与放置。输入前三阶段产物，输出带变换矩阵的场景描述与引擎导出文件。
  • assets/：缓存目录，按内容哈希命名，保证同一物体类别复用同一资产，避免重复采样。
  • asserts/：验收脚本，每个子系统一个，输出结构化报告而非打印日志。

这个划分的关键在于 assets/ 的内容寻址缓存。扩散生成是整条链路里最贵的一步，同一类别同一尺度提示的物体应当只生成一次。缓存键由类别、尺度提示、随机种子三元组哈希得到，命中即跳过采样。系统代价在这里体现得很直接：不做缓存时，一个含数十个物体的世界会重复采样同类别物体，显存与时间按物体数量线性膨胀；做缓存后成本按类别数而非物体数增长。失败模式是缓存键设计过粗（只按类别），导致不同尺度提示的物体被错误复用，出现比例失真的资产混入场景。

另一个结构判断是把配置与代码分离。configs/ 里的坐标系约定必须被所有四个阶段读取同一份，而不是各阶段各自硬编码。工程上常见的崩溃点是地形阶段用 Z 轴向上、物体阶段用 Y 轴向上，组合阶段没有做转换，导出到引擎后整个世界侧翻。把轴向、单位、原点写进一份被强制加载的配置，并在每个阶段的入口做断言，能把这类错误挡在落盘之前。

三 · 数据准备：文本、场景图与资产的三层对齐

论文使用自建世界评测，这意味着复现者拿不到现成的“文本—世界”配对数据，必须自己构造输入侧。数据准备分三层：文本层、场景图层、资产层。文本层是自由描述，需要覆盖地形类型（山地、平原、河谷）、建筑密度、物体类别分布；场景图层是 LLM 布局推理的输出格式，必须有稳定的 schema；资产层是扩散模型的类别与尺度提示词表。三层之间的对齐关系是复现的核心难点：文本里说“山谷中有几座木屋”，场景图必须把它拆成地形区域（山谷）、建筑类别（木屋）、数量与相对位置，资产层必须有为“木屋”准备的类别提示与尺度范围。

场景图 schema 的最小字段集建议为：区域列表（每区域含地形类型、边界、高度范围）、物体列表（每物体含类别、所属区域、相对位置、尺度提示、朝向约束）、全局约束（可行走连通性要求、物体间最小间距）。字段缺失时的降级策略要写死：区域缺失则整图退化为单一平原；物体位置缺失则按区域内均匀采样；尺度提示缺失则用类别默认尺度。降级不是容错，而是让失败可见——降级发生时验收脚本必须记录，否则复现者会把降级产物误当作正常输出。

资产层的提示词表需要与扩散模型的训练分布对齐。论文指出资产质量参差是局限之一，复现时应把类别提示限制在扩散模型可靠生成的类别集合内，超出集合的类别走程序化替代或占位几何体。这是一个明确的工程取舍：宁可世界里有占位几何体，也不要让扩散模型在不可靠类别上产出破碎 mesh 污染组合阶段。系统代价是类别覆盖度下降，换来的是组合阶段的稳定性。失败模式是提示词表与场景图类别不一致，LLM 推理出场景图里没有对应资产的类别，组合阶段静默丢弃该物体，世界变得比文本描述稀疏，而验收脚本若不检查“场景图物体数 vs 实际放置物体数”就发现不了。

$$\text{coverage}=\frac{|\{\text{placed objects}\}|}{|\{\text{scene-graph objects}\}|}$$

这个覆盖率断言应作为组合阶段的硬门槛：低于阈值即判定该世界不合格，而不是继续导出。它把“资产缺失”从隐性失败变成显性失败，是复现中最值得先写的断言之一。

四 · 超参与最小可跑配方

由于是系统级组合，超参分布在四个子系统，不存在统一的训练超参表。复现时应按子系统列出关键旋钮，并给出 MVP 的保守取值原则而非具体数字（论文未给出可复用的数值）。LLM 布局侧的关键旋钮是采样温度、场景图字段约束（结构化输出）、区域数量上限、每区域物体数量上限。温度过高会让场景图字段漂移，结构化输出约束（如 JSON schema 强制）比调温度更能稳定布局。程序化地形侧的关键旋钮是高度场分辨率、噪声倍频层数、坡度阈值、可行走掩码的腐蚀半径。扩散物体侧的关键旋钮是采样步数、引导强度、每类别采样数、mesh 后处理（去噪、简化、归一化朝向）。组合侧的关键旋钮是物体间最小间距、物体与地形的最小穿插容差、放置失败的重试次数。

子系统关键旋钮MVP 取值原则失败表现
LLM 布局结构化输出约束、区域/物体上限强约束 schema，上限取小字段漂移、物体数爆炸
程序化地形高度分辨率、坡度阈值分辨率适中，坡度阈值偏严不可行走陡坡、地形破碎
扩散物体采样步数、引导强度、朝向归一化步数偏多，强制朝向归一mesh 破碎、朝向错位
组合放置最小间距、穿插容差、重试次数间距偏大，容差偏小物体重叠、悬空/埋入

MVP 配方的时间预算分配是复现者最容易忽略的工程判断。扩散采样通常占据端到端时间的大头，LLM 布局与程序化地形相对便宜，组合阶段几乎免费但失败重试会放大成本。因此 MVP 应把物体数量上限压到很小（例如每区域少量物体），先验证链路连通，再逐步放开上限。这与“先调质量”的直觉相反：链路不通时调质量是在错误的基座上优化。系统代价是 MVP 世界显得空旷，但空旷世界的验收断言更容易定位失败点。

失败模式在超参层面表现为耦合：放宽坡度阈值会让更多区域可行走，但组合阶段把物体放在陡坡上会导致物体悬空；提高扩散引导强度会让物体更贴合提示，但过度引导会产出过饱和纹理并在组合阶段暴露穿插。超参不能单独调，必须成组调并在每次调整后跑全套验收断言。伪代码思路如下：

$$\text{for each config in sweep:}\ \text{run four stages}\rightarrow\text{run asserts}\rightarrow\text{record pass/fail per assert}$$

把验收断言的通过情况作为超参扫描的目标，而不是把目视效果作为目标，是复现工程化的关键一步。

五 · 验收断言：可自动判定的硬门槛

验收断言要覆盖四个子系统与三个跨阶段契约。子系统断言：布局阶段断言场景图 schema 合法、区域与物体字段完整、数量在配置上限内；地形阶段断言高度场无 NaN、可行走掩码连通、坡度在阈值内的面积占比达标；物体阶段断言每个 mesh 非空、包围盒尺度在类别提示范围内、朝向已归一化；组合阶段断言覆盖率达标、物体间无重叠、物体与地形穿插在容差内。跨阶段契约断言：单位一致（所有阶段读同一份配置）、坐标系一致（轴向与原点）、随机种子可复现（同种子同输入产出同世界）。

每条断言都应输出结构化结果而非布尔值，便于定位。例如重叠断言应输出重叠物体对与重叠体积，穿插断言应输出穿插深度与位置。系统代价是断言脚本本身的维护成本，尤其是跨阶段契约断言需要在每个阶段入口重复执行。但这类重复执行正是把接口错误挡在早期的手段：坐标系错误若在布局阶段就被断言拦住，就不会浪费扩散采样成本。

一个具体例子：组合阶段发现某物体包围盒与地形高度场穿插深度超过容差。若断言只报“失败”，复现者会去查放置算法；若断言报出穿插位置与深度，并能回溯到该物体的尺度提示与地形该处坡度，就能判断是尺度提示过大还是坡度阈值过松。断言的信息量决定了调试路径的长度。失败模式是断言阈值设置过松，导致带缺陷的世界被判为通过，缺陷在引擎里才暴露，此时已无法定位是哪个阶段引入的。

可复现性断言值得单独强调。论文的系统是组合式，随机性来自 LLM 采样、扩散采样、程序化噪声三处。固定三处种子并记录每次运行的种子组合，才能让“同一文本产出同一世界”成为可检验的性质。这不是论文声称的能力，而是复现者自己必须建立的工程基线；没有它，任何回归对比都失去意义。

六 · 常见崩溃点与最小可跑版本的收敛路径

常见崩溃点按出现频率排序：接口单位与坐标系不一致、场景图 schema 漂移、扩散资产朝向未归一、组合阶段静默丢弃物体、地形可行走掩码断裂、缓存键过粗导致资产错配。这些崩溃点的共同特征是它们都不表现为异常抛出，而是表现为世界“看起来不对”，因此必须靠断言而非异常捕获来发现。工程判断是：在每个阶段出口写落盘校验，校验失败即中止链路，不允许带缺陷的中间产物进入下一阶段。

收敛路径建议分三步。第一步只跑布局与地形，验证场景图能驱动地形区域划分，验收地形可行走连通性；此步不涉及扩散，成本最低，能最快暴露坐标系与单位问题。第二步加入扩散物体但固定放置位置（按场景图相对位置直接映射，不做复杂放置优化），验证资产朝向与尺度，验收覆盖率与包围盒范围；此步暴露资产层与场景图层的不一致。第三步启用完整 object-aware 分解与放置，验收重叠与穿插断言，并做引擎导出后的行走测试。三步各自有独立的验收门槛，任一步不通过就不进入下一步。

引擎导出是最后一道关卡，也是复现者容易低估的一步。论文声称输出可进游戏引擎，复现时要断言导出文件能被引擎加载、角色能在可行走掩码内移动、至少一个物体可交互。导出格式的坐标系转换、材质引用路径、mesh 缩放单位都是崩溃高发区。失败模式是导出成功但引擎内世界尺度错误（角色如蚂蚁或如巨人），这类错误在导出脚本里加一条尺度断言即可拦截：断言世界包围盒的最大边长在配置的合理范围内。

最后落在具体机制上：object-aware 分解与组合阶段的放置优化是整条链路唯一做全局约束求解的地方，它同时消费布局的相对位置、地形的可行走掩码、资产的包围盒。复现时若把这一步简化成按相对位置直接映射，重叠与穿插断言必然大面积失败；若把它做成带重试的约束满足，则重试次数与最小间距两个旋钮直接决定端到端时间。工程判断是：MVP 阶段允许放置失败并降级为占位几何体，但必须记录降级次数，把降级次数作为放开物体数量上限前的观察指标——降级次数随物体数上升而急升，说明间距或地形可行走面积已成瓶颈，此时调扩散质量是无效的。
