一 · 训练数据的真实边界：ShapeNet 类别子集与“艺术家风格”标签的来历

MeshGPT 的训练数据来自 ShapeNet，覆盖椅子、桌子、飞机等类别。这里必须把“来源”拆成三层看：原始 CAD/扫描资产层、论文使用的清洗子集层、以及进入 VQ-VAE 训练前的面片序列化层。三层之间每一次收缩都会改变模型学到的东西。原始 ShapeNet 资产包含大量非流形边、重复顶点、内部隐藏面、以及不同建模软件导出的法线朝向不一致；论文并没有声称对全部 ShapeNet 做端到端训练，而是选取类别子集，并在预处理阶段把网格规整成可被图卷积编码器消费的形式。所谓“艺术家风格”并不是数据里带了风格标签，而是因为 ShapeNet 的椅子、桌子、飞机本身由人工建模，面数分布天然比等值面提取紧凑，拓扑以四边形主导、三角化后仍保留局部环状结构。模型学到的“紧凑”是数据分布的函数，不是架构自带的属性。

具体机制上，预处理要解决网格的集合结构问题：三角网格是顶点集合加面集合，面与面之间通过共享边邻接，没有天然的顺序。VQ-VAE 的图卷积编码器以面为节点、以共享边为邻接关系构造面邻接图，每个面节点的初始特征来自其三个顶点的坐标、法线以及面片局部几何量。这一步要求输入网格是流形或近似流形，否则面邻接图的度分布会出现异常节点，量化后的词表嵌入会混入拓扑噪声。序列化阶段则要选一个面片遍历顺序，把面片图展平成 token 序列；顺序策略直接决定 Transformer 能学到多长的局部依赖。

系统代价在这里第一次显现：数据清洗的工程量远大于模型代码量。一个非流形边会让面邻接图出现一个度异常节点，该节点在 VQ 量化时可能落到词表中一个语义模糊的嵌入上，Transformer 在训练时会把这种噪声当作合法模式记忆。失败模式不是训练 loss 爆炸，而是生成结果里出现局部翻折面或悬空面——loss 曲线看起来正常，但采样出的网格在渲染时出现黑面。具体例子：一把椅子如果扶手与座面之间存在未焊接的重复顶点，面邻接图会把扶手和座面分成两个不连通分量，序列化后 token 序列在分量边界处出现跳变，Transformer 学到的“下一个面片”预测在该边界处退化为随机选择，生成时表现为扶手与座面错位。

另一个容易误读的点是数据规模。论文明确指出训练数据规模小，这是 MeshGPT 的局限之一，也是后续 MeshAnything 系列要扩数据的原因。数据规模小意味着词表覆盖的局部面片模式有限：VQ 词表大小在消融中被测试，词表太小则不同局部几何被压到同一嵌入，词表太大则每个嵌入的训练样本不足、量化码本出现死码。这个权衡不是调参问题，而是数据量与词表容量的匹配问题。工程复现时，如果直接把 ShapeNet 全量灌进去而不做类别平衡，椅子类占比过高会让词表向椅子局部模式倾斜，生成桌子时桌腿的环状拓扑被椅子腿的模式覆盖。

二 · 评测协议：FID 在网格上的口径与它没有覆盖的东西

论文报告的核心指标是 FID，并声称优于 PolyGen；同时用“生成网格面数显著低于等值面提取、拓扑更紧凑”作为定性证据。这里必须讲清 FID 在网格生成上的口径，否则会把一个分布距离指标误读成几何质量指标。FID 的本质是两组特征分布之间的 Fréchet 距离：把生成网格和真实网格分别送进一个特征提取器，得到特征均值与协方差，再计算两个高斯分布之间的距离。

$$\mathrm{FID}=\|\mu_r-\mu_g\|^2+\mathrm{Tr}\left(\Sigma_r+\Sigma_g-2(\Sigma_r\Sigma_g)^{1/2}\right)$$

公式里 $\mu_r,\Sigma_r$ 是真实网格特征分布的均值与协方差，$\mu_g,\Sigma_g$ 是生成网格的对应量。关键问题在于特征提取器是什么、输入是什么。网格不是规则网格图像，特征提取器要么在渲染视图上提特征，要么在点云/面片采样上提特征。无论哪种，FID 度量的是“生成分布与真实分布在特征空间里有多接近”，它对局部几何瑕疵不敏感：一个面数正确、整体轮廓合理但存在局部翻折面的椅子，在特征空间里可能离真实椅子很近，FID 不会因为翻折面而显著变差。这就是 FID 优于 PolyGen 不能被读成“几何质量全面优于 PolyGen”的原因。

评测协议的另一层是基线口径。等值面提取基线的面数爆炸是结构性的：神经场在规则网格上做 marching cubes，面数由分辨率决定，分辨率越高面数越多，且拓扑由隐式场零等值面决定，容易出现碎片化连通分量。MeshGPT 的面数优势来自 token 序列长度上限——它只能生成有限个面片 token，面数天然被序列长度截断。这个对比里，面数低既是优点也是约束：序列长度限制复杂网格是论文自己列出的局限。所以“面数显著低于等值面提取”这个结论成立，但它同时意味着 MeshGPT 无法生成面数超过序列上限的网格，评测时如果真实网格面数分布尾部很长，生成分布会被截断，FID 的协方差项会失真。

具体例子：飞机类别中，真实资产的面数分布跨度大，机翼与机身的连接处局部拓扑复杂。如果序列长度上限低于该复杂区域所需的面片数，生成器会倾向于省略连接处的过渡面，输出一个机身与机翼直接相交的网格。渲染上看轮廓正确，FID 特征空间里也可能接近，但拓扑上连接处是非流形的。评测协议如果不加拓扑合法性检查，这类失败不会被指标捕获。工程验收时必须把“面数低于阈值”“拓扑连通分量数”“非流形边比例”作为独立断言，不能只信 FID。

三 · 指标口径的错位：面数、紧凑性与“艺术家级”的三件不同的事

论文用“面数远低于等值面提取、拓扑更紧凑”来描述优势，用 FID 优于 PolyGen 来描述分布优势。这三件事——面数、紧凑性、分布接近度——口径不同，不能互相替代。面数是标量计数；紧凑性是拓扑与几何的综合判断，通常指同样形状下用更少的面、更规则的边环、更少的狭长三角形；FID 是特征分布距离。一个模型可以面数很低但拓扑碎片化，也可以 FID 很好但面数偏高。MeshGPT 的消融覆盖了 VQ 词表大小、序列长度、图卷积 vs MLP，这些消融改变的是 tokenization 质量与序列建模能力，而指标只报告了 FID 与定性面数对比，没有给出紧凑性的量化定义。

具体机制上，紧凑性来自 VQ 词表的局部模式归纳：图卷积编码器把面片及其邻域编码成量化嵌入，词表里的每个 token 对应一类局部几何/拓扑模式。生成时 Transformer 逐个预测 token，解码器把 token 还原成面片。如果词表学到的模式是“环状边流”“规则四边形三角化”这类艺术家常用结构，生成网格自然紧凑；如果词表被噪声污染，token 对应的面片模式不规则，紧凑性下降。消融中图卷积 vs MLP 的对比正是在检验邻域信息是否进入 token：MLP 只看单面特征，丢失邻接上下文，词表退化为孤立面片模式，生成时面片之间接缝不齐。

系统代价：紧凑性没有统一量化口径，导致跨论文比较困难。后续工作若声称“比 MeshGPT 更紧凑”，必须说明紧凑性怎么测——是面数、是边环规整度、还是非流形边比例。工程复现时如果只对齐 FID，可能得到一个 FID 相近但面数翻倍、拓扑碎片化的模型，因为 FID 对拓扑不敏感。失败模式具体表现为：生成一把椅子，FID 与真实椅子分布接近，但椅腿与座面之间用大量狭长三角形缝合，面数接近等值面提取的水平，紧凑性优势消失。这种结果在只看 FID 的评测表里看不出来。

另一个口径错位是“艺术家风格”这个词。论文摘要说生成紧凑、艺术家风格的网格，但数据里没有风格标签，评测里也没有风格分类器。艺术家风格是定性描述，指向 ShapeNet 人工资产的面数分布与拓扑规整度，不是可测指标。把这句话读成“模型具备风格控制能力”是误读；MeshGPT 没有风格条件输入，它生成的是数据分布的平均风格。工程判断：如果下游需要特定风格，必须在 tokenization 或条件输入上另做工作，不能指望基座模型自带风格解耦。

四 · 作弊风险：序列长度截断、词表死码与评测集泄漏的三条路径

MeshGPT 的评测存在三类可被无意或有意利用的作弊路径，工程复现时必须显式封堵。第一类是序列长度截断带来的面数优势假象。因为生成面数被序列长度上限硬截断，任何提高序列长度的改动都会同时提高面数与表达能力。如果评测时对生成网格和真实网格用不同的面数归一化，或者只报告面数低而不报告截断率，就会把“生成能力不足”包装成“紧凑”。具体机制：Transformer 在 token 序列上自回归，序列长度 $N$ 是硬上限，$p(\mathcal{M})=\prod_{i=1}^{N}p(t_i\mid t_{

第二类是 VQ 词表死码。VQ 量化把编码器输出映射到最近邻词表嵌入，训练中若某些嵌入长期不被选中，梯度不再更新，成为死码。死码在生成时表现为：Transformer 采样到该 token，解码器还原出一个语义模糊的面片，或者还原失败。消融测试词表大小时，词表越大死码比例越高，因为每个码本嵌入分到的训练信号越少。作弊风险在于：如果评测只统计成功解码的网格，把解码失败样本丢弃，FID 会被乐观偏置。正确做法是把解码失败计入分母，或单独报告解码成功率。

第三类是评测集泄漏。ShapeNet 类别子集训练、同分布评测是常规做法，但如果预处理管线在训练集和评测集之间共享了归一化统计量或面片序列化顺序策略，评测集的信息会以间接方式进入训练。具体机制：序列化顺序若按全局几何量排序，而全局几何量的统计量在全体数据上计算，评测样本的排序会受训练样本分布影响。这种泄漏不会让 FID 剧烈变化，但会让跨数据集泛化被高估。工程复现清单里应把“预处理统计量只在训练集上拟合”作为硬断言。

具体例子：椅子类别评测中，若序列长度上限恰好覆盖大多数椅子的面片数，只有少数复杂椅子被截断，FID 看起来很好；换到飞机类别，机翼连接处面片数普遍超过上限，截断率上升，FID 变差。如果不分类别报告截断率，就会误以为模型在飞机上只是“风格不同”，实际是表达能力被序列长度卡住。这就是一个容易误读的数字：总体 FID 优势可能由简单类别的高覆盖率撑起，复杂类别被截断样本稀释。

五 · 消融的口径：词表大小与序列长度不是独立旋钮

论文消融覆盖 VQ 词表大小、序列长度、图卷积 vs MLP。这三个旋钮在口径上不独立：词表大小决定每个 token 承载多少局部信息，序列长度决定能容纳多少 token，两者共同决定一个网格能被表达的总信息量。词表大、序列短，则每个 token 信息量大但 token 数少，长程结构靠少量 token 拼；词表小、序列长，则局部模式粗糙但序列能覆盖更多面片。图卷积 vs MLP 则决定 token 里是否含邻域上下文。消融若只报告单一旋钮的 FID 变化，会把交互效应误读成主效应。

具体机制：VQ-VAE 先训重建，重建质量用面片还原误差衡量；Transformer 再在 token 序列上训自回归。词表大小改变的是重建阶段的目标：词表太小，不同局部几何被压到同一嵌入，重建误差上升，Transformer 学到的序列是粗粒度的；词表太大，码本利用率下降，死码增多，Transformer 见到的 token 分布稀疏，自回归预测的熵升高。序列长度改变的是 Transformer 的上下文窗口：长度不足则长程依赖被截断，长度过长则训练样本被 padding 稀释，单卡数天的训练预算下有效样本数下降。

系统代价：消融的算力成本随旋钮组合增长。每个词表大小 × 序列长度 × 编码器类型的组合都要重训 VQ-VAE 和 Transformer 两阶段，单卡数天的预算意味着消融网格不能太密。失败模式是消融结论被少量组合的噪声主导：某个组合恰好遇到死码比例高，FID 变差，被归因于词表大小，实际是训练不充分。工程复现时应固定随机种子、报告码本利用率与死码比例，否则消融表不可复现。

具体例子：图卷积 vs MLP 的对比里，MLP 版本在词表较小时 FID 差距不明显，因为词表小已经把邻域信息压掉了，图卷积的邻域优势无处发挥；词表较大时差距拉开。这说明“图卷积更好”这个结论依赖词表大小，不能脱离消融网格单独引用。工程判断：复现时先定序列长度上限（由目标网格复杂度决定），再在预算内选词表大小，最后验证图卷积是否带来可测增益；顺序反过来会得到误导性结论。

六 · 工程验收断言：把评测口径钉死在可执行检查上

基于以上口径与作弊风险，MeshGPT 类系统的验收不能只依赖 FID 一个数字。可执行断言应覆盖四层：数据层、tokenization 层、生成层、评测层。数据层断言：面邻接图的连通分量数、非流形边比例、重复顶点率在预处理后低于阈值；训练集与评测集的预处理统计量分离。tokenization 层断言：VQ 码本利用率高于阈值、死码比例低于阈值、重建面片误差分布无长尾异常。生成层断言：解码成功率、生成网格的非流形边比例、面数分布与真实分布的分位数对比、序列截断率按类别报告。评测层断言：FID 的特征提取器与输入表示固定、解码失败计入分母、跨类别结果分开报告。

具体机制上，序列截断率是最容易被忽略的断言。对每个评测样本，先算其序列化后的 token 数，若超过序列长度上限则标记为截断；报告生成结果时，截断样本单列。这样 FID 的优势不会被截断样本稀释，面数优势也不会被误读为表达能力。另一个断言是词表死码检查：训练后统计每个码本嵌入被选中的频率，频率为零的嵌入在生成时若被采样到，解码器输出不可信，应把该 token 的采样概率置零或重映射。这是推理期的工程补丁，不改变训练目标，但能减少解码失败。

失败模式具体例子：一个复现版本在椅子类别上 FID 接近论文，但飞机类别 FID 明显差；检查发现飞机样本的序列截断率远高于椅子，且截断样本的解码网格缺失机翼连接面。若验收只看总体 FID，会误判复现成功；按类别报告截断率后，问题定位到序列长度上限与飞机复杂度的不匹配。工程判断：序列长度不是越大越好，它受单卡数天训练预算与有效样本数约束；正确做法是按目标类别的最复杂样本定上限，再在该上限下优化词表与编码器，而不是先训模型再解释截断。

最后落在评测口径的一个硬判断：FID 优于 PolyGen 是分布层面的结论，面数低于等值面提取是表达能力与截断共同作用的结果，拓扑更紧凑是定性观察。三者不能互相替代，也不能脱离序列长度上限与数据规模小这两个约束单独引用。验收断言必须把“截断率”“死码比例”“非流形边比例”“解码成功率”与 FID 并列，否则一个容易误读的数字——总体 FID——会掩盖序列长度限制与数据规模小带来的真实失效。
