一 · 管线定位：把三阶段拆成可交付的服务边界

在真实生产管线里，Hi3DGen 不是一个单体模型，而是一段被切开的四段式链路：图像预处理与法线扩散、法线条件几何生成、纹理生成、以及后处理与资产封装。把它放进管线的正确方式是先确定服务边界，再确定接口契约。工程上最稳妥的切法是让「法线」成为显式的中间产物落盘，而不是在进程内隐式传递。理由很直接：法线阶段是整条链路里唯一同时承担 2D 语义对齐与 3D 高频细节编码的环节，它一旦出错，后面几何阶段没有任何机制能把它纠正回来，只能把错误放大成几何噪声。把法线落盘意味着可以单独重跑、单独验收、单独缓存，也意味着上游美术可以人工修正法线后再喂给几何阶段。

接口层面，图像到法线扩散的输入是单张 RGBA 图加一个相机先验（正交或透视、视场角、物体朝向），输出是与输入图像像素对齐的法线图，通道约定必须固定为相机空间还是世界空间，并在契约里写死。几何阶段输入是法线图加可选的掩码与包围盒尺度，输出是三平面表示或网格，具体取决于几何表示的选择。纹理阶段输入是几何加原始图像，输出带 UV 与贴图的资产。整条链路的单位、坐标系、朝向约定（Y-up 还是 Z-up）、尺度归一化方式必须在接口文档里逐条写明，因为这些约定错一个，下游引擎里就会出现模型躺倒或比例失真的问题。

一个具体的失败模式是坐标系漂移：法线阶段按相机空间输出，几何阶段按世界空间解释，两者之间的旋转没有显式对齐，结果生成的几何在正面视角看起来正常，转到侧面就出现整体倾斜。这类错误在单张渲染图里几乎看不出来，只有在多视角检查或引擎里加载后才暴露。系统代价是每个阶段都要带一个显式的变换矩阵字段，并在几何阶段入口做一次断言校验，验证法线图的主方向与相机先验一致。

从成本角度看，三阶段的串联意味着推理延迟是累加的。论文给出的量级是数秒到数十秒，这个区间在离线批处理里可以接受，但在交互式预览场景里就是硬约束。工程判断是：把法线阶段与几何阶段放在 GPU 常驻服务里，纹理阶段可以异步排队，因为纹理不阻塞几何可用性。这样前端可以先拿到几何做占位预览，纹理稍后补齐。

$$\text{Latency}_{\text{e2e}}=\sum_{s\in\{\text{normal},\text{geo},\text{tex}\}} T_s + T_{\text{io}},\qquad \text{Cost}_{\text{batch}}=N\cdot\left(C_{\text{normal}}+C_{\text{geo}}+C_{\text{tex}}\right)$$

这里的 N 是批大小，C 是单次调用的算力成本。工程上要盯的不是单次延迟，而是每资产的总成本与失败重试率。法线阶段一旦失败（例如输入图像背景杂乱导致法线图崩坏），整条链路都要重跑，重试成本等于三阶段之和，这是串联架构的固有代价。

二 · 上下游接口：输入契约与输出契约的硬约束

上游通常是三类来源：用户上传的商品图、设计稿渲染图、以及从视频抽帧得到的单视图。这三类输入的分布差异极大，直接决定法线阶段的表现。商品图往往有纯色背景、均匀打光，法线扩散能拿到干净的语义；设计稿渲染图可能带透明通道与风格化着色，法线阶段会把风格化阴影误读成几何起伏；视频抽帧则带运动模糊与压缩伪影。接口契约里必须写明输入的分辨率下限、背景处理要求、以及是否允许带 alpha 通道。一个可执行的规则是：输入统一缩放到固定分辨率、背景做抠图后填中性灰、alpha 通道作为掩码单独传递，而不是让模型自己去猜前景。

输出契约比输入契约更容易被忽视。几何阶段的输出如果是三平面表示，下游需要的是网格，就必须有一个明确的提取步骤与后处理：去孤立面片、补洞、简化到目标面数、重算法线、生成 UV。这些步骤不属于论文的方法本身，但属于生产管线的必需环节。纹理阶段的输出要规定贴图分辨率、是否带金属粗糙度通道、UV 是否重叠。工程上常见的坑是 UV 重叠导致纹理阶段在不同面片上写入冲突的颜色，表现为模型局部出现脏斑。

接口必填字段校验断言典型失败
图像→法线分辨率、相机先验、通道空间约定法线图单位长度误差在阈值内背景杂乱导致法线崩坏
法线→几何法线图、掩码、包围盒尺度几何包围盒与尺度先验一致坐标系漂移、比例失真
几何→纹理网格、UV、原始图像UV 无重叠、面数在预算内UV 冲突导致脏斑
资产封装朝向、单位、材质槽引擎加载后朝向正确模型躺倒、材质丢失

伪代码层面的接口校验可以写成入口断言：在几何阶段入口检查法线图的通道统计量是否落在合理区间，在纹理阶段入口检查 UV 展开是否自交。这些断言不提升生成质量，但能把错误拦在链路早期，避免把坏资产交付给下游。系统代价是每个断言都要跑一遍几何计算，增加少量 CPU 开销，但相比重跑整条链路的 GPU 成本，这笔开销是划算的。

一个具体例子：某商品图带大面积反光高光，法线阶段把高光区域读成凸起，几何阶段生成了一排不该存在的脊线。如果入口断言检查了法线图的局部梯度异常，就能在几何阶段之前拦下并提示重新打光或人工修法线。这就是把法线显式化带来的工程收益：错误可见、可定位、可修复。

三 · 成本结构：算力、延迟与重试的经济学

三阶段架构的成本不是均摊的。法线扩散是像素级扩散，计算量与分辨率强相关；几何阶段的条件生成在三平面或网格表示上做，计算量与表示分辨率强相关；纹理阶段依赖 2D 先验，计算量相对可控但受贴图分辨率影响。论文给出的推理量级是数秒到数十秒，这个区间意味着单卡可以支撑离线批处理，但不适合高并发在线请求。工程判断是把链路分成同步段与异步段：法线与几何走同步，纹理走异步队列。

成本模型要区分「成功成本」与「有效成本」。有效成本等于总成本除以验收通过率。法线阶段的失败会传导到几何阶段，表现为几何细节崩坏但网格仍然生成，这类失败不会报错，只会产出低质量资产，是最难发现的成本泄漏。工程上必须建立自动验收指标，例如法线保真度的重投影一致性、几何的多视角轮廓一致性，把隐性失败显式化为可统计的通过率。

$$\text{EffectiveCost}=\frac{C_{\text{normal}}+C_{\text{geo}}+C_{\text{tex}}}{P_{\text{accept}}},\qquad P_{\text{accept}}=P_{\text{normal}}\cdot P_{\text{geo}}\cdot P_{\text{tex}}$$

串联架构的通过率是相乘的，这意味着每一段的通过率都必须高，否则有效成本会迅速膨胀。假设三段各自通过率都不错，乘积仍然会明显低于单段通过率，这是串联链路的数学事实，不需要实验数字也能定性判断。降低有效成本的杠杆不在算力优化，而在提高每一段的通过率，尤其是最上游的法线段。

一个具体机制是缓存法线中间产物。同一张输入图在调参或重跑纹理时，法线图不变，可以直接复用，省掉一次扩散推理。缓存键要包含输入图哈希、相机先验、法线模型版本，三者任一变化都要失效。系统代价是存储开销与缓存一致性管理，但相比重复推理的 GPU 成本，缓存是明确的净收益。失败模式是缓存键设计不当，例如漏了相机先验，导致不同视角的输入命中同一份法线图，生成几何朝向错误。

四 · 合规与风险：法线桥接带来的新暴露面

合规风险分三层。第一层是输入数据的权利：用户上传的商品图、设计稿、视频帧，是否拥有生成衍生 3D 资产的授权。这条链路会产出可商用的网格与贴图，权利链条必须在接口层留痕，记录输入来源与授权状态。第二层是训练数据的来源：论文在 Objaverse 与合成 CAD 数据上训练，Objaverse 的资产许可混杂，下游商用时要确认模型输出是否受训练数据许可的约束。这不是技术问题，但会直接影响资产能否上线。

第三层是法线桥接特有的暴露面：法线图是中间产物，它比最终网格更直接地编码了输入的几何信息。如果法线图被落盘并对外提供，等于把输入的几何结构以另一种形式泄露出去。工程判断是法线中间产物只在内部流转，不进入对外 API 的返回体，对外只交付最终资产与必要的元数据。系统代价是内部存储与访问控制，但这是可管理的。

另一个风险是生成内容的可追溯性。三阶段链路每一步都可能引入不可复现的随机性（扩散采样、几何生成的条件采样），同一输入两次运行可能得到不同资产。生产管线需要固定随机种子并记录，否则质量回归时无法定位是哪一段发生了变化。失败模式是版本管理缺失：法线模型升级后几何质量下降，但因为种子与版本都没记录，无法判断是模型问题还是采样问题。

具体例子：一批商品图经过链路生成资产后上线，其中部分资产在引擎里出现朝向错误。追溯发现是某次法线模型更新改变了通道空间约定，而几何阶段的变换矩阵字段没有同步更新。合规与质量在这里交汇：没有版本记录，就无法证明这批资产是按哪一版契约生成的，召回与修复都无从下手。

五 · 上线检查清单：从契约到验收的逐项断言

清单的第一项是接口契约冻结：坐标系、单位、通道空间、分辨率、朝向约定逐条写入文档并有对应的入口断言。第二项是中间产物策略：法线图是否落盘、缓存键包含哪些字段、对外是否暴露。第三项是分段验收指标：法线阶段的重投影一致性、几何阶段的多视角轮廓一致性、纹理阶段的 UV 无冲突检查。第四项是失败分类：把失败分为可重试（采样随机性）、可修复（法线可人工修正）、不可用（输入本身不合格）三类，分别对应不同的处理路径。

  • 契约：坐标系与单位写死，入口断言校验法线主方向与相机先验一致。
  • 缓存：法线中间产物缓存键含输入哈希、相机先验、模型版本。
  • 验收：每段独立通过率可统计，有效成本按乘积模型核算。
  • 版本：模型版本、随机种子、契约版本三者绑定记录，支持质量回归定位。
  • 合规：输入授权留痕，法线中间产物不对外暴露，训练数据许可在商用前确认。
  • 降级：几何可用即先交付占位预览，纹理异步补齐，避免整条链路阻塞前端。

清单的第五项是降级路径：当纹理阶段排队过长时，先交付无法线贴图的几何占位，保证前端可用。第六项是回归测试集：固定一批覆盖不同输入分布的样例（纯色背景商品图、带高光的设计稿、带运动模糊的视频帧），每次模型或契约变更后跑一遍，比较法线保真度与几何细节的定性变化。回归测试不追求绝对数值，而是捕捉分布漂移。

一个具体机制是把验收断言做成流水线门禁：几何阶段产出的网格必须通过包围盒尺度校验与面数预算校验才能进入纹理阶段，纹理阶段产出的资产必须通过 UV 自交检查才能进入封装。门禁失败的资产进入人工复核队列，而不是直接丢弃，因为部分失败是可通过修法线或调尺度挽救的。系统代价是人工复核的人力成本，但相比把坏资产交付到下游引发的返工，门禁是更便宜的拦截点。

最后落在工程判断上：Hi3DGen 的三阶段结构决定了它的生产价值不在单次生成的峰值质量，而在中间产物的可干预性。法线作为显式桥梁，让错误可以在链路中段被看见、被修正、被缓存，这是直接回归几何的单体模型不具备的工程属性。把法线落盘、把契约写死、把每段通过率纳入成本模型，这三件事做到位，法线误差传导这个固有缺陷就从不可控的随机故障变成了可管理的工程参数。
