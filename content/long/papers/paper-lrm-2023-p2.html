一 · 从一张图到三张平面：整体数据流

LRM 的前向过程是一条单向流水线，输入只有一张 RGB 图像和它的相机参数，输出是一组三平面（triplane）表示，再由三平面经体渲染或网格提取变成可用的 3D 资产。整条链路可以拆成四段：图像编码、相机调制、跨注意力解码、体渲染监督。每一段都有明确的张量形状与职责边界，理解这些形状是理解后续所有设计取舍的前提。

第一段是图像编码。输入图像 I 被切成 patch，送入 DINO ViT。ViT 输出一串 token，每个 token 是一个维度为 d 的向量，同时保留其对应的 patch 空间位置。这里的关键机制是：LRM 并不要求 ViT 输出一个全局的、与空间无关的语义向量，而是保留 token 序列，让后面的解码器能够按空间位置去“查询”图像的不同区域。这一点决定了 LRM 是重建模型而不是分类模型——它需要的是空间对应的特征，而不是池化后的语义。

第二段是相机调制。单图重建的本质困难是输入视角只覆盖了物体的一面，背面没有任何像素证据。相机参数 c（外参加内参）告诉模型“这张图是从哪个方向看的”，从而让模型知道哪些区域是可见的、哪些区域必须靠先验补全。LRM 把相机参数编码后注入解码过程，使得同一个图像在不同相机假设下可以解码出不同的三平面。消融实验把相机调制列为单独一项，说明它不是可有可无的装饰，而是决定背面推断方向性的关键输入。

第三段是跨注意力解码。一个 Transformer 解码器（24 层、宽度 1024）以一组可学习的查询 token 为起点，通过 cross-attention 反复读取 ViT 的 token 序列，最终输出三个平面的特征图。三个平面分别是 T_xy、T_xz、T_yz，每个是 64×64 空间分辨率、32 通道。三个平面两两正交，共同张成一个轴对齐的体积特征场：空间中任意一点 (x,y,z) 的特征由它在三个平面上的投影特征拼接而成。

$$(\mathbf{T}_{xy},\mathbf{T}_{xz},\mathbf{T}_{yz})=\mathrm{Transformer}_\theta(I,\mathbf{c}),\qquad \hat{I}=\mathrm{VolumeRender}(\mathbf{T},\mathbf{c}')$$

第四段是体渲染。给定三平面和一个目标相机 c'，沿每条射线采样若干点，把每点的三平面特征取出、拼接、送入一个小 MLP，得到该点的密度与颜色，再沿射线积分得到像素颜色 \(\hat{I}\)。训练时 c' 是多视角监督相机，推理时 c' 可以是任意视角，也可以完全跳过渲染、直接从三平面提取网格。这条公式把整条链路压缩成一行：编码器加解码器产出三平面，体渲染把三平面变成图像。

这条数据流有一个容易被忽略的工程含义：三平面是唯一的中间瓶颈。图像信息必须全部压进三个 64×64×32 的张量里，任何在编码阶段丢失的细节都无法在渲染阶段找回。这解释了后面所有的失败模式——背面细节缺失、网格分辨率有限，根源都在这个瓶颈的容量与监督信号，而不在渲染器本身。

二 · 编码器与解码器的分工：谁负责看，谁负责想

LRM 的架构分工可以用一句话概括：ViT 负责“看”，Transformer 解码器负责“想”。看的部分是证据提取，想的部分是先验补全。这个分工不是任意的，它对应了单图重建的信息结构——输入图提供了物体可见面的证据，而不可见面只能由模型在训练数据中学到的形状先验来填充。

DINO ViT 在这里扮演的是特征提取器的角色。论文中它可以是冻结的，也可以是微调的。冻结的好处是训练稳定、显存占用低，因为 ViT 的参数量不参与梯度更新；微调的好处是特征可以适配重建任务而非分类任务。无论哪种，ViT 输出的都是一组带位置信息的 token，而不是一个全局向量。这个设计选择直接决定了 cross-attention 能否做空间查询：解码器的每个查询 token 通过注意力权重去“挑选”它需要的图像区域，而不是被动接收一个已经池化的摘要。

解码器的结构是标准的 Transformer 解码器堆叠：24 层，每层包含自注意力与 cross-attention，宽度 1024。查询 token 的数量与三平面的空间网格对应——三个 64×64 的平面共 12288 个空间位置，每个位置需要 32 维特征。解码器要做的就是把 ViT 的 patch 级特征重新组织成平面级的特征图。自注意力让不同空间位置的查询互相协调，避免相邻平面区域出现不连续的特征；cross-attention 则把图像证据拉进来。

这里有一个具体的机制值得展开：三平面之间的耦合。三个平面不是独立解码的，它们在同一个解码器里共享注意力。一个位于 T_xy 上的查询 token 在 cross-attention 时可能读取到与 T_xz 相关的图像区域，因为图像 patch 本身不区分平面。这种共享使得三个平面在特征层面天然一致：同一个空间点在不同平面上的投影特征不会互相矛盾。如果三个平面分开解码，就会出现平面间不一致，体渲染时表现为物体表面的撕裂或密度跳变。

分工的代价体现在参数量与计算量上。24 层、1024 宽的解码器是模型的主体，十亿参数中的绝大部分在这里。cross-attention 的计算量随查询 token 数与图像 token 数的乘积增长，12288 个查询 token 对上千个图像 token 做注意力，是前向过程中最重的一步。这也是推理约 10 秒的主要耗时来源之一——不是渲染慢，而是解码器要把大量查询 token 逐一与图像特征对齐。

一个具体的失败模式是：当输入图像的分辨率不足或物体在图中占比过小时，ViT 的 patch token 无法提供足够细的空间证据，解码器的查询 token 只能依赖先验“猜”细节。此时三平面在可见面附近仍然合理，但在细节密集区域（比如纹理、薄结构）会出现模糊。这不是解码器容量不够，而是证据不够——分工的边界在这里暴露：想的部分不能凭空创造看的部分没有捕捉到的信息。

三 · 三平面表示：为什么是三个正交平面

三平面是 LRM 的核心中间表示，也是它区别于 pixelNeRF 的关键。pixelNeRF 把图像特征直接投影到射线上逐点查询，特征场是隐式的、没有显式的空间结构；三平面则把体积特征场显式地分解成三个正交的二维特征图。这个分解带来两个直接好处：特征存储从三维降到二维，计算量大幅下降；同时二维卷积式的结构让特征图具备空间连续性，便于解码器用注意力生成。

具体机制是这样的：空间中一点 (x,y,z) 归一化到单位立方体后，分别在三个平面上采样。在 T_xy 上取 (x,y)，在 T_xz 上取 (x,z)，在 T_yz 上取 (y,z)，每个采样通过双线性插值得到 32 维向量，三个向量拼接成 96 维，再送入 MLP 得到密度与颜色。双线性插值保证了特征场在空间上的连续性，这是三平面能用较小分辨率（64×64）表达较平滑体积的原因。

为什么是三个平面而不是两个或一个？两个平面无法唯一确定三维空间中的点——两个正交平面只能覆盖两个坐标轴的信息，第三个轴的依赖会丢失。一个平面更是只能表达二维结构。三个正交平面是覆盖三维坐标的最小完整集合，任意一点在三个平面上都有唯一投影。这个选择是几何上的必然，不是超参数。

三平面的分辨率 64×64×32 是一个明确的容量约束。64×64 的空间分辨率意味着平面上相邻采样点的间距是 1/64 个物体尺度，对于精细结构（薄片、镂空、细纹理）来说这个间距太粗，双线性插值会把细节抹平。32 通道则是每个采样点的特征维度，通道数决定了 MLP 能从中提取多少信息。消融实验把三平面分辨率列为单独一项，说明提高分辨率是提升质量最直接的杠杆之一，但代价是解码器查询 token 数按平方增长，计算量随之上升。

一个具体的系统代价：三平面的显存占用。三个 64×64×32 的浮点张量在推理时不算大，但在训练时，解码器要为每个查询 token 保留中间激活，24 层、1024 宽的激活量乘以 12288 个查询 token，是训练显存的主要消耗。这就是为什么训练需要数十 GPU 天——不是数据量大到无法处理，而是模型宽度与查询数量共同决定了单步训练的显存与算力门槛。

三平面作为表示的另一个工程优势是可提取网格。推理时不需要体渲染出图，可以直接在三平面上跑 marching cubes：在体积网格上采样密度，找到等值面，输出三角网格。这条路径比体渲染快，但受限于三平面的分辨率——网格的精细程度不会超过 64×64 平面所能表达的细节。这正是论文局限中“网格分辨率有限”的技术根源。

四 · 相机调制与跨注意力：把视角信息注入解码

相机调制是 LRM 中容易被低估的模块。单图重建的输入是一张图加一个相机位姿，相机位姿告诉模型这张图是从哪个方向拍的。如果没有相机信息，模型无法区分“这是物体的正面”和“这是物体的背面”，背面补全就失去了方向性。相机调制的作用就是把这种方向性编码进解码过程。

具体机制上，相机参数（外参的旋转平移、内参的焦距主点）被编码成一个向量，注入到解码器的查询 token 或 cross-attention 的键值中。这样同一个图像特征在不同相机假设下会产生不同的查询行为：当相机假设与输入一致时，解码器倾向于复制可见面的证据；当相机假设偏离输入时，解码器倾向于调用先验补全不可见面。这种条件化让模型学会了一件事——可见性与视角相关，补全必须尊重视角。

跨注意力是相机调制发挥作用的地方。解码器的查询 token 通过 cross-attention 读取 ViT 的 token，注意力权重决定了每个查询从图像的哪个区域取信息。相机调制改变了查询的表示，从而改变了注意力分布。一个直观的例子：位于物体背面的查询 token，在相机调制的作用下，其注意力会更多地落在图像中物体轮廓边缘的 token 上，而不是物体中心的 token——因为背面信息只能从轮廓和先验中推断，中心区域提供的是正面纹理。

这里有一个具体的失败模式：相机参数估计错误。如果输入的相机位姿与实际拍摄视角不符，相机调制会把错误的方向性注入解码，导致三平面在错误的方向上补全。表现是重建物体的朝向偏移，或者可见面与不可见面的衔接出现错位。这不是模型容量问题，而是输入条件错误——相机调制是条件化的，条件错了，输出就错了。

消融实验把相机调制列为单独一项，其含义是：去掉相机调制后，模型仍然能出三平面，但背面补全的质量下降，新视角渲染的 PSNR 降低。这说明相机调制不是提升容量的模块，而是提升条件正确性的模块。在工程上，这意味着部署 LRM 时相机参数的准确性直接影响输出质量，不能把相机位姿当作可有可无的元数据。

跨注意力的计算代价也值得记录。每个查询 token 要与所有图像 token 计算注意力分数，图像 token 数随输入分辨率增长。如果输入图像分辨率提高，ViT 的 token 数增加，cross-attention 的计算量线性增长，而查询 token 数是固定的 12288。这意味着提高输入分辨率是提升证据质量的直接手段，但代价落在 cross-attention 上，而不是解码器的宽度上。

五 · 训练信号：多视角渲染损失如何塑造三平面

LRM 的训练不用 3D 真值，而用多视角渲染损失。这是一个关键的工程选择：训练数据是 Objaverse 约 50 万物体，每个物体渲染 16–32 个视角的图像。训练时，输入是其中一个视角的图像加相机参数，监督是其他视角的渲染图像。模型被要求：从一张图解码出三平面，再用三平面渲染出其他视角，渲染结果要与真实渲染一致。

损失函数是 MSE 加 LPIPS。MSE 约束像素级的颜色一致性，LPIPS 约束感知层面的相似性。两者结合的原因是：纯 MSE 会导致模糊的平均颜色，因为模型在面对不确定的背面时会倾向于输出均值；LPIPS 通过特征空间的比较，鼓励模型生成感知上合理的纹理与结构，而不是一味平滑。这个组合在体渲染训练中是常见做法，LRM 沿用了它。

训练流程的伪代码思路可以这样描述：对每个训练样本，取一个物体的多视角图像集合，随机选一个视角作为输入，其余视角作为监督；输入图过 ViT 得到 token，相机参数编码后与查询 token 一起送入解码器，输出三平面；对每个监督视角，用体渲染从三平面渲染图像，计算 MSE 与 LPIPS，反传更新解码器与（可选的）ViT。优化器是 AdamW，训练持续数十 GPU 天。

这个训练信号塑造三平面的方式很直接：三平面必须包含足够的信息，使得从任意监督视角渲染都能匹配真实图像。这意味着三平面不仅要编码可见面，还要编码不可见面的合理猜测——因为监督视角中有一部分是从背面或侧面看的。模型在训练中学会了“从可见面推断不可见面”的映射，这个映射就是形状先验的来源。

一个具体的系统代价是训练数据的渲染成本。50 万物体、每物体 16–32 视角，意味着需要预先渲染上千万张图像。这些渲染图像是训练数据的一部分，其质量直接影响模型学到的先验。如果渲染时的光照、材质设置与实际部署场景不符，模型学到的先验就会有偏差。这是数据工程的代价，不是模型结构的代价。

另一个失败模式是过拟合到训练物体的分布。Objaverse 的物体以合成资产为主，类别分布与真实场景不同。如果部署时遇到训练分布外的物体（比如极端比例、非常规材质），三平面的补全会退化——模型没见过类似的形状，先验无法给出合理猜测。这不是训练信号不足，而是数据分布覆盖不够。论文的实验在 Objaverse、Google Scanned Objects、Amazon Berkeley Objects 上评估，跨数据集的泛化是它要回答的问题之一。

六 · 模块边界与工程判断

把 LRM 的模块分工画清楚之后，可以看到一条明确的边界：编码器与解码器决定三平面的内容，体渲染只负责把三平面翻译成图像，网格提取只负责把三平面翻译成几何。所有质量问题的根源都在三平面这个瓶颈上，而不在翻译环节。这个判断对工程实践有直接含义：如果要提升质量，应该动的是三平面的分辨率、解码器的容量、训练数据的覆盖，而不是渲染器的采样数或网格提取的算法。

具体到模块间的耦合，有三个地方值得注意。第一，ViT 的冻结与微调是一个权衡：冻结降低训练成本但限制特征适配，微调提升适配但增加显存与训练时间。第二，相机调制的准确性是硬条件，错误的相机参数会直接污染解码的方向性。第三，三平面分辨率与解码器查询数是绑定的：提高分辨率意味着更多查询 token，cross-attention 与自注意力的计算量随之上升，这是质量与速度的直接 trade-off。

一个具体的工程例子：部署时如果要求 10 秒内出 3D，那么解码器的宽度与层数、三平面的分辨率、输入图像的分辨率三者共同决定了时间预算。LRM 的配置（24 层、1024 宽、64×64×32 三平面）是在这个预算下选出的平衡点。如果要提速，可以降分辨率或降宽度，但代价是细节丢失；如果要提质，可以升分辨率或升宽度，但代价是时间超出预算。这个平衡点的选择不是理论最优，而是工程约束下的可行解。

表格对比四个模块的职责与代价，可以把分工固定下来：

模块输入输出主要代价失败模式
DINO ViT单图 patch空间 token 序列冻结省显存，微调增成本分辨率不足导致证据缺失
相机调制相机参数条件化查询可忽略位姿错误导致朝向偏移
Transformer 解码器查询 token + 图像 token三平面 64×64×32参数量主体，cross-attention 计算重证据不足时细节模糊
体渲染 / 网格提取三平面 + 目标相机图像 / 网格采样数决定渲染时间受三平面分辨率限制

这张表的核心信息是：解码器是参数量与计算量的主体，三平面是信息容量的瓶颈，渲染与提取是翻译层。工程上判断一个改进是否值得做，就看它是否触及瓶颈——提升三平面分辨率触及容量瓶颈，值得做但代价高；增加渲染采样数不触及瓶颈，收益有限。LRM 之后的改进工作（TripoSR、GS-LRM、MeshLRM、InstantMesh、CRM）大多在框架上动三平面表示或解码效率，而不是动渲染器，这印证了瓶颈判断。

最后落到一个具体的机制判断：LRM 的前向链路是“证据提取—条件化补全—瓶颈压缩—翻译输出”四步，每一步的失败都可以定位到具体的模块。可见面细节丢失定位到 ViT 的 patch 分辨率；背面补全不合理定位到相机调制与训练数据分布；网格粗糙定位到三平面分辨率；渲染慢定位到采样数与解码器计算量。这种可定位性是模块化架构的工程价值——它让调试有方向，而不是面对一个端到端黑箱无从下手。
