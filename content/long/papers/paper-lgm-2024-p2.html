一 · 从四张图到一组高斯：整条数据流的骨架

LGM 的输入不是单张图像，也不是点云或体素，而是一组固定数量的视图。整条链路可以拆成四个串联的阶段：多视图生成、视图编码、高斯参数预测、可微光栅化。第一阶段由 MVDream 承担，它接收一个条件（文本或图像），输出 4 张彼此一致的多视图图像 I_{1:4}。这 4 张图不是随意渲染的四个角度，而是扩散模型在训练中学会的、共享同一隐式 3D 结构的正交或半正交视角组合，因此它们之间具备几何一致性，这一点是后续前馈预测能否成立的前提。

第二阶段是多视图 Transformer。它把 4 张图分别 patch 化、线性投影为 token 序列，再在视图内部与视图之间做注意力。视图间的注意力是核心：模型必须从 4 个不同投影方向上聚合出同一个三维结构，而不是把 4 张图当作 4 个独立样本。第三阶段是高斯参数头，它把 Transformer 输出的 token 映射为每个高斯的属性：中心位置、颜色（球谐系数或 RGB）、不透明度、旋转四元数与尺度。第四阶段是可微光栅化，把高斯集合按目标相机 \(\mathbf{c}\) 投影、排序、alpha 混合，得到渲染图 \(\hat{I}\)。整条前向写成一行就是论文给出的核心式：

$$\mathcal{G}=\mathrm{GaussianHead}(\mathrm{Transformer}(I_{1:4})),\qquad \hat{I}=\mathrm{Rasterize}(\mathcal{G},\mathbf{c})$$

这条式子的工程含义比它看起来重。它声明了两件事：其一，高斯集合 \(\mathcal{G}\) 是视图集合的确定性函数，没有迭代优化、没有逐场景的测试时拟合，因此推理是单次前馈；其二，监督信号来自渲染损失而非 3D 真值，意味着训练时不需要高斯级别的标注，只需要多视角图像与对应相机。第二点决定了整个训练管线可以规模化——只要有带相机位姿的多视图数据，就能构造监督。

把这条链路画成数据流，每一步的张量形态都在变：4 张 \(H\times W\) 的 RGB 图，经 patch 嵌入变成 \(4\times N\) 个 token（N 为每视图 patch 数），经 Transformer 保持 token 数不变但语义变为跨视图融合特征，经高斯头变成 M 个高斯的属性向量，经光栅化变成目标分辨率下的 2D 图像。这里有一个容易被忽略的约束：token 数与高斯数不必相等，高斯头通常把 token 序列解码为固定或可变数量的高斯，M 是超参，消融里专门考察过高斯数对质量与显存的影响。

一个具体的失败模式出现在这条链的接缝处：MVDream 生成的 4 视图若存在轻微的不一致（例如同一物体在两视图中的轮廓宽度不同），Transformer 会把这部分不一致当作真实几何信号编码进去，高斯头随之产生互相矛盾的深度与尺度，光栅化时表现为漂浮的高斯或背面穿透。这不是训练不充分的问题，而是误差从生成阶段传导到预测阶段的结构性缺陷，后文会单独展开。

二 · 多视图 Transformer：视图内与视图间的两级注意力

Transformer 在 LGM 里承担的不是通用骨干的角色，而是「跨视图几何对齐器」。它的输入是 4 个视图各自的 patch token 序列，输出是融合了四视图信息的 token。实现上有两条常见路线：一是把 4 个视图的 token 直接拼接成一条长序列做全局自注意力；二是分离为视图内自注意力与视图间交叉注意力两级。LGM 采用的是多视图注意力结构，其分工很明确——视图内注意力负责提取单张图的局部纹理与轮廓，视图间注意力负责把同一三维点在不同视图中的投影关联起来。

用伪代码描述其前向逻辑：对每个视图 i，先做 patch 嵌入得到 \(X_i\in\mathbb{R}^{N\times d}\)；然后堆叠若干层，每层内先对每个 X_i 做自注意力，再把 4 个视图的 token 拼成 \(X\in\mathbb{R}^{4N\times d}\) 做全局注意力，或用一个跨视图注意力块让每个视图的 token 以其余视图为 key/value 做查询。两种写法在表达能力上接近，差别在计算代价：全局拼接的注意力矩阵是 \(4N\times 4N\)，跨视图分离写法是 \(N\times 4N\) 量级，后者显存更友好，但需要额外的位置编码来区分视图身份。

位置编码在这里是关键机制。由于 4 个视图的相机参数已知，模型可以把相机位姿编码进 token，使得视图间注意力具备几何意义——它知道哪个 token 来自哪个视角，从而学会把对应关系建立在投影几何上而非纯数据统计上。这也是 LGM 能泛化到未见物体的原因之一：相机条件是输入的一部分，模型学的是「给定这些视角，三维结构应该是什么」，而不是记忆某个物体的外观。

系统代价体现在注意力的二次复杂度上。视图数从 4 增加会线性增加 token 总数，但注意力矩阵随 token 数平方增长；分辨率提高同样使 N 增大。这就是为什么 LGM 选择 4 视图而非更多：更多视图理论上能提供更完整的覆盖，但显存与计算会迅速吃掉收益，且多视图扩散生成更多视角的一致性更难保证。消融中视图数是一个被专门考察的维度，说明这个取舍是设计上的显式选择而非偶然。

一个具体例子可以说明两级注意力的分工：假设输入是一个带细长把手的杯子，某一视图里把手被杯身遮挡只露出一点。视图内注意力在该视图里只能看到一小段轮廓，无法判断这是把手还是噪声；视图间注意力借助另一视图里完整的把手轮廓，把这段轮廓与三维中的把手结构关联起来，高斯头因此能在被遮挡区域也放置合理的高斯。若去掉视图间注意力，被遮挡区域的高斯会缺失或错位，渲染时从新视角看会出现空洞。

三 · 高斯参数头：从 token 到可光栅化的属性向量

高斯头是整条链路里最「3D 化」的模块。它的任务是把 Transformer 输出的跨视图 token 解码为一组 3D 高斯，每个高斯由位置 \(\mu\in\mathbb{R}^3\)、颜色（常用球谐系数）、不透明度 \(\alpha\)、旋转四元数 q、尺度 \(s\in\mathbb{R}^3\) 构成。渲染时每个高斯在屏幕上的贡献由其投影协方差决定，协方差由旋转与尺度经线性变换得到：

$$\Sigma' = J W \Sigma W^{\top} J^{\top}$$

其中 \(\Sigma\) 是世界坐标系下的协方差（由 q 与 s 构造），W 是视图变换，J 是投影的雅可比近似。这个式子说明尺度与旋转不是装饰性参数，它们直接决定高斯在屏幕上的覆盖范围，进而决定渲染的分辨率上限与细节表现。高斯头必须预测出合理的各向异性尺度——太大会糊掉细节，太小会留下空洞。

头的结构通常是若干线性层或小型 MLP，把每个 token 映射为固定维度的高斯属性向量，再按需 reshape 成 M 个高斯。这里有一个设计选择：token 与高斯是一对一还是一对多。一对一实现简单，但受限于 token 数；一对多（例如每个 token 解码出 k 个高斯）能在相同 token 预算下提高高斯密度，代价是头部的输出维度变大、显存占用上升。消融里的高斯数维度正是在考察这个权衡：高斯太少，细节与薄结构表达不足；高斯太多，显存与光栅化开销上升，且训练时更多高斯竞争同一区域容易产生冗余。

位置预测是高斯头最敏感的部分。Transformer 的 token 本身没有显式的三维坐标，头必须从跨视图特征里回归出 \(\mu\)。这相当于让网络隐式地做三角化：同一三维点在多个视图中的投影特征应当一致，头据此推断深度。失败模式很直接——若多视图特征在某区域不一致，头回归出的 \(\mu\) 会落在错误深度，光栅化后从原视角看可能仍然正确（因为原视角的投影恰好对齐），但从新视角看就是错位的高斯。这种「原视角正确、新视角错误」的过拟合是前馈高斯模型的典型病症，也是渲染损失必须覆盖多个训练视角的原因。

一个具体例子：对薄片状物体（如叶片或纸张），高斯头若倾向预测各向同性的大尺度高斯，薄片会被渲染成有厚度的块状；要正确表达薄片，头必须预测出沿法线方向极小的尺度与沿平面方向较大的尺度，即强各向异性。这要求训练数据里存在足够多的薄结构视角，且渲染损失对侧视角敏感。消融中高斯数与视图数的组合，本质上就是在测试头能否在有限 token 下恢复这种各向异性。

四 · 可微光栅化与多视图渲染损失：监督如何回流

光栅化是整条链路唯一产生 2D 图像的地方，也是梯度回流的入口。高斯光栅化的流程是：按深度对高斯排序，对每个像素按投影顺序做 alpha 混合，颜色为球谐系数在视线方向上的求值。混合公式为：

$$C=\sum_{j\in\mathcal{N}} c_j \alpha_j \prod_{k

其中 \(\mathcal{N}\) 是该像素覆盖的高斯集合，按深度从前到后排列，\(\alpha_j\) 是该高斯在该像素的有效不透明度（由二维高斯值与不透明度相乘得到）。这个式子的可微性来自 \(\alpha_j\) 对尺度、旋转、位置的连续依赖，因此渲染损失可以直接对高斯属性求导，不需要任何近似梯度或强化学习。

训练损失是多视图渲染损失：给定一组训练相机，渲染 \(\hat{I}\) 并与真值 I 比较，常用 L1 或 L1 加感知/SSIM 项。关键在于「多视图」三个字——损失不是只在输入视图上算，而是在额外的监督视图上算。若只在输入 4 视图上算损失，模型可以学到一组恰好在这 4 个视角投影正确的高斯，但新视角完全错误；加入监督视图迫使高斯在输入视图之外也保持一致，这是前馈模型泛化到新视角的必要条件。这也解释了为什么训练需要带相机位姿的多视图数据，而不是单图。

系统代价在这里体现为显存。光栅化要为每个训练视图保留高斯排序与混合的中间量，监督视图越多、分辨率越高、高斯数越多，激活显存越大。LGM 的显存开销被明确列为局限之一，其来源正是「多视图 + 高分辨率 + 大量高斯」三者相乘。工程上的缓解手段包括降低训练分辨率、减少监督视图数、分块训练，但这些都会与质量取舍。

一个具体失败模式：若监督视图与输入视图的相机分布差异过大（例如输入是正交四视图，监督是任意随机视角），光栅化的深度排序在极端视角下容易出现高斯穿插，梯度信号变得噪声化，训练不稳定。实践中需要控制监督视角的分布，使其既覆盖新视角又不至于离输入视角太远。这不是理论问题，而是训练配置里的实际约束。

五 · 两阶段训练与场景分块：规模化的两条路径

LGM 的训练分两阶段。第一阶段是 MVDream 的多视图生成，它是一个独立的扩散模型，负责从条件生成 4 视图；第二阶段是高斯模型本身，在 Objaverse 与场景数据上训练，用多视图渲染损失监督。两阶段的解耦很重要：高斯模型不参与扩散模型的训练，它把 MVDream 的输出当作固定输入分布来学习。这意味着高斯模型的质量上限被 MVDream 的视图一致性锁死——生成阶段的误差会直接成为预测阶段的输入噪声，这就是论文列为局限的「误差传导」。

训练时长以数天计，推理以秒计。这个不对称是前馈方法的卖点：逐场景优化（如 DreamGaussian 类方法）在推理时需要迭代优化高斯，耗时以分钟计；LGM 把优化挪到训练阶段，推理只做一次前向加光栅化。代价是训练需要大规模多视图数据与大量算力，且模型容量受显存限制。

场景扩展走的是分块路线。高分辨率场景若整体用一组高斯表达，高斯数与显存会随场景体积增长而爆炸；LGM 的做法是把场景划分为块，每块独立预测高斯，再组合渲染。分块的机制性问题是块间接缝：相邻块若各自预测高斯，接缝处可能出现密度不连续或颜色跳变，因为两块的高斯头看不到对方的上下文。缓解方式包括块间重叠、共享上下文 token、或在渲染时做混合。消融中场景分块是被考察的维度，说明接缝质量与块大小、重叠策略直接相关。

一个具体例子：一个室内场景若切成若干块，每块用 4 视图输入预测高斯，块边缘的墙面上，一块预测的高斯可能略微超出块边界，另一块在相同位置预测了不同尺度的高斯，渲染时接缝处出现重影或亮度突变。这不是光栅化 bug，而是分块决策丢失了全局上下文。工程判断是：分块能换来场景规模，但必须付出接缝处理与额外显存的代价，块越大接缝越少但显存越高，这是一个显式的规模-质量曲线。

把五个模块的分工串起来看：MVDream 负责把条件变成几何一致的 4 视图，Transformer 负责把 4 视图对齐成跨视图特征，高斯头负责把特征变成可渲染的 3D 属性，光栅化负责把属性变成监督信号，两阶段训练与分块负责把整套链路推到物体与场景两个尺度。每个模块都有明确的失败模式与系统代价，而这些代价的叠加——误差传导、显存、细节上限——构成了 LGM 作为「多视图 + 高斯」代表配方的工程边界。
