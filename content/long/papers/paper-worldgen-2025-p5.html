一 · 失效条件：组合式世界生成在哪里断链

WorldGen 的公式把世界写成三个来源的组合：

$$\mathcal{W}=\mathrm{Compose}\!\left(\mathrm{Layout}_{\mathrm{LLM}}(t),\mathrm{Terrain}_{\mathrm{proc}},\{\mathrm{Gen}(o_i)\}\right)$$
这个式子的工程含义是：任何一条支路失效，都不会被另外两条自动补偿。组合式系统的失败是「局部失效 + 全局放大」，而不是端到端模型那种整体退化。要判断哪里不能照搬，先要把断链点列清楚。

第一类断链在布局推理。LLM 输出的是场景图与空间约束，它对「文本里没说的东西」不做保证。文本给出「山谷中的村落，四周有山脊，一条河从北侧穿过」，LLM 能推出村落、山脊、河流的相对关系，但它不会自动保证山脊闭合、河道不穿过建筑、村落出口连通到外部。这些是几何与拓扑层面的约束，LLM 的符号推理不承担。工程上表现为：布局图看起来合理，落到地形与放置阶段才发现不可穿越或自相交。失效模式是「语义正确、几何错误」，而且错误在管线后段才暴露，返工成本高。

第二类断链在程序化地形与布局的接口。程序化生成器按参数产出高度场、河流、道路，它不读 LLM 的场景图语义，只读被翻译成参数的约束。翻译层是整条管线最脆弱的地方：LLM 说「缓坡」，翻译成坡度阈值；LLM 说「河谷」，翻译成高度场下切幅度。翻译错了，地形就与布局脱节。一个具体例子：文本要求「村落位于河的一侧，另一侧是陡坡」，若翻译层把陡坡的坡度阈值设得偏低，程序化地形会在河对岸生成一片可通行缓坡，玩家可以直接走过去，村落的空间叙事被破坏。这类失效不报错，只在验收时以「世界不符合文本」的形式出现。

第三类断链在扩散资产生成。每个物体 \(\mathrm{Gen}(o_i)\) 独立生成，独立生成意味着没有跨物体的尺度与风格一致性约束。同一场景里的门、窗、台阶由不同采样过程产出，尺度可以互相矛盾：门高与台阶高不匹配，窗宽与墙段不匹配。资产质量参差是论文自己列出的局限之一，工程上要把它当成必然项而不是偶发项。失效模式是「单件可看、组合不可用」：每个资产单独渲染都合格，放进场景后出现穿模、悬空、比例失真。更麻烦的是，这类问题在 object-aware 分解与放置阶段才被发现，而那时资产已经生成完毕，重生成的成本是整条管线里最贵的一环。

第四类断链在组合与放置。object-aware 分解把世界拆成物体与背景，放置阶段要把物体放回场景并满足接触、支撑、遮挡关系。放置算法依赖布局给出的锚点，锚点来自 LLM 的场景图，场景图的精度是语义级而非几何级。于是放置阶段要自己做几何求解：物体底部贴合地形高度、物体朝向对齐墙面、物体之间不重叠。这些求解在物体数量上升时组合爆炸。失效模式是「放置失败率随规模上升」：小场景里放置冲突可以人工修，大尺度世界里冲突数量超出人工修复能力，管线要么放弃部分物体，要么输出带缺陷的世界。

把这四类断链放在一起，可以得到一个工程判断：WorldGen 的可靠性由最弱支路决定，而不是由最强支路决定。LLM 布局再准，地形翻译错一步就全错；扩散资产再好，放置冲突多到修不完就不可交付。照搬这套架构时，必须先确定自己的场景里哪条支路是瓶颈，再决定是否值得引入全部四条支路。

二 · 被谁继承：组合路线与可穿越目标的扩散

WorldGen 被继承的不是某段代码，而是两个提法。第一个提法是「LLM + 程序化 + 扩散」的组合路线：LLM 负责语义与布局，程序化负责大尺度结构，扩散负责物体外观，三者用 object-aware 分解缝合。这个分工在论文之后成为场景生成的一条默认路线，因为它把「语义推理」「几何规模」「视觉质量」三类能力分别交给最擅长的模块，避免了单一模型在三件事上同时妥协。继承者通常保留这个三分结构，替换其中一块：把 LLM 布局换成更强的空间推理模型，或把扩散资产换成检索加微调，或把程序化地形换成基于高度场库的拼接。替换一块不影响整体骨架，这是组合路线被继承的根本原因。

第二个提法是「可穿越世界」作为目标。论文把场景生成从房间级推到世界级，并把「可穿越、可交互、可进游戏引擎」写成输出规格。这个规格改变了评测的锚点：不再只看渲染图好不好看，而要看世界能不能走通、能不能交互、能不能导出。继承者接过这个锚点，即使不接 WorldGen 的具体模块，也会按「可穿越」来定义任务。这带来一个副作用：可穿越性难以自动度量，评测缺失成为这条路线共同的短板。论文自己把评测缺失列为局限，继承者至今没有给出公认标准，于是「可穿越」更多是定性验收而非定量指标。

被替代的部分同样清楚。房间级与单图外扩的做法（Text2Room、WonderWorld 这类基线所代表的方向）在「大尺度」这一维上被组合路线取代：单图外扩的视野有限，房间级生成缺少世界级布局，二者都无法直接产出可穿越的大尺度世界。但替代不等于全面胜出：房间级方法在单房间的视觉密度与几何精度上仍有优势，组合路线在大尺度上胜出、在局部精度上让位。工程上这意味着选型要按场景规模分档，而不是一律采用组合路线。

还有一类被替代的是「纯 3D 生成模型直接出世界」的设想。纯生成模型缺布局与游戏逻辑，输出不可编辑、不可导出引擎，WorldGen 用模块化组合绕开了这个限制。但绕开是有代价的：系统复杂度上升，模块间接口成为新的故障源。继承者面对的选择是：接受复杂度换取可控性，或者退回纯生成模型接受不可控。论文的立场是前者，这个立场在工程上只在「需要编辑与引擎导出」的场景里成立；如果目标只是预览图或视频，组合路线的复杂度就是净负担。

把继承关系落到工程判断上：如果你的管线需要布局可控、尺度可控、风格可控，并且要导出到引擎，那么三分结构值得继承；如果你的目标是单房间高保真或快速预览，房间级方法与纯生成模型仍然是更短的路。照搬 WorldGen 的全部模块，只在「世界级 + 可编辑 + 可导出」三个条件同时成立时才是合理选择。

三 · 工程复现清单：按支路拆解的落地项

复现 WorldGen 不是复现一个模型，而是复现一条管线。清单按四条支路拆开，每项都写明输入、输出与验收方式，避免「跑通即完成」的误判。

布局支路。输入是文本，输出是场景图：节点是物体与区域，边是空间关系（包含、相邻、朝向、连通）。落地项包括：场景图的 schema 定义（节点类型、关系类型、坐标约定）、LLM 提示与约束解码（强制输出合法 schema）、场景图到几何约束的翻译层（把「相邻」「连通」翻译成距离阈值与连通性要求）。验收断言：场景图必须通过 schema 校验；翻译后的约束必须能在地形上求解出至少一个可行布局；布局必须包含从入口到所有关键区域的连通路径。失败模式是 schema 合法但约束不可满足，此时要回退到 LLM 重新推理，而不是放宽约束硬解。

地形支路。输入是几何约束，输出是高度场、河道、道路与可通行区域标记。落地项包括：程序化生成器的参数化接口（坡度、下切幅度、噪声种子）、约束求解（把布局约束投影到高度场）、可通行性计算（坡度阈值 + 障碍标记）。验收断言：关键区域之间的路径坡度在阈值内；河道不穿过建筑锚点；世界边界闭合或按设计开放。失败模式是约束冲突导致求解失败，工程上要保留「放宽非关键约束」的降级路径，并记录降级项供人工复核。

资产支路。输入是物体清单（来自场景图），输出是每个物体的网格与材质。落地项包括：生成提示的模板化（把物体类型、风格、尺度写成提示）、尺度归一化（生成后按场景图给的尺寸重缩放）、质量过滤（几何完整性、法线一致性、材质缺失检测）。验收断言：每个资产通过网格完整性检查；尺度与场景图偏差在容差内；材质槽非空。失败模式是资产不合格，工程上要区分「可修复」（重缩放、补材质）与「不可修复」（几何破碎），后者触发重生成，重生成预算要事先设定上限。

组合与导出支路。输入是资产、地形、布局，输出是引擎可读的场景。落地项包括：object-aware 分解的物体-背景分离、放置求解（接触、支撑、不重叠）、引擎导出格式（节点层级、变换、材质引用）。验收断言：放置后无穿模、无悬空；导出文件在目标引擎中可加载；场景图节点与引擎节点一一对应。失败模式是放置冲突与导出不兼容，前者要有限次迭代上限，后者要在管线早期锁定引擎版本与格式。

把清单压缩成一张表，便于排期与验收：

支路关键落地项验收断言典型失败模式
布局schema、约束解码、翻译层schema 合法、约束可解、路径连通语义对、几何错
地形参数化接口、约束投影、可通行计算坡度达标、河道避让、边界闭合约束冲突求解失败
资产提示模板、尺度归一、质量过滤网格完整、尺度达标、材质非空单件合格、组合失真

清单之外还有一项跨支路的工程项：模块间接口的版本管理。四条支路各自迭代时，接口 schema 会漂移，漂移在管线里表现为「上游改了字段、下游静默忽略」。复现时必须把接口 schema 纳入版本控制，并在每次管线运行时做 schema 校验。这一项不写进论文，但它是组合式系统能否长期维护的分水岭。

四 · 验收断言：可穿越与可交互怎么判定

论文把「可穿越、可交互、可进游戏引擎」写成输出规格，但没有给出定量标准。工程复现要自己补上判定，否则验收会退化成「看起来能走」。判定分三层：几何层、逻辑层、引擎层。

几何层的核心断言是连通性。给定入口与关键区域集合，要求存在一条路径满足坡度与障碍约束。形式化地，把世界离散成通行图 \(G=(V,E)\)，节点是可站立点，边是满足坡度与高度差的相邻关系，断言是入口节点到每个关键区域节点在 \(G\) 中可达。这个断言可以自动计算，代价是通行图的规模随世界尺度增长，大尺度世界的通行图构建本身是工程开销。失败模式是「局部可走、全局不通」：每个区域内部连通，区域之间被地形断开。这类失败在渲染图上完全看不出来，只有跑通行图才暴露。

逻辑层的断言是交互对象的可达性与状态一致性。可交互意味着玩家能接近物体并触发行为，行为由游戏逻辑定义。断言包括：交互物体周围存在可站立区域；交互触发条件在场景图里有对应节点；物体状态（开/关、可破坏/不可破坏）与场景图一致。失败模式是「看得见、够不着」：物体放在陡坡或水面上，视觉上在场景里，通行图上不可达。这类失败源于放置阶段只考虑视觉锚点、不考虑通行性，是组合管线里最常见的逻辑层缺陷。

引擎层的断言是导出可用性。断言包括：导出文件在目标引擎中加载无报错；节点层级与场景图对应；材质引用可解析；碰撞体与可视网格匹配。失败模式是「引擎里能看、不能走」：可视网格导出成功，碰撞体缺失或与网格错位，玩家穿墙或卡住。这类失败在管线末端才暴露，修复要回到组合阶段补碰撞体生成，是返工成本最高的一类。

三层断言要按顺序执行：几何层不过，逻辑层与引擎层没有意义；逻辑层不过，引擎层导出的是不可交互的世界；引擎层不过，前两层全白做。工程上要把三层断言写成管线的一部分，每次运行自动跑，失败项分级：几何层失败阻断交付，逻辑层失败标记待修，引擎层失败阻断导出。这样验收才有可操作的判据，而不是靠人工试玩。

还有一项断言针对布局可控性。论文把「布局可控」列为结果之一，工程上要把它变成可检验项：给定文本里的空间关系，断言场景图与最终世界在这些关系上一致。具体做法是把文本里的关系抽成断言集（「村落在河的东侧」「山脊环绕村落」），在世界生成后逐条检验。失败模式是「文本说东、世界在西」，这类失败在 LLM 布局阶段就可能发生，检验要前置到布局输出，而不是等世界生成完再查。

五 · 哪里不能照搬：规模、评测与资产质量的硬边界

有三处不能照搬，每一处都对应论文自己承认的局限，工程上要当成硬边界而不是待优化项。

第一处是系统复杂度。WorldGen 是四条支路加翻译层加放置求解的组合系统，模块数量与接口数量随支路增加而增长。照搬全部模块意味着承担全部接口的维护成本，而接口故障在组合系统里是主要故障源。不能照搬的判断是：如果你的团队没有能力长期维护四条支路的接口与版本，就不应照搬全管线，而应选择其中一到两条支路，其余用现成资产或简化方案替代。具体例子：只保留 LLM 布局加程序化地形，资产用检索库而非扩散生成，管线短一半，故障面也短一半，代价是风格多样性下降。这个取舍在工程上是合理的，在论文的完整架构里看不出来。

第二处是评测缺失。论文把评测缺失列为局限，意味着「世界好不好」没有公认标准。照搬管线但不照搬评测，会导致交付质量不可比：两次运行的世界都「能走」，但布局合理性、资产一致性、交互完整性差异很大，却没有指标区分。不能照搬的判断是：必须自建评测集与断言集，把可穿越性、布局一致性、资产合格率写成可计算项。论文给出的自建世界评测是方向，不是标准；照搬它的评测方法而不补充自己的断言，验收会失去判据。工程上要把评测当成管线的一部分，而不是事后附加。

第三处是资产质量。论文明确把资产质量参差列为局限，扩散资产生成的单件质量与组合一致性都没有保证。照搬资产支路意味着接受这个不确定性，而资产质量直接决定世界的可用性：穿模、悬空、比例失真在可穿越世界里是阻断级缺陷。不能照搬的判断是：如果目标世界要求资产一致性（例如同一建筑风格的门窗台阶），扩散独立生成不足以满足，需要引入跨物体的风格约束或改用检索加微调。具体例子：同一村落的建筑若由独立采样生成，屋顶坡度、墙体材质、门窗比例会互相矛盾，玩家在穿越时会感知到风格断裂。这类问题不是靠增加采样数量能解决的，因为独立采样没有跨物体约束。

把三处硬边界合起来看，可以得到一个选型判断：WorldGen 的完整架构适合「世界级 + 可编辑 + 可导出 + 有维护能力」的场景；缺少任一条件，就应缩减支路而不是照搬全管线。缩减的优先级是：先砍资产支路（改用检索或手工资产），再砍地形支路（改用简化高度场），保留布局与组合导出，因为这两条支路承载了「可控」与「可进引擎」两个核心规格。这个优先级来自失效条件的分布：资产与地形的失效多为局部可修复，布局与导出的失效多为阻断级。

最后一处工程判断落在接口上。组合式世界生成的可靠性不取决于单条支路的最优性能，而取决于支路之间接口的稳定性。WorldGen 的公式把世界写成组合，组合的成败在 \(\mathrm{Compose}\) 这一层：它要把语义布局、程序化几何、生成资产三套不同精度的表示对齐到同一个空间与同一套约束。照搬时最容易被忽略的就是这一层，因为它不产出可见结果，只在失败时以「世界不符合文本」或「放置冲突」的形式出现。工程上要把 \(\mathrm{Compose}\) 当成一等模块来设计和验收，而不是当成胶水代码；接口 schema、约束求解、失败降级路径都要显式定义。这一层做不好，四条支路各自再好，输出的世界也不可交付。
