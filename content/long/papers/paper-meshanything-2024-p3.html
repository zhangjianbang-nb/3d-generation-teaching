一 · 目标函数：从「重建」到「条件序列似然」

MeshAnything 的训练目标不是最小化顶点坐标的欧氏误差，也不是优化 Chamfer 距离，而是把输出网格当作一个由面片 token 构成的离散序列，最大化在给定输入形状条件下的序列似然。设输入形状经编码器得到的条件特征为 c = Encφ(Min)，输出网格被 token 化为长度 L 的面片序列 y = (y1, …, yL)，则训练损失是标准的自回归负对数似然：

这里 θ 是解码器参数，φ 是形状编码器参数，𝒟 是 Objaverse 艺术家网格构成的配对数据集。关键点在于：损失对 φ 也是可导的，因为条件特征 c 通过交叉注意力进入每一层解码器，梯度会回流到点云编码器。这与「先冻结编码器、只训解码器」的两阶段做法不同，端到端训练让编码器学会输出对「面片序列可预测性」友好的特征，而不只是对形状分类友好的特征。

变量含义需要逐层拆开。yt 不是单个顶点坐标，而是一个面片 token；按论文的 tokenization 设计，一个 token 承载一个面片的顶点与邻接信息，因此序列长度 L 直接等于输出面片数（在约 800 面这一量级上）。y<t 是已生成的面片前缀，解码器在每一步只能看到此前生成的面片，这保证了推理时的因果性。c 是输入形状的点云 Transformer 输出，通常是一组定长特征向量，作为交叉注意力的 key/value。

这个目标的系统代价在于：它把「几何精度」问题转化成了「离散分类」问题。每个面片 token 的预测是一个在词表上的 softmax，词表大小由顶点量化分辨率与邻接编码方式决定。词表越大，单步 softmax 越贵；词表越小，顶点坐标量化越粗，输出网格的几何保真度越差。这是一个必须在训练配方里显式权衡的超参，而不是可以事后补救的细节。

具体例子：假设输入是一个面数两万的稠密三角汤，输出目标是一个 800 面的艺术家网格。若采用逐顶点坐标回归，损失会在稠密区域被大量冗余顶点主导；而采用面片序列似然，每个面片 token 对损失的贡献是均等的，模型被迫学会「哪些面片该保留、哪些该合并」，这正是重拓扑所需要的归纳偏置。失败模式也随之而来：当输入形状的局部细节超出 800 面的表达能力时，似然目标不会「报警」，它只会把细节压平成一个可预测的面片序列，输出看起来拓扑干净但细节丢失。

二 · 面片 token 化与词表：离散化的几何代价

要把面片喂进自回归 Transformer，必须先把连续几何离散化。MeshAnything 的做法是把每个面片的顶点坐标量化到固定网格分辨率，再把顶点索引与邻接关系打包成一个 token。设量化位数为 b，每个坐标轴被划分为 2b 个格子，则单顶点坐标的可能取值是 23b；一个三角面片含三个顶点，若朴素地独立编码，词表规模会随 b 指数膨胀。实际实现必须利用面片之间的共享顶点与局部邻接来压缩词表，否则 softmax 层与嵌入矩阵的参数量会失控。

形式化地，设面片 token 的词表为 𝒱，则单步预测的计算量为 O(|𝒱|·d)，其中 d 是隐藏维度。训练时每一步都要对整个词表做 softmax，序列长度 L 步累计为 O(L·|𝒱|·d)。当 L ≈ 800、d 取数百、|𝒱| 取数千到数万时，单条样本的损失计算已经不可忽略；若 batch size 再乘上去，显存与算力开销会迅速成为瓶颈。这就是论文把输出面数上限设在约 800 的直接工程原因之一：序列长度与词表规模共同决定了训练的可承受成本。

tokenization 的消融在论文中被列为关键实验维度，说明它不是无关紧要的预处理。一个具体的失败模式是「顶点漂移」：如果量化格子过粗，同一个顶点在不同面片中被量化到不同格子，解码器会生成拓扑上不连通的「裂缝网格」；如果量化过细，词表爆炸且长尾 token 的梯度稀疏，模型倾向于退化成高频重复的局部面片。工程判断是：量化分辨率必须与目标面数匹配，800 面的输出不需要为百万级顶点预留分辨率。

数值玩具例子：设量化位数 b = 6，每轴 64 格，单顶点坐标空间为 643 = 262144 种。若三个顶点独立编码，朴素词表为 2621443，显然不可行；若改为「首顶点绝对坐标 + 后两顶点相对偏移」的局部编码，并把偏移限制在邻接格内（例如每轴 −1/0/+1 共 27 种），则词表可压缩到 262144 × 27 × 27 量级，仍然偏大，实际还需进一步共享与分块。这个算式说明：tokenization 的设计直接决定了 softmax 是否可训，而不是一个可以随手拍定的格式问题。

三 · 梯度路径与采样：教师强制、因果掩码与逐面推理

训练阶段使用教师强制（teacher forcing）：第 t 步的输入是数据集中的真实前缀 y<t，而不是模型自己采样的前缀。配合因果注意力掩码，位置 t 的表示只能 attend 到 ≤ t 的位置，保证训练与推理的条件结构一致。梯度通过交叉注意力回传到形状编码器，形成「解码损失 → 面片表示 → 条件特征 → 点云编码器」的完整链路。这条链路的代价是：编码器必须为解码器的每一步提供稳定特征，任何输入点云的噪声都会沿这条链路放大。

推理阶段则是自回归逐面生成：从起始 token 开始，每一步对词表做 softmax，按采样或贪心选出一个面片 token，追加到前缀，再喂回解码器。设已生成 t 个面片，第 t+1 步的分布为 pθ(yt+1 | y≤t, c)。采样策略直接决定输出的稳定性：贪心解码确定性高但容易陷入重复面片；温度采样增加多样性却可能生成拓扑冲突的面片；top-k 或 nucleus 采样是常见的折中。论文的推理是逐面生成，这意味着 800 面的输出需要 800 次前向，每次前向都要重算或缓存前缀的 key/value。

系统代价在这里非常具体：逐面生成无法并行化序列维度，推理延迟随面数线性增长。若用 KV cache，显存占用随序列长度增长；若不用 cache，每步重算前缀注意力，计算量是 O(L2) 级别。对于 800 面的输出，这意味着推理是一个串行过程，吞吐受限于单序列延迟而非 batch 并行度。这也是后续 V2 用相邻 token 降低序列长度的动机：序列越短，串行步数越少，推理越便宜。

失败模式举例：在教师强制下，模型从未见过自己的错误前缀。推理时一旦某一步采样出一个拓扑上不可能的面片（例如与已有面片重叠或共享边冲突），后续步骤会在错误前缀上继续生成，误差累积，最终输出一个局部破碎的网格。这是自回归生成的通病，MeshAnything 的缓解手段是依赖输入形状条件 c 的强约束——条件特征在每一步都参与注意力，使模型倾向于生成与输入对齐的面片，但并不能完全消除误差累积。对输入噪声敏感这一局限，正是这条梯度链路与逐面采样共同作用的结果。

四 · 训练配方：数据、规模与关键超参

训练数据是 Objaverse 的艺术家网格，配对方式是「输入形状」与「艺术家网格」的对应。输入形状可以用点云或网格表示，论文把输入表示列为消融维度，说明输入的形式会影响编码器特征的质量。训练在数天量级完成，这个时间尺度对应的是自回归面片预测在中等规模数据上的收敛成本，而不是大规模预训练的周级开销。

关键超参可以列成一张表，每一项都对应一个可观测的系统代价：

超参作用代价或失败模式
输出面数上限（约 800）决定序列长度 L 与细节上限超出上限的细节被压平；序列越长训练与推理越贵
顶点量化分辨率决定词表规模与几何保真度过粗产生裂缝网格；过细词表爆炸、长尾梯度稀疏
输入表示（点云/网格）决定编码器特征点云稀疏导致条件不足；网格稠密导致编码开销大

训练配方的核心张力是「容量 vs 序列长度」。解码器要记住的是「在给定形状条件下，下一个面片应该放在哪里」的条件分布，这个分布的复杂度随输入形状的多样性和输出面数增长。Objaverse 艺术家网格覆盖大量类别与风格，模型必须在单一权重里容纳这种多样性，这要求足够的层数与隐藏维度；但每一层面片 token 的计算又随序列长度线性叠加。论文选择约 800 面的输出上限，本质上是在这个张力下取的一个工程平衡点。

具体例子：若把输出面数上限从 800 提到 2000，序列长度变为原来的 2.5 倍，训练时单条样本的损失计算与显存占用同步上升，逐面推理的串行步数也变为 2.5 倍。这不是一个可以靠增加 GPU 数量线性摊薄的代价，因为序列维度的串行性限制了并行效率。反过来，若把上限降到 400，细节表达能力进一步受限，重拓扑后的网格在曲面区域会出现明显的棱角。消融实验把输出面数列为维度，正是为了量化这条曲线。

五 · 数值玩具例子：一次前向与一次梯度更新

为了把公式落到具体数字上，构造一个极小的玩具设定：序列长度 L = 4（即输出 4 个面片），隐藏维度 d = 8，词表 |𝒱| = 16（仅为示意，真实词表远大于此）。输入形状编码为 3 个条件向量，每个维度 8。解码器在每一步输出 16 维 logits，经 softmax 得到分布。

设第 2 步的真实面片 token 是类别 5，模型给出的 logits 中类别 5 的值为 2.0，其余 15 类的值合计使得 softmax 分母为 Z。则第 2 步的负对数似然为 −log(exp(2.0)/Z) = log Z − 2.0。若 Z 使得 p(y2=5) = 0.25，则该步损失为 −log 0.25 ≈ 1.386。四步损失相加得到序列损失，反向传播时梯度对类别 5 的 logit 是 p5 − 1 = −0.75，对其余类别的 logit 是 pj（j ≠ 5），即把正确类别的 logit 往上推、把错误类别的 logit 往下压。这个梯度再经交叉注意力回传到条件向量，再回传到点云编码器。

把这个玩具放大到真实规模：L ≈ 800、|𝒱| 数千、d 数百。单条样本的 softmax 计算量约为 800 × |𝒱| × d 次乘加，梯度更新要对整个词表的嵌入矩阵做稀疏更新（只有被采样到的 token 获得非零梯度）。这意味着训练时词表嵌入的梯度是高度稀疏的，长尾 token 学得慢，常见面片模式学得快。失败模式是「模式坍塌」：模型倾向于反复生成训练集中高频出现的面片配置，对罕见但几何上必要的面片预测不足，表现为输出网格在复杂区域出现空洞或过度简化。

再给一个采样侧的数字：若贪心解码在每一步取 argmax，则 800 步的串行前向中，任何一步的 argmax 落在错误面片上都会污染后续所有步骤。若改用温度 T = 0.8 的采样，分布被平滑，低概率面片有机会被选中，多样性上升但拓扑冲突概率也上升。工程上通常配合「拓扑合法性检查」在采样时屏蔽非法面片 token，这相当于在解码器输出上叠加一个硬约束掩码，把概率质量重新归一化到合法子集。这个掩码的代价是每步多一次合法性判定，但它把误差累积从「不可控」降为「可控」。

六 · 训练与推理的耦合代价：为什么配方不能只看损失

把目标函数、tokenization、梯度路径与超参放在一起看，会发现一个结构性事实：训练时的损失下降并不等价于推理时的网格质量。教师强制下的序列似然衡量的是「在真实前缀下预测下一个面片」的能力，而推理时模型面对的是自己生成的前缀。两者之间的分布偏移（exposure bias）在长序列上被放大，800 步的串行生成让这种偏移有足够的机会累积。论文把「序列长度受限」列为局限，其工程含义不只是「不能生成更多面」，还包括「序列越长，训练与推理的分布偏移越难控制」。

另一个耦合点是输入噪声敏感。条件特征 c 来自点云编码器，点云的采样密度、离群点、缺失区域都会改变 c。由于梯度链路端到端，编码器在训练中学会的是「对 Objaverse 艺术家网格配对分布最优」的特征，而不是「对任意噪声输入鲁棒」的特征。推理时若输入是重建模型输出的带噪稠密网格，条件特征会偏离训练分布，解码器在每一步的预测都会受到扰动，最终输出的面片序列可能在局部与输入形状错位。这不是可以通过调采样温度解决的问题，而是训练分布与推理分布之间的系统性差距。

具体机制上，交叉注意力是噪声进入解码器的主通道：每一步的 query 来自已生成面片前缀，key/value 来自条件特征。若条件特征中某些向量被噪声主导，注意力权重会错误地集中到这些向量上，导致面片位置偏移。缓解手段包括在输入侧做点云降采样与离群点剔除，以及在训练时对输入点云做扰动增强，使编码器见过带噪条件。这些手段的代价是训练配方更复杂、数据管线更长，但它们直接作用于「输入噪声敏感」这一局限的根源。

工程判断落在具体机制上：MeshAnything 的训练配方之所以把输出面数、输入表示、tokenization 三者作为消融维度，是因为这三者共同决定了「条件特征 → 面片序列」这条映射的可学习性与可推理性。面数决定序列长度与串行步数，输入表示决定条件特征的噪声鲁棒性，tokenization 决定词表规模与几何离散误差。任何一项偏离目标应用场景，损失曲线可能依然漂亮，但推理输出的网格会在拓扑或细节上失效。这就是为什么读这篇论文的训练部分，不能只看负对数似然这一个标量，而要把梯度路径、采样策略与系统代价放在同一张图上衡量。
