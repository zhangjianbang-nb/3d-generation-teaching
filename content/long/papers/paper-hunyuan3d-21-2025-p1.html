一 · 场景：一个资产进不了引擎

设想一个典型的生产现场：美术在概念阶段用一张角色或道具的参考图，通过图像到 3D 的生成模型得到网格与贴图，随后把资产交给关卡设计师放进实时引擎。此时问题立刻显形。生成结果只有一张基础颜色贴图，网格本身带顶点色或一张 diffuse 图，看起来在建模软件的默认视口里尚可，但一旦进入引擎的光照管线，材质就“塌”了：金属部件没有金属感，塑料件和金属件在同一光照下反射行为完全一致，粗糙表面被渲染成光滑镜面，高光沿着错误的法线方向铺开。关卡设计师能做的只有手工重画粗糙度与金属度贴图，或者干脆把资产降级为纯装饰物。这个环节的返工成本远高于生成本身，因为它要求人理解材质的物理含义，而不只是修补一张图。

这个场景暴露的不是“贴图不够好看”，而是资产的数据结构不完整。实时渲染管线消费的是 PBR 材质：一组按物理量定义的通道，至少包括反照率（albedo，即无光照的基色）、粗糙度（roughness）、金属度（metallic），通常还有法线与环境光遮蔽。渲染方程把这些通道作为输入，与光源、环境探针一起决定像素颜色。缺一个通道，方程就少一项，光照表现便无法物理正确地重建。Hunyuan3D 2.0 输出的正是“只有基色”的资产：它能给出形状与颜色，但没有粗糙度与金属度，于是引擎只能拿默认常量填充，材质在物理上失真。这就是 Hunyuan3D 2.1 要解决的现场问题——把纹理阶段从“上色”升级为“生成完整 PBR 材质”，让生成资产可以直接重光照、直接进引擎。

二 · 主流做法：几何与颜色分开，材质被留在门外

在 Hunyuan3D 2.1 之前，图像到 3D 的主流技术路线可以粗略分成两段：几何生成与纹理生成。几何一侧以扩散模型或三平面表示为核心，从单图或多图推断出网格或隐式场；纹理一侧则把生成的颜色投影到网格表面，常见做法是多视图扩散生成若干视角的颜色图，再做视角间的融合，或者直接在 UV 空间做补全。Hunyuan3D 2.0 属于这一路线的代表：形状由 DiT 生成，纹理阶段输出基础颜色，资产在视觉上完整，但材质语义缺失。同期基线里，SF3D 与 TRELLIS 也各自在几何与外观上推进，但它们共同面对的是同一个结构性缺口——颜色是外观，材质是物理。

把颜色当作纹理的全部，会带来三个具体痛点。第一，光照被烘焙进颜色。多视图扩散模型在生成颜色时，看到的参考图本身带有拍摄或渲染时的光照，模型会把阴影、高光、环境色一并画进基色图。这样的贴图在原始光照下好看，换一个光照环境就出现“脏”阴影和错误高光，因为它把光照当成了材质。第二，通道之间不独立。真实材质的反照率、粗糙度、金属度是三个独立的物理量，而只有一张颜色图时，模型无法表达“同一颜色、不同粗糙度”的差异，金属与电介质在颜色上可能完全相同，却在反射上截然不同。第三，管线无法消费。引擎的材质图需要按通道绑定，缺通道意味着必须人工补齐，生成资产因此停在“预览可用、生产不可用”的位置。

于是问题被重新定义：不是“如何生成更好看的贴图”，而是“如何从图像生成带完整 PBR 通道、且能通过物理渲染验证的资产”。这个定义把监督信号从像素相似度推进到渲染相似度，也把数据要求从“多视图颜色”推进到“多视图 PBR 材质”。Hunyuan3D 2.1 的整个设计都围绕这个重新定义展开。

三 · 机制：多视图 PBR 扩散、UV 融合与光照解耦

Hunyuan3D 2.1 沿用 2.0 的形状 DiT，把改动集中在材质分支。材质分支的第一步是多视图 PBR 扩散：对采样得到的若干视角，分别生成反照率、粗糙度、金属度三张图，而不是只生成一张颜色图。这意味着扩散模型的输出通道从 3 个扩展到 9 个（三个物理量各三通道），模型必须在同一视角下同时给出一致的材质分解。多视图之间还要保持材质一致性：同一块金属在不同视角下的粗糙度应当相同，否则融合后会出现斑驳的通道跳变。

第二步是 UV 空间融合。多视图预测是视角局部的，必须投影回网格的 UV 参数化上，才能成为引擎可绑定的贴图。融合的做法是把各视角的预测按可见性与置信度加权投影到 UV 域，再在 UV 空间做补全，填补被遮挡或未被任何视角覆盖的纹素。这一步的工程难点在于 UV 展开本身：网格的 UV 参数化若存在重叠、拉伸或接缝，投影就会产生错位，材质在接缝处断裂。论文把 UV 失败列为明确的局限，说明这不是偶发瑕疵，而是管线中的结构性风险。

第三步是光照解耦。由于参考图与多视图预测都携带光照，模型必须在训练中被引导把光照从材质中分离出去，否则反照率会继续吸收阴影与高光。解耦通过训练策略实现：用带不同光照条件的多视图 PBR 数据，配合渲染监督，让模型学会在改变光照时保持反照率与粗糙度稳定，而把亮度变化归因于光照项。这一步是“可重光照”的前提——只有材质通道与光照解耦，资产换环境后才会表现正确。

监督信号的核心是 PBR 通道的回归损失，论文给出的形式是对每个视角的三个通道做逐项平方误差：

$$\mathcal{L}_{\mathrm{PBR}}=\sum_{v}\left\|\hat{\mathbf{a}}_v-\mathbf{a}_v\right\|^2+\left\|\hat{r}_v-r_v\right\|^2+\left\|\hat{m}_v-m_v\right\|^2$$

其中 $\hat{\mathbf{a}}_v,\hat{r}_v,\hat{m}_v$ 是视角 $v$ 上预测的反照率、粗糙度、金属度，$\mathbf{a}_v,r_v,m_v$ 是对应真值。这个损失只约束通道数值，单靠它不足以保证渲染正确，因此训练还叠加可微 PBR 渲染监督：把预测的材质通道送入可微渲染器，在给定光照下渲染出图像，再与真实渲染比对。可微渲染把“通道对不对”转化为“渲染像不像”，使梯度能够穿过渲染方程回传到材质预测，纠正那些通道数值接近但渲染表现错误的解。这是把物理正确性写进损失的关键机制。

训练数据由 Objaverse 与内部 PBR 资产共同构成，后者提供带完整通道的真值，前者提供规模。形状部分沿用 2.0 的权重与数据，材质分支则用多视图 PBR 数据加渲染监督单独训练。推理阶段，形状与材质分阶段执行，整体耗时在数十秒量级——这个数字本身就是代价：相比只出颜色的管线，多视图 PBR 扩散、UV 融合与渲染监督都增加了计算与显存开销。

四 · 代价与失败模式：数据、UV 与推理时间

第一个代价是数据限制。PBR 材质的真值不像颜色图那样容易获得：带粗糙度与金属度标注的 3D 资产在公开数据中稀少，内部 PBR 资产因此成为训练的主力。数据的稀缺直接约束了模型的泛化边界——对训练分布之外的材质类型（例如特殊涂层、各向异性金属、次表面散射材质），模型没有足够的监督去正确分解通道。论文把数据限制列为局限，意味着 PBR 真实感的提升受制于数据而非架构。

第二个代价是 UV 展开失败。UV 融合依赖网格的参数化质量，而生成网格的 UV 展开并不总是干净：接缝位置不当、岛重叠、拉伸过大都会让投影与补全出错。失败的表现是材质在接缝处出现色差或粗糙度突变，或者某些纹素根本没有被覆盖，融合后留下空洞。这类失败不是靠增加视角数量就能消除的，因为问题出在参数化本身。工程上的应对是检查 UV 质量并在必要时重新展开，但这又把人工环节引回了管线。

第三个代价是推理慢。数十秒的推理时间对于批量资产生成是可以接受的，但对于交互式编辑或大规模场景填充，它构成了吞吐瓶颈。多视图 PBR 扩散要为每个视角生成三个通道，UV 融合与补全还要额外的计算，渲染监督虽然主要在训练期，但推理期的材质验证同样需要渲染。这些开销叠加，使 Hunyuan3D 2.1 的定位偏向“生产级资产生成”而非“实时预览”。

一个具体的失败例子可以说明三者的耦合：假设生成一个带金属扣的皮革包。皮革的粗糙度高、金属度为零，金属扣的粗糙度低、金属度高。若 UV 展开在扣子与皮革的交界处产生接缝错位，融合后的粗糙度图会在交界处出现一条高粗糙度的带，金属扣边缘因此失去金属反射；同时，如果训练数据中缺少类似“高粗糙度皮革紧邻低粗糙度金属”的样本，模型可能把两者的通道预测得过于接近，光照解耦也无法纠正，因为解耦只保证光照变化下通道稳定，不保证通道本身的物理正确。最终资产在引擎中表现为扣子发暗、皮革发亮，需要人工重画通道图。

五 · 为什么非改不可：从“有颜色”到“有 PBR”的分界线

把上述痛点放回管线，就能看清为什么这是一次非改不可的升级，而不是可选的增强。工业管线的验收标准是物理正确的渲染：资产要在不同光照、不同环境探针下表现一致，要能参与基于物理的反射与阴影计算，要能被材质编辑器按通道调整。只有基色的资产无法通过这条验收线，因为它把光照烘焙进了颜色，任何光照变化都会暴露错误。Hunyuan3D 2.1 把纹理阶段升级为 PBR 材质生成，等于把生成资产从“预览物”推进到“管线物”：反照率、粗糙度、金属度三通道齐备，光照解耦使重光照可行，可微渲染监督使物理正确性成为训练目标而非事后修补。

与同期基线相比，这条分界线也很清楚。Hunyuan3D 2.0 提供形状与基色，SF3D 与 TRELLIS 在几何与外观上各有推进，但 PBR 通道的完整性是 Hunyuan3D 2.1 的明确主张：它让生成资产的重光照表现优于基础色模型，并声明工业管线可用。论文的消融进一步确认了这条分界线的三个支点——PBR 通道、光照解耦、贴图分辨率：去掉任一，材质的物理正确性或重光照稳定性都会退化。这说明 PBR 不是“多几张图”，而是训练目标、监督信号与数据结构的整体改变。

从影响看，Hunyuan3D 2.1 与 SF3D 一起把“生产级材质”定义为 3D 生成的新标准：资产不只要能看，还要能进引擎、能重光照、能按通道编辑。这个标准一旦确立，后续的生成模型就被迫在材质语义上竞争，而不是只在几何精度或颜色相似度上竞争。对工程读者而言，判断一个图像到 3D 系统是否可用，第一条就是看它输出的材质通道是否完整、是否经过渲染监督、是否与光照解耦——这三项决定了资产能否通过管线的物理验收，而不是停留在视口里的好看。
