一 · 对比坐标：三条表示路线与两种监督口径

把 Step1X-3D 放进同期方法的坐标系里，第一件事不是比分数，而是确认它们各自站在哪条表示路线上。Step1X-3D 走的是「几何与纹理分离」：几何由 3D 原生扩散（DiT 主干 + SDF/网格解码）产出，纹理由多视图扩散加 UV 反投影产出，两者通过显式网格 M 交接。Hunyuan3D 2.0 同样把形状与纹理拆成两段流水线，但它的形状段以隐式表示为主、纹理段依赖多视图渲染再烘焙，属于「两段式但耦合更紧」的形态；TRELLIS 的核心是结构化潜表示（structured latents），把多种输出格式统一到同一潜空间里再解码，几何与外观在同一个表示框架内解决；Direct3D 则强调从图像/文本直接落到可用的 3D 表示，减少中间环节，走的是「少阶段、强端到端」的路子。

表示路线直接决定了监督口径。Step1X-3D 的几何段可以用 SDF 的符号距离回归加可微渲染的轮廓/深度监督，纹理段则依赖多视图扩散的分数匹配损失再叠加可微渲染的颜色一致性；TRELLIS 的监督更多落在潜空间的重建与渲染一致性上，因为它的输出格式由解码器决定；Direct3D 的端到端形态使得监督信号必须同时覆盖几何与外观，损失项之间的权重平衡成为主要工程负担。用公式表述这种差别：Step1X-3D 的目标可写成两段解耦的形式

$$\mathcal{L}=\mathcal{L}_{\mathrm{geo}}(\mathcal{M},c_{\mathrm{geo}})+\lambda\,\mathcal{L}_{\mathrm{tex}}(\mathcal{T},\mathcal{M},c_{\mathrm{tex}})$$

而端到端方法的损失里 M 与 T 共享同一组参数梯度，λ 不再是两段之间的桥，而是同一网络内部多任务平衡的系数。这个差别在失败模式上非常具体：解耦方案里几何段的错误不会直接污染纹理网络，但几何一旦偏差，纹理段会在错误法线与错误 UV 展开上「忠实地」画出漂亮却贴不上的纹理；端到端方案里几何与外观的错误会互相耦合，表现为整体模糊或局部塌陷，定位困难。工程上判断哪种更适合，取决于你是否需要对几何做独立验收——如果需要，解耦的接口（显式网格）就是可测试的边界。

二 · 可控性逐项拆解：条件通道与编辑接口

Step1X-3D 的可控性由三件事构成：条件编码器（文本/图像/草图/分割）、几何与纹理各自的条件下采样、以及局部编辑接口。机制上，条件不是简单拼接进噪声，而是分成 cgeo 与 ctex 两路：草图与分割主要约束几何段的结构与部件边界，文本与参考图更多影响纹理段的材质与风格；局部编辑则通过在已生成的网格上划定区域、重跑对应段的扩散并保持其余区域不变来实现。对比之下，Hunyuan3D 2.0 的条件通道更偏向图像驱动的整体生成，逐部件的结构指定能力弱；TRELLIS 的强项是输出格式的灵活性而非逐区域编辑；Direct3D 的端到端形态让「局部改一处」缺乏显式接口，只能整体重生成。

这里有一个必须讲清的代价：局部编辑的「保持其余不变」在扩散采样里不是免费的。若编辑区域与保留区域共享 UV 图块或共享潜变量，重采样会通过注意力与卷积的感受野把扰动泄漏到边界之外，表现为接缝处的颜色跳变或法线不连续。工程上的做法是给编辑区域加掩码并在采样时对保留区域做潜变量回填（inpainting 式约束），伪代码思路是：

  • 输入：已生成网格 M、纹理 T、编辑掩码 m、新条件 c′；
  • 对 m 内区域重采样，每步去噪后将 m 外的潜变量替换为原始轨迹对应步的值；
  • 解码后仅在 m 内替换 UV 像素，边界做窄带羽化；
  • 用可微渲染在若干视角核对颜色与轮廓一致性，不达标则回退。

具体例子：给一个已生成的角色资产把袖子改成金属材质，掩码落在袖子对应的 UV 岛；若该岛与躯干共享图集边缘，不做回填就会在袖口出现躯干颜色的渗色。这个失败模式在对比中很能说明问题——Step1X-3D 因为几何与纹理分离、UV 显式存在，编辑接口可以落在「网格区域 + UV 岛」这一可寻址的层级上；而潜空间统一表示的方法做同样的事，需要先在潜空间里找到与袖子对应的子集，这个寻址本身就没有稳定保证。

三 · 速度与显存：两段式流水线的账

推理成本要按段拆开算。Step1X-3D 的几何段是 3D 原生扩散，采样步数与 DiT 的序列长度共同决定耗时；纹理段是多视图扩散，视图数量乘以每视图的去噪步数是主要开销，再叠加 UV 反投影与烘焙。论文给出的量级是推理数十秒，这个数字对应的是两段串行、且纹理段多视图采样的配置。对比方法里，TRELLIS 的单阶段结构化潜表示在采样步数上更紧凑，但解码到高分辨率网格与纹理时仍有可观开销；Direct3D 的端到端路径阶段少，前向次数低，但要在一次前向里同时承担几何与外观的精度，往往需要更大的主干或更多采样步来补偿；Hunyuan3D 2.0 的两段式与 Step1X-3D 结构相近，耗时量级可比，差别主要在纹理段的多视图策略与烘焙分辨率。

显存方面，两段式的优势是峰值可以分段控制：几何段只需承载 SDF/网格解码与 3D 注意力，纹理段才需要多视图 batch 与高分辨率 UV 图集，两段之间可以释放中间激活。代价是串行带来的总时延不可压缩，且段间交接（网格导出、UV 展开、法线传递）引入额外的 CPU 侧开销与失败点。用一条粗略的成本分解表达：

$$T_{\text{total}}\approx T_{\text{geo}}(N_{\text{step}}^{\text{geo}},L_{\text{seq}})+T_{\text{tex}}(N_{\text{view}},N_{\text{step}}^{\text{tex}},R_{\text{uv}})+T_{\text{bake}}$$

其中 Lseq 是几何 DiT 的 token 长度，Ruv 是 UV 图集分辨率。工程判断很直接：若你的部署目标是交互式预览，纹理段的 Nview 是第一个该砍的旋钮，砍它会直接损失背面与遮挡区域的纹理完整性；若目标是离线资产生产，几何段的采样步数与 Lseq 更值得投入，因为几何误差会通过 UV 展开放大到纹理上。失败模式举例：显存受限时把纹理段多视图 batch 调小但保持视图总数，会拉长串行时间并让不同视图之间的噪声轨迹不一致，烘焙后出现视角间的色调漂移——这不是精度问题，而是采样调度问题。

四 · 失败模式对照：每种表示在哪里先坏

逐项对照失败模式，比对照成功案例更有工程价值。Step1X-3D 最先坏的地方是几何段的薄结构与小部件：SDF 在薄壳处梯度稀疏，网格解码容易出现孔洞或厚度失真，随后 UV 展开在这些区域产生拉伸，纹理段即使生成了正确材质也会被拉伸糊掉。第二个坏点是纹理的真实感受数据限制，论文明确把这一点列为局限——训练数据的材质分布决定了模型对金属、布料、次表面散射的覆盖，遇到分布外的材质，多视图扩散会退化成「看起来像但不像那种材料」。第三个坏点是控制能力的边界：草图与分割能约束大结构，但对精细拓扑（例如镂空、缠绕）的指定能力有限。

对比方法各自的先坏点不同。TRELLIS 的结构化潜表示在输出格式切换时，若解码器与潜空间的对应关系不够紧，会在高分辨率细节上出现格式间的不一致；Hunyuan3D 2.0 的两段耦合使得形状段的偏差会直接传导到纹理烘焙的视角选择上；Direct3D 的端到端形态在需要局部修改时缺乏可寻址接口，任何改动都要整体重跑，且端到端损失的平衡一旦偏向外观，几何的锐利边缘就会被平滑掉。把这些放在一张表里，工程上就能按「你的验收断言落在哪一层」来选型。

五 · 决策表：按验收断言选型

把上表转成决策规则，核心问题是「你的验收断言写在哪一层」。若断言是「给定草图，部件位置与比例正确」，那么条件通道对几何的直接约束是硬需求，Step1X-3D 的 cgeo 分离与草图编码正好对上，代价是要接受数十秒的串行时延与薄结构风险。若断言是「同一资产要能导出多种格式并保持外观一致」，TRELLIS 的结构化潜表示更合适，代价是高分辨率细节的格式一致性与解码显存。若断言是「从单图快速出可用资产，接受后续人工修」，Direct3D 的少阶段路径时延更友好，代价是局部修改只能整体重来。若断言是「质量优先、控制其次」，Hunyuan3D 2.0 与 Step1X-3D 形成质量与控制的互补，前者偏质量、后者偏控制，这一点在论文的影响表述里被明确指出。

决策还要看编辑频率。高频局部编辑的场景里，可寻址的编辑接口比单次生成质量更重要：Step1X-3D 的「网格区域 + UV 岛」寻址让每次编辑的改动范围可界定，配合掩码回填可以把泄漏控制在窄带内；而潜空间方法每次编辑都要重新定位子集，工程上难以写成稳定的验收断言。反过来，一次性批量生成的场景里，串行两段式的时延会被摊薄，解耦带来的可测试边界（几何先验收、纹理后验收）反而降低整体返工率。这里有一个具体的工程判断：如果你的流水线里有独立的几何质检环节（例如检查水密性、薄壁厚度、部件数量），解耦表示让这个环节可以插在两段之间，失败就停在几何段，不必浪费纹理段的数十秒；端到端方法做不到这种「早停」，一次失败就是全流程重跑。

最后落在机制上：Step1X-3D 在对比中的位置不是「全面更强」，而是把可控性做成了可寻址的接口——条件分成几何与纹理两路、编辑落在网格与 UV 的显式层级、两段之间有可验收的交接面。这套机制的代价是串行时延、薄结构几何风险与数据受限的材质真实感；收益是失败可以分段定位、编辑可以局部界定。选型时把这三条代价与你的验收断言对齐，比看单一生成质量更能决定这套方法在你的管线里是否站得住。
