一 · 训练数据的真实来源：没有 3D 配对集，只有冻结的 Imagen

DreamFusion 的“数据”一节最容易引起误读。论文标题与摘要反复强调“无 3D 数据”，这句话的准确含义是：优化过程中不存在任何 (文本, 3D 资产) 或 (文本, 多视图) 的配对监督信号，也不存在一个 3D 训练集被用来预训练或微调 3D 网络。整个系统里唯一被训练过的参数载体是 2D 文本到图像扩散模型 Imagen，而它在 DreamFusion 中完全冻结，不接收任何梯度。真正被优化的只有 3D 表示本身的参数 θ——mip-NeRF 360 风格的哈希网格 NeRF。

因此，把 DreamFusion 说成“用 Imagen 的数据训练 3D”是一种口径错误。Imagen 的语料（图文对）确实间接决定了先验的质量与偏置，但它从未以数据集的形式进入 3D 优化循环；循环里流动的只有渲染图像 x、随机噪声 ε、时间步 t、文本 y，以及扩散模型输出的噪声预测 ε_φ(x_t;y,t)。数据来源应当被精确表述为：先验来自冻结的 2D 扩散模型，监督信号来自该模型对加噪渲染图的噪声预测残差。这也解释了为什么 DreamFusion 的“泛化”本质上是继承 2D 先验的泛化，而不是 3D 数据分布上的泛化。

这个设定带来一个具体的机制后果：优化目标不是 RGB 重建损失，而是 SDS。若写成伪代码思路，训练循环的骨架是——采样随机相机位姿与随机光照；用可微渲染器把当前 NeRF 渲染成 64×64 图像 x；采样 t 与 ε，构造 x_t；把 x_t、y、t 送入冻结的 Imagen 得到 ε_φ；计算加权残差 w(t)(ε_φ−ε)；用该残差乘 ∂x/∂θ 反传，更新 θ。注意这里没有任何一张“正确”的 3D 图作为标签，残差本身就是监督。这使训练数据问题转化为“先验是否覆盖该文本所指的视觉概念”的问题，而不是“训练集是否包含该物体”的问题。

系统代价也随之而来。由于监督信号是噪声预测残差而非像素级真值，SDS 梯度带有很高的方差：同一文本、同一 θ，在不同 t、不同相机、不同 ε 下给出的更新方向并不一致。工程上的直接表现是每资产需要约 15k 步、单卡数小时才能收敛，且收敛过程对随机种子与超参敏感。失败模式之一是“先验幻觉被固化”：如果 Imagen 对某文本的典型视图带有系统性偏置（例如偏好正面视角、偏好某种材质高光），SDS 会把这个偏置写进几何与纹理，而不是被多视图一致性纠正。具体例子是生成带文字的物体时，2D 先验倾向于把文字画在朝向相机的面上，SDS 便可能把文字“贴”到多个视角都合理的位置，产生多面重复的纹理，这正是论文自述的多面/过饱和局限的一个来源。

二 · 评测协议：没有标准测试集，只有基线对比与用户偏好

DreamFusion 的评测协议与常规监督学习论文不同：它没有 held-out 测试集，因为没有 3D 训练集也就没有可划分的 3D 测试集；它也没有统一的文本提示清单被当作固定 benchmark。论文采用的评测是与基线的定性/定量对比加上用户偏好研究。基线明确为两类：CLIP-guided mesh optimization 与 Dream Fields。前者代表 2022 年前“用 CLIP 相似度引导可微网格优化”的路线，后者代表用 NeRF 加 CLIP 引导的路线。对比的维度是生成质量与文本对齐，结论是 DreamFusion 显著优于 CLIP 引导方法，用户偏好高。

这里必须讲清指标口径。CLIP 引导方法的优化目标是最大化渲染图与文本的 CLIP 嵌入相似度，这个标量本身可以被“刷”：优化过程能找到与文本嵌入接近、但视觉上并不像该物体的图像，典型表现是形状粗糙、纹理糊、视角间不一致。DreamFusion 的评测若以“人眼看起来像不像”为准，CLIP 引导的分数优势就不转化为感知质量优势，这正是论文用用户偏好而非单一标量来支撑结论的原因。用户偏好研究的口径是让受试者在并排呈现的生成结果中选择更符合文本、更真实的一项；它衡量的是感知质量与文本对齐的联合判断，而不是几何精度。论文没有给出几何误差类指标（如 Chamfer 距离），因为无真值 3D 资产可比。

用表格把评测要素的边界列清楚，可以避免把“无 3D 数据”误读成“无评测”：

要素DreamFusion 的做法口径含义
训练数据无 3D 训练集；先验为冻结的 Imagen不存在配对 3D 监督，只有 2D 先验
测试数据无固定 3D 测试集；按文本提示逐资产生成评测是逐例生成后的感知判断
基线CLIP-guided mesh optimization、Dream Fields对比的是引导信号与表示，不是数据量

这套协议的系统代价是可复现性弱：用户偏好依赖受试者、呈现方式与提示集合，论文未给出可冻结的提示清单与统计口径细节，后续工作难以在同一协议下严格比较。失败模式是“跨论文数字不可比”：不同工作的“用户偏好高”各自定义不同，把两个百分比直接并列就是口径混用。具体例子是后续 Magic3D、ProlificDreamer 等在同一优化式框架上改进时，通常各自重建评测协议，而不是复用 DreamFusion 的偏好数据；这本身说明该协议不是可移植的 benchmark。

三 · 那个容易误读的数字：CFG 尺度约 100

论文训练配方里有一个数字最容易被误读：CFG 尺度约 100。在 2D 文生图实践中，无分类器引导（CFG）尺度通常是个位数量级，取大了会导致过饱和、色彩溢出、模式坍塌。读者看到“100”第一反应往往是“这不可能”或“这一定是笔误”。要正确理解它，必须回到 SDS 的梯度结构，而不是把它当成 2D 采样时的引导强度。

在 2D 采样中，CFG 直接作用于采样轨迹：ε = ε_uncond + s·(ε_cond − ε_uncond)，s 越大，条件方向被放大得越狠，样本迅速偏离自然图像流形，出现典型过饱和。而在 DreamFusion 中，CFG 只用来构造 SDS 的噪声预测目标，梯度是

$$\nabla_\theta\mathcal{L}_{\mathrm{SDS}}=\mathbb{E}_{t,\epsilon}\!\left[w(t)\big(\epsilon_\phi(x_t;y,t)-\epsilon\big)\frac{\partial x}{\partial\theta}\right]$$

其中 ε_φ 是带 CFG 的条件噪声预测。关键在于：这个残差不是直接加到像素上，而是乘上 ∂x/∂θ 后经可微渲染反传到 3D 参数，再被优化器（及其隐式步长）缩放。也就是说，CFG 尺度在 SDS 里相当于一个梯度方向的放大系数，而不是采样步上的位移系数；它放大的是“往文本条件方向走”的分量，而每一步实际走多远由优化器与 w(t) 共同决定。把 s 取到约 100，等价于在残差空间里把条件方向压过无条件方向，使 SDS 的更新方向强烈偏向文本对齐，而优化器的步长把它拉回可控范围。这就是同一个数字在两种语境下含义不同的原因。

误读的代价是工程上的直接翻车：若把 2D 采样里的 s=7.5 直接搬到 SDS，文本对齐会明显不足，生成物偏向先验的平均形状；若把 s=100 搬到 2D 采样，图像会过饱和到不可用。失败模式因此是“超参跨语境移植”。具体例子是复现者在自己的 3D 优化循环里照抄 2D 的 CFG 配方，得到几何模糊、文本不贴合的结果，却误判为 SDS 本身不work；反之，把 100 用在 2D 预览图上会看到严重过饱和，从而误判论文数字有误。正确口径是：CFG 尺度必须与它作用的阶段绑定——在 SDS 残差构造阶段取大值，在 2D 采样阶段取小值，两者不可互换。论文的消融也把 CFG 尺度列为敏感维度，说明它不是可以随手取的常数，而是与 w(t)、步数、优化器共同决定收敛点的配方参数。

四 · 消融的口径：验证的是配方与表示，不是数据规模

DreamFusion 的消融列表——CFG 尺度、视角范围、光照随机化、哈希网格 vs 纯 MLP——每一项都指向“训练配方与 3D 表示”，没有一项指向数据规模。这本身就是评测口径的一部分：论文要证明的是“冻结 2D 先验 + SDS + 可微渲染”这套机制成立，而不是“更多 3D 数据带来更多提升”。因此读消融时不能套用监督学习的“数据消融”直觉。

逐项看机制与代价。视角范围消融检验的是随机相机分布对多视图一致性的作用：若相机只在窄视角范围内采样，SDS 只在该视角流形上施加约束，背面与侧面的几何缺乏监督，提取网格时会出现空洞或厚度异常；扩大视角范围能改善全局一致性，但每一步的梯度方差上升，收敛更慢。光照随机化消融检验的是把“材质/反照率”与“光照”解耦的能力：固定光照会让 SDS 把阴影与高光烘进反照率，换视角后出现不合理的明暗；随机光照迫使 NeRF 学出更中性的反照率，代价是优化难度增加、需要更多步数。哈希网格 vs 纯 MLP 消融检验的是表示容量与收敛速度：哈希网格提供更高的空间频率容量，能更快拟合唱片的细节，纯 MLP 则更平滑但收敛慢、细节不足；代价是哈希网格参数更多、显存占用更高，且对哈希冲突与正则更敏感。

这些消融的共同失败模式是“消融结论被当成通用配方”。例如“哈希网格更好”是在 64×64 渲染分辨率、约 15k 步、单卡数小时的设定下成立的；换到更高分辨率或更少步数，容量与收敛的权衡会变。具体例子是复现者在小显存上直接用大哈希网格，未调正则，得到噪点状几何，却归因于 SDS 不稳定；实际是表示容量与优化步数、正则不匹配。正确口径是：消融给出的是在论文设定下的相对优劣，不是跨设定的绝对结论；引用时应连同渲染分辨率、步数、CFG 尺度一起引用，否则就是口径漂移。

五 · 作弊风险：SDS 可被“刷”的方向与不可比的数字

优化式文生 3D 的评测存在结构性作弊风险，根源是监督信号来自一个可微的、被冻结的 2D 模型，而不是来自独立真值。第一类风险是对先验的对抗性利用：SDS 只要求渲染图在加噪后能让 Imagen 给出“符合文本”的噪声预测，优化过程可以找到让该残差很小、但人眼看来不像该物体的解。典型表现是多面纹理（同一图案在多个视角重复出现，因为 2D 先验对每个视角都给出相似预测）、过饱和（高对比度区域更容易让条件预测占优）、以及几何不精确（薄片、悬浮部件在 64×64 分辨率下残差很小，但提取网格后暴露）。这些不是偶发 bug，而是目标函数与评测口径不一致的必然产物。

第二类风险是指标不可比。用户偏好没有冻结的提示集与统计口径，CLIP 分数又可以被优化过程直接刷高，几何指标缺失。于是“某方法比 DreamFusion 好”这类陈述在不同论文之间往往不可严格比较。工程判断应当是：看到优化式文生 3D 的对比数字，先问三件事——提示集是否相同、评测是人评还是标量、标量是否就是被优化的目标。若标量就是优化目标（如 CLIP 相似度），则该数字不能作为独立证据；若人评没有冻结协议，则跨论文并列就是口径混用。

第三类风险是选择性呈现。逐资产生成意味着提示选择本身会影响观感；挑出先验覆盖好的提示，结果自然更好。论文未给出固定提示清单，这使得“平均质量”难以被外部复核。具体例子是同一文本在不同随机种子下生成的资产差异明显，单张精选图不能代表该文本的期望质量；复现时应固定种子集合并报告分布，而不是只报最好的一张。对应的工程验收断言应是：固定提示集、固定种子集合、固定相机轨迹，报告人评分布与失败率，而不是单一最优样本。

把上述风险落到一个可执行的判断上：DreamFusion 的“数据与评测”真正的贡献不是某个数字，而是把评测问题从“有没有 3D 真值”转成“2D 先验是否被忠实利用、是否被对抗性利用”。读它的实验部分时，应把“显著优于 CLIP 引导”理解为在感知口径下、在论文设定的提示与配方下的相对结论；把“用户偏好高”理解为定性支撑而非可移植 benchmark；把“CFG 约 100”理解为 SDS 残差构造阶段的梯度放大系数，而不是 2D 采样强度。这三条口径一旦混用，后续 Magic3D、ProlificDreamer 等在同一框架上的改进数字就会被错误地横向比较，而它们各自重建的评测协议恰恰说明：这套评测的可比性边界，本身就是工程复现时必须先固定下来的东西。
