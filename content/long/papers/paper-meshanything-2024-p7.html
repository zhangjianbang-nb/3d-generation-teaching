一 · 对比坐标：把“重拓扑”拆成可比的四个轴

把 MeshAnything 与同期方法放在一张表上，前提是先把“网格提取”拆成互不重叠的比较轴。第一个轴是表示：输出究竟以什么形式存在——隐式场加等值面提取、顶点聚类加二次误差简化、还是离散面片 token 序列。第二个轴是监督：训练信号来自几何重建损失（ Chamfer、法向一致），还是来自艺术家网格的逐 token 最大似然。第三个轴是推理代价：一次前向是固定开销，还是随面数线性增长的逐 token 自回归。第四个轴是失败模式：在什么输入上会崩，崩成什么样。只有把四轴同时钉住，跨方法的“谁更好”才有意义；否则拿一个 800 面的生成结果去比一个百万面的简化结果，比较的是预算而不是方法。

MeshAnything 的定位由公式直接给出：

$$\mathcal{M}_{\mathrm{out}}=\mathrm{Dec}_\theta(\mathcal{M}_{\mathrm{in}}),\qquad |\mathcal{M}_{\mathrm{out}}|\ll|\mathcal{M}_{\mathrm{in}}|$$

这个式子说明它不是“重建”而是“重拓扑”：输入可以是稠密三角汤、点云或神经场，输出面数被压到约 800 量级，且面片序列由自回归解码器逐面产生。对照方法里，等值面提取（marching cubes 一类）保持输入场的分辨率，面数量级由体素栅格决定；Quadric 简化在保持几何误差的前提下合并边，面数可调但拓扑继承原网格的缺陷；MeshGPT 则在固定类别的小网格上做生成，无法接受任意输入形状。三条路线在“是否条件于任意输入”这一列上就已经分叉。

具体机制上，MeshAnything 的面片 token 把顶点坐标与邻接关系编码进离散码本，解码器每步预测下一个面片 token，序列长度与输出面数成正比。这带来一个直接的系统代价：序列长度是硬上限。面数上限约 800 意味着细节被截断，超过这个预算的锐边、薄片、镂空会被合并或丢弃；而等值面提取没有这个上限，代价转移到体素分辨率与显存。举例：一个带细密栅格窗花的建筑构件，简化算法能保留窗花但面数上万，MeshAnything 在 800 面预算下会把窗花压成实心面片——这不是算法错误，是预算与表示的联合约束。

二 · 表示与监督：三条路线的信号来源不同

表示差异决定监督差异。等值面提取本质是无监督的几何查询：给定隐式函数，在栅格上求零等值面，不需要训练，误差来自采样分辨率与符号歧义。Quadric 简化是几何误差驱动的贪心合并：每条边计算合并后的二次误差，按代价排序折叠，监督信号是解析的误差度量，没有学习成分。MeshAnything 则是数据驱动的：在 Objaverse 艺术家网格上训练，输入形状编码为点云特征，解码器以逐面片 token 的交叉熵为损失，学的是“艺术家会怎么排布这 800 个面”。

这个差别在失败模式上立刻显形。简化算法的失败是拓扑性的：它继承输入网格的连通性缺陷，稠密三角汤里的自交、非流形边、重复面在折叠后依然存在，甚至被放大。等值面提取的失败是分辨率性的：细薄结构在栅格上漏采样，产生孔洞或断裂，且面数随分辨率立方增长。MeshAnything 的失败是分布性的：输入噪声（点云离群点、神经场的浮渣）会被编码器带进条件特征，解码器据此生成错位面片；同时 800 面预算外的细节被系统性抹平。三者不是同一类错误，不能用一个指标横比。

监督信号还决定了对“艺术家级”的定义权。简化与等值面提取优化的是几何逼近，输出可以是任意拓扑，包括三角汤；MeshAnything 优化的是艺术家网格的 token 分布，输出天然是紧凑、四边形倾向、边流顺滑的拓扑。代价是它只在训练分布内可靠：Objaverse 艺术家网格覆盖的类别之外，解码器没有先验，输出退化为保守的块状面片。这一点在消融里由“输入表示”和“tokenization”两项间接体现——换输入编码或换 token 粒度都会改变输出拓扑的规整度。

一个具体例子能说明监督差异的工程后果：给一个扫描得到的、带噪声的稠密三角汤，简化算法会保留噪声造成的锯齿边，因为二次误差把它们当作几何特征；等值面提取需要先拟合隐式场，噪声在拟合阶段被平滑，但薄结构同时被抹掉；MeshAnything 把点云送进形状编码器，噪声点作为条件特征进入注意力，解码器可能在噪声处生成多余面片。三者都需要前置清理，但清理的目标不同：简化要修拓扑，等值面要修符号，MeshAnything 要修分布。

三 · 速度与显存：固定开销对线性开销

推理代价的结构差异比绝对数字更重要。等值面提取的开销由栅格分辨率决定：显存占用随体素数量增长，一次遍历即可产出全部面片，时间与体素数量近似线性，且高度可并行。Quadric 简化的开销由输入面数和目标面数决定：每轮折叠需要维护代价堆，复杂度与边数相关，输出面数越少迭代越多，但整体是多项式级的批处理。MeshAnything 的开销由输出序列长度决定：自回归逐面生成，每步一次解码器前向，序列长度约等于面数，因此时间随面数线性增长且无法并行化到单序列内部；显存则被形状编码器的点云注意力和解码器的键值缓存共同占据。

伪代码层面，三者的控制流完全不同：

  • 等值面提取：for each voxel cell → 查隐式值符号 → 查表产出三角形，无状态、可任意切分。
  • Quadric 简化：建代价堆 → while 面数 > 目标: 弹出最小代价边 → 折叠 → 更新邻域代价，有全局状态、依赖迭代顺序。
  • MeshAnything：编码点云 → for t in 1..L: 解码器前向 → 采样面片 token → 追加到序列，序列内串行、序列间可批。

系统代价的具体形态：MeshAnything 的批处理只能跨样本并行，单样本内部无法并行，因此吞吐受限于最长序列；800 面上限实际上也是延迟上限，超过预算的模型要么截断要么拒绝。等值面提取的显存峰值出现在高分辨率栅格，分辨率翻倍显存约翻八倍，这是它真正的墙。Quadric 简化的代价堆在百万面输入上会占据可观内存，且折叠顺序影响最终拓扑质量，重复性不如前两者。工程上选择哪条路线，先看预算是“显存换细节”还是“延迟换拓扑”。

一个具体场景：游戏管线里，一个生成模型吐出五十万面的稠密网格，需要进引擎。等值面路线要先体素化再提取，显存峰值出现在体素栅格；简化路线直接在五十万面上折叠到八千面，时间是批处理级；MeshAnything 路线把网格采样成点云，逐面生成 800 面，延迟由序列长度锁定但显存平稳。若目标是“进引擎可渲染”，三者都能交付；若目标是“艺术家可继续编辑的拓扑”，只有第三条给出规整边流，代价是细节上限。

逐项读这张表：在“输入条件”一列，MeshGPT 直接被排除在重拓扑任务之外，它的价值是证明了自回归面片生成可行，而不是解决任意输入。在“拓扑质量”一列，MeshAnything 的优势来自监督分布，而不是来自任何几何优化；这也是为什么它的失败模式是分布性的而非几何性的。在“速度结构”一列，等值面提取的并行度最高，MeshAnything 最低，但后者的输出面数被预算锁死，绝对延迟反而可控。工程判断因此不是“谁最快”，而是“延迟是否可预测”——800 面上限让 MeshAnything 的延迟上界可算，等值面提取的延迟上界取决于调用者给的栅格分辨率。

失败模式的具体例子：一个神经场重建出的薄壳物体，等值面提取在中分辨率下会漏掉壳体产生孔洞，提高分辨率则面数爆炸；Quadric 简化在稠密三角汤上折叠，非流形边被保留，进引擎后法线计算出错；MeshAnything 把薄壳采样成点云，800 面预算下壳体被压成单层面片，形状对齐但厚度信息丢失。三者都“失败”，但失败的位置不同：采样、拓扑、预算。验收断言必须按失败位置分别写，不能共用一条“几何误差小于阈值”。

决策表的使用方式是先钉住两列硬约束：输入是否任意、拓扑是否必须艺术家级。两列都为“是”时，MeshAnything 是唯一同时满足的选项，其余路线要么不接受任意输入（MeshGPT），要么输出继承原拓扑（简化），要么面数不受预算控制（等值面）。但只要有一列放松，代价结构就翻转：面数不敏感时等值面提取的保真优势压过 MeshAnything 的预算约束；可接受原拓扑时简化的批处理速度压过自回归的串行延迟。这张表不是排名，是约束到路线的映射。

工程判断落在最后一行：MeshAnything 的价值不在单点指标，而在它把“重拓扑”变成了可条件生成的一步，从而能嵌进 3D 生成管线作为标准后处理；它的约束（800 面上限、序列长度、输入噪声敏感）是这条路线固有的，不是实现缺陷。选它之前，先确认下游能接受 800 面预算与分布内先验；不能接受时，退回简化或等值面，并接受各自的拓扑或显存代价。决策表的意义是把“哪个方法更好”翻译成“哪条约束先被违反”。
