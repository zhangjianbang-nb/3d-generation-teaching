一 · 数据集构成与评测口径

实验部分的第一个问题是：用什么数据训练、用什么数据比较。论文给出的数据来源只有两类——Objaverse 与内部资产。这两类数据的角色并不对称，理解这种不对称是读懂后续所有结果的前提。Objaverse 是公开的、可复现的、覆盖长尾类别的资产集合，它承担的是「广度」：让形状分支见到足够多样的拓扑、让纹理分支见到足够多样的材质语义。内部资产承担的是「密度」：工业级资产在单一类别上的采样密度远高于公开集合，它把模型在特定品类上的分辨率上限和纹理细节上限拉高。二者混合训练的直接后果是，模型在公开基准上的表现不能完全代表其在工业资产上的表现，反之亦然。论文没有给出两类数据的配比数字，但明确了两阶段各自独立训练、共享图像条件这一事实，这意味着数据配比可以在形状与纹理两个阶段分别调整，而不必迁就同一个折中值。

评测口径上，论文的基线是 TRELLIS、Direct3D、LRM。这三个基线代表了三条不同的技术路线：TRELLIS 走结构化潜表示路线，Direct3D 走直接生成路线，LRM 走大重建模型路线。把它们并列的意义不在于排名，而在于说明「高分辨率几何 + 纹理」这一目标在当时的开源模型里没有现成满足者。论文的定性结论是工业可用性优于同期开源模型，几何与纹理都比同期模型完整。这里必须强调，论文没有给出可引用的定量对比表数字，因此任何「提升百分之多少」的说法都不属于给定事实。可核查的提升来源只有三处：分辨率、纹理的有无与完整度、以及形状与纹理解耦带来的分工。下面的分析全部围绕这三处展开。

还有一个口径问题值得工程读者注意：形状与纹理是分开评测的。形状分支的输出是 SDF，经 Marching Cubes 转成网格，因此形状质量同时受 SDF 精度与等值面提取分辨率影响；纹理分支的输出是 UV 贴图，经多视图渲染与 UV 投影得到，因此纹理质量同时受多视图覆盖度与 UV 展开质量影响。论文把这两个环节分开报告，正是为了让「提升来自哪里」可归因。如果只报一个端到端的资产质量分，就无法区分是几何变好了还是贴图变完整了。

二 · 形状分支的证据链：VecSet 与分辨率消融

形状分支的核心机制是 VecSet 表示加 DiT 扩散，输出 SDF 再由 Marching Cubes 提取网格。消融里明确列出的三项是：形状/纹理分离、VecSet、分辨率。这三项恰好对应三个不同层次的决策，需要分开看。

第一项是形状与纹理分离。消融的逻辑是：如果把纹理生成并入形状阶段做联合建模，会发生什么。论文的答案是形状与纹理的生成目标不同——形状要的是几何精度与拓扑正确性，纹理要的是外观一致性与材质语义，二者对表示、对监督信号、对分辨率的需求都不同。单阶段联合建模会让两个目标互相牵制：几何分支被迫携带外观信息，纹理分支被迫在低分辨率几何上工作。分离之后，形状分支可以专心把 SDF 推到高分辨率，纹理分支可以专心在多视图/UV 空间做扩散。这一项的消融不是「分数涨了多少」，而是「能不能同时拿到高分辨率几何和完整纹理」这个定性门槛。

第二项是 VecSet。VecSet 是一种稀疏、无序的点集式潜表示，它替代了稠密体素或三平面表示。其工程意义在于：稠密体素的分辨率每翻一倍，显存与计算量按立方增长；VecSet 把表示成本与表面复杂度挂钩而非与包围盒体积挂钩，因此在同样的显存预算下能把有效分辨率推得更高。代价是 VecSet 到 SDF 的转换需要额外的解码与等值面提取步骤，且点集的无序性要求网络对排列不敏感。消融中 VecSet 被单列，说明它是形状分支分辨率提升的直接承载者。用伪代码思路描述这条链路：潜变量采样 → DiT 去噪得到 VecSet → 解码为 SDF 场 → 在目标分辨率网格上做 Marching Cubes → 网格后处理。每一步都可能成为失败点，其中 Marching Cubes 的分辨率是最容易被低估的一个。

第三项是分辨率。这是最直观也最昂贵的一项。分辨率的提升不是线性的：SDF 场的采样密度提高后，等值面提取的网格面数上升，显存占用上升，推理时间上升。论文给出的推理代价是数十秒量级，这个数字已经包含了高分辨率提取的开销。一个具体的失败模式是：当目标分辨率高于训练时见过的有效分辨率时，SDF 场在薄壁、尖锐边角处的符号判断会出错，Marching Cubes 会把这些区域提取成断裂的面片或错误的连通分量。这不是扩散模型本身的问题，而是表示与提取环节的分辨率失配。工程上的判断是：形状分支的分辨率上限由「训练分布的有效分辨率」和「提取网格的显存预算」两者中较小的那个决定，而不是由参数量决定。

$$\mathcal{L}_{\mathrm{shape}}=\mathbb{E}_{t,x_0,\epsilon}\big\|\epsilon-\epsilon_\theta(x_t,t,c_{\mathrm{img}})\big\|^2,\qquad x_0=\mathrm{VecSet}(SDF)$$

这条式子只表达形状分支的训练目标：在图像条件 c_img 下对 VecSet 潜变量做去噪。它不涉及纹理项，这正是分离的体现。注意条件 c_img 是共享的——形状与纹理用同一张参考图作条件，但两个分支各自训练、各自 scaling。共享条件的好处是端到端合成时条件语义一致；代价是如果参考图本身对几何的指示有歧义（例如只给正面视图），形状分支只能靠先验补全背面，这部分补全的质量不会因为纹理分支变强而改善。

三 · 纹理分支的证据链：多视图监督与 UV 投影

纹理分支的机制是多视图扩散加 UV 投影。训练监督是多视图渲染，损失形式在给定事实中写得很清楚：对每个视图 v，比较渲染图与真值图的平方误差并求和。这条损失的关键在于「渲染」二字——它不是在 UV 空间直接比对像素，而是把当前 UV 贴图渲染到多个视角后再比对。这样做的好处是监督信号与最终观察方式一致，坏处是梯度要穿过渲染算子，渲染的可见性判断（遮挡）会让梯度在某些面上为零。

$$\mathcal{L}_{\mathrm{tex}}=\sum_{v}\|\hat{I}_v-I_v\|^2,\qquad \hat{I}_v=\mathrm{Render}(\mathrm{UV\text{-}proj}(D_\theta),\,v)$$

这条式子暴露了纹理分支的两个失败模式。其一是视图覆盖不足：如果训练或推理时的视图集合没有覆盖资产的某些区域（例如底面、内凹结构），这些区域的 UV 像素收不到任何梯度，扩散模型只能靠先验填充，结果是模糊或语义错误的贴图。其二是 UV 展开失败：UV 投影要求网格已经有合理的参数化，而形状分支输出的网格是 Marching Cubes 的产物，拓扑可能包含非流形边、细小孔洞或过度细分的区域，这些都会让 UV 展开产生重叠或拉伸。论文明确把 UV 展开失败列为局限之一，这与上面的机制分析一致——UV 失败不是纹理扩散的问题，而是形状输出与参数化之间的接口问题。

一个具体例子可以说明这个接口问题的严重性：假设形状分支在一个薄壁结构上输出了两层几乎重合的面，UV 展开时这两层会被映射到同一块 UV 区域，纹理扩散在这块区域上收到的多视图监督来自两个不同深度的表面，梯度方向相互冲突，最终贴图在这块区域上呈现平均化的颜色，既不属于正面也不属于背面。工程上的缓解手段是在 UV 展开前做网格清理与重拓扑，但这会引入额外的时间成本，而论文已经指出推理较慢是代价之一。

纹理真实感受数据限制这一点也需要放在机制层面理解。多视图监督的监督信号来自渲染图，渲染图的真实感上限由数据本身决定。如果训练数据的材质以漫反射为主、缺乏各向异性高光、次表面散射等复杂材质，那么纹理扩散学到的分布就不会包含这些效果，无论模型多大。这不是 scaling 能解决的问题，而是数据分布的问题。论文把「纹理真实感受数据限制」列为局限，措辞是定性的，没有给出材质类别的覆盖统计，因此工程读者应当把它理解为「纹理分支的上限由数据材质分布决定」这一判断，而不是一个可以通过增大模型规模绕过的瓶颈。

四 · 端到端合成与主要结果的归因

两阶段合成的流程是：形状分支出网格，纹理分支在该网格上出 UV 贴图，最后合成带纹理资产。合成的接口有两个契约：网格的拓扑必须能被 UV 展开，UV 贴图必须与网格的 UV 参数化对齐。这两个契约在分离训练时是不被联合优化的，因此端到端结果的质量不等于两个分支各自质量的最大值，而是两者交集。这就是为什么论文的主要结果强调「完整」而不是单项指标——几何与纹理都比同期模型完整，完整指的是两个契约同时被满足的比例。

把提升归因到具体来源，可以分成三层。第一层是分辨率：形状分支用 VecSet 加高分辨率 SDF 提取，把几何细节推到同期开源模型之上，这一层的证据是分辨率消融。第二层是纹理的有无：同期前馈模型多输出无纹理或低分辨率纹理，而 Hunyuan3D 2.0 输出的是 UV 贴图，这一层不需要消融，它是能力的有无之别。第三层是分工：形状与纹理分离让两个分支可以各自 scaling，这一层的证据是分离消融。三层之中，第一层和第三层是方法贡献，第二层是能力补全。工程读者应当注意，第三层的收益是间接的——它不直接提高任何单项指标，但它使得「同时提高几何分辨率和纹理完整度」成为可能，而在单阶段方案里这两个目标互相挤压。

消融项被移除后的后果对应的机制
形状/纹理分离两个生成目标互相牵制，难以同时拿到高分辨率几何与完整纹理目标函数与表示需求不同
VecSet表示成本随包围盒体积立方增长，有效分辨率受限稀疏点集表示替代稠密体素

表中三行的共同点是：它们都不是「换个损失函数」级别的改动，而是表示层与流程层的决策。这也解释了为什么论文把「两个阶段独立 scaling」放在核心思想的位置——独立 scaling 的前提是表示与流程已经解耦，否则增大任一分支的规模都会被另一分支的瓶颈吃掉。

五 · 代价核算：训练规模、推理时间与失败面

论文给出的训练代价是数十 GPU 天，推理代价是数十秒。这两个数字需要放在两阶段结构下解读。数十 GPU 天是形状与纹理分开训练的总量级，分开训练的好处是任一分支的规模可以单独扩大而不必重跑另一分支，坏处是总训练成本按两个分支相加而非共享。数十秒的推理时间同样要拆开：形状分支包含扩散采样与 Marching Cubes 提取，纹理分支包含多视图扩散与 UV 投影，两段串联。工程上的判断是，推理时间的主要构成不是扩散步数，而是高分辨率网格提取与 UV 展开这两个非神经环节——它们不受 GPU 并行度的线性眷顾，且随分辨率上升而恶化。

失败面可以按分支列举。形状分支的失败面是：高分辨率下的薄结构断裂、拓扑非流形、以及图像条件歧义导致的背面补全错误。纹理分支的失败面是：UV 展开失败导致的重叠与拉伸、视图覆盖不足导致的空洞、以及数据材质分布限制导致的真实感上限。端到端合成的失败面是：两个契约不匹配时出现的贴图错位。这四类失败中，UV 展开失败是论文明确点名的，也是最容易被工程流程缓解的一类——在形状输出与纹理输入之间插入网格清理与重参数化步骤，可以把失败率压下来，代价是时间。

还有一个代价容易被忽略：共享图像条件但独立训练，意味着两个分支对同一张参考图的理解可能不一致。形状分支可能把参考图中的某个区域理解为凸起，纹理分支可能把同一区域理解为平面上的图案。合成时这种不一致表现为几何与贴图的语义错位。这不是通过增大任一分支能解决的，它需要条件编码层面的一致性约束，而论文的分离设计并没有强制这一点。工程读者在复现时应当把这一项列为已知风险。

六 · 影响面的证据：从基线到新基线

论文的影响陈述是定性的：把开源 3D 生成推到工业级，形状-纹理双阶段成为后续 2.1 与 Step1X-3D 的基础，并让「高分辨率 + 纹理」成为 2025 年的基线要求。这三句话里，第一句是能力判断，第二句是方法传承，第三句是评测口径的迁移。第三句最值得工程读者重视：当「高分辨率 + 纹理」成为基线要求后，只输出无纹理网格的模型在工业场景中就不再被视为可比较的对象，评测的默认门槛被抬高。这不是某个指标数字的变化，而是比较对象的集合发生了变化。

从证据链角度看，影响面的支撑来自消融的三项而非主要结果的排名。因为排名依赖基线的选择与评测口径，而消融揭示的是「哪个决策承载了哪部分能力」。形状/纹理分离承载了同时满足两个目标的能力，VecSet 承载了分辨率的经济性，分辨率本身承载了几何细节的上限。后续工作继承的正是这三项决策，而不是某个具体的分数。这也解释了为什么论文把「独立 scaling」写在核心思想里：继承者可以替换扩散骨架、替换条件编码、替换数据配比，但只要保留分离与稀疏表示这两个结构决策，就能继续沿这条路 scaling。

最后落到一个工程判断上：这份实验证据的说服力不在于它证明了某个模型比另一个模型好，而在于它把「提升来自哪里」拆成了可分别验证的三层——表示层的 VecSet、流程层的分离、以及输出层的分辨率与纹理补全。三层之中任何一层被移除，都能在消融里看到对应的能力缺失，而不是一个笼统的分数下降。对于要复现或改造这条路线的人，这意味着改造点是可以定位的：想提分辨率就动 VecSet 与提取预算，想提纹理完整度就动视图覆盖与 UV 参数化接口，想让两个目标不再互相牵制就维持分离训练。这三件事各自有独立的代价核算，也各自有独立的失败模式，把它们混在一起谈「端到端提升」会掩盖真正的瓶颈所在。
