一 · 失效条件：深度条件不是万能的

TextMesh 的核心赌注是：把渲染深度作为扩散模型的条件输入，让 2D 先验在“看到几何”的前提下给梯度，从而把纹理与几何解耦。这个机制在什么情况下会失效，必须从条件信号的物理含义说起。深度条件扩散在深度-图像对上微调，推理时把当前网格的可微渲染深度 \(d\) 与噪声图像潜变量 \(x_t\) 一起喂给去噪网络 \(\epsilon_\phi(x_t;y,d,t)\)。注意这里的 \(d\) 是光栅化得到的 Z 缓冲，它只记录沿相机射线的第一命中距离，是一个 2.5D 信号。当网格存在自遮挡、薄壳结构、凹槽或背面时，单视角深度图无法表达被遮挡区域的几何，去噪网络对这些区域的梯度只能靠先验“猜”。结果是：可见面被拉向正确形状，而遮挡区缓慢漂移，形成局部塌陷或背面穿孔。

第二个失效条件是深度尺度与相机内参的耦合。SDS 梯度对 \(d\) 的依赖隐含了“深度图与训练时深度分布同尺度”的假设。若在优化中改变相机焦距、视场角或渲染分辨率，深度值的动态范围随之改变，扩散模型看到的条件分布偏离微调分布，梯度方向开始失真。工程上表现为：换一个 FOV 后，同一提示词的网格在几轮迭代内出现整体膨胀或收缩，纹理也跟着糊掉。这不是超参问题，而是条件分布漂移。

第三个失效条件是过饱和。SDS 本身是 score 蒸馏，梯度期望指向“更像数据分布”的方向，但缺少真实多视角一致性约束。深度条件缓解了几何-纹理混淆，却没有消除高学习率下颜色向极端值漂移的倾向。当纹理学习率与顶点学习率不匹配时，纹理分支会先收敛到高对比度解，随后几何在过饱和纹理的梯度下被错误塑形。具体例子：提示词里出现“金属光泽”时，纹理分支迅速把高光推到饱和白，深度条件网络把这些高亮区域误读为凸起，几何上出现不该有的脊线。这是典型的跨模态误耦合，深度条件并不能免疫。

第四个失效条件是正则的边界。Laplacian 平滑与法线一致正则压制高频几何噪声，但它们对“结构性错误”无能为力：如果 SDS 把某个区域整体拉向错误深度，平滑只会让错误更连贯。正则的权重需要随迭代阶段调整，前期弱、后期强，固定权重要么抑制细节要么放任噪声。系统代价是：每次调权都要重跑数十分钟到数小时的优化，试错成本高。

二 · 被谁继承，被谁替代

TextMesh 在路线图上的位置是“直接网格 SDS + 深度条件”的可行性证明。它继承的是 DreamFusion 的 SDS 骨架：冻结 2D 扩散、用可微渲染把梯度回传到 3D 参数。它替换掉的是“先训辐射场再提取网格”的两段式管线，把网格表示放到优化回路里，使面数与纹理分辨率在优化期就可控。这个替换带来的直接后果是纹理清晰度优于从辐射场提取的结果，因为纹理是独立参数而不是密度场的副产物。

被继承的部分主要是深度条件这一思想。后续直接网格生成的可微路线把“渲染几何作为条件”当作标准组件：有的把深度换成法线或深度+法线双条件，有的把条件从单视角扩展到多视角拼接，目的都是让 2D 先验“知道自己在看什么几何”。TextMesh 证明这条路径能跑通，于是深度条件从论文里的一个消融项变成了工程默认项。

被替代的部分是“纯 SDS 单阶段”的假设。TextMesh 的慢与分辨率受限，使得后续工作倾向于引入更强的 3D 先验或分阶段策略：先用粗几何快速定型，再在局部做高分辨率纹理细化；或者用多视角扩散替代单视角深度条件，减少遮挡区的盲猜。需要说清楚的是，这些替代不是否定 TextMesh 的机制，而是把它当作基线来加约束。TextMesh 自身没有解决多视角一致性，这恰好是后续路线切入的点。

还有一类替代来自“非可微路线”：把网格生成转成离散 token 序列的自回归模型。这类方法绕开了 SDS 的慢与过饱和，但代价是失去连续可微的纹理优化能力，纹理往往要靠后续贴图管线补。TextMesh 的可微路线在纹理清晰度上有优势，在速度与分辨率上处于劣势，这个取舍决定了它适合“少量资产、高质量、可等待”的场景，而不适合批量快速出模。

工程判断上，TextMesh 更像一个“机制验证器”而非“生产管线”。它证明了深度条件能让网格 SDS 不把纹理烘进顶点色，但没有证明这套管线在任意提示词、任意拓扑下都稳定。把它的结论照搬到生产环境，最常见的错误是低估相机与分辨率变化带来的条件漂移。

三 · 工程复现清单

复现 TextMesh 不是复现一个损失函数，而是复现一条数据流：网格参数 → 可微光栅化 → RGB 与深度 → 深度条件扩散 → SDS 梯度 → 顶点与纹理更新 → 正则。任何一环的接口不一致都会让梯度失真。下面按依赖顺序列出必须固定的接口与检查点。

  • 网格表示：顶点位置、面索引、UV、纹理图。若启用位移，位移方向必须与法线一致，否则 Laplacian 正则会与位移场打架。检查点：初始化网格的面数上限与 UV 无重叠。
  • 可微光栅化：必须同时输出 RGB、深度、以及每个像素对应的面索引（用于把梯度散射回顶点）。深度必须是相机空间线性深度而非归一化值，否则条件分布与微调时不一致。检查点：对同一网格旋转相机，深度图应连续变化，无跳变。
  • 深度条件扩散：冻结权重，输入通道为“噪声潜变量 + 深度条件 + 文本嵌入”。深度条件的归一化方式必须与微调时完全一致，包括裁剪范围与缩放系数。检查点：用真实渲染深度做一次去噪，输出应与输入深度语义对齐。
  • SDS 更新：顶点与纹理使用独立学习率；梯度按面索引散射到顶点时要做面积加权，否则小面片梯度被放大。检查点：单步更新后网格体积变化应在可控范围。
  • 正则：Laplacian 平滑作用于顶点邻域，法线一致作用于相邻面法线夹角。权重随迭代退火。检查点：关闭正则跑若干步，观察是否出现尖刺，以确认正则确实在起作用。

伪代码层面的关键顺序是：先渲染深度与 RGB，再把深度送入条件网络得到 \(\epsilon_\phi\)，用 \(\epsilon_\phi-\epsilon\) 乘以外层权重 \(w(t)\) 与 \(\partial x/\partial\theta\) 回传。注意 \(\partial x/\partial\theta\) 同时经过颜色分支与几何分支，纹理梯度与顶点梯度在同一张渲染图上耦合。若把纹理学习率设得过高，纹理先动，几何梯度被纹理变化污染。工程上建议先冻结纹理若干步让几何定型，再联合优化。

系统代价方面，每步迭代包含一次光栅化、一次扩散前向、一次反向散射，显存占用由分辨率与网格面数共同决定。分辨率受限不是实现细节，而是显存与扩散输入尺寸的硬约束：提高渲染分辨率会同时提高深度条件图尺寸，扩散网络输入变大，单步时间线性上升。复现时若强行提高分辨率而不调整相机内参，会触发第一节说的条件漂移。

一个具体例子：复现“一把带雕花的木椅”时，若 UV 展开把雕花区域压缩到很小纹理块，纹理梯度散射后该区域更新量不足，雕花细节在数十分钟优化后仍模糊。这不是 SDS 的问题，而是 UV 布局与纹理分辨率的联合约束。复现清单里必须加一条：UV 岛面积与目标细节尺度匹配。

四 · 验收断言：怎么判断复现成功

验收不能只看“渲染图好看”，因为 SDS 的过饱和会让渲染图在特定视角下显得锐利，换视角就崩。验收要针对 TextMesh 声称解决的三个痛点分别设断言：几何干净、纹理不烘进顶点色、面数可控。

验收维度断言失败模式
几何干净多视角渲染深度图的法线连续性：相邻像素法线夹角超过阈值的比例低于基线遮挡区塌陷、背面穿孔
纹理独立关闭纹理、仅用顶点色渲染，图像应显著劣化；说明纹理确实承载了外观纹理被烘进顶点色，关闭纹理后外观几乎不变
面数可控输出网格面数等于设定上限，且简化后轮廓不崩面数失控或简化后几何塌陷
条件一致换相机 FOV 后，同一网格的深度条件分布偏移在容差内整体膨胀/收缩
过饱和纹理亮度直方图不集中在两端，高光区域面积占比低于阈值高对比度解导致几何脊线

其中“纹理独立”这条断言最容易被忽略。TextMesh 的动机就是避免纹理与几何混淆，若复现结果在关闭纹理后外观几乎不变，说明优化把外观编码进了顶点色或几何位移，深度条件没有起到解耦作用。检查方法是：在优化中途分别冻结纹理与冻结顶点，观察损失下降来自哪一支。若冻结纹理后损失仍快速下降，说明几何在替纹理“作弊”。

“条件一致”断言的实现方式是：固定网格，改变相机内参渲染深度，把深度送入条件网络，比较去噪输出的语义一致性。若换 FOV 后去噪输出出现系统性偏移，说明归一化或裁剪范围与微调不一致。这条断言不需要真实标签，只需要自一致性。

过饱和断言需要定量：统计纹理图在亮度空间的分布，若高亮像素占比超过设定比例且伴随几何脊线，则判定失败。失败后的修复不是简单降学习率，而是检查 \(w(t)\) 权重 schedule 是否在后期过大，以及纹理与顶点学习率比例是否失衡。

还有一个验收断言针对正则：关闭 Laplacian 与法线正则跑相同步数，若网格质量指标（如法线夹角分布）与开启时差异不显著，说明正则权重过小或实现有误。这条断言用来防止“正则写了但没生效”的静默失败。

五 · 哪里不能照搬

第一，不能照搬“单视角深度条件足以约束全局几何”的假设。TextMesh 的深度条件是单视角渲染，优化过程中相机在采样，但每一时刻只有一个视角的深度进入条件网络。对于对称物体这没问题，对于非对称、有背面细节的物体，背面几何只能靠先验补。照搬到需要全周细节的资产上，会出现正面精细、背面糊成一片。工程对策是显式加入多视角深度拼接或背面专用相机，但这已超出 TextMesh 原文机制。

第二，不能照搬“数十分钟到数小时”的时间预算到交互场景。TextMesh 的慢来自每步一次扩散前向与光栅化反向，这是 SDS 的结构性代价，不是调参能消除的。把它的管线放进需要秒级反馈的工具里，必须做蒸馏或缓存，否则用户体验不可接受。照搬时若只优化实现效率而不改算法，收益有限。

第三，不能照搬“分辨率受限是暂时问题”的判断。分辨率受限与显存、扩散输入尺寸、网格面数三者耦合，提高分辨率会同时抬高深度条件图尺寸与纹理图尺寸，单步成本超线性增长。照搬到高分辨率纹理需求（如近景特写）时，必须分块优化或引入超分，而不是简单调大渲染尺寸。

第四，不能照搬过饱和的“可接受”态度。TextMesh 把过饱和列为局限，但在演示级资产上可容忍。照搬到需要物理正确材质的管线（如金属、玻璃）时，过饱和会破坏后续 PBR 贴图的动态范围，导致材质管线无法复用。工程上应在 SDS 之后加一道纹理色调映射或重新拟合 BRDF，而不是直接把 SDS 输出当最终贴图。

第五，不能照搬“无 3D 训练集”就等同于“无 3D 先验”。TextMesh 依赖的 2D 扩散模型本身携带了大量物体先验，深度条件只是在微调阶段注入几何感知。照搬到分布外的提示词（如抽象雕塑、非自然结构）时，2D 先验的覆盖不足会放大遮挡区盲猜的问题。验收时应把分布外提示词单列一组，观察失败模式是否集中在几何而非纹理。

最后落在工程判断上：TextMesh 的可复现核心是“深度条件 + 网格 SDS + 独立纹理参数”这三件套的接口一致性，而不是某个超参。照搬它的管线时，最该固定的是深度归一化与相机内参的契约、纹理与顶点梯度的散射权重、以及正则的退火 schedule；最该怀疑的是单视角条件对遮挡区的覆盖能力。把这三条契约写成断言，比复现论文里的任何单点结果都更能决定这套管线在你的场景里是否成立。
