一 · 复现目标与最小可跑版本的边界

复现 SF3D 时最容易犯的错误，是把论文当成一个端到端黑盒去追指标。论文给出的能力边界很明确：单图输入，0.5 秒推理，输出带 UV、带 PBR 材质、光照解耦的网格。这四件事在工程上是四条独立的流水线，任何一条断了，最终资产都进不了引擎。所以复现的第一步不是抄超参，而是把“最小可跑版本”定义清楚：它必须能产出一个能被 Blender 或引擎读入、UV 不重叠、带 basecolor/metallic/roughness/normal 贴图的网格，哪怕几何粗糙、材质平淡。指标可以后补，管线闭环必须先立起来。

最小版本的模块切分对应论文架构的六段：单图编码、网格/SDF 解码、快速 UV unwrap、UV 空间纹理生成、材质与法线预测、delighting。复现时建议把前两段和后四段分成两个可独立验收的子系统。前两段决定“有没有网格”，后四段决定“网格能不能用”。很多复现失败在第二段之后就停止了：网格有了，但 UV 是顶点色投影凑出来的，材质是常数填充，delighting 直接省略，结果资产在引擎里换光照就崩，和论文要解决的问题完全脱节。

一个具体的验收例子：拿一张白色陶瓷杯的产品图，最小版本应输出一个闭合网格，UV 岛数量在个位数到几十之间、无重叠，basecolor 贴图上能看到杯身与把手的区分，metallic 接近 0、roughness 中等，normal 贴图在边缘有细节。若输出是顶点色网格或三平面纹理，说明 UV 段没接上；若换一张暖光环境图重渲染后颜色整体偏移，说明 delighting 段缺失。这两个断言比任何 PSNR 都更能判断复现是否走在正确路上。

二 · 目录结构与数据准备的工程约定

推荐的单仓结构按“数据—模型—管线—验收”四层划分，避免训练代码和推理管线互相污染。数据层放原始资产、预处理缓存和 delighting 增强结果；模型层放编码器、SDF/网格解码器、UV 展开器、纹理与材质头；管线层是推理编排，负责把六段串起来并做后处理；验收层放断言脚本和渲染对比工具。关键约定是：UV 展开器和纹理生成器必须是可单独调用的纯函数式模块，输入网格顶点与面，输出 UV 坐标与岛划分，这样崩溃点才能被隔离定位。

数据准备的核心是联合监督的对齐。论文在 Objaverse 与内部产品图上训练，网格、UV、材质联合监督，意味着每条训练样本必须同时具备：干净网格、参考 UV、参考材质贴图、以及用于 delighting 的多光照或低频光照标注。工程上最容易被低估的是 UV 参考的质量——如果参考 UV 本身岛划分混乱，UV 损失会把错误当成目标。建议在预处理阶段加一道 UV 质量过滤：岛数量上限、岛面积下限、拉伸率阈值，不满足的样本直接剔除而不是修补。

delighting 数据增强不是简单的亮度扰动，而是要去除低频光照。可操作的做法是对参考图做低频分量估计并除以它，得到近似 albedo 的目标，同时保留高频细节作为法线与材质线索。增强时要注意成对一致性：同一资产在不同低频光照下的输入图，其 delighting 目标应指向同一 albedo，否则材质头会学到光照残差。这一步的数据代价很高，内部产品图往往没有多光照采集，只能用合成光照近似，这也是复现中材质真实感普遍弱于论文的根因之一。

三 · 超参与联合损失的落地配置

论文的目标函数是三项加权：几何、UV、材质。复现时不要把它当成三个独立训练阶段简单拼接，而要理解权重之间的耦合。几何项收敛慢，UV 项对网格拓扑敏感，材质项依赖前两者提供的 UV 参数化。一个可操作的策略是分阶段解锁：先只训几何到网格闭合稳定，再冻结几何、训 UV 展开器，最后联合训纹理与材质头。每阶段切换时重新校准权重，因为 UV 项在几何未定时梯度会污染顶点位置。

$$\mathcal{L}=\mathcal{L}_{\mathrm{geo}}+\lambda\mathcal{L}_{\mathrm{uv}}+\mu\mathcal{L}_{\mathrm{mat}},\qquad \mathcal{L}_{\mathrm{uv}}=\|\hat{T}(u,v)-T(u,v)\|^2$$

UV 项的形式是在 UV 空间比较预测纹理与参考纹理，这意味着它要求 UV 坐标本身先可用。若 UV 展开器输出重叠岛，同一 (u,v) 会映射到多个面，损失会把不同区域的纹理平均掉，表现为贴图模糊而非报错——这是典型的静默失败。工程上应在 UV 项之外加一个岛重叠惩罚或后验检查，把重叠率作为硬约束而不是软损失。材质项的权重 μ 不宜过大，否则材质头会去拟合光照残差，delighting 步骤反而被绕过。

一个数值玩具例子：设几何项量级为 1，UV 项量级为 0.1，材质项量级为 0.05。若 λ 取 10，UV 梯度会主导更新，几何在早期被拉扯变形；若 μ 取 10，材质头在 UV 尚未稳定时就开始拟合，输出贴图出现跨岛渗色。合理的起点是让三项在初始 batch 上的梯度范数接近同一量级，再按阶段微调。这不是精确配方，而是复现时必须自己测的量——论文没有给出逐项权重，任何声称照抄权重的做法都不可信。

训练配方上，论文提到网格、UV、材质联合监督与 delighting 增强，推理 0.5 秒。复现时要区分训练成本与推理成本：0.5 秒是推理指标，训练侧的 UV 展开若用迭代优化会非常慢，必须换成可并行的快速展开实现，否则数据吞吐撑不起联合训练。常见崩溃点是 UV 展开在训练图中不可微或不可批处理，导致只能离线预计算 UV，进而失去“UV 与几何联合优化”的论文卖点。

四 · 六段管线的接线与常见崩溃点

推理管线按顺序接线：单图编码得到条件特征，SDF/网格解码出显式网格，快速 UV unwrap 生成参数化，UV 空间纹理生成填充 basecolor，材质与法线头预测 metallic/roughness/normal，delighting 去除低频光照后输出 PBR 网格。每一段的输出契约必须写死：网格段输出顶点、面、法线；UV 段输出每顶点的 (u,v) 与岛标签；纹理段输出固定分辨率的贴图张量；材质段输出通道顺序固定的贴图组。契约不清是复现中最常见的集成失败来源。

崩溃点一：UV 展开失败。论文自己把 UV 失败列为局限。工程表现为岛重叠、退化三角形、或展开时间超预算。触发条件通常是网格拓扑复杂或解码网格有自交。缓解手段是展开前做网格清理与简化，展开后做重叠检测并回退到保守切分。注意这不是精度问题而是可用性问题：一个 UV 重叠的网格在引擎里会直接显示错误，不能靠调参掩盖。

崩溃点二：材质通道错位。metallic 与 roughness 常被引擎按不同通道打包，若复现时按论文默认顺序输出而目标引擎期望另一顺序，表现为材质全金属或全粗糙。这类错误不报异常，只在渲染对比中暴露，所以验收层必须有通道断言。崩溃点三：delighting 缺失或过强。缺失时换光照整体偏色；过强时 albedo 被压平、高频细节丢失，表现为贴图发灰。两者都只能通过重光照对比发现。

一个具体例子：复现者用解码网格直接送 UV 展开，未做清理，展开器在把手与杯身连接处产生自交，UV 岛重叠率超过阈值，纹理段把把手颜色渗到杯身。管线没有报错，输出资产在引擎里杯身出现把手纹理残影。修复不是调纹理头，而是在 UV 段加自交检测与切分回退。这说明崩溃点必须按段隔离，跨段调参只会掩盖问题。

五 · 验收断言：把“能跑”变成“可用”

验收断言要覆盖论文的四项能力，而不是只测重建误差。第一组是几何断言：网格闭合性、面数上限、退化面比例。第二组是 UV 断言：岛数量范围、重叠率为零、拉伸率上限。第三组是材质断言：通道顺序、metallic/roughness 取值范围、normal 贴图单位长度接近 1。第四组是光照解耦断言：同一资产在两种低频光照下重渲染，albedo 贴图差异应低于阈值。每组断言都应能在无人工查看的情况下给出通过或失败。

光照解耦断言的构造需要小心。做法是用管线输出的 PBR 贴图在两种不同环境光下渲染，比较渲染结果除以各自光照后的残差；若残差大，说明 albedo 里仍混有光照。这个断言直接对应论文的 delighting 卖点，也是顶点色方法必然失败的项。注意断言阈值要按资产类型分档：产品图的平坦区域容易通过，复杂纹理区域需要放宽，否则会把正常的高频细节误判为光照残留。

验收还应包含一个“最小可跑版本对照”：用同一输入分别跑顶点色基线（如 TripoSR、InstantMesh、CRM 这类基线所代表的顶点色或三平面路线）与 SF3D 复现管线，比较 UV 可用性与重光照稳定性。论文的实验结论是 SF3D 在 0.5 秒内给出 UV + PBR + 光照解耦，重光照优于顶点色方法。复现不必复刻全部基线数字，但必须能定性复现这个对比方向：若你的管线在重光照断言上不如顶点色基线，说明 UV 或 delighting 段接错了，而不是模型不够强。

六 · 复现判断：哪些能照搬，哪些必须自建

能照搬的是架构分工与损失结构：显式网格生成、UV 空间纹理、材质与法线预测、delighting 的顺序是论文的核心贡献，复现时应保持这个数据流不变。不能照搬的是具体权重、UV 展开实现细节与 delighting 增强配方，论文没有给出可直接复制的数值，且这些量高度依赖数据分布。把论文当配方抄的人会在 UV 段和材质段同时遇到静默失败，因为这两段的正确性靠断言而非损失曲线保证。

必须自建的是验收层与崩溃隔离。论文的局限写明 UV 失败、材质真实感受数据限制、几何细节有限，这三条在复现中会以不同形式出现：UV 失败表现为重叠，材质受限表现为贴图平淡，几何有限表现为边缘圆钝。工程判断是：先保证 UV 与 delighting 两段正确，再谈几何细节；因为 UV 与光照解耦是 SF3D 相对顶点色方法的根本差异，几何细节只是程度问题。一个 UV 正确、材质平淡的资产可以进管线迭代，一个几何精细但 UV 重叠的资产无法进引擎。

最后落到具体机制上：复现 SF3D 的成败判定不在训练损失，而在 UV 展开器的输出契约与 delighting 的双光照残差断言。把这两处做成硬门禁，其余段落的超参与实现才有意义；否则任何指标提升都建立在不可用资产之上。
