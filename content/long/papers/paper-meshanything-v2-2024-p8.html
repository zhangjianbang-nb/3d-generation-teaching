一 · 训练语料的构成与筛选口径

MeshAnything V2 的训练数据来源是 Objaverse 中的艺术家网格。这里的“艺术家网格”不是泛指 Objaverse 里所有带几何的资产，而是指经过人工建模、具有相对规整面片组织的那一部分。这个限定直接决定了模型学到的是什么分布：它学到的是“人类建模习惯下的面片排布”，而不是扫描重建或程序化生成器产出的三角面堆。工程上复现时，第一个要问的问题不是“用了多少模型”，而是“筛选脚本按什么条件把资产划进艺术家子集”。论文没有给出筛选阈值，因此可复现的只有定性口径：面片数量落在可被序列长度容纳的区间、网格连通、无退化面、法线朝向一致。任何试图用全量 Objaverse 直接替换的做法都会改变训练分布，进而改变模型对“下一个面片该接在哪条边上”的先验。

数据进入训练前的关键机制是序列化。AMT 把网格表示成一个面片序列，每个面片只编码相对于前一个面片的新顶点。这意味着训练样本不是“网格对象”，而是“网格对象在某种遍历顺序下的 token 串”。遍历顺序本身是一个隐含的超参数：同一个网格可以有多种合法的面片遍历，产生不同的 token 序列，而它们都对应同一个几何。若训练时只取单一确定性遍历，模型会过度拟合该遍历的局部模式；若做随机化遍历增强，则等价于告诉模型“顺序不重要，邻接关系才重要”。论文的表述停留在“在 Objaverse 艺术家网格上训练、使用 AMT 序列”，没有展开遍历策略，这正是复现时最容易被忽略、又最影响收敛的环节。

另一个筛选维度是面数上限。由于序列长度仍然有限，训练样本必须落在模型能完整编码的长度预算内。超出预算的网格要么被截断（破坏拓扑），要么被丢弃（改变分布）。这构成一个隐蔽的选择偏差：模型从未见过“面数超过预算的完整网格”，因此推理时一旦生成接近上限的网格，它对外围闭合的处理就缺乏监督信号。这一点在评测里会以“复杂网格成功率提升但仍有失败”的形式表现出来，而不是以某个显式指标出现。

具体例子：一个由艺术家手工建的低模角色，躯干、四肢、头部各自是独立的面片簇，面片沿环状结构排列。AMT 序列化时，沿环走一圈只需在起始面片记录三个顶点，之后每个面片只新增一个顶点，序列长度接近“面片数 + 常数”。而同样这个模型若用逐面三顶点的旧表示，每个面片都要写三个索引，序列长度约为前者的两倍。训练语料里这类环状、带状结构占比越高，模型越倾向于生成连续条带式的面片推进，而不是随机跳跃的面片。

二 · 评测协议：基线、任务与判定方式

评测的基线是 MeshAnything 与 MeshGPT。三者共享同一个任务设定：给定形状条件（形状编码器输出的条件信号），自回归地生成一个艺术家风格的网格。评测协议的核心不是像素级或 Chamfer 距离这类连续几何指标，而是“生成结果是否是一个合法、可用的网格”，以及“在给定序列预算下能生成多少面”。这决定了指标口径必须同时覆盖拓扑合法性与面数容量两个维度。

协议里最容易被误读的是“成功率”。论文报告的是“复杂网格成功率提升”，这个成功率的分母是“被评测的复杂形状样本”，分子是“生成了拓扑合法且面数达到预期的网格的样本”。它不是生成质量的连续评分，而是一个通过/不通过的布尔判定聚合。判定拓扑合法性通常要检查：边是否恰好被两个面共享（流形性）、是否存在自交、是否存在孤立顶点、面片朝向是否一致。这些检查项里任何一项失败，该样本即计为不通过。因此“成功率”对判定脚本的严格程度极度敏感——放宽自交检查会显著抬高数字，而论文并未给出判定脚本的阈值细节。

面数指标的口径同样需要拆开看。“输出面数 1600”是在同等序列预算下达到的上限，而不是所有样本的平均面数。它描述的是容量：在固定 token 预算内，AMT 表示让模型有可能输出到 1600 面，而旧表示在同一预算下只能到 800 面。把 1600 当作“平均生成面数”是误读；把“800 到 1600”当作“质量翻倍”更是误读——它只是表示容量翻倍，质量仍由拓扑合法性与形状贴合度决定。

具体例子：假设评测集有若干复杂形状，每个形状在固定 token 预算下跑一次自回归生成。旧表示下，模型在写到第 800 个面附近就耗尽预算，被迫截断，截断处产生非流形边，判定失败。AMT 下，同样预算能写到 1600 面，模型有机会把外围闭合，判定通过。成功率提升的来源是“预算够用让闭合得以完成”，而不是“模型变聪明了”。这个区分对工程判断至关重要：如果你的目标形状面数远低于预算，AMT 带来的成功率增益会明显缩小。

三 · 指标口径的陷阱：序列减半不等于信息减半

公式给出的关系是序列长度层面的：

$$\mathrm{AMT}(\mathcal{M})=\big(t_1,\ldots,t_N\big),\qquad |\mathrm{AMT}(\mathcal{M})|\approx \frac{1}{2}|\mathrm{VTT}(\mathcal{M})|$$

这个约等号描述的是 token 数量的比值，不是信息熵的比值，也不是模型有效容量的比值。AMT 之所以能减半，是因为相邻面片共享一条边，共享边的两个端点已经被前一个面片编码过，只需记录新顶点。但“少写两个索引”并不意味着“模型少学两个决策”：模型仍然要在每一步决定“下一个面片接在哪条已有边上、朝哪个方向走”。这个决策的搜索空间没有缩小，只是输出端的书写成本降低了。把序列减半直接等同于“训练难度减半”或“推理速度翻倍”是口径误读——推理仍是逐 token 自回归，步数减少约一半，但每步的注意力上下文与采样开销并未按同比例下降。

更细的陷阱在于“新顶点”的定义。AMT 每一步只编码新顶点，前提是模型能正确推断出共享边的两个端点。推断依赖前序上下文：如果前一步的面片选择了一条与预期不同的边，后续的“新顶点”就会指向错误的几何位置，误差沿序列累积。这意味着序列缩短带来的收益，被“单步错误代价变高”部分抵消。旧表示下每个面片自带三个顶点，单步错误是局部的；AMT 下单步错误会污染后续所有依赖该共享边的面片。这是一个真实的系统代价，论文以“拓扑合法性仍需检查”定性表述，没有量化其传播率。

具体例子：设一个环状条带由 100 个面片组成。旧表示需要约 300 个顶点 token；AMT 下第一个面片写 3 个顶点，之后 99 个面片各写 1 个，共约 102 个 token，比值接近 1/3 而非 1/2——比值随结构而变。若模型在第 50 步选错边，第 51 到 100 步的新顶点全部错位，最终网格在该处出现折叠或非流形。旧表示下第 50 步的错误只影响该面片自身。这就是“序列减半”背后未被公式捕捉的风险结构。

四 · 作弊风险：成功率与面数如何被无意抬高

第一类风险来自判定脚本的宽松化。拓扑合法性检查若只查“边是否被至少一个面引用”而不查“是否恰好两个面”，那么带边界开口的网格也会被判合法。AMT 在预算耗尽时倾向于留下开口，宽松判定会把这种未闭合结果计为成功。复现时应把流形性检查写成断言而非软性评分：每条内部边计数必须等于 2，每个顶点必须至少属于一个面，面片法线一致性用相邻面共享边的走向做符号检查。

第二类风险来自面数指标的选取。若报告“最大面数”而非“预算内平均面数”，任何一次侥幸写到上限的样本都会拉高数字。正确口径应固定 token 预算，报告该预算下的面数分布（中位数与截断率），而不是单点上限。截断率是更诚实的指标：它直接反映“有多少样本因预算不足而无法闭合”。

第三类风险来自训练/评测分布重叠。Objaverse 艺术家网格既是训练来源，若评测集从中抽样且未做资产级划分，模型可能记住特定资产的局部面片排布，成功率被记忆效应抬高。资产级划分要求同一资产的所有变体只出现在一侧，而不是按网格实例随机切分。论文未展开划分细节，复现时必须自行保证这一点。

第四类风险是基线配置不对等。MeshAnything 与 MeshGPT 若在评测时使用了比 V2 更小的 token 预算，面数上限的比较就失去意义。公平比较要求三者共享同一预算口径，并各自报告在该预算下的截断率。表格里的 800 与 1600 只有在“同等预算”这一前提下才可比较，脱离该前提就是口径错配。

具体例子：一个评测脚本把“自交”检查实现为包围盒相交的粗筛，漏掉了大量细长面片的穿插。AMT 生成的条带式网格恰好容易产生细长面片，粗筛下这些穿插未被发现，成功率虚高。换成精确的三角形-三角形相交测试后，同一批样本的成功率下降。这不是模型变差，而是口径变严——说明任何成功率数字都必须附带判定实现的描述。

五 · 一个容易误读的数字：1600

“输出面数从 800 提到 1600”是本部分最容易被误读的数字。它出现在“同等预算下”这一限定里，含义是：固定自回归序列的 token 上限，AMT 表示使模型在耗尽预算前能写出的面片数上限从 800 变为 1600。它不是模型平均输出 1600 面，不是所有形状都能到 1600 面，也不是质量指标。误读的三种典型形态：把它当作平均面数、把它当作“能力翻倍”、把它当作与形状复杂度无关的常数。

为什么是约两倍而不是精确两倍？因为 AMT 的压缩比依赖网格的邻接结构。高度条带化、环状闭合的网格压缩比接近 1/2 甚至更低；而面片邻接稀疏、频繁跳转到不相连区域的网格，每个新面片仍要写较多新顶点，压缩比下降。因此 1600 是在训练分布（艺术家网格，条带结构占比高）下的容量上限，换到邻接稀疏的分布上，同一预算下的可达面数会低于 1600。这个数字是分布相关的，不是表示方法的内禀常数。

工程判断上，应把 1600 当作“预算-容量曲线的端点”来用，而不是当作验收阈值。验收断言应写成：在给定 token 预算 B 下，生成网格的面数中位数不低于某值、截断率不高于某值、流形性检查通过率不低于某值。三个指标联立才能约束住“容量被用满但拓扑崩坏”和“拓扑合法但容量没用满”两种失败模式。单看 1600 无法区分这两者。

具体例子：同一模型对两个形状生成。形状 A 是环状条带，AMT 下写到 1600 面时预算刚好耗尽，闭合完成，判定通过。形状 B 是多个不相连的面片簇，每次跳转到新簇都要写三个新顶点，写到约 900 面时预算耗尽，留下开口，判定失败。两者共享同一预算、同一模型，面数却差近一倍——这正说明 1600 是上限而非均值，且上限的可达性由邻接结构决定。

六 · 复现时的数据与评测清单

数据侧的最小清单：资产级划分训练/评测，禁止同资产跨侧；序列化遍历策略显式记录（确定性或随机化），因为遍历改变 token 分布；面数超出预算的样本处理方式（丢弃或截断）必须与评测口径一致，否则训练与评测的分布错位；艺术家子集的筛选条件写成脚本并留档，因为它是“艺术家风格”这一先验的唯一来源。

评测侧的最小清单：固定 token 预算 B，三者（V2、MeshAnything、MeshGPT）共享；报告面数中位数、截断率、流形性通过率三项，而非单点上限；流形性检查实现为硬断言（每条内部边计数等于 2、无孤立顶点、法线一致），并记录检查实现的版本；成功率的分母明确为评测样本数，分子为三项断言全过的样本数；对 AMT 特有的“单步错误传播”做定向抽样，统计错误步之后的失败面片占比，作为序列压缩的代价度量。

失败模式的验收断言应覆盖三类：预算耗尽导致的开口（截断率）、共享边推断错误导致的折叠（流形性通过率）、邻接稀疏分布下面数上限下降（面数中位数随分布漂移）。这三类恰好对应 AMT 的三个结构性代价：序列仍有限、拓扑合法性仍需检查、细节上限。把它们写成可执行的断言，比记住 1600 这个数字更有工程价值。

最后落在机制上：AMT 的评测口径必须与它的表示机制对齐——它压缩的是书写成本而非决策空间，因此任何以“序列长度”为分母的指标都不能直接换算成质量；任何以“面数上限”为分子的指标都必须附带预算与分布限定。评测协议若不显式记录遍历策略、预算口径与合法性检查实现，成功率与面数就只是脚本参数的函数，而不是模型能力的度量。
