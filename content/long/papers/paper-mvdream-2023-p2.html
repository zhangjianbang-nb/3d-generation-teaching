一 · 一次前向的数据通路：从文本与位姿到四张图

MVDream 的推理入口有两个张量：一条文本提示的 token 序列，和四个相机位姿。位姿不是随手给的欧拉角，而是每个视角一个相机到世界的外参与内参组合，工程上通常压成一个位姿向量再经 MLP 投到嵌入空间。四个位姿在训练时取自 Objaverse 渲染管线里固定的环绕采样，因此模型学到的是「同一物体、四个已知相对方位」的联合分布，而不是任意视角的连续场。这一点决定了后面所有模块的分工：位姿是条件，不是待求量。

数据流的每一步可以拆成五段。第一段，文本经冻结的文本编码器得到上下文序列，作为 U-Net 的 cross-attention 条件，四个视角共享同一份文本嵌入，这是跨视图语义一致的第一道锚。第二段，四张图各自 patch 化，展平成 token 序列，每张图的 token 前面拼上该视角的位姿嵌入，使同一 patch 在不同视角下带有不同的几何标签。第三段，四段 token 序列按视角顺序拼接成一条长序列送入 U-Net，这是「拼成序列」的字面含义——不是四个独立 batch，而是一条序列里的四个区块。第四段，U-Net 的自注意力在这一条长序列上做全局计算，于是视角 A 的 patch 可以直接 attend 到视角 B 的 patch，跨视角约束就发生在这一步。第五段，一次去噪迭代同时输出四张图的噪声预测，采样结束时得到四张几何一致的多视图图像。

把这条通路写成伪代码式的骨架，能看清条件注入的位置：

$$\begin{aligned} c &= \mathrm{TextEnc}(y) \\ e_i &= \mathrm{PoseMLP}(\pi_i),\quad i=1\ldots 4 \\ x_i &= \mathrm{Patchify}(I_i^{(t)}) + e_i \\ X &= [x_1; x_2; x_3; x_4] \\ \hat{\epsilon} &= \mathrm{UNet}(X, t, c) \\ X^{(t-1)} &= \mathrm{Scheduler}(X^{(t)}, \hat{\epsilon}) \end{aligned}$$

注意拼接发生在 patch 维度而非像素维度：四张图并没有被拼成一张大画布，而是在 token 层面串成一条序列。这个选择带来两个工程后果。其一，序列长度是单图 token 数的四倍，自注意力的计算量与显存随序列长度呈二次增长，四视图的代价不是线性的四倍，而是注意力矩阵的四倍规模再乘上长度因子。其二，位置编码必须区分「这是第几个视角的第几个 patch」，否则模型无法知道某个 token 属于哪张图，跨视角注意力会退化成无序的全局池化。论文的位姿嵌入承担的正是这个区分职责，它同时编码了视角身份和几何方位。

一个具体的失败模式出现在位姿嵌入被削弱时：如果只给视角索引而不给几何方位，模型仍能生成四张「看起来像同一物体」的图，但视角间的相对旋转关系会漂移，四个视角可能对应四个不相容的相机朝向，接 SDS 时梯度互相打架。消融里跨视角注意力和视图数被单独拆开验证，说明这两者不是冗余设计，而是分别负责「信息互通」和「几何锚定」。

二 · 跨视角自注意力：一致性到底从哪里来

一致性的来源不是损失函数里的显式约束项，而是注意力机制里的隐式耦合。单视图扩散模型的自注意力只在同一张图的 patch 之间计算，每个视角独立去噪，于是同一物体在不同视角下被独立「幻想」出各自的细节，纹理和结构对不上。MVDream 把注意力矩阵扩展到跨视角区块，让视角 i 的 query 可以取到视角 j 的 key 和 value，去噪时每个视角的更新都参考了其他视角当前的状态。这就是「互相看到」的机制落地。

论文给出的注意力形式在标准缩放点积上只加了一项偏置：

$$\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}+b_{\mathrm{view}}\right)V$$

其中 $b_{\mathrm{view}}$ 是视角相关的偏置项，用来调制跨视角注意力的强度或方向。这个式子的工程含义是：跨视角耦合不是一个硬约束，而是可学习的软偏置。模型可以在需要时让某两个视角强耦合（比如相邻视角共享大量可见面），在遮挡关系明确时减弱耦合。相比把多视图一致性写成显式的重投影损失，软偏置的好处是不需要可微渲染器参与训练，坏处是没有几何上的硬保证——一致性是学出来的统计规律，不是解出来的几何约束。

这里有一个容易被忽略的系统代价：跨视角注意力让四张图的去噪轨迹互相依赖，采样不再是四个独立马尔可夫链，而是一个联合链。工程上这意味着不能对四个视角分别做 batch 并行再合并，必须把整条拼接序列作为一个样本前向。批量大小因此被序列长度挤压，四视图联合采样的显存占用明显高于四次单视图采样之和。在有限显存下，这直接限制了可用的分辨率与视图数，也是论文把视图数固定为四的现实约束之一。

具体例子可以看一个带文字的物体：单视图模型在正面视角生成某个字母，转到背面视角时会把同一区域幻想成完全不同的图案，因为背面视角从未「看到」正面的决策。而在联合去噪里，背面视角的 query 在早期去噪步就会 attend 到正面视角尚未成形的 token，两者在噪声阶段就交换了布局信息，最终纹理在四个视角上趋于同一套假设。这种早期耦合是关键：一致性不是在最后一步对齐出来的，而是在整条去噪轨迹上逐步协商出来的。

失败模式也随之而来。跨视角注意力只能约束「共同可见」的部分。四个环绕视角覆盖了物体的侧面，但顶部、底部以及被遮挡的内凹区域没有任何视角直接观测，这些区域的 token 没有可 attend 的对应证据，只能靠先验填充。这就是论文承认的背面幻想问题的机制根源：不是模型不想一致，而是注意力没有可耦合的对象。视图数固定为四，等于把可观测立体角钉死在一个有限范围，超出范围的几何没有任何跨视角证据。

三 · 联合训练：Objaverse 多视图与 2D 图像各司其职

训练数据由两路构成，分工明确。Objaverse 的多视图渲染提供「同一物体、多个已知位姿」的监督对，让模型学会跨视角一致性；LAION 的 2D 图像提供单视图的视觉先验，让模型保住通用图像生成能力。联合训练不是简单混合采样，而是要让两路数据共享同一套参数而不互相侵蚀。这里的关键设计是：2D 图像被视为「只有一个视角可见」的特例，其跨视角注意力区块为空，模型在 2D 样本上退化为标准单视图扩散。这样同一组注意力权重既能在多视图样本上学习耦合，又能在 2D 样本上维持单图质量。

训练目标的写法与标准扩散一致，对拼接序列整体计算噪声预测损失：

$$\mathcal{L}=\mathbb{E}_{X_0,\epsilon,t}\left[\left\|\epsilon-\hat{\epsilon}\left(X_t,t,c,\pi_{1:4}\right)\right\|_2^2\right]$$

损失在整条拼接序列上取平均，四个视角的误差被同等对待。这带来一个数据层面的代价：Objaverse 渲染的多视图在视角覆盖、光照、背景上高度同质，模型学到的「一致性」带有数据集偏差。渲染管线固定的环绕采样让四个视角的相对关系始终是同一套，模型可能把「一致」学成「符合这套采样几何的固定模式」，换一套相机分布时一致性会退化。论文把数据偏差列为局限，其机制就在这里：一致性是相对于训练分布的一致性。

2D 数据的保留在消融中被单独验证，说明它不是可有可无的正则。若只用多视图数据训练，模型会过度拟合渲染数据的合成外观，文本跟随能力和开放域泛化下降；若只用 2D 数据，跨视角注意力学不到耦合。联合训练让两路梯度在同一参数上折中，代价是训练周期拉长到数天量级，且两路数据的采样比例成为需要调的超参——比例偏向多视图则 2D 先验流失，偏向 2D 则一致性学不牢。

具体例子：给「一只戴帽子的猫」这类开放域提示，纯多视图训练的模型倾向于生成 Objaverse 风格的干净资产外观，帽子的材质和背景趋于单一；联合训练后模型能借用 2D 先验生成更丰富的纹理与光照，同时四视图仍保持结构一致。这个折中不是免费的，它意味着模型在「资产级干净」与「开放域多样」之间做了一个固定的取舍，无法在推理时切换。

四 · 从四视图到 3D：SDS 与重建两条下游路径

四张一致图本身不是 3D 资产，它们是下游的输入。论文给出两条路径，分工不同。第一条是 SDS（分数蒸馏采样）：把 MVDream 当作多视图先验，优化一个隐式表示（如 NeRF 或网格），在每次迭代中从当前 3D 表示渲染出四个视角，加噪后送入 MVDream 求梯度，用扩散模型的分数指引 3D 参数更新。第二条是重建：把四视图直接送入前馈重建网络，一次前向得到 3D。两条路径对四视图质量的要求不同——SDS 只需要四视图作为「评分器」，容忍一定的不一致，因为优化过程会平均掉矛盾；重建则把四视图当作硬证据，不一致会直接变成几何错误。

SDS 的梯度形式可以写成对渲染图像与扩散先验之间差异的回传：

$$\nabla_\theta \mathcal{L}_{\mathrm{SDS}}=\mathbb{E}_{t,\epsilon}\left[w(t)\left(\hat{\epsilon}\left(X_t,t,c,\pi\right)-\epsilon\right)\frac{\partial X}{\partial \theta}\right]$$

这里 $X$ 是从 3D 参数 $\theta$ 渲染出的四视图，$\hat{\epsilon}$ 是 MVDream 的噪声预测。工程上的关键点是：SDS 把多视图一致性从「生成时的联合去噪」转移到了「优化时的联合评分」。四视图在一次评分中同时进入模型，跨视角注意力在评分阶段继续起作用，于是 3D 优化收到的梯度自带一致性偏好。代价是每次优化迭代都要跑一次四视图的扩散前向，计算开销远高于单视图 SDS，且四视图的渲染分辨率受限于扩散模型训练时的分辨率。

重建路径的分工更直接：四视图作为前馈网络的输入，网络输出几何与纹理。这条路径把一致性责任从扩散模型转移到了重建网络，MVDream 的角色退化为「高质量多视图数据生成器」。论文的影响部分指出 InstantMesh、CRM 等前馈重建模型用其生成多视图做训练或推理，正是这条路径的延伸。这里的系统代价是：重建网络的上限被四视图的信息量钉死，四个视角看不到的背面，重建网络只能靠对称性先验或数据驱动补全，补全质量取决于训练分布而非输入证据。

一个具体失败模式出现在 SDS 路径上：当四视图在某个区域给出互相矛盾的纹理假设时，SDS 的梯度会在该区域来回拉扯，优化在局部震荡，表现为 3D 表面出现模糊或「重影」纹理。这不是优化器的问题，而是多视图先验在该区域没有形成统一分数。相比之下，重建路径遇到同样矛盾时会直接选一个视角的假设覆盖另一个，表现为几何接缝。两条路径对不一致的容忍方式不同，工程选型要按下游对几何硬约束的敏感度来定。

五 · 模块分工的边界：谁负责什么，谁不负责什么

把模块职责列成表，能看清这套架构的能力边界与责任划分。

模块输入输出负责不负责
文本编码器提示词上下文嵌入语义条件，四视图共享几何方位
位姿嵌入相机外参内参每视角 token 偏置视角身份与相对方位视角间一致性
跨视角自注意力拼接 token 序列耦合后的特征可见区域的互相约束不可见区域的几何
U-Net 去噪含噪序列、时间步四视图噪声预测联合去噪轨迹3D 表示本身
SDS / 重建四视图3D 资产把图像证据转为几何补全无证据区域

这张表暴露的核心边界是：没有任何模块对「未被任何视角观测的几何」负责。跨视角注意力只耦合可见证据，SDS 只在有渲染视角的地方评分，重建只从输入视图取证。背面幻想不是某个模块的缺陷，而是整个分工体系的空白区。论文把「视图数固定」和「背面幻想」并列为局限，二者其实是同一个边界的两面：固定四视图决定了可观测立体角的上限，超出上限的区域没有模块认领。

另一个边界在训练数据与推理分布之间。Objaverse 多视图的环绕采样固定了四视角的相对几何，位姿嵌入学到的方位表示也绑定在这套采样上。推理时若换一套相机分布（比如更密的环绕或非均匀仰角），位姿嵌入进入训练时未见过的输入区域，跨视角注意力的耦合强度会失准。这不是注意力机制本身的问题，而是条件编码的外推问题。工程上要扩展视图数或改变采样几何，必须重新训练位姿嵌入与注意力偏置，而不能只改推理时的位姿输入。

具体到系统代价，四视图联合去噪的显存与计算随序列长度二次增长，使得分辨率、视图数、批量三者互相挤压。论文选择固定四视图，是在一致性收益与系统开销之间取的一个工程点：四视图足以覆盖侧面主要立体角，又不至于让注意力矩阵大到不可训练。这个选择后来成为多视图扩散路线的默认配置，InstantMesh、CRM 等下游模型沿用了这一视图数与采样几何，说明这个工程点在实践里被验证为可用的折中，而不是理论最优。

最后一个机制层面的判断落在注意力的软约束性质上。$b_{\mathrm{view}}$ 让跨视角耦合可学习、可调制，这让模型在多视图一致性与单图生成质量之间保持了同一套参数下的平衡，但也意味着一致性没有硬保证。任何要求几何严格一致的下游任务，都不能只依赖 MVDream 的输出，而要在重建或优化阶段引入显式的几何校验。这套架构的分工是清晰的：扩散模型负责生成互相协商过的多视图证据，几何正确性的最终责任落在下游的 SDS 或重建模块上，而下游模块的能力又被输入视图的覆盖范围所限制。
