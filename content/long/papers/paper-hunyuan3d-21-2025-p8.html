一 · 训练数据的构成与 PBR 监督信号的来源

Hunyuan3D 2.1 的 PBR 分支并不是在单一数据源上训练出来的。论文给出的数据集合是 Objaverse 与内部 PBR 资产两部分，这两类数据在监督信号的性质上有本质区别，理解这一点是读懂后续所有指标口径的前提。Objaverse 提供的是大规模、多样但材质标注不完整的资产；内部 PBR 资产提供的是带完整反照率、粗糙度、金属度通道的、经过工业管线校验的资产。形状分支沿用 2.0 的训练配方，PBR 分支则必须同时吃到这两类数据，原因在于 PBR 通道的监督比基础色稀疏得多：一个资产可以没有粗糙度贴图，但不可能没有基础色。

具体机制上，PBR 分支的监督来自两个层面。第一层是多视图 PBR 数据上的逐通道回归，即公式中的逐视图 L2 项：

$$\mathcal{L}_{\mathrm{PBR}}=\sum_{v}\left\|\hat{\mathbf{a}}_v-\mathbf{a}_v\right\|^2+\left\|\hat{r}_v-r_v\right\|^2+\left\|\hat{m}_v-m_v\right\|^2$$

这里 $\hat{\mathbf{a}}_v,\hat{r}_v,\hat{m}_v$ 是第 $v$ 个视角上预测的反照率、粗糙度、金属度，$\mathbf{a}_v,r_v,m_v$ 是对应真值。注意这个损失是逐视图、逐通道等权求和的，它并不区分材质通道之间的物理耦合关系，因此单靠它训练出来的分支会在通道间产生不一致，例如金属度接近 1 的区域粗糙度预测漂移。第二层是可微 PBR 渲染监督：把预测的 PBR 通道送进渲染方程，与真实光照下的参考图像比对，从而把通道间的物理约束以梯度的形式回传。光照解耦训练则是为了让反照率通道不被训练数据中 baked-in 的光照污染——如果直接用带光照的渲染图监督反照率，网络会把阴影和高光烤进 albedo，重光照时就会露馅。

系统代价在于数据配比。内部 PBR 资产数量远小于 Objaverse，但它是唯一提供完整三通道真值的来源；Objaverse 数量大但通道缺失，只能用于形状与部分通道的弱监督。工程上这意味着采样器必须做分层采样，否则 PBR 分支会被大量缺通道样本稀释成只会预测反照率的退化模型。失败模式很具体：当某个 batch 里金属度真值缺失比例过高时，金属度头的梯度方差会显著上升，表现为训练中期金属度预测塌缩到接近 0 的常数。这不是假设，而是多通道监督中缺失标注的典型表现，复现时必须显式记录每个通道的有效监督比例。

一个具体例子：假设一个内部资产只有反照率与粗糙度贴图，金属度通道缺失。若直接把缺失通道当 0 参与 L2 损失，网络会学到“这个资产的金属度是 0”，而真实情况是未知。正确做法是给损失加通道掩码，只对存在的通道求梯度。这个掩码机制看似琐碎，却是 PBR 分支能否收敛到物理合理材质的分水岭。

二 · 评测协议：从图像指标到可重光照性

PBR 生成的评测不能沿用基础色纹理时代的协议。基础色模型的评测通常只看生成纹理与参考纹理在图像空间的相似度，而 PBR 资产的正确性只有在渲染条件下才能体现。Hunyuan3D 2.1 的评测协议因此分成两层：一层是材质通道本身的误差，另一层是重光照后的渲染一致性。前者可以用逐通道的 L1/L2 或感知指标衡量，后者必须固定一套光照与相机配置，把预测材质与真值材质分别渲染，再比较渲染结果。

机制上，重光照评测的关键是控制变量：同一几何、同一相机、同一环境光照，只替换材质。这样渲染差异就归因于材质预测误差，而不是几何或视角差异。论文报告的结论是 PBR 材质完整、重光照表现优于基础色模型，这是定性表述，没有给出具体数值，读者不应把它读成某个确定的百分比提升。工程复现时，重光照协议必须写死环境光照的分辨率与色调映射曲线，否则不同实现之间的数字不可比。

系统代价在于评测成本。逐通道误差可以在 UV 空间直接算，代价低；重光照评测需要对每个样本做多次渲染，且渲染器必须支持可微或至少支持与训练一致的 BRDF。如果评测渲染器和训练渲染器的 BRDF 实现不一致，重光照指标会系统性偏移，这种偏移不会体现在通道误差上，因此两层评测必须同时报告。失败模式是“通道误差低但重光照差”：反照率预测得很准，但粗糙度与金属度的空间分布错了，渲染出来高光位置不对。这类失败在只看通道指标的协议下完全不可见。

一个具体例子：一个金属杯子的反照率是灰色，粗糙度低，金属度高。若网络把金属度预测成 0、粗糙度预测成高，通道 L2 误差可能不大（灰色反照率仍然接近），但重光照下它会从镜面金属变成哑光塑料，视觉差异巨大。这就是为什么评测协议必须把渲染层作为主指标，通道误差只作为诊断指标。

三 · 指标口径：一个容易误读的数字

论文的实验部分列出了数据集 Objaverse 与内部 PBR 资产、基线 Hunyuan3D 2.0、SF3D、TRELLIS，并给出“PBR 材质完整、重光照表现优于基础色模型”的结论。这里最容易被误读的是“优于基础色模型”这一定性表述被转述成具体倍数或百分比。事实是论文没有给出可引用的具体提升数字，任何“提升了多少”的说法都超出了给定事实。读者在有工程背景的情况下，应当把这句话读成方向性判断：在重光照协议下，带 PBR 通道的资产比只有基础色的资产更接近物理正确的渲染，而不是某个可复现的数值差距。

为什么这个数字容易被误读？因为基线里混了不同性质的系统。Hunyuan3D 2.0 是同一形状分支的前代，输出基础色纹理，它的“差”是结构性的——它根本没有粗糙度和金属度通道，重光照时只能靠基础色近似，物理上不可能正确。SF3D 与 TRELLIS 是同期系统，它们的材质完整度与 Hunyuan3D 2.1 不在同一口径上。把这三条基线的结果放在一个表格里比较时，如果不标注每条基线输出的通道数，读者会把“通道缺失导致的物理错误”误读成“模型能力差距”。正确的口径是：先声明比较的是完整 PBR 三通道输出，再声明重光照协议的光照配置，最后才谈优劣。

机制上，指标口径的差异来自通道完备性。基础色模型的重光照误差有一个不可消除的下界，这个下界由“用 albedo 近似 BRDF”的物理近似误差决定，与网络容量无关。因此拿 PBR 模型与基础色模型比重光照指标，本质上是在比“有没有物理通道”，而不是在比“预测得多准”。工程判断是：这类比较只能用于论证 PBR 路线的必要性，不能用于论证某个模型在材质预测精度上的领先。若要比较精度，必须在同为三通道输出的模型之间、在同一重光照协议下进行。

系统代价是评测表格的可比性维护。每新增一条基线，都要重新核对它的输出通道、UV 布局、渲染器 BRDF 是否与主协议一致。一个具体的失败模式是：某基线输出的是 sRGB 空间的基础色，而主协议期望线性空间的反照率，直接比较会产生系统性色偏，且这种色偏会被误判为材质预测误差。复现清单里必须有一条断言：所有参与比较的资产在进入渲染器前都经过同一色彩空间转换。

四 · 作弊风险：数据泄漏、协议漏洞与指标投机

PBR 生成的评测存在几类具体的作弊风险，工程读者在复现或引用结果时必须能识别。第一类是数据泄漏：Objaverse 与内部 PBR 资产的划分如果没有严格按资产 ID 隔离，训练集与评测集可能共享同一资产的不同视角或不同 LOD，导致评测分数虚高。多视图训练的模型尤其容易在这里出问题，因为同一资产的不同视角在训练时已经见过，评测时换个视角并不构成真正的泛化。第二类是协议漏洞：重光照评测如果允许为每个样本单独调光照，模型可以通过拟合光照来掩盖材质误差，这在只报告渲染相似度的协议下无法被发现。

第三类是指标投机，也是最隐蔽的一类。逐通道 L2 损失对大面积平坦区域敏感，对高频细节不敏感。一个把粗糙度预测成全局常数的模型，在平坦区域占主导的资产上可以获得很低的通道误差，但它在重光照下完全没有空间变化的高光，物理上是错的。这类模型在通道指标上“好看”，在渲染指标上“露馅”，因此两层指标必须联合报告，且渲染指标应作为主判据。第四类是 UV 展开相关的投机：UV 融合阶段如果对失败样本做了回退处理（例如退化为简单投影），这些样本在通道指标上可能仍然可算，但 UV 质量已经不合格，属于被指标掩盖的失败。

机制上，防作弊的核心是评测集的资产级隔离与协议冻结。资产级隔离意味着划分单位是资产而不是视图；协议冻结意味着光照、相机、渲染器版本在评测前固定，不允许按样本调整。系统代价是评测集规模受限：严格隔离后可用于评测的完整 PBR 资产数量不多，这会让指标的置信区间变宽，因此定性结论比精确数值更可靠。一个具体例子：若评测集只有少量内部 PBR 资产，单条样本的失败就能显著拉动平均指标，此时报告均值而不报告失败样本清单是有误导性的。工程判断是：PBR 评测必须附带失败样本的逐条诊断，否则均值不可信。

五 · UV 失败与数据限制如何污染评测数字

论文明确列出的局限是数据限制、UV 失败、推理慢。这三者在评测语境下的影响不同，其中 UV 失败对指标口径的污染最直接。UV 空间融合是把多视图预测拼接到一张 UV 贴图上的步骤，当几何的 UV 展开本身有重叠、接缝错位或参数化退化时，融合结果会出现接缝处的材质不连续。这种不连续在逐通道指标上表现为局部高误差，但在全局均值上被稀释；在重光照指标上则表现为接缝处的光照跳变，视觉上非常明显。

机制上，UV 失败有两种来源：几何侧的参数化失败，和融合侧的接缝对齐失败。前者是形状分支继承下来的问题，后者是 PBR 分支新增的问题。评测时如果不区分这两类失败，就会把几何问题算到材质头上。一个具体的诊断方法是：对同一资产分别用真值 UV 和预测 UV 做融合，比较通道误差，差值即为 UV 失败贡献的部分。这个诊断在复现清单里应当作为固定步骤。

数据限制对评测的影响则体现在覆盖面上。内部 PBR 资产的材质分布偏向工业常见材质（金属、塑料、织物），对罕见材质（次表面散射、各向异性）覆盖不足。评测集如果也来自同一分布，指标会偏乐观；若评测集刻意加入分布外材质，指标会显著下降。论文没有给出分布外评测的数字，因此“PBR 材质完整”这一结论的适用范围应限定在训练分布内。工程判断是：把 Hunyuan3D 2.1 接入管线时，验收断言必须包含分布外材质的抽检，而不能只看评测集均值。

推理慢这一局限与评测的关系在于复现成本。数十秒级的推理意味着大规模评测的时间成本高，这会诱导复现者缩小评测集，而小评测集正是前述均值不可信问题的根源。系统代价是评测吞吐与统计可靠性之间的权衡，工程上通常的做法是固定一个小而严格的评测集用于回归，另用大评测集做一次性统计，两者分开报告。

六 · 工程复现中的评测断言与口径冻结

把上述内容落成可执行的复现清单，核心是三条断言。第一条是通道完备性断言：参与比较的所有资产必须具有反照率、粗糙度、金属度三通道，缺失通道的样本不得进入重光照比较。第二条是色彩空间断言：所有材质在进入渲染器前统一转换到线性空间，反照率不得带 baked-in 光照。第三条是 UV 有效性断言：融合后的 UV 贴图必须通过接缝连续性检查，失败样本单独列出而不是静默回退。

机制上，这三条断言对应三个可自动化的检查点：通道掩码统计、色彩空间转换日志、UV 接缝误差图。每个检查点都应在评测流水线中输出可追溯的记录，而不是只输出一个总分。系统代价是流水线复杂度上升，但换来的是指标的可解释性——当重光照指标下降时，能定位到是通道缺失、色彩偏移还是 UV 失败，而不是笼统地归因于“模型变差”。

一个具体例子：复现者在自己的管线上跑 Hunyuan3D 2.1，发现重光照指标比论文定性描述差。逐条检查后发现，其渲染器使用的是 sRGB 空间直接渲染，而训练侧的可微 PBR 渲染在线性空间进行，色彩空间不一致导致反照率通道被系统性压暗。这不是模型问题，是口径问题。修正色彩空间后指标回归正常。这个例子说明，PBR 评测的数字对口径的敏感度远高于基础色时代，口径冻结不是形式主义，而是数字可比性的前提。

最后落到一个工程判断上：PBR 生成的评测应以重光照协议为主判据、通道误差为诊断、失败样本清单为必附项，三者缺一不可。任何只报告单一均值、不声明通道完备性与色彩空间的结果，在工程验收中应被视为不可用。这一判断直接决定了 Hunyuan3D 2.1 这类生产级材质模型能否被可信地接入管线，也决定了后续基线比较是否有意义。
