一 · 评测口径：为什么“世界级”不能沿用房间级指标

WorldGen 的实验部分首先要回答一个方法论问题：当生成对象从“一个房间”变成“一片可穿越的世界”时，原有的评测坐标系是否仍然成立。论文给出的数据集标注是“自建世界评测”，这意味着作者没有现成的公开基准可以直接套用，而是围绕“世界”这一目标重新组织评测样本与判据。这一点必须被严肃对待：它不是实验章节的装饰，而是整篇论文主张能否成立的前提。房间级生成常用的判据——单视角图像相似度、局部几何误差、纹理一致性——在大尺度场景里会系统性失效。原因在于，可穿越世界的核心属性是跨视角的连贯、空间尺度的合理、以及进入引擎后的可交互性，而这些属性在单帧或短序列上几乎不可观测。一个在单图上纹理极佳的资产，放到几百米尺度的地形上可能尺度失真；一段在局部看起来连贯的几何，走进去十米就可能出现断裂或穿模。论文把评测对象定义为“可穿越、可交互、可进引擎”，实际上是把判据从“看起来像”迁移到“走进去成立”。

具体机制上，WorldGen 的评测必须覆盖三类证据：布局层面的可控性（文本描述的空间关系是否被 LLM 场景图忠实表达）、几何层面的可穿越性（相机在生成世界中连续运动时是否出现不可解释的遮挡、塌陷、悬空）、以及系统层面的引擎可导出性（资产、材质、层级是否满足游戏引擎的导入约束）。这三类证据对应三种不同的采集方式：布局可以用场景图与文本约束的比对来检验；可穿越性需要在生成世界中做路径采样与碰撞检验；引擎可导出性则是对导出产物做结构校验。论文的实验叙述正是沿这条线索展开，而不是把三项拼成一张好看的分数表。

这里有一个必须点明的系统代价：自建评测意味着结论的可复现性依赖作者对评测流程的完整披露。若评测样本的构造规则、路径采样策略、引擎校验的判定阈值没有同步给出，外部读者无法判断“大尺度、可穿越”是生成能力的属性还是评测口径的宽松。论文的定位是“组合式世界生成”的代表，其证据链的说服力因此不只来自结果本身，还来自评测设计是否把失败模式暴露出来。一个只报告成功案例的评测，对世界级生成几乎没有信息量，因为世界级生成最典型的失败恰恰发生在边界处：地形与建筑的接缝、物体与地面的接触、远景与近景的尺度过渡。

用公式表达这种评测口径的迁移，可以把世界级判据写成一个约束满足问题，而不是一个标量相似度：

$$\mathrm{Valid}(\mathcal{W})=\mathbb{1}\!\left[\mathrm{LayoutOK}(\mathcal{W},t)\wedge\mathrm{TraverseOK}(\mathcal{W})\wedge\mathrm{EngineOK}(\mathcal{W})\right]$$

其中 $\mathcal{W}$ 是组合出的世界，$t$ 是输入文本。这个式子的工程含义是：三项判据是合取关系，任何一项失败都意味着世界不可用，而不是用加权平均把失败稀释掉。这与房间级评测里“相似度 0.87 所以还不错”的思路截然不同。举例来说，一个布局完全符合文本、物体资产精致、但地形在某个坡面上出现不可通行断层的世界，在合取判据下直接判为失败；而在平均分体系里，它可能因为前两项高分而被误判为成功。论文选择“可穿越”作为核心词，实际上就是选择了这种合取式判据。

二 · 基线对照：三类系统各自暴露的短板

论文列出的基线是 Text2Room、WonderWorld、SceneCraft。这三个名字对应三种不同的技术路线，把它们放在一起对照，才能看清 WorldGen 的提升究竟来自哪一层。Text2Room 代表的是从文本出发、以房间为单位的室内场景生成路线，其能力边界天然停在房间尺度；WonderWorld 代表的是以单图或短提示外扩的方式构造可探索场景，其优势在视觉连续性，弱点在布局推理与游戏逻辑；SceneCraft 代表的是借助 LLM 做场景组织、把资产按脚本摆放的路线，其强项在布局语义，弱项在大尺度地形与可穿越几何的生成。WorldGen 的实验叙述把这三者作为参照系，实际上是在说：单一环节的强并不等于世界级可用，世界级可用要求布局、地形、资产、组合四层同时成立。

对照的机制层面可以这样拆解。Text2Room 的生成单元是房间，房间之间的连接不是它的原生能力，因此当评测要求跨房间、跨地形的连续穿越时，它的失败模式是边界处的几何不连续与空间尺度突变。WonderWorld 的外扩机制在视觉上能延伸场景，但外扩不产生真正的布局推理：文本里“山谷东侧有一座塔”这类空间约束，外扩路线没有机制去保证，失败模式是布局与文本脱节。SceneCraft 的 LLM 布局能力强，但它依赖可用的资产与地形基底，当评测要求大尺度地形时，它的失败模式是资产悬浮、地形缺失、场景在远处空洞化。这三种失败模式恰好对应 WorldGen 组合架构的四个模块：LLM 布局、程序化地形、扩散资产、object-aware 分解组合。基线的短板分布，就是消融实验要验证的假设来源。

这里必须避免一种常见的误读：把基线对照理解成“WorldGen 在每个维度都更好”。论文的证据结构不支持这种读法。更准确的读法是：基线各自在某个维度上有明确能力，但在“可穿越、可交互、可进引擎”的合取判据下无法同时满足，而 WorldGen 的组合方式把这四个维度拼成一个可运行的整机。这意味着对照的价值不在于排名，而在于定位：当 Text2Room 在跨房间连续性上失败时，说明布局与地形的耦合是必要的；当 WonderWorld 在布局约束上失败时，说明 LLM 场景图不是可选项；当 SceneCraft 在大尺度基底上失败时，说明程序化地形不是装饰。实验章节把这些失败模式逐一暴露，构成了组合架构的必要性论证。

系统代价在这里体现为对照的不对称性。WorldGen 是一个多模块系统，其运行成本、资产质量波动、导出流程的复杂度都高于单一模型基线；基线则是相对紧凑的端到端或半端到端管线。因此“WorldGen 更好”的结论必须限定在判据上：它在合取式世界级判据下可用，代价是系统复杂度与资产质量的方差。论文把“系统复杂、资产质量参差、评测缺标准”列为代价，正是承认这种不对称。工程判断上，这意味着采用 WorldGen 路线不是替换一个模型，而是接管一条管线：布局、地形、资产、组合、导出每一环都要有人负责调参和排障。

三 · 主要结果：提升来自组合而非单点

论文的主要结果表述为：大尺度、可穿越、可进引擎、布局可控。这四个词不是四个独立分数，而是组合架构四个模块各自贡献一项能力后的联合产物。要把“提升来自哪里”讲清楚，必须把每个词回溯到具体模块。大尺度来自程序化地形：地形基底提供了房间级方法无法覆盖的空间范围，使世界在尺度上不再受单房间边界约束。可穿越来自 object-aware 分解与放置：物体与地形、物体与物体之间的接触关系被显式处理，相机路径上的遮挡与通行性因此可以被检验。可进引擎来自引擎导出环节：生成产物被组织成引擎可导入的结构，而不是停留在渲染图像或点云。布局可控来自 LLM 场景图：文本中的空间关系被转成可执行的布局约束，使尺度、风格、布局的控制有落点。

把这四项放回组合公式，提升的来源就一目了然：

$$\mathcal{W}=\mathrm{Compose}\!\left(\mathrm{Layout}_{\mathrm{LLM}}(t),\mathrm{Terrain}_{\mathrm{proc}},\{\mathrm{Gen}(o_i)\}\right)$$

公式右侧三项分别对应布局、地形、资产，Compose 对应分解组合与放置。主要结果中的每一个“可”字，都是某一项或某几项联合成立的产物，而不是某个单模型的指标提升。这一点是理解整篇论文实验的关键：WorldGen 没有训练一个更大的端到端模型去直接输出世界，它把世界拆成可分别验证的部分再拼起来。因此它的结果证据也必须是分层的——布局层验证文本约束，地形层验证尺度与通行，资产层验证物体质量，组合层验证接触与导出。论文的实验叙述沿这个分层展开，而不是把所有能力压成一个总分。

具体例子可以说明分层验证的必要性。假设文本要求“一片开阔谷地，谷地北侧有石阶通向高处的遗迹，谷地中央有一棵孤树”。LLM 布局给出谷地、石阶、遗迹、孤树的相对位置与尺度；程序化地形生成谷地与高地的落差；扩散模型生成石阶、遗迹构件、树的资产；object-aware 分解把石阶与坡面接触、遗迹与高地接触、树与地面接触逐一处理。若只看最终渲染图，四项都可能“看起来对”；但可穿越性检验会在石阶与坡面的接缝处暴露问题——如果石阶的每一步没有与地形高度对齐，相机走上去就会出现悬空或穿模。这个失败不会出现在布局分数里，也不会出现在单物体资产质量里，只会出现在组合层的接触检验里。主要结果之所以强调“可穿越”，正是因为这类失败只有在组合层才可见。

系统代价在这一节表现为资产质量的方差。扩散模型生成的物体资产在单体质量上并不稳定，同一个提示下的多次生成可能给出细节水平差异明显的资产。组合架构把这批资产拼进同一个世界，方差就被放大：一个精细的遗迹构件旁边可能是一个粗糙的石阶。论文把“资产质量参差”列为代价，指向的正是这种跨资产的不一致。工程上，这意味着主要结果的“可进引擎”不等于“可直接上线”：导出后的世界仍需要资产筛选、材质统一、LOD 处理等后处理，而这些工作不在论文的自动管线之内。判断 WorldGen 的结果时，应把它读作“可运行的原型世界”，而不是“成品关卡”。

四 · 消融：四个模块各自拿掉后剩下什么

论文的消融对象是 LLM 布局、程序化、扩散资产、分解。这四个消融项与组合公式的三项加 Compose 一一对应，因此消融的设计逻辑是：逐项移除，观察世界级判据中哪一项先崩。这种消融不是调参式的边际贡献测量，而是必要性验证——每个模块被拿掉后，失败模式应当能回溯到该模块负责的那项能力。若某个模块拿掉后世界仍然“可穿越、可进引擎”，那这个模块在组合路线里就不是必要的，组合架构的主张就会被削弱。因此消融结果的信息量集中在失败模式的具体形态上，而不是分数下降的幅度上。

移除 LLM 布局，剩下的是程序化地形加扩散资产加分解。此时世界仍有地形与物体，但文本中的空间关系失去执行者：谷地、石阶、遗迹的相对位置不再由场景图约束，而是由地形与资产的默认分布决定。失败模式是布局不可控——文本说“北侧”，生成结果可能把遗迹放在任意方位。这与 WonderWorld 的短板同构，说明 LLM 布局不是可选的润色层，而是文本到空间关系的唯一通道。移除程序化地形，剩下的是 LLM 布局加扩散资产加分解。布局给出了位置，但没有大尺度基底承接这些位置，资产只能悬在局部空间里，远处空洞化。失败模式与 SceneCraft 在大尺度基底上的短板同构，说明程序化地形不是背景装饰，而是尺度与通行性的承载者。

移除扩散资产，剩下的是 LLM 布局加程序化地形加分解。地形与布局成立，但物体没有生成来源，世界退化为空场地。失败模式是场景语义缺失：布局坐标还在，但“遗迹”“孤树”这些文本实体没有对应的几何。这说明扩散资产负责的是语义实体的几何化，而不是可被程序化替代的填充物。移除分解，剩下的是 LLM 布局加程序化地形加扩散资产，但没有 object-aware 的组合与放置。此时各模块的产物都在，但接触关系没有被显式处理：石阶可能浮在坡面上方，遗迹可能嵌进地形里，树可能悬空。失败模式是接触失败，而这恰好是可穿越性判据最先崩的地方。这一项消融最能说明 Compose 不是简单的拼接，而是带接触约束的组合优化。

把四项消融并排看，可以得到一个工程判断：WorldGen 的四个模块不是可互相替代的冗余，而是各自承担一项不可让渡的判据。LLM 布局对应布局可控，程序化地形对应大尺度，扩散资产对应语义实体，分解对应可穿越的接触正确性。任何一项缺失都会让合取判据中的某一项直接失败，而不是让总分轻微下降。这正是组合式世界生成与端到端世界生成在证据结构上的根本差异：端到端模型的消融往往表现为整体质量平滑退化，组合系统的消融表现为判据的离散崩塌。论文选择报告后者，是因为后者对工程决策更有用——它告诉你在管线里哪一环不能省。

消融的系统代价是实验成本。四个模块各自预训练，消融需要在不破坏其余模块的前提下替换或移除某一环，这要求模块间接口足够干净。若接口耦合过深，消融就退化为“改一处、动全身”，结论的可归因性下降。论文把“模块化支持布局/尺度/风格控制”作为架构特性，实际上也是在为消融的可归因性做铺垫：模块边界清晰，移除某一模块的后果才能被干净地观测到。这一点对复现者尤其重要——复现 WorldGen 的消融，难点不在跑模型，而在维持模块接口的隔离。

五 · 证据的边界：评测缺失与资产方差如何影响结论

论文把“评测缺失”列为局限，这不是谦辞，而是对证据边界的准确标注。自建世界评测解决了“没有现成基准”的问题，但没有解决“判据是否被外部认可”的问题。世界级生成的判据目前没有社区共识：可穿越性的检验路径如何采样、引擎可导出性的结构校验到什么粒度、布局可控性如何量化文本约束的满足度，这些都还没有标准答案。因此论文的结果应被读作“在该论文自建判据下成立”，而不是“在世界级生成的通用判据下成立”。这个区分对工程读者至关重要：采用这条路线时，你需要自己定义判据，而不能指望论文的判据直接迁移到你的产品约束上。

资产质量的方差是另一条边界。扩散模型生成物体资产的能力在单体上可用，但在一个世界里要拼进几十上百个资产时，方差会累积成可见的风格断裂与细节落差。论文的消融没有把资产质量作为独立变量来控制，因此“扩散资产必要”这一结论成立，但“扩散资产足够好”这一结论不成立。工程判断上，这意味着 WorldGen 的资产层需要外挂筛选与后处理：按细节水平、材质一致性、尺度合理性做过滤，再进入组合。论文的自动管线给出的是可运行的世界，不是可发布的世界；这两者之间的差距主要就落在资产方差上。

还有一个证据边界来自系统复杂度。WorldGen 是多模块系统，其主要结果是在作者控制的管线配置下取得的。模块间的超参——布局的场景图粒度、地形的分辨率、资产的生成预算、分解的接触阈值——都会影响最终世界的可用性。论文没有把这些超参的敏感性作为实验主线，因此结果的鲁棒性边界没有被完整刻画。复现者若换一套超参，可能得到“可穿越”判据下的不同成功率。这不是对论文的否定，而是对证据范围的限定：组合系统的结果天然依赖配置，单点结果的复现不等于整机行为的复现。

把这些边界合起来看，论文的实验证据支持的是一个定性结论：组合四件事可以把场景生成从房间推到世界，且四个模块各自必要。它不支持定量结论：某个判据下的成功率是多少、资产质量的分布如何、超参变化对可用性的影响曲线是什么。工程读者应据此调整预期——WorldGen 的证据足以支撑“这条路线可行且必要”，不足以支撑“这条路线已可直接产品化”。论文把“系统复杂、资产质量、评测缺失”三项并列为代价，正是把这条边界画在了明处。

六 · 从证据到工程判断：提升的可归因性与接管成本

把实验与证据放回工程语境，最需要回答的问题是：提升是否可归因。WorldGen 的证据结构给出的答案是肯定的，但归因的单位是模块而非单点。大尺度归因于程序化地形，布局可控归因于 LLM 场景图，语义实体归因于扩散资产，可穿越的接触正确性归因于 object-aware 分解。这种归因方式的好处是可操作：当你的世界在某个判据上失败时，你可以定位到对应模块去修，而不是面对一个端到端模型无从下手。坏处是接管成本高：四个模块各自有预训练权重、各自的调参空间、各自的失败模式，维护一条这样的管线需要跨领域的工程能力——LLM 提示与场景图设计、程序化地形参数、扩散模型采样与筛选、几何接触与放置优化、引擎导出与结构校验。

具体到失败排查，可归因性带来的流程是：先跑合取判据定位失败项，再按失败项回溯模块。布局不可控，查 LLM 场景图与文本约束的映射；大尺度空洞，查地形分辨率与程序化参数；语义实体缺失或质量差，查扩散资产的提示与筛选；接触失败，查分解的接触阈值与放置优化。这个流程的每一步都对应消融里的一项，因此消融结果不只是论文的证据，也是工程排障的索引。这是组合式路线相对端到端路线的实质优势：它的实验章节同时是一张故障树。

接管成本的另一面是资产方差的管理。论文的自动管线不包含资产筛选，因此工程上必须在组合之前插入一道过滤：按尺度、材质、细节水平给资产打分，剔除离群项，必要时对同一实体多次生成取优。这道过滤的成本不在论文的实验里，但它决定了最终世界是否可发布。把这一点与消融结果对照：扩散资产是必要的，但“必要”不等于“免检”。消融证明的是没有资产就没有语义实体，没有证明资产可以直接进组合。工程判断应把资产筛选视为组合架构的第五个隐含模块，尽管论文没有把它列为消融项。

最后落在评测的可迁移性上。论文的自建世界评测是为“可穿越、可交互、可进引擎”这组判据设计的，若你的产品约束不同——比如要求世界在特定引擎版本下可运行、要求特定帧率下的可穿越性、要求布局满足更严格的文本约束——判据需要重新设计，而判据的重设计又会改变模块的必要性排序。举例来说，若引擎导出约束收紧到特定材质规范，扩散资产的筛选标准就要随之收紧，资产模块的权重上升；若可穿越性检验加入碰撞体积的精确校验，分解模块的接触阈值就要重新标定。这意味着 WorldGen 的实验证据不能被当作固定配方搬运，只能被当作路线必要性的论证。组合式世界生成的证据结构，最终要求采用者自己完成从判据到模块的映射——这一步没有现成答案，也正是这条路线在 2025 年仍处于原型阶段的原因。
