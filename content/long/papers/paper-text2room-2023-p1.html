一 · 从一句提示词到一间房：需求现场

设想一个具体的工程任务：给一段室内漫游原型做内容填充，输入只有一句提示词——“一间有木地板、白墙、靠窗摆着书桌的小书房”。目标是拿到一个可以导入引擎、带 UV 与纹理、能从任意角度看都不穿帮的房间网格。这个任务在 2023 年的技术栈里会立刻撞上一个结构性矛盾：文本到图像模型已经能稳定产出单张高质量室内图，但单张图只是一个视角的二维投影，它背后的三维结构是欠定的。同一张照片可以由无穷多种几何解释，透视、遮挡、材质反射都在把信息压扁。工程上要的不是“一张好看的图”，而是“一个封闭的、几何自洽的、纹理连续的体”。

这个矛盾可以写成一个约束满足问题。给定文本 $p$，需要求解网格 $\mathcal{M}$ 与纹理 $\mathcal{T}$，使得从任意选定相机 $\mathbf{c}_i$ 渲染出的图像 $R(\mathcal{M},\mathcal{T},\mathbf{c}_i)$ 在语义上符合 $p$，同时在相邻视角之间满足几何与光度一致性：

$$\min_{\mathcal{M},\mathcal{T}}\ \sum_i \mathcal{L}_{\text{sem}}\!\left(R(\mathcal{M},\mathcal{T},\mathbf{c}_i),\, p\right)\ \ \text{s.t.}\ \ \left\|R(\mathcal{M},\mathcal{T},\mathbf{c}_i)-R(\mathcal{M},\mathcal{T},\mathbf{c}_j)\right\|_{\text{overlap}}\le \epsilon$$

麻烦在于，$\mathcal{L}_{\text{sem}}$ 只能通过 2D 模型间接评估，而一致性约束是硬约束，两者不在同一个可微体系里。Text2Room 的全部设计，本质上就是在这个不可微的缝隙里搭一条工程流水线。理解这条流水线之前，必须先看清它之前的主流做法为什么会在这里失效。

二 · 论文之前的两条主路：单物体文生 3D 与全景重建

第一条路是单物体文生 3D，代表是 DreamFusion 一类的工作。它的机制是分数蒸馏采样：把 2D 扩散模型当作一个“打分器”，对从当前 3D 表示渲染出的任意视角图像计算噪声残差，把该残差反传回 3D 参数，从而在没有任何 3D 训练数据的情况下优化出一个物体。这条路的成功建立在两个隐含前提上：物体可以被一个紧致的边界框包住，且 2D 模型对“物体”这一语义类别有稳定的多视角先验。一旦把场景换成一间房，前提立刻崩掉——房间不是从外部看的物体，而是从内部看的容器；相机在房间里，视野里永远只有一面墙、一个角落，没有任何一个视角能同时看到六个面。用物体级的 SDS 去优化房间，等价于让一个只见过“椅子正面”的先验去猜“椅子背面贴着墙时是什么样”，监督信号在视角间自相矛盾。

第二条路是先合成全景图再重建。思路很直接：既然单视角信息不足，那就先生成一张 360° 等距柱状投影图，再用全景深度或优化方法反推出房间几何。这条路的痛点不在生成，而在几何。全景图是球面参数化的，赤道附近一个像素对应的立体角远大于两极；把它展开成平面后，直线会变成曲线，平面会变成扭曲的条带。更关键的是，全景生成模型本身没有几何约束——它保证的是“接缝处颜色连续”，而不是“接缝处深度连续”。于是重建阶段拿到的是一张光度上自洽、几何上互相打架的图：墙与地板的交界线在图像里对得上，但反投影出来的平面法向对不上，房间会呈现出缓慢的扭曲或非欧几里得式的“膨胀”。这类失败在工程上极难修补，因为误差已经弥散到整张全景里，没有局部抓手。

把两条路并排看，问题就清楚了：单物体方法有几何优化机制但缺场景级视角覆盖；全景方法有视角覆盖但缺几何约束。房间级生成真正缺的不是“更大的模型”，而是一个能把视角覆盖、几何反投影、纹理补全三者串起来、并且允许误差被局部修正的迭代框架。

三 · 具体痛点：三个必须同时满足的硬条件

第一个硬条件是多视角一致性。2D 文生图模型对同一提示词的不同视角调用，本质上是独立采样。即便固定随机种子，改变相机方位角后，模型对“书桌靠窗”这一语义的空间布局也会给出不同解释：这一帧窗在左墙，下一帧窗跑到了右墙。工程上这不是“画风差异”，而是几何矛盾——两帧反投影出的墙体平面在空间中相交，融合后产生重影或撕裂。Text2Room 用连续对齐来压制这一点，但压制不等于消除，残余误差会随视角数累积，这正是后文要谈的长距离漂移的根源。

第二个硬条件是几何完整性。相机每前进一步，视野边缘就会露出未被观测的区域。单目深度估计只对图像内像素负责，图像外是空的。房间要封闭，就必须把这些空洞补上。补洞不能靠几何外推——从一面已知墙推另一面未知墙的法向是病态的；只能回到 2D 先验，用文本条件 inpainting 在图像域里“画”出缺失部分，再反投影。这就引出一个系统代价：补洞质量直接受限于 2D 模型对该语义的先验强度。模型没见过“带斜屋顶的阁楼角落”，补出来的就是一面平墙，几何上虽然闭合，语义上却是错的。

第三个硬条件是纹理连续性。房间网格的 UV 展开必须让相邻面的纹理在接缝处对齐。若每帧独立生成再拼接，接缝处会出现色差、光照方向突变、材质尺度跳变。Text2Room 的做法是把新帧对齐融合进已有网格，让重叠区域的纹理由已有观测主导、新观测只补充未覆盖部分，从而在机制层面保证接缝的连续性。代价是融合规则必须足够保守，否则新帧的误差会污染已经正确的区域。

硬条件失效表现对应机制系统代价
多视角一致墙体平面相交、重影连续对齐融合误差随视角数累积
几何完整视野边缘空洞、房间不闭合文本条件 inpainting补洞受 2D 先验上限约束
纹理连续接缝色差、光照跳变重叠区融合规则保守融合拖慢覆盖速度

三个条件互相牵制：为了几何完整要激进补洞，激进补洞会引入语义错误；为了纹理连续要保守融合，保守融合会让新视角贡献变少、覆盖变慢。这个三角张力就是 Text2Room 必须回答的工程问题，也是它为什么不能简单套用已有单物体管线的原因。

四 · 为什么非改不可：单帧路线的信息论下限

可以把单帧路线的失败写得更形式化一点。设真实房间的几何为 $\mathcal{M}^*$，单张图像 $I$ 是 $\mathcal{M}^*$ 经相机投影与遮挡后的产物。反投影算子 $\mathrm{BackProject}(D,I,\mathbf{c})$ 依赖深度 $D$，而单目深度估计给出的 $D$ 只是在训练分布上的条件期望：

$$D=\mathbb{E}\!\left[D^* \mid I\right],\qquad \mathrm{Var}\!\left[D^*\mid I\right]>0\ \text{在遮挡边界与无纹理区域尤其显著}$$

方差大于零意味着反投影出的点云不是一个确定曲面，而是一个概率分布。在遮挡边界（桌沿后面是墙还是窗）和无纹理区域（白墙的深度几乎不可观测），这个方差会大到让几何决策失去意义。单帧路线无论怎么优化，都无法突破这个条件方差给出的下限——它缺的不是算力，是观测。要降低方差，唯一的办法是增加对同一空间区域的不同观测，也就是让相机移动、让同一面墙在不同视角下被重复看到，再用多帧观测去约束同一个几何量。这正是 Text2Room 把“相机逐步移动”作为核心机制而非附属步骤的原因：移动不是为了漫游，是为了采集约束。

一个具体的失败例子：只用单帧生成“靠窗书桌”并反投影，书桌桌面与窗台在图像里前后相邻，深度估计把两者压到近似同一深度，反投影后桌面穿进了墙体。工程上表现为渲染时桌面被墙面裁掉一半。要修这个，必须换一个略高的视角再看一次，让桌面与窗台在图像上分离，用新观测覆盖旧观测的错误深度。这个“换视角—重观测—覆盖”的循环，就是 Text2Room 迭代框架的雏形，也解释了为什么它的输出单位是“逐步长出的网格”而不是“一次生成的网格”。

五 · 从痛点反推设计：迭代生长作为唯一可行解

把上面的分析收拢，可以得到一条设计推理链：房间级生成需要多视角观测来降低深度条件方差；多视角观测要求相机移动，而移动会产生新的未观测区域；未观测区域必须用 2D 先验补全，补全结果又必须与已有观测在几何和纹理上对齐；对齐后的结果成为下一轮观测的先验基底。这条链是闭环的，任何一环断开，输出就不是一个自洽的房间。Text2Room 的架构正是这条链的直接映射：文本进 2D 文生图出首帧，单目深度反投影成初始网格，相机按选定视角移动，新视角图像经文本条件 inpainting 补齐后反投影，再与已有网格连续对齐融合。融合公式写成集合式的增量更新：

$$\mathcal{M}_{t+1}=\mathcal{M}_t\cup\mathrm{BackProject}\!\left(D_t,I_t,\mathbf{c}_t\right)$$

这个公式看起来平淡，但工程含义很重：并集操作意味着旧观测不被丢弃，新观测只做增量。它带来一个直接的系统代价——网格顶点数随视角数单调增长，显存占用随之上升，房间规模因此被显存卡住。这也是为什么论文把“规模受显存限制”列为局限：不是算法不想长更大，是增量并集的数据结构不允许无界增长。反过来，如果改成滑动窗口式的替换融合，漂移会被局部修正，但历史观测丢失又会让远处几何失去约束。这个取舍没有免费解，Text2Room 选择了保守的并集，把漂移问题留给了对齐环节。

再看视角选择这一环。它不是随手挑一个方向就走，而是要在“新视角能覆盖多少未观测区域”和“新视角与已有网格的重叠是否足够做对齐”之间取平衡。重叠太少，对齐无约束、漂移大；重叠太多，覆盖效率低、显存吃得快。消融实验把视角选择列为关键项，正说明这一环不是装饰性的启发式，而是决定漂移速率与覆盖效率的核心参数。一个具体判断：当房间狭长时，沿长轴推进的单步位移若过大，重叠区缩小到只剩一条窄带，对齐退化为单线约束，墙体法向会绕该线旋转，产生可见的倾斜漂移；此时必须缩小步长或增加侧向视角，代价是视角数上升、显存提前触顶。

把这些放在一起，Text2Room 的定位就明确了：它不是“更好的单物体生成器”，而是把 2D 生成模型改造成一个可迭代的场景采集器。它的每一个机制都对应一个具体的痛点，每一个痛点都对应一个可观测的失败模式。后续要讨论的对齐细节、补洞策略与漂移抑制，都是在这条已经确定的闭环上做加固，而不是另起炉灶。
