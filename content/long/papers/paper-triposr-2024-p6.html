一 · 最小可跑版本的目录骨架与模块边界

复现 TripoSR 的第一条工程判断是：不要把它当成一个单体模型，而是当成一条“编码器—三平面解码器—等值面提取器”的三段流水线。目录结构必须让这三段可以独立替换、独立测速、独立验收。建议的最小骨架如下：

  • configs/：存放模型规模、三平面分辨率、训练数据配比、增强开关的 YAML；每个实验一个文件，禁止把超参写进代码常量。
  • data/：Objaverse 多视图渲染的索引清单、每对象的相机参数与掩码路径；Google Scanned Objects 只作为验收集挂载，不参与训练。
  • models/encoder.py：DINO 或轻量 ViT 的封装，输出固定维度的图像 token 序列。
  • models/triplane.py：三平面解码器，把 token 序列映射为三张正交特征平面。
  • models/isosurface.py：可微等值面提取，负责从三平面采样出网格顶点与面片。
  • train.py / infer.py：训练循环与推理入口，两者共享同一份模型构建函数，避免训练与推理的预处理不一致。
  • tests/：形状断言、数值断言、端到端冒烟测试。

模块边界的关键在于：编码器只输出图像特征，不感知三平面分辨率；三平面解码器只输出 [3, C, H, W] 的张量，不感知网格提取的阈值；等值面模块只接收三平面与查询坐标，不感知图像。这条边界一旦打破，调参就会变成牵一发动全身的耦合调试。公式上，整条链路是

$$\mathbf{T}=\mathrm{Dec}_\theta(\mathrm{Enc}(I)),\qquad \mathcal{M}=\mathrm{IsoSurface}(\mathbf{T})$$
其中 Enc 的输出维度、Dec 的三平面通道数与空间分辨率、IsoSurface 的采样网格密度，是三个必须分别记录在 config 里的量。

最小可跑版本不必等数据齐全。先用一张固定图片、随机初始化的权重跑通前向：断言编码器输出形状为 [B, N, D]，三平面输出为 [B, 3, C, H, W]，等值面模块返回顶点数大于零的网格对象。这个冒烟测试能在几分钟内暴露绝大多数张量维度错位。常见崩溃点是三平面分辨率与等值面采样网格不匹配：解码器输出 H=W=32 的平面，而等值面模块按 128³ 的体素网格查询，插值坐标越界直接返回 NaN，网格顶点全空。系统代价是这类错误不会在 loss 上立刻显现，训练 loss 照常下降，直到推理阶段才发现输出是空网格——这是复现中最昂贵的一类失败模式。

二 · 数据准备：多视图渲染清单与配比的可复现性

TripoSR 在 Objaverse 上训练，用多视图渲染加渲染损失与掩码监督。工程上要复现的不是“下载 Objaverse”，而是“把每个对象的渲染结果固化成一份可审计的清单”。清单每条记录至少包含：对象 ID、视角索引、相机内外参、RGB 路径、掩码路径、以及该对象被采样的次数。把视角索引和相机参数写进清单而不是运行时随机生成，是保证两次训练看到同一批样本的前提；否则数据配比实验无法归因。

数据配比是论文明确提到的训练配方要素之一。复现时把它实现为采样权重表，而不是在文件系统层面复制数据：

$$p_i=\frac{w_{c(i)}}{\sum_j w_{c(j)}},\qquad w_{c}=\text{config 中的类别权重}$$
其中 c(i) 是样本 i 所属的对象类别或来源桶。这样调整配比只需改一个数字，且可以在日志里打印每个 epoch 实际采样的类别直方图，作为验收断言的一部分。常见崩溃点是权重表与清单不同步：清单里某个类别被过滤掉，权重表仍保留该项，归一化后实际采样概率与预期偏离，训练曲线看起来正常但质量分布偏移。

增强是另一个容易失控的点。渲染损失加掩码监督意味着增强必须同时作用于 RGB 与掩码，且几何变换要作用在相机参数上而不是只作用在像素上。只对图像做随机裁剪而不同步更新相机内参，会让监督信号与几何不一致，模型学到的是“图像与形状错位”的映射。系统代价是这种错误在单视图训练中不会报错，只会表现为收敛后轮廓模糊。具体例子：对一张 512×512 渲染图做中心裁剪到 448×448，若不修改主点偏移，重建出的物体在归一化坐标系里整体平移，等值面提取后网格偏离原点，后续的尺度归一化断言会失败。

验收断言应放在数据加载器之后、模型之前：断言每个 batch 的掩码与 RGB 空间尺寸一致、相机参数矩阵可逆、采样类别直方图与配置权重的偏差在容差内。这三条断言能在训练开始前拦住大部分数据侧崩溃，代价是每个 batch 多几次张量检查，相对于前向计算的开销可以忽略。

三 · 超参分层：模型规模、三平面分辨率与训练配方

论文的消融明确覆盖了模型规模、数据配比、等值面分辨率三项。复现时要把超参分成三层，每层独立记录、独立扫描，禁止交叉污染。

  • 规模层：编码器类型（DINO 或轻量 ViT）、解码器宽度与层数、三平面通道数。这一层决定显存占用与单步时间。
  • 分辨率层：三平面空间分辨率 H×W、等值面查询网格密度。这一层决定输出网格的细节上限与提取耗时。
  • 配方层：学习率、批大小、渲染损失与掩码损失的权重、数据配比、增强强度。这一层决定收敛速度与最终质量。

三平面分辨率与等值面分辨率不是同一个量，这是复现中最常见的概念混淆。三平面是解码器输出的特征图，分辨率受显存约束；等值面提取是在连续场上按查询网格采样，网格密度可以高于或低于三平面分辨率，靠插值桥接。二者关系可写成

$$\mathbf{f}(x)=\mathrm{Interp}\big(\mathbf{T},\, \pi(x)\big),\qquad \text{mesh}=\{x:\mathbf{f}(x)=\tau\}$$
其中 π(x) 把三维查询点投影到三张平面上取特征，τ 是等值面阈值。把等值面网格密度调高而不动三平面分辨率，细节不会凭空出现，只会让插值更平滑、提取更慢；把三平面分辨率调高而不动网格密度，则高频特征被采样网格欠采样，白白浪费显存。消融中“等值面分辨率”这一项之所以单独列出，正是因为它与三平面分辨率是可分离的两个旋钮。

训练配方的复现难点在于单卡可训这一约束。单卡意味着批大小受限，而渲染损失对批内多样性敏感。工程上的做法是梯度累积配合固定的有效批大小，并在 config 里同时记录物理批大小与累积步数，保证换卡后有效批大小不变。失败模式是只改物理批大小而忘记同步学习率与累积步数，导致有效批大小漂移，收敛曲线与论文配方不可比。具体例子：物理批大小从 8 降到 4、累积步数从 1 升到 2，有效批大小保持 8，但若学习率按物理批大小缩放，实际步数翻倍而每步梯度噪声不同，最终质量会出现难以归因的偏移。

超参验收断言应写成可执行的检查：断言三平面通道数能被注意力头数整除、断言等值面网格密度不低于三平面分辨率的某个倍数、断言有效批大小在训练日志中恒定。这些断言把“配置错误”从训练中期的玄学调试提前到启动瞬间的报错。

四 · 训练循环的崩溃点与数值稳定性

渲染损失加掩码监督的组合在数值上比纯渲染损失更敏感，因为掩码把监督限制在前景区域，背景梯度被压制。复现时要显式处理两个问题：前景占比极低的样本，以及等值面附近的梯度截断。前者会让 loss 被少量前景像素主导，后者会让可微等值面提取在阈值附近产生梯度尖峰。

可微等值面提取的伪代码思路是：在查询网格上采样特征，找到特征穿越阈值 τ 的格子，对每个穿越格子做线性插值定位顶点，再按格子拓扑连接面片。梯度通过插值权重回传到三平面特征。崩溃点在于：当某个格子的八个角点特征全部在阈值同一侧时，该格子不产生顶点，梯度为零；当特征在格子内剧烈变化时，插值权重接近 0 或 1，梯度出现尖峰。系统代价是训练后期 loss 突然抬升，且抬升幅度与等值面网格密度正相关——网格越密，穿越格子越多，尖峰越频繁。

工程上的缓解手段不是改公式，而是控制输入尺度：对三平面特征做层归一化，把等值面阈值固定为常数而不是可学习参数，并在提取前对特征做一次平滑。这些手段不改变论文的方法语义，但能显著降低复现时的数值抖动。具体例子：若阈值被设为可学习参数，训练初期阈值漂移到特征分布的尾部，穿越格子数量骤降，渲染损失无法回传，模型退化为输出常数场，网格提取结果是一个包围盒。这类失败在日志上表现为顶点数突然从数万跌到个位数，因此“每 N 步记录一次顶点数”应作为训练循环的固定监控项。

另一个崩溃点是混合精度。三平面解码器的注意力部分在 FP16 下容易出现溢出，表现为 loss 变 NaN。复现时应把归一化层与等值面插值保持在 FP32，其余部分用 FP16，并在每个 step 后断言 loss 有限。这个断言的代价是一次标量比较，收益是把 NaN 定位到具体 step 而不是等到整个训练结束后才发现权重已损坏。

五 · 推理路径与 0.5 秒预算的拆解

论文给出的推理时间是 0.5 秒（A100），且推理时直接提取网格、不做额外优化。复现时要做的不是复现这个绝对数字，而是把 0.5 秒拆成可测量的分段预算，并在每段上设断言。分段至少包括：图像预处理、编码器前向、三平面解码、等值面提取、网格后处理（去重顶点、合并面片）。前四段是模型链路，最后一段是纯几何操作，容易被忽略却在稠密网格上耗时可观。

等值面提取的耗时随查询网格密度呈立方增长，而三平面解码的耗时随分辨率呈平方增长。这意味着推理预算的瓶颈会随配置切换而转移：低网格密度时解码器主导，高网格密度时提取器主导。复现时应在 config 里记录两个分辨率，并在推理脚本里分别计时，输出一张分段耗时表。
阶段耗时随何增长典型崩溃点
编码器前向图像分辨率、token 数预处理与训练不一致导致特征分布偏移
三平面解码三平面分辨率平方通道数与注意力头数不整除
等值面提取查询网格密度立方插值坐标越界返回 NaN
网格后处理顶点数、面片数重复顶点未合并导致面片拓扑断裂

推理路径最常见的崩溃点是训练与推理的预处理不一致。训练时图像按某种归一化与裁剪送入编码器，推理时若省略同一步骤，编码器输出的特征分布偏移，三平面解码出的场整体缩放错误，等值面提取出的网格要么过大要么过小。验收断言应直接比较：同一张图在训练预处理与推理预处理下的编码器输出，逐元素差异应在容差内。这条断言比任何视觉检查都可靠。

网格后处理的失败模式是拓扑断裂。等值面提取按格子独立生成面片，相邻格子共享的边会生成重复顶点；若不合并，网格在渲染时出现裂缝，且顶点数虚高，拖慢后续任何基于网格的操作。具体例子：一个查询网格密度为 128³ 的提取结果，未合并顶点时顶点数可达合并后的数倍，后处理耗时占比从个位数百分比上升到与解码器相当。这也是为什么分段计时必须把后处理单列，否则会把后处理的开销误记到提取器头上。

六 · 验收断言清单与不可照搬的边界

复现的终点不是“跑出网格”，而是“跑出的网格通过一组可执行断言”。断言分四类，每类都要能在 CI 里自动运行。

  • 形状断言：编码器输出、三平面输出、网格顶点与面片的维度关系；三平面通道数被头数整除；等值面网格密度与三平面分辨率的比例在配置范围内。
  • 数值断言：每个 step 的 loss 有限；等值面阈值固定；混合精度下归一化层保持 FP32；编码器在训练与推理预处理下的输出差异在容差内。
  • 几何断言：提取出的网格顶点数大于零；网格包围盒在归一化范围内；合并顶点后无重复顶点；面片索引不越界。
  • 预算断言：分段耗时表中每一段都有记录，且总耗时与配置声明的目标区间一致；有效批大小在训练日志中恒定。

这些断言的价值在于把“质量略低于慢方法”这一论文结论转化为工程上可接受的下限。论文明确说 TripoSR 质量略低于 LRM/InstantMesh，纹理一般、分辨率有限。复现时不应把验收标准设成“追平 LRM”，而应设成“在 0.5 秒量级的预算内，网格非空、拓扑完整、包围盒正确、分段耗时可控”。把质量断言写成与慢方法的对比，会让复现陷入无休止的调参，而速度优势才是这条基线被社区采用的原因。

不可照搬的边界有三处。其一，等值面分辨率不能无限提高：它受三平面分辨率与显存双重约束，盲目提高只会让提取耗时立方增长而细节不增。其二，数据配比不能照抄论文的类别权重而不检查自己的清单覆盖：清单里缺失的类别会让权重表失真，采样直方图断言会失败。其三，推理的 0.5 秒是特定硬件上的量级表述，复现时应把它当作预算区间的锚点而非硬指标；在单卡上跑通链路、分段计时、断言总耗时落在同一量级，才是可复现的工程目标。具体机制上，真正决定能否复现的是三平面分辨率与等值面网格密度这两个旋钮的分离管理，以及训练与推理预处理的一致性断言——前者决定细节上限与耗时结构，后者决定输出是否落在正确的归一化坐标系里。
