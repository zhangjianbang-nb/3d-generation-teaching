一 · 复现边界：哪些东西必须自己造

MeshGPT 的复现难点不在 Transformer 本身，而在“面片词表”这一中间层。论文把流程拆成两段：先训图卷积 VQ-VAE 得到面片级码本，再在码本 token 序列上训 decoder-only 自回归模型。仓库里不存在一个端到端可跑的单一脚本，两段之间靠序列化格式耦合。复现者必须先决定：码本容量、面片序列化的排序规则、以及 token 与顶点索引的对齐方式。这三者任一错位，第二段训练会静默地学到错误分布——损失下降但采样出的网格面片互相穿插。

最小可跑版本的目标不是复现论文指标，而是打通“网格→token→网格”的闭环，并用断言锁住每一步的形状与语义。建议目录按职责切分，而不是按论文图切分：

  • data/：原始 ShapeNet 网格、预处理后的面片邻接缓存、序列化 token 文件。
  • vqvae/：图卷积编码器、量化层、解码器，以及码本使用率统计脚本。
  • tokenizer/：面片排序、token 拼接、序列长度截断与 padding 规则。
  • transformer/：decoder-only 模型、采样器、采样时的合法性约束。
  • eval/：重建误差、码本 perplexity、采样网格的面数与拓扑断言。

关键机制在于：VQ-VAE 的编码器输入是“面片及其邻域”，输出是每面片一个量化向量；解码器则要把量化向量还原成顶点坐标与三角连接。这里有一个容易忽略的工程代价——解码器输出的顶点是面片局部坐标系下的坐标，拼回全局网格时需要按面片顺序做坐标变换与去重。若去重阈值设得过松，会出现重复顶点导致非流形边；设得过紧，相邻面片共享的顶点被拆成两个，网格出现裂缝。这个阈值是复现期最常被低估的超参。

具体例子：取一把 ShapeNet 椅子，约数百个面片。序列化后 token 长度若超过 Transformer 的位置编码上限，必须截断。截断策略若按面片索引顺序硬切，会把椅腿和椅背切开，采样时模型学到“序列末尾总是突兀结束”，生成结果缺失支撑结构。正确做法是在序列化阶段按空间连通性排序，让截断发生在拓扑边界处。这一步没有公式可循，只能靠可视化断言：截断后的子网格必须仍是连通的。

二 · 数据准备：从网格到面片序列

数据管线要产出两类文件：VQ-VAE 训练用的面片样本，以及 Transformer 训练用的 token 序列。前者以面片为中心，后者以整网格为单位。两者必须共享同一套面片排序与索引映射，否则第二段训练时 token 的语义与第一段码本的语义不对应。

面片特征构造是第一个具体机制。图卷积编码器需要每个面片的局部几何与拓扑：面片三个顶点的坐标、面片法向、以及邻接面片的索引。邻接关系由共享边定义。构造邻接表时要注意，ShapeNet 网格存在非流形边和孤立面片，直接建图会引入度数为零的节点，图卷积在这些节点上退化为自环。预处理阶段应过滤掉邻接度低于阈值的面片，或在编码器中为孤立面片单独走一条 MLP 分支。

具体例子：飞机类网格的面片数分布比椅子更集中，但机翼与机身的连接处面片密度高。若按面片数均匀截断，机翼尖端常被切掉。工程上的妥协是优先保留邻接度高的面片，把低度数面片放在序列尾部，让截断优先丢弃它们。这是一个启发式规则，不是论文给出的，但复现时必须有明确的排序策略并在断言中固定下来。

三 · 两阶段超参：码本、序列与训练配方

第一阶段 VQ-VAE 的超参核心是码本大小与量化维度。码本太小，面片局部几何被过度合并，重建网格丢失锐利边缘；码本太大，码本使用率低，大量码字从未被激活，第二段 Transformer 学到的 token 分布稀疏且长尾。复现时应把码本使用率作为一等监控指标：每个 batch 后统计被激活码字数，若长期低于某个比例，说明码本容量过剩或承诺损失权重不当。

VQ 的承诺损失（commitment loss）权重是第二个敏感超参。它约束编码器输出靠近所选码字，权重过大会让编码器输出坍缩到少数码字，权重过小则编码器输出漂移，码字更新跟不上。复现时建议固定编码器与码字的学习率比例，而不是分别调。这个比例没有论文给出的数值可照搬，只能通过重建误差与码本 perplexity 的联合曲线来判断：重建误差下降但 perplexity 骤降，说明坍缩正在发生。

第二阶段 Transformer 的超参包括层数、注意力头数、位置编码方式与采样温度。序列长度上限直接由第一阶段的面片序列化决定，不能独立调。一个常见错误是把 Transformer 的上下文长度设得比实际 token 序列长，导致大量 padding token 参与注意力，模型学到“序列总是以 padding 结尾”，采样时提前终止。正确做法是按数据集的实际序列长度分布设定上下文，并对短序列做右侧 padding 加注意力掩码。

训练配方上，两阶段是串行的：VQ-VAE 收敛后再冻结码本，Transformer 只在 token 序列上训练。冻结码本是关键工程决策——若允许码本在第二阶段继续更新，token 语义会漂移，Transformer 学到的条件分布失效。复现时应在代码里硬性断言码本参数在第二阶段 requires_grad=False，并在训练日志里打印码本哈希，确认它未变。

具体例子：消融里对比了图卷积与 MLP 编码器。复现最小版本可以先用 MLP 跑通闭环，再换图卷积。MLP 版本忽略邻接关系，重建网格在面片边界处出现缝隙，但训练更快、崩溃点更少。这个替换不是偷懒，而是把“拓扑建模”与“序列建模”两个失败源分开定位。若 MLP 版本能跑通而图卷积版本崩溃，问题就在邻接表构造或图卷积的消息传递实现上。

四 · 验收断言：每一步都要能证伪

复现工程的核心不是跑出漂亮网格，而是让每一步失败都能被断言捕获。建议在管线中埋四类断言，每类对应一个具体机制。

  • 形状断言：VQ-VAE 编码器输出的面片嵌入维度、量化后索引范围、解码器输出的顶点数与面片数必须与输入一致。重建阶段面片数不一致，说明解码器的连接预测有误。
  • 语义断言：量化索引必须落在码本容量内；序列化后的 token 序列长度必须等于面片数；token 到面片的映射必须是双射。任一违反，第二段训练就是在学噪声。
  • 拓扑断言：重建网格的欧拉示性数应与原网格接近；非流形边数量必须低于阈值；孤立顶点数必须为零。这些断言在采样阶段同样适用。
  • 分布断言：采样网格的面数分布应与训练集同量级；若采样面数系统性偏少，说明模型学会了提前终止，通常是 padding 掩码错误或终止 token 位置错误。

公式上，重建误差可以写成面片级 Chamfer 距离与法向一致性的组合，但复现时更实用的是逐面片的顶点坐标最大偏差。因为 VQ 量化是有损的，逐面片偏差能直接反映码本容量是否够用。若最大偏差集中在少数面片上，说明这些面片的局部几何落在码本覆盖之外，需要扩充码本或增加面片特征维度。

系统代价在于断言本身的运行开销。拓扑断言需要构建半边数据结构，在大网格上耗时不可忽略。工程上的折中是只在验证集的一个子集上跑全量拓扑断言，训练过程中只跑形状与语义断言。这个分层策略要在配置文件里显式写出，避免复现者误以为所有断言都在每个 batch 上执行。

具体例子：采样阶段最常见的崩溃是生成的面片索引越界——Transformer 预测的 token 对应的码字解码出的顶点索引超出了当前已生成顶点数。这不是模型能力问题，而是采样器缺少合法性约束。修复方式是在采样时对候选 token 做掩码，只允许那些解码后不产生越界索引的 token。这个掩码逻辑必须与训练时的 token 语义严格一致，否则掩码会引入训练时未见的分布偏移。

五 · 常见崩溃点与最小可跑路径

崩溃点一：面片排序不稳定。广度优先遍历依赖邻接表的遍历顺序，若邻接表用字典存储且未排序，不同运行之间面片顺序会变，token 序列不可复现。修复是固定邻接表的键排序，并在序列化文件里存下排序种子。

崩溃点二：坐标归一化不一致。VQ-VAE 训练时若按每个网格独立归一化到单位球，解码器输出的坐标也在归一化空间；拼回全局网格时若忘记反归一化，采样网格的尺度会全部错乱。这个错误不会让损失异常，只会让可视化结果看起来“太小”或“漂浮”。断言应检查重建网格的包围盒与原网格包围盒的比例。

崩溃点三：码本死锁。VQ 的码字更新依赖批次内被选中的样本，若某些码字长期未被选中，它们的梯度为零，永远不更新。这是 VQ 的经典失败模式，复现时要用码字重启或 EMA 更新来缓解。论文未展开这一点，但复现者若忽略，码本使用率会持续下降。

崩溃点四：自回归采样无终止。decoder-only Transformer 需要显式的序列结束 token。若训练时序列未加结束符，采样时模型不知道何时停，会一直生成到上下文上限。修复是在序列化阶段为每个网格追加结束 token，并在采样器中把结束 token 的概率纳入终止判断。

最小可跑路径建议按以下顺序推进：先用少量网格跑通 VQ-VAE 的单面片重建，确认编码-量化-解码的形状闭环；再把多个面片拼成序列，确认序列化与反序列化的双射；然后冻结码本，用极小的 Transformer 在短序列上过拟合几个样本，确认它能复现训练序列；最后才放开数据规模与序列长度。每一步都用断言锁住，失败时能定位到具体模块，而不是面对一个“生成的网格很丑”的黑箱。

工程判断上，MeshGPT 的复现价值不在于复刻指标，而在于把“网格即语言”的接口固定下来：码本容量决定了几何表达的上限，序列长度决定了拓扑复杂度的上限，两者的乘积就是这套方法的能力边界。复现者若能在自己的数据上量出这两个上限，就已经完成了对论文工程含义的验证。
