一 · 训练数据的双轨结构：Objaverse 合成资产与内部产品图

SF3D 的训练数据由两条来源拼成，论文明确列出的是 Objaverse 与内部产品图。这两条来源在监督信号的性质上并不等价，理解它们的差异是理解后续所有指标口径的前提。Objaverse 提供的是带完整几何、材质、纹理标注的合成资产，这类数据可以同时监督网格、UV 展开、UV 空间纹理、材质参数与法线贴图，是联合损失里每一项都能落地的来源。内部产品图则是真实拍摄或渲染的电商级资产，它的价值在于把模型拉向真实材质分布与真实光照条件，但它的标注完备度不如合成资产，通常只能提供图像级或粗粒度的监督。

这种双轨结构直接决定了训练时的采样策略。工程上可以把它写成按来源加权的采样伪代码：对每个 batch，先按比例 $r$ 抽 Objaverse 样本、按 $1-r$ 抽内部产品图样本；对前者启用完整的 $\mathcal{L}_{\mathrm{geo}}+\lambda\mathcal{L}_{\mathrm{uv}}+\mu\mathcal{L}_{\mathrm{mat}}$ 联合监督，对后者则视标注情况屏蔽或降权 UV 与材质项，只保留几何与图像重建相关项。这个比例 $r$ 是训练配方里的关键超参之一，它决定了模型是更偏向合成资产的干净分布，还是更偏向真实资产的噪声分布。

机制上，Objaverse 资产之所以能支撑 UV 监督，是因为它们本身带有作者制作的 UV 布局，$\mathcal{L}_{\mathrm{uv}}=\|\hat{T}(u,v)-T(u,v)\|^2$ 才能在同一个 $(u,v)$ 参数化下逐像素比对预测纹理与参考纹理。而内部产品图往往没有可信的 UV 参考，强行套用同一损失会把噪声当监督。这里的系统代价是：双轨采样让每个 batch 的损失量纲不一致，几何项、UV 项、材质项的梯度尺度随来源切换而波动，需要靠 $\lambda$、$\mu$ 与来源权重共同压制，否则训练后期容易出现某一项主导、其余项退化的失败模式。一个具体的例子是：当内部产品图占比过高且未屏蔽 UV 项时，UV 分支会在无参考的样本上被推向平滑解，导致展开后的纹理出现大面积糊化，这种退化在合成资产上不可见，只在真实图上暴露。

二 · 评测协议：重光照对比与 UV/PBR 可用性检查

SF3D 的评测协议不是单一的图像相似度打分，而是围绕它声称解决的两个痛点设计的：能不能进引擎、能不能换光照。协议因此分成两层。第一层是重光照对比，把重建出的 PBR 网格放进新的光照环境下渲染，与顶点色方法的输出并排比较；论文的定性结论是重光照表现优于顶点色方法。第二层是资产可用性检查，即输出是否真的带标准 UV、是否带可分离的材质通道、法线贴图是否与几何一致。这两层合起来才构成对“生产级资产”的完整验收。

重光照对比的机制值得拆开看。顶点色方法把颜色烘死在顶点上，换光照时没有任何可调的反射参数，渲染器只能把顶点色当作自发光或漫反射常量处理，阴影与高光无法随光源变化。SF3D 输出的是材质参数加 UV 空间纹理，渲染时按 PBR 方程重新积分：给定新的光源方向与强度，基色、粗糙度、金属度、法线共同决定像素值。评测协议因此要求渲染管线真正走一遍 PBR 着色，而不是把贴图直接贴上去。可以用一个简化的评估伪代码描述：对每个测试资产，固定相机与几何，遍历一组预设光照配置，对每种配置分别渲染 SF3D 输出与基线输出，再由人工或感知指标比较。这里的系统代价是评测本身变重了——它依赖一个可信的渲染器与一套光照配置，评测结果对渲染器实现细节敏感，不同引擎的色调映射会让同一资产的对比结论漂移。

失败模式出现在协议的第二层。UV 展开是 SF3D 的显式模块，但展开本身会失败：拓扑复杂、细长部件、非流形接缝都可能让 unwrap 产生重叠或断裂的 UV 岛。评测协议若只做重光照渲染而不检查 UV 有效性，就会漏掉这类失败——渲染图看起来正常，但资产导入引擎后贴图错位。因此可用性检查必须包含 UV 重叠率、岛数量、接缝连续性这类结构性断言，它们是重光照指标无法替代的。一个具体例子是带细长悬挂部件的资产：unwrap 把细长条压成极窄的 UV 岛，纹理分辨率被严重压缩，重光照下颜色大体正确，但近距离检查会发现该部件纹理明显模糊，这类问题只有结构性检查能抓到。

三 · 指标口径：几何、纹理、材质三套尺子不能混用

SF3D 的损失由三项组成，评测指标也自然分成三套口径，混用会直接导致误读。几何口径衡量网格或 SDF 与参考几何的距离，常用 Chamfer 距离一类指标；纹理口径衡量 UV 空间纹理 $\hat{T}(u,v)$ 与参考 $T(u,v)$ 的逐像素差异，对应 $\mathcal{L}_{\mathrm{uv}}$ 的形式；材质口径衡量预测的基色、粗糙度、金属度与法线是否落在合理分布内。三套尺子的量纲、敏感度、失败模式都不同，把它们加权成一个总分是危险的，因为权重选择会直接决定排名。

$$\mathcal{L}_{\mathrm{uv}}=\|\hat{T}(u,v)-T(u,v)\|^2$$

这个公式看起来是标准的 L2，但它的口径有一个容易被忽略的前提：$\hat{T}$ 与 $T$ 必须定义在同一个 UV 参数化上。如果预测的 UV 布局与参考布局不同，逐像素比对就没有意义，此时要么先把预测纹理重采样到参考 UV，要么改用与参数化无关的指标。这就是纹理口径的脆弱点——它对 UV 对齐高度敏感，而 UV 对齐又依赖 unwrap 模块的成功率。工程上常见的做法是只在 unwrap 成功的子集上报告纹理指标，但这会引入选择偏差：失败样本被排除，指标看起来变好，实际部署时的失败率却没被计入。

材质口径的问题更隐蔽。材质真实感受数据限制，这是论文自己承认的局限。合成资产的材质分布与真实产品图不同，模型在 Objaverse 上学到的粗糙度、金属度分布未必迁移到真实电商资产。评测若只在合成测试集上做材质比对，会系统性高估材质质量。一个具体的失败模式是：模型对金属度预测偏保守，把本应是金属的部件预测成高粗糙度电介质，在合成测试集上因为参考材质也偏保守而得分不低，但在真实产品图上重光照时高光缺失，肉眼即可识别。这说明材质口径必须搭配真实来源的定性检查，不能只靠合成集上的数值。

四 · 消融的口径陷阱：UV vs 顶点色、材质/法线、delighting 各自证明了什么

论文的消融覆盖三组：UV 与顶点色的对比、材质与法线预测的贡献、delighting 步骤的必要性。这三组消融各自对应不同的指标口径，读的时候必须对齐，否则会把一组消融的结论错误地搬到另一组上。UV vs 顶点色的消融，其证据主要在重光照与引擎可用性上，而不是在几何指标上——两种表示共享同一个几何解码器，几何质量本就不该有显著差异，若有人拿几何指标来论证 UV 的优越性，那就是口径错配。材质/法线的消融，证据在重光照下的高光与细节表现，对应材质口径。delighting 的消融，证据在换光照后低频光照是否被剥离，对应的是光照解耦这一特定能力。

delighting 的机制值得单独说清，因为它是消融里最容易被误读的一项。delighting 步骤去除低频光照，其作用是在训练与推理时把输入图像中的环境光照成分从反照率中分离出去，使预测的基色更接近材质本身的颜色而非“被照亮的颜色”。如果没有这一步，模型会把输入图里的阴影与色调当作基色烘进纹理，换光照时这些烘死的阴影就会跟着资产走，产生“双重阴影”的失败模式。消融中移除 delighting 后重光照表现下降，正是这个机制在起作用。系统代价是 delighting 依赖对输入光照的估计，估计错误时会过度剥离或剥离不足：过度剥离让基色偏亮偏灰，剥离不足则残留光照耦合。数据增强在这里的作用是让模型见过多种光照条件，从而对估计误差更鲁棒。

一个具体的误读场景：有人看到消融表里移除某一项后某项指标下降，就断言该项“必不可少”。但消融的每一项都在特定口径下被测量，移除材质预测主要伤的是材质口径，移除 delighting 主要伤的是光照解耦口径，移除 UV 主要伤的是引擎可用性口径。三者的“下降”不可直接比较大小，因为它们不在同一把尺子上。正确的读法是：每项消融回答的是“这个模块对它对应的那个能力是否必要”，而不是“哪个模块最重要”。

五 · 那个容易误读的数字：0.5 秒的计时口径

SF3D 最醒目的数字是 0.5 秒，它出现在摘要、实验与影响描述里。这个数字极易被误读成“端到端从一张图到可进引擎资产的总耗时”，但它的口径需要拆解。0.5 秒对应的是推理阶段的前向过程：单图编码、网格/SDF 解码、快速 UV unwrap、UV 纹理生成、材质/法线预测、delighting 这一串模块的推理耗时。它不包含数据准备、不包含训练、也不包含资产进入引擎后的导入与材质校准。把 0.5 秒当作“生产管线总延迟”来规划产能，就会低估实际吞吐。

计时口径的机制差异在于各模块的耗时分布并不均匀。UV unwrap 是显式模块，它的耗时随网格拓扑复杂度上升，简单资产快、复杂资产慢；UV 纹理生成与材质预测是网络前向，耗时相对稳定；delighting 依赖光照估计，也有固定开销。因此 0.5 秒更像是一个在典型资产分布上的代表性数字，而不是对所有输入都成立的硬保证。工程上正确的用法是把它当作推理预算的量级锚点，再在自己的资产分布上实测分位数，而不是把 0.5 秒写进 SLA。

失败模式在于把推理耗时与可用性混为一谈。0.5 秒的推理可以产出一个带 UV、带 PBR 的网格，但这个网格可能 UV 展开失败、可能材质在真实光照下偏保守。速度指标不度量质量，质量指标不度量速度，两者必须分开报告。一个具体例子是批量资产生成场景：若按 0.5 秒估算单卡每小时产能，得到的是一个理论上限，实际产能要被 UV 失败率与人工修复时间打折。把 0.5 秒误读成“无需人工介入的端到端时间”，是这类数字最常见的作弊式解读——它用一个受控口径下的推理数字，冒充了包含失败修复的全流程数字。

六 · 作弊风险与工程判断：指标可被哪些捷径刷高

任何评测协议都有被捷径刷高的空间，SF3D 的三套口径各自对应不同的作弊路径。几何口径可被“保守平滑”刷高：把网格预测得偏平滑，Chamfer 距离在多数参考几何上不会太差，但细节丢失，这与论文承认的“几何细节有限”局限正好重合。纹理口径可被“UV 对齐投机”刷高：只在 unwrap 成功的子集上报指标，失败样本被静默排除，指标好看但部署失败率不变。材质口径可被“分布回归”刷高：把材质预测压向训练集均值，在合成测试集上稳定得分，但真实资产的多样性被抹平。重光照口径可被“光照配置选择”刷高：只报告对模型有利的几组光照，避开暴露材质缺陷的极端配置。

识别这些作弊的关键是要求评测报告同时给出分母与失败率。纹理指标必须报告 unwrap 成功率与失败样本的处理方式；材质指标必须报告测试集来源构成，合成与真实各占多少；重光照必须报告光照配置集合是否预先固定、是否覆盖极端条件。工程判断上，SF3D 作为生产级基线的价值不在于某一个数字多高，而在于它把 UV、PBR、光照解耦这三件事同时做进了 0.5 秒的推理预算里，并且消融明确指出了每个模块对应哪个能力。验收时应把这三项能力拆成独立断言：UV 有效性用结构性检查、PBR 通道完整性用导入引擎后的材质检查、光照解耦用固定光照配置下的重光照对比，而不是用一个加权总分掩盖口径差异。

最后落到一个具体机制上：delighting 让基色与光照分离，这意味着评测重光照时必须真正改变光源参数再渲染，若只是把同一张贴图换个背景，就测不出解耦是否成立。这个机制决定了重光照评测的最小可信协议——固定几何与相机、遍历预设光源、走完整 PBR 着色、并同时报告 UV 结构有效性。任何省略其中一步的评测，都在给“看起来能重光照”和“真的能重光照”之间留下作弊空间。
