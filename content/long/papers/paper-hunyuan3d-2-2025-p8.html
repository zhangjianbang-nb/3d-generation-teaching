一 · 训练数据的构成：Objaverse 与内部资产的双轨制

论文给出的数据来源只有两条：公开的 Objaverse，以及一个未公开规模的内部资产库。这个双轨结构不是随手拼凑，而是由两阶段架构决定的。形状分支需要的是几何监督信号——SDF 场或可微渲染下的一致性约束，Objaverse 的几十万量级物体提供了足够的形状多样性，足以覆盖椅子、车辆、动物、建筑构件等常见工业品类。纹理分支需要的则是带纹理的多视图渲染，而这恰恰是 Objaverse 的短板：大量资产要么无纹理，要么贴图分辨率低、UV 布局混乱，直接拿来训练纹理扩散会让模型学到的是「贴图噪声的统计分布」而非「材质与光照的物理规律」。因此内部资产承担了纹理侧的主力，其价值不在于数量，而在于可控的采集协议——同一物体在固定视角环、固定光照条件下渲染，保证多视图之间的光度一致性，这正是纹理扩散损失函数所依赖的前提。

从机制上看，形状侧的监督是 SDF 回归加渲染一致性：网络输出 VecSet 表示的隐式场，采样点上的 SDF 值与真值比较，同时通过可微渲染把隐式场投到多视角深度图上做几何约束。纹理侧的监督则是纯渲染域的，损失写成

$$\mathcal{L}_{\mathrm{tex}}=\sum_{v}\|\hat{I}_v-I_v\|^2$$

其中 $v$ 遍历预定义视角集合，$\hat{I}_v$ 是纹理分支在 UV 空间生成贴图后经投影渲染得到的图像，$I_v$ 是参考渲染。这个损失对 UV 展开质量极度敏感：如果参考资产的 UV 岛排布与模型预测的 UV 布局不一致，逐像素比较就会退化为噪声。工程上这意味着纹理训练必须先把所有资产规范到统一的 UV 展开流程，否则损失曲线会出现「训练集降、验证集不降」的典型过拟合形态。

数据侧的代价是明确的：内部资产的采集、清理、重拓扑与 UV 规范化是一条人工密集的流水线，论文只定性描述为「大规模数据」，没有给出具体规模。这本身就是一个信号——纹理真实感受数据限制，而数据限制的瓶颈不在数量而在标注质量。一个具体例子：若某批内部资产在采集时使用了不一致的曝光参数，纹理分支会把曝光差异学成材质差异，生成结果在换光照后出现整体色偏。这类失败不会在训练损失上暴露，只会在下游渲染中显现，属于典型的静默数据缺陷。

二 · 评测协议：几何与纹理分开度量

由于两阶段独立训练，评测也必须拆开看，否则一个「几何好、纹理差」的模型会被平均指标掩盖。论文的评测协议对形状侧使用高分辨率几何指标——本质上是比较生成网格与参考网格在采样点上的距离分布，常用 Chamfer 距离与法向一致性；对纹理侧则使用多视图渲染后与参考图像的感知相似度，指标口径落在图像域而非 UV 域。这个选择有明确的工程理由：UV 域的比较要求两套展开完全对齐，而生成模型的 UV 布局是自由预测的，逐像素比较无意义；渲染域比较则把 UV 展开的差异吸收进「最终看起来像不像」这一可观测目标里。

协议的关键机制是参考渲染的构造。纹理评测需要一组「标准视角」的参考图，这些图由参考资产在固定相机参数与固定光照下渲染得到。生成侧则用自己预测的 UV 贴图在同一组相机参数下渲染，再逐视角比较。这里有一个容易被忽略的口径问题：如果参考渲染使用了环境光照而生成侧使用了点光源，比较结果反映的是光照不匹配而非纹理质量。论文的协议把光照条件固定，正是为了消除这个混淆变量。伪代码层面的协议可以写成：对每个测试资产，固定相机环 $C=\{c_1,\dots,c_n\}$ 与光照 $L$，计算 $\frac{1}{n}\sum_i \mathrm{sim}(\mathrm{render}(M_{\mathrm{gen}},T_{\mathrm{gen}},c_i,L),\ \mathrm{render}(M_{\mathrm{ref}},T_{\mathrm{ref}},c_i,L))$，其中 $M$ 为网格、$T$ 为贴图。

失败模式在于视角覆盖。若标准视角只覆盖正面半球，背面纹理的错误完全不被惩罚，模型可以学会「只把正面贴图做对」。这在工业资产上尤其危险，因为下游使用者会从任意角度观察。工程复现时的验收断言应当要求视角环覆盖全向，并对背面单独统计。另一个代价是评测成本：每个资产要渲染多视角、每个视角要做感知相似度计算，测试集规模一大，评测本身就成为 GPU 时间的可观开销，这也是论文只定性报告「工业可用性优于同期开源模型」而不铺开大规模评测数字的现实约束。

三 · 指标口径与「一个容易误读的数字」

论文实验部分给出的可比对象是 TRELLIS、Direct3D、LRM 三个基线，结论是高分辨率几何加纹理、工业可用性优于同期开源模型。这里有一个极易被误读的口径：当读者看到「优于同期开源模型」时，直觉会把它理解为「在所有维度上更好」。但两阶段架构的评测是分维度报告的，形状指标与纹理指标各自独立，不存在一个把两者加权成单一分数的官方口径。把形状分数与纹理分数简单平均，或者拿形状分数去和只输出无纹理几何的基线比，都是口径错配。

具体机制在于：LRM 类前馈模型输出的是低分辨率、往往无纹理的资产，它在「几何指标」这一列上可以和 Hunyuan3D 2.0 的形状分支同台比较，但在纹理列上根本没有可比对象——不是它差，而是它不产出纹理。Direct3D 与 TRELLIS 各自有纹理能力，但分辨率与完整性不同。因此「优于」这个判断的正确读法是：在各自有定义的指标上，Hunyuan3D 2.0 的形状分支达到高分辨率几何水平，纹理分支产出完整 UV 贴图，两者合起来构成工业可用资产；而不是说它在任何一个单一标量上碾压所有基线。

误读的风险还来自分辨率口径。形状分支输出 SDF 后经 Marching Cubes 出网格，网格分辨率是一个可调参数，分辨率越高三角形越多、细节越丰富，但评测时的采样密度若固定，高分辨率网格的优势会被采样不足掩盖。工程判断是：比较两个模型的几何指标前，必须确认 Marching Cubes 的网格分辨率与评测采样密度匹配，否则「高分辨率」这个卖点在数字上体现不出来。一个具体例子：把生成网格降到低分辨率再算 Chamfer 距离，两个模型的差距会显著缩小，这不是模型变差了，而是评测口径把分辨率优势抹平了。这也是为什么论文把「分辨率」列为消融项——它要证明的是分辨率本身对最终质量有贡献，而不是靠口径取巧。

四 · 作弊风险：数据泄漏与评测过拟合

3D 生成评测的作弊面比 2D 更宽，因为参考资产本身可能就在训练集里。Objaverse 是公开数据集，任何使用它的模型都可能与测试资产重叠。论文没有给出训练/测试划分的具体去重协议细节，这构成一个需要工程侧自行把关的风险点：若测试资产与训练资产是同一物体的不同视角渲染，模型实际上是在做「记忆检索」而非「生成」，指标会虚高。防御手段是资产级去重——按物体 ID 而非按渲染图去重，并在测试集中保留一定比例的、训练时未见过的内部资产，用跨域测试暴露过拟合。

第二个作弊面是纹理评测的视角选择。如前所述，若标准视角集中在正面，模型可以通过「正面贴图做精、背面随便填」来刷分。这在训练中也会自发出现：纹理扩散的损失对每个视角等权，但如果训练数据的参考渲染本身背面覆盖不足，模型学到的就是「背面不重要」的先验。工程验收应当加入背面与侧面的单独指标，并对 UV 接缝处的纹理连续性做专项检查——接缝断裂是 UV 展开失败的典型表现，而它在正面视角的感知相似度上几乎不可见。

第三个作弊面是形状与纹理的耦合口径。两阶段独立训练意味着形状分支不知道纹理分支会怎么贴图，纹理分支也不知道形状的 UV 布局从哪来。若评测只报「合成后的渲染图相似度」，一个几何略差但纹理贴得准的模型可以拿到高分，反之亦然。正确的口径是把几何指标与纹理指标分开报告，并额外报告「合成失败率」——即 UV 展开失败导致贴图无法投影的资产比例。论文明确把 UV 失败列为局限，这说明失败率是一个真实存在的量，评测协议若不统计它，就会系统性高估工业可用性。

五 · 工程复现的数据与评测清单

复现这套数据与评测体系时，第一件要确定的事是纹理训练数据的 UV 规范化流程。所有资产必须经过统一的展开、岛排布与贴图烘焙，否则 $\mathcal{L}_{\mathrm{tex}}$ 的逐像素比较会引入系统性偏差。第二件事是参考渲染的光照与相机参数必须与生成侧完全一致，任何一侧的偏差都会污染指标。第三件事是测试集的资产级去重与跨域保留，前者防记忆，后者测泛化。

  • 数据侧：形状训练可用公开 Objaverse 为主，纹理训练必须以内部或自采的高质量带纹理资产为主，且采集协议统一。
  • 评测侧：几何用采样点距离与法向一致性，纹理用固定视角环、固定光照下的渲染域感知相似度，两者分开报告。
  • 风险侧：统计 UV 展开失败率与背面视角指标，作为工业可用性的硬门槛。
  • 口径侧：不把形状分数与纹理分数加权成单一标量，不与无纹理基线在纹理列上比较。

系统代价方面，纹理分支的多视图渲染与 UV 投影在推理时是串行链路，数十秒的推理时间里有相当比例花在 UV 展开与贴图烘焙上，而不是扩散采样本身。这意味着数据侧的 UV 规范化质量直接决定推理侧的失败率：训练时 UV 布局混乱，推理时投影就会错位，表现为贴图在接缝处撕裂。一个具体的工程断言是：对每个生成资产，检查 UV 岛的边界是否闭合、接缝两侧的纹素颜色差是否在阈值内，不满足则判定为纹理失败并回退到无纹理几何输出。这条断言比任何平均指标都更能反映工业可用性，因为它直接对应下游渲染会不会出可见瑕疵。

最后落到一个机制判断上：这套数据与评测体系的核心不是某个指标数字，而是「形状与纹理分开监督、分开度量」这一结构性选择。它使得形状分支可以吃公开几何数据、纹理分支可以吃私有高质量渲染数据，两者的数据瓶颈互不传染；代价是评测必须承担双份工作量，且任何试图把两列指标压成一个分数的做法都会掩盖真实的失败模式。工程上应把 UV 失败率与背面视角指标当作一等公民，而不是附在平均分后面的脚注。
