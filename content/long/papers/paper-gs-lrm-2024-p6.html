一 · 复现边界与最小可跑版本的定义

复现 GS-LRM 时，第一件要定清楚的事不是超参，而是“什么算跑通”。论文的核心断言是：一个 Transformer 从 2–4 张带相机位姿的图像直接回归 N 个高斯的均值、协方差、不透明度与球谐颜色，训练信号只来自可微光栅化的多视图渲染损失。因此最小可跑版本必须同时满足三个条件：前向能输出形状合法的完整高斯参数张量；可微光栅化能对这些参数求梯度并回传；一次前向的产物能被独立的光栅化器渲染出新视角且不报错。缺任何一条，都只是“张量形状对了”，不是复现。

工程上把这个最小版本切成四段：数据管线（多视图图像 + 相机嵌入）、Transformer 编码解码（多视图 patch 化 token）、高斯参数头（逐高斯回归四组量）、渲染监督（MSE + LPIPS 经可微光栅化）。四段之间用固定的张量契约连接，契约一旦写死，后续换分辨率、换高斯数、换视图数都只动配置不动代码。这个契约就是复现的骨架。

需要提前声明不能照搬的部分：论文的 Transformer 规模、高斯数上限、训练天数都是其算力预算下的选择，不是可移植的常量。复现的目标是复现“机制成立”，而不是复现“同等指标”。显存高与稀疏视图不稳是论文自己承认的局限，它们在复现里会以具体崩溃点的形式出现，下面逐节对应。

二 · 目录结构与张量契约

推荐的单仓结构按数据流分层，避免渲染器与模型互相污染。顶层分 data/、model/、render/、train/、eval/、configs/、asserts/ 七个目录。data/ 只负责把多视图样本整理成定长张量；model/ 只做 token 化与 Transformer；render/ 封装可微光栅化及其反向；train/ 组装损失与优化器；eval/ 独立实现一个不参与求导的光栅化路径用于验收；configs/ 存超参；asserts/ 存验收断言脚本。关键点是 eval/ 的光栅化必须与 render/ 的实现解耦，否则“能训”和“能渲”会共享同一个 bug 而互相掩盖。

张量契约用一张表固定下来，任何模块改动都要先过这张表：

张量形状含义与约束
images[K, 3, H, W]K 为输入视图数，取 2–4；像素归一化到固定区间
cameras[K, C_cam]相机嵌入，内参外参编码后拼接，C_cam 由编码方案定
tokens[K·P, D]P 为每视图 patch 数，D 为 Transformer 宽度
gauss_params[N, C_g]N 个高斯，C_g 为均值 3 + 协方差参数 + 不透明度 1 + 球谐系数
rendered[V, 3, H, W]V 个监督视角的光栅化输出

协方差不能直接回归 3×3 矩阵的九个元素，否则无法保证半正定。通行做法是回归一个旋转四元数与三个尺度对数，再组装 Σ = R diag(s) diag(s)T RT，这一步在参数头内部完成，对外仍暴露扁平的 C_g 维向量，使光栅化器只看到合法的协方差。球谐颜色按阶数展开，阶数决定每高斯颜色系数个数，这是 C_g 的主要组成部分，也是显存占用的隐形大头。

一个具体例子：K=4、H=W=256、patch 边长 16，则每视图 P=256，token 总数 1024，D 取一个中等宽度即可在单卡放下编码器；但 N 若取数万，gauss_params 的字节数会迅速超过 token 侧，显存瓶颈从注意力转移到高斯缓冲。这就是为什么复现时先固定小 N 跑通，再逐级放大。

三 · 数据准备与相机嵌入的对齐陷阱

数据侧的最小闭环是：每个样本含 K 张输入视图、若干监督视图、每张图的相机内外参。Objaverse 的多视图渲染数据天然满足这一形态，Google Scanned Objects 用于跨域验收。复现时最容易出错的地方不是图像读取，而是相机坐标系约定。Transformer 看到的相机嵌入与光栅化器使用的投影矩阵必须来自同一套约定（世界到相机的手性、归一化方式、视锥深度范围），否则模型会学到一个“补偿性”的位姿偏移，训练损失下降但新视角渲染系统性错位。

相机嵌入的具体机制：把外参旋转与平移、内参焦距与主点编码成定长向量，与 patch token 相加或拼接。这里有一个必须写进断言的约束——同一样本内所有视图的相机嵌入必须可区分，且交换视图顺序时输出高斯集合应在置换意义下近似不变。后者是检验模型是否真的在做多视图融合、而非记住某个视图顺序的廉价探针。

预处理要固定三件事：分辨率、裁剪策略、颜色空间。分辨率决定 patch 数进而决定 token 长度；裁剪若按物体包围盒归一化，必须把同一变换应用到所有视图与监督视图，任何一视图漏变换都会让光栅化监督产生固定偏移。颜色空间若在 sRGB 与线性之间混用，MSE 会稳定在一个偏高的平台，LPIPS 却看不出异常，这是典型的“损失不降但不是模型问题”。

数据管线的系统代价在于 I/O 与解码。多视图样本若每步都从磁盘解码高分辨率图，GPU 利用率会被 CPU 解码拖住；通行做法是预先把样本缓存为定长张量分片，代价是磁盘占用随视图数与分辨率线性增长。复现时应先量化单样本字节数，再决定缓存粒度，而不是先写 DataLoader 再发现瓶颈在解码。

四 · 超参分层与训练配方

超参按“影响机制”分三层，而不是按论文表格照抄。第一层是结构超参：Transformer 宽度与深度、patch 边长、高斯数 N、球谐阶数。它们决定模型容量与显存，改动任何一个都要重跑最小闭环。第二层是监督超参：MSE 与 LPIPS 的权重比、监督视角数 V、是否对不透明度做正则。第三层是优化超参：学习率、warmup、梯度裁剪、批大小。三层之间耦合弱，可以逐层冻结调参。

训练目标的形状是渲染损失，写成通用形式：

$$\mathcal{L}=\lambda_{\mathrm{mse}}\,\big\|\hat{I}-I\big\|_2^2+\lambda_{\mathrm{lpips}}\,\mathrm{LPIPS}(\hat{I},I)$$

其中 Ī 是光栅化器对预测高斯在监督视角下的渲染，I 是该视角真值。梯度经可微光栅化回传到每个高斯的均值、协方差、不透明度与颜色。伪代码思路是：前向出 gauss_params → 按监督视角逐个光栅化 → 累加损失 → 反向。注意光栅化的反向对不透明度和协方差的梯度尺度与对颜色的梯度尺度差异很大，若不分别设学习率或做梯度归一，颜色会先收敛而几何停滞，表现为渲染“颜色对、轮廓糊”。

一个数值玩具例子说明权重比的作用：若某像素颜色误差的 MSE 量级在百分之一，而 LPIPS 量级在十分之一，取等权会让 LPIPS 主导，几何被推向感知平滑但高频细节丢失；把 LPIPS 权重压低一个量级，MSE 主导颜色与轮廓，LPIPS 只做微调。这个比例不是普适常量，必须按自己的分辨率与监督视角数实测，且要在固定随机种子下比较，否则会被数据顺序掩盖。

系统代价出现在批大小与高斯数的乘积上。可微光栅化的中间缓冲随“像素数 × 覆盖高斯数”增长，批大小翻倍往往不是显存线性翻倍而是超线性，因为每个监督视角都要保留光栅化中间量用于反向。复现时的务实做法是固定批大小为 1、用梯度累积模拟大 batch，先验证梯度正确性再谈吞吐。

五 · 常见崩溃点与失败模式

崩溃点一：协方差非半正定导致光栅化产生 NaN。根因通常是尺度对数回归出极端值或四元数未归一化。断言应在前向出口检查协方差矩阵的最小特征值下界，或在参数头强制尺度对数截断、四元数归一化。这类 NaN 一旦进入反向会污染全部参数，表现为损失突然跳到 NaN 且不可恢复。

崩溃点二：高斯数 N 与显存。论文明确把“高斯数限制”列为局限，复现时若直接取大 N，光栅化缓冲与参数头输出会同时吃显存，典型症状是前向能过、反向 OOM。定位方法是分别测参数字节数与光栅化中间量字节数，前者随 N 线性，后者随 N 与像素覆盖超线性。缩 N 或缩监督分辨率是唯一直接手段。

崩溃点三：稀疏视图几何不稳。2–4 张输入视图下，未被任何输入视图覆盖的区域其高斯均值与协方差不被监督约束，模型会输出漂浮的高斯或把不透明度压到接近零。表现为新视角出现空洞或雾状伪影。这不是训练 bug，而是论文承认的失效条件；复现时应把“输入视图数”作为消融变量记录，而不是指望调参消除。

崩溃点四：相机约定错位。症状是训练损失正常下降但 eval 渲染整体旋转或镜像。断言做法是用真值高斯（若能取得）或已知位姿的合成场景跑一次前向，检查渲染与真值的对齐；更廉价的是交换两视图输入，检查输出高斯的空间分布是否随之合理变化。

崩溃点五：可微光栅化与独立光栅化不一致。训练用的可微实现与 eval 用的实现若在前向排序、alpha 合成顺序上有差异，会出现“训练渲染好、验收渲染差”。这是最隐蔽的失败模式，因为两边都不报错。唯一可靠的办法是让 eval 路径对同一组 gauss_params 与训练路径逐像素比对，差异超过阈值即视为实现分歧。

六 · 验收断言清单

验收断言按“机制是否成立”而非“指标是否达标”来写，每条都可自动执行。第一条：前向输出形状与数值合法性——gauss_params 形状匹配 [N, C_g]，协方差半正定，不透明度在合法区间，球谐系数无 NaN。第二条：单步梯度存在性——对均值、协方差、不透明度、颜色四组参数分别检查梯度非零且非 NaN，任一组为零说明该参数未被监督路径触达。

第三条：置换等变性探针——交换输入视图顺序，输出高斯集合在最近邻匹配下的均值偏差应小于阈值，否则模型依赖视图顺序而非多视图融合。第四条：渲染一致性——训练光栅化与验收光栅化对同一 gauss_params 的输出逐像素差异小于阈值。第五条：视图数消融记录——在 2、3、4 视图下分别记录损失与新视角渲染，确认稀疏视图退化是数据条件而非实现错误。

第六条：显存与吞吐基线——记录固定 N 与分辨率下的峰值显存与前向耗时，作为放大 N 或分辨率的预算依据。第七条：跨域抽查——在 Objaverse 训练后在 Google Scanned Objects 上跑少量样本，确认不是对训练分布过拟合到无法渲染。这些断言不追求论文指标，只保证“机制在跑”，是把复现从“看起来能训”推进到“知道哪里会坏”的分界线。

最后落在具体机制上：GS-LRM 的复现成败几乎不取决于 Transformer 本身，而取决于高斯参数头与可微光栅化之间的契约是否被断言钉死。协方差合法性、梯度触达、两条光栅化路径的一致性这三项一旦自动化，稀疏视图不稳与显存上限就退化为可测量的边界条件，而不是随机崩溃。
