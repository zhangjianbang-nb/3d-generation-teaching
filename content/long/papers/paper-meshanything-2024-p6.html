一 · 复现边界与最小可跑目标

复现 MeshAnything 的第一件事不是装环境，而是把“复现什么”钉死。论文的核心主张是条件生成式重拓扑：给定任意 3D 表示，自回归 Transformer 输出与输入形状对齐、面数紧凑的面片序列。复现验收必须围绕这个主张，而不是围绕“跑出一个网格”。一个最小可跑版本（MVP）应当满足三条硬断言：其一，输入可以是三角汤、点云或神经场采样点，统一走形状编码器；其二，输出是面片序列解码出的三角网格，面数量级在论文所述的约 800 附近，且远小于输入面数；其三，输出网格在几何上贴合输入形状，拓扑上不是简化算法的产物——即不存在简化算法典型的退化三角形、非流形边和拓扑断裂。做不到第三条，复现就退化成“又一个网格简化器”。

MVP 的规模要主动收缩。论文训练用 Objaverse 艺术家网格，数天量级；从零复现不可能一上来就复刻这个规模。合理的 MVP 是：取 Objaverse 的一个小子集（按类别分层抽样，保证艺术家网格的拓扑多样性），输入侧用固定点数的点云采样，输出侧把面数上限压到远低于论文的 800，先验证“条件对齐 + 紧凑面数”这条链路能闭合。这里的关键工程判断是：面数上限和序列长度是耦合的，面片 token 化后每个面片占若干 token，序列长度上限直接决定能生成多少面。MVP 阶段把面数上限调小，等于把序列长度、显存、采样步数一起调小，是唯一能让单卡跑通的办法。

验收断言要写成可执行的检查，而不是人工目测。几何对齐用采样点到输出网格表面的 Chamfer 距离或最近面距离分布；紧凑性用输出面数与输入面数的比值；拓扑质量用非流形边计数、退化三角形计数、连通分量数。这三个指标构成 MVP 的通过门槛：Chamfer 距离不能显著劣于输入自身的采样噪声水平，面数比值要落在论文所述量级的合理区间，拓扑指标要明显优于 Quadric 简化基线。任何一项不达标，先怀疑数据管线和 tokenization，而不是怀疑模型容量。

二 · 目录结构与模块切分

从零复现的目录结构应当直接映射论文的数据流，让每个模块的边界清晰可测。建议的骨架是：

  • data/：Objaverse 艺术家网格的下载、过滤、点云采样、面片序列化；
  • tokenizer/：面片 token 化与反 token 化，顶点量化、邻接关系编码；
  • encoder/：点云 Transformer 形状编码器；
  • decoder/：自回归面片解码器，含因果掩码与采样逻辑；
  • train/：训练循环、损失、超参配置；
  • eval/：几何对齐、紧凑性、拓扑三类断言；
  • export/：token 序列到网格的组装与合法性修复。
这个切分不是为了好看，而是为了让“崩溃点”可定位。面片序列化出错会在 tokenizer/ 的往返测试里暴露；形状对齐失败会在 encoder/ 的固定输入过拟合测试里暴露；自回归采样发散会在 decoder/ 的教师强制与自由采样对比里暴露。

模块之间要有契约。形状编码器输出固定维度的形状特征或固定点数的点云嵌入，解码器以这些特征为条件、以已生成的面片 token 为历史做下一步预测。这个契约决定了训练时的条件注入方式：是把形状特征作为前缀 token 拼进序列，还是作为交叉注意力的 key/value。两种方式在工程代价上不同——前缀 token 方式实现简单但占用序列长度预算，交叉注意力方式不占序列但要求解码器每层都接条件分支。MVP 建议先用前缀 token，因为序列长度预算在 MVP 阶段本来就压得很小，实现复杂度低，失败模式也更容易归因。

导出模块常被低估。自回归生成的面片序列不保证构成合法网格：可能出现重复面、悬空顶点、非流形边。导出模块必须做合法性修复，并且修复策略要可审计——是丢弃非法面、合并重复顶点，还是回退到最近合法前缀。这个策略直接影响验收指标，必须在复现报告里写清楚，否则拓扑指标不可比。

三 · 数据准备与面片序列化

数据准备的第一步是过滤，不是采样。Objaverse 艺术家网格的质量参差不齐，直接拿来训练会把噪声灌进 tokenizer。过滤准则应当围绕“可被面片 token 化”展开：网格必须是三角网格或可三角化的多边形网格；面数不能超过序列长度预算能容纳的上限；必须连通或连通分量数在可控范围；不能有大量退化面。过滤后按类别分层，保证艺术家网格的拓扑风格（四边面主导、均匀布线、局部环状结构）在训练集里有足够覆盖。

面片 token 化的核心是把一个面片的顶点与邻接关系编码成离散 token。论文的做法是每个面片 token 编码顶点与邻接关系，这意味着 tokenizer 要先做顶点量化：把连续坐标映射到离散网格，再按面片遍历顺序把顶点索引和邻接标记串成序列。量化精度是第一个超参，精度太高会让词表爆炸、序列变长，精度太低会让输出网格出现台阶状几何误差。MVP 阶段应当把量化精度设成与输入点云采样密度匹配的量级，并用往返测试验证：任意一个训练网格经 token 化再反 token 化后，几何误差要小于采样噪声。

序列化顺序是第二个关键决策。面片遍历顺序决定了自回归模型学到的“生成语法”。按空间邻近顺序遍历，模型学到的是局部生长的面片序列，生成时更容易保持拓扑连贯；按文件原始顺序遍历，模型学到的是艺术家建模的历史顺序，可能包含大量跳跃。论文没有把遍历顺序作为独立消融项列出，但复现时这是必须显式选择的工程参数。MVP 建议用空间邻近顺序，因为它的失败模式更可预测：生成到一半断裂时，断裂位置通常对应空间上远离已生成区域的面片，便于定位。

数据准备的系统代价主要在存储与预处理吞吐。面片序列化后的 token 序列比原始网格大，且需要与形状条件（点云）配对存储。一个具体例子：一个艺术家网格经量化与序列化后，token 序列长度可能达到数千，若面数上限设为数百，则每条样本的序列长度在数千 token 量级；乘以数据集规模，存储和加载带宽会成为训练瓶颈。缓解办法是预处理时就把序列截断到预算上限，并在截断处记录标记，让模型学会在预算内收尾，而不是在训练循环里动态截断。

四 · 超参与训练配方

超参分三组：形状侧、序列侧、优化侧。形状侧的关键是点云采样点数与编码器层数。采样点数决定输入形状的信息量，点数太少会让对齐失败，点数太多会让编码器计算量上升且引入冗余。MVP 阶段采样点数应与量化精度匹配，保证点云能覆盖输出面片的顶点分布。编码器层数在 MVP 阶段不宜深，因为形状编码器只提供条件，容量瓶颈通常在解码器的序列建模上。

序列侧的超参直接受面数上限约束。设面数上限为 N_f，每个面片占 k 个 token，则序列长度上限约为 N_f × k 加上条件前缀长度。这个关系是硬约束：

$$L_{\max} \approx N_f \cdot k + L_{\mathrm{cond}}$$
其中 L_cond 是形状条件占用的前缀长度。调大 N_f 会同时抬高显存、采样步数和训练时间，MVP 阶段应把 N_f 压到远低于论文所述的 800，先验证链路。解码器的注意力窗口与位置编码必须覆盖 L_max，否则长序列尾部会失去位置信息，表现为生成末段面片空间错乱。

优化侧的核心是教师强制与自由采样的差距。训练用教师强制，即用真实历史面片 token 作为下一步输入；推理用自由采样，即用模型自己生成的 token 作为历史。两者分布不一致会导致暴露偏差：训练损失很低，自由采样却在中段发散。MVP 阶段必须做这个对比测试，并记录发散起始位置。缓解手段包括在训练中按一定概率用模型自己的预测替换真实 token（ scheduled sampling 思路），或把序列长度预算压短，让模型在短序列上先学会稳定收尾。

训练配方的另一个工程点是条件注入的稳定性。形状特征作为前缀 token 时，前缀部分的损失应当被掩掉，只对输出面片 token 计损失。若误把前缀也计入损失，模型会花容量去重建形状条件，表现为输出面片与输入对齐变差。这是一个常见崩溃点，症状是训练损失正常下降但验收的 Chamfer 距离不降。

五 · 常见崩溃点与定位手段

崩溃点一：tokenizer 往返不一致。症状是训练能跑、损失下降，但导出网格几何错乱。定位手段是对训练集做批量往返测试，统计反 token 化后的顶点坐标误差与面片邻接误差。根因通常是量化精度与顶点索引编码不一致，或面片遍历时邻接标记写错。修复方式是先把 tokenizer 冻结，用固定网格过拟合一个小解码器，确认往返链路无误后再放开训练。

崩溃点二：形状条件被忽略。症状是输出网格面数紧凑、拓扑尚可，但与输入形状不对齐，表现为输出像是从训练集里“平均”出来的形状。定位手段是做条件替换测试：固定解码器输入的历史，替换形状条件，观察输出是否随之改变。若不改变，说明条件注入路径失效，常见原因是前缀 token 被因果掩码错误地屏蔽，或交叉注意力分支未接梯度。

崩溃点三：自由采样中段发散。症状是前若干面片合理，随后出现重复面、跳跃面或非法邻接。定位手段是对比教师强制与自由采样的逐步预测熵，发散点通常对应熵骤升。根因是暴露偏差与序列长度预算不匹配。修复方式是缩短 N_f、增加训练时的历史扰动、或在导出模块加入合法性回退。

崩溃点四：拓扑指标被导出修复污染。症状是拓扑指标很好看，但几何对齐很差。根因是导出模块过度修复，把非法面大量丢弃后剩下的网格恰好连通且无退化面，但已不贴合输入。定位手段是统计修复前后的面数差与 Chamfer 距离差，把修复率作为验收报告的必要字段。这是一个容易被忽略的系统代价：修复策略越激进，拓扑指标越不可信。

崩溃点五：显存与序列长度的隐性耦合。症状是调大面数上限后训练直接 OOM，或梯度检查点开启后训练速度骤降。根因是注意力计算随序列长度平方增长，而面数上限直接抬序列长度。定位手段是记录不同 N_f 下的峰值显存与每步耗时，画出曲线，确认瓶颈在注意力还是在前缀条件。MVP 阶段应把 N_f 作为第一个被调小的超参，而不是最后才动的旋钮。

六 · 验收断言与工程判断

验收断言应当分三层，且每层都有明确的通过条件。第一层是链路断言：tokenizer 往返误差低于采样噪声；固定输入过拟合后，训练集上的 Chamfer 距离收敛到与输入采样密度同量级。第二层是泛化断言：在留出集上，输出面数落在论文所述量级的合理区间，面数比值显著小于 1；Chamfer 距离不显著劣于输入自身的采样噪声；非流形边与退化三角形计数明显低于 Quadric 简化基线。第三层是鲁棒性断言：对输入加轻度噪声后，输出面数与拓扑指标不发生数量级退化——论文明确指出对输入噪声敏感，这条断言正是用来量化“敏感”的程度。

这三层断言对应三种失败模式。链路断言失败，问题在数据与 tokenizer；泛化断言失败，问题在模型容量或条件注入；鲁棒性断言失败，问题在输入表示与训练分布。把失败模式与模块对应起来，复现才不会陷入“调参碰运气”。一个具体例子：若泛化断言中 Chamfer 距离达标但拓扑指标不达标，说明模型学到了几何对齐但没学到艺术家布线，此时应检查训练集的拓扑多样性，而不是加大模型。

工程判断的落点在于：MeshAnything 的复现价值不在于复刻 800 面这个数字，而在于复刻“条件生成式重拓扑”这条链路，并量化它的三个边界——面数上限限制细节、序列长度受限、对输入噪声敏感。MVP 把面数上限压小，等于主动把第一个边界暴露出来，让复现者看清细节损失与面数预算的取舍关系。验收断言里的面数比值与 Chamfer 距离联合分布，就是这条取舍曲线的离散采样。若复现报告只报一个平均 Chamfer 距离，而不报面数上限与序列长度的对应关系，这份复现就无法回答“这套方法在我的管线上能不能用”这个工程问题。

最后一个具体机制层面的判断：导出模块的合法性修复必须与验收指标解耦。修复率高的样本应当单独统计，不能混入平均指标。因为修复本质上是用规则补模型的短板，修复率上升意味着模型在自由采样下的合法性下降，这正是序列长度受限与暴露偏差的联合症状。把修复率作为一等指标记录，复现者才能在调大面数上限时立刻看到合法性代价，而不是等到拓扑指标被污染后才发现问题。
