一 · 目标函数：从三平面到像素的端到端可微链路

LRM 的训练目标不是直接监督三平面，也不是监督网格顶点，而是把三平面渲染成图像，再和真值视图逐像素比较。整条链路是：输入图 I 与输入相机 c 进入 Transformer，输出三平面 T；给定一个监督视角的相机 c′，体渲染器沿射线采样、查询三平面特征、经 MLP 得到密度与颜色，最后合成像素值。损失只作用在合成像素上，梯度沿渲染器反传，穿过 MLP、穿过三平面、穿过 Transformer 解码器的 cross-attention，一直回到 DINO ViT 的输入侧。这个「渲染即监督」的设计是 LRM 能用纯 2D 图像数据训练 3D 表示的根本原因：不需要 3D 真值，只需要多视角一致的照片。

形式化地，记渲染算子为 R，则训练目标是

$$\mathcal{L}(\theta)=\mathbb{E}_{(I,\{I'_k,c'_k\})\sim\mathcal{D}}\Big[\sum_{k}\big\|\hat{I}_k-R(\mathrm{Transformer}_\theta(I,\mathbf{c}),c'_k)\big\|^2+\lambda\,\mathrm{LPIPS}\big(\hat{I}_k,I'_k\big)\Big]$$

其中 θ 是 Transformer 与渲染 MLP 的全部参数，D 是 Objaverse 的多视图渲染数据集，k 遍历同一物体的多个监督视角。MSE 项约束低频颜色与整体亮度，LPIPS 项约束高频纹理与感知质量，λ 是两项的权重比。注意监督视角 c′ 与输入视角 c 是分开的：输入相机只用于让 Transformer 知道「这张图是从哪个方向拍的」，从而把图像特征放到正确的空间位置上；监督相机则是随机采样的，逼迫模型在未见过的视角下也给出正确渲染。

这个目标函数有一个容易被忽略的性质：它对三平面的尺度是不变的。渲染器只关心沿射线的积分结果，三平面整体乘以一个常数、MLP 相应调整，可以给出同样的像素。真正约束三平面几何的是多视角一致性——同一个 3D 点从不同相机看过去必须给出相同的密度和颜色。这也是为什么单视图监督不够、必须多视图监督：单视图下无穷多个三平面都能完美重投影，多视图才把解钉住。

失败模式出现在监督视角的分布上。如果训练时监督相机只围绕输入视角附近采样，模型会学到「只在输入视角邻域内正确」的捷径，背面和侧面的密度场塌陷成噪声。LRM 的做法是在整个球面上采样监督相机，包括与输入视角接近对跖的方向，这才让三平面在背面也有可用的外推。代价是优化更难：对跖视角的梯度信号弱，早期训练容易出现背面颜色均值化的现象，需要靠 LPIPS 项和足够大的 batch 把高频细节拉回来。

二 · 变量含义：三平面、相机与特征的对齐

三平面 T 由三个正交的特征平面组成：Txy、Txz、Tyz，每个分辨率 64×64、通道数 32。查询一个 3D 点 x=(x,y,z) 时，把它的三个坐标对分别投影到三个平面上做双线性插值，得到三组特征，拼接后送入一个轻量 MLP，输出该点的密度 σ 与颜色 c。这个表示的关键在于：三个平面共享同一套空间坐标，任意一个 3D 点都能被三个平面同时索引，因此三平面是一个「显式的、坐标可寻址的」3D 特征场，而不是隐式的 MLP 权重场。显式的好处是 Transformer 可以直接输出它——解码器最后一层就是一个卷积或线性头，把 token 序列 reshape 成 3×64×64×32 的张量，没有 NeRF 那种「网络即场景」的不可解释性。

相机参数 c 进入 Transformer 的方式是调制，而不是简单拼接。输入相机的外参和内参被编码成若干 token，与图像 patch token 一起送入解码器的 cross-attention，作为 query 侧的位置提示。这样做的机制意义是：Transformer 需要知道「这张图是从哪个方向看到的」，才能把图像中看到的正面特征放到三平面中正确的 Txy 区域，而不是均匀地摊到三个平面上。消融实验里相机调制被单独列出，说明它不是可有可无的装饰——去掉它，模型在输入视角与监督视角差异较大时质量明显下降。

监督相机 c′ 不进入 Transformer，只进入渲染器。它决定射线方向，射线上的采样点决定查询三平面的哪些位置。这里有一个变量对齐的细节：三平面的坐标系必须与相机坐标系一致，否则渲染出的图像和真值视图对不上，损失会给出错误的梯度。LRM 在数据准备阶段把每个物体的多视图渲染统一到同一个规范坐标系下，输入相机与监督相机共享这套坐标，三平面也就继承了这套坐标。

一个具体的失败模式是通道数不足导致的「特征瓶颈」。32 通道的三平面要同时编码几何（密度）和外观（颜色），在高频纹理区域容易出现通道争用：几何需要锐利的边界，外观需要平滑的渐变，两者在同一个特征向量里打架。表现是渲染图在物体轮廓处出现彩色振铃。这不是靠调损失权重能解决的，而是表示容量的硬约束，也是后续工作把三平面通道数往上推的动机之一。

三 · 梯度与采样：体渲染反传的路径与噪声

体渲染的梯度路径值得单独拆开看，因为它是整个训练里计算量最大、也最容易出问题的一段。对一条射线，渲染器在近远平面之间采样 N 个点，查询三平面得到 σi 和 ci，然后按离散化的体积积分合成：

其中 δi 是相邻采样点的间距，Ti 是累积透射率。梯度对 σi 的依赖同时出现在两项里：当前点的「不透明度」项，以及它作为后续所有点透射率因子的指数项。这意味着一个点的密度变化会通过透射率影响它后面所有点的贡献，梯度是长程耦合的。对 Txy 的梯度则来自所有落到该平面上的采样点，双线性插值把梯度分摊到四个邻近像素上，形成一种天然的空间平滑。

采样策略直接决定梯度的信噪比。均匀采样在空白区域浪费大量查询，在物体表面附近又采样不足，导致密度边界模糊。LRM 采用粗采样加重要性采样的两阶段思路：先均匀采样一批点估计粗略的透射率分布，再在透射率变化剧烈的位置加密采样。这个机制让梯度集中到真正决定像素值的表面附近，而不是被空气区域的零梯度稀释。代价是每个像素的查询次数翻倍，渲染器成为训练吞吐的瓶颈。

伪代码层面，一个训练步的核心循环是：

  • 取一个 batch 的 (输入图, 输入相机, 监督相机, 真值视图)；
  • 前向 Transformer 得到三平面 T；
  • 对监督相机的每个像素生成射线，两阶段采样得到 N 个点；
  • 查询三平面 + MLP，得到 σ、c，合成像素 Î；
  • 计算 MSE + λ·LPIPS，反传至 T 与 Transformer；
  • AdamW 更新，学习率按 warmup 加余弦衰减调度。

梯度噪声的一个具体来源是监督视角的随机性。同一个物体、同一张输入图，每个 step 采到的监督相机不同，损失曲面在参数空间里是抖动的。这既有好处也有代价：好处是相当于一种数据增强，逼迫模型对所有视角一致；代价是 batch 必须足够大才能把噪声平均掉，而大 batch 又撞上显存墙——三平面 3×64×64×32 的张量加上渲染器对每条射线的 N 次查询，显存占用随分辨率平方增长。LRM 用数十 GPU 天训练，很大一部分算力花在渲染器而不是 Transformer 上，这是「渲染即监督」路线的固有税。

另一个失败模式是透射率饱和。当某个区域的密度被优化得过高，Ti 迅速趋近于零，后面点的梯度被指数压低，表面之后的几何再也收不到信号。表现是物体背面出现「空洞」——渲染图在背面视角下透出背景。缓解手段是给密度加一个上界或在早期训练里降低密度初始化，让透射率保持在梯度可用的区间。

四 · 训练配方：数据、优化器与超参的量级

数据侧，LRM 在 Objaverse 约 50 万物体上训练，每个物体渲染 16–32 个视图。这个数字不是随便定的：视图太少，多视角一致性约束不足，三平面在未见视角下塌陷；视图太多，单物体的渲染成本线性上升，而边际信息量递减。16–32 是一个在「覆盖球面足够密」和「单步成本可承受」之间的工程折中。输入图从这些视图中选一张，监督视图从其余视图中采，这样输入与监督共享同一套渲染管线，颜色和光照风格一致，不会引入域差异。

优化器用 AdamW，这是 Transformer 训练的标准选择，权重衰减把三平面里不活跃的通道慢慢压向零，起到一种隐式的稀疏化。学习率调度采用 warmup 加余弦衰减：warmup 阶段让 cross-attention 的随机初始化先稳定下来，避免早期梯度把三平面推向退化解；余弦衰减让后期更新变小，把高频细节磨出来。这些是配方层面的选择，论文没有给出逐项的超参表，但量级上属于十亿参数 Transformer 的常规配置。

模型规模是配方里最敏感的一项。解码器 24 层、1024 宽，加上 DINO ViT，总参数到十亿级。消融实验把模型规模单列，说明规模不是「越大越好」的单调曲线：规模太小，三平面的表达能力不够，背面细节直接丢失；规模太大，在固定数据量下过拟合到训练物体的纹理，新视角泛化变差。50 万物体这个数据量级，恰好支撑十亿参数而不至于严重过拟合，这是 LRM 能成立的前提之一——数据和模型是配套放大的。

三平面分辨率 64×64 是另一个关键超参。它决定了网格提取的上限：三平面是 64×64 的网格，提取出的网格分辨率不可能超过这个尺度，这就是论文局限里「网格分辨率有限」的直接来源。把分辨率翻倍，三平面张量变成 4 倍，渲染器查询的插值成本上升，显存和算力都吃紧。LRM 选 64 是在质量与成本之间划线，后续工作往上推分辨率时，撞到的正是这条成本曲线。

相机调制的消融值得单独说。去掉相机调制，Transformer 只能从图像内容猜视角，遇到对称物体（比如一个正面和背面看起来相似的椅子）就会把正面特征错误地复制到背面。加上调制后，模型知道「这张图是正面」，于是把特征放到 Txy 的正确区域，背面由三平面的其他区域外推。这个机制的代价是相机参数的编码需要与图像 token 对齐，编码器设计不好会引入额外的噪声。

五 · 数值玩具例子：一次前向与一次反传的手算

为了让上面的公式落地，构造一个极小的例子。假设三平面退化成单通道、分辨率 2×2，只保留 Txy 一个平面，数值为 [[0.2, 0.4],[0.6, 0.8]]。一条射线在平面上打到一个查询点，双线性插值落在四个像素中间，权重各 0.25，得到特征 f=0.25×(0.2+0.4+0.6+0.8)=0.5。MLP 简化为 σ=f，颜色恒为 1。射线上采两个点，间距 δ=0.5，第一点 σ1=0.5，第二点 σ2=0.3。

按体渲染公式，T1=1，第一点不透明度 1−e−0.5×0.5=1−e−0.25≈0.221；T2=e−0.25≈0.779，第二点不透明度 1−e−0.3×0.5=1−e−0.15≈0.139。合成像素 Î=0.221×1+0.779×0.139×1≈0.221+0.108=0.329。若真值像素是 0.5，MSE 损失为 (0.329−0.5)2≈0.029。

反传时，损失对 Î 的梯度是 2×(0.329−0.5)=−0.342。这个梯度要分到两个采样点的 σ 上。对 σ1，它同时影响第一点的不透明度和 T2：前者贡献 −0.342×δ×e−0.25×1≈−0.342×0.5×0.779≈−0.133，后者通过 T2 的指数项贡献一个符号相反的小量。两项部分抵消，说明第一点的梯度被透射率耦合稀释了。对 σ2，梯度只来自第二点的不透明度项，约 −0.342×0.779×0.5×e−0.15≈−0.342×0.779×0.5×0.861≈−0.115。两个点的梯度都指向「增大密度以提亮像素」，因为当前渲染值低于真值。

再往上一层，σ=f，所以 f 的梯度等于 σ 的梯度之和。双线性插值把 f 的梯度按 0.25 分摊到四个平面像素上，每个像素得到约 (−0.133−0.115)×0.25≈−0.062。这个数就是三平面张量上四个位置的梯度。一次 AdamW 更新会把它们往正方向推一点，下次渲染这个像素就更亮。这个玩具例子展示了三件事：梯度沿射线是耦合的、双线性插值把梯度空间平滑、以及单条射线的梯度量级很小——真实训练靠的是每步成千上万条射线把信号累加起来。

把玩具例子放大到真实规模，可以估算单步的计算量级。一张 64×64 的监督图有 4096 条射线，每条射线两阶段采样几十个点，单物体单视角的查询次数在十万量级；batch 里几十个物体、每个多个视角，单步查询次数到千万量级。这正是渲染器成为瓶颈的原因，也是为什么 LRM 的训练成本是数十 GPU 天而不是几小时。玩具例子里的手算和真实训练之间，差的是三个数量级的并行度，但梯度的结构与耦合方式是一样的。

六 · 配方与目标的耦合：为什么这些超参不能单独调

把目标函数、变量、梯度、配方放在一起看，会发现它们不是可以独立调节的旋钮，而是一条互相牵制的链。监督视角的球面覆盖度决定了三平面背面是否有梯度信号；三平面分辨率决定了网格上限，也决定了渲染器的查询成本；模型规模决定了三平面能承载多少高频细节，而细节的监督信号又依赖 LPIPS 项的权重；batch 大小决定了梯度噪声能否被平均掉，而 batch 又受显存约束。改动其中一项，其他项的最优值跟着移动。

一个具体的耦合例子是分辨率与 LPIPS 权重的关系。三平面分辨率提高后，渲染图能表达更锐利的边缘，MSE 项会奖励这种锐利（因为真值边缘也锐利），但 LPIPS 项在早期会惩罚过于锐利的伪影。如果不同步调整 λ，高分辨率配置下模型会收敛到一种「边缘过冲」的状态，轮廓外出现一圈亮边。这不是分辨率本身的错，而是两项损失在新容量下的平衡点移动了。工程判断是：分辨率翻倍时，λ 需要重新扫一遍，不能沿用低分辨率的配置。

另一个耦合是数据规模与模型规模的配套。50 万物体支撑十亿参数，是因为每个物体提供 16–32 个视角的监督，等效的监督信号量是物体数乘以视角数。如果把模型规模再往上推而数据不变，过拟合的表现不是训练损失下降，而是新视角 PSNR 停滞——模型把容量花在记忆训练视角的纹理上，而不是学习可外推的几何。反过来，数据翻倍而模型不变，收益也会饱和，因为十亿参数的三平面表示已经装不下更多细节。LRM 的消融把模型规模和数据规模并列，正是在说这两者要一起动。

最后落在渲染器的采样上。两阶段重要性采样让梯度集中到表面附近，但它引入了一个隐式的超参：粗采样点的数量。粗采样太少，透射率估计不准，重要性采样的密度分布会偏，表面附近的梯度反而变稀；粗采样太多，成本上升而收益递减。这个超参不在论文的主表里，却是复现时最先撞到的工程细节。它和 batch 大小、监督视角数一起，构成了「渲染即监督」路线里那些不写在公式里、但决定训练是否收敛的隐性配方。
