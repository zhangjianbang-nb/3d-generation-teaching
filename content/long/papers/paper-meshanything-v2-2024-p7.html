一 · 对比框架：把“表示”作为第一变量

把 MeshAnything V2 与 MeshGPT、MeshAnything 放在同一张表上时，最容易犯的错误是按“模型大小”或“训练时长”对齐，然后比较输出质量。这三者的真正分水岭在表示层：同一张艺术家网格被序列化成什么形状的 token 流，直接决定了自回归 Transformer 在固定上下文窗口里能“看见”多少面。MeshGPT 走的是逐面片三顶点路线，每个三角面贡献三个顶点 token，顶点在不同面之间被反复编码；MeshAnything 沿用这一思路，序列长度随面数线性膨胀。AMT 则利用相邻面共享一条边的拓扑事实，把“已出现过的两个顶点”折叠进上下文，只吐出新顶点。于是同一张网格的 token 数近似减半，这不是压缩算法的胜利，而是对网格连通性的显式利用。

对比时必须把“表示效率”和“监督信号”分开看。三者的监督目标都是自回归下一个 token 预测，损失函数形式相同，差别在于 token 的语义粒度：MeshGPT 的 token 是顶点坐标的离散化码字，MeshAnything 继承之；AMT 的 token 是“相对于当前边的第三个顶点”，其条件分布依赖前两个顶点，因此解码器必须维护一个“当前边”状态机。这个状态机是隐式的，藏在序列顺序里，而不是显式的图结构输入。工程上这意味着：模型容量相同、上下文长度相同时，AMT 能覆盖的面数上限更高，但每一步的合法性约束更紧——一旦当前边状态错位，后续 token 全部失效。

$$\mathrm{AMT}(\mathcal{M})=\big(t_1,\ldots,t_N\big),\qquad |\mathrm{AMT}(\mathcal{M})|\approx \frac{1}{2}|\mathrm{VTT}(\mathcal{M})|$$

这个约减半的关系不是精确恒等式：它依赖网格的平均顶点度数。规则四边形网格、艺术家手工拓扑的三角化网格，共享边比例高，减半成立；而大量悬挂边、非流形接缝、孤立面片的网格，共享边少，AMT 的收益退化。对比实验里若只报“序列减半”，就会掩盖这一分布依赖。一个具体例子：一个由 1600 个三角面构成的封闭艺术家模型，若平均每个新面只引入一个新顶点，则 AMT 序列约 1600 个 token 量级；同样面数用逐面三顶点编码则接近 4800 个 token。前者能塞进与后者相同的上下文预算，后者则被迫截断或降面数。这就是“800 面到 1600 面”提升的机制来源，而非模型本身变强。

二 · 监督与训练代价：同一目标，不同收敛路径

三个方法共享自回归训练配方：在 Objaverse 艺术家网格上做 token 级交叉熵，逐 token 采样，训练数天量级。差别在于监督信号的“可学性”。逐面三顶点序列中，每个顶点的出现位置与面片顺序强相关，模型必须同时学会“这个顶点属于哪个面”和“这个面接在哪个面后面”，两种信息纠缠在同一 token 流里。AMT 把“接在哪条边后面”编码进顺序本身，模型只需预测“新顶点在哪”，条件更集中，梯度信号更干净。代价是训练数据的序列化必须严格遵循网格的邻接遍历顺序，序列化器一旦产生不连通跳变（例如从一个连通分量跳到另一个），AMT 的“当前边”假设破裂，模型会学到错误的边状态转移。

用伪代码思路描述这一差异：逐面编码的采样循环是“取下一个面 → 吐三个顶点 → 追加”；AMT 的循环是“取当前边 (u,v) → 吐新顶点 w → 压入新边 (v,w) 或 (u,w) → 继续”。后者的状态转移是确定性的，但要求序列化阶段保证每个新面都与前一个面共享一条边。这就是为什么 AMT 的失败模式里“拓扑合法性仍需检查”排在首位：模型可以生成语法合法的 token 序列，却在几何上产生自交、翻转法向或非流形边。训练损失只监督 token 匹配，不监督欧拉示性数或流形性。

  • 监督粒度：逐面三顶点 = 顶点级监督；AMT = 边条件下的顶点级监督，条件更强。
  • 序列化前置条件：AMT 要求邻接遍历，序列化器是训练管线的一部分，不是预处理的可选项。
  • 失败代价：AMT 的状态错位会级联污染后续所有 token；逐面编码的错误更局部，一个面错了下一个面还能独立开始。

具体例子：训练时若把两个不相连的部件按文件顺序拼接，AMT 序列在部件边界处没有共享边，模型被迫学习一个“凭空开始新边”的转移，这个转移在推理时会以任意概率触发，产生悬浮面片。工程复现时必须在序列化阶段做连通分量切分，并对每个分量独立起始，否则训练损失会收敛到一个包含非法转移的分布。

三 · 速度与显存：序列长度是主导项

推理速度的对比不能只看“每秒 token 数”，要看“每张网格所需 token 数 × 每 token 耗时”。Transformer 自回归解码的耗时近似与序列长度平方相关（注意力）加线性相关（前馈），显存则与序列长度和批大小线性相关（KV cache）。AMT 把序列减半，在同等面数下直接把 KV cache 压到约一半，注意力开销压到约四分之一。这是显存对比里最硬的一项：逐面编码在 1600 面时序列接近五千 token，KV cache 随层数线性增长；AMT 在同样面数下约两千多 token，同一张卡能放更大的批或更长的上下文。

$$\text{cost}_{\text{decode}} \approx \alpha L^2 + \beta L,\qquad \text{cache} \propto L \cdot d_{\text{model}} \cdot n_{\text{layer}}$$

但速度对比有一个反直觉的代价：AMT 的每 token 解码需要维护“当前边”状态，解码器还原网格时要按边状态做拓扑缝合，这一步是串行的、带条件分支的，比逐面三顶点直接写三角形要慢。也就是说，token 生成阶段 AMT 更快，网格还原阶段 AMT 更慢，净速度取决于两者的比例。在面数高、序列长时，生成阶段占主导，AMT 净胜；在面数低、序列短时，还原阶段的分支开销可能抵消收益。对比实验若只报端到端墙钟时间而不拆阶段，就会把这一交叉点藏起来。

显存的另一个隐性项是训练时的序列打包。逐面编码可以把多个短网格拼进一个长序列，填充率低；AMT 的序列必须保持邻接连续性，跨网格拼接会破坏边状态，因此打包粒度更粗，填充浪费更高。具体例子：一批 8 个中等复杂度网格，逐面编码可拼成一条长序列、填充少；AMT 需按网格分别起始，短网格的尾部填充比例上升，有效吞吐下降。这是“序列减半”在训练侧被部分抵消的机制，工程上要靠按长度分桶来缓解。

四 · 失败模式逐项对照

失败模式的对比要落到“错误在哪个阶段产生、能否被后处理修复”。MeshGPT 与 MeshAnything 的典型失败是面数上限触顶：序列预算耗尽时生成被截断，网格出现开放边界或缺失部件，这类失败是“预算性”的，可通过提高预算或降面数缓解。AMT 的失败更多是“结构性”的：边状态错位导致后续面片挂错边，产生非流形接缝；或者新顶点预测落在已有面内部，产生自交。前者无法靠增加预算修复，后者无法靠拓扑检查自动缝合，只能丢弃重采样。

五 · 决策表：按任务约束选表示

选型不应按“哪个方法更新”排序，而应按任务的三条硬约束排序：目标面数上限、拓扑合法性要求、可接受的还原后处理成本。下面给出可直接落地的判断顺序。

决策表的第一行对应论文的主结果：同等预算下输出面数从 800 提到 1600，复杂网格成功率提升。这里的“同等预算”指上下文长度与训练 token 预算不变，提升完全来自表示效率。第二行是反例：若任务本身就是低面数、低延迟，AMT 的还原分支开销会让它失去优势，逐面编码反而更稳。第三行是最常见的工程陷阱：艺术家网格常含多个部件、悬挂边，直接套 AMT 会在分量边界产生非法转移，必须先做连通分量切分再序列化。

最后落到一个具体机制上：AMT 的解码器在还原网格时，必须按 token 顺序重建“当前边”栈，每吐一个新顶点就压入两条新边、弹出一条旧边；这个栈的深度与网格的局部连通性相关，栈错一位，后续所有面片挂错位置。工程验收断言应写成“解码后每条边被恰好两个面共享（流形）或标记为边界”，而不是“token 序列长度符合预期”。前者能抓住结构性失败，后者只能抓住预算性失败。这也是为什么 AMT 让“生成 1600 面网格”成为可用基线，却仍把拓扑合法性检查留在管线末端：表示效率的提升不改变自回归模型只监督 token 匹配这一事实。
