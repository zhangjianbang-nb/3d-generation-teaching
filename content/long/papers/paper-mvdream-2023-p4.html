一 · 实验要回答的问题与证据链设计

MVDream 的实验部分不是简单报一个“我们更好”，而是要把“跨视角自注意力让四个视图互相看见”这一机制与最终 3D 质量之间的因果链拆开。这条链有三段：第一段，四视图联合去噪是否真的比逐视角生成更一致；第二段，这种一致性是否能通过 SDS 传递到 3D 几何上；第三段，一致性到底来自哪个组件——是跨视角注意力、是视图数量、还是 2D 数据保留带来的先验。论文的实验设计基本围绕这三段展开，数据集、基线、主结果和消融各自对应一段。

需要强调的是，这条证据链的每一段都有独立的失败模式。第一段如果只比单张图的 FID，就测不出跨视图关系；第二段如果 SDS 优化本身不稳定，一致性提升会被优化噪声淹没；第三段如果消融不控制变量，视图数变化会同时改变显存占用和注意力感受野，导致归因不清。因此读实验时不能只看“显著优于”的定性结论，而要看每个对比是否把变量隔离干净。

论文使用的数据集合是 Objaverse 多视图渲染与 LAION 2D 图像的联合训练。前者提供同一物体在多个相机位姿下的配对视图，是学习跨视角约束的监督来源；后者提供大规模自然图像，用来保持 2D 先验不被多视图数据稀释。这个组合本身就是实验设计的一部分：如果只用 Objaverse，模型会过拟合到渲染数据的分布，文本到图像的泛化会退化；如果只用 LAION，则根本没有跨视角配对信号。联合训练是机制成立的前提，也是后面消融“2D 数据保留”一项的直接对象。

基线选择上，论文对比 Zero-1-to-3 与 DreamFusion。前者代表逐视角生成路线：每次只生成一个视角，视图之间没有信息交换，因此同一物体在不同视角下容易出现纹理、轮廓、部件位置的不一致。后者代表 SDS 路线：用 2D 扩散先验通过分数蒸馏优化 3D 表示，但 2D 先验本身没有多视图约束，容易出现“每个视角单独看都合理、合起来几何矛盾”的 Janus 问题。MVDream 的位置正好在两者之间：它既不是逐视角，也不是纯 2D 先验，而是把多视图一致性直接做进扩散模型，再把这种一致性喂给 SDS 或重建。

这里有一个容易被忽略的实验代价：多视图联合去噪把序列长度从单图扩展到四图，自注意力的计算量随 token 数平方增长。四视图拼接后 token 数约为单图的四倍，注意力矩阵规模约为十六倍，显存与算力开销显著上升。论文用固定四视图换取一致性，这个 trade-off 在实验中体现为视图数消融：增加视图数能提升约束，但代价是显存和训练时间；减少视图数则约束变弱。实验要在“一致性收益”和“系统代价”之间给出可操作的判断，而不是宣称视图越多越好。

二 · 主结果：一致性提升从哪里来

主结果的核心主张是：四视图联合生成在视角一致性上显著优于逐视角生成，并且这种一致性在接入 SDS 后转化为 3D 质量的提升。要理解提升来源，需要把“一致性”拆成可观测的量。逐视角生成的不一致表现为同一物体在不同视角下出现不同的纹理细节、不同的部件形状、甚至不同的整体轮廓；而联合生成时，跨视角自注意力让每个视图的 token 在去噪每一步都能读取其他视图的 token，相当于在潜空间里做了一次隐式的多视图对齐。

公式上，跨视角注意力的偏置项是理解提升的关键：

$$\mathrm{Attn}(Q,K,V)=\mathrm{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}+b_{\mathrm{view}}\right)V$$

其中 \(b_{\mathrm{view}}\) 是视图偏置，它让注意力在跨视图方向上获得额外的结构性引导，而不是完全依赖内容相似度。没有这一项，跨视角注意力仍然存在，但模型需要从数据中自己学出“哪些 token 属于同一空间位置”，学习信号更弱；有了视图偏置，跨视图对齐在训练早期就能获得稳定的梯度方向。主结果中一致性的提升，一部分来自注意力机制本身，另一部分来自这个偏置带来的训练效率。消融实验如果只去掉跨视角注意力而不动偏置，会把两者混在一起，因此读消融时要区分“机制移除”和“结构引导移除”。

第二个提升来源是联合训练中的 2D 数据保留。Objaverse 多视图渲染的分布相对单一：背景干净、光照可控、物体居中。如果只在这种数据上训练多视图扩散，模型会学到“渲染风格的一致性”，而不是“真实世界的一致性”，接 SDS 后生成的 3D 在材质和光照上会显得塑料感。LAION 2D 图像的加入让模型在学跨视角约束的同时保留自然图像的纹理与光照先验，这使得 SDS 阶段的 2D 先验没有被多视图训练破坏。主结果中 3D 质量的提升，不能全部归给跨视角注意力，2D 先验的保留是并行的贡献项。

第三个来源是四视图序列的固定结构。固定四个视角意味着模型在训练和推理时看到的是同一组相机位姿分布，跨视角注意力的位置编码与视图偏置可以针对这四组位姿专门优化。代价是灵活性丧失：视图数固定，无法在推理时按需增加视角来补全背面。这个代价在主结果里表现为“背面仍靠幻想”——四个视角覆盖了物体的正面与侧面，背面没有被观测到，模型只能根据正面信息外推。因此主结果中 3D 质量的提升主要集中在被四视图覆盖的区域，背面的一致性并没有被实验证明。这是一个明确的边界，而不是可以用“显著提升”掩盖的细节。

具体例子可以说明提升的形态：对同一个文本提示，逐视角生成可能在前视图给出一个带把手的杯子，在侧视图把手位置偏移或消失；四视图联合生成时，前视图与侧视图的把手在跨视角注意力下被拉到同一空间位置，SDS 优化时多视图的梯度方向一致，3D 几何的把手不会在优化过程中被不同视角的冲突梯度撕裂。这个例子的关键不是“更好看”，而是“冲突梯度减少”，这才是 SDS 阶段质量提升的机制解释。

三 · 消融：跨视角注意力、视图数、2D 数据

消融实验要回答的是归因问题：一致性提升到底来自哪个组件。论文列出三项消融——跨视角注意力、视图数、2D 数据保留——每一项对应一个可独立移除或改变的变量。读这三项消融时，重点是看每项移除后失败模式是什么，而不是只看指标下降。

跨视角注意力的消融是最核心的一项。移除跨视角注意力后，四个视图仍然在一次去噪中生成，但每个视图的 token 只能在自己的视图内做注意力，视图之间没有信息交换。这时模型退化为“批量逐视角生成”：共享同一个 U-Net 权重和同一个文本编码，但视图之间互不可见。失败模式很直接：同一物体的不同视图在纹理和部件位置上重新出现不一致，说明一致性确实由跨视角注意力承载，而不是由共享权重或共享文本条件隐式带来。这个消融把“一次生成四张图”和“四张图互相看见”区分开了，后者才是 MVDream 的机制核心。

视图数的消融改变的是序列长度。视图数增加，跨视角约束的覆盖范围变大，一致性收益上升，但注意力计算量与显存占用随之上升；视图数减少，约束变弱，一致性下降，但系统代价降低。这里没有免费的午餐：四视图是论文选择的固定配置，它在覆盖范围与计算代价之间取了一个点。消融的意义不是证明“越多越好”，而是说明这个固定配置的收益边界——超过四视图后，新增视角带来的约束可能被注意力开销和训练难度抵消。论文没有给出视图数无限增加仍然有效的结论，固定视图数本身就是局限的一部分。

2D 数据保留的消融移除 LAION 2D 图像，只用 Objaverse 多视图训练。失败模式是 2D 先验退化：模型在跨视角一致性上可能仍然表现不错，因为多视图配对信号还在，但接 SDS 后生成的 3D 在纹理丰富度和光照自然度上变差，文本到图像的泛化能力下降。这个消融说明一致性与 2D 先验是两个正交的贡献：前者来自跨视角注意力与多视图数据，后者来自 LAION。把两者混为一谈会导致错误的工程判断——如果只看一致性指标，会以为 2D 数据不重要；但接 SDS 的实际质量会暴露先验退化。

三项消融合起来给出的归因是：一致性主要由跨视角注意力承载，视图数决定约束覆盖范围与系统代价，2D 数据保留决定 SDS 阶段的质量上限。这三者不是可互相替代的，而是各自对应不同的失败模式。工程上如果要复现或改造 MVDream，应该分别监控这三个变量，而不是只盯一个总指标。

消融项移除/改变后的机制变化典型失败模式
跨视角注意力视图间无 token 交换，退化为批量逐视角纹理与部件位置跨视图不一致
视图数序列长度与注意力覆盖范围变化约束变弱或显存/算力开销上升
2D 数据保留失去自然图像先验，只剩渲染分布SDS 后纹理与光照退化，泛化下降

四 · 从四视图到 3D：SDS 与重建两条路径的证据

主结果中“用于 SDS 后 3D 质量提升”这一条，需要单独看证据形态。MVDream 生成的四视图不是最终 3D，而是作为多视图监督信号接入 SDS 或重建。SDS 路径下，四视图提供的是多视角一致的分数蒸馏目标：优化 3D 表示时，每个采样视角的梯度都来自一个已经跨视图对齐过的扩散模型，因此不同视角的梯度冲突减少。这正是前面例子中“把手不被撕裂”的机制来源。

伪代码思路可以写成：对 3D 表示采样一个相机位姿，渲染出图像，把该图像与文本条件送入多视图扩散模型，取扩散模型对四视图联合分布的分数估计，反传梯度到 3D 参数。关键在于扩散模型的分数不是在单视图上估计的，而是在四视图联合分布上估计的，因此梯度天然带有跨视角一致性约束。代价是每次梯度计算都要过四视图序列，显存与时间开销高于单视图 SDS；并且四视图的相机位姿是固定的，SDS 采样视角如果偏离这四组位姿，一致性约束会减弱。

重建路径下，四视图直接作为前馈重建模型的输入，一次前向得到 3D。这条路径的证据更多体现在后续影响上：InstantMesh、CRM 等前馈重建模型用 MVDream 生成的多视图做训练或推理数据。这里的逻辑是，前馈重建需要高质量、几何一致的多视图输入，而逐视角生成的多视图不一致会直接污染重建监督；MVDream 的四视图联合生成提供了更干净的配对数据。论文本身的主结果是 SDS 路径，但重建路径的证据说明多视图一致性不仅是 SDS 的辅助，也是前馈重建的数据基础。

两条路径的共同失败模式是背面幻想。四视图覆盖的是固定相机位姿，背面没有被观测，SDS 或重建只能根据正面信息外推。在 SDS 路径下，背面区域的梯度缺少多视图约束，优化会退回到单视图先验的幻想；在重建路径下，背面几何由前馈模型根据正面推断，误差不会被四视图纠正。因此“3D 质量提升”这个结论必须限定在被四视图覆盖的区域，背面质量没有被实验证据支持。这是实验部分必须讲清的边界，否则会把一致性提升误读为全视角几何正确。

五 · 数据偏差与指标：一致性成为核心指标之后

数据集本身带来偏差，这一点在实验部分有直接体现。Objaverse 多视图渲染的物体分布偏向干净背景、可控光照、居中构图，训练出的多视图扩散在同类渲染风格上一致性好，但迁移到真实场景或复杂光照时，跨视角注意力学到的对齐可能依赖渲染数据的统计规律，而不是真实的几何对应。LAION 2D 图像的加入缓解了纹理与光照的先验退化，但没有改变多视图配对信号只来自 Objaverse 这一事实。因此一致性的提升是在 Objaverse 分布内测得的，跨分布的泛化没有被实验证明。

指标层面，MVDream 让“多视图一致性”成为 3D 生成的核心指标。在它之前，逐视角生成的评估更多看单图质量或与参考图的相似度，视图之间的关系没有被单独度量；MVDream 的实验把一致性拎出来作为主结果，后续工作开始把多视图一致性作为标准评估项。这个转变的工程意义在于：一个 3D 生成系统如果单图质量高但多视图不一致，在 SDS 或重建阶段会把冲突传给几何，最终 3D 质量受限。一致性不是附加项，而是决定下游 3D 质量的前置条件。

但一致性指标本身也有失败模式。如果只用四视图之间的一致性做评估，模型可以通过“四个视图都模糊但彼此相似”来获得高分，而几何细节丢失。论文的主结果结合了 SDS 后的 3D 质量，部分缓解了这个问题，但一致性指标与 3D 质量之间不是单调关系：过度追求一致性可能牺牲单视图细节。工程上应该把一致性指标与下游 3D 质量、单视图保真度一起监控，而不是把一致性当成唯一目标。

数据偏差与指标局限合起来，给出一个具体的工程判断：MVDream 的实验证据支持“在 Objaverse 类分布内，四视图联合生成的一致性显著优于逐视角生成，并能在 SDS 后提升被覆盖区域的 3D 质量”；但它不支持“任意分布、任意视角、包括背面在内的全局几何正确”。读实验时要把这两个范围分开，前者是机制成立的证据，后者是尚未被证据覆盖的边界。

六 · 实验给出的工程取舍

把主结果、消融和两条下游路径放在一起，实验部分实际给出的是一组工程取舍，而不是一个单一的最优解。第一个取舍是视图数与系统代价：四视图固定配置在一致性收益与注意力开销之间取点，增加视图数能扩大约束覆盖，但 token 数线性增长、注意力矩阵平方增长，显存与训练时间随之上升；减少视图数降低开销但削弱约束。工程上如果要改视图数，必须同时重估显存预算和训练配方，不能只改序列长度。

第二个取舍是一致性与背面覆盖：跨视角注意力把被观测的四视图对齐，但没有观测的背面仍靠幻想。要补背面，需要增加覆盖背面的相机位姿或引入额外的几何先验，代价是视图数增加或模型结构改动。MVDream 的实验没有证明固定四视图能解决背面问题，因此任何声称“全局一致”的工程判断都超出了证据范围。

第三个取舍是 2D 先验与多视图监督的配比：LAION 2D 数据保留是 SDS 阶段质量的上限来源，移除后一致性指标可能不降但下游质量退化。工程上如果为了节省训练成本削减 2D 数据，需要用下游 SDS 或重建质量来验证，而不能只看一致性指标。这三个取舍共同说明，MVDream 的实验证据是分段的：一致性来自跨视角注意力，覆盖范围由视图数决定，下游质量由 2D 先验保底，背面是明确的未覆盖边界。

最后一个机制层面的判断落在注意力偏置上：跨视角注意力的收益不是自动的，\(b_{\mathrm{view}}\) 提供的结构性引导让跨视图对齐在训练早期就有稳定梯度，移除它会削弱机制的可学习性。工程上复现时如果把跨视角注意力当成普通自注意力直接拼接序列，而不加视图偏置，一致性收益会打折扣。这是实验消融能够支持的具体机制判断，也是从证据回到实现的落点。
