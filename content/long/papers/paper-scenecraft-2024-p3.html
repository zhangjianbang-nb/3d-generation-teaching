一 · 目标函数：从“文本→脚本”到可优化的分层损失

SceneCraft 本身不做参数训练，所以“目标函数”不是反向传播意义上的 loss，而是智能体在每一轮迭代中隐式最小化的一个分层目标。把论文的流水线拆开看，它实际在同时压低三类误差：结构误差、执行误差与视觉误差。结构误差衡量场景图与文本描述的语义偏离；执行误差衡量生成的 Blender Python 脚本能否无异常跑完并产出渲染图；视觉误差衡量渲染结果与文本意图之间的差距，由 GPT-V 打分。三者不是简单相加，而是串行依赖：结构错了，脚本再干净也没用；脚本崩了，视觉反馈无从谈起。

形式化地，设文本为 \(t\)，场景图为 \(\mathcal{S}\)，脚本为 \(\mathrm{Script}\)，渲染图为 \(\mathcal{I}\)，则一轮迭代的复合目标可写成：

$$\mathcal{L}(t)=\underbrace{\mathcal{L}_{\text{struct}}(\mathcal{S},t)}_{\text{语义一致性}}+\underbrace{\mathcal{L}_{\text{exec}}(\mathrm{Script})}_{\text{可执行性}}+\underbrace{\mathcal{L}_{\text{vis}}(\mathcal{I},t)}_{\text{视觉一致性}}$$

三个分量的变量含义需要说清楚。\(\mathcal{L}_{\text{struct}}\) 的输入是场景图的节点集合与边集合，节点是资产类别与属性，边是空间关系（左、右、上、下、前、后、相邻、包含）。它衡量的是“文本里提到的物体是否都在图里、关系是否被正确编码”。\(\mathcal{L}_{\text{exec}}\) 的输入是脚本的抽象语法树与运行日志，取值是二值的：脚本抛异常或渲染为空即为失败。\(\mathcal{L}_{\text{vis}}\) 的输入是渲染图与原始文本，由 GPT-V 以自然语言评述的方式给出，本质是一个不可微的黑箱评分器。

关键机制在于：这三个分量不是通过梯度下降联合优化的，而是通过“生成—执行—观察—修正”的闭环逐轮压低。每一轮 LLM 接收上一轮的场景图、脚本、渲染图与 GPT-V 的评述，产出一份修正后的场景图与脚本。这等价于在离散的脚本空间里做一种带视觉先验的采样搜索，而不是连续优化。系统代价随之而来：视觉评分器是黑箱且昂贵，每轮都要真实渲染，渲染是整条流水线的时间瓶颈；同时黑箱评分不可微，无法把视觉误差回传去调整场景图的具体数值，只能靠自然语言评述做粗粒度修正。

具体例子：文本要求“一张桌子，桌上有一盏台灯，桌子左侧有一把椅子”。若第一轮场景图把台灯编码为桌子的子节点但漏掉“左侧”这条边，结构误差不为零；脚本仍能跑通，渲染图里椅子可能被放在桌后，GPT-V 评述“椅子不在桌子左侧”，于是下一轮修正场景图的边并重新生成脚本。这里没有任何梯度，修正信号完全来自视觉评述的离散反馈。

二 · 变量含义：场景图、约束与脚本的三层映射

要理解这套目标怎么落地，必须把三层映射的变量逐个拆开。第一层是场景图 \(\mathcal{S}=(V,E)\)。节点 \(v_i\) 携带资产类别、尺寸、朝向、材质等属性；边 \(e_{ij}\) 携带空间关系类型与强度。第二层是数值约束：每条空间关系边被翻译成对物体变换（平移、旋转、缩放）的不等式或等式约束。第三层是脚本：约束被写成 Blender Python 的赋值语句与函数调用。

约束翻译是这套方法的核心机制。以“A 在 B 左侧”为例，它被转成对 A 的世界坐标 \(x_A\) 与 B 的 \(x_B\) 的不等式，加上一个最小间距以避免重叠：

$$x_A+\frac{w_A}{2}+\delta\;\le\;x_B-\frac{w_B}{2},\qquad \delta>0$$

其中 \(w_A,w_B\) 是两个物体的包围盒宽度，\(\delta\) 是最小间隙。类似地，“在桌上”被转成 \(z_A \ge z_B + h_B/2\) 且水平投影落在桌面范围内。这些约束不是求解器解出来的，而是 LLM 直接把数值写进脚本的坐标赋值里。也就是说，LLM 同时扮演了约束翻译器和数值求解器的角色，它凭对场景的语义理解给出具体坐标，而不是调用一个显式的约束求解程序。

这带来一个明确的失败模式：LLM 给出的坐标可能自相矛盾。当场景含上百个资产时，手工在提示里维持所有不等式的一致性超出模型能力，容易出现物体重叠、比例错误，正是论文指出的直接写脚本的痛点。场景图的作用就是把这种全局一致性从“一次性生成”变成“分层生成”：先在图上确定关系拓扑，再逐条翻译成数值，降低了单次生成的组合复杂度。

具体例子：一个含书桌、书架、三把椅子、两盏灯的房间，场景图先固定“书架靠墙、书桌在书架前方、椅子围绕书桌”的拓扑，再逐条翻译成坐标。若 LLM 在翻译“椅子围绕书桌”时把两把椅子放到同一坐标，渲染图会出现重叠，GPT-V 评述指出后，下一轮修正对应边的数值。变量层面的可解释性就在这里：出错可以定位到某条边、某个坐标，而不是面对一整段脚本无从下手。

三 · 梯度与采样：没有反向传播时的搜索策略

因为没有可微损失，SceneCraft 的“优化”本质是采样加筛选。每一轮迭代相当于从 LLM 的条件分布中采样一份新的场景图与脚本，条件是该轮的文本、上一轮产物与视觉评述。可以把第 \(k\) 轮的采样写成：

$$\mathcal{S}^{(k)},\mathrm{Script}^{(k)}\sim p_{\text{LLM}}\left(\cdot\mid t,\mathcal{S}^{(k-1)},\mathrm{Script}^{(k-1)},\mathcal{F}^{(k-1)}\right)$$

其中 \(\mathcal{F}^{(k-1)}\) 是上一轮 GPT-V 给出的视觉评述。这个分布不是通过训练得到的，而是预训练 LLM 在提示上下文下的条件生成。所谓“梯度”，在这里被替换成评述文本所提供的方向性信号：评述说“椅子偏右”，下一轮采样就倾向于把椅子的 \(x\) 坐标调小。这是一种离散的、语言介导的伪梯度。

采样策略上有两个可调的关键点。其一是迭代轮数：论文说明每个场景迭代数轮，轮数太少视觉误差压不下去，轮数太多则渲染开销线性增长且可能来回震荡。其二是修正的粒度：是整图重采样还是只改被评述点名的子图。整图重采样容易破坏已经正确的部分，局部修正则依赖评述能否准确定位问题节点。library learning 在这一层起到降低采样方差的作用：常用函数（如“沿墙排列”“围绕中心布置”）被沉淀成库，后续场景直接复用，减少了每次从零采样坐标的随机性。

系统代价很直接：每轮采样都要真实调用 Blender 渲染，渲染慢是整条流水线的瓶颈；GPT-V 调用也是外部开销。失败模式是震荡——某一轮把椅子左移，下一轮评述又说“太靠左”，在两三个坐标之间反复，收敛判据只能靠评述不再提出新问题或达到轮数上限。具体例子：一个含上百资产的场景，若每轮都整图重采样，前几轮已摆好的书架可能被重新摆错，导致轮数增加而视觉误差不降；改用局部修正后，评述点名的椅子被单独调整，其余节点保持不变，收敛更稳。

四 · 训练配方与关键超参：无训练系统的“超参”是什么

论文明确无需训练，用预训练 LLM 加 GPT-V。因此传统意义上的学习率、批大小、优化器都不存在。但这不等于没有配方：系统的行为由一组非参数化的“超参”决定，它们共同构成训练配方。可列出如下：

配方项含义对系统的影响
迭代轮数每个场景的修正循环次数轮数不足则视觉误差残留；轮数过多则渲染开销累积并可能震荡
修正粒度整图重采样或局部子图修正整图重采样方差大、易破坏已正确部分；局部修正依赖评述定位精度
评述详细度GPT-V 评述的颗粒度过粗则无法定位节点；过细则提示膨胀、单轮成本上升
库复用阈值何时把一段函数沉淀进库过早沉淀会固化错误模式；过晚则复用收益低
资产库约束可用资产集合资产库缺失的类别无法生成，是硬性失败边界

其中 library learning 的配方最值得展开。它的机制是：当某个函数（例如“把一组物体沿墙等距排列”）在多个场景中被反复生成且被视觉反馈确认有效，就把它抽象成带参数的库函数，后续场景直接调用。这相当于把跨场景的采样经验固化，降低每次生成的搜索空间。代价是库的维护：库函数若参数化不当，会在新场景里被误用，产生系统性错误；而库的沉淀依赖跨场景的重复出现，单场景任务无法受益。

另一个关键配方是评述与场景图修正的耦合方式。若评述只给自然语言而不回填到具体边，LLM 需要自己把“椅子偏右”映射到某条空间关系边，这一步容易出错。配方上更稳的做法是让评述尽量点名物体与关系类型，使修正能落到图的边上。失败模式是评述与图结构脱节：评述说“整体拥挤”，但没有指出哪条边该改，下一轮采样只能盲目调整，收敛变慢。

具体例子：在一个含上百资产的场景里，若库中已有“沿墙排列”函数，LLM 生成书架排布时直接调用，坐标由函数参数决定，采样方差显著小于逐个数值手写；反之若库为空，每个书架坐标都要 LLM 现编，重叠概率上升，需要更多轮视觉修正。

五 · 数值玩具例子：三个物体、两轮修正

用一个极小的例子把上述变量、约束与采样走一遍。文本：“一张桌子，桌上一盏台灯，桌子左侧一把椅子。”设桌子包围盒宽 \(w_T=1.2\)、高 \(h_T=0.75\)，台灯宽 \(w_L=0.2\)、高 \(h_L=0.5\)，椅子宽 \(w_C=0.5\)。最小间隙取 \(\delta=0.1\)。场景图初始化为三个节点加两条边：台灯“在桌上”、椅子“在桌子左侧”。

第一轮，LLM 把约束翻译成坐标。桌子置于原点，桌面高度 \(z_T=0.75\)。“在桌上”给出台灯 \(z_L = z_T + h_L/2 = 0.75+0.25=1.0\)，水平投影落在桌面内，取 \(x_L=0\)。“在桌子左侧”给出不等式 \(x_C + w_C/2 + \delta \le x_T - w_T/2\)，即 \(x_C + 0.25 + 0.1 \le -0.6\)，解得 \(x_C \le -0.95\)。若 LLM 取 \(x_C=-1.0\)，约束满足。但假设这一轮 LLM 把椅子误放在 \(x_C=-0.4\)，则 \(x_C+0.35=-0.05 > -0.6\)，违反不等式，渲染图里椅子与桌子重叠。

第二轮，GPT-V 看渲染图后评述“椅子与桌子重叠，应移到桌子左侧”。LLM 据此修正场景图对应边的数值，重采样得到 \(x_C=-1.0\)，不等式满足。此时结构误差（关系边齐全且数值满足）、执行误差（脚本跑通）、视觉误差（评述不再指出重叠）三者同时压低，迭代停止。这个例子说明：约束不等式是数值层的判据，视觉评述是离散层的判据，两者共同构成没有梯度时的收敛信号。

把例子放大到上百资产，机制不变但代价放大：每轮都要渲染整场景，渲染慢成为瓶颈；约束之间的耦合从两条边变成数百条边，LLM 单次维持全局一致性的难度上升，必须依赖场景图分层与库函数复用把组合复杂度压下来。物理交互弱在这里也暴露出来：上述不等式只保证不重叠与相对位置，不保证椅子真的能被拉到桌边、台灯不会悬空，视觉反馈能看出悬空却无法给出物理正确的修正，这是该目标函数的固有边界。
