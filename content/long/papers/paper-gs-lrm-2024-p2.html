一 · 从多视图像素到高斯参数：一条前向数据流的全貌

GS-LRM 的方法骨架可以用一句话概括：给定 K 张已标定相机位姿的图像，让一个 Transformer 一次性回归出 N 个 3D 高斯的全部属性，再用可微光栅化把这些高斯渲染回图像，用渲染损失端到端地监督网络。整条数据流是严格前馈的，推理阶段没有优化循环、没有三平面、没有网格提取，只有一次前向传播。

形式化地，网络是一个参数化的映射：

$$\mathcal{G}=\{(\mu_i,\Sigma_i,\alpha_i,\mathbf{c}_i)\}_{i=1}^{N}=\mathrm{Transformer}_\theta(I_{1:K},\mathbf{c}_{1:K})$$

这里 $I_{1:K}$ 是输入视图，$\mathbf{c}_{1:K}$ 是对应的相机参数（内参与外参），输出 $\mathcal{G}$ 是 N 个高斯的集合：均值 $\mu_i\in\mathbb{R}^3$ 决定位置，协方差 $\Sigma_i$ 决定各向异性的形状与朝向，不透明度 $\alpha_i$ 决定混合权重，球谐系数 $\mathbf{c}_i$ 决定视角相关的颜色。注意输出是一个无序集合而非张量网格，这一点决定了后面所有模块的设计取舍。

数据流可以拆成四段。第一段是图像与相机的联合 token 化：每张输入图被切成固定大小的 patch，每个 patch 经线性投影变成一个 token；相机信息不是作为额外条件拼接在最后，而是以位置编码的方式注入，使每个图像 token 都知道自己来自哪个视角、在空间中朝哪个方向看。第二段是 Transformer 主干：所有视图的 patch token 拼成一个长序列，经过若干层自注意力，让不同视角的 token 相互“对齐”，完成跨视图的几何一致性推理。第三段是输出头：Transformer 输出的 token 被解码为 N 组高斯参数，这里的关键是 N 与 token 数不必相等，需要一个从序列到集合的重排或查询机制。第四段是可微光栅化：把预测的高斯集合按目标相机投影、排序、混合，得到渲染图，与真值图比较产生损失。

这条链路的一个具体机制值得展开：相机嵌入不是简单的 one-hot 或标量，而是把相机的旋转与平移编码成与 patch token 同维的向量，加到每个 patch token 上。这样做的直接后果是，同一个物体在不同视角下的 patch 在 token 空间里被“拉到”同一个几何参考系附近，自注意力才有机会学到跨视图对应。如果去掉相机嵌入，网络只能靠图像内容猜视角关系，在 2–4 张稀疏视图下几乎必然失败，因为遮挡与视角差异让纯内容匹配欠定。

系统代价出现在第一段与第二段的交界处：K 张图的 patch 数随分辨率平方增长，而自注意力的计算量随序列长度平方增长。输入 4 张图、每张切成数百个 patch，序列长度就到了千级，注意力矩阵的显存占用迅速成为瓶颈。这是 GS-LRM 显存高的第一个来源，也是后面消融实验里“输入视图数”与“Transformer 规模”成为敏感旋钮的原因。一个失败模式是：当把输入视图数从 2 提到 4 时，序列变长带来的显存增长是非线性的，若不同步调整 batch size 或梯度检查点策略，训练会直接 OOM，而不是简单地“变慢一点”。

二 · 输出头：把 Transformer 的 token 变成 N 个高斯的解码契约

整个方法最核心的工程决策在输出头：Transformer 不输出图像、不输出三平面，而是输出高斯参数。这带来一个必须回答的问题——token 与高斯之间是什么对应关系？GS-LRM 的做法是把输出 token 组织成固定数量的“高斯槽位”，每个槽位由一个 token（或一组 token）负责回归一个高斯的全部属性。N 因此是一个超参数，由输出头的设计固定下来，而不是由输入内容动态决定。

每个高斯的参数回归需要处理几个数值上的坑。均值 $\mu_i$ 是三维坐标，通常在一个归一化的立方体空间内回归，避免绝对尺度带来的数值不稳。协方差的参数化不能直接回归 6 个独立元素，因为任意 6 个数不保证半正定；常见做法是回归一个旋转四元数 $q_i$ 与三个尺度 $s_i$，再组合成 $\Sigma_i=R(q_i)\,\mathrm{diag}(s_i^2)\,R(q_i)^\top$，其中 $R(q_i)$ 是由四元数构造的旋转矩阵。这个参数化保证了协方差始终合法，代价是多了一次矩阵构造与四元数归一化。不透明度 $\alpha_i$ 经 sigmoid 压到 $(0,1)$。球谐颜色按阶数展开，若用 3 阶则每个高斯有 16 组 RGB 系数，输出维度随之膨胀。

伪代码层面的输出头大致是：

$$\text{for } i \text{ in } 1..N:\quad \mu_i = \tanh(W_\mu h_i),\ \ q_i = \mathrm{normalize}(W_q h_i),\ \ s_i = \exp(W_s h_i),\ \ \alpha_i = \sigma(W_\alpha h_i),\ \ \mathbf{c}_i = W_c h_i$$

其中 $h_i$ 是第 i 个输出槽位对应的隐状态。这里的每一个激活函数选择都对应一个失败模式：用 $\exp$ 回归尺度可以保证正性，但若初始化不当，早期训练中尺度会指数爆炸，高斯瞬间铺满整个空间，渲染变成一片模糊；用 $\tanh$ 回归均值把位置限制在立方体内，代价是物体若超出归一化范围就会被截断，表现为边缘细节被“压平”。这些不是理论上的可能性，而是前馈高斯模型训练初期最常见的崩溃形态。

输出头的另一个分工问题是：谁负责“在哪里放高斯”？在纯前馈设定下，高斯的空间分布完全由输入视图的内容与相机几何决定，网络必须在一次前向中同时完成“看到什么”和“放在哪”。这与 3DGS 的优化式流程形成鲜明对比：后者从 SfM 点云初始化高斯位置，再用梯度逐步修正；前者没有初始化点云，位置回归是网络从多视图 token 中推断出来的。这个分工差异直接解释了稀疏视图下的几何不稳——当只有 2 张图时，三角化约束不足，网络对深度的推断高度欠定，均值回归容易在视线方向上漂移，表现为新视角下的漂浮物或厚度失真。

具体例子：假设输入是两张相隔较大视角的椅子图像，网络需要为椅背、椅腿、坐面分别放置高斯。对于被两张图同时看到的区域，跨视图注意力能给出较强的对应信号，位置回归相对稳定；但对于只在一张图中出现的椅腿背面，网络只能靠形状先验“猜”出背面几何，此时若球谐颜色也在这部分被高估，新视角渲染就会出现明显的拉伸伪影。这不是渲染器的问题，而是输出头在欠定区域的回归不确定性没有被显式建模。

三 · 可微光栅化：监督信号如何穿过离散排序

预测出高斯集合后，监督来自渲染。GS-LRM 用可微光栅化把高斯投影到目标相机平面：每个 3D 高斯经相机变换与透视投影变成 2D 椭圆，按深度排序后做 alpha 混合。渲染一个像素的颜色是沿视线方向对贡献的高斯做加权和：

训练损失是渲染损失，MSE 加 LPIPS：MSE 约束像素级颜色，LPIPS 约束感知层面的纹理与结构。两者组合的具体机制是，MSE 在早期提供稳定的全局梯度，LPIPS 在后期锐化细节，因为纯 MSE 倾向于产生均值化的模糊输出。这里有一个系统代价：LPIPS 需要对渲染图与真值图各跑一次特征提取网络，显存与计算量都不可忽略，尤其在多视图监督下，每个训练步要对多个目标视角渲染并计算损失，显存占用随监督视角数线性增长。这是 GS-LRM 显存高的第二个来源，与第一节的注意力开销叠加。

一个具体的失败模式是“高斯数限制”与光栅化的相互作用。N 固定意味着网络必须在有限预算内分配高斯：细节多的区域需要更多高斯，平坦区域需要更少。若 N 设得偏小，网络会把高斯“摊大”，用大尺度高斯覆盖多个表面，渲染时表现为表面糊成一片、边缘发软；若 N 设得偏大而监督视角不足，多余的高斯会落在没有监督覆盖的区域，成为新视角下的漂浮伪影。消融实验里“高斯数”成为敏感旋钮，正是因为它在“表达力”与“稀疏视图下的过拟合风险”之间走钢丝。

另一个工程判断在于监督视角的选择。训练时渲染的目标视角若与输入视角重合，网络可以靠“复制输入像素”降低损失，学不到真正的几何；若目标视角与输入视角差异过大，稀疏视图下的欠定区域又会产生无法消除的损失。GS-LRM 在 Objaverse 多视图数据上训练，本质上是用大量物体的多视角覆盖来平均掉单个视角组合的欠定性，但这也意味着推理时若输入视角组合落在训练分布之外，渲染质量会下降——这是前馈模型无法回避的分布偏移代价。

四 · 模块分工与端到端训练的耦合关系

把四个模块的分工画清楚，才能理解为什么这套架构能一次前向出结果。token 化模块负责把像素与相机变成统一序列，它的输出维度决定了注意力的成本；Transformer 主干负责跨视图对齐与几何推断，它是唯一携带“全局场景理解”的模块；输出头负责把隐状态翻译成合法的物理参数，它承担了所有数值稳定性的责任；光栅化负责把参数变成可比较的图像，它提供了唯一的监督信号。四者之间没有中间表示可以单独调试，梯度从渲染损失一路回传到 token 化，任何一个模块的数值问题都会以渲染伪影的形式暴露。

这种端到端耦合带来一个具体的机制后果：输出头的参数化与光栅化的可微性必须匹配。例如若协方差参数化不保证半正定，光栅化在计算 $\Sigma_i^{2D\,-1}$ 时会遇到奇异矩阵，梯度变成 NaN，整个训练崩溃；若球谐阶数与渲染时的视角方向计算不一致，颜色会出现视角相关的闪烁。这些不是可以分开修的 bug，而是必须在架构设计阶段就对齐的契约。

训练规模上，GS-LRM 在 Objaverse 多视图数据上训练数天，推理一次前向出高斯。这个“数天”对应的系统代价是：Transformer 规模、输入视图数、高斯数三个旋钮共同决定了单步显存与吞吐，而三者又相互制约——增大 Transformer 提升几何推断能力，但序列注意力成本上升；增大高斯数提升细节表达，但光栅化与输出头的显存上升；增大输入视图数提升欠定区域的约束，但 token 序列变长。消融实验对这三个旋钮分别扫描，本质上是在刻画这条三维权衡曲面的形状。

与基线相比，模块分工的差异最能说明问题。LRM 输出三平面，渲染需要体渲染，提取网格还有额外损失；GS-LRM 把三平面这一中间表示整个删掉，让输出头直接对接光栅化。InstantMesh 走的是网格路线，渲染需要光栅化三角形而非高斯；3DGS 优化则是逐场景优化，没有前馈。GS-LRM 的分工是“前馈推断几何 + 显式高斯表达 + 实时光栅化”，三者各司其职，换来的是推理一次前向、渲染实时的组合，代价是把所有几何不确定性都压给了那一次前向。

具体例子可以看输入视图数从 2 到 4 的变化：2 视图时，跨视图注意力能对齐的 patch 对更少，输出头在视线方向上的深度回归更欠定，新视角下常见背面几何的拉伸；4 视图时，同一表面被更多视角覆盖，注意力能形成更强的三角化约束，位置回归更稳，但序列长度增加使显存压力上升，训练时若不减小 batch 就得降低分辨率，而分辨率下降又削弱细节监督。这个例子说明模块分工不是静态的，输入配置一变，瓶颈就在注意力成本与几何约束之间转移。

五 · 一次前向的内部时序：从 patch 到像素的每一步

把一次推理展开成时序，可以看清每一步的输入输出与失败点。第一步，K 张图各自切 patch，每个 patch 线性投影成 token，同时相机参数被编码成同维向量加到 token 上；此步的输出是长度为 $K\times P$ 的序列（P 为每图 patch 数），失败点是分辨率过高导致序列过长。第二步，序列进入 Transformer 的若干层，每层做自注意力与前馈，跨视图信息在此交换；失败点是注意力在稀疏视图下学不到稳定对应，表现为 token 特征在不同视角间不一致。第三步，输出槽位从主干取隐状态，回归均值、四元数、尺度、不透明度、球谐系数；失败点是数值参数化不当导致的尺度爆炸或协方差非法。第四步，高斯集合按目标相机投影、排序、混合成图像；失败点是排序跳变与高斯数不足导致的模糊或漂浮。

这条时序里有一个容易被忽略的机制：输出槽位与输入 token 之间没有显式的物理对应，网络必须自己学会“哪个槽位负责哪个表面区域”。在训练早期，槽位分配是混乱的，同一个表面可能被多个槽位重复覆盖，另一些区域没有槽位；随着渲染损失的回传，槽位逐渐分化。这个分化过程依赖跨视图监督的密度——监督视角越多，重复覆盖与空洞越容易被损失惩罚，分化越快。稀疏视图下分化不足，正是几何不稳的微观来源之一。

系统代价在这一步体现为显存峰值出现在光栅化而非 Transformer：多视角监督要求同时对多个目标视角渲染，每个视角的渲染都要保留中间的高斯投影与混合缓冲，显存随监督视角数线性叠加。工程上的缓解手段包括减小监督视角数、降低渲染分辨率、或用梯度检查点换显存，但每一种都直接削弱监督信号的质量，形成“显存—监督—质量”的三角约束。

工程判断落在最后：GS-LRM 的方法总览说明，前馈高斯模型的核心不是某一个模块的巧妙，而是四个模块在数值契约上的严格对齐——相机嵌入对齐 token 空间，参数化对齐光栅化的可微性，高斯数对齐监督密度，输入视图数对齐几何约束。任何一处不对齐，都会以新视角伪影的形式在渲染图上显形，而不是在某个中间张量上报警。这也是为什么后续工作延续“前馈 + 实时渲染”路线时，首先要继承的不是 Transformer 结构，而是这套从像素到高斯再到像素的端到端契约。
