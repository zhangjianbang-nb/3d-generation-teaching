一 · 对比坐标的选取：为什么是 GS-LRM、DreamGaussian、LRM

把 LGM 放进同期方法的坐标系里，第一步不是列分数，而是确定“和谁比才有信息量”。这三个基线分别占据三条不同的技术路线：GS-LRM 是最近邻的前馈高斯路线，同样从 2–4 个视图直接回归高斯，是 LGM 最直接要超越的对象；DreamGaussian 代表“先优化后表示”的路线，用扩散生成单图或少量视图，再通过逐场景优化得到高斯或网格；LRM 则是前馈三平面（triplane）路线的代表，用 Transformer 从单图回归神经辐射场表示。三者分别对应“前馈+高斯”“优化+高斯”“前馈+隐式场”三种组合，因此逐项对比能暴露出表示、监督、速度、显存四个维度上的取舍结构，而不是单纯比谁的分高。

需要强调的是，这三条路线的差异不是实现细节的差异，而是监督信号来源的差异。GS-LRM 与 LRM 的训练监督都来自对真值资产的渲染，模型学到的是“给定视图，直接预测一个可渲染的表示”；DreamGaussian 的监督来自生成模型的先验加上逐场景的渲染损失优化，没有跨场景的泛化训练。LGM 的位置很特殊：它的输入视图由 MVDream 生成，训练监督仍是多视图渲染损失，因此它同时继承了前馈路线的泛化性和扩散路线的内容先验，代价是把生成模型的误差引入了前馈管道。这条“误差传导链”是理解后面所有对比项的钥匙。

对比的公平性需要交代清楚：LGM 与 GS-LRM 都在 Objaverse 与场景数据上训练，输入视图数量在 4 附近（GS-LRM 用 2–4，LGM 固定 4），因此二者在“输入信息量”上大致可比；DreamGaussian 与 LRM 的输入条件不同（前者常从单图出发，后者是单图前馈），把它们放在同一张表里时，比较的是“端到端系统能力”而非同等输入下的表示质量。任何把 LRM 的单图结果与 LGM 的四视图结果直接相减的做法，都会把输入条件差异误读成方法差异。

二 · 表示维度：显式高斯的可扩展性与隐式场的分辨率耦合

表示层面的第一个机制是“表示的容量如何随分辨率增长”。高斯表示由一组带位置、协方差、不透明度、球谐系数的点构成，渲染时通过可微光栅化投影到图像平面。其容量是点数 N 的线性函数，而与输出图像分辨率解耦：渲染分辨率提高只增加光栅化的像素开销，不要求表示本身扩容。相比之下，三平面表示把场景编码为三个二维特征平面加一个解码器，其有效分辨率与平面分辨率、解码器容量强耦合，提高细节需要同时提高平面分辨率和解码器宽度，显存与计算随分辨率呈近似平方增长。

$$\mathcal{G}=\{({\mu}_i,{\Sigma}_i,{\alpha}_i,\mathbf{sh}_i)\}_{i=1}^{N},\qquad \hat{I}=\mathrm{Rasterize}(\mathcal{G},\mathbf{c})$$

这个公式里 N 是唯一显式的容量旋钮。LGM 的高斯头从多视图 Transformer 的特征回归每个高斯的参数，N 由头的输出维度决定；消融里对高斯数的扫描正是围绕这个旋钮展开的。工程含义是：想在保持实时渲染的前提下提高细节，增加 N 比提高隐式场分辨率更“线性”地消耗显存，但也更容易在高频区域出现点密度不足导致的空洞或过度拉长的拉长高斯（needle-like Gaussian），这是显式表示的典型失败模式。

具体例子：一个包含细长栏杆与薄叶片的物体，三平面路线在平面分辨率不足时会把薄结构糊成半透明块；高斯路线在 N 不足时则表现为沿视线方向的拉长椭球，从侧面看出现“拖影”。LGM 的消融显示高斯数对细节有直接影响，但论文同时指出细节仍然有限——这说明容量旋钮存在，但前馈预测的质量（而非点数）才是瓶颈。GS-LRM 同样用高斯，但视图数与分辨率覆盖有限，因此在场景尺度上点数分配不足；LGM 通过场景分块把 N 分摊到多个块，缓解了单块点数被场景体积摊薄的问题，代价是块间一致性需要额外处理。

DreamGaussian 的表示也是高斯，但它通过逐场景优化获得，因此点数可以针对该场景自适应加密，表示效率在单场景上更高；代价是每个场景都要重新优化，没有跨场景的容量先验。LRM 的三平面在单物体上紧凑，但一旦要求高分辨率渲染，隐式解码器的采样成本随分辨率上升，实时性难以维持。表示维度的结论是：高斯赢在“容量与分辨率解耦 + 光栅化实时”，输在“前馈预测的点分布质量”和“薄结构稳定性”；三平面赢在紧凑与平滑，输在分辨率耦合。

三 · 监督维度：渲染损失、扩散先验与误差传导链

监督层面的核心机制是“监督信号从哪里来”。LGM 与 GS-LRM 都用多视图渲染损失：把预测的高斯在若干相机位姿下光栅化，与真值渲染图逐像素比较，梯度经光栅化回传到高斯参数与 Transformer。这条路径的优点是监督稠密、端到端可微；缺点是监督只覆盖训练时采样的视角，模型在未见视角上的外推能力取决于训练视角分布的覆盖度。LGM 用 MVDream 生成 4 个视图作为输入，这 4 个视图本身带有扩散模型的先验，因此输入分布比真实渲染图更“规整”，但也把扩散的几何不一致带进了前馈管道。

误差传导链可以写成复合形式：设扩散模型生成的视图为 I1:4，真值为 I*1:4，则前馈模型的输入误差为 ‖I−I*‖，输出高斯误差经渲染算子放大。由于光栅化对高斯位置与协方差的敏感度在不同视角下不同，扩散在多视图间的不一致（例如同一物体在四个视图中的纹理细节漂移）会被 Transformer 编码为矛盾特征，高斯头在矛盾特征上倾向于输出“平均化”的模糊几何。这就是论文所述“多视图误差传导”的具体机制，也是 LGM 细节有限的直接来源之一。

$$\mathcal{L}=\sum_{c\in\mathcal{C}}\big\|\mathrm{Rasterize}(\mathcal{G},c)-I^{\star}_{c}\big\|^{2},\qquad \mathcal{G}=f_{\theta}(I_{1:4})$$

对比之下，DreamGaussian 的监督是“扩散先验 + 逐场景 SDS/渲染损失”，没有跨场景的输入误差，但每个场景都要承受优化时间；LRM 的监督是单图到三平面的渲染损失，输入误差来自单图生成或真实图，误差传导链更短但输入信息更少。GS-LRM 的监督与 LGM 同构，但输入视图更少、分辨率覆盖更窄，因此在场景尺度上监督覆盖不足。这里的系统代价是明确的：LGM 用“更多视图 + 扩散先验”换取了场景覆盖与高分辨率，代价是把扩散误差纳入训练分布，模型必须学会在含噪输入上输出稳定高斯，这需要更大的数据量与更长的训练（论文给出数天量级）。

具体例子：当 MVDream 生成的四个视图中有一个视图的背面纹理出现幻觉性细节，而其余三个视图没有对应结构时，Transformer 的跨视图注意力会把该细节稀释，高斯头在对应区域输出的点要么缺失要么被拉平；渲染新视角时该区域表现为模糊或空洞。这个失败模式在 GS-LRM 上不出现（输入是真值渲染），但在 LGM 上是结构性的，只能通过提高扩散视图质量或增加视图数缓解，不能通过增加高斯数消除。

四 · 速度与显存：两阶段管道的固定开销与分块扩展

速度维度的机制要拆成两段看：第一阶段是 MVDream 生成 4 视图，属于扩散采样，耗时与采样步数成正比，是固定开销；第二阶段是多视图 Transformer 前馈加高斯头，属于单次前向，耗时与视图数、Token 数、高斯数相关。论文给出的定性结论是推理数秒、渲染实时。这里的“实时”指光栅化渲染阶段，而非端到端生成；把两者混为一谈是常见的误读。端到端延迟 = 扩散采样时间 + 前馈时间 + 光栅化时间，前两项是秒级，第三项是毫秒级。

显存维度的机制是注意力复杂度与高斯参数存储的叠加。多视图 Transformer 在 4 个视图的 Token 上做跨视图注意力，Token 数随视图分辨率平方增长，注意力矩阵随 Token 数平方增长；高斯头输出 N 个高斯的参数，每个高斯含位置、协方差、不透明度与球谐系数，存储随 N 线性增长。场景分块把大场景切成多个块，每块独立前馈，显存峰值由单块决定而非全场景，这是 LGM 相对 GS-LRM 在场景扩展性上的关键机制；代价是块间边界的一致性需要后处理或重叠采样，否则出现接缝处的几何断裂。

五 · 失败模式的逐项归因与决策表

把失败模式逐项归因，可以避免“哪个方法更好”的笼统判断。LGM 的模糊来自扩散视图的跨视图不一致经注意力稀释；薄结构拖影来自前馈点分布在高频区域密度不足；块间接缝来自分块独立前馈缺乏全局约束。GS-LRM 的失败是覆盖不足导致的点数摊薄，属于容量分配问题而非监督问题。DreamGaussian 的失败是逐场景优化没有跨场景先验，单场景可以很精细但换场景即失效，且优化时间使其不适合批量生成。LRM 的失败是高分辨率下隐式解码的采样成本与平面分辨率耦合，薄结构因平面分辨率不足而半透明。

决策表的读法是“按约束选路线”，而不是“按分数选路线”。若约束是端到端秒级且要求实时渲染，LGM 与 GS-LRM 是候选，前者胜在场景覆盖与分辨率，后者胜在显存与无扩散误差；若约束是单场景极致细节且不计优化时间，DreamGaussian 更合适；若约束是单图输入且存储紧凑，LRM 的三平面更合适。把 LGM 放在这张表里的位置是“高分辨率 + 场景扩展 + 实时渲染”的交集，代价列明确写着显存高与误差传导，这两项在部署时必须作为验收断言写进工程清单。

具体例子：批量资产生成管线若要求每个资产在数秒内产出且可实时预览，选 LGM 并把显存预算按单块峰值设定，同时把“块间接缝检测”写成渲染后的自动断言（例如重叠区深度差超过阈值即拒收）；若管线跑在显存紧张的推理卡上且输入本身就是引擎渲染的真值多视图，选 GS-LRM 更稳，因为省掉了扩散阶段也省掉了误差传导项。这两个判断都不依赖分数，只依赖约束与代价的匹配。

最后落在机制上：LGM 的相对优势不是某个单项指标，而是“扩散生成多视图 → 前馈高斯 → 可微分块”这条管道把生成、表示、扩展三个环节解耦，每个环节可以独立替换（换更强的扩散模型、换更大的高斯头、换更细的分块策略），而 GS-LRM 把输入视图与表示绑得更紧、LRM 把分辨率与表示绑得更紧、DreamGaussian 把优化与场景绑得更紧。解耦带来的可替换性正是它在 2024 年成为“多视图 + 高斯”主流配方的原因，也是部署时必须为误差传导与显存峰值付出代价的原因。
