一 · 管线定位：SJC 在资产生产链中的真实坐标

把 SJC 放进真实生产管线，第一件事不是问它“能不能生成一个好看的物体”，而是问它“在哪个环节被调用、被谁调用、产出物以什么契约交给下游”。SJC 的输入是文本提示（或图像提示）加一个 3D 表示的选择（NeRF 或网格），输出是一组 3D 参数 θ——对 NeRF 是密度与颜色场的权重，对网格是顶点位移与纹理参数。它不产出可直接上架的资产，产出的是“可被下游重拓扑、展 UV、烘焙、LOD 化”的中间几何。这一点决定了它在管线中的位置：它坐在资产生成的**概念探索段**，而不是**最终交付段**。

具体机制上，SJC 把渲染器当作一个可微函数 x = R(θ, c)，其中 c 是相机位姿与光照等条件。得分链式法则要求对每个采样相机都执行一次前向渲染加一次反向传播，把 2D 扩散模型在噪声图上的图像得分 ∇_x log p_t(x) 乘上渲染雅可比 ∂x/∂θ。因此管线的上游接口是：提示词编码器（把文本转成扩散模型的条件嵌入）、相机采样器（决定每步看哪些视角）、以及 3D 表示的初始化器（决定 θ 的起点，通常是粗网格或低分辨率 NeRF）。下游接口是：θ 的序列化格式、渲染一致性检查、以及几何后处理。

系统代价在这里非常具体。每个优化步要对 N 个相机做渲染与反传，渲染成本随分辨率线性上升，反传成本随 3D 表示参数量上升；论文给出的量级是“每资产数小时”，这意味着它不是交互式工具，而是批处理作业。失败模式也随之而来：如果相机采样器只覆盖赤道一圈，优化出的 θ 在极区会塌陷成噪声；如果初始化器给的 θ 起点太差，链式法则的方差会放大，退火前期就发散。一个具体例子是：把 SJC 接到一个已有管线，上游提示词来自运营配置表，下游要求输出带 UV 的网格，那么中间必须插入“NeRF 转网格 + UV 展开”的环节，而这个环节的误差会直接吃掉 SJC 在视角一致性上的收益。

$$\nabla_\theta\log p(\theta)\approx\mathbb{E}\!\left[\nabla_x\log p_t(x)\frac{\partial x}{\partial\theta}\right]$$

这条公式在工程上等价于一个契约：3D 得分的质量取决于两件事的乘积——图像得分模型的准确度，和渲染雅可比的准确度。任何一端退化，整条链就退化。所以管线定位的第一条判断是：SJC 不适合放在“无人值守、一次成型”的位置，它适合放在“有人审、可重跑、可回退”的位置。

二 · 上下游接口：把 θ 和相机当作一等公民

SJC 的接口设计核心是把 θ 和相机采样策略显式化，而不是藏在优化循环里。上游接口至少需要三个字段：提示词及其负向提示、3D 表示的类型与分辨率档位、以及相机分布（方位角范围、仰角范围、焦距）。下游接口至少需要：θ 的快照（含优化步数、退火 schedule 的当前阶段）、每个采样相机的渲染图与对应噪声水平 t、以及一个可复现的随机种子链。缺少任何一项，下游的质检就无法判断“这个物体是优化没收敛，还是相机没覆盖到”。

具体机制上，退火 Langevin 采样要求噪声水平 t 从大到小逐级下降，每一级对应一个“粗到细”的尺度。工程上这意味着接口必须暴露当前 t，因为下游若要在中途接管（例如人工挑一个中间快照继续优化），必须知道 t 才能匹配扩散模型的条件。伪代码思路是：外层循环遍历退火档位，内层循环对每个档位执行若干步“采样相机 → 渲染 → 取图像得分 → 乘雅可比 → 加噪声更新 θ”。接口的粒度应定在“档位”而非“单步”，因为单步的 θ 变化方差大，序列化单步快照没有意义。

系统代价在于序列化体积。NeRF 表示的 θ 参数量随分辨率上升，每个档位存一次快照会让存储成本按档位数倍增；若改为只存最终 θ，则失去中途接管能力。失败模式是接口契约漂移：上游改了相机分布但没通知下游质检，下游仍按旧分布做视角一致性断言，结果把好资产判成坏资产。一个具体例子是：上游把仰角范围从 ±30° 扩到 ±60°，SJC 在极区渲染的得分方差显著变大，若下游仍用旧的视角集合做一致性检查，就会漏掉极区塌陷。

接口必填字段缺失后果
上游提示词正向/负向提示、种子不可复现，无法归因
上游相机方位/仰角范围、焦距视角覆盖盲区，极区塌陷
上游表示类型、分辨率档位雅可比维度不匹配
下游 θ快照、步数、退火档位无法中途接管
下游质检渲染图、t、种子链误判收敛与覆盖

三 · 成本结构：算力、时间与方差税

SJC 的成本不是单一数字，而是三块叠加：渲染算力、反向传播算力、以及“方差税”——为了压低方差而多跑的采样步数。渲染算力随相机数 N 和分辨率线性增长；反传算力随 θ 参数量增长，NeRF 的高频编码会让反传显存占用显著上升。论文给出的“每资产数小时”是这三块的总和，且是在冻结 2D 扩散模型的前提下——扩散模型只做前向推理，不参与训练，这省掉了大模型反传的开销，但每次取图像得分仍要跑一次扩散前向。

具体机制上，方差来自链式法则中期望的蒙特卡洛估计：∇_θ log p(θ) 是用有限个相机样本估计的，相机数 N 越少，估计方差越大；退火前期 t 大，图像得分本身噪声大，方差进一步放大。工程上的应对是增大 N 或增大每档位的步数，两者都直接推高成本。伪代码思路：在退火每个档位，先固定 N，若连续若干步 θ 更新的范数低于阈值则提前进入下一档位，否则加步数——这是一种用方差换时间的自适应策略，但阈值设错会导致过早收敛到局部。

失败模式是成本失控的隐蔽路径：雅可比近似。若为了省显存对 ∂x/∂θ 做低秩或分块近似，单步成本下降，但得分方向偏差变大，需要更多步数补偿，总成本未必下降，且质量不可预测。一个具体例子是：把 NeRF 的视角相关颜色分支冻结，只优化密度，单步反传成本降下来，但渲染雅可比对颜色的偏导为零，链式法则丢失了颜色线索，生成的物体几何可辨但外观与提示不符。这就是“省了算力、赔了语义”的典型。

$$\theta\leftarrow\theta+\eta\nabla_\theta\log p(\theta)+\sqrt{2\eta}\,\xi$$

这条更新式里的 η 和 ξ 也是成本变量：η 过大则发散需要重跑，η 过小则步数膨胀。工程判断是：把 η 与退火档位绑定，档位越细 η 越小，并把“重跑次数”计入单资产成本预算，而不是只算一次成功运行的成本。

四 · 合规风险：提示词、训练数据与产出物权属

SJC 本身不训练 2D 扩散模型，它冻结并使用预训练的 Stable Diffusion。这意味着合规风险的第一层不在 SJC 代码里，而在被冻结的扩散模型的许可证与训练数据来源上。工程上必须把“扩散模型版本 + 许可证 + 已知数据来源声明”作为管线的一个配置项固化下来，而不是散落在某个脚本的注释里。第二层风险在提示词：SJC 的输入提示会直接决定产出物的语义，若提示包含受保护的角色、品牌或风格描述，产出物可能落入侵权争议。

具体机制上，SJC 的得分链把图像得分的语义偏置原样传导到 3D 参数：扩散模型对某些概念的先验越强，θ 就越被拉向那个概念。这不是 SJC 能控制的，它是链式法则的必然结果——∇_x log p_t(x) 里已经编码了扩散模型的偏好。因此合规检查点应放在“提示词进入管线之前”和“θ 快照离开管线之后”，而不是试图在优化循环里做内容过滤，因为在循环里过滤会破坏得分估计的连续性，导致优化不稳定。

系统代价是审计成本：每个资产要留存提示词、扩散模型版本、相机分布、种子链，才能在被质疑时复现并解释产出过程。失败模式是“不可归因”：若管线只存最终网格不存 θ 与种子，一旦产出物被指侵权，无法证明它是从哪个提示、哪个模型版本生成的，也就无法做针对性整改。一个具体例子是：运营批量生成一批资产，提示词表被后续编辑覆盖，产出物与提示的对应关系丢失，合规审计时只能整批下架。这不是 SJC 的算法问题，是管线设计问题。

风险层检查对象工程动作
模型许可扩散模型版本与许可证配置项固化，随资产留存
提示语义正向/负向提示入口过滤，留存原文
可归因θ、种子链、相机分布随资产归档，支持复现
产出物权属网格与纹理下游合同明确中间产物地位

五 · 上线检查清单：从可复现到可回退

上线检查清单的第一组是“可复现”：提示词原文、扩散模型版本与许可证、相机分布参数、随机种子链、退火 schedule 的档位表，五项缺一不可。第二组是“可观测”：每个档位结束时记录 θ 更新的范数、渲染图与对应 t、以及相机覆盖的方位/仰角直方图。第三组是“可回退”：至少保留一个中间档位的 θ 快照，且该快照能被独立加载继续优化，否则一旦最终结果不合格只能整段重跑。

具体机制上，可观测性直接对应 SJC 的两个已知弱点：方差大与实现复杂。方差大表现为 θ 更新范数在档位间剧烈波动，若没有逐档位记录就无法区分“正常退火”与“发散”。实现复杂表现为雅可比近似与得分模型选择的耦合，若没有记录近似方式，复现时换一个近似就会得到不同结果。伪代码思路：检查清单在管线里应实现为一个断言集合，每个断言在档位边界执行，失败则阻断进入下一档位并落盘现场。

系统代价是检查本身的开销：逐档位存渲染图会推高存储，逐档位算覆盖直方图会推高 CPU。折中是只对关键档位（最粗与最细）做全量记录，中间档位只记标量。失败模式是断言过严：把“θ 更新范数必须单调下降”写成硬断言，而退火 Langevin 的噪声项天然带来非单调，断言会在正常运行时误触发，导致管线频繁阻断。一个具体例子是：把覆盖直方图的仰角下限设为固定值，而上游相机分布是自适应的，断言与上游契约不一致，每次运行都报错。

  • 可复现五项：提示原文、模型版本与许可、相机分布、种子链、档位表。
  • 可观测三项：更新范数、渲染图与 t、覆盖直方图。
  • 可回退一项：中间档位 θ 快照可独立加载。
  • 断言设计：区分硬约束（契约字段齐全）与软告警（范数波动）。
  • 成本预算：把重跑次数与存储计入单资产成本，而非只算成功一次。

六 · 工程判断：SJC 该被放在“可解释的得分链”位置

论文摘要给出的判断是：SJC 给 SDS 提供了严格的理论解释，但实现复杂、方差大，实际质量与 DreamFusion 接近，价值主要在“把启发式变成可推导的得分链”这一层。这个判断直接决定它在生产管线中的角色：它不是用来替代 DreamFusion 做批量生成的性价比方案，而是用来做**归因与诊断**的方案。当产出物质量不达标时，SJC 的链式法则允许你把误差拆成“图像得分偏差”与“渲染雅可比偏差”两部分，而 SDS 的噪声差更新做不到这种拆分。

具体机制上，这种拆分在工程上表现为两个可独立测量的量：固定 θ 只换相机，观察图像得分的变化，可测相机覆盖的影响；固定相机只换 3D 表示的分辨率，观察雅可比的变化，可测表示容量的影响。这两个测量不需要重跑整条链，只需要在中间档位做受控实验。系统代价是这些受控实验本身要占用算力，但它们比整段重跑的代价低，且能产出可复用的诊断结论。

失败模式是把 SJC 当“质量提升工具”上线：期望它比 DreamFusion 生成更好，结果发现质量接近而成本更高，于是判定项目失败。正确的工程判断是把它当“得分链参考实现”上线，用于校准其他快速方法的偏差来源。一个具体例子是：团队用 SJC 在一个小规模资产集上跑出基准，记录每个档位的得分范数与渲染一致性，然后用这些记录去调 DreamFusion 类方法的超参，把 SJC 的诊断结论迁移过去，而不是把 SJC 放进批量生产队列。

最终落在具体机制上：SJC 的上线价值取决于你是否需要“可推导的得分”这一属性。若管线只需要吞吐量，SJC 的链式法则与退火采样是额外负担；若管线需要可归因的质量诊断与合规复现，那么把 θ、相机、t 与种子链当作一等公民的接口设计，就是它真正该占据的位置。检查清单的意义不在于形式，而在于让每一次失败都能被定位到链上的具体一环，而不是笼统地归为“生成效果不好”。
