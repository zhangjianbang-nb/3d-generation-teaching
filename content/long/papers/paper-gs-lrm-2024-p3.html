一 · 目标函数：像素级监督如何落到高斯参数上

GS-LRM 的训练目标不是直接回归高斯参数的真值——论文并没有为每个高斯提供人工标注的均值、协方差或球谐系数。监督信号只来自渲染结果：把 Transformer 预测出的 N 个高斯交给可微光栅化器，在给定相机位姿下渲染成图像，再与真实的多视图图像比较。因此目标函数是一个复合的渲染损失，由 MSE 与 LPIPS 两项构成。MSE 约束低频色彩与整体亮度的一致性，LPIPS 约束感知层面的纹理与边缘锐度；两者相加，使高斯参数在“数值正确”和“看起来对”之间取得平衡。

形式化地，设输入视图为 \(I_{1:K}\)、对应相机为 \(\mathbf{c}_{1:K}\)，网络输出高斯集合 \(\mathcal{G}=\mathrm{Transformer}_\theta(I_{1:K},\mathbf{c}_{1:K})\)。对每个监督视角 \(v\)（可以是输入视角，也可以是额外采样的新视角），光栅化器 \(\mathrm{Raster}\) 产生渲染图 \(\hat{I}_v=\mathrm{Raster}(\mathcal{G},\mathbf{c}_v)\)，损失为：

$$\mathcal{L}=\sum_{v}\Big(\lambda_{\mathrm{mse}}\,\|\hat{I}_v-I_v\|_2^2+\lambda_{\mathrm{lpips}}\,\mathrm{LPIPS}(\hat{I}_v,I_v)\Big)$$

关键在于梯度路径：损失对 \(\hat{I}_v\) 求导，经光栅化的可微实现回传到每个高斯的 \(\mu_i,\Sigma_i,\alpha_i,\mathbf{c}_i\)，再经解码器与 Transformer 回传到 \(\theta\)。光栅化本身对 \(\mu_i\) 的梯度来自投影位置对像素覆盖的影响，对 \(\Sigma_i\) 的梯度来自二维协方差的投影变换，对 \(\alpha_i\) 的梯度来自 alpha 混合权重，对 \(\mathbf{c}_i\) 的梯度则直接来自球谐求值后的颜色贡献。这条链路上任何一环不可微或数值不稳，训练就会在对应参数上失效。

一个具体的失败模式是协方差的参数化。若直接让网络回归 \(\Sigma_i\) 的六个独立元素，梯度下降很容易产生非正定矩阵，光栅化时二维协方差求逆会爆炸。工程上的做法是让网络输出一个旋转四元数与三个尺度（对数域），再组装 \(\Sigma=R S S^\top R^\top\)，保证正定性并让尺度梯度处于对数空间、数值更平稳。这不是论文摘要里逐字写出的细节，但它是让上述损失可训练的必要机制；缺少它，MSE 项会在训练早期出现 NaN。

另一个机制是损失对输入视角与 novel 视角的分配。若只用输入视角做监督，模型倾向于把高斯“贴”在输入像素上、对未观测区域缺乏约束，新视角渲染会出现空洞或拖影。因此在训练时除输入视角外还渲染若干随机新视角参与损失，迫使高斯在输入视野之外也保持合理几何。代价是每步前向要多跑几次光栅化，显存与算力随监督视角数线性增长——这正是 GS-LRM 显存开销高的来源之一。

二 · 变量含义：N 个高斯、四组参数与相机条件

输出张量的形状决定了整套训练的显存与收敛行为。每个高斯携带四组量：均值 \(\mu_i\in\mathbb{R}^3\)、协方差 \(\Sigma_i\in\mathbb{R}^{3\times3}\)（实际以旋转+尺度参数化，存储为若干标量）、不透明度 \(\alpha_i\in[0,1]\)、球谐颜色 \(\mathbf{c}_i\)（若干阶球谐系数，用于视角相关颜色）。N 是固定的高斯数量上限，由架构超参决定，而不是随场景自适应。消融实验专门考察了输入视图数与高斯数对质量的影响，说明 N 是一个需要权衡的超参：N 太小则细节不足，N 太大则显存与光栅化时间上升。

相机条件 \(\mathbf{c}_{1:K}\) 进入 Transformer 的方式是相机嵌入：每个视图的位姿被编码为嵌入向量，与 patch token 相加或拼接，使注意力能够区分“这个 token 来自哪个视角”。这带来一个变量层面的约束：网络必须学会把不同视角的 token 对应到同一组三维高斯上，即跨视图的特征匹配隐式地发生在注意力里。若相机嵌入的编码方式与位姿分布不匹配（例如训练位姿范围窄、测试位姿超出范围），注意力会错配，高斯均值出现系统性偏移。

下表把变量、维度与梯度来源对齐，便于排查训练异常：

变量含义典型参数化梯度主要来源
\(\mu_i\)高斯中心3 维实数投影位置对像素覆盖的影响
\(\Sigma_i\)三维协方差四元数 + 对数尺度二维协方差投影与混合权重
\(\alpha_i\)不透明度sigmoid 后的标量alpha 混合中的权重
\(\mathbf{c}_i\)视角相关颜色球谐系数球谐求值后的颜色贡献
\(\theta\)Transformer 权重—上述全部经解码器回传

一个系统代价是 N 与球谐阶数的乘积决定了输出头的宽度。若每个高斯带三阶球谐，颜色通道数远大于 3，输出层参数量与激活显存随之膨胀。这也是为什么 GS-LRM 的显存瓶颈不在 Transformer 主干而在输出头与光栅化的中间缓冲：N 个高斯的属性、投影后的二维协方差、每像素的混合列表都要驻留显存。失败模式是 batch size 被迫压到很小，梯度噪声大，训练需要更多步数才能稳定。

三 · 梯度与采样：可微光栅化的反向路径与视角采样策略

可微光栅化的反向传播不是对整张图做一次全局求导，而是按像素的混合顺序逐层累积。前向时每个像素维护一个按深度排序的高斯列表，颜色为 \(\sum_j \alpha_j \prod_{k<j}(1-\alpha_k)\,\mathbf{c}_j\)。反向时，损失对第 j 个高斯颜色的梯度是 \(\partial\mathcal{L}/\partial\mathbf{c}_j\) 乘以该高斯在混合中的有效权重 \(w_j=\alpha_j\prod_{k<j}(1-\alpha_k)\)；对 \(\alpha_j\) 的梯度还要考虑它对后续所有高斯透射率的遮挡效应。这意味着一个被前排高斯遮挡的后排高斯，其梯度会被透射率乘积衰减——稀疏视图下若高斯排序错误，梯度信号会被错误地分配，几何更新方向出错。

伪代码层面的训练循环可以写成：

  • 采样一个 Objaverse 物体及其多视图图像与相机；
  • 取 K 张作为输入视图，经 patch 化与相机嵌入送入 Transformer；
  • 解码出 N 组高斯参数，组装 \(\mu,\Sigma,\alpha,\mathbf{c}\)；
  • 选取若干监督视角（输入视角 + 随机新视角），逐个可微光栅化；
  • 计算 MSE + LPIPS，反传，更新 \(\theta\)。

视角采样是训练配方的核心之一。输入视图数 K 在 2–4 之间变化，消融实验考察了它对质量的影响：K 越小，跨视图约束越少，几何歧义越大；K 越大，Transformer 的 token 序列越长，注意力开销上升。训练时随机化 K 与视角组合，可以让同一个模型在推理时接受不同数量的输入，这是前馈模型相对逐场景优化的一个实际优势。代价是模型必须在欠定与过定之间折中，稀疏视图下的不稳是这一折中的直接后果。

另一个采样层面的机制是监督视角的位姿分布。若监督视角全部落在输入视角附近，模型学到的只是插值；若监督视角分布过远，光栅化时大量高斯落在视野外，梯度稀疏。工程判断是让监督视角覆盖输入视角之间的弧段并适度外扩，使损失既约束插值也约束外推。失败模式是外扩过度导致新视角出现“飞点”——高斯均值被拉向视野外以降低损失，反而破坏输入视角的重建。

四 · 训练配方与关键超参：数天、多视图、固定 N

论文给出的训练事实是：在 Objaverse 多视图数据上训练，使用渲染损失（MSE + LPIPS）与可微光栅化，训练历时数天，推理一次前向即输出高斯。这几个事实对应三个配方决策。第一，数据是多视图的，即每个训练样本自带同一物体的多个视角与相机，监督信号来自这些视角的渲染比对，而不是单图。第二，损失是渲染层面的，没有对高斯参数的直接回归项，因此不存在“真值高斯”的标注成本。第三，训练时长以天计，说明这不是逐场景优化那样的分钟级拟合，而是跨物体的元训练。

关键超参中，N（高斯数）与 K（输入视图数）是消融实验直接考察的两个。N 固定意味着模型必须学会在固定预算内分配高斯：细节区域多放、平坦区域少放，这一分配不是显式规则，而是损失梯度自然形成的——平坦区域的高斯对 MSE 贡献小，梯度弱，逐渐被推向低不透明度或被细节区域的高斯覆盖。失败模式是 N 过小时，模型倾向于用大尺度高斯“糊”住细节，渲染锐度下降；N 过大时，大量高斯不透明度趋近零，光栅化仍要处理它们，算力浪费。

Transformer 规模是第三个被消融的维度。更大的主干带来更强的跨视图匹配能力，但也带来显存与训练时间上升。由于输出头已经是 N 个高斯的宽张量，主干规模的边际收益会被输出头瓶颈稀释：显存先被高斯缓冲吃满，主干再大也放不下更大的 batch。这是一个系统层面的判断——GS-LRM 的扩展瓶颈不在注意力，而在高斯表示本身的显存占用。

学习率与损失权重的具体数值论文摘要未给出，这里不编造。可定性说明的是：MSE 与 LPIPS 的权重比决定了高频细节与低频色彩的相对优先级；LPIPS 权重过高会让训练早期出现纹理噪声，因为随机初始化的高斯颜色尚未收敛，感知损失对噪声敏感。工程上的稳妥做法是先用 MSE 主导、LPIPS 权重较小，待颜色大致收敛后再提高 LPIPS 比重，或全程保持固定比例但配合较长的 warmup。

五 · 数值玩具例子：两个高斯、一个像素的梯度手算

考虑一维简化情形：某像素的深度方向上排列两个高斯，前高斯不透明度 \(\alpha_1=0.5\)、颜色 \(c_1=0.2\)，后高斯 \(\alpha_2=0.5\)、颜色 \(c_2=0.8\)。前向混合给出 \(\hat{I}=0.5\times0.2+(1-0.5)\times0.5\times0.8=0.1+0.2=0.3\)。设真值 \(I=0.7\)，MSE 损失 \(\mathcal{L}=(\hat{I}-I)^2=0.16\)。

对颜色的梯度：\(\partial\mathcal{L}/\partial\hat{I}=2(\hat{I}-I)=-0.8\)。前高斯的有效权重 \(w_1=\alpha_1=0.5\)，故 \(\partial\mathcal{L}/\partial c_1=-0.8\times0.5=-0.4\)；后高斯的有效权重 \(w_2=(1-\alpha_1)\alpha_2=0.25\)，故 \(\partial\mathcal{L}/\partial c_2=-0.8\times0.25=-0.2\)。梯度下降（学习率 \(\eta=0.1\)）后 \(c_1\leftarrow0.2+0.04=0.24\)，\(c_2\leftarrow0.8+0.02=0.82\)。可以看到前排高斯获得的颜色梯度是后排的两倍——遮挡结构直接决定了梯度分配。

对不透明度的梯度更能说明问题。\(\partial\hat{I}/\partial\alpha_1=c_1-(1-\alpha_2)c_2=0.2-0.5\times0.8=-0.2\)，故 \(\partial\mathcal{L}/\partial\alpha_1=(-0.8)\times(-0.2)=0.16\)，梯度为正，意味着降低 \(\alpha_1\) 能减小损失：前高斯颜色偏暗却遮挡了更亮的后高斯，网络应学会让它更透明。而 \(\partial\hat{I}/\partial\alpha_2=(1-\alpha_1)c_2=0.4\)，\(\partial\mathcal{L}/\partial\alpha_2=-0.32\)，梯度为负，增大 \(\alpha_2\) 有利。这个玩具例子展示了训练中真实发生的竞争：同一像素上的高斯通过不透明度互相“让位”，而让位方向由颜色与遮挡关系决定。

把这个例子放大到 N 个数万的高斯与整张图像，梯度信号的稀疏性与排序敏感性就显现出来：每个像素只有少数高斯获得非零梯度，且梯度大小随透射率乘积指数衰减。稀疏视图下若某些区域只被一两个视角覆盖，这些区域的高斯获得的梯度总量远低于中心区域，收敛更慢，表现为新视角下的局部模糊或空洞。这正是“稀疏视图几何不稳”在梯度层面的具体机制，而不是一句定性描述。

六 · 训练与推理的代价对照：一次前向背后的显存账

推理一次前向输出高斯，听起来廉价，但代价被转移到了显存与固定预算上。前向时 Transformer 要为 K 张图的 patch token 做注意力，输出头一次性产生 N 个高斯的全部属性，光栅化器要为每个监督视角建立像素级混合列表。训练时这些缓冲还要保留用于反向传播，显存占用远高于纯推理。系统代价的具体表现是 batch size 受限、监督视角数受限、N 受限，三者互相挤压。

与逐场景 3DGS 优化相比，GS-LRM 把优化时间换成了训练时间：逐场景优化每个物体都要迭代，GS-LRM 一次前向即可，但前提是已经花了数天在 Objaverse 上训练。这个交换的工程判断是：当应用需要大量物体、低延迟生成时，前馈是合算的；当应用只处理少量物体且追求极致质量时，逐场景优化仍有优势。论文把 3DGS 优化列为基线，正是为了对照这一权衡。

失败模式的清单可以落到具体机制上：显存高源于 N 与球谐通道的乘积以及光栅化中间缓冲；稀疏视图不稳源于跨视图约束不足导致的高斯均值歧义与梯度稀疏；高斯数限制源于固定 N 无法自适应场景复杂度。这三者不是独立的，固定 N 加剧了稀疏视图下的分配困难——预算有限时，模型更倾向于把高斯放在多视角一致的区域，放弃只被单视角观测的区域，从而在新视角下暴露空洞。

从训练配方看，GS-LRM 的核心工程判断是把 3DGS 从“逐场景优化变量”变成“前馈输出头”：损失仍是渲染损失，梯度仍经可微光栅化回传，但被优化的对象从单个场景的高斯集合变成了跨场景共享的 Transformer 权重。这一转变让实时渲染与一次前向生成同时成立，代价是显存与稀疏视图稳定性被写进了模型的设计约束里——N 固定、K 有限、监督视角有限，三者共同定义了这套配方能达到的质量上限。
