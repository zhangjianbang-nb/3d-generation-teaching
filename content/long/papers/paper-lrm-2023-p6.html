一 · 复现边界：先钉死“最小可跑”与“论文级”的分界线

复现 LRM 最容易犯的错误，是把“跑通一次前向”和“复现论文结果”混为一谈。这两件事的工程量相差一个数量级，崩溃点也完全不同。工程上应当先把目标切成三层，每层有独立的验收断言，任何一层不达标就不要往上叠。

第一层是结构可跑：DINO ViT 编码单图，相机参数调制，24 层、1024 宽的 Transformer 解码器输出 3 个 64×64×32 三平面，三平面加 MLP 做体渲染，能对任意相机位姿渲染出一张图。这一层不训练，只验证张量形状、坐标约定和渲染管线是否自洽。第二层是单场景过拟合：拿一个 Objaverse 物体、16–32 个视图，冻结 DINO、只训解码器与渲染头，损失必须单调下降到肉眼可见的重建。第三层才是论文级训练：约 50 万物体、数十 GPU 天、AdamW、MSE + LPIPS。绝大多数团队的崩溃发生在第二层，却误以为是第三层的超参问题。

最小可跑版本的关键判断是：不要在第一天就接入 50 万物体的数据管线。先用单物体过拟合把“编码器—解码器—三平面—体渲染—损失”这条链路的符号错误全部挤出来。这条链路上任何一个转置、任何一个归一化区间错位，都会表现为“损失不降”，而损失不降的表象与学习率、batch size 错误完全一样，无法从曲线上区分。因此验收断言必须比损失更细。

$$\text{assert } \mathbf{T}_{xy},\mathbf{T}_{xz},\mathbf{T}_{yz}\in\mathbb{R}^{64\times64\times32},\quad \hat{I}=\mathrm{VolumeRender}(\mathbf{T},\mathbf{c}')\in[0,1]^{H\times W\times3}$$

系统代价在这里体现为显存。三平面本身是 3×64×64×32 个通道值，单精度下约 1.5 MB，可忽略；真正吃显存的是体渲染时沿射线的采样点。若每条射线采 128 点、每批 1024 条射线、每点过一个小 MLP，中间激活是 1024×128×MLP 宽度，这才是 OOM 的来源。失败模式很典型：解码器前向正常，一进渲染就爆显存，于是有人误调解码器宽度，把 1024 改小，结果把论文级配置破坏掉却仍 OOM。正确做法是先把射线数降下来做单物体过拟合，确认渲染正确后再升。

二 · 目录结构与模块切分：让每个失败都能定位到文件

复现项目的目录应当按“数据流阶段”切分，而不是按“模型/工具”切分。按阶段切分的好处是：当损失不降时，你能沿着目录顺序逐段打印中间张量，定位到具体阶段。推荐的结构如下（文字描述，不写代码块）：根目录下分 data/、models/、render/、train/、eval/、configs/、tests/ 七个顶层目录。

  • data/：Objaverse 多视图渲染的索引、相机参数解析、图像归一化。核心是一个 dataset 类，输出 (image, c_in, c_target, target_image) 四元组。相机参数必须统一到同一套坐标系约定，这是复现中最隐蔽的坑。
  • models/encoder.py：DINO ViT 封装，负责把输入图切成 patch、加位置编码、输出 token 序列。冻结或微调由 config 开关控制。
  • models/decoder.py：24 层、1024 宽的 Transformer 解码器，cross-attention 把图像 token 与相机调制 token 融合，输出三平面 token，再 reshape 成 3 个 64×64×32。
  • render/：三平面采样、MLP 查询、体渲染积分。这一层必须与训练时的渲染损失共用同一份代码，否则训练与推理的渲染不一致，表现为“训练 PSNR 高、导出网格烂”。
  • train/：训练循环、损失组合、优化器与调度、梯度裁剪、断点续训。
  • eval/：新视角 PSNR、网格提取与定性渲染。
  • tests/：形状断言、坐标约定断言、渲染可微断言。

模块切分的具体机制在于接口契约。解码器输出的三平面必须约定通道顺序：是 (xy, xz, yz) 还是 (yz, xz, xy)，是通道在前还是空间在前。论文公式写作 (T_xy, T_xz, T_yz) = Transformer(I, c)，但工程实现里三个平面的采样坐标映射必须与体渲染代码严格一致。一个具体例子：若 T_xy 被解释为“固定 z、在 xy 平面采样”，而渲染代码按“固定 y”去索引，则三平面在几何上互相错位，单物体过拟合会收敛到一个模糊团块而非清晰形状——这个失败模式在曲线上看不出来，只能靠可视化三平面切片发现。

系统代价是耦合风险。把渲染代码复制两份（训练一份、评估一份）是常见的省事做法，代价是任何一次坐标修正都要改两处，漏改一处就产生“训练好、评估差”的假象。验收断言应当直接比较两条路径在同一相机、同一三平面下的输出是否逐像素相等。

三 · 数据准备：相机约定、视图采样与归一化区间

LRM 训练用 Objaverse 约 50 万物体、每物体 16–32 个视图的多视图渲染。复现时数据准备有三个必须钉死的量：相机内参、相机外参的坐标系、以及图像与三平面采样坐标的归一化区间。

相机约定的具体机制：渲染监督要求 c_in（输入视角）与 c_target（监督视角）在同一世界坐标系下表达。常见错误是输入图用“物体归一化到单位球、相机看向原点”的约定，而多视图渲染数据用另一套约定，导致解码器学到的相机调制与实际渲染位姿不一致。验收断言：对同一物体，用 c_target 渲染出的图必须与数据集里对应的 target 图在无噪声条件下高度一致（这是数据自洽性检查，不是模型能力检查）。若不一致，先修数据，不要训模型。

视图采样：每物体 16–32 视图，训练时通常随机取一张作输入、另一张作监督，构成“单图进、多视角出”的监督对。这里有一个工程取舍：输入视角与监督视角的角距过小，模型学到的是“复制输入图”；角距过大，监督信号在背面区域几乎无约束。论文的失效条件之一正是背面细节有限，这与监督视角分布直接相关。复现时应在 config 里显式记录角距采样范围，作为可复现性的一部分。

$$\mathcal{L}=\lambda_{\mathrm{MSE}}\|\hat{I}-I\|_2^2+\lambda_{\mathrm{LPIPS}}\,\mathrm{LPIPS}(\hat{I},I)$$

归一化区间是第三个坑。三平面采样要求把世界坐标映射到 [-1,1] 或 [0,1]，图像像素要求 [0,1] 或 [-1,1]，两者必须各自一致且互相匹配。一个具体失败模式：图像归一化到 [-1,1] 而渲染输出被 clamp 到 [0,1]，MSE 损失会系统性偏大且梯度方向错误，表现为损失下降极慢、渲染图整体偏亮。这类错误无法从超参调优中救回来。

系统代价是存储与 IO。50 万物体、每物体 16–32 张渲染图，即使按较低分辨率存，也是 TB 级。复现时若全量预渲染落盘，IO 会成为训练瓶颈；若在线渲染，CPU 渲染开销会拖慢 GPU 利用率。工程判断是：单物体过拟合阶段用在线渲染即可，论文级训练必须预渲染并做分片索引，且索引里要带相机参数，避免训练时重新解析。

四 · 超参配置：哪些必须对齐，哪些可以省

论文给出的关键结构超参是：解码器 24 层、宽度 1024、三平面 64×64×32、DINO ViT 编码器（冻结或微调）、AdamW、MSE + LPIPS、数十 GPU 天。复现时的超参策略应当区分“结构超参”和“优化超参”：结构超参决定模型容量与表示，必须对齐才能谈复现；优化超参决定收敛速度，可以在小规模上先调。

类别项复现处理不对齐的后果
结构解码器 24 层 / 1024 宽必须对齐容量不足，三平面表达力下降，消融无法比较
结构三平面 64×64×32必须对齐分辨率改变直接改变网格精度上限
结构DINO ViT 冻结/微调按 config 显式记录冻结与微调的可训练参数量差异巨大，影响显存与收敛
优化AdamW对齐优化器族换成 SGD 需重调学习率，曲线不可比
优化MSE + LPIPS 权重先固定比例，再小规模扫LPIPS 权重过高会牺牲像素精度换感知质量
规模50 万物体 / 16–32 视图论文级必须接近数据规模是消融项之一，缩水后无法复现质量台阶

具体机制上，学习率与 batch size 的耦合必须显式处理。Transformer 解码器在 1024 宽、24 层下对学习率敏感，单物体过拟合可用较小学习率快速验证可训练性；论文级训练若沿用单物体学习率，会在早期出现损失尖峰。验收断言：训练前若干步的损失应快速下降，若出现 NaN 或尖峰，先查梯度裁剪与 LPIPS 输入的数值范围，再查学习率。

系统代价是“数十 GPU 天”这一量级。复现者若只有少量 GPU，正确判断是放弃论文级全量训练，转而做规模消融的缩小版：固定结构超参，缩小数据规模，验证“数据规模增大时质量单调提升”这一定性结论是否成立。这不能替代论文结果，但能验证核心机制。失败模式是把缩小版训练出的模型拿去和论文数字比，得出“复现失败”的错误结论。

五 · 验收断言清单：从张量形状到几何一致性

验收断言应当分层，每层有明确的通过/失败判据，且尽量不依赖“看损失曲线”这种模糊判断。以下清单按执行顺序排列。

  • 形状断言：解码器输出严格为 3 个 64×64×32；体渲染输出与 target 图同分辨率、同通道数；相机参数张量维度与解码器调制层输入匹配。
  • 坐标断言：取三平面中一个已知切片，沿固定轴采样，验证采样坐标映射与世界坐标的对应关系；用同一相机渲染两次，输出逐像素相等（确定性检查）。
  • 可微断言：对三平面施加小扰动，渲染输出必须变化，且梯度非零；对相机参数施加扰动，输出必须变化（相机调制生效）。
  • 单物体过拟合断言：固定一个物体、固定输入视角，训练若干步后，对训练视角的重建 PSNR 应显著高于未训练基线；渲染图应呈现物体轮廓而非均匀色块。
  • 几何一致性断言：从三平面提取网格后，在训练视角下渲染网格，应与体渲染结果在轮廓上一致；若网格与体渲染明显不符，说明网格提取的等值面阈值或坐标映射有误。
  • 规模趋势断言：在缩小版数据上，增大数据规模应带来新视角 PSNR 的单调提升；若不成立，先查数据管线是否有重复样本或相机参数错配。

具体机制上，“可微断言”是最容易被跳过却最能救命的一条。三平面采样若用了不可微的索引操作（例如整数索引而非双线性插值），梯度会在采样点处断掉，表现为解码器参数几乎不更新、只有渲染头在学。这种失败在损失曲线上看起来像“收敛到平台”，与容量不足难以区分。一个具体例子：三平面采样用最近邻而非双线性，单物体过拟合仍能下降（因为渲染头可以补偿），但新视角泛化极差——这正是复现者常报告的“训练好、测试烂”现象的一个来源。

系统代价是断言本身的运行成本。几何一致性断言需要提取网格，网格提取（如 marching cubes）在 64×64×32 三平面上开销可控，但在高分辨率评估时会成为瓶颈。工程判断是把几何一致性断言放在单物体阶段执行，论文级评估只做抽样检查。

六 · 常见崩溃点与工程判断

把复现中反复出现的崩溃点按“症状—根因—处置”列清楚，比泛泛而谈的调试建议有用。以下每一条都对应前文某个机制。

  • 症状：损失不降，且渲染图均匀。根因通常是相机调制未生效或三平面通道顺序错位。处置：跑坐标断言与可微断言，不要调学习率。
  • 症状：单物体过拟合很好，新视角 PSNR 极低。根因可能是输入/监督视角角距过小，模型学会复制输入；或三平面采样不可微导致泛化差。处置：检查角距采样范围，检查采样是否双线性。
  • 症状：训练正常，导出网格破烂。根因是训练渲染与网格提取的坐标/阈值不一致。处置：跑几何一致性断言，统一渲染与提取代码。
  • 症状：一进体渲染就 OOM。根因是射线采样点与批大小的乘积过大。处置：降射线数做单物体验证，确认渲染正确后再升，不要动解码器宽度。
  • 症状：损失出现 NaN 或尖峰。根因可能是 LPIPS 输入超出预期数值范围，或学习率与 batch size 不匹配。处置：检查图像归一化区间，加梯度裁剪。
  • 症状：缩小版数据上规模趋势不成立。根因可能是数据索引重复或相机参数错配。处置：抽样比对渲染图与数据集 target 图。

工程判断的核心是：LRM 的复现难度不在超参，而在坐标约定与渲染管线的一致性。论文的结构超参（24 层、1024 宽、64×64×32）是公开且明确的，照抄即可；真正消耗时间的是把 DINO 编码、相机调制、三平面采样、体渲染、网格提取这五个环节的坐标与数值区间对齐。一个具体机制上的判断：把“渲染”写成唯一一份可微实现，训练损失、评估渲染、网格提取全部调用它，这样任何坐标修正只改一处，崩溃点从“多处不一致”收敛为“单点错误”。代价是这份渲染实现必须同时满足训练时的批处理效率与评估时的确定性，需要在实现里显式区分训练模式与评估模式，而不是复制两份代码。

最后落在可执行的判断上：若你的团队只有个位数 GPU，正确路径是完成第一层与第二层验收，并在缩小数据上验证规模趋势，而不是追求论文级数字；若你有数十 GPU 天预算，则先花时间把单物体过拟合的坐标断言跑穿，再启动全量训练——因为全量训练一旦因坐标错位而失败，损失的是数十 GPU 天，而不是几小时。
