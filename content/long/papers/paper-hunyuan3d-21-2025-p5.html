一 · 失效条件：PBR 真实感的数据天花板

Hunyuan3D 2.1 的 PBR 分支不是从物理第一性原理推出来的，而是从多视图 PBR 数据里学出来的。这一点决定了它的失效边界：凡是训练分布里缺少的材质组合，模型就只能靠插值硬撑。论文把「数据限制」列为第一条局限，不是客套话——反照率、粗糙度、金属度三个通道的联合分布，在真实采集里极难覆盖全。金属度接近 1 且粗糙度落在中间区间的拉丝金属、带次表面散射的蜡质与皮肤、各向异性高光（CD 光盘、拉丝铝），这些在 Objaverse 与内部 PBR 资产里都是稀疏样本。

机制上，PBR 分支的输出是逐视图的三通道图，监督信号来自

$$\mathcal{L}_{\mathrm{PBR}}=\sum_{v}\left\|\hat{\mathbf{a}}_v-\mathbf{a}_v\right\|^2+\left\|\hat{r}_v-r_v\right\|^2+\left\|\hat{m}_v-m_v\right\|^2$$
这个逐像素 L2 把三个通道当成同等重要的回归目标。问题在于，粗糙度与金属度的感知误差不是均匀的：金属度在 0 与 1 附近的判别边界极窄，一个 0.05 的回归偏差就足以让「金属」变成「塑料」；而反照率的同等偏差几乎看不出来。L2 对各通道一视同仁，等于把判别性最强的通道淹没在数值噪声里。工程上的直接后果是：模型在训练集覆盖的材质上表现稳定，一旦遇到分布外材质，金属度通道先崩，表现为「该亮的地方不亮、该反射的地方发灰」。

失败模式还有一层是光照解耦的不彻底。光照解耦训练的目标是把反照率从观测光照里剥离出来，但解耦是否成功取决于训练数据里光照的多样性。如果内部 PBR 资产的采集光照偏单一（影棚环境为主），模型学到的「解耦」更接近于「减掉一个平均光照」，而不是真正的本征分解。把这样的资产放进引擎、换一个 HDRI 环境光，反照率里残留的光照信息就会以「 baked-in 阴影」的形式暴露：本应是中性灰的墙面在强光下泛出暖色，本应是纯色的表面出现方向性渐变。这不是渲染器的问题，是材质本身不干净。

具体例子：一个带金属拉手和磨砂塑料外壳的产品图。模型能给出完整三通道，但拉手的金属度若被回归到 0.7 而非 0.95，磨砂塑料的粗糙度若被压到 0.4 而非 0.6，进引擎后拉手失去镜面反射的锐利边缘，塑料反而显得像半抛光。验收时肉眼在默认视角下看不出问题，一换环境光就露馅。所以照搬这套方法时，第一条不能照搬的就是「把 L2 当唯一材质监督」——生产环境需要在金属度通道上加判别性损失或分层加权，并对解耦质量做独立验证。

二 · UV 展开：几何与拓扑的硬约束

UV 空间融合是 2.1 纹理阶段的关键一环：多视图预测出的 PBR 图要在 UV 域拼成一张无缝贴图。这一步的失效不来自扩散模型，而来自几何本身。UV 展开要求网格可参数化，而生成形状的拓扑是模型自己吐出来的——薄片、自交、非流形边、高亏格结构，都会让展开算法失败或产生严重拉伸。论文把「UV 失败」列为局限，指向的正是这条链路：形状 DiT 沿用 2.0，形状质量决定了 UV 质量的上限。

机制上，UV 融合可以理解为三步：对每个视图的预测做反投影，把可见像素映射到表面；在 UV 图上按可见性做加权融合；对不可见区域（背面、遮挡区）用扩散补全或邻域插值填补。伪代码思路是：对每个面片采样若干点，查询各视图的可见性与预测值，按视角权重累加，再对 UV 图做泊松式或扩散式补洞。失败模式集中在两处：一是接缝处的通道不一致——两个视图对同一 UV 区域的粗糙度预测差 0.2，融合后接缝出现一条可见的材质跳变；二是补洞区的语义漂移——背面从未被任何视图看到，补全只能靠先验，金属件背面可能被补成非金属。

系统代价是可量化的工程负担：UV 失败不是二值事件，而是连续的质量谱。展开算法在拉伸率超过阈值时报警，但报警之后没有自动回退路径——要么重跑形状生成（耗时且不保证更好），要么人工修 UV。生产管线里这意味着一个资产生成流程不能端到端无人值守，必须插入 UV 质量闸门。具体例子：一个带细长凸起的天线结构，展开时凸起侧面被压成极窄的 UV 条带，纹素密度骤降，PBR 通道在该区域糊成一片，进引擎后高光在该条带上断裂。验收断言应当包括「UV 拉伸率上分位数不超过阈值」与「接缝两侧通道差在容差内」，而不是只看贴图分辨率。

三 · 推理成本：数十秒背后的管线账

论文给出的推理时间是「数十秒」，这个数字在单资产、离线生成的语境下可接受，但它不是端到端管线的全部成本。2.1 的链路包含形状 DiT、多视图 PBR 扩散、UV 融合、可微 PBR 渲染监督（训练期）与贴图烘焙。数十秒通常指 PBR 分支的采样时间，而形状生成、UV 展开、融合补全各自还有开销。工程复现时若按「数十秒一个资产」做容量规划，会在批量场景下低估吞吐。

机制上，多视图扩散的采样步数与视图数是乘性的：视图越多，融合的可见性覆盖越好，但采样次数线性增长；步数越多，通道一致性越好，但时间同样线性增长。这是一个明确的精度—时延权衡，而不是可以靠工程优化抹平的常数。失败模式是批量队列的尾延迟：单资产数十秒在交互式场景里已经超出「点击即得」的阈值，若再叠加 UV 失败重试，长尾资产的端到端时间会显著偏离均值。系统代价体现在调度上——生产环境需要把形状生成与材质生成拆成两级队列，形状先出、材质后补，允许材质阶段异步完成。

具体例子：一个包含数十个资产的场景批量生成，若按均值做容量估算，实际会因为少数 UV 失败资产触发重跑而排队堆积。验收断言应区分「PBR 分支采样时延」与「端到端资产时延」，并对重试率设上限。照搬这套方法时不能照搬的是「数十秒」这个单点数字——它是分支时延，不是管线 SLA。

四 · 被谁继承：与 SF3D、TRELLIS 的坐标系

论文把 SF3D 与 TRELLIS 列为基线，同时把 2.1 与 SF3D 并置为「生产级材质标准」的定义者。这个定位值得拆开看：2.1 的贡献是把 PBR 三通道生成、UV 融合、光照解耦与可微渲染监督串成一条完整链路，并在 2.0 的形状基础上做增量升级；SF3D 走的是另一条路线，把材质生成与快速重建绑定。两者共享的问题是同一个：PBR 真实感受数据限制。这意味着后续工作无论继承哪一条，都会继承同一个数据瓶颈，而不是继承一个已解决的材质先验。

继承关系在工程上表现为可替换的模块边界。2.1 的架构把形状 DiT 与 PBR 分支解耦，形状沿用 2.0，材质分支独立训练。这个切分让「换形状模型、保留材质链路」成为可能，也让「换材质监督、保留形状」成为可能。被替代的部分通常是扩散骨干与融合策略，被继承的部分是「多视图 PBR 预测 + UV 融合 + 可微渲染监督」这套数据流。表格对比能看清各自的位置：

失败模式的继承同样明确：UV 失败是几何链路的通病，推理慢是多视图扩散的通病，数据限制是三通道联合分布的通病。这三条不会因为换一个骨干而消失。具体例子：把 2.1 的材质分支接到另一个形状生成器上，若新形状的拓扑更碎，UV 失败率会上升，而材质分支本身没有能力修复几何——这说明继承的是数据流，不是端到端保证。照搬时不能照搬的是「基线对比的胜负关系」：不同形状来源下，材质链路的相对优势会变，验收必须绑定自己的形状分布。

五 · 工程复现清单与验收断言

复现 2.1 的材质阶段，第一件要定清楚的事是数据配方。PBR 分支依赖多视图 PBR 数据加渲染监督，光照解耦依赖光照多样性。复现清单的第一项是数据审计：反照率、粗糙度、金属度三通道是否逐像素对齐，采集光照是否覆盖足够多的方向与色温，金属度分布是否在 0 与 1 两端有足够样本。第二项是监督配方：逐通道 L2 是基线，但金属度通道需要额外权重或判别性项，否则分布外材质先崩。第三项是 UV 质量闸门：展开拉伸率、接缝通道差、补洞区占比，三项都要在融合后检查，而不是等渲染暴露。

验收断言应当是可判定的，而不是「看起来对」。建议的断言集合包括：三通道完整性（无缺失通道、无全零区域）；金属度在已知金属区域的召回（用少量标注样本做点检）；换环境光后的重光照一致性（同一资产在两个 HDRI 下，反照率不应随光照显著变化，变化量超过容差即判解耦不彻底）；UV 拉伸率上分位数阈值；接缝两侧通道差容差；端到端时延与重试率上限。每一条都对应一个具体机制：完整性对应扩散覆盖，金属度召回对应通道判别性，重光照一致性对应光照解耦，UV 指标对应几何参数化，时延对应采样乘性成本。

系统代价要提前算清：可微 PBR 渲染监督在训练期引入渲染开销，渲染分辨率与视图数直接决定训练吞吐；UV 融合的补全步骤在推理期引入额外时延；光照解耦若数据不足，需要人工构造光照增强数据，这是数据工程成本而非模型成本。具体例子：一个验收流程里，若只检查贴图分辨率与通道数量，会放过「金属度系统性偏低」这类错误——通道齐全但语义错。必须加入点检样本的通道值比对。照搬这套方法时最不能照搬的是「以通道齐全作为完成标准」：生产级材质的验收标准是物理正确性，不是文件完整性。

最后落在工程判断上：2.1 把 3D 生成从「有颜色」推进到「有 PBR」，这条链路的可复现部分是多视图预测、UV 融合与可微渲染监督的数据流，不可照搬的部分是它对数据分布的隐含假设——三通道联合分布覆盖、光照多样性、几何可参数化。复现时把这三条假设写成显式的准入检查，比复现任何一个模块都更能决定成败。UV 融合的接缝容差与金属度通道的判别权重，是两个最容易被忽略、也最先在换光照时暴露的参数。
