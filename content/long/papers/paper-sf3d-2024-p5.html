一 · 失效条件：UV 展开在什么几何上必然崩

SF3D 的快速 UV 展开不是通用的参数化算法，而是一个与网格解码器联合训练的预测头。它的输入是解码出的网格顶点与面片索引，输出是一张把每个面片映射到 UV 平面的图集。这个头在训练分布内表现稳定，但它的失败模式有明确的几何触发条件，工程上必须提前识别。

具体机制上，UV 展开本质是给每个面片分配一个二维坐标块，同时保证块与块之间不重叠、接缝处顶点位置一致。当网格出现高亏格（比如带孔的零件、多次穿插的拓扑）或大量非流形边时，展开器需要在图集里切出足够多的接缝才能把曲面摊平。接缝数量一多，图集利用率急剧下降，纹理分辨率被摊薄。更严重的是，如果解码器输出的面片法线朝向混乱，展开器无法判断哪些面片属于同一张连续曲面，会把相邻面片分到图集的不同角落，接缝处纹理出现明显断裂。

用公式描述图集利用率与接缝的关系：设网格有 $F$ 个面片，图集边长为 $S$，每个面片平均占据的 UV 面积为 $a$，则有效纹理密度为

$$\rho = \frac{F \cdot a}{S^2}$$

当接缝导致面片被切碎、$a$ 随切碎程度下降时，$\rho$ 随之下降。工程上可接受的 $\rho$ 下限取决于目标纹理分辨率；低于该下限时，UV 空间纹理生成会退化为模糊的低频色块，法线贴图也失去细节。

系统代价体现在两个层面。其一是重试成本：展开失败不会抛异常，而是静默产出一张接缝错乱的图集，下游纹理生成照常运行，直到渲染阶段才暴露为可见的纹理拉伸。其二是管线阻塞：如果资产要进引擎做烘焙，错乱图集会导致法线烘焙失败，整个资产需要回退到顶点色路径，而 SF3D 的顶点色路径并未针对引擎做优化。一个具体例子是带镂空结构的机械支架：解码器倾向于把镂空边缘的面片预测成独立薄片，展开器把这些薄片分散到图集边缘，接缝处出现像素级错位，重光照时高光在接缝两侧跳变。

工程判断：不要把 SF3D 的 UV 输出当作无条件可用。对高亏格、薄壁、非流形输入，应在解码后加一道拓扑检查，统计亏格数与边界边数量，超过阈值就标记为「UV 高风险」，走人工复核或回退路径。

二 · 材质与光照解耦的边界：delighting 去不掉什么

SF3D 的 delighting 步骤目标是去除输入图里的低频光照，把反照率与光照分离，从而让输出的 PBR 材质在换光照后仍然成立。这个步骤的有效范围有明确边界：它处理的是低频、全局性的光照分量，对高频、局部性的光照耦合无能为力。

机制上，delighting 依赖一个假设：输入图的光照可以分解为低频环境项与高频细节项，前者可以被估计并除以，后者保留在反照率里。实现上通常用一个低通滤波后的光照图做逐像素除法，或用一个小网络预测光照乘子。问题在于，当输入图存在强方向光造成的硬阴影、镜面高光、或次表面散射造成的颜色渗透时，这些分量在频域上与材质本身的颜色分布重叠，除法会把材质颜色一并削掉。

用公式表达这个耦合：设观测像素为 $I = A \cdot L + S$，其中 $A$ 是反照率，$L$ 是低频光照，$S$ 是高频镜面与阴影项。delighting 估计 $\hat{L}$ 后计算 $\hat{A} = I / \hat{L}$，得到

$$\hat{A} = A + \frac{S}{\hat{L}}$$

只要 $S$ 不为零，$\hat{A}$ 就混入了高频光照残差。对于金属材质，镜面高光 $S$ 幅值大，残差会表现为反照率上的亮斑，换光照后这些亮斑不会消失，反而被新的光照再次照亮，形成「双重高光」。

系统代价是材质真实感受数据限制。训练数据里金属、玻璃、织物的样本比例决定了 delighting 网络对这些材质的去耦能力；样本少的材质类别，去耦残差更大。一个具体例子是抛光金属件：输入图里有一条明亮的条状高光，delighting 把它部分保留在反照率里，输出的 PBR 金属度贴图在高光位置偏高，换到柔和环境光下渲染时，该位置出现不自然的亮带。另一个例子是皮肤类资产，次表面散射造成的红润在 delighting 后被当作反照率保留，换冷色光照时肤色偏暖，与光照不匹配。

工程判断：delighting 的输出应附带一个置信度或残差图，标记高频光照残留严重的区域。对金属度高于某阈值的像素，不应直接信任去耦后的反照率，而应回退到基于材质先验的补全。

三 · 几何细节的上限：显式网格解码器的分辨率墙

SF3D 选择显式训练网格生成，换来的是速度与 UV 的可得性，代价是几何细节受解码器输出分辨率约束。这个约束不是训练不足，而是表示能力的天花板。

机制上，显式网格解码器通常在一个固定分辨率的体素格或四面体格上预测占据与顶点位移，再提取等值面。设格点分辨率为 $N$，则能表达的最小特征尺度约为 $1/N$ 的体素边长。小于该尺度的细节，比如细线、薄片边缘、微小凹槽，在格点采样时被平均掉，等值面提取后表现为圆角或缺失。用公式描述可分辨的最小曲率半径 $r_{\min}$ 与分辨率的关系：

$$r_{\min} \gtrsim \frac{1}{N}$$

提高 $N$ 会线性增加显存与计算量，而 0.5 秒的推理预算限制了 $N$ 的上限。这就是分辨率墙：速度目标与细节目标在显式表示下直接冲突。

系统代价体现在资产验收环节。引擎管线对硬表面资产的边缘锐度有要求，圆角化的边缘在法线贴图里无法完全补偿，因为法线贴图只能改变着色，不能改变轮廓。一个具体例子是带细刻线的装饰件：输入图里刻线清晰，SF3D 输出的网格把刻线抹平，UV 空间法线贴图试图用高频噪声伪造刻线，但轮廓仍是平的，侧光下刻线消失。另一个例子是薄壁壳体：壁厚接近体素边长时，等值面提取会把内外壁合并，产生破洞或厚度不均。

工程判断：把 SF3D 定位为「中景资产」生成器，适合镜头距离较远、细节要求不高的场景。对需要特写的硬表面资产，应在 SF3D 输出后接一道细节增强步骤，比如基于法线贴图的高频雕刻或位移贴图，而不是指望解码器直接给出锐利几何。

四 · 被谁继承、被谁替代：2024–2025 的资产标准格局

SF3D 与 Hunyuan3D 2.1 一起定义了 2024–2025 年资产生成的标准：快速、带 UV、带 PBR、可重光照。这个标准的确立意味着后续工作不再需要从零论证「为什么要 UV 和 PBR」，而是直接在它们的输出格式上做增量。继承关系体现在三个方向。

第一是 UV 与材质管线的继承。后续资产生成工作普遍采用「先出网格、再展开 UV、再在 UV 空间生成纹理」的三段式，SF3D 把这三段压缩进单次推理的做法被当作基线对照。第二是 delighting 的继承。SF3D 让 delighting 从可选步骤变成管线必备步骤，后续工作在数据准备阶段就内置 delighting 增强，而不是在推理后补救。第三是速度基线的继承。0.5 秒成为单图资产生成的参照点，新方法要么在同等速度下提升质量，要么在更高质量下论证速度代价的合理性。

替代关系则出现在两个方向。其一是更高保真的隐式或混合表示：当任务要求几何细节超过显式网格分辨率墙时，基于神经隐式表面或高斯泼溅的管线在质量上替代 SF3D，代价是推理时间与 UV 可得性。其二是端到端引擎格式生成：直接把资产生成为引擎可读的网格加材质包，跳过中间表示，这类工作在管线集成度上替代 SF3D 的三段式。

用表格对比继承与替代的边界：

方向关系触发条件工程代价
UV + PBR 三段式继承需要标准 UV 进引擎UV 失败需回退
delighting 前置继承输入图光照未知高频残差需标记
0.5 秒基线继承批量资产生成质量上限受速度约束
隐式/高斯表示替代细节要求超分辨率墙推理变慢、UV 不可得
端到端引擎格式替代管线集成度优先灵活性下降

工程判断：选型时先问资产的下游用途。进引擎做重光照、需要标准 UV 的，SF3D 类方法是默认起点；需要特写细节的，直接跳到替代方向，不要试图在 SF3D 上叠加重度后处理来突破分辨率墙。

五 · 工程复现清单：从论文到可跑管线的断言

复现 SF3D 不是复现一个模型文件，而是复现一条带验收断言的管线。清单按数据流顺序列出，每条都对应一个可观测的失败模式。

  • 输入预处理断言：输入图需去背景、居中、归一化到训练分布。失败模式是背景被当作几何，解码出多余薄片。验收：输出网格的包围盒与输入主体比例偏差在阈值内。
  • 网格解码断言：统计输出面片数、亏格数、边界边数。失败模式是高亏格导致 UV 高风险。验收：亏格数与边界边数低于阈值，否则标记复核。
  • UV 展开断言：检查图集利用率 $\rho$ 与接缝处顶点一致性。失败模式是接缝错位、纹理拉伸。验收：$\rho$ 高于下限，接缝两侧 UV 坐标差为零。
  • UV 纹理生成断言：检查纹理在 UV 空间的连续性，对比渲染结果与输入图的低频颜色一致性。失败模式是纹理断裂、色块模糊。验收：接缝处颜色梯度连续。
  • 材质与法线断言：检查金属度、粗糙度贴图的分布是否落在训练数据覆盖范围内，标记高频光照残留区域。失败模式是双重高光、肤色偏暖。验收：金属度高于阈值的像素附带置信度标记。
  • delighting 断言：用合成光照重渲染，对比重光照前后反照率的一致性。失败模式是换光照后材质崩坏。验收：重光照后反照率的低频分量变化在阈值内。
  • 几何细节断言：测量输出网格与输入轮廓的边缘锐度偏差。失败模式是圆角化、薄壁合并。验收：锐度偏差低于阈值，否则标记为「中景资产」。

每条断言都对应一个具体的系统代价：断言不通过时，管线要么回退到顶点色路径，要么进入人工复核队列。回退路径的存在是复现清单的一部分，因为 SF3D 的失败是静默的，没有断言就没有可观测的失败信号。

伪代码思路描述断言编排：对每个资产，依次执行预处理、解码、展开、纹理、材质、delighting、细节检查，任一步断言失败则记录失败码并短路后续步骤。失败码与资产 ID 一起写入日志，供批量统计失败分布。这个编排的关键是把「静默失败」转成「显式失败码」，否则批量生成时无法定位问题资产。

六 · 哪里不能照搬：三条硬边界

第一条硬边界是 UV 展开的通用性。SF3D 的展开头与它的网格解码器联合训练，换一个网格来源（比如外部扫描网格或另一个生成器的输出）时，展开头的输入分布偏移，接缝质量下降。不能把 SF3D 的 UV 模块当作独立工具复用到任意网格上，除非重新训练或加一道通用参数化兜底。

第二条硬边界是材质真实感的数据依赖。delighting 与材质预测的能力上限由训练数据的材质覆盖决定。训练数据里没有的材质类别，比如特定织物纹理或特殊涂层，输出的 PBR 参数是外推结果，不能当作可信材质使用。照搬 SF3D 的材质头到新品类资产上，必须先做材质覆盖度评估，缺失类别走人工材质库匹配。

第三条硬边界是速度与细节的取舍。0.5 秒的推理预算绑定了显式网格的分辨率上限，任何试图在 SF3D 框架内突破分辨率墙的改动都会破坏速度基线。不能既要求 0.5 秒又要求特写级几何细节，这两个目标在显式表示下互斥。工程上应把 SF3D 定位在中景批量生成，特写资产走替代管线。

这三条边界的共同点是：它们不是调参能解决的，而是表示能力与数据覆盖的结构性约束。复现时把边界写进管线文档，比在失败后逐个排查更省成本。具体机制上，边界检查应前置到资产分类阶段：按亏格、材质类别、镜头距离给资产打标签，标签决定走 SF3D 还是替代路径，而不是等生成失败后再补救。
