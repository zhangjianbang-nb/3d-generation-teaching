一 · 对比口径：把「表示—监督—速度—显存—失败」拆成可观测的轴

跨方法对比最容易滑向「谁更好」的笼统结论。工程上真正有用的做法是把每个方法拆成五条可观测的轴，并明确每条轴的测量对象。第一条是表示：模型最终输出的是什么对象——点云、隐式函数（MLP 权重或 SDF 场）、显式网格、还是可微渲染场。表示决定了输出能否带纹理、能否提取拓扑、能否直接进入下游渲染管线。第二条是监督：训练信号来自哪里——多视图渲染的 2D 监督、3D 资产的直接拟合、还是预训练 2D 扩散模型的分数蒸馏。监督方式决定了训练管线的复杂度与数据需求。第三条是速度：从条件输入到可交付资产的端到端时延，包含采样步数与解码/提取开销。第四条是显存：训练与推理的峰值占用，尤其要区分「潜空间扩散的显存」与「解码器渲染/提取网格时的显存」。第五条是失败模式：方法在什么输入下会系统性地产出不可用结果。

这五条轴不是并列的，它们之间存在耦合。表示的选择会反过来约束监督方式：若输出是隐式 MLP 权重，编码器就必须把 3D 资产压缩成一组权重，这要求多视图渲染提供稳定的 2D 监督信号；若输出是显式网格，监督就退化为对顶点序列的自回归建模，序列长度成为硬约束。监督方式又决定速度：分数蒸馏（SDS）需要在每次采样迭代中做可微渲染并反传梯度到 2D 扩散模型，单资产优化耗时以小时计；而前馈潜空间扩散只需一次前向去噪加一次解码。显存则被解码路径主导：隐式解码要在网格提取阶段对空间格点做密集查询，显存随提取分辨率增长；点云解码只需一次前向输出固定点数，显存平坦。失败模式是上述选择的必然副产品，而不是偶发 bug。

本部分选取三个对照对象：Point-E（同期前馈点云生成）、DreamFusion（同期 SDS 优化路线）、以及后继的结构化潜变量工作 TRELLIS（其 SLAT 表示直接继承了 Shap-E 的「潜空间 + 隐式解码」思路）。选择这三个对象的理由是它们分别占据了「前馈点云」「优化式可微渲染」「结构化潜变量」三个位置，与 Shap-E 的「前馈隐式函数」形成完整的坐标覆盖。对比只使用给定事实中的定性结论与已有数字（Shap-E 速度约 1 分钟、训练数天），不引入外部实验数据。

二 · 表示与监督：三种输出对象的本质差异

Point-E 的输出是点云。点云是 3D 坐标的集合，没有面片连接关系，因此没有拓扑，也没有纹理坐标。它的监督是直接的：编码器把 3D 资产映射为点集，扩散在点集空间去噪。这条路径的优点是解码极轻——一次前向输出固定数量的点，无需网格提取；缺点是下游无法直接渲染出带纹理的表面，必须先做表面重建，而重建本身会引入新的失败模式。Shap-E 的输出是隐式函数，具体形式是 MLP 权重：编码器用多视图渲染加 Transformer 预测一组 MLP 权重，这组权重定义了一个隐式场，解码时通过在该场上做等值面提取得到网格。因为隐式场可以携带颜色/纹理通道，Shap-E 的输出天然带纹理，且提取出的网格具有拓扑。代价是解码变重：网格提取要在空间格点上密集查询 MLP，显存与时延都随提取分辨率上升。

DreamFusion 走的是另一条路：不训练前馈生成器，而是对每个条件输入做个体优化，用预训练 2D 扩散模型的分数蒸馏作为监督，通过可微渲染把 2D 梯度回传到 3D 表示（如 NeRF）。它的表示是可微渲染场，监督是 SDS 损失。这条路径的几何细节通常更锐利，因为 2D 扩散先验在像素级提供了强约束；但每个资产都要独立优化，速度以小时计，且没有「一次训练、多次前向」的摊销。TRELLIS 的 SLAT 则把 Shap-E 的潜变量思路结构化：潜变量不再是扁平的 MLP 权重，而是带空间结构的稀疏潜变量网格，扩散在该结构上运行，解码仍走隐式/显式提取。这保留了前馈速度，同时缓解了扁平权重对几何细节的表达瓶颈。

用一个具体机制说明监督差异的后果。Shap-E 的编码器训练阶段，多视图渲染提供 2D 监督：对同一 3D 资产渲染若干视角，Transformer 从这些视图预测 MLP 权重，损失比对渲染结果与真实视图。这意味着编码器的监督信号是「渲染一致性」，而不是「几何精度」。当资产的几何细节在渲染视角下不可分辨时（例如薄壁、细小镂空），编码器没有动力把这些细节编码进权重，于是解码出的网格在这些区域系统性丢失细节。这正是给定事实中「几何细节弱」的机制来源，而不是采样噪声的偶发结果。相比之下，SDS 的监督直接作用在渲染像素上，且优化是针对单个资产的，因此能把像素级梯度压进几何，细节更强——但代价是每个资产都要重新优化。

$$\mathcal{L}_{\text{enc}}=\sum_{v}\big\|\,\mathrm{Render}\big(\mathrm{MLP}_{\mathbf{z}}(\cdot)\big)_{v}-\mathbf{I}_{v}\big\|^{2},\qquad \mathbf{z}=E_{\phi}(\{\mathbf{I}_{v}\})$$

上式刻画了编码器阶段的核心：潜变量 $\mathbf{z}$ 由多视图 $\{\mathbf{I}_{v}\}$ 经编码器 $E_{\phi}$ 得到，解码后的隐式场在相同视角下渲染，与输入视图比对。监督只约束「在这些视角下看起来对」，不约束视角之外的几何。这就是为什么 Shap-E 在训练分布内的视角一致性尚可，但新视角下的几何细节会退化。工程判断：若下游需要高保真几何，不能指望这条监督路径自动补足；要么增加视角覆盖，要么换用带几何先验的监督。

三 · 速度与显存：前馈摊销 vs 个体优化

速度轴上，Shap-E 与 Point-E 同属前馈摊销路线：训练一次（数天），推理时采样潜变量并解码，端到端约 1 分钟。这 1 分钟里，潜空间扩散的采样步数占大头，解码与网格提取占其余部分。Point-E 的解码更轻，因为它只输出点集，无需等值面提取；但点云到可用网格之间还隔着表面重建，若把重建计入端到端时延，Point-E 的实际交付时间并不占优。DreamFusion 则完全不同：没有摊销，每个条件输入都要跑完整的 SDS 优化循环，每次迭代包含可微渲染与 2D 扩散模型的反传，时延以小时计。这不是常数因子差异，而是算法结构差异——前馈方法把成本前置到训练，优化方法把成本摊到每个样本。

显存轴上，要区分两个阶段。训练阶段，Shap-E 的显存峰值出现在编码器训练：多视图渲染需要保持多个视角的渲染图与梯度，Transformer 预测 MLP 权重的参数量也不小；潜空间扩散阶段的显存相对可控，因为扩散在低维潜空间运行，序列长度远小于显式网格的顶点序列。推理阶段，显存峰值出现在解码：网格提取要对空间格点做密集 MLP 查询，查询批次大小与提取分辨率共同决定峰值。给定事实中「网格质量一般」与「训练管线复杂」并列，提示解码路径的分辨率与管线耦合是工程复现的主要成本点。Point-E 推理显存平坦，因为点集输出维度固定；DreamFusion 的显存峰值在可微渲染与 2D 扩散反传，且随渲染分辨率上升。

四 · 失败模式逐项对照：每种表示都有自己的系统性缺陷

Point-E 的失败模式是结构性的：点云没有拓扑，因此无法直接表达「面」与「纹理坐标」。给定事实明确指出 Point-E「生成的点云无拓扑、无纹理」。下游若需要可渲染网格，必须做表面重建，而重建算法在稀疏点集、薄结构、开放边界处会产出孔洞或错误连接。这不是 Point-E 采样质量问题，而是表示本身不承载拓扑信息。工程上，把 Point-E 接入渲染管线时必须插入重建步骤，并为重建失败准备回退路径。

Shap-E 的失败模式有三条，给定事实已列出：细节弱、网格质量一般、训练管线复杂。细节弱的机制在第二节已说明——多视图渲染监督不约束视角外几何。网格质量一般的机制在解码路径：隐式场经等值面提取得到的网格，其平滑度与保真度受限于提取分辨率与隐式场的局部梯度行为；在薄结构处，等值面可能断裂或粘连。训练管线复杂则来自两阶段训练：先训编码器（多视图到隐式权重），再训潜空间扩散，两阶段的接口是潜变量分布，若编码器输出的潜变量分布与扩散先验不匹配，第二阶段会退化。这是一个真实的工程风险：编码器与扩散器不是端到端联合训练的，接口处的分布偏移不会被任何一方的损失直接惩罚。

DreamFusion 的失败模式是成本与不稳定性：逐资产优化意味着时延随资产数量线性增长，没有摊销；SDS 损失的梯度方差较大，优化过程可能收敛到局部解，表现为几何在多个视角下不一致（经典的「多面」伪影）。给定事实中「几何细节不如 SDS」是站在 Shap-E 视角的比较结论，反过来也说明 SDS 在细节上的优势，但这一优势以时延与稳定性为代价。TRELLIS 的 SLAT 失败模式则转移到结构侧：稀疏潜变量网格的分辨率与稀疏度是一对矛盾，分辨率高则显存上升，稀疏度高则细节丢失，且稀疏结构的构建本身依赖前处理。

把失败模式与表示对齐，可以得到一条清晰的判断：失败模式不是随机噪声，而是表示与监督选择的必然投影。点云的失败在拓扑，隐式权重的失败在视角外几何与提取分辨率，可微渲染场的失败在优化成本与多视角一致性，结构化潜变量的失败在结构分辨率。工程选型时，应先问下游需要什么，再问哪种失败模式可以接受，而不是先问哪个方法指标更高。

五 · 决策表：按下游约束选方法

决策表的行是下游约束，列是候选方法，单元格是「是否匹配 + 主要代价」。约束一：是否需要带纹理的可渲染网格。Shap-E 匹配，因为它解码出带纹理网格；Point-E 不匹配，需重建且无纹理；DreamFusion 匹配但时延高；TRELLIS 匹配且结构更细。约束二：是否需要批处理与低时延。Shap-E 与 Point-E 匹配（前馈），DreamFusion 不匹配（逐资产优化）。约束三：几何保真度是否优先于速度。DreamFusion 优先保真，Shap-E 在细节上让步。约束四：训练管线复杂度是否可接受。Shap-E 的两阶段管线复杂，Point-E 相对简单，DreamFusion 无需训练生成器但需 2D 扩散先验。约束五：显存预算是否紧张。Point-E 推理最省，Shap-E 在提取阶段吃显存，DreamFusion 在反传阶段吃显存。

用两个具体场景把决策表落地。场景 A：内容平台需要批量生成带纹理的道具，时延预算分钟级，几何细节要求中等。按表，Shap-E 是匹配项——前馈、约 1 分钟、带纹理网格；代价是细节弱与网格质量一般，需要在后处理中做网格清理，并为薄结构准备人工修补。Point-E 在此场景不匹配，因为下游要网格且要纹理，重建步骤会引入额外失败。场景 B：单件高保真展示资产，时延不敏感，几何细节优先。按表，DreamFusion 匹配，代价是小时级优化与多视角一致性风险；Shap-E 在此场景是次优，因为细节弱是系统性缺陷，不能靠后处理补足。场景 C：需要结构化潜变量以支持编辑或局部生成。TRELLIS 的 SLAT 是匹配项，因为它把潜变量结构化，代价是结构分辨率与稀疏度的权衡。

决策表的一个关键读法是：没有一行是「全面胜出」。Shap-E 的定位是「前馈 + 隐式 + 带纹理」，它在速度与可交付性上占优，在几何保真上让步；这个让步是表示与监督选择的直接后果，不是实现缺陷。给定事实中「用户偏好优于 Point-E，但几何细节不如 SDS」正好对应这条定位：用户偏好反映的是「能拿到带纹理网格」的交付价值，几何细节的比较则暴露了监督路径的边界。工程判断应落在「下游能否接受细节弱」这一问上，而不是「哪个方法更好」。

六 · 对比的方法论：为什么这些轴不能被压成一个分数

把五条轴压成一个综合分数是常见的做法，但它会掩盖耦合。速度与显存的耦合在第三节已说明：Shap-E 的提取分辨率同时影响两者，调高分辨率改善网格质量却推高显存与时延，这不是三个独立指标，而是一个权衡曲面。表示与失败模式的耦合在第四节已说明：失败模式是表示的投影，换表示就换失败模式，而不是消除失败。监督与速度的耦合在第三节已说明：SDS 的监督强度换来的是逐资产优化，前馈的摊销换来的是监督只约束渲染一致性。把这些耦合压成一个分数，等于假设各轴可独立加权，而事实是它们互相牵制。

另一个方法论要点是对比对象的时序位置。Point-E 与 DreamFusion 是同期基线，TRELLIS 是后继。同期对比回答「在同一时间点，不同路线的取舍是什么」；后继对比回答「这条路线被继承后如何演化」。Shap-E 的「潜空间 + 隐式解码」被 TRELLIS 的 SLAT 继承，说明这条路线在结构化方向上仍有生命力；但继承不等于原样照搬——SLAT 把扁平权重换成结构化稀疏潜变量，正是对「细节弱」这一失败模式的针对性回应。工程复现时，若照搬 Shap-E 的扁平 MLP 权重，就会继承其细节弱的失败模式；若采用结构化潜变量，则要承担结构分辨率的新权衡。

最后落在一条具体机制上：Shap-E 的编码器监督是渲染一致性，这决定了它的潜变量携带的是「视角可见信息」而非「完整几何」。任何基于该潜变量的下游任务，其信息上限由这条监督路径设定。对比其他方法时，应把这条监督路径作为比较的锚点：Point-E 的监督是点集拟合，信息上限是点位置；DreamFusion 的监督是像素级分数，信息上限是渲染一致性但需逐资产优化；TRELLIS 的监督继承潜空间扩散，信息上限由结构化潜变量的分辨率设定。选型的实质，是选择一条监督路径及其信息上限，并接受与之绑定的失败模式。
