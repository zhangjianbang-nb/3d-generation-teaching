一 · 复现边界与仓库骨架：先把“两阶段”钉进目录

复现 Hunyuan3D 2.0 的第一件事不是装环境，而是把论文里的“形状 DiT + 纹理 DiT”两阶段解耦关系映射成可独立启停的代码单元。工程上最忌讳的做法是把两个分支塞进同一个训练脚本，用 if stage== 分支控制——这样一旦形状分支的 VecSet 表示或 Marching Cubes 参数变动，纹理分支的多视图渲染缓存就会连带失效，调试时无法判断误差来自几何还是来自 UV 投影。正确的骨架是三个顶层包：shape/ 负责 VecSet 扩散、SDF 监督与网格提取；texture/ 负责多视图扩散、UV 投影与贴图烘焙；common/ 只放两分支共享的图像条件编码器、相机采样与数据管线。共享图像条件但独立训练，意味着 common/ 里的条件编码器必须版本冻结，任何一侧改动都要走显式接口变更，而不是就地改张量形状。

目录内部再按“表示—模型—监督—导出”四层切分。shape/voxel/ 放 VecSet 的稀疏体素化与反量化，shape/dit/ 放扩散主干与时间步嵌入，shape/sdf/ 放 SDF 采样与 Eikonal 类正则，shape/mc/ 放 Marching Cubes 的网格提取与后处理。纹理侧对称：texture/mv/ 放多视图采样与渲染，texture/uv/ 放 UV 展开与投影，texture/bake/ 放贴图合成。这种切分让“形状/纹理分离”这一消融项在代码层面可验证：删掉 texture/ 整个目录，形状分支仍应能独立跑通并输出无纹理网格，这是最小可跑版本的第一条验收断言。

配置层要区分“结构超参”和“训练超参”。结构超参（VecSet 分辨率、DiT 层数、多视图相机数）决定显存与导出质量，训练超参（学习率、扩散步数、λ）决定收敛。把两者混在一个 YAML 里是常见崩溃点：复现者调低分辨率想省显存，结果连带改了 SDF 监督的采样密度，网格出现阶梯状伪影却误判为模型能力不足。建议用两份配置并以哈希绑定，导出网格时记录结构超参哈希，验收断言比对哈希而非比对文件名。

最后是产物目录。runs/shape/ 与 runs/texture/ 分离，各自保存 checkpoint、渲染快照与失败样本。runs/compose/ 只做合成：读形状网格、读纹理贴图、按 UV 写回。合成阶段不重新训练、不重新采样，只做几何与纹理的对齐校验。这条边界如果模糊，复现者会在合成脚本里偷偷加一次纹理重采样，导致“两阶段独立 scaling”的结论无法被自己的实验支撑。

二 · 数据准备：图像条件、SDF 监督与多视图渲染缓存

形状分支的监督是 SDF，纹理分支的监督是多视图渲染，两者共享同一张输入图像条件。数据准备的核心矛盾在于：SDF 需要水密、尺度归一化的网格，多视图渲染需要与 UV 展开一致的相机与光照。若用同一份原始资产直接喂两个分支，形状侧会因非水密网格在 Marching Cubes 后出现孔洞，纹理侧会因相机外参未对齐而在 UV 接缝处产生错位。工程做法是建立两级缓存：一级缓存把原始资产规范化为统一尺度、统一朝向、水密化后的网格，并采样出稠密 SDF 网格；二级缓存从规范化网格渲染固定数量的多视图，连同相机参数、法线缓冲、深度缓冲一起落盘。

SDF 采样的伪代码思路是：对规范化网格做体素栅格化，每个体素中心查询最近表面距离并带符号，靠近表面的窄带用高密度采样，远离表面的区域用低密度采样以省显存。符号判定依赖法线与射线求交，非水密网格在这里必然出错，所以水密化是硬前置。采样完成后要断言：窄带内 SDF 的梯度模长接近 1，这是 Eikonal 约束的可观测代理；若大量体素梯度模长偏离 1，说明网格法线朝向不一致，后续扩散学到的将是噪声。

$$\mathcal{L}_{\mathrm{shape}}=\mathbb{E}_{x_0,\epsilon,t}\big\|\epsilon-\epsilon_\theta(x_t,t,c)\big\|^2+\lambda_{\mathrm{sdf}}\sum_{p\in\mathcal{N}}\big(\|\nabla_p \hat{s}\|-1\big)^2$$

纹理侧的多视图缓存要固定相机环、固定分辨率、固定光照模板。相机数量是结构超参，增加相机数提升 UV 覆盖率但线性增加渲染与扩散成本。一个具体失败模式：相机环只覆盖上半球，UV 展开后底部接缝无监督，贴图在底面出现明显拉伸；复现者往往误以为是 UV 展开算法缺陷，实际是视图覆盖不足。验收断言应检查每个 UV 岛是否至少被两个视图覆盖，覆盖率不足的岛在训练损失中降权或标记为不可信。

数据规模上，论文使用 Objaverse 与内部资产，形状与纹理分开训练但共享图像条件。复现时不要试图用单卡跑全量：形状分支的 SDF 监督与渲染、纹理分支的多视图扩散都是数十 GPU 天量级。最小可跑版本应取小子集，先验证管线闭环，再谈 scaling。子集选择要覆盖三类难例：薄壳结构、多部件铰接、高曲率细节，这三类分别对应 Marching Cubes 的拓扑失败、UV 展开的岛分裂、纹理扩散的高频失真。

三 · 形状分支超参与最小可跑配置

形状分支的主干是 VecSet 扩散加 DiT，输出 SDF 后经 Marching Cubes 出网格。最小可跑配置的关键取舍是：VecSet 分辨率决定显存上限，DiT 深度决定感受野，扩散步数决定采样质量与推理时间。论文报告推理数十秒，这个量级意味着采样步数不能太少，否则 SDF 场不平滑、网格出现噪点。复现时先把分辨率压到能单卡跑通的水平，固定 DiT 深度与扩散步数，只调分辨率观察网格质量曲线，找到“质量开始明显退化”的拐点，这个拐点就是该硬件下的最小可用分辨率。

训练配方上，形状用 SDF 监督加渲染监督。渲染监督的作用是把 SDF 场拉向与输入图像一致的外轮廓，但渲染需要可微的体素或隐式表面查询，代价是每步训练要多一次前向。一个系统代价：渲染监督使单步显存增加，若与高分辨率 VecSet 叠加，容易在反向传播时 OOM。缓解手段是渲染监督降频——每若干步才计算一次渲染损失，而不是每步都算。这属于工程折衷，必须在配置里显式记录，否则复现者无法解释为何自己的损失曲线与论文描述的形状不同。

Marching Cubes 是形状分支最容易被低估的崩溃点。SDF 场在薄壳处可能出现符号翻转不连续，提取出的网格出现自交或孔洞；分辨率提高后三角形数量暴涨，导出与后续 UV 展开的时间非线性增长。验收断言应包含：网格水密性检查（边是否恰好被两个面共享）、自交检测、三角形数量上限。若水密性检查失败，优先回查 SDF 窄带采样密度与法线一致性，而不是调 Marching Cubes 阈值。

一个具体例子：输入是一张带细长把手的杯子图像，形状分支在把手与杯身连接处 SDF 梯度剧烈变化，低分辨率下把手被合并进杯身，高分辨率下把手保留但连接处出现薄片。这不是模型失败，而是 VecSet 分辨率与 SDF 采样密度不匹配。复现者应把这类样本单独建集，作为分辨率扫描的固定探针，每次改超参都跑同一批探针，用网格体积与连通分量数作为可比较的验收指标。

四 · 纹理分支超参与 UV 投影的失败面

纹理分支是多视图扩散加 UV 投影。超参分三组：视图组（相机数、分辨率、环带覆盖）、扩散组（步数、条件强度）、投影组（UV 展开算法、接缝填充、贴图分辨率）。三组耦合极强：视图分辨率低则扩散生成的高频细节不足，投影到高分辨率 UV 上只是插值放大；UV 展开算法激进则岛数量多、接缝多，接缝填充稍有不慎就出现可见缝线。最小可跑配置应固定视图组与扩散组，只调投影组，先让贴图在无接缝的简单资产上正确，再逐步引入复杂拓扑。

$$\mathcal{L}_{\mathrm{tex}}=\sum_{v}\|\hat{I}_v-I_v\|^2,\qquad \mathcal{L}=\mathcal{L}_{\mathrm{shape}}+\lambda\mathcal{L}_{\mathrm{tex}}$$

注意 λ 在复现中的实际含义：论文公式把两阶段损失写成加权和，但训练是分开的，λ 更多是联合微调或合成阶段的权重，而非单次反向传播中的两项相加。复现者若把两个分支塞进一次反向传播并直接用该公式，会遇到梯度尺度严重不匹配——形状损失的梯度范数与纹理损失差几个量级，λ 调不动。正确做法是分别训练、分别验收，合成阶段只做几何与纹理对齐，不引入联合梯度。

UV 展开失败是论文明确列出的局限。具体机制：多视图扩散在视图重叠区给出不一致的颜色，投影到 UV 后在接缝处产生色差；UV 岛边界若落在高频纹理区，接缝填充的插值会抹掉细节。系统代价是接缝填充需要额外的图像修补或泊松融合，增加合成阶段时间。验收断言应包含：接缝处颜色梯度连续性检查、UV 岛覆盖率检查、贴图分辨率与网格面积比检查。覆盖率不足的岛应标记为低置信，而不是强行填充。

一个具体失败模式：资产是带镂空花纹的金属片，UV 展开把镂空边缘切成多个小岛，多视图扩散在小岛上采样不足，投影后花纹边缘出现模糊与色偏。复现者若只看整体渲染图会误判为纹理真实感不足，实际是视图覆盖与岛分裂的联合问题。处理方式是提高相机数或改用更保守的 UV 展开，并在验收时单独统计小岛的平均置信度。

五 · 合成、验收断言与常见崩溃点清单

合成阶段只做三件事：读形状网格、读纹理贴图、按 UV 写回并渲染校验。验收断言分三级。一级是管线断言：形状分支单独跑通输出水密网格，纹理分支单独跑通输出无接缝贴图，合成脚本不重新采样。二级是质量断言：网格连通分量数与输入图像外轮廓一致，贴图接缝梯度连续，渲染多视图与输入图像在轮廓上对齐。三级是回归断言：固定探针集上的网格体积、三角形数、贴图平均置信度在超参变更后不出现跳变。

崩溃点可观测症状优先排查
非水密网格进 SDF 采样窄带梯度模长偏离 1，网格孔洞水密化前置与法线一致性
VecSet 分辨率与采样密度不匹配薄壳合并或薄片伪影分辨率扫描探针集
渲染监督每步计算反向传播 OOM渲染损失降频
相机环覆盖不足UV 底部接缝拉伸视图覆盖率断言
两分支联合反向传播λ 调不动，梯度尺度失配分开训练、分开验收
合成阶段偷偷重采样两阶段独立性无法验证合成脚本只读不采样

最小可跑版本的验收顺序不可颠倒：先形状后纹理再合成。形状侧先验证 SDF 场在探针上的梯度模长，再验证 Marching Cubes 的水密性与连通分量；纹理侧先验证单视图投影在简单平面上的正确性，再验证多视图接缝；合成侧先验证无纹理网格与贴图的 UV 对齐，再验证渲染轮廓。每一步失败都应在该步内解决，不要带着形状侧的孔洞去调纹理侧的接缝，否则误差归因不可能完成。

推理时间是复现者最容易低估的系统代价。论文报告数十秒量级，意味着扩散步数与 Marching Cubes 分辨率都不能随意拉高。复现时应把推理拆成形状采样、网格提取、多视图扩散、UV 投影、贴图烘焙五段分别计时，找出占比最大的一段。若形状采样占大头，优先降扩散步数并观察探针质量；若网格提取占大头，优先降 Marching Cubes 分辨率并检查薄壳探针。分段计时是验收断言的一部分，不是可选的性能分析。

六 · 独立 scaling 的工程判断

“两分支可独立 scaling”在论文里是核心卖点，在复现里是可验证的工程命题。验证方法是：固定纹理分支配置，只放大形状分支的分辨率与 DiT 深度，观察网格质量提升而贴图质量不变；再固定形状分支，只放大纹理分支的相机数与贴图分辨率，观察贴图细节提升而网格拓扑不变。若两次实验中出现跨分支的质量耦合——例如放大形状分辨率后贴图接缝变差——说明共享图像条件编码器或数据缓存存在隐式耦合，必须回到 common/ 层排查，而不是继续调超参。

工程判断的落点是缓存与接口的稳定性。形状分支放大分辨率会改变 SDF 采样密度，进而改变多视图渲染缓存所依赖的网格法线；若纹理分支直接读形状分支的中间网格而非规范化网格，独立 scaling 就被破坏。正确做法是两级缓存之间只通过规范化网格与固定相机参数通信，形状分支的内部表示（VecSet 分辨率、DiT 深度）不泄漏到纹理分支。这条接口约束应写成断言：纹理分支的数据加载器不得引用形状分支的任何结构超参。

最后一个具体机制：合成阶段的 UV 写回要使用形状分支导出的网格顶点索引，而不是重新三角化。重新三角化会改变 UV 岛边界，使纹理分支训练时的投影假设失效。复现者若在合成时为了“优化网格”而重跑 Marching Cubes，等于把两阶段解耦退回单阶段耦合，独立 scaling 的结论不再成立。验收断言应比对合成前后网格的顶点数与索引哈希，任何变化都视为管线违规。
