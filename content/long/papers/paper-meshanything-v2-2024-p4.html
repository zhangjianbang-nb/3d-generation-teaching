一 · 数据集与评测口径：为什么只认 Objaverse 艺术家网格

MeshAnything V2 的训练与评测数据落在 Objaverse 的艺术家网格子集上。这个选择不是随手取一个“大数据集”，而是由任务定义倒推出来的：模型要生成的是艺术家手工建模那种带明确边流、面片密度不均、局部有清晰结构意图的网格，而不是扫描重建或程序化生成的均匀网格。扫描网格的顶点分布由传感器采样决定，面片朝向杂乱、拓扑常带孔洞；程序化网格则往往过于规则，面片尺寸单一。用这些数据训练，自回归模型会学到与“艺术家网格”不一致的局部统计，生成结果即使面数达标，也不具备可编辑性。

评测口径因此围绕三个可测维度展开。第一是输出面数上限，即在固定序列预算下模型能稳定产出多少面；第二是复杂网格的成功率，即在高面数、多部件、局部细节密集的输入形状上，生成结果是否仍能保持合法拓扑并被判为可用；第三是序列长度，它直接决定自回归解码的步数与显存占用。这三个维度互相牵制：面数越高，序列越长；序列越长，越容易在中途出现拓扑错误。论文的核心主张正是这三者之间的关系被 AMT 改写了。

这里有一个容易被忽略的工程细节：面数上限并不是模型参数直接决定的，而是由训练时使用的序列长度预算和 tokenization 方案共同决定的。同样的 Transformer、同样的训练步数，换一种序列化方式，可生成的面数就变了。这也是为什么消融实验必须把 tokenization 单独拿出来对比，否则无法判断提升来自模型容量还是来自表示效率。

数据规模方面，论文只给出定性描述：在 Objaverse 艺术家网格上训练，耗时数天。没有给出具体网格数量、训练 token 总数或数据过滤比例，因此不能引用任何精确数字。可确认的是，训练使用的是 AMT 序列而非逐面 token 序列，这一点在消融中被单独验证。

二 · 基线选择与对比逻辑：MeshAnything 与 MeshGPT 各自代表什么

基线选了两个：MeshAnything 和 MeshGPT。它们不是随便凑数的对比对象，而是代表了两种不同的技术路线，正好把 AMT 的改进点夹在中间。

MeshGPT 代表的是“逐面 token”路线的早期形态：每个面片用三个顶点 token 表示，序列长度与面数成线性关系，且相邻面片共享的边被重复编码。它的贡献在于确立了“把网格当成离散 token 序列、用自回归模型生成”的范式，但序列长度成为硬瓶颈。MeshAnything 沿用了逐面 token 的基本表示，在架构和训练上做了工程化改进，把这条路线的能力推到可用水平，但序列长度的根本约束没有解除。

MeshAnything V2 的对比逻辑因此是：在同等序列预算下，AMT 把每个新面片的平均 token 数压到接近逐面方案的一半，于是同样长度的序列能容纳约两倍的面数。论文给出的对照是输出面数从 800 提到 1600，序列长度约减半。这两个数字是同一枚硬币的两面：不是模型变大了，而是每个面片占用的序列位置变少了。

需要强调的是，这个对比是在“同等预算”下成立的。如果给逐面 token 方案两倍的序列长度，它也能生成 1600 面，但解码步数翻倍、显存占用翻倍、长序列上的误差累积也更严重。所以 AMT 的收益不只是“能生成更多面”，而是在相同计算代价下生成更多面，这对自回归推理的可行性是决定性的。

基线对比中没有引入基于扩散的网格生成方法或基于隐式场的方案，因为任务定义不同：那些方法产出的是可渲染的表面，而这里要求的是带合法拓扑、可导入建模软件继续编辑的面片网格。评测口径因此不跨路线比较，只在自回归网格生成内部比较。

三 · 主要结果：提升来自 tokenization，不来自模型容量

主要结果可以归结为一句话：在同等序列预算下，AMT 把可生成的面数上限从 800 提到 1600，同时复杂网格的成功率提升。这两个结论必须分开看，因为它们的机制来源不同。

面数翻倍的机制是直接的算术后果。逐面 token 方案中，一个与已有面片相邻的新面片需要编码三个顶点；而 AMT 利用“相邻面片共享一条边”这一几何事实，只编码新顶点，共享边的两个端点从上下文继承。论文给出的关系是：

$$\mathrm{AMT}(\mathcal{M})=\big(t_1,\ldots,t_N\big),\qquad |\mathrm{AMT}(\mathcal{M})|\approx \frac{1}{2}|\mathrm{VTT}(\mathcal{M})|$$

序列长度约减半，意味着同样长度的序列能容纳约两倍的面片。这不是渐进优化，而是表示层面的常数因子改进，直接抬高了面数天花板。

复杂网格成功率提升的机制则更微妙。序列变短带来的不只是容量增加，还有误差累积路径的缩短。自回归解码逐 token 进行，每一步的预测误差会传入后续上下文；序列越长，误差累积的机会越多，在中后段出现非法拓扑（例如新面片与已有面片重叠、共享边不匹配、法向翻转）的概率越高。AMT 把序列压短，等于减少了误差累积的步数，因此在复杂形状上更容易走到合法终态。论文只给出定性表述“复杂网格成功率提升”，没有给出具体百分比，因此不能引用任何精确数字。

这两个机制共同解释了为什么提升不能归因于模型变大。论文没有报告参数量的变化，架构描述中形状编码器、自回归 Transformer、解码器的分工与前代一致，改进集中在序列化环节。消融实验进一步确认了这一点：换回逐面 token，面数上限回落到 800 附近，说明增益确实来自 AMT 而非其他因素。

一个具体的例子可以说明面数上限的实际含义。假设输入是一个带多个部件、局部有密集倒角的机械零件形状。逐面 token 方案在 800 面左右就触及序列上限，生成结果在大平面上尚可，但在倒角与部件交界处被迫用大面片糊过去，边流断裂。AMT 方案在同样预算下能走到 1600 面，倒角处可以分出足够的面片维持边流，部件交界处的共享边也能被正确编码。差别不在“模型更聪明”，而在“预算够不够分到细节上”。

四 · 消融：三个变量各自贡献了多少

消融实验围绕三个变量展开：AMT 与逐面 token 的对比、面数上限、形状编码。这三个变量分别对应表示效率、容量约束和条件控制，拆开看才能定位提升来源。

第一组是 AMT 对逐面 token。这是核心消融，直接回答“序列减半是否真的转化为面数翻倍”。结论是肯定的：在同等预算下，AMT 版本能生成 1600 面，逐面 token 版本停在 800 面附近。这组对比排除了“训练数据变多”或“训练更久”的解释，因为两组共享同一数据与训练配方，唯一变量是序列化方式。

第二组是面数上限。这组消融检验的是：当把目标面数继续往上推时，模型是否还能维持拓扑合法性。结论是序列长度仍是硬约束——面数上限由序列预算决定，AMT 只是把这条上限抬高了一倍，并没有解除它。超过预算后，生成结果开始出现截断、未闭合或非法共享边。这组消融的意义在于给工程使用划出边界：1600 面是可用基线，不是无限能力。

第三组是形状编码。这组消融检验条件控制是否真的在起作用，即生成结果是否跟随输入形状，而不是退化为无条件先验采样。结论是形状编码对复杂形状的生成质量有实质影响；去掉或弱化形状条件后，生成结果与输入形状的对应关系变差。论文没有给出具体的条件控制强度数值，只作定性表述。

三组消融合起来给出一个清晰的归因结构：面数翻倍来自 AMT 的表示效率，复杂形状成功率提升来自序列缩短带来的误差累积减少，形状编码负责把生成结果锚定到输入。三者不是叠加关系，而是各自负责一个维度，缺一个都会在对应维度上退化。

从工程角度看，消融的价值在于它把“要不要换 tokenization”变成一个可计算的决策。如果下游任务只需要 800 面以内的网格，AMT 的收益主要体现在推理步数减半；如果需要 1600 面，AMT 是必要条件而非可选项。

五 · 失败模式与代价：1600 面不是免费午餐

结果数字背后有三类代价，必须在工程部署前算清楚。

第一类是序列长度约束仍在。AMT 把序列减半，但没有改变自回归解码逐 token 进行的事实。推理时每生成一个 token 都要跑一次前向，序列越长，延迟线性增长。1600 面的 AMT 序列与 800 面的逐面序列长度相当，因此推理延迟没有恶化，但也没有改善；想要 3200 面，序列会重新变长，延迟随之上升。这是容量与延迟之间的硬 trade-off，AMT 只是把平衡点往容量一侧推了一格。

第二类是拓扑合法性仍需检查。AMT 的编码假设“相邻面片共享一条边”，解码器据此还原网格。但如果自回归过程中预测出与上下文不一致的新顶点，或共享边的端点匹配失败，还原出的网格就会出现非法拓扑：面片重叠、边不闭合、法向不一致。论文明确把“拓扑合法性仍需检查”列为局限，意味着输出不能直接当作合法网格使用，下游需要一道验证与修复工序。这道工序的代价取决于非法率，而非法率随面数上升而上升，因为长序列上的误差累积更多。

第三类是细节上限。1600 面对于带倒角、螺纹、密集开孔的复杂形状仍然不够。AMT 抬高的是面数天花板，不是细节分辨率的天花板。超过 1600 面后，要么序列预算不够，要么拓扑合法性下降，两者都构成实际瓶颈。

一个具体的失败场景：输入是一个带内部空腔和薄壁结构的形状。AMT 在薄壁处需要密集面片维持壁厚，在空腔处需要面片闭合。当序列预算耗尽时，模型往往优先保证外表面连续，内部空腔的闭合被截断，输出网格带孔洞。这类失败不是随机噪声，而是预算分配的策略性后果，检查工序必须能识别未闭合边界。

这些代价共同决定了 AMT 的定位：它把“生成 1600 面网格”变成可用基线，但没有把网格生成变成无条件可靠的操作。工程判断应该是：在 1600 面以内、配合拓扑检查工序、接受逐 token 推理延迟的场景下，AMT 是当前自回归路线的最优 tokenization；超出这个范围，需要等序列效率的下一轮改进。

六 · 证据链的边界：哪些结论被支持，哪些没有

把实验证据按强度排序，可以看清这篇论文的结论边界。

最强的一档是序列长度与面数的关系。AMT 序列约为逐面 token 序列的一半，同等预算下面数从 800 到 1600，这是有公式支撑、有对照实验确认的结论，可以直接用于工程估算。

中间一档是复杂网格成功率提升。论文给出定性表述，没有给出具体数字，因此只能作为方向性判断：序列缩短减少了误差累积，复杂形状上更容易走到合法终态。这个机制是合理的，但提升幅度不可引用。

较弱的一档是形状编码的贡献。消融确认了形状条件在起作用，但没有量化条件强度与生成质量的关系，因此无法回答“形状编码器要多大才够”这类工程问题。

没有被支持的结论包括：AMT 对任意面数都成立（实际受序列预算约束）、输出网格可直接使用（实际需拓扑检查）、推理速度有改善（实际逐 token 延迟未变）。这三条都是常见误读，实验证据明确不支持。

从证据链看，这篇论文的贡献是表示层面的常数因子改进，而不是能力层面的质变。它把可用基线从 800 面推到 1600 面，代价是拓扑检查工序和序列约束仍在。这个判断直接决定下游怎么用：把 AMT 当作 tokenization 的标准件接入自回归管线，在 1600 面预算内配合检查工序使用，超出预算则等待下一轮序列效率改进；后续 PartCrafter 等工作借鉴其效率思想，也印证了这条路线是可复用的工程基础设施，而非一次性技巧。
