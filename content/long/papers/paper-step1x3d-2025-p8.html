一 · 训练数据的双轨结构与来源口径

Step1X-3D 的训练数据不是单一来源的大杂烩，而是按几何与纹理两条生成轨道分别组织的。几何轨以 Objaverse 这类公开三维资产库为主体，纹理轨则叠加了内部可控数据。这个“公开库 + 内部可控集”的组合不是随意拼盘，它直接决定了模型能力的分布：公开库提供规模与多样性，内部集提供条件对齐信号。理解这一点，是理解后面所有评测数字的前提。

具体机制上，几何分支吃的是带 SDF/网格监督的资产，纹理分支吃的是多视图渲染加 UV 展开后的监督对。内部可控数据的构造逻辑是：给定一个资产，配套生成草图、分割掩码、文本描述等条件通道，使得同一条资产在不同条件模态下都能被检索到。这就把“条件控制”从推理时的外挂变成了训练时的监督信号。伪代码层面的数据装配可以写成：对每个资产 $a$，采样条件 $c_{\mathrm{geo}}\in\{\text{草图},\text{分割},\text{文本}\}$，渲染多视图 $V(a)$，展开 UV 得 $\mathcal{T}(a)$，然后分别送入两条轨道。关键在于条件通道与几何、纹理的绑定关系必须在数据层就固定，否则条件编码器学到的只是噪声。

系统代价在于内部可控数据的标注成本。草图与分割不是免费的：草图需要人工或半自动描摹轮廓，分割需要按部件切分，这两类标注的吞吐远低于直接抓取公开资产。因此内部集的规模必然受限，而规模受限会直接传导到条件控制的泛化边界——模型见不到的条件组合，推理时就不会响应。这是一个结构性失败模式：条件类型在训练分布内表现良好，一旦用户给出训练时未配对的“草图 + 特定材质风格”组合，控制信号会退化。具体例子是，用分割掩码指定“只改椅腿材质”这类局部编辑，若内部数据中该部件的分割样本稀少，编辑接口的响应就会漂移，表现为编辑区域溢出到相邻部件。

另一个容易忽略的口径问题是公开库与内部集的资产重复度。若内部可控数据是从公开库资产派生而来，那么几何轨与纹理轨之间存在资产级重叠，评测时若不做去重切分，几何指标与纹理指标会同时被“记忆”抬高。工程上必须按资产 ID 做切分，而不是按视图或按条件样本切分，否则同一资产的不同视图会跨训练/测试边界泄漏。

二 · 评测协议：条件通道如何被逐条激活

Step1X-3D 的评测协议围绕“可控”展开，而不是只比几何精度。协议的基本结构是：固定一组测试资产，对每个资产分别施加文本条件、草图条件、分割条件，再叠加局部编辑请求，逐条记录生成结果。这与只报单一 FID 或 Chamfer 距离的做法不同，它把控制能力拆成了可分别观测的通道。消融实验中的“条件类型”一项，正是这套协议的直接产物：去掉某一条件通道，观察对应指标如何塌陷。

机制上，条件编码器把文本、图像、草图映射到统一的条件空间，几何 DiT 与纹理扩散各自消费对应的条件子向量。评测时若只给文本，几何与纹理都走文本通道；若给草图，几何通道的权重被抬高，纹理通道仍可回落到文本。这种“条件路由”意味着评测必须记录每条通道的激活状态，否则同一张输出无法归因。公式上可以把条件路由写成加权组合：

$$c=\sum_{k\in\{\text{txt},\text{sketch},\text{seg}\}} w_k\, E_k(\cdot),\qquad \sum_k w_k=1$$

其中 $E_k$ 是各模态编码器，$w_k$ 由输入中实际提供的条件决定。评测协议的关键就在于固定 $w_k$ 的取值组合，逐组报告。若协议不固定权重，不同基线之间的比较就失去意义，因为基线可能只支持文本，而 Step1X-3D 支持多通道叠加，权重差异会直接改变输出分布。

系统代价是评测吞吐。每增加一个条件通道，就要为同一资产多跑一次完整推理，而推理本身是数十秒量级。若测试集有数百资产、每资产四到五种条件组合，评测总时长会迅速膨胀到不可接受。工程上的折中是分层抽样：对条件通道做配对采样而非全组合，代价是通道间的交互效应无法被完整观测。失败模式随之而来——局部编辑接口在单通道评测下看起来可用，但在多通道叠加时可能因为条件冲突而失效，而分层抽样恰好漏掉了这类冲突组合。具体例子是“草图指定整体轮廓 + 分割指定局部材质”的叠加请求，单通道评测各自通过，叠加后编辑区域与草图轮廓错位。

三 · 指标口径：几何、纹理与控制各算各的账

指标口径必须与两条生成轨道对齐。几何轨的指标衡量 SDF/网格与参考资产的接近程度，纹理轨的指标衡量多视图渲染与 UV 贴图的一致性，控制轨的指标则衡量输出对条件的响应程度。三者不能混算成一个总分，因为它们的失败模式互不相关：几何对了纹理可能错，纹理对了控制可能没响应。论文的实验结论“高保真 + 可控”是三条口径分别成立后的合取，而不是某个加权总分的胜出。

几何口径的机制是采样点距离类度量，纹理口径的机制是渲染视图与参考视图的感知距离，控制口径的机制是条件与输出的对齐度。控制口径最容易被误读，因为它没有统一的数学形式。一种可操作的写法是把控制对齐定义为条件编码与输出编码在共享空间中的距离：

$$\mathcal{L}_{\text{ctrl}}=\big\|E_c(c)-E_o(\mathcal{M},\mathcal{T})\big\|_2^2$$

其中 $E_c$ 是条件编码器，$E_o$ 是输出编码器。这个量小只说明输出“像”条件，不说明输出“对”条件——编码器可能把两者都塌缩到同一区域。因此控制口径必须配合人工或规则化的可判读检查，例如草图轮廓与生成网格投影的重合度、分割区域与编辑区域的交并比。这就是为什么论文把“局部编辑可用”作为定性结论而非单一数字：编辑接口的正确性依赖区域级判读，而不是全局距离。

系统代价在于纹理口径的渲染开销。多视图渲染需要可微渲染管线参与，评测阶段虽可关闭梯度，但渲染本身仍是瓶颈。失败模式是纹理指标对视角采样敏感：若评测视角与训练渲染视角分布重合，纹理会显得更真实，指标被抬高；若评测视角偏离，纹理接缝与 UV 拉伸会暴露。具体例子是资产背面的纹理，在训练视角覆盖不足时，评测若只取正面视角，纹理真实感被高估，而用户实际旋转模型后会看到接缝。这就是“纹理真实感受数据限制”在指标层面的体现。

口径度量对象主要失败模式受数据影响的环节
几何SDF/网格与参考的距离薄壁与细结构塌陷公开库资产密度
纹理多视图渲染感知距离背面接缝、UV 拉伸渲染视角覆盖
控制条件与输出的对齐条件冲突、编辑溢出内部可控数据配对

四 · 作弊风险：条件泄漏与视角重合

可控生成的评测有一类特有的作弊风险：条件信息通过非预期通道泄漏进输出。最典型的是草图条件。草图本身携带轮廓信息，若几何分支在训练时把草图与参考网格做了像素级对齐，模型可能学会“描图”而非“按草图生成”——输出网格直接贴合草图的像素边界，而不是在三维空间中合理重建。这种输出在草图口径上得分极高，但换一个视角或换一条草图就会崩。评测若只比对草图投影，就无法区分“理解条件”与“复制条件”。

机制上，防泄漏的做法是在条件编码阶段对草图做几何归一化，剥离尺度与位置信息，只保留拓扑与比例。但归一化本身会损失信息，代价是草图控制的精度下降。这是一个真实的权衡：归一化越彻底，泄漏越少，控制越弱。工程判断是保留部分归一化，并在评测中加入“跨视角草图”测试——用同一资产的不同视角草图分别生成，检查输出是否一致。若输出随草图视角剧烈变化，说明模型在描图而非重建。

第二类作弊风险是视角重合。纹理轨的训练渲染视角与评测渲染视角若来自同一采样分布，纹理指标会被系统性抬高。这不是模型能力强，而是评测集与训练集在视角维度上重叠。防法是评测视角做分布外采样，例如加入低角度与背面视角。代价是纹理指标会明显下降，且下降幅度难以归因——究竟是模型纹理差，还是视角分布偏移导致的合理退化，需要对照实验区分。具体例子是同一资产的正面纹理在两个视角下都清晰，但侧面接缝在一个视角下可见、另一个视角下被遮挡，指标差异完全由视角选择决定。

第三类风险是条件通道的“全给”评测。若评测时同时提供文本、草图、分割三条通道，模型可以从容选择最容易响应的那条，而评测者无法判断它究竟用了哪条。这会让控制指标虚高。协议上必须做通道消融，逐条关闭，观察指标的单通道表现。消融实验中的“条件类型”一项正是为此设计。代价是评测工作量翻倍，且单通道表现通常低于多通道叠加，报告时需要明确口径，避免读者把叠加结果误读为单通道能力。

五 · 一个容易误读的数字：局部编辑的“可用”

论文把“局部编辑可用”作为结论之一，这个表述最容易被误读成“局部编辑在任意资产、任意部件上都可靠”。实际口径要窄得多。局部编辑接口的可用性依赖三个前提：编辑区域在分割条件下可被清晰界定、该区域在训练数据中有足够的配对样本、编辑请求不与其他条件通道冲突。三者任一不满足，“可用”就退化为“有时可用”。把定性结论读成定量保证，是这一类论文最常见的误读。

机制上，局部编辑通过掩码把纹理扩散的更新限制在指定 UV 区域，几何分支则通过局部 SDF 扰动实现部件级修改。伪代码思路是：给定编辑掩码 $m$，纹理更新只在 $m$ 内生效，边界处做羽化以掩盖接缝；几何更新只在 $m$ 对应的三维区域内采样。失败模式集中在边界：羽化不足会出现硬接缝，羽化过度会让编辑溢出到相邻部件。具体例子是给一个带纹理的杯子换杯柄材质，若杯柄与杯身的 UV 岛相邻，掩码边界稍有偏差，杯身纹理就会被污染。这种失败在单资产演示中不易察觉，在批量评测中会以“编辑溢出率”的形式暴露。

另一个误读点是“数十秒推理”与“局部编辑”的关系。局部编辑不是增量推理，它仍要走完整的纹理扩散流程，只是更新被掩码约束。因此编辑一次与生成一次的时间代价同量级，用户若期望“改一笔只需一秒”，就会失望。这是推理慢这一局限在编辑场景下的具体表现。工程上若要支持交互式编辑，必须做缓存与增量采样，而这超出了论文所述范围。把“可用”理解为“可交互”，是第二层误读。

正确的读法是：局部编辑在受控演示条件下成立，其可靠性由分割质量与数据配对决定，其代价与全量生成同量级。评测协议若要报告这一项，应当同时给出编辑成功率、溢出率与单次编辑耗时，三者缺一不可。只报成功率会掩盖溢出，只报耗时会让读者误判交互性。

六 · 评测与数据的耦合：口径选择即工程判断

数据来源与评测协议不是两个独立环节，它们通过口径耦合在一起。公开库决定几何指标的基线难度，内部可控数据决定控制指标的可得上限，渲染视角分布决定纹理指标的可比性。任何一项口径的调整，都会改变三条轨道之间的相对权重。工程复现时最容易犯的错是照搬指标名而不照搬口径：同样叫 Chamfer 距离，采样密度不同结果就不可比；同样叫控制对齐，编码器不同结论就不可迁移。

机制上，可复现的评测需要固定四件事：测试资产 ID 列表、条件通道的配对方式、渲染视角集合、指标计算所用的采样参数。这四件事任何一件变动，数字就不能跨实现比较。系统代价是评测脚本的维护成本，因为条件通道与渲染视角的组合会随模型能力演进而膨胀。失败模式是“指标漂移”：同一模型在不同版本的评测脚本下给出不同结论，而差异全部来自口径而非模型。具体例子是纹理指标在加入背面视角后整体下降，若报告时不注明视角集合变更，读者会误以为模型退化。

工程判断上，应当把评测口径当作模型的一部分来版本化管理。对于 Step1X-3D 这类双轨模型，几何与纹理的口径必须分开版本，控制口径单独版本，三者不共享采样参数。这样当某一轨道的数字变化时，可以定位到是数据、是口径还是模型。反过来，若三轨共享一套采样参数，任何一处改动都会同时扰动三条口径，归因就失效了。

最后落在具体机制上：控制口径的编码器选择直接决定“可控”能否被测量。若用与训练同源的编码器做对齐度量，指标会偏向模型已学会的条件分布；若用独立编码器，指标更接近人类判读但噪声更大。这不是一个可以回避的选择，它本身就是工程判断——选同源编码器意味着接受分布内乐观偏差，选独立编码器意味着接受方差。论文的定性结论“更可控”成立的前提，是这套口径在受控条件下被逐条激活并逐条报告，而不是被压缩成一个总分。
