一 · 从一组高斯到一张图：端到端的数据流

3DGS 的整条流水线可以拆成三段：场景参数化、投影与光栅化、梯度回传与致密化。输入是一组由 SfM 得到的稀疏点云和对应的相机位姿，输出是一张 1080p 的合成图像。中间没有 MLP，没有体素网格，也没有每像素的射线采样。场景的全部信息被压进一个显式的基元集合：每个基元是一个 3D 高斯，携带均值 μ（3 维）、协方差 Σ（3×3，由旋转 R 与缩放 S 参数化为 Σ=RS S^T R^T）、不透明度 α（标量）、以及一组球谐系数用于表达视角相关的颜色。这个集合在训练开始时只有 SfM 点云那么稀疏，在训练结束时通常膨胀到数百万个。

数据流的每一步都是显式可查的。给定相机视图矩阵 W 与投影雅可比 J，每个高斯的 3D 协方差被变换到屏幕空间：Σ'=J W Σ W^T J^T。这个变换把世界坐标中的椭球投影成屏幕上的 2D 椭圆，决定了该高斯在图像平面上覆盖哪些像素、以什么形状衰减。随后所有高斯按视图空间深度排序，逐像素执行从前到后的 alpha 混合。混合公式是：

$$C=\sum_{i\in\mathcal{N}} \mathbf{c}_i\,\alpha_i\prod_{j=1}^{i-1}(1-\alpha_j),\qquad \Sigma'=J W \Sigma W^{\top}J^{\top}$$

这里 c_i 是第 i 个高斯在该像素处的颜色（由球谐系数与视线方向求值得到），α_i 是它的不透明度乘以 2D 高斯在该像素的衰减值。乘积项是前序所有高斯的透射率累积。注意这个求和的顺序必须严格按深度递增，否则遮挡关系会被破坏——这正是排序环节存在的理由，也是整个系统里最不“并行友好”的一步。

一个具体例子可以说明这条链路的信息密度。假设场景中有一片树叶，SfM 在叶面附近给出若干稀疏点。训练初期，这些点各自对应一个较小的各向同性高斯，投影到屏幕上是一片模糊的绿色斑块。随着梯度信号指出该区域的重建误差，致密化机制会在梯度大的位置分裂或克隆高斯，协方差也在学习率作用下被拉成沿叶面方向的扁椭球。最终，几百个扁高斯以不同深度叠在一起，从某个视角看是一片清晰的叶子，换一个视角则因为椭球的朝向正确而仍然合理。整个过程中没有任何隐式网络参与，几何与外观都写在这组参数里。

这条数据流的工程代价集中在两点。其一是排序：数百万个高斯每帧都要按深度重排，即便用 GPU 上的基数排序，也是一笔不可忽略的开销，且排序结果依赖于相机，无法跨帧复用。其二是显存：每个高斯的位置、协方差参数、不透明度、球谐系数加起来是几十个浮点数，数百万个高斯就是数百 MB 级别的常驻显存，且随基元数线性增长。这两个代价直接决定了后续所有优化的方向。

二 · 协方差投影：为什么用雅可比而不是直接投影

把 3D 高斯投影到 2D 是整条流水线里数学上最讲究的一步。朴素的做法是把均值 μ 投影到屏幕得到像素中心，然后随便给一个屏幕空间的半径。这样做在透视投影下会出错：同样大小的 3D 椭球，靠近相机的投影大，远离相机的小，而且斜视角下椭球的投影形状会随视角剧烈变化。3DGS 的做法是对协方差做局部仿射近似，用投影变换在均值处的雅可比矩阵 J 与视图矩阵 W 共同作用：Σ'=J W Σ W^T J^T。

这个近似的含义是：把非线性透视投影在 μ 附近一阶展开，得到一个仿射变换，再用这个仿射变换去搬运协方差的二阶统计量。JW 是 3×3 的矩阵，Σ 是 3×3，乘出来的 Σ' 是 2×2 的屏幕空间协方差（实际实现中取前两维）。有了 Σ'，屏幕上的 2D 高斯衰减就可以解析计算，不需要对每个像素做采样。这一步是整个方法能做到实时的关键：它把“一个 3D 椭球在屏幕上长什么样”变成了一个闭式表达式。

工程上这一步的失败模式很具体。当高斯非常靠近相机、或者均值落在视锥边缘时，雅可比近似会失真，投影出的 2D 椭圆可能过大或方向错误，表现为画面边缘的拉伸伪影或突然出现的色块。另一个失败模式是数值退化：如果协方差矩阵接近奇异（例如缩放参数被优化到极小），求逆和特征分解会不稳定，2D 椭圆的轴长计算会爆掉。实现中通常会给协方差加一个小的正则项，或者对缩放参数设下限，但这些补丁本身会影响收敛行为。

还有一个容易被忽略的细节：Σ' 必须是半正定的，否则 2D 高斯的指数项会发散。JW Σ W^T J^T 在数学上保持半正定性，但浮点运算下的舍入误差可能破坏它，尤其是在 Σ 的条件数很大时。这就是为什么协方差初始化会影响收敛——消融实验里明确观察到这一点。如果初始高斯过于扁平或过于细长，投影后的 2D 椭圆在早期训练中就会数值不稳，梯度信号被污染，致密化机制可能在错误的位置增删基元。

三 · 逐像素 alpha 混合与排序：并行的边界在哪

排序之后的混合阶段是纯并行的：每个像素独立地沿深度顺序累加颜色与透射率，像素之间没有依赖。这正是光栅化相对于体渲染的优势——NeRF 类方法每像素要沿射线采样几十上百个点，每个点都要过一遍 MLP，计算量随采样数线性增长；而 3DGS 每像素只处理投影后覆盖它的那些高斯，且每个高斯的贡献是解析的指数衰减，没有网络前向。

但“纯并行”有一个前提：深度顺序必须已经确定。排序是全局操作，数百万个高斯按视图空间深度排一次序，这个操作无法在像素级并行中完成。实现上通常把排序放在 GPU 的并行基数排序里，按深度量化为若干位的关键字，然后每个像素的混合线程按排序后的索引遍历。这里的系统代价是排序的带宽：每帧都要把全部高斯的深度关键字写入显存再读出，基元数越多，这笔开销越大。对于数百万高斯的场景，排序本身可能占用帧时间的一个可观比例。

混合公式的数值行为也值得注意。透射率乘积 ∏(1-α_j) 在深度方向上单调递减，当累积不透明度接近 1 时，后面的高斯贡献被指数级压制。这意味着位于场景深处的高斯即使参数错误，对最终图像的梯度贡献也很小，训练信号会被前层遮挡“吃掉”。这是 alpha 混合的固有性质，也是为什么致密化要依赖梯度而不是单纯依赖重建误差——梯度大的位置说明该处的前层透射率还没有饱和，仍有信息可学。

一个具体的失败模式是薄结构。一片栏杆或一根细线，在投影后只覆盖极少数像素，如果排序或混合的粒度不够细，这些像素的 alpha 累积会出错，表现为结构断裂或闪烁。消融实验里致密化与剪枝对薄结构的影响被单独列出，原因就在这里：薄结构需要足够多的小高斯以正确的深度顺序叠加，任何一步的粒度损失都会直接反映为几何瑕疵。

四 · 可微光栅化：梯度如何穿过排序

训练要求整条流水线可微，但排序是一个离散操作，本身不可微。3DGS 的处理方式是：排序只决定求和的顺序，不参与梯度计算。梯度从最终颜色 C 出发，沿混合公式对每个参与的高斯参数求偏导——对颜色 c_i、不透明度 α_i、以及通过 Σ' 间接影响 2D 衰减的位置与协方差参数。排序顺序在反向传播中被视为常数，因为改变顺序对应的是基元的离散重排，不是参数的连续变化。

这个设计在实践中有微妙之处。排序依赖于高斯的均值 μ，而 μ 是可学习的。当 μ 在训练中移动时，排序可能在某一步发生交换，导致混合公式的求和顺序突变，梯度信号出现不连续。这不是理论上的瑕疵，而是训练中真实存在的噪声源：两个深度接近的高斯在排序边界附近反复交换，会让它们的梯度方向抖动。实现上通常不去显式处理这个问题，而是依赖学习率和致密化的平滑性来吸收它。

反向传播的计算量与前向相当，因为每个像素的混合链都要回传。公式上，对第 i 个高斯的颜色梯度正比于 α_i 乘以前序透射率，对不透明度的梯度则涉及该高斯之后的全部项。这意味着反向传播的访存模式与前向的排序顺序一致，缓存友好，但也意味着显存中要保留前向的中间量（每个像素的透射率链）或者重算。这是训练显存开销的另一个来源，与基元数增长叠加在一起。

伪代码层面的思路是：前向对每个像素维护一个累积颜色与累积透射率，遇到覆盖该像素的高斯就更新两者；反向则从最终颜色出发，按相反顺序遍历同一批高斯，用保存的透射率值计算各参数的梯度并原子累加到全局梯度缓冲。原子累加是必要的，因为一个高斯会覆盖多个像素，多个像素的梯度要汇总到同一个参数上。这个原子操作的争用程度随高斯在屏幕上的覆盖面积增长，是训练吞吐的隐性瓶颈。

五 · 致密化与剪枝：每 100 步的自适应调度

初始的 SfM 点云远不足以表达细节，致密化机制负责在训练中增删基元。调度是固定周期的：每 100 步检查一次，依据是两个信号——位置梯度的大小与高斯自身的尺度。位置梯度大的区域说明该处的几何没有被现有基元充分表达，需要更多基元；高斯过大的则说明它覆盖了不该覆盖的区域，需要拆分。

具体机制分两种操作。split 针对高梯度但尺度较大的高斯：把它拆成两个更小的高斯，位置在原有分布内采样，缩放按比例缩小。clone 针对高梯度但尺度较小的高斯：复制一份并沿梯度方向微移，相当于在细节密集处增加采样密度。剪枝则针对不透明度低于阈值的高斯，以及在世界空间中尺度过大的高斯——前者是几乎不贡献颜色的冗余基元，后者是错误地跨越了多个物体的“幽灵”高斯。这套增删规则没有学习率，是硬编码的启发式，但消融实验显示它对薄结构与背景的重建质量有实质影响。

这套调度的系统代价是显存与算力的非线性增长。致密化在训练早期增长最快，因为梯度信号遍布全图；随着训练收敛，增删趋于平衡。但基元数的峰值往往出现在训练中段，此时显存占用最高，排序与混合的开销也最大。一个场景通常 30–60 分钟的训练时间，很大程度上由这个增长曲线决定：早期致密化快，后期主要是参数微调。如果初始点云过于稀疏，致密化会在早期疯狂增点，显存峰值更高；如果初始点云过密，剪枝会先删掉一批，训练反而更稳。

失败模式在这里很直观。剪枝阈值设得过高，薄结构会被误删，画面出现空洞；设得过低，冗余基元堆积，显存爆掉且渲染变慢。split 与 clone 的判据如果只看梯度幅值而不看尺度，会在纹理丰富但几何平坦的区域过度增点，产生大量几乎共面的高斯，它们对视角变化的响应错误，表现为高光处的闪烁。消融实验里球谐阶数影响高光，正是同一个问题的另一面：视角相关效果需要足够的高阶球谐来表达，但高阶球谐也让每个基元的参数更多、训练更慢。

六 · 参数分组与初始化：谁在什么时候被更新

3DGS 的训练把参数分成几组，各自用不同的学习率。位置 μ 的学习率随训练进程衰减，因为早期需要大幅移动基元到正确位置，后期只需微调；协方差参数（旋转与缩放）用另一组学习率，通常更小，因为几何形状的调整比位置更敏感；颜色（球谐系数）与不透明度又各自一组。这种分组不是装饰性的：如果位置与协方差不解耦，早期的大步长位置更新会带着错误的协方差一起抖动，投影出的 2D 椭圆在屏幕上乱跳，梯度信号无法收敛。

初始化来自 SfM 稀疏点云。每个点给一个初始均值，协方差初始化为各向同性且尺度与最近邻点距离相关，不透明度取一个中间值，球谐系数置零（即只用零阶的直流颜色）。这个初始化的质量直接决定收敛速度：如果 SfM 点云在某些区域缺失（例如纹理弱的墙面），该区域在训练初期没有任何基元，梯度为零，致密化也无从触发，最终表现为重建空洞。这是稀疏视图几何不稳的一个具体来源——不是优化失败，而是初始支撑不足。

球谐阶数是一个显式的容量旋钮。零阶只能表达与视角无关的颜色，一阶开始有方向性，更高阶才能表达高光与反射的方向变化。消融实验确认阶数影响高光区域的质量。代价是每个高斯的系数数量随阶数平方增长，显存与反向传播的计算量同步上升。对于以漫反射为主的场景，低阶足够；对于有金属或玻璃的场景，低阶会把高光抹平，表现为材质感丢失。这是“透明与反射建模弱”这一局限在参数层面的根源之一，不是渲染环节的缺陷。

把这几组合在一起看，整个系统的工程判断就很清楚：3DGS 的实时性来自显式基元与解析投影，可训练性来自可微光栅化与排序解耦，自适应性来自固定周期的致密化调度，而所有这些的代价都汇聚到显存与排序带宽上。一个场景能否在目标硬件上跑起来，取决于基元数的峰值是否落在显存预算内，以及排序的带宽是否被基元数压垮。这两个量在训练开始前就可以从 SfM 点云密度和场景复杂度做出粗略估计，而不是等到训练中途显存溢出才发现。
