一 · 一个卡在 800 面上的现场

设想一条真实的生产链路：美术在 DCC 里雕了一个高模，几十万面，细节到位但拓扑混乱；下游要把它塞进引擎、做 LOD、做骨骼绑定、做碰撞。工程上需要的不是那个高模，而是一个面数可控、四边面为主、边流向合理的“艺术家网格”。过去这一步靠人重拓扑，一个角色几个小时到几天。MeshAnything 这类工作的目标就是把这一步交给自回归模型：输入形状（点云或隐式表示），输出一个面片序列，逐 token 解码成网格。

问题出现在预算上。MeshAnything 的序列化方式把每个面片写成三个顶点 token，一个面三个 token，序列长度与面数成线性关系，系数是 3。自回归 Transformer 的上下文长度是硬约束，训练时的显存与注意力计算也随长度增长。当上下文被固定在某个量级时，能表达的面数就被钉死在 800 面左右。800 面对于硬表面道具尚可，对于一个有五官、有褶皱、有装备分件的角色就是灾难：模型被迫用极少的面去逼近复杂形状，结果是大块塌陷、细节消失、拓扑在关节处崩坏。

这不是“模型不够大”的问题，而是“表示不够紧”的问题。同样一笔上下文预算，如果每个面只花一个多 token 而不是三个，能表达的面数就翻倍。MeshAnything V2 的全部动机就压在这一句话上：先把序列变短，再谈生成更复杂的网格。它给出的答案是相邻网格 tokenization（AMT），把序列长度压到约一半，在同等预算下把输出面数从 800 提到 1600。

二 · 逐面三顶点的编码代价从哪里来

要理解痛点，必须看清顶点 token 序列（VTT）的结构。一个三角网格由顶点集合与面集合组成，面是顶点的三元组。最直白的序列化是把每个面写成它的三个顶点索引，形如 (v1,v2,v3),(v4,v5,v6),…。这种写法有一个致命冗余：网格是连通的，相邻面共享边，一条边被两个面共用，于是这条边上的两个顶点被编码了两次；在顶点扇周围，一个顶点会被它所有的邻面反复引用，度越高重复越多。

把冗余量化。设网格有 F 个面、V 个顶点、E 条边。三角网格满足欧拉关系与面边计数：每条边被两个面共享，每个面三条边，故 3F=2E；平均顶点度约为 2E/V。VTT 的序列长度是 3F 个 token。而真正需要被“新写出来”的信息量是顶点数 V 加上面之间的连接关系。对于艺术家网格这种以四边面为主、三角化后度分布较均匀的网格，V 与 F 大致同阶，于是 3F 与“F 加少量连接信息”之间存在接近三倍的差距。AMT 把这个差距砍掉一半左右，落到约 1.5F 的量级。

$$\mathrm{AMT}(\mathcal{M})=\big(t_1,\ldots,t_N\big),\qquad |\mathrm{AMT}(\mathcal{M})|\approx \frac{1}{2}|\mathrm{VTT}(\mathcal{M})|$$

公式写的是结果，机制在过程里。AMT 的核心观察是：如果下一个面与上一个面共享一条边，那么这条边的两个端点已经在序列里出现过了，不需要重新编码，只需要写出这个面的第三个新顶点，外加一个指明“从哪条已有边生长出去”的局部选择。于是每个面摊到的 token 数从 3 降到约 1 到 2 之间，具体取决于该面是否与前一帧相邻、共享边在局部环上的位置。序列因此变成一条沿着网格表面游走的“面片路径”，而不是一张平铺的面片清单。

这个机制带来一个直接的系统代价：序列不再是位置无关的集合，而是有顺序的路径。顺序一旦确定，模型就必须学会在“当前边的哪一侧生长”这种局部几何决策上做选择，解码器也必须维护一个随位置更新的边表。换句话说，省下来的 token 预算被换成了状态维护的复杂度。工程上这不是免费的：解码时每生成一个面，都要在已构建的半边结构里查找共享边、判断朝向、避免重复面。序列短了，但每一步的逻辑重了。

三 · 为什么“把模型做大”救不了这个现场

面对 800 面的天花板，最直觉的反应是加大上下文、加大模型。这条路在自回归网格生成上走不通，原因有三层，且都是结构性的。

第一层是注意力成本。标准自注意力的计算量与显存随序列长度呈二次增长。把上下文从能容纳 800 面翻到能容纳 1600 面，序列长度翻倍，注意力矩阵规模变为四倍。训练时这是显存墙，推理时这是延迟墙。逐 token 解码意味着生成 1600 面要跑约 2400 个 token 的自回归步（按 AMT 折算），每步都要对全序列做注意力，长上下文的解码时间被放大到不可接受。

第二层是数据效率。序列越长，序列内部的长程依赖越稀疏：第一个面与第两千个面之间的几何关系几乎不可学习。模型在长序列上要维持全局一致性，但监督信号只告诉它下一个 token 是什么。长度增加并不自动带来表达力增加，反而稀释了每个 token 的学习信号。这就是为什么单纯放大上下文往往得到“面数上去了、质量下来了”的结果。

第三层是拓扑合法性。自回归解码是逐面追加的，每加一个面都可能产生非流形边、重复面、朝向翻转、孤立顶点。序列越长，累积错误的机会越多，而错误一旦发生就无法回退——解码器没有全局修复机制。800 面时这类错误尚可被后处理勉强收拾，1600 面时错误密度上升，后处理的成功率下降。论文把“拓扑合法性仍需检查”列为局限，正是这一层的直接体现。

用一个具体例子把三层叠起来看：一个带披风与腰带的角色，高模三角化后约 5 万面。要在 1600 面预算内表达，披风的褶皱需要连续的四边形带，腰带需要闭合的环状拓扑，肩部需要过渡的边流。VTT 在 800 面预算下根本排不下这些结构，模型只能二选一：要么丢掉披风细节，要么让腰带断开。加大上下文到能排 1600 面，注意力成本翻四倍，而模型仍然缺乏“记住腰带是个环”的长程机制，解码到腰带末端时早已忘记了起点。问题不在容量，在表示的紧致度与局部性。

四 · 相邻面共享边这一事实被浪费了

把痛点归结成一句可操作的判断：网格的局部性是天然的压缩先验，而 VTT 完全无视它。网格不是点集，是一个二维流形（在理想情况下），每个面与邻居通过边相连，信息在局部高度相关。一个面片的三个顶点，绝大多数情况下至少有两个来自邻居。VTT 把每个面当作独立三元组重写一遍，等于把这份局部相关性扔掉了。

AMT 把这个先验显式化。它的序列化伪代码思路可以写成：从任意一个种子面开始，写出它的三个顶点；然后每一步，在当前已生成的面片集合的边界上选一条边，写出该边对应的新顶点，形成一个与已有面共享该边的新面；重复直到覆盖整个网格。写成流程是：

  • 初始化：选种子面，压入三个顶点 token，建立半边表；
  • 循环：在边界边上按某种确定性顺序选一条边 e=(a,b)；
  • 写出新顶点 c 的坐标 token，形成面 (a,b,c)；
  • 更新半边表，把 e 标记为已用，把 (b,c)、(c,a) 加入边界；
  • 终止：边界为空或达到面数上限。

关键在“选哪条边”这一步。它必须是一个确定性的、可由序列本身复原的规则，否则解码器无法从 token 流里恢复出同样的遍历顺序。这一步的选择策略直接决定了序列长度：如果总是沿着当前面的邻边深度优先游走，共享边的命中率高，每面摊到的 token 少；如果在边界上跳跃，共享边命中率下降，token 数回升。AMT 的约一半压缩比，正是这类局部游走策略在艺术家网格上取得的平均效果。

这里有一个容易被忽略的失败模式：当网格存在非流形结构、边界洞、或分离的连通分量时，单条游走路径无法覆盖全部面片。序列化必须处理“跳转”——从一个连通分量跳到另一个，或从一条边界跳到另一条边界。每次跳转都要额外编码目标位置，压缩比在这些区域退化。艺术家网格里常见的分离部件（眼睛、牙齿、扣子）正是这类退化点。这也是为什么论文把拓扑合法性单列为局限：AMT 假设网格近似流形，而真实资产并不总是满足。

五 · 同等预算下的账：800 到 1600 意味着什么

把压缩比换算成工程账。设上下文预算为 L 个 token。VTT 下可表达的面数约为 L/3；AMT 下约为 L/1.5，即约两倍。论文给出的结果是从 800 面提到 1600 面，这与“序列长度约减半、面数翻倍”的换算一致。这不是靠更大的模型或更长的上下文换来的，而是靠同一份预算装下更多面。

维度逐面三顶点（VTT）相邻网格 token（AMT）
每面 token 数3约 1–2，均值约 1.5
同等预算面数8001600
序列结构面片清单，位置无关沿表面游走的面片路径
解码状态无，直接拼三元组需维护半边表与边界
主要失败模式面数不够，细节塌陷跳转退化、非流形、朝向错误

1600 面在实践中的意义要具体看。对于硬表面道具、家具、机械零件，1600 面足以表达主要倒角与分件，是可用的基线。对于角色，1600 面仍然紧张，但已经从“完全不可用”跨到“可作为低模底稿、再手工细化”的门槛。论文把“生成 1600 面网格”确立为可用基线，这句话的分量在于：它把任务从“玩具级面数”推进到了“生产链路可接手”的区间。后续 PartCrafter 等工作借鉴其效率思想，也是因为这条基线让自回归网格生成第一次具备了工程讨论的价值。

代价同样要记在账上。AMT 把预算效率提上去了，但没有解除序列长度限制：1600 面仍是上限，细节上限仍在，拓扑合法性仍需检查。换句话说，这一版解决的是“同样的钱买更多面”，不是“钱不够”这件事本身。理解这一点，才能理解后续部分为什么要继续在 tokenization、形状条件、以及解码约束上做文章。

六 · 基线对照：MeshAnything 与 MeshGPT 的痛点定位

论文的基线是 MeshAnything 与 MeshGPT。两者都走自回归路线，都把网格变成 token 序列，都在面数预算上撞墙。MeshGPT 的思路更接近“学一个网格的离散表示再生成”，其序列同样随面数线性增长；MeshAnything 则把形状条件引入，用形状编码器约束生成，但序列化仍是逐面三顶点。AMT 改的不是生成范式，而是序列化本身——形状编码器保留，自回归 Transformer 保留，解码器还原网格的流程保留，唯独把面片序列的写法换掉。

这个定位很重要，因为它说明痛点的根源不在“模型不会生成网格”，而在“网格被写成了浪费的字符串”。同一套架构，换一种写法，预算效率翻倍。这也是为什么论文的消融要对比 AMT 与逐面 token、面数上限、形状编码三项：前两项直接检验序列化与预算的因果，第三项检验形状条件是否仍是必要的约束。工程判断上，这意味着如果你已经有一套自回归网格管线，AMT 是一个可以局部替换的模块，而不需要重训整个范式。

但替换不是无痛的。逐面 token 的解码器是无状态的，读到三个索引就拼一个面；AMT 的解码器是有状态的，必须按序列顺序重建半边表，并在每一步验证新面与已有边的邻接关系。状态带来的失败模式是级联的：一个朝向判断错了，后续所有依赖该边的面都会错位，最终输出非流形或自交。这就是为什么“拓扑合法性仍需检查”不是一句客套话，而是 AMT 解码器结构决定的必然检查项。工程上必须配一个后处理或校验环节，把解码出的网格过一遍流形性、朝向一致性、重复面检测，才能进入下游。

把这一部分的落点收在一个具体机制上：AMT 的压缩来自“共享边不重写”，它的风险也来自“共享边必须被正确识别”。序列变短的那一刻，解码器从无状态拼接变成了有状态生长，预算效率与拓扑正确性被绑在同一根边上。这条边是否被正确匹配、朝向是否一致，决定了 1600 面是可用基线还是一堆需要返工的碎片。
