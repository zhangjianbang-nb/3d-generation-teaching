一 · 序列长度与自回归误差累积：从 token 预算到解码预算

把网格送进自回归 Transformer 之后，系统瓶颈首先从显存转移到序列长度。一个三角面由三个顶点坐标构成，若按顶点逐个离散化，一个中等复杂度的物体很容易产生数万级 token；MeshAnything V2 的相邻网格 tokenization 之所以关键，是因为它把相邻面共享的顶点信息折叠进单个 token 的局部上下文，使序列长度相对逐顶点方案压缩一个量级。这不是单纯的压缩技巧，而是改变了注意力的代价结构：标准注意力的计算量随序列长度平方增长，KV 缓存随长度线性增长，解码步数等于序列长度。序列压缩一个量级，意味着解码步数、缓存占用和每步的注意力开销同时下降，工程上才具备批量生成重拓扑网格的可能。

误差累积的机制与序列化解码同构。自回归模型在每一步以已生成 token 为条件预测下一个 token，一旦某个 token 预测出拓扑上非法的连接（例如一个面引用了不存在的顶点、或三个顶点共线导致退化三角形），后续 token 只能在这个错误上下文上继续，错误不会被局部纠正，而是被固化进序列。形式化地，若每步的条件分布为 \(p_\theta(x_t \mid x_{<t})\)，序列概率为

$$p_\theta(x_{1:T}) = \prod_{t=1}^{T} p_\theta(x_t \mid x_{<t})$$

早期步骤的偏差会通过条件链放大，这与长序列语言模型中的曝光偏差是同一类问题，但后果更硬：语言模型输出病句仍可读，网格输出非法连接则直接导致网格无法进入管线。工程上的缓解手段包括在解码时施加拓扑合法性约束（禁止引用未定义顶点、禁止重复面）、用 beam search 保留多个候选序列并按合法性重排、以及在训练时注入带噪声的前缀以模拟推理期的错误上下文。这些手段都有代价：约束解码会降低采样多样性，beam search 成倍增加解码开销，噪声注入会拉低干净样本上的似然。

一个具体例子：对一个含数千面的输入网格做重拓扑，若序列长度在万级，单条序列的解码在消费级 GPU 上需要可感知的等待；批量生成多个候选时，KV 缓存成为显存主导项，而非模型权重。失败模式是解码到后段时缓存溢出或被迫截断，截断的序列对应一个拓扑不闭合的网格，重拓扑结果不可用。系统设计上因此需要把“序列预算”当作一等公民：在 tokenization 阶段就控制面数与顶点复用率，在解码阶段设定最大长度与合法性回退策略，而不是把长度问题留给推理时被动处理。

二 · 拓扑合法性与水密性：合法性判定、修复代价与失败模式

拓扑合法性不是单一指标，而是一组可判定的约束：流形性（每条边至多被两个面共享）、朝向一致性（相邻面法向一致）、无自交、无退化面、水密性（闭合曲面无边界边）。这些约束在 token 序列上并不天然成立，因为序列化把网格拆成离散符号，模型学的是符号共现分布，而不是全局拓扑不变量。于是系统必须在解码后增加一个合法性验证与修复环节。验证可以用半边数据结构遍历：对每个面插入三条有向半边，检查每条无向边的两个方向是否成对出现；成对则内部边，单侧出现则边界边；若某条无向边出现超过两次，即为非流形边。

修复的代价随缺陷类型分化。小的边界缺口可以通过补洞三角化处理，代价是局部面数增加；非流形边需要拆分顶点或删除冗余面，可能改变局部几何；自交检测与消除的计算代价最高，通常需要空间加速结构做三角形对相交测试，复杂度与面数和对数因子相关。工程判断是：把合法性验证放在重拓扑输出之后、进入下游管线之前，作为硬门槛；修复只做保守操作（补洞、删退化面），不做全局重算，因为全局重算等于放弃生成结果。

失败模式有两类值得单独指出。第一类是“表面合法、语义错误”：网格水密且流形，但部件之间的连接关系荒谬，例如椅腿与座面之间生成了一条本不该存在的桥接面，拓扑检查通过而语义检查失败。第二类是“局部修复引入新缺陷”：补洞三角化在狭窄缺口上产生细长三角形，后续做细分或布尔运算时数值不稳定。这两类失败说明合法性指标必须与几何质量指标联合使用，单看水密性会给出虚假的安全感。

具体例子：MeshAnything 系列的目标是把任意输入网格重拓扑为艺术家级网格，其输出需要满足面数可控、边流向合理、四边面主导等特征。若输出中存在一条被三个面共享的边，导入 DCC 工具时通常触发非流形警告，后续的 UV 展开与法线烘焙会失败。系统层面的应对不是让模型“学会”流形性，而是在 tokenization 的词表与解码约束中编码局部合法性，再用后验验证兜底。这是生成系统与几何处理系统交界处的典型分工：模型负责分布，规则负责不变量。

三 · 部件语义与铰接关系：组合式生成的系统接口与评测盲区

PartCrafter 把物体拆成有语义的部件，用组合式潜变量扩散一次生成多个部件。这里的系统瓶颈从“单网格合法性”转移到“部件间关系”。组合式生成的核心机制是为每个部件维护独立的潜变量，并在去噪过程中通过共享的全局上下文或部件间注意力交换信息，使得各部件在同一坐标系下对齐、尺度协调、接触面匹配。形式化地，若部件潜变量为 \(z_1,\dots,z_K\)，联合去噪可写为对联合分布 \(p(z_1,\dots,z_K \mid c)\) 的采样，条件 \(c\) 包含全局形状与部件语义标签；实现上通常分解为

$$p(z_1,\dots,z_K \mid c) \approx \prod_{k} p_\theta(z_k \mid c, \{z_j\}_{j \neq k})$$

并在每步去噪时用近似条件替换精确联合，代价是部件间一致性的近似误差。这个近似在部件数量增加时误差累积：每个部件的条件依赖其他部件的当前噪声估计，早期去噪步的部件边界不稳定，后期难以收敛到紧密贴合的接触面。

铰接关系是更深一层的问题。门、抽屉、关节类物体不仅要求部件分割正确，还要求铰链轴位置、运动自由度、部件间的父子关系正确。当前组合式生成主要产出静态部件分解，铰接参数通常需要额外的预测头或后处理拟合。评测上的盲区在于：部件分割指标（如按语义标签的 IoU）无法反映铰接正确性，而铰接正确性又缺少统一的自动度量，往往依赖人工检查或下游物理仿真中的稳定性测试。系统代价是评测管线必须引入仿真或运动学验证，成本远高于纯几何指标。

具体例子：生成一个带抽屉的柜子，部件级扩散可能正确分出柜体、抽屉面板、把手，但抽屉面板与柜体的接触面若存在微小穿插，导入引擎后做刚体仿真会立即产生穿透抖动；若铰链轴被预测在面板几何中心而非边缘，抽屉无法旋转。失败模式是“部件对、关系错”，这类失败在只看渲染图的评测中不可见，只有把部件放进带运动约束的场景才暴露。工程判断是：部件生成的评测必须包含关系层指标，且这些指标应尽量可自动计算，例如接触面法向一致性、铰链轴与部件边界的距离分布、运动自由度与语义标签的匹配率。

四 · 与生成大模型的接口标准化：表示、坐标系与资产契约

网格生成不是孤立模块，它要接在 3D 大模型的输出之后、游戏或影视管线之前。接口标准化的第一个问题是表示选择：上游等值面提取输出的是稠密三角汤，重拓扑模块期望的输入是带朝向的网格，下游引擎期望的是带 UV、法线、材质槽和 LOD 层级的资产。三者之间的转换若没有契约，就会出现“能生成但不能进管线”的断裂。契约至少应规定：坐标系手性与单位、面朝向约定、顶点焊接容差、UV 是否存在及展开方式、材质槽命名规则、面数上限与四边面比例目标。

第二个问题是接口的失败传播。上游等值面网格若存在自交或非流形边，重拓扑模型会把缺陷当作输入分布的一部分，输出可能继承或放大这些缺陷。系统设计上应在模块边界设置输入验证：检查输入是否水密、是否流形、面数是否超出模型训练分布；不满足时要么拒绝，要么先做预处理修复。拒绝策略需要与上游协商回退路径，例如降低等值面分辨率重新提取，而不是把非法输入静默送进重拓扑。

第三个问题是资产契约的可测性。面数可控、拓扑干净、艺术家可编辑这些目标需要转化为可自动检查的条目：面数区间、非流形边计数、边界边计数、退化面比例、四边面占比、UV 重叠率。每条都应有阈值和失败时的处置动作。系统代价是这些检查增加管线延迟，但相比下游返工，延迟是更便宜的代价。失败模式是契约只写在文档里而没有自动检查，导致生成资产在批量导入时才暴露问题，定位成本高。

具体例子：MeshAnything V2 的相邻 tokenization 改变了输出序列的局部结构，若下游工具假设输出是逐顶点索引流，解析器会错位。接口标准化要求 tokenization 方案与解析器版本绑定，并在资产元数据中记录生成器版本与 tokenization 方案标识。这是工程上容易被忽略但直接决定可复现性的一环。

五 · 评测指标：几何、拓扑、语义与可用性的分层度量

评测不能只用单一指标。合理的分层是：几何层度量生成表面与参考表面的偏差，常用 Chamfer 距离与法向一致性；拓扑层度量流形性、水密性、面数、四边面比例、边流向规则性；语义层度量部件分割与标签正确性；可用性层度量导入下游工具的成功率、UV 展开成功率、绑定与仿真通过率。每层指标对应不同的失败模式，混在一起会掩盖问题。

层级指标对应失败模式系统代价
几何Chamfer 距离、法向一致性表面偏移、细节丢失需参考网格，采样成本
拓扑非流形边计数、边界边计数、面数、四边面占比无法进管线、细分失败半边遍历，近线性
语义部件 IoU、标签匹配率部件错分、关系错误需部件级标注
可用性导入成功率、UV 成功率、仿真通过率资产不可用需真实管线回归

指标之间的张力需要显式处理。面数越低越可控，但过低会损失几何细节，Chamfer 距离上升；四边面占比越高越利于细分与动画，但强制四边化可能引入非流形或自交。评测报告应给出指标向量而非标量总分，让选型者按管线需求加权。形式化地，可用性可以定义为多层约束的合取：

$$\text{Usable}(M) = \mathbb{1}[\text{manifold}(M)] \cdot \mathbb{1}[\text{watertight}(M)] \cdot \mathbb{1}[\text{faces}(M) \leq F_{\max}] \cdot \mathbb{1}[\text{uv}(M)\ \text{valid}]$$

合取意味着任一条件失败即整体不可用，这与管线现实一致：非流形网格不会因为 Chamfer 距离低而变得可用。失败模式是指标被单独优化：模型在 Chamfer 距离上进步，但非流形边计数上升，评测若只报前者会误导选型。工程判断是：把合取式可用性作为主指标，几何与语义指标作为诊断项。

六 · 开放问题与下一步：长序列、部件关系与评测基础设施

开放问题集中在三处。其一是长序列与误差累积的联合治理：相邻 tokenization 压缩了长度，但没有消除自回归的条件链；下一步需要在解码期引入更强的拓扑约束与可回退的局部重采样，而不是单纯增大模型或延长训练。其二是部件语义与铰接关系的联合生成：PartCrafter 的组合式扩散解决了“一次生成多个部件”，但铰接参数、运动约束与部件间接触面的精确匹配仍未纳入同一生成过程；CraftsMan3D 的交互式几何精修补足了拓扑，但交互意味着人工介入，规模化评测与自动化管线之间仍有缺口。其三是评测基础设施：可用性指标依赖真实管线回归，成本高、难并行；需要把导入、UV、仿真等检查封装成可批量运行的服务，并固定随机种子与版本标识以保证可比性。

下一步的工程判断是：把生成系统的边界画清楚。模型负责在训练分布内产出高概率的网格序列与部件分解，规则层负责拓扑不变量、资产契约与可用性门槛，评测层负责分层度量与失败归因。三者之间的接口应以可自动检查的条目固定下来，而不是靠文档约定。一个具体机制是：在重拓扑输出后立即运行半边遍历与面数统计，失败则触发局部重采样或回退到保守修复；在部件输出后运行接触面法向一致性与铰链轴距离检查，失败则标记为需人工复核。这些机制不追求让模型学会所有约束，而是把不可学习的硬约束交给确定性代码，把可学习的分布交给模型。系统代价是管线变长、延迟增加，但换来的是生成资产可被批量验证、失败可被定位、版本可被复现——这正是网格、拓扑与部件生成从演示走向生产的分界线。
