一 · 迭代扩场景的工程瓶颈：误差累积与位姿漂移

Text2Room 式的迭代式场景网格补全，把「生成一个房间」拆成「生成当前视角的一帧 → 修补深度与纹理 → 反投影成网格 → 移动到下一个视角继续补」。这条流水线的工程本质是一个闭环反馈系统：每一轮的输出（当前网格与相机位姿）既是下一轮的输入，也是下一轮误差的来源。真正决定系统能否走远的，不是单帧生成质量，而是这个闭环里误差如何被放大。

具体机制上，每一轮包含三个耦合步骤：给定当前相机位姿渲染已有网格得到已知区域；对未观测区域用 2D 修补模型生成 RGB 与深度；把新像素按估计深度反投影并融合进全局网格。融合通常依赖截断符号距离场（TSDF）式的加权平均，权重随观测角度与深度置信度衰减。问题在于，深度由单目估计或扩散模型隐式给出，其尺度与真实几何存在系统性偏差；当相机沿轨迹前进时，新视角的位姿若由相邻帧匹配估计，偏差会以随机游走方式累积。

$$\sigma_{T}^{2}(n)\approx\sum_{k=1}^{n}\left(\sigma_{p}^{2}+\sigma_{d}^{2}\,\|\mathbf{t}_{k}-\mathbf{t}_{k-1}\|^{2}\right)$$

上式给出一个定性判断：位姿噪声 $\sigma_p$ 与深度噪声 $\sigma_d$ 随步数 $n$ 线性叠加，位移越大放大越明显。这意味着「走十步」和「走一百步」不是同一类问题——前者是生成质量问题，后者是几何一致性问题。失败模式很具体：绕房间一周回到起点时，墙面出现双层重影，地板高度错位，门框不再闭合。这类闭环不一致无法靠提高单帧分辨率修复，只能靠全局优化（回环检测、位姿图优化、网格重投影对齐）来压制。

系统代价体现在两处。其一是显存：全局网格与纹理图集随覆盖面积增长，纹理分辨率若按每平方米固定像素数分配，一个多层建筑很快撑爆单卡。其二是算力：每一轮都要跑一次 2D 生成模型，步数与场景面积成正比，且回环优化需要反复重算，延迟不可预测。工程上的典型折中是限制单次会话的漫游半径，把长距离一致性交给离线后处理，代价是牺牲「边生成边漫游」的交互感。

二 · 高斯泼溅扩展的实时性账本：带宽、排序与显存

WonderWorld 用高斯泼溅做场景外扩，把「可漫游」从离线网格推进到实时渲染。高斯泼溅的表示是一组带位置、协方差、不透明度与球谐颜色的各向异性高斯核，渲染时按深度排序后做 alpha 混合。它的优势在于渲染是显式的、可并行的，不需要神经网络的逐点查询；代价则集中在三本账上：排序、带宽、显存。

排序是每帧都要做的全局操作。随着场景外扩，高斯核数量从数万增长到数十万乃至更多，每帧按视角深度重排的复杂度是 $O(N\log N)$，且排序结果与相机位置强相关，无法跨帧复用。带宽账更隐蔽：每个高斯核要读取位置、协方差（通常存为四元数加缩放）、不透明度与球谐系数，球谐若用三阶则每核数十个浮点数；当核数量达到十万量级，每帧的顶点级读取量已接近中端 GPU 的带宽上限，帧率对分辨率与核数量的乘积敏感。

$$B_{\text{frame}}\approx N\cdot\left(b_{\text{geom}}+b_{\text{sh}}\right)\cdot f$$

其中 $b_{\text{geom}}$ 为几何属性字节数，$b_{\text{sh}}$ 为球谐系数字节数，$f$ 为帧率。这个式子说明：想同时要「大场景」和「高帧率」，必须压缩单核属性或做层次化剔除，而不是单纯增加核数。

具体例子是场景外扩时的「新区域生成」：当相机看向未观测方向，系统需要用单图生成模型补出新视角的内容，再把新像素提升为高斯核并入全局集合。这里有两个失败模式。第一，新生成区域与已有区域的接缝处，高斯核的深度与不透明度不匹配，表现为一条可见的「雾带」或突然的遮挡跳变。第二，随着核集合增长，显存占用线性上升，而实时漫游要求常驻显存，工程上只能靠核剪枝（剔除低不透明度、远距离、被遮挡的核）来换取容量，剪枝策略不当会在回看时丢失细节。这就是「实时可漫游」的真实代价：它不是免费的渲染升级，而是把几何一致性问题的战场从网格搬到了核集合的管理上。

三 · 文本到可穿越世界与代码化场景：可控性与可验证性

WorldGen 走的是文本直接到可穿越世界的路线，SceneCraft 走的是 LLM 生成 Blender 代码的路线。两者在工程上代表两种截然不同的可控性模型：前者是「生成即世界」，后者是「程序即场景」。

WorldGen 的机制核心是把文本解析为地形、物体布局与可行走区域的约束，再生成带碰撞语义的几何。它的优势是端到端、无需人工建模；代价是可控性弱——文本里的「一条穿过森林的小路」在生成结果中是否真的可通行，取决于系统对可行走性的隐式建模，而非显式约束。失败模式是「看起来能走，走进去卡住」：视觉上地形连续，但碰撞体与渲染几何不一致，或坡度超出角色控制器阈值。

SceneCraft 的机制是把场景合成转化为代码合成：LLM 作为 agent 反复编写、执行、检查 Blender Python 脚本，通过渲染反馈修正布局。这条路线把「场景」变成可读、可 diff、可参数化的程序，可控性来自代码结构本身——物体位置是变量，材质是函数调用，布局约束是断言。系统代价是执行闭环的延迟：每次修改都要跑一次 Blender 渲染来验证，迭代轮数多，且 LLM 生成的代码存在 API 误用与几何退化（例如物体互相穿插、缩放为零）。失败模式是「代码能跑，场景不对」：脚本无报错但布局违反物理常识，需要额外的几何校验器兜底。

路线可控性来源主要系统代价典型失败模式
文本到可穿越世界隐式约束、端到端可行走性难以显式验证视觉连续但碰撞不一致
LLM 生成 Blender 代码代码结构、断言渲染验证闭环延迟脚本无错但布局失真

工程判断上，两条路线的分水岭在于「谁承担验证责任」。代码化路线把验证责任交给可执行的检查（渲染、几何断言），因此更适合需要精确布局与可复现的场景；端到端路线把验证责任交给生成模型，适合追求多样性与规模、但对精确性容忍度高的场景。两者都不是「更好」，而是把不确定性放在了系统的不同位置。

四 · 物理参数估计：视频驱动与真实性缺口

PhysDreamer 让生成物体具备可交互的物理属性，其机制是用视频生成模型作为「物理先验」：给定物体与外力作用，生成模型预测形变序列，再从序列反推材质参数（如杨氏模量、阻尼）。这条路线把物理参数估计从「手工标注」变成「从生成视频中蒸馏」，但真实性缺口也随之而来。

具体机制可以拆成三步：构造受力场景并渲染初始状态；用视频模型生成未来若干帧的形变；以可微物理仿真器为前向模型，最小化仿真轨迹与生成轨迹的差异来拟合参数。这里的目标函数是轨迹级匹配，而非单帧外观匹配，因此对参数的可辨识性有要求——若形变幅度太小或观测角度单一，多个参数组合会产生几乎相同的轨迹，拟合退化为病态问题。

$$\theta^{*}=\arg\min_{\theta}\sum_{t}\left\|\mathcal{S}_{\theta}(x_{0},f_{t})-\hat{x}_{t}\right\|^{2}+\lambda\,\mathcal{R}(\theta)$$

其中 $\mathcal{S}_\theta$ 是参数为 $\theta$ 的仿真器，$\hat{x}_t$ 是生成视频的第 $t$ 帧，$\mathcal{R}$ 是参数正则（例如把模量约束在合理区间）。失败模式有两类。第一类是「生成视频本身不守物理」：视频模型可能产生看似合理但能量不守恒的形变，拟合出来的参数只是在对一个错误轨迹做回归，交互时表现为物体「太软」或「抖个不停」。第二类是「参数不可辨识」：单一视角、单一受力方向下，刚度与阻尼的权衡无法分离，交互换一个方向就失真。

系统代价在于闭环成本：每次参数拟合都要多次前向仿真，仿真步长与网格分辨率直接决定算力；若要支持实时交互，物理参数还必须与碰撞检测、接触求解一起进入渲染循环，帧预算被进一步压缩。工程上的现实做法是离线拟合、在线查表：把常见材质的参数预先拟合好，交互时按语义标签检索，牺牲个性化换取实时性。这正是「物理真实性」与「交互实时性」之间的硬约束。

五 · 评测指标：几何、物理、交互三层缺一不可

场景生成的评测难点在于：没有一个指标能同时覆盖「看起来对」「几何一致」「能走进去」「推得动」。现有评测实践大致落在三层，每层都有明确的失效边界。

  • 几何层：用渲染新视角与真值的感知距离（如 LPIPS 类指标）、深度误差、网格 Chamfer 距离衡量。问题是这些指标对长距离一致性不敏感——局部视角都很像，回环处却错位，指标仍然好看。
  • 物理层：用仿真轨迹与参考轨迹的偏差、参数拟合残差衡量。问题是参考轨迹本身可能来自生成模型，形成「用生成评生成」的循环论证。
  • 交互层：用可行走区域覆盖率、碰撞穿透率、交互帧率衡量。问题是这些指标依赖具体角色控制器与硬件，跨系统不可比。

更根本的缺口是「一致性」缺少统一度量。长距离几何一致性需要一个跨视角的闭环误差定义，例如把相机轨迹闭合后的重投影偏差作为指标；但闭环轨迹的构造本身依赖系统，评测者难以中立地指定。物理真实性同样缺少地面真值：真实材质的参数测量成本高，生成物体的「正确物理」在语义上就没有唯一答案。

层级代表指标失效边界
几何新视角感知距离、深度误差、Chamfer对长距离回环错位不敏感
物理轨迹偏差、参数拟合残差参考轨迹可能来自生成模型
交互可行走覆盖率、穿透率、帧率依赖控制器与硬件，不可跨系统比较

工程判断是：评测应当分层报告，而不是压成一个总分。一个系统可以在几何层得分高、在交互层崩掉（渲染好看但碰撞体缺失），也可以物理参数拟合残差小而交互帧率不达标。把三层分开报告，才能定位瓶颈在生成、在表示、还是在运行时。

六 · 开放问题与下一步：把一致性做成系统属性

开放问题可以按「瓶颈在哪一层」来组织，而不是按论文列表罗列。

第一，长距离几何一致性。当前迭代式方法把一致性寄托在单轮生成质量上，但误差累积是闭环的结构性属性。下一步的工程方向是把一致性从「生成时祈祷」变成「运行时约束」：维护一个全局位姿图与网格重投影残差，当残差超过阈值时触发局部重生成或全局对齐，而不是无条件继续外扩。这需要系统具备「知道自己哪里不确定」的能力，即不确定性估计要进入流水线，而不只是输出一张图。

第二，场景规模与显存的矛盾。高斯泼溅的核集合与网格的纹理图集都随面积线性增长，而实时漫游要求常驻。可行的机制是层次化表示：远景用低分辨率核或隐式场，近景用高分辨率核，按相机距离动态换入换出；代价是切换时的 popping 与缓存管理复杂度。这个问题不解决，「可漫游世界」就只能停留在单房间尺度。

第三，物理参数的真实性。视频驱动的参数估计把生成模型当物理先验，但生成模型的物理正确性本身未被验证。下一步需要的是「物理可辨识性」的前置检查：在拟合前判断当前观测是否足以区分参数，不足则主动请求新的交互或视角，而不是硬拟合出一个病态解。这把主动感知引入了物理估计环节。

第四，交互与碰撞的实时性。渲染几何与碰撞几何的分离是当前系统的常见妥协：视觉上用高精度表示，碰撞上用简化体。失败模式是两者不一致导致的穿透或卡顿。工程上的方向是让碰撞体从表示中派生而非手工指定，例如从高斯核的不透明度与尺度推断占据区域，再生成凸包或 SDF；代价是派生过程本身要花算力，且派生结果随表示更新而漂移，需要版本化管理。

把这四条放在一起看，下一步的工程判断是清晰的：场景生成系统的竞争力不再取决于单帧生成模型的大小，而取决于它能否把「一致性、规模、物理、实时」四件事组织成一个可验证的闭环。评测的角色也随之改变——它不是事后打分，而是闭环里的传感器：几何残差、参数可辨识性、碰撞穿透率都应当作为运行时信号反馈给生成与优化环节。谁先把评测信号接进系统回路，谁就能把「生成一个世界」从一次性输出变成可持续维护的环境。
