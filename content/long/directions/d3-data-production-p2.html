一 · 资产来源路线：抓取式数据集与合成数据引擎

数据侧的第一条路线是抓取式：从公开互联网收集带标注的 3D 资产，形成大规模数据集。Objaverse 与 Objaverse-XL 是这条路线上的两个刻度——前者把可用资产组织到十万级，后者推到千万级。这条路线解决的是“有没有”的问题：模型预训练需要覆盖足够宽的物体类别、风格与拓扑，十万级资产在类别长尾上明显不够，千万级才勉强支撑起开放词表的文本到 3D 训练。抓取式路线的机制核心是标注管线：每个资产需要附带描述文本、类别标签、许可信息与几何统计，否则数据只是文件堆，无法参与条件生成训练。

抓取式路线的代价集中在三处。其一是许可与版权：公开可下载不等于可商用、可再分发，许可字段缺失或冲突的资产必须在训练前剔除，否则模型权重的合规性无法主张。其二是质量分布不可控：抓取资产在网格水密性、面数、UV 有无、材质完整性上高度异质，直接混合训练会让模型学到互相矛盾的先验。其三是长尾覆盖仍然稀疏：罕见材质与罕见拓扑在自然分布中本就稀少，抓取再多也补不上。工程上常见的处理是先做一轮几何与材质的规范化过滤，再按类别重采样，代价是过滤规则本身成为新的偏差来源。

第二条路线是合成数据引擎：用程序化生成或渲染管线批量产出带精确标注的资产。它的机制优势在于标注是“免费”的——几何真值、材质参数、光照条件、相机位姿全部由生成过程直接给出，不需要人工或模型反推。这对评测侧尤其关键，因为几何真值指标缺失正是当前评测的痛点。合成引擎还能定向补长尾：指定材质类型、指定拓扑复杂度、指定遮挡关系，按需生成。代价是域间隙：合成资产的渲染统计与真实拍摄、真实扫描不一致，模型在合成域上学到的材质先验迁移到真实输入时会退化。另一个代价是引擎本身的维护成本，程序化生成器要覆盖足够多的物体类别，其复杂度会迅速逼近一个独立的资产生成系统。

两条路线的选型判据不在“哪个更好”，而在训练阶段与目标域。预训练阶段需要广度，抓取式数据集的类别覆盖是合成引擎短期难以复制的；微调与评测阶段需要精确标注与可控分布，合成引擎的优势不可替代。工程上可行的组合是抓取式做预训练底座、合成引擎做定向补强与评测集构造，两者之间用统一的资产规范（网格水密性、UV 存在性、PBR 通道定义）对齐，否则混合训练时规范化步骤会反复撕裂数据分布。

路线代表工作主要收益主要代价
抓取式数据集Objaverse、Objaverse-XL类别广度、开放词表覆盖许可清洗、质量异质、长尾稀疏
合成数据引擎程序化生成与渲染管线精确标注、定向补长尾、几何真值域间隙、引擎维护成本

二 · 生产化路线：从出网格到出可交付 PBR 资产

生产侧的分水岭是“输出是否可直接进引擎”。早期路线只保证网格几何，输出是一团三角面，没有 UV、没有材质分层、光照烘死在顶点色或纹理里。这种输出在演示里可用，在管线里不可用：引擎需要 UV 才能贴图，需要 PBR 通道才能参与物理光照，需要光照解耦才能在任意环境下重新打光。SF3D 与 Hunyuan3D 2.1 代表的是第二条路线，把 UV 展开、光照解耦与 PBR 材质分解纳入生成过程本身，而不是留给后处理。

这条路线有三个具体机制。UV 展开：生成网络在输出网格的同时预测展开参数或直接输出带 UV 的网格，避免传统展开算法在非流形、高亏格网格上的失败。光照解耦：把观测图像中的 shading 与反照率分离，使生成的 base color 不含烘死的高光与阴影，否则资产换一个光照环境就会暴露伪造感。PBR 分解：输出 albedo、roughness、metallic 等通道，让资产能参与基于物理的渲染，而不是只作为一张贴图存在。三者串联的伪代码思路是：几何分支出网格与 UV 参数，材质分支在解耦后的反照率上回归 PBR 通道，最后按 UV 图集打包成引擎可读的资产包。

$$I = f_{\text{BRDF}}(\text{albedo},\ \text{roughness},\ \text{metallic},\ \mathbf{n},\ \mathbf{l},\ \mathbf{v})$$

公式表达的是生产化路线的目标：生成结果要能代入 BRDF 求值，而不是把观测亮度直接烘进纹理。代价随之而来。UV 图集带来接缝问题：展开算法在接缝处的纹理连续性需要额外约束，否则渲染时出现可见裂缝。PBR 通道的回归在单图输入下是欠定的——同一张图可以对应多组 albedo 与光照组合，模型必须依赖先验做选择，先验错了就出现“看起来对、换光照就崩”的失败模式。光照解耦还会放大噪声：输入图像中的阴影被误判为反照率暗部，资产在强光下出现脏斑。工程上的判断是：生产化路线的验收标准不是视觉相似度，而是资产在引擎里换光照、换视角、换材质参数后的稳定性。

具体例子：一个从单张产品图生成的资产，若只出网格与烘死纹理，进入引擎后无法响应场景光源变化，美术必须手工重做 UV 与材质，等于生成环节白做；若走 UV + PBR 路线，资产可以直接挂到材质实例上，代价是生成阶段要多付出展开与通道回归的算力，以及接缝与欠定性带来的返修率。选型判据因此很直接：下游是否要求资产可编辑、可重打光、可参与物理渲染。若只做预览与检索，网格路线足够；若要做资产交付，PBR 路线是唯一可进管线的选项。

三 · 评测路线：感知指标、几何真值与口径混乱

评测侧目前的主流路线是感知指标与用户偏好：CLIP 相似度衡量生成结果与文本或参考图的语义对齐，FID 类指标衡量渲染图像分布的接近程度，用户偏好研究给出主观排序。这条路线的好处是易实施、跨类别可比，坏处是与几何质量脱节。一个语义对齐良好但拓扑破碎、UV 缺失、法线翻转的资产，在 CLIP 分数上可能很高，在引擎里却不可用。3DGS 综述暴露的正是这种口径混乱：不同工作在渲染分辨率、训练视图数、评测集划分上各行其是，分数之间不可比。

第二条路线是几何真值指标：倒角距离、法线一致性、水密性、拓扑亏格、UV 接缝长度等。这些指标需要真值网格，因此只在合成数据或有扫描真值的子集上可行。机制上，几何指标直接对应下游可用性：水密性决定能否做布尔运算与物理仿真，亏格与面数决定能否做 LOD，UV 接缝决定纹理管线是否可用。代价是覆盖面窄——真实场景的单图生成没有真值，几何指标无法计算，只能退回到感知指标或人工检查。

第三条路线是任务导向评测：把生成资产放进下游任务里测，例如渲染后做检测、分割、重识别，或直接测引擎导入成功率与美术返修工时。这条路线最接近生产判断，但成本最高，且任务选择本身引入偏差。三条路线的关系不是替代，而是分层：感知指标做大规模筛选，几何指标做子集校验，任务导向评测做交付验收。选型判据是评测目的——若用于模型选型，感知指标加几何子集足够；若用于资产交付验收，必须引入任务导向指标，否则分数与可用性之间的鸿沟无人负责。

评测路线代表信号覆盖范围主要失效模式
感知指标CLIP、FID、用户偏好大规模、跨类别与几何可用性脱节
几何真值倒角距离、水密性、UV 接缝合成或有真值子集真实输入无真值、覆盖窄
任务导向引擎导入率、下游任务指标交付验收成本高、任务选择偏差

四 · 路线间的耦合：数据规范决定评测口径，评测口径反推生产目标

三条路线不是并列的独立选择，而是互相约束。数据侧的资产规范直接决定评测能测什么：若数据集不记录 UV 存在性与 PBR 通道完整性，评测就无法报告生产可用性指标，只能退回感知分数。反过来，评测口径会反推生产目标：当交付验收要求引擎导入成功率时，生成模型必须把 UV 与 PBR 纳入输出，否则再高的 CLIP 分数也过不了验收。这种耦合意味着选型不能逐项独立做，必须按“目标域—验收标准—数据规范—模型输出”的顺序倒推。

耦合处的典型失败模式是规范漂移：数据侧按一套 UV 图集布局打包，生产侧按另一套布局输出，评测侧又按第三套渲染设置计算指标，三者之间的差异被误读为模型能力差异。工程上的对策是把资产规范写成可执行的校验器，在数据入库、模型输出、评测渲染三个环节跑同一套检查，任何环节不合规直接拒绝，而不是让不合规资产流入下一环再靠指标“感觉”出问题。校验器的代价是吞吐下降与误杀率，但比返修成本低。

具体例子：一个团队用抓取式数据集预训练、用感知指标选型，模型分数领先，但交付时发现大量资产缺 UV、材质烘死，美术返修工时吞掉全部收益。倒推后的修正不是换模型，而是先定验收标准（引擎导入率、换光照稳定性），再据此改数据规范（强制 UV 与 PBR 通道字段）、改模型输出（纳入展开与分解分支）、改评测（加入几何与任务导向子集）。这条链上任何一环单独改动都不解决问题，因为瓶颈在耦合处而不在单点。

五 · 选型判据：按交付形态与合规约束分档

第一条判据是交付形态。只做预览、检索、演示的场景，网格路线加感知评测足够，成本最低；要求资产可编辑、可重打光、可参与物理渲染的场景，必须选 UV + PBR 生产路线，并配套几何与任务导向评测。中间档是“可渲染但不可编辑”，例如只用于离线渲染的资产，可以接受烘死光照但要求水密网格，此时生产路线可以省去 PBR 分解，评测仍需几何指标。

第二条判据是合规约束。抓取式数据集的许可清洗成本随规模上升，千万级资产的逐条许可核验不是可选项；若目标域要求商用再分发，合成数据引擎在许可上的确定性更高，代价是域间隙。选型时要把许可成本计入总成本，而不是当作数据侧的附带工作。第三条判据是长尾需求：若目标域包含罕见材质与罕见拓扑，抓取式数据的自然分布补不上，必须引入合成引擎定向生成，并接受域间隙带来的迁移退化。

第四条判据是评测预算。几何真值指标需要真值网格，任务导向评测需要下游管线，两者的成本都高于感知指标。预算有限时的可行分档是：感知指标做全量筛选，几何指标做固定比例子集校验，任务导向评测只对候选模型做一次交付验收。这样做的风险是子集抽样偏差，对策是按类别与材质分层抽样，而不是随机抽样。

把四条判据合起来，选型不是选“最强路线”，而是选与交付形态、合规约束、长尾需求、评测预算匹配的组合。工程判断落在具体机制上：先写资产规范校验器，再定验收标准，最后才选数据路线与模型输出分支；顺序颠倒的团队会在分数与可用性之间反复返工，而返工成本远高于前期规范成本。
