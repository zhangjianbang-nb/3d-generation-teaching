一 · 从 MeshGPT 到 MeshAnything：序列化对象的替换

MeshGPT 确立的范式是“把网格当语言”：用 VQ-VAE 风格的编码器把三角形面片量化成离散码字，再让 decoder-only Transformer 在码字序列上做自回归建模。它的关键设计在于序列的构造方式——每个 token 对应一个面片，面片的三个顶点坐标经过量化后拼进同一个码字空间，序列按面片邻接关系排序。这样做的直接后果是：序列长度与面片数成正比，一个几千面的物体就会产生几千个 token，注意力的二次代价立刻成为瓶颈。MeshGPT 的继承者并没有推翻“网格即序列”这一前提，而是把被序列化的对象从“面片”换成了“带邻接信息的局部结构”。

MeshAnything 的改动看似温和，实则改变了整条链的输入输出契约。它不再要求输入是一个干净的、由自家编码器量化出来的 token 序列，而是接受任意来源的网格——包括 3D 大模型输出的等值面三角汤——并输出一个面数受控、边流向合理的艺术家级网格。这相当于把 MeshGPT 的“生成”降级为“重拓扑”，把自回归 Transformer 从生成器改造成条件重写器。代价是：模型必须处理输入网格的几何噪声与拓扑缺陷，编码器要能容忍非流形输入，解码器要在输出端保证水密性与流形性。收益是：它可以直接插进现有管线，不必等待上游生成模型改造输出格式。

这里出现第一个明确的断裂点。MeshGPT 的序列化假设输入网格已经是“可 token 化”的，即面片顺序存在某种规范；而真实生成模型的输出没有这种规范，面片顺序是随机的、顶点是重复的、法向是不一致的。MeshAnything 用输入网格的几何特征（顶点位置、面片法向、邻接关系）构造条件，让 Transformer 在“给定这个乱序网格”的前提下逐 token 输出重排后的面片。伪代码思路是：

其中条件特征不进入自回归序列本身，而是作为 cross-attention 的键值。失败模式很具体：当输入网格存在大量退化三角形（面积趋零）时，编码器提取的法向不可靠，cross-attention 学到的是噪声，输出网格会在这些区域产生翻折面。系统代价是推理时的序列长度仍然由输出面数决定，重拓扑一个高面数输入并不会缩短输出序列，只是把“生成多少面”变成可控超参。

二 · 相邻 token：序列长度压一个量级的机制

MeshAnything V2 的核心贡献是 adjacent mesh tokenization。要理解它为什么是改进而非替代，需要回到 MeshGPT 序列化的根本缺陷：按面片逐个 token 化，等于把网格的邻接结构丢弃在序列顺序里，模型必须自己学会“下一个面片应该接在哪条边上”。这既拉长了序列，又让自回归误差在长程上累积——一个面片接错边，后续所有面片都跟着错位。

相邻 token 的做法是把“一条边 + 一个相邻面片”打包成一个 token 单元。具体机制是：从种子面片出发，沿一条未访问的边走到相邻面片，把这个面片的剩余顶点与这条边的信息联合编码；然后从新面片继续沿边扩展，形成一条类似深度优先的遍历序列。这样每个 token 携带的不再是孤立的面片，而是“相对于上一条边的局部增量”。序列长度下降的来源不是压缩算法，而是信息冗余的消除：一个面片的三个顶点中，有两个已经由“当前边”确定，只需编码第三个顶点和朝向。

$$L_{\text{adj}} \approx \frac{L_{\text{face}}}{k},\quad k \text{ 为平均每 token 覆盖的面片邻接步数}$$

定性地说，V2 把序列长度压了一个量级，这使得自回归的误差累积路径变短，同时让 Transformer 的有效感受野覆盖更大的局部邻域。代价是 tokenization 本身变复杂：遍历顺序必须保证每个面片恰好被访问一次，遇到非流形边或边界边时要引入回退规则，这些规则在训练数据上必须一致，否则模型学到的是遍历算法的伪影而非几何规律。失败模式是“遍历断裂”：当网格存在多个连通分量或孔洞时，序列需要在分量之间跳转，跳转 token 的语义与邻接 token 不同，模型容易在跳转处生成不闭合的边界。

一个具体例子：对一个由多个独立壳体组成的物体做重拓扑，V2 的遍历会在壳体之间插入跳转，输出网格的壳体数量与输入一致，但每个壳体的面数分配由模型自行决定。如果输入壳体之一非常薄，模型倾向于给它分配过少的面片，导致该壳体在输出中退化为一条折线。这是序列化范式的固有代价：面数预算在序列生成过程中是隐式分配的，没有显式的部件级控制。

三 · PartCrafter：从整物体序列到组合式潜变量

PartCrafter 代表的是另一条断裂：不再把整个物体压成一条自回归序列，而是用组合式潜变量扩散一次生成多个部件。它的前提判断是，整物体自回归的序列长度与拓扑合法性之间存在不可调和的矛盾——序列越长，误差累积越严重，而部件级结构（哪些面属于哪个语义部件、部件之间如何铰接）在单一序列里没有显式表示。

机制上，PartCrafter 为每个部件维护一组潜变量，部件之间通过一个共享的组合式 Transformer 交换信息。生成过程是扩散去噪，而非逐 token 自回归：每个去噪步同时更新所有部件的潜变量，部件间的相对位姿与接触关系由 cross-attention 在潜变量之间传递。这与 MeshAnything 的接口关系是互补而非替代：PartCrafter 输出的是带语义分组的部件级网格，每个部件仍需重拓扑才能进管线，MeshAnything 正好承担这一步。伪代码思路是：

$$z^{(t-1)}_{p} = \text{Denoise}\big(z^{(t)}_{p},\ \text{Attn}(z^{(t)}_{p}, \{z^{(t)}_{q}\}_{q \neq p})\big),\quad p \in \text{parts}$$

系统代价出现在部件数量上：组合式注意力的复杂度随部件数增长，部件越多，单次去噪步的显存与算力开销越大；同时，部件间的接触面需要在潜变量层面保持一致，否则去噪后各部件独立解码会出现穿插或缝隙。失败模式是“语义漂移”：当输入条件（如图像或文本）对部件的描述模糊时，模型会把本应属于一个部件的几何拆分到两个潜变量里，输出网格在部件边界处出现重复面或非流形边。

具体例子：生成一个带铰接的台灯，PartCrafter 会把底座、灯杆、灯罩分到不同潜变量，铰接关系体现为灯杆与灯罩接触区域的潜变量耦合。如果耦合过强，灯罩会被拉向灯杆，丢失独立的旋转自由度；如果耦合过弱，接触面出现缝隙。这个权衡没有解析解，只能靠训练数据中的铰接样本分布来隐式约束。

四 · CraftsMan3D 与接口标准化：精修作为补足

CraftsMan3D 的定位不是替代上述任一范式，而是补足拓扑精修环节。它的判断是：自回归重拓扑与组合式扩散都能产出“大致正确”的网格，但在锐边、薄壁、小孔这些几何敏感区域，生成结果的拓扑合法性不达标——要么边流向混乱，要么局部非水密。CraftsMan3D 用交互式几何精修在这些区域做局部重建，把全局生成与局部修复拆成两个阶段。

机制上，精修阶段接受一个已生成的网格和一个指定的局部区域，在该区域内重新求解顶点位置与边连接，约束条件是区域边界上的顶点与边必须与全局网格一致。这本质是一个带边界约束的局部重网格化问题，代价是精修区域的选择需要人工或启发式规则介入，无法完全自动化。失败模式是“边界不匹配”：如果全局网格在区域边界上的边流向本身不合理，局部重建无法在保持边界一致的前提下修复它，精修退化为在错误边界内做无用功。

接口标准化是这条线上尚未解决的问题。MeshGPT 的 token 序列、MeshAnything 的条件重拓扑、PartCrafter 的部件潜变量、CraftsMan3D 的精修区域，四者之间没有统一的中间表示。工程判断是：短期内可行的接口是“网格 + 部件标签 + 面数预算”三元组，上游生成模型输出带标签的部件级网格，重拓扑模块按预算分配面数，精修模块按标签定位敏感区域。这个接口不依赖任何一方的内部表示，代价是标签的语义一致性需要在上游保证，否则下游的重拓扑与精修都会在标签边界处出错。

论文被继承的对象改动主要代价
MeshGPT—面片级 token 序列 + 自回归序列长度随面数线性增长
MeshAnything网格即序列输入改为任意网格，任务改为重拓扑需容忍非流形输入，输出面数靠超参
MeshAnything V2面片级 tokenization相邻 token，序列压一个量级遍历规则复杂，跳转处易生成开边界
PartCrafter整物体生成组合式潜变量扩散，部件级并行部件数增长带来注意力开销与接触面一致性
CraftsMan3D全局生成结果局部几何精修补足拓扑精修区域需外部指定，边界约束依赖全局质量

按年代看，这条线的延续性体现在“网格必须变成可学习的离散或连续表示”这一共识从未动摇；断裂则出现在表示的单位上：面片、相邻边、部件潜变量、局部区域，每一次更换单位都是因为前一种单位在某个系统代价上触到了天花板。MeshGPT 触到的是序列长度，V2 用相邻 token 换长度但引入遍历复杂度，PartCrafter 用部件并行换掉长序列但引入部件间一致性，CraftsMan3D 承认全局生成在敏感区域不可靠而引入局部修复。没有一次改动是纯粹的性能优化，每次都在替换一个失败模式。

工程上真正决定选型的是失败模式落在管线的哪一段。如果上游是 3D 大模型的等值面输出，MeshAnything 系列是唯一能直接吃下乱序三角汤的入口；如果需求是带语义分组的资产，PartCrafter 的部件潜变量提供了显式的分组信号，但必须接受部件数带来的算力增长；如果资产包含锐边薄壁且拓扑合法性是硬指标，CraftsMan3D 的局部精修是必要的收尾，代价是引入人工指定区域这一非自动环节。三者串联的接口目前靠“网格 + 标签 + 预算”三元组维系，这个接口的脆弱点在于标签语义的一致性——上游标签错一个，下游重拓扑会在错误边界上分配面数，精修会在错误区域做局部重建，误差沿管线单向放大而无法回退。
