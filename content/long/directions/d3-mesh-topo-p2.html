一 · 自回归网格序列化：把三角面变成语言

路线对比的第一条轴，是“网格是否被当作离散序列来建模”。MeshGPT 确立了这条路线的基本契约：把三角网格转成 token 序列，用 decoder-only Transformer 逐 token 预测，再解码回三角面。它的关键设计不在于 Transformer 本身，而在于序列化方式——每个面由三个顶点构成，顶点坐标被量化到有限码本，面按某种遍历顺序排列，于是“生成网格”退化为“生成一段合法语法”。这条路线最大的吸引力是接口统一：同一套自回归骨架可以同时吃文本、图像条件，不需要为几何单独设计扩散过程。

具体机制上，序列化要解决三个耦合问题：顶点复用、面顺序、以及序列终止。若每个面独立写三个顶点坐标，顶点会被重复记录，序列长度随面数线性膨胀；MeshGPT 的做法是维护一个“已出现顶点”的字典，新面若引用旧顶点则只写索引，否则写新顶点的量化坐标。面顺序则依赖一种确定性的遍历（例如按面邻接关系深度优先），使相邻 token 在几何上也相邻，从而让注意力的局部性有意义。终止靠序列结束符，但结束符之后必须保证所有面构成流形，这一步不是模型学出来的，而是解码时的合法性检查。

系统代价非常直接：序列长度。一个中等复杂度的物体动辄数千个面，每面至少若干 token，序列长度轻松进入数千到上万量级，而自回归解码是逐 token 串行的，推理时间随面数超线性增长。更麻烦的是误差累积——前面一个顶点坐标量化偏了，后面所有引用它的面都跟着歪，且模型没有回头修正的机制。失败模式典型表现为“局部合理、全局崩坏”：生成的网格在某个区域面片自交、出现非流形边，或者干脆在物体中部留下空洞，因为模型在长序列后段失去了对已生成部分的全局记忆。举例来说，一个带细长把手的杯子，把手与杯身连接处的顶点复用一旦出错，解码器会生成两组不相连的面片，拓扑合法性检查直接拒绝，整段序列作废。

二 · 相邻 token 化：用序列压缩换可行性

MeshAnything V2 的相邻网格 token 化（adjacent mesh tokenization）针对的正是上一条路线的长度瓶颈。它的核心观察是：网格的面在空间上是局部聚集的，若序列化顺序沿着面邻接图行走，则相邻两个面共享一条边，也就是共享两个顶点。于是编码时可以只记录“下一个面相对于当前面的第三个顶点”，共享顶点由上下文隐式给出，不必重复写入。这把每面的 token 数从“三个顶点”压到接近“一个顶点”，序列长度下降一个量级。

机制上，这要求序列化器维护一个“当前面”指针，并保证遍历是一条连续的面邻接路径；遇到分支时需要回溯，回溯本身要编码成特殊 token，否则解码器无法重建遍历顺序。解码端则按同样规则重建面：读入相对顶点，与当前面的共享边拼合，得到新面，再更新当前面指针。合法性约束比 MeshGPT 更强——不仅顶点要合法，面与面之间的共享边关系也必须自洽，任何一步的相对顶点落在错误一侧都会导致后续面全部错位。

  • 收益：序列长度压缩一个量级，自回归步数随之下降，长序列误差累积的窗口变短。
  • 代价：序列化器复杂度上升，需要面邻接图遍历与回溯编码；对非流形或带孔洞的输入网格，遍历可能断裂，需要预处理修补。
  • 失败模式：输入网格本身拓扑脏（例如 T 型接缝、重复面），相邻关系不唯一，序列化产生歧义，解码后出现面片翻转或重叠。

具体例子：把一个扫描得到的、含数万三角面的椅子模型喂给这条管线，序列化器先做面邻接遍历，把椅子腿、座面、靠背各自走成连续路径，分支处插入回溯 token；解码后得到的是面数受控、边共享一致的重拓扑网格，而不是原扫描的三角汤。这里的工程判断是：相邻 token 化把“能不能生成”变成了“输入网格能不能被干净地遍历”，前者是模型问题，后者是数据清洗问题，后者往往更耗时。

三 · 组合式潜变量扩散：从整物体到部件分解

PartCrafter 代表另一条轴：不再把物体当成单一序列，而是用组合式潜变量扩散 Transformer 一次生成多个部件，每个部件有独立的潜变量，部件之间通过注意力或条件耦合。这条路线的前提是“部件级生成”——物体被拆成有语义的部件（椅子的腿、座面、靠背），每个部件是一个独立的生成单元，最后组装成完整网格。它与自回归路线的根本差别在于：自回归是串行语法生成，扩散是并行去噪，前者天然适合表达“面与面的顺序关系”，后者天然适合表达“部件与部件的组合关系”。

机制上，组合式扩散需要解决两个问题：部件潜变量的独立性，以及部件间的空间一致性。独立性靠每个部件一个 latent token 或一组 latent token，去噪时各自演化；一致性靠跨部件注意力，让一个部件的去噪步骤能看见其他部件的当前状态，从而对齐接触面。训练时需要对部件做语义标注或自动分解，分解质量直接决定生成质量。公式上，这是把整物体扩散的联合分布拆成条件分解：

$$p_\theta(\{z_i\}_{i=1}^{K}\mid c)=\prod_{i=1}^{K}p_\theta(z_i\mid c,\{z_j\}_{j\neq i})$$

系统代价在于分解与组装。分解不是免费的：语义部件边界往往与几何边界不一致（例如椅子的座面和腿在几何上是连续的），自动分解会产生错误切分，导致部件之间出现缝隙或重叠。组装阶段需要做接触面匹配，若两个部件的接触面不吻合，要么留缝，要么强行焊接产生非流形边。失败模式典型为“部件各自漂亮、拼起来不对”：每个部件单独看拓扑干净、面数可控，但组装后整体水密性被破坏，或者铰接关系（例如门的转轴）缺失，无法直接进动画管线。具体例子：生成一个带抽屉的柜子，抽屉面板与柜体是两个部件，若跨部件注意力没有对齐两者的接触平面，抽屉会浮在柜体外或嵌进柜体内部，后续需要人工重定位。

四 · 交互式几何精修：拓扑合法性的最后一道闸

CraftsMan3D 走的是第三条路：不追求一次生成完美拓扑，而是用交互式几何精修补足拓扑。它的定位是“生成大模型输出粗网格，精修阶段负责拓扑清理与面数控制”。这条路线承认一个工程事实：纯生成模型在拓扑合法性上不可靠，与其让模型学流形约束，不如把合法性交给确定性的几何算法，模型只负责提供形状先验。

机制上，精修阶段通常包含：网格简化（控制面数）、重网格化（重建边流）、孔洞填补（恢复水密）、非流形边拆分、以及局部重拓扑（在曲率高处加密、在平坦处减面）。这些操作是确定性的，可复现，不依赖模型概率。交互式体现在用户可以指定保留区域、指定目标面数、指定对称平面，算法在这些约束下做优化。代价是管线变长：生成、精修、验证三个阶段串行，任何一段失败都要回退。失败模式是“精修改变语义”：简化算法可能把细小的特征（例如杯口的一圈薄边）抹掉，或者重网格化把锐利边缘磨圆，导致形状与生成意图偏离。

五 · 选型判据：按管线约束而非按论文指标

选型的第一判据是“输入是什么”。若上游是 3D 大模型输出的等值面网格，面数爆炸且拓扑混乱，那么重拓扑路线（相邻 token 化 + 精修）是唯一能直接进管线的选择，因为它的目标就是把脏输入变成干净输出；若上游是文本或图像条件、没有现成网格，那么自回归序列化或组合式扩散才是生成路线，前者适合单物体、后者适合多部件。第二判据是“输出要什么”：游戏管线要面数可控、四边面为主、UV 可展开，影视管线要水密、可细分，动画管线要部件语义与铰接关系。第三判据是“能不能接受串行延迟”：自回归逐 token 解码，面数一多就慢，交互式场景不可接受；扩散去噪步数固定，延迟可预测，但部件数增加时总步数上升。

工程上还有一个常被忽略的判据：合法性检查放在哪。自回归路线把合法性押在解码后的检查上，检查失败就整段作废，重试成本高；组合式扩散把合法性押在组装阶段，失败可以局部重生成单个部件，回退粒度更细；精修路线把合法性交给确定性算法，失败可定位到具体操作。回退粒度决定了系统的可用性——生成一个物体失败一次就重来，和只重生成一个部件，代价差一个量级。具体例子：生成一张多腿桌子，若一条腿的接触面不合法，组合式路线只需重扩散该腿的潜变量，自回归路线则要重跑整段序列。

最后一条判据是“与生成大模型的接口标准化”。当前各路线对条件的消费方式不同：自回归吃 token 化条件，扩散吃潜变量条件，精修吃几何约束。接口不统一意味着上游模型换一次，下游管线就要改一次。工程判断是：把“形状先验”和“拓扑合法性”分成两层，上层用任意生成模型出粗形状，下层用确定性的重拓扑与精修保证合法性，两层之间只传网格与部件标注，不传模型内部表示。这样选型就不再绑定某个具体论文，而是绑定“你的管线能接受多大的回退粒度、多长的串行延迟、多严的水密要求”。相邻 token 化把序列压一个量级这件事，本质上是在降低自回归路线的串行延迟，使其在中等复杂度物体上进入可用区间；而部件分解把回退粒度从整物体降到单部件，是在降低失败代价。两条压缩方向不同，选型时看你的瓶颈在延迟还是在失败率。
