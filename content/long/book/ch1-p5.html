一 · 从链路图到可运行的最小骨架

把第一卷的机制落到代码，第一件事不是写网络，而是把「射线生成 → 采样 → 场查询 → 体渲染积分 → 像素误差 → 反传」这条链拆成可单独测试的函数。一个可信的最小骨架通常包含五个纯函数：get_rays(H, W, c2w, intrinsics) 把相机位姿与内参变成每个像素的原点 o 与方向 d；sample_stratified(t_n, t_f, N) 在近远平面间分层采样；query_field(x, d) 返回 (c, σ)；volume_render(σ, c, t) 做离散积分；photometric_loss(C, C_gt) 算误差。把这几段写成无状态的纯函数，是为了让每一段都能用解析解或数值对照验证，而不是等整条链跑完才发现某处符号错了。

离散体渲染的核心是把连续积分换成区间求和。给定沿射线的 N 个采样点，相邻点间距 δ_i = t_{i+1} − t_i，透射率递推为 T_i = exp(−Σ_{j<i} σ_j δ_j)，像素颜色写成：

$$ \hat{C}(\mathbf{r})=\sum_{i=1}^{N} T_i\left(1-\exp(-\sigma_i\delta_i)\right)c_i,\qquad T_i=\exp\!\left(-\sum_{j=1}^{i-1}\sigma_j\delta_j\right) $$

这段公式在代码里对应一个累积乘积的循环：alpha_i = 1 − exp(−σ_i δ_i)，weight_i = T_i · alpha_i，T_{i+1} = T_i · (1 − alpha_i)。实现时最容易犯的错是把 δ 当成常数 1，或者在分层采样后忘记把排序后的 t 重新算 δ。前者会让密度尺度失去物理意义，后者会让远近样本的权重错位。一个具体例子：若近远平面设为 2 到 6、采样 64 点，δ 约为 0.0625；若误用 δ=1，σ 的梯度会被放大十几倍，训练初期 loss 直接爆炸，表现为渲染图全白或全黑。

系统代价在这里体现为显存与计算的双重放大。每条射线 N 个点，每个点过一遍 MLP，若 batch 是 B 条射线、MLP 隐层宽 256、两层，则单次前向的浮点量大致是 B·N·(输入维度×256 + 256×256 + 256×4)。B 取 1024、N 取 64 时，这个量级已经让单卡训练变得吃紧，于是才有了后续的哈希编码与显式基元。失败模式也很具体：如果 get_rays 的坐标系约定（OpenGL 与 OpenCV 的 y/z 轴方向）与位姿文件不一致，射线会整体偏转，训练 loss 能降但新视角渲染出现系统性重影——这正是「位姿错 1 度，细节糊成一片」在代码层的来源。

二 · 位置编码与分层采样的调参手感

位置编码把低频坐标映射到高频基，常用形式是对每个坐标分量做一组正弦与余弦：

$$ \gamma(p)=\left(\sin(2^0\pi p),\cos(2^0\pi p),\ldots,\sin(2^{L-1}\pi p),\cos(2^{L-1}\pi p)\right) $$

L 是唯一需要手调的参数。L 太小，网络学不出高频纹理，渲染结果像被低通滤波；L 太大，高频基在训练早期提供大量噪声梯度，表面出现椒盐状伪影。工程上的判断标准不是看 loss 曲线，而是看「同一场景在训练集视角与留出视角上的差距」：如果训练视角清晰、留出视角发糊，说明高频被过拟合到具体视角，应降 L 或加视角分离的验证。位置编码只作用于位置，视角方向 d 通常只做低阶编码或不编码，因为视角相关外观主要由方向与法线的相对关系决定，过高的方向频率会让高光变成噪点。

分层采样解决的是「样本该放在哪」的问题。粗网络先在 N_c 个均匀样本上估计密度，得到权重分布，再用逆变换采样把细网络的 N_f 个点集中到权重高的区间。伪代码思路是：先算粗网络的 weights，归一化成概率，构造累积分布，然后用均匀随机数反查区间，在区间内加抖动。这样细样本落在表面附近，而不是均匀铺满整条射线。代价是两倍的前向次数：粗网络与细网络各跑一遍，显存与时间都翻倍。失败模式是「粗网络塌缩」——如果粗网络一开始就把所有权重给到近平面，细采样会全部堆在相机附近，远处表面永远得不到梯度，表现为渲染图近处过曝、远处空洞。

一个具体例子：对一只小猫的场景，若近远平面设得过宽（比如 0.1 到 100），均匀采样会把绝大多数点浪费在空气里，粗网络的密度几乎全为零，权重分布退化成均匀，分层采样失效。正确做法是先根据相机到物体的距离估计一个窄的 near/far 区间，让采样预算花在物体所在的壳层上。这也是为什么复现时「先看位姿与场景尺度，再看网络结构」比反过来更省时间。

三 · 训练循环里的三个隐形陷阱

第一个陷阱是坐标归一化。NeRF 类方法通常把场景缩放到单位球或单位立方体内，射线原点与方向也随之缩放。如果只归一化了位置而忘了同步缩放 near/far，采样区间会与实际物体错位，密度场学到的是一层偏移的壳。检查方法是渲染一张深度图，看最近表面是否落在预期距离上；若整体偏移一个常数，基本可以断定归一化不一致。

第二个陷阱是视角泄漏。训练集与测试集必须按相机位姿划分，而不是按图像随机划分。同一段视频里相邻帧的视角几乎重合，随机划分会让测试视角的信息通过相邻帧泄漏进训练，PSNR 虚高。工程上应保留一份「按位姿聚类后留出」的验证集，并在训练中定期渲染验证视角，观察是否出现「训练视角锐、验证视角糊」的分裂。这个分裂是过拟合的最早信号，比 loss 曲线更可靠。

第三个陷阱是学习率与批大小的耦合。体渲染的梯度来自每条射线上所有采样点的累加，批内射线数越多，单步梯度越平滑，但显存占用线性增长。常见做法是固定「每次前向的采样点总数」而不是固定射线数：当分辨率提高时减少批内射线数，保持总采样量不变。否则在切换分辨率做课程训练时，学习率需要重新调，否则会出现 loss 平台期或震荡。一个具体机制：若总采样点预算为 B·N，把 B 减半、N 加倍，梯度方差会变化，动量项的有效窗口也随之改变，这就是为什么课程训练必须同步调优化器超参。

系统代价还体现在检查点与可视化上。体渲染的渲染函数在评估模式下要跑全分辨率，显存峰值往往出现在评估而非训练。若在训练循环里直接调用全分辨率渲染做可视化，很容易 OOM。稳妥做法是把可视化渲染放到单独的进程或分块渲染，按射线批次拼接图像。

四 · 复现可信度的检查清单

下面这张表把「判断一个 NeRF 复现是否可信」拆成可勾选的条目，每一条都对应一个具体失败模式，而不是泛泛的「调参」。

检查项具体做法不通过时的典型症状
位姿一致性用同一套位姿渲染训练图，与真值图做像素级对照整体重影、边缘双层
坐标归一化渲染深度图，核对最近表面距离表面整体偏移、near/far 错位
训练/测试分离按位姿聚类留出验证视角验证 PSNR 虚高、留出视角发糊
采样预算固定总采样点数，记录每步前向次数换分辨率后 loss 震荡
粗网络权重分布可视化粗网络权重沿射线的直方图权重堆在近平面、远处空洞
视角相关项固定位置、改变视角方向，看颜色是否变化高光不随视角移动、材质像塑料
评估口径报告 PSNR 的同时报告留出视角盲评指标好看但人眼看着糊

这张表里最容易被跳过的是「视角相关项」。5D 输入的意义在于让网络表达高光与反射，但如果训练时每个位置只见过一个视角方向，网络会把视角相关颜色塌缩成视角无关的漫反射，渲染结果失去材质感。检查方法是固定空间位置、绕该点改变方向做一组渲染，观察颜色是否随方向连续变化；若几乎不变，说明视角分支没有起作用，可能是方向编码被丢弃或视角输入在拼接时维度错位。

另一个常被忽略的代价是评估本身的时间。全分辨率留出视角渲染要沿每条射线采几十上百个点，一张图就可能耗尽显存；分块渲染虽然省显存，但会引入块边界不一致。工程判断是：评估口径必须与训练口径解耦，评估用固定的采样数与分块策略，并在报告指标时注明，否则不同复现之间的 PSNR 不可比。

五 · 五道自测题

以下五题覆盖本卷的机制、代价与失败模式，答案要求写出具体机制而非结论。

  • 题一：给定一条射线与 N 个采样点，写出透射率递推与像素颜色的离散形式，并说明若把 δ 误设为常数 1，梯度尺度会怎样变化。要求指出哪个量被放大、为什么会导致训练初期发散。
  • 题二：位置编码的 L 过大时，训练视角清晰而留出视角发糊。请从频谱偏置与过拟合两个角度解释这一现象，并给出一个不依赖 loss 曲线的判断方法。
  • 题三：分层采样中粗网络把权重全给到近平面，细采样失效。请写出逆变换采样的伪代码思路，并说明为什么「先估计场景尺度再设 near/far」能缓解这一问题。
  • 题四：训练/测试按图像随机划分导致 PSNR 虚高。请说明相邻帧视角重合如何造成信息泄漏，并给出按位姿聚类留出的具体操作。
  • 题五：固定空间位置、改变视角方向，渲染颜色几乎不变。请列出两个可能的代码层原因（方向编码丢失、拼接维度错位），并说明如何用一组绕点渲染来定位。

这五题的共同点是都要求把「现象」映射回「链路上的某一环」。题一对应体渲染积分的离散化，题二对应位置编码的频谱行为，题三对应分层采样的概率构造，题四对应评估口径，题五对应 5D 输入的视角分支。能把这五题答成「某函数某行某参数」的人，才算真正把第一卷的链路握在手里，而不是记住了一组名词。

最后落在一个工程判断上：可微渲染的价值不在于某一个网络结构，而在于「误差能沿射线反传到三维参数」这条链的可验证性。判断一个复现是否可信，先看位姿与归一化是否自洽，再看训练/测试是否真的按视角分离，最后看报告的是 PSNR 还是留出视角的实际渲染。三者任一不成立，后面的调参都是在噪声上做优化。
