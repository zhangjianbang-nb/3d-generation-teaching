一 · 从「物体」到「房间」：数据流的第一性差异

第九卷之前的生成对象基本是单个物体：一个杯子、一把椅子、一只鞋。物体的生成可以只关心一个包围盒内的几何与材质，坐标系原点放在质心，背景一律丢弃。房间不是这样。房间的第一性差异在于它有一个「内」——相机站在里面，墙壁在相机背后，地板在脚下，天花板在头顶，而生成器必须保证从任意一个内点朝任意方向看，看到的都是同一个自洽的空间。这个约束把问题从「生成一个形状」变成了「生成一个封闭的、可被遍历的场」。

Text2Room 的数据流是这条差异最直接的体现。它从一段文本出发，先由文本条件扩散模型生成一张室内图；然后用单目深度估计把这张图反投影成一张带颜色的网格（每个像素给一个深度值，按针孔相机模型反投影到相机坐标系，再变换到世界坐标系）；接着在已有网格上选一个新的相机位姿，渲染出该视角下的图像与深度作为条件，让扩散模型补全这个新视角里缺失的区域；补全的结果再次反投影、融合进全局网格。循环往复，直到房间闭合。这里的关键机制是「渲染—补全—融合」三步构成的迭代闭环，而不是一次前向。

把一步写成公式，设第 $k$ 步的相机位姿为 $T_k$，扩散模型在条件 $c_k$（文本 + 当前渲染）下输出图像 $I_k$ 与深度 $D_k$，反投影算子为 $\pi^{-1}$，融合算子为 $\oplus$，则全局网格的更新是：

$$ \mathcal{M}_{k+1} = \mathcal{M}_k \oplus \pi^{-1}\big(I_k, D_k, T_k\big),\qquad c_{k+1} = \mathrm{Render}\big(\mathcal{M}_{k+1}, T_{k+1}\big) $$

这条链路里每一步都引入误差，而误差不会消失，只会被下一步当作条件继承下去。深度估计的尺度偏差会让墙面在融合时错位；扩散模型在无纹理区域（白墙、地板）生成的像素彼此不一致，反投影后形成互相矛盾的薄片；融合算子若用简单的截断符号距离或体素平均，就会把错位的薄片抹成一层模糊的壳。这就是 Text2Room 的边界：深度误差沿迭代累积，房间越大、视角越多，接缝越难对齐。一个具体例子是：生成一间带长走廊的房间，走廊尽头的墙在第一步被估成 4 米远，第五步从侧面看时被估成 3.6 米远，两次反投影的墙面在融合后出现一道斜向的错层，从走廊中段看过去，墙上有一条不该存在的光照断裂线。

工程上的代价是显存的持续增长与融合算子的复杂度。每补全一个视角就多一张网格，若不及时做重采样与剪枝，网格面数随视角数线性上涨，而融合时的邻域查询若用稠密体素，分辨率每翻一倍显存翻八倍。这条管线不是「生成完就结束」，而是「生成到闭合为止」，闭合判据本身就是一个工程问题：是靠相机轨迹覆盖度，还是靠新视角补全区域的面积低于阈值，还是靠渲染出的深度图不再出现空洞。

二 · 分层高斯与引导深度扩散：WonderWorld 的表示选择

WonderWorld 走的是另一条路：从单张图生成可漫游场景，表示用分层高斯（FLAGS）。分层高斯的机制是把场景的高斯基元按「层」组织，每一层对应一个深度区间或一个语义层级（近景、中景、远景，或地面层、墙面层、天空层）。生成时不是一次性撒出全场高斯，而是先由引导深度扩散模型生成一张覆盖全景的深度图，再按深度把高斯分配到各层，层与层之间用深度排序与遮挡关系约束。这样做的直接好处是：单图生成时背面完全不可见，但分层结构给了背面一个「先验位置」——远景层的高斯可以被推到图像之外的区域，近景层的高斯则被约束在估计深度附近。

引导深度扩散的核心是把深度图当作扩散过程的目标，而不是把 RGB 当作唯一目标。设扩散模型在时刻 $t$ 的噪声预测网络为 $\epsilon_\theta$，条件为输入单图 $I_0$ 与文本 $c$，则训练目标是标准的噪声预测损失，但输出通道同时包含 RGB 与深度，或在潜空间里把深度编码为额外通道：

$$ \mathcal{L} = \mathbb{E}_{t,\epsilon}\Big\|\epsilon - \epsilon_\theta\big(z_t;\, t,\, I_0,\, c\big)\Big\|^2,\qquad z_t = \mathrm{Concat}\big(z^{\mathrm{rgb}}_t,\, z^{\mathrm{d}}_t\big) $$

分层高斯的渲染仍是标准 3DGS 光栅化：每个高斯有中心 $\mu$、协方差 $\Sigma$、不透明度 $\alpha$ 与球谐颜色，投影到屏幕后按深度排序做 alpha 混合。分层带来的额外代价是层间排序与接缝处理：当两层高斯在同一像素上深度接近时，排序抖动会产生闪烁；当一层的高斯被推到另一层的深度区间内，遮挡关系就错了。一个具体例子是：从一张客厅照片生成可漫游场景，相机向前推进到沙发背后，远景层（窗外景物）的高斯因为深度扩散估计偏近，被错误地排在了沙发层前面，于是沙发背后出现一片本不该可见的窗外颜色，这就是层间接缝失败的典型表现。

系统代价在于分层高斯的存储与更新。层数越多，每层的深度区间越窄，背面补全的自由度越大，但层间排序的候选对也越多，光栅化的排序开销随层数上升。工程判断是：层数不宜按语义无限细分，而应按「相机可能到达的深度范围」来定，因为漫游路径决定了哪些层会被真正看到，看不到的层再精细也是浪费。

三 · WorldGen 的三段式：LLM 布局、程序化资产、扩散补全

WorldGen 把「文本到可穿越世界」拆成三段：LLM 负责布局，程序化管线负责可交互资产，扩散负责视觉补全。这个拆分的动机是：布局是语义与空间关系的组合问题，适合用语言模型做符号推理；可交互结构（门、楼梯、碰撞体）需要精确的几何与拓扑，适合程序化生成；视觉细节（纹理、光照、磨损）需要 2D 先验，适合扩散。三段之间用中间表示衔接：LLM 输出一份场景图（物体类别、位置、朝向、尺寸、房间连通关系），程序化管线把场景图实例化为带碰撞体的网格，扩散再把网格渲染成带纹理与光照的图像，或直接在网格上做纹理补全。

伪代码思路如下：LLM 读入文本与约束（房间数量、面积、风格），输出 JSON 场景图；程序化模块按类别查资产库，若无匹配资产则用参数化模板生成（例如门用参数化的门框 + 门板 + 铰链）；扩散模块对每个资产或每个房间做纹理生成与光照一致化；最后物理引擎读入碰撞体做可穿越性验证。验证失败（门太窄、楼梯坡度不合理、物体悬空）就回传给 LLM 修正场景图，形成外循环。

这条管线的失败模式很具体：LLM 的空间推理不可靠，它可能把门放在两面墙的交线上，或让两个房间的连通门朝向墙壁；程序化资产库的覆盖度决定了「可交互」的上限，库里没有的类别只能退化成占位几何；扩散补全的纹理在不同房间之间不连续，因为每个房间独立生成，墙纸在门口处对不上。一个具体例子是：文本要求「一间带书架的卧室，书架靠墙，床在窗边」，LLM 给出的场景图里书架与床的包围盒重叠了 0.3 米，程序化实例化后两者穿模，物理引擎的碰撞检测在初始化时就报重叠，管线必须回退到布局阶段重新采样。

系统代价是管线复杂度：三段各有自己的失败模式与超参，端到端调试需要跨模块追踪。但相比单模型端到端，它的优势是可解释、可局部修复——布局错了改布局，纹理错了改扩散，不必重训整个模型。工程判断是：当「可穿越/可交互」是硬指标时，组合管线的可控性比单模型的视觉惊艳更重要。

四 · SceneCraft：让 LLM 写代码，用视觉反馈纠错

SceneCraft 把场景生成变成「写 Blender 脚本」的任务。LLM 读入文本描述，输出一段 Python 代码，调用 Blender 的 API 创建物体、设置材质、摆放相机与灯光；渲染出图像后，用 GPT-V 这类视觉语言模型检查渲染结果是否符合文本描述，若不符合则给出文字反馈，LLM 据此修改代码，循环直到通过检查或达到迭代上限。这条路径的机制核心是「代码即中间表示」：代码是可执行、可检查、可局部修改的，比隐式潜变量更容易定位错误。

把一次迭代写成流程：设第 $i$ 轮代码为 $C_i$，渲染结果为 $R_i = \mathrm{Blender}(C_i)$，视觉检查器输出反馈 $F_i = \mathrm{VLM}(R_i, \text{text})$，若 $F_i$ 判定不通过，则 $C_{i+1} = \mathrm{LLM}(C_i, F_i)$。这里的失败模式有两层：第一层是 API 层，LLM 可能调用不存在的函数、参数类型错误、坐标系约定搞反（Blender 是 Z 轴向上，而多数视觉模型假设 Y 轴向上），这类错误渲染直接报错或产出空场景；第二层是空间推理层，代码语法正确、渲染成功，但物体悬空、穿墙、比例失调，视觉检查器未必能识别，因为它看的是 2D 图像，遮挡与透视会掩盖 3D 错误。

一个具体例子是：文本要求「一张桌子，桌上放一个花瓶，花瓶在桌子左侧」。LLM 写的代码把花瓶的坐标设在桌子包围盒之外，渲染图里花瓶看起来「在桌子旁边」，2D 视觉检查器可能判为通过，但换一个视角就暴露了花瓶悬空。这说明视觉反馈的覆盖面受限于渲染视角的选择，检查器看到的视角越多，能发现的 3D 错误越多，但每多一个视角就多一次渲染与一次 VLM 调用，成本线性上升。

系统代价是迭代轮数与 API 稳定性。Blender 的 Python API 庞大，LLM 的调用正确率随 API 复杂度下降；VLM 的反馈是自然语言，LLM 对反馈的理解偏差会导致「改了但没改对」的震荡。工程上通常给代码加一层沙箱与超时，防止死循环或渲染卡死；给反馈加结构化字段（错误类型、涉及物体、期望位置）比自由文本更稳。

五 · PhysDreamer：可微 MPM 与材料参数的反问题

PhysDreamer 处理的是「物体有弹性/重量」这一层。输入是一段视频（物体在外力下的运动）与一个 3D 表示，输出是材料参数（杨氏模量、泊松比、密度等），使得用这些参数跑物理仿真时，仿真轨迹与视频观测吻合。机制是可微的物质点法（MPM）：把物体离散成物质点，每个点带质量、位置、速度与形变梯度；仿真步进包括粒子到网格的传输、网格上的动量更新、网格到粒子的传输；材料模型把形变梯度映射为应力，参数 $\mathbf{p}$ 就藏在材料模型里。因为整个仿真可微，可以对参数求梯度。

优化目标就是卷导语里给出的那条：

$$ \min_{\mathbf{p}}\ \sum_{t}\left\|\mathrm{Sim}_{\mathbf{p}}(\mathbf{x}_0,t)-\mathbf{V}_{\mathrm{prior}}(t)\right\|^2 $$

其中 $\mathrm{Sim}_{\mathbf{p}}(\mathbf{x}_0,t)$ 是从初始状态 $\mathbf{x}_0$ 出发、用参数 $\mathbf{p}$ 仿真到时刻 $t$ 的状态，$\mathbf{V}_{\mathrm{prior}}(t)$ 是视频先验在时刻 $t$ 的观测（通常是跟踪出的关键点位置或表面几何）。梯度通过仿真步反传，更新 $\mathbf{p}$。这里的失败模式是参数不唯一：不同的杨氏模量与阻尼组合可以产生几乎相同的轨迹，反问题欠定；视频只观测到表面，内部材料分布不可见，参数只能收敛到一个等效值而非真实值。另一个失败模式是仿真贵：MPM 的每一步都要做网格传输，反传要存每一步的中间状态，显存随仿真步数线性增长，长视频的优化在单卡上难以承受。

一个具体例子是：一段果冻被手指按压后回弹的视频，优化出的参数能让仿真在按压阶段吻合，但回弹阶段的振荡频率对不上，因为视频帧率不足以捕捉高频振荡，先验在时间上欠采样，梯度信号在振荡段很弱。工程判断是：材料参数优化适合短时、强交互的片段，长时自由振动需要额外的频率先验或更密的采样。

六 · 走通一个例子：从文本到可碰撞房间的完整链路

把上述机制串起来走一遍。输入文本：「一间小书房，一张书桌靠窗，一把椅子，桌上有一盏台灯，门在右墙。」第一步，WorldGen 的 LLM 布局输出场景图：房间尺寸、书桌包围盒与窗的相对位置、椅子与书桌的间距、台灯在桌面上的坐标、门在右墙的开口位置与宽度。第二步，程序化管线实例化：书桌与椅子从资产库取带碰撞体的网格，台灯用参数化模板生成（底座 + 灯杆 + 灯罩），门用参数化门框，窗在墙上开洞并加玻璃碰撞体（或设为不可穿越）。第三步，扩散补全给墙面、地板、桌面生成纹理，并做跨物体的光照一致化——窗光的方向要同时照亮桌面与地板，台灯的暖光要在桌面附近衰减。第四步，物理引擎读入碰撞体，做可穿越性验证：人形胶囊体从门口走到书桌前，检查路径上无穿模、门宽足够、桌下空间不阻挡。第五步，漫游验收：相机沿路径走一遍，检查墙是否直、门是否能过、台灯是否悬空、窗光是否随视角连续。

这条链路里每一步的失败都会在后面的步骤放大。LLM 把门放在右墙但开口与书桌重叠，程序化实例化后门框与书桌穿模，物理验证直接失败；扩散给每个物体独立生成纹理，桌面与台灯底座的颜色在接触处不连续，漫游时接触边缘出现一条色带；物理引擎的碰撞体是简化几何（书桌用包围盒），视觉网格是精细几何，两者不一致导致「看起来能过、实际撞住」或反之。验收不能只看截图，因为截图是单视角，而房间的问题是长距离、遮挡、接触处的，必须走一遍、撞一下、转个身。

工程判断落在「中间表示的选择」上：WorldGen 用场景图做中间表示，SceneCraft 用代码做中间表示，Text2Room 用网格做中间表示，WonderWorld 用分层高斯做中间表示。表示越符号化，越容易做约束与验证，但视觉细节越依赖后续补全；表示越连续（高斯、网格），视觉越直接，但空间约束越难施加。选择哪种表示，取决于验收标准是「好看」还是「能走能撞」——后者要求表示里必须显式携带碰撞体与连通关系，而这正是组合管线存在的理由。
