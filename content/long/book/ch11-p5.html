一 · 清洗管线的代码骨架：三件事的落地顺序

把「去重、许可过滤、质量分级」写成工程代码时，顺序不能颠倒。先做许可过滤再做去重，会浪费大量哈希算力在根本不能商用的资产上；先做质量分级再做去重，会让同一资产的不同 LOD 版本被当成高质量样本重复计数。正确顺序是：许可白名单 → 几何/纹理哈希去重 → 质量分级 → 长尾分层采样。许可过滤是布尔判定，成本最低；去重是 O(N) 哈希查表；质量分级要跑水密性检测和纹理分辨率统计，成本最高，放最后。

几何哈希不能直接用顶点坐标的字节串，因为同一资产在不同导出管线里顶点顺序、法线朝向、UV 原点都可能不同。可行做法是对「面数 + 包围盒对角线长度 + 体积 + 表面积」四元组做量化后哈希，量化步长取包围盒对角线的千分之一。纹理哈希则对 base color 图做感知哈希（pHash），对 metallic/roughness 通道单独做直方图哈希，因为很多资产几何不同但共用同一套材质贴图，这类「材质复用」在去重时应当保留而不是删除。

$$ h_{\mathrm{geo}} = \mathrm{hash}\Big(\big\lfloor \tfrac{F}{1} \big\rfloor,\ \big\lfloor \tfrac{d}{\epsilon} \big\rfloor,\ \big\lfloor \tfrac{V}{\epsilon^3} \big\rfloor,\ \big\lfloor \tfrac{A}{\epsilon^2} \big\rfloor\Big),\quad \epsilon = 10^{-3}\,d $$

系统代价在于：哈希去重只能抓「近似复制」，抓不到「同一语义不同造型」的长尾稀释。比如一千个不同款式的椅子，几何哈希全部不同，但它们对「椅子」这一概念的信号贡献高度冗余。真正的去重需要语义聚类，而语义聚类又要跑一遍前馈模型提特征，成本翻倍。失败模式是：去重阈值设得太松，训练集里同一资产的十个变体全部保留，模型过拟合到该资产的纹理细节；设得太紧，把合法的对称变体（左右手版本）误删，长尾覆盖反而变窄。

具体例子：一个从 Objaverse 抽出的子集，若不做许可过滤，混入 CC-BY-NC 资产，商用产品线在法务审计时整批下架；若不做纹理 pHash，同一张贴图被 50 个不同网格引用，训练时该贴图的梯度被放大 50 倍，材质分支严重偏置。质量分级里，水密性用「边界边数量 / 总边数」度量，超过阈值即判为开放网格，这类资产在引擎导入时无法做实体碰撞，应降级到「仅渲染」桶。

二 · UV 展开的调参与接缝代价

自动 UV 展开的本质是「在保持面积和角度尽量不变的前提下，把曲面切成若干片摊平」。工程上常用的是基于 LSCM（最小二乘保角映射）或 ABF（角度基函数）的展开器，调参集中在三个旋钮：接缝惩罚权重、拉伸容忍度、图集填充率。接缝惩罚权重决定算法多愿意「切开」高曲率区域；权重高则接缝少但拉伸大，权重低则接缝多但每片更保角。

$$ E_{\mathrm{UV}} = \sum_{t}\Big( \big\|\mathbf{J}_t - \mathbf{R}_t\big\|_F^2 + \lambda_s \sum_{e\in\partial}\|\Delta u_e\|^2 \Big) $$

第一项是每三角片的雅可比与旋转矩阵之差，度量保角性；第二项是接缝边两侧 UV 坐标差，惩罚接缝长度。λ_s 就是那个旋钮。SF3D 用 0.5 秒前向直接出 UV，意味着它把展开器蒸馏进了网络，网络输出的是「已经切好片、摊平、打包进图集」的 UV 坐标，而不是让优化器在线求解。代价是：网络学到的接缝模式受训练集分布约束，遇到训练集里没见过的拓扑（比如高 genus 的镂空件），接缝会落在视觉上突兀的位置。

失败模式很具体：接缝穿过高光区域时，法线贴图在接缝两侧不连续，引擎里出现一条亮线；接缝穿过纹理细节密集区时，mipmap 在接缝处采样越界，出现渗色。调参的工程判断是：把接缝惩罚权重与「曲率积分」挂钩，曲率大的区域自动降低惩罚、允许切开，曲率平缓的区域提高惩罚、强制连续。拉伸容忍度则按「纹理像素密度」设定，密度高的资产容忍度低，因为拉伸在近景可见。

例子：一个带镂空花纹的金属件，若 λ_s 设得过高，展开器拒绝切开镂空边缘，导致花纹区域拉伸到 3 倍以上，base color 贴图在花纹处糊成一团；若 λ_s 设得过低，接缝数量翻三倍，图集填充率跌到 60% 以下，大量图集空间浪费在接缝边距上。图集填充率的经验下限是 75%，低于此值应触发「重新展开」而不是硬塞。

三 · PBR 三通道与 delighting 的误差传播

PBR 的 base color、metallic、roughness 三通道不是独立的：base color 是「去光照后的反照率」，metallic 决定有多少能量进入镜面反射，roughness 决定镜面瓣的宽度。delighting 的任务是从一张带光照的 RGB 图里反解出 base color，公式是逐像素除法，但光照 E_light 是未知的、空间变化的、含遮挡的。SF3D 的做法是用前向网络同时预测 base color 和一张低频光照图，把除法变成「网络隐式学习」。

$$ \mathbf{c}_{\mathrm{base}} = \mathrm{clamp}\!\left(\frac{\mathbf{I}}{\mathbf{E}_{\mathrm{light}} + \varepsilon}\right),\qquad \mathbf{E}_{\mathrm{light}} = \mathbf{E}_{\mathrm{amb}} + \sum_{k} \mathbf{L}_k \max(0, \mathbf{n}\cdot\mathbf{l}_k) $$

误差传播的机制：暗部像素的 I 很小，分母 E_light 的估计误差被放大，base color 出现噪点；高光像素的 I 接近饱和，除法后 base color 被压到接近零，重光照时该区域永远黑。这就是「暗部/高光处容易失真」的数学根源。工程上的缓解手段是：对暗部像素降低置信度权重，对高光像素做「高光剥离」预处理，把镜面分量先减掉再除法。

系统代价：delighting 误差不会在训练时暴露，因为训练损失是在「同一光照下重建 RGB」，网络可以学会「用错误的 base color 配合错误的光照图，重建出正确的 RGB」。这叫「误差对冲」，一旦换光照就崩。失败模式是：产品在引擎里换一张 HDRI，金属件变成塑料感，或者粗糙度通道被烘死导致所有材质看起来一样哑光。Hunyuan3D 2.1 把 PBR 做成生产级，靠的是多光照监督——同一资产在多组光照下渲染，强制网络学到光照不变的反照率。

例子：一个不锈钢水壶，原图高光是一条竖直亮带。若 delighting 把亮带当成 base color 的一部分，base color 里就有一条白色条纹；换到暖色光照下，这条条纹依然是白的，物理上不可能。检查方法是：把 base color 单独渲染成无光照的 albedo 图，若看到明显的高光形状，说明 delighting 失败。调参上，metallic 通道应当接近二值化（金属要么是金属要么不是），roughness 通道应当保留连续分布但避免全图同值。

四 · 评测口径的迁移：从 PSNR 到引擎导入通过率

PSNR/SSIM 度量的是「渲染图与参考图的像素差」，它奖励「在训练视角下看起来像」，但不奖励「换视角几何正确」「换光照材质正确」「进引擎不报错」。这三个「不奖励」正是产品化的死穴。新视角几何误差的做法是：在留出视角上渲染深度图或法线图，与真值比对，度量的是几何而非颜色。引擎导入通过率的做法是：把生成的 glTF/FBX 塞进目标引擎的导入管线，统计「非流形边、退化三角、UV 越界、材质槽缺失」四类错误的触发率。

指标度量对象失效场景工程代价
PSNR/SSIM训练视角像素换视角几何漂移低，可批量
新视角几何误差留出视角深度/法线背面拓扑错误中，需多视角渲染
引擎导入通过率网格合法性非流形/UV 越界高，需跑引擎
人工盲评可用性主观分材质塑料感最高，不可批量

评测泄漏是另一个陷阱：Objaverse 的某些资产在多个数据集中重复出现，若训练集和评测集共享同一资产的不同视角，PSNR 会虚高。防泄漏的做法是对评测集做几何哈希，与训练集哈希表求交，交集资产全部剔除。系统代价是评测集规模缩水，统计置信度下降，需要更多人工盲评补足。

具体例子：一个生成资产 PSNR 很高，但导入引擎后因「UV 坐标超出 [0,1] 区间」被贴图采样器钳制，纹理在边缘出现拉伸条带。PSNR 完全看不到这个问题，因为训练渲染器对 UV 做了 wrap 处理。引擎导入通过率能抓到它，代价是要为每个资产跑一次导入，吞吐远低于纯渲染评测。工程判断是：把导入通过率作为「门禁指标」，不过门禁的资产不进入盲评，节省人工成本。

五 · 五道自测题

以下五题覆盖本卷的机制、公式、代价与失败模式，答不上来说明某一节没读透。

  • 题一：给定几何哈希的四元组（面数、包围盒对角线、体积、表面积），说明为什么量化步长取对角线的千分之一，以及步长过大和过小分别导致什么失败模式。
  • 题二：写出 UV 展开能量函数的两项，解释 λ_s 调高时接缝数量、拉伸程度、图集填充率三者的联动方向，并给出一个 λ_s 设置不当的具体视觉症状。
  • 题三：delighting 公式中分母加 ε 的作用是什么？为什么暗部像素的 base color 误差被放大，而高光像素的 base color 被压到接近零？给出一个检测 delighting 失败的可视化方法。
  • 题四：PSNR 高但引擎导入失败的资产，其失败原因通常落在哪四类错误里？为什么训练渲染器看不到这些错误？
  • 题五：多光照监督如何缓解「误差对冲」？如果只有单光照数据，工程上能用什么替代手段降低 delighting 误差对重光照的影响？

题一的要点是：步长过大把不同资产误判为重复，步长过小让同一资产的不同导出被当成不同资产。题二的要点是 λ_s 与接缝数反相关、与拉伸正相关，填充率随接缝数下降。题三的要点是 ε 防止除零，暗部分母小误差放大，高光分子饱和除法后趋零，检测方法是单独渲染 albedo 看有无高光形状。题四的要点是非流形边、退化三角、UV 越界、材质槽缺失，训练渲染器做了容错处理所以看不见。题五的要点是多光照强制光照不变性，单光照替代手段是高光剥离加置信度加权。

这五题不是知识回忆题，是工程判断题：每题都要求你给出「调参方向」和「失败症状」，因为数据与材质这一层的错误从来不是「模型不收敛」，而是「收敛了但资产进不了引擎」。清洗管线的三件事顺序、UV 展开的三个旋钮、delighting 的误差传播路径、评测口径的四类指标，构成了一条从原始资产到可商用资产的完整链路；链路上任何一环的调参失误，都会在最终的重光照或引擎导入时以具体症状暴露，而不是在训练损失曲线上暴露。
