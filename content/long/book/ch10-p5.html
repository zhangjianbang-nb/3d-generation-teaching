一 · 代码骨架：把「布局—程序化—扩散—物理」拆成可测的四个函数

场景生成管线的第一工程决策不是选模型，而是把整条链路切成职责单一、可单独验收的函数。以 WorldGen 的「文本到可穿越世界」为例，它被拆成 LLM 布局、程序化资产、扩散补全三段；SceneCraft 则把「写 Blender 代码」与「用 GPT-V 看渲染反馈纠错」分成生成与校验两个角色。落到代码结构上，一个可维护的骨架是四个入口：layout(prompt) -> scene_graph、instantiate(scene_graph) -> assets、render_and_infill(scene, views) -> radiance、simulate(scene, params) -> trajectories。四个函数之间只通过显式数据结构通信：场景图里每个节点带语义标签、包围盒、父子变换、可交互标记；资产表里每个条目带网格、材质、碰撞体；辐射场层带相机轨迹与深度图；物理层带材料参数向量 p。这种切法的直接好处是失败可定位：墙不直是布局或程序化的错，接缝裂是扩散融合的错，物体穿模是碰撞体与物理参数的错，而不是「模型不行」。

布局函数的伪代码思路必须写成可判定的约束求解，而不是让 LLM 自由发挥。典型做法是让 LLM 输出一个 JSON 场景图，字段包括房间多边形顶点、门洞位置与宽度、家具的类别与相对关系（「沙发靠墙、茶几在沙发前 0.5 米」），然后由一段确定性代码做几何合法性检查：多边形是否简单（无自交）、门洞是否落在墙段内、家具包围盒是否互相重叠、是否越出房间边界。检查失败就把错误信息回灌给 LLM 重写，形成「生成—校验—重写」循环，这与 SceneCraft 用 GPT-V 看渲染图纠错的思路同构，只是校验器从视觉模型换成了几何断言。这里有一个具体机制值得写进代码：把房间多边形做耳切三角化后再判自交，比逐边两两求交稳定，因为三角化本身就会暴露退化顶点。

程序化函数的职责是把语义节点变成可碰撞的几何。家具用参数化模板（柜体=六个盒子、桌腿=四个圆柱），墙用挤出多边形，门洞用布尔差从墙段里挖出来。这一步的系统代价是资产多样性受模板库限制：模板越少，房间越像样板间；模板越多，碰撞体与视觉网格的一致性维护成本越高。失败模式很具体：程序化生成的柜子视觉上是封闭盒体，但碰撞体只做了外包围盒，于是角色能「站进」柜子里；或者门洞挖了但没在碰撞层同步挖，角色被一堵看不见的墙挡住。工程判断是碰撞体必须由同一份几何派生，而不是另写一份简化版。

扩散补全函数负责把程序化几何「拍好看」。Text2Room 的机制是估深度、反投影成网格、不断选新视角补全并融合，直到房间闭合；WonderWorld 用分层高斯加引导深度扩散，从单图长出可漫游场景。代码上这两者都要求一个「视角选择器」：给定已覆盖区域，选出覆盖率最低的候选视角，渲染当前场景的深度与颜色，把缺失区域交给扩散模型补，再把新内容反投影回三维表示并做融合。融合是整条管线最容易埋雷的地方，因为不同视角的深度估计有偏差，反投影后的点云在接缝处会错位。Text2Room 的边界正是「深度误差累积」：每补一个视角就引入一次深度误差，视角越多累积越重，墙脚与门框处最先开裂。

物理函数是唯一需要「参数唯一性」的环节。PhysDreamer 用视频先验加可微 MPM 优化材料参数，让物体有弹性与重量，其目标函数是让仿真轨迹逼近视频观测：

$$\min_{\mathbf{p}}\ \sum_{t}\left\|\mathrm{Sim}_{\mathbf{p}}(\mathbf{x}_0,t)-\mathbf{V}_{\mathrm{prior}}(t)\right\|^2$$

这里的 p 是杨氏模量、泊松比、密度一类材料参数。代码实现上，MPM 的每一次可微前向都要存粒子网格传输的中间量，反向传播沿时间步展开，显存随帧数线性涨。失败模式有两类：一是参数不唯一，不同 p 组合能拟合同一段视频，优化停在哪个解取决于初始化；二是仿真太贵，优化一轮要跑几十次 MPM 前向，参数维度一高就不可行。工程上常见的折中是先固定密度、只优化弹性参数，把维度压到二到三维，再用少量真实视频片段做校准。

二 · 调参：四类旋钮与它们的耦合

场景管线的调参不是调一个学习率，而是调四类互相耦合的旋钮：布局约束的松紧、程序化模板的粒度、扩散补全的视角策略、物理参数的搜索范围。把它们分开调会互相打架，必须按依赖顺序调。

第一类是布局约束。约束太松，LLM 会生成家具悬空、门开在墙角、走廊宽度不足一人通过；约束太紧，LLM 反复重写也过不了校验，循环次数暴涨。可调的量是包围盒重叠容差与最小通行宽度。经验上的调法是把「硬约束」（多边形简单、门洞在墙内）与「软约束」（家具不重叠、通行宽度）分开：硬约束失败直接重写，软约束失败只记罚分并接受次优解。这样能把重写次数压住，同时保留布局多样性。系统代价是软约束被违反的房间会在漫游时暴露问题，比如沙发与茶几间距过小导致角色卡住，所以软约束的罚分阈值要按角色碰撞半径来定，而不是拍脑袋。

第二类是程序化模板粒度。模板越细，视觉与碰撞越一致，但资产库维护成本越高；模板越粗，生成越快，但房间看起来像积木。一个具体机制是「两级模板」：一级模板只定义拓扑（柜体几个面、桌腿几根），二级模板定义尺寸范围与材质槽位，实例化时按房间尺寸采样。调参的对象是尺寸采样的方差，方差太大则家具比例失调（床头柜比床还高），方差太小则每个房间一模一样。失败模式是模板的碰撞体与视觉网格在极端尺寸下不同步，比如拉伸过度的桌子碰撞体穿出桌面。

第三类是扩散补全的视角策略。核心旋钮是「新视角的覆盖率阈值」与「融合时的深度置信权重」。阈值定得太高，每个视角只补一小块，视角数爆炸，Text2Room 式的深度误差累积更快；阈值定得太低，一个视角要补大片缺失区域，扩散模型在无条件下胡乱生成，接缝处出现结构错乱。融合权重决定新旧观测谁说了算：新观测权重高则接缝锐利但易错位，旧观测权重高则接缝平滑但细节被抹。WonderWorld 的分层高斯结构在这里提供了一种缓解：不同层承担不同尺度，层间接缝是它明确的边界，调参时要专门检查层与层之间的过渡区是否出现「双层墙」。

第四类是物理参数搜索范围。PhysDreamer 式的优化对初值敏感，杨氏模量的搜索区间跨几个数量级，若初值落在刚性区间，优化会停在「几乎不变形」的解，视频里明显的弹性就被拟合没了。调法是按材质类别给先验区间（软体、布料、硬质各一段），把优化限制在区间内，并对参数做对数尺度归一化，否则梯度在数量级差异下极不稳定。系统代价是每个材质类别都要一段校准视频，没有视频先验的类别只能退回默认参数，仿真看起来「不像那个东西」。

四类旋钮的耦合点在于「一致性预算」：布局越松、模板越粗、视角越少，视觉一致性越差，物理参数越难从不可靠的几何上估出来。调参的实际顺序是先定布局硬约束与通行宽度（决定可玩性），再定模板粒度（决定碰撞可靠性），再定视角策略（决定视觉接缝），最后才动物理参数（依赖前三者的几何质量）。反过来调会把物理误差误判成参数问题，白跑优化。

三 · 检查清单：把「走一遍、撞一下、转个身」写成可执行项

场景验收不能只看截图，静态截图会掩盖绝大多数场景问题。把「走一遍、撞一下、转个身」翻译成检查清单，每一项都要有明确的判定方法与失败信号。

几何一致性项。墙是否直：沿每面墙取三个以上采样点，拟合平面，检查残差是否超过墙厚的一个小比例；残差大说明深度反投影在长距离上漂了，是 Text2Room 式迭代补全的典型症状。接缝是否对：在相邻墙段与门框处取剖面，检查两侧几何的法线与位置是否连续，出现台阶就是融合错位。地面是否平：沿漫游路径采样高度，检查是否有超过角色步高的凸起，这是程序化地板与扩散补全深度不一致的常见产物。

可通行性项。门是否能过：用角色碰撞体沿门洞中线做扫掠，检查是否与门框或墙段相交；失败信号是角色在门口抖动或被弹回。走廊是否连通：从入口做一次可达性搜索，检查是否所有标记为「可进入」的房间都能到达；失败信号是某房间被家具堵死。楼梯与坡道是否可走：检查坡度是否超过角色爬升上限，以及台阶高度是否超过步高。这一项最容易被忽略，因为截图里楼梯很好看，走上去才发现角色悬空。

碰撞与穿模项。物体是否会穿模：让角色以不同速度撞向家具，检查是否嵌入网格内部；失败信号是相机穿进柜体看到内壁。物体是否可推：对标记为可交互的物体施加冲量，检查是否按物理参数运动而不是原地不动或飞出场景；后者说明质量参数估错或碰撞体缺失。堆叠是否稳定：在桌上放多个物体，检查是否在仿真若干步后塌陷，这是 MPM 参数与接触处理不稳的典型表现。

光照连续性项。转个身看光照：沿漫游路径连续采样，检查同一面墙在不同视角下的亮度是否跳变；跳变说明不同视角的扩散补全各自带了不同的隐式光照，融合时没有对齐。阴影是否随视角一致：检查同一物体投影在相邻视角下是否落在同一位置，错位说明深度与几何不一致。这一项在分层高斯表示里尤其要查层间过渡，因为不同层可能各自拟合了不同的光照。

物理合理性项。弹性是否像：对软体施加相同冲量，比较形变恢复时间是否落在该材质的合理区间；太快像石头，太慢像橡皮。重量是否像：比较不同物体的推动难易，检查是否与视觉体积相符；一个巨大的花瓶被轻轻一碰就飞，说明密度参数错了。仿真是否稳定：长时间运行后检查是否出现粒子爆炸或穿透，这是 MPM 时间步与网格传输的数值问题，不是参数问题。

把这五类项写成脚本，每项输出通过/失败与定位信息（哪面墙、哪个门、哪个物体），就能在没有人眼的情况下跑回归。清单的价值不在条目多，而在每条都能定位到具体机制：墙不直指向深度累积，门不过指向布局或碰撞体派生，光照跳变指向融合策略，弹性不对指向参数不唯一。

四 · 五道自测题：检验你是否真的理解了组合管线

第一题。Text2Room 从文本出发，估深度、反投影成网格、不断选新视角补全并融合直到房间闭合。问：如果房间很大而视角选择器总是挑覆盖率最低的区域，为什么墙脚与门框处最先出现裂缝？请从深度误差累积与融合权重的角度回答，并给出一个能缓解该问题的工程改动。要点在于：每次补全都引入一次深度估计误差，反投影后点云在接缝处错位，融合时若新观测权重高则错位被固化；缓解手段可以是沿墙脚与门框加几何先验约束（墙必须竖直、门框必须共面），或在融合时对深度做局部一致性滤波。

第二题。WonderWorld 用分层高斯加引导深度扩散，从单图生成可漫游场景。问：分层结构缓解了什么问题，又引入了什么新边界？请指出层间接缝的检查方法。要点在于：分层让不同尺度或不同距离的内容分开建模，缓解了单一高斯表示在远近尺度上的容量冲突；新边界是层与层之间的过渡区可能出现「双层墙」或光照不一致；检查方法是在过渡区沿视线采样，比较两层的高斯贡献是否出现重叠或空洞。

第三题。WorldGen 把文本到可穿越世界拆成 LLM 布局、程序化资产、扩散补全。问：这条管线里哪一步的失败最难定位，为什么？请给出一个把失败归因到具体步骤的诊断顺序。要点在于：扩散补全的失败会伪装成布局或程序化的问题（比如墙看起来歪了，实际是补全深度错了），所以诊断顺序应是先查几何断言（布局多边形、门洞、包围盒），再查碰撞体与视觉网格是否同源，最后才查扩散融合的接缝与光照。

第四题。SceneCraft 让 LLM 写 Blender 代码并用 GPT-V 看渲染反馈纠错。问：这个循环的收敛条件应该怎么定，为什么不能只看「渲染图看起来对了」？请指出 API 与空间推理两类失败的具体表现。要点在于：收敛条件要包含几何断言（物体是否在预期位置、是否重叠、是否越界）与视觉断言（渲染是否包含预期物体），只靠视觉判断会放过「看起来对但坐标错」的情况；API 失败表现为代码调用不存在的函数或参数，空间推理失败表现为物体位置关系与文本描述不符（比如椅子飘在空中）。

第五题。PhysDreamer 用视频先验加可微 MPM 优化材料参数，目标是最小化仿真轨迹与视频观测的差异。问：为什么这个优化可能不唯一，工程上如何把搜索空间压到可接受？请写出你会固定的参数与你会优化的参数，并说明仿真代价的来源。要点在于：不同材料参数组合能拟合同一段轨迹，尤其当视频只覆盖有限视角与有限运动时；压缩手段是按材质类别给先验区间、固定密度只优化弹性参数、用对数尺度归一化；仿真代价来自可微 MPM 沿时间步的反向传播，显存与计算随帧数线性增长。

这五道题共同指向一个判断：场景生成的难点不在单点视觉质量，而在跨步骤的一致性归因。能答对的人应该能说出「这个症状该去查哪个函数的哪个中间量」，而不是笼统地说「模型不够好」。

五 · 工程判断：组合管线为什么比单模型更值得投入

把第十卷的五个方法放在一起看，会发现它们不是互相替代，而是各自占据管线的一段。Text2Room 占据「房间闭合」这一段，WonderWorld 占据「单图到可漫游」这一段，WorldGen 占据「文本到可穿越」的编排，SceneCraft 占据「代码生成加视觉校验」，PhysDreamer 占据「物理参数估计」。单模型端到端在这些段上各自有边界：Text2Room 的深度误差累积、WonderWorld 的层间接缝与背面、WorldGen 的管线复杂度、SceneCraft 的 API 与空间推理、PhysDreamer 的参数不唯一与仿真昂贵。组合管线的价值不是把五个模型串起来就完事，而是让每一段的失败模式被隔离在各自的函数边界内，可以用断言与检查清单定位。

具体机制上，组合管线靠三样东西维持一致性：共享的场景图（语义与空间关系的唯一真相）、同源的几何（视觉网格与碰撞体从同一份数据派生）、显式的融合策略（新观测与旧观测的权重规则写死在代码里而不是隐式学出来）。这三样东西的代价是工程复杂度：场景图的 schema 要版本化，几何派生要保证不漂移，融合策略要针对每种表示（网格、高斯、分层高斯）分别实现。但相比单模型端到端把一致性交给隐式表示去「自己学」，组合管线的失败可复现、可回归、可局部替换——换掉扩散补全那一段不影响布局与物理。

一个具体的工程判断是：先做可通行性与碰撞的硬约束，再做视觉美化。因为可通行性是二值的（能过或不能过），视觉质量是连续的（好看程度），前者失败会让整个场景不可用，后者失败只是不好看。把布局硬约束与碰撞体同源放在管线前段，把扩散补全放在后段，能让「走一遍、撞一下」的检查在便宜阶段就拦住大部分致命问题，而不是等到渲染完才发现门过不去。这也是为什么场景验收清单里几何与可通行性项排在最前，光照与物理合理性项排在后面。

最后落到一个具体的机制上：融合策略里的深度置信权重应当与视角覆盖率挂钩，覆盖率低的视角其深度估计置信度低，融合时权重应下调，否则 Text2Room 式的误差会沿视角链累积。这个权重不是一个可以拍脑袋的超参，它应该由视角选择器记录的覆盖率与深度估计的局部一致性共同决定，并在检查清单的「接缝是否对」一项里被显式验证。工程上把这条规则写进融合函数，比事后调参更能压住长距离漫游时的漂移。
