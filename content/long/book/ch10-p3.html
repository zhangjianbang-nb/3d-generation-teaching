一 · 迭代补全的误差账本：Text2Room 为什么越走越歪

Text2Room 的数据流不是「一次生成整间房」，而是「生成一张图 → 估深度 → 反投影成网格 → 选下一个视角 → 补全 → 融合」。这条链上每一步都带误差，而误差不是并列的，是串联放大的。深度估计给出的是相对深度，尺度靠单目线索猜；反投影把像素抬到 3D 时，一个像素的深度偏差 δd 在焦距 f 下对应的横向漂移近似为 δx ≈ δd · u/f（u 为像素坐标）。当视角转过去、新生成的图再反投影，两次反投影的网格要在重叠区做融合，融合的判据是「几何接近 + 颜色接近」，于是深度偏差直接变成接缝错位。

更麻烦的是闭环条件。房间要闭合，意味着绕一圈回到起点时，最后一块补全的网格必须和最初那块对齐。但迭代过程中每补一个视角，网格就被「最近一次观测」轻微拉扯一次，早期观测的权重被稀释。用伪代码说清楚这个漂移：

$$ \mathbf{G}_{k+1} = \mathrm{Fuse}\big(\mathbf{G}_k,\ \Pi(\mathbf{I}_k, \mathbf{D}_k, \mathbf{T}_k)\big),\quad \mathbf{T}_{k+1} = \mathrm{SelectView}(\mathbf{G}_{k+1}) $$

其中 Π 是反投影，Fuse 是带置信度的加权融合，SelectView 选「覆盖最少、信息增益最大」的新视角。问题在于 Fuse 的置信度往往来自深度网络自身的方差，而深度网络在纹理弱区（白墙、天花板）方差大却常常给出过度自信的输出，于是弱纹理区的融合权重失真，墙面的平面性被破坏。失败模式很具体：绕房间一圈后，门框两侧的墙面出现几厘米的错台，地板和墙的交接处出现一条斜缝，天花板因为视角仰角大、深度误差最大，最容易翘曲。

系统代价体现在两处。其一是显存与时间随视角数线性增长，每补一个视角都要重算融合、重建网格、再做可见性剔除；其二是「闭合判定」本身没有可靠信号，工程上只能靠「覆盖率达到阈值 + 重叠区几何残差小于阈值」硬停，停早了房间有洞，停晚了接缝反复被改写。一个具体例子：生成一间带两扇窗的卧室，绕行到窗户背面时，窗外的「室外」没有任何监督，模型只能凭文本先验编一段街景，反投影后这段街景和窗框的深度不连续，融合时被当成噪声削掉，结果窗户变成一块贴图平板。验收时走一遍就能看出来：转身看窗，视差消失。

二 · 分层高斯的层间账：WonderWorld 的接缝与背面

WonderWorld 走的是另一条路：单图输入，用引导深度扩散把图「撑」成一个可漫游场景，表示用分层高斯（FLAGS）。分层的意思是场景被切成若干层，每层是一组高斯，层与层之间有深度排序和遮挡关系。引导深度扩散负责给新视角提供几何先验，高斯负责显式表达和快速光栅化。这条管线的核心代价不在生成，而在「层间一致性」。

高斯泼溅的合成是按深度排序后做 alpha 混合，公式上每个像素的颜色是沿视线的加权和：

$$ C = \sum_{i \in \mathcal{N}} c_i \alpha_i \prod_{j

分层之后，这个求和被拆成「层内求和 + 层间合成」。层内的高斯由同一张扩散图监督，颜色一致；层间的高斯由不同视角的扩散结果补出来，颜色和几何都可能不一致。失败模式是「层间漏光」：当两层高斯的深度估计在边界处交叠，排序抖动会让前景层的高斯被后景层的高斯穿透，表现为物体边缘一圈闪烁的毛边。走动时最明显，静止截图看不出来。

背面是第二个账。单图只看到一面，背面全靠深度扩散「编」。扩散模型编背面时用的是类别先验（椅子背面大概还是椅子），不是几何约束，所以背面的高斯密度往往偏低、法线朝向混乱。当视角绕到背面，光栅化发现高斯太稀疏，出现空洞，补洞只能靠邻域高斯拉伸，结果是背面糊成一片。系统代价是：为了压住层间抖动，工程上要给每层加深度正则和层间排斥项，训练或优化时间上升；为了补背面，要额外采样多个虚拟视角做一致性约束，显存占用随层数和视角数上升。

具体例子：从一张客厅沙发图生成可漫游场景，正面看沙发皮质纹理连续，绕到侧面发现扶手和靠背的接缝处高斯密度突变，再绕到背面，沙发背面是一团低密度的糊状高斯，颜色比正面暗一档。这不是审美问题，是几何问题：背面的深度扩散没有收到任何来自正面的硬约束，只有类别先验。工程判断是，单图漫游场景的验收必须包含「绕背面」这一项，且要看背面在移动中的稳定性，而不是看一张背面截图。

三 · 组合管线的接口税：WorldGen 的三段式与 SceneCraft 的代码回路

WorldGen 把「文本到可穿越世界」拆成三段：LLM 出布局（房间、物体、空间关系），程序化资产生成可交互结构（碰撞体、可开启的门），扩散补全视觉细节。SceneCraft 则让 LLM 直接写 Blender 代码，渲染出来再用 GPT-V 看反馈纠错。两者都是组合管线，代价都落在「接口」上，而不是落在单个模型的能力上。

WorldGen 的接口税有三笔。第一笔是布局到程序的翻译：LLM 输出的是语义关系（「沙发在窗边，茶几在沙发前」），程序化需要的是坐标、朝向、包围盒。翻译过程要插一个约束求解，把「窗边」解成「距窗 0.5 米、朝向窗」，这个求解没有唯一解，不同采样给出不同布局，同一段文本两次生成可能门的位置不同。第二笔是程序化到扩散的翻译：程序化给出的是低模和碰撞体，扩散要在低模上贴视觉，贴的时候如果低模的 UV 或法线不对，扩散结果会出现拉伸和光照错位。第三笔是可穿越性验证：布局合理不等于连通，门可能被程序化资产堵住，走廊可能宽度不够，这些在扩散阶段看不出来，只有走一遍才暴露。

SceneCraft 的回路是「写代码 → 渲染 → 看图 → 改代码」。这个回路的失败模式是 API 幻觉和空间推理错误。LLM 会写出不存在的 Blender API，或者把旋转矩阵写反，渲染出来物体悬空或穿地。GPT-V 看渲染图能发现「沙发浮在空中」，但很难发现「沙发和墙的间距是 3 厘米导致人过不去」，因为后者需要尺度推理，而渲染图的透视会掩盖尺度。系统代价是每次纠错都要重新渲染，渲染是串行瓶颈，回路轮数越多，时间成本越高；且反馈信号是图像级的，不是几何级的，纠错收敛慢。

具体例子：让 SceneCraft 生成「一间有书架和阅读椅的书房」，第一轮代码把书架贴在墙上但忘了设碰撞体，第二轮加了碰撞体但书架和墙重叠了 5 厘米，第三轮 GPT-V 从渲染图看出书架底部被墙吃掉一条，改坐标。三轮之后视觉上对了，但走进去发现阅读椅和书架之间的通道只有 40 厘米，人过不去。这就是接口税的典型表现：视觉验收通过，可穿越性验收失败。工程上必须把「连通性检查」做成独立于渲染的几何步骤，而不是指望图像反馈。

四 · 物理参数的病态账：PhysDreamer 的可微 MPM 与不唯一性

PhysDreamer 用视频先验加可微 MPM 优化材料参数，让生成的物体有弹性、有重量。它的目标函数是让仿真轨迹逼近视频观测轨迹：

$$ \min_{\mathbf{p}}\ \sum_{t}\left\|\mathrm{Sim}_{\mathbf{p}}(\mathbf{x}_0,t)-\mathbf{V}_{\mathrm{prior}}(t)\right\|^2 $$

这里 p 是材料参数（杨氏模量、泊松比、密度、阻尼等），Sim 是 MPM 仿真，V_prior 是视频先验给出的顶点轨迹。问题在于这个反问题的病态性：不同的参数组合可以产生几乎相同的轨迹。软而重的物体和硬而轻的物体在低速小变形下轨迹接近，视频先验的分辨率和帧率又限制了可辨识性。于是优化会收敛到一个「能复现视频但物理上不对」的参数点，换一个初始条件或换一个交互力度，行为就崩了。

MPM 的仿真代价是另一个账。MPM 要在网格和粒子之间来回传输，每步仿真要做粒子到网格的散射、网格上的动量更新、网格到粒子的收集，时间步长受 CFL 条件限制：

$$ \Delta t \le \frac{h}{v_{\max}} $$

h 是网格间距，v_max 是最大粒子速度。软材料变形大、速度高，步长小，步数多；硬材料步长可以大，但显存和稳定性要求高。可微 MPM 还要存每步的中间量做反向传播，显存随步数线性增长，长视频先验直接撑爆显存。失败模式是「仿真爆炸」：优化过程中参数跑到病态区（比如泊松比接近 0.5），MPM 的体积锁死导致数值不稳定，轨迹发散，梯度爆炸，优化崩掉。工程上要加参数边界和正则，但正则又会把参数拉向先验均值，削弱可辨识性。

具体例子：给一个果冻状的方块做物理参数估计，视频里它被轻推后晃动几下停住。优化出的参数能复现这段晃动，但把同一方块从更高处落下，仿真显示它像石头一样不弹——因为优化只见过小变形，大变形区的参数没有被约束。验收时必须换交互条件重测，而不是只看原视频的重放。这就是物理参数不唯一性的工程含义：单条轨迹的拟合不等于物理正确，参数的可辨识性要靠多条件激励。

五 · 一致性的系统账：长距离漂移、接触崩坏与验收清单

把上面四条管线放在一起看，共性问题是一致性在长距离、遮挡、接触三处崩。长距离漂移来自串联误差累积，Text2Room 的闭环错位和 WonderWorld 的层间漏光都是这个机制；遮挡崩坏来自「没看到的地方靠先验编」，背面高斯稀疏和窗外街景平板是同一类失败；接触崩坏来自几何与物理的接口，碰撞体没对齐、材料参数病态，都会在接触瞬间暴露。

系统代价可以列成一张账：迭代补全的时间随视角数增长，分层高斯的显存随层数增长，组合管线的渲染回路串行且轮数不定，可微 MPM 的显存随仿真步数增长。这些代价不是可选的，是管线结构的直接后果。工程判断是：场景生成的瓶颈不在「生成一张好看的图」，而在「维持一张图在走、撞、转之后仍然成立」。静态截图会掩盖接缝错位、背面空洞、通道过窄、接触穿模，这些只有动态验收能抓到。

管线一致性断点系统代价验收动作
Text2Room闭环接缝、弱纹理墙面时间/显存随视角数线性增长绕一圈看门框与地板交接
WonderWorld层间漏光、背面稀疏层间正则与多视角约束的开销绕到背面看移动中的稳定性
WorldGen布局翻译不唯一、连通性约束求解与三段接口的调试成本走一遍看门是否可过、走廊宽度
SceneCraftAPI 幻觉、尺度推理渲染回路串行、轮数不定几何连通检查独立于渲染
PhysDreamer参数不唯一、仿真爆炸可微 MPM 显存随步数增长换交互条件重测行为

验收清单要落到具体动作上：走一遍看墙是否直、门是否能过；撞一下看物体是否穿模、碰撞体是否对齐；转个身看光照是否随视角连续、接缝是否在移动中抖动；换个交互力度看物理参数是否还在合理区。这些动作对应的是不同的失败模式，不能互相替代。截图验收只能覆盖「静态好看」，覆盖不了「动态成立」。工程上更稳的做法是把几何检查（连通性、碰撞体对齐、平面性）做成独立于渲染和扩散的步骤，把物理检查做成多条件激励，而不是单条轨迹拟合。

最后一个机制层面的判断：组合管线比单模型更容易保证可穿越/可交互，代价是接口多、调试链路长。接口税无法消除，只能前置——把布局到程序的翻译做成可验证的约束求解，把程序到扩散的贴图做成几何感知的投影，把物理参数估计做成多条件联合优化。这些步骤不产生好看的截图，但决定场景能不能走进去、撞得动、转得顺。
