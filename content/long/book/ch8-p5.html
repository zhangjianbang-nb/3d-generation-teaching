一 · 潜变量接口的代码骨架：从张量形状反推管线

读第八卷的模型时，最容易被叙事带偏的地方是「它生成了一个 3D 模型」。工程上真正要问的是：这个模型的输出张量是什么形状、由谁解码、解码器的输入约定是什么。把这三件事写清楚，管线才立得住。以 SLAT 为例，结构化潜变量的骨架是「稀疏体素索引 + 每个有效体素上的局部三平面特征」。代码思路不是先写网络，而是先写索引容器：一个 coords 整型张量（N×3，体素中心整数坐标），一个 feats 浮点张量（N×C，每体素的局部特征），再加一个从坐标到行号的哈希映射。所有注意力、卷积、上采样都只在这个稀疏集合上做，空区域不分配显存。这就是它相对稠密三平面的第一个系统代价差异：显存随有效体素数量线性增长，而不是随包围盒体积立方增长。

解码侧要写成三个独立函数而不是一个：decode_gaussian(feats, coords)、decode_mesh(feats, coords)、decode_radiance(feats, coords)。它们共享同一份潜变量，但各自带自己的解码头和分辨率假设。工程判断在这里出现：三个解码器的误差不会互相抵消，只会叠加。高斯头在薄结构上会把一个体素摊成椭球，网格头在同样位置抽出的是等值面，两者的「同一物体」在视觉上并不重合。所以管线里必须有一个「主表示」的概念——下游引擎消费哪一个，就以哪一个的误差为准做验收，其余两个只作为预览或中间产物。

$$\mathbf{z}=\{(\mathbf{p}_i,\ \mathbf{f}_i)\}_{i=1}^{N},\qquad \mathbf{f}_i=\mathrm{TriLocal}(\mathbf{p}_i),\quad N=|\{\mathbf{p}:\ \text{occupied}\}|$$

一个具体例子：单图输入经编码器得到约几万个有效体素（数量级随物体复杂度变化，不是固定值），潜空间 DiT 在这个稀疏集合上做去噪，每步只更新 feats，coords 在去噪过程中基本冻结。冻结坐标是个重要设计：如果每步都重新判定占用，注意力索引会抖动，训练不稳定。代价是生成阶段无法「长出新部件」——拓扑在编码那一刻就定了上限。这解释了为什么这一卷的模型大多需要 CraftsMan3D 式的「生成 + 精修」两段：精修段才有机会改拓扑。

二 · 双 DiT 与 PBR 三通道的调参顺序

Hunyuan3D 2.0 把形状与纹理拆成两个 DiT，2.1 再把材质扩成 PBR 三通道。调参时最容易犯的错是同时调两个阶段的学习率。正确顺序是先把形状 DiT 调到「几何稳定」——判据不是渲染好看，而是同一提示词多次采样的法线图在轮廓处一致；再把纹理 DiT 冻结形状条件后单独调。原因很直接：纹理 DiT 的条件输入是形状的几何缓冲（法线、深度、掩码），形状一抖，纹理的监督信号就变成噪声，两个阶段一起调会互相拖。伪代码思路如下：

  • 阶段 A：for step in shape_steps: loss = diffusion_loss(shape_dit(x_t, t, cond))，cond 只含图像/文本嵌入；监控法线一致性。
  • 阶段 B：freeze(shape_dit); geo = render_buffers(shape); loss = diffusion_loss(tex_dit(x_t, t, geo, cond))；此时才引入 PBR 三通道监督。
  • 阶段 C：loss += w_mat * mat_loss(base, metal, rough)，权重从 0 缓慢升到目标值，避免材质头在早期把 base color 拉向灰色。

PBR 的公式在卷导语里已经给了验收口径：$$\mathcal{M}=\{\mathbf{c}_{\mathrm{base}},\ m,\ r\},\qquad \mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I})$$。调参上的关键判断是 delighting 误差会污染整个材质头：如果输入图里带着强方向光，而 delighting 没去干净，网络会把阴影学进 base color，metallic 和 roughness 就会被迫去补偿这个错误，结果是「换一套光照就崩」。这不是模型容量问题，是监督目标问题。系统代价体现在数据侧：delighting 需要光照估计或成对数据，标注成本直接压在训练集规模上，而这一卷的模型都依赖大规模资产清洗管线，清洗管线里 delighting 是最贵的一环。

失败模式举例：金属件在暖光下渲染正确、在冷光下变成塑料感。诊断路径是固定几何、只换环境光，观察 base color 是否随光照变化——如果变化，说明光照被烘进了反照率。修复不是重训整个 DiT，而是回到阶段 C 加大材质监督权重并补一批带多光照的合成样本。

三 · UV 与接缝：SF3D 那 0.5 秒买到的是什么

SF3D 的定位是快速 UV + PBR + delighting，卷内给出的量级是 0.5 秒可用资产。这个数字要拆开看：它买到的是「一次前向出带 UV 的网格和材质」，不是「高质量」。UV 展开决定纹理分辨率与接缝，这是接口层面的硬约束。工程上要区分两种接缝：参数化接缝（UV 岛边界，纹素不连续）和几何接缝（法线/位置不连续）。前者靠 padding 和接缝感知的纹理扩散缓解，后者只能靠重拓扑解决，属于第九卷的范畴。SF3D 这类快速管线通常不解决几何接缝，所以它的资产适合做背景件、道具、原型，不适合做需要动画的主角。

检查 UV 的具体机制：把纹理坐标的梯度可视化，拉伸区域表现为纹素密度骤降；再在引擎里用棋盘格贴图渲染，接缝处会出现明显错位。系统代价是纹理预算：UV 岛越碎，接缝 padding 占用的纹素比例越高，同样的 2K 贴图有效分辨率越低。一个具体例子：一个带细长把手的杯子，把手内侧如果被展开成独立小岛，纹素密度可能只有杯身的几分之一，近景渲染时把手内侧会糊。这不是生成模型能修的，是 UV 算法和分辨率预算的取舍。

调参上，UV 相关参数往往不在扩散模型里，而在后处理：岛打包的间隙、纹素密度目标、接缝 padding 宽度。这些参数与 DiT 的采样步数无关，改它们不需要重跑生成，所以管线应该把 UV 后处理做成可重入的独立阶段。失败模式是把它耦合进生成：一旦 UV 参数变了就得重采样，迭代成本成倍上升。

四 · 可控性与解耦：Step1X-3D 的接口一致性陷阱

Step1X-3D 做几何/纹理解耦与可控编辑。解耦的工程价值在于「改纹理不动几何、改几何不重画纹理」，但接口一致性是陷阱：几何一改，原来的 UV 和纹理投影就失效。代码思路上，解耦必须配一个重投影步骤——几何编辑后，把旧纹理通过最近面片或 UV 重参数化映射到新几何上，再让纹理 DiT 做局部修补。伪代码：new_geo = edit(geo); uv_new = unwrap(new_geo); tex_new = warp(tex_old, uv_old, uv_new); tex_new = inpaint(tex_dit, tex_new, mask)。少了 warp 这一步，编辑后的资产会出现纹理错位，且错位在单视角预览里看不出来，进引擎一转就暴露。

系统代价是编辑的原子性：几何编辑和纹理重投影必须在一个事务里完成，否则中间态资产不可用。失败模式举例：把椅子的靠背加高，UV 岛重新打包后位置全变，旧纹理贴上去花纹错位；如果管线只保存了最终纹理没保存 UV 映射，这个资产就无法回滚。工程判断是：解耦模型必须同时输出 UV 映射和纹理，映射本身是一等公民，不能当临时变量丢掉。

可控性还有一层：部件级控制。这一卷的模型大多在整体层面可控，部件拆分属于第九卷。所以在 Step1X-3D 上做「换一条腿」这类操作，实际是在几何潜变量上做局部编辑再重投影，接口一致性风险最高。检查清单里应该有一条：任何局部编辑后，必须验证未编辑区域的纹理是否漂移。

五 · 验收检查清单：把「好看」翻译成可测项

卷内的工匠笔记给了一条验收口径：在引擎里换三套光照（暖光/冷光/逆光），看金属是否像金属、粗糙度是否合理、暗部是否带阴影。只在一套光照下好看的资产，通常是把光照烘进了 base color。把这条展开成可执行的清单，每一项都对应一个具体机制和一个失败判据。

检查项机制失败判据
三光照重渲染PBR 三通道解耦光照base color 随光照变化，金属在冷光下失去高光
法线一致性形状 DiT 采样稳定性多次采样轮廓抖动，纹理条件被污染
UV 拉伸纹素密度梯度棋盘格贴图在局部糊成一片
接缝UV 岛边界 padding跨岛纹素不连续，近景可见错位
多解码器对齐SLAT 三头共享潜变量高斯预览与网格渲染轮廓不重合
编辑回滚UV 映射持久化局部编辑后未编辑区域纹理漂移
拓扑可动画网格连通性存在非流形边，绑定权重求解失败

这张表的使用方式是逐项打勾而不是打分。任何一项失败，资产就停在「预览可用、引擎不可用」的状态。系统代价在于验收本身要跑引擎：三光照重渲染需要真实的光照环境，不能靠离线渲染近似，否则烘进光照的错误测不出来。一个具体例子：一个看似完美的金属水壶，在逆光下暗部完全没有环境遮蔽的层次，说明粗糙度和法线被生成成了「平均化」的值，这类资产在游戏里一进夜景就露馅。

六 · 五道自测题

以下五题只依赖本卷给定的事实与机制，不依赖外部数字。每题给出判据而不是唯一答案，用于自检是否真的理解了接口层面的取舍。

  • 题一：SLAT 的潜变量为什么能同时解成高斯、网格和辐射场？如果三个解码器对同一区域的几何判断不一致，管线应该以谁为准？请从「主表示」和误差叠加两个角度作答。
  • 题二：Hunyuan3D 2.0 的形状/纹理双 DiT 为什么不能同时调学习率？请写出阶段 A、B、C 的伪代码顺序，并说明阶段 C 里材质权重为什么要从 0 缓慢上升。
  • 题三：给定公式 $$\mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I})$$，如果 delighting 没去干净方向光，metallic 和 roughness 会怎样补偿？请描述这个错误在「换三套光照」验收中的表现。
  • 题四：SF3D 的 0.5 秒资产在什么场景下够用、在什么场景下不够用？请从 UV 接缝和几何接缝的区别作答，并指出哪一类接缝只能靠重拓扑解决。
  • 题五：Step1X-3D 做几何编辑后，为什么必须保存 UV 映射而不能只保存纹理？请写出重投影伪代码中 warp 的作用，并给出一个「编辑后未编辑区域纹理漂移」的具体例子。

自测的判据是：能否在不引用任何渲染截图的情况下，用张量形状、解码器约定和验收项把问题讲清楚。讲不清的地方，通常就是管线里被当成「魔法」的那一段——而这一卷的全部工程价值，恰恰在于把那些段落写成可检查的接口。
