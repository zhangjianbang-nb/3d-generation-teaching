一 · 面片词表：把三角面变成可写的符号

重拓扑生成的第一层机制，是把“网格”从几何对象改写成离散序列。MeshGPT 的做法不是直接回归顶点坐标，而是先构造一个“面片词表”：用图卷积网络把每个三角面片编码成一个定长向量，这个向量要吸收该面片的顶点坐标、法向以及它与邻接面片的连接关系；随后用向量量化（VQ）把连续向量映射到码本中的离散 token。码本大小是超参数，编码器输出维度与码本维度对齐，量化操作把每个面片压缩成一个整数索引。于是任意一个网格被写成 $\mathcal{M}\mapsto(\mathbf{t}_1,\dots,\mathbf{t}_N)$，每个 $\mathbf{t}_i$ 是词表里的一个符号。

这一步的关键在于“共享边”没有被显式写入序列。面片 token 只携带自己的几何与局部邻域信息，解码时由 token 序列重新拼出顶点与边。图卷积的感受野决定了每个 token 能看到多远：一层卷积只看一跳邻居，堆几层才能让一个面片“知道”自己处在平面区还是曲率突变区。工程上这意味着编码器的深度直接决定词表能否区分“平坦大面”与“细碎转折面”，而这两类面在艺术家拓扑里的处理方式完全不同。

$$\mathbf{z}_i=\mathrm{GCN}(\mathcal{N}(f_i)),\quad \mathbf{t}_i=\arg\min_{k}\|\mathbf{z}_i-\mathbf{e}_k\|_2,\quad \hat{\mathbf{z}}_i=\mathbf{e}_{\mathbf{t}_i}$$

数据流是：稠密网格 → 面片邻接图 → 每面片特征 → GCN 编码 → VQ 离散 → token 序列 → decoder-only Transformer 自回归。训练时 Transformer 以“前 $i-1$ 个 token 预测第 $i$ 个 token”的交叉熵为目标；推理时从起始符号开始逐个采样，直到遇到终止符号。这里有一个系统代价：VQ 的码本坍缩。如果码本利用率低，大量面片被映射到少数几个 token，解码器就学不到面片之间的差异，生成的网格会出现大面积重复面或退化面。工程上要靠码本重置、承诺损失（commitment loss）和码本熵监控来压住这个问题。

具体例子：一个由艺术家手工重拓扑的角色头部，面数在几百到一千之间，面片沿眼周、口周呈环状分布。GCN 编码时，眼周环状面片的邻域模式与脸颊大面片明显不同，VQ 会把它们分到不同 token；Transformer 学到的序列统计就是“先写一圈眼周面，再写过渡带，再写大面”。如果输入是一个扫描得到的三角汤，面片大小杂乱、没有环状结构，编码出的 token 序列分布与训练分布偏离，解码器只能给出“看起来像头”但边流混乱的网格。这就是词表机制的边界：它学的是训练集中艺术家的面片分布，不是任意输入的最优重拓扑。

二 · 自回归写网格：序列概率与解码约束

MeshGPT 的生成端是一个 decoder-only Transformer，把面片 token 序列当作语言建模。给定已写出的 token 前缀，模型输出下一个 token 的分布，采样后追加到序列末尾。形式上是链式分解：

$$p(\mathcal{M})=\prod_{i=1}^{N}p\left(\mathbf{t}_i\mid \mathbf{t}_{

这个分解看起来和文本生成一样，但网格序列有额外的硬约束：每个新面片必须与已生成的面片共享边或顶点，否则拼出来的网格是非流形的、断裂的。纯自回归采样不保证这一点，因为 token 只编码面片自身，解码器在采样时并不知道“当前已有哪些顶点”。工程实现上通常要在解码阶段加一个合法性检查：把 token 解码回面片，检查它与已生成面片的邻接关系，不合法就重新采样或屏蔽该 token。这个检查的代价是解码速度下降，因为每写一个面片都要做一次几何一致性查询。

另一个代价是序列长度与面数成正比。MeshGPT 的序列长度随面数线性增长，Transformer 的注意力成本是序列长度的平方，所以面数一上去，显存和延迟都吃不消。这也是为什么后续工作要改 tokenization 而不是单纯加大模型。训练时的失败模式是“长程漂移”：前面写出的面片局部合理，写到后面时，模型已经偏离了训练分布中常见的全局结构，开始生成悬空面或重叠面。缓解手段包括在训练中随机截断序列、加入全局形状 token 作为条件，以及在解码时用 beam search 而不是纯采样。

具体例子：让模型生成一个椅子。前几十个 token 写出座面的一圈面片，接着写出四条腿的起始面片。如果模型在写第二条腿时没有参考第一条腿的位置，两条腿可能相交或间距异常。Transformer 的注意力理论上能让后面的 token 看到前面的 token，但训练数据里面片顺序是按某种遍历顺序排的，模型学到的“顺序先验”未必对应空间上的邻近关系。工程判断是：自回归写网格的可用性，取决于 token 顺序是否与几何构造顺序一致；顺序错了，注意力再长也救不回来。

三 · 相邻 tokenization：AMT 如何缩短序列

MeshAnything V2 的相邻网格 tokenization（AMT）针对的正是“每个面片一个 token、序列太长”的问题。AMT 的思路是：相邻面片共享一条边，写新面片时只写“新顶点”而不重复写共享顶点。于是 token 不再对应“一个完整面片”，而对应“一次局部扩展”——给定一条已有边，写出与之相连的新顶点，从而形成一个新面片。序列长度因此从“每面片一 token”降到“每新顶点一 token”量级，支持的面数从约 800 面上推到约 1600 面。

机制上，AMT 要求解码器维护一个“已写顶点表”和“边界边表”。每步采样一个 token，token 解码为“在哪条边界边上、朝哪个方向、偏移多少”形成一个新顶点；新顶点与边界边两端点组成新面片，更新边界边表。这样相邻面片天然共享边，非流形边在构造上就被排除了。代价是解码状态更复杂：边界边表是一个动态数据结构，每步都要查询和更新，解码器的输出头要预测“边索引 + 顶点偏移”，而不是一个扁平词表索引。工程上这增加了实现复杂度，但换来了序列缩短和拓扑合法性。

$$\mathbf{t}_i=(\text{edge}_i,\Delta\mathbf{p}_i),\quad \mathbf{v}_{\text{new}}=\mathbf{v}_{a}+\mathbf{v}_{b}+\Delta\mathbf{p}_i,\quad \mathcal{F}_{\text{new}}=(\mathbf{v}_a,\mathbf{v}_b,\mathbf{v}_{\text{new}})$$

失败模式是“边界边耗尽”或“边界边爆炸”。如果模型总是往同一条边界边上加面片，边界边表不增长，生成会停滞在一个局部区域；如果模型不断在外围加面片而不闭合，边界边表膨胀，解码越来越慢。训练数据里面片的遍历顺序决定了模型学到的扩展模式，如果训练集中艺术家习惯从中心向外一圈圈扩展，模型就倾向于这种模式；遇到需要从多个区域同时扩展的形状，模型会表现吃力。具体例子：一个带凹槽的机械零件，凹槽内壁和外侧平面需要交替扩展，AMT 的单一扩展顺序假设会让模型在凹槽入口处反复加面，形成局部密集、外侧稀疏的不均匀网格。

系统代价还包括“约 1600 面”这个上限背后的显存与延迟。序列缩短了，但每步解码要查边界边表、要做几何合法性检查，单步成本比纯词表采样高。面数再往上，边界边表的管理成本和 Transformer 的注意力成本叠加，推理时间不可接受。这就是为什么 AMT 是一个工程折中：用更复杂的解码状态换更短的序列，把可用面数推到一个实际可用的区间，而不是无限扩展。

四 · 重生成不是简化：QEM 与艺术家拓扑的分野

理解 MeshAnything 的关键，是把它和 QEM 简化区分开。QEM（二次误差度量）的机制是：对每个顶点计算其到相邻面片平面的二次误差，折叠代价最小的边，把两个顶点合并成一个，重复直到面数降到预算。输出网格的顶点位置是原网格顶点位置的子集或线性组合，几何误差被最小化，但拓扑结构继承自原网格——原网格是三角汤，简化后还是三角汤，只是面少了。QEM 的目标函数是最小化近似误差：

$$\Delta(\mathbf{v})=\mathbf{v}^{\top}\mathbf{Q}\mathbf{v},\quad \mathbf{Q}=\sum_{f\ni\mathbf{v}}\mathbf{n}_f\mathbf{n}_f^{\top}\cdot(\mathbf{n}_f^{\top}\mathbf{p}_f)$$

MeshAnything 的机制完全不同：它不保留原网格的顶点，而是让模型“重新理解形状”，按训练集中艺术家的拓扑习惯重新写一遍网格。输出可能和输入拓扑完全不同：输入是一个扫描的三角汤，输出是沿主曲率走的边流、均匀的三角面、可展开 UV 的四边形主导网格。它追求的是“面数省、拓扑顺、能动画”，不是“最小误差”。这意味着不能用 QEM 的误差指标去评价 MeshAnything——它的输出和输入在几何上可能有可见偏差，但拓扑质量高得多。

失败模式也完全不同。QEM 的失败是“简化过头”：面数降太多，特征边被抹平，尖锐转角变成圆角。MeshAnything 的失败是“理解错形状”：模型把输入误判成训练集中某个类别，按那个类别的拓扑习惯写网格，结果几何对不上。具体例子：输入一个非流形的扫描件，QEM 会保留非流形边，输出仍然不能动画；MeshAnything 会按“干净网格”的习惯重写，可能把非流形区域强行闭合，几何上产生偏差，但输出是流形的、可动画的。工程判断是：要“保几何”用 QEM，要“保可用”用重生成；两者不是替代关系，是不同目标。

系统代价方面，QEM 是纯几何算法，毫秒级到秒级，无训练成本；MeshAnything 是前馈模型，推理要过 Transformer，秒级到十秒级，还有训练分布的限制。验收时不能只看渲染图：面数少但拓扑乱的网格，渲染图可能很漂亮，一动画就露馅。工匠笔记里的验收清单——边流是否沿主曲率、三角面是否均匀、有没有非流形边、UV 是否能展开、面数是否在预算内——正是针对重生成网格的，因为它的失败模式是“看起来对、动起来错”。

五 · 走通一个例子：从稠密网格到可动画资产

用一个具体例子把数据流走通。输入是一个扫描得到的稠密网格，面数几十万，面片大小不一，拓扑乱，带非流形边。第一步是预处理：估计主曲率方向，把网格切成若干区域，每个区域送进编码器。第二步是面片编码：GCN 在面片邻接图上做几层卷积，每个面片得到一个向量，VQ 把它映射到码本 token。第三步是序列化：按某种遍历顺序把 token 排成序列，序列长度与面数成正比。第四步是 Transformer 自回归：从起始符号开始，逐个采样 token，每采样一个就解码回面片并做合法性检查。第五步是后处理：检查非流形边、检查面片均匀性、做 UV 展开。

在这个例子里，AMT 版本的解码器维护边界边表，每步只写新顶点。假设输入是一个带手柄的杯子：模型先写杯身的一圈面片，边界边表是一圈闭合边；然后写杯底，边界边表变成杯底外圈；再写手柄，手柄与杯身相接处的边界边需要被识别出来，模型要在正确的边界边上加面片，否则手柄会悬空。这里的具体机制是“边索引预测”：解码器输出头要预测当前步用哪条边界边，这要求它从已写 token 的上下文里推断出边界边表的空间布局。失败模式是“手柄接错位置”：模型选了一条错误的边界边，手柄长在杯身侧面而不是预留的接口处，几何上看起来像杯子，但手柄和杯身之间是非流形连接。

系统代价在这个例子里体现为三步：编码阶段的 GCN 要对几十万面片做邻域聚合，显存占用与面数成正比；解码阶段的 Transformer 注意力成本与序列长度平方成正比，AMT 把序列缩短后这个成本可控，但边界边表查询是每步一次的动态操作；后处理阶段的 UV 展开和流形检查是确定性算法，成本低但不可省略。工程判断是：这条流水线的瓶颈在编码和解码，不在后处理；要提速，先压缩输入面数（用 QEM 预简化到模型可处理的量级），再上 AMT 解码。

验收这个例子的输出：看边流是否沿杯身的主曲率走、手柄与杯身的连接处是否有非流形边、三角面是否均匀、UV 是否能展开、面数是否在预算内。如果输出面数少但手柄连接处拓扑乱，渲染图看不出来，动画时手柄会撕裂。这就是“只看渲染图会被骗过去”的具体含义。走通这个例子的价值在于：它把“面片词表 → 序列 → 自回归 → 边界边表 → 后处理”这条链上的每个环节和每个失败模式都暴露出来，而不是停留在“模型能生成网格”的层面。

六 · 部件化的接口：全局注意力与部件数预测

PartCrafter 把“整体网格”推进到“部件网格”，机制是组合式潜变量加全局注意力。每个部件有自己的潜变量，部件内的面片由该潜变量解码；全局注意力让所有部件的潜变量互相可见，保证部件之间的空间关系——比如椅子的四条腿要落在座面的四个角上，而不是各自飘在空间里。形式上是联合分布分解为部件条件分布的乘积，全局注意力提供跨部件的上下文：

$$p(\{\mathcal{M}_k\})=\prod_{k}p(\mathcal{M}_k\mid \mathbf{z}_k,\{\mathbf{z}_{j}\}_{j\neq k}),\quad \mathbf{z}_k\sim\mathcal{N}(\mathbf{0},\mathbf{I})$$

这个机制解决的是“整体网格能看不能修”的问题：整体网格是一个不可拆的对象，部件网格可以拆、可以换、可以单独动画。代价是部件数预测难：模型要先决定生成几个部件，这个数量没有先验，不同形状的部件数差异很大；部件数错了，要么部件被强行合并，要么出现多余的空部件。另一个代价是部件间遮挡和接触复杂：全局注意力要处理部件之间的空间约束，接触面要共享边界，遮挡关系要在潜变量层面表达，这比单部件生成难得多。

具体例子：生成一个带抽屉的柜子。部件数是柜体、抽屉面板、把手，三个部件。全局注意力要让抽屉面板落在柜体的开口处，把手落在面板上。如果部件数预测成两个，抽屉面板和柜体被合并，抽屉就不能单独动画；如果预测成四个，多出的部件可能是一个悬空的装饰件，几何上不合理。失败模式是“接触面错位”：抽屉面板和柜体的接触面没有对齐，渲染时看不出，动画时抽屉拉出会露出缝隙。工程判断是：部件化的收益是可编辑性，代价是部件数和接触关系的建模难度；在部件数少、接触关系简单的资产上，PartCrafter 的机制可用；在部件数多、遮挡复杂的资产上，部件数预测和接触建模是瓶颈。

把这条链和前面的重拓扑链对比：MeshAnything 的输出是一个整体网格，拓扑顺但不可拆；PartCrafter 的输出是多个部件网格，可拆但每个部件的拓扑质量取决于部件解码器。两条链的共同点是都把“生成”变成“可用资产”的一步：前者解决动画所需的边流和面数，后者解决编辑所需的部件拆分。工程上选哪条链，取决于资产的下游用途——要动画选重拓扑，要编辑选部件化；两者都需要验收清单，都不能只看渲染图。
