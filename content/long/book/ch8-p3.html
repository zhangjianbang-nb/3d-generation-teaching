一 · 潜变量训练的三条代价线：VAE 重建上限、扩散采样预算、解码器误差

把高分辨率 3D 压进潜空间，训练侧的第一笔账不是「模型多大」，而是「VAE 压到什么程度还能还原」。Direct3D 的路线是先用 3D VAE 把高分辨率 3D 压成潜变量，再在潜空间做 DiT 扩散。这条路线把扩散的算力从体素/三平面原始分辨率搬到低维潜空间，代价被转移到了 VAE 的重建上限上：潜变量维度越低，扩散越省，但解码回来的几何细节越依赖 VAE 的容量。工程上要盯的不是扩散 loss，而是「VAE 重建误差随潜变量压缩率的变化曲线」——这条曲线决定了整条管线的天花板，扩散只是在天花板下面做条件采样。

形式化地，设编码器 $E$、解码器 $D$、潜变量 $z=E(x)$，训练目标可写成重建项加正则项：

$$ \mathcal{L}_{\mathrm{VAE}}=\mathbb{E}_{x}\big[\|D(E(x))-x\|^{2}\big]+\beta\,D_{\mathrm{KL}}\big(q(z\mid x)\,\|\,p(z)\big) $$

$\beta$ 越大，潜空间越规整、越适合扩散，但重建越糊。这不是调参问题，是结构性取舍：扩散模型学的是 $p(z)$，如果 $z$ 已经把细节丢掉，扩散采样再准也补不回来。失败模式很具体——薄壁、锐边、镂空结构在低维潜变量里被抹平，解码出来是「圆角化的近似体」。系统代价体现在两处：一是 VAE 本身要在大规模 3D 数据上训，显存和吞吐都不低；二是潜空间扩散的采样步数乘以解码一次的前向，推理延迟被解码器主导。

第二笔账是扩散采样预算。潜空间扩散仍然是迭代采样，步数、CFG 强度、采样器选择都直接影响出模时间。第三笔账是解码器误差：SLAT 这类结构化潜变量需要多解码器（高斯、网格、辐射场各一套），每套解码器有自己的误差分布，同一潜变量解成网格和解成高斯，表面位置不完全一致。工程判断是：不要把「潜变量好」当成「资产好」，验收必须落在解码后的具体表示上。

二 · 双 DiT 与两阶段误差：形状与纹理拆开训练，误差会相乘

Hunyuan3D 2.0 把形状与纹理拆成两个 DiT，先出几何再出纹理。拆分的动机是分辨率：几何需要高分辨率体素/潜变量来表达细节，纹理需要高分辨率图像空间来表达材质，两者共享一个网络会互相挤占容量。但拆分引入了一个新的失败模式——两阶段误差耦合。第一阶段几何的微小偏差（比如法线朝向错了、局部凹陷浅了）在第二阶段会被当成条件，纹理 DiT 会「忠实地」把纹理贴到一个错误的表面上，误差不是相加而是相乘。

用伪代码思路描述这个数据流：

  • 阶段一：$z_{\mathrm{geo}}\sim p_\theta(z\mid \text{条件})$，解码得几何 $G=D_{\mathrm{geo}}(z_{\mathrm{geo}})$；
  • 阶段二：以 $G$ 渲染的条件图（法线、深度、掩码）为条件，$z_{\mathrm{tex}}\sim p_\phi(z\mid G,\text{文本})$，解码得纹理图 $T$；
  • 合成：把 $T$ 投影回 $G$ 的 UV 或直接烘到顶点/面片上，得到带纹理资产。

关键系统代价在「条件渲染」这一步：阶段二需要从 $G$ 渲染多视角条件图，渲染分辨率、视角数量、是否带法线通道，都决定了纹理 DiT 能不能对齐。视角太少，背面纹理靠猜；视角太多，渲染和条件编码的开销线性上涨。失败模式是「纹理漂移」：正面纹理精细，转到侧面接缝处出现拉伸或错位，根源是阶段一几何的 UV 或参数化与阶段二投影不一致。

Hunyuan3D 2.1 在此之上加 PBR 三通道，把材质从「一张颜色图」升级为 $\mathcal{M}=\{\mathbf{c}_{\mathrm{base}},m,r\}$，即 base color、metallic、roughness。这带来第三个 DiT 或至少第三个输出头，训练数据要求也变了：需要带 PBR 标注的资产，而这类数据远少于纯颜色纹理数据。工程上的直接后果是——PBR 通道的监督信号稀疏，metallic 和 roughness 容易退化成常数图（全金属或全粗糙），在引擎里表现为「所有材质看起来像塑料或像铁」。验收时必须换光照看：暖光、冷光、逆光三套，金属是否像金属、粗糙度是否有层次、暗部是否带阴影。只在一套光照下好看的资产，通常是把光照烘进了 base color。

三 · SLAT 的多解码器系统代价：一套潜变量，三种误差

TRELLIS 的 SLAT 是稀疏体素加局部三平面：在物体表面附近的稀疏体素里存局部三平面特征，远处为空。这个结构的好处是一套潜变量可解成高斯、网格或辐射场，坏处是「一套潜变量、多套解码器」意味着误差不统一。解成高斯时，误差表现为泼溅核的尺度与不透明度估计偏差；解成网格时，误差表现为等值面提取的阈值敏感和拓扑碎片；解成辐射场时，误差表现为体渲染积分下的密度偏移。同一潜变量，三种下游，三种验收标准。

稀疏体素的结构决定了计算代价的分布：特征只存在表面附近，空区域不占算力，这是它相对稠密三平面的优势。但稀疏结构的构建本身有代价——需要先从粗几何确定哪些体素激活，这个「激活判定」如果错了，细节就永久丢失。失败模式是「薄结构断裂」：叶片、线缆、镂空花纹的体素激活不足，解码出的网格出现孔洞或断连。系统层面，多解码器意味着管线里要维护多套提取代码，DMTet 可微网格提取、高斯光栅化、体渲染积分各自有超参，任何一套的超参漂移都会让同一资产的三种表示对不上。

具体例子：一个带细长把手的杯子，SLAT 潜变量在把手处的局部三平面分辨率若不够，解成高斯时把手变成一串模糊的椭球，解成网格时把手断成两截，解成辐射场时把手在半透明边缘处「消失」。这不是模型没训好，是结构化潜变量的空间分辨率与解码器的提取粒度不匹配。工程判断：SLAT 类表示适合「一套潜变量喂多种下游」的管线，但必须为每种下游单独定验收阈值，不能用一个指标通吃。

四 · 生成加精修与解耦可控：管线越长，接口越容易错

CraftsMan3D 做「生成 + 精修」：先出一个粗几何，再用精修阶段补细节、修拓扑。Step1X-3D 做几何/纹理解耦与可控编辑。两者的共同点是管线变长，而管线每多一段，就多一个接口，多一个接口就多一处可能错的地方。精修阶段的输入是粗几何，粗几何的拓扑质量（面片分布、是否有非流形边）直接决定精修能不能收敛；如果粗几何带自交或翻转法线，精修阶段的法线引导会放大这些缺陷。

解耦可控的系统代价在「接口一致性」：几何 DiT 和纹理 DiT 各自有潜空间，编辑几何后纹理潜空间的条件必须同步更新，否则出现「几何改了、纹理还贴在旧位置」的错位。可控编辑还要求潜变量有语义方向，这需要训练时的属性标注或解耦正则，数据成本高。失败模式是「编辑泄漏」：改一个部件，相邻部件跟着变形，根源是潜变量没有真正解耦，只是条件向量在统计上相关。

工程上，长管线的验收要按段做：粗几何段看拓扑是否可动画（四边面比例、是否有非流形边），精修段看细节是否过拟合噪声，解耦段看编辑是否局部。任何一段的失败都会在最终资产上表现为「进不了引擎」——不是渲染不出来，是导入后拓扑检查不过、UV 重叠、材质槽对不上。

五 · SF3D 的快速路径与 UV/PBR 接口：速度换来的是接缝与歧义

SF3D 做快速 UV + PBR + delighting，目标是在很短时间内给出可用资产。它的系统代价被压在「UV 展开」和「材质歧义」两处。UV 展开决定纹理分辨率与接缝：快速 UV 往往用投影式或简化展开，接缝位置不优化，纹理在接缝处出现拉伸或错位；分辨率分配也不均匀，重要区域（脸、logo）和大面积平坦区域拿到同样的纹素密度。

delighting 是 PBR 管线的前置步骤：把输入图的光照去掉，得到 $\mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I})$，才能重光照。delighting 的失败模式是「光照残留」——阴影和高光被部分烘进 base color，换光照后阴影位置不对、高光跟着视角走。材质歧义则是 metallic 与 base color 的耦合：一个暗色高反射表面，既可能是深色金属，也可能是低粗糙度的深色塑料，单图输入无法区分，模型只能猜。工程验收必须用三套光照测试，并检查 metallic/roughness 图是否有空间变化，常数图就是退化的信号。

速度路径的系统代价还体现在「一次前向出全部通道」的容量挤占：UV、几何、PBR 共享一个网络，任何一项的精度都被其他项稀释。具体例子：一个带金属扣的皮包，快速路径可能把扣子的金属感做成 base color 里的亮色块，metallic 通道却是 0，换到冷光下扣子不反光，资产在引擎里「看起来对、动起来错」。

六 · 训练与推理的系统账：数据、显存、延迟与验收口径

这一卷所有模型的训练侧共同代价是数据：结构化潜变量要求 3D 资产带几何、带纹理、最好带 PBR 标注，而带 PBR 的资产远少于纯几何资产。数据清洗管线（大规模 3D 资产清洗）因此成为瓶颈——去重、修非流形、统一尺度、重算 UV、分解材质，每一步都消耗人力与算力。训练时的显存账在潜空间扩散上被缓解，但在 VAE 和解码器上仍然沉重：高分辨率 3D 的 VAE 训练需要大 batch 和长训练，解码器要覆盖多套表示。

推理侧延迟由三段构成：潜空间扩散采样、解码、后处理（UV 展开、PBR 烘焙、delighting）。SF3D 的快速路径把后处理压进前向，代价是接缝与歧义；CraftsMan3D 的精修段把延迟拉长，换来细节与拓扑。工程判断是：延迟预算要按「资产用途」分配，游戏内静态道具可以容忍长管线，实时交互场景必须走快速路径并接受接缝。

验收口径必须写进管线，而不是靠人眼看。建议的检查项：拓扑检查（非流形边、翻转法线、四边面比例）、UV 检查（重叠、拉伸率、纹素密度分布）、PBR 检查（三通道是否有空间变化、三套光照下金属/粗糙度是否合理）、部件检查（是否可拆、是否可仿真）。任何一项不过，资产就退回上一段，而不是在最终端打补丁。这一卷的模型各自解决一小块，真正的管线要把它们串起来，而串联的代价就落在这些接口检查上——接口错了，资产就进不了引擎，生成再漂亮也没用。
