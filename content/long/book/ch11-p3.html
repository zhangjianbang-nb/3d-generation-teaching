一 · 训练侧：清洗管线本身就是一条推理链

把 Objaverse 的八十万物体、Objaverse-XL 的一千多万物体直接喂进 LRM 或 TRELLIS 这类前馈模型，训练并不会因为数据变多而线性变好。原因不在优化器，而在数据管线：清洗的每一步都是一个带阈值、带分支、带丢弃率的判定函数，这些判定函数串起来，等价于一条在训练前跑完的推理链。工程上要把它当成一个独立系统来设计，而不是当成脚本。

去重是这条链的第一环。几何哈希的做法是把网格归一化到单位包围盒，按固定分辨率体素化，得到占据栅格，再对栅格做感知哈希；纹理哈希则对 base color 图做降采样后的颜色直方图与感知哈希。两者取联合键，落在同一个桶里的资产视为重复。伪代码思路是：对每个资产计算键 k = H(geo_hash, tex_hash)，用并查集合并同键项，保留面数最高或水密性最好的那一个。代价是体素化本身是 O(N³) 的，对高面数网格必须先在 CPU 上做简化，否则清洗吞吐会被几何哈希拖垮。失败模式是阈值过松：不同姿态的同一物体被哈希成不同键，重复项漏网，训练集里同一资产出现多次，模型对该资产的纹理细节过拟合，长尾类别的梯度被重复样本淹没。

许可过滤是第二环，也是最容易被跳过的一环。做法是维护一张商用白名单，把每个资产的来源标记（平台、上传者、许可字段）映射到布尔值，非白名单直接丢弃。这里的系统代价不是算力，而是覆盖率：白名单越严，可用数据越少，长尾类别越容易整类消失。一个具体例子是长尾的工业零件或医疗器械，这类资产在开放平台上本就稀少，许可字段往往缺失，严格过滤后可能一个不剩。工程判断是分级而不是一刀切：把许可分成可商用、可研究、不可用三档，训练时按档位加权采样，而不是把研究档直接扔掉。

质量分级是第三环。面数、纹理分辨率、水密性、法线一致性、UV 是否存在重叠，这些指标各自有阈值，组合成一个分级函数。分级的意义在于采样权重：高质量资产权重高，低质量资产权重低但不为零，否则模型学不到低质数据的分布，推理时遇到脏输入就崩。失败模式是分级指标与下游可用性脱节：一个面数很高但 UV 严重拉伸的资产会被判为高质量，训练出的模型生成的 UV 接缝错位，进引擎后贴图撕裂。

$$ w_i = \alpha \cdot \mathbb{1}[\text{license}_i \in \text{commercial}] + \beta \cdot q_i + \gamma \cdot \frac{1}{1+\text{dup}_i} $$

上式是采样权重的一个具体形式：许可项是硬门控，质量项 q_i 是连续分级分，重复惩罚项随重复次数衰减。三个系数不是拍脑袋，而是按类别平衡调出来的：长尾类别提高 α 的相对权重，头部类别压低。代价是这套权重需要按类别统计后重新归一，每次数据增补都要重跑，管线维护成本随规模上升。

二 · 推理侧：一次前向的显存与时间预算

前馈模型的核心卖点是「一次前向」，但一次前向的代价分布很不均匀。以 LRM 系的三平面 Transformer 为例，输入单图先过视觉编码器得到 token 序列，再经交叉注意力生成三平面特征，最后由三平面解码出 SDF 或高斯。显存峰值通常不在 Transformer 主体，而在三平面解码阶段：三平面是三个正交的二维特征图，分辨率提高一倍，显存翻四倍，而 Transformer 的注意力是序列长度的平方。工程上要分别对这两段做预算，不能只看参数量。

时间预算同理。SF3D 用 0.5 秒前向出 UV + PBR + delighting，这个数字对应的是特定分辨率与特定硬件下的端到端延迟，拆开看是编码、三平面生成、网格提取、UV 展开、PBR 分解、delighting 六段串行。任何一段的分辨率上调都会破坏这个预算。失败模式是分辨率与延迟的耦合被忽视：把三平面分辨率从基准提到两倍，显存溢出先发生在解码段，而不是注意力段，调参时如果只盯着注意力优化，会误判瓶颈。

另一个代价是批处理与延迟的权衡。前馈模型在服务端通常按批推理以提高吞吐，但批大小受显存峰值限制，而显存峰值由批内最大分辨率样本决定。一个具体例子是混合批：批内同时有一个高分辨率资产和一个低分辨率资产，显存按高的算，低分辨率样本白白占用预算。工程做法是按分辨率分桶，桶内批处理，桶间串行，代价是调度复杂度上升，收益是显存利用率提高。

失败模式还包括数值稳定性。三平面解码出的 SDF 在网格提取时用 marching cubes 或 DMTet，阈值附近的符号翻转对浮点误差敏感。批内不同样本的 SDF 尺度不一致时，统一阈值会导致部分样本表面破碎或过度平滑。工程判断是对每个样本做尺度归一后再提取，代价是额外的归一化步骤与反归一化，收益是提取成功率稳定。

三 · UV 展开：接缝、拉伸与人工修的接口

UV 自动展开是前馈管线里最容易被低估的一段。它的目标是把三维表面映射到二维平面，同时控制接缝数量与拉伸误差。拉伸误差的度量通常用面积失真比：三维面片面积与二维映射后面积之比，偏离 1 越多失真越大。接缝则是映射不连续处的边界，接缝越多，纹理接缝处的走样越明显，人工修的工时越长。

$$ \text{distortion} = \frac{1}{|F|}\sum_{f \in F}\left|\log\frac{A_{3D}(f)}{A_{2D}(f)}\right| $$

上式是面积失真的对数平均，取对数是为了让拉伸与压缩对称惩罚。自动展开的算法通常在接缝数量与失真之间做权衡：接缝少则失真大，接缝多则失真小但人工修成本高。失败模式是算法在复杂拓扑上失效：带孔洞、带薄壁、带自交的资产，展开后出现重叠 UV 岛，贴图在重叠区互相污染。一个具体例子是带镂空的装饰件，自动展开把镂空边缘映射到同一 UV 区域，渲染时边缘出现纹理拉花。

系统代价在于人工修的接口设计。自动展开的输出必须带可编辑的接缝标记与 UV 岛分组，否则人工修无从下手。工程上把接缝标记写成边属性，UV 岛写成面分组，导出为标准格式，修图工具按标记高亮。失败模式是格式不兼容：自动展开输出的是自有格式，导入引擎后接缝信息丢失，人工只能在引擎里盲修。工程判断是展开阶段就对齐目标引擎的 UV 约定，代价是展开器要支持多种输出约定，收益是下游返工率下降。

拉伸与接缝的联合优化还有一个隐性代价：展开时间随面数超线性增长。高面数资产的展开可能比前向本身还慢，管线里必须设面数上限，超过上限先简化再展开。失败模式是简化改变了拓扑，展开结果与原始资产不匹配，贴图在简化后的模型上错位。

四 · PBR 分解与 delighting：三通道的误差传播

PBR 需要 base color、metallic、roughness 三通道，才能在任意光照下正确反射。只给一张 RGB 贴图，金属度与粗糙度被烘死在颜色里，换光照就错。分解的本质是从观测图像反解材质参数，而观测图像里混着光照。delighting 就是把光照从观测里剥离，得到与光照无关的 base color。公式上，观测 I 等于 base color 乘以光照 E，反解 c_base = I / E 在光照已知时是逐像素除法，在光照未知时是病态问题。

$$ \mathbf{c}_{\mathrm{base}}=\frac{\mathbf{I}}{\mathbf{E}_{\mathrm{light}}},\qquad \mathbf{I}=\mathbf{c}_{\mathrm{base}}\cdot\mathbf{E}_{\mathrm{light}} $$

误差传播的具体机制：暗部像素的观测值接近零，除法放大噪声，base color 出现彩色噪点；高光像素的观测值接近饱和，除法把高光压成灰色，金属感丢失。这两类区域是 delighting 的固有失败模式，不是调参能消除的。工程上对暗部做阈值截断、对高光做饱和检测，代价是截断区与检测区的材质信息缺失，需要多光照监督补回来。

多光照监督的做法是用同一资产在不同光照下的多张观测联合反解，光照作为隐变量估计。代价是采集成本：每个资产要多张图，Objaverse 级别的数据不可能逐资产多光照采集，只能对少量高质量资产做，其余靠单光照加先验。失败模式是先验与真实材质分布不匹配：先验假设金属度集中在 0 或 1，真实资产有大量中间值，分解出的 metallic 通道出现系统性偏移。

Hunyuan3D 2.1 把 PBR 做成生产级，SF3D 在 0.5 秒内完成 UV + PBR + delighting，这两个事实说明管线已经能跑通，但跑通不等于正确。一个具体例子是暗色金属件：观测图像里金属反射环境光，暗部与高光同时存在，delighting 后 base color 偏亮，metallic 通道被低估，进引擎后在强光下反射过弱。工程判断是对金属类资产单独设阈值与先验，代价是分类器要先判材质大类，收益是金属件的重光照正确率提升。

五 · 评测与系统耦合：从 PSNR 到引擎导入

PSNR 与 SSIM 衡量的是渲染图像与参考图像的像素差异，它们对几何误差与材质误差都不敏感。一个新视角几何误差指标衡量的是渲染深度或法线与真值的偏差，引擎导入通过率衡量的是资产能否被目标引擎无错加载，人工盲评衡量的是可用性。这三类指标与训练侧的清洗、推理侧的分辨率、UV 展开的接缝、PBR 的 delighting 误差直接耦合。

具体机制：引擎导入通过率是一个布尔判定链，检查 UV 是否存在、法线是否归一、材质通道是否齐全、面数是否超限、是否有退化三角形。任何一项失败，资产就进不了引擎。这条链的失败模式是静默失败：引擎加载成功但渲染错误，比如 UV 重叠导致贴图错位，导入通过率看不出来，只有人工盲评能发现。工程上把导入通过率拆成硬性检查与软性警告两级，硬性失败直接拒，软性警告进人工队列。

评测泄漏是另一个系统性问题。Objaverse 级别的数据里，训练集与评测集可能共享同一资产的不同版本，几何哈希去重不彻底时，评测集里的资产在训练集里出现过，新视角几何误差被低估。失败模式是评测分数虚高，模型上线后在新资产上崩。工程判断是评测集单独做去重，与训练集做跨集哈希比对，代价是评测集规模缩小，收益是分数可信。

人工盲评的成本是评测环节里最高的。盲评要控制光照、视角、背景一致，评审者只看渲染结果不看来源。代价是吞吐低，一个资产的多视角盲评需要分钟级人力，无法覆盖全量。工程做法是分层抽样：头部类别少抽，长尾类别多抽，因为长尾的失败率更高。失败模式是抽样偏差：只抽高质量资产，盲评分数好看，长尾问题被掩盖。

指标衡量对象系统代价典型失败模式
PSNR/SSIM像素差异低，可自动对几何与材质误差不敏感
新视角几何误差深度/法线偏差中，需真值评测泄漏导致低估
引擎导入通过率格式与约定合规低，可自动静默失败，渲染错但加载成功
人工盲评可用性高，人力密集抽样偏差掩盖长尾

这张表的工程含义是：四类指标覆盖不同的失败面，任何单一指标都会漏。PSNR 高但导入失败，说明格式约定没对齐；导入成功但盲评低，说明材质或 UV 有静默错误；几何误差低但盲评低，说明评测集与真实分布不匹配。评测系统的设计要把这四类指标串成一条判定链，而不是并列打分。

六 · 管线耦合的工程判断

清洗、前向、UV、PBR、评测这五段不是独立的，它们的误差会互相放大。清洗阶段漏掉的重复资产让模型过拟合，推理阶段的分辨率不足让 UV 接缝更明显，UV 展开的拉伸让 PBR 分解的 base color 在接缝处错位，评测阶段的泄漏让这些误差在分数上被掩盖。工程判断是把管线当成一个闭环：每一段的输出带质量标记，下游按标记决定是否降级处理。

具体机制是质量标记的传递。清洗阶段给每个资产打许可档、质量分、重复标记；训练阶段按标记加权；推理阶段对低质量输入降低分辨率预期；UV 阶段对接缝多的资产标记人工修；PBR 阶段对暗部与高光区域标记不确定；评测阶段按标记分层抽样。代价是标记体系要贯穿全管线，任何一段不读标记就断链。失败模式是标记语义漂移：上游改了分级阈值，下游仍按旧语义解释，降级策略错配。

另一个工程判断是失败的可观测性。前馈模型的失败往往是静默的：输出看起来像个物体，但 UV 重叠、法线翻转、metallic 偏移都不报错。管线里要埋检查点：UV 岛重叠检测、法线一致性检测、材质通道范围检测，任何一项触发就把资产送进人工队列而不是直接放行。代价是检查点的计算开销与队列积压，收益是把静默失败转成显式失败。一个具体例子是批量生成的装饰件，UV 重叠检测触发后整批进人工队列，虽然吞吐下降，但避免了贴图错位的资产流入引擎。

最后落在采样权重与检查点的耦合上：权重决定模型学什么，检查点决定什么能出厂，两者共用同一套质量标记。标记体系一旦建立，训练侧的加权采样与推理侧的降级处理就是同一套判定的两个应用，管线的一致性由此保证。
