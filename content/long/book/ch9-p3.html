一 · 训练：面片词表与序列预测的耦合

MeshGPT 的训练不是把网格当成连续几何去回归，而是先把网格离散成「面片语言」。图卷积编码器在面片邻接图上聚合特征，每个面片得到一个定长向量；随后向量量化（VQ）把连续特征映射到码本中的离散 token，码本大小决定了词表容量。训练目标因此分成两段：编码器与码本要学出「面片之间的局部几何关系能被离散符号保留」，decoder-only Transformer 要学出「给定前序 token，下一个面片 token 的条件分布」。这两段共享同一个损失回传路径，但梯度性质完全不同：VQ 的直通估计器（straight-through estimator）把 decoder 的梯度近似地传回编码器，编码器实际收到的是「量化误差被忽略后的梯度」，这使编码器容易收敛到码本覆盖密集的区域，而稀疏区域的面片类型被系统性丢弃。

形式化地，设面片序列为 \(\mathbf{t}_1,\dots,\mathbf{t}_N\)，自回归分解为

$$ p(\mathcal{M})=\prod_{i=1}^{N}p\left(\mathbf{t}_i\mid \mathbf{t}_{

训练时对每个位置计算交叉熵，但真正决定网格能否闭合的不是单 token 准确率，而是序列末尾的「停止 token」与「面片邻接一致性」。一个具体机制是：Transformer 的注意力掩码只允许看前序 token，因此模型在写第 \(i\) 个面片时并不知道后面还有多少面片要写；它只能从已写出的面片推断「当前边界在哪里」。这导致训练分布内的形状表现稳定，一旦输入形状的面片密度超出词表覆盖，模型会在边界处反复写同类面片，形成局部面片堆叠。

系统代价体现在三处。其一是词表大小与序列长度的乘积：码本越大，单 token 的区分度越高，但 Transformer 的输出层参数量和 softmax 计算量线性增长；序列越长，自回归解码的步数越多，每一步都要跑一次完整前向。其二是训练数据的序列化开销：把网格转成面片序列需要先做面片排序，排序策略（如按空间邻近或按图遍历）直接影响模型学到的邻接先验，不同排序策略训练出的模型不能混用。其三是失败模式：非流形边和孤立面片在序列化时没有稳定的邻接表示，模型倾向于把它们写成「合法但错误」的三角面，渲染图上看不出问题，但导入动画软件后边流断裂。验收时必须查非流形边，而不是只看渲染。

二 · 推理：自回归解码的步数与约束

推理阶段，MeshGPT 从起始 token 开始逐面片采样，直到发出停止 token 或达到最大长度。这里的关键机制是「采样策略与几何约束的冲突」：温度采样让输出多样，但面片之间的共享边要求后写出的面片必须复用已写顶点的坐标，而 token 本身只携带面片类型与局部关系，不携带全局顶点索引。模型实际上是在隐式地学「第 \(i\) 个面片的三个顶点中，哪些是已出现过的」，这依赖训练时序列化的一致性。推理时若温度偏高，模型会在共享边处写出新顶点而非复用旧顶点，产生裂缝。

一个可操作的伪代码思路是：解码每一步后，把新面片与已解码面片做顶点坐标的最近邻匹配，若匹配距离超过阈值则拒绝该 token 并回退重采样。这相当于在自回归循环里插入一个几何校验器，代价是每步多一次空间查询，解码总时间随面片数超线性增长。对于约 800 面的输出，这个校验器还能承受；面数再往上，回退重采样的次数会显著拖慢推理。

失败模式有两类。第一类是「序列提前终止」：模型在形状尚未闭合时发出停止 token，输出一个开口网格，渲染时背面缺失。第二类是「序列超长」：模型在局部细节处反复写面片，直到撞上最大长度限制，输出面数远超预算且面片大小不均。这两类失败都源于同一个机制——自回归模型没有全局面数预算的概念，它只看到前序 token。工程上常见的补救是给解码器加一个面数计数器，在接近预算时强制提高停止 token 的概率，但这会改变采样分布，使输出偏向训练集中面数较少的形状。

具体例子：输入一个带细长凸起的稠密形状，编码器把凸起处的面片压成少数几个 token，解码器在凸起根部反复写面片试图「补全」过渡区域，结果凸起被一圈密集小面片包围，面数分布与艺术家习惯相反。这说明推理阶段的失败不是随机噪声，而是词表覆盖与序列化策略共同决定的系统性偏差。

三 · 系统：MeshAnything 的重生成管线与 AMT 的序列压缩

MeshAnything 把「重拓扑」重新定义为「重生成」：输入稠密网格或点云，输出一个全新的、面数受控的网格，拓扑可以与输入完全不同。系统上它仍走自回归路线，但输入侧不再依赖类别标签，而是把稠密形状编码成条件特征，解码器在条件特征引导下写面片序列。这里的关键机制是「条件特征与面片 token 的对齐」：条件特征提供全局形状信息，面片 token 提供局部拓扑决策，两者在 Transformer 的交叉注意力中融合。代价是条件编码器本身要处理几十万面的输入，显存占用与输入面数成正比，稠密输入在推理前必须先做降采样或分块，否则单次前向就超出显存。

MeshAnything V2 的相邻网格 tokenization（AMT）是序列层面的系统优化。普通 tokenization 每个面片写三个顶点，相邻面片重复写共享顶点；AMT 让相邻面片共享边，只写新顶点，序列长度因此缩短。这个机制的直接收益是自回归步数减少，间接收益是模型在训练时看到更多「长程邻接」样本，因为同样长度的序列能覆盖更大的网格区域。AMT 能支持约 1600 面的输出，面数上限由序列长度与 token 压缩率共同决定。

系统代价在 AMT 上表现为「邻接顺序的敏感性」：共享边的写法要求面片按邻接顺序排列，排序一旦出错，解码器会在不该共享的地方共享边，产生非流形结构。训练时必须保证序列化器与解码器的邻接约定一致，否则模型学到的「共享边」先验与实际几何不符。失败模式是「边共享错位」：两个空间上远离的面片被写成共享一条边，渲染时出现跨区域的细长三角面，这种错误在面数统计上看不出来，只能靠边流检查发现。

具体例子：一个带凹槽的机械零件，AMT 序列化时凹槽内外壁的面片被排到相邻位置，解码器误以为它们共享边，输出中凹槽被一层薄面片封住。这说明 AMT 的收益依赖排序策略，排序策略不是实现细节，而是决定拓扑正确性的系统组件。

四 · 部件生成：PartCrafter 的组合潜变量与全局注意力

PartCrafter 走的是另一条系统路线：不生成单一网格，而是生成多个可编辑部件。机制上它用组合式潜变量，每个部件有独立的潜变量，全局注意力在部件之间传递空间关系，保证拼在一起时位置与朝向一致。训练时部件数是一个离散变量，模型要同时学「生成几个部件」和「每个部件长什么样」。这与单网格自回归的失败模式不同：单网格的失败是局部拓扑错误，部件生成的失败是「部件数预测错误」和「部件间遮挡/接触处理错误」。

形式化地，设部件潜变量为 \(\mathbf{z}_1,\dots,\mathbf{z}_K\)，全局注意力让每个部件的去噪过程看到其他部件的中间状态，条件分布近似为

$$ p(\mathcal{M})=\int \prod_{k=1}^{K}p\left(\mathcal{M}_k\mid \mathbf{z}_k,\{\mathbf{z}_{j}\}_{j\neq k}\right)d\mathbf{z}_{1:K} $$

系统代价在于全局注意力的计算量随部件数平方增长，部件数越多，单次去噪越慢；同时部件间的接触区域需要额外的碰撞或穿透检查，否则生成的部件在拼合时互相插入。失败模式是「部件数漂移」：模型对同一输入在不同采样噪声下给出不同部件数，导致下游装配流程无法稳定复用。工程上常见的补救是固定部件数上限并在训练时做部件数的课程学习，但这会牺牲对复杂形状的覆盖。

具体例子：一把带握柄和护手的剑，PartCrafter 把剑身、护手、握柄分成三个部件，全局注意力保证护手卡在剑身与握柄之间；若部件数预测为两个，护手被并入剑身，输出仍能渲染，但无法单独替换握柄材质。这说明部件化的价值不在渲染，而在下游可编辑性，验收时必须检查部件边界是否与语义边界对齐。

五 · 代价对比：三条路线的系统瓶颈

把三条路线放在同一张表里看，瓶颈位置不同。MeshGPT 的瓶颈在词表覆盖与序列长度，MeshAnything 的瓶颈在条件编码器的显存与 AMT 排序，PartCrafter 的瓶颈在部件数预测与全局注意力的平方代价。三者共同的失败模式是「渲染图看不出错，但拓扑或部件结构不可用」，因此验收不能只看渲染。

这张表揭示一个工程判断：重拓扑与部件生成的系统设计，本质上是在「序列长度」「词表容量」「部件数」三个离散维度上做预算分配。任何一个维度超预算，失败模式都会从「几何误差」转成「结构错误」，而结构错误无法用 Chamfer 距离或渲染损失衡量。验收清单里的边流、三角面均匀性、非流形边、UV 可展开性、面数预算，正是针对这些结构错误的检查项。

具体到一个装配场景：游戏角色需要一套可动画的网格，面数预算固定，部件需要能单独换材质。MeshGPT 的输出面数受序列长度限制，可能达不到预算上限；MeshAnything V2 能到约 1600 面但拓扑由模型决定，边流不一定沿主曲率；PartCrafter 给出可编辑部件但部件数不稳定。工程上通常把三者串起来：先用 PartCrafter 分部件，再用 MeshAnything V2 对每个部件重生成，最后用 QEM 在保留几何的前提下压到预算内。这条管线的代价是三次模型前向加一次 QEM，失败点从单模型转移到管线接口——部件边界处的重生成可能破坏部件间的接触关系。

六 · 训练与推理的接口：验收为何必须看结构

训练阶段学到的先验与推理阶段的约束在接口处汇合：训练时的序列化策略决定了模型认为「什么是合法的面片邻接」，推理时的采样策略决定了「实际写出什么邻接」。两者不一致时，输出在渲染上正常，在结构上错误。一个具体机制是停止 token 的训练分布：若训练集中大多数形状在面数达到某个范围时终止，模型会把「面数接近该范围」与「停止」关联起来，推理时即使输入形状更复杂，模型也倾向于提前停止。这不是模型容量问题，而是训练分布与推理需求之间的接口错位。

工程判断落在验收环节：重拓扑网格的验收必须查边流是否沿主曲率、三角面是否均匀、有没有非流形边、UV 是否能展开、面数是否在预算内。只看渲染图会被「面数少但拓扑乱」骗过去。部件网格的验收还要加一条：部件边界是否与语义边界对齐，部件间接触是否无穿透。这些检查项对应的是训练与推理接口处的系统性偏差，而不是随机误差，因此不能靠多次采样取平均来消除。

最后一个具体机制：AMT 的序列压缩率与面数上限的关系。序列长度固定时，压缩率越高，能覆盖的面数越多，但每个 token 携带的邻接信息越复杂，解码器出错的代价也越大。工程上选择压缩率不是追求最大面数，而是让「单 token 错误」不至于破坏整条边流。这个判断没有公式可套，只能靠对失败模式的观察：边共享错位一旦发生，修复成本远高于多写几个 token。
