一 · 从「重建」到「生成」：问题换了一个方向

前三卷的主线是同一件事：给定若干张照片，恢复出场景的三维结构。可微渲染把 2D 像素的误差反传进 3D 场，哈希编码把查询成本压到可接受区间，SDF 与 Eikonal 正则把表面从一团密度雾里挤出来。这条链路的能力边界很清楚——它的输入是图像，输出是对这些图像的 3D 解释。只要图像存在，问题就是良定的；图像不够，问题就退化为病态的补全。

第四卷要问的是另一个问题：能不能不经过 2D 图像这个中介，直接在 3D 表示空间里采样生成？换句话说，生成器的输出空间本身就是三维的，而不是先画出一张图、再想办法把它「抬」成三维。这个转向听起来只是把输出层换掉，实际影响的是整条训练链路：监督信号从哪来、表示如何参数化、采样成本随分辨率怎么涨、评测拿什么当准绳。

把这个问题讲清楚，需要一个具体的场景。设想一个资产管线：美术要给一个开放世界游戏批量产出街边小物件——消防栓、邮筒、路障、垃圾桶。需求是每个物件带纹理、能直接进引擎、面数可控、风格统一。传统做法是建模师手工做，或者用扫描件重拓扑。若用前三卷的重建路线，得先有每个物件的多视角照片；拍摄、抠图、相机标定、逐物体训练 NeRF，再提取网格。单件成本高，且流程是「先有实物、再有模型」，无法凭空产出新造型。

原生 3D 生成想解决的正是这一步：给一个类别先验（甚至一句文本），直接从分布里抽一个三维样本。EG3D 抽的是三平面，GET3D 抽的是带纹理的显式网格，Point-E 抽的是点云，Shap-E 抽的是隐式函数的 MLP 权重。四种输出空间对应四种完全不同的工程取舍，这一卷就是把它们拆开看。

为什么上一卷的答案不够？因为 SDF 那一卷解决的是「如何把一个已有的三维场表示干净」，它默认这个场已经被观测约束住了。生成问题里没有观测，只有分布。一个未经训练的 SDF 网络在空间中任意位置都能给出一个数值，Eikonal 正则只能保证它是个合格的距离场，不能保证它长得像一把椅子。表示能力与生成能力是两件事，第三卷把前者做到了，第四卷要补的是后者。

二 · 三平面：把三维查询降成三次二维采样

EG3D 的核心机制可以用一句话概括：不在三维网格上存特征，而是在三个正交的二维平面上存特征，查询三维点时把这一个点投影到三个平面上分别取值再拼接。设三个平面分别为 XY、XZ、YZ，特征平面记作 $\mathbf{F}_{xy}$、$\mathbf{F}_{xz}$、$\mathbf{F}_{yz}$，则空间中任意点 $\mathbf{x}=(x,y,z)$ 的特征为：

$$\mathbf{f}(\mathbf{x})=\mathrm{concat}\left(\mathbf{F}_{xy}(x,y),\ \mathbf{F}_{xz}(x,z),\ \mathbf{F}_{yz}(y,z)\right)$$

每个 $\mathbf{F}$ 都是一张二维特征图，取值用双线性插值。这个设计的直接后果是存储与计算随分辨率平方增长，而不是体素的三次方。一个 $256^2$ 的平面只有 65536 个格点，三张平面合计不到二十万；同样分辨率的体素网格是 $256^3$，一千六百万格点，差了两个数量级。这就是三平面能在单卡上跑起来的原因。

生成端是 StyleGAN2：潜码经映射网络与逐层调制，卷积出三张平面特征图。解码端是神经渲染：沿相机射线采样若干点，每点做上述三平面查询，得到一个特征向量，再送进一个小 MLP 解成密度与颜色，按体渲染积分合成像素。判别器只看合成出来的 2D 图像，加上相机姿态条件，梯度就从像素误差回流到三平面，再回流到 StyleGAN2 的权重。整个过程不需要任何 3D 真值。

系统代价有三处值得记。第一，平面分辨率决定细节上限。平面太粗，消防栓顶上的小螺帽、邮筒侧面的铆钉这类尺度接近格点间距的结构会被双线性插值抹平；平面太细，显存与二维卷积成本上涨，StyleGAN2 的卷积核在 $512^2$ 上的开销远高于 $256^2$。工程上的做法是先按物体尺度选 256 或 512，再用神经渲染的输出分辨率补细节——渲染分辨率可以高于平面分辨率，MLP 在连续坐标上插值，视觉上能挽回一部分锐度，但几何上的真实细节仍然受平面网格限制。第二，三平面是轴对齐的，对沿坐标轴延展的结构友好，对斜向的细长结构（比如斜挎的带子）会有方向性偏差，因为三个平面在斜方向上的采样密度不均匀。第三，神经渲染解码器本身是一个需要训练的 MLP，它与三平面联合优化，训练不稳定时表现为多视角之间的「闪烁」——同一物体在不同视角下细节不一致，这是 2D 判别器监督的固有弱点：它逐视角判断真假，不直接约束跨视角一致性。

举个具体例子：生成一个带把手的马克杯。把手是细结构，且在 XY 平面上投影面积小。若平面分辨率不足，把手在与平面近似平行的视角下会变细甚至断裂；换到把手正对的视角，又因为 XZ、YZ 平面上的采样补回来。这种视角依赖的几何质量波动，就是三平面分辨率与轴对齐共同造成的失败模式。实践中的判断标准很直接：把生成的物体绕一圈渲染，看细结构在哪几个角度塌陷，塌陷的角度集合能反推出平面分辨率是否够用。

三 · 显式网格与点云：两种「跳过解码器」的路线

GET3D 的选择更激进：生成器直接输出带纹理的显式网格，不做体积式的神经渲染，而是用可微光栅化把网格渲染成 2D 图像，再用 2D 判别器对抗训练。光栅化比体渲染积分便宜得多，梯度路径也短——从像素到顶点位置、到纹理、到生成器权重，中间没有采样密度的随机性。代价是拓扑固定：生成器输出的网格连通性在训练前就定死了，能变的只有顶点位移与纹理。这意味着 GET3D 擅长生成同一拓扑类别内的形状变化（椅子、汽车、摩托车这类有稳定部件结构的物体），但对拓扑本身会变的类别（比如从实心到带孔）无能为力。训练难度也更高，因为可微光栅化对顶点位置的梯度在遮挡边界处不连续，容易出现局部塌陷或面片翻转。

Point-E 走的是另一条路：文本扩散生成 1024 个点，再上采样到 4096 个点。点云的好处是容易学——点是没有连通性的无序集合，扩散模型在点坐标上的建模比在网格或隐式场上简单得多，采样也快，适合做快速预览。代价同样明确：点云没有拓扑，也没有表面，下游要用它做资产必须重建表面并重拓扑。4096 个点对一个消防栓来说，点间距在厘米量级，细节全靠后续重建去猜。工程判断是：点云适合做「概念草图」和「批量候选生成」，不适合直接进渲染管线。

Shap-E 则生成隐式函数的 MLP 权重：解码时查询任意点的占用与颜色，能保留连续表面与拓扑，提取网格时用等值面算法即可。这条路线在表示上最「干净」，但权重维度高、训练难——一个 MLP 的权重是成千上万个浮点数，扩散模型要在这么高维的空间里学分布，样本效率低，且权重空间与几何空间之间没有直观的对应关系，插值两个权重得到的中间形状未必有意义。这是原生 3D 的共同难题：表示越接近「函数」，越难训练；表示越接近「离散结构」，越容易训练但越难直接使用。

方法表示监督优点代价
EG3D三平面2D 对抗 + 姿态平方增长、2D GAN 成熟神经渲染解码、非网格
GET3D显式网格 + 纹理2D 可微光栅化直接出网格拓扑固定、训练难
Point-E点云文本扩散容易学、快速预览无拓扑、需重建
Shap-E隐式函数权重扩散连续表面、可提取网格高维参数、训练难

这张表里的四行不是四个可以互换的选项，而是四种不同的工程契约。选三平面，等于接受「必须带一个神经渲染解码器」；选显式网格，等于接受「拓扑在训练前定死」；选点云，等于接受「下游必须重建」；选隐式函数权重，等于接受「训练成本高、采样慢」。这一卷后面的部分会逐一展开每种契约的内部机制与失败模式。

四 · 原生 3D 的三重代价：数据、训练、评测

把三维放进生成器的输出空间，理论上更直接，但代价是结构性的。第一重是 3D 数据稀缺。2D 图像几乎无限，3D 资产的数量与多样性差了几个量级，且质量参差——扫描件带噪声、手工模型带风格偏差、拓扑规范不统一。原生 3D 方法大多绕开这个问题：EG3D 与 GET3D 用 2D 判别器，从图像里学，不需要 3D 真值；Point-E 与 Shap-E 用文本-3D 配对数据做扩散，配对数据的规模就是天花板。这条「用 2D 监督 3D」的路径是前三卷可微渲染思想的延续，但它监督的是「渲染出来像不像」，不是「三维本身对不对」。

第二重是表示难训练。三平面的轴对齐偏差、显式网格的拓扑固定、点云的无序性、隐式函数权重的高维性，每一个都是训练动力学上的硬约束。以三平面为例，StyleGAN2 的逐层调制在二维特征图上工作得很好，但三张平面之间的特征必须保持一致——同一个三维点从三个平面取到的特征要能拼成一个连贯的向量，否则神经渲染解码器会收到自相矛盾的输入。这种跨平面一致性没有显式的损失项去约束，只能靠联合训练隐式地学出来，训练不稳定时表现为几何的「重影」。

第三重是评测难。2D 生成有 FID 这类成熟指标，3D 生成没有对应的公认标准。渲染多视角算 FID 是一种替代，但它衡量的是图像分布的距离，不是几何的距离； Chamfer distance 需要 3D 真值，而生成任务恰恰没有真值；人工评分昂贵且主观。评测的缺失反过来影响训练：没有可靠的指标，就无法判断一个改动是改善了几何还是只改善了渲染外观。这是原生 3D 在工程上最容易被低估的成本——它不只是多了一个维度，而是多了一整套尚未标准化的度量体系。

具体到那个消防栓的例子：用 EG3D 生成，得到的是三平面加神经渲染，要进引擎必须提取网格，提取过程会损失细节且拓扑不可控；用 GET3D 生成，直接得到网格，但如果消防栓的拓扑（比如出水口的空心结构）不在生成器的拓扑模板里，就做不出来；用 Point-E 生成，几秒钟出点云预览，但要变成可用资产还得走一遍重建与重拓扑；用 Shap-E 生成，能查询出连续表面，提取网格后拓扑正确，但采样与训练都慢。四种路线在这个具体物件上的表现差异，就是这一卷要拆解的工程现实。

五 · 潜空间的意义：为什么「先有好表示」是规模化的前提

原生 3D 的深层价值不在单次生成的质量，而在它提供了一个可复用的三维潜空间。EG3D 的三平面是一个连续的、分辨率可控的、能被 2D 卷积操作的潜表示；一旦这个潜空间训练好了，后续的编辑、插值、条件控制都可以在这个空间里做，而不必每次重新跑一遍体积渲染。这个思路是后来前馈大模型与结构化潜变量的思想前身：先有一个好的 3D 潜空间，才谈得上规模化生成。

这里的机制值得说清楚。三平面的潜码是一个低维向量，经 StyleGAN2 映射到三张特征图。对这个潜码做插值，得到的是三平面特征的连续变化，渲染出来是几何的连续形变——这是 2D GAN 潜空间性质的直接迁移。但迁移不是免费的：三平面的分辨率固定，潜码能控制的只有特征图的内容，不能控制分辨率本身；细结构的变化在低分辨率平面上被压缩，插值路径上容易出现「中间态塌陷」，即两个有效形状之间的插值结果是一个模糊的平均体，而不是一个合理的过渡形状。这是潜空间维度与表示分辨率不匹配造成的失败模式。

工程判断在这里很具体：如果一个管线需要批量生成同一类别的变体（比如一百个不同样式的邮筒），三平面潜空间是合适的，因为变体在潜空间里是连续可采样的；如果一个管线需要生成拓扑各异的物体，三平面就不合适，因为它的输出必须经过神经渲染解码，而解码器不改变拓扑。表示的选择本质上是对「变化维度」的选择：三平面变的是特征图内容，显式网格变的是顶点位置，点云变的是点坐标分布，隐式函数变的是函数参数。每一种变化维度对应一类可控的生成需求，也对应一类无法表达的变化。

回到本卷开头的问题：能不能直接在 3D 表示空间里采样生成？答案是能，但「直接」的代价是把 2D 图像中介承担的许多隐性工作（拓扑、表面连续性、跨视角一致性）转移到了表示本身。三平面用轴对齐的平面承担了一部分，显式网格用固定拓扑承担了一部分，点云干脆放弃了拓扑，隐式函数用高维权重承担了全部。这些取舍没有免费的选项，只有与具体资产管线匹配与否的判断。
