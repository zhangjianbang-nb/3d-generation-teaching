一 · 从一张渲染图到一次引擎导入：这一卷要回答的问题

前馈大模型把「单图到 3D」压缩成一次前向：输入一张照片，输出三平面、高斯或网格。到第十卷为止，这条链路在几何侧已经足够顺滑——模型能给出形状、能给出粗略外观、能在几秒内吐出可预览的结果。但把同一个资产拖进 Unity 或 Unreal，问题立刻换了一副面孔：网格没有 UV，贴图是一张被光照烘死的 RGB，金属件看起来像塑料，粗糙度无处安放。渲染器要的不是「看起来像」的像素，而是能被任意光源重新照亮的材质参数。这一卷要回答的正是这个落差：前馈模型的上限由数据决定，而产品化的下限由数据与材质共同决定。前者决定模型能学到多长的长尾，后者决定资产能不能进引擎。

把问题拆成两句更具体的问法。第一句是数据侧：Objaverse 约 80 万带标注物体、Objaverse-XL 把规模推到 1000 万+，这些数字让 LRM、TRELLIS、Hunyuan3D 的「一次前向」成为可能，但 3D 数据没有 2D 那样的互联网级语料——采集难、格式杂、许可乱、标注贵。于是「堆量」并不自动等于「涨点」，重复、低质、长尾、评测泄漏都会稀释信号。第二句是材质侧：PBR 需要 base color、metallic、roughness 三通道，才能在不同光照下正确反射；只给一张 RGB 贴图，金属度与粗糙度被烘死，重光照必然失真。这两句话合起来，就是本卷的叙事主轴：模型给出的是候选资产，数据与材质决定它是不是可用资产。

这里要先把一个常见误解摆正。前馈模型的输出并不是「最终资产」，而是「资产候选」。候选到资产之间隔着一条清洗与分解的流水线：几何要去重、要水密、要重拓扑；纹理要展开 UV、要拆接缝、要把光照从反照率里剥离出来。这条流水线的每一环都有系统代价，也都有失败模式。本卷不讨论「模型能不能生成」，那是前七、八卷的事；本卷讨论「生成出来的东西能不能被下游消费」。这个视角的转换，是理解后面所有工程判断的前提。

二 · 一个具体场景：暗部高光处的 delighting 失真

设想一个具体资产：一把带磨砂金属手柄的咖啡壶，单张产品图输入 SF3D，0.5 秒前向输出 UV、PBR 三通道与 delighting 后的反照率。预览窗口里它看起来不错——壶身有高光，手柄有金属感。但把同一资产放进引擎，换一盏侧逆光，问题暴露：手柄的暗部出现一块不该有的亮斑，壶身高光区被压成一片死灰。原因不在几何，而在 delighting。delighting 要做的是从观测图像 $\mathbf{I}$ 中除掉光照 $\mathbf{E}_{\mathrm{light}}$，还原反照率 $\mathbf{c}_{\mathrm{base}}$：

$$\mathbf{c}_{\mathrm{base}}=\frac{\mathbf{I}}{\mathbf{E}_{\mathrm{light}}},\qquad \mathbf{I}=\mathbf{c}_{\mathrm{base}}\cdot\mathbf{E}_{\mathrm{light}}$$

这个除法在数学上干净，在工程上脆弱。暗部像素的 $\mathbf{I}$ 接近零，分母上的光照估计稍有偏差，商就被放大成噪声；高光区则相反，像素值饱和，$\mathbf{c}_{\mathrm{base}}$ 被系统性低估，重光照时该区域反射不足。SF3D 用 0.5 秒前向完成 UV + PBR + delighting，速度是它的卖点，但 delighting 本身的误差不会因为前向快而消失。Hunyuan3D 2.1 把 PBR 做成生产级，改善的是通道一致性与训练监督，而不是把逆渲染变成病态问题的解药。暗部与高光处的失真，是逆渲染固有的病态区间，只能靠多光照监督、先验约束与人工修来压。

这个场景的工程含义很直接：delighting 不是「顺手做掉」的后处理，而是一个需要独立评测的环节。它的失败模式有明确的视觉签名——暗部噪点、高光压平、金属件在换光后失去方向性反射。一个团队如果只看预览窗口的 PSNR，会误以为资产合格；一旦进入引擎换光，才发现反照率里混进了光照。这正是本卷要把评测从 PSNR/SSIM 推向新视角几何误差、引擎导入通过率与人工盲评的原因：像素相似度对 delighting 误差几乎不敏感，而重光照一致性对它是敏感的。

三 · 为什么上一卷的答案不够：几何对了，材质没对

第八卷处理的是结构化潜变量与 PBR 的表示问题：形状-材质双 DiT 怎么把几何与材质解耦，前馈高斯输出头怎么接。那一卷回答的是「表示能不能承载材质」，答案是能。但表示能承载不等于数据能监督。一个双 DiT 可以在架构上输出三通道，但如果训练语料里绝大多数物体只有一张被光照烘死的 RGB 贴图，metallic 与 roughness 通道就没有可靠监督信号，模型学到的只是「把 RGB 拆成三个近似通道」的恒等映射。架构给了容量，数据没给约束，容量就退化成过拟合的通道复制。

这就是上一卷答案不够的第一层原因：表示与监督是两件事。第八卷把表示做对了，但没有解决监督从哪来。Objaverse 的 80 万物体里，真正带完整 PBR 三通道的只是少数；大量资产是扫描件、是游戏 rip、是单图重建结果，它们的材质要么缺失、要么被烘死。Objaverse-XL 把规模推到 1000 万+，来源更混杂，这个问题只会更严重而不是更轻。堆量在这里不涨点，因为新增的多数样本在材质通道上没有信息量，反而把噪声引进来。

第二层原因在几何侧。前馈模型输出的网格往往没有 UV，或者 UV 接缝位置糟糕、拉伸严重。第八卷的网格提取管线能给出干净表面，但「干净表面」与「可贴图表面」不是一回事。UV 自动展开要处理接缝选择、岛 packing、拉伸最小化，每一步都有代价：接缝选得不好，纹理在缝上错位；岛 packing 不紧，纹理分辨率被浪费；拉伸大，细节被拉糊。快速 UV 加人工修是现实路线，但人工修的成本随资产数量线性增长，这与「一次前向」的规模化叙事直接冲突。

第三层原因在评测。第八卷沿用 PSNR/SSIM 作为主要指标，这两个指标衡量的是渲染像素与参考像素的接近程度，对几何微错、对材质通道错配都不敏感。一个 metallic 通道全错的资产，在固定光照下渲染出来的像素可能仍然接近参考图，因为光照恰好掩盖了错误。评测与可用性脱节，导致模型迭代朝着「像素更像」而不是「资产更可用」的方向走。本卷要做的，是把评测锚点从像素搬到下游：新视角几何误差测的是换视角后几何是否还站得住，引擎导入通过率测的是资产能不能被管线接受，人工盲评测的是换光后是否可信。

四 · 数据侧的具体机制：三件事不做，训练集越大噪声越多

数据清洗的优先级可以用一句话概括：去重、许可过滤、质量分级。这三件事不是可选项，而是训练集规模化的前置条件。去重针对的是几何与纹理哈希：Objaverse-XL 的来源混杂，同一资产可能以不同格式、不同缩放、不同三角化方式重复出现多次。重复样本在训练中会被反复加权，等效于给这批资产偷偷加了学习率，模型对它们的分布过拟合，对长尾分布欠拟合。几何哈希可以用归一化后的体素占用或采样点集做近似，纹理哈希可以用感知哈希在缩略图上做粗筛，两者结合能把大部分重复挡在训练集外。

许可过滤针对的是商用白名单。3D 数据的许可比 2D 更乱：扫描件、游戏 rip、CC 协议、自定义许可混在一起，很多资产的许可状态在元数据里缺失或矛盾。不做许可过滤，训练集里就混进了不可商用资产，模型学到的分布与产品可用的分布错位，下游法务风险也会传导回数据管线。许可过滤的代价是召回率下降——白名单会误杀一部分许可模糊但实际可用的资产，这个代价必须接受，因为误用的代价更高。

质量分级针对的是面数、纹理分辨率与水密性。前馈模型对训练网格的质量敏感：面数过低，细节学不到；面数过高，三角化噪声被当成几何信号；非水密网格会让 SDF 类监督出现符号歧义。分级不是简单阈值过滤，而是把资产分成若干档，训练时按档位采样，避免低质资产在损失里占据主导。这三件事合起来，是一个「先减法后加法」的管线：先去重减冗余，再过滤减风险，再分级减噪声，最后才谈规模。

五 · 材质侧的具体机制：三通道与 UV 的耦合

PBR 三通道的工程含义要说清楚。base color 是反照率，描述表面本身的颜色，不含光照；metallic 是二值或连续的金属度，决定反射是漫反射主导还是镜面主导；roughness 决定镜面反射的锐利程度。三者耦合才能让渲染器在不同光照下算出正确结果。只给一张 RGB 贴图，等于把三者烘成一个通道：金属件的高光被画进颜色里，换光后这块高光不会随光源移动，而是钉在纹理上。这就是「无法重光照」的具体机制，不是抽象说法。

三通道与 UV 的耦合在于采样。UV 展开决定纹理空间到表面的映射，接缝决定映射在哪里断开，拉伸决定纹素密度是否均匀。metallic 与 roughness 对拉伸的敏感度高于 base color：base color 拉伸只是颜色糊，metallic 拉伸会让金属/非金属边界在表面上漂移，roughness 拉伸会让高光锐度在表面上不一致。这意味着 UV 展开的质量对材质通道的可用性有放大效应。快速 UV 加人工修之所以是现实路线，是因为自动展开在接缝选择上缺少语义：它不知道哪里是金属与塑料的交界，也不知道哪里是高光需要连续的地方。

delighting 与 UV 的关系同样具体。delighting 在图像空间做除法，输出的是反照率图；这张图要贴到 UV 空间，就要经过重采样。重采样会引入两类误差：接缝处的插值误差，以及暗部噪声在重采样后的空间相关化。后者更麻烦，因为空间相关的噪声在盲评里看起来像「纹理细节」，容易被误判为合格。多光照监督是压这类误差的主要手段：同一资产在多个光照下观测，反照率的解被约束在交集里，暗部噪声因为不一致而被平均掉。代价是采集成本，这正是 3D 数据没有互联网级语料的根源之一。

SF3D 的 0.5 秒前向与 Hunyuan3D 2.1 的生产级 PBR，代表两种工程取向：前者把速度做到极致，后者把通道一致性做到可用。两者都不是 delighting 误差的解药，因为误差源在逆渲染的病态性，不在前向速度。一个团队选型时要问的不是「谁更快」，而是「谁的 delighting 误差在换光后更不可见」。这个问题只能靠引擎内换光测试与人工盲评回答，不能靠预览窗口的像素指标回答。

六 · 评测锚点的迁移：从像素相似到下游可用

评测迁移的机制要说具体。PSNR/SSIM 在固定视角、固定光照下比较渲染图与参考图，它的敏感度集中在像素级亮度与结构，对材质通道错配不敏感。新视角几何误差换一个视角渲染，比较几何轮廓与深度，对「几何在换视角后是否站得住」敏感。引擎导入通过率把资产送进真实管线，检查 UV 是否存在、材质通道是否完整、网格是否水密、单位与朝向是否合规，对「资产能不能被消费」敏感。人工盲评把换光后的渲染并排给评审，对「重光照是否可信」敏感。三个锚点各自覆盖一类失败模式，合起来才构成可用的评测。

迁移评测锚点有系统代价。新视角几何误差需要额外的视角与参考，引擎导入通过率需要维护管线兼容性矩阵，人工盲评需要评审人力与一致性校准。这些代价换来的是一件事：模型迭代的方向被锚定在下游可用性上，而不是像素相似度上。一个只优化 PSNR 的模型，会在 delighting 误差与 UV 接缝上静默退化，因为这些误差在固定光照的像素比较里被掩盖。评测锚点不迁移，数据与材质的工程投入就没有反馈回路。

把这一卷的叙事收束到一个具体机制上：前馈模型的输出是资产候选，候选到资产的转换由数据清洗与材质分解完成，这两步的失败模式都有明确的视觉签名与下游签名。数据侧的三件事——去重、许可过滤、质量分级——决定训练分布的信噪比；材质侧的三通道与 UV 耦合决定资产能否重光照。评测锚点从像素迁到下游，是让这两侧的工程投入获得反馈的唯一路径。一个团队如果只在前向速度上竞争，而不在清洗管线与 delighting 误差上投入，得到的是一批预览好看、导入失败的候选资产。这不是模型能力问题，是数据与材质的地基问题。
