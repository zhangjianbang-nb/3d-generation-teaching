一 · 证据的读法：把论文结论拆成可复现的接口断言

读这一卷的论文，不能停在「它生成了一个好看的模型」。工程读者要问的是：论文声称的表示，在什么分辨率、什么解码路径、什么下游接口下成立？把每篇论文的结论改写成一句可检验的接口断言，是这一部分的方法。比如 Direct3D 的断言是「3D VAE 把高分辨率 3D 压进潜空间后，DiT 能在潜空间完成扩散，且解码回几何的重建误差不超过 VAE 本身的上限」；TRELLIS 的断言是「一套 SLAT 潜变量能分别解成高斯、网格、辐射场，三种解码器共享同一潜变量而不互相破坏」；Hunyuan3D 2.1 的断言是「PBR 三通道输出在换光照后仍保持材质语义」。这些断言都能被拆成三个可测项：表示的分辨率预算、解码器的误差来源、下游引擎的接受条件。

把断言写成公式，是为了让失败模式显式化。以潜空间扩散为例，前向加噪与去噪目标可写为：

$$ \mathbf{z}_t=\sqrt{\bar\alpha_t}\,\mathbf{z}_0+\sqrt{1-\bar\alpha_t}\,\boldsymbol\epsilon,\qquad \mathcal{L}=\mathbb{E}_{t,\mathbf{z}_0,\boldsymbol\epsilon}\big\|\boldsymbol\epsilon-\boldsymbol\epsilon_\theta(\mathbf{z}_t,t,\mathbf{c})\big\|_2^2 $$

这里 $\mathbf{z}_0$ 是 3D VAE 编码后的潜变量，$\mathbf{c}$ 是条件（图像或文本）。公式本身不新鲜，关键在于 $\mathbf{z}_0$ 的维度与感受野：VAE 的压缩率决定了潜变量能保留多少高频几何，DiT 的注意力半径决定了它能否在潜空间里协调远距离部件。Direct3D 的工程代价就落在这两处——VAE 重建上限是硬天花板，扩散再强也补不回被压掉的花纹；而潜空间扩散的采样步数与潜变量分辨率共同决定推理成本，分辨率翻倍，注意力代价按平方增长。

一个具体例子：用同一张输入图分别跑「高压缩 VAE + 大 DiT」与「低压缩 VAE + 小 DiT」两条配方，前者在薄壁、镂空结构上容易出现融合或断裂，后者在同样显存下只能生成较低频的形体。这不是谁好谁坏，而是接口预算的分配问题：压缩率买的是规模化，代价是重建上限；DiT 容量买的是全局协调，代价是推理时间。论文里的定性结论必须落到这两个预算上才有工程意义。

失败模式也由此可分类。第一类是表示误差：VAE 解码出的几何在薄结构处失真，属于编码器瓶颈。第二类是条件误差：DiT 在潜空间里把条件信息「平均」掉了，表现为多视角输入下背面与正面风格不一致。第三类是接口误差：潜变量本身没问题，但解码器输出的网格没有 UV，进引擎后无法贴图。三类误差在论文里常被混为一谈，工程上必须分开定位，否则调参方向会错。

二 · 模型配方的对照：同一目标，不同的误差账本

把这一卷的模型按「表示—解码—下游」三段拆开，配方差异立刻清楚。Direct3D 走的是「3D VAE + 潜空间 DiT」，优势是潜空间规模化，误差账本上记的是 VAE 重建上限与潜空间分辨率。TRELLIS 走 SLAT：稀疏体素提供空间索引，局部三平面提供局部细节，一套潜变量挂多个解码头。它的账本记的是分辨率与解码误差——稀疏体素的分辨率决定能表达多细的结构，局部三平面的插值方式决定表面是否连续，多解码器之间的一致性决定同一潜变量解成高斯和网格时是否「像同一个东西」。

Hunyuan3D 2.0 把形状与纹理拆成两个 DiT，账本上多了一笔两阶段误差：形状 DiT 先出几何，纹理 DiT 再在几何上生成贴图，几何的微小偏差会在纹理阶段被放大成接缝或错位。2.1 加 PBR 三通道，账本再添 delighting 误差。PBR 的定义可写成：

$$ \mathcal{M}=\{\mathbf{c}_{\mathrm{base}},\ m,\ r\},\qquad \mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I}) $$

$\mathbf{c}_{\mathrm{base}}$ 是去光照后的基础色，$m$ 是金属度，$r$ 是粗糙度。delighting 的目标是把输入图里的光照成分剥离，只留下反照率。这件事在单张图上是不适定的：同一张暗部像素，既可能是低反照率，也可能是阴影。模型只能靠先验猜，猜错就把阴影烘进了 base color。工程后果很直接：在引擎里换一套逆光，资产暗部仍然「自带阴影」，金属高光位置不对，材质语义崩掉。

CraftsMan3D 的配方是「生成 + 精修」，账本记的是管线长度：生成阶段出粗模，精修阶段补细节与拓扑，两段之间的接口（粗模的拓扑是否支持精修）决定最终质量。Step1X-3D 做几何/纹理解耦与可控编辑，账本记的是接口一致性：几何改了，纹理是否跟着改；纹理改了，几何的 UV 是否还对得上。SF3D 走快速 UV + PBR + delighting，账本记的是 UV 接缝与材质歧义——0.5 秒出可用资产，速度来自对 UV 展开的简化，简化就会在接缝处留下拉伸或错位。

三 · 实验数字的边界：只引用给定事实里的量

这一卷的事实里，唯一明确的数字是 SF3D 的「0.5 秒可用资产」。这个数字必须被正确解读：它描述的是从输入到可进引擎的资产的端到端时间量级，而不是生成质量的上限。0.5 秒意味着管线里没有迭代式优化、没有多视图重投影、没有人工精修，UV 展开与 PBR 分解都被压进一次前向。代价写在账本上：UV 接缝与材质歧义。速度买的是吞吐，不是保真度。

其余模型在给定事实中没有具体实验数字，因此只能做定性对照。定性对照也要有结构：把「快」「统一」「能用」三个维度分开看。第七卷的三平面/高斯解决「快」，第八卷解决「统一」与「能用」。统一指的是同一潜变量多解码（TRELLIS 的 SLAT），能用指的是 PBR、UV、delighting 这些下游接口（Hunyuan3D 2.1、SF3D）。快与统一之间存在张力：多解码器共享潜变量，要求潜变量在多种解码方式下都保持语义，这会限制潜变量的压缩率与稀疏度；统一与能用之间也存在张力：PBR 三通道要求潜变量保留材质信息，而几何潜变量往往把材质当噪声压掉。

把张力写成约束，可以指导配方选择。设潜变量为 $\mathbf{z}$，几何解码器为 $D_g$，材质解码器为 $D_m$，则统一性要求：

$$ \min_{\mathbf{z}}\ \mathbb{E}\big[\|D_g(\mathbf{z})-G\|^2+\|D_m(\mathbf{z})-M\|^2\big]\quad\text{s.t.}\ \dim(\mathbf{z})\le B $$

$B$ 是潜变量预算。预算固定时，几何与材质争夺同一批维度：几何要高频细节，材质要反照率与粗糙度的平滑分布，两者的最优编码不同。TRELLIS 用稀疏体素 + 局部三平面缓解这个争夺——空间索引让几何细节有地方放，局部三平面让材质在局部平滑；Hunyuan3D 2.1 干脆用两个 DiT 分开承担，代价是两阶段误差。没有免费的统一。

一个具体失败案例的思路（不编造数字）：把 Hunyuan3D 2.0 的形状/纹理双 DiT 输出直接送进引擎，不做 delighting，只在一套暖光下验收，资产看起来「好看」。换冷光后，base color 里烘进的暖色阴影暴露，金属区域失去高光方向感。这不是模型生成失败，而是验收流程失败——验收只覆盖了一套光照，等于没有测 PBR 接口。工匠笔记里的三套光照（暖光/冷光/逆光）正是为了把这类失败逼出来。

四 · 反例的解剖：接口错位比生成质量更致命

反例一：三平面解码错位。第七卷的三平面要解码成网格或高斯，如果解码时的等值面阈值与训练时的密度分布不匹配，表面会出现「双层」或「空洞」。这不是生成模型的问题，是解码接口的问题。工程上表现为：同一潜变量，解成高斯看起来正常，解成网格却出现自交。TRELLIS 的多解码器设计正是为了暴露这类错位——一套潜变量解成三种表示，任何一种解错都说明潜变量的语义不够统一。

反例二：UV 展开与纹理分辨率的错配。UV 展开决定纹理分辨率与接缝。如果 UV 岛在展开时被过度拉伸，纹理贴上去后在拉伸方向模糊，在压缩方向出现摩尔纹。SF3D 的快速 UV 为了速度简化了展开，接缝处的拉伸就是速度的代价。工程判断是：如果下游要批量贴图、要动画，UV 接缝必须作为验收项，不能只看渲染图。

反例三：拓扑不可动画。生成模型输出的网格如果三角面分布不均、有大量细碎三角形，绑定骨骼后形变会撕裂。CraftsMan3D 的精修阶段部分解决这个问题，但精修与生成之间的接口如果没对齐（精修改变了顶点顺序），动画管线仍然会失败。第九卷的重拓扑正是为了补这一环，第八卷的模型只保证「能生成」，不保证「能动画」。

反例四：部件不可拆。生产资产要求部件能拆、物理要能仿真。Step1X-3D 的几何/纹理解耦提供了可控编辑的接口，但解耦不等于部件分割。如果生成的是一个整体网格，没有部件标签，物理仿真时无法分别赋材质、无法做刚体分解。这是第八卷模型共同缺的一块，真正的管线要把它们与第九卷的部件生成串起来。

把这些反例放在一起，结论是：接口错位的代价通常高于生成质量的微小差距。一个生成得漂亮但 UV 接缝明显的资产，进引擎后需要人工返工；一个生成得稍粗糙但接口干净的资产，可以直接进管线。工程选型应优先看接口，再看保真度。

五 · 验收机制：把 PBR 与 UV 变成可执行的检查

验收不是主观「好看」，而是一组可执行的检查。第一项是光照切换：在引擎里换三套光照（暖光/冷光/逆光），看金属是否像金属、粗糙度是否合理、暗部是否带阴影。只在一套光照下好看的资产，通常是把光照烘进了 base color。第二项是 UV 检查：看接缝处是否有拉伸、纹理密度是否均匀、UV 岛是否重叠。第三项是拓扑检查：三角面是否均匀、是否有非流形边、绑定后形变是否撕裂。第四项是部件检查：能否按语义拆分、拆分后物理参数是否可赋。

把验收写成伪代码思路，是为了让检查可批量执行：

$$ \text{accept}=\big[\text{relight}(3\ \text{setups})\ \wedge\ \text{uv\_seam}<\tau_s\ \wedge\ \text{manifold}\ \wedge\ \text{parts\_labeled}\big] $$

$\tau_s$ 是接缝拉伸的容忍阈值，具体数值由下游引擎的纹理分辨率决定，给定事实里没有数字，因此只能定性表述为「按目标分辨率设定」。这个合取式的意义在于：任何一项失败，资产就不进管线。工程上常见的错误是把验收简化成渲染图对比，渲染图只覆盖一套光照、一个视角，恰好绕过了 PBR 与 UV 的大部分失败模式。

系统代价在这里体现为验收吞吐。三套光照 × 多视角渲染 × UV 检查 × 拓扑检查，单资产验收时间可能超过生成时间。SF3D 的 0.5 秒生成在验收环节被拉长，端到端吞吐由验收瓶颈决定。这是生产化的真实账本：生成快不等于管线快，验收与返工才是吞吐的决定项。

一个具体机制：delighting 的验收可以用「重光照一致性」来测。把资产的 base color 与法线、粗糙度、金属度一起送进渲染器，换光源方向，看高光是否随光源移动。如果高光不动，说明光照被烘进了 base color；如果高光位置错，说明金属度或粗糙度估计错。这个检查不需要真值，只需要物理一致性，因此可以批量跑。

最后落在工程判断上：第八卷的模型各自解决一小块，真正的管线要把它们串起来，而串联的粘合剂就是验收机制。选型时先定验收项，再定模型配方；验收项覆盖不到的地方，就是管线会漏的地方。PBR 三通道与 UV 展开不是「加分项」，是资产能否进引擎的门槛；delighting 误差与 UV 接缝不是「小瑕疵」，是返工成本的来源。把这三件事写进验收脚本，比在论文里比较生成质量更能决定生产线的成败。
