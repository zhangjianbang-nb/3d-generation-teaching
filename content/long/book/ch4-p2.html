一 · 三平面的几何定义与采样机制

三平面表示把三维空间中的一个查询点拆成三组二维坐标，分别在三个正交平面上做特征查表。设三个平面为 XY、XZ、YZ，每个平面是一张形状为 C×R×R 的特征图，C 为通道数，R 为平面分辨率。对空间中任意点 x=(x,y,z)，定义三个投影采样：

$$ \mathbf{f}(\mathbf{x})=\mathrm{concat}\left(\mathbf{F}_{xy}(x,y),\ \mathbf{F}_{xz}(x,z),\ \mathbf{F}_{yz}(y,z)\right) $$

其中 Fxy(x,y) 表示在 XY 平面上以连续坐标 (x,y) 做双线性插值取出的 C 维向量，另两项同理。拼接后得到 3C 维特征，送入一个小型 MLP 解码为颜色与密度，或解码为 SDF 值。关键在于：三平面不是体素，它不存储 R3 个体素，而是三张 R2 的图，存储量从三次方降到平方。这是三平面能进入生成器输出空间的根本原因——生成器只需输出三张 2D 特征图，而不是一个三维张量。

双线性插值的具体机制值得展开。对平面坐标 (u,v)，先定位四个相邻格点 (⌊u⌋,⌊v⌋)、(⌊u⌋+1,⌊v⌋)、(⌊u⌋,⌊v⌋+1)、(⌊u⌋+1,⌊v⌋+1)，用小数部分 α=u−⌊u⌋、β=v−⌊v⌋ 做加权：

$$ \mathbf{F}(u,v)=(1-\alpha)(1-\beta)\mathbf{F}_{00}+\alpha(1-\beta)\mathbf{F}_{10}+(1-\alpha)\beta\mathbf{F}_{01}+\alpha\beta\mathbf{F}_{11} $$

这一步是可微的，梯度能回传到平面特征图上，因此三平面可以作为生成器的输出端被 2D 判别器间接监督。工程上要注意坐标归一化：查询点通常先映射到 [−1,1] 或 [0,1] 区间，再乘以 R 得到像素坐标；越界查询需要 clamp 或 padding，否则边缘会出现特征断裂。

一个具体例子：假设 R=256、C=32，则单个平面有 256×256×32 个浮点数，三平面合计约 630 万参数（以 float32 计约 25 MB）。若改用同分辨率的体素，2563×32 将超过 5 亿个值，显存直接不可行。这就是三平面在生成任务中被选中的直接理由：它把「三维细节」压缩进「二维卷积可处理的张量」。

失败模式也很明确。平面分辨率决定细节上限：细小的把手、薄片、镂空结构在 256 分辨率下会被双线性插值抹平，因为平面上的一个像素对应三维空间中一条贯穿的射线，沿该射线方向的所有点共享同一组平面特征。三平面本身没有沿轴方向的区分能力，它依赖 MLP 在拼接后恢复各向异性。若 MLP 容量不足或训练不充分，物体在某一轴向上会出现「拉丝」或「粘连」——两个在 XY 投影上重叠、但在 Z 上分离的部件会被错误地混为一谈。

二 · 从 StyleGAN2 到三平面：生成器的数据流

EG3D 的数据流可以拆成四段：潜码 → 三平面 → 神经渲染 → 2D 图像。第一段，一个 512 维潜码 z 经 StyleGAN2 的映射网络变成中间码 w，再经若干层调制卷积生成三张特征图。第二段，三平面作为「3D 特征场」被查询：给定相机位姿，沿每条射线采样若干点，每点做三平面拼接得到特征，送入轻量 MLP 解码密度与颜色。第三段，体渲染积分把射线上的密度与颜色合成为像素值。第四段，渲染出的多视角图像送入 2D 判别器，与真实图像分布对抗。

这里的数据流有一个容易被忽略的细节：三平面生成器输出的是特征图，不是最终几何。几何与外观是在渲染阶段由 MLP 解码出来的，因此生成器的监督信号完全来自 2D 图像。判别器只看渲染结果，不看三平面本身。这意味着三平面的语义结构是「自发涌现」的：网络为了让多视角渲染都像真实物体，必须让三平面在三维查询下保持一致，否则侧视角会穿帮。姿态条件在这里是必需的——没有相机参数，渲染器无法把三平面投影成正确的 2D 图，对抗信号也就无法定位到三维结构上。

伪代码层面的数据流如下：

  • 输入：潜码 z、相机外参 E、内参 K。
  • w = MappingNetwork(z)；T = TriplaneGenerator(w)，输出形状 [3, C, R, R]。
  • 对每条射线，采样 N 个点 {xi}；每点计算 fi = concat(Fxy, Fxz, Fyz)。
  • (σi, ci) = MLPDecoder(fi, 视角方向)。
  • 像素值 = 体渲染积分({σi, ci})；渲染图送入判别器。

系统代价集中在两处。其一是渲染成本：每条射线采样数十到上百个点，每个点三次双线性采样加一次 MLP 前向，分辨率越高、采样越密，成本线性上涨。其二是 2D 卷积成本：三平面分辨率 R 翻倍，平面元素数变为四倍，生成器卷积与显存同步上涨。实践中的取舍是先按物体尺度定 R（256 或 512），再用渲染分辨率与采样数补细节，而不是一味堆平面分辨率。

失败模式：三平面生成器与渲染器联合训练时，若判别器过强，生成器会倾向于产出「平面化」的特征——即三平面在三个方向上高度相似，渲染出的物体在多视角下看起来像同一张图贴上去，缺乏真正的三维厚度。另一种失败是「视角记忆」：生成器学会了在训练相机分布内渲染正确，但换到分布外视角时三平面查询暴露矛盾，出现背面塌陷。这两种失败都源于同一个机制缺口——2D 判别器只约束渲染结果，不直接约束三平面的三维一致性。

三 · 走通一个例子：从潜码到可查询的 3D 场

取一个具体场景：生成一把带弯曲手柄的杯子。设定 R=256、C=32、MLP 隐藏层宽度 64、射线采样 48 点、渲染分辨率 128×128。第一步，随机采一个 z，映射网络输出 w。第二步，三平面生成器输出三张 32×256×256 的特征图。此时三平面还没有任何可解释的几何含义，它只是一组待解码的特征。

第三步，选定一个前视角相机，从像素中心发出一条射线，射线上均匀采样 48 个点。对每个点 xi，计算 (x,y)、(x,z)、(y,z) 三组平面坐标，各自双线性采样出 32 维向量，拼接成 96 维，送入 MLP。MLP 输出该点的密度 σi 与颜色 ci。第四步，体渲染积分沿射线累加：

其中 δi 为相邻采样点间距。累加结果就是该像素的颜色。对 128×128 个像素重复此过程，得到一张渲染图。第五步，这张图与真实杯子图像一起送入 2D 判别器，梯度回传，同时更新三平面生成器、MLP 解码器与映射网络。

训练收敛后，三平面获得了结构。此时可以做一次「查询实验」：固定 w，在三维空间中取一个点，比如杯柄弯曲处的中心，计算三平面拼接特征并解码密度。若该点落在杯柄实体内部，密度应显著高于空气点；若落在杯口空心处，密度应接近零。这就是「可查询的 3D 场」——三平面加 MLP 构成了一个隐式的密度场，任意点都能查询，不依赖网格或体素。

这个例子里有一个具体的工程判断：采样数 48 是否足够？杯柄是细长结构，若射线采样过疏，细柄可能被跳过，渲染出的图缺柄，判别器给出惩罚，生成器被迫加粗柄或抹掉柄。这是三平面生成中典型的「细节—采样」矛盾：细节越细，越需要密采样；密采样越贵，训练越慢。解决方向通常是在粗采样后做重要性采样，把采样点集中到密度高的区间，而不是均匀铺满整条射线。

另一个失败模式出现在杯子的内壁：三平面在 XY 投影上，杯口的内外壁可能落在同一像素附近，双线性插值把两者特征混合，MLP 解码出「半透明」的壁，渲染时出现重影。这说明三平面的平面分辨率不仅限制细节，还限制「沿轴分离」的能力——两个在某一投影上靠近、在另一轴上远离的结构，需要 MLP 有足够容量从拼接特征中分辨，否则会被平面采样混淆。

四 · 三平面作为潜空间：为什么它能被生成器输出

三平面之所以能成为生成器的输出空间，核心在于它的张量形状与 2D 卷积兼容。StyleGAN2 的调制卷积天然处理 [C,H,W] 形状的特征图，三平面恰好是三张这样的图。生成器不需要为三维数据结构改写卷积算子，也不需要像体素那样引入 3D 卷积或稀疏卷积。这是工程上的巨大便利：整个生成器栈可以复用成熟的 2D GAN 组件，判别器也是 2D 的，训练管线几乎不变。

但「能被输出」不等于「能被学好」。三平面的一个结构性问题是三个平面之间没有显式的耦合约束。XY、XZ、YZ 三张图是独立生成的，它们在三维查询时才被拼接。若生成器在三张图上写入不一致的特征，拼接后的 MLP 会收到矛盾输入，解码结果不可预测。训练中这表现为三平面出现「分工不均」：某一张平面承载了大部分结构，另两张接近噪声，模型退化为「单平面加两张几乎不携带信息的平面」。这种退化在判别器信号弱或训练早期常见，因为单平面已经足以让某个视角的渲染看起来合理。

一个具体的机制补救是共享卷积骨干：先用一个 2D 骨干生成一张基础特征图，再通过不同的变换（例如沿不同轴的 reshape 或转置卷积）派生出三张平面，使三者共享部分统计结构。这样三平面在早期就具备相关性，不容易退化为单平面。代价是表达能力受限——三平面被迫相似，各向异性的细节可能被牺牲。

系统代价还有一处：三平面的查询是「无界」的。任意三维点都能查询，包括远离物体的空域。空域查询返回的密度应接近零，但若 MLP 在空域上输出非零密度，渲染会出现雾状伪影。训练时需要通过体渲染的透明度项自然压制空域密度，但这依赖采样覆盖。若采样只集中在物体附近，空域从未被查询，MLP 在空域的行为就是未定义的，换视角时可能冒出伪影。这是三平面生成器在视角外推时不稳定的机制根源。

具体例子：生成一个椅子，训练相机集中在前方 180 度。三平面在背面区域的特征从未被渲染监督过，因为背面从未出现在训练视角里。当换到背面视角查询时，三平面拼接出的特征落在未训练区域，MLP 解码出任意密度，背面可能塌陷成一片平板或冒出空洞。这不是三平面表示本身的缺陷，而是 2D 对抗监督的覆盖问题——判别器只见过前方渲染，背面没有梯度。

五 · 与体素、点云、隐式权重的机制对照

把三平面放进原生 3D 表示的谱系里，它的位置由「存储增长阶」和「查询方式」共同决定。体素是三次方存储，查询是 O(1) 查表，但分辨率一高就爆显存；点云是稀疏点集，存储随点数线性增长，查询需要最近邻搜索，没有拓扑；隐式函数（如 Shap-E 生成的 MLP 权重）把整个场压缩进网络参数，存储与网络宽度相关，查询是一次前向，连续且可提取网格，但权重维度高、训练难。三平面介于体素与隐式之间：存储平方增长，查询是三次双线性采样加一次小 MLP，既有显式的空间结构，又有神经解码的连续性。

表示存储增长查询机制拓扑能力主要代价
体素O(R³)直接查表固定网格，需等值面提取显存随分辨率三次方上涨
三平面O(R²)三次双线性 + MLP隐式，可提取网格平面分辨率限制细节与轴向分离
点云O(N)最近邻/半径搜索无拓扑下游需重建与重拓扑
隐式 MLP 权重与网络宽度相关一次前向连续表面，拓扑自由高维参数、训练不稳定

这张对照表揭示了一个机制层面的取舍：三平面用「降维」换「可卷积」，用「MLP 解码」换「连续性」，代价是把各向异性和细节上限交给了平面分辨率与 MLP 容量。点云用「稀疏」换「易学」，代价是丢掉拓扑；隐式权重用「参数化」换「连续表面」，代价是高维优化。三者不是互相替代，而是对应不同的下游需求：要快速预览选点云，要直接出网格选显式网格方法，要连续表面与可提取几何选隐式或三平面。

一个具体的失败对照：假设要生成一个带细长天线的设备。体素在低分辨率下天线直接消失（一个体素格放不下细杆）；三平面在 256 分辨率下天线可能被抹成一条模糊的脊；点云能保留天线的点，但没有面，渲染出来是一串漂浮的点；隐式 MLP 权重若训练充分能表达细杆，但权重扩散的采样噪声会让细杆时有时无。四种表示在同一物体上的失败方式不同，选择哪一种取决于下游是渲染、是网格、还是拓扑编辑。

工程判断落在「分辨率预算」上：三平面的 R 不是越高越好。R 翻倍，平面元素四倍，生成器卷积与显存四倍，而细节提升受限于 MLP 容量与渲染采样密度。实践里先把 R 定在物体尺度对应的档位（256 或 512），再用渲染分辨率与重要性采样补细节，比直接堆 R 更划算。这是三平面在生成任务中被广泛采用的直接工程理由：它在平方增长的成本下，提供了可卷积、可查询、可渲染的 3D 特征场。
