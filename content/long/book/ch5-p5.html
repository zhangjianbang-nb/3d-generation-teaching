一 · 从公式到代码：SDS 更新的最小骨架

把 $$ \nabla_\theta \mathcal{L}_{\mathrm{SDS}}=\mathbb{E}_{t,\epsilon}\left[w(t)\left(\epsilon_\phi(\mathbf{x}_t;y,t)-\epsilon\right)\frac{\partial \mathbf{x}}{\partial \theta}\right] $$ 落成可运行代码，关键不在公式本身，而在四个接口的边界划分：可微渲染器输出 x（一张 H×W×3 的渲染图），噪声调度器给出 t 与 ᾱ_t，扩散模型给出 ε_φ，优化器持有 θ。伪代码思路如下：采样相机位姿 c ~ p(cam)，渲染 x = render(θ, c)；采样 t ~ U(t_min, t_max) 与 ε ~ N(0, I)；构造 x_t = √ᾱ_t · x + √(1−ᾱ_t) · ε；把 x_t、t、文本嵌入 y 送进冻结的 ε_φ，得到噪声预测；计算残差 r = ε_φ(x_t; y, t) − ε；用 w(t) 加权后，通过渲染器的反向传播把 r · ∂x/∂θ 变成 θ 的梯度。

这里有一个极易被忽略的工程细节：∂x/∂θ 不是标量而是雅可比，实际实现中并不显式构造它，而是把加权残差 w(t)·r 当作渲染图的上游梯度 ∂L/∂x，直接调用 x.backward(gradient=w(t)*r)。这意味着 SDS 的“损失函数”在代码里根本不存在——没有 loss 张量被 backward() 消费，只有一个人为注入的梯度。任何试图用 loss.backward() 常规写法复现 SDS 的尝试都会失败，因为扩散模型的前向过程本身不可微到 x（x_t 对 x 的依赖被 ε 采样截断，这正是 SDS 省略 U-Net 雅可比的近似来源）。

系统代价体现在显存与计算图管理上：渲染图必须保留在计算图中直到反向传播完成，而扩散模型的前向必须在 no_grad 下执行，否则 U-Net 的激活会撑爆显存。一个 512×512 的渲染图配一个十亿参数级的扩散模型，单步前向在消费级显卡上已接近显存上限；若把 t 的采样批量化（一次渲染多个相机），显存线性增长。失败模式是“梯度污染”：若误把扩散模型参数设为可训练，或忘记 detach() 噪声预测，优化器会同时更新 θ 与 φ，几轮之后扩散先验被渲染分布带偏，输出退化为噪声图。具体例子：用 DreamFusion 配方训练一只孔雀，若渲染器是 Instant NGP 的哈希编码 NeRF，则 θ 包含哈希表与 MLP 权重，哈希表的梯度稀疏且量大，学习率必须与 MLP 分开设置，否则哈希冲突区域先崩。

二 · 调参顺序：相机、CFG、w(t)、步数

工匠笔记给出的顺序是硬约束，不是建议。第一步是相机分布 p(cam)：仰角覆盖从俯视到平视、方位角覆盖 360°、半径在一个窄区间内抖动。机制上，SDS 的每个采样相机独立打分，视角覆盖决定了哪些表面被优化过。若相机只绕正面 ±60° 转，背面从未进入渲染图，也就从未收到梯度，背面几何停留在初始化状态——初始化是球或椭球时，背面就是一个光滑球面。失败模式不是“背面难看”，而是“背面不存在”：提取网格时背面是空的或塌陷的。具体例子：训练一只孔雀，正面羽毛纹理丰富，转到背面只见一团无纹理的椭球，因为 p(cam) 的方位角上限卡在了 90°。

第二步是 CFG 尺度。文本条件扩散的噪声预测实际使用 ε_φ(x_t;y,t) = ε_uncond + s·(ε_cond − ε_uncond)，s 即无分类器引导尺度。SDS 残差里 s 直接乘在文本对齐分量上，s 越大，梯度越偏向“贴合文本语义”，但残差的幅值也被放大，等效于对渲染图施加更强的饱和推力。机制上，扩散模型在高 s 下的得分场偏离真实数据分布，把样本推向分布边缘——颜色通道被推到极值，出现塑料感与过饱和。系统代价是纹理细节被高频噪声淹没，因为 s 放大的是语义方向而非细节方向。具体例子：s 从 50 提到 100，孔雀的蓝绿羽毛从自然渐变变成荧光色块，同时背景出现彩色噪点。

第三步是 w(t)。噪声水平 t 决定扩散模型“看到”的是结构还是纹理：高 t（重噪）时噪声预测主要编码全局形状与语义，低 t（轻噪）时编码高频纹理。若 w(t) 在高 t 段权重过大，几何先粗后细的收敛顺序被打乱，表面出现低频鼓包；若低 t 段权重过大，纹理在几何尚未定型时就被烘焙上去，随后几何变动导致纹理“粘”在错误的表面上。典型配方是对 w(t) 做钟形或分段线性加权，让中段 t 主导。第四步才是步数：步数不足表现为几何未收敛，步数过多则在已收敛区域反复采样低 t，把过饱和与纹理粘连放大。调参顺序颠倒的代价是：先调步数再调相机，等于在一个视角缺失的配置上浪费算力，最终仍要回到相机分布重训。

三 · 检查清单：从渲染图到网格的逐项核对

训练中的检查项按数据流顺序排列，每项对应一个可观测信号而非主观判断。

  • 相机覆盖：把采样到的位姿画在单位球上，检查方位角是否有空洞、仰角是否越过两极。空洞即梯度盲区。
  • 渲染图动态范围：每若干步存一张渲染图，检查是否有通道值贴到 0 或 1。贴边即过饱和前兆。
  • 残差幅值：记录 ‖ε_φ − ε‖ 的滑动均值。持续上升说明渲染分布偏离扩散先验的训练分布，需检查 s 与 w(t)。
  • 多视角一致性：固定三个相隔 120° 的相机，比较同一语义部位（如孔雀的尾屏）在三张渲染图中的位置与颜色。Janus 现象在此项暴露——正面与背面各长一张脸。
  • 几何提取质量：用 DMTet 或 marching cubes 提取网格后，检查是否有漂浮碎片、非流形边、法线翻转。SDS 的几何噪声常表现为表面细碎起伏。
  • 纹理粘连：把网格贴图展开到 UV 平面，检查相邻 UV 岛之间是否有颜色渗透。SDS 在低 t 段的梯度不区分 UV 接缝，纹理会在接缝处糊成一片。

每一项都有对应的失败模式与修复路径。相机空洞的修复是扩大 p(cam) 的方位角范围并重训，而非在后期补视角；残差幅值上升的修复是降低 s 或调整 w(t) 的高 t 权重；Janus 的修复不是调参能解决的，需要引入视角一致性约束（如 VSD 的粒子模型或 ISM 的区间得分），这属于方法级改动而非超参改动。系统代价上，检查清单本身消耗工程时间：每项检查需要插桩、存图、可视化，一套完整的监控管线在项目初期就要搭好，否则训练到一半才发现相机空洞，只能从头再来。

具体例子：用 DreamGaussian 的 3DGS 配方做分钟级生成，检查清单里的“几何提取质量”一项要换成“高斯椭球分布”：检查是否有大量椭球漂浮在物体外部的空白区域，这些是 SDS 在低 t 段产生的伪影，会在光栅化时形成雾状噪点。修复方式是提高不透明度正则的权重，或在少步 SDS 中降低低 t 的采样概率。

四 · 家族对比的工程读法：每个补丁对应一个失败模式

把第五卷的对比表当作故障排查手册来读，每一行的方法改动都精确对应上一行的遗留问题。

方法核心改动解决的失败模式引入的新代价
DreamFusionSDS + Imagen无 3D 数据的文生 3D多面矛盾、过饱和、训练慢
SJC加噪 + PAAS得分落在训练分布外导致的方差视角一致性仍未显式约束
Magic3D粗 NeRF + DMTet 精修低分辨率几何细节不足两阶段调参、阶段间误差传递
ProlificDreamerVSD 粒子模型过饱和与多样性坍缩粒子集前向成本
Fantasia3D几何/外观解耦纹理掩盖几何缺陷两阶段误差累积
DreamGaussian3DGS + 少步 SDS训练时间过长几何粗糙、椭球伪影
LucidDreamerISM 区间得分方差大、几何不稳DDIM 反演的计算成本

读表的关键是识别“补丁的补丁”。SJC 的 PAAS 把渲染图加噪到扩散模型训练分布内再打分，机制上是把 x_t 的构造从“渲染图加噪”改为“渲染图先加噪再按扩散前向加噪”，使得分估计的方差下降；但它没有触碰视角一致性，所以 Janus 仍在。VSD 引入粒子模型，把单个 3D 实例的得分替换为一组粒子的分布得分，机制上是在 SDS 残差里减去“当前 3D 分布”的得分，从而抑制过饱和并恢复多样性；代价是每次更新要前向多个粒子，显存与算力成倍增长。ISM 用 DDIM 反演构造区间得分，把 t 的采样从单点扩展为区间，降低方差；代价是反演本身需要多步扩散前向，训练时间回升。

系统代价的传递链值得注意：DreamGaussian 用 3DGS 把时间压到分钟级，代价是几何粗糙，而几何粗糙又会让后续的纹理检查清单失效——高斯椭球的分布无法直接提取为流形网格，检查项必须换成点云或椭球可视化。具体例子：用 DreamGaussian 生成孔雀，分钟级出结果，但尾屏的羽枝结构糊成一片椭球云，此时若强行用 DMTet 提取网格，得到的表面布满孔洞。工程判断是：分钟级路径适合预览与迭代方向，精细资产仍需回到 Magic3D 的两阶段或 VSD 的慢速路径。

五 · 五道自测题

以下五题覆盖本卷的机制、代价与工程判断，答案落在具体机制而非结论口号上。

  • 题一：SDS 的代码实现中为何不存在 loss 张量？若强行用 loss.backward() 复现，会在哪一步断裂？提示：考察 x_t 对 x 的依赖路径与 ε 采样的截断。
  • 题二：相机方位角只覆盖 180° 时，背面几何为何停留在初始化状态？请从梯度盲区与 ∂x/∂θ 的稀疏性两个角度说明，并给出修复顺序。
  • 题三：CFG 尺度 s 放大时，SDS 残差的幅值与方向如何变化？为何颜色先于几何过饱和？提示：考察 s 乘在文本对齐分量上，而颜色通道的动态范围最窄。
  • 题四：SJC 的 PAAS 与 ISM 的区间得分都在降方差，二者的机制差异在哪？各自引入的系统代价是什么？提示：一个改 x_t 的构造，一个改 t 的采样范围。
  • 题五：给定一个“分钟级出预览、精细资产后补”的管线，DreamGaussian 与 Magic3D 的分工边界应划在哪里？检查清单在两条路径上分别要替换哪一项？提示：考察几何表示（3DGS 椭球 vs DMTet 网格）对检查项的决定作用。

自测题的工程价值在于把“调参直觉”还原为可验证的机制判断。题一的正确答案必须指出：扩散模型前向在 no_grad 下执行，ε_φ 对 x 的雅可比被省略，梯度只能通过人为注入的 w(t)·r 回传；断裂点在 x_t 的构造处，因为 ε 是采样得到的随机量，计算图在此截断。题二的正确答案必须区分“从未渲染”与“渲染了但梯度稀疏”：前者是盲区，后者是哈希编码的稀疏梯度导致背面更新缓慢，修复顺序是先扩相机再调学习率。题五的正确答案必须落到检查项替换：3DGS 路径检查椭球分布与不透明度，DMTet 路径检查流形性与法线，二者不可混用。

最后落在具体机制上：SDS 的偏差不是可以通过调参消除的噪声，而是“每个相机独立打分、视角间无一致性约束”这一结构的必然产物。工程上能做的，是把一致性从隐式期望变成显式检查项——相机覆盖检查、多视角一致性检查、UV 接缝检查——并在方法选型时承认：DreamFusion 的便宜来自省略一致性建模，SJC、VSD、ISM 的昂贵来自补上这一课。调参顺序、检查清单与自测题，本质上都是在为这个结构性的取舍做账。
