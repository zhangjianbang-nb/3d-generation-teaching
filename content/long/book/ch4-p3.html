一 · 三平面的训练回路：2D 判别器如何把梯度送回 3D 特征图

EG3D 的训练回路是一个「生成器—解码器—判别器」三段结构，但三段之间的梯度路径并不对称。生成器是一个 StyleGAN2 主干，输出不是图像，而是三张 2D 特征平面 Fxy、Fxz、Fyz，每张形状为 C×H×W。给定相机位姿与一条射线，神经渲染器沿射线采样若干 3D 点，对每个点做三平面投影与双线性采样，拼接成特征向量，再过一个轻量 MLP 得到密度与颜色，最后按体渲染积分合成该像素。判别器只看合成出来的 2D 图像，它不知道三平面的存在。于是梯度必须穿过体渲染积分、穿过 MLP、穿过双线性采样，才落到三张特征图上。

这个回路的第一个机制性事实是：三平面本身没有任何 3D 卷积。3D 一致性不是靠 3D 算子强加的，而是靠「同一个 3D 点在不同视角下被投影到同一组平面坐标」这一几何约束隐式保证的。换句话说，三平面把 3D 归纳偏置外包给了投影几何，生成器主干仍然是纯 2D 卷积。这带来训练上的好处：StyleGAN2 的成熟技巧（风格混合、路径长度正则、EMA）可以原样搬过来；也带来训练上的隐患：如果相机分布采样不当，平面上的特征可以「记住」视角而不是记住形状。

$$\mathcal{L}=\mathbb{E}_{\mathbf{z},\theta}\left[\log D\big(\mathrm{Render}(\mathbf{f},\theta)\big)\right]+\mathbb{E}_{\mathbf{I},\theta}\left[\log\big(1-D(\mathbf{I})\big)\right]+\lambda\,\mathcal{L}_{\text{path}}$$

其中 Render 是体渲染算子，θ 是采样相机，Lpath 是 StyleGAN2 的路径长度正则。注意判别器条件于 θ：同一张 3D 资产在不同视角下渲染出的图像被当作同一类真样本，判别器必须学会区分「几何一致的多视角」与「几何穿帮的多视角」。这正是 EG3D 能收敛到合理几何的关键压力来源，也是它最脆弱的地方。

系统代价集中在显存与算力两端。三平面存储随分辨率平方增长：H=W=256、C=32 时单张平面约 2M 个浮点数，三张合计约 6M；若把分辨率推到 512，参数量翻四倍，2D 卷积的激活显存同样翻四倍。渲染端每条射线要采样数十到上百个点，每个点三次双线性采样加一次 MLP 前向，batch 内每条射线独立计算，显存峰值出现在「射线数 × 采样点数 × 特征维度」这个三维张量上。工程上常见的做法是降低每条射线的采样数、用分层采样把点集中到表面附近、或者把渲染分辨率与平面分辨率解耦。

失败模式有三类值得记住。第一类是「平面糊弄」：当平面分辨率不足，细小的把手、鞋带、眼镜腿会被抹平，渲染出的多视角图像仍然自洽，判别器无从察觉，因为判别器只看 2D 投影，投影会把细节缺失伪装成模糊。第二类是「视角记忆」：如果训练相机分布过窄（例如只在赤道附近采样），平面特征会把「正面好看」编码进去，一旦推理时换到俯视角，几何立刻崩塌。第三类是「密度—颜色纠缠」：体渲染积分对密度和颜色是对称可乘的，网络可以把不透明度藏进颜色里，导致提取等值面时表面位置漂移。具体例子：生成一把带细长壶嘴的茶壶，平面分辨率 256 时壶嘴常被渲染成一团半透明雾，多视角看都「像」，但一旦用 marching cubes 提取网格，壶嘴要么消失要么断裂——这就是 2D 判别器监督与 3D 几何之间的缝隙。

二 · 神经渲染解码的推理代价：每条射线都是一次三平面查询

推理阶段，EG3D 的代价结构与训练不同：训练时梯度要回传，推理时只要前向，但前向的绝对开销决定了它能否用于交互。渲染一张 512×512 图像需要约 26 万条射线，每条射线采样 N 个点，每个点做三次双线性采样（每次 4 个邻域值加权）加一次 MLP。若 N=64，单张图就是约 1700 万次三平面查询。这个量级在单卡上可以做到实时以下、交互以上，但离「拖动视角即出图」还有距离。

加速的机制主要有两条。第一条是「粗到细」：先用低分辨率平面或少量采样点估计大致深度，再把采样点集中到表面附近，把有效 N 从 64 降到 16 而不损失表面精度。第二条是「缓存平面查询」：同一帧内相邻像素的射线在 3D 空间里邻近，查询结果可以复用，但三平面投影坐标随射线方向变化，复用的粒度受限于平面分辨率。这两条都改变不了平方增长的底层成本：平面分辨率翻倍，单次查询的带宽需求翻倍，缓存命中率下降。

失败模式在推理端表现为「视角外推崩塌」与「分辨率错配」。视角外推崩塌的机制是：三平面在训练相机分布之外没有约束，投影坐标落在平面边缘或未训练区域，双线性采样退化为外插，特征值无意义，渲染出彩色噪声。分辨率错配的机制是：平面分辨率 H 与渲染分辨率 R 是两个独立旋钮，若 R 远大于 H，每个像素对应的平面采样间隔变大，高频细节被平均掉，表现为「近看糊、远看锐」的反常观感。具体例子：把训练好的 EG3D 模型渲染到 1024×1024，平面仍是 256，靠近相机的前景物体边缘会出现明显的块状模糊，而背景反而清晰——因为前景占据了更多像素但平面采样密度不变。

还有一个系统层面的代价常被忽略：三平面解码器与生成器是解耦的，但推理时必须成对部署。生成器输出平面，解码器消费平面，两者的显存占用叠加。若要把模型塞进边缘设备，压缩平面分辨率是最直接的手段，但压缩的代价直接落在细节上限上，这正是「平面分辨率决定细节上限」这条工程判断的来源。

三 · GET3D 的可微光栅化：把网格拓扑写死在生成器里

GET3D 换了一条监督路径：生成器直接输出带纹理的显式网格，用可微光栅化渲染成 2D 图像，再用 2D 判别器对抗训练。它不需要 3D 真值，也不需要神经渲染的体渲染积分。可微光栅化的机制是：把每个三角面投影到图像平面，计算覆盖的像素与重心坐标，按深度排序做 z-buffer，像素颜色由重心坐标插值顶点属性得到。整个过程对顶点位置、顶点颜色、纹理坐标都可微，梯度可以从像素颜色回传到网格顶点。

$$\mathbf{I}(p)=\sum_{t\in\mathcal{T}(p)}w_t(p)\,\mathbf{c}_t,\qquad w_t(p)=\text{barycentric weight of triangle }t\text{ at pixel }p$$

其中 T(p) 是覆盖像素 p 的三角面集合，wt 是重心坐标权重，ct 是该面的插值颜色。z-buffer 决定哪些面可见，可见性本身不可微，但实践中用软 z-buffer 或排序近似绕过。GET3D 的关键设计是「拓扑固定」：生成器输出的网格顶点数与面数是预先规定的，生成器只预测顶点位移与纹理，不预测拓扑。这让可微光栅化的实现变得简单，也让训练稳定，但代价是表达能力被拓扑锁死。

系统代价有两块。第一块是光栅化的分辨率与面数耦合：面数越多，光栅化越慢，显存里要存每个面的投影坐标与深度；面数太少，细节表达不了。第二块是纹理与几何的纠缠：可微光栅化对纹理坐标的梯度容易爆炸，尤其是当三角面在图像平面上退化成细长条时，重心坐标的数值条件变差，梯度出现尖峰。工程上常用拉普拉斯平滑或纹理坐标正则来压制。

失败模式最典型的是「拓扑不够用」。生成一把带镂空花纹的椅子，固定拓扑的网格无法表达镂空——镂空需要额外的边界环与面片，而生成器没有「加面」这个动作。网络只能把镂空渲染成纹理上的暗色图案，多视角看是「画上去的洞」，一旦提取网格或换光照就穿帮。第二个失败模式是「面片翻转」：顶点位移过大导致三角面法向翻转，光栅化时背面剔除或 z-buffer 出现撕裂，渲染图像上出现黑色裂缝，判别器会把这类样本判为假，但梯度信号是局部的，网络可能学会「避免翻转」而不是「学会正确几何」。具体例子：GET3D 生成一辆汽车，车轮与车身的连接处常出现面片穿插，因为固定拓扑不允许在连接处增加几何细节，网络只能用位移硬凑，凑不好就穿插。

四 · Point-E 的两段式扩散：点云容易学，但拓扑是下游的债

Point-E 走的是点云路线，训练被拆成两段：第一段文本条件扩散生成 1024 个点，第二段以这 1024 点为条件上采样到 4096 点。两段都是扩散模型，第一段学「整体形状的粗分布」，第二段学「在粗点云约束下补细节」。点云的优势在于表示简单：每个点就是三个坐标（加可选颜色），没有拓扑、没有面片、没有纹理坐标，扩散模型的输出维度是 3×N，训练信号直接、收敛快。

$$\mathbf{x}_{t-1}=\frac{1}{\sqrt{\alpha_t}}\left(\mathbf{x}_t-\frac{1-\alpha_t}{\sqrt{1-\bar{\alpha}_t}}\,\epsilon_\theta(\mathbf{x}_t,t,\mathbf{c})\right)+\sigma_t\mathbf{z}$$

这是标准扩散反步公式，εθ 是噪声预测网络，c 是文本条件。Point-E 的工程重点是「置换不变」：点云没有点的顺序，噪声预测网络必须对点的排列置换等变或不变，实践中用 Transformer 加位置无关的注意力，或者干脆把点云当集合处理。第二段上采样网络以粗点云为条件，输出细点云，两段之间没有联合训练，是串行的。

系统代价在于「没有拓扑」这件事本身不是免费的。点云渲染需要 splatting 或点云光栅化，点与点之间的空隙在多视角下会露出背景，近看是「筛子」。更重的代价在下游：要把点云变成可用的网格资产，必须做重建（泊松重建、球旋转）或重拓扑，这两步都是离线、耗时、且容易失败的。重建对噪声敏感，重拓扑对尖锐特征不友好。Point-E 的定位因此是「快速预览」：它能在几十秒内给出一个可看的 3D 形状，但不承诺可编辑、可动画、可重光照。

失败模式有两类。第一类是「点云稀疏导致的形状歧义」：1024 个点在复杂物体上分布不均，薄壁、细杆、镂空处点数不足，上采样网络只能猜，猜错就出现「粘连」或「断裂」。第二类是「两段式误差累积」：第一段生成的粗点云若有系统性偏差（例如整体偏胖），第二段会把这个偏差当成条件继承下来，无法纠正。具体例子：生成一把剪刀，1024 点阶段两个刀片常被生成成一团，上采样阶段即使想分开也无从下手，因为条件里没有「两个分离部件」的信息。

五 · Shap-E 的隐式函数权重生成：高维参数空间里的扩散

Shap-E 的选择最激进：不生成点、不生成平面、不生成网格，而是生成一个隐式函数的 MLP 权重。解码时，把权重加载进 MLP，查询任意 3D 坐标得到占用值与颜色，再用等值面提取得到网格。这条路线保留了连续表面与拓扑——因为隐式函数的零等值面天然是连续的，拓扑由函数本身决定，不受固定网格拓扑的限制。

机制上的核心难题是「权重维度」。一个能表达复杂形状的 MLP 动辄数十万到数百万参数，直接对这些参数做扩散，等于在一个极高维空间里做生成。Shap-E 的做法是先训练一个编码器把隐式函数压成低维潜码，再在潜码空间做扩散，解码时把潜码映射回 MLP 权重。这本质上是一个两阶段自编码器加扩散，训练难度集中在「潜码是否保留了足够的几何信息」上。

$$\theta_{\text{MLP}}=\mathrm{Dec}(\mathbf{z}),\qquad \mathbf{z}\sim p_\theta(\mathbf{z}\mid\mathbf{c}),\qquad \hat{o}(\mathbf{x})=\mathrm{MLP}_{\theta_{\text{MLP}}}(\mathbf{x})$$

其中 z 是潜码，Dec 是潜码到权重的解码器，o(x) 是查询点的占用值。训练代价是双重的：自编码器阶段要保证重建精度，扩散阶段要保证潜码分布可学。两个阶段的目标不完全一致——自编码器追求重建误差最小，扩散追求分布匹配——这个张力是 Shap-E 训练不稳定的根源之一。

系统代价在推理端体现为「查询成本」。生成一个资产要先跑扩散得到潜码，再解码成权重，再对网格提取所需的每个查询点做 MLP 前向。等值面提取要在三维网格上查询数十万到数百万个点，每个点一次 MLP 前向，成本远高于三平面的双线性采样。好处是查询分辨率可以任意调，坏处是调高分辨率线性增加成本。

失败模式有三类。第一类是「权重空间不平滑」：潜码的微小扰动可能导致 MLP 权重剧烈变化，生成结果的拓扑突变（例如从实心变空心），扩散模型在这样不平滑的空间里难以稳定采样。第二类是「表面漂移」：隐式函数的零等值面位置对权重敏感，训练时若占用值的监督信号有偏，提取出的表面会整体膨胀或收缩。第三类是「颜色—几何解耦失败」：颜色作为查询点的附加输出，与占用值共享同一个 MLP，网络可能把颜色信息编码进占用通道，导致提取出的网格颜色错位。具体例子：生成一个带把手的杯子，把手与杯身的连接处是薄壁结构，隐式函数在这个区域容易把两侧表面「焊死」，提取出的网格丢失把手与杯身之间的空隙——这是连续表示在薄结构上的经典失败。

六 · 四种表示的代价对照与工程判断

把四条路线的训练与推理代价放在一张表里，能看出它们各自的「成本落点」不同：EG3D 的成本落在平面分辨率的平方增长与神经渲染的逐射线查询；GET3D 的成本落在固定拓扑与可微光栅化的面数耦合；Point-E 的成本落在无拓扑导致的下游重建；Shap-E 的成本落在高维权重空间的训练难度与逐点 MLP 查询。

工程判断的第一条是：选表示等于选「失败模式」，而不是选「优点」。四种方法都能生成看起来像样的 2D 渲染，但它们的失败模式决定了它们能进入哪条下游管线。EG3D 的产物是神经渲染，适合做多视角展示与 2D 监督的数据增强，不适合直接进游戏引擎；GET3D 的产物是网格，适合进引擎，但拓扑固定意味着它只能生成「同一类拓扑」的资产；Point-E 的产物是点云，适合快速预览与点云下游任务，不适合需要 UV 与 PBR 的管线；Shap-E 的产物是隐式函数，适合需要连续表面与任意分辨率提取的场景，但训练与查询成本高。

第二条判断是：训练难度与表示的表达力之间存在交换。三平面把 3D 问题降成 2D 卷积，训练最成熟，但表达力受平面分辨率限制；隐式函数权重表达力最强（连续、任意拓扑），但训练最难。GET3D 与 Point-E 位于中间：前者用固定拓扑换训练稳定，后者用无拓扑换训练简单。这个交换关系解释了为什么原生 3D 生成在早期普遍选择「降维」或「简化表示」——不是不知道隐式函数好，而是训练不动。

第三条判断落在系统层面：推理成本的可预测性比绝对速度更重要。三平面的查询成本是「射线数 × 采样数 × 平面分辨率」的乘积，可预测、可预算；隐式函数的查询成本是「查询点数 × MLP 宽度 × 层数」，也可预测但常数更大；点云的成本最低但下游不可预测（重建可能失败）；可微光栅化的成本随面数线性增长但受拓扑约束。做系统设计时，先确定下游需要什么（网格？渲染？点云？），再倒推表示，最后按表示的失败模式设计兜底策略——例如三平面路线必须配一个「视角外推检测」，隐式函数路线必须配一个「薄结构检测」。

最后落到一个具体机制上：三平面的双线性采样在平面边界处的行为决定了整个系统的鲁棒性上限。采样坐标落在 [0,H-1] 之外时，双线性采样退化为钳制或外插，特征值不再有几何意义。工程上必须在渲染器里显式处理边界——要么把射线限制在平面覆盖的视锥内，要么在边界处衰减密度——否则视角外推时出现的不是「模糊」而是「彩色噪声」，而彩色噪声会被 2D 判别器误判为真样本的纹理变化，训练时不会触发任何惩罚。这个细节比任何宏观选型都更能决定一个原生 3D 生成系统在真实相机轨迹下的表现。
