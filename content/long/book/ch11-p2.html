一 · 从一张图到可进引擎的资产：数据流总览

把「一次前向」拆开看，它其实是一条从像素到引擎资源的流水线，而不是一个孤立的网络。给定一张单视图 RGB 输入，前馈模型先把它编码成结构化潜变量或三平面，再解码出几何与材质，随后做 UV 展开与 PBR 通道分解，最后导出成引擎可读的格式。这条链上任何一环出错，都会在下游被放大：几何歪一点，UV 就跟着拉伸；材质通道错一点，重光照就整片失真。因此理解这一卷的机制，必须把「数据」与「材质」当成同一条流水线上的两个耦合环节，而不是两门独立的课。

数据流的第一段是条件编码。输入图像经过视觉主干（ViT 或卷积）得到 token 序列，再与相机参数、可学习查询一起送入 Transformer 或扩散去噪器。第二段是几何解码：三平面被采样成密度场，或用 DMTet 之类的可微网格提取把隐式场转成三角面。第三段是材质解码：与几何共享同一潜空间，但输出 base color、metallic、roughness 三通道，并附带法线与 AO 等辅助贴图。第四段是 UV 展开：把刚生成的网格参数化到 2D 平面，让贴图有落点。第五段是打包导出：把网格、UV、PBR 贴图写成 glTF/USD 之类的容器，交给引擎。

这条流水线的系统代价在于「耦合失败」。几何与材质若分开训练，容易出现几何对了但 UV 接缝落在高曲率处，导致贴图撕裂；或者 UV 展开得漂亮，但材质是在另一套拓扑上烘的，通道对不上。SF3D 之所以强调 0.5 秒前向同时出 UV + PBR + delighting，正是把这几段压进同一个可微链路，让梯度能从最终渲染回传到几何与材质两侧。代价是显存与算力：同时持有三平面、网格提取中间量与多张 2K 贴图，单卡 batch 被迫压到很小，训练吞吐下降。工程上常见的折中是先粗几何后精材质的两阶段，但这会重新引入耦合误差。

一个具体例子：输入是一张金属水壶的正面照，背景干净。模型前向得到三平面，提取出约几万面的网格；UV 展开把壶身柱面摊平，接缝放在背面；材质解码给出 base color 偏灰、metallic 接近 1、roughness 偏低。若 delighting 把照片里的高光当成反照率烘进 base color，导出到引擎后换一个环境光，壶身会出现一块不该有的亮斑——这就是「烘死」的典型失败。数据流本身没断，但材质语义错了，资产不可重光照。

二 · 反照率与光照的分解公式

材质之所以能「重光照」，前提是把观测到的像素拆成反照率与光照两部分。最简的成像模型是乘性分解：观测像素等于反照率乘以入射光照。写成公式就是本卷导语给出的那一组：

$$\mathbf{c}_{\mathrm{base}}=\frac{\mathbf{I}}{\mathbf{E}_{\mathrm{light}}},\qquad \mathbf{I}=\mathbf{c}_{\mathrm{base}}\cdot\mathbf{E}_{\mathrm{light}}$$

这里 $\mathbf{I}$ 是图像像素，$\mathbf{c}_{\mathrm{base}}$ 是 base color（反照率），$\mathbf{E}_{\mathrm{light}}$ 是光照项。delighting 的任务就是估计 $\mathbf{E}_{\mathrm{light}}$ 并从 $\mathbf{I}$ 中除掉它。看似一次除法，实际是病态问题：单张图里光照与反照率的乘积只有一个观测，两个未知数无法唯一确定。工程上的做法是引入先验——假设光照是低频的、反照率是分段光滑的，或用多光照数据监督，让网络学会在暗部与高光处做合理猜测。

PBR 的三通道进一步把问题拆细。metallic 决定有多少光被镜面反射、多少进入次表面；roughness 决定镜面瓣的宽度。只给一张 RGB 贴图时，金属感与粗糙度被烘死在颜色里，引擎无法在换光照时重新计算反射。这就是为什么「有贴图」不等于「有材质」：前者是外观快照，后者是光学参数。公式上，完整的 BRDF 渲染要把 base color、metallic、roughness 一起代入微表面模型，才能在新光照下算出正确像素；缺一个通道，方程就退化成查表。

系统代价落在 delighting 的误差上。暗部信噪比低，除法会把噪声放大成彩色斑块；高光处若被误判为反照率，金属会被烘成塑料。SF3D 用前向一次性输出 delighting 结果，速度快但误差不可忽略；Hunyuan3D 2.1 把 PBR 做成生产级，靠的是更严的数据管线与多光照监督，代价是训练数据成本上升。失败模式很具体：一个白色陶瓷杯在强侧光下，暗面被 delighting 压成灰黑，导出后换柔光环境，杯身出现不自然的脏边。

具体例子可以走一遍数值直觉（不引用实验数字，只做量级说明）：若某像素观测为中等亮度，而光照估计偏高，则除法得到的反照率偏低，材质整体偏暗；反之光照估计偏低，反照率被抬高，金属会显得过亮。工程判断是：delighting 的输出必须带置信度或不确定性图，让下游知道哪些区域不可信，而不是把一张「看起来还行」的贴图直接塞进引擎。

三 · UV 展开：参数化与接缝的代价

UV 展开是把 3D 曲面映射到 2D 平面的过程，数学上是一个参数化映射 $\phi: \mathcal{S}\to\mathbb{R}^2$。理想情况下这个映射保角且保面积，但高斯曲率非零的曲面不可能无 distortion 地摊平，所以必然有接缝与拉伸。自动 UV 的常见做法是：先做网格分割，把曲面切成若干可展开的片，再用 LSCM 或 ABF 之类的保角方法逐片展开，最后把片排布到 2D 图集里，尽量提高纹理利用率。

伪代码思路可以写成：输入网格，计算每点的曲率与法线；按曲率与可见性做分割，把高曲率脊线作为切缝候选；对每片求解保角能量最小化，得到 2D 坐标；检测片间重叠与拉伸，迭代调整切缝；最后做图集打包，输出 UV 坐标与接缝标记。这条链的每一步都有代价：分割太碎则接缝多、贴图拼接痕迹重；分割太粗则单片的拉伸大，纹理在曲面上被拉长。

系统代价体现在「接缝处的梯度断裂」。贴图在接缝两侧不连续，渲染时若不做 seam-aware 的采样，会出现一像素宽的裂缝。更隐蔽的代价是生成模型与 UV 的耦合：前馈模型输出的网格拓扑是它自己决定的，UV 展开必须在这套拓扑上做，若拓扑本身有非流形边或退化面，展开算法会失败或产出扭曲图集。失败模式很具体：一个带细长把手的杯子，把手与杯身连接处曲率突变，自动切缝若落在把手内侧，展开后把手贴图被压成一条细带，纹理细节全丢。

具体例子：生成一个带浮雕纹样的花瓶，网格约几万面。自动 UV 把柱面摊成矩形，接缝放在背面；浮雕区域曲率高，被单独切成一片，展开后纹样被轻微拉伸。若不做拉伸校正，导出到引擎后从侧面看，纹样密度不均。工程判断是：UV 自动展开只能作为起点，生产管线必须留人工修接缝的环节；前馈模型若宣称「一次出 UV」，其价值在于把 80% 的工作自动化，而不是消灭最后 20% 的修整。

四 · PBR 三通道与重光照的机制

PBR 的核心是把材质描述成一组光学参数，让渲染方程在不同光照下都能求值。base color 是反照率，metallic 是金属度（0 为电介质，1 为金属），roughness 是微表面粗糙度。三者共同决定 BRDF：金属的镜面反射带颜色，电介质的镜面反射接近白，粗糙度控制高光瓣的宽窄。渲染时，环境光与直接光分别与 BRDF 卷积，得到最终像素。这就是「能重光照」的机制：像素不是烘死的，而是每次渲染重新算出来的。

公式上，微表面 BRDF 可写成镜面项与漫反射项之和，镜面项含法线分布函数、几何遮蔽与菲涅尔项，漫反射项由 base color 与金属度调制。工程实现里常把环境光预卷积成不同粗糙度级别的 mipmap，渲染时按 roughness 查表，这就是 split-sum 近似。代价是：roughness 若估计不准，高光会在错误的 mip 级别上采样，金属看起来像蒙了一层雾。

系统代价还有「通道间的物理一致性」。base color、metallic、roughness 不是独立的：金属的 base color 应是反射色而非漫反射色，若网络把金属的暗部当成漫反射烘进 base color，metallic 又给了 1，渲染时会出现「黑金属」——既不反射也不漫反射。失败模式很具体：一把不锈钢勺，delighting 把环境反射误当反照率，base color 里混入高对比条纹，metallic 设为 1，换一个纯色环境后勺面出现鬼影般的条纹。

具体例子走通一遍：输入单图，模型输出网格与三通道贴图。把资产导入引擎，设一盏方向光加一张环境贴图。若 roughness 偏低，高光变成一个小亮点，金属感强但显得假；若 roughness 偏高，高光散开，金属像磨砂塑料。调参的过程就是验证材质语义是否正确的过程。工程判断是：PBR 资产验收不能只看渲染图，要在至少两种光照下对比，看反射是否随环境变化而合理变化——这是「可重光照」的操作性定义。

五 · 数据侧：Objaverse 与 Objaverse-XL 如何喂进这条流水线

前馈模型的上限由数据决定。Objaverse 约 80 万带标注物体，Objaverse-XL 把规模推到 1000 万+，它们让 LRM、TRELLIS、Hunyuan3D 的「一次前向」成为可能。但规模不等于信号：3D 数据没有 2D 那样的互联网级语料，采集难、格式杂、许可乱、标注贵。堆量不涨点，因为重复、低质、长尾与评测泄漏都会稀释信号。这条流水线的训练数据必须经过清洗才能用。

清洗的三个具体机制对应工匠笔记：去重（几何/纹理哈希）、许可过滤（商用白名单）、质量分级（面数/纹理/水密性）。去重不能只做文件哈希，要做几何哈希与纹理哈希，因为同一资产常被转格式后重复上传；许可过滤要把非商用许可的资产挡在训练集外，否则产品化时无法交付；质量分级要把破面、缺贴图、非水密的资产降级，避免它们污染几何与 UV 的学习信号。代价是清洗本身消耗人力与算力，且分级标准一旦定错，会把长尾资产误杀。

失败模式很具体：训练集里混入大量重复的同一把椅子，模型会过拟合成「椅子先验」，生成新椅子时几何趋同；若评测集里也有同一来源的资产，指标虚高，掩盖了长尾失败。工程判断是：数据管线要记录每个资产的来源、许可、质量分级与哈希，训练时按分级采样，评测时按来源划分，杜绝泄漏。

具体例子：一个带复杂雕花的木箱，纹理哈希与几何哈希都独特，许可为商用，面数与水密性达标，进入高质量分级。它在训练中提供的是「雕花细节 + UV 接缝处理」的信号。若它被重复上传十次而未去重，采样权重被放大十倍，模型对雕花过拟合，生成素面木箱时也硬加纹样。这就是「堆量不涨点」的微观机制。

六 · 评测侧：从 PSNR/SSIM 到引擎导入通过率

这条流水线的验收不能停在图像指标。PSNR/SSIM 衡量的是渲染图与参考图的像素差异，但它们与「资产能否进引擎」脱节：一张 PSNR 很高的图，可能对应一个 UV 接缝错位、PBR 通道矛盾的网格。评测要跟着变，走向新视角几何误差、引擎导入通过率、人工盲评。新视角几何误差检验的是几何在多视角下是否一致；导入通过率检验的是格式、UV、材质通道是否满足引擎的硬性要求；盲评检验的是人眼对材质真实感的判断。

具体机制上，引擎导入通过率可以做成自动检查清单：网格是否流形、UV 是否在 0–1 范围内且无重叠、PBR 三通道是否齐全且数值范围合法、贴图分辨率是否达标、文件是否能被目标引擎无警告加载。每项检查失败都记一个具体原因，而不是一个总分。代价是检查清单需要随引擎版本维护，且不同引擎的严格程度不同，跨引擎的通过率不可直接比较。

失败模式很具体：一个模型在 PSNR 上表现很好，但导出时 UV 图集有重叠，引擎加载后贴图随机闪烁；或者 metallic 通道被写成 0–255 的整数而未归一化，引擎把它当全金属，渲染全黑。这些失败在图像指标里看不出来，只有在导入检查里才暴露。工程判断是：评测管线要把「可用性」作为一等指标，与图像指标并列，而不是事后补测。

具体例子：同一批生成资产，图像指标排序与导入通过率排序不一致。排在前面的资产里，有一部分因 UV 重叠被引擎拒绝；排在后面的资产里，有一部分几何粗糙但 UV 干净、PBR 齐全，导入后在新光照下表现稳定。这说明图像指标奖励的是「像」，而引擎要的是「对」。这一卷的评测转向，本质是把「对」的判据从像素搬到资产契约上。
