一 · 证据链的入口：从“数据集规模”到“可用资产率”

讨论 Objaverse 与 Objaverse-XL 时，最容易犯的错误是把“物体数”直接当作“训练信号量”。给定事实里 Objaverse 约 80 万带标注物体，Objaverse-XL 把规模推到 1000 万+，这两个数字描述的是抓取与登记层面的规模，不是清洗后进入训练循环的有效样本数。真正决定前馈模型上限的，是一条逐级衰减的漏斗：原始条目 → 可解析几何 → 许可可用 → 质量达标 → 与评测集不泄漏 → 进入训练。每一级都会砍掉一批，且砍掉的往往不是随机分布，而是集中在长尾类别与低资源格式上。工程上必须把这条漏斗显式建模，否则“堆量不涨点”会被误读成模型容量问题，实际是信号被稀释。

具体机制上，清洗管线通常并行做三路哈希：几何哈希（对归一化后的顶点/面索引做稳健摘要）、纹理哈希（对反照率图做感知哈希）、以及结构哈希（面数、水密性、连通分量数的组合键）。三路哈希取并集做近重复判定，比单一几何哈希更能抓住“同模型不同导出格式”这类常见重复。伪代码思路是：对每个资产先做尺度归一化与坐标系对齐，再计算三路键，落入桶后仅保留质量分最高者。质量分由面数区间、纹理分辨率、是否水密、是否有退化三角面共同决定，是一个分段打分而非连续回归，便于审计。

系统代价在于：哈希与解析是 I/O 密集且可并行的，但质量分级里的水密性检测需要拓扑遍历，单资产成本远高于哈希。对 1000 万+ 量级，全量做水密性检测在工程上不可行，通常采用分层抽样加外推，这就引入了分级偏差——被抽中的往往是格式规整的资产，长尾格式被系统性低估。失败模式是：清洗后训练集在类别分布上比原始集更陡，模型在常见家具、车辆上表现稳定，在罕见器物上退化，而评测若只用常见类别，就看不出这个退化。

具体例子：一个从多个来源抓来的“椅子”类别，可能同时存在扫描网格（高面数、带噪声）、CAD 导出（低面数、水密）、以及游戏资产（带 UV、带 PBR）。三者在几何哈希上不同，但在语义上高度重复。若不做语义级去重，模型会在椅子上过拟合，挤占长尾类别的梯度预算。工程判断是：去重必须同时做几何级与语义级，语义级可用渲染多视图的嵌入距离近似，代价是多一次前向渲染。

二 · 许可过滤与“商用白名单”的硬约束

许可问题是 3D 数据区别于 2D 互联网语料的核心难点。2D 语料可以通过大规模抓取加事后下架处理，3D 资产的许可条款更分散：有的禁止商用，有的要求署名，有的对衍生模型有传染性条款。给定事实明确把“许可乱”列为瓶颈，并把“许可过滤（商用白名单）”列为清洗三件事之一。这意味着管线里必须有一个显式的许可标签字段，而不是靠人工记忆或事后补救。

机制上，许可过滤不是简单的布尔过滤，而是把许可类型映射到使用场景矩阵：训练可用、商用分发可用、可再分发衍生。白名单策略是只允许明确落入“训练可用且商用分发可用”的资产进入生产训练集，其余进入研究池或直接丢弃。这个矩阵要随资产元数据一起落库，因为同一资产在不同版本间许可可能变化，重新抓取时必须重新判定。伪代码思路：许可解析器读取元数据中的许可标识，归一化到内部枚举，查矩阵得到三个布尔位，任一关键位为假则打上排除标记并记录原因码，便于后续审计与申诉。

系统代价是：许可元数据本身经常缺失或格式不一，解析器需要大量规则与人工兜底，这部分成本不随规模摊薄，反而随来源增多而线性上升。失败模式有两种：一是过度保守，把大量实际可用的资产排除，导致训练集在风格上偏窄；二是过滤不彻底，把受限资产混入生产集，带来法律风险，且这种风险在模型权重里不可追溯。工程判断是：宁可保守，但要把排除原因码统计出来，定期复核规则，避免规则腐化。

具体例子：某批资产元数据只写了来源站点而未写许可，解析器无法判定，落入“未知”桶。若直接丢弃，可能损失一整类风格；若放行，则风险不可控。可行做法是把“未知”桶单独训练一个小规模对照模型，观察其风格贡献是否显著，再决定是否投入人工复核。这是用实验换确定性，而不是用猜测换规模。

三 · PBR 三通道与 delighting 的误差结构

材质瓶颈的根源在于：只给一张 RGB 贴图，金属度与粗糙度被烘死在颜色里，资产无法在不同光照下正确反射。给定事实指出 PBR 需要 base color、metallic、roughness 三通道才能重光照，并给出逆渲染的基本关系：观测图像等于 base color 乘以光照，因此 base color 可由图像除以光照估计得到。这个公式看似简单，但它假设光照已知且无遮挡、无间接光，真实扫描图里暗部与高光恰恰违反这个假设。

$$\mathbf{c}_{\mathrm{base}}=\frac{\mathbf{I}}{\mathbf{E}_{\mathrm{light}}},\qquad \mathbf{I}=\mathbf{c}_{\mathrm{base}}\cdot\mathbf{E}_{\mathrm{light}}$$

delighting 的误差结构可以分三层看。第一层是光照估计误差：若把环境光近似为常数或低频球谐，方向性强光会被错误摊平，导致 base color 在受光面偏暗。第二层是饱和截断：高光处像素值接近上限，除法无法恢复真实反照率，金属高光尤其严重，因为金属的反照率本身就接近光源颜色。第三层是暗部噪声放大：暗部像素信噪比低，除以较小的光照估计会放大噪声，形成彩色斑块。这三层误差在给定事实里被概括为“暗部/高光处容易失真”，工程上要分别处理，不能指望一个网络端到端抹平。

具体机制上，SF3D 用 0.5 秒前向出 UV + PBR + delighting，这个时间预算意味着 delighting 必须是轻量前向，不能做多轮优化。轻量前向的代价是无法对每个资产做个性化光照求解，只能依赖训练分布里的光照先验。失败模式是：训练集里以棚拍均匀光为主，遇到户外强方向光扫描的资产，delighting 会把阴影烘进 base color，重光照时阴影跟着资产走，出现“自带脏影”的伪影。Hunyuan3D 2.1 把 PBR 做成生产级，说明工程上已经能把这条链路跑通，但“生产级”不等于“无误差”，而是误差被控制在可接受范围并有兜底流程。

具体例子：一个金属杯的扫描图，高光处像素饱和，delighting 后 base color 在高光区被压成灰色，metallic 通道若被预测为高值，重光照时该区域会反射出错误颜色。工程兜底是：对高光饱和区域做掩码，降低该区域在材质监督中的权重，并允许人工在 DCC 工具里修补。这就是为什么 UV 自动展开之后仍需要人工修，接缝与拉伸之外，材质修补是另一类人工介入点。

四 · UV 展开的接缝代价与“快速 UV + 人工修”

UV 自动展开的失败模式集中在接缝与拉伸。接缝是参数化必须切开的地方，切开就会在纹理上产生不连续；拉伸是面积畸变，导致纹素密度不均，细节在拉伸区被模糊。给定事实把“接缝/拉伸”列为 UV 的瓶颈，方向是“快速 UV + 人工修”。这意味着自动展开的目标不是完美，而是把人工修的成本压到可接受。

机制上，快速 UV 通常走分块参数化加打包：先把网格按曲率或法线聚类切成若干块，每块做保角或保面积的参数化，再把块打包进一张图集。保角优先保证角度不失真，保面积优先保证纹素均匀，两者不可兼得，工程上按资产类型选权重。伪代码思路：聚类 → 每块参数化 → 计算每块的拉伸能量 → 若超过阈值则重新切分 → 打包 → 检测接缝两侧的法线与颜色连续性 → 输出接缝掩码供人工复核。接缝掩码是关键，它把“哪里需要修”显式化，而不是让人工全图扫一遍。

系统代价是：分块越多，接缝越多，打包效率越低，图集利用率下降。图集利用率下降直接浪费纹理分辨率，对移动端资产是硬成本。失败模式是：自动切分把语义上连续的区域切开，比如把一张脸的左右脸颊分到不同块，接缝落在视觉敏感区，人工修的成本陡增。工程判断是：切分要引入语义先验，至少避免在平面度高的区域切，因为平面区域的接缝最容易暴露。

具体例子：一个带雕花的木箱，自动展开把雕花区切成多块，接缝穿过花纹，纹理对不齐。人工修的做法是在 DCC 里把接缝移到箱子棱边，棱边本身是几何不连续处，接缝被几何掩盖。这说明 UV 质量不只是算法问题，还是与几何布局协同的问题，自动管线应输出接缝建议位置而非最终位置。

五 · 评测的迁移：从 PSNR/SSIM 到可用性指标

给定事实指出评测现状以 PSNR/SSIM 为主，但与可用性脱节，方向是下游任务与盲评。PSNR/SSIM 衡量的是渲染图像与参考图像的像素级接近，它无法反映几何是否水密、UV 是否可导入引擎、PBR 是否可重光照。一个 PSNR 很高的资产可能在引擎里导入失败，因为法线朝向错误或材质通道缺失。评测必须跟着产品链路走。

具体机制上，新视角几何误差衡量的是从训练视角之外渲染时，深度或法线与真值的偏差，它比像素误差更能抓住几何漂浮与背面塌陷。引擎导入通过率是一个布尔指标：资产能否在目标引擎里完成导入、材质绑定、光照渲染而不报错，这是最接近产品验收的指标。人工盲评则是把生成资产与参考资产混排，让评审在不知道来源的情况下打分，用于捕捉风格与可用性的主观维度。三者组合，形成“几何—工程—感知”的三层证据。

系统代价是：引擎导入通过率需要真实引擎环境跑批，成本远高于离线渲染指标；人工盲评更贵，且评审一致性需要校准。失败模式是：只用 PSNR/SSIM 做模型选择，会选出像素漂亮但几何破碎的模型，因为像素指标对几何错误不敏感，尤其在纹理丰富的资产上，错误几何被纹理掩盖。工程判断是：评测集必须包含“难例”，即那些像素指标容易高分但工程指标容易失败的资产，比如薄壁、透明、金属高光物体。

具体例子：一个薄壁花瓶，PSNR 很高，但壁厚在网格提取时被压成零，引擎导入后法线翻转，渲染出黑面。新视角几何误差会暴露壁厚偏差，导入通过率会直接失败。这说明评测指标的选择本身就是在定义“什么是好资产”，选错指标等于选错优化目标。

六 · 反例的用法：把失败案例变成管线约束

失败案例的价值不在于证明某方法不行，而在于把失败模式转成管线里的硬约束。给定事实里的失败模式可以归成四类：重复稀释信号、低质拉低上限、长尾被淹没、评测泄漏虚高。每一类都对应一个可执行的检查项，而不是一句定性描述。

重复稀释对应去重检查：训练前统计近重复簇的规模分布，若某簇占比过高，则降采样。低质对应质量分级门槛：面数过低、纹理分辨率过低、非水密的资产进入低质池，不进入主训练集。长尾被淹没对应类别配额：按类别频次做重采样或损失加权，保证长尾类别有最小梯度预算。评测泄漏对应泄漏检测：用几何与纹理哈希比对训练集与评测集，命中即从训练集剔除。这四项检查都是可自动化的，且成本远低于训练本身。

系统代价是：配额与加权会改变训练分布，可能牺牲常见类别的精度换取长尾召回，这是一个显式的取舍，必须在产品需求层面确认。失败模式是：泄漏检测只做几何哈希，漏掉“同模型重贴图”的变体，导致评测虚高；这类变体在纹理哈希上不同，但几何相同，必须双哈希联合判定。工程判断是：泄漏检测要在每次评测前跑，而不是一次性跑完就固化，因为训练集在持续扩充。

具体例子：某长尾类别“乐器”在原始集里条目不少，但清洗后因格式杂乱大量落入低质池，主训练集里几乎消失。若不设类别配额，模型在该类别上生成结果坍缩成通用块状物。配额机制强制保留一定比例的低质但语义正确的样本，用较低权重参与训练，换取语义覆盖。这是用质量换覆盖的工程取舍，而不是追求单一指标最优。

最终落在机制上：数据与材质的证据链不是一条直线，而是一组互相牵制的约束——去重压规模、许可压范围、质量压上限、配额保长尾、泄漏检测保评测可信。任何一项放松，都会在另一项上以失败模式的形式回弹。工程判断是：先把这组约束跑通并量化，再谈扩规模；否则规模只是把噪声放大。
