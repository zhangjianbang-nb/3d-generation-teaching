一 · 从「一张图」到「一套潜变量」：编码器把 3D 压进可扩散的空间

前馈工厂的第一道工序不是扩散，而是编码。Direct3D 的路线是把高分辨率 3D 资产先送进一个 3D VAE，压成低维潜变量，再在这个潜空间里跑 DiT 扩散。这一步的工程含义常被低估：扩散模型并不直接生成三角面或体素，它生成的是一个张量；这个张量的形状、通道语义、空间分辨率，决定了后面所有解码器能做什么、不能做什么。换句话说，潜变量不是「压缩文件」，而是「接口契约」——它规定了生成器承诺交付什么，解码器承诺还原什么。

形式化地，编码器 $E$ 把资产 $x$ 映射为潜变量 $z=E(x)$，解码器 $D$ 负责 $D(z)\approx x$。扩散在 $z$ 上定义前向加噪 $z_t=\alpha_t z+\sigma_t\epsilon$，网络学习预测噪声或得分，采样时从纯噪声迭代回 $z_0$。训练目标是重建项与扩散项的组合，重建项约束 VAE 不丢信息，扩散项约束潜空间分布可被高斯先验覆盖：

$$\mathcal{L}=\mathcal{L}_{\mathrm{rec}}\big(x,D(E(x))\big)+\lambda\,\mathbb{E}_{t,\epsilon}\big\|\epsilon-\epsilon_\theta(z_t,t,c)\big\|^2$$

这里的 $c$ 是条件（图像、文本或两者），$\lambda$ 平衡两项。机制上，VAE 的重建上限就是整条管线的天花板：如果 VAE 在编码时把细小的倒角、薄片、镂空压没了，DiT 再强也采样不回来。这是 Direct3D 路线最典型的失败模式——潜空间规模化换来了生成速度与分辨率，但代价是重建误差被固化进接口。工程上判断一个 3D VAE 是否够用，不看它的生成样例好不好看，而看它在极限细节上的重建残差：把同一资产编码再解码，量一下表面偏差与纹理漂移。

具体例子：给定一个带细密栅格的金属罩，VAE 的空间下采样会把栅格条压成一片模糊的灰色块。DiT 在这个潜空间里学到的「栅格」概念本身就是模糊的，采样出来的资产在引擎里近看是一层糊。这不是扩散的错，是编码器在契约里就没承诺保留这个频段。解决办法要么提高潜空间分辨率，要么换结构化表示——这正是下一节 SLAT 要处理的问题。

二 · SLAT：稀疏体素加局部三平面，一套潜变量多路解码

TRELLIS 的核心表示 SLAT（Structured LATent）把「结构化」落在两件事上：稀疏体素决定哪里有事，局部三平面决定每个有事的地方长什么样。稀疏体素是一组被激活的体素坐标，只有表面附近的体素被保留，空区域不占算力；每个激活体素携带一个局部三平面特征，三个正交的 2D 特征图在这个体素的小邻域内插值出连续场。这样，潜变量既不是稠密的三平面网格（浪费在空处），也不是纯点云（缺乏局部连续性），而是「稀疏骨架 + 局部连续特征」。

数据流可以写成伪代码思路：输入图像经图像编码器得到条件特征；一个稀疏体素 Transformer 在激活体素之间做注意力，预测每个体素的局部三平面；解码时按需选择解码器——解成高斯用于实时渲染，解成网格用于引擎资产，解成辐射场用于新视角合成。同一套潜变量，三种出口，这是 SLAT 相对三平面表示的关键差别：三平面必须先解码成某种显式表示才能用，SLAT 把「解码选择」推迟到消费端。

  • 稀疏体素注意力：只在激活体素间计算，复杂度随表面面积而非包围盒体积增长。
  • 局部三平面：每个体素三个小特征图，插值得到该体素内的连续特征，避免体素间的块状断裂。
  • 多解码器：高斯头、网格头、辐射场头共享同一潜变量，各自承担不同的误差。

系统代价在于解码误差不再统一。高斯解码器光栅化快，但高斯是显式基元，薄面与锐边需要大量扁高斯才能表达，内存与排序开销上升；网格解码器要做等值面提取或可微网格提取，拓扑质量受潜变量分辨率限制；辐射场解码器渲染慢，但视角一致性好。三者对同一潜变量的「理解」不同，工程上必须选一个主出口，其余作为辅助。失败模式很具体：当潜变量的体素分辨率不足以分辨两个相邻薄片时，高斯解码会把它们糊成一个厚壳，网格解码会把它们焊成一块，辐射场解码则给出半透明的鬼影。分辨率与解码误差是 SLAT 路线绕不开的权衡。

具体例子：一个带镂空花纹的灯罩，稀疏体素在花纹边缘激活得较密，但在花纹内部空隙处不激活。若体素尺寸大于花纹缝隙宽度，缝隙在潜变量里就不存在，三种解码器都还原不出透光效果。此时提高体素分辨率能救，但注意力成本与显存随之上升；另一个办法是在局部三平面里编码更高频的特征，让插值在体素内部恢复缝隙——这要求训练时重建损失对高频足够敏感。

三 · 双 DiT 与三通道 PBR：形状与材质为什么要拆开

Hunyuan3D 2.0 把形状与纹理拆成两个 DiT：形状 DiT 生成几何潜变量，纹理 DiT 在给定几何的条件下生成纹理潜变量。2.1 进一步把材质做成 PBR 三通道，即 base color、metallic、roughness。拆开的理由不是美学，而是条件依赖的方向性：几何决定了纹理该往哪里贴、哪里该有接缝、哪里该有环境光遮蔽；反过来纹理不该改变几何。若用一个 DiT 同时出几何与材质，网络要在同一组参数里纠缠两种统计特性，训练信号互相干扰，且材质通道的数值范围与几何潜变量的分布差异很大。

PBR 的接口定义在卷导语里已经给出：

$$\mathcal{M}=\{\mathbf{c}_{\mathrm{base}},\ m,\ r\},\qquad \mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I})$$

$\mathrm{Delight}$ 把输入图里的光照去掉，留下反照率。这一步是生产化的分水岭：只在一套光照下「好看」的资产，通常是把光照烘进了 base color，换一套光照就露馅。三通道的物理含义决定了它们必须可重光照：metallic 决定镜面反射的颜色是否被 base color 染色，roughness 决定高光宽度，base color 在金属处应接近反射色、在电介质处才是漫反射色。任何一条通道错了，引擎里的材质就「不像」。

双 DiT 的数据流：形状 DiT 从条件（图像或文本）采样出几何潜变量，解码成网格或隐式场；纹理 DiT 以几何的法线、位置、可见性作为条件，采样出三通道材质潜变量，解码成 UV 空间的贴图。两阶段的误差会叠加：几何若有微小凹凸错位，纹理的接缝与 AO 就贴不齐；纹理若在不可见区域瞎猜，背面与底部的材质就会与正面矛盾。这是双 DiT 的典型失败模式——两阶段各自合理，拼起来在接缝处崩。

具体例子：一把带磨损边缘的金属扳手。形状 DiT 出几何，纹理 DiT 出 base color（磨损处偏灰）、metallic（磨损处接近 0，露出底层电介质）、roughness（磨损处偏高）。若 delighting 没做干净，输入图里的高光被烘进 base color，那么在引擎里换冷光后，磨损处会带着暖光下的高光颜色，金属感立刻假掉。验收方法就是工匠笔记里那一条：换三套光照（暖光、冷光、逆光），看金属是否像金属、粗糙度是否合理、暗部是否带阴影。

四 · 走通一个例子：从单图到引擎可用资产的全链路

取一个具体对象：一张正面拍摄的旧铜壶，带锤纹、局部氧化、壶嘴有高光。目标是产出一个能进引擎、能换光照、UV 不拉伸的资产。按本卷的接口逻辑，链路分四段，每段都有明确的输入输出契约与失败点。

第一段，几何。用形状 DiT（或 SLAT 的几何出口）从单图采样几何潜变量，解码成网格。此时要检查的是拓扑：壶嘴与壶身的连接处是否焊死、锤纹是否被平滑掉、壶底是否封闭。失败模式是「好看但不可用」——渲染图漂亮，但网格是非流形的，进引擎后法线计算与碰撞体生成都会出问题。工程判断是看网格的欧拉特征与边界边数量，而不是看渲染图。

第二段，UV 展开。SF3D 路线强调快速 UV 加 PBR 加 delighting，UV 展开决定纹理分辨率与接缝位置。壶是近似旋转体，柱面展开能把接缝藏在背面；但壶嘴是分支结构，展开时容易在分支处拉伸。失败模式是接缝处的纹理错位与拉伸条纹。工程上要检查的是 UV 岛的利用率与拉伸度量，而不是贴图看起来是否花哨。

第三段，材质。纹理 DiT 在 UV 空间出三通道。锤纹处 roughness 应有起伏，氧化处 metallic 应下降、base color 偏暗绿，壶嘴高光处若 delighting 干净，base color 不应带高光。失败模式是材质歧义：网络把阴影当成氧化、把高光当成浅色漆。这里没有实验数字可引，只能定性判断——换光照后阴影不该跟着 base color 走。

第四段，验收。把资产导入引擎，配三套光照。暖光下铜的 base color 应偏暖但 metallic 处反射的是环境色；冷光下金属应反射冷色而不是被 base color 染成暖色；逆光下暗部应带环境光遮蔽的阴影而不是死黑。任何一套光照下「不像铜」，就回到第三段查通道语义。这条链路的每一段都对应本卷某个模型的一小块能力，真正的管线要把它们串起来，而串起来的粘合剂就是接口契约：潜变量形状、UV 布局、通道语义、单位与朝向。

五 · 接口错了，资产就进不了引擎：系统代价与工程判断

把上面四段抽象成工程判断，核心是一句话：生成模型的输出不是「模型」，是「待验收的接口」。三平面要解码，高斯要光栅化，SLAT 要多解码器，网格要 UV 与 PBR。任何一个接口错了，资产就进不了引擎。系统代价分布在三处：解码误差（潜变量到显式表示的损失）、阶段误差（双 DiT 两阶段的叠加）、消费端误差（UV 接缝、通道语义、单位朝向）。这三处误差不会互相抵消，只会叠加。

具体到可操作的检查项，可以列成一张验收表：

检查项对应接口失败表现判断依据
网格流形性几何解码法线断裂、碰撞体生成失败边界边、非流形边计数
UV 拉伸UV 展开接缝错位、条纹拉伸UV 岛利用率、拉伸度量
通道语义PBR 三通道换光照后金属变塑料三套光照下的反射一致性
delighting 残留base color阴影跟着反照率走逆光下暗部是否死黑
朝向与单位资产导出进引擎后倒置或比例错包围盒与坐标轴对齐

这张表的价值在于把「好看」翻译成「可验收」。一个只在一套光照下好看的资产，通常是把光照烘进了 base color；一个渲染图漂亮但网格非流形的资产，进引擎就崩。工程判断的顺序应该是先接口后观感：接口不过，观感没有意义。

最后落到一个具体机制上：delighting 不是后处理滤镜，它是 base color 通道的定义的一部分。若把 $\mathrm{Delight}$ 当成可选项，三通道 PBR 就退化成「带高光的贴图」，重光照能力随之消失。因此在这条管线里，delighting 的误差预算必须与几何重建误差分开计量——前者污染的是材质语义，后者污染的是形状，两者在引擎里表现为不同的故障，不能用同一个「像不像」的主观标准去验收。
