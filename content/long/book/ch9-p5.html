一 · 序列化与解码的代码骨架

把网格当成语言来写，第一步不是建模，而是定义「词」和「句法」。MeshGPT 的路线是：对每个三角面做图卷积编码，得到面片级特征，再经 VQ 量化到一个离散词表，于是整张网格变成一条 token 序列；decoder-only Transformer 在这条序列上做自回归，逐 token 预测下一个面片。工程上这条链路要拆成三段可独立测试的代码：编码器（面片图 → 特征）、量化器（特征 → 词表索引）、解码器（索引序列 → 面片集合）。三段之间用固定的张量契约连接，任何一段改动都不该让另外两段重新调参。

编码器的输入不是顶点坐标的裸列表，而是面片邻接图。每个面片是一个节点，共享边的面片之间连边，节点特征通常取面片的顶点坐标、法向、面积、边长比。图卷积在这里的作用是把「这个面片长什么样」和「它周围的面片长什么样」混在一起，因为拓扑的局部规律（边流、面片密度）本质上是邻域性质，单看一个面片无法判断它是否处在一条好的边流上。

$$ \mathbf{z}_f = \mathrm{GCN}(\mathbf{X}, \mathbf{A})_f,\quad \mathbf{q}_f = \arg\min_{k}\ \|\mathbf{z}_f - \mathbf{e}_k\|_2,\quad \mathbf{t} = (\mathbf{q}_1,\dots,\mathbf{q}_N) $$

量化这一步是整条链路最容易被低估的地方。VQ 词表的大小决定了表达上限：词表太小，不同拓扑位置的面片被压到同一个 token，解码器无法区分「该在这里收边」还是「该继续铺面」；词表太大，码本利用率下降，大量 token 在训练中几乎不被选中，等于浪费了序列长度。工程判断是：先统计训练集上面片特征的分布，看需要多少个聚类中心才能把重构误差压到可接受范围，再定词表尺寸，而不是拍一个整数。

解码器是标准的自回归 Transformer，但输出头不是词表上的 softmax 就完事。每个 token 对应一个面片，而面片的顶点坐标是连续的，所以输出头要同时给出「选哪个词」和「这个词对应的顶点偏移」。实践中更稳的做法是把顶点坐标也离散化，让每个 token 携带完整的顶点三元组，解码时直接查表还原，避免连续回归带来的漂移。代价是序列变长：一个面片一个 token，N 个面片就是 N 步自回归，步数与面数线性相关。

失败模式在这里非常具体：自回归解码没有全局约束，生成到后半段时，已写出的面片可能已经围出了一个闭合区域，而模型还在往里塞面片，结果是非流形边和自交。另一个失败是「序列断裂」——某个 token 预测出的顶点索引指向了尚未出现的顶点，解码器只能回退或丢弃该面片，导致网格出现孔洞。系统代价是解码时间随面数线性增长，且无法并行，一张八百面的网格在单卡上逐 token 生成，延迟是秒级的，这对交互式资产管线是硬约束。

具体例子：给定一个椅子形状，编码器把椅面、椅腿、靠背的面片分别编码，VQ 把它们归入不同的词。解码器先写出椅面的大片三角，再写椅腿的细长面片，最后写靠背。如果训练集里椅腿总是出现在椅面之后，模型会学到这个顺序；一旦遇到椅腿从椅面中间穿出的设计，顺序假设失效，生成的面片就会和已有面片冲突。这说明序列化本身就编码了一种「面片出现的先后偏好」，它不是中立的表示。

二 · 相邻 token 化与序列压缩的调参

MeshAnything V2 的相邻网格 tokenization（AMT）解决的是序列长度问题。朴素方案里每个面片独立写三个顶点，相邻面片共享的边被重复编码，序列里大量冗余。AMT 的做法是让相邻面片共享边、只写新顶点：当新面片与已写出的面片共享一条边时，token 只需给出第三个顶点，另外两个顶点从邻接关系里继承。这样序列长度从「每面三顶点」降到「每面一顶点加上少量共享信息」，在同等上下文窗口下能覆盖更多面数，公开描述里支持到约 1600 面。

$$ L_{\text{naive}} \approx 3N,\quad L_{\text{AMT}} \approx N + c\cdot N_{\text{shared}},\quad c<1 $$

调参的核心是「共享判定」的阈值。两个面片是否算共享边，不能只靠坐标完全相等——浮点误差会让本应共享的边被判为不共享，于是 token 退化成独立写顶点，压缩率归零。工程上要先把输入网格做顶点焊接（按距离阈值合并重复顶点），再建立边到面片的映射表，解码时用这张表判断新面片能否继承已有顶点。焊接阈值太小，共享边漏判；太大，不同部位的顶点被错误合并，生成出拓扑粘连。这个阈值必须和输入网格的尺度绑定，按包围盒对角线的一个比例来设，而不是固定绝对值。

另一个调参点是「新顶点」的编码方式。AMT 里新顶点仍然需要坐标，如果坐标是连续回归，误差会沿着序列累积：第一个新顶点偏了一点，后续所有继承它的面片都跟着偏。更稳的做法是把新顶点坐标也放进离散码本，按空间分辨率分桶，解码时查桶中心。桶太粗，网格表面出现台阶；桶太细，码本爆炸、利用率下降。经验上的折中是让桶的分辨率与目标面片平均边长同量级，这样量化误差不超过一个面片的尺度。

失败模式：AMT 假设网格是流形的、边最多被两个面片共享。一旦输入里有非流形边（三个以上面片共享一条边），共享判定表会出现一对多映射，解码器不知道继承哪两个顶点，只能退化为独立写顶点，序列变长且拓扑更乱。公开描述里 MeshAnything 的边界正是「约 800 面/非流形」，说明这类结构是这条路线明确的失效区。系统代价是预处理变重：焊接、建边表、建面片邻接，都是 O(N) 但常数不小，且必须对每个输入网格重跑，无法跨样本复用。

具体例子：一个约 1600 面的汽车模型，车身大片曲面由规则三角铺成，相邻面片大量共享边，AMT 能把序列压到接近一面一 token；但轮毂辐条之间的细碎面片共享关系复杂，焊接阈值稍大就把辐条之间的缝隙焊死，生成出的轮毂变成一坨。调参时要把车身和轮毂分开看：整体压缩率好看，不代表局部拓扑正确。

三 · 重拓扑不是简化：QEM 与重生成的取舍

QEM（二次误差度量）的机制是：为每个顶点维护一个误差矩阵，衡量把该顶点合并到某处后，周围面片到原表面的二次距离增加多少；每次挑代价最小的边收缩，直到面数降到预算。它的输出仍然是原网格的近似，顶点位置由原几何决定，拓扑结构继承原网格的连通性。也就是说，QEM 减面但不改「形状理解」：原网格哪里有一条乱边，减面后那条乱边的痕迹还在，只是面片变大了。

$$ \Delta(v) = v^{\top}\left(\sum_{f\ni v} \mathbf{K}_f\right) v,\quad \mathbf{K}_f = \mathbf{n}\mathbf{n}^{\top} + (\mathbf{n}^{\top}\mathbf{p})^2 $$

MeshAnything 走的是另一条路：它不保留原网格的顶点和连通性，而是把输入形状重新理解一遍，按学习到的艺术家拓扑分布重新铺面。输出可能和输入拓扑完全不同——原网格是一堆碎三角，输出是沿主曲率走的边流。它追求的是面数省、拓扑顺、能动画，而不是最小几何误差。这两条路线的取舍在工程上很明确：需要「忠实还原扫描件」时用 QEM，需要「产出可绑定的资产」时用重生成。

调参上，QEM 的关键参数是目标面数和边界保持权重。边界保持权重太低，模型的硬边（比如桌角）被抹圆；太高，减面在边界附近停滞，面数降不下去。重生成路线的关键参数是「艺术家拓扑」的先验强度，体现在训练数据的分布上：如果训练集里全是游戏资产的规则四边面主导网格，模型会倾向于输出均匀面片；如果训练集混杂扫描件，模型学到的拓扑就偏碎。这不是推理时可以调的旋钮，而是数据配比决定的。

失败模式：QEM 在薄壁结构上会把两面墙合并成一面，因为二次误差在薄壁两侧的法向相反、误差抵消，边收缩代价被低估。重生成路线在分布外的形状上会「自信地编造」：输入一个训练集里没有的拓扑类型（比如大量镂空的雕塑），模型仍按学到的规律铺面，铺出的边流与真实曲率不符，动画时蒙皮会撕裂。系统代价：QEM 是纯几何算法，无训练成本但需要人工设面数预算；重生成需要训练、需要推理延迟，且输出不可控——同一个输入两次采样可能得到不同拓扑，资产管线要接受这种不确定性。

具体例子：一个扫描得到的石雕，面数几十万、面片大小不一、有大量非流形碎边。走 QEM，减到几千面后石雕轮廓还在，但表面是一层不均匀的大三角，绑骨骼时关节处没有环状边流，形变会出褶。走 MeshAnything，输出是沿雕刻起伏走的规则面片，面数约八百，边流顺，但细节被「理解」掉了——原扫描件上的小凹坑被抹平，因为模型认为那不是艺术家会保留的特征。

四 · 部件生成的组合式潜变量与验收

PartCrafter 的机制是组合式潜变量：不是先生成一个整体网格再切，而是从一开始就按部件建模，每个部件有自己的潜变量，部件之间用全局注意力交换信息，保证空间关系（比如椅腿接在椅面下方、靠背在椅面后方）。生成结果是多个可编辑部件，每个部件能单独拆、换、动画。这和整体网格的差别在于「可修」：整体网格能看不能改，部件网格能进 DCC 工具逐件调整。

$$ p(\mathcal{P}\mid \mathbf{c}) = \prod_{k=1}^{K} p(\mathbf{z}_k\mid \mathbf{c}, \mathbf{z}_{

调参的核心是部件数 K。K 是离散的、不可微的，模型要在生成前预测它。预测少了，多个部件被塞进一个潜变量，拆不开；预测多了，出现空部件或碎片部件，拼回去时缝隙对不上。工程上的做法是给 K 设一个上限，让模型在生成过程中自行决定何时停止新增部件，类似序列生成里的终止 token。全局注意力的强度也要调：太弱，部件各自为政，椅腿飘在空中；太强，部件之间互相渗透，椅腿和椅面长在一起，失去可编辑性。

失败模式集中在遮挡与接触。部件之间的接触面在单视图或多视图输入下往往不可见，模型只能靠先验猜接触关系，猜错就出现穿模或悬空。遮挡还会让部件边界模糊：一个被椅子挡住一半的桌腿，模型可能把它和椅子生成成同一个部件。系统代价是生成时间随部件数线性增长，且每个部件都要单独解码、单独做拓扑检查，验收工作量比整体网格大一个量级。

验收清单要按顺序过，不能跳步。先看边流：边流是否沿主曲率走，关节处是否有环状边流；再看面片均匀度：三角面大小是否在同一量级，有没有突然出现的长条面；再看非流形边：有没有三个以上面片共享一条边，有没有孤立顶点；再看 UV：能否展开、接缝是否落在隐蔽处；最后看面数预算：是否在目标范围内。只看渲染图会被「面数少但拓扑乱」骗过去——渲染图不显示边流，也不显示非流形边。

具体例子：生成一把带扶手的椅子，部件数预测为四（椅面、靠背、两条扶手），但实际扶手和椅面在接触处共享一段边，全局注意力把两者拉得太近，解码出的扶手根部嵌进椅面。验收时边流检查能发现扶手根部的面片方向突变，UV 展开时接缝被迫落在接触面上，动画时扶手旋转会撕开椅面。修法是调低全局注意力权重、在训练数据里增加「部件接触但独立」的样本，而不是事后手动切网格。

五 · 五道自测题

以下五题用来检验对机制、代价与失败模式的理解，答案要求给出机制层面的理由，而不是名词复述。

  • 题一：MeshGPT 的 VQ 词表如果缩小一半，最直接的系统代价落在哪一段链路上？请从码本利用率、序列长度、解码器区分能力三个角度回答。
  • 题二：AMT 的共享判定为什么必须先做顶点焊接？如果跳过焊接直接按坐标相等判定，压缩率会怎样变化，拓扑会出现什么错误？
  • 题三：QEM 在薄壁结构上为什么容易把两面墙合并？请写出二次误差在两侧法向相反时的抵消过程，并说明这个失败模式对扫描件资产的影响。
  • 题四：PartCrafter 的部件数 K 预测错误时，两种错误方向（偏少、偏多）分别导致什么可编辑性损失？全局注意力权重过强会带来什么接触面问题？
  • 题五：验收一张重拓扑网格时，为什么不能只看渲染图？请列出渲染图无法暴露的三类拓扑缺陷，并说明每一类在动画或 UV 阶段的具体后果。

题一的关键在于词表缩小会让不同拓扑位置的面片共享 token，解码器失去区分「收边」与「铺面」的能力，序列可能变短但重构误差上升，码本利用率反而可能提高——因为所有 token 都被频繁使用，但表达力下降。题二要指出焊接把浮点误差归一，否则共享边漏判，token 退化为独立写顶点，压缩率归零，且边表出现一对多映射时解码器无法继承顶点。题三要写出两侧法向相反时 $\mathbf{n}\mathbf{n}^{\top}$ 项在求和里相互抵消，边收缩代价被低估，薄壁被压成单面，扫描件的薄壳结构失去厚度。题四要区分偏少导致多部件挤进一个潜变量、偏多导致空部件与缝隙，注意力过强导致部件渗透、接触面粘连。题五要列出边流紊乱、非流形边、面片尺寸突变三类缺陷，分别对应蒙皮撕裂、法线错误与 UV 接缝被迫落在可见处。

这五题的共同指向是一个工程判断：网格手艺的每一步都有明确的失效区，且失效区往往不在渲染图上显形。序列化路线的失效区是非流形与序列断裂，AMT 的失效区是焊接阈值与共享判定，QEM 的失效区是薄壁与边界，部件生成的失效区是部件数与接触面。调参不是找一组万能数字，而是把每个参数和它对应的失效区绑定，在验收清单里逐项检查。最后落在具体机制上：边流检查之所以排在验收第一位，是因为边流是拓扑与动画之间的唯一接口——边流错了，后面的面数、UV、蒙皮全都建立在错误的基础上，改起来不是调参能解决的。
