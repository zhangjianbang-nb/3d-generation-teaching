一 · 从“快”到“能用”：这一卷要回答的问题

第七卷的答案可以压缩成一句话：把三平面或高斯当作前馈网络的输出头，一次前向就能在秒级拿到一个三维对象。这条路线解决的是“快”——训练一个图像到三平面的 Transformer，推理时不需要逐场景优化，也不需要 SDS 那种以小时计的蒸馏。但“快”并不等于“能用”。一个在浏览器里旋转起来很好看的模型，拖进引擎之后会立刻暴露三类问题：它没有可动画的拓扑，它没有不拉伸的 UV，它的颜色把光照烘死在里面，换一套灯就崩。第八卷要回答的问题因此不是“怎样更快”，而是“生成模型输出什么，下游才能接”。这一卷的主题词是接口：三平面要解码，高斯要光栅化，SLAT 要多解码器，网格要 UV 与 PBR。任何一个接口错位，资产就进不了引擎。

把接口问题讲清楚，需要先承认一个事实：前馈模型的输出表示与生产资产之间不是同一种东西。三平面是一个 2D 特征张量集合，它本身不是表面；高斯是一堆带协方差的椭球，它本身没有面；网格是三角面片，但它缺 UV、缺材质语义；PBR 材质是 base color、metallic、roughness 三个通道，它要求输入图像先被 delighting——把拍摄时的光照从颜色里剥掉。第七卷把“从图像到三维表示”这一段做通了，第八卷要处理的是“从三维表示到生产资产”这一段，而这一段的每一环都有独立的失败模式。

一个具体的场景足以说明问题。假设一个技术美术拿到一张金属水壶的照片，用前馈模型在几秒内生成了一个带纹理的网格，导入引擎，打一盏暖光，看起来尚可；再换一盏冷光，壶身仍然是暖色调，金属高光的位置也不随光源移动——因为生成的颜色里已经包含了原照片的暖光。这不是模型“不够好”，而是接口错了：模型输出的是“带光照的颜色”，引擎需要的是“可重光照的材质”。要修这个问题，管线必须在某个环节插入 delighting，并把材质拆成三通道。第八卷里的 Hunyuan3D 2.1 与 SF3D 正是在这个环节上做文章，前者把 PBR 三通道作为生成目标，后者把 UV、PBR 与 delighting 打包进一条快速路径。

$$\mathcal{M}=\{\mathbf{c}_{\mathrm{base}},\ m,\ r\},\qquad \mathbf{c}_{\mathrm{base}}=\mathrm{Delight}(\mathbf{I})$$

这个式子看起来简单，代价却不小。Delight 是一个病态逆问题：给定一张已经把光照乘进反照率的图像，要恢复反照率，必须对光照做假设，而假设一旦错了，金属会变得像塑料，粗糙度会变得像镜面。工程上的判断是：delighting 误差不会在生成阶段被消除，它会被后续所有重光照放大。所以第八卷讨论 PBR 时，重点不在“能不能输出三个通道”，而在“这三个通道在换三套光照之后是否仍然自洽”。工匠笔记里那条验收标准——暖光、冷光、逆光各打一遍，看金属是否像金属、暗部是否带阴影——就是这条判断的操作化。

二 · 上一卷的答案为什么不够：表示与资产之间的三道裂缝

第七卷的三平面/高斯路线在“快”这一维上成立，但它留下的裂缝有三道，每一道都对应一种具体的系统代价。

第一道裂缝是重建上限。三平面把 3D 降成 2D 卷积，容量受限于平面的分辨率与特征通道数；高分辨率 3D 被压进潜变量时，细节在编码阶段就丢了，解码器再强也补不回来。Direct3D 的做法是用 3D VAE 把高分辨率 3D 压成潜变量，再在潜空间做 DiT 扩散——这解决了规模化生成的问题，但 VAE 的重建上限成了整条管线的天花板。工程上的表现是：生成的对象轮廓正确、大形正确，但边缘倒角、细小凹槽、薄片结构在潜空间里被抹平。这不是采样噪声，是编码器的信息瓶颈。

第二道裂缝是表示与下游的不匹配。高斯输出是一组显式基元，要变成引擎里的网格必须经过光栅化或表面提取，而提取出来的表面没有 UV，也没有部件语义；三平面输出要解码成网格，需要等值面提取，提取的拓扑不可控，动画师无法直接拿去做骨骼绑定。第七卷的模型大多停在“能渲染”，而生产资产要求“能动画、能拆件、能仿真”。拓扑要能动画意味着边环要沿关节走；UV 要不拉伸意味着展开要按曲率与面积优化；部件要能拆意味着生成时就要有部件级的潜变量，而不是事后分割。这些要求没有一个能靠“把三平面解码得更细”解决。

第三道裂缝是材质语义的缺失。第七卷的输出头大多只预测颜色，而颜色是光照与反照率的乘积。一个只在单套光照下好看的资产，通常是把光照烘进了 base color；这种资产在引擎里换灯就崩，在 PBR 管线里无法参与金属度/粗糙度的物理计算。更麻烦的是，颜色预测的损失函数不区分“这是阴影”还是“这是深色漆”，模型没有动机去分离两者。第八卷引入 PBR 三通道，本质上是把“颜色”这个标量场拆成三个有物理含义的通道，让损失函数能分别约束它们。

三道裂缝共同指向一个结论：上一卷的答案在“表示”这一层是够的，在“接口”这一层是不够的。第八卷的模型各自解决一小块——Direct3D 解决潜空间规模化，TRELLIS 用 SLAT 解决一套潜变量多解码，Hunyuan3D 2.0 用形状/纹理双 DiT 解决高分辨率带纹理，2.1 加 PBR 三通道，CraftsMan3D 做生成加精修，Step1X-3D 做几何/纹理解耦与可控，SF3D 做快速 UV 加 PBR 加 delighting——但没有一个模型单独解决整条管线。真正的管线要把它们串起来，而串联的接缝正是这一卷要讨论的对象。

三 · 结构化潜变量：SLAT 为什么是这一卷的枢纽

要理解第八卷的接口问题，SLAT 是最好的入口。SLAT 是“稀疏体素 + 局部三平面”的结构化潜变量：它在对象表面附近保留稀疏体素，每个被激活的体素携带一个局部三平面特征，而不是全局一张大三平面。这个设计的直接后果是：一套潜变量可以解成多种输出——解成高斯用于快速渲染，解成网格用于引擎，解成辐射场用于新视角合成。同一套潜变量多解码，意味着接口不再绑死在一种表示上，下游要什么就解什么。

机制上，SLAT 的关键是“稀疏”与“局部”。全局三平面的问题是分辨率与显存成正比：要提高细节就得提高平面分辨率，而平面分辨率一高，卷积代价与显存占用一起涨。SLAT 把特征放到表面附近的稀疏体素上，空区域不存特征，于是特征总量随表面面积而非包围盒体积增长。局部三平面则让每个体素的特征只描述该体素邻域，解码时按查询点所在的体素取对应三平面采样。伪代码思路大致是：编码阶段由图像特征预测哪些体素被激活、每个激活体素的局部三平面系数；解码阶段对查询点做体素索引，取局部三平面双线性采样，拼接后过一个小 MLP 得到该点的密度或颜色。

这套结构的代价在解码误差与分辨率上。稀疏体素的分辨率决定了局部三平面的空间支撑，体素粗则细节被平滑，体素细则激活数量与索引开销上升；多解码器之间还存在一致性误差——解成高斯时的表面与解成网格时的等值面不一定重合，因为两者的解码器是分开训练的。工程上的表现是：用高斯预览时看到的轮廓，与导出网格后的轮廓有细微偏差；这种偏差在特写镜头下可见，在部件拼接处会被放大。TRELLIS 的“仍缺什么”一栏写的是分辨率/解码误差，指的就是这件事。

一个具体例子：生成一个带镂空花纹的金属装饰件。SLAT 的稀疏体素在花纹边缘激活密集，在镂空处不激活，因此潜变量能保留“这里有孔”的信息；但解成网格时，等值面提取的步长如果大于孔径，孔会被填上。这不是生成失败，是解码接口的分辨率不匹配。要修，要么提高体素分辨率，要么在网格解码器里做自适应步长——两者都增加系统代价。第八卷讨论“一套潜变量多解码”时，真正要问的是：多解码器之间的一致性由谁保证，误差预算怎么分配。

四 · 双 DiT 与两阶段误差：形状与纹理拆开之后

Hunyuan3D 2.0 的选择是把形状与纹理拆成两个 DiT：一个生成几何，一个生成纹理。拆开的好处是每个 DiT 的容量可以独立分配，几何 DiT 专注轮廓与拓扑，纹理 DiT 专注颜色与细节，高分辨率带纹理的对象不必让一个网络同时扛两件事。代价是两阶段误差：纹理 DiT 以几何为条件，几何一旦有偏差，纹理会跟着错位；而纹理阶段的误差不会回传给几何阶段，两阶段之间没有联合优化。

机制上，形状 DiT 在几何潜空间做扩散，输出一个几何表示（可以是三平面、SLAT 或隐式场）；纹理 DiT 以几何的渲染或特征为条件，在纹理潜空间做扩散，输出颜色场。条件注入的方式决定了误差传播的形态：如果纹理 DiT 只看几何的深度图，那么几何的背面误差不会影响正面纹理，但接缝处的纹理会漂移；如果纹理 DiT 看几何的完整特征，那么几何的局部错误会被纹理放大。伪代码思路：第一阶段采样几何潜变量并解码为网格；第二阶段对网格做 UV 展开或直接在表面点上查询，以几何特征与法线为条件采样纹理潜变量，解码为颜色。

两阶段误差的工程表现是“贴图对不上”。一个具体例子：生成一个带缝线的皮靴，几何 DiT 把鞋帮与鞋底的交界做成一条硬边，纹理 DiT 在硬边两侧分别采样，缝线在交界处断开或错位。这不是纹理生成的质量问题，是两阶段之间缺少联合约束。Hunyuan3D 2.1 在 2.0 的基础上加 PBR 三通道，把材质从“颜色”扩展成 base color、metallic、roughness，等于在纹理阶段增加了三个需要彼此自洽的通道；通道之间的不一致（比如 metallic 高但 roughness 也高）会让金属看起来像湿塑料。这一步的代价是训练数据要求更高：需要带 PBR 标注的资产，而这类数据比带颜色的资产少得多。

从接口角度看，双 DiT 的真正问题是“几何与纹理的坐标系由谁定”。如果几何阶段输出的是隐式场，纹理阶段要查询表面点，就必须先做等值面提取或球面追踪；提取的精度决定了纹理采样的精度。工程判断是：两阶段管线里，几何阶段必须输出一个带稳定参数化的中间表示，否则纹理阶段无法保证接缝一致。这也是为什么 UV 展开在第八卷里不是附属步骤，而是接口的一部分。

五 · UV 与 PBR：资产进引擎的最后一道门

UV 展开决定纹理分辨率与接缝。一个网格如果没有 UV，纹理只能以顶点色或三平面投影的方式存在，前者分辨率受顶点数限制，后者在引擎里需要额外的着色器支持。UV 展开的目标是让每个三角面在 2D 平面上占据与其 3D 面积成比例的区域，同时把接缝放在不显眼的位置。拉伸的度量可以用面积比或角度畸变：对每个三角面，比较其在 3D 与 UV 空间中的面积比，比值偏离 1 越多，拉伸越严重。工程上的代价是：自动 UV 展开是一个组合优化问题，接缝位置的选择影响纹理分辨率分配，而生成模型输出的拓扑往往不规则，展开器要在不规则拓扑上找接缝，失败模式是接缝穿过重要特征（比如人脸的眼睛）。

PBR 三通道的接口问题更微妙。base color 是反照率，metallic 是二值或连续的金属度，roughness 是微观粗糙度。三者共同决定一个表面在给定光照下的外观。生成模型如果只输出颜色，引擎只能把它当无光照材质（unlit）或近似漫反射；要参与物理光照，必须有这三个通道。SF3D 的做法是把 UV、PBR 与 delighting 打包进一条快速路径，目标是在极短时间内给出“可用资产”——这里的“可用”指的是能进引擎、能换灯、能参与金属/粗糙度计算。代价是 UV 接缝与材质歧义：快速展开的接缝可能落在可见处，delighting 的假设可能把深色漆误判为金属。

一个具体例子：生成一个哑光陶瓷杯。如果 delighting 把照片里的高光当成反照率的一部分，base color 会在高光处偏亮，metallic 被误设为中等值，roughness 被设低；引擎里换一盏逆光，杯身会出现不该有的金属反光。验收方法就是工匠笔记里那条：暖光、冷光、逆光各打一遍。只在一套光照下好看的资产，通常是把光照烘进了 base color；这条判断不依赖任何实验数字，只依赖“换灯之后是否自洽”这个定性标准。

从管线角度看，UV 与 PBR 是资产进引擎的最后一道门，也是前面所有接口误差的汇聚点。几何的拓扑不规则，UV 展开就难；纹理阶段的两阶段误差，会在 UV 接缝处显现；delighting 的误差，会在换灯时显现。第八卷的模型各自在这道门上解决一小块：CraftsMan3D 用“生成 + 精修”把细节与拓扑分开处理，Step1X-3D 用几何/纹理解耦做可控编辑，但解耦之后的接口一致性仍是未解问题。工程判断是：管线里必须有一个显式的验收环节，把“换三套光照”作为准入条件，而不是等美术在引擎里发现再回炉。

把这一卷的开场落在具体机制上：接口不是抽象概念，它是潜变量的解码方式、是两阶段条件的注入方式、是 UV 接缝的位置、是 PBR 三通道之间的自洽约束。任何一个环节错位，资产就进不了引擎；而修一个环节的代价，往往要由整条管线分摊。
