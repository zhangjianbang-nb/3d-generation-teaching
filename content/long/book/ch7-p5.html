一 · 从论文到仓库：一次前向的代码骨架

把 LRM 类模型落到工程里，第一件事不是调参，而是把「一次前向」的数据流写成可断点、可缓存的模块。给定事实里那条公式 $$\mathbf{T}=\mathrm{Transformer}\left(\mathrm{ViT}(\mathbf{I}),\ \mathbf{Q}_{\mathrm{triplane}}\right)$$ 看起来只有两层，但工程上它至少被切成五段：图像预处理（去背、居中、归一化到固定分辨率）、ViT patch embedding、图像 token 与一组可学习的 triplane query token 拼接、跨注意力 Transformer 主干、以及把输出 token 重排成三张 2D 特征图。三平面表示的本质是把 3D 降成 2D 卷积，所以最后一步不是「解码出体素」，而是把 token 序列 reshape 成 $$(3, C, H_t, W_t)$$ 的张量，再交给一个轻量卷积头或直接双线性采样。任何一段的 shape 写错，报错都发生在很后面的渲染损失里，所以工程上要在每个边界打 assert。

伪代码思路可以这样组织：

  • 输入图先做前景分割与方形裁剪，保证物体在画面中的尺度一致，否则模型会把「占屏比例」误读成「物体大小」；
  • ViT 输出 $$N_{img}$$ 个 token，query 侧固定 $$N_{q}$$ 个 token，拼接后送进主干；注意 query token 是跨样本共享的参数，不是从图像里算出来的；
  • 主干输出只取 query 那一段，reshape 成三平面；
  • 渲染时对每个采样点 $$\mathbf{x}=(x,y,z)$$ 做三次 2D 采样：$$f_{xy}(x,y),\ f_{xz}(x,z),\ f_{yz}(y,z)$$，再拼接或求和成该点的特征；
  • 损失按给定公式对多个视角做图像重建 $$\mathcal{L}=\sum_{v}\|\hat{\mathbf{I}}_v-\mathbf{I}_v\|_2^2$$。
这里有一个容易忽略的机制：三平面查询是「投影后采样」，不是「三线性插值体素」。这意味着平面的分辨率 $$H_t\times W_t$$ 直接决定细节上限，而采样成本与平面分辨率线性相关、与 3D 分辨率无关——这正是三平面相对体素的经济性来源，也是它细节不足的根源。

系统代价出现在显存与吞吐的权衡上。渲染损失要对每条射线采样几十到上百个点，每个点做三次 2D 采样，batch 里再乘视角数，显存很快被激活值吃掉。常见失败模式是：为了省显存把每条射线的采样数砍到很低，训练 loss 看起来在降，但导出的三平面在薄结构上出现「空洞」或「双层壳」——因为稀疏采样没有惩罚到那些薄片。具体例子：一个带细长手柄的杯子，采样数不足时手柄在渲染里时有时无，梯度信号断续，模型学到的是「手柄区域模糊」，而不是「手柄存在」。工程判断是：采样数不能只看 loss 曲线，要固定一组薄结构验证样本单独看。

二 · 调参的优先级：先数据口径，后学习率

前馈模型的调参顺序与 NeRF 类优化式重建相反。优化式重建里学习率、正则权重是主战场；前馈模型里，第一优先级是数据口径的一致性。原因是 amortized 的本质：模型把「见过的物体分布」蒸进权重，输入预处理一旦在训练与推理之间不一致，先验就错位。给定事实说 LRM 在约 50 万物体上训练，规模决定上限，那么数据清洗管线的口径就是上限的地基。具体机制包括：背景是否去除、物体朝向是否规范化、相机内参是否固定、渲染时的光照是否统一。任何一项在训练集与线上请求之间漂移，都会表现为「同一张图，线下 demo 好看，线上 API 出来是歪的」。

第二优先级是损失里的视角分布。公式只写了求和，但 $$v$$ 怎么采样决定了模型学到什么。如果训练视角集中在正面半球的窄锥内，模型对背面的先验就是「猜」，这与第六卷多视图扩散要补背面是同一类问题，只是这里靠数据而非扩散先验。工程上要把视角采样写成显式的分层策略：赤道环、极区、以及少量极端仰角，避免模型把「背面」当成「正面的镜像」。失败模式是背面出现「贴图拉伸」式的伪影：几何大致对，但纹理是从正面投影过去的，一转到背面就露馅。

第三优先级才是学习率与 warmup。Transformer 主干对学习率敏感，query token 作为共享参数更容易过拟合到训练集的平均形状。一个可操作的检查是：固定一张输入图，改变随机种子只改 query 初始化，看输出差异。如果差异巨大，说明模型对 query 初始化过度敏感，先验没有真正收敛到数据分布上。表格对比能帮读者定位调参重心：

调参对象影响面典型失败信号
预处理口径全局先验对齐线下好、线上歪
视角采样分布背面与极区背面纹理拉伸
射线采样数薄结构梯度手柄/叶片断续
三平面分辨率细节上限边缘糊、细缝丢失
学习率/warmup收敛稳定性loss 尖峰、query 漂移

这里没有编造任何数字：分辨率、采样数、学习率的具体取值依赖模型配方，给定事实只给了 TripoSR 的 0.5 秒量级与 LRM 的约 50 万物体规模，其余只能定性判断。工程上正确的做法是把每个旋钮对应到一个可观测的失败信号，而不是盲目网格搜索。

三 · 输出头的分岔：三平面、高斯、网格各自的验收口径

同一套 ViT+Transformer 主干，换输出头就换了一个产品。三平面头输出的是隐式特征场，验收要看「渲染一致性」与「平面分辨率是否够用」；高斯头（GS-LRM）输出显式基元，验收要看漂浮物、显存与光栅化兼容性；网格头（MeshLRM 的可微网格、DMTet 类等值面提取）输出三角面，验收要看拓扑、非流形边与面数。给定事实里那张对比表已经把代价写清楚了：三平面受数据与分辨率限制，高斯有漂浮物与显存问题，可微网格受等值面分辨率限制。工程笔记的价值在于把这些代价翻译成检查项。

以高斯输出为例，机制上是每个基元带位置、协方差、不透明度与颜色，渲染走泼溅光栅化而非体渲染积分。代价是：优化式 3DGS 里漂浮物可以靠致密化与剪枝策略压下去，但前馈模型一次前向就出全部基元，没有迭代剪枝的机会，漂浮物只能靠训练时的监督去抑制。具体失败模式是物体周围出现「雾状小球」，在引擎里表现为半透明噪点，且因为高斯是显式的，导出后无法像隐式场那样靠提高采样密度消除。工程判断：高斯头适合「预览与快速资产」，不适合直接进需要干净几何的管线。

网格头的机制是等值面提取，典型是可微网格方案让梯度穿过提取过程。代价是分辨率：等值面网格的顶点密度由底层网格分辨率决定，细长结构要么被合并要么产生锯齿。失败模式是非流形边与自交，在引擎里表现为法线翻转、UV 展开失败。具体例子：一个带镂空花纹的装饰件，等值面分辨率不足时镂空被填平，视觉上「变厚」，重拓扑阶段无法恢复。所以网格头的验收必须包含「面数分布」与「非流形边计数」，而不只是渲染图。

三平面头的中间态最容易被误判。它渲染好看，但导出需要先提取网格（ marching cubes 或 DMTet），提取质量取决于平面分辨率与提取阈值。失败模式是「渲染图完美、提取网格破碎」：因为渲染时采样是连续的，提取时是离散阈值化的，两者对薄结构的容忍度不同。工程上要固定一组「渲染-提取」对照样本，专门看薄片与细杆。

四 · 检查清单：从 demo 到引擎的十项硬检查

给定事实里的工匠笔记说得很直接：评估前馈模型别只看「像不像」，让资产进引擎，检查 UV 接缝、法线方向、材质通道、三角面数、是否有非流形边。把这句话展开成可执行的清单，是这一部分最实用的产出。清单要按「几何→拓扑→材质→引擎兼容」的顺序排，因为后面的检查依赖前面的结果。

  • 几何包围盒与尺度：导出单位是否与引擎一致，物体是否居中，是否存在离群点把包围盒撑大（高斯头尤其常见）；
  • 法线方向：逐面检查朝向一致性，翻转面在引擎里表现为黑面或光照错误；
  • 非流形边与自交：网格头必查，非流形边会让布尔运算与碰撞体生成失败；
  • 三角面数分布：是否在薄结构处过度加密、在大平面处过度稀疏，面数预算是否匹配目标平台；
  • UV 接缝：接缝是否落在视觉隐蔽处，展开是否有重叠（重叠 UV 会让烘焙材质互相污染）；
  • 材质通道：是否有独立的 basecolor/roughness/metallic/normal，还是把光照烘进了颜色——后者无法重光照；
  • 透明与薄片：透明材质在前馈模型里常被当成不透明，检查 alpha 是否正确；
  • 漂浮物：高斯头必查，统计离主体距离超过阈值的基元比例；
  • 背面完整性：转一圈看是否有空洞或拉伸纹理，这是单图前馈的固有弱点；
  • 引擎导入回归：在目标引擎里跑一次导入脚本，记录警告数与失败项，作为版本对比基线。

这份清单的机制意义在于：它把「模型能力边界」变成「管线门禁」。前馈模型的工程价值在于批量，API 一次调用出资产，适合内容平台、电商、游戏原型；但批量意味着没有人逐个人工检查，门禁必须自动化。系统代价是门禁本身要写脚本、要维护阈值，且不同输出头需要不同门禁。具体例子：电商场景里，一个商品图生成的资产如果 UV 重叠，烘焙出的材质会在接缝处出现色块，人工抽检很难发现，但自动检查 UV 重叠面积占比就能拦住。

另一个容易被忽略的检查是「同分布验证」。前馈模型的先验来自训练分布，长尾物体、透明材质、没见过的背面仍会错。工程上要维护一组「已知困难样本」——薄结构、透明、极端比例、罕见类别——每次模型或预处理变更都跑一遍，看是否退化。这不是编造指标，而是把给定事实里明确列出的失败模式固化成回归集。

五 · 五道自测题：检验你是否真的理解了 amortized

第一题：给定公式 $$\mathbf{T}=\mathrm{Transformer}\left(\mathrm{ViT}(\mathbf{I}),\ \mathbf{Q}_{\mathrm{triplane}}\right)$$，问 query token 是从图像算出来的还是共享参数？如果把它改成从图像池化得到，会发生什么？这道题考的是对「一次前向」的理解：query 是共享的，模型靠它把图像 token 汇聚成三平面；若改成图像池化，模型失去固定的输出槽位，三平面结构会随输入变化而漂移，训练更难收敛。

第二题：三平面分辨率翻倍，渲染成本与细节上限各怎么变？答：采样成本随平面分辨率线性上升（每个点三次 2D 采样，采样查表规模变大），细节上限提高但受数据先验约束——如果训练集本身没有足够细节监督，提高分辨率只会让模型输出更锐利的「猜」。这道题考的是分辨率与数据的耦合。

第三题：GS-LRM 的高斯输出为什么会有漂浮物，而优化式 3DGS 相对少？答：优化式有致密化与剪枝的迭代过程，前馈一次前向没有剪枝机会，漂浮物只能靠训练监督抑制。这道题考的是「优化蒸进权重」的代价：省掉了迭代，也省掉了迭代带来的自我修正。

第四题：MeshLRM 的可微网格在薄结构上失败，根因是拓扑还是分辨率？答：首先是等值面分辨率，薄片在离散提取时被合并；其次是拓扑，提取出的网格可能非流形。两者要分开检查：提高分辨率看是否改善，若不改善则是拓扑问题。这道题考的是失败模式的归因方法。

第五题：为什么评估前馈模型不能只看渲染图？答：渲染是连续采样，提取与引擎导入是离散化与格式转换，两者对薄结构、UV、法线的容忍度不同；「漂亮 demo」在引擎里一导入就露馅，正是给定事实里工匠笔记的原话意思。这道题考的是「渲染指标」与「资产指标」的鸿沟。

这五道题的共同机制是：前馈模型的每一个优点都对应一个工程代价。amortized 省掉了逐资产优化，代价是数据决定上限、失败模式被固化进权重、且无法在单样本上迭代修正。工程判断因此落在「门禁」而非「调模型」：模型能力边界由数据与输出头决定，管线要做的是把边界内的资产批量放行、把边界外的资产拦下来送人工或送优化式重建。最后一段落在这个机制上：检查清单不是文档装饰，它是把「一次前向」的不可解释性转成可观测失败信号的唯一手段；没有门禁的前馈工厂，只是把 demo 的偶然性放大成批量的必然性。
