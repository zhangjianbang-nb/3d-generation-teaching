四 · 证据链：五种方法各自证明了什么

把第十卷的五种方法放在同一张证据桌上，先要问的不是“谁效果最好”，而是“每一篇论文到底证明了哪一条命题”。Text2Room 证明的是：文本可以经由“估深度—反投影—选新视角—补全融合”这条迭代回路，把一个房间推到闭合状态。它的证据形态是过程性的——论文要展示的不是单张图，而是沿一条相机轨迹连续取帧后，网格是否仍然对齐。WonderWorld 证明的是：单张图可以撑起一个可漫游场景，其证据核心在于分层高斯（FLAGS）与引导深度扩散的配合，使新视角既有视差又有深度约束。WorldGen 证明的是“文本到可穿越世界”可以被拆解为 LLM 布局、程序化资产、扩散补全三段，证据落在管线各段的接口是否稳定。SceneCraft 证明的是 LLM 能写 Blender 代码并借 GPT-V 看渲染反馈纠错，证据是“代码—渲染—纠错”闭环能否收敛。PhysDreamer 证明的是视频先验加可微 MPM 能反推出让物体表现出弹性与重量的材料参数，证据是仿真轨迹与视频先验轨迹的贴合度。

这五条命题的强度并不相同。前三条是“生成侧”的证据，回答“能不能造出一个看起来连得上的空间”；后两条是“交互侧”的证据，回答“造出来的东西能不能按物理规律动”。把它们混为一谈是读论文时最常见的误判：一个方法在漫游视频里墙很直，不等于它的门能过、物体不穿模；一个方法能让布料抖动得像真的，不等于它能生成一个房间。评估时必须把“视觉一致性”和“物理一致性”分开记账。

方法被证明的命题证据形态证据的薄弱处
Text2Room迭代补全可使房间闭合沿轨迹的连续帧与网格对齐深度误差随迭代累积，长轨迹末端接缝暴露

读这张表要抓住一个结构性事实：生成侧方法的证据几乎都是“沿某条路径看过去没崩”，而路径是作者选的。Text2Room 的轨迹若避开墙角与门框，接缝问题就被藏起来了；WonderWorld 的漫游若始终朝向被观测过的正面，背面缺监督的问题就不出现。这不是造假，而是证据的覆盖面问题。工程读者应当反过来问：作者没展示的那条路径上，会发生什么？

五 · 配方拆解：每条管线里真正承重的那一步

把五种方法当配方读，要找出“承重步骤”——去掉它，整条管线立刻失效的那一步。Text2Room 的承重步骤是深度估计与反投影的耦合：文本先出室内图，深度把像素抬成三维点，反投影成网格，然后不断选新视角补全并融合。这里没有端到端网络在兜底，深度误差会直接变成几何误差，而迭代又把误差一层层叠上去。融合策略是唯一的刹车：新观测与旧网格在重叠区做对齐，若对齐阈值放得太松，接缝就糊过去；放得太紧，补全就推不动。这是典型的“参数即证据”结构——融合阈值决定了论文展示的轨迹能走多远。

WonderWorld 的承重步骤是分层高斯与引导深度扩散的接口。FLAGS 把场景分成层，每层用高斯表达，深度扩散负责给新视角提供几何引导。承重之处在于：高斯层是显式的，可以快速光栅化，但层与层之间的接缝没有天然的物理约束；深度扩散给的是引导而非硬约束，因此背面与遮挡区的深度只能靠先验“猜”。一旦漫游路径绕过被观测面，层间错位就会以视差跳变的形式暴露。

WorldGen 的承重步骤是 LLM 布局到程序化资产的转换。文本先被 LLM 解析成空间布局——房间、物体、相对位置、连通关系；布局再驱动程序化资产生成可交互结构；最后由扩散补全视觉细节。承重之处在于布局的语义必须能被程序化管线消费：LLM 输出的若是“一张桌子靠墙”，程序化管线需要的是桌子的尺寸、朝向、与墙的距离这些可执行参数。语义到参数的翻译一旦失真，下游扩散再漂亮也救不回“门打不开”这种结构性错误。

SceneCraft 的承重步骤是 GPT-V 的渲染反馈。LLM 写 Blender 代码，渲染出图，GPT-V 看图后给出纠错意见，LLM 据此改代码。承重之处在于反馈必须可执行：GPT-V 说“椅子浮空了”，LLM 要能把它翻译成具体的坐标修正，而不是重写整段脚本。这里有两个硬边界：Blender API 的覆盖面决定了 LLM 能表达多少操作；GPT-V 的空间推理上限决定了它能否从一张渲染图里读出“浮空”这类三维关系。反馈回路若不能收敛，就会在“改—渲染—再改”之间循环。

PhysDreamer 的承重步骤是可微 MPM 与视频先验的对接。视频提供物体在受力下的运动轨迹，MPM 在给定材料参数下仿真出轨迹，二者做平方误差，对参数求梯度。公式就是卷导语里给出的那条：

$$\min_{\mathbf{p}}\ \sum_{t}\left\|\mathrm{Sim}_{\mathbf{p}}(\mathbf{x}_0,t)-\mathbf{V}_{\mathrm{prior}}(t)\right\|^2$$

承重之处在于可微性：MPM 的每一步都要能对材料参数求导，否则无法反推。这条公式暴露了两个失败模式。其一是参数不唯一——不同的弹性模量与阻尼组合可以拟合出相近的轨迹，优化会落到哪一个取决于初始化与正则，论文展示的那组参数只是其中一个解。其二是仿真贵——每个优化步都要跑完整条时间序列的 MPM，时间跨度越长、分辨率越高，代价越陡。

六 · 反例解剖：四种崩法及其触发条件

反例比正例更有信息量，因为反例标出了方法的适用边界。Text2Room 的典型崩法是深度误差累积：迭代补全每选一个新视角，都要用估计深度把新像素抬进三维，再与旧网格融合。深度估计在纹理贫乏的墙面、反光地面、远处门洞处误差最大，而这些区域恰恰是补全最需要的地方。误差不会自愈，只会被融合步骤部分掩盖；当轨迹足够长、视角绕到房间另一侧时，早期误差与晚期观测在接缝处对不上，墙就不再直。触发条件是“长轨迹 + 弱纹理区域”。

WonderWorld 的典型崩法是层间接缝与背面缺失。分层高斯让每层独立表达，层与层之间的过渡没有共享约束；引导深度扩散在观测覆盖区有效，在背面只能靠先验外推。触发条件是“漫游路径绕到物体背后”或“视角快速转向”。表现出来是视差跳变、背面糊成一片、遮挡关系错乱。这与前文讲过的多视图一致性问题是同源的：单图方法在没看过的地方没有证据，只能靠先验，而先验在几何上是软的。

WorldGen 的典型崩法是管线复杂导致的误差不可归因。LLM 布局错了、程序化资产参数错了、扩散补全把结构盖住了，三者产生的视觉症状可能相似——都是“看起来不对”。工程上最难受的不是错，而是不知道哪一段错。触发条件是“布局语义模糊”，比如文本说“一个舒适的书房”，LLM 可能给出多种布局，程序化管线按其中一种执行，扩散再按执行结果补全，最终产物偏离用户意图却无法定位到具体段。

SceneCraft 的典型崩法是反馈回路不收敛与 API 边界。GPT-V 从渲染图里读出的问题，未必能被 LLM 翻译成合法的 Blender 操作；LLM 改代码时可能引入新的语法错误或破坏已有结构。触发条件是“场景复杂度上升”——物体越多、空间关系越密，GPT-V 的单图判断越不可靠，LLM 的代码修订越容易顾此失彼。这与前馈工厂那一卷的教训一致：结构化输出比自由文本更难保证合法性。

PhysDreamer 的典型崩法是参数不唯一与仿真不稳。视频先验只给了运动轨迹这一条观测，而材料参数是多维的；优化可能收敛到物理上不合理但数值上贴合的解。仿真不稳则出现在大步长、高刚度材料、复杂接触的场景：MPM 的稳定性对时间步与网格分辨率敏感，参数优化过程中若探索到刚度极高的区域，仿真可能直接发散，梯度变成噪声。触发条件是“接触复杂 + 参数搜索范围宽”。

  • 崩法一：深度误差沿迭代累积，长轨迹末端接缝暴露（Text2Room）。
  • 崩法二：层间无共享约束，背面缺监督，绕后即跳变（WonderWorld）。
  • 崩法三：三段管线误差不可归因，症状相似而病因不同（WorldGen）。
  • 崩法四：视觉反馈不可执行，代码修订破坏已有结构（SceneCraft）。
  • 崩法五：参数不唯一加仿真发散，梯度被噪声污染（PhysDreamer）。

七 · 验收方法：把截图换成一条可复现的检查清单

卷导语的工匠笔记说得很直白：场景验收别只看截图，走一遍、撞一下、转个身。这句话可以拆成可执行的检查项。走一遍，检查的是长距离漫游下墙是否直、接缝是否对、光照是否随视角连续——这直接对应 Text2Room 的深度累积与 WonderWorld 的层间接缝。撞一下，检查的是物体是否能碰撞、门是否能过、接触处是否穿模——这对应 WorldGen 的程序化结构与 PhysDreamer 的仿真稳定性。转个身，检查的是背面是否有内容、遮挡关系是否自洽——这对应单图方法的背面缺失。

把这些检查项写成伪代码思路，验收就变成可复现的流程而不是主观观感：

  • 沿预设轨迹采样 N 个视角，逐帧渲染，记录相邻帧在重叠区的几何偏差与光度偏差；偏差超过阈值即标记为接缝候选。
  • 对每个可交互物体施加一次标准冲量，记录仿真是否发散、接触是否穿透、恢复是否合理；发散即判物理参数越界。
  • 把相机绕每个物体转一周，检查背面渲染是否有内容、遮挡顺序是否随视角单调变化；跳变即判层间或背面缺陷。
  • 对管线方法，逐段替换下游模块做消融，定位误差来源；症状相同而消融结果不同，说明误差不可归因。

这套清单的代价是时间：一条完整轨迹的渲染加仿真，远比一张截图贵。但静态截图会掩盖场景问题，这是卷导语给出的判断，也是五种方法共同的证据弱点——它们展示的都是作者选定的路径，而路径之外才是工程真正要面对的地方。验收的本质不是给方法打分，而是把“作者没展示的那条路径”补上。

还有一个容易被忽略的验收维度：一致性要分层记账。房间的墙直不直是几何一致性；接缝对不对是拓扑一致性；光照连不连续是光度一致性；门能不能过、物体会不会穿模是物理一致性；材料参数唯不唯一是参数一致性。五种方法各自只覆盖其中几层，把它们混成一个“场景质量”分数，就会掩盖真正的失败模式。工程判断应当落在“这条管线在我关心的那一层一致性上，有没有承重机制”——Text2Room 的承重是融合阈值，WonderWorld 的承重是深度引导接口，WorldGen 的承重是语义到参数的翻译，SceneCraft 的承重是可执行反馈，PhysDreamer 的承重是可微仿真与参数正则。承重机制缺席的那一层，就是这条管线在长距离漫游、遮挡、接触处崩掉的地方。
