一 · 训练侧的成本结构：优化、蒸馏与前馈三条路

把八方向按“训练时到底在优化什么”切开，代价立刻分化。第一条是逐场景优化：NeRF 的体渲染积分、NeuS 的 SDF 体渲染、3DGS 的高斯泼溅光栅化，都属于“给定一组图像，把表示拟合到这些图像”。它的训练代价由采样密度和迭代次数决定，收敛慢但目标明确，失败模式是过拟合视角覆盖：训练视角之外的外插区域没有梯度约束，背面和边缘会塌成雾状或拉出条纹。第二条是蒸馏：SDS 家族把 2D 扩散先验蒸进 3D，DreamFusion、Magic3D、ProlificDreamer 的差别在得分项怎么估。它的代价不在单次前向，而在每步都要跑扩散模型反传，显存与时间随扩散步数线性增长；失败模式是“先验幻觉”——多面人、Janus 问题、过饱和纹理，因为 2D 先验对背面没有约束。第三条是前馈：LRM、TripoSR、GS-LRM、MeshLRM、LGM 一次前向出三平面、高斯或网格，训练代价前置到大规模资产上，推理便宜；失败模式是分布外输入，单图遮挡区、透明薄结构、长尾类别会直接崩。

三条路的成本不在同一量纲上，必须分开记。逐场景优化的成本是“每资产分钟级到小时级 + 每资产一份参数”；蒸馏的成本是“每资产扩散采样数百到数千步 + 显存峰值”；前馈的成本是“一次性训练 GPU 日 + 推理毫秒到秒级”。选型时把这三项写进预算表，比比较论文里的视觉分数有用得多。一个具体例子：要给电商做批量商品展示，逐场景优化每件商品都要重跑，人工盯收敛；前馈模型一次前向出三平面，但遇到反光金属和透明玻璃就露馅，得补一个逐场景微调环节——这就是“前馈打底 + 优化修补”的混合管线，代价是两套系统都要维护。

$$\mathcal{L}_{\text{SDS}}=\mathbb{E}_{t,\epsilon}\left[w(t)\,\|\epsilon-\epsilon_\theta(\mathbf{x}_t;y,t)\|_2^2\right],\quad \mathbf{x}=\text{Render}(\theta)$$

上式里梯度只经过渲染器回到 3D 参数，扩散模型本身不更新。这意味着每一步的显存峰值包含扩散 U-Net 的激活，而 3D 表示越大、渲染分辨率越高，反传链越长。工程上常见的失败不是算法不收敛，而是显存爆掉后被迫降分辨率，降分辨率又让高频细节丢失，最后得到一个“远看还行、近看糊”的资产。这是蒸馏路线最典型的系统代价：质量与显存直接耦合，没有免费的中间档。

二 · 推理侧：光栅化、体渲染与网格提取的代价分野

推理代价决定下游能不能用。3DGS 的光栅化把显式基元按深度排序后做 alpha 混合，代价随高斯数量和屏幕覆盖增长，实时预览是它的主场；代价是显存：几百万高斯常驻显存，压缩与编辑模块必须补上，否则移动端直接出局。NeRF 与哈希编码的体渲染每像素要沿射线采样几十到上百个点，查表换速度让训练快了，但推理仍是采样密集型，实时性靠预计算或蒸馏到网格。SDF/网格路线在推理时最便宜：等值面提取一次，之后就是普通三角形渲染，代价转移到“提取时的分辨率与拓扑修复”。

这里有一个容易被忽略的失败模式：可微网格提取（DMTet 一类）在训练时把表面表示成可微的形变，推理时却要离散化成三角面。离散化会丢掉薄结构和细小孔洞，水密性不保证，3D 打印前必须跑修复。一个具体例子：用 NeuS 重建一个带把手的杯子，体渲染视角下把手完整，提取成网格后把手内侧出现自交，切片软件报错。这不是算法错了，是“连续表示 → 离散网格”这一步的系统代价，选型表里“要补的模块：水密性/修复”就是为它留的位置。

路线推理主代价典型失败模式要补的模块
3DGS显存常驻 + 排序光栅化薄结构拉丝、反光过曝压缩/编辑
NeRF/哈希每像素射线采样视角外插塌陷预计算/蒸馏
SDF/网格等值面提取 + 修复薄壁丢失、自交水密性/修复
前馈大模型一次前向 + UV/PBR 后处理分布外输入崩坏UV/PBR/重拓扑

把这张表读成“代价转移图”更准确：每条路线都把成本推到了不同环节，没有一条是全栈便宜的。选型的动作不是找最便宜的，而是找“你的下游能吸收哪种代价”。下游是实时预览，就吸收显存代价；下游是 3D 打印，就吸收修复代价；下游是引擎导入，就吸收重拓扑与 UV 代价。

三 · 系统集成：八方向不是孤岛，组合处的接口代价

真正的系统会把多条路线串起来，串接处的接口就是新的失败点。场景重建提供可微渲染，原生表示提供潜空间，SDS 提供无数据先验，多视图提供一致性，前馈模型提供规模化，网格手艺提供可用拓扑，场景/世界提供交互，数据/材质提供地基。每两个模块相接，都要约定表示格式、坐标系、尺度与材质通道。一个具体例子：前馈模型输出三平面，重拓扑模块要网格 tokenization，中间必须做一次等值面提取加网格序列化；提取分辨率选低了，重拓扑拿到的输入已经丢了细节，后面再怎么生成拓扑也救不回来。这类“上游精度决定下游上限”的接口代价，在单方向论文里几乎不讨论，在系统里却是主要故障源。

另一个接口代价是材质。形状-材质双 DiT 或 UV 展开 + PBR 分解的输出，要进引擎重光照，就必须有合法的 UV 和物理合理的粗糙度/金属度。前馈模型常直接出顶点色或三平面颜色，没有 UV，导入引擎时要么烘培要么重展 UV，烘培的分辨率与接缝又成了新问题。选型表里“批量生产 → 前馈大模型 → 要补 UV/PBR/重拓扑”正是这个接口的账单。工程判断是：如果你的下游是引擎，把 UV/PBR 当成必选模块而不是可选项，预算里给它留出时间。

$$\text{系统代价}=\sum_{i}\text{单模块代价}_i+\sum_{i,j}\text{接口代价}_{ij}+\text{集成风险}$$

这个式子没有数值，但它提醒一件事：模块数量增加时，接口代价按组合数增长，集成风险非线性上升。八方向组合的系统，失败往往不在某个模块本身，而在两个模块对“什么是表面”“什么是尺度”的理解不一致。做 A/B 验证时，要专门测接口：把上游输出直接喂给下游，看下游报什么错，比看端到端渲染图更早暴露问题。

四 · 失败模式的分类学：按“缺什么约束”归因

把失败模式按缺失的约束归类，比按路线归类更能指导修补。第一类缺视角约束：单图或稀疏视角输入，背面没有观测，多视图扩散补出的是“讲得通的背面”而非“真实的背面”，长尾物体尤其明显。第二类缺几何约束：SDS 只约束渲染图与文本一致，不约束表面法线连续性，于是出现浮点、空洞、双面片；Interval Score Matching 与法线桥接（如 Hi3DGen 的 normal bridging）就是在补这类约束。第三类缺拓扑约束：隐式表示天然允许非流形，重拓扑与部件生成（MeshAnything、PartCrafter）补的是“可动画、可绑定”的拓扑。第四类缺物理约束：PhysDreamer 一类从视频估计物理参数，但碰撞、摩擦、质量分布仍是开放问题，场景/世界管线里碰撞体常要手工补。

一个具体例子：文本生成一只长颈鹿，SDS 路线能出多视角看着合理的形状，但脖子与身体的连接处法线不连续，导入引擎做骨骼绑定时权重涂不开；换重拓扑路线，网格 tokenization 能出干净四边形，但纹理要重新投影，投影接缝又回到 UV 问题。两次失败分别缺几何约束和拓扑约束，修补动作完全不同。工程上先归因再选模块，比“换个 SOTA 再试”省时间。

  • 缺视角约束 → 补多视图一致性或多视图扩散，代价是推理步数与一致性检查。
  • 缺几何约束 → 补法线/正则项或法线桥接，代价是训练不稳定与调参。
  • 缺拓扑约束 → 补重拓扑或部件生成，代价是纹理重投影与接缝。
  • 缺物理约束 → 补物理参数估计或手工碰撞体，代价是仿真调参。

这张清单也是评测协议的入口：开放问题里的“评测协议”之所以难，是因为不同失败模式需要不同的度量——视角外插要看背面一致性，几何要看水密性与法线，拓扑要看绑定可行性，物理要看仿真稳定性。用单一 FID 或 CLIP 分数横比八方向，等于把四类失败混成一个数，选型会被误导。

五 · 选型动作：把代价写进约束，用小样本 A/B 定案

选型公式是任务匹配乘质量除以成本加集成风险，但工程上真正要做的是把“成本”和“集成风险”写成硬约束，再在可行域里比质量。具体动作：先写下游需求（渲染/编辑/动画/物理/引擎），再写预算（显存/时间/数据），再写风险（许可/长尾/背面），三项写完，八方向表里通常只剩 1–2 个候选。剩下的用一个小样本 A/B 验证，不要凭论文分数拍板。A/B 的设计要覆盖失败模式：故意放一张透明物体、一张薄壁件、一张长尾类别，看候选路线在哪类输入上崩，崩了之后修补模块能不能接上。

一个具体例子：团队要做可漫游室内场景，候选是场景/世界管线（Text2Room、WorldGen 一类）与前馈大模型批量生成再拼装。前者长距离不漂移靠场景一致性模块，但单房间质量一般；后者单件质量高，拼装处接缝与尺度不一致要手工修。A/B 时不要只比单帧渲染，要比“走十米后回头看”的一致性，以及“碰撞体是否自动生成”。这两项一测，候选往往只剩一个，或者确定必须做混合管线。混合管线的代价是两套系统的版本同步与接口测试，这笔账要提前写进预算，否则上线后每次上游更新都要重跑下游回归。

$$\text{可行域}=\{m:\ \text{显存}(m)\le B,\ \text{时延}(m)\le T,\ \text{许可}(m)=\text{OK},\ \text{失败模式}(m)\cap\text{关键输入}=\varnothing\}$$

这个集合写法的作用是把“大概能行”变成“逐项打勾”。许可一项常被忽略：数据与材质的地基（Objaverse 一类）有许可差异，前馈模型训练数据许可不清时，批量生产就有法务风险，这不是技术能补的模块。长尾与背面是质量风险，许可与集成是生存风险，后者一票否决。

最后落在具体机制上：选型的终点不是挑一个模型名，而是画出一条数据流——输入是什么、中间表示是什么、哪个模块补哪种约束、接口处谁负责格式转换、失败时回退到哪条路线。把这条数据流和它的接口代价写成一页纸，比任何选型表都更能防止上线后的返工。八方向的价值在于它们各自提供了一种约束来源，系统的工作是把约束接到需要它的环节上；接不上的地方，就是下一波论文与工程的入口。
