一 · 从“每次优化”到“一次前向”：第七卷的问题域

前六卷的读者已经习惯了一种节奏：给定一组多视图照片，或者给定一句文本提示，我们架起一个可微渲染器，定义一个损失，然后让优化器在几分钟到几十分钟里把 3D 表示“磨”出来。第一卷的体渲染积分告诉我们怎样把 3D 场画成 2D 像素；第二卷的哈希编码与 3DGS 告诉我们怎样把速度从分钟压到秒级渲染；第三卷的 SDF 与 Eikonal 正则告诉我们怎样让表面干净；第四卷的三平面告诉我们怎样把 3D 降成 2D 卷积；第五卷的 SDS 家族告诉我们怎样把 2D 扩散先验蒸进 3D；第六卷的多视图扩散告诉我们怎样让背面也讲得通。这条链路有一个共同的隐含前提：每一个资产都要单独跑一次优化。优化是“按需计算”的，资产之间不共享任何计算。

第七卷要回答的问题正好把这个前提掀翻：如果把“优化”这件事本身蒸进一组权重，让模型在训练阶段见过足够多的物体，那么推理阶段能不能只做一次前向，就吐出三平面、高斯或网格？这个问题的技术名字叫 amortized inference——把逐实例的迭代求解摊销成一次参数化映射。给定输入图像 $\mathbf{I}$，我们不再求解 $\arg\min_{\theta}\mathcal{L}(\theta;\mathbf{I})$，而是直接计算 $\hat{\theta}=f_\phi(\mathbf{I})$，其中 $\phi$ 是在大规模 3D 资产上训好的网络参数。代价从“每个资产一次优化”变成“一次训练、无数次前向”，但上限也被训练数据封死：模型没见过的物体，先验帮不上忙。

本卷导语给出的对照表已经把这条路线上的五个代表钉在了墙上：LRM 用 ViT + Transformer 把图像 token 映射到三平面，秒级出结果；TripoSR 把架构简化加工程优化，把单图重建压到 0.5 秒；GS-LRM 换高斯输出头；MeshLRM 做可微网格；LGM 用 4 视图 Transformer 做多视图高斯。它们的共同公式骨架是：

$$\mathbf{T}=\mathrm{Transformer}\left(\mathrm{ViT}(\mathbf{I}),\ \mathbf{Q}_{\mathrm{triplane}}\right),\qquad \mathcal{L}=\sum_{v}\|\hat{\mathbf{I}}_v-\mathbf{I}_v\|_2^2$$

这个式子里藏着本卷的全部张力。左边是一次前向的产物，右边是监督信号：模型不是被教“3D 长什么样”，而是被教“渲染出来要像输入视图”。这意味着几何正确性是渲染损失的副产品，而不是被显式约束的目标——这正是后面几部分要反复拆解的失败模式源头。

二 · 一个具体场景：内容平台的批量上架

设想一个电商内容平台，商家每天上传数千张商品白底图，运营希望每张图自动变成可在网页里旋转查看的 3D 资产，并且能进引擎做简单的场景摆放。用第五卷的 SDS 路线，每张图要跑一次文本到 3D 或图生 3D 的优化，单资产耗时以分钟计，还要调超参、筛失败样本；用第六卷的多视图扩散加逐资产重建，虽然省掉了文本对齐，但“生成多视图 + 逐资产优化”仍然是两段式流水线，吞吐被优化段卡住。平台的真实约束不是“能不能生成一个漂亮 demo”，而是“一天几千张图，每张图几秒钟内出资产，失败率可控，下游能自动接 UV 和材质”。

前馈模型正是为这个约束设计的。TripoSR 把单图重建压到 0.5 秒这个量级，意味着单卡吞吐从“每小时几个”跳到“每小时上千”，批量 API 一次调用出资产成为工程上可行的事。这里的机制不是魔法：ViT 把输入图切成 token，Transformer 用一组可学习的 triplane 查询 token 做交叉注意力，一次前向就输出三平面特征图；三平面再经体渲染或等值面提取变成可视资产。训练阶段在约 50 万物体上做多视图渲染监督，把“从单视图推断背面”的先验压进注意力权重里。推理阶段没有任何迭代，延迟由骨干网络的前向决定，而不是由收敛速度决定。

但场景一落到工程细节就露馅。导语里的工匠笔记说得很直白：评估前馈模型别只看“像不像”，让资产进引擎，检查 UV 接缝、法线方向、材质通道、三角面数、是否有非流形边。一个在 demo 里旋转起来很顺的资产，导入引擎后可能因为三平面分辨率限制而细节糊成一团，可能因为高斯输出头的漂浮物而在轮廓外出现悬浮噪点，也可能因为可微网格的等值面分辨率限制而薄结构断裂。批量场景放大了这些缺陷：单资产 5% 的失败率，在一天几千张的吞吐下就是每天上百个需要人工返工的资产。

这个场景还暴露了前馈模型的边界条件。长尾物体、薄结构、透明材质、没见过的背面仍会错——这不是调参能解决的，而是数据分布决定的。模型见过的物体越多，先验越强，一次前向就越准；反过来，训练集里稀缺的类别，前向输出就退化成“平均形状加纹理贴图”。平台如果卖的是标准品类（鞋、杯、玩具），前馈模型命中率高；如果卖的是手工艺品、透明玻璃器皿、带细长挂件的饰品，前馈模型就需要下游补救模块。这就是为什么本卷的工程价值落在“批量”而不是“万能”：它把资产生成的边际成本压到接近零，但把质量责任推给了数据覆盖和下游管线。

三 · 为什么上一卷的答案不够：三条被摊销掉的东西

要理解前馈工厂为什么必须存在，得先看清前六卷路线在“批量”这个维度上到底缺什么。缺的不是质量——SDS 和多视图扩散在单资产质量上仍然有优势，尤其是文本对齐和背面想象力。缺的是三样被逐资产优化悄悄承担、但从未被显式定价的东西。

第一样是时间预算的不可预测性。SDS 类方法的收敛步数依赖提示词、初始化和超参，单资产耗时从几分钟到几十分钟不等，且失败模式是“优化跑完了但结果不能用”，需要人工筛查。多视图扩散把生成段固定成若干步采样，但后面的逐资产重建仍然是优化，延迟随资产复杂度浮动。前馈模型把延迟变成一个由网络结构决定的常数：TripoSR 的 0.5 秒是架构加工程优化的结果，不随物体复杂度剧烈波动。对批量系统来说，可预测的延迟比平均更低的延迟更重要，因为调度、限流、重试策略都建立在延迟分布上。

第二样是跨资产不共享的先验。逐资产优化每次从零开始，上一个资产学到的“杯子通常有把手”“椅子通常有四条腿”不会被下一个资产继承。前馈模型把这种先验压进权重：约 50 万物体的训练集让 Transformer 学会从单视图 token 推断被遮挡部分。这个先验的强度直接决定一次前向的准确度，也直接决定它的盲区——训练集里没有的物体类别，先验就是噪声。逐资产优化没有这个问题，因为它对每个资产单独求解，不依赖分布假设；但它也没有先验带来的速度红利。

第三样是表示与下游的耦合方式。逐资产优化可以针对下游需求定制表示：要渲染就用 3DGS，要进引擎就用可微网格提取，要重光照就加材质分支。前馈模型把表示固定成输出头：LRM 出三平面，GS-LRM 出高斯，MeshLRM 出网格，LGM 出多视图高斯。换表示意味着换模型或加转换模块。导语里那句“要进引擎，还要 UV/PBR/重拓扑；要动画，还要部件/骨骼；要物理，还要材料参数”点明了这个耦合的代价：前馈模型只负责“出资产”，不负责“出可用资产”。把 downstream 模块串起来，才是生产管线。

三条合起来，上一卷的答案不够，不是因为它的方法错了，而是因为它的成本结构不适合批量。逐资产优化是“手工艺”模式：质量上限高，边际成本不下降。前馈模型是“工厂”模式：边际成本趋近于零，但质量上限由训练数据和输出表示封顶。第七卷的标题“前馈工厂”正是这个意思——工厂不追求单件极品，追求的是可预测、可批量、可接下游。

四 · 摊销的数学形态与它的失败模式

把摊销写成数学，能看清它到底交换了什么。逐资产优化的目标是求一个实例最优参数：

$$\theta^\star(\mathbf{I})=\arg\min_{\theta}\ \mathcal{L}_{\mathrm{render}}\big(\mathrm{R}(\theta),\mathbf{I}\big)+\lambda\,\mathcal{R}(\theta)$$

前馈模型则学习一个映射 $f_\phi$，在训练集分布 $p(\mathcal{D})$ 上最小化期望损失：

$$\phi^\star=\arg\min_{\phi}\ \mathbb{E}_{\mathbf{I}\sim p(\mathcal{D})}\Big[\mathcal{L}_{\mathrm{render}}\big(\mathrm{R}(f_\phi(\mathbf{I})),\mathbf{I}\big)\Big]$$

注意两个式子的差别：前者对每个 $\mathbf{I}$ 单独求解，后者对分布求期望。这意味着 $f_\phi$ 在分布内是近似最优的，在分布外则没有任何保证。长尾物体、薄结构、透明材质、没见过的背面之所以会错，不是因为网络容量不够，而是因为期望损失被高频类别主导，稀有类别的梯度贡献被稀释。这是摊销的数学形态自带的结构性偏差，不是工程 bug。

第二个失败模式来自输出表示的容量上限。三平面把 3D 降成三个 2D 特征图，分辨率是固定的；三平面分辨率限制细节，薄结构在低分辨率特征图上会被抹平。高斯输出头的漂浮物来自显式基元的自由度：网络可以为了拟合渲染损失而在空中放置高斯，渲染视角下看不出问题，换视角或进引擎就暴露。可微网格受等值面分辨率限制，拓扑在提取阶段被固定，细长部件容易断裂或粘连。这些不是训练不充分，而是表示本身的表达上限。

第三个失败模式是监督信号的盲区。公式里的损失是 $\sum_v\|\hat{\mathbf{I}}_v-\mathbf{I}_v\|_2^2$，只约束渲染结果，不约束几何正确性。一个在训练视角下渲染完美的资产，可能在背面有完全错误的几何，因为背面从来没有被监督过。多视图训练能缓解这个问题，但不能消除：训练视角的覆盖是离散的，视角之间的插值靠先验，先验错了就错。GS-LRM 换成高斯输出、MeshLRM 做可微网格，本质上都是在换一种方式承担同一个盲区。

系统代价也要算清楚。前馈模型的显存开销主要在前向的注意力和输出表示上：三平面输出是固定分辨率特征图，显存随分辨率平方增长；高斯输出随基元数量线性增长，GS-LRM 的漂浮物问题在显存紧张时会被放大，因为网络倾向于用更少的基元覆盖更大的区域。批量推理时，吞吐受限于单次前向的显存占用，而不是优化步数——这又是和逐资产优化相反的瓶颈结构。

五 · 五个模型的分工：输出表示决定下游命运

本卷导语的对比表不是罗列，而是分工图。五个模型共享同一个骨架——ViT 切 token、Transformer 做映射、一次前向出 3D——但输出表示不同，下游命运就不同。理解这张表的关键是问：这个输出头把误差推到了哪里？

模型输出速度量级关键改动主要代价
LRM三平面秒级ViT + Transformer数据 / 分辨率
TripoSR三平面 / 网格0.5 秒架构简化 + 工程优化纹理 / 细节
GS-LRM高斯秒级高斯输出头漂浮物 / 显存
MeshLRM网格秒级可微网格拓扑 / 分辨率
LGM多视图高斯秒级4 视图 Transformer背面 / 多视图依赖

LRM 是这条线的起点：三平面输出把 3D 压成 2D 特征图，好处是可以用 2D 卷积做后续处理，坏处是分辨率一固定，细节就封顶。TripoSR 在 LRM 骨架上做架构简化和工程优化，把延迟压到 0.5 秒，代价是纹理和细节进一步让步——速度是从表示容量里抠出来的。GS-LRM 换高斯输出头，渲染质量上去了，但显式基元的自由度带来漂浮物，显存随基元数量增长。MeshLRM 做可微网格，直接产出引擎友好的三角面，但拓扑和等值面分辨率成了新的天花板。LGM 用 4 视图 Transformer 做多视图高斯，高分辨率是卖点，代价是对多视图输入的依赖和背面一致性压力。

这张表给工程选型的启示是：不要问“哪个模型最好”，要问“我的下游要什么”。要网页旋转查看，高斯或三平面渲染都行；要进引擎做碰撞和动画，网格输出省掉一次转换，但 MeshLRM 的拓扑质量要单独评估；要批量 API，TripoSR 的 0.5 秒量级是吞吐底线。每个输出头都把误差推到了不同的下游环节：三平面把误差推给分辨率，高斯把误差推给漂浮物清理，网格把误差推给重拓扑。导语里“把这些 downstream 模块串起来，才是生产管线”这句话，说的就是误差不会消失，只会转移。

还有一个容易被忽略的工程判断：前馈模型的“秒级”不是单点延迟，而是批量吞吐的前提。0.5 秒的单资产延迟，在并发调度下才能变成每小时上千的吞吐；如果输出表示导致显存占用高，并发度就上不去，秒级延迟也换不来批量吞吐。这就是为什么 GS-LRM 的显存代价和 LGM 的多视图依赖，在批量场景里比在 demo 场景里更致命。

六 · 本卷要拆的机制：从 token 到潜变量再到资产

把场景、数学和分工收拢到一条机制链上，本卷的叙事骨架就清楚了。输入端，ViT 把图像切成 token，每个 token 是一个局部 patch 的特征；Transformer 用一组查询 token（三平面查询、高斯查询或网格查询）做交叉注意力，把图像 token 的信息读进潜变量。这一步的机制核心是“查询决定输出表示”：查询 token 的数量和维度直接对应输出头的容量，三平面查询少则分辨率低，高斯查询多则基元多、显存高。

中间段，潜变量到 3D 的转换决定了误差形态。三平面走体渲染或等值面提取，分辨率是硬约束；高斯走显式基元加光栅化，漂浮物是自由度副产品；可微网格走等值面提取，拓扑在提取时被固定。这一段没有优化，只有一次前向加一次转换，所以误差不会被迭代修正——错了就是错了，直接进下游。

输出端，资产进入引擎前的检查清单就是本卷的工程判断落点：UV 接缝、法线方向、材质通道、三角面数、非流形边。前馈模型不负责这些，它只负责把图像 token 映射成潜变量；把这些潜变量变成可用资产，是第八卷结构化潜变量与 PBR、第九卷重拓扑与部件生成要接的活。本卷的边界因此很清晰：它讲的是“一次前向出 3D”的机制、代价和失败模式，不讲下游修补。

最后落在一个具体机制上：摊销的强度由训练分布决定，输出表示的容量由查询 token 和转换方式决定，两者相乘就是前馈模型的能力上限。工程上判断一个前馈模型能不能进管线，不看 demo 的旋转视频，看三件事——批量吞吐下的延迟分布是否可预测、输出表示是否匹配下游、训练分布是否覆盖目标品类。这三件事任何一件不成立，秒级前向就只是把优化的问题换成了数据的问题，而不是消灭了问题。
