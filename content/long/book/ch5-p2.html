一 · 从「渲染图」到「噪声预测残差」：SDS 的数据流骨架

SDS 的输入是一个可微的 3D 表示参数 θ，输出是一个标量损失对 θ 的梯度。中间要穿过一条四段式的数据流：采样相机 → 体渲染出像素 → 加噪到某一步 t → 送进冻结的 2D 扩散模型。这条链上每一段都有明确的张量形状和可微性要求，任何一段断了，梯度就回不来。

第一段是相机采样。给定一个以物体为中心的球面坐标系，随机抽方位角 φ、仰角 ψ、半径 r，构造 look-at 视图矩阵与透视投影矩阵，得到光线原点 o 与方向 d。这一步不可微，也不需要可微——它只是提供「从哪个角度看」的采样点。第二段是体渲染：沿光线积分密度 σ 与颜色 c，得到像素颜色 x。第三段是加噪：抽一个扩散时间步 t，抽标准高斯噪声 ε，按扩散模型的前向过程把干净图像 x 变成 x_t = α_t x + σ_t ε（α_t、σ_t 是噪声调度给出的系数）。第四段是噪声预测：把 x_t、文本条件 y、时间步 t 一起送进 U-Net ε_φ，得到预测噪声 ε_φ(x_t;y,t)。

关键在于：SDS 并不把「预测噪声与真实噪声的差」当作重建目标去反传。它把这个残差当作一个方向信号，乘上一个权重，再乘上渲染雅可比 ∂x/∂θ，才构成对 θ 的梯度。也就是说，扩散模型本身不被训练，梯度只流向 3D 表示。冻结的 2D 先验是一个「打分器」，3D 表示是一个「被纠正的学生」。

$$ \nabla_\theta \mathcal{L}_{\mathrm{SDS}}=\mathbb{E}_{t,\epsilon}\left[w(t)\left(\epsilon_\phi(\mathbf{x}_t;y,t)-\epsilon\right)\frac{\partial \mathbf{x}}{\partial \theta}\right] $$

这个式子里有三个可调旋钮，它们的作用完全不同。w(t) 是时间步权重，控制「听哪个噪声等级的话」；ε_φ − ε 是残差，方向指向「更像文本描述的图像」；∂x/∂θ 是渲染雅可比，把像素空间的修正翻译成 3D 参数的修正。理解 SDS 的工程行为，本质上就是理解这三项各自在什么条件下会失真。

二 · 为什么残差能当梯度：得分匹配的视角

要理解 ε_φ − ε 为什么有意义，得回到扩散模型的训练目标。去噪模型 ε_φ 在训练时最小化 E‖ε − ε_φ(x_t;y,t)‖²，其最优解与数据分布的对数密度梯度（得分）成正比：ε_φ(x_t;y,t) ≈ −σ_t ∇_{x_t} log p_t(x_t|y)。也就是说，预测噪声本质上编码了「当前带噪图像应该往哪个方向移动才能更接近条件数据分布」。残差 ε_φ − ε 就是把这个得分方向取出来，作用在干净图像 x 上。

如果把 SDS 看成对渲染图像分布 p_θ(x|y) 与真实图像分布 p(x|y) 之间 KL 散度的近似优化，那么对 θ 求导会得到一个涉及 ∇_x log p(x|y) 的项。SDS 用扩散得分替代了不可得的真实得分，同时用一个权重 w(t) 吸收不同噪声等级下的缩放差异。这就是「Score Distillation」名字的由来：把 2D 得分函数蒸馏进 3D 参数。

但这里有一个常被忽略的细节：SDS 的梯度不是任何真实损失的精确梯度。它是一个有偏估计。偏差来源有三：其一，扩散得分是在带噪图像上估的，把它直接用在干净图像上需要假设；其二，w(t) 的选择改变了不同频率成分的相对权重，选错会让几何变糊或纹理变噪；其三，单张渲染图的条件分布 p(x|y) 并不约束多视角之间的联合分布。第三点正是后面所有「视角不一致」问题的根源，也是本卷反复出现的胎记。

用一个具体例子走通：文本 y = 「一只孔雀」。初始化一个低分辨率哈希编码 NeRF，参数 θ 随机。第一轮抽到正面相机，渲染出一团灰雾 x。抽 t = 0.6（中等噪声），加噪后送进 Imagen 类的扩散模型。模型在文本条件下预测噪声，残差指向「这里应该有尾羽的扇形结构、蓝绿色的头部」。这个残差经 ∂x/∂θ 回传，更新哈希表里被正面光线穿过的那些格点。几轮之后，正面开始出现扇形。但背面相机抽到时，同一批参数在背面渲染出的仍是雾，扩散模型对背面的残差同样给出「像孔雀」的修正，于是背面也长出扇形——可它与正面的扇形在 3D 空间里并不共享同一套几何，只是各自在各自视角下「看起来合理」。这就是 Janus 的胚胎。

三 · 渲染雅可比：梯度如何从像素回到 3D 参数

∂x/∂θ 是整条链上计算量最大、也最容易出错的一环。对 NeRF 类表示，一个像素的颜色是沿光线 N 个采样点的加权和：x = Σ_i T_i (1 − exp(−σ_i δ_i)) c_i，其中 T_i 是累积透射率。对 θ 求导要穿过 σ_i 和 c_i 两层网络，还要穿过 T_i 里对前面所有 σ_j 的依赖。显式写出这一项会得到一个 O(N²) 的稠密雅可比，工程上不可行。

实际做法是不显式构造雅可比，而是用反向传播：把 SDS 残差当作像素上的「上游梯度」g = w(t)(ε_φ − ε)，直接对渲染过程做一次反向传播，得到对 θ 的梯度。这等价于 gᵀ ∂x/∂θ，但计算量是 O(N) 而不是 O(N²)。代价是每次 SDS 迭代要做一次完整的前向渲染加一次反向渲染，显存占用与光线采样数成正比。这是 SDS 慢的第一个来源：它不是慢在扩散模型的前向，而是慢在「每步都要渲染一遍再反传一遍」。

第二个代价来自数值稳定性。体渲染的透射率 T_i 是连乘，深层采样点的梯度会被指数衰减。当密度场还没收敛、σ 大面积接近零时，很多采样点的梯度接近于零，只有少数「碰巧有密度」的点在更新。这导致早期训练对初始化敏感：如果初始密度太低，正面相机更新了几个点之后，背面相机看到的仍是空场，梯度几乎为零，训练会卡在「只有一面有东西」的局部解。工程上的对策是给密度一个小的初始偏置，或者用较低的渲染分辨率先跑一段，让梯度覆盖更多采样点。

第三个代价是哈希编码的碰撞。多分辨率哈希把空间切成不同尺度的格点，每个格点存一个特征向量。当两个相距较远的 3D 点映射到同一格点时，它们的梯度会叠加，导致「这边更新、那边也动」。在 SDS 里这表现为：正面相机的更新意外地改变了背面的外观。分辨率越低的哈希层碰撞越严重，所以调参时通常先让低分辨率层收敛出大致形状，再放开高分辨率层补细节——这与工匠笔记里「先相机、再 CFG、再 w(t)、最后步数」的顺序是两套不同的旋钮，前者管表示容量，后者管监督信号。

四 · 时间步与 CFG：两个旋钮如何改变几何与颜色

w(t) 的选择直接决定 SDS 优化的是「大形状」还是「细纹理」。扩散过程早期（t 大）对应高频噪声，模型主要在恢复全局结构；后期（t 小）对应低频噪声，模型在修补细节。如果 w(t) 在大 t 上给高权重，梯度偏向全局形状，几何收敛快但纹理糊；如果在小 t 上给高权重，纹理变锐但几何容易在早期就锁死在错误拓扑上。DreamFusion 用的是与噪声调度相关的一族权重，工程上常见的做法是按 t 做分段或单调衰减，而不是均匀权重。

CFG（无分类器引导）是第二个旋钮。扩散模型同时估有条件噪声 ε_φ(x_t;y,t) 和无条件噪声 ε_φ(x_t;∅,t)，引导后的预测是 ε_φ + s·(ε_φ(x_t;y,t) − ε_φ(x_t;∅,t))，s 是引导强度。s 越大，残差越强烈地指向文本，但残差本身也被放大。在 2D 生成里这表现为颜色饱和、对比度拉高；在 SDS 里，这个被放大的残差经雅可比回传，会把颜色通道推到极值，出现「过饱和」的胎记。更麻烦的是，过饱和的颜色会「粘」在几何上：一旦某个视角把颜色推到饱和，相邻视角的梯度会试图解释这个饱和色，纹理就在视角边界处糊成一片。

这里有一个具体的失败模式值得展开：假设文本是「一只红色的鸟」。CFG 拉到很高时，正面相机把胸口的颜色推到纯红。背面相机抽到时，同一批参数在背面渲染出的颜色也被拉向红，但背面的几何还没长好，红色就涂在了一团没有结构的雾上。等背面几何后来长出来，红色已经和错误的法线、错误的遮挡关系绑定，再想改就得靠更大的梯度把它拽回来——而大梯度又会破坏正面已经收敛的部分。这就是「颜色粘在纹理上」的机制：颜色和几何共享同一套参数，SDS 没有显式的解耦，两者的更新互相污染。

Fantasia3D 的解耦正是针对这一点：把几何（法线/密度）和外观（颜色/材质）分成两套参数，几何阶段只用与几何相关的监督，外观阶段冻结几何。代价是两阶段之间的误差会累积——几何阶段的偏差在外观阶段无法修正，外观阶段的纹理也无法反过来纠正几何。这是「解耦换稳定、稳定换精度」的典型工程权衡。

五 · 一个完整迭代的伪代码与它的系统账单

把上面四段拼起来，一次 SDS 迭代的伪代码思路如下（不写具体框架调用，只写控制流）：

  • 从相机分布中抽一个相机位姿 P，要求覆盖方位角全周、仰角在合理范围内；
  • 用当前 θ 渲染出低分辨率图像 x = render(θ, P)，同时保留渲染图对 θ 的计算图；
  • 抽时间步 t ~ Uniform(t_min, t_max)，抽噪声 ε ~ N(0, I)；
  • 构造 x_t = α_t x + σ_t ε；
  • 前向扩散模型得到 ε_φ(x_t;y,t) 与 ε_φ(x_t;∅,t)，按 CFG 组合成引导预测；
  • 计算残差 g = w(t)·(引导预测 − ε)，把它作为 x 的上游梯度；
  • 对渲染计算图做反向传播，得到 ∇θ；用优化器更新 θ；
  • 每隔若干步，把相机分布、w(t) 或 CFG 按课程调整一次。

这张账单上有四项开销。第一项是渲染：每步一次前向加一次反向，分辨率越高、采样点越多越贵。第二项是扩散前向：每步两次 U-Net 调用（有条件与无条件），这是固定成本，与 3D 表示无关。第三项是显存：计算图要保留渲染中间量，哈希编码的特征表本身也占显存，两者叠加常常是瓶颈。第四项是迭代步数：SDS 收敛慢，因为每步只从一个相机得到一个有偏的梯度，方差大，需要很多步平均。

DreamGaussian 用 3DGS 替换 NeRF 正是针对第一项和第四项：高斯泼溅的光栅化比体渲染快得多，且显式基元让梯度只作用在少数高斯上，单步成本大幅下降，于是可以把步数压到分钟级。代价是几何粗糙——高斯没有干净的等值面，提取网格时容易出现空洞和毛刺。Magic3D 的两阶段则是针对分辨率：粗 NeRF 阶段用低分辨率快速收敛拓扑，DMTet 精修阶段用可微网格提取把细节拉到高分辨率。代价是两阶段之间要调参，粗阶段的错误拓扑在精修阶段很难纠正。

把这些放在一起看，SDS 的工程判断就很清楚：它是一条「没有 3D 数据时最便宜的路径」，但每一步都在用有偏的 2D 先验做监督，偏差不会自己消失，只会被工程补丁压住。相机分布不全，背面必崩；CFG 过高，颜色必饱和；w(t) 选错，几何与纹理必有一头糊。这些不是调参玄学，而是公式里三项各自的失真条件在具体系统上的投影。
