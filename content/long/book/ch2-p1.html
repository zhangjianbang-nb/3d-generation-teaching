一 · 从一张卡住的显卡说起

设想一个具体的工程现场：一台工作站上跑着一个 NeRF 训练脚本，场景是一间摆满书架的屋子。相机绕书架拍了八十来张照片，脚本已经跑了三个多小时，loss 曲线还在缓慢下探，而工程师想做的只是「把中间那排书的书脊文字看清楚一点」。他打开可视化窗口，想拖动视角检查背面那面墙有没有学歪，结果每拖动一次，画面要等十几秒才刷新。这不是显卡坏了，也不是代码写错了，而是第一卷那套答案的固有节奏：一个多层感知机（MLP）被要求同时记住「书架整体的空间布局」和「第三层某本书脊上的一道烫金压痕」，而它每次回答任何一个空间点的颜色与密度，都要把整个网络的权重从头乘一遍。

第一卷《雾与光》给出的核心答案是：把场景表示成一个连续的隐式函数，用可微体渲染把 2D 像素的误差反传回这个函数，于是不需要显式几何也能从多视图重建出 3D。这个答案在数学上是干净的，在工程上却是「慢」的。慢不是一处慢，而是三处叠加：训练要几小时到几天，因为每个像素的每条光线要采样几十上百个点，每个点都要过一次 MLP；渲染要几十秒一帧，因为推理时同样要重复这个昂贵的查询；调参周期被拉长，因为一次实验的反馈延迟以小时计，工程师的迭代节奏被硬生生压成了「提交任务、去吃饭、回来看结果」。

这一卷要回答的问题因此非常具体：能不能在不放弃可微渲染这套骨架的前提下，把「记细节」这件苦力活从 MLP 手里拿走，交给某种可以被常数时间查询的结构？ 以及更进一步：能不能干脆不查询，而是把辐射场拆成一堆可以被并行光栅化的显式基元？ 这两个问法分别通向多分辨率哈希编码与 3D 高斯泼溅，它们共享同一个思想转向——把隐式的神经网络换成显式的、可查的或可光栅化的结构。

二 · 慢在哪里：一次查询的成本账

要把问题问准，得先把「慢」拆成可计量的项。NeRF 的体渲染积分沿一条光线采样 N 个点，每个点查询一次辐射场得到颜色 c 与密度 σ，再按从前往后的 alpha 合成累加。写成离散形式：

$$ \hat{C}(\mathbf{r}) = \sum_{i=1}^{N} T_i \left(1 - e^{-\sigma_i \delta_i}\right) \mathbf{c}_i, \qquad T_i = \exp\left(-\sum_{j

这里的成本结构是：一条光线 N 次网络前向，一次前向若 MLP 有 D 层、每层宽 W，则约 2·D·W² 次乘加。一张 1080p 图约两百万像素，每条光线 N 取 64 到 128，于是一帧渲染要过亿次网络前向。训练时每个 batch 还要再乘上反传的代价，通常是前向的两到三倍。这就是「渲染几十秒、训练几小时」的来源，它不是常数因子的问题，而是「每查一个点都要重算整个网络」这一结构性事实。

更麻烦的是，MLP 的容量被两种互相冲突的需求撕扯。低频的全局结构（墙在哪、地板在哪）需要网络权重在空间上平滑；高频的局部细节（书脊文字、木纹）需要网络在极小邻域内剧烈变化。一个固定宽度的 MLP 要同时满足两者，只能靠把宽度堆大、把位置编码的频率堆高，而这两条都会让每次查询更贵。这就是上一卷答案不够用的第一个层面：它不是精度不够，而是「精度」与「查询成本」被绑死在同一组权重上，无法解耦。

第二个层面是可控性。MLP 是一个黑箱：你想删掉场景里的一把椅子，没有办法在权重里定位「椅子」这件事；你想把某个区域的分辨率调高，也没有接口。所有编辑都得重新优化，而重新优化又是几小时。工程上这意味着 NeRF 更像一件「烧制好的瓷器」，而不是一个可以反复改动的模型。

第三个层面是失败模式的隐蔽性。MLP 在稀疏视角下会把训练视角「记」进权重里，换一个视角就出现雾状拖影；这种失败不会在训练 loss 上明显暴露，因为 loss 只在训练视角上算。工程师看到的是一条漂亮的下降曲线和一个一换视角就崩坏的场景。这种「训练指标与真实质量脱钩」的问题，在显式结构里反而更容易被诊断——因为你可以直接去看那些基元。

三 · 一个具体场景：书架、萤火虫与两种拆法

把镜头拉回那间书架屋子。屋子有一面墙的书架，架上几百本书，书脊颜色各异，有几本摊开放在桌上，窗外是傍晚的天光。要重建这个场景，工程师面对的是两种截然不同的「记细节」策略。

第一种策略是建书架：预先准备好一排排大小不同的格子，粗格子记「这一带是书架还是墙」，细格子记「这一格里有几本书、书脊什么颜色」。查询一个空间点时，先看它落在哪个粗格子，再看它落在哪个细格子，把各层格子里存的特征拼起来，交给一个小网络解码成颜色与密度。这就是多分辨率哈希编码的直觉：L 层不同分辨率的网格，每层 T 个桶、每桶 F 维特征，查询时各层各查一次，拼接后送入小 MLP。粗层记大局，细层记细节，而「格子不够用」导致的冲突由多层平均与梯度来消化。它的代价是显式的：哈希冲突会让不同空间位置共享同一个桶，网格分辨率越高、桶数越少，冲突越严重；显存随层数与桶数线性增长。

第二种策略是放萤火虫：不去建格子，而是往空间里撒一百万只各向异性的萤火虫，每只萤火虫有自己的位置、朝向与形状（协方差）、亮度（不透明度）和颜色（球谐系数）。渲染时把每只萤火虫投影到屏幕上，按深度排序，从前往后做 alpha 合成。这就是 3D 高斯泼溅：场景不再是连续场，而是一堆可排序、可并行光栅化的基元。它的代价同样显式：显存随高斯数量线性增长，一百万只萤火虫就是一笔可观的显存账；透明与反射这类需要「光线穿过并改变方向」的现象，用各向异性高斯很难表达；稀疏视图下，高斯会挤在训练视角附近，形成「记住视角」的伪影。

两种拆法共享同一个判断：把「记细节」从需要反复求值的隐式函数，搬到可以被常数时间访问或并行处理的显式结构上。 书架把细节变成可查的表，萤火虫把辐射场变成可排序的基元。速度的来源不是更聪明的数学，而是更笨但更快的存储与并行。

四 · 为什么上一卷的答案不够：三个不可回避的缺口

把上一卷的答案放到这个场景里检验，会看到三个缺口，每一个都不是「再调调超参」能补上的。

第一个缺口是查询复杂度与表达力的耦合。NeRF 的表达力来自 MLP 的权重，而查询成本也来自同一组权重。想提高细节，就得加宽加深网络或提高位置编码频率，两者都直接推高每次查询的成本。哈希编码把这个耦合拆开了：表达力来自表的容量（层数、每层桶数、每桶特征维数），查询成本却固定为「L 次哈希查找 + 一次小 MLP 前向」，与表的容量几乎无关。这就是为什么训练能从小时降到分钟——不是 MLP 变聪明了，而是它被降级成了一个只做局部解码的小角色，真正记事的活交给了表。

第二个缺口是渲染的并行度。NeRF 的体渲染是「每条光线串行地走 N 个点」，光线之间可以并行，但单条光线内部是串行的 alpha 合成，且每个点的查询都要等网络前向。3DGS 把这个问题翻了过来：每个高斯独立投影、独立着色，光栅化阶段按屏幕 tile 并行，深度排序后做前向合成。1080p 能跑出实时帧率，靠的不是更少的计算，而是把计算组织成了 GPU 擅长的形式——大量独立基元、规则的 tile 划分、可预测的访存。代价是显存随高斯数增长，且排序本身有成本。

第三个缺口是可控性与可诊断性。MLP 权重里没有「椅子」这个实体，而高斯集合里每一只萤火虫都是一个可寻址的对象：你可以删掉一片高斯来移除漂浮物，可以按不透明度阈值剪枝，可以按位置做区域编辑。哈希表同样提供了粗粒度的可控性：调高某一层的分辨率就能局部提细节。这种「结构即接口」的性质，是上一卷的纯隐式表示给不了的。反过来，显式结构也带来了新的工程复杂度：哈希冲突要调、高斯致密化要调、显存要管——这些正是本卷后面要逐项拆解的内容。

把三个缺口合起来看，上一卷的答案不够，不是因为它在数学上错了，而是因为它在工程上把「表达力、速度、可控性」三件事捆在了同一个不可分割的隐式函数里。这一卷的两条路线，本质上都是在做同一个解绑动作：把表达力交给显式结构，把解码交给小网络或光栅化器，把可控性交给可寻址的基元或可调的网格层。

五 · 两条路线的分岔口：先问下游

书架与萤火虫不是互相替代的关系，而是分岔口两侧的两条路。选哪条，取决于下游要什么。这个判断在工程上必须先做，因为它决定了后面所有的调参重点。

方法表示训练时间量级渲染主要代价
NeRFMLP 辐射场小时–天慢逐场景优化
Instant-NGP多分辨率哈希 + 小 MLP分钟快哈希冲突/显存
3DGS各向异性高斯分钟–小时实时显存随高斯数增长

如果下游是「照片级静态重建」，比如文物数字化、建筑存档，那么哈希编码这条路仍然值得：它保留了体渲染的连续性，对透明、薄结构、镜面反射的表达比高斯更自然，且小 MLP 的解码让颜色过渡平滑。它的代价是训练仍需分钟级、渲染不是实时，但存档场景不需要实时交互，这个代价可以接受。

如果下游是「实时预览与编辑」，比如室内设计工具、游戏场景快速原型，那么 3DGS 更合适：光栅化并行、1080p 实时、每只高斯可寻址，编辑响应快。代价是显存随高斯数增长，透明与反射难，稀疏视图容易记住训练视角。这三条代价在选型时不是「以后再说」的细节，而是决定项目能不能落地的主约束——一个显存 24GB 的卡能装多少高斯，直接决定了场景的复杂度上限。

这里有一个容易踩的坑：把「训练快」误当成「整体快」。哈希编码训练分钟级，但渲染仍不是实时；3DGS 渲染实时，但训练仍需分钟到小时，且致密化过程会反复增加高斯、推高显存。工程判断应该落在「下游最在意的那一项」上，而不是笼统地比训练时间。

3DGS 的调参也印证了这种「结构即接口」的性质。工匠笔记里记着三件事：高斯初始化是否覆盖背面、致密化间隔是否让薄结构分裂、不透明度阈值是否把漂浮物剪掉。初始化只覆盖可见面，背面就会长出一层「补丁」——这是稀疏视图记住视角的一种具体形态；致密化太激进，显存会爆——这是显式结构把存储代价摆到明面上的直接后果。这三件事在 NeRF 里没有对应物，因为 NeRF 根本没有「初始化高斯」这个步骤。换一种表示，就换了一整套失败模式与调参语言。

投影协方差的计算也体现了这种结构差异。高斯从世界坐标投到屏幕时，协方差要经过雅可比与视图变换：

$$ \Sigma' = J\,W\,\Sigma\,W^{\top}J^{\top},\qquad \Sigma=R\,S\,S^{\top}R^{\top} $$

其中 Σ 由旋转 R 与缩放 S 构成，W 是视图变换，J 是投影的雅可比。这个式子说明：高斯的形状不是随便给的，它必须与投影几何一致，否则屏幕上的椭圆会与真实投影不符，合成时出现拉伸或空洞。这是显式基元路线特有的工程约束——每一个基元的参数都要与相机模型对齐，而 NeRF 的 MLP 不需要关心这件事，因为它的「基元」是空间点，不是有形状的实体。

六 · 本卷要拆的那台机器

把这一卷要回答的问题收拢成一句工程判断：速度不是靠更聪明的数学换来的，而是靠把「记细节」的活从需要反复求值的隐式函数，搬到可查的表或可光栅化的基元上；换来的速度与可控性，要用存储与工程复杂度来付账。 哈希编码把细节变成 L 层网格里的桶，查询固定为「L 次查找 + 小 MLP 解码」，冲突由多层平均与梯度消化；3DGS 把辐射场变成百万个各向异性高斯，投影、排序、alpha 合成全部并行，显存随高斯数线性增长。

这两台机器的共同骨架是「显式结构 + 轻量解码器」：哈希表是结构，小 MLP 是解码器；高斯集合是结构，光栅化器是解码器。骨架相同，失败模式却完全不同——哈希的失败是冲突与分辨率不匹配，高斯的失败是显存、透明反射与稀疏视图记忆。这意味着本卷后面要拆的，不是一套通用的「显式表示调参法」，而是两套各自独立的工程语言：一套围绕层数、桶数、特征维数与冲突率，一套围绕初始化、致密化、不透明度阈值与排序成本。

回到那间书架屋子。工程师最终可能会发现，他真正想要的不是「把书脊文字看清楚」，而是「在拖动视角时立刻看到书脊文字」。这个需求把问题从「提高表达力」改写成了「降低单次查询与单帧渲染的成本」，而后者正是这一卷两条路线共同瞄准的靶心。选哈希还是选高斯，取决于他是想保留体渲染的连续性，还是想要光栅化的实时性——这个分岔口，就是本卷要逐项展开的工程判断。
