一 · 把“选哪条路线”写成一道可计算的题

前十一卷各自拆开了一条技术路线：可微渲染把 2D 监督变成 3D 场，哈希编码把查表换进体渲染，3DGS 把显式基元交给光栅化，SDF 与 Eikonal 正则把表面逼干净，三平面把 3D 降成 2D 卷积，SDS 把 2D 扩散先验蒸进 3D，多视图扩散让背面也讲得通，前馈大模型一次前向出资产，重拓扑把三角面变成可绑定的语言，场景与物理管线把房间变成可漫游的世界，数据与材质管线把 Objaverse、UV 与 PBR 变成地基。每一卷都在回答“这条路怎么走通”。第十二卷要回答的是另一个问题：给定任务，走哪条路。这个问题不能靠“最新”回答，只能靠“匹配”回答。

把选型写成一道带约束的优化题，是本卷的第一个动作。设候选方法集合为 $m$，任务匹配度 $M(m)$ 描述该方法输出与下游需求的契合程度（例如下游要的是水密网格，那么输出高斯泼溅的方法匹配度就低），质量 $Q(m)$ 描述在该任务评测协议下的表现，成本 $C(m)$ 包含显存、训练/推理时间与数据准备开销，集成风险 $R(m)$ 包含许可、长尾失效、背面真实性、拓扑可用性等。选型规则写成：

$$ \text{选型}=\arg\max_{m}\ \frac{\text{任务匹配}\cdot\text{质量}}{\text{成本}+\text{集成风险}} $$

这道题的工程意义在于：它把“论文分数”从分子里的唯一项降级为分子里的一个因子，并把分母显式化。很多团队踩的坑不是选了一个差方法，而是选了一个分子很高、分母爆炸的方法——比如为了一个静态展示任务上了前馈大模型，结果发现 UV 展开与 PBR 分解没做，资产进引擎后无法重光照，回头补数据与材质管线的成本远超预期。公式里的乘法结构也说明：任务匹配为零时，质量再高结果也是零。一个输出点云的方法，质量分数再漂亮，也不能直接喂给需要三角面拓扑的绑定管线。

需要强调的是，这道题不是一次性求解，而是带反馈的。工程上通常先按公式粗筛出 1–2 个候选，再用小样本 A/B 验证，把验证中暴露的失败模式回填到 $R(m)$ 里，再决定是否换路线。公式的价值不在于算出精确数值，而在于强迫团队把“下游要什么、预算多少、风险在哪”三项写在纸上。这三项写不完，说明需求还没收敛，此时追 SOTA 只是把不确定性往后推。

二 · 一个具体场景：从一张照片到一个能进引擎的资产

设想一个具体任务：美术给了一张角色正面照片，要求产出一个能进游戏引擎、能重光照、能绑定骨骼、能在实时预览里旋转的资产。这个任务把八方向里的至少五条路线同时拉了进来，任何单一路线都无法独立完成。

第一步是几何与外观的初始重建。若只有单图，前馈大模型是批量生产的入口：LRM 一类方法一次前向出三平面，TripoSR 把速度压到可用区间，InstantMesh 用稀疏视图大重建模型出网格，CRM 用卷积重建模型出带纹理网格。这些方法的共同代价是背面与长尾：单图看不到的背面由先验补，补出来的背面在旋转到侧后方时容易出现几何塌陷或纹理拉伸。若任务允许拍多视角，NeRF/哈希路线在照片级静态重建上仍然值得，代价是每资产需要一段训练时间与显存；若要求实时预览与编辑，3DGS 是更匹配的表示，代价是显式基元带来的存储与压缩问题，以及从高斯到网格的转换损失。

第二步是表面清理。引擎与 3D 打印要的是干净表面，SDF/网格路线（NeuS、VolSDF、MeshLRM）在这一步不可替代。SDF 的 Eikonal 正则让表面附近梯度模长趋近 1，等值面提取得到的是水密性更好的网格；代价是薄结构容易丢、透明与反光材质在体渲染下难以约束。一个具体失败模式：角色披风的薄片在 SDF 重建中被当成噪声抹平，或者被两层等值面夹成一块厚板。此时需要回到多视图或前馈路线补细节，或者引入重拓扑与修复模块。

第三步是拓扑与绑定。前馈模型输出的网格三角面分布由等值面提取决定，面数不均、没有语义部件划分，直接绑定会得到一堆无法预测的形变。重拓扑路线（MeshAnything 一类网格序列化 tokenization、PartCrafter 一类组合式部件潜变量扩散）把三角面变成可生成的 token 序列或部件组合，输出面数可控、部件语义清晰的网格；代价是重拓扑本身是一次生成，可能改变原网格的细节，且绑定与骨骼仍需人工或额外管线。

第四步是材质与重光照。形状-材质双 DiT 与 UV 展开 + PBR 材质分解管线把反照率、粗糙度、金属度拆开，资产才能进引擎重光照；代价是 UV 展开本身可能引入接缝，PBR 分解在无监督条件下存在歧义（同一张图可以由不同反照率与光照组合解释）。第五步是实时预览与交互：3DGS 提供实时渲染，场景/世界管线提供碰撞与漫游，但高斯表示与物理管线之间缺少直接的碰撞几何，需要额外的代理网格。

这个场景说明：八方向不是八个孤岛。场景重建提供可微渲染，原生表示提供潜空间，SDS 提供无数据先验，多视图提供一致性，前馈模型提供规模化，网格手艺提供可用拓扑，场景/世界提供交互，数据/材质提供地基。真正的系统会把它们组合起来，而不是押注单一方法。选型的单位不是“方法”，而是“管线”：一条从输入到下游可用资产的、带明确接口与失败回退的管线。

三 · 为什么上一卷的答案不够

上一卷（第十一卷）回答的是数据与材质的地基问题：Objaverse 的规模决定上限，UV 展开与 PBR 分解让资产能重光照，大规模 3D 资产清洗管线把噪声数据变成可训练语料。那一卷的答案是正确的，但它回答的是“地基怎么打”，不是“给定任务选哪条路”。地基好，不等于选型对。一个团队可以把数据管线做得非常干净，却在选型上押注了一个与下游不匹配的方法，结果资产进不了引擎。

更具体地说，上一卷的答案在三个地方不够用。第一，它给出的是“数据规模决定上限”的定性判断，但没有给出“在有限数据下，哪条路线对数据量最敏感”的排序。前馈大模型对数据规模最敏感，SDS 路线对 3D 数据依赖最低（它蒸的是 2D 先验），SDF/网格路线对多视角覆盖敏感，3DGS 对视角密度与曝光一致性敏感。选型时必须把“我有多少数据”翻译成“哪条路线在我的数据预算内能收敛”。第二，它讲的是清洗与材质分解的通用管线，但没有讲这些管线在不同下游下的接口差异：进引擎要的是 PBR + UV + 合理面数，进 3D 打印要的是水密 + 流形，进动画要的是四边面主导 + 部件语义。同一套数据管线，接口不同，选型就不同。第三，它没有处理“组合”的问题：数据与材质是地基，但地基之上盖什么楼，取决于任务，而任务的多样性要求把多条路线拼成管线，拼接处的接口与失败回退才是工程难点。

还有一个更根本的原因：前十一卷每卷都在自己的评价体系里优化。NeRF 卷看的是新视角合成的 PSNR，3DGS 卷看的是渲染帧率与质量，SDF 卷看的是表面精度与法线一致性，SDS 卷看的是文本对齐与多样性，前馈卷看的是单图重建的相似度与速度。这些指标彼此不可直接比较，把它们放在一张表里排序会得到误导性结论。第十二卷要做的，是把这些不可比的指标翻译成下游需求的语言，再用选型公式重新排序。这一步不是前十一卷任何一卷能单独完成的。

四 · 选型表怎么读：一行一行拆

本卷的选型表把下游需求、优先路线、代表工作与要补的模块并列。读这张表的关键不是记住哪一行对应哪个方法，而是理解每一行里“要补的模块”这一列——它标出了该路线在到达下游可用之前必须跨过的缺口。

第一行“实时预览”选 3DGS，因为高斯泼溅的光栅化把渲染变成按基元排序与混合，帧率与显存的关系比体渲染积分直接得多。缺口在压缩与编辑：显式基元的存储随视角覆盖增长，压缩要处理基元剪枝与量化；编辑要处理高斯的增删改与局部重训，而高斯之间没有拓扑连接，编辑后的物理一致性没有保证。第二行“干净表面/打印”选 SDF/网格，因为等值面提取天然给出封闭曲面，Eikonal 正则让表面附近的距离场性质可控。缺口在水密性与修复：薄结构、开放边界、自交在提取后仍需修复，3D 打印对流形性的要求比渲染苛刻。第三行“文本凭空生成”选 SDS/多视图，因为没有 3D 数据时只能蒸 2D 先验或借多视图扩散补一致性。缺口在一致性与背面：SDS 的分数蒸馏在几何上容易过平滑，多视图扩散的背面由先验生成，两者都需要一致性约束（跨视角注意力、区间分数匹配一类机制）来压住。第四行“批量生产”选前馈大模型，因为一次前向的成本与资产数量线性相关，适合流水线。缺口在 UV/PBR/重拓扑：前馈输出的是三平面、高斯或网格，要进生产管线必须补材质分解与拓扑整理。第五行“可动画拓扑”选重拓扑，因为绑定需要可预测的边流与部件语义。缺口在绑定与骨骼：重拓扑输出的是网格，骨骼与权重仍需额外步骤。第六行“可漫游世界”选场景/物理管线，因为交互需要碰撞体与长距离一致性。缺口在碰撞与长场景：高斯或神经场不直接提供碰撞几何，长场景的一致性会随距离漂移。

这张表的读法是“缺口驱动”：先看下游需求锁定行，再看缺口列判断团队是否有能力补上。如果团队没有压缩/编辑能力，实时预览这一行的 3DGS 就不是匹配选择，可能要退回带网格输出的前馈路线再转实时渲染。选型不是选方法，是选“方法 + 你能补的缺口”的组合。

五 · 组合而非押注：拼接处的三个工程判断

真正的系统会把多条路线组合起来。组合的第一个判断是接口表示。前馈模型输出三平面，SDF 路线要的是隐式函数，3DGS 要的是显式基元，网格管线要的是三角面。三平面可以解码成 SDF 再提取网格，也可以解码成高斯参数；但每次转换都有信息损失：三平面到 SDF 的转换受限于解码器容量，SDF 到网格的等值面提取受限于分辨率，网格到高斯的转换需要采样与属性估计。接口选择的原则是“下游需要什么就保留什么”，而不是“哪条路线最方便”。

第二个判断是失败回退。管线里每一段都要有可检测的失败模式与回退路径。单图前馈的背面塌陷可以用多视图扩散补，SDS 的过平滑可以用区间分数匹配或多视图一致性约束压，SDF 的薄结构丢失可以回到多视角重建或引入法线桥接（Hi3DGen 一类法线桥接思路）。回退不是免费的：每加一段回退，成本与集成风险都上升，选型公式的分母变大。工程判断是：回退段数控制在必要的最小集合，且每段回退的触发条件必须可观测（例如用背面法线一致性、水密性检测、面数分布作为触发信号）。

第三个判断是评测协议。组合管线的质量不能只用单段指标衡量，要用下游任务的端到端指标：进引擎后重光照的视觉一致性、绑定后的形变合理性、打印后的流形性、漫游时的碰撞正确性。评测协议本身是开放问题之一——目前缺少跨方向的统一协议，不同论文的指标不可比。工程上的务实做法是自建小样本 A/B：固定下游任务与预算，用同一批输入跑 1–2 个候选管线，记录失败模式与人工修复时间，用修复时间作为集成风险的代理指标。这比凭论文分数拍板可靠，因为论文分数不包含“补缺口”的成本。

组合的代价也要写清楚：每增加一条路线，就增加一个潜空间、一套训练目标、一组超参与一个失败模式。管线越长，调试的搜索空间越大。工程判断是：先做“最小可行管线”——用一条主路线加一段必要回退，跑通端到端，再按失败模式逐段替换或增强。不要一开始就拼五条路线，那会把选型问题变成管线集成问题，而后者更难定位。

六 · 开放问题就是下一波入口

本卷列出的开放问题——薄结构/透明/反光、背面真实性/长尾、拓扑/动画、物理参数、场景一致性、评测协议、数据许可——每一个都对应上面管线里的一个缺口，也都可能成为下一波论文的入口。薄结构与透明反光是体渲染与 SDF 的共同难点：体渲染积分对薄片的高频细节采样不足，SDF 的等值面在薄片处容易合并；透明与反光让颜色与几何解耦困难，PBR 分解的歧义在这里最明显。背面真实性与长尾是单图与前馈路线的固有缺口：先验能补出“合理”的背面，但补不出“正确”的背面，长尾物体（罕见形状、复杂部件）的先验覆盖不足。拓扑与动画是网格手艺与重拓扑路线的缺口：生成拓扑容易，生成可绑定、可形变、部件语义清晰的拓扑难。物理参数是场景与物理管线的缺口：视频驱动物理参数估计能给出材质与运动参数，但参数的唯一性与可迁移性没有保证。场景一致性是长距离漫游的缺口：高斯泼溅世界扩展与迭代式房间网格补全都在处理漂移，但长场景的全局一致性仍是开放问题。评测协议与数据许可则是选型公式里 $Q$ 与 $R$ 的分母：没有统一协议，质量不可比；没有清晰许可，批量生产的资产不能商用。

这些开放问题的工程含义是：选型时不能假设缺口会被自动补上。一个开放问题如果在你的任务里是关键的，就要在选型公式的 $R(m)$ 里给它加权，或者干脆避开依赖它的路线。例如任务要求打印，薄结构是常见输入，那么 SDF 路线的水密性缺口就是高风险项，要么引入修复模块，要么改用多视角重建加网格修复的组合。反过来，如果一个开放问题在你的任务里不关键（例如静态展示不需要绑定），那么重拓扑路线的绑定缺口就不该阻止你选它。

把开放问题写进选型表，是本卷与前十一卷的分界：前十一卷讲“这条路怎么走通”，本卷讲“这条路在你的任务里通不通、缺口你能不能补、补不上的风险你担不担”。选型时把“下游要什么”写在纸上，再对照八方向表，比追 SOTA 更可靠。最后落在具体机制上：选型公式的分母不是抽象的风险，而是可观测的失败模式与可计量的修复成本；把这两项测出来，选型就从论文阅读变成了工程决策。
