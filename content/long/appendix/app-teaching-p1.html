一 · 条目定义与课程骨架

《教学脚本》在附录里是一条“交付物型”条目，而不是一篇论文摘要。它要交付的东西是可直接在课堂上朗读、板书、发问、布置作业的文本序列，覆盖 45 分钟与 90 分钟两种课时。定义上，教学脚本是“以时间轴为索引的教学事件表”：每个时间片绑定一个教学动作（故事、板书、演示、提问、作业、评估），每个动作绑定一个知识断言和一条验证方式。它与讲义的区别在于讲义按知识结构组织，脚本按课堂节奏组织；它与幻灯片大纲的区别在于大纲只列标题，脚本要写出教师说什么、写什么、问什么、学生做什么。

分类可以沿三个轴切。第一轴是课时长度：45 分钟适合单点机制（例如“NeRF 为什么能从 2D 照片学出 3D”），90 分钟适合对照结构（例如“NeuS 与 VolSDF 的密度参数化差异”）。第二轴是教学动作类型：叙事型（故事开场）、推导型（板书公式）、观察型（演示渲染过程）、诊断型（提问与错答预设）、迁移型（作业）。第三轴是评估锚点：脚本必须显式写出“学生做到什么算过关”，否则课堂会滑向教师独白。三个轴交叉后，一条脚本条目就是一个三元组（课时，动作序列，评估锚点）。

脚本的底层机制是“认知负荷预算”。一节课的工作记忆带宽有限，脚本把每个知识块切成“断言—证据—练习”三拍，每拍不超过一个板书屏。伪代码思路如下：对每个知识块 k，分配时长 t_k，要求 Σt_k ≤ 课时；每个 t_k 内必须出现一次“学生输出”（口头回答、纸上写一行、或指出演示中的一处异常）。系统代价在于：脚本越细，教师自由度越低；脚本越粗，课堂越依赖教师即兴，评估锚点漂移。失败模式是“动作堆叠”——把故事、板书、演示塞进同一分钟，学生只记住故事。具体例子：讲 Instant-NGP 的哈希冲突时，若在同一时间片既放多分辨率分层图又放小 MLP 解码图，学生会把“冲突由多层平均消化”误记成“哈希表不会冲突”。正确做法是把分层图放在板书拍，把小 MLP 放在演示拍，中间插一次提问：“如果只有一层哈希，冲突会怎样？”

二 · 故事开场：把机制藏进困境

故事开场的功能不是活跃气氛，而是制造“认知缺口”：让学生先感到某个直觉不成立，再接受机制。脚本写作要求故事里必须包含一个可被后续板书回指的对象。例如讲 NeRF 时，故事可以是“只有一叠照片和拍照时的站位，没有尺子、没有激光，怎么知道杯子在空间里的位置”。这个故事埋下的缺口是“2D 像素如何约束 3D 位置”，后续板书回指它时，学生能把“5D 输入（位置+视角）”和“体渲染积分与透射率 T”挂到同一个困境上。

机制上，故事开场遵循“缺口—代价—悬念”三段。缺口是直觉失效点；代价是如果不解决会失去什么（例如无法从照片做新视角）；悬念是一个待回答的问句。伪代码：story = (intuition_break, cost_if_unsolved, question_held)。系统代价是时间：故事超过三分钟就会挤占板书；失败模式是“故事与机制脱钩”，学生复述故事却答不出机制。具体例子：讲 pixelNeRF 时，故事可以是“一张照片拍到的背面是黑的，但人知道背面有东西”。缺口是“单视图信息不足”，代价是“逐场景优化太慢”，悬念是“能不能一次前向就补出背面”。后续板书回指“CNN 图像特征 + 3D 点投影到视图采样特征 + amortized 推理”，故事与机制就咬合了。

故事还必须为提问预埋“错误直觉”。脚本写作时，故事里要出现一个看似合理但错误的推论，供后续提问收割。例如讲 SDS 的“两张脸”时，故事可以是“一个雕塑家同时听十个方向的评价，每个方向都说‘往这边转一点’，结果他把正面和背面都雕成了脸”。这个故事的错误直觉是“多视角监督自然一致”，而真实机制是逐视角独立导致 Janus。提问环节就可以问：“为什么每个视角的梯度都对，合起来却错？”学生若答“因为视角太多”，教师可回指“SDS 梯度公式里 2D 得分 + 渲染雅可比是逐视角独立的，CFG/随机相机只是缓解”。

故事开场的评估锚点是“复述测试”：课后让学生用一句话说出故事里的缺口，且这句话必须包含一个机制名词。若学生只能说“讲了拍照”，说明故事没有承载机制，脚本需要重写。另一个失败信号是故事太长导致板书被压缩：45 分钟课时里，故事应控制在两到三分钟，90 分钟课时可到五分钟，但必须切成两段，中间插一次提问，否则注意力曲线会塌。

三 · 板书：一条主公式加一条约束

板书的设计原则是“一屏一主链”。每个知识块只允许一条主公式占据视觉中心，其余符号作为约束或注释环绕。主公式的选择标准是：它必须能回指故事缺口，且能推出一个可观察量。例如讲 NeuS 时，主公式是 SDF 到密度的转换与 Eikonal 约束的组合；约束行写“||∇f||=1，零等值面即表面”。学生看到主公式就知道“表面在哪”，看到约束就知道“为什么表面干净”。若把 β 退火 schedule 也写成第三行公式，主链就被稀释了——β 退火是隐形超参，应放在演示或提问里，而不是板书主屏。

公式的呈现要带“量纲检查”。教学脚本要求板书公式旁写一行“每个符号对应课堂上的哪个对象”。例如 3DGS 的投影公式 Σ'=J W Σ Wᵀ Jᵀ，板书时应标注：Σ 是 3D 协方差，由 R S Sᵀ Rᵀ 分解而来；W 是视角变换；J 是投影雅可比；Σ' 是屏幕上的 2D 协方差。这样学生不会把“协方差分解”和“投影”混成一步。系统代价是板书时间：一行带标注的公式约需一分半，90 分钟课时最多容纳四到五条主公式，超出就必须拆成两次课。失败模式是“公式墙”：教师连写五行，学生抄写但不知哪行是主链，课后作业里出现“把 Eikonal 正则当成渲染损失”的错误。

$$\Sigma' = J\,W\,\Sigma\,W^{\top}J^{\top},\qquad \Sigma = R\,S\,S^{\top}R^{\top}$$

板书的评估锚点是“指认测试”：提问时让学生指出主公式里哪个符号对应故事里的对象。例如讲 VolSDF 与 NeuS 的差别时，板书主公式是 SDF 到密度的 CDF 转换，约束行写“共同依赖 Eikonal 与退火”。提问：“VolSDF 用 Laplace、NeuS 用 logistic，差别在参数化还是正则？”学生若指向“α/β 参数化不同”而非“正则不同”，说明板书把约束和主链分清了。具体例子：讲 InstantMesh 时，板书可写“4 视图 LRM 前向 → 三平面/网格潜变量 → FlexiCubes 可微提取”，主链是“前向重建”，约束是“可微提取保拓扑”。若把 FlexiCubes 写成主公式，学生会以为提取是核心，而实际核心是稀疏视图前向。

板书还要为作业留“接口”。每条主公式旁应有一个空位，作业要求学生填入一个具体数值或一个具体场景。例如讲 GS-LRM 时，板书主链是“高斯输出头 + 光栅化实时”，空位写“显存与漂浮物的权衡”。作业就可以是“给定四个视图，写出高斯输出头相比 NeRF 输出头的两个新问题”。这样板书、作业、评估三点连成线，脚本不会散。

四 · 演示与提问：让中间量可见

演示的教学价值在于“把中间量变成可观察对象”。脚本要求每次演示至少暴露一个中间量，而不是只放最终渲染图。例如讲 NeRF 的体渲染时，演示应展示透射率 T 随采样点变化的曲线，而不是只放一张新视角图。学生看到 T 下降的位置，才能把“分层采样/位置编码”与“遮挡”联系起来。讲 3DGS 的致密化与剪枝时，演示应展示高斯点数随训练步数增长再回落的过程，而不是只放最终场景。中间量可见，提问才有落点。

提问的设计原则是“预设错答”。脚本要求每个提问写出至少一个预期错误答案及其纠正路径。例如讲 NeuS 的 β 退火设错时，提问可以是“β 设大设小分别会怎样”，预设错答是“β 越大越精细”。纠正路径：β 大到表面糊，β 小到薄结构噪/发散，β 退火 schedule 是隐形超参。这个提问把“两类典型失败”变成学生可复述的判断规则。另一个例子：讲 MVDream 的四个视角如何互相看见时，提问“代价是什么”，预设错答是“没有代价”。纠正路径：4 视图 token 拼接 + 3D 自注意力跨视角，计算量×4、视角数固定。学生答错一次，机制就记牢一分。

演示与提问的配比是脚本的节奏核心。45 分钟课时建议“一演示两提问”，90 分钟课时建议“两演示四提问”。系统代价是设备与时间：演示需要预跑，提问需要留白，两者都会挤压讲授。失败模式是“演示即结论”：教师放完演示直接说“所以哈希冲突被多层平均消化了”，学生没有经历推理。正确做法是演示后停十秒，让学生写下“刚才哪个量变了”，再提问。具体例子：讲 SyncDreamer 的 16 个视角同步时，演示应展示共享 3D 代价体在去噪中投影-采样的中间状态，提问“如果没有共享体积，16 个视角会怎样”，预设错答是“各自去噪也能一致”。纠正路径：共享 3D 体积在去噪中起同步作用，缺了它各视角会漂移。

提问还要服务评估。每个提问应绑定一条“过关线”：学生答出某个机制名词算过，答出错误直觉算未过。例如讲 Zero-1-to-3 时，提问“它为什么能零样本换视角”，过关线是学生说出“参考图 + 相对位姿，多视图数据训练，不是直接出 3D”。若学生说“它生成了 3D 模型”，说明把“新视角生成”与“3D 重建”混了，脚本需要在板书里加一行区分。评估锚点不是分数，而是“能否在下一节课复述这条区分”。

五 · 作业与评估：可判定的迁移

作业的功能是“迁移测试”：把课堂机制搬到新对象上，看学生是否还能推出可观察量。脚本要求作业必须可判定，即存在一个明确的正确/错误边界。例如讲 DreamGaussian 的两阶段时，作业可以是“写出少步 SDS 与网格提取 + UV 精修各自解决什么，并指出速度换精度发生在哪一步”。判定边界是：学生若把“3DGS 快速收敛”写成精修阶段的作用，即错。另一个例子：讲 CRM 时，作业是“6 视图输入、卷积精修三平面、输出带纹理网格，为什么卷积比全局注意力便宜”。判定边界是学生能否说出“卷积比全局注意力便宜”与“输入输出”的对应关系，而不是复述“CRM 很快”。

评估的设计原则是“锚点少而硬”。一条脚本只允许两到三个评估锚点，每个锚点对应一个可观测行为：复述缺口、指认主公式符号、写出迁移判断。系统代价是批改成本：可判定的作业需要标准答案，标准答案需要脚本作者预先写出错误清单。失败模式是“评估即印象”：教师凭课堂气氛判断“听懂了”，但学生作业里出现“VSD 与 SDS 的核心差别是模型大小”这类错答。具体例子：讲 VSD 时，评估锚点应是“梯度含 (ε_φ−ε_ψ)，KL/变分视角，多样性/过饱和改善”，学生若只写“VSD 更好”，未过。

作业与评估还要覆盖“失败模式”本身。脚本要求至少一道作业问“这个机制在什么条件下会坏”。例如讲 Shap-E 时，作业问“扩散生成 MLP 权重的好处和代价”，判定边界是“可提取网格/渲染”与“高维参数训练难”必须同时出现。讲 Hunyuan3D 2.0 时，作业问“形状 DiT 与纹理 DiT 拆开的工程好处”，判定边界是“不同数据/目标、分别迭代、误差累积/接口对齐”三者至少两项。这样学生不只会背机制，还会判断机制的边界。

评估的最终落点是“下一节课的起点”。脚本要求在评估锚点旁写一行“若未过，下节课先补哪个中间量”。例如讲 TripoSR 的 0.5 秒重建时，若学生未过“LRM 框架简化 + 三平面 + NeRF 渲染 + 大规模数据训练 + 混合精度/工程优化”这条链，下节课应先补“三平面输出”而非“工程优化”。这个设计让脚本成为可迭代的教学单元，而不是一次性讲稿。

六 · 脚本条目的互指与复用

教学脚本条目不是孤立的，它要与附录其他条目互指。脚本写作时，每个知识块应标注“前置条目”与“后继条目”。例如讲 NeuS 的 β 退火时，前置是“SDF 与零等值面”，后继是“VolSDF 与 NeuS 的密度参数化差异”。互指的作用是防止脚本重复讲同一机制，也防止课堂出现“断层”：学生没学过 Eikonal 正则，却直接被问“β 退火设错会怎样”。系统代价是维护成本：互指关系需要随附录更新而同步，否则脚本会指向已删条目。失败模式是“循环互指”：A 说前置是 B，B 说前置是 A，课堂无法开场。具体例子：讲 SDS 家族时，脚本可把“SDS 梯度形式”作为前置，“SJC 的扰动”“ISM 的区间”“VSD 的粒子模型”作为后继，形成一条从得分到方差的线索，而不是四个孤立故事。

复用机制是“动作模板库”。故事开场、板书、演示、提问、作业、评估六类动作各有模板，写新脚本时只替换知识块。例如“演示模板”要求三行：初始状态、中间量、可观察变化。讲 GS-LRM 时，初始状态是四视图输入，中间量是高斯输出头的光栅化，可观察变化是实时渲染与漂浮物。讲 MeshLRM 时，初始状态是提取不可微的问题，中间量是端到端可微网格的梯度回顶点，可观察变化是拓扑/薄结构更好。模板复用降低写作成本，但代价是“模板化疲劳”：学生发现每节课都是同一节奏，注意力下降。缓解办法是每三节课换一次动作顺序，例如把提问放在故事之前，制造“先错后讲”的张力。

脚本的版本管理也要写进条目。每条脚本应记录“课时、动作序列、评估锚点、互指条目、已知失败信号”。版本更新时，只改失败信号对应的动作，不动主链。例如讲 Instant-NGP 的 L、T、F 三角权衡时，若发现学生总把“L/T/F 的三角权衡”记成“三个独立超参”，就在提问里加一条“调大 L 会挤压谁”，而不改板书主公式。这样脚本的稳定性来自主链不变，迭代性来自失败信号的局部修补。

最后落在工程判断上：教学脚本的质量不取决于文采，而取决于“每个知识块是否有一条可回指的主公式、一个可观察的中间量、一条可判定的过关线”。写脚本时先画三列表——知识块、主公式、过关线——再填故事与提问；若某行填不出过关线，该知识块就不该进这节课，而应拆到下一节或降级为阅读材料。这个判断规则比任何课堂技巧都硬，因为它把“讲得好”翻译成了“学生能复述什么、能指认什么、能迁移什么”。
