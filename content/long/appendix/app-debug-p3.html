一 · 症状到原因的速查矩阵

《失败模式手册》前两部分已经按条目逐个拆过定义、分类和案例。这一部分把手册压成一张可现场使用的矩阵：左手边是你在视口或渲染结果里能直接看到的症状，右手边是对应的机制候选、验证动作和系统代价。矩阵的用法不是“看到症状就套结论”，而是“看到症状先锁定候选集合，再用最小实验把候选集合砍到一条”。工程上最常见的错误是跳过锁定直接调参，结果把多面问题当成过饱和去压 CFG，把 UV 接缝当成纹理分辨率不足去加采样，代价是几小时的每资产优化白跑。

症状优先怀疑的机制最小验证动作典型系统代价

这张表的关键列是“最小验证动作”，它决定了你能否在单次会话内完成归因。矩阵本身不产生结论，它只产生候选集合；候选集合的收敛速度取决于验证动作是否真的只动一个变量。

二 · 三条归因链的伪代码

把矩阵落到可执行层面，需要三条固定的归因链。第一条针对生成类症状（多面、过饱和、PBR 失真），第二条针对重建类症状（表面糊、薄结构噪、漂浮物），第三条针对组装类症状（UV 接缝、场景穿模）。三条链共享同一个结构：先冻结随机性，再单变量扫描，最后用几何或统计量判定。

$$\text{attr}(s)=\arg\min_{c\in C(s)}\ \Delta\big(\text{metric}(s\mid c\ \text{fixed}),\ \text{metric}(s\mid c\ \text{scanned})\big)$$

上式只是形式化表达：对症状 s，在候选原因集合 C(s) 里找那个“固定它时指标不变、扫描它时指标显著变化”的变量 c。工程实现上不需要真的算这个最小值，只需要按下面的伪代码顺序执行。

  • 生成链：固定种子与视角采样 → 扫描 CFG 尺度 → 若多面不消失则扫描视角分布 → 若仍不消失则判定为 2D 先验本身的多视图不一致，转去换先验或多视图扩散模型（MVDream、SyncDreamer 一类）。
  • 重建链：固定相机与采样数 → 扫描 hash 表大小或 β 退火曲线 → 若表面糊随表大小改善则归因哈希冲突；若薄结构噪随 β 改善则归因退火敏感；若漂浮物随稀疏视图数量改善则归因几何不稳。
  • 组装链：固定几何 → 扫描 UV 展开参数或部件数 → 接缝随展开改善则归因 UV；穿模随部件数下降则归因组合逻辑；两者都不动则归因纹理后处理与几何分辨率不匹配。

每条链的失败模式是“扫描了错误的变量”。例如把多面当成过饱和去降 CFG，短程内色域确实变正常，但背面依旧复制正面，于是你误判为已修复。判定标准必须写成“症状是否在固定其他变量后单独消失”，而不是“整体观感是否变好”。

三 · 跨条目对比表：表示、代价与失效面

手册的条目分散在 NeRF、隐式表面、3DGS、前馈重建、多视图扩散、原生 3D 生成几条线上。把它们并排看，会发现失效面几乎由表示本身决定，而不是由训练技巧决定。下表只列给定事实中的失效项，不补数字。

表示/方法族核心机制主要失效面代价来源
NeRF 类单场景优化体渲染 + 单场景过拟合无法前馈泛化；渲染慢；静态、无反射/透明每场景优化；难实时
Instant NGP多分辨率哈希编码哈希冲突丢细节；需按场景调表大小；静态难编辑调表成本；静态表示
NeuS / VolSDF 类体积渲染学隐式表面训练慢；薄结构难；β 退火敏感；两者实际差异不大训练时长；退火调参
3DGS显式高斯 + 实时光栅显存开销大；透明/反射弱；稀疏视图几何不稳显存；稀疏视图不稳

对比表暴露一个规律：失效面与“表示是否显式、是否静态、是否依赖 2D 先验”强相关。显式表示（3DGS、点云、网格）的代价集中在显存与拓扑合法性；隐式表示（NeRF、NeuS）的代价集中在训练时长与退火调参；依赖 2D 先验的管线（SDS、多视图扩散）的代价集中在多视图一致性与背面幻想。归因时先问“这个症状属于哪一族的固有失效面”，再问“是不是调参没到位”，顺序反了就会把固有失效当成可调参数。

四 · 自测题：从症状反推机制

以下自测题不给答案选项，只给判定标准，目的是训练“先锁定候选集合再验证”的习惯。每题都对应前两部分出现过的一个条目，答错通常意味着把固有失效面误当成调参问题。

  • 题一：单图重建结果正面清晰、背面出现与正面相同的纹理。判定标准：固定种子只改视角采样，若背面纹理不随视角变化而消失，则归因多视图一致性不足而非纹理分辨率。对应 Zero-1-to-3、SyncDreamer 一类的一致性不足与背面幻想。
  • 题二：隐式表面重建的薄壳在渲染中呈噪点状，加采样数无效。判定标准：冻结 β 只改退火曲线，若噪点随 β 变化则归因退火敏感；对应 NeuS 的 β 退火敏感与薄结构难。
  • 题三：哈希编码重建的表面在高频区域发糊，换更大网络无效。判定标准：只调 hash 表大小与层级分辨率，若发糊改善则归因哈希冲突；对应 Instant NGP 的哈希冲突导致细节损失。
  • 题四：3DGS 场景在稀疏视图下出现漂浮高斯团。判定标准：增加视图数后漂浮物是否收敛；若不收敛则归因稀疏视图几何不稳，而非高斯数上限。
  • 题五：文本到 3D 结果颜色过饱和且多面并存。判定标准：先降 CFG 看色域，再改视角分布看多面；两者独立则说明过饱和与多面是两个机制，不能用一个参数同时修。
  • 题六：部件化生成的模型在关节处出现穿插。判定标准：按部件导出包围盒做相交测试，若相交发生在部件数增加后，则归因组合逻辑而非单部件几何精度；对应 PartCrafter 的部件数易错与缝隙/穿插。

自测的评分不看“答对几个”，而看“验证动作是否单变量”。一个能在两次短程实验内把候选集合从五条砍到一条的读者，比背下所有条目定义的读者更接近手册的使用方式。

五 · 延伸阅读的取舍原则

手册引用的文献覆盖了从 NeRF 到 Hunyuan3D 2.1 的整条线，但延伸阅读不能按时间顺序铺开，而要按“失效面是否可复现”取舍。给定事实里已经点出几个取舍信号：3DGS 综述因快速迭代导致时效性有限、部分工作只有预印本、缺少统一基准实验；NeuS 与 Volume Rendering of Neural Implicit Surfaces 在实际中差异不大；Score Jacobian Chaining 实现复杂、方差大、质量提升有限。这些信号本身就是取舍依据：差异不大的两条线只需读一条，时效性有限的综述只用来建立术语地图，不作为结论来源。

取舍原则可以写成三条。第一，读“失效面被明确列出”的工作，而不是读“指标最高”的工作；手册的条目几乎都来自前者。第二，读“代价被量化描述”的工作，例如每资产数小时、显存翻倍、序列长度限制，这些描述直接对应工程预算。第三，读“管线完整”的工作而非“单点技巧”的工作，因为手册的多数症状发生在管线衔接处（误差传导、纹理后处理、UV 失败），单点技巧的论文通常不覆盖衔接。

$$\text{read}(p)=\mathbf{1}\big[\text{failure}(p)\ \text{explicit}\big]\cdot\mathbf{1}\big[\text{cost}(p)\ \text{quantified}\big]\cdot\mathbf{1}\big[\text{pipeline}(p)\ \text{complete}\big]$$

这个指示函数不是严格评分，只是提醒：三个条件缺一个，这篇文献对手册的使用价值就下降一档。例如只有预印本且缺少统一基准的工作，可以用来确认“某症状存在”，但不能用来确认“某方法修复了该症状”。

六 · 把清单变成回归用例

速查表、对比表和自测题最终要落到回归用例上，否则手册只是一份阅读材料。回归用例的最小结构是：一个固定输入、一个固定种子、一个症状判定函数、一条单变量扫描轴。判定函数必须是可计算的，例如多面用“背面视角与正面视角的纹理相似度”、漂浮物用“主体包围盒外的连通块数量”、UV 接缝用“跨缝纹素梯度突变计数”、穿模用“部件包围盒相交对数”。这些量不需要精确阈值，只需要在同一管线内可比较。

回归用例的失败模式是“判定函数与症状脱钩”。例如用整体 LPIPS 判定多面，会把“整体变清晰但背面仍复制正面”判为通过；用渲染图判定穿模，会被遮挡关系掩盖。工程判断是：每个症状至少配一个几何量或统计量作为判定函数，渲染图只作为辅助。这样做的代价是每次管线变更都要重跑全部用例，但收益是症状在进入资产验收前就被拦截，而不是等到下游才发现 UV 接缝或 PBR 失真。

最后落在具体机制上：手册的八个症状里，多面、过饱和、表面糊、薄结构噪、漂浮物、UV 接缝、PBR 失真、场景穿模，没有一个能靠单一参数修复，因为它们的候选原因跨越了表示、先验和管线衔接三层。速查矩阵的作用是把这三层压成一张可现场查的表，自测题的作用是训练单变量验证，回归用例的作用是把验证固化成可重跑的判定。三者合起来，才是《失败模式手册》从条目走向工程判断的完整路径。
