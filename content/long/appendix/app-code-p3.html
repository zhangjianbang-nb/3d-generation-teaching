一 · 最小跑通清单：从仓库到第一帧

把“代码与工具”落到工程现场，第一件事不是读论文，而是把一条最小可跑通的链路搭起来：环境、依赖、数据、命令、显存。附录条目给出的代表实现——NeRF、3DGS、NeuS、LRM、TRELLIS、MeshAnything——语言与依赖各不相同，但最小跑通的结构是同构的：一个配置入口、一个数据加载器、一个训练循环、一个渲染/导出脚本。区别只在“表示”这一层：NeRF 是 MLP + 体渲染积分，3DGS 是显式高斯集合 + 可微光栅化，NeuS 是 SDF 网络 + 温度映射，LRM/TRELLIS 是 Transformer 输出三平面或结构化潜变量，MeshAnything 是自回归面片 token。

清单应当按“失败点”排序，而不是按目录排序。第一层是驱动与 CUDA 版本：哈希编码、高斯光栅化、可微 Marching Cubes 都含自定义 CUDA 算子，编译失败通常发生在 nvcc 与 PyTorch 的 ABI 不匹配上，而不是 Python 语法。第二层是数据契约：NeRF 类实现要求 transforms.json 式的相机内外参与图像路径；3DGS 要求 COLMAP 稀疏点云作为初始化；NeuS 要求带掩码的多视图；LRM 类要求单图或少量视图且相机归一化到统一规范。第三层是显存门槛：体渲染沿射线采样 N 个点，显存随“射线数 × 采样数 × 网络宽度”增长；3DGS 的显存随高斯数量线性增长，致密化阶段是峰值；三平面生成的显存随平面分辨率平方增长。第四层是评估脚本：PSNR/SSIM/LPIPS 与 Chamfer 距离、法线一致性，缺了评估就无法判断“跑通”与“跑对”。

最小命令的形态在各类实现中高度一致：一个训练入口接受数据根目录与实验名，一个渲染入口接受检查点与相机路径。真正需要工程判断的是“先降规模再调通”：把射线数、采样数、高斯初始点数、三平面分辨率各降一个量级，确认损失下降、渲染出图、导出文件可被外部查看器打开，再逐项恢复。这个顺序能把你从“编译错误、数据错位、数值爆炸”三类问题里分离出来，而不是在满规模下同时调试三件事。

二 · 对比表：同一目标下的四条路线

把“从 2D 到 3D”拆成四个可比较的维度：优化对象、监督信号、推理成本、可控性。优化对象决定梯度回传路径；监督信号决定数据门槛；推理成本决定部署形态；可控性决定编辑能力。四条代表路线分别落在不同角落：NeRF/NeuS 是“逐场景优化 + 多视图监督”，3DGS 是“逐场景优化 + 多视图监督但显式表示”，LRM/TRELLIS 是“前馈推理 + 大规模多视图预训练”，SDS 家族是“逐资产优化 + 2D 扩散先验”。

这条离散求和式是所有体渲染实现的共同骨架：采样点、密度、颜色、透射率。工程差异在于 σ 与 c 从哪来——NeRF 来自 MLP，NeuS 来自 SDF 经温度参数映射的 α，3DGS 则完全绕开沿射线采样，改为把每个高斯投影成 2D 椭圆后按深度排序做 alpha 混合。前者是“射线积分”，后者是“泼溅合成”，两者的梯度路径与显存曲线完全不同：前者随采样数增长，后者随高斯数增长。

前馈路线把优化从“每个场景一次”搬到“预训练一次、推理一次”。LRM 用 DINO ViT 编码输入图，相机参数调制后由 Transformer 解码器输出三平面，再用小 MLP 渲染任意视角；训练损失是渲染图与真值的 MSE 与感知损失。TRELLIS 进一步把表示换成结构化 3D 潜变量：多视图输入构建稀疏体素特征，rectified flow 训练 3D DiT，推理采样 SLAT 后由不同解码器解成 3DGS 或网格。代价从“每场景优化时间”转成“预训练数据规模与推理显存”，可控性则从“逐场景过拟合”转成“受训练分布约束”。

SDS 家族的对比点在于“监督来自 2D 扩散模型而非多视图真值”。SDS 随机采相机与时间步，对渲染图加噪，用冻结扩散模型预测噪声，梯度为 w(t)(ε_φ−ε)∂x/∂θ；CFG 把条件与无条件噪声相减增强文本对齐。Score Jacobian Chaining 改为查询得分再乘渲染雅可比做 Langevin 更新，并用多尺度退火；Variational Score Distillation 维护粒子模型，用冻结模型与粒子模型噪声预测之差作为梯度；Interval Score Matching 用 DDIM inversion 得到噪声轨迹，以两个终点之差为损失并配合 3DGS 加速。它们的共同失败模式是“先验偏差”：扩散模型偏好正面、偏好训练分布内的材质，背面与薄结构容易塌陷。

路线优化对象监督推理成本典型失败

这张对比表的工程用法是“先定约束再选路线”：有多视图且要求高保真，选逐场景优化；只有单图且要求秒级出资产，选前馈；只有文本且允许分钟级优化，选 SDS 家族并接受先验偏差。反过来用会付出代价：用前馈模型处理分布外物体，得到的是“合理但错误”的几何；用 SDS 处理需要精确尺寸的资产，得到的是“好看但不可用”的网格。

三 · 自测题：把机制问到能复现

自测题的目的不是背诵，而是检验“能否从公式推到实现、从实现推到失败模式”。下面按机制分组，每题都指向一个具体的代码位置或数值行为。

  • 位置编码为什么能弥补 MLP 的频谱偏置？给定坐标 x，写出映射到高频基的形式，并说明为什么直接把高频坐标喂给 MLP 而不做编码会失败。
  • 多分辨率哈希编码中，L 个层级分别量化、哈希到固定大小表、取特征拼接后送入小 MLP。粗层与细层各自负责什么？哈希冲突为什么能由梯度平均自然处理，而不是必须做完美哈希？
  • 3DGS 的协方差 Σ 如何保证半正定？投影到 2D 时雅可比如何参与？按深度排序后从前到后 alpha 混合，若排序出错，画面会出现什么具体伪影？
  • NeuS 用可学习温度参数把 SDF 值 f(x) 映射成 α。温度过大与过小分别导致什么？Eikonal 正则 ‖∇f‖=1 缺失时，零等值面会怎样退化？
  • DMTet 初始化稠密四面体网格，网络预测顶点 SDF，按符号组合查表生成三角面，顶点位置线性插值。为什么这种提取是可微的？梯度如何回传到 SDF 与顶点？
  • SDS 梯度中 ∂x/∂θ 是什么？为什么冻结扩散模型只提供噪声预测而不回传？CFG 的条件与无条件噪声相减在实现上对应哪两个前向？
  • VSD 与 SDS 的差别在“粒子模型随 3D 分布更新”。粒子模型用什么数据训练？若粒子模型更新过快或过慢，优化会分别出现什么行为？
  • LRM 的相机参数调制发生在哪一层？三平面 + MLP 渲染任意视角时，三平面分辨率与显存的关系是什么？
  • SLAT 的 rectified flow 训练目标与推理采样路径是什么？不同解码器把 SLAT 解成 3DGS 或网格，意味着表示与解码器解耦，这种解耦的代价是什么？
  • MeshAnything 用面片邻接做深度优先遍历，量化顶点坐标与相邻面索引，BPE 压缩，Transformer 学下一个 token。相邻 token 复用上一条边如何降低面数？序列过长时自回归的失败模式是什么？

自测的判据是“能否写出伪代码”。例如哈希编码的伪代码应包含：对每个层级 l，把坐标缩放后取整、做空间哈希、查表取特征、三线性插值、拼接所有层级、送入小 MLP 输出 σ 与 c。3DGS 的伪代码应包含：由均值与协方差投影出 2D 椭圆、按深度排序、逐像素从前到后累加颜色与透射率、致密化判据（梯度幅值超阈值则分裂或克隆）、剪枝判据（不透明度低于阈值或尺寸异常）。写不出伪代码，说明机制还没落到实现层。

四 · 延伸阅读：按机制而非按论文读

延伸阅读的顺序应当与“表示—监督—提取”三条线对齐，而不是按发表时间。第一条线是体渲染与哈希编码：从体渲染离散求和出发，读位置编码为何弥补频谱偏置，再读多分辨率哈希如何用固定大小表换分辨率，最后读 NeuS 如何把 SDF 映射成 α 并用 Eikonal 正则约束。第二条线是显式表示与光栅化：读 3DGS 的均值、协方差、不透明度、球谐系数四件套，读可微光栅化的排序与 alpha 混合，读致密化与剪枝的自适应增删。第三条线是生成与提取：读 Triplane 的三平面 + 2D 判别器对抗训练，读 DMTet 的四面体切面与线性插值，读 SDS 家族的四条梯度路径，读 LRM/TRELLIS 的前馈与结构化潜变量，读 MeshAnything 的面片序列化与重拓扑。

读的时候要带三个问题：这个表示的梯度路径是什么？这个监督信号的覆盖范围与偏差是什么？这个提取/解码步骤的可微性来自哪里？例如读 DMTet 时要问：顶点 SDF 的梯度如何穿过查表生成的三角面到达渲染损失？答案是顶点位置由线性插值给出，渲染对顶点位置可微，顶点位置对 SDF 可微，因此整条链可回传。读 Triplane 时要问：2D 判别器如何约束 3D 一致性？答案是判别器只看渲染出的 2D 图像，相机分布提供多视角覆盖，一致性来自“同一 3D 点在不同视角渲染出相同颜色”的隐式约束，而非显式 3D 监督。

工程延伸阅读还应包含“数据与清洗”这一环：大规模 3D 资产清洗管线要抓取模型与许可、转 GLB、去重与质量过滤、渲染多视图、CLIP 嵌入与标注、发布数据集与工具链。这一环决定了前馈模型的上限，也决定了评估的可复现性。材质线则要读 UV 展开 + PBR 分解：网格 UV 展开、多视图渲染反投影到 UV、材质扩散补全、光照解耦训练、输出反照率/粗糙度/金属度贴图组。形状-材质双 DiT 把形状分支用 VecSet/稀疏体素扩散出 SDF 再 Marching Cubes 出网格，材质分支在 UV 空间扩散，用渲染损失与材质监督训练，这条线把“几何”与“外观”解耦成两个可独立验证的子问题。

最后一条延伸线是“世界与交互”：迭代式房间网格补全从单图估深度、反投影成网格、移到新视角渲染洞、用 2D 扩散补洞、融合新几何、重复直到闭合；高斯泼溅世界扩展用单图加深度初始化高斯，渲染当前视角，视频扩散生成下一帧，用新帧监督高斯增密；视频驱动物理参数估计用可微 MPM 仿真优化物理参数使渲染轨迹与视频一致。这三者的共同工程判断是“闭环”：生成—渲染—比对—修正，每一轮都要有可验证的信号，否则误差会在迭代中累积成几何漂移。

五 · 练习：从清单到可复现的最小实验

练习一：把体渲染离散求和写成可运行的伪代码，固定射线数、采样数、网络宽度，只改变位置编码的频率层数，观察训练视图 PSNR 与深度图连续性的变化。判据不是数字大小，而是“高频细节是否出现、深度是否出现条纹”。若出现条纹，先查采样数是否不足、采样区间是否覆盖近远平面。

练习二：实现一个最小 3DGS 训练循环：初始化高斯、投影、排序、alpha 混合、可微光栅化回传、致密化与剪枝。把致密化阈值调高与调低各跑一次，观察高斯数量曲线与渲染空洞。失败模式是“致密化失控”：高斯数指数增长、显存峰值出现在致密化步、排序缓冲溢出。工程判断是给致密化加频率上限与不透明度剪枝。

练习三：用 NeuS 的 SDF 到 α 映射做一次消融：去掉 Eikonal 正则、把温度参数固定为常数、去掉掩码监督，各跑一次并检查零等值面。判据是表面是否闭合、法线是否平滑、薄结构是否保留。失败模式是“表面孔洞与法线噪声”，根因通常是 Eikonal 权重过低或采样区间未覆盖零等值面。

练习四：把 SDS 的梯度路径写成四行伪代码：采相机与时间步、加噪、冻结模型预测噪声、计算 w(t)(ε_φ−ε)∂x/∂θ 并更新。然后加入 CFG，观察文本对齐的变化。失败模式是“先验偏差导致的背面塌陷”，工程判断是加多视角相机分布、加几何正则、或用 VSD 的粒子模型抑制过饱和。

练习五：把 MeshAnything 的面片序列化写成状态机：深度优先遍历、量化顶点坐标、记录相邻面索引、BPE 压缩、自回归生成。判据是输出面数下降且流形性检查通过。失败模式是“序列过长导致自回归漂移”，工程判断是限制序列长度、加邻接缓存复用上一条边、并在解码后做重拓扑校验。

练习六：搭一条最小前馈链路：输入图过 ViT、相机参数调制、Transformer 解码三平面、MLP 渲染多视角、与真值算 MSE 与感知损失。判据是多视角渲染一致、导出网格可被外部查看器打开。失败模式是“分布外输入导致背面臆造”，工程判断是检查相机规范化、检查训练数据的视角覆盖、并在推理时给出置信度或拒绝采样。

这些练习的共同结构是“一个机制、一个公式、一个失败模式、一个具体例子”。做完之后，速查表不再是记忆材料，而是排障索引：看到条纹查采样与哈希，看到排序伪影查深度与 alpha 顺序，看到孔洞查 Eikonal 与掩码，看到背面塌陷查先验与相机分布，看到面数失控查序列长度与邻接复用。

工程判断落在最后一步：把“跑通”定义为“损失下降 + 渲染可看 + 导出可读 + 评估可复现”四件事同时成立。缺任何一件，都说明你调通的只是命令，不是机制。清单负责让你到达第一帧，对比表负责让你选对路线，自测题负责让你写出伪代码，练习负责让你看见失败模式——四者合起来，才是“代码与工具”这一条目在工程现场的真正用法。
