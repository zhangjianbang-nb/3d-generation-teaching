一 · 速查清单：把词条变成可操作的检查项

术语表 G–M 的条目彼此不是孤立的标签，而是生成流水线上不同环节的“接口约定”。速查清单的用途不是背定义，而是在拿到一个 3D 生成系统或一篇论文时，快速定位它把复杂度放在了哪一层。下面这份清单按“表示—监督—数据—评估”四类组织，每一条都对应一个可以当场验证的机制问题。

  • 表示层：系统输出的是显式基元（高斯、点云、三角面）还是隐式场（密度场、SDF、潜变量三平面）？显式基元意味着可以直接光栅化、可以直接编辑顶点，代价是内存随基元数线性增长；隐式场意味着分辨率可以连续缩放，代价是每次查询都要过网络或查表。
  • 监督层：监督信号来自多视图图像、单图先验、2D 扩散先验，还是纯 3D 数据？来自 2D 先验的系统必须回答多视图一致性问题；来自 3D 数据的系统必须回答数据规模与覆盖度问题。
  • 数据层：训练集是 Objaverse 量级、Objaverse-XL 量级，还是自建？数据规模直接决定模型能否覆盖长尾类别，这一点在 3D 数据 scaling 的讨论中已经定性说明。
  • 评估层：报告的是渲染指标（PSNR/SSIM/LPIPS）、几何指标（Chamfer 距离、法线一致性），还是下游可用性（能否重光照、能否进引擎）？只报渲染指标的系统可能在几何上是空的。

清单的使用方式是“逐项打勾并写下证据”。例如面对一个声称“单图生成高质量网格”的系统，先问它输出的是三平面、SLAT 还是高斯；再问它的多视图一致性是靠 MVDream 式的多视图扩散保证，还是靠 LRM 式的一次前向回归；最后问它是否输出 PBR 材质。三个问题答不上来，说明该系统在术语表覆盖的范围内存在未交代的环节。

$$\text{检查完备度} = \frac{\text{已交代环节数}}{\text{表示}+\text{监督}+\text{数据}+\text{评估}}$$

这个比值不是评分，而是排查顺序：分母固定为四，分子缺哪一项就去补哪一项的机制知识。失败模式很具体——很多系统在“监督”一栏写“使用 2D 扩散先验”，却不说明是 Score Distillation Sampling 还是 Variational Score Distillation，两者的失败形态完全不同：前者在单点估计上容易过饱和、几何被纹理掩盖，后者把 3D 参数视为分布、需要额外的粒子或 LoRA 网络来承载分布，显存与采样步数代价更高。工程上判断一个系统是否可信，往往就看它有没有把这一栏写清楚。

二 · 对比表：五组容易混淆的词条对

术语表里最容易被混用的，是那些“名字相似但机制相反”的条目。下面五组对比表给出区分维度，每一组都配一个具体例子说明误用的后果。

对比组左侧机制右侧机制关键区分维度
SDF vs 密度场NeuS / VolSDF 式符号距离，Eikonal 正则约束梯度模长为 1NeRF 式体密度，体渲染积分直接累积表面提取方式：SDF 可用 Marching Cubes 直接提面；密度场需先做密度阈值化，表面偏厚
哈希编码 vs 三平面多分辨率哈希查表，显存换速度把 3D 降成三个 2D 特征平面，用 2D 卷积解码参数增长方式：哈希表随分辨率层数增长；三平面随平面分辨率平方增长
SDS vs VSD把 2D 扩散的得分蒸馏为单点梯度把 3D 参数建模为分布，用变分得分蒸馏多样性来源：SDS 趋向单一解；VSD 显式优化分布
LRM vs 多视图扩散一次前向回归出三平面或高斯先采样多视图再重建，如 MVDream / SyncDreamer一致性来源：LRM 靠回归网络隐式学一致；多视图扩散靠跨视图注意力显式约束
网格 tokenization vs 潜变量扩散MeshGPT 式把三角面序列化为 token，自回归生成SLAT / Direct3D 式在结构化潜空间做扩散输出拓扑：tokenization 直接产出面序列，拓扑自由但序列长；潜变量扩散需解码器回到显式表示

以 SDF 与密度场这一组为例：NeuS 的核心是把体渲染的权重函数与 SDF 的零水平集对齐，使得渲染损失能直接优化出干净表面；如果误把密度场当 SDF 用 Marching Cubes 提面，得到的网格会在低密度区域出现“双层壳”，因为密度在表面附近是渐变而非阶跃。反过来，如果把 SDF 直接塞进标准 NeRF 积分而不改权重函数，表面会模糊，Eikonal 正则也救不回来。这就是术语表要求成对记忆的原因：机制与提取方式是绑定的。

哈希编码与三平面的对比则落在显存曲线上。多分辨率哈希编码用多级哈希表加特征插值，查询是 O(1) 的查表加线性插值，训练时靠 Adam 更新被命中的表项，未被命中的表项不更新——这带来一个失败模式：高频细节集中在少数表项上，若哈希冲突严重，不同空间位置会共享特征，表现为局部区域的纹理“串味”。三平面把 3D 查询降为三次 2D 双线性采样再拼接，显存随平面分辨率平方增长，分辨率翻倍显存翻四倍，这是它在高分辨率资产上必须配解码器压缩的原因。

三 · 自测题：从机制反推系统行为

自测题的设计原则是“答案不在定义里，而在失败模式里”。下面六题按难度递增，每题给出考察点与判据。

  • 题一：一个系统报告了很高的渲染 PSNR，但导出的网格在薄结构处破洞。最可能缺了哪一环？考察点：渲染指标与几何指标的脱钩。判据：若系统用密度场且未加 Eikonal 正则或未做表面提取后的孔洞修补，薄结构处密度积分不足，PSNR 仍可因视角平均而好看。
  • 题二：单图生成系统在正面视角完美，转到背面出现纹理拉伸。考察点：多视图一致性。判据：看它是否用 Zero-1-to-3 式的新视角条件扩散，或 MVDream 式的多视图联合去噪；仅靠 LRM 一次前向回归的系统在训练分布外的背面视角上退化更明显。
  • 题三：文本生成 3D 的系统换一个随机种子，几何几乎不变。考察点：SDS 与 VSD 的区别。判据：SDS 的梯度是单点得分，优化趋向众数解；VSD 显式建模分布，换种子应带来可见的形态差异。若不变，说明该系统实际用的是 SDS 或加了强正则。
  • 题四：高斯泼溅系统在场景边缘出现“漂浮絮状物”。考察点：显式基元的初始化与致密化策略。判据：3D 高斯泼溅依赖 SfM 点云初始化与基于梯度的致密化/剪枝；初始化稀疏或致密化阈值过松，会在无纹理区域生成低不透明度高斯，光栅化时表现为絮状。
  • 题五：网格 tokenization 系统生成的面数远超输入，且出现非流形边。考察点：序列化与拓扑约束。判据：MeshGPT 式自回归逐 token 生成面，缺乏全局拓扑约束；MeshAnything V2 的相邻网格 tokenization 通过改变 token 顺序缓解序列长度与局部性问题，但非流形仍需后处理。
  • 题六：物理仿真系统在生成资产上交互时穿模。考察点：PBR 材质与几何的分离，以及 PhysDreamer 式视频先验的物理一致性。判据：若资产只有外观材质而无碰撞体或质量属性，仿真器只能按视觉外壳近似，薄壳与凹结构处必然穿模。

以题三为例展开：Score Distillation Sampling 的梯度形式可写为对 2D 扩散模型噪声预测的加权，权重含采样噪声与时间步；它把 3D 渲染图送入 2D 模型得到“图像应如何修改”的方向，再反传到 3D 参数。这个方向是单点的，因此多次运行会收敛到相近的众数。Variational Score Distillation 则引入一个可学习的 3D 分布（实践中常用低秩适配或粒子集），并用一个辅助扩散模型去匹配该分布与 2D 先验，梯度里多了一项分布散度。代价是显存与每步采样开销上升，收益是多样性。自测时若发现“换种子不变”，不要先怀疑随机数，先查蒸馏目标。

四 · 交叉索引：按流水线阶段重排词条

术语表按字母序排列，便于查找但不便于理解依赖关系。把 G–M 的词条按流水线阶段重排，能得到一张依赖图：数据与表示在前，监督与生成在中，评估与仿真在后。下面按阶段给出交叉索引，每段只列与该阶段强相关的条目，并指出一个跨阶段的耦合点。

阶段相关词条跨阶段耦合点
数据与表示Objaverse / Objaverse-XL、多分辨率哈希编码、三平面表示、SDF 与 Eikonal 正则数据规模决定表示容量的上限：三平面分辨率与哈希表层数需与数据覆盖度匹配，否则容量浪费在记忆训练集上
单图与多视图重建LRM、pixelNeRF、Zero-1-to-3、SyncDreamer、Wonder3D、InstantMesh、TripoSR、GS-LRM、MeshLRMLRM 类一次前向系统的输出表示（三平面/高斯/网格）决定了后续能否直接进引擎；GS-LRM 输出高斯，省去提面但失去拓扑
文本与图像生成SDS、VSD、DreamFusion、Magic3D、ProlificDreamer、Fantasia3D、DreamGaussian、LucidDreamer蒸馏目标与输出表示耦合：DreamGaussian 把 SDS 优化到高斯上，收敛快但几何精度受基元分辨率限制
结构化与组合生成SLAT、PartCrafter、Direct3D、MeshGPT、MeshAnythingSLAT 的结构化潜变量使部件级组合成为可能，但解码器需同时处理几何与材质，误差会跨部件传播
场景与物理Text2Room、WonderWorld、WorldGen、SceneCraft、PhysDreamer、PBR 材质场景一致性要求长距离不漂移，物理仿真要求材质与碰撞属性，两者都依赖生成资产的可重光照与可测量性

跨阶段耦合最典型的是“表示选择决定下游可用性”。以 GS-LRM 与 MeshLRM 为例：两者都是单图到大重建模型，前者输出 3D 高斯，后者输出网格。高斯表示的光栅化速度快、渲染质量高，但没有拓扑，进不了需要 UV 与材质贴图的传统管线；网格表示可以直接进引擎，但提面过程会损失高频细节，且拓扑质量依赖 Marching Cubes 后的简化。工程判断因此不是“哪个更好”，而是“下游要什么”：要实时预览选高斯，要资产交付选网格，要两者兼得就得接受两套表示之间的转换误差。

另一个耦合点是场景一致性与长距离漂移。Text2Room 式方法逐房间生成并拼接网格，WonderWorld 式方法从单图扩展出可交互场景，WorldGen 式方法从文本生成可穿行世界。它们的共同失败模式是：局部生成器各自一致，但拼接处的尺度、光照与几何接缝不匹配。术语表把“场景一致性”单列，就是为了提醒这不是单个模型的属性，而是拼接协议的问题——需要显式的尺度对齐、接缝融合或全局优化，而不是指望生成器“自己学会”。

五 · 延伸阅读路线：按问题而非按字母

延伸阅读不应按论文列表平铺，而应按“你要解决的问题”组织。下面四条路线各给三到四个锚点论文，并说明读它们的顺序与理由。所有论文名均来自给定事实，不附加年份与页码。

  • 路线一：想把 2D 先验蒸进 3D。顺序为 DreamFusion → Score Jacobian Chaining → Magic3D → ProlificDreamer。理由：DreamFusion 建立 SDS 的基本形式；Score Jacobian Chaining 给出把 2D 得分提升到 3D 的雅可比视角；Magic3D 展示从粗到细的两阶段与高分辨率；ProlificDreamer 用 VSD 解决多样性与过饱和。读完后应能回答“为什么 SDS 趋向众数”与“VSD 的额外代价花在哪”。
  • 路线二：想做单图到 3D 的快速前向。顺序为 pixelNeRF → LRM → TripoSR → InstantMesh → GS-LRM / MeshLRM。理由：pixelNeRF 建立单图条件 NeRF 的范式；LRM 把三平面回归做成大模型一次前向；TripoSR 与 InstantMesh 是快速与稀疏视图的工程化；GS-LRM 与 MeshLRM 分别把输出换成高斯与网格，回答“表示决定下游”。
  • 路线三：想做干净表面与可提面几何。顺序为 NeuS → Volume Rendering of Neural Implicit Surfaces → Hi3DGen。理由：NeuS 建立 SDF 与体渲染权重对齐的机制；Volume Rendering of Neural Implicit Surfaces 深化隐式表面的体渲染处理；Hi3DGen 用法线桥接提升几何保真度，回答“渲染好看不等于几何准”。
  • 路线四：想做结构化与可组合生成。顺序为 GET3D → MeshGPT → SLAT → PartCrafter。理由：GET3D 展示从图像学带纹理形状的生成式建模；MeshGPT 把三角面变成 token 序列；SLAT 建立结构化 3D 潜变量；PartCrafter 做部件级组合扩散。读完后应能判断“tokenization 与潜变量扩散各自的拓扑代价”。

每条路线都建议配一个“反向阅读”动作：读完生成侧论文后，回到术语表查对应的表示词条，确认论文里的“三平面”“高斯”“SDF”与词条定义是否一致。常见的不一致是论文把“三平面”泛指任意多平面特征，而词条特指三个正交平面；这种宽泛用法会让复现时的显存估算偏差一个量级。另一个反向动作是查评估词条：论文报告的指标是否覆盖了几何、材质与多视图一致性三项，缺项就意味着结论只在其自设的任务上成立。

以路线二为例，具体机制上的读法是：LRM 的输入是单图经视觉编码器得到的 token，输出是三平面特征图，再经 NeRF 式解码渲染；训练监督是多视图渲染损失。它的失败模式是输入视角外的区域靠先验“猜”，在对称性强的物体上猜得准，在非对称薄结构上猜得差。TripoSR 的工程价值在于把这条前向压到很低的延迟，代价是分辨率与细节的折衷。GS-LRM 把输出换成高斯后，渲染更快但失去了三平面的连续查询能力；MeshLRM 换回网格，回答的是资产交付而非实时预览。这条路线读完，应该能对“一次前向出什么”做出有依据的选择，而不是只看演示视频。

六 · 练习设计：用最小系统验证词条

最后一个环节是把词条变成可运行的练习。练习不追求复现论文指标，而追求“用最小系统触发一个已知失败模式”，从而把术语从名词变成因果。下面给出三个练习的设计，每个都包含机制、伪代码思路、代价与判据。

练习一：体渲染积分的离散化误差。机制：把一条射线上 N 个采样点的颜色与密度按 alpha 合成，采样数不足时薄结构会被漏采。伪代码思路：固定场景为一个薄板，分别用 N 与 4N 个采样点渲染，比较薄板边缘的 alpha 累积。代价：采样数翻倍使渲染时间近似翻倍，训练时反传的显存也随采样数线性增长。判据：若 N 较小时边缘出现“闪烁”或厚度随视角变化，说明离散化不足，需引入重要性采样或分层采样。这个练习直接对应体渲染积分词条，且能解释为什么 Instant NGP 要用哈希编码加速查询——不是为了好看，是为了在相同时间预算下允许更多采样。

练习二：Eikonal 正则的权重敏感性。机制：SDF 的梯度模长应接近 1，Eikonal 项以均方误差惩罚偏离。伪代码思路：在 NeuS 式损失中加入 λ 乘以梯度模长减一的平方，分别取两个相差一个量级的 λ，观察提面后的孔洞与双层壳。代价：λ 过大时表面过度平滑、细节丢失；λ 过小时表面出现噪声与孔洞。判据：用 Marching Cubes 提面后统计非流形边数量与孔洞面积，选使两者都低的 λ 区间。这个练习把“SDF 与 Eikonal 正则”从定义变成可调的工程旋钮。

练习三：多视图一致性的度量。机制：对同一物体渲染正面与背面，用 2D 扩散模型分别去噪，比较两次去噪给出的得分方向是否一致。伪代码思路：固定 3D 参数，渲染两个视角，送入同一 2D 模型的不同噪声采样，计算得分余弦相似度；相似度低说明该 3D 状态在两个视角下讲不通。代价：每次评估需两次前向加反传，若用于训练循环则每步开销翻倍。判据：在 SDS 优化中加入该一致性项后，背面伪影减少但收敛变慢；若一致性项权重过大，优化会停在“各视角都平庸”的解。这个练习对应多视图一致性词条，并解释 MVDream 与 SyncDreamer 为何要在扩散模型内部做跨视图注意力，而不是只在损失里加一项。

三个练习的共同点是：都用最小系统触发一个术语表里写明的失败模式，而不是追求指标。工程判断落在具体机制上——采样数与查询速度的权衡、正则权重与表面质量的权衡、一致性与收敛速度的权衡。术语表 G–M 的价值不在于记住字母序，而在于拿到任何一个 3D 生成系统时，能沿着“表示—监督—数据—评估”的清单逐项追问，用对比表区分相似机制，用自测题从现象反推缺失环节，用练习把名词变成可复现的因果。
