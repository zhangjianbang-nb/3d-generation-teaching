二 · 从“查表”到“插值”：哈希编码里最容易被忽略的一步

多分辨率哈希编码常被概括成“用查表换速度”，这个说法漏掉了真正决定重建质量的环节：查表之后的插值。哈希表本身只存一组可学习的特征向量，每个分辨率层 L 有自己的网格分辨率 NL 和特征维度 F。给定一个三维坐标 x，先按该层的网格间距把它量化到格点，再取包围它的 8 个角点，各自用一组哈希函数映射到表内槽位，取出 8 个特征向量，按三线性权重加权求和。真正进入后续 MLP 的是这些加权和，而不是任何一个单独槽位的内容。

$$h(x)=\bigoplus_{i=1}^{L}\ \sum_{c\in\{0,1\}^3} w_c(x)\,\mathbf{T}_i\big[\,\pi_i(\lfloor x\cdot N_i\rfloor+c)\,\big]$$

这里 πi 是第 i 层的哈希映射，wc 是三线性权重。容易错的地方在于：很多人以为哈希冲突会直接破坏表示，实际上冲突只是让两个不相邻的格点共享同一个槽位，而插值权重仍然由几何位置决定。真正致命的是另一件事——当某一层的网格分辨率远高于数据采样密度时，绝大多数槽位在训练中从未被任何采样点命中，它们停留在初始化值上；一旦推理时相机轨迹落到这些未命中区域，插值就会把“未训练的特征”混进结果，表现为局部色块、雾状拖影或表面针状突起。这是哈希编码的典型失败模式，不是精度问题，而是覆盖率问题。

工程上的对策不是调大表容量，而是控制层数与最高分辨率之间的比例，并在采样策略上保证每条射线在近表面区间有足够多的点落在高分辨率层。具体例子：一个以物体为中心、半径约 1 的重建任务，若最高层网格分辨率设为 1024，则单层格点数达到十亿量级，而每条射线通常只采几十到上百个点，覆盖率极低。把最高层降到 512 并增加中间层，往往比单纯堆分辨率更稳。系统代价方面，哈希编码把显存占用从“随分辨率立方增长”变成“随表容量线性增长”，但代价是缓存不友好：8 个角点的哈希映射是随机访存，GPU 上的实际吞吐受限于显存延迟而非算力，这就是为什么同一份编码在不同 batch 组织方式下速度差异明显。

三 · 体渲染积分的离散化：为什么“采样数”不是一个可以随便设的参数

NeRF 式体渲染把一条射线上的颜色写成透射率加权的积分，离散化后变成对采样点的求和。设射线从 tn 到 tf，第 i 段长度为 δi，密度为 σi，颜色为 ci，则

$$\hat{C}=\sum_{i=1}^{N} T_i\,\big(1-e^{-\sigma_i\delta_i}\big)\,c_i,\qquad T_i=\exp\Big(-\sum_{j

这个式子里有两个隐藏假设：其一，段内密度被视为常数；其二，段内颜色被视为常数。当表面很薄、密度在段内剧烈变化时，这两个假设同时失效，表现为边缘发虚、细结构丢失。更隐蔽的问题出在分层采样：粗网络先给出密度分布，细网络在密度高的区间加密采样。如果粗网络的密度预测在某一区间系统性偏低，细网络就不会去那里采样，于是该区间永远得不到修正——这是一个自洽的失败闭环，而不是随机噪声。

具体机制上，这意味着采样数 N 与场景的“最小特征尺度”绑定。一个包含细栏杆或薄叶片的场景，若每条射线只采 64 个点，段长往往大于特征厚度，积分会把薄结构平均掉。把 N 提到 128 或 256 能缓解，但代价是每条射线的网络前向次数线性增长，训练与推理时间同步上升；在批量渲染时，显存中的中间激活也随 N 增长。工程判断是：先检查透射率 Ti 在表面附近的下降是否过于平缓，若是，则问题在采样密度而非网络容量。

另一个易错细节是背景处理。若把背景视为“密度为零、颜色为固定值”，则积分在 tf 处截断会留下残余透射率，最终颜色是前景与背景的混合；很多实现忘记把残余透射率乘上背景色，导致物体边缘出现暗边。正确做法是在求和末尾补一项 TN+1·cbg。这一项在合成数据上影响很小，在真实拍摄的、背景复杂的图像上会直接体现为轮廓处的颜色偏差，且会被误诊为“表面法线估计不准”。

四 · 高斯泼溅的光栅化：排序、混合与梯度从哪来

3D 高斯泼溅把场景表示为一组各向异性高斯，每个高斯带中心、协方差、不透明度和球谐颜色系数。渲染时先把每个高斯投影到屏幕空间，得到二维协方差，再按深度排序，从前到后做 alpha 混合。屏幕空间协方差的构造是

$$\Sigma'=J\,W\,\Sigma\,W^{\top}J^{\top}$$

其中 W 是视角变换，J 是投影的雅可比矩阵。这个式子是整个方法的核心，也是最容易写错的地方：J 在透视投影下不是常数，它依赖高斯中心到相机的距离，若在实现中把 J 当作全局常量，远处高斯的投影尺寸会被系统性高估，表现为远景“糊成一团”而近景正常。

排序是第二个坑。逐像素的 alpha 混合要求高斯按深度有序，但高斯之间会互相穿插，不存在全局一致的排序。工程实现通常按高斯中心的深度做一次粗略排序，再在 tile 内做局部排序。当两个高斯中心深度接近而实际覆盖区域交叠时，排序错误会导致颜色闪烁，尤其在相机移动时表现为“跳变”。这不是精度问题，而是排序粒度问题；把 tile 划小能缓解，代价是每 tile 的调度开销上升。

梯度来源也值得说清：光栅化本身是可微的，梯度通过 alpha 混合的链式法则回传到每个高斯的颜色、不透明度和协方差。但“致密化”与“剪枝”这两个操作是不可微的启发式规则——梯度大的高斯被分裂，透明度过低的高斯被删除。这意味着优化过程里混入了离散决策，学习率与致密化阈值耦合，阈值设得激进会导致高斯数量爆炸，显存与排序开销同步上升；设得保守则细结构欠拟合。具体例子：一个包含大量细枝的植被场景，致密化阈值偏低时高斯数量会在训练中期快速翻倍，排序阶段成为瓶颈，帧率下降而视觉质量提升有限。工程判断是先固定致密化策略、只调学习率，再看是否真的需要更多基元。

五 · SDS 家族：得分、雅可比链与分布匹配的区别

Score Distillation Sampling 的常见误读是“用 2D 扩散模型的梯度直接优化 3D 参数”。更准确的说法是：把 3D 渲染出的图像加噪后送入扩散模型，取噪声预测误差对图像的梯度，再经渲染器反传到 3D 参数。其更新方向可写成

$$\nabla_\theta \mathcal{L}_{\text{SDS}}=\mathbb{E}_{t,\epsilon}\Big[w(t)\big(\epsilon_\phi(x_t;t,y)-\epsilon\big)\frac{\partial x}{\partial \theta}\Big]$$

注意这里并没有对扩散模型参数 φ 求导，φ 是冻结的；梯度只穿过“图像 x 对 3D 参数 θ”的这一段。这一点决定了 SDS 的系统代价：每次更新都要做一次 3D 渲染加一次扩散前向，渲染的分辨率与采样数直接乘在训练时间上。失败模式也很典型：SDS 倾向于产生“过度平滑、颜色饱和”的结果，因为噪声预测误差在低频上提供主要信号，高频细节的梯度被噪声淹没；同时，若相机采样分布偏向某些视角，其他视角会出现“内容漂移”，即同一物体在不同视角下几何不一致。

Score Jacobian Chaining 与 SDS 的差别在于它显式地处理了雅可比：把 3D 渲染视为从参数到图像的映射，用链式法则把 2D 得分拆成“图像得分 × 图像对参数的雅可比”，并在实现中对雅可比做近似以降低方差。Variational Score Distillation 则换了一个角度：它不把 3D 表示当成一个待优化的点，而是当成一个分布，用一个可学习的分布去匹配扩散先验，从而缓解“单点优化导致的模式坍塌”。Interval Score Matching 关注的是时间步区间：在不同噪声水平上得分信号的信噪比不同，只在特定区间取梯度能减少方差。

一个具体例子能说明三者的工程差异：文本到 3D 生成一个带把手的杯子。SDS 容易把把手与杯身融成一体，因为低频信号主导；VSD 因为维护分布，能在多次采样中保留把手的独立结构，但代价是需要额外的网络或粒子集来参数化分布，显存与训练步数上升；ISC 通过限制时间步区间减少方差，收敛更稳但对提示词变化更敏感。工程判断是：若目标是快速出草稿，SDS 足够；若目标是可重拓扑的干净几何，需要分布匹配类方法，并接受更高的系统开销。

六 · 前馈工厂里的表示选择：三平面、SLAT 与网格 token 的代价对照

前馈生成器的核心问题是“一次前向输出什么表示”。三平面把 3D 降成三个 2D 特征平面，用 2D 卷积骨干生成，再通过插值查询解码为密度与颜色。它的优势是骨干网络成熟、显存占用随分辨率平方增长而非立方；代价是三个平面在轴对齐方向上表达能力强，在斜向结构上会出现“条带”伪影，因为平面间的特征融合依赖解码器的 MLP，而 MLP 容量有限。

结构化 3D 潜变量 SLAT 走的是另一条路：把空间划成稀疏的体素块，只在表面附近激活，每个激活块带一个局部潜变量，用 Transformer 在块之间做注意力。它的机制优势是稀疏性带来的显存节省，以及注意力能建模长距离关系；失败模式是块边界处的不连续——相邻块的潜变量若缺乏约束，解码出的几何在边界处会出现台阶。工程上通常加一个边界一致性损失，代价是训练时需要在块邻接图上多做一次前向。

网格序列化 tokenization 把三角面变成离散 token 序列，用自回归或扩散 Transformer 生成。它的好处是输出直接是可编辑网格，不需要等值面提取；代价是 token 序列长度随面数增长，注意力开销平方增长，且“相邻网格 token 重拓扑”这一步若处理不当，生成结果会出现非流形边或翻转面。具体例子：生成一个中等复杂度的家具，面数在数千量级时序列长度已足以让注意力成为瓶颈；此时用局部窗口注意力替代全局注意力能降开销，但会削弱部件之间的长程协调。

这三者的选择不是“哪个更好”，而是“下游要什么”。若下游是渲染与重光照，三平面加 PBR 分解更顺；若下游是场景组合与编辑，SLAT 的稀疏结构便于局部替换；若下游是直接进引擎，网格 token 省去提取步骤但把复杂度转移到了序列建模。工程判断落在一点：先确定下游管线是否需要显式网格，再决定生成器的输出头，否则会在“生成完再提取”这一步付出重复的算力与精度损失。

七 · 评测词条 FID 的误用：它衡量什么、不衡量什么

FID 用两组图像在特征空间中的分布距离来衡量生成质量，其形式是两组特征高斯的均值差与协方差差的组合。它衡量的是“生成分布与真实分布的统计接近程度”，不衡量单个样本的几何正确性。在 3D 生成里这一点尤其危险：一个从多个视角渲染出来的物体，若每个视角单独看都逼真，但视角之间几何不一致，FID 可能仍然好看，因为它在特征统计上接近真实图像分布。

$$\text{FID}=\|\mu_r-\mu_g\|^2+\operatorname{Tr}\big(\Sigma_r+\Sigma_g-2(\Sigma_r\Sigma_g)^{1/2}\big)$$

具体机制上，FID 的特征提取器是在 2D 图像上预训练的，它对纹理和局部统计敏感，对三维一致性不敏感。因此用 FID 比较两个 3D 生成器时，必须固定渲染视角集合与分辨率，否则视角分布的变化会直接改变特征统计，使比较失去意义。失败模式是“视角挑选”：只渲染正面视角能得到更低的 FID，但背面可能完全崩坏。工程上应把 FID 与多视图一致性指标并列使用，前者看画质统计，后者看几何自洽。

另一个易错细节是样本量。FID 的协方差估计在样本数少时偏差明显，样本数不足会让两个生成器的 FID 差异落在估计噪声内，此时“A 比 B 低 2 个点”不构成判断依据。工程判断是：先确认样本量与视角集合一致，再看差异是否稳定跨批次复现；若不稳定，应回到具体失败案例上做定性分析，而不是继续调参追求指标。
