一 · 症状到原因的映射约定

《失败模式手册》不是“错误码表”，而是一张把可观察症状压缩到有限原因集合的映射表。工程上真正难的不是知道“表面糊”这个现象，而是判断它属于表示容量不足、监督信号缺失、优化步数不够，还是后处理把细节抹平了。手册的条目设计遵循一条原则：每条症状必须能对应至少一个可干预的机制变量，否则条目没有排障价值。

定义上，我们把失败模式记为三元组 (S, C, D)：S 是症状的可观察描述，C 是原因类别，D 是该原因在系统中的可干预点。症状必须用渲染结果或网格检查可复现地描述，例如“同一视角下高频纹理区域出现块状拼接”而不是“看起来不自然”。原因类别限制在五类：表示与容量、监督与先验、优化与调度、几何与拓扑、管线与后处理。可干预点则是具体旋钮，例如哈希表大小、β 退火曲线、视图采样策略、UV 展开算法、显存预算。

分类维度上，手册按“症状主导”而非“方法主导”组织。原因是同一个症状在不同方法族里由不同机制触发：多面问题在 DreamFusion 类分数蒸馏中来自 2D 先验的视角不一致，在图像到 3D 的前馈管线中则来自多视图生成器的背面幻想。若按方法组织，排障者必须先知道方法名才能查表；按症状组织，排障者从渲染结果直接进入。

速查表如下，列给出症状、首要原因类别、典型触发机制与首要干预点。表中不列具体数值，因为阈值依场景与分辨率而变，写死数字会误导。

二 · 多面与过饱和：2D 先验抬升的两种典型畸变

多面指同一物体在不同视角下呈现互相矛盾的正面结构，典型表现是从侧面看仍能看到正面的五官或纹理。机制上，DreamFusion 类方法用 2D 扩散模型对随机视角渲染图打分，梯度通过分数蒸馏回传到 3D 表示。当视图采样分布偏向正面、或视角条件嵌入不够强时，2D 先验会把“正面看起来合理”的结构复制到背面，因为扩散模型对背面没有独立知识。Score Jacobian Chaining 与 ProlificDreamer 都继承这一抬升路径，前者实现复杂且方差大，后者开销大、超参多，但多面问题的根源仍是视角条件与采样覆盖。

形式化地，分数蒸馏的更新可写为对渲染图 x 的梯度期望：

$$\nabla_\theta \mathcal{L} = \mathbb{E}_{c,\epsilon}\left[ w(t)\,(\epsilon_\phi(x_t;c,t)-\epsilon)\,\frac{\partial x}{\partial \theta}\right]$$

其中 c 是视角与文本条件，w(t) 是时间步权重。多面出现的条件是：对背面视角 c_back，条件嵌入未能把先验推向背面语义，导致 ϵ_ϕ 给出的去噪方向与正面视角几乎相同。干预点是提高背面视角采样比例、加入视角条件增强，或在多视图扩散中强制视图间注意力。

过饱和是同一抬升路径的另一端：分数蒸馏的梯度方差大，色彩通道在少数高权重时间步上被反复推高，导致反照率超出合理范围。DreamGaussian 与 TextMesh 都报告过饱和，前者在质量与拓扑上也有妥协。机制上，w(t) 的峰值集中在中间时间步，若 CFG 权重过大，条件与非条件分支的差值被放大，颜色通道首先饱和。干预手段是降低 CFG、对反照率做区间正则、或在 SDS 之外加入重建损失锚定颜色。

系统代价方面，多面与过饱和都不是“训练不收敛”，而是“收敛到错误的不动点”。排查时若只增加步数，过饱和会加剧，多面不会消失。具体例子：一个文本到 3D 管线在正面视角渲染正常，旋转到背面出现第二张脸，同时正面颜色偏艳。按表定位为监督与先验类，干预视图采样后多面缓解，但颜色仍需单独的正则，说明两个症状共享抬升路径却不共享干预点。

三 · 表面糊与薄结构噪：容量、频带与积分密度的耦合

表面糊指高频细节（文字、织物纹理、锐利边缘）在渲染或网格上呈现模糊或块状。原因分三支：表示容量、编码频带、后处理分辨率。Instant NGP 的多分辨率哈希编码在表较小时发生哈希冲突，不同空间位置映射到同一特征向量，细节被平均掉；且表大小需按场景调，调小省显存但丢细节。NeRF 类单场景优化本身渲染慢，若训练步数不足，高频频带尚未拟合，表现为整体发糊。前馈重建管线（如 InstantMesh、CRM、TripoSR）则受网格分辨率与纹理分辨率上限约束，误差从多视图生成传导到重建，最终表现为纹理接缝与模糊并存。

薄结构噪指叶片、栏杆、细线等薄壳在体积渲染下出现孔洞、断裂或颗粒噪声。NeuS 与 Volumetric Rendering of Neural Implicit Surfaces 都把薄结构列为难点，二者实际差异不大。机制上，体积渲染沿射线积分密度，薄壳在有限采样数下被漏采；β 退火控制 sigmoid 密度转换的锐度，退火过快会使薄壳在早期被压平，退火过慢则表面长期模糊。Eikonal 项约束梯度的模，薄结构处梯度方向不稳定，权重过大反而放大噪声。

伪代码层面，薄结构排障的顺序应是：先查采样数是否覆盖薄壳厚度，再查 β 退火曲线是否与训练步数匹配，最后查 Eikonal 权重。一个常见失败模式是把 β 退火写成固定步数而非按损失自适应，导致薄结构在退火完成前已被平滑掉。系统代价是训练慢：NeuS 类方法本身训练慢，增加采样数与放慢退火进一步拉长周期，工程上需在薄结构保真与训练预算间取舍。

具体例子：一个含细栏杆的场景重建后栏杆断裂为点状。按表定位为几何与拓扑类，干预采样密度后断裂减少但出现颗粒，再调 β 退火曲线后颗粒收敛。这说明薄结构噪是采样与退火两个机制的耦合，单改一个旋钮只能把症状从一个形态推到另一个形态。

四 · 漂浮物与场景穿模：无约束几何的两种空间病

漂浮物指密度场在空域形成与主体不相连的孤立高密度团，渲染时表现为物体周围的悬浮碎片。机制上，NeRF 类表示只有渲染损失，没有连通性或空间先验，优化过程中射线在空域积累出局部极小密度团以解释某些视角的亮度。3D Gaussian Splatting 的显存开销大，漂浮高斯同样常见，稀疏视图下几何不稳会加剧。干预点是密度正则（如总变差或熵正则）与后处理连通分量过滤，但过滤会误删合法细结构，需与薄结构排障联动。

场景穿模指多部件组合场景中部件互相插入或悬空。PartCrafter 用组合式 latent 扩散生成部件，部件数易错，缝隙与穿插是其主要失败模式，数据需求也高。机制上，各部件独立生成，latent 之间没有显式空间约束，组合时仅按布局拼接，穿插检测缺失。干预点是在组合阶段加入碰撞约束与穿插重采样，或在 latent 空间加入部件间距离正则。

系统代价方面，漂浮物过滤是后处理，会增加管线复杂度并可能引入新的接缝；穿模重采样会增加生成轮次，部件数越多组合爆炸越明显。具体例子：一个室内场景生成后椅子腿插入地板，同时墙角出现悬浮碎片。按表分别定位为几何与拓扑类的两个条目，前者干预布局约束，后者干预密度正则，二者不能用一个旋钮同时解决。

值得强调的是，漂浮物与薄结构噪在症状上偶有重叠：薄壳断裂后的碎片也表现为悬浮点。区分方法是看碎片是否随视角变化保持空间一致：漂浮物是三维一致的密度团，薄结构噪是采样不足导致的视角相关闪烁。手册要求排障者先做多视角一致性检查，再进入原因分类。

五 · UV 接缝与 PBR 失真：后处理与材质通道的管线病

UV 接缝指网格展开后割缝处纹理不连续，表现为可见的线状色差或错位。Hunyuan3D 2.0 与 2.1 都把 UV 失败列为失败模式，后者面向生产级 PBR 材质，数据限制与推理慢并存。机制上，UV 展开算法在割缝处复制顶点，纹理烘焙时若接缝填充（seam padding）不足，采样越界会取到相邻岛的颜色；烘焙分辨率不足则接缝处细节丢失。干预点是 UV 展开算法选择、接缝填充宽度与烘焙分辨率，三者需匹配，单独提高分辨率而不填充接缝仍会露线。

PBR 失真指反照率、粗糙度、金属度通道不符合物理约束，例如金属度全为 1 导致漫反射缺失，或粗糙度被 2D 先验污染成高频噪声。Hunyuan3D 2.1 的纹理真实感是卖点，但数据限制意味着材质监督不足时通道解耦不充分。机制上，若材质通道与反照率共享同一 2D 先验梯度，先验的绘画风格会渗入粗糙度通道。干预点是通道解耦损失与材质先验，必要时对金属度做二值化正则。

系统代价方面，UV 与 PBR 都是管线末端问题，修复成本高：重新展开 UV 意味着重新烘焙全部纹理，PBR 通道修正可能需要重训材质头。具体例子：一个生成资产在正面看起来正常，转到侧面出现一条竖向色线，同时金属部件呈现塑料感。按表分别定位为管线与后处理类的两个条目，前者查接缝填充，后者查金属度通道分布。二者同属管线类但干预点不同，手册要求在速查表定位后继续查方法族分支。

另一个常见耦合是：UV 接缝填充不足会掩盖 PBR 失真。接缝处的颜色错位让排障者误以为是材质问题，实际是采样越界。手册建议先做无纹理的几何检查，再单独渲染各材质通道，把接缝与材质问题分离后再归因。

六 · 前馈管线的误差传导与条目边界

图像到 3D 的前馈管线（LRM、InstantMesh、CRM、Hi3DGen、GS-LRM、MeshLRM、LGM、Direct3D、Structured 3D Latents）共享一个失败结构：误差传导。单视图输入先经多视图生成器幻想背面，再经重建模型升维，任一环节的误差都会传到最终网格。LRM 的背面细节与网格分辨率受限，TripoSR 质量与纹理一般，GS-LRM 显存高且稀疏视图不稳，MeshLRM 训练难且需纹理后处理。手册把这些统一归入“监督与先验”类的传导分支，干预点是多视图一致性与重建分辨率。

条目边界需要明确：多面在前馈管线中表现为背面幻想，在分数蒸馏中表现为视角条件不足，二者症状同名但机制不同。手册的处理是速查表只给类别，方法族分支给机制。排障者若跳过分支直接按表干预，可能用错旋钮。例如对前馈管线调 CFG 无效，因为管线中没有分数蒸馏的 CFG 项。

具体机制上，误差传导可用链式描述：多视图生成器的视图间不一致 → 重建模型的输入分布偏移 → 网格分辨率上限截断高频 → 纹理后处理引入接缝。系统代价是推理慢与显存高并存，Hi3DGen 推理较慢，Wonder3D 显存翻倍，Structured 3D Latents 管线复杂且显存高。工程判断是：前馈管线的排障应先隔离环节，用中间多视图做一致性检查，再决定是修生成器还是修重建器。

最后落在具体机制上：手册的条目不是互斥标签，而是可叠加的归因向量。一个资产同时出现表面糊、UV 接缝与 PBR 失真时，正确做法是按管线顺序从表示容量查到后处理，而不是并行调三个旋钮。因为后处理问题会伪装成表示问题，而表示问题无法靠后处理修复。条目边界的作用是强制排障者先确定误差进入管线的位置，再选择干预点。
