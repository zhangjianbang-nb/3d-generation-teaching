一 · 条目边界：数据集与许可到底管什么

“数据集与许可”这一附录条目，管的不是模型结构，也不是渲染算法，而是 3D 生成流水线最前端那一段：资产从哪来、以什么形式进来、以什么条款被使用、进来之后要洗成什么样。它把 Objaverse、Objaverse-XL、ShapeNet、Thingi10K 四个名字并列，说明这条目关心的不是单一数据集，而是一条谱系：从早期按类目组织、规模有限、许可相对统一的 CAD 风格数据集，到靠互联网爬取、规模膨胀、许可高度异质、必须逐条清洗的资产池。条目说明里“规模、来源、许可与清洗建议”四个词，正好对应四个必须分开处理的维度，混在一起谈就会把工程问题谈糊。

先把四个维度各自的定义钉住。规模指条目数与资产粒度（是整场景、整物体还是部件），它决定下载带宽、磁盘占用、索引结构和采样策略；来源指资产的生产方式与采集渠道（人工建模、CAD 导出、扫描重建、网页爬取），它决定几何质量分布与元数据完整度；许可指每条资产附带的授权条款及其可再分发、可商用的边界，它决定哪些资产能进训练集、哪些只能进评测集、哪些必须隔离；清洗建议指针对上述三项缺陷所做的过滤、修复与重标注动作，它决定训练前的数据工程预算。四者不是并列的美德，而是互相拉扯的约束：规模越大，许可越杂，清洗成本越高；清洗越狠，有效规模越小。

一个具体的机制性区分：许可不是数据集级别的属性，而是条目级别的属性。把“这个数据集是 CC-BY”当成整体判断，是这类工作里最常见的错误。真实资产池里，同一批下载里会同时出现 CC0、CC-BY、CC-BY-SA、CC-BY-NC、以及各类自定义条款，还有大量没有明确标注的条目。工程上必须把许可当成每条记录的一个字段，而不是一个全局常量。这直接导致索引结构的设计：许可字段必须可查询、可过滤，训练采样器必须能按许可白名单做掩码，否则一次误采样就会把不可再分发的资产带进产物。

再看“清洗建议”为什么必须单独成维。3D 资产的缺陷类型和 2D 图像完全不同：破面、非流形边、重复顶点、法线翻转、单位不一致、原点偏移、纹理丢失、材质引用断裂、多物体粘连成单文件。这些缺陷不会让文件打不开，却会让可微渲染的梯度变得没有意义——一个法线翻转的网格渲染出来是黑的，一个单位是毫米的资产和一个是米的资产混在同一批里，尺度先验直接崩掉。清洗不是“锦上添花”，它是让后续所有渲染损失可用的前置条件。

二 · 来源谱系：从 CAD 到网页爬取的质量断层

四个名字排在一起，隐含一条质量断层线。ShapeNet 这一类资产的来源是受控的：建模者按类目规范生产，坐标系、朝向、尺度有约定，部件切分有标注体系。它的代价是覆盖窄——类目表是封闭的，长尾物体不在其中。Thingi10K 的来源是 3D 打印社区，模型为打印而建，因此天然带有“可打印性”约束：薄壁、自交、非流形是常见缺陷，但整体几何是闭合意图明确的。Objaverse 与 Objaverse-XL 的来源是网页爬取，资产的生产目的五花八门——游戏素材、建筑可视化、科学可视化、扫描重建、程序化生成，元数据靠页面文本推断，质量分布是重尾的。

来源决定的第一件事是元数据可信度。受控来源的类目标签是生产时写入的，可以直接当监督信号；爬取来源的标签是从页面标题、描述、tag 里抽出来的，噪声极大，同一个物体可能被标成完全不同的词。工程上的机制是分层：把元数据分成“生产时写入”“页面抽取”“模型推断”三级，训练时按级别给不同权重，或者只在第一级上做类目条件。第二件事是几何尺度。受控来源有统一单位约定，爬取来源里同一个物体可能以毫米、厘米、米、甚至无量纲单位出现。尺度不统一会直接破坏任何依赖绝对尺度的先验，也会让多视图渲染的相机采样范围失去意义。

这里可以写出一个尺度归一化的判定式，用来把“是否需要对某条资产做重缩放”变成一个可执行规则：

$$\hat{s}=\frac{\text{median}_{i}\lVert \mathbf{p}_i-\bar{\mathbf{p}}\rVert}{r_0},\qquad \text{rescale if } \hat{s}\notin[1/\kappa,\ \kappa]$$

其中 $\mathbf{p}_i$ 是顶点，$\bar{\mathbf{p}}$ 是包围盒中心，$r_0$ 是目标参考半径，$\kappa$ 是容忍倍数。这个式子的作用不是精确测量，而是把“这条资产明显不在合理尺度上”筛出来。它的系统代价是：对每条资产都要算一次中位半径，这在百万级资产池上是一次全量遍历，必须和下载、解压、解析流水线合并，否则会多出一整轮 IO。

失败模式很具体：不做来源分层，直接把爬取资产和受控资产混在一起训练一个以尺度为条件的生成器，生成器会学到“同一语义对应多个尺度”的矛盾分布，表现为采样时同一提示词产出忽大忽小的物体，或者在可微渲染阶段因为相机近远平面设置不当而出现大面积空洞。另一个失败模式是元数据污染：把页面抽取的标签当类目监督，模型会把“下载”“免费”“collection”这类页面词学成类目，生成结果的语义条件随之漂移。

具体例子：一条从网页爬来的资产，文件名是“chair_final_v3.obj”，页面标题写着“office furniture set”，tag 里有“chair”“table”“set”，实际文件里是四把椅子和一张桌子粘在一个网格里。来源分层机制会把它标为“页面抽取、多物体未切分”，清洗阶段要么切分，要么整条隔离出对象级训练集。若不做这一步，对象级生成器会把“多物体粘连”当成一种合法形状学进去。

三 · 许可分层：条目级字段与可再分发边界

许可问题的核心不是“能不能用”，而是“哪一种用”。工程上必须把使用场景拆成至少三层：内部训练、产物再分发、产物商用。三层对应三条不同的许可白名单，不能共用一套过滤规则。CC0 类条款在三层都可用；CC-BY 类在再分发时需要署名，工程上意味着产物必须携带来源清单；CC-BY-SA 类具有传染性，产物再分发可能要求同条款，这与很多商业管线的许可不兼容；CC-BY-NC 类禁止商用，只能在内部训练或研究评测中使用；自定义条款与未标注条目必须默认隔离，不能默认放行。

机制上，这要求索引里有一个许可状态机，而不是一个布尔字段。状态至少包括：已识别且允许、已识别但限制、未识别、冲突（同一资产多个来源给出不同条款）。采样器按目标场景选择状态子集，训练日志记录每次采样命中的许可分布，产物导出时附带来源清单。这个状态机的系统代价是索引体积和查询复杂度上升：每条记录多出若干字段，过滤从一次哈希查找变成一次条件判断，百万级采样时这部分开销会体现在数据加载线程上，必须和图像解码、几何解析并行化，否则会成为吞吐瓶颈。

一个可执行的过滤伪代码思路，写成条件链而非循环体：

$$\text{admit}(a)=\big(\text{lic}(a)\in W_{\text{scene}}\big)\land\big(\text{src}(a)\ge \tau_{\text{src}}\big)\land\big(\text{geom}(a)\ \text{passes}\ G\big)$$

其中 $W_{\text{scene}}$ 是当前场景的许可白名单，$\tau_{\text{src}}$ 是来源可信度阈值，$G$ 是几何检查集合。三个条件必须同时成立才进入训练池。写成合取而不是打分排序，是为了让拒绝原因可归因：每条被拒资产都能落到一个具体条件上，便于后续审计和补洗。

失败模式有两类。第一类是许可泄漏：训练时用了 NC 资产，产物被再分发，法律风险落在产物上而不是训练过程上，这类问题在事后审计时才暴露，代价是整批产物召回。第二类是过度过滤：为了安全把未标注条目全部丢弃，有效规模骤降，长尾覆盖被削掉，生成器在稀有类目上退化。第二类失败不会报错，只会表现为“某些提示词生成质量明显差”，很难归因到数据过滤。工程判断是：未标注条目不应直接进再分发产物的训练池，但可以进内部表征学习或评测，前提是产物侧有隔离机制。

具体例子：同一把椅子在资产池里有三个副本，分别标注 CC0、CC-BY、无标注。按条目级状态机，三条记录状态不同，采样时只有前两条进商用白名单，第三条进隔离区。若按数据集级判断，整个池子被当成一个许可，三条记录会被同等对待，泄漏或过度过滤必然发生其一。

四 · 清洗流水线：几何修复与去重的顺序问题

清洗建议在条目说明里和规模、来源、许可并列，说明它不是可选项。清洗的对象可以分成四层：文件层（能否解析、引用是否完整）、几何层（流形性、自交、法线、单位）、外观层（纹理缺失、材质引用断裂、UV 重叠）、语义层（类目标签、部件切分、多物体粘连）。四层的修复顺序不能随意：文件层必须先过，否则后续解析全部失败；几何层要在去重之前做，因为破面会让基于几何特征的近重复判定失准；外观层要在几何修复之后做，因为重拓扑会破坏原有 UV；语义层最后做，因为它依赖前三层的稳定结果。

去重是清洗里最容易被低估的一环。资产池里同一物体常以不同格式、不同简化级别、不同缩放出现，甚至同一文件被不同用户重复上传。近重复判定需要几何特征，常用做法是采样点集或体素化后的统计量。一个可写的判定思路是：

$$d(a,b)=\big\lVert \phi(a)-\phi(b)\big\rVert_2,\qquad \text{merge if } d(a,b)<\epsilon\ \land\ \text{lic-compatible}(a,b)$$

其中 $\phi$ 是几何特征映射（例如归一化后的点集统计或体素占据率），$\epsilon$ 是阈值。注意第二个合取项：许可不兼容的两个副本不能简单合并成一条，否则会把限制性条款洗掉。合并时保留最严格的许可状态，这是工程上唯一安全的做法。

系统代价在去重的复杂度上。全量两两比较在百万级池子上不可行，必须用近似最近邻索引，而索引构建本身是一次全量特征提取，和几何解析共享 IO。另一个代价是修复工具链的不可逆性：自动重拓扑和破面修补会改变几何，一旦修坏，原始资产无法回滚，所以清洗必须保留原始文件与修复日志，磁盘占用翻倍。失败模式是“修复引入新缺陷”：自动补洞在薄壁结构上会生成自交面，法线重算在非流形边上会翻转局部朝向，这些缺陷在渲染时表现为局部黑斑或穿透，训练损失会把这些当成合法外观学进去。

具体例子：一条从打印社区来的资产，壁厚远小于常规尺度，自动补洞工具按默认参数操作，把薄壁两侧的洞连成了一片，模型从“空心壳体”变成“实心块”。几何检查如果只看是否闭合，这条资产会通过；只有加上壁厚与体积比检查才会被拦下。这说明清洗规则必须是多维的，单一闭合性检查不足以描述几何质量。

五 · 与可微渲染管线的接口约束

数据集条目最终要服务于渲染与生成，因此清洗与许可的产物必须满足下游接口的约束。可微渲染对资产的要求比可视化浏览更严：网格必须是可微渲染器能稳定求交的，法线必须一致，UV 必须无重叠，材质引用必须可解析。以 NeRF 类方法为例，多视角照片的 RGB 损失要能优化 3D 场，前提是相机位姿与资产尺度在同一坐标系下自洽；资产尺度不统一，射线采样范围就要逐条调整，采样器复杂度上升。以 3DGS 类方法为例，高斯基元的初始化常从点云或网格采样，破面与自交会让初始化分布出现空洞与尖刺，致密化阶段会把这些缺陷放大成漂浮伪影。

接口约束可以写成一个准入条件：资产进入渲染训练池前，必须通过“可渲染性”检查，即用固定相机环架渲染若干视角，检查覆盖率与深度一致性。覆盖率过低说明法线或面片朝向有问题，深度不一致说明自交或非流形。这个检查的系统代价是每条资产都要跑一次渲染，属于计算密集环节，必须和清洗流水线并行，且要限制视角数以免预算失控。失败模式是把不可渲染资产放进训练池：渲染损失在这些资产上恒为高值，梯度方向被噪声主导，模型在其他资产上的收敛也被拖慢。

许可与渲染的交叉点在产物侧。可微渲染训练出的 3D 表示（网格、高斯、隐式场）在导出时，其来源清单必须能追溯到训练时命中的资产许可。这意味着训练日志要记录采样命中的资产 ID 与许可状态，产物导出工具要能聚合这份日志。工程判断是：许可追踪不是法务事后补的工作，它必须是数据加载器的一个内建输出，否则在百万级采样下无法重建来源。

具体例子：一条资产在几何上通过检查，但纹理引用指向一个不存在的相对路径。可视化工具会显示为纯色，可微渲染器则会在材质解析处报错或退化为默认材质，训练时这条资产的外观监督变成常数，梯度对纹理分支没有信息。清洗流水线若只做几何检查，这条资产会静默污染外观训练。接口约束要求外观层检查与几何层检查并列，且都在准入之前完成。

六 · 速查表的用法：先定场景再定过滤

把上面几节收束成一个可操作的判断顺序：先定使用场景（内部训练、再分发、商用），由此定许可白名单；再定来源可信度阈值，由此定元数据使用级别；再定几何与外观检查集合，由此定清洗预算；最后才看规模，因为规模是在前三步过滤之后剩下的有效规模，而不是原始条目数。这个顺序不能倒过来：先看规模再定过滤，会导致预算按原始规模分配，实际有效数据远小于预期，训练计划失准。

速查表的每一列对应一个可查询字段，工程上应把这张表落成索引 schema，而不是文档里的说明。规模列对应条目计数与粒度字段，来源列对应采集渠道与生产方式字段，许可列对应条目级状态机字段，清洗列对应已执行的修复动作与检查结果字段。只有落成 schema，过滤才是可执行、可审计、可复现的。失败模式是把这张表当成人读的参考：人读了知道要注意许可，但采样器不知道，于是过滤逻辑散落在脚本里，版本之间不一致，复现实验时无法重建同一数据子集。

最后一个机制性判断：数据集条目的价值不在于它列了哪几个名字，而在于它把“规模、来源、许可、清洗”四件事强制分开。任何把这四件事合并成一个“数据质量分”的做法，都会在某一维上失守而不自知。许可是法律边界，来源是质量分布，清洗是工程预算，规模是结果而非起点。四者分开建模，才能在资产池扩张时保持过滤逻辑的可解释性；合并成一个分数，扩张带来的异质性会被平均掉，缺陷以生成质量退化的形式延迟暴露。
