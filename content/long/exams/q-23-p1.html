一 · 三档答案的骨架：从“能答”到“答穿”

这道题在评分表上被切成两块：输入输出占四成，为何用卷积占六成。三档答案的差别不在字数，而在每一块是否落到机制层。及格档的典型形态是把参考答案复述一遍：六视图加位姿进，带纹理网格出，卷积因为局部性和平移等变性更合适，还比全局注意力便宜。四句话都对，但每一句都停在名词上，没有回答“三平面到底是什么张量”“卷积在哪一层做精修”“便宜在哪一项开销”。良好档会补上三平面的结构：六个视角的图像特征被拼成三张正交的二维特征图，卷积在这三张平面上做局部精修，再把平面特征解码成密集体素或网格。到这里，输入输出的链路已经闭合，但“为什么不是 Transformer”仍然只给了结论。满分档必须把卷积的必要性拆成可验证的机制：三平面是 2D 结构，卷积的归纳偏置与它同构；跨视图对应在特征拼接阶段已经由位姿完成，重建阶段要的是局部高频补全而不是全局再匹配；全局注意力的代价随 token 数二次增长，而三平面上的卷积是固定邻域、线性于像素数。三档之间的落差，本质是“结论—链路—机制”的落差。

评分演练时，一个可操作的判据是：把答案里的每个断言反过来问一句“凭什么”。及格档答不出“凭什么”，良好档能答出链路，满分档能答出代价项和失效条件。比如“卷积比 Transformer 便宜”这句话，及格档只说便宜；良好档会说注意力是全局的、卷积是局部的；满分档会指出三平面被离散成像素网格后，全局注意力要在所有平面像素两两之间建关联，token 数随分辨率平方增长，而卷积核的感受野固定，计算量随像素数线性增长。这不是文字游戏，而是评分人区分档位的实际抓手。

二 · 输入输出的数字底账：6、3、2、1

把输入输出写成一张账本，比背一句话更抗追问。输入侧的第一项是 6 个视角的图像，每个视角带一个位姿。位姿不是可选附件，它决定了六个视角的特征如何被放到同一个世界坐标系里；没有位姿，六张图只是六张互不相干的照片，拼接三平面时无从对齐。第二项是相机参数与位姿构成的几何条件，它把“稀疏视图”这个前提变成可计算的投影关系。第三项是每个视角提取出的图像特征，这些特征随后被拼成三平面。三平面是 3 张正交的二维特征图，分别对应三个坐标平面；把 6 个视角的特征投到这 3 张平面上，是把稀疏视角压成稠密表示的中间步骤。输出侧只有一项：带纹理的网格，即几何加上表面颜色。中间产物是密集体素或三平面特征，它不是最终答案，但它是从平面到网格的桥。

这条链路可以用一个粗粒度的伪代码思路固定下来：

$$\text{for } v \in \{1,\dots,6\}:\ f_v = E(I_v),\quad \text{plane}_{xy},\text{plane}_{yz},\text{plane}_{zx} \leftarrow \text{scatter}(f_v, \pi_v)$$
$$\hat{P} = \text{ConvStack}(\text{plane}_{xy},\text{plane}_{yz},\text{plane}_{zx}),\quad M = \text{Extract}(\hat{P})$$

第一行是特征提取与按位姿投影，第二行是卷积精修与网格提取。账本上的数字是 6、3、2、1：6 个视角、3 张平面、2 维卷积结构、1 个带纹理网格。评分时，输入输出这四成里，漏掉位姿是硬伤，漏掉“带纹理”也是硬伤，把三平面说成三维体素则是概念错位。常见错误里“以为 CRM 不用位姿”正好命中这一条：六视图如果没有位姿，拼接三平面这一步就退化成无锚点的特征堆叠，后续卷积再强也补不回几何一致性。

系统代价在这里第一次出现：三平面的分辨率是显存与精度的直接 trade-off。平面像素越密，局部细节保留越多，但三张平面上的卷积激活和特征缓存同步增长；平面太粗，高频纹理在投影阶段就被抹平，后面卷积无法凭空造出没被采样的细节。失败模式是“平面分辨率与视角覆盖不匹配”：稀疏视角在某些平面上留下大片未观测区域，卷积在该区域的输出是外推而非重建，表现为网格局部发糊或纹理错位。具体例子：六个视角集中在物体前半侧时，背面平面上的特征稀疏，卷积核在空白邻域上滑过，输出的背面几何只能靠对称先验猜，纹理则出现拉伸。

三 · 为何卷积：三平面的 2D 结构与归纳偏置同构

“为什么不用 Transformer”要答穿，先要承认 Transformer 的长处：全局注意力擅长建立远距离对应，在跨视图匹配、长程依赖上确实有优势。但 CRM 的重建阶段面对的不是原始图像集合，而是已经被位姿对齐、拼成三平面的 2D 特征图。此时任务性质变了：跨视图对应已经在投影与拼接阶段完成，剩下的是在每张平面上做局部精修——补全稀疏采样留下的空洞、锐化被平均掉的边缘、把平面特征解码成连贯的几何。这类操作的需求是局部邻域的平滑与高频恢复，恰好是卷积归纳偏置的射程。局部性意味着每个输出像素只依赖固定邻域，平移等变性意味着同一纹理模式在平面任何位置都被同一组核响应，这两条性质与 2D 特征图的结构同构。

反过来看全局注意力在三平面上的代价。三平面被离散成像素网格后，若在其中做全局自注意力，token 数是三张平面像素数之和，注意力矩阵是 token 数的平方。平面分辨率翻倍，token 数翻四倍（三张平面各自边长翻倍），注意力矩阵元素数翻十六倍。卷积则不同：核大小固定，计算量随像素数线性增长，显存里只需保存局部激活。这就是“比 Transformer 的全局注意力便宜”的机制来源，不是笼统的“卷积更轻”，而是复杂度阶数不同。用公式表示，若单张平面边长为 $N$，三平面 token 数 $T \propto 3N^2$，全局注意力代价为：

$$\text{Cost}_{\text{attn}} \propto T^2 \propto N^4,\qquad \text{Cost}_{\text{conv}} \propto T \cdot k^2 \propto N^2$$

其中 $k$ 是卷积核边长。这个对比只在“重建阶段”成立：如果任务退回原始六视图之间的任意对应，全局注意力仍有其位置。CRM 的设计判断是把对应交给位姿与拼接，把精修交给卷积，分工明确。常见错误“以为卷积不能做跨视图对应”正是把分工读反了：卷积确实不擅长在六张原始图之间做无锚点的全局匹配，但 CRM 不需要它在那一层做匹配，匹配已由位姿完成。另一个常见错误“忽略三平面的 2D 结构”则直接抹掉了卷积成立的前提——把三平面误当成无序点集或三维体素，就会得出“卷积不够全局”的错误结论。

失败模式在这里是“把卷积用在错误的层级”：若在拼接之前就用卷积在六视图特征上做跨视图融合，缺少位姿锚点，卷积的平移等变性反而变成负担，因为不同视角的同一物体在不同图像坐标上，局部核无法对齐。具体例子：同一物体的正面纹理在视角一和视角二里出现在完全不同的像素位置，没有位姿投影，卷积核在两张图上分别响应，融合结果是把两个错位模式平均掉，纹理被抹成一片。

四 · 评分演练：四句话如何被追问到机制层

拿参考答案的四句话做一次逐句演练，能看清每一档答案缺什么。第一句“6 个视角的图像特征拼成三平面”：及格档到此为止；良好档会补“每个视角带位姿，特征按位姿投到三张正交平面”；满分档会补“拼接是把稀疏视角压成稠密 2D 表示的降维步骤，三平面是 2D 不是 3D”。第二句“用卷积网络把三平面精修成高分辨率网格”：及格档只说精修；良好档说“卷积在平面上做局部补全，再解码成网格”；满分档说“精修的目标是高频与空洞，卷积的固定感受野与平移等变性匹配这一目标，且计算量线性于像素数”。第三句“卷积的局部性与平移等变性更适合图像/平面特征”：及格档复述；良好档把它与三平面的 2D 结构挂钩；满分档指出这是归纳偏置与数据结构的同构，并给出反例——在三平面无序点集上该偏置失效。第四句“比 Transformer 的全局注意力便宜”：及格档只说便宜；良好档说注意力全局、卷积局部；满分档给出 $N^4$ 对 $N^2$ 的阶数差，并限定“仅在重建阶段”。

评分表上 40% 与 60% 的切分也对应这个演练。输入输出那 40% 里，6 视图、位姿、三平面、带纹理网格四个要素各占一块，漏一个就掉一档；为何卷积那 60% 里，局部性、平移等变性、2D 结构同构、代价阶数差是四个采分点，只答“卷积更好”而不给机制，最多拿良好档的下沿。演练时可以自设追问：如果评分人问“三平面为什么不是体素”，答“三平面是三张 2D 特征图，体素是 3D 网格，卷积在 2D 上做局部精修，计算与显存都低一个维度”；如果问“位姿能不能省”，答“不能，省掉位姿拼接就失去几何锚点，六视图特征无法对齐到同一平面”。这两问两答，正好覆盖常见错误里的两条。

系统代价在评分演练里也要能说出来：三平面分辨率提升带来显存压力，卷积层数加深带来感受野扩大但参数与激活同步增长；若为了省显存把平面压粗，纹理细节在投影阶段丢失，卷积无法恢复。失败模式是“用 Transformer 替换卷积做精修”时的显存爆掉：平面分辨率稍高，全局注意力矩阵就超出单卡容量，训练被迫降分辨率，反而丢掉比卷积方案更多的高频。具体例子：同一稀疏视图输入，卷积方案在较高平面分辨率下完成精修，注意力方案因 token 数平方增长被迫减半分辨率，输出网格的边缘锐度下降——这不是定性猜测，而是复杂度阶数决定的工程后果。

五 · 判分点的交叉验证：每个采分点配一个反例

四个判分点各自配一个反例，能把“答对”与“答穿”分开。判分点一“6 视图输入”：反例是只写“多视图图像”而不写 6，或写了 6 却漏位姿；交叉验证的问法是“六个视角的特征凭什么能拼到同一组平面上”，答案必须落到位姿投影。判分点二“卷积精修三平面”：反例是把卷积说成“在六视图上做融合”，或把三平面说成体素；问法是“卷积的核在哪个数据结构上滑动”，答案必须是 2D 平面像素。判分点三“输出带纹理网格”：反例是只写“网格”漏纹理，或只写“三平面特征”当输出；问法是“最终交付物是特征还是可渲染表面”，答案必须是几何加颜色。判分点四“卷积比全局注意力便宜”：反例是只说“更快”不给代价项；问法是“便宜在哪个复杂度阶数上”，答案必须给出 token 数平方对像素数线性的对比。

这四个反例对应四类失败模式。漏位姿导致几何不一致；把卷积放错层级导致跨视图错位平均；漏纹理导致输出不可渲染；只说便宜不给阶数导致论证空心。每一个都能在评分表上定位到具体扣分块：前两个落在输入输出 40% 里，后两个落在为何卷积 60% 里。演练时按这个交叉表自检，比通读参考答案更能发现空洞。具体例子：一份答案写了“CRM 用卷积因为卷积局部性好，Transformer 全局太贵”，四个判分点里只命中半个——没有 6、没有位姿、没有三平面 2D 结构、没有阶数对比，按表只能落在及格档。

工程判断在这里收束：这道题考的不是“卷积好不好”，而是“在什么数据结构上、什么任务层级上、什么代价约束下，卷积是正确选择”。三平面是 2D、对应已由位姿完成、精修要局部高频、显存要线性增长，四条同时成立时卷积是机制上的必然，而不是风格偏好。答穿这道题的人，应当能反过来指出：若把任务换成无位姿的多视图任意对应，或把表示换成无序点云，卷积的归纳偏置就失去同构对象，此时全局注意力重新获得位置。这种“条件成立才成立”的表述，才是满分档与良好档的真正分界。
