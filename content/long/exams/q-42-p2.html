二 · 变体一：把「文本到可穿越世界」换成「图像到可穿越世界」，拆分逻辑如何迁移

原题问的是文本入口。把入口换成一张概念图，WorldGen 式的拆分并不会消失，但每一段的职责边界会移动。布局段不再由 LLM 从零生成场景图，而是先从图像里抽取可度量的空间结构：相机估计给出视锥与地平线，单目深度给出相对尺度，语义分割给出物体类别与掩码，平面拟合给出地面与墙面的支撑关系。随后仍然要落到一张场景图上，只是这张图带着从像素反推出来的初始位姿与包围盒。程序化资产段的任务从「按语义生成」变成「按几何匹配」：检索或生成与掩码轮廓、深度剖面一致的资产，并把资产的原点、朝向、碰撞体对齐到估计出的位姿。扩散补全段则从「补全未见区域」变成「去噪与扩边」：把低置信度的深度边缘、被遮挡的背面、图像外的世界用扩散模型补出来，同时保持与已有像素的风格一致。

迁移的关键机制是「尺度锚定」。文本入口没有天然尺度，布局段必须自己约定一米等于多少世界单位；图像入口的深度是相对深度，必须用一个锚把相对深度换成米。常用做法是假设地面平面已知，用相机高度作为锚：

$$Z_{\text{metric}} = \frac{h_{\text{cam}} \cdot f}{y_{\text{ground}} - y_{\text{horizon}}}$$

其中 \(h_{\text{cam}}\) 是假设的相机离地高度，\(f\) 是焦距像素值，\(y_{\text{ground}}\) 与 \(y_{\text{horizon}}\) 是像素纵坐标。这个式子一旦锚错，整张场景图的尺度就整体缩放，碰撞体、门宽、台阶高度全部失真。系统代价在这里非常具体：图像入口的误差是「乘性」的，尺度错一次，后面所有程序化放置的门都过不去；文本入口的误差是「加性」的，某个物体放错位置只影响局部。失败模式是「看起来对、走进去不对」：渲染图与输入图高度相似，但角色一迈步就卡在门框里，因为门宽是按错误的尺度生成的。

具体例子：输入一张走廊概念图，分割出左侧连续墙面、右侧三扇门、尽头一扇窗。深度估计把走廊长度估成 6 米，而实际语义上这是一条公共建筑走廊，按门高 2.1 米反推应约 18 米。若不做门高锚定，程序化段会生成三扇间距 1 米的门，角色碰撞体半径 0.4 米，两门之间只剩 0.2 米净空，连通性直接失败。追问会落在「你用什么锚、锚的置信度如何传播到下游」这一点上。

三 · 变体二：把「可穿越」收紧为「可交互且可破坏」，组合管线要多出哪一段

原题的可穿越约束是尺度、碰撞、连通性、交互。若把交互升级为「可破坏」，即墙体可被打穿、物体可被推动并改变连通性，那么原来的三段组合不够用，必须插入一段「结构语义与物理属性绑定」。机制上，布局段产出的场景图节点要从「类别 + 位姿 + 包围盒」扩展为「类别 + 位姿 + 材质 + 结构角色 + 连接关系」。结构角色区分承重墙、隔断、装饰面；连接关系记录门洞、窗洞、通道的拓扑。程序化资产段要为每个节点生成两层表示：渲染网格与碰撞/破坏网格。破坏网格通常是凸分解或体素化的低模，带预计算的断裂面或可切分单元。扩散段只负责外观，不参与物理。

这里必须给出一个可执行的判定思路，而不是空谈。连通性在破坏后要重新验证，可以用图搜索的伪代码表达：

  • 把场景离散为可行走栅格，标记静态障碍与动态障碍；
  • 对每个可破坏单元，预计算其被移除后受影响的栅格集合；
  • 破坏事件发生时，只增量更新受影响集合，再在区域图上跑一次连通性查询；
  • 若起点与目标不再连通，触发「保底通道」规则：保留至少一条不经过该区域的路径，否则拒绝该次破坏或改为局部破损。

系统代价是组合爆炸与状态同步。可破坏意味着场景图不再是静态的，程序化段生成的资产要携带「破坏后形态」，扩散段生成的外观贴图要在断裂面上仍然合理，否则打穿后看到的是没有纹理的黑洞。误差叠加在这里最危险：布局段把一堵墙标成承重，程序化段给了它不可破坏的碰撞体，而扩散段给它生成了薄薄一层装饰面，玩家打上去发现「视觉上碎了、物理上没碎」，交互反馈断裂。失败模式是「破坏后世界漏气」：墙体被移除后，角色掉出可行走区域，因为破坏网格与渲染网格的边界不一致，碰撞体没有随破坏单元一起更新。

具体例子：一间石砌房间，四面墙中两面是承重、两面是隔断。玩家用范围攻击打掉一面隔断，增量更新移除了对应栅格，连通性查询发现房间与外侧走廊连通，允许通过。若同一击波及承重墙，规则拒绝该单元破坏，只在其表面生成裂纹贴图。这个例子能直接检验答题者是否理解「结构角色」与「破坏网格」是两套表示，而不是一句「加个物理引擎」。

四 · 变体三：把「单次生成」改为「流式生成」，管线的时间预算如何重排

原题隐含一次性产出整个世界。若改成玩家边走进边生成，三段组合的调用顺序与预算必须重排。机制上，布局段从「全局场景图」变成「分层场景图」：先出一个粗粒度的区域图，只含区块划分、主干通道、地标位置；玩家接近某区块时再细化该区块的场景图。程序化资产段从「批量放置」变成「按需实例化」，用对象池与延迟加载控制峰值。扩散段从「离线补全」变成「在线补全」，只对当前视锥内、且置信度低的区域做补全，远处用低分辨率占位。

时间预算可以用一个简单的约束表达：设每帧预算为 \(B\)，布局细化耗时 \(t_L\)、资产实例化 \(t_A\)、扩散补全 \(t_D\)，则必须满足

$$t_L + t_A + t_D \le B - t_{\text{render}} - t_{\text{physics}}$$

这个式子暴露了组合管线的真实代价：三段不是并行的，布局细化会阻塞资产实例化，资产实例化会阻塞碰撞体注册，扩散补全又要等几何确定后才能做。失败模式是「边界可见」：玩家走到区块交界处，前方还是低分辨率占位，一步跨过去触发细化，出现明显的几何跳变与贴图闪烁。另一个失败模式是「预算挤占」：扩散补全为了保帧率被降级，导致近处纹理糊，而远处占位反而清晰，视觉一致性被破坏。

具体例子：一条长街，区块长度设为 20 米，玩家移动速度 4 米每秒，则每 5 秒触发一次区块细化。若单次细化耗时 300 毫秒，必须在这 5 秒内分摊，否则在触发帧出现卡顿。工程判断是：把布局细化提前到「距玩家两个区块」时启动，用预取掩盖延迟；把扩散补全限制在「距玩家一个区块内」；碰撞体注册必须与资产实例化同帧完成，不能延后，否则出现「看得见、穿得过」的穿模。追问会集中在「预取距离怎么定、降级策略的优先级怎么排」。

五 · 五个追问：从机制到工程取舍

追问一：布局段用 LLM 生成场景图，如何保证它输出的空间关系是「可计算的」而不是「可读的」？回答要落到表示上：场景图节点带位姿与包围盒，边带关系类型（相邻、包含、朝向、通道），LLM 的输出必须经过一个 schema 校验器，把自然语言关系翻译成约束，再交给一个约束求解或采样器落地。失败模式是 LLM 写出「门在墙的左边」但没给坐标系，落地时朝向随机。

追问二：程序化资产段如何避免「资产库穷举」？机制是参数化资产与检索加变形：按类别检索基础网格，再按包围盒尺寸、材质、结构角色做非均匀缩放与拓扑替换。代价是变形后的碰撞体要重新生成，不能直接缩放原碰撞体，否则薄墙变厚墙后碰撞体穿透。

追问三：扩散补全如何与几何对齐？关键是条件注入：把深度图、法线图、语义掩码作为条件通道，扩散只在这些条件约束下生成颜色与细节。失败模式是扩散「自作主张」改了窗洞位置，导致贴图与几何错位，玩家看到窗框悬空。

追问四：组合管线的误差如何归因？需要一个分段验收机制：布局段验收连通性与尺度，程序化段验收碰撞体覆盖率与可交互标记，扩散段验收视觉与几何的一致性。每一段有独立的通过标准，避免「渲染好看就整体通过」。代价是验收本身要花工程成本，且段间接口要稳定。

追问五：为什么不能用一个 3D 生成模型端到端替代？因为可穿越是「多约束同时满足」：几何真实、尺度正确、碰撞完备、连通、可交互。单一生成模型的输出是几何与外观的联合分布，它没有显式的碰撞体与拓扑表示，也没有约束求解器去保证门宽大于角色直径。组合管线的价值不是每段更强，而是每段可以被单独验证与替换。

六 · 扣分点、常见错误与教学建议

扣分点按评分标准拆成两块。拆分部分占 60%，扣分集中在：只列出「LLM、程序化、扩散」三个词而不说明各自管什么；把布局说成「生成文本描述」而不是「生成可落地的场景图与空间关系」；漏掉「可穿越/交互约束」这一判分点，把组合管线讲成纯视觉管线。为何不能单模型部分占 40%，扣分集中在：只说「一个模型不够强」而不指出具体约束；忽略碰撞与连通性；把「视觉好」等同于「能玩」。常见错误有三类：以为端到端一个模型能同时出几何与碰撞；以为扩散补全可以替代程序化结构；以为场景图只是给 LLM 看的中间文本，不参与下游计算。

教学建议要落到可检验的动作上。第一，让学生手写一张最小场景图的 schema，包含节点位姿、包围盒、关系边、结构角色，再用一个简单约束检查器验证门宽与角色直径。第二，给一个「视觉对但走不通」的案例，让学生定位是哪一段的误差、如何归因。第三，把三个变体题作为迁移练习，要求学生说明「哪一段职责移动了、新增了哪一段、时间预算如何变」。第四，用表格对照三档答案的差异，让学生自己标出判分点对应的句子。

判分点及格答案的表现满分答案的表现
LLM 布局提到 LLM 生成场景说明场景图含位姿、包围盒、关系边，且经 schema 校验落地
程序化资产/结构提到放置物体说明参数化资产、碰撞体与破坏网格两层表示
扩散补全提到生成纹理说明以深度/法线/掩码为条件，只补低置信区域
可穿越/交互约束提到能走给出尺度锚定、连通性查询、破坏后增量更新
组合管线说三个模块组合说明段间接口、误差叠加、分段验收与时间预算

工程判断落在最后一点：组合管线的可靠性来自「每段可被单独证伪」。布局段可以被连通性检查证伪，程序化段可以被碰撞覆盖率证伪，扩散段可以被几何一致性证伪。一个端到端模型无法被这样分段证伪，它的失败只能整体观察，归因困难。因此即便某一天单一模型在视觉上追平组合管线，只要它不暴露可验证的中间表示，工程上仍然会选择保留布局与碰撞的显式层，把生成模型放在外观与细节的位置。
