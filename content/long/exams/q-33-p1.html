一 · 三档答案的分层标准与判分锚点

这道题在评分表上被切成两块：三通道占 50%，delighting 占 50%。这个对半切不是随意定的，它对应着一条因果链的两端——一端是“PBR 需要什么输入”，另一端是“这些输入怎么从训练图里被还原出来”。任何一档答案都必须同时覆盖这两端，否则即使某一边讲得再细，总分也会被腰斩。判分点明确列了四项：base color、metallic、roughness；PBR 与重光照；delighting 去光照；引擎标准输入。这四项就是三档划分的锚点，下面逐档拆开。

及格档的特征是“名词到位、关系断裂”。考生能说出 PBR 需要 base color、metallic、roughness 三个通道，也知道只给一张 RGB 纹理不行，但说不清为什么不行。典型表述是“因为 PBR 要三个通道所以给三个通道”，把结论当理由。对 delighting，及格档通常只给一句“去掉光照”，不区分反照率与阴影/高光残留，也不提误差。这一档能拿到三通道部分的基础分，delighting 部分只能拿到“知道有这一步”的分，合起来是勉强过线。

良好档的特征是“机制连通、代价缺位”。考生能把三通道与重光照挂上钩：单张 RGB 把金属度和粗糙度烘死在颜色里，换一个光照环境，高光位置和反射强度就全错了，因为渲染器拿不到独立的 metallic/roughness 去驱动 BRDF。对 delighting，良好档能说出去光照是为了得到反照率，再在此基础上估金属/粗糙度，使材质能进引擎。缺的那一块是代价：delighting 本身有误差，暗部和高光处容易失真，这个失败模式没被点出来，就停在良好。

满分档的特征是“机制连通 + 代价显式 + 管线定位”。除了良好档的全部内容，满分答案会把 delighting 明确成关键预处理，并指出如果不做，模型会把阴影和高光直接画进 base color——这是生成模型最常见的失败模式，因为训练图里的明暗关系被当成了材质本身的颜色。同时满分答案会把三通道落到“实时渲染的标准输入”这个定位上，说明这不是某个引擎的偏好，而是 BRDF 求值的输入约定。三档之间的差距不在字数，而在是否把“为什么”和“代价”两件事同时说清。

二 · 三通道的机制：BRDF 求值需要彼此独立的输入

要理解三通道为什么必须分开，得从实时渲染的着色方程看。PBR 的核心是一个双向反射分布函数，它在给定入射方向、出射方向和表面法线时，输出反射辐射的比值。一个常用的近似把漫反射项和镜面反射项相加，镜面项里带一个基于粗糙度的法线分布函数和一个菲涅耳项，菲涅耳项在金属处取 base color 作为反射色，在电介质处取一个固定的小反射率。写成简化形式：

$$f_r(\omega_i,\omega_o)=\frac{1-\mathrm{metal}}{\pi}\,\mathrm{baseColor}+\frac{D(h)\,\mathrm{F}(\omega_o,h)\,G}{4\,(\omega_o\cdot n)(\omega_i\cdot n)}$$

这个式子里，base color 出现在漫反射项，同时通过金属度决定菲涅耳项取什么值；粗糙度进入法线分布函数 D，控制高光的锐利程度。三个量各自独立地进入不同的项，渲染器必须在每次求值时分别读到它们。如果只有一张 RGB 纹理，颜色通道里混着“这是铝的固有色”和“这块被灯照亮了”两种信息，着色器无法把它们拆开——它拿到的红色既可能是金属反射色，也可能是高光过曝。三通道的意义就是把这三种物理量解耦，让 BRDF 的每一项都能拿到干净的输入。

这就是“PBR 与重光照”判分点的实质。重光照不是换一张环境贴图那么简单，它要求同一份材质在不同光照条件下产生物理一致的结果。单通道 RGB 做不到这一点：高光已经被烘进颜色，换光源后高光位置不变，看起来像贴纸。三通道材质则允许渲染器重新计算高光位置和强度，因为粗糙度和金属度是独立可读的。工程上判断一份材质能否重光照，标准做法就是看它是否提供独立的 metallic/roughness 贴图，而不是看颜色贴图画得多漂亮。

失败模式在这里很具体：把 metallic 和 roughness 塞进 RGB 的某两个通道，再把 base color 塞进第三个通道，看似“三通道”，实则每个通道都被压缩到 8 位且互相污染。金属度是一个近乎二值的量，粗糙度是连续量，两者与颜色共用位深，暗部的粗糙度变化会被量化噪声吞掉。系统代价是着色器里多一次解包和重排，且美术管线无法单独替换某一通道。具体例子：一个生成模型输出的“三通道贴图”如果 metallic 通道里混进了环境光遮蔽的灰度，引擎会把阴影区误判为高金属度，整个物体在暗部变成镜面，这就是通道语义错位的典型症状。

三 · delighting 的机制：从“被照亮的图”反解反照率

delighting 要解决的问题是：训练图里的像素值是光照与材质的乘积，不是材质本身。一张在室内暖光下拍摄的金属杯，像素里既有杯子的反照率，也有光源的色温和方向造成的明暗分布。如果直接把这张图当 base color 训练，模型学到的是“这个杯子左边暗右边亮”，而不是“这个杯子是某种金属”。换一个光照，模型生成的材质就带着原图的光照烙印，无法进引擎重光照。

delighting 的机制可以写成一条反解链路：先估计图像中的光照分量，再从像素值里除掉它，得到反照率估计，然后在这个反照率基础上估计金属度和粗糙度。伪代码思路大致是：对输入图先做光照估计（可以是基于球谐的全局照明拟合，也可以是学习到的本征分解网络），得到照明图 L；用像素值除以 L 得到反照率 A；再把 A 送入金属/粗糙度估计头，输出 metallic 与 roughness 通道。整条链路的输出才是引擎能吃的三通道材质。

$$A(x)=\frac{I(x)}{L(x)},\qquad (\mathrm{metallic},\mathrm{roughness})=g(A)$$

这条链路的关键在于除法不是无损的。当 L 接近零时，A 会被放大到不可信的范围；当像素接近过曝时，除法又把高光信息压平。这就是解析里点明的代价：delighting 本身有误差，暗部和高光处容易失真。暗部的失真表现为反照率被噪声主导，生成模型在暗部区域输出斑驳的颜色；高光处的失真表现为镜面反射被误当成漫反射颜色，金属感被抹掉。这两个区域恰好是训练图里信息最不可靠的地方，也是 delighting 误差最集中的地方。

失败模式还有一个更隐蔽的版本：delighting 不彻底时，阴影没有被完全去掉，残留的软阴影被当成反照率的一部分。模型于是学会“在材质里画阴影”，生成的 base color 自带一块暗斑。这块暗斑在原始光照下看起来正常，一旦进引擎换光，暗斑就变成一块不随光照变化的污渍。工程判断上，检查 delighting 是否成功，看的不是整体亮度是否均匀，而是暗部和亮部边缘的反照率是否连续——如果阴影边界在反照率图里仍然可见，说明去光照不彻底。

四 · 数字底账：评分权重与判分点的对应关系

评分标准给出的数字只有两个：三通道 50%，delighting 50%。这两个数字决定了答题的时间分配和深度分配。判分点有四项，前两项（base color/metallic/roughness、PBR 与重光照）落在三通道的 50% 里，后两项（delighting 去光照、引擎标准输入）落在 delighting 的 50% 里，其中“引擎标准输入”是横跨两块的收口点。下面用表格把这笔账摊开。

判分点归属权重及格档表现良好档表现满分档表现
base color/metallic/roughness三通道 50% 内列出三个通道名说明三者各自进入 BRDF 不同项指出解耦是重光照前提
PBR 与重光照三通道 50% 内知道单张 RGB 不行说明烘死导致高光位置错误给出换光源后物理一致性的判断标准
delighting 去光照delighting 50% 内只说“去掉光照”说出反照率再估金属/粗糙度点明暗部/高光失真代价
引擎标准输入横跨两块不提提到进引擎定位为实时渲染输入约定而非引擎偏好

这笔账的读法是：及格档在四个判分点上各拿一半左右，总分落在及格线附近；良好档在前三个点上拿满、第四点拿一半，总分明显高于及格但够不到满分；满分档四点全满。注意权重是对半的，这意味着只把三通道讲透、delighting 只写一句的答案，上限就是 50% 加一点零头，不可能到良好。反过来，delighting 讲得再细，三通道只列名词，同样被压在及格档。答题时必须两块都给出机制级的说明。

还有一个隐含的底账：常见错误清单里列了三条——“以为 PBR 就是一张彩色贴图”“忽略 metallic/roughness”“以为 delighting 无损”。这三条恰好对应三档答案的分水岭。第一条错误出现在及格档，第二条出现在及格到良好之间，第三条出现在良好到满分之间。评分时如果答案里出现“delighting 是无损的”这类表述，delighting 部分就不能给满，因为它直接违背了解析里点明的误差代价。这不是扣字眼，而是判分点“delighting 去光照”要求考生理解这一步是有损预处理，而不是一个可逆变换。

五 · 评分演练：三段答案的逐点对照

拿三段假设的答案做演练，看判分点如何落地。第一段是及格档答案：“PBR 需要 base color、metallic、roughness 三个通道，因为 PBR 渲染需要这三个量。只给一张 RGB 纹理不行，金属和粗糙度信息被烘死在颜色里。delighting 把训练图里的光照去掉，得到反照率，再估金属和粗糙度，这样材质才能进引擎。”这段答案把判分点的名词都摆出来了，但每个点都停在结论层：三通道“因为需要所以需要”，重光照只说了“烘死”没说后果，delighting 只说了流程没说代价。按表对照，前两点拿基础分，后两点拿基础分，总分在及格档。

第二段是良好档答案，在及格段基础上补了机制：“三个通道分别进入 BRDF 的不同项，base color 进漫反射和菲涅耳，粗糙度进法线分布函数，金属度决定菲涅耳取值。单张 RGB 把高光烘进颜色，换光源后高光位置不变，看起来像贴纸。delighting 先估光照再除，得到反照率，然后估金属粗糙度。”这段答案把三通道与重光照的因果链接通了，delighting 的链路也说清了，但没提暗部和高光处的失真。按表对照，前三点拿满，第四点“引擎标准输入”只提了“进引擎”没定位，总分落在良好档上沿但够不到满分。

第三段是满分档答案，在良好段基础上补了代价和定位：“delighting 的除法在光照接近零和过曝处有误差，暗部反照率被噪声主导，高光处镜面反射被误当漫反射，所以这一步是有损预处理。去光照不彻底时残留阴影会被画进 base color，模型学会在材质里画阴影，换光后变成不随光照变化的污渍。三通道不是某个引擎的偏好，而是实时渲染 BRDF 求值的输入约定。”这段答案把解析里的代价原话落到了具体机制上，并把“引擎标准输入”从“进引擎”提升为“输入约定”。按表对照，四点全满。

演练的结论是：三档之间的字数差距不大，差距在“是否说出后果”和“是否说出代价”。及格档说“烘死”，良好档说“烘死后高光位置错”，满分档说“烘死后高光位置错且 delighting 有损”。每往上一档，就多一层因果。评分时按判分点逐项打勾，勾满四项且每项都有机制说明，才是满分。只勾名词不给机制的，按及格档处理。

六 · 工程判断：什么时候该怀疑 delighting 没做对

把评分逻辑反过来用，就是工程验收逻辑。给定一份生成的三通道材质，判断 delighting 是否做到位，看三个信号。第一，base color 通道里是否还能看到阴影边界——如果暗部边缘在颜色图上清晰可见，说明去光照不彻底，阴影被当成了反照率。第二，metallic 通道是否在暗部出现异常高值——如果阴影区被误判为金属，说明光照估计把暗部当成了低反照率高反射，通道语义已经错位。第三，换一个与训练图差异大的光照环境渲染，高光位置是否随光源移动——如果不移动，说明高光被烘死在颜色里，三通道没有真正解耦。

这三个信号对应着两个判分点的工程版本：前两个信号检验 delighting 的去光照质量，第三个信号检验三通道的解耦质量。验收时不需要知道 delighting 用了什么网络结构，只需要看输出通道的物理一致性。这也是为什么评分标准把“引擎标准输入”单列成一个判分点——材质的最终检验场是引擎，不是训练损失曲线。训练损失低但通道语义错位的材质，在引擎里会立刻暴露：金属度错的地方反射错，粗糙度错的地方高光形状错。

最后落到一个具体机制上：delighting 的除法在暗部放大噪声，这个放大倍数由光照估计的倒数决定，光照越暗放大越猛。工程上抑制这个放大，要么在暗部降低反照率估计的置信度并回退到先验，要么在训练时对暗部像素降权。这两种做法都会让暗部的材质细节变少，但换来的是通道语义的稳定。判断一份材质能不能用，不是看它在原光照下多像原图，而是看它在换光后是否还物理自洽——这就是三通道与 delighting 这对判分点最终要守住的底线。
