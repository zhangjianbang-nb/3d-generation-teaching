二 · 变体一：把“拆两个 DiT”换成“拆三个模块”

原题问的是形状与纹理两分。一个常见变体是把拆分粒度再推一层：形状 DiT、纹理 DiT，再加一个独立的“材质/反射”模块（或把纹理再拆成基础色与高频细节两路）。这个变体的判分逻辑与原题同构，但考点从“为什么拆”迁移到“拆到哪一层为止”。回答时必须抓住一条主线：拆分的合法性来自数据分布、分辨率、评价指标三者的不一致，而不是来自“模块越多越解耦”。形状的监督信号是几何误差（倒角距离、法线一致性），纹理的监督信号是颜色与细节的感知质量，材质的监督信号是反射参数与光照一致性；三者若强行塞进一个 DiT，共享的 token 序列要同时承载几何位置编码与外观隐变量，训练目标之间会互相拉扯。

机制上，三模块版本的接口比两模块多一层：形状 DiT 输出网格与 UV 展开，纹理 DiT 在 UV 域上生成基础色图，材质模块再在同一 UV 域上回归粗糙度/金属度等通道。接口对齐的约束从“UV/法线对齐”扩展为“UV 布局 + 通道语义对齐”。系统代价也随之上升：两阶段误差累积变成三阶段累积，形状的几何误差会通过 UV 展开失真放大到纹理域，材质的回归又依赖纹理域的分辨率。一个具体失败模式是 UV 接缝处的材质通道不连续，导致渲染时接缝处出现高光断裂——这不是纹理 DiT 能修的，因为它的输出域里根本没有材质通道。

伪代码思路可以写成：

$$\text{shape}=\text{DiT}_s(z_s),\quad (M,UV)=\text{mesh}(\text{shape});\quad T=\text{DiT}_t(z_t,UV);\quad R=\text{Mat}(z_m,UV,T)$$
其中每个模块的损失各自独立：
$$\mathcal{L}=\lambda_s\mathcal{L}_{geo}+\lambda_t\mathcal{L}_{tex}+\lambda_m\mathcal{L}_{mat}$$
关键在于 $\lambda$ 之间没有梯度回传，模块间只通过离散接口（网格、UV 图）耦合。这既是工程好处（可分别迭代、分别加速），也是代价来源（接口不可微，误差不可反向修正）。回答这个变体时，若只罗列“三个模块各自擅长什么”而不指出接口不可微这一结构性代价，按原题评分标准只能拿到拆分理由分，代价分丢失。

三 · 变体二：追问“为什么不拆成自回归 + 扩散的混合管线”

第二个变体把拆分维度从“按模态”换成“按生成范式”：形状用自回归或稀疏体素逐块生成，纹理用扩散生成。这个变体考的是对“拆分依据”的理解是否足够本质——拆分的依据不是模型数量，而是每个子任务的数据形态与评价指标是否匹配某种生成范式。形状的几何准确性可以用离散结构（体素、网格面片序列）承载，自回归在长序列上有明确的似然目标；纹理是稠密的连续场，扩散模型在感知质量上占优。两者混用并非不可，但会引入范式间的接口摩擦。

机制上，混合管线的接口是“离散几何 → 连续纹理域”的转换：自回归输出的网格需要先做参数化（UV 展开或三平面投影），扩散模型才能在该域上采样。这个转换步骤本身没有训练信号，是一个纯几何算法，其质量（接缝、拉伸、面片翻转）直接决定纹理扩散的输入质量。系统代价是双重的：自回归的序列长度随分辨率增长，推理延迟高；扩散的采样步数固定，两者串行后总延迟是两段之和而非取长补短。一个具体失败模式是自回归生成的网格存在非流形边，UV 展开算法在该处退化，扩散模型在退化 UV 上采样出的纹理出现拉伸条纹，而评价指标若只看纹理图像本身，会误判为纹理模型的问题。

公式上可以把接口写成条件生成：

$$p(T\mid M)=\int p_\theta(T\mid UV(M))\,p_{AR}(M)\,dM$$
工程上无法对 $M$ 求期望，只能取自回归的贪心样本，于是方差被单样本固化。这解释了为什么混合管线在演示中效果好、在批量生产中稳定性差。回答这个变体时，得分点在于指出“范式拆分不改变误差累积的方向，只改变累积的形态”：两 DiT 是连续域内的误差传递，混合管线是离散到连续的不可逆信息损失。若把混合管线说成“更先进所以更好”，属于原题常见错误“以为一个 DiT 一定更好”的镜像版本，同样扣分。

四 · 变体三：给定算力预算，问“拆还是不拆”

第三个变体把问题变成工程决策：在固定训练算力与推理延迟预算下，两 DiT 方案与单 DiT 方案如何取舍。这个变体不允许定性糊弄，必须给出可计算的判断依据。原题事实给出的工程好处是“分别迭代、分别加速”，这对应两个可量化的量：单模块的训练收敛步数与推理时的串行开销。单 DiT 的优势是共享 token 序列、一次前向，推理延迟低；劣势是两个目标的梯度在同一参数集上竞争，收敛需要的有效步数更多，且任一目标的调参都会扰动另一目标。

机制上可以把取舍写成预算约束下的优化：

$$\min_{\text{arch}}\ \mathcal{L}_{geo}+\mathcal{L}_{tex}\quad \text{s.t.}\ \ C_{train}\le B_t,\ \ L_{infer}\le B_l$$
两 DiT 把约束解耦为两个子预算，单 DiT 则要求在同一预算内同时满足两个损失。工程判断的落点是：当形状与纹理的评价指标冲突强（几何误差与感知质量的梯度方向不一致）时，拆分的收益超过串行延迟的代价；当两者冲突弱（例如低分辨率、纹理以基础色为主）时，单 DiT 的共享表征反而有利。这不是“哪个更好”的问题，而是冲突强度与预算松紧的二维判断。

系统代价的具体形态是显存与调度：两 DiT 需要同时驻留两套参数与两套优化器状态，显存占用近似相加；推理时两段串行，若第一段的输出需要 CPU 侧网格处理，还会引入主机-设备同步开销。一个具体例子是批量生成时，形状 DiT 可以大批量并行而纹理 DiT 受 UV 图分辨率限制只能小批量，两个模块的最优批大小不一致，调度器若统一批大小，必有一侧利用率不足。回答这个变体时，扣分点在于只谈“拆分灵活”而不给出预算约束下的判断条件；评分标准中代价占 40%，这里正是代价分的落点。

五 · 五个追问的应答骨架

追问一：“两个 DiT 的隐空间是否共享？”应答要点：不共享，各自有独立的条件编码与 token 化方式；共享的只有离散接口（网格、UV、法线）。若强行共享隐空间，等于把两个数据分布的支撑集求交，形状的几何先验会污染纹理的高频细节。追问二：“纹理 DiT 能否反过来修正形状？”应答要点：不能，因为纹理 DiT 的输入域是已参数化的 UV 图，几何错误在参数化阶段已被固化，纹理模型没有几何梯度通道。这正是原题代价“形状错了纹理无法补救”的机制解释。追问三：“接口对齐具体对齐什么？”应答要点：UV 布局的一致性、法线朝向的一致性、以及纹理域分辨率与网格面片密度的匹配；三者任一错位都会在渲染时表现为接缝或拉伸。追问四：“分别加速指什么？”应答要点：两个模块可独立选择采样步数、批大小、量化精度；形状可用少步采样快速出粗模，纹理用多步采样保细节，整体延迟按需分配而非平均分配。追问五：“评价指标不同体现在哪？”应答要点：形状看几何误差与拓扑合法性，纹理看颜色保真与细节感知质量；两者不可用同一损失加权，否则权重选择本身成为超参负担。

这五个追问的共同结构是：每个追问都指向“拆分带来的一个具体接口或一个具体不可逆损失”。应答时若停留在“因为分布不同所以拆”，只是复述拆分理由；必须落到接口的离散性、梯度的不可回传、批大小的不匹配这类可验证的机制上。追问四尤其容易失分，因为“分别加速”在原题参考答案中只有四个字，展开时必须给出步数、批大小、精度三个可独立调节的维度，否则显得空洞。

六 · 扣分点、常见错误与教学建议

按原题评分标准，拆分理由占 60%，代价占 40%。扣分点可归为三类。第一类，理由部分只答“两个任务不同”而不落到数据分布、分辨率、评价指标三个具体维度，扣理由分；这三个维度是原题事实明确给出的，缺一即不完整。第二类，代价部分只写“误差累积”四个字而不说明累积的方向与不可逆性（形状误差经参数化固化，纹理域无几何梯度通道），扣代价分；接口对齐只提 UV 而不提法线，同样扣分。第三类，把工程好处与拆分理由混为一谈，例如用“分别迭代”去论证“分布不同”，逻辑层级错位。

常见错误有三个，均来自原题事实：以为一个 DiT 一定更好（忽略了冲突强时共享表征的梯度竞争）；忽略两阶段接口（把两个 DiT 当成黑盒串联，不谈 UV/法线对齐）；以为纹理能救几何（把纹理模型当成具备几何推理能力的模块）。教学上，建议用一张两行三列的表格把三个维度与两个模块对齐，让读者自己填出“哪个维度在哪个模块上被监督”：

维度形状 DiT纹理 DiT
数据分布几何结构、面片拓扑颜色场、高频细节
分辨率诉求面片密度与几何精度纹理图像素密度
评价指标几何误差、拓扑合法性颜色保真、感知质量

填表过程中，读者会自然发现“接口”不在表内——它是表外的一行，恰是代价所在。教学建议的第二条是让学生复述误差累积的路径：形状误差 → 参数化失真 → 纹理域输入退化 → 渲染接缝，每一步都不可逆，这样“纹理不能救几何”就从断言变成推导。第三条是针对追问四做一次预算演算：给定总延迟预算，把步数与批大小在两个模块间分配，观察分配不均时哪一侧成为瓶颈，从而理解“分别加速”的工程含义不是免费的速度，而是可重新分配的预算。

最后落到工程判断：拆分的合法性由三个维度的不一致性支撑，拆分的代价由接口的离散性决定；当接口不可微且误差方向单一（几何→纹理）时，拆分的收益是可控的，因为失败模式可定位到具体阶段；当接口需要双向修正时，两 DiT 的结构本身就不成立，此时应回到单模型或引入可微接口，而不是继续加模块。
