一 · 变体一：把「最大风险」换成「最先崩的地方」

原题问的是「最大的风险是什么」，这是一个要求排序的问题，考生必须把语法错、API 错、空间关系错、死循环四类风险压到一个「最大」上。变体一改成「这套闭环最先在哪一步崩」，考的是同一套机制里的时序判断，而不是风险清单的背诵。机制上，SceneCraft 的循环是「写代码—渲染—看图—改代码」，四类风险并不在同一个环节暴露：语法错和 API 错在渲染启动前就由解释器抛出，属于零成本失败；空间关系错必须等渲染出图、GPT-V 看过才能发现，属于高成本失败；死循环则卡在渲染这一步本身，既不产出图，也不产出可读的错误文本，闭环直接断掉。用伪代码表达这个时序：

$$ \text{fail}(c)=\begin{cases}\text{syntax/API} & \text{before render},\\ \text{hang} & \text{inside render},\\ \text{spatial} & \text{after render, needs VLM}\end{cases} $$

因此「最先崩」的正确答案落在语法与 API 这一层：它是唯一不需要渲染资源就能判定的失败，也是唯一能靠静态检查或试运行在进入昂贵闭环前拦下的失败。系统代价在这里非常具体：如果把语法错留到渲染阶段才发现，每一轮都要付出一次完整的场景构建与出图开销，而语法错本可以用一次廉价的解释器调用来排除。失败模式是把「最先崩」误答成「空间关系错」，理由是它最难修——难修不等于先崩，这是时序与难度的混淆。具体例子：一段 bpy 代码把 `bpy.ops.mesh.primitive_cube_add` 的参数写成位置关键字而非 `location=`，解释器立刻报错，这一轮根本没有图可看，GPT-V 无从介入；而一段代码把两个物体放在同一坐标导致穿模，代码能跑、图能出，只有看图才发现不对。前者是「最先崩」，后者是「最贵崩」。

二 · 变体二：把「GPT-V 看渲染」换成「换一种反馈通道」

变体二问：如果不给 GPT-V 看渲染图，只给 LLM 渲染日志和场景图（scene graph）的结构化输出，闭环还能不能成立？这考的是反馈通道的信息含量，而不是「有没有反馈」这个是非题。机制上，渲染图携带的是像素级的空间与外观信息，日志携带的是执行层的错误与警告，场景图携带的是物体、位姿、父子关系的符号化描述。三者对四类风险的覆盖并不相同：日志能精确覆盖语法错与 API 错，场景图能覆盖部分空间关系错（例如物体重叠、父子链断裂），但外观类错误（材质、光照、遮挡关系看起来不对）在结构化输出里根本没有对应字段。公式化地看，反馈通道的有效性取决于它对目标错误集合的覆盖率：

$$ \text{cover}(F)=\frac{|\{e\in E:\ F\ \text{能表达}\ e\}|}{|E|} $$

其中 $E$ 是四类风险的集合，$F$ 是反馈通道能表达的错误的集合。只给日志时，$F$ 基本只覆盖前两类，覆盖率低，闭环退化成「编译器报错—改代码」，空间推理这一核心难点完全没有被触及。系统代价是：结构化反馈便宜、可解析、易自动化，但把最难的一类错误留在了盲区；图像反馈昂贵、需要 VLM 推理、反馈是自然语言因而不可精确解析，但它是唯一能触及「看起来不对」的通道。失败模式是考生答「能成立，因为日志也是反馈」，把反馈的存在等同于反馈的有效。具体例子：场景要求「杯子在桌子左侧」，代码把杯子放在桌子右侧，日志无错、场景图的坐标字段也自洽（它只记录实际位姿，不记录意图），只有把渲染图和文本意图对照，才能判出「左右反了」。这说明结构化通道缺的不是精度，而是与意图的对齐。

三 · 变体三：把「闭环纠错」换成「闭环的成本上界」

变体三问：这个「写—渲—看—改」闭环在什么条件下会不收敛，轮数为什么会膨胀？这考的是对闭环终止条件的工程判断。机制上，闭环每一轮包含一次 LLM 代码生成、一次场景构建与渲染、一次 VLM 读图并转文字反馈、一次 LLM 依反馈改写。四步里只有第一步和第四步是语言模型调用，中间两步是图形系统开销，因此单轮成本由渲染主导，而总成本是轮数与单轮成本的乘积。轮数膨胀的根源在于反馈的语义粒度：GPT-V 输出的是「看起来不对」的文字，这段文字不保证指向可执行的修改，LLM 可能改错地方，下一轮图仍然不对，反馈再次模糊，形成震荡。可以把收敛判据写成：

$$ \text{stop when}\ \ \Delta(\text{render}_t,\text{render}_{t-1})<\epsilon\ \ \text{or}\ \ t>t_{\max} $$

问题在于 $\Delta$ 是图像差异，而反馈是文字，两者不同空间，系统无法直接判断「这一轮是否比上一轮更接近意图」，只能靠外部设定的轮数上限硬停。系统代价是：轮数上限既是成本闸门，也是失败掩码——到了上限就停，复杂场景就以「未完成」收场，而系统并不区分「快收敛了」和「在原地打转」。失败模式是把「闭环能纠错」误读为「闭环必然收敛」，忽略了反馈模糊导致的震荡。具体例子：一个多物体场景里，GPT-V 先说「桌子太高」，LLM 降低桌子，下一轮图里杯子悬空，GPT-V 又说「杯子悬空」，LLM 抬高杯子又碰倒台灯，三轮下来场景在几个错误之间来回跳，没有任何一轮同时满足全部约束。这不是模型不够强，而是文字反馈没有把多约束的耦合关系表达出来，闭环缺少一个全局的约束账本。

四 · 五个追问：从机制到边界逐层收紧

追问一：为什么必须让 VLM 看图，而不能让 LLM 自己「想象」渲染结果？因为 LLM 对 3D 空间推理不稳定，它对自己写出的代码的几何后果没有可靠的心智模型，让它自评等于让出错的一方当裁判。追问二：GPT-V 的反馈是文字，文字与代码之间由谁对齐？由 LLM 完成对齐，这正是闭环脆弱的地方——反馈的语义损失发生在 VLM 转文字这一步，恢复发生在 LLM 读文字改代码这一步，两次转换都不保真。追问三：闭环能不能并行？可以并行生成多个候选代码、并行渲染、并行读图，但反馈的合并仍需串行决策，并行降低的是单轮时延而非轮数。追问四：这套闭环能否迁移到非 Blender 的 3D 管线？机制上可以，只要该管线提供「代码/脚本—可渲染—可截图」三件事，闭环就成立；迁移的代价是 API 分布变了，LLM 的 API 错误率重新上升。追问五：如果渲染本身很慢，闭环还划算吗？单轮成本随渲染时间线性上升，而轮数由反馈质量决定，两者相乘决定总成本；渲染慢时，把语法与 API 错误前移到静态检查，是唯一能压住成本的手段。

  • 追问一考的是「谁有资格评判」：评判者必须能看到代码之外的结果。
  • 追问二考的是「反馈通道的保真度」：两次语义转换是误差来源。
  • 追问三考的是「并行改的是时延还是轮数」：并行不改收敛性。
  • 追问四考的是「机制的迁移条件」：三件事齐备即可迁移，代价在 API 分布。
  • 追问五考的是「成本结构」：单轮成本 × 轮数，前移检查是唯一杠杆。

这五个追问的共同结构是：每一个都把原题的一个词（看图、反馈、闭环、Blender、成本）单独拎出来追问其必要性或边界，答对一个追问不算难，难的是答出「去掉这个词机制还成不成立」。具体例子：追问四若答「能迁移，因为都是写代码」，就漏掉了「可截图」这一条——没有截图就没有图像反馈，闭环退化成日志闭环，与原题的核心机制已经不是同一件事。

五 · 扣分点与常见错误：四类典型失分

评分标准是风险 50%、反馈机制 50%，扣分点基本落在这两半的边界上。第一类失分是把风险答成单一名目，例如只说「语法错」或只说「死循环」，丢掉另外三类，风险部分至多拿一半。第二类失分是把反馈机制答成「LLM 自己检查」或「渲染器报错」，没有出现 GPT-V 看图这一环，反馈部分归零。第三类失分是把闭环写成「写—渲—改」三步，漏掉「看」，等于把图像反馈这一核心机制删掉。第四类失分是混淆「代码可执行」与「场景正确」：代码能跑通只排除了语法与 API 错，空间关系错和死循环并不因此消失。用表格对照：

失分类型典型表述被扣的部分正确的落点
风险单一化「最大风险是语法错」风险 50% 中的其余三类四类并列，指出空间推理最难
反馈错认「LLM 自查即可」反馈机制 50%GPT-V 看渲染图转文字
闭环缺环「写—渲—改」反馈机制 50%写—渲—看—改四步
可执行即正确「代码能跑就没问题」风险与反馈各扣可执行只排除前两类风险

系统代价层面，这四类失分有一个共同根源：考生把「代码」当成闭环的中心，而原题的机制中心是「图像」。代码是精确的，但精确不等于正确；图像是模糊的，但模糊里带着代码无法自证的空间信息。失败模式最典型的是第四类：考生看到「bpy 代码」就联想到「Python 能跑」，于是把风险收缩到语法层，把反馈收缩到报错层，整道题的机制被替换成了一个普通的「编译—修复」循环，与 3D 空间推理毫无关系。具体例子：一段代码成功创建了三个物体且无报错，但三者互相穿插、相机被挡在墙外，这段代码「可执行」却完全不可用，只答「可执行即正确」的考生会认为这一轮已经通过。

六 · 教学建议：把闭环拆成可判定的四问

教学上不要直接讲「闭环」这个整体词，而要把它拆成四个可单独判定的小问，每个小问对应一个可观察的系统状态。第一问：代码进入渲染前，谁判定它能不能跑？答案是解释器，判定依据是语法与 API。第二问：渲染产出什么？答案是图像，它是唯一携带空间关系的产物。第三问：谁读图，读出什么？答案是 GPT-V，读出的是自然语言描述的「不对」。第四问：文字如何回到代码？答案是 LLM 依反馈改写，这一环的保真度最低。四问对应四个失败模式，教学时让学生对每一问举一个具体失败例子，比背「写—渲—看—改」四个字有效得多。可以给一个判定表：

$$ \text{pass}=\text{syntaxOK}\ \wedge\ \text{renderOK}\ \wedge\ \text{VLMOK}\ \wedge\ \text{rewriteOK} $$

四项全真才算一轮有效迭代，任一项为假，闭环就在该处断裂，且断裂位置决定了修复成本：越靠前越便宜，越靠后越贵。教学建议的第二条是把「空间关系错」单独拿出来做练习，因为它是唯一必须依赖图像反馈才能发现的错误，也是唯一能证明「为什么需要 GPT-V」的错误。第三条是让学生自己写出轮数上限与终止判据，体会「收敛」不是闭环的自带属性而是外部强加的约束。系统代价要讲透：渲染是闭环里最贵的一步，因此任何能前移到渲染之前的检查都是在省钱；而反馈的模糊性是轮数膨胀的唯一根源，因此提高反馈的具体性（指出哪个物体、哪个方向、与哪个约束冲突）比提高模型规模更能压缩成本。具体例子：把 GPT-V 的反馈从「看起来不对」改成「杯子在桌子右侧，但要求是左侧」，LLM 的改写命中率立刻不同——这不是模型变了，是反馈的语义粒度变了。落到工程判断上：这套闭环的可靠性不取决于 LLM 写代码的能力，而取决于反馈能否把图像里的空间错误压缩成一句可执行的具体指令；闭环的上限由反馈的具体性决定，下限由渲染前的静态检查决定。
