一 · 变体题 A：把“0.5 秒”拆成流水线预算

原题问的是“如何在 0.5 秒内同时给出 UV、PBR 与光照解耦”，变体 A 把问法改成工程预算题：给定单图输入，要求给出一次前向推理内各子阶段的耗时归属，并说明哪一段是不可压缩的、哪一段是可以被缓存或摊销的。这不是文字游戏，而是把“0.5 秒”从宣传口径变成可审计的账目。SF3D 的 0.5 秒是前向时间，不含人工修 UV，这一点必须作为预算的前提写死；一旦把修 UV 算进去，预算立刻失效。

机制上，这条流水线可拆成四段：图像编码与条件注入、网格与几何头前向、UV 展开与纹理烘焙、PBR 三通道（base color / metallic / roughness）回归加 delighting。前三段共享同一次前向的张量生命周期，第四段中的 delighting 是对输入图的逆光照估计，属于像素级后处理，和几何头不在同一张计算图上。伪代码思路如下：

$$ T_{\text{total}} = T_{\text{enc}} + T_{\text{geo}} + T_{\text{uv}} + T_{\text{pbr}} + T_{\text{delight}},\quad T_{\text{uv}} \text{ 与 } T_{\text{pbr}} \text{ 可部分重叠} $$

系统代价在于：UV 展开是组合优化性质的步骤，接缝位置一旦定下就锁死了后续纹理分辨率的上限；把它放进 0.5 秒预算里，意味着展开算法必须是贪心或学习的近似解，而非离线工具里的全局优化。失败模式很具体：当输入图里有大面积自遮挡（例如人物手臂贴躯干），近似展开会把接缝甩到可见面上，PBR 回归再准也救不回接缝处的颜色断裂。具体例子：一张带帽卫衣的半身图，帽檐与肩部重叠，展开器把接缝放在帽檐下沿，重光照后阴影边界与接缝重合，引擎里一眼可见。工程判断是：预算题的正确答法不是把 0.5 秒均分，而是明确指出 UV 段是精度与时间的交换点，delighting 段是误差放大器。

二 · 变体题 B：只给 PBR 三通道，不给 delighting

变体 B 抽掉 delighting，只保留 base color、metallic、roughness 三通道预测，问“资产还能不能进引擎、会在哪一步崩”。这题考的是对三者牵制关系的反向理解：原题说 delighting 错则 base color 带阴影，变体则要求论证去掉 delighting 后 base color 的语义已经变了——它不再是反照率，而是“带光照的彩色贴图”，PBR 管线会把它当反照率用，于是光照被二次施加。

机制上，引擎的着色方程把 base color 视为与入射光无关的量：

$$ L_o = \int_{\Omega} f_r(\omega_i,\omega_o)\, L_i(\omega_i)\, (\omega_i\cdot n)\, d\omega_i,\quad f_r \propto \frac{\text{base color}\cdot(1-\text{metallic})}{\pi} + \text{specular} $$

若 base color 里已经烘进了原图的环境光与阴影，则积分时这部分能量被当作反射率再次乘以新的光照，结果是暗部更暗、亮部过曝，且阴影方向与新光源不一致。系统代价是双重的：一是视觉上出现“脏”的反照率，二是 metallic 与 roughness 的估计失去参照——粗糙度本应由高光斑的锐度推断，而高光斑已被烘进 base color，回归头拿到的证据被污染。失败模式：金属件（如拉链、眼镜框）在去掉 delighting 后 metallic 通道仍被预测为高值，但 base color 里含原图高光，重光照时高光位置固定不动，产生“贴纸感”。具体例子：一张室内暖光下的皮鞋图，去掉 delighting 后鞋面 base color 带暖色高光，换到冷光环境，鞋面仍泛暖光，metallic 与 roughness 的组合无法解释这一现象，美术在引擎里只能手工重画反照率。判分上，这题要求答出“三通道不是彩色贴图”这一常见错误的镜像版本：三通道是物理量，缺了 delighting 就等于物理量被污染。

三 · 变体题 C：UV 接缝与拉伸的验收口径

变体 C 把矛头对准 UV：不问“有没有 UV”，而问“自动化 UV 的接缝与拉伸用什么口径验收，验收不过时该退回哪一步”。原题只定性说自动化 UV 难免接缝/拉伸，变体要求把“难免”变成可判定的门槛。机制上，接缝的代价是纹理在接缝两侧不连续，拉伸的代价是纹素密度在各面片不均；两者都可量化，但量化口径必须与下游引擎的采样方式对齐。

一个可操作的思路是把拉伸定义为面片在 UV 空间的面积与三维空间面积之比偏离 1 的程度，取全网格的分布而非均值：

$$ s_f = \frac{A^{\text{uv}}_f}{A^{\text{3d}}_f},\qquad \text{验收看 } \operatorname{quantile}_{0.95}(s_f) \text{ 与 } \max_f |\log s_f| $$

只看均值会掩盖少数极端拉伸面片，而引擎里最刺眼的恰恰是这些面片。系统代价：为了压低极端拉伸，展开器要增加接缝数量，接缝一多，纹理烘焙时的边缘 padding 成本上升，且在 mipmap 层级上接缝处的颜色渗漏更明显。失败模式是“接缝藏在不可见面”的假设不成立——自动化展开不知道相机将看向哪里，把接缝放在背面，但资产在引擎里会被玩家绕视，接缝暴露。具体例子：一个背包资产，展开器把主接缝放在背带与包体交界的内侧，静态预览完美，进入第一人称视角后玩家低头看到背带内侧的接缝与拉伸条纹。验收不过时的退回顺序应是：先退回 delighting 检查 base color 是否带阴影（阴影会让接缝更显眼），再退回 PBR 检查 roughness 是否在接缝处跳变，最后才考虑换展开算法；这个顺序的依据是接缝的可见性被光照误差放大，先修光照误差成本更低。

四 · 五个追问：从定义到边界

追问一：0.5 秒是否包含纹理烘焙的写回与量化？答法要点是把“前向时间”限定在 GPU 上的张量计算，写回与量化属于 I/O，若算进去则预算口径改变；这不是抠字眼，而是判分点“单图前向”的边界。追问二：UV 展开的输出是顶点级还是纹素级？顶点级展开只给出参数化，纹素级烘焙才决定接缝的实际宽度，两者混淆会导致把“展开成功”误当成“纹理无缝”。追问三：PBR 三通道是分别回归还是共享骨干？共享骨干省时间但通道间会互相泄漏（例如 metallic 的高值区域污染 roughness），分开回归则时间预算翻倍；这是 0.5 秒约束下的真实取舍。追问四：delighting 的逆光照估计若与 PBR 的 roughness 冲突，以谁为准？工程上以 delighting 为准修 base color，因为反照率的语义错误会传播到所有光照条件，而 roughness 的偏差只影响高光锐度。追问五：这套流水线对输入图的假设是什么？单图、无相机参数、无多视约束，因此几何的背面是猜的，UV 的背面接缝也是猜的；追问五的答法必须点明“快速默认选项”的适用边界，而不是把它说成通用解。

  • 追问一考边界定义，答错会把 I/O 混入前向预算。
  • 追问二考展开与烘焙的层级区分，答错会把参数化当成成品。
  • 追问三考通道耦合，答错会忽略共享骨干的泄漏代价。
  • 追问四考误差传播方向，答错会在错误通道上做修补。
  • 追问五考适用域，答错会把默认选项当成万能方案。

五 · 扣分点与常见错误的对应表

评分标准给的是三要素各 25%、牵制关系 25%，扣分点要落到这四块上。下表把常见错误映射到扣分位置与可观察的答题痕迹，便于阅卷时快速定位。

扣分位置常见错误答题痕迹修正方向
单图前向（25%）把 0.5 秒说成含人工修 UV 的全流程答“半秒出成品资产”而不加限定写明前向时间与修 UV 的分界
UV 展开（25%）以为 UV 自动就完美只提“有 UV”不提接缝/拉伸给出接缝与拉伸的验收口径
PBR 三通道（25%）以为 PBR 只是彩色贴图把 base color 当唯一输出点明 metallic/roughness 是物理量
delighting（25%）忽略 delighting 误差不提 base color 带阴影的后果说明误差如何传播到重光照
牵制关系（25%）三要素并列陈述、无交互分段罗列而不写谁制约谁写出 UV→分辨率、PBR→法线、delight→base color 的链条

注意表中“三要素各 25%”与“牵制关系 25%”合计为 100%，但牵制关系是跨要素的，所以同一处错误可能同时扣两个位置：例如“以为 UV 自动就完美”既扣 UV 展开，又因未写出 UV 对纹理分辨率的制约而扣牵制关系。阅卷时应避免重复扣分到同一证据上，做法是要求答题给出至少一条显式的因果句，例如“UV 接缝位置决定纹理分辨率上限，因此展开近似解会压低 PBR 细节的可分辨度”。

六 · 教学建议：用反例驱动而非用术语驱动

教学上最有效的手段不是先讲三要素的定义，而是先给三个反例让学员判断资产能否进引擎：带阴影的 base color、接缝在可见面的 UV、metallic 与 roughness 互相泄漏的通道。每个反例都对应一个具体机制与一个系统代价，学员在判断时会自然逼出 delighting、UV 验收口径、通道耦合这三个概念。课堂上应把“0.5 秒”作为约束反复压回去：任何修补方案只要超出前向预算，就必须标注为离线步骤，否则学员会把默认选项误当万能方案。

另一个建议是把评分标准的四块做成检查清单，让学员在答题前先自问：我写了单图前向的边界吗？我写了 UV 的接缝与拉伸代价吗？我写了三通道的物理语义吗？我写了 delighting 误差的传播路径吗？我写了三者之间的至少一条因果链吗？这五问对应判分点，能显著减少“术语堆砌但无机制”的答卷。最后，教学应强调失败模式的具体性：不要写“可能有接缝”，而要写“帽檐与肩部重叠时接缝落在可见面，重光照后阴影边界与接缝重合”。具体例子比形容词更能证明学员理解了牵制关系。

工程判断落在一点上：这套流水线的价值在于把“能进引擎的资产”做成快速默认选项，而默认选项的可靠性取决于对误差传播方向的清醒认识——delighting 的误差会污染 base color 并放大接缝可见性，UV 的近似解会锁死纹理分辨率上限，PBR 的通道耦合会让物理量互相泄漏；三者不是并列的输出，而是一条误差链上的三个节点，任何一环的近似都会沿链向下游传递。
