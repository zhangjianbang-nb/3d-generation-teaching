一 · 三档答案的分层：从名词罗列到牵制闭环

这道题在评分上被切成四块：单图前向、UV 展开、PBR 三通道、delighting，各占 25%。但真正把考生拉开差距的不是四个名词是否写全，而是最后 25% 的“牵制关系”能否被写成一条因果链。及格档的答案通常长这样：SF3D 输入一张图，前向推理出网格，做 UV 展开，输出 base color、metallic、roughness 三张 PBR 贴图，并用 delighting 去掉输入图的光照，所以能在 0.5 秒内给出可重光照的资产。这段话每个词都对，但它把四个要素并列摆放，没有回答“为什么互相牵制”。良好档会补上一句“UV 决定纹理分辨率和接缝，delighting 错了 base color 会带阴影”，开始出现连接词，但连接是单向的、零散的，没有形成闭环。满分档则要把三者写成互相约束的联合问题：UV 的参数化决定纹理采样密度与接缝位置，接缝处的法线不连续会污染 PBR 的 roughness 估计；PBR 的 metallic/roughness 又依赖对输入图光照的正确分解，而 delighting 的误差会直接以阴影形式烙进 base color，反过来让 UV 接缝在重光照下更显眼。换句话说，三个输出不是流水线上的三个工位，而是同一个欠定问题的三个投影，任何一处的误差都会沿着另外两处放大。

这个分层对应一个具体的判分动作：阅卷时先看四个要素是否各自落地（每个 25% 中的一部分），再看有没有一句话把“UV→法线→PBR”和“delighting→base color→重光照”这两条链中的至少一条说完整。只写“三者互相影响”而不给出影响路径的，归入良好档下限；能把两条链都写出来并指出误差放大方向的，才进入满分档。这里的关键是：牵制关系不是一句形容词，而是一组可检验的依赖。

二 · 机制解析：0.5 秒里到底跑了什么

“0.5 秒”这个数字必须被限定为前向时间。SF3D 的流程是单图输入，一次前向网络同时回归网格几何、UV 参数化和 PBR 三通道，再叠加一个 delighting 分支把输入图的光照成分剥离，得到反照率。这里没有任何人工修 UV、没有手动展平、没有美术在 Substance 里刷贴图的环节。把它写成“0.5 秒生成资产”是错的，正确写法是“0.5 秒给出一个能进引擎的默认资产，UV 接缝与 PBR 歧义由后续人工或自动后处理消化”。

从系统结构看，这是一个多任务前向：几何头输出网格顶点与面，UV 头输出参数化映射，纹理头输出三通道，delighting 头输出光照估计。多任务共享一个主干，意味着三个输出在同一组特征上竞争容量。可以用一个简单的损失分解来说明这种竞争：

$$L = \lambda_g L_{geo} + \lambda_u L_{uv} + \lambda_p L_{pbr} + \lambda_d L_{delight}$$

权重之间的拉扯就是牵制的第一层来源。UV 损失若强调接缝连续性，参数化会倾向低拉伸但可能牺牲纹理分辨率；PBR 损失若强调与输入图的外观一致性，会把 delighting 的残余光照吸收进 base color；delighting 损失若过度平滑，会把真实阴影当成光照去掉，导致重光照时物体“发飘”。这不是调参细节，而是三个目标在同一个前向里不可同时最优的结构性事实。

伪代码层面的思路是：输入图先过主干得到共享特征，几何头回归网格，UV 头在网格上做参数化，纹理头在 UV 空间采样共享特征得到三通道，delighting 头估计一个低频光照场并从输入图里除掉，最后把除掉光照的图作为 base color 的监督。失败模式很具体：当输入图有强方向光投射的硬阴影时，delighting 若把阴影误判为反照率变化，base color 就会在阴影区偏暗；这个偏暗在 UV 接缝处与相邻 chart 的亮度不连续叠加，重光照时接缝变成一条可见的暗线。这就是“UV 接缝污染 PBR、delighting 误差放大接缝”的具体机制。

三 · 数字底账：哪些数字能用，哪些不能编

本题给定的事实里只有两个数字：0.5 秒，以及评分标准的 25%×4。其余一切定量表述都必须定性化。这不是写作上的保守，而是判分上的硬约束：编造“UV 接缝率低于 3%”“PBR 误差 0.08”这类数字，在工程读者面前会立刻暴露为不可追溯的臆造。正确的底账写法是把数字放在它该在的位置，把没有数字的地方用机制和失败模式填满。

项目给定事实可写表述不可写表述
前向耗时0.5 秒前向时间 0.5 秒，不含人工修 UV端到端 0.5 秒交付
评分权重三要素各 25%，牵制 25%四块各占四分之一牵制关系权重更高
UV 质量无定量自动化 UV 难免接缝与拉伸接缝率低于某阈值
PBR 歧义无定量PBR 估计存在歧义metallic 误差小于某值
delighting 误差无定量delighting 错则 base color 带阴影光照剥离准确率某百分比

这张表的用法是：写作时每出现一个数字，先问它是否在给定事实里。0.5 秒可以反复用，但每次都要带上“前向”这个限定词；25% 只在讲评分演练时用。其余地方用“难免”“存在歧义”“会带阴影”这类定性判断，配合具体例子把机制说透。工程读者对定性判断的容忍度远高于对无来源数字的容忍度，因为前者可以被验证，后者只能被怀疑。

数字底账还有一层含义：0.5 秒这个数字本身就是一个工程判断的锚点。它说明 SF3D 的价值不在于质量上限，而在于把“能进引擎的资产”做成快速默认选项。默认选项的意思是：先拿到一个 UV 已展开、PBR 三通道齐全、可重光照的资产，再在这个基础上修。修 UV 接缝、修 delighting 残留、修 PBR 歧义，都是后续工序。把 0.5 秒理解成“免修”是常见错误，把 0.5 秒理解成“前向默认选项”才是正确底账。

四 · 三者牵制的两条因果链

第一条链是 UV→法线→PBR。UV 参数化把三维表面切成若干 chart，chart 边界就是接缝。接缝两侧的纹理采样不连续，法线在边界处出现跳变，而 roughness 与 metallic 的估计依赖局部法线与视角一致性。当法线在接缝处跳变时，同一材质的 roughness 会在接缝两侧给出不同值，重光照时接缝表现为一条高光或暗线。这条链的具体例子是：一个圆柱侧面被展成矩形 chart，接缝落在背面，若 delighting 在背面留下了阴影梯度，base color 在接缝两侧本就不连续，再叠加法线跳变，引擎里旋转光源时接缝会周期性闪烁。这不是 UV 单独的问题，也不是 PBR 单独的问题，而是两者在接缝处的耦合。

第二条链是 delighting→base color→重光照。delighting 的目标是把输入图分解为反照率与光照。这是一个欠定问题：同一张图可以由“亮反照率+弱光”或“暗反照率+强光”解释。SF3D 用前向网络给出一个默认分解，误差以阴影残留的形式进入 base color。当这个带阴影的 base color 被贴到 UV 空间并在新光照下渲染时，阴影残留不会随光源移动，表现为物体表面有一块“固定不动”的暗区。这块暗区若恰好落在 UV 接缝附近，就会与接缝的不连续叠加，让接缝在重光照下更显眼。这就是“delighting 错则 base color 带阴影”的完整路径，也是牵制关系里最容易被忽略的一环。

两条链交汇于一个工程判断：三者的误差不是可加的，而是相乘的。UV 接缝提供不连续的位置，delighting 误差提供不连续的幅度，PBR 歧义提供不连续的表现形式。只修其中一处，另外两处会把修好的地方重新弄脏。满分答案要写出这个“相乘”而非“相加”的结构，因为它是牵制关系的本质。

五 · 评分演练：同一道题的三份答卷

第一份答卷（及格档）：“SF3D 用单图前向预测网格，做 UV 展开，输出 base color、metallic、roughness 三通道 PBR 贴图，并用 delighting 去掉输入图光照得到反照率，所以 0.5 秒内给出可重光照资产。三者互相牵制。”这份答卷四个要素都在，但牵制关系只有一句空话，没有路径。按 25%×4 的权重，前三块拿满，第四块拿零头，落在及格档上限。

第二份答卷（良好档）：“……UV 展开决定纹理分辨率与接缝，PBR 需要正确法线与粗糙度，delighting 错则 base color 带阴影，所以三者互相影响。”这份答卷出现了两条单向连接，但没有闭环，没有指出误差放大方向，也没有说明为什么 0.5 秒不含人工修 UV。第四块拿到部分分，落在良好档。

第三份答卷（满分档）：“……0.5 秒是前向时间，不含人工修 UV。UV 参数化决定采样密度与接缝位置，接缝处法线跳变污染 roughness 估计；delighting 是欠定分解，误差以阴影残留进入 base color，重光照时阴影不随光源移动；两者在接缝处叠加，使接缝在旋转光源下周期性显现。因此三者是同一欠定问题的三个投影，误差相乘而非相加，SF3D 的价值是把可进引擎的默认资产快速给出，修 UV 与修 delighting 残留是后续工序。”这份答卷把两条链写完整，把 0.5 秒限定为前向，把“默认选项”而非“免修”作为价值判断，第四块拿满。

演练的要点是：满分档并没有比良好档多写一个名词，它多写的是依赖方向和误差放大机制。评分时可以用一个简单检验：把答卷里“互相牵制”那句话删掉，看剩下的文字是否还能推出牵制关系。能推出的，是满分档；推不出的，是良好档及以下。

六 · 常见错误对应的机制缺口

“以为 UV 自动就完美”对应的是对参数化本质的误解。UV 展开是一个从三维曲面到二维平面的映射，任何非可展曲面都无法无拉伸地展平，自动化方法只能在拉伸、接缝数量、chart 数量之间做权衡。SF3D 的前向给出的是一个默认权衡，不是最优解。这个错误在答卷里表现为只写“UV 展开”而不写“接缝与拉伸”，第四块直接失分。

“忽略 delighting 误差”对应的是把 base color 当成输入图的直接拷贝。delighting 是一个欠定分解，误差必然存在，且以阴影残留形式进入 base color。忽略这一点，就无法解释重光照下物体表面的固定暗区，也就写不出第二条因果链。

“以为 PBR 只是彩色贴图”对应的是把三通道压成一通道。metallic 与 roughness 是材质参数，不是颜色；它们依赖法线与光照分解的正确性。把 PBR 当彩色贴图，等于放弃了“PBR 需要正确法线/粗糙度”这一环，牵制关系里的 UV→法线→PBR 链条断裂。

这三个错误共同指向一个机制缺口：把三个输出当成三个独立任务，而不是一个联合估计。修复这个缺口的写法是：每写一个要素，就追问它依赖另外两个要素的哪一部分，并把依赖写成一句可检验的话。例如写 UV 时追问“接缝处的法线是否连续，若不连续 roughness 会怎样”；写 delighting 时追问“阴影残留落在接缝附近会怎样”。这种追问式写作能把答案从名词罗列推到牵制闭环，也是这道题从及格到满分的唯一路径。
