一 · 三档答案的判定边界

这道题表面是三个名词对应三篇论文，实质是考察读者能否把“故事隐喻—方法机制—下游需求”三层打通。评分标准写得很直白：三个映射各占 30%，边界占 10%。这意味着及格、良好、满分不是靠字数堆出来的，而是靠命中判分点的完整度区分。及格档的典型特征是三个映射都能报出论文名，但机制描述停留在“用了 VQ”“用了自回归”“用了组合生成”这类标签层面，无法说明 token 是怎么构造的、边是怎么共享的、部件之间靠什么耦合。良好档能把机制说到操作层：知道 MeshGPT 是把面片序列化后过 VQ 码本再自回归预测下一个面片 token；知道 MeshAnything V2 的相邻网格 tokenization 让相邻面共享边、只写新顶点；知道 PartCrafter 是每个部件独立生成潜变量再联合去噪。满分档还要多一层：能指出“重拓扑不等于几何简化”这条边界，并说清为什么故事里的“木工手艺”对应的是自回归生成新网格而不是 QEM 塌缩。三档之间的差距不在记忆量，而在是否理解每个机制解决了什么约束、又付出了什么代价。

判分点的权重分配本身就是一种工程判断。三个映射各 30% 意味着任何一个映射缺失都会直接掉到及格线以下，因为 30%×2 加上边界 10% 只有 70%，已经不足以覆盖“良好”所需的机制完整度。反过来，三个映射全对但边界说错，最多拿到 90%，仍可能被判为良好而非满分。这说明出题人把“重拓扑≠简化”视为区分“背过论文名”和“真懂生成式重拓扑”的分水岭。工程背景的读者容易在这里翻车，因为传统几何处理里重拓扑和简化经常被混为一谈，而生成式方法的重拓扑是重新预测一套面片连接关系，输出网格的顶点数、面数、拓扑结构都可以和输入无关。

评分演练时可以用一个简单的自检清单：能否在不看笔记的情况下写出 MeshGPT 的面片 token 化流程伪代码；能否解释 AMT 中“共享边、只写新顶点”对序列长度的影响；能否说明 PartCrafter 的联合去噪为什么不能退化成各部件独立去噪后拼接。三项都能说清机制细节，才进入良好档；再能说清“为什么不是简化”以及每个机制的系统代价，才进入满分档。这个清单不是评分标准的复述，而是把 30%/30%/30%/10% 翻译成可操作的问答路径。

二 · 面片词表：MeshGPT 的 VQ 面片 token 与自回归

MeshGPT 的核心机制是把网格的面片当成语言序列来处理。具体做法不是对顶点坐标做量化，而是对面片做序列化：每个面由三个顶点构成，顶点按某种顺序排列后，面片被表示成一个固定长度的符号组，再通过 VQ 码本把这些符号组映射到离散 token。这样整个网格就变成了一串面片 token，自回归模型可以像预测下一个词一样预测下一个面片。关键在于 token 的粒度是“面”而不是“顶点”或“坐标”，这让模型直接学习面片之间的连接关系，而不是先学点云再学连接。用伪代码思路描述就是：对输入网格的每个面提取顶点索引三元组，按规范化顺序排列，送入编码器得到连续向量，在码本中找最近邻得到 token id，然后把 token 序列按自回归方式训练，推理时逐 token 采样并用解码器还原面片。

$$\text{face}_i = (v_a, v_b, v_c),\quad z_i = E(\text{face}_i),\quad t_i = \arg\min_k \|z_i - e_k\|_2,\quad p(t_{i+1} \mid t_{\le i})$$

这个机制的系统代价很具体。第一，面片 token 化要求面片顺序有确定性，否则同一个网格可以有多种序列化方式，模型学到的是排列噪声而不是几何结构，训练时需要对面片做规范化排序。第二，VQ 码本的容量决定了可表达的面片模式上限，码本太小会把不同连接模式压到同一个 token，解码后出现面片错连；码本太大则码本利用率下降，大量 token 在训练中得不到梯度。第三，自回归推理是逐 token 的，生成长序列时延迟随面片数线性增长，且早期 token 的错误会沿序列传播，一个错连的面片可能导致后续顶点索引全部偏移。失败模式里最典型的是“悬边”和“非流形边”：自回归模型在局部预测下一个面片时，如果没有显式的边共享约束，可能生成一个只共享一个顶点甚至不共享顶点的面片，解码后网格出现裂缝。

具体例子可以设想一个带凹槽的方块：输入网格有若干面片，MeshGPT 把它们序列化成 token 串，自回归模型在生成凹槽侧壁时，需要根据已生成的面片 token 推断下一个面片应该与哪条边相邻。如果码本中缺少“侧壁与底面共享边”的模式，模型可能生成一个悬空的面片，解码后凹槽底部出现孔洞。这不是假设性的失败，而是 VQ 面片 token 化在码本容量受限时的固有风险。工程上对应的缓解手段是增加面片序列的局部上下文窗口，或在训练时加入边共享的辅助损失，但这些都会增加训练成本。读者在答题时如果只写“MeshGPT 用 VQ 和自回归”，就停在及格档；写出“面片级 token、码本最近邻、逐 token 自回归、错连传播”才进入良好档。

三 · 榫卯共享边：MeshAnything V2 的 AMT

MeshAnything V2 的相邻网格 tokenization（AMT）解决的是面片序列化中的冗余问题。如果每个面片都把三个顶点完整写一遍，相邻面共享的边就会被重复编码，序列长度随面片数线性膨胀，自回归模型的上下文很快被耗尽。AMT 的做法是：相邻面之间共享边，序列化时只写新顶点。也就是说，当模型生成一个与已生成面片相邻的新面片时，它只需要指定新引入的顶点，共享边的两个端点从上下文里继承。这样每个新面片的 token 数从固定三个顶点降到只写增量部分，序列长度显著压缩，模型可以在同样的上下文窗口内覆盖更多面片。伪代码思路是：维护一个已生成顶点集合和边集合，对每个新面片检查它与已生成面片的邻接关系，若存在共享边则只编码新顶点索引，否则编码完整三元组，解码时按同样的邻接规则重建面片。

$$\text{tokens}(\text{face}_i) = \begin{cases} (v_{\text{new}}) & \text{若与已生成面共享一条边}\\ (v_a, v_b, v_c) & \text{否则}\end{cases}$$

这个机制的系统代价在于邻接关系的维护。AMT 要求序列化过程是确定性的，即新面片的生成顺序必须与邻接检查顺序一致，否则解码端无法复现“哪条边是共享的”。训练时需要对每个网格做一致的遍历，推理时模型必须按同样的顺序生成，任何顺序偏差都会导致共享边判断错误。失败模式里最典型的是“共享边错配”：模型预测新面片时继承了一条并不存在的共享边，解码后两个面片在空间上不相邻却被强制共享顶点，产生折叠或自交。另一种失败是“增量顶点越界”：模型写了一个新顶点索引，但该顶点在已生成集合中不存在，解码器无法解析。这些失败都源于 AMT 把拓扑正确性部分外包给了序列化顺序，而自回归模型并不显式保证顺序一致性。

具体例子可以设想一个榫卯结构的转角：两个面片在转角处共享一条边，AMT 让第二个面片只写新顶点，序列长度比完整写法少两个 token。如果模型在生成转角时误判了共享边，把本应共享的边当成新边，就会重复写入两个顶点，解码后转角处出现两个重合但未合并的顶点，网格在渲染时出现接缝。工程上对应的缓解手段是在解码端做顶点合并的后处理，但这会引入额外的几何判断，且合并阈值难以设定。答题时如果只写“MeshAnything V2 用了相邻 tokenization”，就停在及格档；写出“共享边继承、只写新顶点、序列压缩、顺序一致性代价”才进入良好档。还要注意一个常见错误：把 MeshAnything 当成 QEM 简化。AMT 的输出是新网格，面数和拓扑都可以与输入不同，它不是对原网格做边塌缩，而是重新生成一套面片连接。

四 · 组装台：PartCrafter 的组合式潜变量

PartCrafter 的机制是把一个物体拆成若干部件，每个部件独立生成一个潜变量，然后在去噪过程中联合起来。独立生成保证了部件内部的几何完整性，联合去噪保证了部件之间的空间关系。具体做法是：每个部件有自己的潜变量表示，生成时先按部件分别采样，然后在去噪的每一步让各部件的潜变量通过注意力或条件交互共享全局信息，最终解码出组合后的网格。伪代码思路是：对部件集合 \(\{P_1,\dots,P_n\}\)，各自初始化潜变量 \(z_i\)，在去噪时间步 \(t\) 上联合预测噪声，条件中包含其他部件的当前状态，解码时按部件输出网格并保留部件边界。这个机制的关键不是“分部件”，而是“分部件之后还有联合去噪”，否则各部件独立生成后拼接会出现穿插、悬空、比例失调。

$$\epsilon_\theta(z_1^{(t)},\dots,z_n^{(t)}, t) = (\epsilon_1,\dots,\epsilon_n),\quad z_i^{(t-1)} = \text{step}(z_i^{(t)}, \epsilon_i, \{z_j^{(t)}\}_{j\neq i})$$

系统代价在于联合去噪的计算量。每个去噪步都要让所有部件的潜变量参与交互，计算量随部件数增长，部件越多，注意力矩阵越大，显存占用越高。失败模式里最典型的是“部件关系漂移”：联合去噪的早期步如果某个部件的潜变量偏离，其他部件会被拖拽着调整，最终组合后的物体出现部件错位。另一种失败是“部件边界模糊”：联合去噪让部件之间的潜变量过度共享，解码后部件之间的分界消失，原本应该独立的两个部件被融合成一个整体，下游编辑无法按部件选中。具体例子可以设想一把带抽屉的柜子：柜体、抽屉、把手是三个部件，独立生成保证每个部件形状合理，联合去噪保证抽屉嵌在柜体的开口里、把手贴在抽屉面板上。如果去掉联合去噪，抽屉可能生成在柜体外部，或者把手悬空。

答题时如果只写“PartCrafter 按部件生成再组合”，就停在及格档；写出“部件独立潜变量、联合去噪、全局关系、部件数带来的计算代价”才进入良好档。常见错误是以为部件生成不需要全局关系，实际上 PartCrafter 的“组合式”重点就在联合去噪这一步，没有它，部件生成退化成各自为政的独立采样，组合结果不可用。工程判断上，部件数是一个需要权衡的超参数：部件划分越细，编辑粒度越好，但联合去噪的计算量和关系漂移风险也越高。

五 · 数字底账与评分演练

把三个映射的判分点拆成可核对的底账，可以避免答题时“感觉写全了”但实际漏项。下表把每个映射的机制关键词、必须出现的边界、以及对应的系统代价列出来，读者可以逐项打勾。权重按评分标准：三个映射各 30%，边界 10%。注意表中不出现任何实验数字，只列定性机制和代价，因为题目给定事实里没有具体数值。

评分演练可以用三个自问自答来定位档位。第一问：MeshGPT 的 token 是顶点坐标还是面片？如果答顶点坐标，说明没抓住“面片词表”的实质，直接掉档；正确答面片级 token 并说出 VQ 码本和自回归，进入良好档；再能说出码本容量与错连传播的代价，进入满分档。第二问：MeshAnything V2 的 AMT 为什么能压缩序列？如果答“因为用了更好的 tokenizer”而说不出共享边继承和只写新顶点，停在及格档；能说出序列压缩机制并指出顺序一致性代价，进入良好档；再能指出“这不是 QEM 简化”并解释输出拓扑可与输入无关，进入满分档。第三问：PartCrafter 的部件生成能不能各自独立完成再拼接？如果答能，说明忽略了联合去噪，掉档；正确答不能并说出联合去噪的全局关系，进入良好档；再能说出部件数带来的计算代价和关系漂移，进入满分档。

边界那 10% 的权重看似小，但它决定满分档的门槛。边界的具体表述是：故事把重拓扑写成木工手艺，真实方法是自回归生成新网格，不是几何简化。这句话里有两个容易漏的点。第一，“自回归生成新网格”意味着输出网格的面片连接是模型逐 token 预测出来的，不是从输入网格里选边塌缩出来的。第二，“不是几何简化”意味着不能用 QEM 的边塌缩代价、顶点合并阈值这套语言去解释 AMT，AMT 的共享边是序列化层面的增量编码，不是几何层面的边收缩。评分演练时，如果读者在榫卯共享边部分写了“通过合并边来减少面数”，就踩中了常见错误，边界分会被扣掉，即使三个映射的机制都写对了，也进不了满分档。

最后落到一个工程判断上：三档答案的区分不是知识量，而是“机制—代价—边界”三者的闭合程度。及格档能报出论文名和标签，良好档能说清机制的操作细节，满分档能说清每个机制为什么必须这样设计、以及这样设计付出了什么代价。评分标准里 30%/30%/30%/10% 的权重，实际上是在要求读者对三个映射给出同等深度的机制解析，再用边界那 10% 检验是否真正理解生成式重拓扑与几何简化的分野。答题时按上表的四列逐项核对，比按论文顺序复述更接近判分点的实际分布。
