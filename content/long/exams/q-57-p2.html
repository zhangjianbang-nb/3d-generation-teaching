一 · 变体题 A：把“四步”改成“流水线瓶颈定位”

原题问的是四个步骤的名称与关键性，变体 A 把它翻转为工程诊断题：给定一条 3DGS 渲染流水线在特定场景下帧率骤降且出现遮挡闪烁，要求考生指出应当优先检查哪一步，并说明判断依据。这个变体考的不是记忆，而是把“排序最关键”这一结论落到可观测的因果链上。参考机制是：投影阶段由协方差变换 Σ'=J W Σ Wᵀ Jᵀ 决定 2D 椭圆形状，若该步出错，症状是椭圆拉长方向错误、边缘撕裂，属于几何性错误；分桶阶段把椭圆按 tile 分配，若分桶漏掉跨 tile 的大椭圆，症状是 tile 边界处出现矩形接缝；排序阶段在 tile 内按深度排列，若排序缺失或近似过度，症状正是 alpha 合成不可交换所导致的遮挡反转与闪烁。因此诊断的第一步是区分“几何错误”“接缝错误”“遮挡错误”三类症状，再回溯到对应步骤。

伪代码思路可写成症状到步骤的映射：对每一帧采集 tile 边界像素差异、遮挡前后景深度反转计数、椭圆主轴方向残差三个指标，若边界差异显著则查分桶，若深度反转计数非零则查排序，若主轴残差显著则查投影协方差。系统代价在于这套诊断本身需要额外一遍采样与统计，在实时管线中不能每帧执行，通常只在离线回归或灰度发布时开启。失败模式是把三类症状混为一谈：例如把 tile 接缝误判为排序问题，于是反复调整排序精度却毫无改善，因为根因在分桶的覆盖判定。具体例子是一个包含大量近平面超大高斯的重建场景，椭圆跨越多个 tile，分桶若按中心点归属而非按覆盖范围归属，就会在 tile 交界处丢失贡献，表现为规则网格状的暗线，这与排序错误造成的随机闪烁在空间分布上截然不同。

二 · 变体题 B：把“排序”改成“近似排序的代价评估”

变体 B 要求考生评估“在 tile 内用近似排序替代精确排序”的收益与风险。参考事实指出排序通常在 tile 内做，深度冲突时近似处理。这里的机制核心是 alpha 合成的不可交换性：从前往后的合成公式为

$$C=\sum_{i=1}^{N} c_i \alpha_i \prod_{j=1}^{i-1}(1-\alpha_j)$$

该式的乘积项依赖顺序，交换两个高斯会改变透射率累积，从而改变最终颜色。近似排序的常见做法是按量化后的深度桶排序，或按 tile 内中心深度做基数排序，代价是当两个高斯深度差小于量化步长时顺序不确定，产生帧间抖动。系统代价体现在两方面：量化步长越小，排序键的位宽越大，基数排序的遍数增加，tile 内排序的常数开销上升；量化步长越大，深度冲突概率上升，闪烁风险增加。这是一个明确的精度与吞吐权衡，不存在免费午餐。

评估方法应当给出可判定的准则而非定性描述：统计每个 tile 内深度差低于步长的相邻高斯对数量，若该数量占比高，则近似排序在该 tile 上不可接受。失败模式是只测平均帧率而不测帧间稳定性，导致上线后用户看到闪烁却无法复现。具体例子是一个多层透明物体叠加的场景，前后景高斯深度接近，量化步长取大值时，相邻帧的排序结果在两组高斯间来回切换，合成颜色在两种结果间跳变，肉眼可见为边缘噪点闪烁；而把步长减半后闪烁消失，但排序开销上升，帧率下降，这正是变体 B 要求考生指出的权衡点。

三 · 变体题 C：把“协方差投影”改成“数值稳定性追问”

变体 C 从 Σ'=J W Σ Wᵀ Jᵀ 出发，追问该变换在极端视角下的数值行为。机制上，W 为视图变换，J 为投影雅可比，二者复合后协方差矩阵可能接近奇异：当高斯被压扁到接近视线方向时，投影后的 2D 协方差在一个主轴上趋近于零，求逆与特征分解会出现病态。工程实现通常对 2D 协方差加一个小的对角正则项再求逆，或直接由 2D 协方差的特征值构造椭圆的长短轴与旋转角。代价是正则项引入的模糊：正则过大会让极扁椭圆被人为撑圆，表现为远处细节糊成一片；正则过小则数值溢出，产生 NaN 像素。失败模式是 NaN 在 tile 内传播，一个坏像素污染整块 tile 的合成结果。

判据可以写成条件数的检查：对每个高斯的 2D 协方差计算其特征值比，超过阈值时走退化路径，即降级为点或裁剪。具体例子是相机贴近一个薄片状高斯时，投影椭圆退化为一条线段，若仍按常规求逆，长短轴计算出现负值开方，输出黑色或彩色噪点；加入退化分支后该高斯被当作低贡献元素跳过，画面稳定但该处细节丢失。这个变体考的是考生能否把“协方差投影决定椭圆形状”从公式层面推进到数值实现层面，并指出退化处理是正确性的一部分而非可选优化。

四 · 五个追问的递进结构

追问一：为什么分桶不能省略？回答应落到 tile 的局部性：光栅化按 tile 并行，每个 tile 只处理与其相交的高斯，分桶是并行粒度的前提，省略则退化为全局遍历，帧率随高斯总数线性恶化。追问二：排序为什么在 tile 内而不是全局？因为全局排序的键是视图空间深度，但 alpha 合成的正确顺序只需在影响同一像素的高斯之间成立，tile 内排序把问题局部化，减少了排序元素数量，代价是跨 tile 边界的高斯需要在多个 tile 中重复参与排序。追问三：跨 tile 高斯重复排序的代价如何控制？机制是按覆盖范围而非中心点分桶，并对超大高斯做裁剪或分层，代价是分桶阶段的计算量上升。追问四：排序错误为什么表现为闪烁而非静态错误？因为相机或场景微小变动会改变深度比较结果，顺序在帧间翻转，静态单帧可能看不出问题。追问五：如果只允许改一处来提升正确性，改哪里？答案应是排序的稳定性，即引入确定性的深度比较与冲突消解规则，使帧间顺序一致。

这五个追问构成从“必要性”到“局部性”到“代价”到“症状”到“优先级”的链条，每一环都要求考生给出机制而非结论。失败模式是考生把追问二与追问三混答，用“全局排序更准”搪塞局部排序的合理性，却说不清 tile 内排序的元素规模与重复代价。具体例子是一个高斯分布极不均匀的场景，少数超大高斯覆盖上百个 tile，若不做分层，这些高斯在每个 tile 的排序中都出现，排序元素数量被少数元素主导，帧率被拖垮；分层后大高斯单独走一条粗粒度通道，tile 内排序只处理局部高斯，代价与收益都可量化。

五 · 扣分点与常见错误的对应表

评分标准为四步 60%、排序 40%，扣分点应逐项对应。下表把常见错误映射到扣分位置与可观测症状，便于阅卷时快速定位。

错误扣分位置可观测症状纠正方向
跳过排序排序 40% 全扣遮挡反转、帧间闪烁补 tile 内深度排序与冲突消解
把分桶当可选四步 60% 中的分桶项帧率随高斯数线性恶化说明 tile 并行粒度依赖分桶
忽略协方差投影四步 60% 中的投影项椭圆方向错误、边缘撕裂写出 Σ'=J W Σ Wᵀ Jᵀ 并说明退化处理
只答全局排序排序 40% 部分扣无法解释 tile 局部性补 tile 内排序与跨 tile 重复代价
把近似排序说成无损排序 40% 部分扣无法解释闪烁来源给出量化步长与冲突概率的关系

这张表的用法是先看症状再看扣分位置，避免只按关键词给分。系统代价在于阅卷一致性：同一份答案在不同阅卷人手里可能因症状描述模糊而给出不同分数，因此扣分点必须绑定可判定的表述，例如“是否写出 tile 内排序”比“是否理解排序重要性”更可判。失败模式是考生用大段文字描述重要性却不给机制，此时应按“未写出机制”扣分而非按字数给分。具体例子是考生写“排序很重要，否则会出错”，这句话不构成得分点，因为它既未说明不可交换性，也未说明 tile 内实现，属于典型的空转表述。

六 · 教学建议：从公式到症状的对照训练

教学上应把四个步骤各自绑定一个公式或伪代码片段与一个症状，形成对照记忆而非线性背诵。投影绑定 Σ'=J W Σ Wᵀ Jᵀ 与椭圆方向残差；分桶绑定 tile 覆盖判定与边界接缝；排序绑定合成公式中的透射率乘积与帧间闪烁；合成绑定从前往后的累积与透射率衰减。训练方法是给出症状让学生反推步骤，再给出步骤让学生预测症状，双向练习比单向背诵更能暴露“跳过排序”这类错误。代价是课堂时间被症状讨论占据，公式推导被压缩，因此需要把公式作为课后材料，课堂只做对照。

另一个建议是把扣分点前置为评分演练：让学生互相批改并标注扣分位置，重点训练“空转表述不得分”的判断。失败模式是教学只讲正确流程不讲失败症状，学生能背四步却在变体题中无法定位瓶颈。具体例子是让学生看一段出现规则网格暗线的渲染结果，要求指出这是分桶覆盖判定问题而非排序问题，并写出修复思路：按覆盖范围分桶并对跨 tile 高斯做裁剪。这一练习直接把“分桶不可省略”从结论变成可操作的工程判断，也把本部分的变体与追问落到具体机制上。
