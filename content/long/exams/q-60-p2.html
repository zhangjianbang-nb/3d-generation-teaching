一 · 三个变体题：同一考点的三种拧法

原题是「六种身体对六类路线，各有什么代价」。变体题不换考点，只换约束条件，用来检验读者是否真的掌握了「映射 + 代价 + 选型看下游」这条链，而不是背下了六个名词。三个变体分别从「删项」「加约束」「换下游」三个方向拧。

变体 A（删项型）：如果故事里只留下「雾、萤火虫、模子」三种身体，请说明这三条路线各自的能力边界，并指出在什么下游任务下，剩下三条被删掉的路线仍然不可替代。这个变体的机制在于：删项迫使读者承认「少数的三种」不构成闭包。雾对应 NeRF，照片级但慢、逐场景；萤火虫对应 3DGS，实时但显存与透明材质难；模子对应 SDF/NeuS，表面干净但薄结构难。三者都偏向「从已有图像重建」，都不解决「没有 3D 数据也要生成」的问题——这正是画师的梦（SDS）与合唱团（多视图扩散）的位置。工厂（前馈大模型）则解决规模化与速度。评分上，变体 A 的判分点仍是映射 60%、代价 40%，但额外要求「指出被删项不可替代的下游」，答不出这一句就只拿到映射分。

变体 B（加约束型）：给定「必须实时渲染、必须在浏览器里跑、必须支持用户拖动光源」三条硬约束，问六条路线里哪些能进候选集，哪些必须出局，出局理由要落到具体机制上。这条变体的伪代码思路可以写成一次筛选：

$$\text{candidates} = \{\,r \in R \mid \text{latency}(r) \le L_{\max} \;\wedge\; \text{mem}(r) \le M_{\max} \;\wedge\; \text{relight}(r) = \text{true}\,\}$$

其中 $R$ 是六条路线，$L_{\max}$ 是帧预算，$M_{\max}$ 是显存/内存上限，$\text{relight}$ 表示是否支持显式光照编辑。按这条筛选，雾（NeRF）在延迟项上出局，因为逐场景优化与体渲染的采样开销使它难以进入实时帧预算；萤火虫（3DGS）能过延迟项，但显存项与透明材质是风险点；模子（SDF/NeuS）表面干净、便于重光照，但薄结构难，且从 SDF 到实时渲染通常要额外提取网格；画师的梦（SDS）与合唱团（多视图扩散）是生成端，产出仍需落到某种可渲染表示，不能直接满足拖动光源；工厂（前馈大模型）快、可规模化，但拓扑与材质仍难，重光照能力取决于输出表示。系统代价在于：约束越硬，候选集越小，而每条被淘汰的路线都带走一种能力——这就是「没有一种表示通吃」的工程含义。

变体 C（换下游型）：把下游从「渲染」换成「编辑 + 动画 + 物理仿真 + 引擎导入」。这时判分重心从「画得好不好看」转向「数据形态是否可被下游消费」。模子（SDF/NeuS）在这里占优，因为干净表面便于布尔编辑、碰撞体生成与拓扑检查；萤火虫（3DGS）是显式高斯基元集合，编辑与物理接入需要额外的代理几何；雾（NeRF）是隐式场，编辑要借助场操作，动画与物理接入成本高；工厂（前馈大模型）输出若为网格则引擎友好，若为其他表示则要转换。具体例子：一个团队要把生成资产放进游戏引擎做角色动画，选型的第一个问题不是「哪种渲染最像照片」，而是「哪种输出能被绑定骨骼、能生成碰撞体」。答不出这一层的读者，会在变体 C 上丢掉代价分。

二 · 五个追问：把答案逼到机制层

追问的作用是防止答案停在名词对照表。以下五个追问都指向机制，每个都配一个失败模式。

  • 追问 1：雾（NeRF）为什么「慢」是结构性的，而不是工程优化没做好？机制在于体渲染要对每条光线沿路径做密集采样，每个样本都要过一遍 MLP，渲染成本随采样数与网络前向次数线性增长；逐场景优化意味着每个场景都要重新拟合一套参数，没有跨场景复用。失败模式：把「慢」当成「换块更好的 GPU 就行」，忽略了逐场景拟合的时间成本无法靠单卡算力摊薄。
  • 追问 2：萤火虫（3DGS）的显存代价来自哪里？透明为什么难？机制在于 3DGS 用大量显式高斯基元表达场景，显存随基元数量增长，且光栅化时要按深度排序做 alpha 混合；透明与半透明材质要求正确的透射与排序，而基于排序的混合在视角变化与相互穿插时容易出现次序错误。失败模式：只记住「实时」这个优点，答不出「显存/透明难」对应的机制，被判为代价分不足。
  • 追问 3：模子（SDF/NeuS）为什么「表面干净」却「薄结构难」？机制在于 SDF 用带符号距离场表达表面，零等值面提取出的网格天然闭合、法线稳定；但薄结构（薄片、细杆、布料褶皱）在距离场里厚度接近采样分辨率，等值面提取时容易断裂或合并。失败模式：把「干净」等同于「什么都能重建」，在薄结构案例上给出错误承诺。
  • 追问 4：画师的梦（SDS）「有偏/多面」的根源是什么？机制在于 SDS 用 2D 扩散模型的评分蒸馏来优化 3D 表示，监督信号来自多个视角的 2D 先验，缺少真实 3D 数据约束；不同视角的先验可能互相冲突，导致几何出现多面、过饱和或「Janus 问题」式的多脸。失败模式：以为 SDS 是「无 3D 数据也能生成」的免费午餐，忽略其偏置需要在下游用多视图一致性或真实数据校正。
  • 追问 5：合唱团（多视图扩散）「背面一致但会幻想」怎么解释？机制在于多视图扩散在同一去噪过程里共享跨视图注意力，使不同视角的生成结果在潜空间上互相对齐，因此背面与正面一致；但一致性约束只保证「看起来协调」，不保证「符合真实几何」，被遮挡区域没有观测支撑时模型会补出合理但不存在的结构。失败模式：把「一致」误读为「正确」，在需要精确几何的下游（碰撞、测量）直接使用。

五个追问的共同结构是：先问机制，再问失败模式。评分时，只答机制不答失败模式，说明读者知道原理但缺少工程感；只答失败模式不答机制，说明读者在背结论。

三 · 扣分点：评分表背后的四道坎

评分标准写明映射 60%、代价 40%。把这两项拆开，扣分集中在四道坎上。

扣分坎表现对应判分点后果
映射错位把雾对成 3DGS，或把工厂对成 SDS六种身体对应六类路线映射分直接损失，且后续代价论述失去锚点
代价缺失只说优点，或只写「有代价」不写是什么每种都有代价代价分不足，答案退化为名词表
替代论写成「后一种取代前一种」的线性技术史不是替代关系违背「并行演进」的解析，属结构性错误
下游缺位不谈渲染/编辑/动画/物理/引擎，只谈像不像选型看下游无法回答变体 B、C，暴露选型能力缺失

四道坎里，「替代论」最隐蔽。故事用「投胎」串起表示演进，读起来像一条时间线，但解析明确指出真实研究是并行演进的：没有一种表示通吃。把故事当技术史，就会写出「萤火虫取代雾」「工厂取代一切」这类句子。这类句子在映射上也许没错，但在判分点「不是替代关系」上直接失分。具体例子：有读者写「3DGS 出现后 NeRF 就被淘汰了」，这句话同时踩中「替代论」与「忽略代价」两道坎——NeRF 的隐式场在需要连续密度、体积效应与场编辑的下游仍有位置，3DGS 的显存与透明问题也没有被解决。

另一道常被忽略的坎是「代价缺失」的方向性。代价不是一句「慢」或「贵」，而要落到机制：雾的慢来自逐光线采样与逐场景拟合；萤火虫的贵来自显式基元数量与排序混合；模子的难来自薄结构在距离场里的分辨率极限；画师的梦的偏来自 2D 先验缺少 3D 约束；合唱团的幻想来自遮挡区无观测；工厂的难来自数据依赖与拓扑/材质。写不出机制层的代价，就等于没答代价题。

四 · 常见错误：三类典型答卷的解剖

把常见错误按答卷形态分三类，每类都给出可复现的错法与纠正路径。

第一类：名词对照型。答卷是一张六行表，左列故事元素，右列技术名词，没有第三列。错因是把「映射」当成全部考点，忽略了代价 40%。纠正路径是强制加一列「代价机制」与一列「适用下游」，让每一行都必须回答三个问题：它是什么、它贵在哪、它适合谁。这类答卷在变体 A 上会立刻暴露：删掉三项后，读者说不出被删项为何不可替代。

第二类：线性技术史型。答卷按「雾→萤火虫→模子→画师的梦→合唱团→工厂」排成进化链，每一段都写「比前一种更好」。错因是把故事的叙事顺序当成技术替代顺序。纠正路径是画一张并行图：六条路线并列，箭头指向下游任务而不是彼此；并在每条边上标注代价。判分点「不是替代关系」要求答卷明确写出「并行演进」四个字背后的含义——同一时期多条路线各自解决不同约束。

第三类：只谈生成不谈重建型。答卷把六条路线全归到「生成」，忽略了雾、萤火虫、模子本质上是重建/表示路线，画师的梦、合唱团、工厂才是生成端。错因是混淆「表示」与「生成流程」。纠正路径是区分两层：表示层（雾、萤火虫、模子）回答「场景怎么存」，生成层（画师的梦、合唱团、工厂）回答「没有数据怎么造」。两层可以组合——例如用 SDS 或前馈模型产出，再落到 3DGS 或网格表示——但组合不等于替代。具体例子：工厂（前馈大模型）快、可规模化，但输出仍要选一种表示落地，拓扑与材质仍难，这正是「表示层不可跳过」的证据。

三类错误的共同根源是：把「六种身体」当成六个标签，而不是六组「机制—代价—下游」三元组。教学上，只要让读者对每个标签强制写出三元组，三类错误都会显著收敛。

五 · 教学建议：把故事当索引，不当教材

教学建议的核心判断是：故事是记忆索引，不是技术教材。「投胎」提供的是六个好记的意象，帮助读者在压力下回忆起六条路线；但意象不承载机制，机制必须由读者自己补。教学设计应围绕「补机制」展开。

  • 先做映射，再做代价，最后做选型。三步顺序不能颠倒。先让读者把六个意象对到六条路线，错了立刻纠正；再要求每条路线写出一个机制层代价；最后给一个下游任务，让读者从六条里选并说明淘汰理由。这个顺序对应评分权重 60% 与 40%，也对应变体 A、B、C 的难度梯度。
  • 用「删项」和「换下游」做压力测试。变体 A 检验闭包意识，变体 C 检验下游意识。两者都不需要新知识，只需要把已有映射重新组织，因此适合作为课堂练习而非考试题。
  • 把「替代论」设为红线。任何出现「取代」「淘汰」「全面优于」的表述都要被打回，要求改写为「在某某下游约束下更优，但在某某约束下仍有位置」。这条红线直接对应判分点「不是替代关系」。
  • 用失败模式反推机制。追问 1 到 5 的结构是「机制—失败模式」，教学时可以反过来：先给失败模式（例如「薄结构断裂」），让读者反推这是哪条路线、机制是什么。反推比正述更能暴露理解漏洞。

系统代价层面，教学建议也要承认成本：六条路线各配一个机制、一个代价、一个下游例子，信息量已经接近一次完整的技术选型训练；若再叠加变体与追问，课时会紧张。工程判断是：把「映射 + 代价」放在课内，「变体 + 追问」放在课后或讨论课，用评分表逐项对照，避免把有限课时耗在名词记忆上。

最后一个具体机制层面的落点：六条路线的选型不是一次性决策，而是随下游约束变化的持续判断。雾的逐场景拟合在需要快速迭代的场景里是负担，但在需要连续体积效应的下游是优势；萤火虫的显存代价在移动端是硬约束，在桌面端可摊薄；模子的薄结构难题在工业检测里是致命项，在角色动画里可绕过；画师的梦的偏置在多视图校正下可缓解；合唱团的幻想在遮挡区无法根除，只能靠真实观测补；工厂的数据依赖决定了它的能力边界随训练分布移动。选型的工程判断因此落在「约束—机制—代价」三者的匹配上，而不是路线的新旧排序。
