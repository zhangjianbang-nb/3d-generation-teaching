二 · 三个变体题：把“共享边”从结论改写成条件

变体一：把题目从“AMT 如何缩短序列”改成“给定一个面片遍历顺序，判断该顺序下 AMT 的编码是否退化”。这道变体考的不是记忆结论，而是把 AMT 的成立条件显式化。AMT 的局部编码只在当前面片与已编码面片存在一条共享边时成立：编码器写出“新顶点 + 共享边”即可定位当前面片，无需重复写出三个顶点。若遍历顺序使得当前面片与已编码集合没有共享边，则“共享边”字段无处可指，编码只能回退到写出三个顶点，此时 AMT 与普通 tokenization 等价。判据可以写成一句伪代码思路：对每个面片 f，检查 f 的边集合与已编码面片边集合的交集是否非空；非空则走 AMT 分支，空则走退化分支。系统代价在于，这个检查本身要求维护一张边到面片的邻接表，遍历过程中不断把新面片的边插入表中；邻接表的规模随面数增长，内存占用与面数同阶，而普通 tokenization 不需要这张表。失败模式是遍历顺序在局部看似相邻、全局却出现“跳跃”——例如按空间分块排序后块间切换处，当前面片与上一块最后一个面片不共享边，退化分支被触发，序列在该处突然变长。具体例子：一个由两个不相连的网格块组成的场景，若遍历顺序先走完块 A 再走块 B，则块 B 的第一个面片必然退化，这一处的 token 数从 AMT 的少量字段跳回三个顶点。

变体二：把问题改成“AMT 缩短序列后，为什么误差累积的风险没有被消除”。这道变体针对解析中“仍是自回归生成”这一句做展开。AMT 改变的是每个面片的表示长度，不改变生成范式：每个面片的 token 仍然依赖此前所有 token 的条件概率，序列变短只是把同样的链式分解压缩了步数，链式结构本身保留。用公式表达，生成第 n 个面片的概率仍分解为逐 token 条件概率的乘积，AMT 只是让每个因子对应的 token 数变少，条件依赖的跨度并未归零。系统代价是：序列缩短带来的上下文窗口节省，被“更长网格、更多面片”的生成目标抵消——窗口能容纳约 1600 面，意味着自回归链条也延长到约 1600 个面片量级，早期面片的编码错误会沿链条向后传播，且因为面片之间共享边，一个顶点位置的错误会通过共享边字段影响后续多个面片的解码。失败模式是局部错误在邻接图上扩散：某个共享边被解错，后续依赖该边定位的面片全部偏移。具体例子：生成一个闭合曲面时，若前几个面片的共享边字段出现偏移，后续面片会沿着错误的邻接关系继续拼接，最终网格在拓扑上出现裂缝或自交，而序列长度本身看不出异常。

变体三：把问题改成“若把 AMT 用在非流形或带孔洞的网格上，哪些假设会失效”。AMT 的核心假设是相邻面片共享一条边，这在流形网格上成立；非流形边被三个以上面片共享时，“共享边”字段不再唯一确定当前面片，编码器必须额外写出选择哪一侧的信息，局部编码的简洁性被削弱。带孔洞的网格则考验遍历顺序：孔洞边界处的面片邻接关系稀疏，遍历到边界时容易触发退化分支。判分上，这道变体要求答出“共享边唯一性”和“遍历顺序的邻接覆盖”两个前提，而不是复述“只写新顶点”。系统代价是编码器需要为每个面片记录边归属，非流形情形下还要记录方向或面片索引，字段变长，序列缩短的收益被部分吃掉。失败模式是编码器与解码器对“共享边”的理解不一致：编码端按某一侧写入，解码端按默认侧读取，重建出的网格面片朝向翻转。具体例子：一个带内孔的平板，孔壁面片与顶面面片共享边但归属方向相反，若遍历顺序未把孔壁与顶面的邻接关系排在一起，孔壁首个面片退化，且后续面片的共享边字段可能指向错误一侧。

三 · 五个追问：从机制追到边界

追问一：AMT 的“新顶点”字段具体省掉了什么？答：普通 tokenization 对每个面片写三个顶点坐标，其中与已编码面片共享的两个顶点是重复信息；AMT 只写当前面片引入的那个新顶点，另外两个顶点由共享边隐含给出。省掉的是重复顶点的坐标 token，不是坐标精度，也不是拓扑信息。追问二：序列缩短的收益为什么用“约 1600 面”来表达而不是比例？答：收益的落点是上下文窗口能容纳的面数，约 1600 面是给定事实中的容量表述；比例取决于网格的平均邻接度，不同网格的共享边命中率不同，比例不是常数，因此用容量表述更稳。追问三：遍历顺序不好会怎样退化？答：退化为普通 tokenization，即每个面片重新写三个顶点，序列长度回到未压缩水平，AMT 的收益归零，但生成仍然可以进行，只是窗口能容纳的面数下降。追问四：AMT 是压缩算法吗？答：不是。压缩算法对已完整的序列做熵编码，AMT 改变的是序列的构造方式——它在生成时就不写重复顶点，属于表示层的 tokenization 设计，不是对生成结果的后处理。追问五：序列缩短有没有代价？答：有。代价包括编码器维护邻接表的开销、遍历顺序设计的前置工作、退化分支的处理逻辑，以及自回归链条变长后误差累积的暴露面变大。这五个追问的共同指向是：AMT 的收益与前提绑定，答“缩短了序列”而不答前提，就是把条件结论当成了无条件结论。

四 · 扣分点：评分标准如何落到具体表述

评分标准给定为 AMT 机制 60%、收益 40%。扣分点要按这两个权重拆开看。机制部分的扣分集中在三处：其一，只说“利用相邻面共享边”而不说“只写新顶点”，共享边是事实前提，新顶点是编码动作，缺动作则机制不完整；其二，把共享边说成“两个面片的所有顶点都共享”，实际共享的是一条边上的两个顶点，第三个顶点是新引入的；其三，把 AMT 描述成对顶点列表的去重后处理，而不是生成时的局部编码，这会把机制错置到压缩范畴。收益部分的扣分集中在两处：只说“序列变短”而不落到“同样窗口容纳更多面、约 1600 面”，收益没有落点；把序列缩短说成“没有代价”，忽略遍历顺序依赖与误差累积，收益被说成无条件。表格可以把扣分点与判分点对齐：判分点四条——相邻面共享边、只写新顶点、序列缩短、支持约 1600 面——前两条归机制 60%，后两条归收益 40%。常见错误中“以为 AMT 是压缩算法”直接打掉机制分的核心，“忽略遍历顺序”打掉机制分的前提，“以为序列缩短没有代价”打掉收益分的边界。评分演练时的具体判断是：若答案写出“共享边 + 新顶点”但未提遍历顺序，机制分给大部分但不给满；若写出“约 1600 面”但未说明这是窗口容量而非网格上限，收益分打折。

判分点权重归属典型失分表述

只写新顶点机制 60%只说共享边，不写编码动作；或说成顶点去重后处理
序列缩短收益 40%只说变短，不落到窗口容量
支持约 1600 面收益 40%说成网格面数上限，或说成无代价

五 · 常见错误：三类错法的共同根源

第一类错法是把 AMT 当压缩算法。根源在于“缩短序列”这个说法容易被读成“对已有序列做压缩”，而 AMT 的实际位置在 tokenization 层：它在构造序列时就不产生重复顶点的 token。区分办法是问一句“被省掉的 token 是否曾经存在”——压缩算法省掉的是已存在的冗余，AMT 省掉的是从未写入的重复。第二类错法是忽略遍历顺序。根源在于把“相邻面共享边”当成网格的静态属性，而 AMT 的编码依赖的是“当前面片与已编码面片”的动态邻接关系；静态上相邻不等于遍历时已编码，顺序不好就退化。第三类错法是以为序列缩短没有代价。根源在于只看到窗口容量的收益，没看到邻接表维护、顺序设计、退化分支与误差累积四项代价。三类错法有一个共同点：都把 AMT 的成立条件省略成结论。教学上对应的纠偏手段是让学生对每个结论补一句“在什么条件下成立”，例如“序列缩短，前提是遍历顺序保证当前面片与已编码面片共享边”。另一个具体错误是把“约 1600 面”说成模型能生成的面数上限，实际它是同样上下文窗口在 AMT 下能容纳的面数量级，超出这个量级不是不能生成，而是需要更长窗口或分块，误差累积的暴露面也随之变大。

六 · 教学建议：用反例和边界把机制钉住

教学建议一：先给一个退化反例再讲机制。拿一个遍历顺序被打乱的网格，让学生数出哪些面片走了退化分支，再对比顺序良好时的 token 数差异，机制中的“共享边”与“新顶点”就在对比中显形。教学建议二：把公式写在黑板上作为链条长度的表达，让学生看到 AMT 改变的是每个因子的 token 数而不是链式结构本身，从而理解“序列缩短不等于误差累积消失”。教学建议三：用一张边到面片的邻接表让学生手工走三步遍历，体会编码器在每一步要查什么、写什么，系统代价中的邻接表开销就变成可触摸的操作。教学建议四：把评分标准的 60/40 拆成两张检查清单，机制清单问“共享边、新顶点、遍历顺序”，收益清单问“序列缩短、约 1600 面、代价”，让学生自评时逐项打勾，避免用一句“AMT 很高效”覆盖全部判分点。教学建议五：布置一个边界题——非流形边或带孔洞网格——要求学生指出 AMT 哪个假设失效、失效后编码字段如何变长，这把“共享边唯一性”从隐含前提变成显式考点。
