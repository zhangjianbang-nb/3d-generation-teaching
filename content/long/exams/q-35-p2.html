一 · 变体题：把「可控」拆成可判定的三种问法

原题问的是「可控体现在哪些维度、几何与纹理如何解耦」，这是一个复合命题。变体题的价值在于把复合命题拆成单点可判定的问法，检验读者是否真的掌握了机制，而不是背下了参考答案的句式。以下三个变体都只围绕给定事实展开，不引入外部设定。

变体一：「只改纹理、不改形状」在系统层面需要满足什么条件？这道题把「可分别编辑」从一句结论逼成一个接口问题。参考答案给出的机制是几何分支出形状与法线、纹理分支出 PBR 材质，两条分支解耦。要让「只改纹理」成立，纹理分支必须能拿到与当前几何完全一致的 UV 展开与法线朝向；否则新生成的 PBR 材质在旧 UV 上采样时会出现接缝、拉伸或光照方向错位。判定要点是：读者是否指出解耦不等于无耦合，解耦发生在「生成路径」上，而耦合发生在「接口契约」上。只答「因为解耦所以可以只改纹理」属于循环论证，不得分。

变体二：「给额外条件」与「条件越多越好」的区别是什么？这道题直接对准常见错误。参考答案的解析写明：可控条件越多，训练数据要求越高。也就是说，每增加一个条件维度，模型需要在训练中见过「该条件与目标几何/纹理正确配对」的样本，否则条件通道形同虚设甚至引入冲突。判定要点是读者能否把「条件数量」与「数据覆盖」挂钩，并指出多条件引导的收益是有条件的，不是单调递增。

变体三：「可控」是否等于「可交互编辑」？这是最常见错误的正面形式。参考答案中的可控指的是几何与纹理可以分别由文本/图像/条件引导，以及用户可以只改纹理、只改形状或给额外条件——这些都是「重生成式」的操作语义，即提交一次新的引导、跑一次分支、得到一次新结果。交互编辑意味着用户在已有结果上做局部、连续、低延迟的修改，二者在系统代价上完全不同。判定要点是读者能否区分「条件引导的重生成」与「交互式局部编辑」这两种操作模型。

变体考查靶点及格线满分线
只改纹理接口一致性指出需共享 UV/法线指出解耦在生成路径、耦合在接口契约
额外条件数据代价指出条件越多数据要求越高指出条件通道需配对样本，收益非单调
可控 vs 交互操作语义区分重生成与编辑给出两者在延迟与状态维护上的代价差异

三个变体共享一个判分逻辑：凡是把参考答案的结论句复述一遍而不展开机制的，都停在及格线；凡是能把结论句还原成接口、数据、操作模型三类约束的，才进入满分线。这也解释了为什么原题的评分标准把可控维度与解耦各占一半——变体题实际上是在分别加压这两半。

二 · 追问五连：从「是什么」压到「代价在哪」

追问的作用是在答案已经正确的前提下继续下压，暴露理解的边界。以下五个追问按难度递增排列，每个都对应一个具体机制或失败模式。

追问一：几何分支输出形状与法线，纹理分支输出 PBR 材质，这两组输出在什么意义上「解耦」？机制层面，解耦指的是两条分支各自接受引导、各自前向计算、各自产出中间表示，互不阻塞。形状与法线构成几何侧的表达，PBR 材质构成纹理侧的表达。解耦的边界不在输出张量上，而在「引导到输出」的映射上：几何分支的引导变化不要求纹理分支重新训练，反之亦然。这是解耦带来的灵活性来源。

追问二：既然解耦，为什么还需要「共享一致的几何接口」？因为纹理必须落到几何表面上。PBR 材质的空间定义依赖 UV 参数化，光照计算依赖法线朝向。若纹理分支产出的材质所假设的 UV 布局与几何分支实际给出的 UV 不一致，材质无法正确贴合；若法线朝向约定相反，着色结果会系统性翻转。这就是解析里「否则纹理贴不上」的具体含义。接口一致性是解耦的前提，不是解耦的反例。

追问三：「用户可以只改形状」时，纹理侧会发生什么？形状改变意味着 UV 参数化与法线场都可能改变。若纹理分支不重新生成，原有 PBR 材质在旧 UV 上的采样位置与新几何不再对应，表现为纹理错位。因此「只改形状」在操作上是允许的，但在结果上通常要求纹理侧跟随重生成或重投影。这里暴露的失败模式是：把「可分别编辑」误读为「改一边另一边必然不变」。正确的表述是「可以分别发起引导」，而不是「分别发起后另一边无需任何适配」。

追问四：多条件引导时，条件之间冲突怎么办？给定事实只说明可控条件越多、训练数据要求越高，并未给出冲突消解的具体算法。可判定的工程判断是：多条件引导要求训练分布覆盖条件组合，条件通道之间需要有可学习的权重或门控来分配影响力；若训练中从未见过某组合，推理时该组合的行为不可预期。这是一个数据覆盖问题，不是推理时的调参问题。

追问五：这套解耦架构的系统代价落在哪里？代价有三处：其一是接口维护，UV 与法线的约定必须在两条分支间版本一致，任何一侧的表示变更都要同步；其二是数据成本，条件维度增加会抬高配对样本的需求；其三是编排成本，用户发起「只改纹理」或「只改形状」时，系统需要判断哪些分支重跑、哪些中间表示复用，这个调度逻辑本身是工程负担。三处代价都不体现在单次前向的算力上，而体现在系统长期维护上。

$$\text{可用条件集合}\;C=\{c_{\text{text}},c_{\text{image}},c_{\text{cond}}\},\quad \text{训练需求}\;\propto\;|\mathcal{P}(C)|\;\text{的覆盖度}$$

上式只是把「条件越多、数据要求越高」形式化：条件集合的幂集规模随条件数增长，训练需要覆盖的条件组合随之增长。这不是定量结论，而是说明为什么增加条件不是免费的。追问四与追问五在此汇合——多条件的收益被数据覆盖与接口维护两头夹住。

三 · 扣分点：评分标准如何落到具体句子

原题评分标准是可控维度 50%、解耦 50%。把这两个 50% 拆到可观察的答题句子上，扣分点就变得可操作。以下按「缺什么扣什么」的方式列出，每一条都对应参考答案中的一个判分点。

  • 只写「可控」而不列维度：扣可控维度分。可控必须落到文本/图像/条件三类引导，以及「只改纹理、只改形状、给额外条件」三种操作上。缺维度列举即缺一半的可控分。
  • 写了「解耦」但没写两条分支各自的输出：扣解耦分。几何分支对应形状/法线，纹理分支对应 PBR 材质，这是解耦的物质基础，不能只写「两条分支」。
  • 写了「可分别编辑」但没提 UV/法线接口：这是最典型的半截答案。判分点明确列出「UV/法线接口」，缺这一项说明读者没有意识到解耦的边界条件，解耦分应大幅扣减。
  • 把「可控」直接等同于「可交互编辑」：这不是遗漏而是错误，属于常见错误清单第一条。此类答案即使维度列举齐全，也应在可控维度上扣分，因为它把重生成语义替换成了编辑语义。
  • 声称「条件越多越好」而不提数据要求：对应常见错误第三条。解析已明确条件越多训练数据要求越高，反向表述属于与给定事实冲突，应扣分。
  • 只答结论不答代价：解析中的代价句（接口一致性、数据要求）是区分及格与良好的分水岭。缺代价论述的答案停在及格档。

把这些扣分点映射回 50/50 的权重，可以得到一个粗略的判分直觉：可控维度这一半考「列举是否完整、语义是否正确」，解耦这一半考「输出是否对得上、接口是否点到」。两侧都要求「机制 + 代价」成对出现，只给机制不给代价的，单侧最多拿到一半中的机制部分。

扣分点归属性质
未列三类引导可控 50%遗漏
未列三种操作可控 50%遗漏
可控=可交互编辑可控 50%错误
未写形状/法线与 PBR解耦 50%遗漏
未提 UV/法线接口解耦 50%遗漏
条件越多越好解耦 50%错误

注意「错误」类扣分与「遗漏」类扣分的处理不同：遗漏是没写到，补上即可；错误是写反了，必须先纠正语义再补机制。工程背景的读者容易在「可控=可交互」这一条上犯错，因为工程直觉倾向于把「可控」理解为「可操作」，而本题的可控是引导层面的可控，不是交互层面的可控。

四 · 常见错误的三条根因

参考答案列出三条常见错误：以为可控等于可交互编辑、忽略接口一致性、以为条件越多越好。这三条不是孤立的疏忽，各自有一条根因，识别根因比记住错误清单更有用。

第一条根因是操作语义混淆。工程语境里「可控」常与「可调」「可编辑」混用，而本题的可控是「可被引导」：用户提交文本、图像或额外条件，系统重跑对应分支，产出新结果。这里没有「在已有结果上做局部修改」的语义。混淆的代价是读者会去讨论交互延迟、撤销栈、局部编辑工具，而这些都不在本题的判分范围内，写了也不得分，还会挤占篇幅导致真正的判分点被压缩。

第二条根因是把解耦理解为无耦合。解耦描述的是生成路径的独立性，不是数据表示的独立性。两条分支各自生成，但产物必须在同一几何接口上会合：UV 决定材质往哪贴，法线决定光照怎么算。忽略接口一致性的读者，实际上是把「分支独立」外推成了「表示独立」，这一步外推在给定事实里没有依据。失败模式很具体：纹理分支产出的 PBR 材质贴到几何上出现接缝或光照翻转，而读者无法解释为什么解耦架构还会出现这种耦合故障。

第三条根因是把条件当作单调增益。增加一个条件维度，等于增加一个需要被训练数据覆盖的输入通道。给定事实明确说条件越多训练数据要求越高，这意味着条件的边际收益递减甚至为负——当某条件组合在训练中缺失时，该条件不仅不提供控制力，还可能干扰其他条件的引导。工程判断是：条件维度的取舍应按数据覆盖度评估，而不是按「能加就加」的直觉。

三条根因共同指向一个教学事实：本题的难点不在列举，而在边界。可控的边界是「引导 vs 交互」，解耦的边界是「生成路径 vs 接口契约」，条件的边界是「控制力 vs 数据覆盖」。三条边界都是「看起来可以外推、实际不能外推」的地方，这正是常见错误高发的位置。

五 · 教学建议：用反例题和接口图替代背诵

针对上述根因，教学上有效的做法不是让读者复述参考答案，而是让读者在反例上做判断。以下四条建议都围绕给定事实设计，不引入新设定。

建议一：用「只改纹理」的反例逼出接口讨论。给读者一个场景：纹理分支重新生成了 PBR 材质，但几何分支的 UV 未变、法线未变。问：这个操作成立吗？成立的条件下，材质必须按当前 UV 与法线约定生成；不成立的情形，是纹理分支假设了另一套 UV 布局。读者必须自己说出「UV/法线接口」这个词，而不是从答案里抄。这个练习直接对应判分点中的接口项。

建议二：用「可控 vs 交互」的对照表训练语义分辨。让读者分别写出「提交新文本引导并重生成」与「在已有网格上局部改一处纹理」的操作步骤，然后对比两者在状态维护上的差异。前者每次操作产生新结果，后者需要在已有结果上保持连续性。对照之后，读者会自然放弃「可控=可交互」的等式，因为两者连操作步骤都对不上。

建议三：用条件数量的幂集规模做数据代价的直觉训练。不必给出具体数字，只需让读者意识到条件集合的组合数随条件数增长，而训练需要覆盖这些组合。配合第二节的公式，读者能自己推出「条件越多、数据要求越高」不是一句口号，而是组合覆盖问题的直接后果。这比让读者背「条件越多越好是错的」更有效，因为后者只记住了结论，前者记住了推理。

建议四：把评分标准前置为写作清单。在读者动笔前给出四项判分点：几何/纹理解耦、多条件引导、可分别编辑、UV/法线接口。要求每写一段就对照清单勾一项，并额外要求每项配一句代价说明。这样做的效果是把「机制 + 代价」的成对要求变成写作习惯，而不是评分时的补救。工程背景的读者对清单式约束接受度高，这一条在实际教学中落地成本最低。

四条建议的共同点是：都不要求读者记住参考答案的句子，而要求读者在具体场景里做出判断并说出机制名。判分点里的四个词——解耦、多条件、可分别编辑、UV/法线接口——应当在读者的答案里作为「被使用过的概念」出现，而不是作为「被列举过的名词」出现。这两者的区别，就是及格档与满分档的区别。

最后落到一个工程判断上：本题的解耦架构之所以值得考，不是因为「解耦」这个词时髦，而是因为它把一个真实的系统约束摆在了明面上——两条生成分支可以独立引导、独立重跑，但它们的产品必须在同一套 UV 与法线约定下会合。任何声称「完全独立」而不提接口的答案，都在掩盖这个约束；任何声称「条件随便加」而不提数据覆盖的答案，都在掩盖另一个约束。教学的任务，就是让读者在答案里把这两个约束写出来，而不是把它们藏在一句「解耦所以灵活」的套话后面。
