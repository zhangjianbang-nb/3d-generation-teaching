一 · 三档答案的骨架：把“路径—强度—代价”钉在同一张表上

这道题看起来是列举题，实际是结构题。及格档的答案能把三条路径的名字说出来；良好档的答案能把每条路径的“一致性强度”与“系统代价”对上号；满分档的答案还要多走一步：指出三条路径共享同一个失效面——一致性不等于真实。评分标准里三条路径各占 25%、边界占 25%，这个配比本身就在提示：前 75% 是记忆与理解，后 25% 是判断力。只答出三条路径而把边界写成“总之各有优劣”，上限就锁在良好档。

先把三档的判别特征写成可操作的清单，便于演练时逐条对照：

档位必须出现的内容典型缺口
及格三条路径各一句，能区分“注意力 / 体积 / 几何中间量”三种共享对象强度与代价脱钩，边界缺失
良好每条路径给出强度定性（软约束 / 强约束）与代价来源（显存、分辨率、中间量误差）把注意力误当硬约束；不提背面幻想
满分在良好基础上给出“一致性≠真实”的机制解释，并说明视图数与共享显式程度如何同时抬升一致性与代价无（若缺边界则降档）

这张表的作用不是背答案，而是让答题时的每一句话都能被归位到某个判分点上。判分点是五个：共享注意力、共享 3D 体积、共享几何中间量、一致性强弱/代价、一致性≠真实。前三个是“路径”，第四个是“比较”，第五个是“边界”。写答案时最稳的组织方式是：三条路径各一段，每段内部自带强度与代价；最后一段专写边界。这样结构上就不会漏点。

二 · 路径①共享注意力：软约束的机制与它的天花板

MVDream 的做法是把多视角图像放进同一个去噪网络里，让跨视角自注意力在视角 token 之间传递信息。机制上，每个视角的图像 patch 被展平成 token 序列，拼成一条长序列送进 Transformer 的自注意力层；注意力矩阵里天然包含“视角 i 的 token 看向视角 j 的 token”的项。于是当视角 A 在某个区域画出某种结构时，视角 B 的对应 token 会在后续层里收到这份信息，倾向于画出兼容的内容。这就是“共享注意力”的字面含义：共享的不是三维表示，而是注意力这一信息通道。

$$\text{Attn}(Q,K,V)=\text{softmax}\!\left(\frac{QK^{\top}}{\sqrt{d}}\right)V,\qquad Q,K,V \text{ 由多视角 token 拼接而成}$$

这条路径的一致性强度是软约束。原因在于注意力只提供“倾向”，不提供“等式”。softmax 归一化后的权重是连续值，模型完全可以在某一层让视角 B 对视角 A 的注意力权重很小，从而保留自己的独立判断；训练目标也只是多视角图像的联合似然，没有任何一项显式惩罚“视角间几何矛盾”。换句话说，一致性是学出来的偏好，不是被约束出来的性质。

代价方面，这条路径最便宜：不需要额外的三维表示，不需要多趟渲染，显存增量主要来自序列变长后的注意力矩阵。序列长度随视角数线性增长，而标准注意力的计算量与显存随序列长度呈二次增长，所以视角数一多，代价就按平方往上走。这是一个具体的系统代价，也是“视图越多不一定越好”的第一层原因：加视角在信息上是加分，在注意力开销上是平方级的惩罚。

失败模式很具体：正面画了一件带口袋的外套，背面视角在注意力软引导下生成了一个“看起来合理”的背面，但口袋的位置、缝线走向与正面不构成同一件衣服。注意力传递的是纹理与语义的相似性，不是三维坐标的对应关系。模型没有任何机制去检查“背面这个口袋的三维位置是否与正面的口袋冲突”，因为它根本没有三维位置这个概念。这就是软约束的天花板：它能压住风格漂移，压不住几何矛盾。

还有一个常被忽略的细节：跨视角注意力在浅层倾向于对齐低阶统计（颜色、边缘），在深层才传递语义。如果去噪步数不足或视角间初始噪声差异过大，浅层对齐还没完成就进入深层，注意力通道实际处于“半通”状态，一致性会明显弱于训练时的期望。这不是理论推测，而是这类架构在少步采样下的固有行为：信息传递需要层数与步数两重预算，预算不够，软约束就退化成几乎无约束。

三 · 路径②共享 3D 体积：代价体的强约束与显存墙

SyncDreamer 走的是另一条路：先把多视角图像的特征反投影到一个共享的代价体（cost volume）里，再从这个三维体积里读出各视角的一致性信息。机制可以拆成三步。第一步，每个视角的图像特征经过相机参数反投影，落到三维空间的一组体素上；第二步，同一体素会收到来自多个视角的特征，这些特征被拼成一条“代价”向量，衡量各视角在该体素上是否说法一致；第三步，三维网络在代价体上做卷积或注意力，把一致的部分强化、矛盾的部分抑制，再把结果投影回各视角指导去噪。

$$\mathcal{C}(\mathbf{x})=\big[\,f_1\big(\pi_1(\mathbf{x})\big),\ \dots,\ f_N\big(\pi_N(\mathbf{x})\big)\,\big],\qquad \mathbf{x}\in\mathbb{R}^3$$

这里 $\pi_i$ 是第 $i$ 个视角的投影，$f_i$ 是该视角的特征图，$\mathcal{C}(\mathbf{x})$ 就是体素 $\mathbf{x}$ 处的代价向量。一致性强的原因很直接：矛盾在三维空间里是显式可见的。如果视角 1 说某体素是实心的、视角 2 说是空的，代价向量里就出现明显分歧，三维网络必须处理这个分歧，而不能像注意力那样“视而不见”。这是硬约束的味道：它不是惩罚项，而是把多视角信息强制汇合到同一个三维容器里再统一决策。

代价是显存与分辨率的两难。代价体的体积随三维分辨率呈三次增长：分辨率翻倍，体素数变成八倍，特征通道再乘上去，显存占用迅速失控。工程上只能二选一：要么降分辨率，让几何细节变粗；要么缩视角数或特征维度，让一致性证据变少。这就是“显存/分辨率受限”的确切含义——它不是一句定性描述，而是一条立方律的预算线。实际系统里常见做法是在粗分辨率代价体上做一致性推理，再靠图像侧的网络补细节，但补出来的细节不再受三维约束保护，又回到了软约束的地盘。

失败模式同样具体：当视角覆盖不足时，某些体素只被一个视角看到，代价向量里只有一项，无从比较，三维网络对这些区域只能“猜”。更麻烦的是反投影的遮挡问题——某体素在视角 2 里被前景挡住，它的特征其实是前景的特征，却被误当成该体素的证据，污染代价向量。这类污染在物体自遮挡严重的形状上（比如带把手的杯子、有凹槽的鞋底）尤其明显，表现为背面或凹陷处出现“合理但错误”的填充。这正是“一致性不等于真实”的第一个实例：代价体保证了多视角说法统一，但统一到一个错误的三维解释上，系统内部是自洽的，对外部世界却是错的。

四 · 路径③共享几何中间量：法线桥的强几何约束与误差传导

Wonder3D 与 Hi3DGen 代表第三条路：不共享注意力，也不共享体积，而是共享一个几何中间量——法线图。机制是两阶段耦合。第一阶段，多视角扩散模型生成各视角的法线图，法线图是视角无关的几何量：同一个表面点在不同视角下的法线方向应当一致（在相机坐标系下可换算到世界坐标系比较）。第二阶段，以法线图为条件生成彩色图像，颜色必须与法线一致——光照方向、明暗分布都要服从法线给出的表面朝向。Hi3DGen 的“法线桥”把这个思路做成显式的桥接结构：法线作为两个阶段之间的唯一通道，图像侧不能绕过法线自由发挥。

$$\mathbf{n}_{\text{world}} = R_i^{\top}\,\mathbf{n}_i,\qquad \text{约束：}\ \big\|\,R_i^{\top}\mathbf{n}_i-R_j^{\top}\mathbf{n}_j\,\big\|<\epsilon\ \ \text{（同一表面点，跨视角 } i,j\text{）}$$

一致性强度高，因为法线是几何量而非外观量。外观（颜色、纹理）在不同视角下本来就该不同，用外观做一致性信号容易把“正确的视角差异”误判为“矛盾”；法线则天然可比。共享法线等于把“表面朝向”这一层几何锁死，颜色生成被降格为在给定几何上的着色问题，自由度大幅收缩，几何矛盾很难藏身。

代价有两重。第一重是中间量本身的准确性：法线图如果估错，错误会沿着桥直接传导到颜色与最终几何，而且这种错误是系统性的——法线在凹陷处、薄结构处、镜面反射区域最容易失准，失准后颜色生成会“忠实地”照着错误法线打光，产生看似自洽实则错误的明暗。第二重是流程复杂度：两阶段意味着两次采样、两次网络前向，推理时间与显存都要翻倍，工程上还要维护法线坐标系约定、视角间法线对齐、遮挡边界处理等一堆胶水逻辑。这不是“多花一点算力”，而是多了一整条误差传导链。

失败模式的典型例子：一个表面有细微凹凸的物体，法线图在低分辨率下把凹凸抹平，颜色阶段照着一张平滑法线打光，生成的图像看起来干净合理，但背面与正面的凹凸结构对不上——因为法线桥只保证“每个视角的法线自洽”，不保证“跨视角的法线指向同一个真实表面”。法线一致性强于注意力，但它仍然是逐视角估计再对齐，对齐误差在薄结构和自遮挡处会累积。这就是第三条路径的边界：几何约束强，但依赖中间量准确，而中间量的准确性本身没有被约束。

五 · 数字底账：把“强弱”与“代价”换算成可比较的量

答题时最容易失分的地方是把“强”“弱”“便宜”“贵”当成形容词随手写。满分答案要把它们落到可比较的量上。下面这张表把三条路径的共享对象、约束类型、代价来源、失效位置并列，作为演练时的对照底账：

路径共享对象约束类型代价来源典型失效位置
共享注意力（MVDream）跨视角注意力通道软约束，无显式惩罚序列长度二次增长背面几何矛盾、少步采样下通道半通
共享 3D 体积（SyncDreamer）代价体硬约束，三维空间内统一决策体素立方律，显存/分辨率两难视角覆盖不足区、遮挡污染体素
共享几何中间量（Wonder3D / Hi3DGen）法线图 / 法线桥强几何约束，锁死表面朝向两阶段推理开销 + 误差传导链凹陷、薄结构、镜面处的法线失准

“视图数越多越好”这个直觉需要拆开算。对注意力路径，加视角在信息上是线性增益，在代价上是二次惩罚，净收益在某个视角数之后转负；对体积路径，加视角改善覆盖、减少“单视角体素”，但代价体的分辨率被迫下调，细节与覆盖是一对反向杠杆；对法线路径，加视角能提供更多法线约束，但对齐误差与遮挡边界处理的复杂度同步上升。三条路径的共同结论是：视图数不是单调利好，它和共享的显式程度一起，构成一条“一致性—代价”的帕累托前沿。答题时能把这条前沿说清楚，第四个判分点（一致性强弱/代价）就稳了。

还有一个底账要记：三条路径的代价性质不同。注意力的代价是计算量，可以通过分块注意力、稀疏注意力缓解，属于“可优化的贵”；体积的代价是显存，属于“硬墙”，优化空间有限；法线路径的代价是流程与误差链，属于“结构性开销”，加算力也消不掉误差传导。把三种“贵”区分开，是良好档与及格档的分水岭。

六 · 评分演练：三段式答题与逐点自查

演练一个满分级别的答题骨架，按判分点顺序推进，每段自带机制、代价、失效三件套。第一段写共享注意力：机制是跨视角 token 在同一自注意力层里互相可见，公式给出拼接后的注意力形式，强度定性为软约束（无显式几何惩罚），代价是序列长度的二次开销，失效例子是正面口袋与背面口袋不构成同一件衣服。第二段写共享 3D 体积：机制是特征反投影到代价体、同一体素汇合多视角证据，公式给出代价向量，强度定性为硬约束（矛盾在三维空间显式可见），代价是体素立方律导致的显存/分辨率两难，失效例子是遮挡污染体素造成凹陷处“合理但错误”的填充。第三段写共享几何中间量：机制是法线图作为两阶段唯一通道，公式给出跨视角法线在 world 坐标下的对齐约束，强度定性为强几何约束，代价是两阶段开销与误差传导，失效例子是低分辨率法线抹平凹凸后颜色阶段忠实照错法线打光。

第四段专写边界，这是 25% 的判分点，也是三档答案真正的分水岭。要写清三件事：其一，三条路径的一致性都是“系统内部自洽”，不是“对外部世界为真”，代价体可以把多视角统一到一个错误的三维解释上，法线桥可以把多视角统一到一组错误的表面朝向上；其二，一致性随视图数与共享显式程度上升，代价同步上升，存在帕累托前沿而非单调最优；其三，背面幻想是三条路径共有的失效面——背面在多数视角配置下证据最弱，软约束靠语义补、硬约束靠猜、几何约束靠失准的法线，三种机制在背面都退化为“生成合理内容”而非“恢复真实内容”。

自查清单按判分点逐条过：共享注意力是否写清“软”的机制原因（无显式惩罚）？共享 3D 体积是否写清代价的立方律？共享几何中间量是否写清“依赖中间量准确”这一环？强弱/代价是否给出可比较的量而非形容词？一致性≠真实是否给出至少一个具体失效例子？五条全中即满分档；缺第四条降为良好；缺第四条且第三条只写名字，降为及格。演练时建议限时写一遍，再对照本清单逐条打勾，把“漏点”变成可观测的缺口而不是模糊的“感觉没写好”。

最后落到一个工程判断上：选路径不是选“最强一致性”，而是选“失效面可接受”。产品若以正面展示为主、背面只做远景，共享注意力的软约束加二次开销可接受，背面幻想落在远景里不易被察觉；若下游要做三维打印或精确装配，体积路径的硬约束值得付显存墙的代价，但必须接受粗分辨率与遮挡污染；若管线里已有可靠的法线估计器，法线桥的强几何约束最划算，代价是要为误差传导链留出人工复核环节。三条路径的强弱排序只在“同一预算下”成立，跨预算比较没有意义——这是这道题真正想考的工程判断。
