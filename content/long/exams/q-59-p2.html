一 · 变体一：把“三步”拆成“四步”，考的是边界意识

第一个变体把原题的三步流程改写为四步候选：①图卷积编码面片及邻域；②VQ 把连续编码映射到词表 token；③按面片顺序排成序列；④decoder-only 自回归生成。要求考生判断哪一步是“被拆出来的伪步骤”，并说明拆分后哪一步的职责发生了变化。这个变体不考记忆，考的是对流水线边界的判断：编码、量化、序列化、生成这四个动作里，前三步共同构成 tokenization，第四步是消费 token 的生成过程，不属于 tokenization 本身。把③和④并列成 tokenization 的步骤，等于把“造词表并排词”与“用词造句”混为一谈。

具体机制上，tokenization 的产物是离散 token 序列，其消费者才是自回归 decoder。序列化步骤的职责是确定面片在序列中的先后，即遍历顺序；自回归步骤的职责是在给定前缀下预测下一个 token。两者共享“顺序”这个概念，但前者决定训练样本的排列，后者决定推理时的条件分布。用伪代码思路表示：tokenize(mesh) 返回 [t1…tn]，而 generate(prefix) 返回 t_{n+1}；前者不涉及概率，后者才涉及。变体题要求考生指出，若把④并入 tokenization，则“序列长度”这一复杂度限制会被错误地归因到生成阶段，而实际上它在上游就已由面片数和遍历切分决定。

系统代价在于，边界混淆会直接误导工程决策。若团队认为自回归属于 tokenization，就会在数据管线里塞进模型推理，导致预处理阶段显存占用与延迟飙升；反过来，若把序列化当成生成的一部分，就会把排序策略错误地放到推理时执行，训练与推理的分布不一致。一个具体例子：某管线把面片排序放在 dataloader 的 collate 阶段做，训练时每个 batch 的序列顺序与推理时不同，模型学到的局部相邻关系在部署时失效，表现为生成网格在面片接缝处出现断裂。这类失败不是模型容量问题，而是步骤归属错误。

扣分点集中在两处：一是把④说成 tokenization 的第四步而不给出“它消费而非生产 token”的理由；二是只回答“三步变四步”却不指出职责迁移。评分时，能明确指出 tokenization 的终点是 token 序列、自回归是下游消费者，并给出排序策略归属的工程后果，才算越过边界意识这一关。

二 · 变体二：给定词表规模与序列长度，反推可生成复杂度

第二个变体给出两个约束条件——词表大小固定、序列长度上限固定——要求考生反推该配置下可生成网格的复杂度上限，并说明哪一个约束先成为瓶颈。这考的是把“词表大小与序列长度共同限制复杂度”这一定性结论转成可操作的估算。机制上，词表大小决定单个 token 能表示的面片类型数，序列长度决定一次前向能容纳的面片数；两者相乘给出理论上限，但实际可用上限受遍历顺序与邻域编码的局部性约束而更低。

用公式表达，设词表规模为 V、序列长度上限为 L，则单次生成可覆盖的面片数不超过 L，可区分的面片类型数不超过 V，组合空间上界为 V^L，但有效组合远小于此，因为邻域编码要求相邻面片在 token 空间中保持局部一致性。工程上更实用的估算是最小可分辨特征尺寸：面片数 N 与序列长度 L 满足 N ≤ L，而面片平均面积与总表面积之比决定了几何细节的下限。若 V 很小，面片类型被粗量化，即使 L 很大也只能生成粗糙拓扑；若 L 很短，即使 V 很大也无法表达大网格。两者谁先成为瓶颈，取决于目标网格的面数与面片类型多样性哪个更紧张。

系统代价体现在配置选择的不可逆性。词表在训练前确定，序列长度在数据管线中确定，二者一旦定下，后续想提升复杂度只能重训。一个具体例子：面向小物件生成的配置把 L 设得很短以压低显存，结果在生成带细密褶皱的曲面时，面片数被截断，褶皱退化为平滑块；此时增大 V 无效，因为瓶颈在 L。失败模式是团队误判瓶颈位置，把预算花在扩词表上，而真正限制复杂度的是序列长度。

扣分点：只给出 V^L 而不讨论有效上界受局部性约束；或断言“词表越大越好”而不指出词表增大会稀释每个 token 的训练样本、拉长 softmax 计算。能指出瓶颈判定依赖目标网格的面数分布与类型分布，并给出“先测面数上限再定 L、再定 V”的顺序，才算答到工程判断层面。

三 · 变体三：遍历顺序改变后，局部结构还学得到吗

第三个变体只动一个变量：把面片遍历顺序从专门排序策略换成朴素的索引顺序，问模型还能否学到局部结构，并要求给出可观测的失败信号。这考的是解析里那句“顺序差会让相邻面在序列里不相邻”的展开能力。机制上，decoder-only 自回归的注意力只在序列前缀上工作，若几何上相邻的面片在序列中相距很远，模型要建立它们的依赖就必须跨过大量无关 token，局部邻域信息在注意力中被稀释。图卷积编码阶段已经把邻域压进单个面片的表示，但序列化阶段若打散邻接关系，token 序列上的局部模式就与几何局部性脱钩。

伪代码思路：对每个面片 f_i，其几何邻域 N(f_i) 在理想排序下应满足“N(f_i) 中多数面片的序列位置与 i 的距离有界”。朴素索引顺序不保证这一性质，于是训练时的下一 token 预测目标变成“预测一个与当前面片几何不相邻的面片”，模型只能依赖全局统计而非局部延续。可观测的失败信号包括：生成网格在面片接缝处出现非流形边、孔洞或重叠；同一局部几何在不同全局位置生成不一致；增大模型容量后接缝错误不降反升，因为容量被用于记忆全局排列而非局部规则。

系统代价是排序策略本身的计算开销。专门排序需要在 tokenization 前对网格做一次全局遍历规划，代价随面片数增长，且要与图卷积的邻域构造对齐；若排序与邻域编码不同步，编码阶段看到的邻域和序列阶段看到的邻接就是两套关系。一个具体例子：排序按空间分块进行，块内连续、块间跳跃，模型在块内学得很好，跨块接缝处系统性失败；此时不是模型不会生成，而是序列把块边界变成了信息断层。

扣分点：只说“顺序重要”而不给出“相邻面在序列中不相邻”的具体后果；或把失败归因于词表太小。能指出注意力跨度与几何邻域的距离失配、并给出接缝类失败信号，才算答到机制层。

四 · 五个追问：从定义到工程取舍的递进

追问一：VQ 这一步的码本更新与编码器更新是否同步？答：不同步会出问题。若码本更新快于编码器，编码器输出的连续向量会追逐移动的码本中心，造成码本坍缩，大量面片映射到少数 token，词表名义规模大而有效规模小；若编码器更新快于码本，连续表示漂移，量化误差上升。工程上要控制两者的学习率比例与码本使用率监控。

追问二：图卷积的邻域是几何邻域还是拓扑邻域？答：两者不等价。拓扑邻域按共享边定义，几何邻域按空间距离定义；网格在非均匀区域两者分叉。用拓扑邻域编码会让编码器只看到连通性，丢失空间接近但未连通的面片关系；用几何邻域则要处理 k 近邻的构建代价。选择影响 tokenization 后序列的局部性假设是否成立。

追问三：序列长度上限是训练约束还是推理约束？答：两者都要满足，但来源不同。训练时受显存与 batch 组织限制，推理时受自回归步数与缓存限制。若训练用长序列、推理截短，模型在长前缀上的位置编码分布与推理不一致，表现为长网格生成到后半段质量骤降。工程上应让训练与推理的序列长度上限一致，或显式做长度外推。

追问四：词表大小与面片类型多样性如何匹配？答：词表过大会让每个 token 分到的样本变少，量化中心欠训练；过小则把不同面片类型压到同一 token，生成时无法区分。匹配的依据是面片类型在数据中的分布：高频类型需要独立 token，低频类型可合并。代价是词表扩大带来 softmax 与嵌入表的内存增长。

追问五：三步中哪一步最难在工程上复现？答：排序策略。图卷积与 VQ 有成熟实现，自回归是标准 decoder；排序策略与具体网格数据分布强耦合，换数据集就要重调，且其效果不体现在单步指标上，只体现在生成网格的接缝质量上。复现难点在于缺少可比的排序基线。

五 · 扣分点与常见错误：从“词表越大越好”说起

常见错误一：以为词表越大越好。错在忽略词表扩大的三重代价：嵌入表与 softmax 的内存与算力随 V 增长；每个 token 的训练样本被稀释，低频 token 欠拟合；量化中心增多后，编码器与码本的联合优化更难收敛。正确表述是词表规模要与面片类型分布匹配，并以有效码本使用率作为监控指标。

常见错误二：忽略序列长度。错在把复杂度限制只归给词表。序列长度直接决定单次可容纳的面片数，短序列在面数多的网格上必然截断；且自回归的误差随步数累积，长序列的后半段质量下降是结构性的。工程上要在数据管线里统计面数分布，再定 L，而不是先定 L 再裁数据。

常见错误三：忽略遍历顺序。错在把排序当成实现细节。排序决定相邻面在序列中是否相邻，进而决定注意力能否低成本捕获局部结构；排序与邻域编码不一致时，编码阶段与序列阶段的局部性假设冲突，失败表现为接缝错误而非整体形状错误。

常见错误四：把三步的评分权重弄反。判分点是三步 60%、复杂度限制 40%；只答三步而不答词表与序列长度对复杂度的共同限制，最多拿六成；只答限制而不答三步，连基本流程都没建立。扣分点还包括：把自回归说成 tokenization 的一步；把“图卷积编码邻域”说成“编码单个面片坐标”；把 VQ 说成“降维”而不提离散词表映射。

错误错在哪正确落点
词表越大越好忽略稀释与内存代价按类型分布匹配，监控有效使用率
忽略序列长度复杂度只归因词表面数上限由 L 决定，先统计再定 L
忽略遍历顺序排序当实现细节排序决定序列局部性，与邻域编码对齐
自回归算 tokenization生产与消费混淆tokenization 止于 token 序列

六 · 教学建议：用可观测信号替代口头结论

教学上不要让学生背“词表大小与序列长度共同限制复杂度”，而要让他们构造可观测信号。第一个练习：给定一个小网格数据集，固定 L 改变 V，观察生成网格的面片类型多样性与接缝错误率，让学生自己发现 V 增大到某点后收益递减，原因是低频 token 样本不足。第二个练习：固定 V 改变 L，观察面数多的网格是否被截断，让学生看到瓶颈从词表切换到序列长度。这两个练习把定性结论变成可测量的曲线。

第三个练习针对遍历顺序：同一网格用两种排序各训一次，比较接缝处的非流形边数量。学生应看到，排序差时整体形状可能仍对，但接缝系统性出错；这教的是“局部性假设”而非“模型容量”。第四个练习是边界判断：给出四步候选，让学生标注哪一步生产 token、哪一步消费 token，并写出各自的输入输出类型。伪代码层面可要求写出 tokenize 与 generate 的函数签名，签名不同即边界清楚。

评分演练上，让学生互评并对照判分点：三步是否齐全、复杂度限制是否归因到词表与序列长度两者、遍历顺序是否被提及。常见失分是“三步齐全但复杂度只写词表”，这时应扣复杂度部分的权重而不是流程部分。教学落点应放在工程判断：先统计目标网格的面数分布与面片类型分布，再定 L 与 V 的顺序，最后验证排序策略与邻域编码是否对齐；这三步顺序错了，后面调模型容量都是徒劳。
