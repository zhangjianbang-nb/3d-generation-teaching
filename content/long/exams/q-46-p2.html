一 · 变体一：把“来源”换成“许可谱系”

原题问“从哪来”，变体一改成“这些来源的许可谱系如何分层，为什么许可过滤必须发生在去重之后而不是之前”。这不是文字游戏：抓取阶段拿到的是原始条目，同一资产在 GitHub 上以代码仓库附带模型、在 Sketchfab 上以 CC-BY 发布、在 Thingiverse 上以 CC-BY-NC 发布，三份副本的许可标签并不相同。若先去重再过滤，去重键一旦把三份合并成一条，保留哪一份的许可就成了隐式决策；若先过滤再抓取，则会在入口处丢掉本可合法使用的副本。参考答案中“去重、格式转换、许可过滤与元数据对齐”的并列顺序，在工程上应理解为“先做候选归并、再做许可裁决、最后落盘”，而不是四个可以任意交换的流水线阶段。

机制上，许可裁决需要一个“许可优先级函数”：对同一资产的多个副本，按允许商用 > 允许再分发 > 仅研究用途的偏序选出代表条目，并把全部副本的许可标签保留在元数据里作为溯源链。伪代码思路是：对每个去重簇，收集所有副本的 (source, license, url)，用偏序取最大元，若存在不可比较的许可组合则整簇降级为“待人工复核”，不进入训练集。这样做的代价是复核队列会随来源数量线性增长，且跨源许可不可比较的情况在长尾类别里尤其多。

失败模式很具体：某类资产在 GitHub 上以宽松许可出现、在 Sketchfab 上以严格许可出现，去重簇把两者合并后只留下 GitHub 副本，训练集里就出现了“许可看起来干净、但溯源链断裂”的条目；一旦下游要发布模型卡或做商用授权审查，这批条目无法证明其许可来源，只能整批剔除。变体一的扣分点因此落在两处：只答“多来源抓取”而不谈许可分层，扣来源分的下半；把许可过滤说成“抓完统一洗一遍”，扣风险分的机制部分。

教学上，这个变体适合让读者画一张两列对照表：左列写“若先过滤后去重会丢掉什么”，右列写“若先去重后过滤会隐式决定什么”。能填满两列，说明读者理解了顺序即策略，而不是把清洗当成无差别的水洗。

二 · 变体二：把“规模”换成“分布偏移下的评测”

变体二问：“1000 万+ 的规模上去后，为什么‘数据多但分布偏’会让评测虚高？请给出一个可操作的评测分层方案。”参考答案只点出“评测虚高”这一风险，变体二要求把它拆成可检验的机制。核心机制是：评测集的类别分布若与训练集的长尾分布同源，模型在头部类别上的提升会被平均指标放大，而长尾类别的退化被稀释。设评测集有 K 个类别，第 k 类样本数为 n_k，模型在第 k 类的成功率为 p_k，则平均指标为

$$\bar{p}=\sum_{k=1}^{K}\frac{n_k}{N}p_k,\quad N=\sum_{k=1}^{K}n_k$$

当 n_k 高度集中于少数头部类别时，$\bar{p}$ 对头部 p_k 敏感、对长尾 p_k 几乎不敏感。规模扩大若只是把头部类别从百万级推到千万级，$\bar{p}$ 会稳步上升，但长尾类别的绝对样本数可能没有变化，模型在长尾上的真实能力被平均指标掩盖。这就是“虚高”的算术来源，不需要任何实验数字就能说清。

可操作的分层方案是：按类别频次分桶（头部/中部/长尾），每个桶单独报告指标，并额外报告桶间指标的极差；同时报告“有效类别数”，即按样本数加权的类别熵的指数，用来衡量评测集本身的分布集中度。系统代价是评测成本随桶数上升，且长尾桶的样本太少导致置信区间宽，必须报告区间而不是点估计。失败模式是：只报总体平均，评审看到数字涨了就放行，部署到长尾场景才发现退化。

具体例子：一个以家具为主的 3D 资产集，头部类别是椅子与桌子，长尾是乐器与医疗器械。规模翻倍若主要来自椅子，总体生成质量指标会明显改善，但乐器类别的拓扑错误率不变。变体二的扣分点是：只重复“分布偏”三个字而不给出分层机制，扣风险分；把评测虚高归因于“模型过拟合”而非“评测集分布与训练集同源”，属于归因错误，同样扣分。

三 · 变体三：把“警惕什么”换成“质量分级如何进入训练回路”

变体三问：“去重与许可之后，质量分级应以什么信号为依据，分级结果如何反过来影响数据 scaling 的边际收益？”这题把风险从“有什么风险”推进到“风险如何被工程化地定价”。机制上，质量分级至少需要三路信号：几何完整性（是否水密、是否有非流形边）、拓扑合理性（面数与语义复杂度的匹配）、以及元数据一致性（标题、标签与几何内容是否对齐）。三路信号加权成一个分级分数，伪代码思路是：对每个资产计算 s = w1·水密 + w2·拓扑匹配 + w3·元数据一致，按分位数切成 A/B/C 三档，A 档进主训练集，B 档进混合集并降采样，C 档只做负样本或直接丢弃。

分级进入训练回路的代价是：分级本身要跑几何检查，水密性检测与拓扑分析的计算量随面数上升，对千万级资产做全量分级在工程上不可行，必须先用轻量代理信号（如面数分布、文件大小、元数据完整度）做粗筛，再对候选做精确检查。失败模式是分级信号与生成目标错配：若把“面数低”一律判为低质，就会系统性丢弃风格化低模资产，导致生成模型在低模风格上退化；若把“元数据完整”当作高质量代理，就会偏向来源规范的大厂资产，进一步加剧分布偏移。

具体例子：Thingiverse 上的大量打印用模型水密性好但面数高，Sketchfab 上的展示模型面数低但常有非流形边。同一分级阈值套在两个来源上，会把前者判为 A、后者判为 C，训练集因此偏向高面数打印件，生成结果的网格密度整体上移。变体三的扣分点：只列分级维度而不谈分级结果如何改变采样权重，扣机制分；把质量分级说成“人工抽检”而不提代理信号与全量检查的成本权衡，扣工程判断分。

四 · 五个追问：从定义到边界

追问一：“1000 万+ 是去重前还是去重后的口径？”这是口径追问，答“抓取原始条目”与答“去重后入库条目”是两个不同的规模声明，混用会让规模比较失去意义。正确答法是明确口径并说明去重率对口径的影响，扣分点是含糊其辞。

追问二：“格式转换会不会引入新的低质资产？”会。三角化、法线重算、单位归一化都会改变几何，转换失败产生的破面资产若不做校验就入库，等于把转换器的缺陷写进训练集。答法应包含转换后校验与失败隔离。

追问三：“元数据对齐对齐到什么粒度？”至少对齐到类别标签、许可标签、来源 URL 三元组；更细的语义标签对齐成本高，且跨源标签体系不一致，需要映射表。答“对齐标题”属于粒度过粗。

追问四：“长尾类别要不要主动补采？”要，但补采会引入新的许可与质量问题，补采的边际收益随类别稀缺度上升而下降，需要按类别频次设定补采预算。只答“要补”而不谈预算与风险，扣分。

追问五：“规模上去后，评测集要不要同步扩？”要，且评测集的类别分布应独立于训练集采样，否则分层评测失去意义。答“评测集越大越好”而不谈分布独立性，属于未命中机制。

五个追问的共同扣分逻辑是：凡把“规模”当作单一标量回答的，都在口径、分布、质量三个维度上失分；凡能区分“抓取规模、入库规模、有效训练规模”三个口径的，机制分即稳。

五 · 扣分点与常见错误的对应表

下表把评分标准的两个维度拆到具体表述上，便于对照扣分。来源维度占 40%，风险维度占 60%，因此风险表述的缺失比来源列举的遗漏更致命。

表述命中失分归因
列举 GitHub、Thingiverse、Sketchfab来源分—必要不充分
只写“多个来源抓取”—来源分下半无具体来源
写出去重、格式转换、许可过滤、元数据对齐来源分—清洗链路完整
写“1000 万+”但不标口径部分规模分口径混淆
只答“规模等于质量”—风险分大半忽略低质与重复
只答“注意版权”部分风险分未覆盖长尾与分布偏
把评测虚高归因于过拟合—风险分归因错误

常见错误里最隐蔽的一条是“以为去重不重要”：重复资产会让训练集的有效多样性低于名义规模，模型在重复样本上过拟合，评测指标却因重复样本在评测集中同样出现而虚高。这条错误同时踩中规模口径与评测虚高两个扣分点，是失分最重的单句。另一条是“忽略许可”，它不会直接降低生成质量，但会让整个数据集在发布环节不可用，属于延迟爆炸型错误。

教学建议是让读者做“一句话改写”练习：把“规模等于质量”改写成包含口径、清洗、分级三个要素的句子，改不出来就说明机制没吃透。评分演练时应要求读者在答案里显式标出“抓取规模/入库规模/有效训练规模”三个词，缺一个即视为口径不清。

六 · 教学落点：把风险写成可检验的断言

教学上最有效的一步，是把“最需要警惕什么”从形容词改成可检验的断言。例如把“许可混杂”改写成“同一去重簇内存在不可比较的许可组合时，该簇不得进入训练集”；把“低质资产”改写成“分级 C 档占比超过阈值时，触发来源级降采样”；把“分布偏”改写成“评测集头部类别样本占比与训练集头部占比之差超过阈值时，评测报告必须分桶”。每条断言都绑定一个可观测的量和一个动作，读者写不出动作，就说明只记住了风险名词而没有掌握定价机制。

这一落点与原题的关系是：原题的风险清单是名词级的，工程判断要求把它降到动作级。规模到 1000 万+ 之后，真正决定训练价值的不再是抓取总量，而是去重簇的许可裁决、分级信号的采样权重、以及评测分桶的独立性这三条回路能否闭合。任何一条回路缺失，规模越大，虚高越严重。
