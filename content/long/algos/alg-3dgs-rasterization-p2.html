一 · 光栅化的复杂度账本：每像素要碰多少高斯

3D 高斯泼溅的渲染开销不能只用“高斯总数”来估算，真正决定帧时间的是每个像素的混合循环长度。设屏幕分辨率为 \(W\times H\)，场景高斯总数为 \(N\)，第 \(k\) 个像素覆盖到的高斯数为 \(n_k\)，则一次前向渲染的混合运算量近似为 \(\sum_{k=1}^{WH} n_k\)。这个量既不是 \(N\)，也不是 \(WH\)，而是两者的“交叠面积”度量。工程上把它拆成两个可测指标：屏幕空间总覆盖次数（overdraw）和每像素平均混合长度 \(\bar n = \frac{1}{WH}\sum_k n_k\)。

具体机制上，每个高斯投影后的 2D 椭圆由中心、两个主轴半径决定，光栅化器只需在椭圆包围盒内枚举像素，对每个像素计算高斯权重并累加。因此单个高斯贡献的像素数正比于其屏幕面积 \(A_i\)，总覆盖次数为 \(\sum_i A_i\)。当高斯在近处、投影面积大时，单个高斯就能覆盖数万像素；当高斯远离相机时，面积退化到亚像素，覆盖次数趋近于 1，但仍要参与排序和混合。这就是为什么“高斯数翻倍”不等于“帧时间翻倍”：面积分布才是主导项。

$$\text{cost}_{\text{blend}} \approx \sum_{i=1}^{N} A_i \;=\; WH\cdot \bar n,\qquad A_i \propto \frac{\lvert \Sigma'_i\rvert^{1/2}}{z_i^2}$$

失败模式很具体：当场景中存在大量贴近相机的大高斯（例如前景植被、近景墙面），overdraw 会急剧上升，帧率从 100+ FPS 掉到几十 FPS，而高斯总数并没有明显变化。系统代价体现在带宽而非算力：每个被覆盖的像素都要读取该高斯的不透明度、球谐颜色系数和深度，混合是读-改-写，显存带宽成为瓶颈。调参时不能只看 \(N\)，要在 profiler 里看每像素平均混合长度和总覆盖次数，前者高说明排序后仍有大量交叠，后者高说明高斯屏幕面积过大。

一个具体例子：同一场景在 1080p 下渲染，若把高斯按屏幕面积从大到小排序观察，前 1% 的大高斯往往贡献了过半的覆盖次数。工程判断是：致密化阶段要抑制“过大高斯”的生成，剪枝阶段要优先剔除屏幕面积长期偏大的高斯，而不是只按不透明度阈值删。

二 · 显存与通信：显式表示的真实代价

显式表示把场景存成一组高斯参数，每个高斯至少包含位置（3 个 float）、协方差（可用四元数 + 三轴缩放，7 个 float）、不透明度（1 个 float）、球谐颜色系数（按阶数，常见 3 阶为 48 个 float）。粗算单个高斯约 60 个 float，即 240 字节量级；百万级高斯就是数百 MB 量级，千万级则进入 GB 量级。显存随高斯数线性增长，这是与 NeRF 的 MLP 隐式表示最直接的工程差别：NeRF 的显存基本与场景复杂度解耦，而 3DGS 的显存直接绑定基元数量。

训练时的显存峰值还要叠加中间量：投影后的 2D 协方差、排序键、每个像素的混合前缀积、以及反向传播时保存的前向激活。可微光栅化的反向需要重放前向的混合顺序，因此排序结果和每像素的高斯索引列表必须保留，这部分是训练显存的主要增量。系统代价表现为：显存不足时最先崩的不是参数存储，而是排序索引和像素级中间缓冲。工程上常见的做法是分块渲染（tile-based），把屏幕切成小块，每块只加载覆盖该块的高斯子集，用共享内存做局部排序与混合，从而把像素级缓冲限制在块内。

$$\text{mem}_{\text{train}} \approx N\cdot s_{\text{gauss}} + WH\cdot \bar n \cdot s_{\text{inter}} + N\cdot s_{\text{sort}}$$

通信代价在多 GPU 训练时更突出。3DGS 的致密化是数据依赖的：哪些高斯需要分裂、哪些需要剪枝，取决于梯度幅值和投影后的尺度，这些统计量分散在各 GPU 上。若不做全局同步，各卡会独立增删高斯，导致高斯集合不一致，下一轮前向就无法对齐。因此每轮致密化后需要一次全局规约或参数广播，把新增/删除的高斯同步到所有卡。这个同步点的频率不能太高，否则通信开销压过计算；也不能太低，否则各卡的高斯集合漂移过大，负载严重不均衡。

失败模式：多卡训练时若按高斯数量均分，会出现“高斯数相同但屏幕面积差异巨大”的负载倾斜，某些卡因 overdraw 高而成为长尾。具体例子：一个室内场景，前景桌面的高斯在相机附近投影面积大，背景墙面的高斯面积小，按数量均分会让持有前景高斯的卡拖慢整个迭代。工程判断是：分片依据应是“预计覆盖次数”而非高斯计数，且致密化同步要放在迭代边界而非混合循环内部。

三 · 伪代码思路：从投影到混合的四段流水

把光栅化拆成四段可独立优化的流水：投影、剔除、排序、混合。投影段对每个高斯计算屏幕中心、2D 协方差 \(\Sigma'=JW\Sigma W^{\top}J^{\top}\)、以及包围盒；剔除段丢弃包围盒与视锥或屏幕不相交的高斯；排序段按深度键对覆盖同一 tile 的高斯排序；混合段逐像素从前到后累加颜色并维护透射率。伪代码思路如下（用文字描述控制流，不写代码块）：

  • 对每个高斯：由世界坐标经视图投影得到屏幕均值；用雅可比 \(J\) 与视图矩阵 \(W\) 变换协方差；由 2D 协方差的两个特征值确定椭圆主轴，得到包围盒与 tile 列表。
  • 对每个 tile：收集所有包围盒覆盖该 tile 的高斯索引，按深度键排序；若高斯数超过 tile 容量，按不透明度或深度截断。
  • 对 tile 内每个像素：沿排序列表从前到后，读取高斯在该像素的权重 \(g_i\)，乘以不透明度得到 \(\alpha_i\)，累加 \(\mathbf{c}_i\alpha_i\prod_{j
  • 反向：按前向记录的顺序反向遍历，逐项回传颜色、不透明度、协方差与均值的梯度。

关键机制在于“提前终止”与“tile 容量截断”是两个不同的工程杠杆。提前终止按透射率阈值控制每像素实际混合长度，直接降低带宽；tile 容量截断按每 tile 的高斯数上限控制排序与索引存储，直接降低显存和排序时间。两者都会引入近似误差：前者在透射率未真正归零时停止，后者丢弃了排序靠后的低贡献高斯。系统代价是误差随视角变化而不均匀，近景大高斯密集的区域误差更明显。

失败模式：排序键若只用高斯中心深度，会在高斯尺度远大于深度间隔时产生错误的遮挡顺序，表现为边缘闪烁或半透明物体前后关系跳变。具体例子：两片薄墙前后相距很近，各自的高斯尺度与间距相当，中心深度排序无法稳定区分，混合结果随相机微动而抖动。工程判断是：排序键应结合深度与高斯在屏幕上的覆盖范围，或在 tile 内对深度相近的高斯做二次细分。

四 · 工程坑：透明、反射与稀疏视图的过拟合

3DGS 的混合模型本质是“有序 alpha 合成”，它假设每个高斯是一个不透明的局部片元，按深度从前到后累积。这个假设对漫反射表面成立，但对透明和反射失效。透明物体需要沿视线多次穿越同一表面，而光栅化只保留一个深度序；反射需要视角相关的颜色，球谐颜色能表达低频视角变化，但无法表达镜面高光随视角的剧烈跳变。系统代价是：为了拟合这些效果，优化器会生成大量细小高斯堆叠在表面附近，导致高斯数膨胀、overdraw 上升，帧时间变差，而视觉误差仍然存在。

具体机制上，球谐颜色的阶数决定了视角表达的频率上限。低阶球谐只能表达平滑的颜色变化，遇到镜面反射时，优化会把误差转嫁给几何：让高斯在表面法线方向分裂成多层，用不同深度的颜色叠加模拟视角变化。这解释了为什么反射场景的高斯数往往远高于漫反射场景。失败模式是“几何过拟合”：在稀疏视图下，优化器用少量视角的像素误差驱动致密化，生成的高斯只在训练视角下对齐，换视角后出现漂浮片元或空洞。

$$\mathcal{L}=(1-\lambda)\,\mathcal{L}_1+\lambda\,\mathcal{L}_{\text{D-SSIM}},\qquad \lambda\ \text{控制结构项与光度项的权衡}$$

稀疏视图下的过拟合有明确的工程信号：训练损失持续下降但验证视角的误差不降反升，同时高斯数在致密化阶段快速增长。原因是致密化判据只看梯度幅值，梯度大的区域被反复分裂，而稀疏视图无法约束这些分裂的自由度。系统代价是显存和渲染时间随过拟合同步增长。工程判断是：稀疏视图应降低致密化频率、提高剪枝的不透明度阈值，并在损失中加入对高斯尺度的正则，抑制“用大量小高斯拟合单视角”的退化解。

另一个坑是排序与混合对“半透明边缘”的处理。高斯在椭圆边缘的权重趋近于零，但仍有非零不透明度，多个高斯的边缘叠加会产生非预期的颜色偏移。具体例子：树叶边缘由多个高斯叠加，每个高斯的边缘权重很小但数量多，累积后透射率被过早耗尽，背景被错误遮挡。工程上通过提高透射率终止阈值、或在边缘像素降低高斯权重来缓解，代价是边缘出现轻微透光。

五 · 调参顺序：先控数量，再控面积，最后控精度

调参不能从学习率开始，而应从高斯集合的规模与分布开始，因为显存和帧时间由集合决定，精度只是集合之上的微调。推荐顺序是：第一步控制致密化与剪枝的节奏，把高斯总数压到显存预算内；第二步控制高斯的屏幕面积分布，抑制大高斯造成的 overdraw；第三步才调球谐阶数、不透明度阈值和损失权重。这个顺序的依据是：前两步决定系统能否稳定运行，第三步只影响视觉质量。

具体机制上，致密化判据通常基于投影后的梯度幅值与高斯尺度：梯度大且尺度小的区域需要分裂，尺度过大的高斯需要拆分或剪枝。调参时先固定致密化间隔，观察高斯数随迭代的增长曲线，若增长过快则提高梯度阈值或降低致密化频率；再观察每像素平均混合长度，若过高则对屏幕面积超过阈值的高斯做拆分，把大高斯变成多个小高斯以降低单像素覆盖，但要注意拆分本身会增加高斯数，需与剪枝联动。

调参对象直接影响的系统量过度调节的失败模式
致密化频率/梯度阈值高斯总数、显存过密导致显存溢出、帧时间抖动
大高斯拆分阈值每像素混合长度、overdraw拆分过多使高斯数反弹
不透明度剪枝阈值高斯总数、边缘质量过剪导致空洞与透光
透射率终止阈值混合循环长度、带宽过早终止导致背景缺失
球谐阶数单高斯存储、视角表达高阶增加显存但反射仍不完美

失败模式：把学习率调高以加快收敛，会同时放大梯度幅值，使致密化判据更容易触发，高斯数在早期爆炸，显存先于精度崩溃。具体例子：同一场景把位置学习率提高一个档位，致密化在前期生成大量冗余高斯，后期剪枝来不及删除，最终高斯数偏高而视觉误差并未改善。工程判断是：学习率与致密化阈值必须联合调节，先固定学习率再调阈值，或先固定阈值再微调学习率，不能两者同时大幅变动。

最后落在具体机制上：3DGS 的工程上限由“高斯集合的屏幕覆盖分布”决定，而不是由高斯总数单独决定。一个可执行的判断是，在目标分辨率下测量每像素平均混合长度与总覆盖次数，若前者高则拆分大高斯并提高终止阈值，若后者高则整体剪枝并降低致密化频率；只有当这两个量进入预算区间后，调球谐阶数和损失权重才有意义。显存、带宽与排序同步点构成系统约束，精度调参必须在这个约束内进行，否则任何视觉改进都会被帧时间和显存溢出抵消。
