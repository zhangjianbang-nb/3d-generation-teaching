一 · 从集合结构到序列：问题的形式化

三角网格在数学上是一个复合对象：顶点集合 V、面片集合 F、以及把面片绑定到顶点三元组的关联关系。它没有内禀的起点，也没有内禀的顺序。自回归 Transformer 的输入却必须是一个下标化的序列 t1, t2, …, tN，并且训练目标要求每个位置的条件分布只依赖它之前的位置。这两者之间的鸿沟不是工程细节，而是表示层面的不匹配：把集合强行摊平成序列，会引入任意性——同一个网格可以产生指数级数量的等价序列，模型必须把这些序列全部视为同一分布的不同样本，否则就是在学习遍历顺序的噪声而非几何本身。

更具体地，问题可以拆成三个子问题。第一是遍历问题：给定面片邻接图，如何选出一条覆盖所有面片的路径，使得相邻 token 之间的条件依赖尽可能强。第二是编码问题：每个面片携带的是连续坐标，而 Transformer 的词汇表是离散的，必须定义从 (顶点坐标, 邻接面索引) 到整数 token 的映射。第三是长度问题：序列长度随面片数线性增长，而自注意力的计算代价随长度平方增长，这直接决定了可处理的网格规模上限。

网格序列化 tokenization 的核心判断是：不要试图设计一个与顺序无关的集合编码器，而是主动构造一个确定的遍历，把遍历产生的顺序当作网格的一种“写法”，然后让语言模型去学这种写法下的条件分布。这与把图神经网络塞进自回归框架的路线形成对照：后者保留置换不变性但难以直接复用 token 级采样的简洁性；前者放弃不变性，换取与 decoder-only 架构的完全兼容。

二 · DFS 遍历：把邻接图展开成一条路径

选择深度优先而非广度优先，理由在于条件依赖的局部性。DFS 在访问一个面片后立刻深入它的一个未访问邻居，使得序列中相邻的 token 在网格上也是邻接的；BFS 则会把同一环上的面片排在一起，导致序列相邻但几何上可能隔着一条带。对于自回归建模，相邻 token 的强相关是最有价值的信号，因此 DFS 的“沿着曲面走”特性直接提高了每一步预测的可压缩性。

遍历的具体机制是：从任意一个面片出发（通常是索引最小或最靠近某个规范位置的面片），把它标记为已访问并写入序列；然后在其邻接表中按固定规则（例如按邻接面索引升序）选一个未访问邻居，递归深入；当当前面片没有未访问邻居时回溯，直到所有面片被覆盖。这个过程产生一棵以起始面片为根的生成树，序列就是这棵树的先序遍历。关键点在于：邻接表中“已访问”与“未访问”的区分必须在编码时记录下来，否则解码端无法重建遍历路径。

伪代码层面的思路是：

  • 维护一个栈 S 和一个访问标记数组 visited；
  • 将起始面片压栈，循环弹出栈顶面片 f，若未访问则标记、追加到序列，并将其未访问邻居按规则逆序压栈；
  • 对每个写入序列的面片，记录其三个顶点的量化坐标，以及它在生成树中的父面片索引（即 Ni 的核心内容）。

这里的系统代价出现在邻接表的规模上。一个面片最多有三个邻接面，但生成树只保留一条父边，另外两条邻接边在序列中表现为“回边”，即指向序列中更早位置的面片。回边必须被编码进 token，否则解码端无法恢复非树边，网格的拓扑就会退化成树状。回边的索引是相对于当前位置的偏移量，偏移量越大，词汇表中需要的索引范围越宽，量化越困难。对于长条状或高亏格的网格，回边偏移量分布弥散，这是序列长度之外的第二重压力。

一个具体例子：一个由两个环共享一条边构成的简单网格，DFS 从共享边的一个面片出发，会先绕完第一个环，回溯到共享边，再绕第二个环。序列中第二个环的第一个面片的父面片是共享边上的面片，而它的另一条邻接边指回第一个环中已经访问的面片，形成一条偏移量约为第一个环面片数的回边。若第一个环有几十个面片，这个偏移量就落在词汇表的中段，量化误差开始显现。

三 · 量化与 BPE：离散化的两级压缩

坐标量化是第一级离散化。顶点坐标是连续实数，必须映射到有限网格。设坐标范围为 [a, b]，量化位数为 k，则量化步长为 Δ = (b − a)/2k，量化值为 round((x − a)/Δ)。每个顶点三个坐标各占一个 token 槽位，一个面片三个顶点就是九个坐标 token，加上邻接索引 token，单个面片的原始 token 数在十个以上。这一步的失败模式是细节损失：薄壳结构、尖锐特征、以及坐标恰好落在量化边界上的顶点，会在 round 之后发生微小位移，导致面片翻转或自交。量化误差不会在训练中被模型“学会补偿”，因为它是确定性的信息丢失，模型只能学到在误差后的几何上做条件预测。

第二级压缩是 BPE。原始序列中大量模式重复：规则网格的局部连接方式、平面区域的坐标增量、以及常见的回边偏移组合，都会以固定子串形式反复出现。BPE 从字符级词汇表开始，迭代合并频率最高的相邻 token 对，把常见模式折叠成单个 token。这直接缩短了序列长度，把自注意力的平方代价压下来，同时让模型在更长的上下文窗口内看到更多的面片。BPE 的合并表是在训练集上统计得到的，因此它隐含了数据分布的偏置：在规则网格上高频的模式，在扫描重建的噪声网格上可能并不高频，压缩率会下降。

这里存在一个容易被忽略的耦合：量化步长决定了坐标 token 的字母表大小，而字母表大小又影响 BPE 的合并效率。步长过细，坐标 token 种类多、重复模式少，BPE 难以形成长合并；步长过粗，重复模式多、压缩率高，但几何细节损失加剧。这个权衡没有解析最优解，只能由目标网格的尺度分布经验性地确定。工程判断是：宁可让 BPE 压缩率低一些，也要保证量化步长小于目标应用中最薄特征的厚度，否则拓扑正确性无从谈起。

四 · 与相邻算法的数学差别

与把网格当作像素化体素或多视图投影的方法相比，网格序列化的差别在于表示的原生性。体素化把曲面嵌入规则三维栅格，代价是分辨率与内存的三次方关系，且丢失了面片连接关系；多视图投影把三维对象降维成二维图像序列，代价是视角覆盖的完备性问题，背面与遮挡区域只能靠模型推断。网格序列化不引入外部栅格，直接在面片邻接图上定义顺序，因此拓扑信息是显式保留的，代价是序列长度与面片数成正比而非与包围盒分辨率成正比。

与图神经网络式的网格生成相比，差别在于条件分解的结构。图模型通常做置换不变的消息传递，输出是节点或面片级别的联合分布，采样需要额外的顺序化步骤；网格序列化则把顺序写进表示本身，条件分布天然是链式的，采样就是逐 token 解码。数学上，前者建模的是 p(M) 的一个置换不变近似，后者建模的是 p(π(M))，其中 π 是确定的遍历。两者优化的目标函数不同：前者对遍历顺序边缘化，后者对单一顺序做极大似然。这解释了为什么网格序列化能生成“较干净”的拓扑——它不需要在多个等价顺序之间做平均，从而避免了平均导致的拓扑模糊。

与同样基于自回归的序列化方法（例如按顶点索引顺序排列顶点坐标）相比，差别在于邻接信息的显式编码。纯顶点序列只给出坐标，面片连接必须由模型隐式推断，这在局部平坦区域可行，但在拓扑复杂处会产生非流形连接。网格序列化把每个面片的邻接面索引写进 token，等于把一部分拓扑作为条件直接喂给模型，降低了推断负担，代价是 token 数增加和回边偏移的量化问题。

从信息论角度看，三种路线的差别可以写成对 p(M) 的不同分解。网格序列化选择了一个确定的、依赖邻接的分解顺序，其似然下界受遍历顺序质量影响：若 DFS 在某个分支上产生长回边，该位置的条件熵就高，序列的可压缩性下降。这不是算法缺陷，而是把“顺序选择”这一自由度从模型转移到了预处理脚本，从而让模型只承担条件分布的建模。工程含义是：遍历脚本的确定性必须与训练、推理严格一致，任何邻接表排序规则的变动都会改变序列分布，使已训练模型失效。

五 · 序列长度与生成可行性

长度问题是这条路线最硬的约束。序列长度 N 约等于面片数乘以每面片 token 数再除以 BPE 压缩率。自注意力的计算量随 N2 增长，而自回归采样需要 N 步前向，每步都要维护键值缓存。因此，长网格的生成不是“慢一点”的问题，而是显存与时间预算直接越界。BPE 压缩率在这里起到杠杆作用：压缩率提高一倍，注意力代价降到四分之一。但压缩率受量化步长与网格规则性制约，不能任意提高。

另一个失败模式是误差累积。自回归采样在每一步都从条件分布中取一个 token，早期面片的量化误差或拓扑错误会作为后续步骤的条件被固化。DFS 的顺序放大了这一点：一个分支上的错误会沿着生成树传播到整个子树，因为子面片的父索引指向错误的面片。这与图像自回归中像素错误局部扩散不同，网格的邻接约束使错误具有结构性。缓解手段是在训练时加入 teacher forcing 的噪声扰动，但推理时的暴露偏差仍然存在。

可扩展性方面，部件级生成是这条路线的一个自然延伸：把网格分解为部件，每个部件单独序列化，再用一个高层序列描述部件之间的连接。这把长度问题从单个长序列转移到多个短序列加一个短高层序列，代价是部件分解本身需要额外的分割步骤，且部件间的邻接 token 需要跨序列引用，词汇表设计变得更复杂。工程判断是：在面片数超过某个阈值时，单序列路线的采样成本已经不可接受，部件级分解不是可选项而是必需项；而在阈值以下，单序列的拓扑一致性更好，不应过早引入分解。

最后落在机制上：网格序列化的可行性边界由三个量共同决定——量化步长决定的几何保真度、BPE 压缩率决定的序列长度、以及 DFS 回边偏移分布决定的邻接编码精度。这三个量不是独立的：细化量化会降低压缩率，压缩率下降会拉长序列，序列变长会迫使模型依赖更远的上下文，而更远的上下文又要求回边偏移被更精确地编码。任何一项的调整都会通过这条耦合链传导到其他两项，因此该算法的参数配置本质上是一个受约束的联合优化，而非逐项调参。
