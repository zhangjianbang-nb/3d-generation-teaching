一 · 与“顶点色直出”和“三平面纹理”的逐项对比

把 UV 展开 + PBR 材质分解放到相邻算法的坐标系里，第一个要对比的是“顶点色直出”。顶点色直出的机制是：生成模型在网格顶点上回归 RGB，渲染时由光栅化插值得到表面颜色。它没有 UV 参数化这一步，因此不存在接缝、拉伸、重叠这些展开失败模式；代价是颜色分辨率被网格分辨率锁死。一个十万顶点、平均边长 2 毫米的网格，顶点色能表达的最高细节尺度就是 2 毫米量级，再细的纹理细节只能靠插值“糊”出来。更关键的是，顶点色只承载基色，粗糙度、金属度要么另开顶点属性通道，要么干脆丢失，引擎侧无法做基于物理的着色。UV + PBR 分解把颜色搬进 2K/4K 的 UV 空间，分辨率与网格解耦，同时输出反照率、粗糙度、金属度三张图，这是顶点色直出在结构上做不到的。

第二个对比对象是三平面纹理（triplanar）。三平面纹理的机制是：不做 UV 展开，沿 X/Y/Z 三个轴向分别采样一张纹理，按法线权重混合。它的优点是零展开失败、天然无缝、对任意拓扑鲁棒；缺点是三张纹理常驻显存、采样三次并做权重混合，着色器开销约为单次 UV 采样的三倍量级，且斜面上的投影拉伸无法消除，细节在 45° 面上会被拉长。UV + PBR 分解则把这份运行时开销换成了离线的一次性展开与反投影：引擎侧只做标准 UV 采样，开销回到基线，但代价是展开阶段可能失败。换句话说，三平面把风险放在运行时（性能与拉伸），UV 展开把风险放在资产管线（展开成功率）。

第三个对比对象是“隐式材质场 + 神经渲染”。这类方法把材质存成网络权重或体素场，渲染时在线求值，天然不需要 UV，但无法导出成引擎认识的贴图组，导出即需要一次烘焙，而烘焙过程本质上又回到了 UV 展开或三平面投影。UV + PBR 分解的价值就在于它把“导出”这件事做成了算法的一部分，而不是后处理补丁。三者的数学差别在前文已推导，这里只强调选型含义：如果你的下游是实时引擎且需要重光照，UV + PBR 是唯一能直接交付贴图组的路线；如果下游是离线渲染或研究可视化，隐式场更省事。

二 · 失效条件：UV 展开为什么会失败

UV 展开失败不是偶发噪声，它有明确的几何触发条件。第一种是亏格大于零的拓扑：网格带把手、穿孔、内部空腔时，展开算法必须切足够多的缝才能把曲面摊平，缝的数量与亏格成正比。切缝过多会导致 UV 岛数量爆炸，岛与岛之间的接缝在反投影时出现颜色不连续，材质扩散模型被迫在接缝两侧“猜”连续性，补全结果在缝附近出现色带。第二种是高曲率细长结构：发丝、枝条、尖刺这类几何，展开后单个 UV 岛的拉伸率极高，反投影到 UV 空间时一个像素对应表面上一大片区域，反照率被平均掉，细节丢失。拉伸率可以用面积畸变度量：设三维面片面积为 $A_{3d}$、其在 UV 空间的对应面积为 $A_{uv}$，畸变比为 $A_{uv}/A_{3d}$，该比值偏离 1 越远，反投影的信息损失越大。

$$\text{distortion}(f)=\max\left(\frac{A_{uv}(f)}{A_{3d}(f)},\ \frac{A_{3d}(f)}{A_{uv}(f)}\right)$$

第三种是自交与重叠：展开算法把两个不相邻的面片映射到 UV 空间的同一区域，反投影时两个面片的颜色写进同一批像素，后写的覆盖先写的，材质扩散模型看到的是混合后的错误颜色，补全结果对两个面片都不正确。重叠检测需要在展开后做一遍 UV 空间的面片相交测试，代价是 $O(n\log n)$ 量级的扫描线或 BVH 查询，对百万面片网格是秒级开销，工程上常被跳过，于是重叠成为最隐蔽的失效模式。第四种是尺度极端不均：一个模型上既有大平面又有微小的倒角，统一展开参数会让小特征挤在几个像素里，反投影采样不足，材质扩散补全只能给出先验均值，表现为倒角处粗糙度“糊成一片”。

具体例子：一个带内部空腔的机械零件网格，亏格为 3，展开后产生数十个 UV 岛，接缝总长度占表面积的比例显著上升；反投影阶段每个岛边缘的颜色来自不同视角，光照解耦训练时这些边缘像素的输入光照方向不一致，解耦网络在缝附近输出振荡的反照率，最终贴图在引擎里表现为沿缝的暗线。这不是扩散模型的能力问题，而是输入几何本身不满足“可展”假设。工程判断是：展开前先做拓扑检查，亏格大于零且无法通过填孔简化的资产，直接退回三平面或顶点色路线，不要在展开上硬扛。

三 · 材质补全的失效：先验依赖与光照解耦不彻底

材质扩散补全的机制是：把反投影得到的稀疏、带噪声的 UV 观测作为条件，用扩散模型在 UV 空间生成完整的反照率、粗糙度、金属度。它的失效根源是“观测不足处全靠先验”。反投影的覆盖率取决于多视图渲染的视角数量与遮挡关系：凹槽、内壁、被遮挡区域在多数视角下不可见，UV 上对应像素没有观测，扩散模型只能从邻域和训练分布里外推。外推在统计上合理，在具体资产上可能完全错误——一个从未被观测到的凹槽，模型可能补成光滑金属，而实际应是粗糙的氧化表面。这种错误无法通过增加采样步数修正，因为条件信息本身缺失。

光照解耦不彻底是第二个失效源。解耦训练的目标是把观测颜色分解为反照率与光照的乘积，但单张图像的反照率-光照分解是欠定的：同一个像素颜色可以由“亮反照率 + 暗光照”或“暗反照率 + 亮光照”解释。多视图提供了额外约束，但约束强度取决于视角覆盖与光照变化。如果多视图渲染使用同一套环境光照，解耦网络学到的只是“把这套光照除掉”，换一套光照后残留的光照成分就会以烘焙阴影的形式留在反照率贴图里。公式上，解耦损失若只约束重建颜色，网络会倾向于把光照信息编码进反照率通道以降低重建误差：

$$\mathcal{L}_{\mathrm{dec}}=\left\|\mathbf{c}_v-\hat{\mathbf{a}}_v\odot L(\mathbf{n}_v)\right\|^2+\lambda\left\|\hat{\mathbf{a}}_v-\mathbf{a}_v\right\|^2$$

当 $\lambda$ 偏小，第二项对反照率的监督不足，网络把 $L$ 的成分塞进 $\hat{\mathbf{a}}$，重建项仍然很小，训练损失看不出问题，但导出的反照率贴图带有方向性明暗，重光照时出现“双重光照”。这是典型的系统代价：离线指标漂亮，运行时换光照就露馅。工程上的调参顺序是先固定光照多样性（多套环境光、多方向主光），再调 $\lambda$，最后才调扩散补全的采样参数；顺序颠倒会让补全模型去拟合一个本身就没解耦干净的反照率。

具体例子：一个角色头部的生成网格，耳朵后方与颈后区域在正面、侧面视角中均不可见，反投影覆盖率低；扩散补全把这些区域补成与可见皮肤一致的反照率，粗糙度取训练分布的均值。导出到引擎后，换一束侧逆光，颈后区域出现明显的高光断层，因为补全的粗糙度与实际几何的法线分布不匹配。修复只能靠补采视角或手工修贴图，算法层面无解。这说明材质补全的能力边界由观测覆盖率决定，而不是由扩散模型的参数量决定。

四 · 选型建议：按下游约束排序

选型不应按“算法新旧”排，而应按下游的三个硬约束排：是否需要重光照、是否实时渲染、资产管线能否承担离线展开。第一个约束是重光照。需要重光照的场景（游戏、交互式预览、AR）必须拿到反照率与粗糙度、金属度分离的贴图组，顶点色直出和未解耦的隐式场都不满足，UV + PBR 分解是默认选项。第二个约束是实时渲染。实时渲染要求运行时采样开销可控，三平面纹理的三次采样在移动端是实打实的带宽代价，UV 展开把这份代价移到离线，运行时回到单次采样，因此实时场景优先 UV 路线，除非展开失败率不可接受。

第三个约束是资产管线的离线预算。UV 展开 + 多视图反投影 + 扩散补全 + 解耦训练是一条串行流水线，每一段都有失败可能，整条流水线的成功率是各段成功率的乘积。若展开成功率、反投影覆盖率、补全可接受率各自都不是 1，串联后整体良品率会明显下降。工程判断是：对批量资产生成，先跑展开与重叠检测做筛选，把拓扑不合格的资产分流到三平面烘焙；对单件高价值资产，允许人工介入修 UV 与补视角。不要试图用更大的扩散模型去救展开失败的资产，那是把几何问题误当成生成问题。

还有一个常被忽略的选型维度是“可编辑性”。UV + PBR 输出的是标准贴图组，美术可以在 Substance 一类工具里直接修改反照率与粗糙度，修改结果与算法输出同构；隐式场与顶点色的可编辑性差得多。若资产进入后续手工打磨环节，UV 路线的总拥有成本更低，因为算法输出落在美术熟悉的表示上。这一点在批量管线里不显眼，在单件精修里往往是决定性的。

五 · 三道练习

练习一（畸变诊断）：给定一个展开后的网格，每个面片有三维面积 $A_{3d}$ 与 UV 面积 $A_{uv}$。要求写出计算全局畸变分布的伪代码思路，并指出在什么畸变阈值下应判定该资产不适合反投影。提示：先按面片计算畸变比，再统计高分位（而非均值），因为少数极端面片决定了反投影的信息损失上限；判定阈值应结合目标纹理分辨率——若一个面片在 UV 上覆盖的像素数少于其三维细节尺度所需，即判不合格。这道练习的目的是把“展开失败”从定性感受变成可计算的筛选条件。

练习二（覆盖率与补全边界）：给定一组多视图渲染的相机位姿与网格，要求设计一个统计 UV 空间反投影覆盖率的流程，并标出覆盖率低于某比例的 UV 区域。进一步要求：对这些低覆盖区域，比较“扩散补全”与“从邻域插值”两种策略的适用条件，说明为什么在低覆盖且邻域材质不连续时，扩散补全的先验外推可能比简单插值更糟。这道练习对应第二、三节的失效机制，目的是让读者亲手划出补全模型的能力边界。

练习三（解耦验证）：给定解耦训练后的反照率贴图与一组新的环境光照，要求设计一个重光照验证流程：用导出的 PBR 贴图组在新光照下重新渲染，与“原光照渲染结果除以原光照再乘新光照”的参考结果对比，定位残留光照成分。要求写出对比所用的误差度量，并说明当误差在接缝附近集中时，应优先怀疑展开接缝而非解耦网络。这道练习把第三节的“双重光照”失效变成可复现的检测手段，也是上线前最值得自动化的一步。

三道练习的共同指向是：UV + PBR 分解的可靠性不取决于扩散模型的规模，而取决于几何可展性、观测覆盖率、解耦监督强度这三个前置条件。工程上应把这三项做成流水线前的硬门槛与流水线后的自动验收，而不是寄希望于模型在失败输入上“猜对”。当展开畸变高分位超阈值、覆盖率低于补全可信区间、重光照误差在接缝处聚集时，正确的动作是分流资产或补采数据，而不是调大模型。
