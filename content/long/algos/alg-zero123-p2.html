一 · 计算图与复杂度：一次去噪采样到底在算什么

把 Zero-1-to-3 当成一个系统看，它的推理过程不是“一次前向”，而是“条件编码一次 + N 步去噪 + 多视角重复”。参考图 x 先经图像编码器（扩散模型自带的 VAE 编码或 CLIP 类图像塔）得到一个条件张量，这个张量在整个采样循环里是常量，可以缓存；真正逐步骤重算的是 U-Net 主干。位姿条件 ΔR、ΔT 被展平后经一个小 MLP 映射成若干 token，通过 cross-attention 注入每个分辨率层，因此每个去噪步的注意力计算量比无条件图像扩散多出一份“条件侧”的 K/V 投影，但 Q 侧规模不变。

单步复杂度可以用标准 DiT/U-Net 的近似式描述。设主干在某一层的 token 数为 $N$，通道数为 $C$，条件 token 数为 $M$（由位姿嵌入长度决定，通常远小于 $N$），则自注意力与交叉注意力的主导项为：

$$\mathcal{C}_{\text{step}} \approx \sum_{l} \left(4N^2C + 4NMC\right),\qquad \mathcal{C}_{\text{total}} \approx S\cdot \mathcal{C}_{\text{step}} + V\cdot S\cdot \mathcal{C}_{\text{step}}$$

其中 $S$ 是采样步数，$V$ 是要生成的视角数量。注意第二项：多视角不是并行的免费午餐，每个视角都要独立跑一遍完整去噪链。这意味着系统的总算力随 $V$ 线性增长，而 $V$ 又直接决定重建质量——视角太少，背面覆盖不足；视角太多，成本失控。这是 Zero-1-to-3 在工程上最本质的取舍：它把“单图缺信息”的问题转化成了“用算力换视角覆盖”的问题。

一个具体例子：生成 4 个方位角、每视角 50 步、主干为常规 latent 扩散尺寸时，实际耗时大致是单张图生成的 4 倍量级，且这 4 次采样之间没有任何共享计算（除了条件编码）。如果工程上想省，唯一合法的共享是条件张量缓存和位姿嵌入的预计算，主干激活无法跨视角复用，因为每个视角的初始噪声与位姿条件都不同。

失败模式在这里很明确：把 $V$ 拉大但步数压低，会得到一批“各自看着还行、拼起来互相矛盾”的视角，重建阶段会把这些矛盾平均成糊状几何。复杂度预算必须同时约束 $V$ 与 $S$，不能只调一个。

二 · 显存与通信：条件注入的驻留成本

显存占用的主体是主干激活，而不是位姿嵌入。位姿 MLP 的输出 token 很小，cross-attention 的 K/V 缓存也小；真正吃显存的是 U-Net 各层的特征图与注意力矩阵。设批大小为 $B$、分辨率 token 数 $N$、层数 $L$、通道 $C$，粗略的激活驻留量为：

$$\mathcal{M}_{\text{act}} \approx B\cdot L\cdot N\cdot C\cdot b + B\cdot H\cdot N^2\cdot b$$

其中 $b$ 是每元素字节数，$H$ 是注意力头数。第二项是注意力的二次项，在较高分辨率层会迅速压过第一项。Zero-1-to-3 的位姿条件通过 cross-attention 注入，不改变 $N$，但会额外驻留条件 K/V，量级为 $B\cdot H\cdot M\cdot C\cdot b$，相对 $N^2$ 项可忽略。因此“加了位姿条件”本身不是显存杀手，杀手仍是分辨率与批大小。

工程上的直接后果：多视角生成不适合用大 batch 一次塞进去。若把 $V$ 个视角打成一批，激活按 $B=V$ 线性膨胀，注意力项按 $V\cdot N^2$ 膨胀，很容易撞上显存墙。更稳的做法是逐视角串行采样，把显存峰值压到单视角水平，用时间换空间；代价是 GPU 利用率下降，因为每步去噪的并行度只来自单张图的 token 维度。

通信方面，如果采用多卡数据并行逐视角分摊，每张卡独立跑自己的视角，几乎不需要通信——这是 Zero-1-to-3 推理的一个便利之处：视角之间在采样阶段是解耦的。但一旦进入重建阶段（NeRF 或网格优化），视角图像要被汇聚到同一进程做多视图一致性约束，此时才出现真正的通信与同步。伪代码思路如下：

  • 阶段 A（可并行）：每个 worker 持有参考图与自己的 ΔR、ΔT，独立执行 S 步去噪，输出目标视角图像，无跨卡通信。
  • 阶段 B（需汇聚）：收集全部 V 张图像与对应位姿，构建多视图监督，进入重建优化循环。
  • 阶段 C（可选）：若重建也分片，则每步需 all-reduce 辐射场参数或梯度，通信量随参数量线性增长。

失败模式：在阶段 A 用大批量追求吞吐，结果单卡显存不足被迫降分辨率，而分辨率下降直接损害位姿条件的有效性——低分辨率下相机位姿的细微差别在像素上几乎不可辨，模型倾向于忽略 ΔR、ΔT，退化成“生成一个大致合理的正面”。这是显存压力反向污染算法行为的典型链路。

三 · 伪代码思路：条件编码、注入与采样循环

把流程写成结构化伪代码，重点在“什么进循环、什么出循环”。参考图编码与位姿嵌入都在循环外算一次；去噪循环内只做主干前向、条件 cross-attention、噪声调度更新。示意如下（以文字描述代替代码块）：初始化潜变量为纯噪声；对每一步 t，将当前潜变量与时间步嵌入送入主干；在每一层的 cross-attention 中，以主干特征为 query，以“图像条件 token + 位姿 token”拼接后的序列为 key/value；得到噪声预测后按调度器更新潜变量；循环结束后经解码器得到像素图像。外层再套一个视角循环，遍历预设的 ΔR、ΔT 集合。

关键设计点是条件序列的拼接顺序与位置编码。图像 token 与位姿 token 若共用一套位置编码，位姿 token 的位置索引必须与图像 token 区分开，否则注意力会把位姿误当成图像块的空间邻居，导致位姿信号被空间先验淹没。工程上通常给位姿 token 单独的嵌入段，或在拼接后加一个类型标记。这个细节不改变公式，但直接决定位姿条件是否“真的被用上”。

采样循环里还有一个易被忽视的点：噪声调度与视角数量的耦合。若每个视角独立从同一分布采初始噪声，视角间的随机性完全独立，这正是“视角间一致性不足”的来源之一。伪代码层面可以做的一件事是共享部分初始噪声（例如低频分量共享、高频分量独立），但这属于对算法的改动而非原样实现，工程上要明确标注为“非原始配方”。

失败模式：把位姿嵌入错误地做成加性偏置（加到时间步嵌入上）而不是 cross-attention 的独立 token，会让位姿信息在深层被稀释，表现为“改变 ΔR 输出几乎不变”。诊断方法是固定参考图与噪声、只扫 ΔR，观察输出视角是否单调变化；若不变，说明注入路径断了。

具体例子：生成一圈 4 个视角时，若把 4 个视角的位姿 token 拼成一个大条件序列一次性注入，主干会同时“看到”四个目标位姿，输出会趋向于四个视角的平均而非某一个具体视角。正确做法是每次只注入当前视角的位姿，视角循环在外层。

四 · 工程坑：位姿约定、分辨率与一致性

第一个坑是位姿约定。公式 $\Delta R=R'R^{-1}$、$\Delta T=T'-T$ 里的 $R$、$T$ 是相机到世界还是世界到相机，旋转是主动还是被动，坐标系是右手还是左手，这些约定在训练数据渲染管线与推理输入之间必须完全一致。Objaverse 渲染出的多视图对自带一套约定，若推理时按另一套约定构造 ΔR，模型会收到一个“看起来合理但语义错位”的条件，输出视角朝向系统性偏移。这类错误不会报错，只会表现为“生成的背面总是偏左或偏上”。

第二个坑是分辨率与位姿可辨性。生成分辨率有限是已知不足，但工程含义更具体：在低分辨率下，相邻视角的像素差异很小，位姿条件提供的信息量相对于图像先验变小，模型倾向于用“物体大致长这样”的先验覆盖位姿信号。提高分辨率能缓解，但显存与算力代价按 token 数二次增长。折中做法是先低分辨率采样确定大体朝向，再对关键视角做高分辨率细化，但这会引入两次采样之间的分布不匹配。

第三个坑是视角间一致性。每个视角独立去噪，几何上互相矛盾的区域（例如同一块背面在两个视角里被生成成不同形状）在重建阶段会被多视图监督拉扯。系统代价是重建优化需要更多迭代才能收敛，且收敛到的几何是“折中解”而非真实解。工程上可加的约束包括：在采样阶段引入跨视角的注意力共享（改动较大），或在重建阶段加大不一致区域的惩罚权重（改动较小但可能过平滑）。

坑表现根因工程对策
位姿约定错位视角系统性偏移训练/推理坐标系不一致统一到渲染管线约定，做单变量扫描验证
低分辨率位姿信号被先验淹没像素差异小于先验强度提高分辨率或分级采样
视角不一致重建几何糊化各视角独立采样重建端加权或采样端共享噪声
位姿注入路径断改 ΔR 输出不变条件被加性稀释独立 token + 类型标记

具体例子：若参考图是正面，要生成正后方，ΔR 接近 180 度旋转。此时位姿条件与图像先验的冲突最大——图像先验强烈倾向生成“看得见的脸”，而位姿要求“看不见”。工程上这一档视角的失败率最高，表现为背面被生成成一张模糊的、带正面特征的图。这不是调参能根治的，而是单图条件的固有信息缺口。

五 · 调参顺序：先对齐语义，再压成本，最后修一致性

调参不能从步数或学习率开始，而要从“条件是否被正确消费”开始。第一步是语义对齐验证：固定参考图与初始噪声，只改变 ΔR（绕单一轴小角度递增），观察输出是否随之平滑变化；再固定 ΔR 改变参考图，观察输出是否跟随参考图内容。两个扫描都通过，才说明位姿与图像两条条件路径都活着。此步不涉及任何超参，只涉及约定与注入结构。

第二步是成本约束下的采样配置。在 $V$ 与 $S$ 之间做预算分配：先固定一个能覆盖背面所需的最小 $V$（按方位角均匀铺开），再把剩余预算给 $S$。判断依据是重建阶段的多视图覆盖度，而不是单张图的观感。单张图好看但视角覆盖有洞，重建一定失败；单张图略糙但覆盖均匀，重建反而稳。这是一个反直觉但工程上成立的排序。

第三步才是修一致性。可选手段按侵入性排序：重建端加权（不改生成）→ 采样端共享低频噪声（轻改生成）→ 跨视角注意力（重改生成）。每往右一步，系统复杂度与调试成本都上升一个量级，且重改生成会偏离原始配方，需重新验证语义对齐是否被破坏。

失败模式：跳过第一步直接调 $S$ 和引导强度，会把“位姿路径断了”误诊为“采样不足”，于是不断加步数，算力花光而输出依旧不随 ΔR 变化。诊断顺序错了，调参就是往错误方向堆资源。

具体例子：一圈 4 视角、每视角固定步数时，若发现正后方视角始终带正面特征，先查 ΔR 的旋转轴与角度约定是否与训练渲染一致，再查该视角的位姿 token 是否在 cross-attention 中被图像 token 压制（可看注意力权重分布）。两步都排除后，才考虑提高该视角的采样步数或单独加权。

六 · 系统边界：把生成器当先验模块而非成品

从系统架构看，Zero-1-to-3 的正确定位是“背面先验生成器”，不是“3D 重建器”。它的输出是一组带位姿的图像，这些图像的价值在于给重建模型提供训练信号与初始化，而不在于自身作为最终资产。因此系统设计要把生成与重建解耦：生成端只负责在给定位姿下产出合理图像，重建端负责把多视图矛盾消化成几何。解耦的好处是生成端可以独立替换、独立调参、独立做语义对齐验证；代价是两端的误差会叠加，生成端的位姿偏差会直接变成重建端的几何偏差。

系统代价的量化边界在于：生成端的算力随 $V\cdot S$ 线性增长，重建端的算力随多视图数量与迭代次数增长，两者相乘构成总预算。工程判断是——当 $V$ 已经覆盖全部方位且重建仍不收敛时，瓶颈在一致性而非覆盖度，此时加 $V$ 无效，应转向一致性约束；当重建几何有明显空洞时，瓶颈在覆盖度，此时加 $S$ 无效，应加 $V$。这个判断规则把调参从“凭观感”变成“看重建诊断”。

最后一个具体机制层面的落点：位姿条件的注入强度与图像条件的注入强度在 cross-attention 中共享同一套 softmax 归一化，两者的相对权重由 token 数量与嵌入尺度隐式决定。工程上若发现位姿信号弱，除了检查注入路径，还可以调整位姿 token 的数量（用更多 token 表达同一组 ΔR、ΔT）来提升其在注意力中的占比——这是不改公式、只改条件表示的自由度，也是系统层面最容易被忽视的一个可调旋钮。
