一 · 计算图与复杂度：一次前向到底在算什么

把 NeuS 的一次训练迭代拆开看，计算量并不集中在“渲染”这个动作上，而是分布在采样、MLP 求值、alpha 合成、梯度回传四段。射线从相机出发，先做粗采样得到一组候选点，再在粗采样给出的高权重区间做细采样（分层采样，hierarchical sampling），最终每条射线保留的点数记为 N。每个点都要过一遍 MLP：输出一个标量 SDF 值 f(x) 和一个颜色向量 c。于是单条射线的 MLP 前向次数是 N，一个 batch 若含 R 条射线，前向次数就是 R·N。这与 NeRF 的稠密采样同构，区别只在于网络头多了一个 SDF 分支以及 Eikonal 正则需要对空间梯度再求一次导。

Eikonal 项 ‖∇f‖=1 的代价常被低估。它不是对输出值求导，而是对输入坐标求导，需要在每个采样点上做一次反向传播来拿到 ∇f，再对这个梯度向量求范数并二次反传。也就是说，一个采样点在一次迭代里至少要经历两次自动微分链路，显存里要同时保留一阶图与二阶图的部分中间量。工程上这直接决定了 batch 大小：同样的显卡，纯 RGB 损失能开的射线数，加上 Eikonal 后往往要砍掉一截，否则在反向时爆显存。

alpha 合成本身是廉价的。给定相邻两点的累积分布函数值 Φ(si) 与 Φ(si+1)，离散 alpha 为

$$\alpha_i=\max\!\left(\frac{\Phi(s_{i+1})-\Phi(s_i)}{\Phi(s_{i+1})},0\right)$$

随后按从近到远的顺序做透明度累积 Ti=∏j<i(1−αj)，颜色为 ∑iTiαici。这一步是 O(N) 的标量运算，相对 MLP 求值可以忽略。真正的复杂度瓶颈是 R·N 次 MLP 前向加上同量级的二阶梯度，以及细采样阶段对粗采样权重的排序与区间划分。若把粗、细两级采样点数分别记为 Nc、Nf，则每条射线的有效求值点是两者之和，而梯度只对最终参与合成的点回传，粗采样点的梯度通常被丢弃——这是一处常见的实现取舍，也是显存与精度之间的直接交换。

失败模式在这里很具体：当场景包围盒很大而表面很薄时，均匀粗采样会大量落在空区，MLP 在这些点上输出的 SDF 远离零，Φ 接近饱和，alpha 贡献趋近于零，梯度信号也随之消失。表现为损失下降但表面不收敛，或收敛到一层“雾”。对策不是加大网络，而是把采样预算向零等值面附近倾斜，这也是后面调参顺序里第一条要动的东西。

二 · 显存与通信：单卡装不下时发生了什么

NeuS 的显存占用由四块构成：网络参数与优化器状态、激活值（用于反向）、Eikonal 的二阶图中间量、以及采样点坐标与颜色缓冲。参数量本身不大，一个几层、每层百余通道的 MLP 在百万参数级别，优化器若用 Adam 还要再乘三倍左右。真正吃显存的是激活：R·N 个点的每层输出都要留存到反向结束，且 Eikonal 分支让每个点多出一条梯度计算路径。实践中调 batch 的手段往往不是改射线数，而是改每条射线的采样点数，因为后者是线性放大激活的乘数。

多卡训练时，通信模式取决于并行策略。数据并行下每张卡持有完整网络副本，各自跑不同的射线子集，反向时对梯度做 all-reduce。由于网络小、梯度张量小，all-reduce 的通信量并不构成瓶颈；瓶颈反而在负载均衡——不同射线穿过的表面厚度不同，细采样点数在实现里可能是动态的，导致各卡每步耗时不一致，同步点上的等待被放大。若采用把大场景切块、按空间分区的并行方式，则要处理跨块射线的归属与边界采样，通信从梯度同步变成采样点坐标的交换，复杂度上升但单卡显存压力下降。

一个具体的系统代价例子：当把每条射线的细采样点数从较小值提高一档以捕捉薄结构时，激活显存近似线性增长，而每步时间也近似线性增长，但收敛所需的迭代数不一定下降。这意味着“加采样点”在墙钟时间上通常是净亏的，除非薄结构确实是当前损失的主要来源。工程判断是：先用较低采样点数把大体形状收敛，再针对残留的薄结构局部提高采样密度，而不是全局拉满。

另一个坑是数值精度。SDF 值在表面附近变化剧烈，Φ 的 logistic 变换对温度参数敏感，若用半精度跑前向，Φ 的饱和区会出现明显的量化台阶，alpha 在相邻点间跳变，合成颜色出现条纹。可行做法是前向用半精度、把 Φ 与累积透明度这一步切回单精度，或在温度参数上做数值裁剪，避免 Φ 在分母上过小导致 alpha 爆炸。

三 · 伪代码思路：一次迭代的骨架

下面用结构化伪代码描述单次迭代，重点标注每一步的系统含义而非数学推导。

  • 采样：对 batch 内每条射线，先在近远区间均匀取 Nc 个点，前向得到 SDF 与颜色，算出粗权重；按权重反变换取 Nf 个细点，与粗点合并排序。此步的代价是两次前向与一次排序，排序在 GPU 上是分段操作，射线数大时不可忽略。
  • 求值：对合并后的点集做一次 MLP 前向，得到 f 与 c；同时以 requires_grad 方式保留坐标，供 Eikonal 使用。
  • 转换：用可学习温度把 f 映射为 Φ，按上式算 α，做透明度累积得到像素颜色。
  • 损失：RGB 重建项对像素求差；Eikonal 项对每个采样点求 ∇f 并惩罚 (‖∇f‖−1)2；若有掩码则再加一项。三项加权求和。
  • 反向：一次 backward 同时穿过 RGB 链路与 Eikonal 链路；注意 Eikonal 的图要在采样点维度上求和后再反传，避免逐点反传造成的调度开销。
  • 更新：优化器步进；温度参数通常用单独的、更小的学习率，或采用随训练进程的调度，避免早期温度过小导致 alpha 过早硬化。

伪代码里最容易被写错的是 α 的分母。上式除以 Φ(si+1) 是为了在离散区间上做归一化，使 α 落在合理范围；当 Φ(si+1) 接近零时（点落在表面之前很远），除法会放大数值误差。工程上要加一个下限裁剪，或在实现里改写成等价的无除法形式并配合 clamp。这个细节不涉及算法正确性，但直接决定训练早期是否出现 NaN 与颜色爆点。

失败模式：若把 Eikonal 损失错误地对 batch 内所有点等权求和，而采样点大量落在空区，则空区的梯度范数本应接近 1（SDF 在自由空间是线性增长的），惩罚会把这些区域的场拉平，反而削弱了表面对比度。正确做法是让 Eikonal 在全体采样点上生效但权重与 RGB 损失平衡，且不要在空区做过强的额外约束。这属于实现层面的权重分配问题，不是公式问题。

四 · 工程坑：从零等值面到可交付网格

训练结束后的提取环节同样有坑。推理时在零等值面跑 Marching Cubes，需要先在一个三维网格上密集求值 SDF。网格分辨率决定了薄结构能否被分辨：分辨率低于结构厚度时，零等值面在体素间被抹平，提取出的网格出现断裂或粘连。分辨率提高是立方级的内存与时间增长，因为网格点数是边长的三次方。工程上常见的折中是先用中等分辨率提取整体，再对感兴趣区域做局部高分辨率重提取，而不是全局拉高。

第二个坑是 SDF 的符号约定与边界。若网络在包围盒边界外没有约束，边界体素上的 SDF 可能取到与内部不一致的符号，Marching Cubes 会在盒子表面封口，产生一层不该有的外壳。对策是在采样时把射线限制在包围盒内，或在损失里对边界点加约束，使场在边界处保持正的、单调的取值。

第三个坑是颜色分支与几何分支的耦合。颜色网络以位置（有时加上法向或视角）为输入，若几何尚未收敛就大力优化颜色，网络会用颜色去“补偿”错误的几何，表现为渲染图好看但网格噪声大。调参顺序上应让几何先行的信号更强：早期提高 Eikonal 权重、降低颜色学习率或延后颜色分支的充分优化，等表面大致成形后再放开颜色。

第四个坑与薄结构和非闭合表面有关。SDF 天然倾向于表达水密、闭合的形状，对纸张、叶片、布料这类薄片，零等值面两侧的场梯度很陡，离散采样稍粗就会把两侧合并成一块实体。这不是调参能完全解决的，属于表示能力的边界；工程上要么提高局部采样与提取分辨率，要么接受薄结构被加厚的事实并在下游处理。

具体例子：一个包含细长栏杆的场景，粗采样阶段栏杆所占体素极少，粗权重几乎为零，细采样不会把点投到栏杆上，于是栏杆在训练中始终得不到梯度，最终网格里缺失。解决方式是在采样策略里加入按空间重要性的分层，或人为提高射线在细长结构附近的采样密度，代价是整体训练时间上升。

五 · 调参顺序：先动什么，后动什么

把可调项按对结果的影响排一个顺序，能避免在错误的方向上反复试。第一顺位是采样策略：粗采样的范围与点数、细采样的点数与区间划分方式。表面缺失、薄结构丢失、损失停滞，多数时候先在这里找原因，而不是先动网络宽度。第二顺位是温度参数及其调度：温度过大会让 alpha 在很大范围内平缓，表面模糊；温度过小会让 alpha 过早硬化，梯度只落在少数点上，训练不稳定。通常从较平滑的设置起步，随训练推进逐步收紧。

第三顺位是损失权重。RGB 项与 Eikonal 项的相对大小决定了“像”与“是干净表面”之间的取舍。Eikonal 权重过低，场不再是距离场，零等值面附近梯度不均，提取出的网格厚度不匀；权重过高，几何被过度约束而颜色拟合不足。掩码项若存在，用于剔除背景射线，避免空区主导损失。第四顺位才是网络容量与学习率：在采样与权重都合理的前提下，加宽加深才是有意义的；否则只是把错误的信号拟合得更精细。

顺位可调项主要影响典型症状
1粗/细采样点数与区间薄结构是否被覆盖、梯度是否到达表面结构缺失、损失停滞
2温度参数与调度alpha 的锐度、表面平滑度表面模糊或训练抖动
3RGB / Eikonal / 掩码权重几何与外观的平衡网格厚度不均、颜色欠拟合
4网络容量、学习率表达上限与收敛速度欠拟合或过拟合噪声

这张表的价值在于约束试错成本。每次只动一个顺位上的一个量，并观察两个指标：渲染损失与提取网格的视觉质量。二者背离时（渲染好、网格差），说明几何信号不足，应回到顺位 1 与 3；二者同差时，才考虑顺位 4。系统代价上，顺位 1 的调整直接改变每步时间与显存，顺位 4 的调整改变的是收敛所需迭代数，两者的墙钟成本不同，不能混在一起比较。

还有一个跨顺位的耦合：提高采样点数会同时放大显存与单步时间，若此时又提高了 Eikonal 权重，二阶图的显存会叠加，很容易在调参中途爆显存而误判为“参数不对”。稳妥的做法是固定采样预算做权重扫描，再固定权重做采样扫描，避免两个乘数同时变化。

六 · 与 3DGS 的系统性差异落在哪里

训练慢于 3DGS 是给定事实，其系统根源不在网络大小，而在每步的计算结构。3DGS 用显式的高斯基元，前向是投影与按深度排序的合成，梯度只经过少量基元参数，单步成本与基元数近似线性且常数小；NeuS 每步要对 R·N 个点做 MLP 求值并做二阶求导，单步成本高出一个量级，且随采样点数线性放大。这不是实现优劣，而是隐式场表示与显式基元表示在计算图上的结构性差别。

显存侧同样如此：3DGS 的显存主要随基元数增长，可控且可剪枝；NeuS 的显存随 batch 与采样点数增长，且被二阶图放大，调节手段更少。通信侧，3DGS 的多卡扩展更多是基元分片与排序的负载均衡问题，NeuS 则是梯度同步加采样负载不均。两者在工程上的调参直觉不能直接迁移：把 3DGS 的“加基元”思路搬到 NeuS 上，对应的是“加采样点”，而后者在墙钟时间上通常是净亏的。

工程判断落在具体机制上：NeuS 的收敛速度由“有效梯度点”的数量决定，而不是由总采样点数量决定。空区的采样点对几何没有贡献，只消耗算力；把预算集中到零等值面附近的高权重区间，是在不增加显存的前提下提高有效梯度密度的唯一手段。因此分层采样与温度调度不是可选的调优项，而是系统设计的一部分——它们决定了每一份算力是否落在能改变表面的位置上。这也是为什么在实现里，细采样的区间划分逻辑值得单独优化，而不是当成一次简单的张量拼接。
