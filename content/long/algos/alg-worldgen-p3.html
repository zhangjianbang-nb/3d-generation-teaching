一 · 与纯 LLM 布局生成的逐项对比

把“LLM+程序化+扩散”放回相邻算法的坐标系里，第一个要对比的是纯 LLM 布局生成：只让语言模型输出场景图，物体位置、朝向、房间划分全靠文本推理，几何与外观交给下游资产库或人工。两者在“布局推理”这一层是共用的，差别出现在布局之后。纯 LLM 布局的产物是一张带坐标与语义标签的场景图，它的正确性由语言模型的先验保证，但场景图的每个节点最终要落到具体网格上，而语言模型对“这个物体多大、放在这里会不会穿墙、门能不能打开”没有几何直觉。组合系统把这段几何落地拆给程序化模块与扩散模块，LLM 只负责“哪里该有什么、大致什么关系”，尺度与碰撞由程序化地形/建筑和 object-aware 组合来兜底。

机制上，纯 LLM 布局的失败模式是“语义合理、几何荒谬”：场景图里客厅连着厨房、沙发对着电视，坐标却让沙发嵌进墙里，或者门宽只有半米。组合系统用 $$\mathcal{W}=\mathrm{Compose}\!\left(\mathrm{Layout}_{\mathrm{LLM}}(t),\mathrm{Terrain}_{\mathrm{proc}},\{\mathrm{Gen}(o_i)\}\right)$$ 把布局与几何解耦：$$\mathrm{Layout}_{\mathrm{LLM}}(t)$$ 只输出语义与粗尺度约束，$$\mathrm{Terrain}_{\mathrm{proc}}$$ 负责可穿越的地形与建筑壳体，$$\{\mathrm{Gen}(o_i)\}$$ 逐个生成物体，最后由 $$\mathrm{Compose}$$ 做 object-aware 的分解与放置。代价是系统从“一次前向推理”变成“多模块串行加组合求解”，延迟与工程复杂度都上一个量级；纯 LLM 布局一次调用就能出图，组合系统要跑 LLM、程序化生成、多次扩散采样和组合优化，任何一环失败都要回退。

具体例子：提示“一座带庭院的二层小楼，院子里有棵大树”。纯 LLM 布局能给出“庭院在南、树在庭院中央、门朝南”的场景图，但树的包围盒可能和围墙重叠，二层楼板高度可能低于一层门高。组合系统里，程序化模块先按可穿越尺度生成楼体与围墙，扩散模块生成树与门，object-aware 组合在放置时检查包围盒相交与通行净空，冲突时回退到布局层要求 LLM 重排。这个回退环是纯 LLM 布局没有的，也是组合系统复杂度的主要来源。

二 · 与纯程序化生成的逐项对比

纯程序化生成（规则驱动的地形、建筑、植被）在可穿越大世界上是最成熟的路线：噪声地形、L-system 建筑、规则放置植被，全部由确定性算法产出，尺度可控、可复现、可进引擎。它的短板在语义与风格：程序化规则能保证“这里有一片森林”，但很难保证“这片森林符合提示里‘阴森的、有废弃小屋的’氛围”，更难生成提示里点名的具体物体。组合系统把程序化模块降级为“壳体与地形提供者”，把语义与具体物体交给 LLM 与扩散，等于用生成模型补上程序化的语义缺口。

机制差别在于控制粒度。纯程序化生成的控制参数是规则超参（噪声频率、建筑密度、植被分布），调参靠人工试错，风格变化需要改规则或换种子。组合系统的控制入口是文本提示：LLM 把“阴森”“废弃”翻译成场景图里的材质、光照、物体类别约束，扩散模型按物体类别逐个生成，风格一致性由 LLM 的场景图统一约束。代价是确定性丧失：扩散采样有随机性，同一提示两次运行得到不同资产，复现需要固定种子并记录每个模块的中间产物；程序化部分仍可复现，但组合结果的可复现性取决于整条链的种子管理。

失败模式也不同。纯程序化生成在大尺度上稳定，但容易“千篇一律”，玩家走十公里看到的森林是同一种树、同一种密度；组合系统能生成多样物体，却可能在边界处露馅：程序化地形与扩散物体的接触面（树根与地面、建筑与地形高差）需要 object-aware 组合做贴合，贴合失败会出现悬浮或穿地。具体例子：程序化地形生成起伏山坡，扩散生成的树按包围盒底部放置，若组合阶段不做地形高度采样，树会一半悬空。这类失败在纯程序化路线里不存在，因为树是规则按地形高度直接放置的。

三 · 与纯扩散 3D 生成的逐项对比

纯扩散 3D 生成（单物体或房间级）在资产质量与多样性上是强项：给定图像或文本，扩散模型能产出细节丰富的网格或神经场。它的边界在尺度与布局：房间级场景生成无法扩展到可穿越的大世界，因为扩散模型的采样成本随场景体积增长，且模型没有“游戏逻辑”的概念——它不知道门要能开、走廊要能走、楼梯要能上。组合系统把扩散限制在“单个物体”的粒度，用 LLM 布局与程序化壳体承担大尺度与逻辑，扩散只负责 $$\{\mathrm{Gen}(o_i)\}$$ 里的每个 $$o_i$$。

这个粒度选择有明确的系统代价。纯扩散房间级生成一次采样就能得到整间屋子的几何，组合系统要为场景里每个物体单独采样，物体数量随世界规模线性增长，采样总次数与显存占用都随规模上升；好在单物体采样的分辨率需求低于整场景，单次成本可控，总量靠批处理与缓存摊薄。另一个代价是一致性：纯扩散整场景生成时，物体间的风格由同一次采样隐式统一；组合系统里每个物体独立采样，风格一致性要靠 LLM 场景图给每个物体附上风格标签，并在组合阶段做材质与色调的归一化，否则会出现“同一间屋子里一把写实椅子配一个卡通桌子”。

失败模式：纯扩散在房间级容易生成“看起来对、走进去不对”的几何——墙面的开口是装饰而非通道，楼梯坡度不可行走。组合系统用程序化壳体保证通行性，扩散物体只做装饰与可交互道具，把“可穿越”与“好看”分开保证。具体例子：提示“废弃医院走廊”。纯扩散能生成一条视觉上阴森的走廊，但门可能是贴图；组合系统里程序化模块生成带门洞的走廊壳体与可通行门框，扩散生成病床、轮椅、输液架，object-aware 组合保证这些道具不堵住主通道。代价是组合阶段要维护通行图，放置时查询净空，这是一层纯扩散没有的约束求解。

四 · 失效条件与系统代价清单

组合系统的失效不是单点失效，而是模块间契约失效。第一类失效是布局与几何的契约破裂：LLM 场景图给出的房间尺寸与程序化壳体生成的实际尺寸不一致，导致物体放置越界或门洞错位。触发条件是提示里含模糊尺度词（“宽敞”“狭小”）而 LLM 未给出数值约束，程序化模块按默认尺度生成。第二类是物体与地形的契约破裂：扩散物体按自身局部坐标系生成，组合阶段若不做地形高度与法线对齐，出现悬浮、穿地、斜坡上的物体倾斜错误。第三类是风格契约破裂：多物体独立采样导致色调、材质分辨率、多边形密度不一致，在近距离观察时突兀。

系统代价可以按模块列清单。LLM 布局：一次推理的延迟与 token 成本，场景图越大越贵，且 LLM 对数值尺度的输出不稳定，需要后处理校验。程序化地形/建筑：确定性、低成本，但规则库维护成本高，新风格要写新规则。扩散物体：单次采样成本乘以物体数量，显存峰值出现在批处理时，缓存命中率决定实际开销。object-aware 组合：约束求解的复杂度随物体数量与碰撞对数量上升，通行图维护是额外数据结构。引擎导出：格式转换与 LOD 生成，资产质量参差时导出失败率上升。

失效类型触发条件观测现象缓解手段
布局-几何契约破裂提示含模糊尺度词，LLM 未给数值物体越界、门洞错位布局后处理加尺度校验，回退重排
物体-地形契约破裂组合阶段未采样地形高度/法线悬浮、穿地、斜坡倾斜错误放置前做高度与法线对齐
风格契约破裂多物体独立采样，无统一约束色调/材质/密度不一致场景图附风格标签，组合阶段归一化
通行性失效道具放置未查净空主通道被堵，门不可开维护通行图，放置时查询净空

具体例子：提示“一个被藤蔓覆盖的废墟庭院，中央有口井”。LLM 给出庭院尺寸与井的位置，程序化生成围墙与地面，扩散生成井、藤蔓、碎石。若组合阶段不查通行净空，碎石可能堆在唯一入口；若不采样地形高度，井可能半悬空。这两类失效在纯程序化路线里由规则直接避免，在组合系统里必须显式加校验，校验本身是工程成本。

五 · 选型建议：按约束选路线

选型的第一问是“世界是否需要可穿越的大尺度”。若只需要房间级展示、资产质量优先、不需要游戏逻辑，纯扩散 3D 生成是成本最低的路线，一次采样出图，无需布局与组合。若需要大尺度可穿越、风格与语义可控、要进游戏引擎，组合系统是当前能同时满足这三条的路线，代价是系统复杂度与评测缺失。若只需要确定性、可复现、低成本的大世界，纯程序化生成仍是首选，语义与风格缺口用人工资产或少量扩散物体补，不必上完整组合链。

第二问是“控制入口是什么”。控制入口是文本提示、且提示含具体物体与风格词，组合系统的 LLM 布局加扩散物体是匹配的；控制入口是规则超参、且团队有程序化规则库，纯程序化路线更直接。第三问是“失败代价落在哪”。展示型应用可以容忍风格不一致与偶发悬浮，组合系统的校验层可以简化；可交互游戏不能容忍通行性失效与穿模，组合系统必须维护通行图与地形对齐，工程投入向组合阶段倾斜。

  • 房间级、质量优先、无逻辑：纯扩散 3D 生成，单次采样，跳过布局与组合。
  • 大世界、确定性优先、规则库成熟：纯程序化生成，扩散只做点缀资产。
  • 大世界、文本控制、要进引擎：组合系统，LLM 布局 + 程序化壳体 + 扩散物体 + object-aware 组合，校验层不可省。
  • 语义优先、几何容忍：纯 LLM 布局 + 人工/资产库落地，组合阶段只做粗放置。

组合系统内部的调参顺序也有选型含义：先固定程序化壳体与地形规则，保证可穿越底线；再调 LLM 布局的尺度约束输出，减少契约破裂；再调扩散物体的采样分辨率与批大小，控制显存与一致性；最后调组合阶段的净空阈值与地形对齐容差。顺序反了会在不稳定的布局上反复重采样，成本翻倍。评测缺标准是这条路线当前的现实约束：没有统一的布局正确性、通行性、风格一致性指标，选型时只能按项目自建验收清单，把失效类型逐项列为检查项。

六 · 三道练习

练习一（契约校验）：给定一条提示“一座带围墙的庭院，中央有口井，入口在南侧”，写出 LLM 场景图应包含的最小字段（房间/区域、物体类别、粗尺度、朝向、连通关系），并设计一个布局后处理校验：检查井的包围盒是否与围墙相交、入口净空是否大于最小通行宽度。要求给出校验失败后的回退策略——是重问 LLM、还是由程序化模块调整壳体尺寸，并说明两种回退各自的代价。

练习二（地形对齐）：程序化地形生成一片起伏山坡，扩散模型生成若干棵树，组合阶段按包围盒底部放置。写出放置前的地形高度与法线采样伪代码思路：对每个物体包围盒底面取若干采样点，查询地形高度，取最大值作为放置高度，按法线调整朝向；说明采样点数量与查询成本的权衡，以及采样不足时会出现什么失败现象（悬浮、穿地、斜坡倾斜）。进一步说明若地形是程序化噪声生成的解析函数，能否跳过采样直接解析求高度，代价是什么。

练习三（选型论证）：给出两个项目约束——A：房间级展示，资产质量优先，无交互；B：可穿越大世界，文本控制，要进游戏引擎，团队有程序化规则库但无扩散资产管线。分别论证应选哪条路线，列出组合系统在 B 项目中必须保留的校验层（通行图、地形对齐、风格归一化），并说明若 B 项目砍掉扩散模块、只用 LLM 布局加程序化壳体，会失去什么能力、换来什么代价。要求论证落在具体机制上，不写泛泛的优缺点列表。
