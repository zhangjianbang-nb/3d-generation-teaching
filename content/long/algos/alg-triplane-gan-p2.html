一 · 从公式到张量：三平面生成器的计算图与复杂度账本

把 G(z)=TriPlane_θ(z) 落到工程上，第一步是决定三张平面的张量形状。设平面分辨率 R×R、每像素通道数 C，则三平面总参数量级为 3·R²·C，而同样视觉精度的体素表示是 R³·C。这个比值 3/R 是整套系统显存账本的起点：当 R=256 时，三平面特征图总量约为体素方案的 1/85；当 R=512 时约为 1/170。注意这里说的是特征图本身，不含生成器主干与 MLP 解码器。

生成器主干通常是若干 2D 卷积/上采样块，从低分辨率潜码逐步放大到 R×R，最后分出三个通道组分别对应 T_xy、T_xz、T_yz。这一步的计算量按 2D 卷积的 O(R²·C²·k²) 增长，与体素 3D 卷积的 O(R³·C²·k³) 相比是降维打击。真正的开销大头不在生成平面，而在渲染阶段的采样查询。

体渲染每条相机射线采样 S 个点，每点要做三次双线性插值（每张平面一次）加一次 MLP 前向。设 batch 内射线数 N_ray，则每步训练的点查询数为 N_ray·S，插值部分是纯 gather+lerp 的访存密集型操作，MLP 部分是小型矩阵乘。工程上常见的配比是 S 取 32 到 64、N_ray 取数千量级，于是单步查询点在十万到数十万级别——这个量级决定了你不能用逐点 Python 循环，必须把插值写成可向量化的索引运算。

$$\text{Cost}_{\text{render}} \approx N_{\text{ray}}\cdot S\cdot\left(3\cdot\text{interp} + \text{MLP}(3C\rightarrow H\rightarrow 4)\right)$$

一个具体机制：三平面插值的坐标归一化。3D 点 x=(x,y,z) 落在 [-1,1]³ 的规范体积内，映射到平面像素坐标时要区分「哪个轴被压掉」。对 T_xy 用 (x,y)，对 T_xz 用 (x,z)，对 T_yz 用 (y,z)，且三张图的 uv 轴向必须与生成器输出通道的排列严格一致。这个映射写错一个轴，训练仍会收敛，但几何会呈现系统性镜像或扭转——这是最隐蔽的失败模式之一，因为损失曲线看起来完全正常。

系统代价方面：三平面方案把显存从体素的 R³ 压到 3R²，但代价是表达冗余。三个平面在空间中并非独立，任意两个平面的组合在交线上会重复编码同一区域的信息，网络必须学会让三者在重叠处保持一致。这种一致性没有任何显式约束，只靠 2D 判别器从多视角渲染中反向施压。结果是：平面分辨率越高，冗余越贵（三张 R² 图都要存、都要卷积），而几何精度并不会随 R 线性提升，因为平面插值在轴向上是「投影后插值」，沿被压掉的那个轴没有直接的深度分辨率。

二 · 显存与通信：训练循环里的真实瓶颈分布

训练一步的显存占用可以拆成四块：生成器激活（三平面特征图 + 主干中间层）、渲染采样缓存（每条射线的 S 个点的坐标、插值结果、MLP 中间激活）、判别器激活、以及优化器状态。前三块随 batch 线性增长，第四块随参数量线性增长。三平面方案的特点是：生成器激活小（2D 特征图），但渲染采样缓存大（N_ray·S·3C 的浮点张量），因为反向传播要穿过插值和 MLP，所有采样点的中间量都得留着。

这导致一个反直觉的工程判断：在三平面 GAN 里，省显存的第一优先级不是缩小平面分辨率，而是控制每条射线的采样点数 S 与 batch 内射线数。把 S 从 64 降到 32，渲染缓存直接减半，而视觉质量在多数物体尺度下退化有限；把 R 从 512 降到 256，平面特征图减到四分之一，但高频细节会明显丢失。调参顺序应当是先定 R（由目标细节决定），再用 S 和 N_ray 去凑显存预算。

通信方面，单卡训练时没有跨设备通信，瓶颈是 HBM 带宽：插值的 gather 操作是随机访存，三张平面各自被不同射线以不同 uv 命中，缓存命中率低。多卡数据并行时，每步要 all-reduce 生成器与判别器的梯度，梯度量与参数量成正比，而三平面方案的参数量主要集中在 2D 主干上，all-reduce 开销与单卡计算开销的比例通常比体素方案更友好——因为计算被渲染采样主导，梯度同步相对便宜。但若采用模型并行把三张平面分到不同卡，插值时的跨卡 gather 会引入点对点通信，延迟远高于本地访存，这条路线在实践中不划算。

一个具体例子：当 R=256、C=32 时，三平面特征图约 3·256²·32 个浮点数，按 fp32 约 24 MB；若 batch 内射线数取 4096、S=48，采样点约 20 万，每点拼接特征 3C=96 维，仅拼接特征缓存就约 75 MB，加上 MLP 隐层激活与插值中间量，渲染缓存是平面特征图的好几倍。这解释了为什么很多实现选择在渲染时对 S 做分层采样（粗采样 + 细采样），而不是均匀铺满。

失败模式：显存碎片化。三平面特征图、采样缓存、判别器激活的生命周期不同，若框架的缓存分配器不能复用，峰值显存会显著高于理论值。工程上应把渲染采样放在独立的显存池，或在两步之间显式释放不再需要的中间张量。另一个坑是混合精度：插值用 fp16 会在平面边界产生可见的条带，因为双线性权重在 fp16 下精度不足；常见做法是插值用 fp32、MLP 用 fp16，代价是额外的类型转换开销。

三 · 伪代码思路：从隐向量到一条射线的完整路径

下面用伪代码把前向路径写清楚，重点标注每一步的张量形状与易错点。设潜码维度 D，平面分辨率 R，通道 C，MLP 隐层宽度 H。

  • T = G_main(z)：输出形状 [B, 3, C, R, R]，第 1 维索引 0/1/2 分别对应 xy/xz/yz。切分时必须与后续插值的轴映射表一致。
  • pts = sample_along_rays(rays, S)：形状 [B, N_ray, S, 3]，坐标已归一化到 [-1,1]。
  • 对每个平面做 grid_sample 风格的插值：把 pts 的对应两轴拼成 uv，形状 [B, N_ray·S, 1, 2]，在 [B, C, R, R] 的平面上双线性采样，得到 [B, N_ray·S, C]。
  • 三份插值结果沿通道拼接为 [B, N_ray·S, 3C]，送入 MLP 得到 [B, N_ray·S, 4]（RGB + 密度）。
  • 体渲染积分：沿 S 维做离散累积，得到每条射线的颜色与深度，形状 [B, N_ray, 3]。
  • 渲染图送 2D 判别器，与真实图做对抗损失；可加姿态条件则把相机参数拼进判别器输入或生成器条件。

关键实现细节：插值的 uv 顺序。以 T_xy 为例，若平面张量的空间维是 [H, W]，则 grid_sample 期望的坐标顺序是 (x=宽方向, y=高方向)，而 3D 点的 (x,y) 哪个对应宽、哪个对应高，取决于你如何定义世界坐标系。这个约定一旦在生成器输出、插值、相机投影三处不一致，就会产生前面说的镜像错误。建议在代码里写一张显式的轴映射表，并在单元测试里用「已知点查已知平面值」的方式验证。

另一个细节：三平面插值结果的拼接顺序必须固定，因为 MLP 的第一层权重是按这个顺序学的。若在推理时改变了拼接顺序（例如为了优化而重排通道），必须同步置换 MLP 第一层的输入权重，否则输出完全错乱。这类错误在导出模型、换框架重写时高发。

系统代价：grid_sample 在多数框架里对 5D 输入的支持与性能不一，实践中常把 [B, N_ray, S, 3] 展平为 [B, N_ray·S, 3] 再 reshape 成 4D 做采样，reshape 本身是零拷贝或一次拷贝，但若布局不对会触发隐式转置，带来额外带宽开销。失败模式：把 N_ray·S 展平后忘记恢复 S 维，体渲染积分就会沿错误的轴累加，渲染出的是「所有采样点平均色」而非沿射线的 alpha 合成，图像会呈现整体雾状。

四 · 工程坑：对称性冗余、固定拓扑与判别器依赖

三平面表达的对称性冗余是结构性的：三个平面各自是一张完整的 2D 特征图，但它们在 3D 空间中编码的是同一个场。网络没有任何机制强制 T_xy 在 z 方向的信息与 T_xz 在 y 方向的信息一致，一致性完全由渲染损失间接驱动。工程后果是：训练早期三张平面可能学到彼此矛盾的几何，渲染出的多视角图像出现「同一物体在不同视角下形状漂移」。缓解手段是提高视角采样密度、让判别器看到足够多的视角组合，但这会线性增加每步渲染开销。

固定拓扑是另一个硬约束。三平面是规则网格，没有显式的部件或语义结构，因此无法做「只改椅子腿」这类局部编辑——任何编辑都会通过插值扩散到整个平面，进而影响全局几何。若产品需要部件级控制，三平面生成器只能作为几何先验，后面接一个分割/编辑模块，而不是在表示内部直接操作。这是表示层面的限制，不是调参能解决的。

训练依赖 2D 判别器意味着几何真值弱。判别器只看渲染出的 2D 图像，不看 3D 点云或深度，因此几何正确性只能通过多视角一致性间接约束。失败模式：生成器可以学会「用纹理欺骗判别器」——在平面上画出高频纹理，使渲染图在训练视角下逼真，但换一个视角就暴露出几何是扁平的。这类过拟合在视角采样不足时尤其明显。工程对策是显式加入视角分布的条件、并在验证时用留出视角做检查，而不是只看训练视角的 FID 类指标。

一个具体例子：姿态条件。若生成器接受相机姿态作为条件，姿态编码必须与三平面的轴映射在同一坐标系下定义，否则条件与几何脱钩，网络会忽略条件、退化成无条件生成。验证方法是固定 z、扫一遍姿态输入，看渲染图是否随之旋转；若不旋转，说明条件通路没有生效，常见原因是条件向量在拼接时被主干的高维特征淹没。

还有一个实现坑：平面边界。双线性插值在平面边缘会 clamp 到边界像素，导致物体在规范体积边界处出现拉伸伪影。若物体贴近 [-1,1]³ 的边界，这些伪影会被体渲染放大。工程上通常把物体缩放到规范体积的内部（留出边距），或在插值时对越界坐标做衰减，而不是简单 clamp。

五 · 调参顺序：先定分辨率，再定采样，最后动学习率

调参顺序应当由系统的瓶颈结构决定，而不是从学习率开始盲扫。第一步定平面分辨率 R：它由目标细节尺度决定，且一旦定下就锁死显存的下限。第二步定每条射线采样点数 S 与粗/细采样比例：S 决定渲染缓存与几何精度，粗采样负责覆盖、细采样负责表面附近。第三步定 batch 内射线数与视角采样策略：这决定判别器看到的视角多样性，进而决定三平面一致性能否被有效约束。第四步才是学习率、判别器/生成器更新比例等优化器超参。

这个顺序的理由是：前三步决定的是「系统能表达什么、能看到什么」，属于结构性选择；后一步决定的是「优化能否走到那里」，属于收敛性问题。若先调学习率而 S 太小，几何精度被采样不足卡死，学习率怎么调都救不回来；若视角采样太稀疏，一致性约束不足，生成器会走纹理欺骗的捷径。

$$\text{有效几何分辨率} \sim \min\left(R,\ \frac{1}{S}\text{ 沿射线的采样间距}^{-1}\right)$$

这个定性关系说明：平面分辨率 R 给出的是「平面内」的上限，而沿射线方向的精度由 S 与采样策略决定。两者不匹配时，系统会在一个方向上清晰、另一个方向上模糊——这正是三平面「投影后插值」的结构性特征。工程判断：若发现物体沿某一轴系统性模糊，先检查该轴对应的平面分辨率与射线采样密度是否匹配，而不是去调 MLP 宽度。

系统代价：提高 S 会同时增加前向与反向的显存与计算，且反向的插值梯度是 scatter 操作，比前向的 gather 更慢。实践中常把细采样限制在粗采样估计的表面附近，用粗采样的密度峰值定位表面区间，再在该区间内加密——这是把 S 的有效预算花在刀刃上的标准做法。失败模式：粗采样太稀导致表面定位错误，细采样落在空区，几何出现空洞或双层表面。

最后落在具体机制上：三平面生成器的工程核心矛盾是「2D 卷积的生成效率」与「3D 查询的渲染开销」之间的配比。生成端便宜，渲染端贵，因此所有调参决策都应围绕如何用最少的 3D 查询点换取足够的几何约束——分辨率定表达上限，采样定几何精度，视角分布定一致性压力，三者构成一个互相牵制的三角，任何一项单独拉满都会被另外两项的瓶颈抵消。
