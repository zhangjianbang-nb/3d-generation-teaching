一 · 复杂度账本的记账口径

把 NeuS 的训练开销拆成可加项，前提是先固定“一次迭代”到底算什么。工程上把一次迭代定义为：一个 batch 的 B 条射线，每条射线沿方向采样 N 个点，前向得到 SDF 与颜色，反向传播 RGB 损失与 Eikonal 正则。所有后续估算都以这个单位为基准，避免把“一个 epoch”与“一次网络前向”混为一谈。记账分四栏：浮点运算量（时间主项）、激活与梯度显存、参数与优化器状态显存、以及采样点坐标与中间张量的带宽。四栏不是并列关系——时间由算力或带宽之一封顶，显存由激活或参数之一封顶，必须先判断哪一栏是约束，否则调参就是盲调。

一个必须写进账本的机制是：NeuS 的每条射线不是均匀采样，而是先粗采样再按 alpha 重要性重采样，且 Eikonal 正则的梯度点与体渲染采样点不是同一批。这意味着一次迭代里网络前向的次数大于“B×N”这个朴素计数。设粗采样 N_c 点、细采样 N_f 点、Eikonal 独立采样 N_e 点，则单次迭代的网络评估点数为 B×(N_c+N_f+N_e)。把这三个数写死进配置而不是散落在代码里，是让账本能对上的最低要求；否则任何“训练慢”的判断都缺乏可比性。

$$C_{\text{fwd}} \approx B\,(N_c+N_f+N_e)\cdot\bigl(C_{\text{MLP}}+C_{\text{color}}\bigr)$$

这里的 C_MLP 是 SDF 分支一次前向的乘加数，C_color 是颜色分支的乘加数。公式只做量级估算，不追求精确 FLOPs，但它把“采样策略”与“网络宽度”两个可调项显式暴露出来：增大 N_f 是线性涨时间，加宽隐藏层是平方涨时间（权重矩阵乘法的乘加数随宽度平方增长），二者的性价比完全不同。

二 · 一个具体规模下的时间估算

取一个可复现的规模：B=1024 条射线/迭代，N_c=64，N_f=64，N_e=32，即每条射线 160 个评估点，单次迭代 163840 个点。SDF 分支取 8 层隐藏层、每层 256 宽、输入为位置编码后的坐标（维度记为 D_in），颜色分支取 4 层、每层 256 宽、输入为位置编码加视角方向加 SDF 特征。按每层一次矩阵乘法计，单点 SDF 分支的乘加数约为 8×256×256 加上首末层，量级在 5×10^5 次乘加；颜色分支量级在 2×10^5。合计单点约 7×10^5 次乘加，单次迭代约 1.1×10^11 次乘加，即约 2.3×10^11 FLOPs（乘加按 2 FLOP 计）。

把这个数放到硬件上：一张主流数据中心 GPU 的 FP32 峰值在数十 TFLOPS 量级，但 MLP 的小矩阵乘法（batch 内每点是独立向量）难以吃满峰值，实际可达比例受限于 kernel 启动、访存与占用率。工程经验是把有效算力按峰值的十分之一到三分之一估，于是单次迭代的前向时间落在毫秒到十几毫秒之间；反向传播约为前向的两到三倍，加上重采样与 Eikonal 的额外图节点，单次迭代总时间在几十毫秒量级。按此推算，十万次迭代量级的训练对应小时到十小时量级——这与“训练慢于 3DGS”的定性判断一致，但账本给出了差距的来源：不是单点算力不够，而是每条射线要评估上百个点，而 3DGS 每个高斯只做一次投影与排序。

账本项规模假设量级估算约束类型
单次迭代评估点数B=1024，160 点/射线1.6×10^5 点线性可调

这张表的价值不在绝对数字，而在比例关系：把 N_f 从 64 提到 128，时间近似翻倍；把隐藏宽度从 256 提到 512，单点乘加数约翻四倍。若目标是缩短训练，先动采样数还是先动宽度，账本给出的答案是前者更可控，因为采样数与视觉质量的关系可以通过重采样策略局部补偿，而宽度削减会同时损伤 SDF 高频细节与颜色表达。

三 · 显存账本：激活、参数与优化器状态

显存分三块。第一块是激活：为了反向传播，每个评估点的每层中间结果都要保留，单点激活量约为层数×宽度×4 字节。按 12 层、256 宽计，单点约 12KB；乘以单次迭代 1.6×10^5 点，激活量级在 2GB 上下。这是最容易被忽视的一块——它随 batch 与采样数线性增长，而不是随模型参数增长。第二块是参数：SDF 与颜色分支合计约数百万参数，FP32 下为数十 MB，加上 Adam 的一阶二阶动量再乘三倍，仍在百 MB 量级。第三块是采样坐标、射线方向、alpha 与透射率等中间张量，量级与激活同阶但常数更小。

由此得到一个反直觉的结论：在中等规模下，NeuS 的显存瓶颈是激活而非参数。想加大 batch 提升吞吐，先撞墙的是激活。工程上的对策是梯度检查点：不保留全部中间激活，反向时重算前向。代价是时间增加约三成到一倍（取决于重算比例），收益是激活显存降到与层数无关的量级。另一个对策是把 Eikonal 的采样点单独成一个小 batch 前向，避免它与体渲染采样共享同一张大激活图，这样两块显存峰值错开而非叠加。

$$M_{\text{act}} \approx B\,(N_c+N_f)\cdot L\cdot W\cdot 4\ \text{bytes}$$

失败模式很具体：当把 N_f 从 64 提到 128 以提高薄结构处的采样密度时，激活翻倍，若同时把 batch 翻倍，四倍增长直接触发 OOM；此时若盲目减小网络宽度，SDF 的高频表达能力下降，零等值面在细杆与薄片上出现断裂。正确顺序是先上梯度检查点、再把 Eikonal 采样拆批，最后才考虑降采样数。这个顺序本身就是账本给出的工程判断。

四 · 带宽账本与真正的瓶颈位置

带宽项常被忽略，但在小 batch、多点采样的负载下它可能是主约束。每次迭代要把采样坐标从主机或缓存搬到计算单元，坐标本身是三维浮点加位置编码，编码后维度可达数十维；单点编码后的字节数乘以 1.6×10^5 点，再乘以前向与反向各读一遍，量级在百 MB 到 GB 级。若位置编码在核内实时计算而非预存，则省掉这部分读写但增加算力；若预存，则显存与带宽同时吃紧。这是一个明确的取舍点，账本要把它写成二选一而不是“优化一下”。

更隐蔽的带宽开销来自重采样：粗采样得到 alpha 后要在主机或设备端做排序与累积，再生成细采样坐标，这一步涉及一次全量 alpha 的读写与一次索引重排。它的数据量小于激活，但它是串行依赖——必须等粗采样前向完成才能开始，无法与前向重叠。于是单次迭代的墙钟不是“前向+反向”的简单相加，而是“粗前向 → 重采样 → 细前向 → 反向”的链式结构，链上每一环都有启动开销。在小 batch 下，这些启动开销的占比上升，GPU 占用率下降，表现为“算力没用满但就是慢”。

具体例子：把 B 从 1024 降到 256 以减少显存，单次迭代的 FLOPs 降到四分之一，但墙钟往往只降到二分之一左右，因为链式结构中的固定开销与核启动次数没有同比减少。这就是带宽与延迟主导区的典型特征。判断是否处于该区的办法是看增大 batch 后单点耗时是否下降：若下降明显，说明在延迟主导区，应优先增大 batch 或合并核；若几乎不变，说明已进入算力或带宽主导区，此时再增大 batch 只增显存不增吞吐。

五 · 推理侧与端到端账本

训练账本之外还有推理账本，二者不能混算。NeuS 推理不是体渲染，而是在包围盒内按分辨率网格逐点查询 SDF，再跑 Marching Cubes。设网格分辨率为 R（每轴体素数），查询点数为 R^3；按 R=512 计约 1.3×10^8 个点，单点只跑 SDF 分支（不需颜色），乘加数量级在 5×10^5，总 FLOPs 在 10^14 量级，比单次训练迭代高三个数量级。这就是为什么推理阶段的网格提取是独立的一次性大开销，且它只做前向、可用半精度与分块查询来摊平显存峰值。

端到端账本要把训练与推理相加，并计入数据侧：多视图监督意味着每步要从图像里采样射线，图像解码与坐标变换的成本随分辨率与视角数增长，虽不进入网络 FLOPs，但进入墙钟。失败模式是数据加载成为瓶颈而网络利用率低——表现为 GPU 利用率曲线呈锯齿状，随 batch 到达而脉冲。对策是预先把射线原点与方向烘焙成扁平数组，避免每步重复做相机变换。

把这张表与前面的公式对齐，可以得出一个明确的工程判断：NeuS 的训练瓶颈在“每条射线上百点的 MLP 评估”这一结构性事实上，而不在参数量或单点算力；显存瓶颈在激活而非参数；推理瓶颈在 R^3 次 SDF 查询。三者对应的调优手段互不通用——为训练省显存的手段（梯度检查点）对推理无效，为推理降分辨率的手段会直接损伤薄结构。账本的意义就是阻止把一种瓶颈的对策错用到另一种瓶颈上。

最后一个具体机制层面的判断：温度参数与采样策略在账本里不是“精度旋钮”而是“成本旋钮”。温度过大会让 alpha 在零等值面附近摊平，重采样难以集中到表面附近，等效于把 N_f 的有效利用率拉低，于是为了达到同等表面精度必须增大 N_f，时间线性上涨；温度过小则 alpha 过于尖锐，梯度在表面外几乎为零，Eikonal 正则的采样点大量落在无梯度区，等效于浪费 N_e。把温度、N_f、N_e 三者放在同一张账本上联合调，而不是分别调，才是这套复杂度估算真正要支撑的工程动作。
