一 · 单步迭代的复杂度账本

把迭代式房间网格补全当成一个系统看，第一步要算清的是“每一步迭代到底在做什么、花多少代价”。一次完整迭代由五个阶段串成：单图深度估计、反投影建网格、新视角渲染、2D 扩散补洞、深度融合。这五个阶段的复杂度量级完全不同，把它们混在一起谈“算法快不快”是没有意义的。深度估计是一次前向推理，代价与输入分辨率近似线性，但模型本身是重量级网络，单次调用在工程上属于“贵但可预测”的开销。反投影是纯几何变换，对每个像素做一次矩阵乘加，复杂度与像素数成正比，几乎不构成瓶颈。真正的大头在渲染与补洞：渲染要对当前全局网格做光栅化或射线求交，代价随网格面数增长；补洞则要跑一次 2D 扩散采样，采样步数与分辨率共同决定耗时，通常是整条流水线里最慢的一环。

用符号把账本写清楚。设单帧分辨率为 \(H\times W\)，扩散采样步数为 \(S\)，当前网格面数为 \(F\)，迭代轮数为 \(T\)。单轮渲染的代价近似为 \(O(F)\) 量级的面片遍历，单轮补洞的代价近似为 \(O(S\cdot H\cdot W)\) 的神经网络前向，而反投影与融合是 \(O(H\cdot W)\) 的逐像素操作。总代价大致是：

$$\mathrm{Cost}\approx T\cdot\big(O(S\cdot H\cdot W)+O(F)+O(H\cdot W)\big)$$

这个式子给出的工程判断很直接：当 \(S\cdot H\cdot W\) 远大于 \(F\) 时，系统是“扩散主导”的，优化方向是降采样补洞、减少采样步数、缓存重绘区域；当 \(F\) 随迭代迅速膨胀、超过补洞项时，系统转为“网格主导”，此时瓶颈变成渲染与融合，优化方向转为网格简化、分块管理、剔除不可见面片。两条曲线的交叉点决定了你该先调哪一边，而不是凭感觉去压缩扩散步数。

一个具体例子：房间从一角开始生长，前几轮网格面数很小，渲染几乎瞬时完成，整轮时间几乎全花在扩散补洞上；随着相机绕行、房间逐步闭合，全局网格面数持续累积，渲染开始出现可感知的延迟，此时再砍扩散步数收益已经很小。失败模式也随之出现：如果只按固定预算分配算力，前几轮浪费在渲染上、后几轮浪费在补洞上，整体吞吐被最慢环节拖住。工程上的做法是按阶段做自适应预算，让每一轮的算力分配跟随当前 \(F\) 与补洞区域面积的比例走。

二 · 显存与通信：全局网格是真正的成本中心

场景规模受显存限制，这句话的落点不在扩散模型，而在全局网格的存储与访问。网格不是一张图，它由顶点、面片、颜色/纹理属性以及融合所需的辅助结构（例如每个体素或面片的置信度、观测次数）组成。显存占用随面数线性增长，而迭代式补全的特点是“只增不减”：每一轮都把新反投影的几何并进 \(\mathcal{M}_t\)，旧几何不会被主动删除。于是显存曲线是单调上升的，直到撞上上限。

把融合写成集合运算，能看清成本结构：

$$\mathcal{M}_{t+1}=\mathcal{M}_t\cup\mathrm{BackProject}\!\left(D_t,I_t,\mathbf{c}_t\right)$$

这个并集操作在实现上不是免费的。新反投影出的面片与已有面片在空间上大量重叠，必须做去重与属性融合：位置相近的面片要合并，颜色要按观测置信度加权，冲突区域要判定保留哪一方。若采用体素哈希做空间索引，每次插入都要查表、比较、可能触发重哈希；若采用稀疏块结构，则要处理块边界处的接缝。这些操作的计算量不大，但访存模式零散，实际耗时常常超过预期。更麻烦的是通信：如果渲染与融合跑在 GPU 上，而网格管理放在主机内存或分块换入换出，那么每轮迭代都要在设备与主机之间搬运网格块，PCIe 带宽成为隐性瓶颈。当网格规模超过单卡显存，就必须做分块流式加载，此时“当前视角需要哪些块”的判定逻辑本身就是一个调度问题。

具体的失败模式是显存碎片化而非简单的容量耗尽：反复插入与合并会让稀疏结构产生大量空洞，名义上还剩空间，实际却分配不出连续块，表现为随机的分配失败。工程对策是在迭代若干轮后做一次网格压实（compaction），把稀疏结构重新打包，代价是一次全量遍历，但能换回可预测的后续行为。另一个具体例子是颜色融合的精度问题：同一面墙被多个视角观测，若用低精度浮点累加置信度，长距离迭代后会出现颜色漂移，表现为墙面出现缓慢变化的色带，这不是扩散模型的错，而是融合累加器的数值设计问题。

通信侧还有一个容易被忽略的点：补洞阶段需要把当前视角渲染成一张带洞的 RGB-D 图送给 2D 扩散模型，补完后再取回。这一来一回的图像传输量是 \(O(H\cdot W)\) 每轮，看似不大，但如果补洞在远端服务上执行，网络往返延迟会直接叠加到迭代周期上。把补洞放在本地、把网格放在显存、把深度估计做成批处理，是降低通信占比的常规手段。

三 · 伪代码思路：主循环与三个不变量

主循环的结构本身不复杂，复杂的是维持三个不变量：相机轨迹的连续性、网格与当前渲染的一致性、补洞结果与已有几何的兼容性。下面用伪代码思路描述，不写具体语言。

  • 初始化：由首帧图像估计深度 \(D_0\)，反投影得到初始网格 \(\mathcal{M}_0\)，设定相机位姿 \(\mathbf{c}_0\)。
  • 循环：按轨迹推进相机到 \(\mathbf{c}_t\)；用 \(\mathcal{M}_t\) 在 \(\mathbf{c}_t\) 下渲染出颜色图与深度图，标记出无几何覆盖的洞区域；把带洞图像送入 2D 扩散补全，得到补全后的 \(D_t\) 与 \(I_t\)；将 \((D_t,I_t,\mathbf{c}_t)\) 反投影为新面片；与 \(\mathcal{M}_t\) 做空间去重与属性融合，得到 \(\mathcal{M}_{t+1}\)；判定房间是否闭合，未闭合则继续。
  • 终止：当新视角下的洞区域面积低于阈值，或相机轨迹回到起点且首尾几何对齐，停止扩展。

三个不变量对应三处工程约束。第一，相机轨迹必须连续且步长受控：步长过大，新视角与已有几何的重叠区太小，融合缺少约束，漂移会加速累积；步长过小，迭代轮数暴涨，显存与时间成本线性上升。第二，渲染必须与网格状态严格同步：如果在融合尚未完成时就推进相机，渲染出的洞会包含“已补但未融合”的区域，导致同一块几何被重复反投影，形成叠层。第三，补洞结果必须被当作“带置信度的观测”而非“真值”：扩散模型补出的深度在洞边缘与已有几何可能不连续，直接并集会在接缝处产生折痕，因此融合阶段需要做边界一致性检查，对不连续处降权或做局部重采样。

一个具体的失败模式来自不变量二：异步流水线为了提速，把渲染与融合放在不同线程，结果渲染读到了半更新的网格，洞的判定出现抖动，补洞区域在相邻两轮之间来回跳变，表现为画面闪烁与几何抖动。修复方式不是加锁那么简单，而是把“网格版本号”作为渲染的输入参数，保证渲染看到的是一致快照。另一个例子是终止判定：若只用洞面积阈值，可能在房间尚未真正闭合时提前停止，留下一个朝向未知方向的开口；工程上通常叠加首尾位姿对齐检查，用几何重叠度而非像素面积做最终判据。

四 · 工程坑：漂移、接缝与先验失配

长距离漂移是这类迭代系统最本质的缺陷，它不是调参能消除的，只能被约束。漂移的来源是每轮反投影都依赖当前相机位姿与当前深度估计，而深度估计本身有误差，误差随轮数累积到全局网格上。表现形式是相机绕行一圈回到起点时，新观测的几何与最初建立的几何对不上，出现重影或错位。工程上的缓解手段是引入回环约束：当检测到当前视角与历史视角重叠时，用重叠区的几何做位姿与尺度的联合校正，再把校正量分摊到全局网格。这本质上是在迭代流程里嵌入一个轻量的配准环节，代价是每轮多一次重叠检测与优化，收益是把漂移从“无界累积”压成“有界抖动”。

接缝问题出现在补洞与已有几何的交界处。2D 扩散模型在补洞时看到的是渲染出的带洞图像，它对洞外区域的几何一无所知，只看到颜色与深度的二维投影。于是补出的深度在洞边缘可能与真实几何差一个台阶，融合后形成可见的折痕。具体机制是：扩散模型倾向于生成平滑过渡，而真实几何在边缘处可能有尖锐的深度跳变（例如墙角），两者冲突。工程对策是在融合前做边缘一致性约束，把洞边界一圈像素作为条件输入扩散过程，或在融合时对边界带做泊松式平滑，把台阶分摊到若干面片上。

先验失配是另一类坑：补洞依赖 2D 先验，而 2D 先验来自自然图像分布，对室内场景的特定结构（例如踢脚线、门框、吊顶线）并不总是给出几何合理的补全。当补洞区域较大时，扩散模型可能生成视觉上合理但几何上不自洽的内容，例如把一面墙补成两个不同深度的平面。这类错误在单帧上看不出来，但在相机继续移动、新视角渲染时暴露为几何矛盾。失败模式是“补洞越成功、后续越难融合”：补出的内容越丰富，与真实几何冲突的概率越高。工程上的判断是控制单轮补洞的面积上限，宁可多迭代几轮、每轮补小洞，也不要在单轮里让扩散模型自由发挥大片区域。

五 · 调参顺序：从几何一致性到视觉质量

调参不能按“哪个参数显眼先调哪个”的顺序来，而应按误差传播链的顺序来。误差链是：相机位姿与深度估计 → 反投影几何 → 融合结果 → 渲染出的洞 → 补洞内容 → 下一轮几何。链条上游的误差会被下游放大，因此调参必须从上游开始。

顺序调参对象判据调错的代价
1相机步长与轨迹采样相邻视角重叠区是否足够做融合约束步长过大导致漂移加速，步长过小导致轮数爆炸
2深度融合的置信度与去重阈值重叠区是否出现叠层或重影阈值过松产生重复面片，过紧丢失新观测
3洞区域判定与补洞面积上限单轮补洞是否引入几何矛盾面积过大导致先验失配，后续融合失败
4扩散采样步数与分辨率补洞边缘与已有几何的连续性步数过少边缘粗糙，分辨率过高显存吃紧
5网格压实与分块调度显存占用曲线是否可预测压实过频浪费算力，过疏导致分配失败

这个顺序的工程含义是：前两项决定几何骨架是否可信，若骨架本身在漂移，后面所有关于纹理与补洞的调参都是在错误的基础上做优化。一个具体例子是，很多实现先调扩散步数追求画面好看，结果发现无论怎么调，绕行一圈后墙角总是错位，回头才发现是步长与融合阈值的问题。反过来，先把步长压到重叠区足够、把融合阈值调到重影消失，再去看补洞质量，调参空间会清晰得多。

调参的另一个判断点是预算分配：当显存成为硬约束时，优先压缩网格的辅助属性（置信度精度、颜色位宽），而不是压缩补洞分辨率，因为前者影响的是长期融合稳定性，后者影响的是单轮视觉质量，而视觉质量可以在后续轮次被新观测修正，融合稳定性一旦破坏则难以回滚。这个取舍本身就是工程判断：迭代式系统的本质是“用多轮观测换一致性”，任何削弱一致性的压缩都比削弱单轮画质的压缩更危险。
