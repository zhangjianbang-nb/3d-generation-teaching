一 · 序列长度与自回归步数的真实代价

相邻网格 token 重拓扑把重拓扑写成自回归面片序列生成，工程上第一个要面对的账不是“面数降了多少”，而是“解码器要跑多少步”。输出网格的面数记为 |M_out|，每个面片由一个 token 表示，则解码步数等于面片数。相邻 token 编码让每个面只引用前一个面的一条边，序列中不必重复记录共享边，因此同样拓扑下 token 序列比“逐顶点+逐面索引”的写法短，但步数仍然与输出面数线性相关。生成一个两万面的干净网格，就意味着两万次自回归前向，每次都要维护 KV 缓存并采样。这个线性关系是硬约束，不是靠调 batch 能绕过去的。

把单步代价拆开看：解码器每步要做一次注意力查询，键值缓存长度随已生成 token 增长。若层数为 L、隐藏维度为 d、缓存长度为 t，单步注意力读写量近似正比于 L·d·t。总解码开销对步数求和后出现二次项：

$$C_{\text{dec}}\;\approx\;\sum_{t=1}^{N}\big(c_0 + c_1 L d t\big)\;=\;c_0 N + \tfrac{1}{2} c_1 L d N(N+1)$$

其中 N=|M_out|，c_0 是每步固定的前向与采样开销，c_1 是单位缓存读写系数。这说明面数翻倍时解码时间不止翻倍，KV 缓存带来的二次项会显著放大。工程上的直接后果是：高面数输出必须做分块或分层生成，把一次长序列拆成若干段，每段重新以局部特征为条件，否则单卡显存和时延都撑不住。

失败模式很具体：当输出面数上升到数万量级，KV 缓存占用按 L·d·t 增长，若同时开较大 batch 做并行采样，显存会在解码中途耗尽，表现为长序列后段突然 OOM，而不是一开始就报错。另一个失败模式是采样温度设置不当导致序列提前进入退化循环，反复生成同一条边的相邻面，拓扑上形成自缠绕，面数虚高而有效覆盖不增。具体例子：把一张扫描得到的十万面杂乱网格送入，期望输出两万面干净四边主导网格，若不分块，解码到后段时缓存已占满，只能降低 batch 到 1，吞吐塌陷，单件耗时从秒级升到分钟级。

二 · 显存布局：特征、缓存与批处理的三角约束

显存占用由三块构成：输入侧的点云/网格特征、解码器的键值缓存、以及批处理带来的并行副本。编码器提取的特征通常是对采样点云的逐点或逐块嵌入，尺寸与采样点数成正比；这部分在解码开始后可以部分释放，但相邻 token 编码需要持续访问局部几何上下文，因此特征不能全部丢弃，只能压缩或分块驻留。KV 缓存则是随解码步数单调增长的，无法预分配一个固定上限而不浪费。

设采样点数为 P、特征维度为 d_f、批大小为 B、缓存精度为 b 字节，则显存下界可写成：

$$M_{\text{gpu}}\;\gtrsim\;B\big(P\,d_f\,b_{\text{feat}} \;+\; L\,d\,t\,b_{\text{kv}}\big) \;+\; M_{\text{weights}}$$

这个式子给出调参顺序的第一条线索：先降 t（即控制单段输出面数），再降 B，最后才考虑降 d 或量化缓存，因为后两者直接损伤生成质量。实践中把输出网格按空间区域切成若干块，每块独立解码，块间共享编码器特征，可以把 t 压到可控范围，代价是块边界处的拓扑缝合需要额外处理。

失败模式：块边界处两个相邻面各自引用自己块内的“前一个面”的边，缝合时出现重复边或 T 型接缝，表现为渲染时边界处出现裂缝或法线断裂。具体例子：对一个角色头部做分块重拓扑，前额块与颞部块在边界各自生成闭合边环，合并后边界处多出一圈冗余面，面数比预期高出几个百分点，且该圈面片不适合动画变形。工程判断是：分块必须带重叠区，重叠区内只保留一侧的面，另一侧作为条件上下文而非输出。

三 · 伪代码思路：从特征到面片序列的调度

下面给出调度层面的伪代码思路，重点不在模型内部，而在工程上如何组织编码、解码与相邻边复用。相邻 token 编码的关键状态是“上一条边”，它既是序列上下文，也是拓扑连续性的保证，因此每一步都要显式维护这条边的两个端点索引。

伪代码结构如下（文字描述，不用代码块）：第一步，对输入网格做泊松盘或体素下采样得到点云，送入编码器，得到逐点特征与全局特征；第二步，初始化序列状态，把“当前边”设为空，把已生成顶点表设为空；第三步，进入自回归循环，解码器以全局特征、局部邻域特征和当前边为条件，输出下一个面片 token；第四步，解析 token，若它引用当前边，则复用该边的两个端点，只新增一个顶点；若它不引用当前边（起新壳），则新增三个顶点；第五步，把新边设为当前边，更新顶点表与面表，继续循环直到达到停止 token 或面数上限；第六步，做拓扑清理，合并重复顶点、删除退化面、检查非流形边。

这个循环里有两个工程要点。其一，顶点索引的分配必须是确定性的，否则同一 token 序列在不同实现下会得到不同顶点编号，影响可复现性。其二，停止条件不能只靠模型输出的停止 token，还要加面数上限和拓扑合法性检查，因为模型在噪声输入下可能生成自交面，此时继续解码只会放大错误。用公式表达停止判据：

$$\text{stop}\;\iff\;\big(\text{token}=\text{END}\big)\;\lor\;\big(|M_{\text{out}}|\ge N_{\max}\big)\;\lor\;\big(\text{non-manifold}(M_{\text{out}})>0\big)$$

失败模式：拓扑合法性检查放在解码末尾做，代价是已经生成了大量非法面才回滚，浪费算力。更好的做法是每步增量检查新面是否与已有面相交或产生非流形边，一旦触发就截断该分支并回退到上一个合法状态。具体例子：输入一个带薄壁结构的机械零件点云，解码器在薄壁两侧各生成一层壳，两层壳在中间相交，若不增量检查，最终输出包含大量自交面，后处理阶段不得不整体丢弃重来。

四 · 通信与数据搬运：特征驻留与块间同步

当输出面数大到需要多卡或多进程分块时，通信开销从“可忽略”变成主导项。编码器特征如果每块都重新计算，算力浪费；如果集中驻留在一张卡上，其他卡每次解码都要拉取局部特征，形成频繁的小消息传输。相邻 token 编码的局部性意味着每步只需要当前边附近的特征，因此可以按空间划分把特征切片分发到各卡，块间只同步边界处的边状态。

设块数为 K、每块解码步数为 t_k、每步需要拉取的边界特征量为 s，则块间通信量近似为：

$$V_{\text{comm}}\;\approx\;\sum_{k=1}^{K} t_k\, s \;+\; K\, s_{\text{seam}}$$

其中 s_seam 是缝合阶段交换的边界边与顶点索引。这个式子的工程含义是：块数增加会线性增加缝合通信，但减少每块的 t_k，从而压低单卡缓存压力。存在一个折中点，块太少则单卡显存放不下，块太多则缝合通信和边界错误率上升。调参顺序上，应先固定块数使单块缓存占用落在显存安全线以下，再优化块内解码的批大小。

失败模式：异步解码时各块进度不一致，先完成的块把边界边写入共享缓冲区，后完成的块读到的是尚未稳定的边状态，导致缝合处出现悬挂边。具体例子：四卡并行重拓扑一个大型场景网格，两块先完成并在边界写入边索引，另两块稍后完成时读到旧索引，合并后边界出现重复顶点，顶点数比预期多出可观比例，且这些重复顶点在动画蒙皮时会被撕开。工程判断是：缝合必须做同步屏障，或者让边界区只由单一责任块生成，其他块只提供条件不输出面。

五 · 工程坑：噪声输入、退化面与细节丢失的连锁反应

算法对输入噪声敏感，这一点在系统层面会放大成多个连锁问题。噪声点云会让编码器特征在局部出现高频抖动，解码器据此生成的面片在法线方向上反复翻转，形成薄片状退化面。退化面本身面数不多，但它破坏了相邻 token 的边复用前提：当一条边被两个以上面引用时，后续面无法确定“前一个面”是谁，序列上下文断裂，生成质量骤降。

退化面的判定可以用面积与法线一致性两个量：面积低于阈值，或相邻面法线夹角超过阈值，即标记为可疑。用公式表达一个简单的过滤判据：

$$\text{degenerate}(f)\;\iff\;\text{area}(f)<\epsilon_a\;\lor\;\cos\big(\mathbf{n}_f,\mathbf{n}_{f'}\big)<\epsilon_n$$

其中 f' 是沿共享边相邻的面。工程上不能等解码结束再统一过滤，因为退化面会污染后续 token 的边状态，必须在每步更新边状态前做一次局部检查，发现退化就丢弃该面并回退边指针。

细节丢失是另一类坑，且与面数压缩直接相关。输出面数大幅低于输入，意味着高频几何细节（倒角、刻线、薄片）在重拓扑中被平滑掉。系统层面表现为：同一输入在不同采样密度下输出差异明显，采样过疏时细节完全消失，采样过密时噪声又被当成细节保留，生成一堆碎面。具体例子：对一个带雕花的装饰件做重拓扑，雕花深度小于采样间距时被整体抹平，输出网格虽然干净但失去可辨识特征；把采样加密后，雕花被保留，但表面噪声也被保留，面数回升且拓扑出现局部缠绕。调参顺序应是先定采样密度匹配目标细节尺度，再调解码温度压低随机性，最后才考虑面数上限。

六 · 调参顺序与系统边界的工程判断

把上述约束串起来，得到一个有依据的调参顺序，而不是凭经验乱试。第一步定输出面数上限 N_max，它由目标用途决定：动画变形需要均匀四边主导拓扑，面数按骨骼影响范围估算；渲染用途可以接受更高面数但要求法线连续。第二步定分块数与每块面数，使单块 KV 缓存落在显存安全线内，同时让块边界落在几何平坦区而非特征区，减少缝合错误。第三步定采样密度，使其略高于目标细节尺度，避免细节被抹平或噪声被放大。第四步调解码温度与停止判据，压低随机性以保证拓扑稳定。第五步才做批处理与多卡并行，此时单件质量已稳定，并行只影响吞吐。

这个顺序背后的判断是：面数与分块决定系统能否跑完，采样与温度决定输出是否可用，并行只决定跑得多快。把并行提到前面调，往往在质量未定时就放大错误，返工成本更高。系统边界上还有一个硬约束：相邻 token 编码的边复用要求面片序列在拓扑上连续，一旦输入网格本身是非流形的（扫描数据常见），编码器特征无法提供一致的局部定向，解码器会在非流形处反复起新壳，面数虚高。工程上应先在输入侧做非流形清理与定向统一，再送入重拓扑，而不是指望解码器自行修复。

最后一个具体机制落在边状态的增量维护上：每生成一个面，只有一条边被消费、两条边被新建，边表更新是常数时间；但顶点合并检查需要查询邻域，若用哈希表按坐标量化索引，查询代价与局部顶点密度相关。把量化精度设得过细会导致本应合并的顶点未被合并，设得过粗会把邻近但不同的顶点错误合并，产生塌陷。这个精度参数应与采样间距同量级，并在分块缝合前统一，否则块间顶点无法对齐，缝合阶段只能做暴力最近点匹配，代价从常数时间升到与边界顶点数平方相关。
