一 · 前向一次出三平面的计算图与张量形状

把 LRM 的前向拆成可核算的张量流水线，是判断它能否落地的第一步。输入是一张图 \(I\in\mathbb{R}^{H\times W\times 3}\) 与相机参数 \(\mathbf{c}\)（外参旋转平移加内参，通常压成一个向量或若干 token）。DINO ViT 先把图切成 patch，输出 token 序列 \(\mathbf{Z}\in\mathbb{R}^{N\times d}\)，\(N\) 是 patch 数、\(d\) 是通道宽。相机调制不是简单拼接：常见做法是把 \(\mathbf{c}\) 过一个小 MLP 得到调制向量，再以 FiLM 式仿射变换注入解码器的 cross-attention 的 key/value，或作为额外的条件 token 参与注意力。解码器输出的是三张正交平面特征图，记作 \(\mathbf{T}_{xy},\mathbf{T}_{xz},\mathbf{T}_{yz}\)，每张形状 \(R\times R\times C\)，\(R\) 是平面分辨率、\(C\) 是特征通道。三平面拼起来就是 \(3RC\) 个浮点数，这是整个系统的“资产表示”大小。

关键机制在于 cross-attention 的不对称性：query 来自三平面上的可学习网格位置（或从粗到细的 latent 网格），key/value 来自图像 token。也就是说，解码器不是从图像“卷积”出平面，而是让平面上的每个位置主动去图像里“取”它需要的证据。这带来一个直接后果：三平面分辨率 \(R\) 与图像 patch 数 \(N\) 解耦，\(R\) 可以独立调大而不改 ViT 输入尺寸，代价是 query 数量按 \(R^2\) 增长，注意力矩阵按 \(R^2\times N\) 增长。

$$\mathbf{Q}=\mathrm{GridEmbed}(R^2,d),\quad \mathbf{K}=\mathbf{Z}W_K,\quad \mathbf{V}=\mathbf{Z}W_V,\quad \mathbf{T}=\mathrm{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^{\top}}{\sqrt{d}}\right)\mathbf{V}$$

系统代价首先落在注意力显存上。若 \(R=128\)、\(N=256\)（16×16 patch）、\(d=768\)，单个平面的注意力分数矩阵是 \(16384\times 256\)，约 4M 元素，乘以头数与层数后显存迅速吃紧；工程上必须用分块注意力或把 query 分批。失败模式很具体：不分块时在单卡上直接 OOM；分块但忘了对 softmax 做数值稳定（减最大值）时，混合精度下会出现 NaN，表现为渲染图突然全黑。另一个坑是三平面共享解码器还是各自独立解码器：共享省参数但三个平面互相竞争容量，独立则参数翻三倍，且三个平面的 query 网格必须用不同的位置编码，否则三个平面学到几乎相同的特征，体渲染时正交方向信息退化。

具体例子：把 \(R\) 从 64 提到 128，三平面浮点数从 \(3\times 64^2\times C\) 变为 \(3\times 128^2\times C\)，是 4 倍；若 \(C=32\)，前者约 39 万、后者约 157 万浮点，单资产表示仍在 MB 级以下，这正是 triplane 作为“通用中间表示”的工程吸引力——表示小到可以批量存盘、批量送进渲染器。

二 · 体渲染的采样预算与分辨率损失

三 · 训练数据的多视图渲染与损失配比

训练信号来自 Objaverse 渲染的多视图：每个资产预先渲染若干视角的真值图，训练时输入取其中一个视角，监督取其余视角。这带来一个数据工程上的硬约束：多视图必须与输入视角的相机参数一致地参数化，否则相机调制注入的条件与监督视角对不上，网络学到的是“忽略相机”的捷径。失败模式很典型：如果训练时随机丢弃相机条件，网络会退化成把输入视角的内容直接“贴”到输出三平面上，换视角渲染时背面全是输入视角的镜像或模糊块——这正是“背面细节靠数据先验”的工程根源，不是算法缺陷而是监督覆盖不足。

损失是渲染图 MSE 加感知损失。MSE 对大结构收敛快但对高频纹理不敏感，感知损失（用预训练视觉骨干的特征距离）补上纹理与边缘。配比是个调参重点：感知损失权重过大时，渲染图在感知上“好看”但几何密度场变糊，网格提取出现漂浮碎片；权重过小时，纹理发灰、细节缺失。伪代码层面的训练循环是：采样资产与输入视角，前向出三平面，随机采若干监督视角渲染，算损失，反传。这里有一个系统代价常被忽略：每个训练步要渲染多个视角，渲染是串行在计算图里的，显存占用随监督视角数线性增长，视角数一多就得梯度累积或减小 batch。

具体例子：一个资产若监督 4 个视角、每视角 \(64\times 64\) 像素、每像素 64 个采样点，单步渲染的采样点数是 \(4\times 64^2\times 64\)，约百万级，乘上 MLP 的每点计算，单步渲染开销与解码器注意力开销同量级。这解释了为什么这类系统的训练吞吐受渲染器而非 Transformer 主导，优化渲染器（降低采样数、用重要性采样）往往比换更大骨干更划算。

四 · 显存、通信与并行切分

把系统放到多卡上，切分维度有三个候选：数据并行、把三平面 query 按空间切、把渲染射线按像素切。数据并行最简单，但每卡都要放完整的 ViT 与解码器，显存瓶颈在注意力激活；query 空间切分能把注意力矩阵按行切开，每卡只算一部分平面位置，代价是图像 token 的 key/value 要广播到所有卡，通信量是 \(N\times d\) 乘以层数，属于可控的 all-gather。渲染射线切分则把像素分给不同卡，每卡都要拿到完整三平面，通信量是 \(3RC\)，比 key/value 广播小，但三平面在每卡上重复一份，显存不省。

工程上的判断是：训练阶段用 query 切分配合梯度检查点，把注意力激活换时间；推理阶段用射线切分，因为推理没有反传、三平面只算一次，重复存放的代价可接受。失败模式出现在混合精度与 all-gather 的交界：key/value 用 fp16 广播后，softmax 前的分数在长序列上容易溢出，需要保留 fp32 的 softmax 累加，或者用在线 softmax 的分块算法。另一个坑是梯度检查点与 dropout 的随机性：重算时若随机种子没对齐，前后向的 dropout 掩码不一致，梯度有偏，表现为损失曲线抖动但不下降。

表格对比三种切分的代价（定性）：

切分维度显存节省主要通信适用阶段
数据并行无（激活全量）梯度 all-reduce小模型、多资产
query 空间切分注意力激活按卡分摊图像 key/value 广播训练

具体例子：当 \(R\) 提到 256 时，单平面 query 数到 65536，注意力分数矩阵在 \(N=256\) 时是 \(65536\times 256\)，单卡 fp16 下已接近数 GB，必须 query 切分；而推理时三平面 \(3\times 256^2\times 32\) 约 630 万浮点、十几 MB，射线切分下每卡复制一份完全可接受。

五 · 工程坑清单与调参顺序

第一类坑在坐标约定。三平面是 \(xy\)、\(xz\)、\(yz\) 三张正交平面，射线采样点 \((x,y,z)\) 投影到每张平面时，哪个轴做行、哪个轴做列、归一化到 \([-1,1]\) 还是 \([0,1]\)，必须与网格提取阶段完全一致。不一致的典型症状是渲染图正常但提取出的网格整体镜像或旋转 90 度——因为渲染损失对平面内的轴对称变换不敏感（网络可以学到镜像的特征布局），而提取器按固定约定读平面，于是错位。工程上要把这套约定写成单元测试：给定一个已知点的三平面坐标，断言插值取值与渲染器一致。

第二类坑在相机调制的归一化。不同资产的相机内参焦距差异大，若不统一归一化，调制向量的分布随数据集漂移，解码器学到的条件映射被稀释。做法是把焦距、主点、外参统一到规范空间，并在输入侧做与训练分布一致的裁剪。第三类坑在密度场的激活：密度常用 softplus 或 exp，前者在负值区梯度小、收敛慢，后者容易爆；工程上先用 softplus 加一个偏置把初始密度压到接近零（空场），让粗采样先看到透明背景，再逐步学出表面。

调参顺序有明确的依赖关系，不能乱序：先固定 \(R\) 较小（如 64）把渲染损失降到能出大致形状，确认坐标约定与相机归一化无误；再提 \(R\) 与渲染分辨率，观察高频细节是否随分辨率提升而改善，若不改善说明监督视角数或感知损失权重不足；然后调感知损失与 MSE 的配比，用固定几个资产的渲染图做肉眼对比而非只看标量损失；最后才上多卡切分与混合精度，因为并行引入的数值问题会掩盖前面的调参信号。失败模式是反过来做：一上来就大 \(R\) 加多卡，坐标约定的小错被并行掩盖，损失曲线看似正常但网格提取全错，排查成本极高。

具体例子：一个常见的“调参陷阱”是把学习率与 \(R\) 同时放大。\(R\) 变大后 query 数变多，注意力输出的方差随 \(N\) 与 \(R\) 变化，原学习率下解码器输出饱和，三平面特征趋同，渲染图变成一片平均色。正确做法是提 \(R\) 时同步检查注意力分数的量级（打印每层分数均值与最大值），必要时对 query/key 做归一化或调温度，而不是盲目降学习率。

六 · 推理路径与网格提取的工程边界

推理是一次前向出三平面，再提取网格。这条路径的工程边界在于：三平面是特征而非几何，提取器要在特征场上定义密度，再在密度场上跑 marching cubes。伪代码思路是：在 \(G^3\) 的体素网格上逐点查三平面插值、过 MLP 得密度，对每个体素边做线性插值找等值面交点，输出三角面片。系统代价是 \(G^3\) 次 MLP 前向，\(G=256\) 时是 1670 万次，这是推理的主要开销，远超 Transformer 本身。优化手段是把 MLP 在小体素块上批量化、用半精度、以及在粗网格上先定位表面附近再细化。

失败模式有两个。其一是薄结构丢失：三平面插值在薄壁处给出平滑密度，marching cubes 的等值面阈值一高就整片消失，阈值一低就膨胀出多余面片；工程上要按资产尺度自适应选阈值，或在训练时加一个对密度场稀疏性的正则。其二是网格提取分辨率与三平面分辨率不匹配导致的“台阶”：\(G\) 大于 \(R\) 时，插值在体素间是分段线性的，等值面出现规则的小平面块，视觉上是低模感。这不是 bug 而是表示上限，判断标准是：若把 \(R\) 提一档后台阶感明显减弱，说明瓶颈在 \(R\)；若不变，瓶颈在 \(G\) 或密度 MLP 容量。

具体例子：单图输入、一次前向、秒级出 3D 的承诺，在工程上要拆成“前向时间 + 提取时间”。前向是 Transformer 的一次推理，提取是 \(G^3\) 次 MLP 查表，后者在 \(G=256\) 时是数量级更大的开销。因此“秒级”能否成立，取决于提取器是否批量化与是否用粗到细策略，而不是取决于 Transformer 多大。工程判断落在这一点：把提取器当作独立子系统优化，它的吞吐决定端到端体验，三平面的分辨率 \(R\) 决定几何上限，两者要分开调、分开测。
