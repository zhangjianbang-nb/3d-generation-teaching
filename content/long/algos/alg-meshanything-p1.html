一 · 问题定义：面数爆炸与拓扑失序的双重困境

生成模型输出的网格，问题从来不只是"面多"。面数爆炸是表象，拓扑失序才是根因。一个由隐式场经 Marching Cubes 提取的网格，面片数量与体素分辨率呈立方关系，分辨率翻倍，面数就是八倍；而它的顶点连接关系由等值面穿越格点的局部规则决定，既没有全局的边流向，也没有可预期的四边形环结构。对渲染管线而言，这意味着顶点缓存命中率低、索引缓冲膨胀；对绑定与动画而言，这意味着找不到连续的边环来放置骨骼影响权重，蒙皮时出现撕裂。更麻烦的是，这类网格的顶点位置带有数值噪声，法线在相邻面之间跳变，导致着色出现块状伪影。

于是问题被形式化为一个映射：给定任意输入网格或点云 $\mathcal{M}_{\mathrm{in}}$，产出一个面数远小于输入、拓扑干净、边流向可被艺术家预期的网格 $\mathcal{M}_{\mathrm{out}}$。这里"干净"不是审美判断，而是可检验的结构条件：绝大多数顶点度数接近四（四边形网格）或六（三角形网格的规则顶点），存在贯穿模型的边环，面片尺寸分布集中而非长尾。传统重拓扑依赖艺术家手工绘制边环，或依赖参数化后的四边形重采样，前者不可扩展，后者在复杂拓扑（多亏格、薄壁、自交）上频繁失败。

相邻网格 token 重拓扑的核心判断是：把重拓扑从"几何优化问题"改写为"序列生成问题"。这个改写的关键在于，序列的每一项不是顶点坐标，而是面片；面片之间的引用关系被压缩到只依赖前一个面的一条边。这一约束同时解决了两件事——序列长度被显著缩短，且拓扑连续性由解码过程的构造方式自动保证，而不是靠后处理修补。

二 · 核心思想：以面为 token、以边为粘合剂的自回归构造

把网格写成序列，最直觉的做法是顶点序列加索引三元组。但顶点序列的问题是：每个顶点坐标是三个连续浮点数，序列极长；更致命的是，索引三元组之间的拓扑关系是全局的，解码器在生成第 $k$ 个面时无法从前面已生成的面中直接读出"下一条边应该接在哪里"，只能隐式地学习全局一致性，这在长序列上必然漂移。

相邻 token 编码换了一个构造性视角。设想网格是一个面片的有序列表，每个面片由若干条边围成。若规定生成顺序沿着一条边环推进，则相邻两个面共享一条边。于是第 $i$ 个面只需要记录"我相对于第 $i-1$ 个面的那条共享边，往哪一侧延伸、延伸出几个新顶点"。共享边不需要重新编码，它由上一步的输出直接复用。这就是"相邻"二字的工程含义：token 的语义不是绝对坐标，而是相对于前一面片的增量拓扑操作。

这一设计带来两个直接后果。其一，序列长度与面数成正比而非与顶点数乘三成正比，且每个 token 承载的拓扑信息密度更高——一个 token 同时确定了新面的边数、新顶点的相对位置和与前一面的连接方式。其二，拓扑连续性成为构造不变量：解码器不可能生成一个与前一面完全无关的孤立面，因为它的输入里就含着前一面的边引用。这消除了序列生成模型在网格任务上最常见的失败模式——生成出一堆互相穿插但拓扑不连通的碎片。

用伪代码表达解码循环的骨架：维护一个"前沿边"变量 $e_{\mathrm{front}}$，初始为种子面的一条边；每一步解码器输出一个 token，该 token 被解释为"从 $e_{\mathrm{front}}$ 出发，生成一个新面，并指定新面中哪条边成为下一轮的 $e_{\mathrm{front}}$"；循环直到闭合条件满足或达到终止 token。整个过程中，新顶点坐标由 token 中的相对偏移量与已有点云特征共同决定，而非自由回归三个浮点数。

三 · 公式逐步解释：从输入到输出的映射与面数压缩

主映射写作：

$$\mathcal{M}_{\mathrm{out}}=\mathrm{Dec}_\theta(\mathcal{M}_{\mathrm{in}}),\qquad |\mathcal{M}_{\mathrm{out}}|\ll|\mathcal{M}_{\mathrm{in}}|$$

逐项拆解。$\mathcal{M}_{\mathrm{in}}$ 在进入解码器前并非原始网格，而是经过采样与特征编码的中间表示：先从输入网格表面采样点云，再由编码器（点云卷积或 Transformer 类结构）提取逐点特征。因此 $\mathrm{Dec}_\theta$ 的实际输入是特征张量而非网格本身，公式中的写法是接口层面的抽象。$\theta$ 是解码器参数，与编码器联合训练。

关键在于 $|\mathcal{M}_{\mathrm{out}}|\ll|\mathcal{M}_{\mathrm{in}}|$ 这个不等式的来源。它不是靠事后减面实现的，而是由 token 的构造方式内蕴决定的。设输入面数为 $N_{\mathrm{in}}$，输出面数为 $N_{\mathrm{out}}$。在相邻 token 方案下，每个输出面平均引入的新顶点数远小于三——因为大量顶点由共享边复用。设平均每个新面引入 $v$ 个新顶点、复用 $s$ 条已有边，则输出网格的顶点数约为 $v\cdot N_{\mathrm{out}}$，而输入网格的顶点数约为 $N_{\mathrm{in}}/2$（三角网格的欧拉关系近似）。解码器的终止条件由曲率或特征覆盖率驱动，在平坦区域快速推进、在高曲率区域细化，因此 $N_{\mathrm{out}}$ 由几何复杂度而非输入分辨率决定。这就是"大幅降低"的机制来源：输出面数跟随特征复杂度，输入面数跟随采样分辨率，两者解耦。

四 · 与相邻算法的数学差别：为什么不是"网格版的语言模型"

把网格生成写成序列，已有若干相邻路线，差别在于 token 的语义与序列的构造约束。第一类路线是顶点序列加面索引的扁平化，其概率模型为 $p(V)\,p(F\mid V)$，顶点坐标独立回归，面索引在第二步生成。这类模型的序列长度是 $3|V|+|F|\cdot 3$，且 $p(F\mid V)$ 必须隐式学习全局拓扑一致性，在长序列上误差累积，生成结果常出现非流形边或翻转面。相邻 token 方案把两步合并为一步，序列长度降到 $|F|$，且拓扑一致性由构造保证而非由学习保证——这是结构性的差别，不是训练技巧的差别。

第二类路线是体素或隐式场的序列化，本质上仍是在规则格点上做局部决策，输出需要后处理提取等值面，拓扑干净度受格点分辨率限制。相邻 token 方案直接在面片层面操作，输出即是最终网格，无需提取步骤，但代价是解码器必须自己维护前沿边的合法性。

第三类差别体现在对输入噪声的响应上。由于解码器每步只依赖一条前沿边和编码特征，局部噪声不会通过全局顶点表传播；但反过来，编码特征若被噪声污染，前沿边的推进方向会偏，导致在薄壁或尖锐特征处生成错误的边环走向。这是该方案对输入噪声敏感的数学原因：条件概率的马尔可夫性把误差局部化，却也让每一步都暴露在特征误差之下，没有全局优化来纠正。

五 · 系统代价与失败模式：序列瓶颈与细节丢失的工程账

相邻 token 方案的代价首先落在序列长度上。虽然 $|F|$ 比 $3|V|+3|F|$ 短得多，但自回归解码是逐 token 串行的，$|F|$ 达到数万时，推理延迟随面数线性增长，且无法像扩散模型那样并行去噪。工程上的缓解手段是分块：把网格切成若干 patch，各自生成后再缝合边界边环；但缝合处的前沿边匹配是新的失败点，边界 token 的偏移量若与邻块不一致，会产生缝隙或重叠面。这是"序列长度仍是瓶颈"的具体机制，不是定性抱怨。

第二个代价是细节丢失。解码器在平坦区域快速推进以减少面数，这一决策由曲率或特征覆盖率阈值控制；阈值偏大时，细小特征（铆钉、刻痕、薄片边缘）被跨过，重拓扑后的网格在这些位置失去几何。更隐蔽的是，丢失发生在 token 层面而非顶点层面：一旦某步决定"此处不细化"，后续 token 无法回溯补回，因为前沿边已经推进过去。这与减面算法的可逆性不同，重拓扑的丢弃是不可逆的构造性丢弃。

第三个失败模式是对输入噪声敏感。点云采样若包含离群点，编码特征在局部被拉偏，前沿边在噪声区域可能生成自交面或退化面（面积趋零）。合法性检查只能事后剔除，剔除后留下孔洞，又需要额外的填补逻辑。具体例子：一个带薄壁的机械零件，壁厚小于采样间距时，两侧表面在特征空间中混叠，解码器可能把两侧面片连成一条穿越壁体的边环，输出网格在物理上不可打印。这类失败无法靠增大模型容量解决，只能靠输入预处理（法线一致性过滤）或解码时的壁厚约束项。

六 · 机制推导的落点：构造不变量与特征解耦的取舍

把上述推导收束到一条工程判断上：相邻网格 token 重拓扑的真正贡献不是"用 Transformer 做网格"，而是把拓扑合法性从学习目标降级为构造不变量，同时把面数从输入分辨率的函数改写为特征复杂度的函数。这两个改写各自有明确的数学代价——前者牺牲了全局优化的纠错能力，把误差局部化到每一步的条件概率上；后者牺牲了细节的可逆性，把丢弃变成不可回溯的构造决策。工程上是否采用，取决于任务更怕哪一种失败：若下游是动画绑定，拓扑连续性优先，该方案的构造不变量正合需求；若下游是几何测量或 3D 打印，细节保真优先，则需要在解码时加入曲率下界约束，或退回带全局优化的重网格化路线。公式 $\mathcal{M}_{\mathrm{out}}=\mathrm{Dec}_\theta(\mathcal{M}_{\mathrm{in}})$ 里那个不起眼的 $\theta$，承载的正是这套取舍的全部重量。
