一 · 每条射线的算术账：采样数、MLP 前向与梯度带宽

把体渲染积分搬进工程系统，第一件事是算清一条射线要付多少代价。离散求和形式下，一条射线取 N 个采样点，每个点要查询一次 MLP 得到密度 σ 与视角相关颜色 c。若 MLP 是 L 层、每层宽度 W，则单点前向的乘加量约为各层矩阵乘之和，量级为 O(L·W²)；一条射线就是 N 倍。训练时还要反传，反向计算量约为前向的两倍，且需要保存中间激活。于是单条射线的训练浮点开销近似为

$$\text{FLOPs}_{\text{ray}} \approx 3\,N\,L\,W^{2}$$

系数 3 来自前向一次、反向近似两次。这个式子决定了系统的第一个瓶颈：N 与 W 是乘性关系，任何一方翻倍都直接翻倍算力需求。工程上不能只盯着网络宽度，采样策略同样是一等公民。

更隐蔽的代价在梯度带宽。每条射线产生 N 组 (σ, c) 的中间量，反传时这些中间量都要参与链式求导。若一个 batch 有 B 条射线，激活显存大致随 B·N·W 线性增长。粗采样阶段 N 较大时，激活显存会先于参数显存成为限制。一个具体例子：当把每条射线的粗采样点从数十量级提到上百量级，同时保持 batch 不变，显存占用会出现明显的阶跃式上升，训练直接 OOM，而参数量并没有变化。这说明显存规划必须按“射线数 × 采样点数”而不是按“模型大小”来做。

失败模式也随之而来。若为了省显存把 batch 压到很小，梯度噪声变大，密度场会出现局部塌陷：某些视角下 σ 在错误位置堆积，渲染出雾状伪影。这不是数学错误，而是小 batch 下方差过大的典型表现。工程判断是：优先保证每条射线的采样点覆盖有效区间，再在射线数上做 batch 缩放，而不是反过来砍采样。

二 · 分层采样与重要性采样的两级结构

经典实现采用两级采样：粗网络在近端 t_n 到远端 t_f 之间均匀分层取 N_c 个点，得到粗略的 σ 与颜色，据此估计沿射线的权重分布；再按该分布做逆变换采样，取 N_f 个精细点，把两级点合并后送入精细网络输出最终像素。这个结构的核心机制是把“哪里可能有表面”这一信息用于分配采样预算，使采样点集中在权重大的区间。

其中 δ_i 是相邻采样点间距。粗网络的 w_i 归一化后作为分段常数概率密度，逆变换采样即在该累积分布上取分位点。伪代码思路如下：

  • 对每条射线，在 [t_n, t_f] 上等分 N_c 段，取段内扰动点，查询粗 MLP，算 σ、c 与 w。
  • 把 w 归一化为 pdf，构造累积分布 CDF；对 N_f 个均匀随机数做逆 CDF 采样，得到精细点位置。
  • 合并粗点与精细点，按 t 排序，一次性查询精细 MLP，用全部点做离散积分得到像素颜色。
  • 损失只用精细输出与真实像素的 MSE；粗输出可加辅助损失，也可不加。

系统代价在于：两级结构使 MLP 查询次数变成 N_c + N_f，且精细阶段要对合并后的点重新排序，排序在 GPU 上是分支密集的操作，容易造成 warp 内 divergence。另一个坑是粗网络的梯度是否回传。若粗输出不参与最终损失，粗 MLP 只作为采样器存在，其参数更新依赖辅助损失或共享参数；若两级共享同一 MLP，则粗阶段的前向也要保留激活，显存进一步上升。

具体例子：当场景中存在大面积天空或透明区域时，粗网络在这些区间给出的 σ 接近零，w 很小，精细采样几乎不落在该区间，结果是背景区域采样稀疏、颜色估计方差大，渲染出低频色块。工程上的应对是给采样分布加一个均匀分量做混合，保证任何区间都有最低采样密度，代价是少量算力被浪费在空区域。

三 · 位置编码的显存与频谱代价

位置编码把三维坐标与视角方向映射到多频正弦基。对坐标做 L 级编码后，输入维度从 3 变为 3 + 6L（每级含 sin 与 cos 各三个分量）；对方向做编码同理。第一层权重矩阵因此从 W×3 变成 W×(3+6L)，参数量与首层乘加量随之上升。这是用输入维度换频谱表达力的典型交易。

机制上，MLP 对低频函数有强烈的谱偏置，直接吃原始坐标很难拟合高频几何细节；正弦基把坐标展开到多个频段，使网络在第一层就能线性组合出高频分量。代价是首层激活的数值范围变大，且高频项对采样位置极其敏感：采样点位置的微小扰动会通过高频基放大，导致同一表面在不同采样扰动下给出不一致的 σ，表现为渲染噪点。

失败模式是编码级数选得过高时的过拟合与混叠。高频基在训练视角上能拟合细节，但在新视角上产生振铃状伪影，因为网络把高频基当成了记忆坐标的查表工具，而不是学习连续场。工程判断是：编码级数应与场景尺度匹配，且必须配合足够的视角覆盖；视角稀疏时，高频编码带来的收益会被新视角伪影抵消。

另一个系统代价是首层矩阵乘的显存。编码后输入维度可达数十，首层权重与激活都随之变大；在混合精度下，高频正弦值的动态范围要求小心处理，否则半精度下的舍入会让高频项失真。具体例子：把坐标编码从低级别提到高级别而不同步调整学习率，训练初期损失下降更快但后期出现密度场高频抖动，本质是高频基的梯度尺度与低频不一致。

四 · 显存布局与通信：射线批、点批与分块渲染

训练时的张量布局通常有两种：以射线为主序，把每条射线的 N 个点连续存放；或以点为主序，把所有射线的采样点展平成一个长向量再统一查询 MLP。后者对 GPU 更友好，因为 MLP 查询是稠密矩阵乘，展平后 batch 维度更大、利用率更高；但展平后需要记录每个点属于哪条射线，用于后续的分段求和，这引入索引张量与散射求和（scatter-add）操作。

散射求和的代价常被低估。离散积分要对每条射线的点做前缀累积（透射率 T 的连乘），这在展平布局下需要按射线分组做段内扫描，GPU 上的分段扫描比规则扫描慢，且分组长度不一时分支开销明显。工程上常见的折中是固定每条射线的采样点数，使分组长度一致，用规则重排代替动态分段。

渲染阶段的显存压力与训练不同：推理不需要保存激活，但需要为每条射线保留 N 个点的中间结果以完成积分。高分辨率图像意味着射线数按像素数增长，若一次性渲染整幅图，中间张量会超出显存。分块渲染（tile）是标准做法：把图像切成小块，逐块生成射线、采样、积分、写回。分块的系统代价是块边界处的相机射线参数化要重复计算，且块太小会降低 MLP 查询的 batch 利用率。

多卡训练时的通信量主要来自梯度同步，参数量本身不大，通信不是首要瓶颈；真正的瓶颈是负载不均——不同射线的有效采样区间长度不同，导致各卡的散射求和与积分耗时不一致，出现等待。具体例子：同一 batch 内既有近景密集几何又有远景空区域，近景射线的权重集中、精细采样点多落在表面附近，远景射线大量采样点落在空区，两类的计算路径长度不同，造成卡间不同步。工程判断是优先做射线级负载均衡，而不是加大通信带宽。

五 · 工程坑清单与调参顺序

第一类坑是数值稳定性。透射率 T 是连乘形式，长射线上 σ 累积过大时 T 会下溢到零，之后所有点的贡献都为零，梯度消失。实现上通常用 log 空间累积再取指数，或在累积超过阈值时提前截断射线，把剩余贡献视为零。截断的代价是远处物体的梯度被切断，若场景有远距离结构，截断阈值需要放宽。

第二类坑是采样区间。t_n 与 t_f 由相机近远平面决定，若近平面设得过近，大量采样点落在相机与物体之间的空区，算力浪费；若远平面过远，背景采样稀疏。更隐蔽的是场景尺度与坐标归一化不一致：坐标未归一化时，位置编码的频率与场景尺度错配，导致同一编码级数在不同场景上表现差异巨大。

第三类坑是视角相关颜色的输入。方向向量必须归一化后再做编码，否则方向模长会混入颜色网络，使同一视角在不同距离下给出不同颜色。这是一个典型的实现细节错误，表现为渲染结果随相机距离轻微变色。

调参顺序上，合理的次序是：先固定采样数与网络宽度，把学习率与坐标归一化调到损失稳定下降；再调编码级数，观察训练视角与留出视角的差距，若留出视角明显差于训练视角则降级数；然后调粗/精细采样比例，在显存允许下增大精细点数；最后才动网络深度与宽度。反过来先堆宽度会让采样不足的问题被掩盖，损失下降但细节仍然模糊，误判为容量不够。
