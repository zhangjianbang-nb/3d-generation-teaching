一 · 双分支并行的计算图与复杂度拆解

把跨域法线-颜色扩散落到工程上，第一件事是把“两个扩散分支”画成一张可标注的计算图。输入是参考图与相机位姿序列，输出是同一组位姿下的多视角颜色图与多视角法线图。图中存在三类张量：颜色潜变量、法线潜变量、以及由位姿与参考图编码出的视角条件。两个分支各自持有一套 U-Net 主干（下采样、注意力块、上采样），在每一层通过跨域注意力把一侧的特征注入另一侧。理解复杂度的关键，是分清哪些算力是“按分支线性叠加”的，哪些是“按跨域交互二次增长”的。

设单分支在某一分辨率下的 token 数为 $N$，通道数为 $C$。标准自注意力的计算量为 $O(N^2 C)$，显存占用同样随 $N^2$ 增长。跨域注意力把颜色分支的 $N$ 个 token 作为 query、法线分支的 $N$ 个 token 作为 key/value，其复杂度仍是 $O(N^2 C)$，但它引入的注意力矩阵尺寸为 $N\times N$，与单分支自注意力同阶。于是双分支的总注意力开销近似为单分支的三倍：颜色自注意力、法线自注意力、跨域注意力各一份。这一点在分辨率翻倍时尤为致命，因为 $N$ 随空间尺寸平方增长，注意力矩阵随 $N^2$ 增长，等于随分辨率四次增长。

$$\text{Cost}_{\text{attn}}\approx \underbrace{2N^2C}_{\text{两支自注意力}}+\underbrace{N^2C}_{\text{跨域}},\qquad \text{Mem}_{\text{attn}}\propto 3N^2$$

卷积与归一化部分则是干净的线性叠加：两个分支各有一份主干，参数量与激活值约为单分支的两倍。因此显存翻倍这一“不足”并非笼统说法，而是可以定位到具体来源——主干激活翻倍、注意力矩阵三倍、以及跨域注意力需要同时保留两侧的特征图而不能像单分支那样及时释放。工程上常见的失败模式是：在低分辨率调试时显存尚可，一旦把输出分辨率提到训练配置的上限，跨域注意力层的 $N^2$ 矩阵直接触发 OOM，且报错位置往往在中间层而非最后一层，因为中间层 token 数最多。

一个具体的例子：若在 64×64 的潜空间上做去噪，单分支注意力矩阵是 $4096\times4096$，双分支加跨域就是三份这样的矩阵同时驻留；若切到 128×128，单份变成 $16384\times16384$，三份叠加的显存需求呈十六倍上升。这不是靠调小 batch 能完全缓解的，因为单样本内部的激活就已经越界。可行的机制性对策包括：跨域注意力只在部分层启用（例如只在最低分辨率的瓶颈层做交换）、对跨域注意力采用分块计算、或在时间步上做梯度检查点。每一种对策都对应明确的代价：只在瓶颈层交换会削弱细粒度纹理与几何的耦合；分块计算增加 kernel 启动次数与实现复杂度；梯度检查点用重算换显存，反向传播时间上升。

二 · 显存账本：激活、注意力与优化器状态

把显存拆成四本账更利于定位瓶颈。第一本是模型参数：两个分支的主干参数、视角条件编码器、以及跨域注意力的投影矩阵。第二本是前向激活：每一层下采样与上采样保留的张量，双分支意味着这份账目翻倍。第三本是注意力中间矩阵，即上文的三份 $N^2$。第四本是优化器状态：若使用 Adam 类优化器，每个可训练参数额外携带一阶与二阶动量，参数量翻倍会直接让这部分翻倍。

显存组成随分支数的 scaling主要触发条件典型缓解手段
模型参数约 2×参数量固定，与分辨率无关共享部分主干权重、低秩适配
前向激活约 2×随分辨率与 batch 线性增长梯度检查点、减小 batch
注意力矩阵约 3×随 token 数平方增长限制跨域层数、分块注意力
优化器状态约 2×随可训练参数量线性增长冻结一支、只训跨域层

这张表的意义在于给出调参顺序的依据。很多实现一上来就调低分辨率或砍 batch，但如果瓶颈其实在注意力矩阵，降分辨率确实有效；如果瓶颈在优化器状态，降分辨率毫无帮助，必须减少可训练参数或换用更省状态的优化器。判断方法是：固定分辨率、固定 batch，逐层打印激活峰值，看峰值出现在注意力块还是卷积块；再对比开启与关闭跨域注意力时的峰值差。这个诊断步骤比盲目试参更可靠。

一个具体的系统代价例子：当把跨域注意力从“每层都开”改为“仅瓶颈两层开”时，注意力显存从三份降到接近两份加两个小矩阵，但颜色与法线在高分辨率层的特征不再直接对齐，法线分支的细节纹理开始与颜色分支脱节，表现为法线图在边缘处出现与颜色图不一致的折痕。这说明显存优化不是免费的，它改变的是跨域约束的作用范围。工程判断是：如果下游重建对几何细节敏感，就不能把跨域注意力压得太狠；如果只是把法线当作 LRM 的额外输入通道，瓶颈层交换通常够用。

三 · 伪代码思路：并行去噪与跨域交换的时序

下面用结构化伪代码描述一次前向与一次训练步的组织方式，重点在时序而非具体 API。核心是：两个分支在同一时间步上同步去噪，跨域注意力在每个被选中的层插入，视角条件在进入主干前就已完成编码并被两支共享。

  • 输入：参考图 $I_{\text{ref}}$、位姿集合 $\{P_i\}$、目标视角索引；噪声时间步 $t$ 与对应噪声水平。
  • 编码：视角条件编码器把参考图与位姿编码为条件张量 $c$，颜色分支与法线分支共用同一份 $c$，不各自重算。
  • 初始化：颜色潜变量 $z_c\sim\mathcal{N}(0,I)$，法线潜变量 $z_n\sim\mathcal{N}(0,I)$，两者独立采样但共享同一组目标视角。
  • 循环 $t$ 从高到低：对每个被选中的层 $\ell$，先各自做分支内自注意力，再把 $z_c$ 的 token 作为 query、$z_n$ 的 token 作为 key/value 做跨域注意力，反向亦然（对称交换）。
  • 两支各自预测噪声 $\hat\epsilon_c,\hat\epsilon_n$，按各自调度器更新潜变量。
  • 输出：解码颜色潜变量得多视角颜色，解码法线潜变量得多视角法线；法线经归一化后送入泊松重建或作为 LRM 额外输入。

训练步的组织需要注意损失的分工。颜色分支的监督来自多视角颜色真值，法线分支的监督来自法线真值，总损失是两项加权和。公式中的 $\lambda$ 不是装饰，它控制几何约束相对纹理约束的强度。若 $\lambda$ 过大，法线项主导梯度，颜色分支被拉向几何一致但纹理退化的解；若 $\lambda$ 过小，法线分支学不到有效几何，跨域注意力交换的特征对颜色分支没有约束力。调参顺序上，应先在固定 $\lambda$ 下确认两支各自能单独收敛（即关掉跨域注意力时两支损失都下降），再打开跨域注意力观察总损失是否出现震荡。

$$\mathcal{L}=\mathcal{L}_{\mathrm{color}}+\lambda\mathcal{L}_{\mathrm{normal}},\qquad \mathcal{L}_{\mathrm{normal}}=\|\hat{n}-n\|^2$$

这里 $\hat{n}$ 是预测法线，$n$ 是真值法线，二范数平方逐像素求和。注意法线是单位向量，直接做 L2 回归会让网络倾向于输出幅值偏小的向量以降低误差，工程上通常会在损失前对 $\hat n$ 做归一化，或在推理后强制归一化。这个细节不属于算法核心，但属于实现坑：不做归一化时，法线图看起来“灰蒙蒙”，泊松重建出的表面法向偏软。一个具体失败模式是：训练损失下降良好，但重建结果的表面出现整体倾斜，追查后发现是法线幅值未归一导致积分时方向被系统性缩放。

四 · 通信与并行：多卡切分时的跨域耦合

双分支结构在多卡训练时引入一个单分支没有的问题：跨域注意力天然要求颜色 token 与法线 token 在同一设备上或可高效互换。若按分支切分——一张卡跑颜色、一张卡跑法线——那么每一层跨域注意力都要做一次 all-to-all 或 all-gather，把另一侧的 token 拉到本地。这个通信量与 $N\times C$ 成正比，且在每个被选中的层都要发生一次，层数越多通信越频繁。

若按空间切分——每张卡持有同一视角下的一部分 token——那么跨域注意力可以在本地完成一部分，但全局注意力仍需跨卡聚合，通信模式与标准序列并行类似。两种切法的代价不同：按分支切分实现简单但通信集中且与层数线性相关；按空间切分通信更均匀但对注意力的分块实现要求更高。工程判断是：当跨域层数少（只在瓶颈）时，按分支切分可接受；当跨域层数多时，按空间切分更稳。

一个具体的通信代价例子：假设瓶颈层 token 数为 $N$、通道 $C$，按分支切分时每层跨域注意力需要把 $N\times C$ 的法线特征传到颜色卡，反向再把颜色特征传到法线卡，一个训练步内若跨域层有 $L$ 层，则通信量为 $2LNC$ 量级。当 $L$ 从 2 增到 8，通信量翻四倍，而计算量只增了跨域注意力那部分，于是训练从计算受限转为通信受限，GPU 利用率下降。这个转折点可以通过 profiler 观察到：跨域层增加后，计算 kernel 的占用率不升反降，等待通信的时间上升。

另一个系统代价是视角条件的共享。由于两支共用同一份条件编码，条件编码器只需算一次，这节省了计算但也形成耦合：若条件编码有误（例如位姿标定偏差），误差会同时污染颜色与法线两支，且跨域注意力会把这种污染在两支间来回放大。失败模式表现为：多视角输出整体出现一致的视角偏移，颜色与法线同步偏移，看起来像“两支都学错了”，实则是共享条件的单点故障。缓解手段是在条件编码后加一层轻量校验或在训练时对位姿做扰动增强，让两支对条件误差有一定鲁棒性。

五 · 工程坑清单与调参顺序

把已知的不足逐条翻译成可操作的工程坑，比泛泛而谈更有用。第一条坑是法线估计本身的误差。法线分支不是几何真值生成器，它从参考图与位姿推断法线，参考图里没有看到的区域其法线是外推的。跨域注意力会把这种外推误差当作约束传给颜色分支，导致颜色分支在不可见区域被“几何上合理但纹理上错误”的法线牵着走。表现为：新视角合成时，被遮挡区域的颜色出现与法线一致的块状结构，而不是平滑的纹理延续。

  • 坑一：法线幅值未归一，重建表面系统性偏软或倾斜。
  • 坑二：跨域注意力层数过多，显存与通信同时越界，训练转为通信受限。
  • 坑三：$\lambda$ 设置过大，颜色纹理退化；过小则几何约束失效。
  • 坑四：共享视角条件单点故障，位姿误差同步污染两支。
  • 坑五：两支独立采样噪声，早期时间步跨域交换的是近乎纯噪声，交换无信息量，浪费算力。
  • 坑六：法线解码后未做视角一致性检查，多视角法线在重叠区出现折痕，泊松重建把这些折痕积分为真实几何误差。

坑五值得展开：扩散早期 $t$ 接近最大值时，两支潜变量都接近纯噪声，此时跨域注意力交换的特征主要是噪声统计，对一致性没有贡献。工程上可以在时间步调度里让跨域注意力只在 $t$ 低于某个阈值后启用，把早期步的算力省下来。代价是实现上需要条件分支，且阈值选错会让两支在中期失去对齐机会。这个阈值不是超参玄学，它对应的是“噪声水平降到特征开始携带结构信息”的时间点，可以通过观察两支中间特征的相关性随 $t$ 的变化来定。

调参顺序应当是：先固定单分支能收敛，再开跨域注意力并只放在瓶颈层，确认总损失不震荡；然后逐步增加跨域层数，同时监控显存峰值与通信占比，找到计算受限转通信受限的拐点；再调 $\lambda$，以重建质量为判据而非训练损失；最后处理法线归一化与视角一致性后处理。这个顺序的依据是每一层调参都建立在前一层稳定的基础上，避免多个变量同时变动导致无法归因。一个具体例子：若先调 $\lambda$ 再开跨域注意力，$\lambda$ 的最优值会在跨域开启后失效，因为跨域交换改变了梯度在兩支间的分配，必须重调。

视角一致性仍不完美这一不足，在系统层面表现为多视角法线在重叠区的折痕。跨域注意力提供的是特征级约束，不是显式的多视角几何一致性损失，因此重叠区仍可能出现法线方向的小幅不一致。工程上可以在输出后加一步基于重叠区的法线融合，或把法线作为 LRM 的额外输入让下游网络自己消化不一致。判断依据是下游任务：若做泊松重建，折痕会被积分放大，必须在融合阶段处理；若只做 LRM 输入，网络对小幅不一致有一定容忍度，可以省掉融合步骤。

六 · 从系统代价反推设计取舍

把上述复杂度、显存、通信与坑位放在一起，可以反推几个设计取舍的边界。第一，跨域注意力的放置位置决定了显存与约束强度的权衡：瓶颈层交换省显存但只约束全局结构，多层交换约束细粒度但显存与通信同时上升。第二，两支是否共享主干权重是一个未被给定事实明确的方向，但共享会减少参数量与优化器状态，代价是两支的特征表达被强制同构，颜色与法线本应解耦的纹理与几何可能互相干扰。第三，$\lambda$ 与跨域层数存在耦合：跨域层少时 $\lambda$ 需要偏大才能让法线信息有效传入颜色分支，跨域层多时 $\lambda$ 偏大反而让颜色分支过约束。

一个具体的机制性判断：当显存是硬约束时，优先砍跨域层数而不是砍分辨率。砍分辨率会同时降低颜色与法线的输出精度，且注意力矩阵随分辨率四次增长，砍分辨率的显存收益大但质量损失也大；砍跨域层数只损失部分跨域约束，颜色与法线的分辨率得以保留，法线仍可作为 LRM 输入使用。这个取舍的依据是下游重建对分辨率的敏感度高于对跨域层数的敏感度，因为泊松重建需要足够密的法线采样，而跨域层数主要影响两支的对齐精度。

最后落在通信与计算的拐点上：当跨域层数增加到使通信时间超过跨域注意力的计算时间时，继续加层不再提升一致性，只增加等待。工程上应把跨域层数停在这个拐点之前，并用 profiler 确认计算 kernel 仍占主导。这个拐点不是固定值，它随 GPU 互联带宽、token 数与通道数变化，因此每次换硬件或换分辨率都需要重新测。把拐点作为配置项而非拍脑袋的常数，是这类双分支扩散系统能否稳定训练的关键。
