一 · 双分支的算力账本：分辨率决定谁贵

把形状 DiT 与材质 DiT 放进同一套训练预算里看，第一个反直觉的结论是：贵的那一支通常不是参数量大的那一支，而是 token 数多的那一支。形状分支在 VecSet 或稀疏体素上做扩散，其 token 数量随目标几何分辨率的三次方（体素）或二次方（表面采样）增长；材质分支在 UV 空间做扩散，token 数量只随贴图边长平方增长，但通道数从 1 变成 3（反照率、粗糙度、金属度）。注意力的计算量按 token 数的平方走，因此形状分支一旦把有效分辨率推高一档，注意力开销就按四倍量级上升，而材质分支推高一档贴图边长只按四倍线性增长。这解释了为什么两个分支必须独立设定宽度与深度：共享一套超参会强制其中一支在错误的规模上运行。

用公式表达单步前向的主要项。设形状分支有效 token 数为 \(N_s\)、隐藏维 \(d_s\)、层数 \(L_s\)；材质分支 token 数 \(N_m\)、隐藏维 \(d_m\)、层数 \(L_m\)。注意力主导项近似为：

$$\mathcal{C}\approx 4\sum_{l=1}^{L_s}N_s^2 d_s+4\sum_{l=1}^{L_m}N_m^2 d_m+\underbrace{2(N_s d_s^2 L_s+N_m d_m^2 L_m)}_{\text{FFN 与投影}}$$

在典型配置下 \(N_s\) 远大于 \(N_m\)，第一项压过其余项，于是“形状分辨率”成为整个系统的总算力瓶颈。工程上的直接后果是：调形状分支的分辨率必须与批大小联动，而调材质分支的贴图边长几乎可以独立进行，因为它对总算力的边际贡献小。做 scaling 实验时若把两支绑在一起扫参，得到的曲线会被形状分支主导，材质分支的真实 scaling 行为被掩盖。

失败模式出现在分辨率与批大小的错配。形状分支 token 数上升后若不同步降批，单卡显存会在注意力中间张量上爆掉，表现为前向尚可、反向在注意力梯度处 OOM；反过来，若为了塞进显存把批降到很小，稀疏体素上的有效监督信号变稀，SDF 在薄壁与细杆处出现阶梯状伪影。具体例子：一个带细长把手的杯状物体，把手厚度只占几个体素，批太小导致这些体素在多数步中不被任何样本覆盖，Marching Cubes 抽出的网格在把手处断裂。这不是模型容量问题，而是采样密度问题。

二 · 显存分布与激活重算的取舍

显存占用可以拆成三块：参数与优化器状态、激活、以及扩散采样时的中间缓存。参数块由两支各自的宽度决定，通常不是主要矛盾；激活块由 \(N_s\) 与批大小决定，是主要矛盾；采样缓存则是形状分支特有的负担——稀疏体素扩散在去噪循环中要保留每一级的稀疏索引结构，索引本身是整型张量，随分辨率上升而膨胀，且不像浮点激活那样容易用重算换显存。

激活重算（gradient checkpointing）在这里的收益不对称。对材质分支，重算几乎无损，因为它的层数浅、token 少，重算的额外前向开销占比小；对形状分支，重算能显著压低峰值显存，但代价是反向多一次前向，而形状分支的前向本身就贵，于是总步时上升明显。工程判断是：形状分支用重算换批大小，材质分支不用重算、直接吃满显存。这个不对称策略比全局统一开重算更划算，因为全局开会让材质分支白白付出重算时间。

稀疏索引带来的另一个坑是显存碎片。稀疏体素在不同样本间的有效体素数差异很大，若按批内最大体素数分配张量，短样本浪费大量显存；若用变长打包，反向时的索引聚合又会产生不规则访存。实践中常见做法是按体素数分桶，同桶内成批，桶间串行。代价是桶边界处的批大小偏小、GPU 利用率下降，且桶的划分本身是一个需要调的超参——桶太细则串行开销大，桶太粗则浪费显存。这个调参项在论文里通常不写，但在实现里绕不过去。

具体例子：一个场景里同时有简单方块与带镂空花纹的薄片，两者体素数差一个量级。不分桶时批大小被薄片拖死；分桶后薄片桶的批很小，梯度噪声大，SDF 在花纹边缘抖动。缓解手段是对薄片桶单独调低学习率或增大梯度累积步数，把有效批补回来。

三 · 伪代码思路：两段式训练循环

两支独立训练意味着训练循环不是单一前向反向，而是按阶段切换的数据管线。形状阶段吃图像条件与几何监督，材质阶段吃图像条件、已展开的 UV 与材质监督。伪代码思路如下，重点在阶段切换处的数据依赖：

  • 阶段 A：采样图像条件 \(c\)，编码为条件 token；形状 DiT 在稀疏体素上做前向去噪，预测 SDF 残差；损失为 SDF 回归项加表面法向一致性项；反向只更新形状分支参数。
  • 阶段 B：冻结形状分支，对每个样本跑完整去噪得到 SDF，Marching Cubes 抽网格，做 UV 展开，把 UV 与网格法向一起作为材质分支的几何条件；材质 DiT 在 UV 网格上扩散三通道 PBR；损失为 \(\mathcal{L}_{\mathrm{PBR}}\) 加渲染损失。
  • 阶段 C（可选联合微调）：两支同时前向，渲染损失通过可微渲染器回传到材质分支，形状分支只接收几何项梯度，避免渲染梯度污染 SDF。

伪代码的关键判断是阶段 B 里“冻结形状分支”不是可选项而是必需项。若在材质训练时让渲染损失回传形状分支，渲染器对几何的梯度会把 SDF 往“看起来好看”而非“几何准确”的方向拉，典型表现是薄结构被加厚以改善阴影、凹槽被填平以减少自遮蔽。这是渲染损失与几何监督的目标冲突，必须在梯度层面隔离。

系统代价出现在阶段 B 的串行性：每个样本都要先跑完整形状去噪才能开始材质训练，形状分支的采样步数直接乘以材质阶段的数据准备时间。若形状采样用几十步，材质阶段的实际吞吐被数据准备卡住，GPU 在等 UV 展开。缓解是把形状采样结果缓存成离线数据集，材质阶段从缓存读，代价是缓存占存储且形状分支更新后缓存失效、需要重跑。这是一个典型的“用存储换吞吐”的工程折中，缓存失效的判定粒度（按检查点还是按步）决定了重跑频率。

失败模式：UV 展开在拓扑复杂处失败，展开后出现重叠岛或拉伸。重叠岛会让材质分支在同一 UV 坐标上收到冲突的监督信号，反照率出现鬼影；拉伸则让纹素密度不均，粗糙度在高频区域糊成一片。具体例子：带多个穿孔的薄壳，展开算法把两个孔之间的窄桥压成一条缝，材质在此处的金属度在训练中被平均成中间值，渲染时出现不自然的半金属条带。

四 · 通信与数据流：条件共享但不共享梯度

两支共享图像条件，但条件的编码方式可以不同：形状分支需要的是全局形状先验，材质分支需要的是与 UV 对齐的局部纹理线索。若两支跑在不同 GPU 上，条件编码器要么各算一遍（冗余计算但无通信），要么算一遍后广播（省算力但引入通信）。在单机多卡下广播的代价通常小于重算，因为条件编码器相对两支主干很小；在多机下则要权衡链路带宽。

更隐蔽的通信开销来自渲染损失。渲染需要网格、UV、PBR 三样东西同处一卡，而形状分支与材质分支可能分处不同卡。此时要么把网格与 UV 传到材质卡（传输量随网格面数增长），要么把 PBR 传回形状卡再渲染（传输量随贴图分辨率增长）。面数与贴图分辨率的相对大小决定哪条路更省：高模低贴图时传 PBR 更省，低模高贴图时传网格更省。这个选择在实现里往往写死，但在分辨率配置变化后就不再最优。

同步点也是坑。若两支在同一优化器步里联合更新，梯度同步的屏障会让快的一支等慢的一支，而两支的计算量本就不对称，等待浪费明显。异步更新能消除等待，但会引入两支参数版本不一致：材质分支用的几何来自旧版形状分支，渲染损失的梯度指向旧几何，更新后的形状分支已不匹配。工程上常见的折中是按固定步数比更新，比如形状分支每更新若干步、材质分支才跟一次，把版本偏差控制在可接受范围内，代价是收敛曲线出现周期性抖动。

具体例子：形状分支因分辨率高而单步慢，材质分支单步快，同步更新时材质卡大量空转。改为按步数比更新后，材质分支的有效学习率需要相应放大以补偿更新次数减少，否则材质收敛明显滞后于形状，合成资产的材质细节跟不上几何精度。

五 · 调参顺序：先几何后材质，先分辨率后容量

调参顺序错了会让实验结论互相污染。合理的顺序是：先把形状分支的几何质量调到可用，再动材质分支，最后才做联合微调。原因是材质分支的输入依赖形状分支的输出，几何不准时材质再怎么调也是在错误的 UV 上拟合，调出来的超参在几何改善后全部作废。

形状分支内部的顺序是分辨率优先于容量。先把有效分辨率推到目标档位，观察 SDF 在薄结构与凹槽处的表现，再决定是否加宽加深。反过来先加容量后提分辨率，会得到“参数够但采样不够”的假象：模型容量足以表达细节，但稀疏体素的采样密度撑不住，细节被抹平，于是误判为容量不足继续加宽，浪费算力。判定方法是固定容量只提分辨率，看几何指标是否还有增益；若增益消失而损失仍在降，才是容量瓶颈。

材质分支内部的顺序是监督信号优先于网络规模。\(\mathcal{L}_{\mathrm{PBR}}\) 的三项权重 \(\lambda\) 与渲染损失的相对大小，直接决定材质是“数值准”还是“看起来对”。三项等权时反照率主导（因其动态范围大），粗糙度与金属度被压制，渲染出现塑料感；渲染损失过大时材质向视觉讨好的方向漂移，PBR 数值偏离真实分布，进引擎后光照响应不对。调参应从纯监督项起步，确认三通道各自收敛，再逐步加渲染损失并观察数值偏移。

联合微调阶段的坑是学习率重置。两支独立训练时各自收敛到局部最优，联合时若沿用各自末端学习率，形状分支的几何项梯度会与渲染回传的材质梯度在共享条件编码器处打架，条件表示被两边拉扯。做法是联合阶段把条件编码器的学习率单独调低，让两支主干在冻结的条件表示上适配。具体例子：联合后反照率在物体边缘出现与几何轮廓不符的色晕，根因是条件编码器被材质梯度带偏，边缘的形状线索被纹理线索覆盖。

最后落在工程判断上：这套双 DiT 的系统成本不在单支的算力，而在两段管线之间的数据依赖与梯度隔离。形状分支的分辨率决定总算力上限，材质分支的监督权重决定资产能否直接进引擎，而 UV 展开的失败率是整条管线最不可控的一环——它既不在两支的损失函数里，也无法通过调参消除，只能在数据侧做拓扑预检与失败样本剔除。
