一 · 序列长度从哪里来：面片数、邻接度与 BPE 的实际账

把网格当语言建模，第一笔系统账不是模型参数，而是序列长度。DFS 遍历按面片邻接关系展开，序列的原子单位是一个面片 token 组：顶点坐标量化值加上邻接面索引。设网格有 F 个面片，每个面片平均邻接度为 d（三角网格内部面片通常邻接三个面，边界处更少），则原始 token 数近似为 F·(c+d)，其中 c 是坐标量化后的 token 数。BPE 压缩把这个数压到 F·r，r 是每面片平均剩余 token 数，r 随网格规则性变化：规则栅格状网格的邻接模式重复度高，BPE 合并收益大；扫描重建或雕刻产生的非规则网格邻接模式杂乱，合并收益小。工程上必须把 r 当作数据集的统计量来测，而不是当作常数。

$$L \approx F \cdot r,\qquad \text{cost}_{\text{attn}} \propto L^2 d_{\text{model}},\qquad \text{cost}_{\text{mem}} \propto L \cdot d_{\text{model}}$$

这条式子决定了三件事。第一，自注意力的计算量随 L 平方增长，而 L 正比于面片数，所以高面片数网格在训练时是二次惩罚。第二，激活显存随 L 线性增长，但反向传播要保存每层注意力中间量，实际峰值显存对 L 的敏感度高于线性。第三，KV 缓存随生成长度线性增长，推理阶段每生成一个面片就要多存一组键值，长网格生成时缓存会成为瓶颈而不是权重。

具体例子：一个由若干规则四边形区域组成的部件级网格，面片邻接模式高度重复，BPE 可以把每面片的坐标与邻接 token 合并成少量复合 token，序列被压得较短；而一个带大量三角扇和细碎倒角的雕刻件，邻接索引分布散乱，BPE 词表里难以形成高频复合模式，同样面片数下序列明显更长。两者在同一个 batch 里混训时，长序列样本会主导显存峰值和注意力计算，短样本被 padding 浪费。这是第一个工程坑：按面片数分桶而不是按文件大小分桶，否则 batch 内长度方差过大。

二 · 量化与词表的耦合：坐标精度、邻接索引与词表膨胀

每个面片编码为 t_i = quantize(v_i, N_i)，其中 v_i 是顶点坐标，N_i 是邻接面索引。量化不是独立环节，它直接决定词表结构和序列长度。坐标量化通常把连续坐标映射到固定栅格，栅格分辨率越高，坐标 token 的种类越多，词表越大，嵌入层和输出 softmax 的参数量与计算量随之上升。邻接面索引则是一个局部编号问题：如果索引是全局面片 ID，词表会随网格规模膨胀，且同一邻接模式在不同网格里编号不同，BPE 无法跨样本复用；如果索引是相对当前面片的局部偏移（例如“父面片、左邻、右邻”之类的角色编码），词表被压到很小的固定集合，邻接模式可以跨网格共享，但代价是解码时必须维护已生成面片到局部角色的映射，遍历顺序一旦偏离 DFS 约定，角色编码就会歧义。

系统代价在这里体现为词表规模与序列长度的权衡。全局索引方案词表大、序列短（一个索引一个 token），但嵌入矩阵和 softmax 的分母变大，训练时输出层成为计算热点；局部角色方案词表小、泛化好，但每个面片需要更多 token 来描述其邻接关系，序列变长，注意力成本上升。工程判断是：部件级、拓扑规整的数据集偏向局部角色编码，因为跨样本复用带来的数据效率收益大于序列变长的代价；面片数多、拓扑杂的数据集偏向受限的全局索引加 BPE，因为序列长度已经是主要瓶颈。

量化损失是第二个失败模式。坐标量化到栅格后，顶点落在栅格点附近而非精确位置，细小的倒角、薄壁和锐利边缘在量化后被抹平。更隐蔽的问题是量化误差在 DFS 链上累积：每个面片的顶点坐标独立量化，相邻面片共享的顶点如果被量化到不同栅格点，重建时会出现裂缝或非流形边。解决办法是在量化前做顶点去重与共享索引，让共享顶点只量化一次，面片 token 引用顶点 token 而不是重复写坐标。这会把序列结构从“每面片自带坐标”改成“顶点表 + 面片引用”，序列变短但引入了间接寻址，解码器必须在生成面片时同步维护顶点表，自回归的因果性要求顶点先于引用它的面片出现，DFS 顺序恰好满足这一点，但一旦采样偏离 DFS，顶点表就可能被引用到尚未生成的位置。这是实现中最容易踩的坑之一。

三 · 伪代码思路：DFS 展开、量化打包与训练循环

把流程写成伪代码，重点是三个数据结构的生命周期：面片邻接图、DFS 栈、以及 token 缓冲。邻接图在预处理阶段构建，每个面片记录其邻接面列表；DFS 从任一面片出发，用显式栈而不是递归，避免深网格爆栈。遍历时对每个面片做两件事：量化其顶点坐标（或查顶点表），把邻接面按局部角色排序后编码。排序必须确定，否则同一网格两次预处理得到不同序列，训练数据不可复现。

伪代码思路如下：输入网格，构建面片邻接表；选种子面片，压栈；循环弹出面片，若未访问则标记访问，输出该面片的坐标 token 与按固定角色顺序排列的邻接 token；把未访问的邻接面压栈；遍历结束后对 token 序列跑 BPE 合并；把压缩后的序列加起始/结束标记写入训练样本。训练时 decoder-only Transformer 以标准下一 token 预测为目标，损失对每个 token 计算，但工程上通常对坐标 token 和邻接 token 加权，因为邻接 token 的预测错误会直接破坏拓扑，而坐标 token 的误差只影响几何细节。

系统代价出现在 BPE 与自回归的耦合上。BPE 合并是在完整序列上做的，合并后的 token 跨越了面片边界，一个复合 token 可能同时包含上一个面片的邻接索引和下一个面片的坐标。这破坏了“每面片一组 token”的对齐，使得按面片做掩码或加权变得困难。工程上的折中是：BPE 只在面片内部做合并，禁止跨面片合并，保证 token 组边界清晰，代价是压缩率下降，序列比全局 BPE 长。另一个代价是采样阶段的约束解码：生成邻接 token 时必须限制在合法角色集合内，否则会生成指向不存在面片的索引，导致拓扑断裂。约束解码需要在每一步对 logits 做掩码，掩码表随已生成面片状态变化，实现上是一个状态机，而不是静态词表掩码。

具体例子：生成一个带孔洞的部件时，DFS 走到孔洞边界，邻接角色里出现“边界”这一特殊标记，模型必须学会在边界处停止向该方向扩展。如果训练数据里边界样本少，模型会在边界处生成非法邻接索引，解码器要么丢弃该 token 重新采样，要么接受一个非流形结果。前者拖慢生成速度，后者污染输出。这就是为什么邻接 token 的损失权重和约束解码的严格程度需要一起调，而不是分开调。

四 · 显存与通信：长序列训练的分块、梯度检查点与多卡切分

训练阶段的显存由四部分组成：权重、优化器状态、激活、以及注意力中间量。权重和优化器状态对 L 不敏感，激活和注意力中间量随 L 增长。对长网格样本，单卡放不下一个长序列的完整激活，标准做法是梯度检查点：前向时不保存中间激活，反向时重算。代价是计算量增加，重算比例取决于检查点粒度，按层检查点重算整层前向，按 token 块检查点重算块内前向。对网格序列，按面片组做检查点比按固定 token 数更自然，因为面片组是语义边界，重算时不会切断一个面片的 token 组。

多卡训练时，序列并行比张量并行更直接：把长序列切成分段，每张卡持有一段，注意力需要跨段通信。标准注意力在段边界处需要交换键值，通信量与段数乘以隐藏维度成正比。对网格序列，切分点应落在面片组边界，否则一个面片的坐标与邻接 token 被分到两张卡上，跨卡注意力的语义对齐会变复杂。另一种做法是样本并行加梯度累积：每个卡处理不同网格，长样本单独成 micro-batch，短样本拼批。这避免了序列切分的通信开销，但要求数据加载器按长度分桶并做动态批处理，否则短样本等待长样本，GPU 利用率被拉低。

推理阶段的显存瓶颈是 KV 缓存。自回归逐面片生成，每步追加一组键值，缓存大小随已生成面片数线性增长。对长网格，缓存可能超过权重本身。工程手段是缓存量化与分页：把历史键值量化到低精度，或按面片组分页换出到主机内存。代价是每次注意力计算要反量化或换入，延迟上升。另一个手段是限制生成长度上限，超过上限就截断或回退，这直接对应算法“长网格难生成”的不足，工程上表现为生成质量在超过某个面片数后明显下降，而不是突然失败。

具体例子：一个面片数较多的网格在单卡上训练时，激活显存峰值出现在注意力层，梯度检查点把峰值压到可接受范围但训练步时变长；换到多卡序列并行后，通信成为新的瓶颈，尤其是段边界处的键值交换。调参顺序应该是先定序列切分策略，再定检查点粒度，最后调 batch 组成，因为切分策略决定了通信模式，检查点粒度决定了计算冗余，两者都影响单步时间，而 batch 组成只影响利用率。

五 · 工程坑与调参顺序：从数据预处理到采样约束

第一个坑是 DFS 种子与遍历顺序的不确定性。同一网格从不同种子出发得到不同序列，如果预处理没有固定种子策略，训练集里同一网格的多个变体会被当成不同样本，浪费数据且让模型学到顺序无关的假象。固定策略可以是“选面片 ID 最小者”或“选邻接度最大者”，后者倾向于从稠密区域开始，序列前段信息密度高，但可能让边界区域集中在序列尾部，增加长程依赖难度。

第二个坑是邻接索引的合法性。DFS 遍历时，邻接面可能尚未访问，也可能已访问。编码时必须区分“未访问的邻接面”和“已访问的邻接面”，否则解码器无法判断该角色是否还能扩展。常见做法是用特殊标记表示“该方向已访问”或“该方向不存在”，把邻接 token 变成三态而非二态。这会增加词表但减少非法生成。

第三个坑是 BPE 词表与量化栅格的耦合。坐标量化栅格改变后，坐标 token 分布改变，原 BPE 词表的合并规则失效，必须重新训练 BPE。工程上把量化栅格和 BPE 词表版本绑定，任何一方变更都触发全量预处理，否则训练样本里混着两套 token 语义，模型学到矛盾的模式。

调参顺序建议如下。先定量化栅格与邻接编码方案，因为它们决定词表和序列长度，是后续所有系统参数的基础。再定 BPE 合并范围（面片内还是全局）与序列长度上限，长度上限由显存预算反推。然后定 batch 分桶策略与梯度检查点粒度，使单步时间与显存都在预算内。接着定损失权重（坐标 vs 邻接）与约束解码严格度，这两者一起影响生成拓扑质量。最后调采样温度与回退策略，因为前三步决定了模型能生成什么，采样只决定从分布里取哪个样本。

最后一个具体机制层面的判断：网格序列化的系统成本主要由序列长度和邻接合法性检查两件事决定，前者是注意力的二次成本，后者是解码状态机的实现复杂度。工程上不应把这两件事分开优化，因为压缩序列的 BPE 策略会改变面片组边界，而面片组边界正是约束解码状态机的状态转移依据。任何压缩率的提升都要重新验证约束解码的合法性覆盖率，否则省下的显存会被非法生成的重采样抵消。
