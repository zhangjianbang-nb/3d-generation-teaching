一 · 一句话：把重建从优化问题挪到推断问题

LRM 的核心主张可以压成一句可执行的话：给定一张图像 I 与相机参数 c，用一次前向的 Transformer 直接回归出三平面 T，再让 T 经体渲染产生多视角图像，用渲染结果与真值的差异来训练这个回归器。这句话里每个词都有工程后果。“一次前向”意味着推理阶段不存在逐场景的迭代优化循环，没有每场景几百上千步的梯度下降，也没有针对单场景的可学习参数；“回归出三平面”意味着网络的输出不是点云、不是网格、不是隐式函数的权重，而是一组固定形状的张量；“用渲染损失训练”意味着监督信号不落在 3D 几何上，而落在 2D 图像上。三者合起来，把传统意义上“重建”这个逆问题，改写成了“预测”这个前馈映射问题。

要看清这个改写的分量，需要对照它替代的对象。经典的三平面重建流程是：给定稀疏视角输入，初始化三个特征平面，定义体渲染算子，然后在每个场景上最小化渲染图与输入图的差异，反复迭代直到收敛。这个流程的代价结构是“每场景一份”。LRM 把这份代价搬到训练阶段一次性支付：在大量物体上学习一个映射，推理时只做一次函数求值。于是单场景成本从“优化步数 × 每步渲染开销”变成“一次前向的浮点运算量”，而泛化能力则完全押注在训练分布上。这不是免费的午餐，而是把成本在时间轴和场景轴之间做了重新分配。

从信息论角度，这个映射是欠定的：单张图无法唯一确定物体的背面与内部。LRM 并不试图消除这种欠定性，而是用数据先验去填充它。网络在训练集上见过大量物体后，学会了“这类正面轮廓通常对应那样的背面结构”的统计规律。因此 LRM 的输出严格说不是“重建”，而是“在给定先验下的最可能三平面”。这一点决定了它的失效边界：当输入物体落在训练分布之外，先验不再成立，输出会退化为看似合理但几何错误的形状。理解 LRM 的第一步，就是接受它是一个条件生成模型，而不是一个几何求解器。

二 · 严格定义：映射、表示与损失三件套

把上面那句话形式化，LRM 定义为一个参数化映射：

$$\mathbf{T}=\mathrm{Transformer}_\theta(I,\mathbf{c}),\qquad \mathcal{L}=\sum_{v}\left\|\mathrm{VolumeRender}(\mathbf{T},\mathbf{c}_v)-I_v\right\|^2$$

这里 θ 是 Transformer 的全部权重，I 是输入图像，c 是输入相机参数，T 是三平面表示，cv 与 Iv 是训练时采样的第 v 个监督视角及其真值图像。映射的定义域是“图像 + 相机”，值域是三平面张量；损失的定义域是“渲染图与真值图的对”，值域是标量。注意损失里没有出现任何 3D 监督项：没有 Chamfer 距离，没有 SDF 回归，没有体素交叉熵。唯一的监督来自 2D 渲染，这是整个方法可扩展性的来源——多视角图像比 3D 几何标注便宜得多，也更容易大规模采集或渲染。

三平面本身需要严格交代。它是三个正交的特征平面，通常记为 XY、XZ、YZ 三个 64×64 的二维网格，每个格点带一个 32 维特征向量。查询任意三维点 p=(x,y,z) 时，把 p 投影到三个平面上做双线性采样，得到三个特征向量，再按某种方式聚合（拼接后过一个小 MLP，或直接相加）成该点的特征。这个表示的关键性质是可微：双线性插值对坐标的梯度存在且良定义，因此渲染出的像素值对平面特征的梯度可以一路回传。没有这个性质，渲染损失就无法训练编码器。三平面的分辨率与特征维度共同决定了表达上限：64×64×32 的三个平面总参数量是 3×64×64×32，相对紧凑，但空间分辨率固定，细粒度几何会被量化。

Transformer 的角色是把图像 token 分配到三平面 token。输入图像经 ViT 切成 patch token，例如 512×512 图像经 DINO ViT 得到 1024 个 token；这些 token 作为 cross-attention 的 key 与 value，三平面被展平成的 token 序列作为 query。24 层解码后，query 序列被重塑回 3×64×64×32 的三平面张量。cross-attention 在这里的语义是“每个 3D 特征位置从图像特征里取什么信息”，等价于学习一个从图像特征空间到 3D 特征空间的映射。相机参数 c 通过位置编码或条件注入参与这个过程，使网络知道图像是从哪个视角拍的，从而把 2D 证据放到正确的 3D 位置上。

训练流程可以写成如下伪代码思路：

  • 前向：tokens = vit(img)，tri = transformer(tokens, cam)，返回三平面。
  • 损失：对每个监督视角 (c, I)，计算 mse(volume_render(tri, c), I) 并求和。
  • 反传：梯度穿过体渲染算子回到三平面，再穿过 cross-attention 回到 ViT 与 Transformer 权重。

这里有一个容易忽略的工程细节：体渲染算子必须对三平面可微，且渲染时的采样点数量、深度范围、重要性采样策略都会影响梯度的方差。渲染 16 个视角意味着每次训练前向要做 16 次体渲染，这是训练成本的主要来源之一。推理时则只需一次 Transformer 前向加一次（或几次）体渲染，不需要多视角监督循环。

三 · 为什么需要：逐场景优化的三笔账

要理解 LRM 为什么值得存在，得把逐场景优化的账算清楚。第一笔是时间账。逐场景优化要为每个新物体重新跑一遍迭代，迭代次数取决于场景复杂度与初始化质量，且没有跨场景复用。第二笔是算力账。每次迭代都要做体渲染与反传，渲染分辨率、采样密度、视角数量都直接乘在单步成本上；场景越多，总成本线性增长。第三笔是工程账。逐场景优化需要为每个物体保存一份优化状态，流水线里存在串行的“优化—导出”阶段，难以批量并行，也难以放进低延迟的在线服务。三笔账叠加，使得逐场景优化在大规模资产生产场景里成为瓶颈。

LRM 的交换条件是：把这三笔账在训练阶段一次性付清。训练时要处理大量物体、每个物体多个视角、每个视角一次体渲染，成本确实高；但训练是一次性的，推理是摊销的。推理时一次前向出三平面，单场景延迟从“迭代收敛时间”降到“一次网络前向时间”。给定事实里提到，50 万物体训练后推理约 10 秒——这个数字的量级说明它不是毫秒级服务，但已经脱离了“每场景几分钟到几十分钟优化”的范畴。更重要的是，推理可以批量并行：一批图像进网络，一批三平面出网络，没有场景间的串行依赖。

还有一笔隐性收益：监督信号的可扩展性。逐场景优化只需要输入视角，不需要 3D 真值，但它的质量受限于输入视角的覆盖；LRM 用多视角渲染损失训练，监督来自大量物体的多视角图像，这些图像可以来自渲染管线，成本远低于人工 3D 标注。于是训练集规模可以推到几十万物体量级，而这是逐场景优化完全无法利用的资源。换句话说，LRM 把“每个场景单独求解”换成了“在大量场景上学习一个先验”，用数据规模换单场景成本。

代价同样明确。第一，泛化被训练分布锁死：背面细节靠数据先验，训练集里没见过的结构类型，网络没有理由预测正确。第二，输出受固定分辨率限制：三平面是 64×64 网格，网格提取有分辨率损失，细薄结构、锐利边缘会在量化中丢失。第三，训练成本高：50 万物体、每物体多视角、24 层 Transformer、16 次体渲染，这是一笔实打实的训练预算。第四，推理不是零成本：一次前向加体渲染仍需约 10 秒量级，对延迟敏感的场景要另做蒸馏或缓存。这些代价不是实现缺陷，而是方法定位的直接后果。

四 · 常见误解之一：它不是“多视角立体”的加速版

第一个常见误解是把 LRM 当成多视角立体（MVS）的神经网络加速版：以为它还是在做三角测量，只是用网络替代了手工匹配。这个理解错在监督信号的位置。MVS 的监督或约束落在几何一致性上——特征匹配、极线约束、深度图融合，最终通过显式几何计算得到点云或网格。LRM 的监督落在渲染图像上，网络内部是否形成了可解释的匹配关系并不重要；cross-attention 学到的是“哪个图像 token 对哪个 3D 位置有用”，这是一种任务驱动的特征路由，不是几何测量。因此 LRM 可以在输入视角极少（单张图）时工作，而 MVS 在单张图上是欠定的。

这个区别有具体的机制后果。MVS 的失败模式通常是纹理缺失区域的匹配歧义、重复纹理的误匹配、遮挡边缘的深度不连续；LRM 的失败模式则是先验错配——输入物体的类别或结构与训练分布不符时，网络会输出“统计上合理”但几何错误的背面。前者可以通过增加视角、改善纹理来缓解，后者只能通过扩充训练分布来缓解。把 LRM 当 MVS 用，会在分布外样本上得到系统性错误，而且错误是平滑的、不报错的，这比 MVS 的显式失败更难排查。

另一个机制差异在表示。MVS 的输出通常是离散几何（点云、深度图、网格），几何精度由采样密度决定；LRM 的输出是连续可微的三平面，几何通过体渲染的等值面或密度场提取。三平面的 64×64 分辨率意味着空间量化误差是结构性的，不是靠后处理能消除的。把 LRM 的输出当作高精度测量结果使用，会低估这种量化损失；把它当作“带先验的粗几何提案”使用，才符合它的定位。

五 · 常见误解之二：它不是“隐式函数 + 逐场景拟合”的换皮

第二个常见误解是把 LRM 归入 NeRF 类方法，认为它只是把逐场景的 MLP 换成了 Transformer。这个类比在表示层面有部分道理——两者都用体渲染监督——但在优化层面完全相反。NeRF 类方法的可学习参数是场景专属的，训练就是拟合这些参数；LRM 的可学习参数是跨场景共享的权重，场景专属的信息只存在于一次前向的激活值里。前者推理时必须优化，后者推理时禁止优化。把两者混为一谈，会误判 LRM 的失效条件：NeRF 的失效是优化不收敛或视角覆盖不足，LRM 的失效是分布外输入。

这个区别也解释了为什么 LRM 必须用 cross-attention 而不是简单的池化。逐场景拟合方法可以把所有输入视角的特征聚合成一个场景码，因为优化过程会反复使用这个码；LRM 只有一次前向，必须让每个 3D 位置主动从图像 token 里取信息，cross-attention 提供了这种按位置查询的能力。三平面被展平成 token 序列后，每个 token 对应一个空间位置，query 该位置需要什么特征，key/value 是图像 token。这个机制的可解释性有限，但它的功能定位清晰：一次前向内的信息路由，而不是迭代优化中的状态更新。

还有一个常被混淆的点是“可微表示”与“可训练编码器”的关系。三平面可微，只保证渲染损失能回传到三平面；要让损失回传到 ViT 与 Transformer，还需要 cross-attention 对输入 token 的梯度路径畅通。这条路径的存在，才使得“用渲染损失训练编码器”成立。如果中间有任何不可微的离散化（例如硬量化、不可微的采样），训练就会断链。工程上这意味着三平面的重塑、双线性采样、体渲染的积分近似都必须保持可微，任何为了效率引入的离散操作都要检查梯度。

六 · 常见误解之三：一次前向不等于一次渲染，也不等于零成本

第三个常见误解是把“一次前向出三平面”读成“一次前向出最终图像”或“推理零成本”。严格说，一次前向产出的是三平面张量，要得到可看的图像还需要体渲染；推理管线里体渲染的次数取决于要出几个视角。如果下游只需要三平面本身（例如做资产存储、做几何提取），那么体渲染可以省掉；如果要出多视角预览，就要为每个视角做一次体渲染。给定事实里“推理约 10 秒”是整条管线的量级，不是单次矩阵乘法的量级。把“一次前向”当成“一次轻量计算”，会在容量规划上出错。

成本结构上，Transformer 前向的浮点运算量与 token 数、层数、特征维度成正比；24 层、1024 个输入 token、三平面 3×64×64 个输出 token，这个规模的前向不是免费的。体渲染的成本与采样点数、视角数成正比，16 个视角的渲染在训练时是主要开销，推理时若只出少量视角则可控。真正的工程判断是：LRM 把成本从“每场景迭代”挪到了“训练一次性 + 推理固定”，推理的固定成本是否可接受，取决于业务对延迟的容忍度。对离线资产生产，10 秒量级完全可接受；对实时交互，需要蒸馏、缓存或降分辨率。

还有一个失败模式值得单独指出：网格提取的分辨率损失。三平面是 64×64 网格，从中提取网格时，等值面重建的空间分辨率受限于这个网格；细薄结构（例如叶片、线缆）在量化中会断裂或消失。这不是渲染损失训练能修复的，因为损失只监督 2D 图像，不监督几何细节。工程上的缓解手段是提高三平面分辨率或加残差细化，但两者都增加计算与内存。把 LRM 的输出直接当作高精度网格使用，会在细薄结构上系统性失败；把它当作粗几何提案、再用其他手段细化，才符合它的能力边界。

最后落到一个具体机制上：LRM 的推理管线是“ViT 切 token → 24 层 Transformer 做 cross-attention → 重塑为 3×64×64×32 三平面 → 按需体渲染”。这条管线里没有任何逐场景的梯度步，所有场景专属信息都在一次前向的激活值里。工程判断因此变得清晰：LRM 适合“大量物体、中等精度、可接受秒级延迟”的批量生产场景；不适合“单物体极高精度”或“分布外结构”的场景。它的价值不在于替代逐场景优化，而在于把重建问题重新定义为预测问题后，用训练规模换推理成本——这个交换是否划算，取决于你的训练预算与分布覆盖，而不是取决于网络结构本身。
