一 · 一句话与严格定义：从「雾」到「有符号距离」

NeRF 的密度场是一团没有边界的雾：任意一点都有一个非负密度值，体渲染沿射线把这些密度积分起来，得到的是一张「看起来像」的图像，但密度场本身并不告诉你表面在哪里。它只有「这里有多不透光」，没有「这里离表面多远、在表面哪一侧」。SDF（Signed Distance Field，有符号距离场）补上的正是这两个缺失的量：给定空间点 x，f(x) 返回它到最近表面的距离，并且用符号区分内外——表面之外为正，表面之内为负，表面上为零。于是表面不再是一个需要从密度阈值里猜出来的东西，而是 f 的零等值面 {x : f(x)=0}，一个由函数方程直接定义的集合。

严格定义要写清楚两件事。第一是距离性：对任意点 x，|f(x)| 等于 x 到零等值面的最短欧氏距离。第二是符号性：f 在零等值面外侧取正、内侧取负（约定不同可以整体取反，但全文必须一致）。这两条合起来等价于一个几乎处处成立的一阶条件：梯度的长度恒为 1。原因很直接——距离函数沿最速上升方向（即梯度方向）每走单位长度，距离就恰好增加 1；如果梯度长度大于 1，说明函数在某个方向上「涨得太快」，那它就不再是距离；如果小于 1，说明它「涨得太慢」，同样不满足距离的定义。写成公式就是 Eikonal 方程：

$$\|\nabla f(\mathbf{x})\| = 1 \quad \text{（几乎处处）},\qquad \mathcal{L}_{\mathrm{eik}}=\left(\|\nabla f(\mathbf{x})\|-1\right)^2$$

「几乎处处」这个限定不能省。SDF 在远离表面的地方是光滑的，但在中轴（medial axis）上——也就是到两个以上表面点距离相等的点集——距离函数不可微，梯度没有定义。工程上这意味着 Eikonal 损失不能在中轴附近逐点强制，否则会把一个本来合法的 SDF 往错误的方向拉。实践中的处理是：Eikonal 项只在采样点梯度的模长偏离 1 时给惩罚，并且这个惩罚是平方形式，对中轴附近的少数异常点具有天然的鲁棒性——它们的梯度模长要么不存在、要么数值上很怪，但因为权重是平方，单个坏点不会主导整体损失。这一点在实现里体现为对梯度做 clip 或对模长做截断，属于工程细节而非理论要求。

把 SDF 变成可体渲染的密度，需要一个桥接函数。给定 SDF f，定义密度 σ = α·Ψ_β(−f)，其中 Ψ_β 是 S 形函数（sigmoid 或 erf），β 控制陡峭程度，α 是整体密度尺度。注意自变量是 −f：在表面外侧 f>0，−f<0，Ψ_β 接近 0，密度接近 0；在表面内侧 f<0，−f>0，Ψ_β 接近 1，密度接近 α；在表面上 f=0，密度恰好是 α/2。这个构造把「距离」翻译成了「不透光程度」，并且翻译的方式是单调的、可微的，因此可以端到端训练。

一个必须立刻建立起来的直觉是：SDF 的零等值面就是表面，而密度只是这个表面的「渲染代理」。密度场可以很糊，但只要 Ψ_β 足够陡，体渲染积分出来的不透明度就会在跨过零等值面时出现一个尖峰，视觉上就是一条干净的边界。换句话说，表面的干净程度不由密度场的平滑程度决定，而由 SDF 的零等值面是否被 Eikonal 正则约束成一个真正的距离场决定。这是本主题全部工程取舍的出发点。

二 · 为什么需要：密度场的三个结构性缺陷

要理解 SDF 为什么值得引入，得先看清纯密度场在几何提取上的三个结构性缺陷，它们不是调参能解决的，而是表示本身带来的。

第一个缺陷是表面位置的不确定性。密度场只给出「某点有多不透光」，要从它提取表面，必须选一个阈值（比如 σ>τ）再做等值面提取。阈值选多少？不同的场景、不同的光照、不同的训练轮次，最优阈值都在漂移。更糟的是，密度在表面附近是渐变的，阈值稍微一动，提取出的表面就整体内缩或外扩一层。这意味着几何精度被一个超参数绑架，而这个超参数没有物理意义。SDF 没有这个问题：表面就是 f=0，不需要阈值，零等值面的位置由函数值直接给出。

第二个缺陷是内外不分。密度是非负的，它无法表达「这一点在物体内部」和「这一点在物体外部但靠近表面」的区别——两者都可能有相近的密度值。对于体渲染这无所谓，因为射线只关心累积不透明度；但对于几何处理（碰撞检测、布尔运算、法线估计、纹理映射）这是致命的，因为这些操作全都需要知道点在表面的哪一侧。SDF 的符号天然携带这个信息，而且符号是全局一致的，不依赖局部密度的高低。

第三个缺陷是梯度不可靠。密度场的梯度在表面附近指向密度增加的方向，但这个方向不一定垂直于表面——因为密度等值面和几何表面并不重合。用密度梯度当法线，得到的法线会有系统性的偏斜，表现为渲染中的高光位置漂移和几何提取后的表面凹凸。SDF 的梯度则严格垂直于零等值面（在可微处），因为距离函数沿梯度方向增长最快，而增长最快的方向必然垂直于等距面。这就是为什么 SDF 表示的法线质量通常明显好于密度场表示，也是为什么很多几何重建管线宁愿多花一份 SDF 的网络开销。

这三个缺陷有一个共同的根源：密度场是一个「渲染导向」的表示，它的参数是为积分好看而优化的，不是为几何正确而优化的。SDF 是一个「几何导向」的表示，它的约束（Eikonal）直接编码了几何性质。把两者用 σ=αΨ_β(−f) 桥接起来，等于让几何约束去指导渲染，而不是让渲染去猜测几何。这个方向的转变带来一个具体的系统代价：网络输出从一维标量（密度）变成一维标量（SDF），看起来没变，但训练目标多了一项 Eikonal 正则，而这一项需要对输入点求梯度——也就是要对网络做一次反向传播之外的额外求导。这个开销在后面的部分会展开，这里只需记住：SDF 不是免费的，它用计算换几何确定性。

具体例子可以说明这种转变的价值。考虑一个半径 1 的球，SDF 为 f(x)=|x|−1。在球心 x=(0,0,0)，f=−1，σ=αΨ_β(1)≈α（内部高密度）；在 x=(0,0,2)，f=1，σ=αΨ_β(−1)≈0（外部低密度）；在表面 |x|=1，f=0，σ=α/2。沿一条从外到内的射线采样，密度在 |x|≈1 附近从接近 0 跳到接近 α，体渲染积分得到的不透明度曲线在表面处出现陡峭上升，合成的像素颜色在边界处干净利落。如果换成纯密度场，同样的球需要网络自己学出「球心密度高、球外密度低」的映射，而这个映射在训练不足时会糊成一片渐变，边界位置随阈值漂移。SDF 把「球」这个几何先验直接写进了函数形式，网络只需要学一个标量场，难度低了一个量级。

三 · 桥接机制：Ψ_β 如何把距离变成不透明度

σ=αΨ_β(−f) 这个式子看起来只是一个激活函数，但它决定了体渲染中不透明度的分布形状，进而决定了表面看起来有多锐。拆开看：Ψ_β 是 S 形函数，β 是它的陡峭参数。以 sigmoid 为例，Ψ_β(z)=1/(1+exp(−βz))，β 越大，函数在 z=0 附近越陡。代入 z=−f 后，密度在 f=0 附近的变化率正比于 β。体渲染中，相邻采样点 i 和 i+1 之间的不透明度 α_i 由这两点的密度变换值之差决定（在分段常数近似下，α_i=1−exp(−σ_i·Δs)，其中 Δs 是采样间距）。当采样跨过零等值面时，Ψ_β(−f) 从接近 0 跳到接近 1，α_i 出现峰值。β 越小，跳变越缓，峰值越矮越宽，表面越糊；β 越大，跳变越陡，峰值越高越窄，表面越锐。

这里有一个容易被忽略的耦合：β 和采样间距 Δs 必须匹配。如果 β 很大而 Δs 也很大，采样点可能直接跨过整个跳变区，导致 α_i 的峰值被欠采样——渲染出的表面会出现锯齿或空洞，因为积分没有捕捉到密度跃变。反过来，如果 β 很小而 Δs 很细，跳变被过度采样，表面显得过厚、过糊，而且远处表面的不透明度会被错误地累积。工程上的做法是让 β 随训练进程退火：早期 β 小，密度场平滑，梯度信号覆盖范围广，网络容易学到全局形状；后期 β 增大，表面收紧，细节变锐。这个退火策略是有效的，但它对超参数敏感——退火太快，网络还没学到正确形状就把密度压尖了，会出现表面破碎；退火太慢，训练后期表面仍然糊，Eikonal 正则的约束被平滑的 Ψ_β 掩盖，零等值面不够干净。这是 SDF 体渲染最典型的失效模式之一，属于「β 退火敏感」这一类。

另一个机制性细节是 α 的角色。α 是密度的整体尺度，它决定了内部的最大不透明度。如果 α 太小，即使表面内侧的 Ψ_β 接近 1，累积不透明度也不够，射线会穿透物体，渲染出「透明」的假象；如果 α 太大，表面外侧的 Ψ_β 即使很小（比如 10⁻³），乘以 α 后也可能贡献可观的不透明度，导致表面外出现一层「雾」。所以 α 和 β 要联合调：β 控制跳变的陡峭度，α 控制跳变的高度，两者共同决定表面处的信噪比。这个联合调节没有解析最优解，只能靠训练监控——观察渲染图中表面边缘的锐度和背景的干净程度来反推。

把桥接机制写成伪代码，核心就是三行：

def sdf_loss(sdf, rays, gt):
    rgb = volume_render(sdf, rays)
    eik = ((grad(sdf, pts).norm(dim=-1) - 1)**2).mean()
    return mse(rgb, gt) + lam * eik

第一行做体渲染，内部把 SDF 经 Ψ_β 转成密度再积分；第二行对采样点求 SDF 的梯度，算 Eikonal 残差；第三行把 RGB 重建损失和 Eikonal 正则按权重 lam 相加。注意 grad(sdf, pts) 是对输入坐标求导，不是对网络参数求导——这是 Eikonal 正则区别于普通正则的关键：它约束的是函数在空间中的行为，而不是参数的大小。这个求导需要网络在前向时保留计算图到输入层，显存开销比纯密度场训练高，这是 SDF 方法的固定成本。

四 · Eikonal 正则：为什么 |∇f|=1 是几何约束而非数值技巧

很多人第一次看到 Eikonal 正则，会把它当成一个「让梯度别爆炸」的数值稳定项，类似于梯度惩罚。这个理解是错的，而且错得很危险——按这个理解去调权重，会把 SDF 训成一个「梯度接近 1 但零等值面位置错误」的函数，表面看起来干净，几何却是错的。Eikonal 正则的本质是几何约束：它来自距离函数的定义，不是来自优化的需要。

推导只有一句话：沿梯度方向走单位长度，距离变化 1。设 x 处梯度为 g=∇f，沿 g/|g| 方向走一小步 ε，函数值变化约为 ε·|g|。如果 f 是距离函数，这个变化必须等于 ε（因为走的是「最速远离表面」的方向，距离就该增加 ε）。于是 ε·|g|=ε，即 |g|=1。反过来，如果 |g|≠1，那么沿梯度方向走单位长度，距离的变化就不是 1——这个函数就不是距离函数，它的等值面间距就不是均匀的，零等值面附近的「距离」读数就不可信。所以 Eikonal 正则不是在「帮助」训练，而是在「定义」什么是合法的 SDF。训练损失里的 (|∇f|−1)² 是对这个定义的偏离度量，最小化它就是迫使网络输出逼近一个真正的距离场。

这个约束的几何后果很具体。没有 Eikonal 正则时，网络可以输出任意形状的标量场，只要它的零等值面大致落在表面附近、并且经 Ψ_β 转换后能渲染出对的颜色，RGB 损失就会满意。但这个标量场可能在表面附近梯度很陡、远处梯度很平，等值面间距不均匀。这样的场在体渲染时，表面处的密度跳变可能仍然锐利（因为 Ψ_β 只看 f 的符号和局部值），但一旦你要做几何操作——比如沿法线方向偏移表面、计算点到表面的真实距离、做球体追踪（sphere tracing）——就会出错，因为 f 的读数不再等于真实距离。Eikonal 正则把这些「看起来对但用起来错」的解排除掉，代价是训练时必须对输入求导，并且权重 lam 要足够大才能压住 RGB 损失对几何的拉扯。

lam 的取值是一个工程判断，不是理论常数。lam 太小，Eikonal 约束被 RGB 重建淹没，网络优先把颜色拟合好，几何退化成任意函数；lam 太大，Eikonal 约束主导，网络被迫输出一个全局近似距离场，但可能牺牲局部细节——薄结构、锐边、非闭合表面这些「不满足距离函数光滑性」的几何会被过度平滑。这是 SDF 方法的第二个典型失效模式：薄结构和非闭合表面难。薄结构的厚度小于采样间距时，零等值面在两侧各出现一次，中间的负值区域很窄，Ψ_β 的跳变在两次跨面时叠在一起，体渲染的不透明度峰值合并，表面糊成一片。非闭合表面（比如一张纸）没有「内部」，SDF 的符号定义在纸的两侧都为正，零等值面是一张零厚度的面，Eikonal 约束在面附近要求梯度模长 1，但面两侧的符号相同意味着梯度在跨面时不变号，这与「距离函数在表面处取零并变号」的直觉冲突，训练容易在该处产生伪影。

具体到系统代价：Eikonal 正则让每次训练迭代多一次对输入的梯度计算，显存占用增加（要保留从输入到输出的计算图），训练速度下降。这个代价是固定的，不随场景复杂度变化，所以在小场景上显得不划算，在大场景上则被几何收益抵消。工程上的判断标准是：如果你的下游任务需要几何精度（碰撞、测量、编辑），Eikonal 正则必须开；如果只是要一张好看的渲染图，纯密度场可能更省。这个判断没有中间地带，因为 SDF 表示的全部价值就在于几何确定性，去掉 Eikonal 正则等于放弃了这份确定性，只剩下一个换了激活函数的密度场。

五 · 常见误解：四个必须纠正的直觉

误解一：SDF 就是「密度加个符号」。不是。密度是非负标量，符号是 SDF 的定义性成分，不是装饰。去掉符号，f 就退化成「到表面的无符号距离」，零等值面两侧无法区分，内外判断失效，Eikonal 约束也失去意义（无符号距离在表面处不可微，梯度会跳变）。符号的存在使得 f 在表面处穿过零点并变号，这正是体渲染中 Ψ_β(−f) 能产生跳变的原因——如果 f 不变号，Ψ_β(−f) 在表面两侧同高，密度没有跃变，表面就糊了。

误解二：Eikonal 正则越强越好。不是。前面已经说过 lam 太大会过度平滑细节。更深一层的原因是：真实几何并不总是距离函数。一个带锐边的立方体，其精确 SDF 在棱和角附近梯度不连续，|∇f| 在那些点附近不严格等于 1（在棱上梯度多值）。强行用 Eikonal 正则压平，会把锐边磨圆。所以 Eikonal 正则的目标不是「处处 |∇f|=1」，而是「几乎处处 |∇f|=1，且在几何允许的范围内」。工程上这体现为对 Eikonal 损失做掩码或降权，在梯度模长异常大的点（棱、角、中轴）减小惩罚。这个细节决定了 SDF 能不能保住锐利特征。

误解三：β 越大表面越干净，所以直接拉满。不是。β 和采样间距 Δs 耦合，β 过大而 Δs 不够细时，跳变被欠采样，表面出现锯齿和空洞；β 过大还会让 Ψ_β 的梯度在跳变区变得极陡，反向传播时该区域的梯度信号爆炸，训练不稳定。正确做法是 β 退火，并且退火曲线要和 Δs 的调度（粗到细的采样策略）同步。这是「β 退火敏感」失效模式的根源，也是 SDF 体渲染调参中最花时间的一项。

误解四：SDF 训练慢是因为网络大。不完全是。SDF 训练慢的主因是 Eikonal 正则需要对输入求导，这增加了每次迭代的计算图和显存；其次是 β 退火要求训练分阶段，不能一次性端到端跑完；第三是薄结构和非闭合表面的收敛慢，因为这些区域的 Eikonal 约束和 RGB 损失互相拉扯，梯度方向不一致。网络大小只是次要因素。理解这一点很重要，因为它决定了优化方向：想加速 SDF 训练，应该优化求导的实现（比如用有限差分近似替代精确求导，牺牲一点精度换速度），而不是盲目缩小网络。

这四个误解有一个共同点：它们都把 SDF 当成「密度场的变体」来理解，而不是当成「几何表示」来理解。一旦接受 SDF 的首要身份是几何表示，Eikonal 正则的几何含义、β 的渲染含义、符号的定义性作用就都变得自然了。后面的部分会沿着这个身份展开：体渲染如何精确地把 SDF 转成像素、Eikonal 正则如何在离散采样下近似、以及工程上如何在几何精度和渲染质量之间做取舍。
