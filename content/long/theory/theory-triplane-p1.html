一 · 一句话与严格定义：从 3D 体积到三张正交特征图

三平面表示的核心操作只有一句：把三维空间中的任意一点，投影到三个互相垂直的二维平面上，分别取特征，再拼接解码。它不是把 3D 数据压成一张图，而是保留三张互相正交的 2D 特征图 T_xy、T_xz、T_yz，让每个 3D 点同时从三个方向获得描述。对工程读者而言，最重要的不是“三张图”这个视觉比喻，而是它把 3D 查询变成了三次 2D 双线性插值加一次小 MLP 前向，从而让 2D 卷积网络可以直接参与 3D 内容的生成与学习。

严格定义如下：给定三张二维特征图 T_xy ∈ R^{N×N×C}、T_xz ∈ R^{N×N×C}、T_yz ∈ R^{N×N×C}，其中 N 为平面分辨率、C 为每平面通道数。对任意 3D 点 x=(x,y,z)（归一化到同一坐标范围），其连续特征由下式给出：

$$F(\mathbf{x})=\mathrm{MLP}\!\left(\mathrm{interp}(T_{xy},\mathbf{x}),\mathrm{interp}(T_{xz},\mathbf{x}),\mathrm{interp}(T_{yz},\mathbf{x})\right)$$

这里 interp 指双线性插值：T_xy 取 (x,y)，T_xz 取 (x,z)，T_yz 取 (y,z)。三个插值结果各为 C 维向量，拼接后得到 3C 维输入，送入一个小型 MLP，解码为密度、颜色或 SDF 等目标量。注意定义中的关键约束：三张平面共享同一坐标归一化范围，插值必须是连续的，否则查询在平面边界处会出现特征跳变；MLP 只负责融合与解码，不负责从坐标重建空间结构，空间结构已经由三张平面的二维布局承载。

这个定义与体素表示的区别不在“精度”而在“参数组织方式”。体素把空间切成 N³ 个体素单元，每个单元存一个 C 维特征；三平面只存 3N² 个单元。对 N=256、C=32，三平面参数量约为 3×256×256×32≈630 万，而同分辨率体素为 256³×32≈5.4 亿，相差约 85 倍。这不是近似省略，而是把三维索引拆成三组二维索引，用共享的二维卷积核在每张平面上滑动。查询时三次插值的结果拼接，等价于让每个 3D 点从三个正交切片中各取一份局部证据。

一个具体例子可以说明查询路径：要取点 (0.3, 0.7, 0.2) 的特征，先在 T_xy 上按 (0.3,0.7) 双线性插值，得到 xy 分量；在 T_xz 上按 (0.3,0.2) 插值，得到 xz 分量；在 T_yz 上按 (0.7,0.2) 插值，得到 yz 分量；三者拼接成 3C 维向量送入 MLP。整个过程中没有任何 3D 卷积，也没有 N³ 大小的张量驻留显存。生成器因此可以沿用成熟的 2D 卷积骨架：先在低分辨率平面上做卷积、上采样、再卷积，最后把三张平面交给查询模块渲染。

二 · 为什么需要：显存维度与卷积生态的双重约束

直接生成 3D 体素的第一道墙是显存。体素特征张量随分辨率呈立方增长：N 从 128 提到 256，体素单元数变成 8 倍；再叠加通道数 C，显存占用按 N³·C 膨胀。训练生成器时还要保存中间激活、梯度和优化器状态，实际占用远高于特征张量本身。三平面把参数与激活降到 3N²·C，分辨率翻倍只带来 4 倍增长，而不是 8 倍。对单卡训练 512×512 人脸生成这类任务，这个差距决定了“能不能在一张卡上跑起来”，而不是“跑得快不快”。EG3D 用三平面生成 512×512 人脸并做到单卡可训，正是建立在这个维度缩减上。

第二道墙是卷积生态。隐式 MLP 表示（如 NeRF 式全连接网络）把整个场景塞进 MLP 权重，查询灵活、连续性好，但它难以直接套用 2D 卷积的成熟堆栈：没有空间局部性的卷积核，没有现成的上采样与多尺度结构，生成器设计退化成对 MLP 权重的全局调制。三平面把“空间结构”重新放回二维特征图，卷积核在平面上滑动时天然获得局部性、平移等变性和多尺度层级。生成器可以先在 64×64 平面上卷积，再上采样到 128、256、512，每一级都用 2D 卷积学习局部纹理，这与图像生成网络的工程经验完全对齐。

第三层原因是查询成本与渲染管线的匹配。体素查询是 O(1) 索引，但体素张量本身太大；隐式 MLP 查询是若干次全连接，单点成本高且难以批量化到高分辨率渲染。三平面查询是三次 grid_sample 加一次小 MLP，单点成本固定且可向量化：一次渲染上百万个采样点时，grid_sample 在 GPU 上按批并行，MLP 只处理 3C 维输入，宽度很小。伪代码层面的查询函数可以写成：

  • 输入：三张平面 planes=[T_xy,T_xz,T_yz]，点集 x，形状 [B,P,3]；
  • xy = grid_sample(planes[0], x[..., :2])，xz = grid_sample(planes[1], x[..., [0,2]])，yz = grid_sample(planes[2], x[..., 1:])；
  • 返回 mlp(cat([xy,xz,yz], dim=-1))。

这段伪代码揭示了一个系统代价：三次 grid_sample 各自独立，平面之间没有查询时的耦合，耦合全部推给 MLP。好处是查询可并行、可微、易实现；代价是 MLP 必须学会从三份可能互相矛盾的证据中做取舍。如果三张平面在训练早期给出不一致的特征，MLP 会承受额外的融合负担，表现为渲染早期的高频噪声或密度不一致。工程上常见的缓解手段是让三平面共享部分卷积权重、或在低分辨率阶段先做平面间的一致性约束，而不是一味加宽 MLP。

还有一个容易忽略的动机：三平面让“生成”和“渲染”解耦。生成器只负责产出三张 2D 特征图，渲染器只负责查询与体渲染。二者之间的接口是固定形状的张量，而不是耦合的网络结构。这使得替换生成 backbone（比如换不同的 2D 卷积架构）不需要重写渲染器，替换渲染方式也不需要重训生成器。对工程系统而言，这种接口稳定性比单点性能更重要。

三 · 三平面如何覆盖 3D 空间：投影、插值与冗余

三张正交平面覆盖 3D 空间的机制是投影：任意点 (x,y,z) 在 T_xy 上的坐标是 (x,y)，在 T_xz 上是 (x,z)，在 T_yz 上是 (y,z)。三组二维坐标合起来包含该点的全部三个坐标分量，因此三张平面共同覆盖整个空间。但覆盖不等于唯一：同一个 3D 点在三张平面上各有一次观测，三次观测之间必然存在冗余。比如沿 z 轴移动的点，在 T_xy 上的投影不变，只有 T_xz 和 T_yz 会变化；沿 x 轴移动时，T_yz 不变。这种“某张平面看不见某个方向变化”的性质，正是三平面冗余的来源。

冗余在定义上是缺陷，在工程上是特性。若三张平面完全独立训练，它们可能学到互相冲突的局部结构，MLP 被迫做不一致融合。但若用 2D 卷积在平面上学习，卷积核的局部性和共享权重会倾向于让三张平面学到相似的结构先验：边缘、角点、纹理块在三个投影方向上重复出现。冗余因此变成一种正则：同一空间结构在三个视角下被多次表达，2D 卷积可以从任一张平面学到它，再通过 MLP 融合。这也解释了三平面为什么“能用 2D 卷积”：不是因为平面之间没有关系，而是因为关系足够强，强到共享卷积核不会破坏表达能力。

插值方式是覆盖机制的另一半。双线性插值把离散的 N×N 网格变成连续函数，查询点落在网格单元内时，取四邻域特征的加权平均。权重由点在该单元内的相对位置决定，权重和为 1。这个操作对坐标可微，梯度可以回传到平面特征，因此三平面可以端到端训练。系统代价在于：插值会平滑高频细节，平面分辨率 N 决定了可表达的最高空间频率。当渲染分辨率远高于 N 时，查询会反复落在同一组网格单元内，表现为细节模糊。工程上要么提高 N，要么在 MLP 中加入位置编码补偿，但后者会削弱“纯 2D 卷积”的简洁性。

一个具体失败模式：当三张平面分辨率相同但坐标归一化不一致时，同一个 3D 点在 T_xy 与 T_xz 上的插值位置会错位，MLP 收到的是三个不同空间位置的特征拼接，渲染结果出现重影或密度断层。这不是理论缺陷，而是实现错误：三平面定义要求三张平面共享同一坐标范围与同一归一化约定，任何一张平面的平移或缩放都会破坏正交投影的一致性。工程检查清单里应把“三平面坐标约定一致”列为硬性约束，而不是交给训练去自适应。

四 · 常见误解：三平面不是三视图，也不是体素压缩

第一个常见误解是把三平面当成“三视图”。三视图是三个正交方向的投影图像，每个像素是沿投影方向的积分或可见表面颜色；三平面不是投影图像，而是三张特征图，每个像素存的是 C 维特征，不是颜色，也不做沿轴积分。查询时取的是对应坐标处的局部特征，而不是某条射线上的累计量。把三平面误读为三视图，会导致错误地期待“三张图拼起来就是 3D 形状”，从而低估 MLP 的融合作用，也误解了训练目标：三平面不需要与任何真实三视图对齐，它只需要在查询时能解码出正确的密度与颜色。

第二个误解是“三平面是体素的低秩压缩”。体素是 N³ 个独立单元，三平面是 3N² 个单元，参数少并不等于把体素做 SVD 或低秩分解。三平面的结构约束是“每个 3D 点的特征必须来自三个正交投影的插值拼接”，这是一个固定的查询算子，而不是从体素数据中学习到的低秩因子。体素低秩分解仍然保留 N³ 的索引结构，只是用因子矩阵近似；三平面直接取消了 N³ 索引，改用三组二维索引。二者在显存曲线上不同：前者仍可能实例化大张量，后者从结构上就不需要。

第三个误解是“三平面只能表示静态、固定拓扑的场景”。三平面确实有固定拓扑：三张平面一旦确定分辨率与坐标范围，空间就被固定划分，难以做部件级编辑（比如单独移动一只手臂而不影响其他区域）。失效条件里明确列出“固定拓扑，难部件编辑；几何真值弱”。但这不是说三平面不能表示动态内容：动态可以通过在平面上做形变、或让 MLP 接受时间条件来实现，代价是查询算子变复杂、2D 卷积的局部性假设被削弱。工程判断是：三平面适合“整体生成、整体渲染”的任务，不适合需要精细部件操控或强几何监督的任务。

第四个误解是“三平面参数量少所以表达力弱”。参数量少是维度缩减的结果，不是表达力的上限。三平面的表达力来自三张平面上的 2D 卷积层级与 MLP 的非线性融合，而不是来自参数计数。真正限制表达力的是平面分辨率 N 与通道数 C：N 决定空间频率上限，C 决定每个位置的特征维度。把 N 从 256 提到 512，参数量变为 4 倍，查询成本不变（仍是三次插值），但显存与训练成本上升。工程上要在 N、C、MLP 宽度之间做取舍，而不是简单认为“参数少一定差”。

第五个误解与失效条件直接相关：三平面“几何真值弱”。三平面是为渲染监督（多视角图像）设计的，密度与颜色由 MLP 解码，几何（SDF 或网格）不是原生输出。若任务需要精确几何，三平面需要额外的几何正则或从密度场提取等值面，后者会引入 marching cubes 的分辨率误差。这不是三平面独有的问题，但三平面的固定拓扑会让几何提取的误差在平面边界处更明显。工程上应把三平面定位为“可渲染的 3D 表示”，而不是“精确几何表示”。

五 · 工程取值：分辨率、通道与查询成本的三角权衡

三平面的系统取值集中在三个量：平面分辨率 N、每平面通道数 C、MLP 宽度与层数。N 决定空间频率上限与参数量（3N²·C），C 决定每个位置的特征维度与拼接后的 MLP 输入宽度（3C），MLP 决定融合能力与单点查询成本。三者不是独立的：提高 N 会同时提高显存与插值精度，提高 C 会提高 MLP 输入维度与平面卷积的计算量，加宽 MLP 会提高渲染时每个采样点的成本。工程取值的目标不是单项最优，而是在给定显存与渲染预算下让三者匹配。

一个可操作的取值思路：先由目标渲染分辨率反推 N。若渲染图像为 512×512，平面 N 取 256 或 512 是常见量级；N 过低会让插值平滑吃掉高频细节，N 过高会让平面卷积的显存与计算成为瓶颈。再由任务复杂度定 C：C=32 时三平面参数量在 N=256 下约 630 万，拼接输入为 96 维，小 MLP 足以融合；C 过大则 MLP 输入变宽，查询成本上升，而平面卷积的通道数也上升。最后定 MLP：宽度不必大，因为输入只有 3C 维且三份证据已经由插值对齐到同一空间点，融合是局部决策，不是全局推理。

取值项作用代价或失败模式
平面分辨率 N决定空间频率上限与参数量 3N²·CN 过低细节模糊；N 过高平面卷积显存吃紧
通道数 C决定每位置特征维度与 MLP 输入 3CC 过大查询变贵；C 过小融合信息不足
MLP 宽度/层数融合三平面证据并解码密度/颜色过宽则渲染采样点成本高；过窄则融合不一致
坐标归一化保证三平面投影一致不一致导致重影、密度断层

查询成本的具体机制：渲染时每条射线采样数十到上百个点，每个点做三次 grid_sample 与一次 MLP。grid_sample 的成本与平面分辨率、通道数、采样点数成正比；MLP 的成本与 3C、宽度、层数成正比。若 N=256、C=32、MLP 为两层 64 宽，单点查询是可控的；若把 C 提到 128，MLP 输入变为 384 维，单点成本显著上升，而平面卷积的通道数也变为 4 倍。工程上常见的失败模式是“为了细节把 N 和 C 同时拉高”，结果训练显存与渲染延迟一起失控，而细节提升并不线性。正确做法是先定位瓶颈：是插值平滑导致的模糊，还是 MLP 融合不足导致的不一致，再单独调整对应量。

还有一个取值与失效条件相关：三平面的对称冗余意味着三张平面在训练中可能学到重复结构，若不加约束，参数量虽少但有效表达被冗余吃掉。工程上可以通过共享部分卷积权重、或在低分辨率阶段对三平面做一致性损失来缓解。代价是训练目标变复杂，收益是 MLP 融合负担下降。这个取舍没有统一答案，取决于任务是“整体生成”还是“强几何监督”：前者可以容忍冗余，后者需要更紧的一致性约束。最终落在具体机制上：三平面的工程价值不在于参数量少，而在于它把 3D 查询固定为三次 2D 插值加一次小 MLP，使 2D 卷积生态与 3D 渲染管线在一个稳定接口上对接；取值决策应围绕这个接口的成本结构展开，而不是围绕“像不像体素”展开。
