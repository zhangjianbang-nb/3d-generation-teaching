一 · 失效条件：序列长度、拓扑合法性与量化损失

AMT 把网格压成一条按 DFS 邻接顺序排列的 token 句子，压缩比来自「相邻面片只新增一个顶点」这一几何事实。但压缩比不是免费的：它把复杂度从「顶点数」转移到了「序列长度」，而序列长度是自回归模型的硬约束。一个 800 面的网格在 AMT 下约需 1200 个顶点 token，在 4096 上下文里能生成约 1600 面；同样的上下文，逐面三顶点编码只能生成约 800 面。这条对比说明：上下文窗口是系统的第一道闸门，不是模型能力的软限制，而是生成复杂度的硬上限。当面数继续上升，序列长度线性增长，注意力计算的代价随序列长度呈二次增长，显存占用与推理时延同步放大。工程上必须把「目标面数」反推成「token 预算」，再反推成「上下文长度」，而不是先定模型再抱怨生成不了高面数网格。

第二类失效是拓扑合法性。AMT 的 token 只编码「新顶点」，隐含假设是 DFS 遍历中每个面片恰好引入一个新顶点，且该顶点与已有顶点通过共享边连接。这个假设在流形网格上成立，在非流形、带孔洞、带孤立面片的网格上会破裂。解码器把 token 还原成面片时，如果新顶点索引指向一个不存在的顶点，或者面片的三个顶点不构成一条合法边环，就会产生「悬空面」——面片在拓扑上不与任何邻居共享边。系统必须在解码后做一次拓扑校验：检查每条边被两个面片共享（流形条件）、检查顶点索引在合法范围内、检查面片绕向一致。校验失败的面片要么丢弃，要么触发局部重采样。这一步不是可选的装饰，而是生成管线的一部分，代价是额外的图遍历与索引重建。

第三类失效是量化损失。token 编码顶点坐标时，坐标被量化到离散网格。量化步长决定了细节保留的下限：步长过大，薄壁、锐边、小特征被抹平；步长过小，词表膨胀，嵌入层参数与输出 softmax 的计算量上升。量化误差不是均匀分布的：在曲率高的区域，同样的步长造成的几何偏差更大。一个具体机制是：对顶点坐标做分轴量化，每轴用固定比特数，则单顶点 token 的信息量为三轴比特数之和；词表大小随比特数指数增长。系统取值要在「词表规模—嵌入显存—细节保真」三者之间做权衡，而不是把比特数拉到最大。

$$\mathrm{AMT}(\mathcal{M})\approx\frac{1}{2}\mathrm{VTT}(\mathcal{M}),\qquad L_{\text{seq}}\approx \frac{1}{2}L_{\text{VTT}}$$

上式只给出期望压缩比，实际序列长度还受 DFS 分支顺序影响：一个高 genus 的网格，DFS 回溯次数多，某些面片的新顶点可能不是「一个」，而是「零个」（回边情形）。此时序列长度低于一半，但解码时的邻接重建更复杂。工程判断是：压缩比是统计期望，不是逐网格保证；系统必须按最坏情况预留 token 预算。

二 · 系统取值：词表、上下文与解码校验的联合配置

把 AMT 放进生成系统，需要确定的取值至少有四组：词表规模、上下文长度、量化比特数、拓扑校验策略。它们不是独立可调的旋钮，而是相互耦合的约束。词表规模由量化比特数决定：若顶点坐标每轴用 b 比特，加上面片结束符与邻接标记，词表大小约为 \(2^{3b}\) 量级。词表越大，嵌入矩阵与输出投影的参数越多，softmax 归一化的计算越重。上下文长度由目标面数决定：按 AMT 约减半的关系，目标面数 F 对应约 F/2 个新顶点 token，再加上序列起止符与可能的邻接控制符，上下文应留出余量。量化比特数由细节保真需求决定：b 增大，几何误差下降，但词表与显存上升。

一个具体机制是「序列预算反推」：给定上下文长度 C，扣除起止符与控制符占用 c₀，可用于顶点 token 的预算为 C−c₀；按 AMT 减半关系，可生成面数约为 2(C−c₀)。若目标面数为 F，则要求 C ≥ F/2 + c₀。这个不等式是系统配置的第一道筛子。第二个机制是「词表分层」：把顶点坐标 token 与结构控制 token 分开编码，控制 token 只占少量词表位置，坐标 token 占主体。这样 softmax 的主体分布在坐标上，控制符的概率不会被坐标 token 稀释。代价是解码器需要识别两类 token 的边界，增加了解析逻辑。

第三个机制是「解码后校验回路」：解码器按 token 序列重建面片时，每遇到一个新顶点 token，就把它挂到当前 DFS 栈顶面片的共享边上；序列结束后，遍历所有面片，统计每条边的共享面片数。若某条边只被一个面片引用，标记为边界边；若被三个及以上面片引用，标记为非流形边。校验回路把「生成」与「合法」分开：模型只负责概率采样，合法性由确定性图算法兜底。系统代价是额外的遍历时间与内存，但换来的是下游渲染与仿真管线不会因非法拓扑崩溃。失败模式是校验过严：把合法的边界边误判为悬空面，导致有效网格被丢弃。工程上要给边界边留出豁免规则。

三 · 与相邻理论的差别：为什么不是逐顶点序列、不是面片图网络

AMT 最容易被混淆的邻居是「逐顶点序列化」：把顶点按某种顺序排成序列，每个顶点一个 token。逐顶点序列的优点是顶点不重复，序列长度等于顶点数；缺点是丢失了面片连接关系，模型学不到「哪些顶点构成一个面」。AMT 的 token 是面片，编码的是「新顶点 + 邻接」，序列里隐含了 DFS 树结构。两者的差别不在压缩比，而在「序列是否携带拓扑」。逐顶点序列解码后需要额外的三角化步骤，AMT 解码直接得到面片。系统代价上，逐顶点序列的三角化是另一个不确定性来源，AMT 把三角化内嵌进 token 顺序，减少了后处理环节。

第二个邻居是「面片图网络」：把每个面片当作图节点，邻接关系当作边，用图神经网络做消息传递。图网络的优势是置换不变、局部感受野明确；劣势是不能直接套用 Transformer 的 next-token prediction，生成长序列时需要图级别的自回归采样，采样顺序难以固定。AMT 把图「拉直」成序列，换来了 Transformer 的成熟训练管线，代价是序列顺序引入了人为的 DFS 偏置：同一个网格，不同的 DFS 起点会产生不同的 token 序列，模型必须对这种顺序变化保持稳健。工程判断是：AMT 用「顺序偏置」换「管线复用」，图网络用「置换不变」换「采样复杂」，两者不是替代关系，而是不同系统约束下的取舍。

第三个邻居是「隐式场 / 占用网格」表示：用连续函数或体素网格描述形状，生成时采样等值面。隐式表示的分辨率由采样密度决定，不受序列长度约束；但它的输出是稠密场，提取网格需要 marching cubes 之类的后处理，且拓扑细节受分辨率限制。AMT 的输出是显式面片序列，拓扑由 token 顺序直接决定，不需要等值面提取。代价是 AMT 的面数受上下文硬约束，隐式表示的面数由分辨率软约束。一个具体例子：同样生成一个带薄壁的零件，隐式表示在低分辨率下会把薄壁合并，AMT 在量化步长过大时会把薄壁顶点压到同一格点，两者失效机理不同，但都指向「细节保真与表示预算的权衡」。

$$\text{AMT}: \mathcal{M}\mapsto (t_1,\dots,t_N),\quad \text{图网络}: \mathcal{M}\mapsto \text{消息传递},\quad \text{隐式}: \mathcal{M}\mapsto f(\mathbf{x})$$

三者的系统代价可以并列比较：AMT 的瓶颈是序列长度与量化步长；图网络的瓶颈是采样顺序与图规模；隐式表示的瓶颈是采样分辨率与等值面提取。AMT 的独特之处在于它把「拓扑」编码进了「顺序」，因此解码是确定性的图重建，而不是搜索或提取。这也意味着 AMT 的失败模式更集中：序列一断，拓扑就断；量化一粗，细节就丢。

四 · 练习：从失效反推配置，从配置反推预算

练习一：给定一个目标面数 F 与上下文长度 C，写出 AMT 可生成面数的上界，并指出哪些因素会让实际面数低于上界。参考思路：按减半关系，上界约为 2(C−c₀)；实际面数低于上界的情形包括 DFS 回边导致新顶点数为零、控制符占用超出预估、量化后重复顶点被合并。这个练习的目的是把「上下文」翻译成「面数预算」，而不是把上下文当作抽象参数。

练习二：给定量化比特数 b，估算词表规模，并说明 b 增大一倍时嵌入层参数与 softmax 计算的变化量级。参考思路：每轴 b 比特，三轴合计 3b 比特，词表约为 \(2^{3b}\) 量级；b 增大一倍，词表从 \(2^{3b}\) 变为 \(2^{6b}\)，即平方级增长，嵌入参数与输出投影同步平方级增长。这个练习的目的是让读者意识到「细节保真」不是免费参数，而是词表与显存的平方级代价。

练习三：设计一个拓扑校验伪代码，输入是解码后的面片列表，输出是非法面片索引列表。参考思路：建立边到面片的映射字典，遍历每个面片的三条边，把面片索引追加到对应边的列表中；遍历结束后，检查每条边的列表长度，长度为一的标记为边界边，长度大于二的标记为非流形边，长度为零的标记为悬空边；再把涉及非流形边或悬空边的面片索引收集为非法列表。这个练习的目的是把「合法性」从模型概率中剥离出来，变成确定性算法。

练习四：比较 AMT 与逐顶点序列在同一个 800 面网格上的 token 数，并说明两者解码后处理步骤的差别。参考思路：逐面三顶点需要 2400 个顶点 token，AMT 约需 1200 个；逐顶点序列的 token 数等于顶点数（少于 2400，但丢失面片连接），解码后需要三角化；AMT 解码直接得到面片，但需要拓扑校验。这个练习的目的是让读者看清「压缩比」与「后处理复杂度」是两组独立的账，不能只算其中一组。

练习五：给定一个带薄壁的网格，分析量化步长过大与 DFS 顺序不当分别会造成什么失效，并给出各自的缓解手段。参考思路：量化步长过大把薄壁两侧顶点压到同一格点，缓解手段是提高局部比特数或对薄壁区域做自适应量化；DFS 顺序不当导致回边过多、新顶点数为零，序列变短但邻接重建复杂，缓解手段是固定 DFS 起点策略或在 token 中显式编码回边标记。这个练习的目的是把两类失效分开归因，避免把「细节丢失」与「拓扑断裂」混为一谈。

五 · 工程判断：把 tokenization 当作系统契约而非预处理

AMT 的边界最终落在「契约」二字上：tokenization 不是模型之前的无关预处理，而是模型与几何之间的契约。契约规定了三件事：序列长度对应面数预算，词表规模对应量化精度，token 顺序对应拓扑重建规则。任何一件被打破，系统就在对应环节失效。工程上常见的错误是把 tokenization 当作「喂数据」的格式转换，先定模型再补 tokenizer，结果上下文不够、词表爆炸、拓扑校验缺失三件事同时爆发。正确的顺序是反过来的：先定目标面数与细节保真等级，反推上下文与词表，再定模型规模，最后把拓扑校验写进解码管线。

一个具体机制是「预算表」：把面数、token 数、上下文、词表、量化比特、校验开销列成一张表，每次改动一个取值，表上其他项同步更新。例如把目标面数从 800 提到 1600，token 预算从约 1200 提到约 2400，上下文必须相应扩大，注意力计算代价随之上升；若上下文不能扩大，就只能降低量化比特或接受面数上限。预算表的作用是让耦合关系显式化，避免「调一个参数、崩三个环节」。系统代价是维护这张表的人力，收益是配置决策可追溯、失效可归因。

最后一个机制是「失效注入测试」：在解码管线里故意注入非法 token（越界顶点索引、断裂的邻接标记、超长序列截断），观察拓扑校验能否捕获、下游渲染是否崩溃。这个测试把「失效条件」从纸面变成可执行的检查项。工程判断是：AMT 的可靠性不取决于模型概率有多高，而取决于校验回路有多完整；概率负责生成，校验负责兜底，两者缺一不可。
