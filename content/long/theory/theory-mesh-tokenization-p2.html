伪代码思路要体现“只编码新顶点”这一条：

  • 对网格建邻接表，记录每个面片的三个邻接面（共享边的那些）。
  • 选一个起始面，把它的三个顶点全部写入序列，作为种子。
  • 用 DFS 栈遍历面片；每到一个未访问面片，找出它与已访问面片共享的边，只把该边对面的那个新顶点写入序列，同时写入连接标记。
  • 遇到已访问面片则跳过，避免重复编码共享边。
  • 遍历结束后检查：所有面片是否都被覆盖、序列中每个新顶点是否都能由前缀唯一确定其所属面片。

这段流程的系统代价在于 DFS 顺序对序列长度的影响并不均匀。规则网格上每条共享边恰好被两个面片使用，减半成立；但遇到非流形边（被三个以上面片共享）或边界边（只被一个面片使用）时，新顶点计数会偏离“每面一个”。非流形处一个顶点可能被多个面片重复引用，tokenizer 要么把它记成多次新顶点（序列变长），要么引入引用标记（token 取值空间变大）。两种选择都是代价：前者浪费上下文，后者增加词表与预测难度。失败模式是遍历在非流形处产生歧义，解码器无法判断某个新顶点属于哪个面，还原出的网格出现裂缝或自交。

三 · 序列长度减半的推导：共享边账本

减半结论需要一个可核算的账本，而不是“相邻面片共享边所以省一半”的直觉复述。设网格有 \(F\) 个面片、\(V\) 个顶点、\(E\) 条边，闭合流形满足欧拉关系 \(V-E+F=2\)，且每条边恰好被两个面片共享，即 \(3F=2E\)。逐面三顶点编码的总 token 数是 \(3F\)，因为每个面片独立写三个顶点，共享边被两侧各写一次。AMT 的 token 数等于“种子顶点数 + 每个后续面片新增顶点数”。在 DFS 遍历中，除起始面外，每个面片都与已访问部分共享至少一条边，因此它带来的新顶点数至多为 1；把整条遍历链加起来，新增顶点总数不超过 \(F\)，加上起始面的 3 个种子顶点，上界是 \(F+3\)。

把两个账本放在一起：

$$\mathrm{VTT}(\mathcal{M})=3F,\qquad \mathrm{AMT}(\mathcal{M})\le F+3$$

对 800 面网格，\(3F=2400\)，\(F+3=803\)，实际 AMT 约 1200，介于两者之间。为什么不是 803？因为 DFS 并非每个面片都恰好只新增一个顶点：当遍历从一个面片跳到另一个不相邻的面片（跨越一个“切口”）时，新面片可能与已访问部分只共享一个顶点甚至不共享，此时需要写入两个或三个新顶点。这类跳转的次数取决于网格的拓扑复杂度与遍历策略。对简单连通的规则网格，跳转少，AMT 接近 \(F\)；对带多个连通分量或大量边界的网格，跳转多，AMT 向 \(3F\) 靠拢。所以“约减半”是对典型单连通网格的定性描述，不是对所有网格成立的恒等式。

公式 \(\mathrm{AMT}(\mathcal{M})\approx\frac{1}{2}\mathrm{VTT}(\mathcal{M})\) 里的“约”字承担了这部分误差。工程上更该关心的是比值 \(\mathrm{AMT}/\mathrm{VTT}\) 随网格类型的变化：规则闭合网格接近 \(1/3\)（因为 \(F+3\) 对 \(3F\)），带切口网格升高，碎片化网格可能接近 1。这个比值直接决定上下文预算的分配。若按最坏情况预留 \(3F\) 的预算，就等于放弃了 AMT 的全部收益；若按最好情况预留 \(F\)，遇到碎片化网格就会截断。可行做法是在 tokenizer 里统计跳转次数，把预算按实际序列长度分配，而不是按面数一刀切。

具体例子：一个 800 面的网格若被切成两个互不相连的连通分量，DFS 在第一个分量遍历完后必须跳到第二个分量，跳转处需要写入一个新的种子面（三个顶点）。若切成 \(k\) 个分量，AMT 长度约为 \(F+3k\)，减半效果随 \(k\) 增大而衰减。这说明 tokenizer 的遍历策略与网格的连通结构耦合：先做连通分量分解、再在每个分量内 DFS，可以把跳转次数控制在分量数上；若不做分解、直接按面表顺序遍历，跳转次数可能远高于分量数，序列变长且条件前缀的邻接信息变弱。

系统代价还有一层：DFS 需要显式的邻接表与访问标记，内存开销与面数成正比；对超大网格，递归 DFS 会爆栈，必须改成显式栈。显式栈的弹出顺序决定了序列顺序，不同实现可能给出不同的合法序列，训练数据若来自多种实现，模型会见到顺序分布上的差异。失败模式是栈实现错误导致面片被重复访问或漏访，序列里出现重复 token 或缺失面片，解码器还原出的网格面数对不上。检查手段是在 tokenize 结束后做一次覆盖校验：序列中每个面片标记恰好出现一次，且每个新顶点都能在前缀里找到其所属的共享边。

四 · 条件前缀的表示：位置、邻接与量化

自回归模型看到的 \(t_{

位置编码在这里不能只承担“第几个”的功能。两个前缀若 token 数相同但拓扑不同，模型必须能区分它们，否则条件分布被错误地合并。做法之一是把 DFS 的深度或当前面片的邻接度数编进位置信号，让相同序号的 token 在不同拓扑位置上有不同的表示。代价是位置编码不再是简单的正弦表，需要随遍历动态计算，推理时每一步都要更新，增加了序列建模的常数开销。失败模式是位置信号与 token 内容冲突：模型学会了靠位置猜连接类型，一旦推理时遍历顺序与训练分布不同，预测就崩。

量化损失是另一条被低估的代价。顶点坐标是连续量，进入 token 序列必须离散化。若每个坐标轴用 \(b\) 位量化，一个顶点就是 \(3b\) 位的信息，AMT 下每个面片平均携带一个顶点，序列的信息密度远高于文本 token。量化误差不会在 tokenization 阶段消失，它会传播到解码器：还原出的顶点落在量化格点上，相邻面片的共享边可能因为两侧顶点被量化到不同格点而裂开。工程上要么在解码后做一次焊接（按距离阈值合并顶点），要么在 tokenizer 里保证共享边只编码一次、两侧引用同一个顶点 id，后者正是 AMT 的结构优势，但前提是引用关系在序列里显式可查。

具体例子：一个 800 面网格若顶点坐标量化到较粗的格点，两个本应重合的共享边端点可能被量化到相邻格点，解码后出现微缝。逐面编码时这种裂缝更常见，因为共享边被两侧独立量化；AMT 只编码一次新顶点，裂缝只可能出现在跳转处的新种子上。这解释了为什么 AMT 不仅在长度上占优，在还原保真度上也占优——它把共享边的表示唯一化了。代价是 tokenizer 必须维护顶点 id 到序列位置的映射，解码器要按这个映射回填坐标，映射错位会导致面片引用错误的顶点。

系统取值上，连接类型字段、动态位置信号、顶点 id 映射三者共同决定了 token 序列的表达力与开销。三者都加，序列短但每 token 信息量大，模型容量要求高；只加顶点坐标，序列实现简单但条件信息弱，模型得自己学邻接。没有普适最优，选择取决于网格类型与上下文预算。判断依据是：若网格以规则闭合面为主，连接类型分布集中，加字段的收益大于词表代价；若网格碎片化严重，跳转频繁，动态位置信号的收益更明显。

五 · 解码器还原：从 token 回到面片

解码不是 tokenizer 的逆操作那么简单，因为自回归生成时前缀是模型自己产出的，可能不合法。一个具体机制是约束解码：每一步只在合法 token 集合里采样。合法性由当前部分网格决定——新顶点必须能与已访问顶点构成非退化面，连接类型必须与前缀的邻接结构一致。约束解码把 \(p(t_i\mid t_{

还原流程可以写成：

  • 维护一个部分网格结构，记录已还原的顶点与面片。
  • 按序列顺序读 token；对每个 token，依据连接类型字段找到它引用的已访问顶点。
  • 用新顶点与引用顶点构造面片，检查三点不共线、边不重复。
  • 若检查失败，回退到上一个合法前缀重新采样，而不是强行写入。
  • 序列结束后做全局校验：面片数、欧拉示性数、边界边计数是否与预期一致。

这套流程的系统代价主要在回退。自回归生成是单向的，回退意味着丢弃已生成的后缀，重采样成本随回退深度增长。若模型在长序列后段频繁产出不合法 token，回退会反复触发，生成时间不可控。缓解办法是把拓扑检查前移：在 tokenizer 阶段就把合法性约束编码进 token 取值空间，让不合法组合根本无法被表示，而不是等到解码时再拦截。这相当于把检查成本从推理期转移到数据构造期，代价是 token 取值空间变大、稀有组合的监督信号变少。

具体例子：800 面网格在 4096 上下文下，AMT 能生成约 1600 面，逐面编码约 800 面。若解码器在生成到第 1200 个 token 时发现一个退化面，回退到第 1199 个前缀重采样，已生成的后缀全部作废。对 AMT 来说这损失约 400 个 token 的工作量；对逐面编码来说，同样位置的回退损失更大，因为它的序列更长、每个面片占三个 token。这说明序列长度减半不仅省上下文，也降低了回退的绝对成本。但回退概率本身与模型质量相关，序列短不保证回退少——条件前缀弱、邻接信息不足时，AMT 的模型可能更容易在连接类型上出错。

全局校验是最后一道防线，也是失败模式最集中的地方。欧拉示性数对闭合流形是 2，对带边界网格是 \(2-2g-b\)（\(g\) 是亏格，\(b\) 是边界分量数）。解码器若还原出的网格示性数不符，说明序列里有面片缺失、重复或连接错误。这类错误在长序列上会累积，单步检查发现不了，只有全局校验能捕获。代价是校验需要完整的网格结构，不能在流式生成中增量完成，必须等序列结束。工程判断是：对交互式生成，全局校验可以异步做，先返回结果再报错；对批量生成，校验失败即丢弃，不进入下游管线。

六 · 失效条件与工程取舍

长序列限制是最直接的失效条件。上下文长度是硬上限，AMT 把同样预算下的面数上限提高约一倍，但没有改变“超出即截断”的性质。截断发生在序列中段时，前缀的条件信息不完整，解码器还原出的网格在截断处出现开放边界。工程上要么分块生成再拼接（拼接处的共享边需要重新编码，等于局部退化为逐面编码），要么在 tokenizer 阶段就按预算切分网格，把大网格拆成多个可独立生成的子网格。后者代价是子网格之间的接缝需要额外处理，接缝处的顶点被两侧各编码一次，局部减半效果消失。

拓扑合法性检查是第二类失效条件。tokenizer 假设输入网格是合法的，但真实数据里存在非流形边、重复面、零面积面。这些在 DFS 遍历时会打乱“每个面片新增至多一个顶点”的账本：非流形边被多个面片共享，遍历到第三个面片时它可能不新增顶点也不共享边，连接类型无法归类。失败模式是 tokenizer 静默跳过或强行归类，序列里出现无法还原的 token。可行做法是在 tokenize 前做一次清洗，把非流形结构拆开或标记为特殊 token，代价是清洗规则本身可能改变网格语义。

量化损失细节是第三类。坐标量化位数决定了还原精度，也决定了 token 的信息密度。位数高，序列短但每个 token 的取值空间大，模型输出层的 softmax 计算量上升；位数低，序列信息密度下降，还原出的网格细节丢失。这个取舍没有免费选项，工程判断依据是下游任务对几何精度的要求：若下游只做粗粒度分类，低位数够用；若要做精细渲染或仿真，高位数必要，代价是模型容量与推理算力。

系统取值上，tokenizer 的设计空间可以归纳为三个旋钮：遍历策略（DFS 顺序、连通分量分解、跳转处理）、token 字段（坐标、连接类型、拓扑标记）、量化精度。三个旋钮共同决定序列长度、词表大小、还原保真度与检查成本。调高任一旋钮的表达力，都会在另一处付出代价。AMT 的核心收益来自遍历策略里的“共享边只编码一次”，这个收益在规则网格上最大，在碎片化网格上衰减。判断一个网格是否适合 AMT，看的是共享边账本的实际比值，而不是面数本身。

最后一个具体机制落在预算分配上：给定上下文长度 \(L\)，AMT 下的面数上限约为 \(L\)（每个面片约一个 token），逐面编码约为 \(L/3\)。若目标网格面数 \(F\) 超过 \(L\)，就必须切分或放弃。切分点的选择影响接缝数量，接缝数量影响实际序列长度，实际序列长度又反过来影响能生成的面数——这是一个需要迭代求解的预算问题，不是一次性估算。工程上可行的做法是先按连通分量与几何连续性选切分点，再统计每个子网格的 AMT 长度，若总和超出预算则调整切分粒度，直到每个子网格都能在 \(L\) 内完成。这个循环的收敛速度取决于网格的碎片化程度，碎片化越高，切分越难收敛。
