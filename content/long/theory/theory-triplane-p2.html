二 · 从三维坐标到三组二维坐标：投影与插值的符号链条

设世界坐标中的查询点为 x = (x, y, z) ∈ ℝ³，归一化到 [-1, 1]³ 区间（这是 grid_sample 一类算子的约定域）。三张平面分别记作 T_xy ∈ ℝ^{N×N×C}、T_xz ∈ ℝ^{N×N×C}、T_yz ∈ ℝ^{N×N×C}，N 为平面边长分辨率，C 为每像素特征通道数。所谓“投影到三个正交平面”，在实现层面不是几何投影算子，而是三次坐标切片：xy 平面取 (x, y)，xz 平面取 (x, z)，yz 平面取 (y, z)。每一组二维坐标再各自做双线性插值，得到三个 C 维向量，拼接成 3C 维，送入小 MLP 解码。

双线性插值的严格写法如下。以 xy 平面为例，先把归一化坐标映射到像素网格坐标：u = (x+1)/2·(N−1)，v = (y+1)/2·(N−1)。取 i = ⌊u⌋，j = ⌊v⌋，α = u−i，β = v−j，则

$$\mathrm{interp}(T_{xy},\mathbf{x})=\sum_{a\in\{0,1\}}\sum_{b\in\{0,1\}}T_{xy}[i+a,\,j+b]\,(1-\alpha)^{1-a}\alpha^{a}(1-\beta)^{1-b}\beta^{b}$$

这个式子是四个角点特征的凸组合，权重随 α、β 连续变化。它的关键性质是对坐标连续可微（除整数网格边界处导数有折点），因此反传梯度能穿过插值回传到平面特征图上，这正是三平面能被端到端训练的前提。xz 与 yz 平面同理，只是把第二维换成 z 或把第一维换成 y。三组插值结果拼接后：

$$F(\mathbf{x})=\mathrm{MLP}\!\left(\mathrm{interp}(T_{xy},\mathbf{x}),\mathrm{interp}(T_{xz},\mathbf{x}),\mathrm{interp}(T_{yz},\mathbf{x})\right)$$

符号上要区分三件事：T 是被学习的参数张量（生成器的输出或可优化变量），interp 是无参数的确定性算子，MLP 是共享的小解码器（通常 1–2 个隐藏层，宽度远小于平面通道数）。三平面表示的“表达力预算”几乎全部压在 T 上，MLP 只负责把三路特征融合成密度/颜色/SDF 标量或向量。这个分工很重要：它意味着生成器的 2D 卷积主干可以直接输出 T，而 MLP 是固定的轻量头部，不参与 2D 卷积的显存账本。

一个具体的数值例子：取 N=256、C=32。单张平面元素数为 256×256×32 = 2,097,152，三张合计约 630 万参数。若改用同分辨率的体素表示，体素网格为 256³ = 16,777,216 个体素，每体素 32 通道，则参数量为 256³×32 ≈ 5.37 亿，两者相差约 85 倍。这个差距不是常数因子，而是随 N 增长的维度差：三平面是 O(N²)，体素是 O(N³)。当 N 翻倍，三平面参数变 4 倍，体素变 8 倍，差距继续拉大。工程上这就是“把 3D 降成 2D 卷积”的显存收益来源。

失败模式在这里已经埋下：双线性插值只聚合 2×2 邻域，平面分辨率不足时，高频几何细节会在插值中被抹平；更隐蔽的是三平面交叉处的坐标耦合——xy 平面在 z 方向没有分辨率，xz 平面在 y 方向没有分辨率，yz 平面在 x 方向没有分辨率。若某条沿 z 轴延伸的细结构只在 xy 平面上有投影，它在 xy 平面上是一个点，插值邻域极小，梯度信号弱，训练时容易被平滑掉。这是分辨率预算与几何频率之间的硬约束，不是调参能绕过的。

三 · 参数量推导：3N² 与 N³ 的数量级落差

把上面的例子一般化。三平面参数量 P_tri = 3·N²·C；体素参数量 P_vox = N³·C。比值 P_vox / P_tri = N/3。也就是说，分辨率每提高一倍，体素相对三平面的参数膨胀就翻一倍。在 N=256 时比值约 85，在 N=512 时比值约 170。这条比值曲线解释了为什么高分辨率 3D 生成几乎必然走三平面或隐式路线：体素在 N=512 时的参数量已是 512³×C 量级，单卡放不下，而三平面仍是 3×512²×C，量级可控。

表示参数量级N=256、C=32 时的量级随 N 的增长
三平面3N²C约 630 万平方增长
体素N³C约 5.4 亿立方增长

但参数量只是账本的一栏。真正的系统代价还包括查询时的访存：每查询一个 3D 点，要发起三次 grid_sample，每次读 4 个角点、共 12 次特征读取，再拼接送 MLP。体素表示只需一次三线性插值（8 个角点），访存次数更少但单次数据块更大。所以在渲染阶段，三平面的查询开销并不必然低于体素；它的优势集中在生成阶段——2D 卷积主干可以在平面张量上做规整的稠密卷积，显存占用与 2D 图像生成同级。这是“生成用 2D、查询用插值”的分工，代价被推到了推理侧。

推导中还有一个容易被忽略的项：三平面之间的冗余。三个平面各自独立存储，但它们在空间中覆盖同一批 3D 点，信息存在重叠。严格说，三平面是对 3D 特征场的一种过完备分解，参数量 3N²C 大于单张平面能承载的独立自由度，但小于体素的 N³C。这种冗余不是浪费：它让 2D 卷积在三个平面上学习共享的局部结构，同一物体的边缘、纹理在三个平面上以不同朝向重复出现，卷积核因此获得多视角的一致性约束。冗余在这里充当了正则项，而不是纯粹的存储开销。

失败模式：当 N 较小（例如 N=64 或 128）时，3N²C 与 N³C 的差距缩小，三平面的参数优势不再显著，而它的插值平滑与坐标耦合缺陷开始主导，此时体素或混合表示反而更稳。另一个代价是平面间的对齐假设：三平面默认三张图共享同一归一化坐标系，若生成器输出的三张平面在尺度或朝向上不一致（例如训练中某一平面通道塌缩），插值拼接后的特征会出现系统性偏差，MLP 难以纠正。这类失败在训练早期表现为三平面中某一张的梯度范数显著低于另外两张。

四 · 伪代码思路：查询函数的四条执行路径

把公式落成代码，核心是一个 query 函数。下面给出伪代码思路，重点标注每一步的张量形状与代价。

  • 输入归一化：x 形状 [B, P, 3]，B 为批大小，P 为采样点数。先检查坐标是否落在 [-1,1]³，越界点按边界截断或标记为无效，避免 grid_sample 的越界行为不一致。
  • 三次切片：xy 取 x[..., :2]，xz 取 x[..., [0,2]]，yz 取 x[..., 1:]。注意 xz 的列索引是 [0,2] 而非 [0,1]，这是最常见的实现错误——把 xz 写成 x[..., :2] 会让 xz 与 xy 完全重合，三平面退化成两平面。
  • 三次 grid_sample：每次输出 [B, P, C]。grid_sample 的采样网格需 reshape 成 [B, P, 1, 2]，平面张量需 unsqueeze 成 [B, C, N, N]。三次调用的访存是查询阶段的主要开销。
  • 拼接与解码：cat 后形状 [B, P, 3C]，送 MLP 得到 [B, P, D_out]，D_out 为密度/颜色/SDF 的输出维度。

伪代码层面的关键判断是批处理策略：渲染时 P 可达数十万（每条射线多个采样点），若一次性送 MLP，中间激活 [B, P, 3C] 会撑爆显存。工程做法是按射线分块（chunking），每块固定点数，逐块查询再拼接结果。分块大小由 3C 与 MLP 隐藏宽度共同决定，块太小则 kernel launch 开销占比上升，块太大则显存峰值失控。这是一个典型的吞吐与峰值的折中，没有普适最优值，需按卡型实测。

另一个实现细节是梯度检查点：训练生成器时，三平面 T 由 2D 卷积主干输出，query 阶段的插值与 MLP 若全部保留中间激活，反传显存会远超前向。对 MLP 段启用梯度检查点（前向不存激活、反传重算）可以把这部分显存压下来，代价是约多一次前向计算。这个取舍在 N=256、C=32 的规模下通常是值得的，因为 MLP 很浅，重算成本低。

失败模式：grid_sample 对越界坐标的默认行为（零填充或边界填充）在不同框架版本间存在差异，若训练与推理用了不同的填充模式，会出现边界处的密度跳变，表现为渲染图像边缘的暗环或亮环。另一个失败是坐标切片的顺序错误导致三平面通道语义错位——这种 bug 不会报错，只会让训练损失下降变慢，排查成本高。防御手段是在 query 函数里加一个形状断言：三路插值结果的通道数必须相等，且拼接后维度为 3C。

五 · 数值例子走一遍：N=256、C=32 的一次前向

取一个具体配置走一遍账本。N=256、C=32，三平面张量总元素约 630 万，以 float32 存储约 25 MB；若用 float16 则约 12.6 MB。生成器主干是 2D 卷积，输入为隐向量，输出三张 [C, N, N] 的特征图，这部分显存与同分辨率 2D 图像生成器同级。对比体素：256³×32 的 float32 张量约 2.1 GB，仅存储就吃掉一张消费级卡的大部分预算，更不用说卷积激活。

查询阶段，假设一次渲染 1024 条射线、每条 64 个采样点，则 P = 65,536。三次 grid_sample 各读 4 个角点，共约 786,432 次特征读取（每次读 C=32 维向量）。拼接后 [1, 65536, 96] 的中间张量约 25 MB（float32），送 MLP 后若隐藏层宽度为 64，中间激活再增一层。这个量级在单卡上可承受，但若 P 放大到 50 万，中间张量升到约 190 MB，加上 MLP 激活，峰值显存迅速逼近上限——这就是分块查询的必要性来源。

训练侧的账本不同。生成器反传时，梯度需从渲染损失穿过 query 回到三平面，再回到 2D 卷积主干。三平面张量的梯度本身是 630 万元素，与参数同量级；但 query 阶段的中间激活（插值结果、MLP 隐藏层）若全部保留，显存占用与前向的 P 成正比。EG3D 用三平面生成 512×512 人脸、单卡可训，其可行性正来自这个账本结构：主干是 2D 卷积（显存可控），query 是轻量插值加小 MLP（可分块、可检查点），两者叠加后仍在单卡预算内。

失败模式：当 C 增大（例如 C=64 或 128）时，3C 维拼接后的 MLP 输入变宽，MLP 第一层参数量按 3C×hidden 增长，query 的算力开销上升。此时若仍按原分块大小查询，单块计算时间变长，渲染吞吐下降。工程判断是：C 的选择要与 MLP 宽度、分块大小联合调，不能只按平面分辨率定。另一个失败是 float16 存储三平面时的插值精度损失：双线性插值的凸组合在 float16 下对相邻角点差异敏感，高频区域可能出现条带伪影，需在插值后转 float32 再送 MLP。

六 · 失效条件的机制根源：冗余、拓扑与几何真值

三平面的三个失效条件各有机制根源，不是泛泛的“能力不足”。第一，对称冗余：三张平面覆盖同一 3D 空间，同一局部结构在三个平面上重复出现，这带来正则收益，但也意味着平面之间存在信息竞争。若训练信号不足，某张平面可能塌缩为近似常量，而另外两张承担全部表达，此时三平面退化为两平面甚至单平面，表达力下降却不报错。监测手段是逐平面统计特征方差，方差趋零即为塌缩信号。

第二，固定拓扑：三平面是规则网格上的稠密特征图，没有部件级的分组结构。要编辑一个部件（例如换掉人脸的下颌），需要在三张平面上同时定位并修改对应区域，而三平面的坐标耦合让“同一部件”在三个平面上的投影形状不同，编辑操作难以保持一致。这是表示结构决定的，不是训练策略能解决的。对比之下，基于部件的表示或结构化隐式场在编辑性上有优势，代价是生成阶段更难用 2D 卷积。

第三，几何真值弱：三平面的监督信号通常来自渲染损失（多视角图像），而非直接的 3D 几何真值。插值平滑与平面分辨率限制会让高频几何（薄片、尖角、细杆）在优化中被抹平，因为渲染损失对这些细节的梯度信号弱于大面积区域。这不是三平面独有的问题，但三平面的 O(N²) 预算让它在同等显存下更难提升 N，从而放大了这一缺陷。工程上的缓解是加几何正则（如 SDF 的 eikonal 项）或在 query 中引入位置编码，但两者都增加算力开销。

把这三条失效条件放回公式看：F(x) 的表达力上界由 T 的分辨率 N 与通道 C 决定，MLP 只做融合不做生成；插值的 2×2 邻域是平滑的来源；三路拼接的坐标切片是拓扑固定的来源。因此调参的方向是明确的——提 N 换细节、提 C 换融合容量、加正则换几何精度，每一项都有对应的显存与算力代价。三平面不是免费的三维降维，它是把三维的表达力预算重新分配到二维网格上，代价以插值平滑、坐标耦合和固定拓扑的形式出现在下游。
