二 · 从渲染损失到三平面梯度：可微链条的推导

LRM 的训练之所以成立，关键不在于 Transformer 本身，而在于三平面被设计成一条端到端可微的链路：图像 token 进 Transformer 出三平面参数，三平面参数进体渲染出像素，像素与真值比较得到标量损失，标量损失再沿原路回传，一直传到 ViT 的权重。这条链上任何一环不可微，整个“用渲染损失训练编码器”的想法就落空。因此推导的第一步不是写网络结构，而是把损失对三平面参数的依赖关系拆开。

设三平面为三个正交的特征图 \(\mathbf{P}_{xy},\mathbf{P}_{xz},\mathbf{P}_{yz}\)，每个尺寸 \(H\times W\times C\)。对空间点 \(\mathbf{x}=(x,y,z)\in[-1,1]^3\)，三平面特征由双线性采样后拼接或求和得到：

$$\mathbf{f}(\mathbf{x})=\mathrm{cat}\big[\mathrm{BiLerp}(\mathbf{P}_{xy},x,y),\ \mathrm{BiLerp}(\mathbf{P}_{xz},x,z),\ \mathrm{BiLerp}(\mathbf{P}_{yz},y,z)\big]$$

这里的 \(\mathrm{BiLerp}\) 对特征图坐标做连续采样，权重是四个相邻格点的双线性系数。因为系数是坐标的分段线性函数，\(\partial \mathbf{f}/\partial \mathbf{P}\) 在每个格点上是常数，\(\partial \mathbf{f}/\partial \mathbf{x}\) 在格点内部是常数、跨格点处不连续但几乎处处有定义。这就是三平面可微性的来源：它不是把 3D 体素插值成连续场，而是把三张 2D 特征图沿三个轴向“投影—采样—拼接”，梯度可以直接落到 2D 卷积式的特征图上。

接着是体渲染。沿相机射线采样 \(N\) 个点 \(\mathbf{x}_i=t_i\)，密度 \(\sigma_i\) 与颜色 \(\mathbf{c}_i\) 由一个小的 MLP 从 \(\mathbf{f}(\mathbf{x}_i)\) 解出，像素颜色是离散 alpha 合成：

$$\hat{I}(\mathbf{r})=\sum_{i=1}^{N}T_i\big(1-e^{-\sigma_i\delta_i}\big)\mathbf{c}_i,\qquad T_i=\exp\Big(-\sum_{j

把 \(\hat{I}\) 与真值 \(I_v\) 的平方误差对 \(\mathbf{P}\) 求导，链式法则经过 \(\mathbf{c}_i,\sigma_i\)、经过 \(\mathbf{f}(\mathbf{x}_i)\)、经过双线性权重，最终得到每个被采样格点的梯度。由于一条射线只覆盖三张平面上的少数格点，梯度是稀疏的；但 16 个视角、每视角多条射线叠加后，覆盖密度足以让三平面的大部分区域获得有效梯度。这就是“渲染损失能训练三平面”的机制层面解释，而不是一句“可微所以能训”。

系统代价在这里第一次显现：体渲染的采样数 \(N\) 直接决定前向与反向的计算量，而梯度稀疏性意味着远离任何训练视角的三平面区域几乎收不到信号。失败模式是：如果训练视角集中在物体正面，背面三平面区域的梯度接近于零，网络只能靠数据先验“猜”背面。这不是训练不收敛，而是损失函数在那些区域没有定义良好的监督。

具体例子：输入 512×512 图，DINO ViT 出 1024 个 token；24 层 Transformer 解码成 \(3\times64\times64\times32\) 三平面；渲染 16 个视角，与 Objaverse 真值算 MSE+LPIPS。这里 16 个视角的射线集合决定了哪些三平面格点被采样，\(64\times64\) 的分辨率决定了每个格点承载的特征粒度。若把视角数减到 4，背面格点的梯度覆盖会明显变差，这不是靠调学习率能补的。

三 · 符号逐项解释：每个维度在系统里对应什么

公式 \(\mathbf{T}=\mathrm{Transformer}_\theta(I,\mathbf{c})\) 里的每个符号都不是装饰。\(I\) 是输入图像，工程上它是经过归一化的张量，尺寸与 ViT 的 patch 切分一致；\(\mathbf{c}\) 是相机参数，它进入 Transformer 的方式决定了模型是否具备视角条件化能力。若 \(\mathbf{c}\) 只作为额外 token 拼接，模型学到的是“给定这个视角的图，预测规范坐标系下的三平面”；若 \(\mathbf{c}\) 参与 cross-attention 的 query 构造，模型则可以把图像 token 按目标视角重新加权。LRM 的设定里 \(\mathbf{c}\) 是输入条件的一部分，推理时它对应输入图的相机，训练时它对应每个监督视角的相机，两者在同一个映射里被区分开。

\(\mathbf{T}\) 是三平面，维度 \(3\times H\times W\times C\)。三个“3”不是通道数，而是三张正交平面；\(H\times W\) 是平面分辨率，\(C\) 是每格点特征通道。工程上这三个数直接对应显存与渲染成本：分辨率翻倍，三平面参数量翻四倍，体渲染时每次采样的双线性读取也翻四倍。通道数 \(C\) 决定 MLP 输入的宽度，进而决定密度与颜色的表达力。LRM 用 \(64\times64\times32\) 是一个明确的工程折中：分辨率足够表达物体级几何，又不至于让渲染采样成为瓶颈。

损失里的 \(v\) 是监督视角索引，\(\mathrm{VolumeRender}(\mathbf{T},\mathbf{c}_v)\) 表示用第 \(v\) 个相机参数对同一组三平面做体渲染。这里有一个容易被忽略的符号细节：\(\mathbf{T}\) 不随 \(v\) 变化，也就是说三平面是视角无关的 3D 表示，视角只进入渲染过程。这正是“一次前向出 3D”的符号层面的含义：网络输出的是与相机解耦的 \(\mathbf{T}\)，多视角只是用来监督 \(\mathbf{T}\) 的渲染一致性。若 \(\mathbf{T}\) 依赖 \(v\)，那就退化成逐视角的 2D 生成，不再是 3D 表示。

\(\mathcal{L}\) 是求和而非平均，工程上这意味着视角数改变会改变损失量级，进而影响有效学习率。实践中要么固定视角数，要么在实现里做归一化。LPIPS 项与 MSE 并列时，两者的量级差异需要权重平衡，否则梯度会被其中一项主导。这是符号背后真实的系统取值问题，而不是数学上的等价变换。

符号含义工程对应代价或失败模式
\(I\)输入图像ViT patch 切分后的张量分辨率不足则 token 表达力受限
\(\mathbf{c}\)相机参数条件 token 或 query 构造条件化方式错误则视角泛化差
\(\mathbf{T}\)三平面\(3\times64\times64\times32\) 特征图分辨率损失、显存随分辨率平方增长

这张表的意义在于把公式里的抽象符号钉到具体的系统取值上。读者如果有工程背景，看到 \(\mathbf{T}\) 的第一反应应该是显存占用与采样成本，而不是“一个张量”。LRM 的可行性恰恰来自这些取值被压到了可训练、可推理的范围：50 万物体训练后，推理约 10 秒，这个数字对应的是 \(64\times64\) 分辨率与固定采样数下的前向开销。

四 · 数值例子：从一张图到 16 个视角的完整账

用一个具体例子把整条链路走一遍。输入 512×512 图，DINO ViT 出 1024 个 token。这个数字来自 patch 切分：512×512 被切成固定大小的 patch，token 数由 patch 数与可能的 cls token 决定，工程上 1024 是一个常见的量级。1024 个 token 进入 24 层 Transformer，每层做 self-attention 与 cross-attention，cross-attention 把图像 token 分配到三平面 token 上。三平面 token 的数量是 \(3\times64\times64=12288\)，远多于图像 token，这意味着 cross-attention 是一个“扩张”映射：少量图像 token 要生成大量 3D 特征 token。这个不对称是 LRM 的核心计算特征，也是它必须依赖数据先验的原因——1024 个 token 不可能无损编码所有 3D 细节，网络学到的是从图像到 3D 的统计映射。

24 层 Transformer 解码成 \(3\times64\times64\times32\) 三平面。参数量与计算量在这里有一个明确的取舍：层数越多，cross-attention 的表达力越强，但训练成本线性增长；50 万物体的训练规模意味着这个成本必须被控制在可接受范围。三平面的 \(32\) 通道是每个格点的特征宽度，体渲染时 MLP 从这个 32 维向量解出密度与颜色。若通道数降到 8，表达力下降；若升到 64，渲染时的 MLP 输入翻倍，采样成本上升。

渲染 16 个视角，与 Objaverse 真值算 MSE+LPIPS。16 个视角的选择不是随意的：它要覆盖物体的多个方位，才能让三平面的大部分格点收到梯度。每个视角的渲染需要沿射线采样若干点，每个点做三次双线性采样加一次 MLP 前向。16 个视角的渲染是训练时每一步的主要开销，也是推理时“一次前向出 3D”之后可选的验证步骤。推理时不需要渲染 16 个视角，只需要输出三平面；渲染只在训练与评估时发生。这个区分很重要：推理约 10 秒对应的是 ViT+Transformer 的前向，而不是 16 视角体渲染。

50 万物体训练后，推理约 10 秒。这个数字的工程含义是：一次前向的成本落在秒级，而不是逐场景优化的分钟级。逐场景优化需要对每个物体单独拟合三平面，成本随物体数线性增长；LRM 把成本前移到训练阶段，推理阶段摊薄为固定的一次前向。代价是训练成本高：50 万物体的多视角渲染监督，每一步都要跑 16 个视角的体渲染与反向传播，这是整个系统最重的部分。失败模式也在这里：如果训练规模不足，cross-attention 学到的“图像特征到 3D 特征”的映射会退化为记忆训练分布，背面细节靠数据先验的质量直接决定泛化。

网格提取的分辨率损失是另一个数值层面的代价。三平面是 \(64\times64\) 的特征图，从它提取网格时，等值面提取的分辨率受限于特征图分辨率与采样密度。即使三平面在连续域上定义了密度场，离散提取仍会丢失小于格点尺度的细节。这不是训练问题，而是表示与提取环节的固有损失。工程判断是：如果下游需要高精度网格，三平面分辨率与提取算法要一起设计，不能只调网络。

五 · 伪代码思路：前向与损失的最小骨架

把上面的推导压缩成最小伪代码，重点看数据流而不是语法：

  • 前向：tokens = vit(img) 把图像切成 token 并编码；tri = transformer(tokens, cam) 用 cross-attention 把 token 映射到三平面 token，再 reshape 成 \(3\times64\times64\times32\)；返回 tri。
  • 损失：对每个监督视角 (c, I)，调用 volume_render(tri, c) 得到渲染图，与 I 算 MSE 与 LPIPS，求和返回。
  • 反向：损失对 tri 求导，经过体渲染的双线性采样与 MLP，落到三平面 token，再经过 cross-attention 落到图像 token 与 ViT 权重。

这个骨架里有两个工程上必须显式处理的点。第一，transformer(tokens, cam) 中 cam 的注入方式决定了条件化的正确性：若 cam 只拼在输入序列末尾，cross-attention 的 query 不包含视角信息，模型学到的是视角无关的映射，推理时换视角会失效；若 cam 参与 query 构造，cross-attention 才能按目标视角重新分配图像 token。第二，volume_render 的采样策略决定梯度的覆盖：固定均匀采样实现简单，但对薄表面与背面区域的梯度覆盖差；分层采样或重要性采样能改善覆盖，但增加实现复杂度与计算量。

伪代码层面的失败模式是“损失看似下降但 3D 不一致”。原因是渲染损失只约束被渲染视角的像素，未被采样到的三平面区域没有梯度，网络可以用数据先验填出“看起来合理”的背面，但多视角一致性无法保证。工程上的缓解手段是增加视角覆盖与在渲染时对三平面做正则，但这些手段都增加训练成本。50 万物体训练后推理约 10 秒的设定下，训练成本已经被推到较高水平，再加正则需要重新权衡。

另一个伪代码细节是 tri 的 reshape。Transformer 输出的是 token 序列，要 reshape 成三平面张量才能做双线性采样。reshape 的顺序必须与 cross-attention 中三平面 token 的排列一致，否则三个平面的语义错位，渲染出的几何会系统性扭曲。这类错误在实现里不会报错，只会表现为训练损失下降缓慢或渲染结果异常，属于典型的“符号正确但工程错位”的失败模式。

六 · 失效条件的推导视角：先验、分辨率与训练成本

从推导角度看，LRM 的失效条件不是三个孤立的缺点，而是同一条可微链条上的三个断点。第一个断点是背面细节靠数据先验。渲染损失只对采样到的视角给梯度，背面格点的梯度覆盖不足，网络只能依赖 cross-attention 学到的“图像特征到 3D 特征”的统计映射。这个映射的质量由训练分布决定：50 万物体的规模提供了先验，但先验不是几何约束，遇到分布外物体时背面会退化。推导上，这对应 \(\partial\mathcal{L}/\partial\mathbf{P}_{\text{back}}\) 在训练视角覆盖不足时接近于零，优化器没有信号可用。

第二个断点是网格提取的分辨率损失。三平面分辨率 \(64\times64\) 决定了特征图的格点尺度，等值面提取在这个尺度上离散化密度场。即使连续域上的密度场是准确的，提取出的网格也会丢失小于格点尺度的细节。这不是可微链条的断点，而是表示与提取环节的固有损失。工程判断是：三平面分辨率与下游网格精度要匹配，不能指望 \(64\times64\) 的特征图提取出高精度网格。

第三个断点是训练成本高。16 个视角的体渲染与反向传播是每一步的主要开销，50 万物体的训练规模把这个开销放大到整个训练周期。推导上，体渲染的采样数 \(N\) 与视角数 \(v\) 共同决定每步的计算量，两者都是超参数，调大改善梯度覆盖但增加成本。这是系统取值问题，不是算法正确性问题。LRM 的工程取舍是把成本前移到训练，换取推理的一次前向；代价是训练阶段的门槛高，小规模数据无法复现同样的先验质量。

把三个断点放在一起看，LRM 的适用边界就清楚了：它适合物体级、训练分布覆盖良好的场景，推理要求秒级一次前向；不适合需要高精度网格、或训练分布外的稀有物体。这个判断来自可微链条的结构，而不是实验数字。具体机制上，cross-attention 的“扩张”映射（1024 个图像 token 到 12288 个三平面 token）决定了它必须依赖数据先验，而体渲染的采样策略决定了梯度覆盖的稀疏性。两者共同构成了 LRM 的能力与局限。
