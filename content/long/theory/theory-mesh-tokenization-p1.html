一 · 一句话与严格定义：从面片集合到条件概率链

网格 tokenization 的一句话版本是：网格是点和面的集合，不能直接喂给 Transformer；tokenization 把它变成序列，每个面片编码成一个 token，按邻接关系排成一条「句子」。这句话里已经埋了两个关键约束：第一，Transformer 的输入必须是离散符号的有序序列，而网格是带拓扑的二维复形；第二，序列的排列不是任意的，必须沿邻接关系走，否则共享边无法被复用。把这两点合起来，才得到严格定义：网格 M 被映射成 token 序列 (t_1,…,t_N)，每个 token 编码一个面片的顶点与邻接信息，自回归模型学习 p(t_i | t_<i)。写成链式分解就是：

这里 AMT 指按邻接遍历、相邻面片只新增一个顶点的编码方式，VTT 指每个面片独立编码三个顶点的逐面编码。定义的重点不在「编码成 token」这个动作，而在「条件概率链」这个结构：模型不是一次性预测整个网格，而是在第 i 步只看 t_<i，预测第 i 个面片。这意味着 token 的语义必须自包含到足以让解码器还原面片，同时又必须让前缀携带足够的拓扑上下文，使下一步的邻接关系可被推断。定义里没有明说但必须成立的一条是：序列顺序与网格的遍历顺序一致，token 之间的邻接关系由遍历顺序隐式携带，而不是每个 token 都显式列出全部邻居。

一个具体例子可以把这个定义钉死。取一个 800 面的网格，若逐面独立编码三个顶点，需要 2400 个顶点 token；按 DFS 遍历面片、相邻面片只新增一个顶点，则只需约 1200 个 token，序列长度减半。定义中的 N 从 2400 降到 1200，而 p(M) 的链式分解结构不变，变的只是每个 t_i 携带的信息量和前缀的复用效率。这就是定义与工程之间的接缝：数学上 N 只是一个下标上界，工程上 N 直接决定 4096 上下文能装下多少面——同样 4096 的上下文，AMT 能生成约 1600 面，逐面编码只能生成约 800 面。

二 · 为什么需要：Transformer 的输入契约与网格的拓扑结构不匹配

Transformer 的输入契约是「定长或变长的离散 token 序列 + 位置编码」，注意力机制在序列维度上做全对全的软对齐。网格的天然表示是顶点坐标矩阵加面索引数组，前者是连续浮点数，后者是变长的整数三元组，二者都不满足「离散符号序列」这一契约。直接把顶点坐标当 token 喂进去，等于让模型在连续空间里做回归，注意力权重失去符号级的可解释性；直接把面索引数组展平，则丢失了「哪些面共享边」这一拓扑信息，模型只能从索引的数值巧合里猜邻接。tokenization 的作用就是造一座桥：把面片这个二维拓扑单元压成一个离散符号，再按邻接顺序排成序列，让注意力机制在「面片之间」而不是「坐标之间」建立关系。

桥的承重结构是共享边复用。若每个面片独立编码三个顶点，相邻面片会重复编码共享边：一条内部边被两个面片各写一次，顶点坐标被重复送入序列。按 DFS 遍历面片时，进入一个新面片只新增一个顶点，另外两个顶点来自已编码的相邻面片，于是序列长度约减半。伪代码的思路是：

  • 对网格做 DFS 遍历，维护一个已访问顶点集合；
  • 每到一个面片，检查其三个顶点，只把未访问的顶点追加进序列；
  • token 中同时记录该面片相对前一个面片的邻接方向，供解码器还原面片朝向；
  • 遍历结束后，序列长度等于顶点数加面片数级别的量，而非三倍面片数。

对应的伪代码可以写成 def tokenize(mesh): seq=[]; for face in dfs(mesh): seq.append(new_vertex(face)); return seq 的骨架，但工程实现里 new_vertex 必须返回「新顶点坐标 + 该面片与前驱面片的共享边索引」，否则解码器无法判断这个面片接在哪条边上。这就是为什么需要 tokenization 而不是简单展平：展平丢拓扑，逐面三顶点丢复用，只有沿邻接遍历的编码同时保住拓扑和复用。

系统代价在这里第一次显形：DFS 遍历要求网格是流形或至少是连通的，非流形边、悬挂面、重复面会让「共享边」的判定失败，token 序列出现断裂。一个 800 面的网格如果有 3 条非流形边，DFS 会在这些边上分叉，序列不再是一条单链，解码器按前缀还原时会在分叉处产生歧义。失败模式不是数值误差，而是拓扑合法性检查缺失导致的序列语义崩坏。

三 · 常见误解之一：tokenization 等于量化或压缩

最常见的误解是把网格 tokenization 等同于「把坐标量化成整数」或「把网格压缩成更短的数组」。量化只改变数值精度，不改变序列结构：把每个顶点的三个浮点坐标各量化成 8 位整数，得到的仍是一个顶点一个 token 的逐面编码，序列长度不变，AMT 的减半效应完全不会出现。压缩则改变存储布局，比如用索引缓冲区去掉重复顶点，但它不产生「按邻接顺序排列的条件概率链」，Transformer 仍然无法在压缩后的字节流上做 next-token prediction。tokenization 的实质是重排加复用：重排让面片按邻接关系成句，复用让共享边只写一次。量化损失是这条链上的一个细节代价——坐标被量化后，解码器还原的面片顶点有误差，误差会沿序列累积，但这不是 tokenization 的定义性特征。

用一个对照例子说明区别。同一个 800 面网格，方案 A 做坐标量化但不重排：2400 个顶点 token，每个 token 是量化后的三整数，序列长度 2400，4096 上下文只能装约 800 面。方案 B 做 AMT：约 1200 个 token，每个 token 是新顶点加共享边索引，序列长度 1200，同样上下文能装约 1600 面。两者都「把网格变成了整数序列」，但只有 B 改变了 N 的量级。误解的代价是工程选型错误：以为做了量化就等于做了 tokenization，结果上下文预算按 2400 花掉，生成面数只有预期的一半。量化损失细节是另一个独立问题：8 位量化在 800 面网格上造成的顶点偏移会通过共享边传播到相邻面片，解码器需要在 token 里保留足够的边索引信息来约束这种传播，否则误差在序列后半段放大。

四 · 常见误解之二：序列顺序无关紧要，反正注意力是全局的

第二个误解是「注意力机制对顺序不敏感，所以面片按什么顺序排都行」。这个说法只在没有位置编码、且任务对置换等变时才近似成立；自回归解码是因果的，p(t_i | t_<i) 只看到前缀，顺序直接决定前缀里有什么。若把面片按随机顺序排，相邻面片在序列里可能相隔很远，共享边复用失效，每个面片都得重新编码全部三个顶点，AMT 退化成 VTT，序列长度回到 2400。更糟的是，解码器在第 i 步看不到第 i+1 步才出现的邻接面片，随机顺序会让「这个面片接在哪条边上」在前缀里找不到依据，拓扑合法性无法保证。

正确的顺序是沿邻接关系的遍历顺序，DFS 是其中一种。DFS 的性质是：进入新面片时，前驱面片刚被编码过，共享边在前缀末尾，解码器只需看最近几个 token 就能确定邻接方向。这就是为什么定义里强调「按邻接关系排成一条句子」而不是「排成任意序列」。系统代价体现在长序列上：DFS 在复杂网格上会产生深递归，序列前缀的拓扑上下文是局部的，一旦遍历进入一个远离起点的分支，前缀里最近的 token 与当前面片的邻接关系变弱，模型需要更长的注意力跨度来维持一致性。失效条件是长序列限制复杂度：当 N 接近上下文上限时，DFS 的深分支让前缀的有效上下文被稀释，生成的面片在后半段更容易出现拓扑错误。一个具体场景是 1600 面的 AMT 序列填满 4096 上下文，序列末尾的面片其最近邻接 token 可能已在数百步之前，解码器必须依赖位置编码和边索引显式找回邻接，而不能只靠「最近几个 token」。

五 · 常见误解之三：token 只需编码顶点，邻接可以事后补

第三个误解是「token 里只放顶点坐标就够了，邻接关系解码后再用几何最近邻补上」。这个做法在稠密规则网格上偶尔能跑通，因为最近邻搜索能找回共享边；但在非均匀网格、薄壳结构、自交附近，几何最近邻与拓扑邻接不一致，事后补邻接会把面片接到错误的边上。定义里写的是「每个 token 编码一个面片的顶点/邻接」，邻接是 token 的一部分，不是后处理。原因在条件概率链：p(t_i | t_<i) 要求第 i 步的邻接信息可从前缀推断，如果 token 不含邻接，模型只能从顶点坐标猜，猜错时整个后缀的拓扑都错。

工程上的做法是在 token 中显式携带「共享边索引」或「相对前驱面片的转向」。以 DFS 为例，进入新面片时，前驱面片的一条边是共享边，新顶点接在这条边上，token 只需记录「新顶点 + 共享边在前驱面片中的局部编号」。解码器按前缀还原前驱面片后，用这个局部编号定位共享边，再把新顶点接上去，面片朝向由顶点顺序决定。这样每个 token 的信息量是「一个新顶点 + 一个边引用」，而不是三个顶点。代价是 token 的语义变复杂：解码器必须先还原前驱面片才能解释当前 token，前缀错误会沿链传播。失效模式是拓扑合法性需检查：如果共享边引用指向的边在前驱面片中不存在（例如遍历顺序与前驱记录不一致），解码器必须报错而不是静默修补。一个 800 面网格若在 token 化时漏记一条共享边引用，解码到该面片时只能退化为三顶点独立编码，序列局部的 AMT 减半效应消失，整体 N 上升。

六 · 定义边界与工程判断：什么算 tokenization，什么不算

把上面的误解收拢，可以给出一条可操作的判定边界：一个网格到序列的映射算 tokenization，当且仅当它同时满足三条——序列是离散符号的有序排列；每个符号编码一个面片及其与前缀的邻接关系；序列长度因共享边复用而显著小于逐面三顶点的三倍面片数。只满足第一条是量化或展平，只满足前两条是带邻接的逐面编码（N 仍为 3F 量级），三条都满足才是 AMT 意义上的 tokenization。用 800 面网格对照：逐面三顶点 2400 token 不满足第三条；带邻接但每面仍写三顶点也是 2400 token，不满足第三条；AMT 约 1200 token 满足全部三条。判定边界直接对应上下文预算：4096 上下文下，满足第三条的方案能生成约 1600 面，不满足的只能生成约 800 面。

工程判断落在两个取舍上。其一是遍历顺序与序列长度的取舍：DFS 让相邻面片只新增一个顶点，序列减半，但深递归使前缀上下文局部化，长序列末尾的邻接要靠显式边索引找回；广度优先或按空间分块遍历能缩短注意力跨度，但共享边复用率下降，N 上升。其二是 token 语义复杂度与解码鲁棒性的取舍：token 携带边引用让 N 减半，但解码器必须按前缀顺序还原，前缀一旦出错就沿链传播；token 只带顶点让解码独立，但 N 回到三倍面片数，上下文装不下面数。这两个取舍没有免费选项，定义里的 p(M) 链式分解已经把代价写死：条件概率链越长，前缀依赖越重，拓扑合法性检查越不可省。量化损失细节是第三个取舍，它不改变 N 的量级，但决定解码器还原的面片在几何上是否可接受——坐标量化误差通过共享边传播，边索引的精度必须与顶点量化精度匹配，否则解码器定位共享边时出现歧义。

最后落到一个具体机制上：AMT 的减半效应来自「相邻面片只新增一个顶点」这一条，而这条成立的充要条件是遍历顺序保证每个新面片至少有一条边已在前缀中。DFS 满足它，因为进入新面片时前驱面片刚被编码；随机顺序不满足，共享边可能尚未出现，新面片只能写三个顶点。因此 tokenization 的定义不是「编码成 token」这个宽泛动作，而是「按邻接遍历 + 共享边复用 + 条件概率链」这三件事的合取。工程上判断一个网格 tokenizer 是否合格，只需看它在 800 面网格上产出的 N 是接近 1200 还是接近 2400，以及解码器能否在不做几何最近邻搜索的前提下还原全部面片邻接。这两个可测的量，就是定义边界在系统里的投影。
